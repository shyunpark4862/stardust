# O4: minimize(Newton-CG, trust-ncg, trust-exact)의 속도 (scipy 1.18.1과 비교)

`bench/optimize/o4/speed.py`로 쟀다(2026-11-20, Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, Accelerate). 시간은 ms, 여러 번(많아야 5번, 2초를 넘으면 그만) 가운데 가장 빠른 값이다. 원래 출력은 `speed.log`, 값 전체는 `speed.json`이다.

- 문제: scipy의 일반화된 Rosenbrock(`rosen`, `rosen_der`, `rosen_hess`, `rosen_hess_prod`), n = 2, 10, 100, 1000, x0 = (−1.2, 1, −1.2, 1, …). 함수는 각 라이브러리의 배열로 썼다(sd는 sd, scipy는 numpy; 값은 비트까지 같다). Newton-CG는 `hess`, `hessp`, `hess='2-point'`, 둘 다 없음(기울기의 차분), trust-ncg는 `hess`와 `hessp`, trust-exact는 `hess`다. n = 1000은 반복 상한(`max_iter`, 두 라이브러리에 같게)을 두었다.
- "반복당 자기 비용"은 전체 시간에서 사용자 함수(`fun`, `jac`, `hess`, `hessp`) 안의 시간을 빼고 반복 수로 나눈 것이다. 방법 자체의 비용(CG, 부분문제, 선 탐색, 차분의 고리, 콜백을 부르는 고리)이다.
- 걸음이 scipy와 같으므로(O9) 모든 줄에서 반복 수, `nfev`, `status`가 같다. `njev`·`nhev`가 다른 곳은 결정 때문이다: `nhev`는 실제 호출 수라(O68, O69) `hessp`만 준 trust-ncg는 scipy보다 하나 적고(scipy의 자리 채움), `hess`를 준 trust-ncg는 결과의 `hess` 호출 하나가 많다. newton-cg의 `njev`는 x의 기울기를 위한 끝 호출(O70)이 있으면 하나 많다.
- 1스레드 / 10스레드를 함께 적었다. 사용자 함수가 Python이고 큰 계산(n = 1000의 dgemv, potrf)도 한 번에 하나라 두 값이 측정 잡음 안에서 같다.

- n = 2–100에서 반복당 자기 비용은 scipy의 1/3–1/60이다(trust-exact n = 10: 2.2 µs 대 59 µs, Newton-CG n = 10: 0.9 µs 대 26 µs, trust-exact n = 100: 51 µs 대 142 µs). scipy는 CG의 걸음마다, 부분문제의 λ 반복마다 Python에서 numpy·scipy.linalg를 부르고(trust-exact의 최소 특이값 추정은 n번의 Python 고리다), 이 라이브러리는 반복 전체가 C++이고 콜백만 Python이다.
- 차분의 헤세 곱은 차이가 더 크다(Newton-CG '2-point' n = 1000: 0.034 ms 대 0.31 ms). scipy는 곱마다 `LinearOperator`를 거쳐 `approx_derivative`의 고리를 Python으로 돈다.
- `hess`의 행렬을 쓰는 n = 1000의 Newton-CG·trust-ncg는 scipy와 비슷하거나 조금 느리다(0.23 대 0.22 ms, 0.17 대 0.13 ms). 두 쪽 모두 시간의 대부분이 CG 걸음마다의 같은 dgemv(8 MB의 행렬)다. 이쪽은 사용자가 돌려준 행렬을 한 번 복사해 두고(scipy는 사용자의 배열을 그대로 쓴다: 사용자가 나중에 그 배열을 고치면 scipy의 부분문제도 바뀐다), 그 복사가 반복 하나에 0.03 ms쯤이다.
- trust-exact n = 1000: 5.2 ms 대 7.2 ms. 반복마다 H + λI의 Cholesky(같은 Accelerate potrf)가 대부분이다. 이쪽은 potrf가 읽는 위 삼각만 열 우선으로 옮기고(타일로 나눈 전치), scipy는 반복마다 n × n 행렬 넷(`np.eye`, λ배, H + λI, f2py의 열 우선 복사)을 만든다.
