# O0 기준선: scipy 1.18.1

`bench/optimize/o0/speed.py`로 쟀다(2026-11-20, Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, Accelerate). 시간은 ms, 여러 번(많아야 5번, 2초를 넘으면 그만) 가운데 가장 빠른 값이다. 원래 출력은 `speed.log`, 값 전체는 `speed.json`이다.

- 문제는 numpy로 쓴 것이다(Python 고리가 아니라 scipy의 비용을 재려고): 스칼라 근은 sin x − x/2(APS 1)와 x³ − 2x − 5(Chandrupatla 1), 스칼라 최솟값은 eˣ − 5x, 배치는 x³ − 2x − c = 0과 (x − c)² + 0.01cx⁴의 최솟값(c는 10³–10⁶개), 다변수 최소화는 확장 Rosenbrock(`scipy.optimize.rosen`, x0 = (−1.2, 1, …)), 최소제곱은 y − exp(Xθ)(X는 N(0, 1/n), θ* = 0.3, 0에서 시작), 방정식계는 Broyden 삼중대각, 선형 최소제곱은 b = A·linspace(−1, 1, n) + N(0, 1)과 경계 [−0.5, 0.5](경계의 절반쯤이 걸린다).
- 스레드 수는 `VECLIB_MAXIMUM_THREADS`로 바꿨다(프로세스마다). 사용자 함수가 Python이고 반복이 Python·C의 순차 코드라, 10스레드가 빨라지는 곳은 BFGS n = 1000(밀집 역헤시안 갱신의 행렬·벡터 곱, 59.0 s → 36.6 s)뿐이다. 나머지는 1·10스레드가 측정 잡음 안에서 같다. 그래서 아래 표는 1스레드만 적고 차이가 있는 줄만 따로 적는다.

- 괄호는 (nfev, nit) 또는 (nfev, nhev)다. 차분 L-BFGS-B는 n = 1000에서 12반복, n = 10⁴에서 1반복 만에 멈춘다(차분 기울기의 잡음 때문에 ftol 판정이 일찍 선다; 해에 닿지 않았다). n = 10⁴의 L-BFGS-B는 `maxfun` 15000에 닿았다.
- BFGS n = 1000은 반복 하나에 밀집 n × n 갱신이 있어 12 ms이고, trust-exact n = 1000은 반복마다 헤시안의 Cholesky 분해로 부분문제를 풀어 6.7 ms다. 나머지는 반복 하나에 수십 µs로 Python의 비용이 크다.
