# O5: root, lsq_linear, nnls의 속도 (scipy 1.18.1과 비교)

`bench/optimize/o5/speed.py`로 쟀다(2026-11-20, Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, Accelerate). 시간은 ms, 여러 번(많아야 5번, 2초를 넘으면 그만) 가운데 가장 빠른 값이다. 원래 출력은 `speed.log`, 값 전체는 `speed.json`이다. 1스레드 / 10스레드를 함께 적었다.

## root

- 문제: Broyden의 삼중대각 방정식계 f_i = (3 − 2x_i)x_i − x_{i−1} − 2x_{i+1} + 1, n = 2, 10, 100, x0 = (−10, …, −10). 함수와 야코비안은 각 라이브러리의 배열로 썼다(sd는 sd, scipy는 numpy).
- "반복당 자기 비용"은 전체 시간에서 사용자 함수(`fun`, `jac`) 안의 시간을 빼고 반복 수로 나눈 것이다. 반복은 'hybr'이 시험한 걸음(sd의 `n_iter`; 걸음이 scipy와 같다), 야코비안이 있는 'lm'이 야코비안 수(두 쪽 각자의 `njev`)다. 차분의 'lm'은 시간만 적었다.
- nfev는 sd의 수와 scipy가 `fun`을 부른 수다. scipy는 x0에서 두 번 더 부른다(모양 확인과 감싸개).

- 반복당 자기 비용은 scipy와 비슷하다(hybr n = 10: 0.95 µs 대 0.94 µs, n = 100: 29 µs 대 28 µs; lm n = 100: 0.17 ms 대 0.17 ms). 앞의 마일스톤과 달리 scipy의 `root`도 반복 전체가 C(MINPACK의 C 판)이고 콜백만 Python이라 덜어 낼 Python 고리가 없다. n = 100의 시간은 hybr의 QR(qrfac, n³)과 Broyden 갱신(n²)의 같은 계산이다. lm은 m = n이라 LAPACK QR을 먼저 하지 않고 lmder의 QR을 바로 한다(먼저 하면 n = 100에서 0.23 ms였다).
- 작은 n에서 lm은 scipy의 1/1.5–1/2(n = 10: 2.1 µs 대 4.2 µs)다. scipy의 `root(method='lm')`은 `fun`을 호출 수를 세는 Python 함수(`_root_leastsq`의 `_wrapped_fun`)로 한 번 더 감싸고, 그 몫이 자기 비용에 든다.
- 전체 시간은 사용자 함수가 대부분이다. 차분의 n = 100에서 sd가 10% 남짓 느린 것은 `fun` 호출 하나의 고정 비용(새 `sd.ndarray`를 만들어 넘기고 돌려받은 값을 확인) 0.4 µs쯤이 900번 쌓인 것이다.

## lsq_linear, nnls

- 문제: A (m, n)는 표준정규(시드 9), b = Az + e, 경계는 x ≥ 0. `lsq_linear`의 'trf'·'bvls'와 `nnls`를 (m, n) = (100, 10), (1000, 100), (10⁴, 100)에서 쟀다. 세 함수 모두 모든 줄에서 x가 scipy와 비트까지 같다.

| 함수 | m | n | sd ms (1/10) | scipy ms (1/10) | 반복 sd/scipy | status sd/scipy |
|---|---:|---:|---:|---:|---:|---:|
| trf | 100 | 10 | 0.0415 / 0.0452 | 0.354 / 0.358 | 7/7 | 1/1 |
| bvls | 100 | 10 | 0.029 / 0.0291 | 0.0516 / 0.0464 | 2/2 | 1/1 |
| nnls | 100 | 10 | 0.0129 / 0.0117 | 0.0083 / 0.0083 | 6/− | 1/− |
| trf | 1000 | 100 | 5.04 / 5.37 | 5.93 / 6.4 | 8/8 | 1/1 |
| bvls | 1000 | 100 | 6.94 / 7.38 | 7 / 7.41 | 9/9 | 1/1 |
| nnls | 1000 | 100 | 5.48 / 5.59 | 5.41 / 5.38 | 53/− | 1/− |
| trf | 10⁴ | 100 | 35.4 / 36.7 | 36.7 / 38.2 | 13/13 | 2/2 |
| bvls | 10⁴ | 100 | 25.3 / 25.3 | 25.5 / 24.8 | 4/4 | 1/1 |
| nnls | 10⁴ | 100 | 44.8 / 45.4 | 44.4 / 44.9 | 55/− | 1/− |

- 작은 문제의 'trf'는 scipy의 1/9(0.04 ms 대 0.35 ms)다. scipy는 반복마다 `LinearOperator`를 만들고 numpy 연산 수십 개를 Python에서 부른다. 'bvls'는 반복마다의 lstsq(gelsd)가 대부분이라 1/1.7이다.
- 큰 문제는 같은 LAPACK·BLAS 호출(geqp3, orgqr, gelsd, dgemv, dlarf)이 거의 전부라 scipy와 같다. 10스레드의 값도 1스레드와 측정 잡음 안에서 같다(두 라이브러리 모두).
- `nnls` (100, 10)은 scipy보다 4 µs 느리다(13 µs 대 8 µs). 반복은 같은 C 계산이고, 차이는 입력의 확인(유한성, 모양)과 결과 객체(잔차 A x − b와 cost를 계산한다; scipy는 x와 rnorm만 돌려준다)다.
