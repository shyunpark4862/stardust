# O1: least_squares와 approx_fprime의 속도 (scipy 1.18.1과 비교)

`bench/optimize/o1/speed.py`로 쟀다(2026-11-20, Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, Accelerate). 시간은 ms, 여러 번(많아야 5번, 2초를 넘으면 그만) 가운데 가장 빠른 값이다. 원래 출력은 `speed.log`, 값 전체는 `speed.json`이다.

- 문제: MGH의 Rosenbrock(n = 2), Osborne 2(n = 11, m = 65), Brown almost-linear(n = 40)는 잔차를 Python 리스트로 계산하는 같은 코드를 두 라이브러리가 쓴다(sd.ndarray와 numpy 배열로 감쌀 뿐). O0의 y − exp(Xθ)(설계 §5의 크기)는 각 라이브러리의 배열로 썼다(sd는 sd, scipy는 numpy).
- "반복당 자기 비용"은 전체 시간에서 사용자 함수(`fun`, `jac`) 안의 시간을 빼고 반복 수로 나눈 것이다(sd는 `n_iter`, scipy는 'trf'의 `njev`, 'lm'은 `njev`가 있으면 그것, 없으면 `nfev`). 방법 자체의 비용(부분문제, 분해, 콜백을 부르는 고리)이다.
- nfev는 각 라이브러리의 수다. sd는 차분의 호출을 센다(O18). 그래서 2점 차분의 sd nfev는 scipy nfev + n·njev다(예: Rosenbrock 'trf' 61 = 25 + 2·18).
- 1·10스레드의 차이는 측정 잡음 안이다(사용자 함수가 Python이라 병렬은 큰 QR의 LAPACK 안뿐이다). 아래는 1스레드다.

- 모든 줄에서 멈춘 이유가 scipy와 같고, 차분의 호출을 뺀 nfev와 njev도 같다. 'lm' 해석적의 njev가 scipy보다 하나 많은 것은 결과의 야코비안을 마지막 반복점에서 한 번 더 계산하기 때문이다(scipy도 `jac(x)`를 부르지만 njev에 세지 않는다; 반복의 야코비안 수 `n_iter`는 scipy의 njev와 같다).
- 작은 문제에서 반복당 자기 비용은 scipy의 1/4–1/20이다(Rosenbrock 'trf' 3.5 µs 대 47 µs). scipy는 반복마다 Python에서 numpy 연산과 `VectorFunction`의 감싸기를 거치고, 이 라이브러리는 반복 전체가 C++이고 콜백만 Python이다.
- 2점 차분에서 차이가 더 크다(Osborne 2 'trf' 19 µs 대 161 µs): scipy는 차분을 Python의 `approx_derivative`로 만든다.
- 큰 m에서는 m × n의 분해가 대부분이다. 이 라이브러리는 야코비안마다 LAPACK의 Householder QR 하나(블록 알고리즘)만 m 크기로 하고 나머지는 n 크기로 한다. (10⁴, 100)의 'lm'은 반복당 6.5 ms 대 42 ms다(scipy의 MINPACK `qrfac`는 m × n에서 열마다 Householder를 하는 블록이 아닌 C 코드다). (10⁵, 10)은 1.4–1.8배다.
- Brown almost-linear n = 40(m = n)에서만 반복당 비용이 scipy와 비슷하거나 조금 크다(lm 65 µs 대 60 µs, trf 92 µs 대 89 µs). m = n이면 먼저 하는 QR이 덜어 주는 것이 없고(lm은 QR을 두 번 하는 셈이다), trf의 SVD는 [R d; D](2n × n)를 분해한다(scipy의 경계 없는 trf는 n × n). nls의 비트를 지키려고 커널의 계산 순서를 바꾸지 않았다. O6(최적화)의 후보다.
- 전체 시간에는 사용자 함수의 비용도 든다. exp 문제의 사용자 함수는 sd와 numpy로 각각 썼으므로 전체 시간의 비는 두 라이브러리의 배열 연산 속도도 반영한다.

## approx_fprime (scipy의 rosen)

| n | scipy (앞쪽 차분, √ε) ms | sd 앞쪽 차분(`epsilon=2**-26`) ms | sd 정확한 차분(기본) ms | sd 정확한 차분의 호출 수 |
|---:|---:|---:|---:|---:|
| 10 | 0.093 | 0.067 | 0.734 | 101 |
| 100 | 0.716 | 0.630 | 10.2 | 1201 |
| 1000 | 10.7 | 10.1 | 192 | 10001 |

- 앞쪽 차분은 scipy와 비트까지 같고 시간도 비슷하다(호출 n + 1번).
- 기본(정확한 차분)은 변수 하나에 함수를 10–12번 부른다(간격을 고르며 5점 차분을 두세 번). 그만큼 느리고, 상대 정확도는 10⁻¹¹–10⁻¹³이다(앞쪽 차분은 10⁻⁸ 근처).
