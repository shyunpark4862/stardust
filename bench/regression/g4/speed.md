# G4 속도: 강건 회귀 (최적화 8772322 전 측정)

> 이 파일의 수치는 회귀 커널 최적화(커밋 8772322) 전에 잰 값이다. 그 뒤의 수치는 다시 재야 한다(설계 문서의 일부 값은 그 최적화 때 따로 빠르게 잰 것이다).

`bench/regression/g4/speed.py`로 쟀다(2026-11-18, Apple M4 Pro, statsmodels 0.15.0, scipy 1.18.1, R 4.6.2·robustbase 0.99.7). 시간은 ms, 여러 번 가운데 가장 빠른 값이다(가장 큰 문제는 2번·1번; 원래 출력은 `speed.log`). sd의 스레드는 `sd.set_num_threads`, statsmodels 밑의 BLAS는 threadpoolctl로 같은 수로 정했다.

- 데이터: X는 표준정규 (n, k), y = Xβ + 0.5 + 표준정규 잡음에 행의 5%를 +10 옮긴 것(세로 이상점). MM은 행의 20%를 지렛대 무리(X ~ N(5, 0.5²), y ~ N(−10, 1))로 옮겼다.
- statsmodels: `RLM(y, add_constant(X), M=HuberT() / TukeyBiweight()).fit()`의 기본값(목적함수의 절대 변화 ≤ 1e-8, `maxiter` 50). '배'는 statsmodels의 시간 / sd의 시간, '차이'는 계수의 최대 차이 / sd 계수의 최대 절댓값이다.
- MM은 Python 참조가 없어 sd의 시간만 재고, R의 `lmrob`(기본값, 한 번 데운 뒤 한 번)을 참고로 적었다. `lmrob`은 n > 2000이면 묶음 표본 알고리즘(400행 묶음 5개에서 후보를 고른다)이라 모든 행으로 후보를 다듬는 sd와 하는 일이 다르다.
- 기울기: x, y = 2x + 잡음(표준정규), n개 점. '같은 비트'는 scipy의 결과와 비트까지 같은지다(0의 부호 빼고). scipy는 n = 10⁵에서 n × n 배열(80 GB)을 만들 수 없어 재지 않았다.

- statsmodels는 반복마다 `pinv`(SVD)로 가중 최소제곱을 풀고, sd는 정규방정식(덩어리 `dsyrk`)과 마지막의 개선한 QR이다. statsmodels는 스레드 수와 상관없이 같은 시간이었다.
- sd의 반복 수는 뉴턴 걸음을 넣은 수다(목적함수 판정 뒤 2–3번).

## rlm(method='MM')
n > 2000은 robustbase의 큰 n fast-S(G58: 행 400개의 묶음 5개, 병합, 전체 행)다. '작은 n 방식'은 같은 문제를 모든 행의 후보 500개로 푼 것(커널의 `large_n=False`, 벤치마크만 쓴다)이고, 두 방식의 S 척도는 이 문제들에서 12자리까지 같다. lmrob은 기본값이고 '차이'는 sd 계수와의 최대 차이 / sd 계수의 최대 절댓값이다.

- sd는 lmrob보다 1스레드에서 1.4–1.7배, 10스레드에서 2.7–6.2배 빠르다. 남은 시간의 대부분은 모든 행에서의 S 다듬기와 고정점까지의 연마(50여 번)다.
- lmrob의 `scale`은 마지막 고정점 걸음의 값이라(`refine.tol` 1e-7) 자기 잔차의 정확한 M-척도와 10⁻⁶ 정도 다르고, 그래서 sd보다 클 때도 작을 때도 있다. 같은 잔차의 M-척도는 R의 `find_scale`과 sd가 10⁻¹⁰(R의 `scale.tol`) 안에서 같다.

- Theil–Sen은 n = 1,000(5×10⁵쌍)까지 한 배열에 모아 선택하고(1스레드), 10⁴부터는 훑기다(n = 10⁴ 1번, 10⁵ 2–3번; 쌍 하나에 약 3.6 ns, 대부분 나눗셈과 피벗 비교 4×4개).
