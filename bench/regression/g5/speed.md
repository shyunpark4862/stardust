# G5 속도: 분위 회귀

`bench/regression/g5/speed.py`로 쟀다(2026-11-19, Apple M4 Pro, R 4.6.2·quantreg 6.1, statsmodels 0.15.0). 시간은 ms, 여러 번 가운데 가장 빠른 값이다(원래 출력은 `speed.log`). sd의 스레드는 `sd.set_num_threads`, statsmodels 밑의 BLAS는 threadpoolctl로 같은 수로 정했다. R은 한 세션 안에서 같은 자료(double 그대로 읽은 것)를 `system.time`으로 쟀다(시작 시간 빼고; n = 1,000은 100번 부른 시간을 나눴다). R은 1스레드다.

- 자료: X는 표준정규 (n, k), y = Xβ + 0.5 + t₃ 잡음.
- sd iid: `quantreg(y, X, q=0.5, cov_type='iid')`(적합과 희소도의 작은 중앙값 회귀; 표준오차를 내지 않는 R의 `rq.fit`에 가장 가깝다). sd nid: 기본값(q ± h의 적합 둘이 더해진다). R fn·br: `rq.fit(cbind(1, X), y, tau, method)`. R fn + nid: `fn` 적합과 `summary.rq(se = "nid")`(q ± h에서 `fn`으로 두 번 더 적합한다). br은 n = 10⁶에서 재지 않았다(처음부터의 심플렉스라 몇 분 걸린다).
- statsmodels: `QuantReg(y, add_constant(X)).fit(q)`의 기본값(IRLS, `p_tol` 1e-6, `max_iter` 1000; 표준오차도 이 안에서 계산한다). '목적함수 초과'는 statsmodels의 Σρ_q(r)을 sd의 값으로 나눈 것 − 1이다(sd는 정확한 최솟값).

- sd iid는 R fn보다 (10⁵, 10)에서 1.5배(1스레드)·5.8배(10스레드), (10⁶, 10)에서 1.4배·6.4배 빠르고, (10³, 5)에서는 같다(0.48 ms와 0.52 ms). R br보다는 (10⁵, 10)에서 50배·190배 빠르다. 기본 표준오차를 붙인 시간(sd nid / R fn + nid)은 2.4–2.5배·8.2–9.3배다.
- 내부점법의 반복은 R fn과 거의 같고(11–12번과 13–16번), 시간의 대부분이다. 그 뒤의 피벗(교차 뒤 5번, 14번)은 정확한 꼭짓점과 증명서를 위한 것이다. R fn의 계수는 내부점법의 근사다(정확도 표).
- statsmodels는 sd iid보다 (10⁵, 10)에서 2.5배·9.4배, (10⁶, 10)에서 1.5배·6.7배 느리고, 목적함수가 10⁻¹⁰–10⁻⁹ 크다. statsmodels의 시간은 스레드 수와 상관없었다.
