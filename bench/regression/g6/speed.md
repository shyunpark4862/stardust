# G6 속도: 비선형 최소제곱

`bench/regression/g6/speed.py`로 쟀다(2026-11-19, Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, R 4.6.2). 시간은 ms, 여러 번 가운데 가장 빠른 값이다(원래 출력은 `speed.log`).

- 모형(x는 [0.01, 5]의 균등, 잡음은 신호 범위의 2%인 정규, p0는 참값의 1.1배(가우스의 중심은 +0.05)): p = 2 a·exp(−bx), p = 4 네 모수 로지스틱 d + (a − d)/(1 + (x/c)^b), p = 10 가우스 다섯 개의 합 Σ a_k exp(−((x − c_k)/0.4)²).
- sd: `nls(f, x, y, p0=...)`(차분)를 1·10스레드로, 해석적 `jac`은 10스레드로. 스레드는 모형 안의 sd 연산과 QR에만 들어간다. sd nfev 칸의 괄호는 반복 수와 다듬기의 가우스–뉴턴 걸음 수다.
- scipy: `curve_fit(f, x, y, p0)`(MINPACK lmdif, 2점 차분, numpy 모형)과 `jac=`. R: 한 세션 안에서 `nls(formula, start)`의 기본값을 `system.time`으로 쟀다(n = 100은 100번, 10⁴은 10번 부른 시간을 나눴다). R의 `numericDeriv`는 야코비안마다 p번 f를 부르지만 nls가 세지 않으므로 반복 수를 적었다.
- 마지막 열은 sd와 scipy의 계수의 상대 차이(scipy의 멈춤 정밀도)다.

- 차분일 때 sd는 f를 scipy보다 5–7배 많이 부른다: 해의 정확한 야코비안(모수마다 간격을 한 번 고르는 약 16p번, 그 뒤 야코비안마다 4p번)과 다듬기의 가우스–뉴턴 걸음(보통 2–4번)이다. 그래서 1스레드 시간이 scipy의 4–13배다(n = 10⁶, p = 10에서 13.3 s와 0.99 s). 모형의 sd 연산이 나뉘는 큰 n에서는 10스레드가 그 차이를 줄인다(n = 10⁶에서 scipy 시간의 1.4배(p = 2), 0.87배(p = 4), 2.0배(p = 10)).
- 해석적 `jac`이면 다듬기의 비용이 거의 없다(nfev 7–13, scipy jac은 4–6): n = 10⁶에서 sd jac(10스레드)은 p = 2에서 scipy jac과 같고(53.8 ms와 52.8 ms) p = 4·10에서 1.4–1.5배 빠르며(99.6과 146, 353과 499), n = 100에서는 Python 쪽의 고정 비용 때문에 1.9–2.4배 느리다(0.09–0.50 ms).
- R nls는 n = 10⁴까지 sd 차분과 비슷하거나 빠르고(p = 10에서 12.6 ms와 130 ms), n = 10⁶에서는 sd 10스레드가 p = 2·4에서 2.1배 빠르고 p = 10에서 1.5배 느리다.
- 정확도는 `accuracy.md`: sd의 계수는 해에 반올림 수준(`jac`) 또는 차분의 정확도 수준(10⁻¹³–10⁻¹⁰)이고, scipy·R은 멈춤 판정의 정밀도(10⁻⁷–10⁻¹⁰)다.
