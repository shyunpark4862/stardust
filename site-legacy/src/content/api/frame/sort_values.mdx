## 한눈에 보기

`sort_values`는 값의 크기순으로 행을 다시 늘어놓아요. 엑셀에서 열 하나를 골라 "오름차순 정렬"을 누르는 것과 같아요. 표의 한 행은 하나의 기록(과일 하나의 이름과 가격)이라서, 정렬할 때 행이 통째로 함께 움직여요. 이름과 가격의 짝이 흩어지지 않아요.

이럴 때 써요.

- 가장 비싼 상품, 가장 많이 팔린 상품부터 보고 싶을 때
- 점수 순위표를 만들 때
- 보고서에 낼 표를 이름순, 날짜순으로 정리할 때

DataFrame은 어느 컬럼을 기준으로 정렬할지 첫 인자로 알려 줘요.

```python
>>> import stardust as sd
>>> df = sd.frame.DataFrame({"fruit": ["pear", "apple", "kiwi", "apple", "pear"],
...                          "price": [800, 1200, 500, 1000, 800]})
>>> df
   fruit  price
0   pear    800
1  apple   1200
2   kiwi    500
3  apple   1000
4   pear    800
>>> df.sort_values("price")
   fruit  price
2   kiwi    500
0   pear    800
4   pear    800
3  apple   1000
1  apple   1200
```

<Fig caption="price가 작은 행부터 다시 늘어놓아요. 행이 통째로 움직이고, 왼쪽의 라벨도 행을 따라가요.">
  <FrameFig name="df" columns={['fruit', 'price']} dtypes={['string', 'int64']}
    data={[['pear', 800], ['apple', 1200], ['kiwi', 500], ['apple', 1000], ['pear', 800]]}
    colTones={['', 'a']} />
  <Op note='sort_values("price")'>→</Op>
  <FrameFig columns={['fruit', 'price']} index={[2, 0, 4, 3, 1]}
    data={[['kiwi', 500], ['pear', 800], ['pear', 800], ['apple', 1000], ['apple', 1200]]}
    colTones={['', 'a']} />
</Fig>

결과는 새 DataFrame이에요. 원래 `df`는 그대로예요. 정렬한 표를 계속 쓰려면 변수에 담아요.

Series는 값이 한 줄뿐이라 기준을 고를 필요가 없어요. 인자 없이 불러요.

```python
>>> s = df["price"]
>>> s.sort_values()
2     500
0     800
4     800
3    1000
1    1200
Name: price, dtype: int64
```

## 라벨은 행을 따라가요

위 결과의 왼쪽 라벨이 `2, 0, 4, 3, 1`이에요. 행이 움직일 때 라벨도 함께 움직였기 때문이에요. 그래서 정렬한 뒤에도 "이 행은 원래 몇 번 행이었나"를 알 수 있어요([라벨이 무엇인지](/api/frame/alignment/)).

```python
>>> df.sort_values("price").index
Index([2, 0, 4, 3, 1], dtype=int64)
```

이 점은 정렬한 결과에서 행을 꺼낼 때 중요해요. `.loc`은 라벨로, `.iloc`은 위치로 골라요. 정렬한 뒤에는 둘이 가리키는 행이 달라요([loc과 iloc](/api/frame/loc-iloc/)).

```python
>>> top = df.sort_values("price", descending=True)
>>> top["fruit"].iloc[0]
'apple'
>>> top["fruit"].loc[0]
'pear'
```

`.iloc[0]`은 정렬한 결과의 첫 행(가장 비싼 `apple`)이고, `.loc[0]`은 라벨이 `0`인 행, 곧 원래 표의 첫 행(`pear`)이에요. "1등"을 꺼내려면 `.iloc`을 써요.

### `ignore_index`: 라벨을 새로 붙이기

원래 순서가 필요 없고 순위만 중요하다면 `ignore_index=True`를 줘요. 원래 라벨을 버리고 `0, 1, 2, …`를 새로 붙여요. 결과의 Index는 RangeIndex예요.

```python
>>> ranked = df.sort_values("price", descending=True, ignore_index=True)
>>> ranked
   fruit  price
0  apple   1200
1  apple   1000
2   pear    800
3   pear    800
4   kiwi    500
>>> ranked.index
RangeIndex(start=0, stop=5, step=1)
```

이렇게 하면 라벨과 위치가 같아서 `.loc[0]`도 1등이에요.

## `descending`: 큰 값부터

기본은 작은 값부터(오름차순)예요. `descending=True`를 주면 큰 값부터(내림차순) 늘어놓아요. 배열의 [`sd.sort`](/api/array/sort/)와 같은 이름, 같은 뜻이에요.

```python
>>> df.sort_values("price", descending=True)
   fruit  price
1  apple   1200
3  apple   1000
0   pear    800
4   pear    800
2   kiwi    500
```

문자열은 글자의 코드 순서(코드포인트 순서)로 비교해요. 영어 소문자끼리는 사전순과 같아요. 대문자는 모든 소문자보다 앞에 와요(`"Z"`가 `"a"`보다 앞). bool은 `False`가 `True`보다 작아요.

## 같은 값의 순서: 언제나 안정 정렬

위 결과에서 `pear`의 두 행은 가격이 800으로 같아요. 이렇게 기준 값이 같은 행은 원래 순서(라벨 `0`이 `4`보다 먼저)를 그대로 지켜요. 이런 정렬을 **안정 정렬**(stable sort)이라고 해요.

오름차순이든 내림차순이든 똑같아요. 그래서 내림차순 결과는 오름차순 결과를 거꾸로 뒤집은 것과 달라요. 뒤집으면 같은 값끼리의 순서도 뒤집히지만, `descending=True`는 그 순서를 지켜요.

이 성질 덕분에 결과가 언제나 하나로 정해져요. 같은 데이터를 정렬하면 몇 번을 하든, 스레드 수가 몇이든 같은 결과가 나와요.

`stable=False`도 받지만 결과는 같아요. 배열의 `sd.sort`와 인자를 맞추려고 받아요. `stable=False`는 "안정 정렬이 아니어도 된다"는 허락일 뿐이라, 정렬은 그래도 안정 정렬이에요.

```python
>>> df.sort_values("price", stable=False).index
Index([2, 0, 4, 3, 1], dtype=int64)
```

## 여러 컬럼으로 정렬하기

`by`에 컬럼 이름의 리스트를 주면 앞의 컬럼부터 차례로 비교해요. 첫 컬럼이 같은 행끼리만 둘째 컬럼으로 순서를 정해요. 전화번호부가 성으로 먼저 정렬하고, 성이 같으면 이름으로 정렬하는 것과 같아요.

```python
>>> df.sort_values(["fruit", "price"])
   fruit  price
3  apple   1000
1  apple   1200
2   kiwi    500
0   pear    800
4   pear    800
```

`fruit`가 이름순으로 정렬되고, 같은 `apple`끼리는 `price`가 작은 행이 먼저 와요.

`descending`에 키마다 하나씩 리스트를 주면 방향을 따로 정할 수 있어요. 아래는 과일을 이름순(오름차순)으로, 같은 과일 안에서는 비싼 것부터(내림차순) 늘어놓아요.

```python
>>> df.sort_values(["fruit", "price"], descending=[False, True])
   fruit  price
1  apple   1200
3  apple   1000
2   kiwi    500
0   pear    800
4   pear    800
```

<Fig caption="첫 키 fruit로 묶음이 정해지고, 같은 과일 안에서는 둘째 키 price를 내림차순으로 늘어놓아요.">
  <FrameFig name="df" columns={['fruit', 'price']}
    data={[['pear', 800], ['apple', 1200], ['kiwi', 500], ['apple', 1000], ['pear', 800]]}
    rowTones={['3', '1', '2', '1', '3']} />
  <Op note='descending=[False, True]'>→</Op>
  <FrameFig columns={['fruit', 'price']} index={[1, 3, 2, 0, 4]}
    data={[['apple', 1200], ['apple', 1000], ['kiwi', 500], ['pear', 800], ['pear', 800]]}
    rowTones={['1', '1', '2', '3', '3']} />
</Fig>

리스트의 길이는 키 수와 같아야 해요. 값 하나(`True`나 `False`)를 주면 모든 키에 같이 적용해요.

```python
>>> df.sort_values(["fruit", "price"], descending=[True])
Traceback (most recent call last):
    ...
ValueError: sort_values(): 'descending' has 1 values for 2 sort keys
```

## NaN과 NA는 어디에 오나요

데이터프레임에는 "값이 없음"을 나타내는 `NA`와, 실수의 특별한 값 NaN(숫자가 아님)이 따로 있어요. 정렬에서도 둘을 다르게 다뤄요([NA와 NaN](/api/frame/na/)).

- NaN은 값이에요. 다른 수와 크기를 비교할 수 없지만 정렬하려면 어딘가 놓아야 하므로, +inf(무한대)보다도 큰 값으로 쳐요. 오름차순이면 inf 뒤, 내림차순이면 맨 앞이에요. 배열의 `sd.sort`와 같은 규칙이에요.
- NA는 값이 없다는 표시예요. 크다 작다를 말할 수 없으니 방향과 상관없이 `na_position`이 정한 자리에 와요. 기본은 `"last"`(맨 뒤)예요.

```python
>>> t = sd.frame.Series([3.0, sd.frame.NA, sd.nan, 1.0, sd.inf], name="t")
>>> t.sort_values()
3    1.0
0    3.0
4    inf
2    NaN
1   <NA>
Name: t, dtype: float64
>>> t.sort_values(descending=True)
2    NaN
4    inf
0    3.0
3    1.0
1   <NA>
Name: t, dtype: float64
>>> t.sort_values(na_position="first")
1   <NA>
3    1.0
0    3.0
4    inf
2    NaN
Name: t, dtype: float64
```

| | 오름차순 | 내림차순 |
|---|---|---|
| NaN | 뒤쪽(inf 다음) | 맨 앞 |
| `NA` | `na_position` (기본 맨 뒤) | `na_position` (기본 맨 뒤) |

<Callout type="warn" title="내림차순의 첫 행이 NaN일 수 있어요">
  `descending=True`로 정렬해서 첫 행을 "가장 큰 값"으로 쓸 때, 컬럼에 NaN이 있으면 NaN이 먼저 나와요. NaN이 섞일 수 있는 데이터라면 `s.isnan()`으로 먼저 걸러 내세요([결측값 찾기](/api/frame/isna/)).
</Callout>

### 키마다 다른 `na_position`

여러 키로 정렬할 때 `na_position`도 `descending`처럼 키마다 하나씩 리스트로 줄 수 있어요. 아래는 반 이름이 없는 학생을 맨 앞에, 점수가 없는 학생을 반 안에서 맨 뒤에 둬요.

```python
>>> st = sd.frame.DataFrame({"cls": ["A", None, "B", "A", None],
...                          "score": [90, 70, None, None, 85]})
>>> st.sort_values(["cls", "score"], na_position=["first", "last"])
    cls  score
1  <NA>     70
4  <NA>     85
0     A     90
3     A   <NA>
2     B   <NA>
```

`None`은 DataFrame을 만들 때 `NA`가 돼요.

방향과 NA 자리를 모두 키마다 정할 수도 있어요.

```python
>>> st.sort_values(["cls", "score"], descending=[False, True], na_position=["last", "first"])
    cls  score
3     A   <NA>
0     A     90
2     B   <NA>
4  <NA>     85
1  <NA>     70
```

## 조심할 점

### 기준 컬럼은 이름 없이 넘겨요

`by`는 첫 인자로, 이름을 붙이지 않고 넘겨요. 나머지 옵션은 모두 이름을 붙여요([데이터프레임의 기본](/api/frame/basics/)).

```python
>>> df.sort_values(by="price")
Traceback (most recent call last):
    ...
TypeError: DataFrame.sort_values() got some positional-only arguments passed as keyword arguments: 'by'
```

Series에는 `by`가 없어요. 값이 한 줄뿐이라 고를 것이 없어요.

```python
>>> s.sort_values("price")
Traceback (most recent call last):
    ...
TypeError: Series.sort_values() takes 1 positional argument but 2 were given
```

### 없는 컬럼, 빈 리스트

```python
>>> df.sort_values("qty")
Traceback (most recent call last):
    ...
KeyError: "sort_values(): no column 'qty'"
>>> df.sort_values([])
Traceback (most recent call last):
    ...
ValueError: sort_values(): 'by' must name at least one column
```

### 옵션의 타입

`descending`, `stable`, `ignore_index`에는 `True`나 `False`만 써요. `1`이나 `None`은 `TypeError`예요. `na_position`은 `"first"`나 `"last"`만 받아요.

```python
>>> df.sort_values("price", descending=1)
Traceback (most recent call last):
    ...
TypeError: sort_values(): 'descending' must be True or False, not int
>>> df.sort_values("price", na_position="middle")
Traceback (most recent call last):
    ...
ValueError: sort_values(): 'na_position' must be 'first' or 'last', not 'middle'
```

방향의 이름은 `descending`이에요. `ascending`은 없어요.

```python
>>> s.sort_values(ascending=False)
Traceback (most recent call last):
    ...
TypeError: Series.sort_values() got an unexpected keyword argument 'ascending'. Did you mean 'descending'?
```

### 제자리 정렬은 없어요

`sort_values`는 언제나 새 객체를 돌려주고, 원래 객체를 바꾸는 `inplace` 옵션은 없어요. 정렬한 결과를 계속 쓰려면 `df = df.sort_values("price")`처럼 다시 받아요.

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 다른 점 |
|---|---|---|
| 값으로 행을 정렬 | `sort_values` | 기준 컬럼의 값으로 행을 늘어놓아요. |
| 라벨로 행을 정렬 | [`sort_index`](/api/frame/sort_index/) | 왼쪽의 라벨 순서로 늘어놓아요. `sort_values`로 섞은 순서를 원래대로 되돌릴 때도 써요. |
| 배열의 값을 정렬 | [`sd.sort`](/api/array/sort/) | 라벨이 없는 배열이에요. NA가 없어서 `na_position`도 없어요. 순서 규칙(NaN은 inf 뒤, `descending`)은 같아요. |
| 고유값을 정렬된 순서로 | [`unique_values`](/api/frame/unique_values/) | 같은 값은 하나만 남겨요. |
| 많이 나온 값부터 | [`value_counts`](/api/frame/value_counts/) | 값마다 개수를 세어 개수의 내림차순으로 줘요. |
| 그룹을 키 순서로 | [`groupby`](/api/frame/groupby/) | `sort=True`(기본)면 그룹이 키의 오름차순으로 나와요. 정렬 규칙은 같아요. |
| 앞의 몇 행만 | [`head`](/api/frame/head-tail/) | 정렬한 뒤 `head(3)`로 상위 3개를 볼 수 있어요. |

## pandas를 아는 분께

- 방향은 `ascending=True` 대신 `descending=False`예요. 리스트로 키마다 줄 수 있는 것은 같아요.
- `by`는 위치로만 받아요. `df.sort_values(by="a")`는 `TypeError`예요.
- NaN은 결측이 아니라 값이에요. pandas는 NaN을 결측으로 보고 `na_position`이 정한 자리에 두지만, 여기서는 +inf 뒤(내림차순이면 맨 앞)에 와요. `na_position`은 `NA`에만 적용돼요.
- `na_position`도 키마다 리스트로 줄 수 있어요. pandas 3.1.1에서는 `ValueError`예요.
- 언제나 안정 정렬이에요. pandas의 기본 `kind="quicksort"`는 키가 하나일 때 같은 값의 순서를 보장하지 않아요(실제로 순서가 섞여요). `kind`, `key`, `inplace`, `axis`는 없어요.
