## 한눈에 보기

길이 $n$인 줄 $h$가 $h_{n-j} = \overline{h_j}$를 지키면 **에르미트 신호**라고 해요. 실수 신호의 스펙트럼이 켤레 대칭인 것처럼, 에르미트 신호의 스펙트럼은 실수예요. `hfft`는 그런 신호를 앞쪽 절반만 받아 실수 스펙트럼을 돌려주고, `ihfft`는 실수 스펙트럼에서 신호의 앞쪽 절반을 되살려요.

```python
>>> import stardust as sd
>>> half = sd.asarray([1.0, 2.0, 3.0])
>>> sd.fft.hfft(half)
array([ 8.0, -2.0,  0.0, -2.0], dtype=float64)
>>> sd.fft.fft(sd.asarray([1.0, 2.0, 3.0, 2.0]))
array([ (8+0j), (-2+0j),      0j, (-2-0j)], dtype=complex128)
>>> sd.fft.ihfft(sd.fft.hfft(half))
array([(1-0j), (2-0j), (3-0j)], dtype=complex128)
```

`[1, 2, 3]`은 신호 `[1, 2, 3, 2]`의 앞쪽 절반이에요. 뒤의 2는 칸 1의 켤레라서 적지 않았어요. `hfft`의 결과는 그 신호를 [`fft`](/api/fft/fft/)한 값과 같고, 처음부터 실수(float64)예요.

## 무엇을 계산하나요

[`rfft`](/api/fft/rfft/)와 [`irfft`](/api/fft/rfft/)는 신호가 실수이고 스펙트럼이 켤레 대칭이에요. `hfft`와 `ihfft`는 그 자리를 맞바꿔서, 신호가 켤레 대칭이고 스펙트럼이 실수예요.

| | 신호 쪽 | 스펙트럼 쪽 | 절반만 저장하는 쪽 |
|---|---|---|---|
| `rfft`, `irfft` | 실수 | 켤레 대칭 | 스펙트럼 |
| `hfft`, `ihfft` | 켤레 대칭 | 실수 | 신호 |

`hfft`는 앞쪽 절반 $h_0, \dots, h_{\lfloor n/2 \rfloor}$를 $h_{n-j} = \overline{h_j}$로 펴서 길이 $n$의 신호를 만든 뒤 순방향 변환을 해요(`norm='backward'`일 때).

$$
y_k = \sum_{j=0}^{n-1} h_j \, e^{-2\pi i\, jk/n} \in \mathbb{R}
$$

`ihfft`는 실수 줄 $y$의 역변환 가운데 앞쪽 $\lfloor n/2 \rfloor + 1$칸이에요.

$$
h_j = \frac{1}{n} \sum_{k=0}^{n-1} y_k \, e^{+2\pi i\, jk/n}, \qquad j = 0, \dots, \lfloor n/2 \rfloor
$$

식으로는 `hfft(h, n)`이 `irfft(conj(h), n)`에 $n$을 곱한 것이고, `ihfft(y)`가 `conj(rfft(y))`를 $n$으로 나눈 것이에요. 실제로도 그 계산과 같은 비트예요.

```python
>>> h = sd.asarray([1.0, 2j, 3.0])
>>> sd.fft.hfft(h, n=5)
array([                 7.0, -0.04987590106907058,    5.205242975419577,
         0.5029609570797922,   -7.658328031430299], dtype=float64)
>>> sd.fft.irfft(sd.conj(h), n=5) * 5
array([   7.000000000000001, -0.04987590106907059,    5.205242975419577,
         0.5029609570797922,   -7.658328031430299], dtype=float64)
```

## 어디에 쓰나요

에르미트 신호는 실수 줄의 **자기상관**에서 자주 나와요. 실수 줄 $r$을 $j$칸 밀어 자신과 곱해 더한 값(순환 자기상관)은 $j$와 $n-j$에서 같아서 켤레 대칭(실수이고 대칭)이고, 그 스펙트럼은 $r$의 스펙트럼의 절댓값 제곱(파워 스펙트럼)이에요. `hfft`는 자기상관의 앞쪽 절반에서 파워 스펙트럼을 바로 실수로 줘요.

```python
>>> r = sd.asarray([1.0, 2.0, 0.0, -1.0, 3.0, 1.0])
>>> power = sd.abs(sd.fft.fft(r)) ** 2
>>> acf = sd.fft.irfft(sd.abs(sd.fft.rfft(r)) ** 2, n=6)
>>> acf
array([             16.0,               3.0,               2.0,
                    10.0,               2.0, 2.999999999999999], dtype=float64)
>>> float(sd.max(sd.abs(sd.fft.hfft(acf[:4], n=6) - power))) < 1e-12
True
```

`acf`는 칸 1과 칸 5, 칸 2와 칸 4가 반올림 끝자리 안에서 같아요. 앞쪽 네 칸만 `hfft`에 주면 여섯 칸의 파워 스펙트럼이 반올림 크기의 차이 안에서 나와요.

반대로 `ihfft`는 실수 스펙트럼(예를 들어 파워 스펙트럼)에서 에르미트 신호(자기상관)의 앞쪽 절반을 줘요.

```python
>>> float(sd.max(sd.abs(sd.fft.ihfft(power) - acf[:4]))) < 1e-12
True
```

## 길이 `n`

`hfft`의 `n`은 **펴진 신호와 결과의 길이**예요. 기본값은 $2(m-1)$이에요($m$은 입력의 길이). 앞쪽 절반만 보고는 펴진 신호의 길이를 알 수 없어서(길이 4와 5의 신호는 앞쪽 절반이 모두 3칸이에요), 홀수 길이는 `n`으로 줘야 해요.

```python
>>> sd.fft.hfft(half).shape
(4,)
>>> sd.fft.hfft(half, n=5).shape
(5,)
>>> sd.fft.hfft(half, n=5)
array([               11.0,  -2.618033988749895, -0.3819660112501051,
       -0.3819660112501051,  -2.618033988749895], dtype=float64)
```

`hfft`는 입력에서 $\lfloor n/2 \rfloor + 1$칸만 써요. 입력이 더 길면 뒤를 버리고, 짧으면 0을 채워요. 칸 0과(짝수 $n$이면) 칸 $n/2$의 허수부는 읽지 않아요. 에르미트 신호라면 그 두 칸은 자기 자신과 짝이라 실수여야 하기 때문이에요.

`ihfft`의 `n`은 [`rfft`](/api/fft/rfft/)와 같아요. 입력을 `n`개로 자르거나 끝에 0을 채운 뒤 변환하고, 결과는 $\lfloor n/2 \rfloor + 1$칸이에요.

```python
>>> sd.fft.ihfft(sd.asarray([8.0, -2.0, 0.0, -2.0]), n=2)
array([(3-0j), (5-0j)], dtype=complex128)
>>> sd.fft.ihfft(sd.asarray([8.0, -2.0, 0.0, -2.0]), n=6).shape
(4,)
```

## 축 `axis`

2차원 이상의 배열은 `axis`를 따라 놓인 줄마다 따로 변환해요. 결과에서 `axis`의 길이만 바뀌어요. 두 축 이상을 함께 변환하려면 [`hfft2`, `hfftn`](/api/fft/hfftn/)을 써요.

```python
>>> H = sd.asarray([[1.0, 2.0, 3.0],
...                 [4.0, 0.0, 1.0]])
>>> sd.fft.hfft(H)
array([[ 8.0, -2.0,  0.0, -2.0],
       [ 5.0,  3.0,  5.0,  3.0]], dtype=float64)
>>> sd.fft.hfft(H, axis=0, n=2)
array([[ 5.0,  2.0,  4.0],
       [-3.0,  2.0,  2.0]], dtype=float64)
```

## 정규화 `norm`

`hfft`는 **역방향 쪽으로** 세어져요. 신호에서 스펙트럼으로 가는 변환이지만, `irfft`와 같은 계산이라서 정규화의 짝도 `irfft`를 따라요.

| `norm` | `hfft`에 곱하는 수 | `ihfft`에 곱하는 수 |
|---|:---:|:---:|
| `'backward'`(기본값) | $1$ | $1/n$ |
| `'ortho'` | $1/\sqrt{n}$ | $1/\sqrt{n}$ |
| `'forward'` | $1/n$ | $1$ |

$n$은 실수 쪽의 길이예요. 기본값에서 `hfft`는 나누지 않아서 결과가 `fft`와 같은 크기이고, `ihfft`가 $n$으로 나눠요. 같은 `norm`으로 짝지으면 원래 값이 돌아와요.

```python
>>> sd.fft.hfft(half, norm='forward')
array([ 2.0, -0.5,  0.0, -0.5], dtype=float64)
>>> sd.fft.ihfft(sd.fft.hfft(half, norm='ortho'), norm='ortho')
array([(1-0j), (2-0j), (3-0j)], dtype=complex128)
```

## 경계의 값

| 입력 | 결과 |
|---|---|
| `hfft`에 길이 1이고 `n` 없음 | `ValueError`(기본 길이 $2(1-1)$이 0이에요). `n`을 주면 돼요 |
| `ihfft`에 길이 1 | 그 값 하나 |
| 변환할 축의 길이가 0 | `ValueError`. `hfft`에 `n`을 주면 0을 채운 입력으로 봐요 |
| 다른 축의 길이가 0 | 빈 결과 |
| 줄에 NaN이나 inf | 그 줄의 결과 칸에 NaN이나 inf가 섞여요. 어느 칸인지는 약속하지 않아요 |
| `hfft`가 읽지 않는 자리(칸 0과 칸 $n/2$의 허수부, 쓰지 않는 뒤쪽 칸)의 NaN | 결과에 들어가지 않아요 |

```python
>>> sd.fft.hfft(sd.asarray([5.0]))
Traceback (most recent call last):
    ...
ValueError: hfft(): the default 'n' = 2 (m - 1) is 0 for an axis of length m = 1; give 'n'
>>> sd.fft.hfft(sd.asarray([5.0]), n=1)
array([5.0], dtype=float64)
>>> sd.fft.ihfft(sd.asarray([5.0]))
array([(5-0j)], dtype=complex128)
>>> sd.fft.hfft(sd.asarray([complex(1.0, sd.nan), 2.0, 3.0, sd.nan]), n=4)
array([ 8.0, -2.0,  0.0, -2.0], dtype=float64)
```

마지막 예에서 NaN은 칸 0의 허수부와 쓰지 않는 칸 3에만 있어서 결과가 깨끗해요.

`ihfft`의 칸 0의 허수부는 −0이에요. 켤레를 취하면서 +0의 부호가 바뀌기 때문이에요. 값으로는 0과 같아요.

```python
>>> sd.fft.ihfft(sd.asarray([8.0, -2.0, 0.0, -2.0]))
array([(1-0j), (2-0j), (3-0j)], dtype=complex128)
```

## 정확도와 같은 결과

`hfft`는 [`irfft`](/api/fft/rfft/)의, `ihfft`는 [`rfft`](/api/fft/rfft/)의 계산을 그대로 쓰므로 정확도의 약속도 같아요. 줄 전체의 노름 상대오차로 약속하고, 칸 하나의 상대오차는 약속하지 않아요. 잰 값은 [`rfft`](/api/fft/rfft/)에 있어요.

같은 입력이면 스레드 수, 배치, 배열이 메모리에 놓인 모양과 상관없이 같은 비트예요. 반올림까지 정확히 지키는 관계는 이래요. 아래에서 `norm`의 방향을 바꾼다는 것은 `'backward'`와 `'forward'`를 맞바꾸는 것이에요(`'ortho'`는 그대로).

- `ihfft(x, norm=a)`는 `conj(rfft(x, norm=`방향을 바꾼 `a))`와 같은 비트예요.
- `hfft(x, n, norm=a)`는 `irfft(conj(x), n, norm=`방향을 바꾼 `a)`와 같은 비트예요.

```python
>>> y = sd.random.default_rng(5).random(1000)
>>> bool(sd.all(sd.fft.ihfft(y) == sd.conj(sd.fft.rfft(y, norm='forward'))))
True
>>> c = sd.fft.ihfft(y)
>>> bool(sd.all(sd.fft.hfft(c, n=1000) == sd.fft.irfft(sd.conj(c), n=1000, norm='forward')))
True
```

## numpy·scipy를 아는 분께

- `numpy.fft.hfft`·`ihfft`, `scipy.fft.hfft`·`ihfft`와 정의가 같아요. `n`, `axis`, `norm`은 키워드로만 받아요.
- 정규화를 거꾸로 세는 것(`'backward'`에서 `hfft`가 나누지 않는 것)은 numpy와 같아요.
- `ihfft`의 칸 0 허수부는 −0이에요. numpy와 같고, scipy는 +0이에요.
- `hfft(x, n=0)`은 `ValueError`예요. 기본 `n`이 0이 되는 길이 1의 입력도 `ValueError`이고, 메시지가 `n`을 주라고 알려 줘요.
- `ihfft`에 complex128을 주면 `TypeError`예요. numpy, scipy와 같아요.
- `norm=None`, `out`, `workers`, `overwrite_x`, `plan`이 없어요. 반올림 크기의 끝자리는 numpy, scipy와 다를 수 있어요.
