## 한눈에 보기

`sd.stats`는 scipy.stats의 일부를 다시 만든 영역이에요. 들어 있는 것은 네 묶음이에요.

- 단변량 분포 31개: 연속 21개(정규, t, 카이제곱, F, 감마, 베타, 지수, 로그정규, 균등, 코시, 라플라스, 베이불, 로지스틱, Gumbel, 일반화 극값, 파레토, 레일리, 역감마, 비중심 카이제곱·t·F)와 이산 10개(이항, 포아송, 기하, 음이항, 초기하, 베르누이, 이산 균등, 베타이항, 로그 급수, Zipf).
- 다변량 분포 4개: 다변량 정규, 다변량 t, 다항, 디리클레.
- 행렬 분포 3개: Wishart, 역Wishart, 행렬 정규.
- 기술통계 함수 11개: `describe`, `skew`, `kurtosis`, `moment`, `zscore`, `rankdata`, `sem`, `iqr`, `mode`, `entropy`, `differential_entropy`.

이 영역의 뼈대는 다섯 가지예요.

1. **분포는 Python 객체, 계산은 C++ 원소별 함수예요.** `sd.stats.Gamma(a=2.5)`는 매개변수만 담은 얇은 객체이고, `X.cdf(x)`는 C++ 함수 `gamma_cdf(a, scale, x)` 하나를 불러요. 단변량 분포 31개 × 메서드 20개 = 620개의 원소별 함수를 손으로 쓰지 않고, 분포 구조체 하나에서 템플릿 `DistOp<D, M>`이 만들어요([원소별 엔진과 빠른 경로](/internals/stats/engine/)).
2. **special 위에 서 있지만 감싸기만 하지 않아요.** 누적분포의 대부분은 [sd.special](/internals/special/overview/)의 불완전 감마·베타와 정규분포 함수예요. 다만 그 함수에 넣을 인자 $x/\text{scale}$, $(x-\mu)/\sigma$를 float64로 반올림하면 꼬리에서 자릿수를 잃어서, stats는 그 인자를 double-double로 만들어 1차 보정까지 더해요.
3. **정확도는 계약으로 약속해요.** 분포마다 정한 보장 영역 안에서 Arb(구간 산술)로 만든 참값과의 상대오차가 $10^{-14}$ 이하예요. `ccdf`와 log 메서드는 꼬리에서도 상대 정확도예요.
4. **값 때문에 실패하지 않고, 정해진 시간 안에 끝나요.** 매개변수가 정의역 밖이면 그 원소만 NaN이고, 에러는 내지 않아요. 모든 합·탐색·반복에는 상한이 있고, 상한에 닿으면 중간값 대신 NaN을 내요.
5. **같은 입력이면 같은 비트예요.** 같은 기계, 같은 스레드 수면 실행마다 같은 비트예요. 단변량 분포의 메서드는 원소별이라 배열의 레이아웃과 원소의 위치에도 의존하지 않고, 지금은 스레드 수와도 상관없어요(약속은 아니에요). 표본도 같은 `rng` 상태에서 같은 값이에요.

```python
>>> X = sd.stats.Gamma(a=2.5)
>>> X
Gamma(a=2.5, scale=1.0)
>>> x = sd.asarray([0.5, 2.5, 10.0, 50.0])
>>> X.cdf(x)
array([0.03743422675270364,   0.584119813004492,  0.9987502694369687,
                       1.0], dtype=float64)
>>> X.ccdf(x)
array([   0.9625657732472963,   0.41588018699550794, 0.0012497305630313755,
        5.28514836094324e-20], dtype=float64)
>>> sd._core.stats.gamma_cdf(2.5, 1.0, x)
array([0.03743422675270364,   0.584119813004492,  0.9987502694369687,
                       1.0], dtype=float64)
>>> X.cdf(2.5) == X.cdf(x)[1]
True
```

마지막 원소에서 `cdf`는 1.0으로 반올림되지만 `ccdf`는 $1 - \text{cdf}$가 아니라 위꼬리를 직접 계산해서 $5.3 \times 10^{-20}$이 살아 있어요.

- 분포 하나는 구조체 하나예요. 매개변수의 이름과 정의역, 메서드마다의 원소 함수를 정적 함수로 적어요. 바인딩은 `def_continuous<stats::Gamma>(m)` 한 줄로 그 분포의 메서드 20개를 모두 등록해요. 이름은 `<분포>_<메서드>`이고(`gamma_cdf`, `binomial_pmf`), 입력은 (매개변수..., x) 또는 매개변수만이에요.
- Python 클래스에는 이름과 매개변수만 적어요. `Gamma`의 몸체는 `_name = "gamma"`, `_params = ("a", "scale")`과 키워드 전용 생성자뿐이에요. 메서드 20개와 `sample`은 공통 기반 `_Distribution`에 한 번 있고, 클래스를 정의하는 순간(`__init_subclass__`) `_core.stats`에서 그 분포의 함수를 찾아 표로 담아 둬요.
- 의존은 한 방향이에요. `stats/`는 `special/`과 `array/`를 쓰지만 그 반대는 없어요. n항 디스패처와 바인딩 템플릿(`nary_bind.hpp`)은 special과 같은 파일이에요.
- 다변량·행렬·기술통계는 이 틀 밖에 있어요. 원소별 함수가 아니라 배치 단위로 일하는 커널이라 `DistOp`을 거치지 않고, Python 쪽이 매개변수를 (배치, ...) 모양으로 펼쳐 커널을 불러요.

공통 기반에서 메서드 하나는 이런 모양이에요.

```python
# src/stardust/stats/_distribution.py (발췌)
class _Distribution:
    # ...
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if not cls._name:  # the bases ContinuousDistribution and DiscreteDistribution
            return
        ops = {m: getattr(_k, f"{cls._name}_{m}") for m in cls._density + _INPUT_METHODS + _PARAM_METHODS}
        ops["sample"] = getattr(_k, f"{cls._name}_sample")
        ops["sample1"] = getattr(_k, f"{cls._name}_sample1")
        ops["sample1s"] = getattr(_k, f"{cls._name}_sample1s")
        cls._ops = ops
        cls._s1 = staticmethod(ops["sample1s"])  # sample()'s scalar call, one attribute away
        for i, p in enumerate(cls._params):  # read-only attributes (T19)
            setattr(cls, p, _parameter(i, p))
        for m in cls._density + _INPUT_METHODS:
            setattr(cls, m, _fast_input(m, ops[m], len(cls._params), getattr(cls, m)))
        _calls.keyword_init(cls)

    # ...
    def cdf(self, x, /, *, out=None):
        """P(X <= x)."""
        if type(x) is int:
            _int_input(x, "cdf")
        try:
            return self._ops["cdf"](*self._p, x, out=out)
        except _RENAMED as e:
            raise _renamed(e, "cdf", "x", x) from None
```

위의 `cdf`는 기반 클래스의 메서드예요. 클래스를 만들 때 `_fast_input`이 입력 메서드마다 그 앞에 짧은 길을 하나 더 만들어 붙여요. 매개변수 개수에 맞춘 함수를 생성해서, 입력이 Python float이고 `out=`이 없으면 매개변수 튜플을 풀어 네이티브 함수를 바로 불러요. 그 밖(int, 배열, `out=`)은 위의 기반 메서드로 가서 int64 검사와 `out=`을 처리해요. 이름, 시그니처, 에러 메시지는 같아요. 네이티브 함수 쪽에도 같은 짧은 길이 있어요([원소별 엔진](/internals/stats/engine/#python-float-하나의-짧은-길)). 생성자도 매개변수가 모두 Python float이나 double 범위 안의 int이면 아래의 검사를 건너뛰어요.

C++ 쪽 분포 구조체는 이렇게 생겼어요.

```cpp
// csrc/stats/dist/normal.hpp (줄인 발췌)
struct Normal {
    static constexpr char name[] = "normal";
    static constexpr std::array<const char*, 2> params{"mu", "sigma"};

    static bool valid(double mu, double sigma) { return std::isfinite(mu) && sigma > 0.0 && std::isfinite(sigma); }

    static double pdf(double x, double mu, double sigma) {
        using namespace normal_detail;
        if (std::isinf(x)) return 0.0;
        const DD z = num::standardize(x, mu, sigma);
        if (std::fabs(z.hi) > kHugeZ) return 0.0;
        return num::exp_dd(-neg_log_density(z, sigma));
    }
    // ...
    static double cdf(double x, double mu, double sigma) { return tail(x, mu, sigma, false); }
    // ...
    static void cdf_chunk(const Chunk<2>& c, double* out) { tail_chunk(c, out, false); }
    // ...
    static double mean(double mu, double) { return mu; }
    // ...
};
```

`valid`가 정의역의 전부예요. 엔진이 원소마다 이것을 먼저 보고 거짓이면 NaN을 내기 때문에, `pdf`, `cdf` 같은 원소 함수는 유효한 매개변수와 NaN이 아닌 입력만 받는다고 가정하고 써요. `*_chunk`는 1024원소 묶음을 한 번에 계산하는 빠른 경로이고, 닫힌 꼴 분포의 입력 메서드 대부분, 감마 계열의 밀도, 이산 분포의 입력 메서드 대부분에 있어요.

## 매개변수 검사와 브로드캐스트

### 만들 때: 형과 모양만

생성자는 매개변수를 키워드로만 받고(`Gamma(2.5)`는 `TypeError`), 두 가지만 검사해요.

- 형: 실수 하나(Python의 `bool`·`int`·`float`, numpy의 실수 스칼라)이거나 complex가 아닌 `sd.ndarray`여야 해요(`_check_param`). 그 밖은 `TypeError`예요. float으로 바꾸면 넘칠 만큼 큰 Python int는 `OverflowError`(`Normal(): 'mu' is out of range`)예요.
- 모양: 배열 매개변수가 둘 이상이면 서로 브로드캐스트되는지 확인해요. 뷰만 만드는 `broadcast_arrays`를 불러 보고, 안 되면 그 자리에서 `ValueError`예요.

검사를 지난 매개변수는 `_kept`가 보관할 꼴로 바꿔요. 배열은 한 번 복사해 읽기 전용으로 들고, 속성과 모든 메서드가 그 사본을 봐요. 그래서 만든 뒤 사용자가 준 배열을 고쳐도 분포가 바뀌지 않고, 다변량 분포에서 만들 때 구한 분해와 속성이 어긋나지 않아요. 비용은 매개변수 크기의 복사 한 번이에요. numpy의 실수 스칼라는 Python 수로 바꿔 둬서 `repr`도 `Normal(mu=1.0, sigma=1.0)`처럼 Python 수로 보여요.

```python
# src/stardust/stats/_distribution.py (발췌)
def _kept(v):
    ...
    if isinstance(v, _sd_core.ndarray):
        c = v.copy()
        c._set_readonly()
        return c
    r = _real_scalar(v)
    return v if r is None else r
```

매개변수만 쓰는 메서드(모멘트, `median`, `mode`, `entropy`, `support`)가 배열을 내면 `_readonly`로 같은 표시를 해서 돌려줘요. 입력을 받는 메서드의 결과는 부를 때마다 새로 만든 배열이라 쓸 수 있어요.

생성자의 에러는 모두 클래스 이름으로 시작해요(`Normal(): ...`). 브로드캐스트 에러도 배열 영역이 낸 메시지의 앞머리를 클래스 이름으로 바꿔 다시 내요. 호출 모양이 틀린 에러(모르는 키워드, 빠진 필수 매개변수, 위치 인자)도 같은 꼴이에요.

호출 모양 에러는 Python이 직접 내서, 그대로 두면 `Normal.__init__() got an unexpected keyword argument 'cool'`처럼 사용자가 부른 적 없는 `__init__`을 말해요. 그래서 `__init_subclass__`의 마지막 줄 `_calls.keyword_init`이 클래스의 `__init__`을 감싸요. `_calls`는 모든 영역이 호출 모양 에러를 같은 꼴로 바꾸는 데 함께 쓰는 모듈이에요. 위치 인자가 있으면 원래 생성자를 부르지 않고 Python의 문장과 같은 `takes 0 positional arguments but 1 was given`으로 바로 에러를 내고, 나머지는 원래 생성자를 부른 뒤 `TypeError`의 앞머리가 `Normal.__init__() `이고 생성자의 본문이 아니라 호출을 묶는 단계에서 난 에러이면(트레이스백에 생성자의 프레임이 없으면) 그것을 `Normal(): `로 바꿔 다시 내요(`got an `도 떼요). 매개변수 검사가 낸 에러는 이미 `Normal(): `로 시작하므로 그대로 지나가요. 감싼 함수에 `__wrapped__`를 달아 두어서 `inspect.signature`는 원래의 키워드 전용 매개변수를 보여 줘요. 다변량·행렬 분포도 같은 함수로 감싸요. `Wishart`와 `InverseWishart`는 `__init__` 하나를 함께 쓰지만, 메시지의 이름은 부른 클래스의 것이에요. 공통 기반 `ContinuousDistribution`, `DiscreteDistribution`은 `isinstance` 검사용이라 직접 만들면 `TypeError`예요.

틀린 형의 메시지는 받은 값의 타입 이름을 보여 줘요. 이름은 모든 영역이 함께 쓰는 함수 하나(C++의 `py_type_name`, Python에서는 `_core._type_name`)가 만들어요. 보통은 모듈 없는 짧은 이름(`str`, `list`, `ndarray`)이고, numpy의 타입만 공개 모듈을 붙여요(`numpy.ndarray`, `numpy.float64`, `numpy.random.Generator`). sd의 `ndarray`나 Python의 `bool`과 같은 짧은 이름이라 헷갈리기 때문이에요. 모듈 경로에서 `_`로 시작하는 비공개 부분부터는 떼어서, `numpy.random._generator`가 아니라 `numpy.random`이에요.

```cpp
// csrc/bind/errors.cpp (발췌)
std::string py_type_name(nb::handle o) {
    // ...
    PyTypeObject* t = Py_TYPE(o.ptr());
    const char* name = t->tp_name;
    const char* dot = std::strrchr(name, '.');
    std::string out = dot ? dot + 1 : name;
    PyObject* mod = PyObject_GetAttrString(reinterpret_cast<PyObject*>(t), "__module__");
    if (mod == nullptr) {
        PyErr_Clear();
        return out;
    }
    if (PyUnicode_Check(mod)) {
        const char* m = PyUnicode_AsUTF8(mod);
        if (m == nullptr) PyErr_Clear();
        else if (std::strncmp(m, "numpy", 5) == 0 && (m[5] == '\0' || m[5] == '.')) {
            std::string pub;  // the module's parts up to the first private one
            for (const char *p = m, *e; *p != '\0'; p = *e ? e + 1 : e) {
                e = std::strchr(p, '.');
                if (e == nullptr) e = p + std::strlen(p);
                if (*p == '_') break;
                pub += (pub.empty() ? "" : ".") + std::string(p, e);
            }
            out = pub + "." + out;
        }
    }
    Py_DECREF(mod);
    return out;
}
```

### 부를 때: 매개변수와 입력을 함께

메서드를 부르면 매개변수와 입력을 한 번에 n항 디스패처에 넘겨요. 그래서 매개변수끼리, 그리고 매개변수와 입력이 numpy와 같은 규칙으로 함께 브로드캐스트해요. 매개변수만 쓰는 메서드(`mean`, `variance`, `median`, `mode`, `entropy`, `support` 등)는 매개변수의 브로드캐스트 모양을 돌려줘요. 모든 피연산자가 Python 숫자면 결과도 Python `float`예요.

```python
>>> Y = sd.stats.Normal(mu=sd.asarray([0.0, 10.0]), sigma=2.0)
>>> Y.cdf(sd.asarray([[0.0], [10.0]]))
array([[                   0.5, 2.8665157187919396e-07],
       [    0.9999997133484281,                    0.5]], dtype=float64)
>>> Y.mean()
array([ 0.0, 10.0], dtype=float64)
```

입력의 형이 틀리면 C++ 커널이 `gamma_cdf(): 'x' must be ...` 같은 메시지로 에러를 내요. 이 앞머리는 사용자가 부른 적 없는 이름이라, Python 층이 이를 메서드 이름으로 바꾸고 complex 배열에 대한 문구도 실수만 받는다는 말로 고쳐요(`_renamed`). int64 범위 밖의 Python int 입력은 커널에 넘기기 전에 `OverflowError`예요. sd.special의 함수와 같은 규칙이에요(`_int_input`).

```python

    ...

>>> sd.stats.Normal().cdf(2**70)

    ...
OverflowError: cdf(): Python int too large to convert to int64
```

## 정확도 계약과 보장 영역

### 계약

계약은 [sd.special](/internals/special/overview/)과 같은 틀이에요. 메서드마다 오차를 재는 방법만 다르게 골라요.

| 메서드 | 기준 (보장 영역 안) |
|---|---|
| `pdf`, `cdf`, `ccdf`, `logcdf`, `logccdf`, 모멘트 | 상대오차 $10^{-14}$ |
| `logpdf`, `entropy` (값이 0을 지나요) | $\lvert \text{오차} \rvert \le 10^{-14} \max(1, \lvert \text{값} \rvert)$ |
| `icdf`, `iccdf`, `ilogcdf`, `ilogccdf` | $\lvert \Delta x / x \rvert \le 10^{-14} \max(1, \kappa)$, $\kappa$는 그 메서드의 입력에 대한 조건수 |
| 이산 분포의 분위수 | 후방 오차: 목표를 상대 $10^{-14}$ 안에서 움직였을 때의 정확한 분위수 중 하나 |
| 결과가 서브노멀 | 절대오차 $45 \times 2^{-1074}$ |

역함수의 조건수는 `icdf(p)`에서 $\kappa = \lvert p / (x f(x)) \rvert$, `ilogcdf(logp)`에서 $\kappa = \lvert \log p \cdot p / (x f(x)) \rvert$예요. 입력 $p$가 이미 float64로 반올림돼 있어서, 그 0.5 ULP가 $x$에서 $\kappa$배로 커지는 것은 어떤 알고리즘으로도 피할 수 없어요. 예를 들어 `Normal(mu=1.5, sigma=2.0).icdf(0.2267)`은 $x = 1.5 + 2z$에서 두 항이 거의 지워져 $4.8 \times 10^{-4}$이 되는 점이에요. 여기서 $\kappa \approx 3120$이고, 결과의 상대오차 $3.3 \times 10^{-13}$은 계약 단위로 $1.1 \times 10^{-16}$이에요.

`ccdf`와 `logccdf`는 $1 - \text{cdf}$로 만들지 않아요. 두 꼬리 중 작은 쪽을 계산하고, 큰 쪽은 $1 - \text{작은 쪽}$, 그 로그는 `log1p(-작은 쪽)`이에요. 꼬리가 float64의 정규수 아래로 내려가도 `logcdf`·`logccdf`는 값을 가져요(`Normal().logcdf(-1e5)`는 $-5.0 \times 10^{9}$).

### 감싸기만 하면 생기는 오차

감마 분포의 위꼬리는 정의로는 `sd.special.gammaincc(a, x / scale)`예요. 그런데 `x / scale`을 float64로 반올림하면 그 상대오차(최대 $2^{-53}$)가 결과에서 조건수 $\lvert y\,Q'(y)/Q(y) \rvert$배로 커져요. 위꼬리에서 이 조건수는 대략 $y - a$이고 $y + 1$을 넘지 않아요. $a = 2000$, $y = 7001/3 \approx 2334$에서는 340이에요.

| 호출 | 결과 | Arb 참값 대비 상대오차 |
|---|---|---:|
| `sd.stats.Gamma(a=2000.0, scale=3.0).ccdf(7001.0)` | 6.72146801267098e-13 | $2.9 \times 10^{-16}$ |
| `sd.special.gammaincc(2000.0, 7001.0 / 3.0)` | 6.721468012671129e-13 | $2.2 \times 10^{-14}$ |

stats는 $y = x/\text{scale}$을 double-double $y_\text{hi} + y_\text{lo}$로 만들고(나눗셈의 나머지를 FMA로 정확히 구해요), 불완전 감마는 $y_\text{hi}$에서 계산한 뒤 $y\,Q'(y) \cdot (y_\text{lo}/y_\text{hi})$를 1차 보정으로 더해요. 2차 항은 $y_\text{lo}^2$ 크기라 남지 않아요. 정규분포의 $z = (x-\mu)/\sigma$, 로그정규의 $\log x$, 베이불의 $c \log(x/\text{scale})$도 같은 방식이에요. 이 문제와 해법의 일반형은 [분포 함수](/internals/special/distributions/)의 "인자의 반올림" 절에 있고, 분포별 적용은 [연속 분포의 수치 기법](/internals/stats/continuous/)에서 다뤄요.

### 보장 영역

보장 영역은 분포마다 정해 둔 매개변수 범위예요. 그 밖도 값을 계산하지만 계약으로 약속하지는 않고, 잰 정확도를 문서에 적어요.

| 분포 | 보장 영역 |
|---|---|
| 닫힌 꼴 12개(정규, 지수, 균등, 라플라스, 코시, 로그정규, 베이불, 로지스틱, Gumbel, GEV, 파레토, 레일리) | 매개변수와 입력의 정의역 전체 |
| 감마·역감마 / 카이제곱 | $a \le 10^6$ / $\text{df} \le 2 \times 10^6$ |
| 베타 / t / F | $a, b \le 10^5$ / $\text{df} \le 10^6$ / $\text{dfn}, \text{dfd} \le 10^5$ |
| 비중심 카이제곱·F / 비중심 t | $\text{df} \in [10^{-2}, 10^4]$, $\text{nc} \le 10^4$ / $\text{df} \in [0.1, 10^5]$, $\lvert \text{nc} \rvert \le 100$; 확률 $10^{-300}$까지. 엔트로피는 보장하지 않아요 |
| 이산 | 이항 $n \le 10^6$, 포아송 $\mu \le 10^6$, 기하 $p \ge 10^{-9}$, 음이항 $n \in [0.1, 10^4]$·$p \ge 10^{-4}$, 초기하 total $\le 3000$, 베타이항 $n \le 2000$·$a, b \in [0.1, 100]$, 로그 급수 $p \ge 10^{-8}$, Zipf $a \le 60$. 베르누이와 이산 균등은 전체 |
| 다변량 정규·t (밀도, 엔트로피) | $\kappa(\text{cov}) \le 10^9$, $d \le 100$ |
| 다변량 정규·t (누적확률) | 정규 $d = 2$는 $P \ge 10^{-15}$, $d = 3$은 상관의 부호와 조건수에 따른 범위, t의 $d = 2, 3$은 $P \ge 7 \times 10^{-13}$. $d \ge 4$는 준몬테카를로라 `atol`까지의 느슨한 계약 |
| 행렬 분포 | $\kappa \le 10^9$, $p \le 100$. Wishart·역Wishart의 `logpdf`는 df $\le 10^{30}$ |

보장 영역 안에서 잰 최대 오차는 중심 연속 12개가 $9.2 \times 10^{-15}$(87만 점), 이산 10개가 $6.3 \times 10^{-15}$(61만 점, 분위수는 모든 점이 허용 구간 안), 극값·수명·비중심 9개가 $4.7 \times 10^{-15}$(60만 점)이에요. 같은 점에서 scipy 1.18.1은 꼬리에서 상대오차 1에 이르거나 inf를 내는 메서드가 여럿이에요. 표 전체는 [정확도와 성능](/internals/stats/accuracy-performance/)에 있어요.

### 정답지

참값은 special과 같은 방식으로 만들어요. `tools/stats_ref.py`가 Arb(python-flint)로 값을 계산해 `tests/stats/ref/`에 저장하고, 테스트(`tests/stats/test_reference.py`)는 Arb를 부르지 않고 이 파일의 모든 점에서 계약을 확인해요.

- Arb의 공 $[m \pm r]$의 반지름이 값의 $2^{-110}$배 아래로 정착한 값만 써요. 도구가 직접 자른 급수와 적분은 잘라 낸 꼬리의 상한을 공에 더해요.
- 점마다 시간 제한을 두고, 결과는 계산하는 대로 바로 출력해요. 10프로세스로 나눠 돌리고 워커는 500점마다 새로 띄워요.
- 입력점은 파일에 고정해요. 일부 파일은 입력을 라이브러리 자신의 `icdf`로 뽑기 때문에, 고정하지 않으면 라이브러리를 고칠 때마다 입력이 달라져요.

## NaN 규칙과 정해진 시간

### NaN이 나오는 곳

NaN이 나오는 경우는 다섯 가지뿐이고, 이때 에러도 경고도 내지 않아요.

1. 매개변수가 정의역 밖이거나 NaN일 때: 그 원소의 모든 메서드가 NaN이에요. 엔진이 원소 함수를 부르기 전에 걸러요. 정의역 밖이어도 극한 분포가 있는 매개변수(t의 df = inf는 정규, 음이항의 n = 0은 0의 점질량)는 NaN이 아니라 그 분포의 값이에요. 베타·베타이항의 $2^{-1021}$ 아래 모양도 같은 장치로 두 점 분포의 값이에요([원소별 엔진과 빠른 경로](/internals/stats/engine/#매개변수의-극한)).
2. 입력이 NaN일 때: 입력을 받는 메서드는 NaN이에요.
3. 확률 입력이 확률이 아닐 때: `icdf`·`iccdf`의 입력이 $[0, 1]$ 밖이거나, `ilogcdf`·`ilogccdf`의 입력이 양수일 때예요. 0과 1(log 쪽은 $-\infty$와 0)에서는 지지집합의 끝이에요.
4. 값이 정의되지 않을 때: 코시의 평균, $\text{df} \le 1$인 t의 평균처럼 정의되지 않는 모멘트, 최빈값이 하나로 정해지지 않는 `mode`(균등, $a, b < 1$이거나 $a = b = 1$인 베타, 이항의 $(n+1)p$가 정수일 때 등)예요. 발산하는 모멘트는 NaN이 아니라 inf예요.
5. 보장 영역 밖에서 값을 구할 수 없을 때: 정해진 상한 안에 끝나지 않는 합이나 반복, 정밀도가 모자라 근을 확인할 수 없는 역함수예요.

지지집합 밖의 입력은 NaN이 아니에요. `pdf`는 0(`logpdf`는 $-\infty$), `cdf`는 0이나 1이에요. 확률과 밀도(`pdf`, `pmf`, `cdf`, `ccdf`)는 −0.0을 내지 않아요. 식이 음수 인자와의 곱에서 언더플로해 −0.0으로 반올림되는 곳이 있어서, 엔진이 결과에 `+ 0.0`을 더해 +0.0으로 바꿔요. 로그 메서드는 부호를 그대로 둬요. 1로 반올림되는 확률의 로그 −0.0은 아래에서 다가가는 극한이기 때문이에요.

### 모든 호출은 정해진 시간 안에 끝나요

합·탐색·반복에는 모두 근거가 있는 상한이 상수로 있어요. 원칙은 셋이에요.

- **보장 영역 안에서는 상한에 닿지 않아요.** 상한은 영역 안에서 잰 최대 반복 수보다 넉넉하게 잡아요.
- **상한에 닿으면 NaN이에요.** "항이 합의 $2^{-60}$ 아래가 되면 멈춤" 같은 수렴 조건만으로는 항의 수가 보장되지 않아요. 상한에서 그때까지의 부분합이나 마지막 반복값을 내면, 틀린 값이 아무 표시 없이 나가요.
- **루프 카운터를 double로 두지 않아요.** 가장 큰 항 $j$에서 아래로 걷는 루프를 `j - i >= jmin`으로 쓰면, $j \approx 10^{50}$에서 `j - i`가 `j`와 같아져 영원히 끝나지 않아요.

| 어디 | 상한 | 보장 영역 안의 최대 |
|---|---|---|
| 비중심 분포의 포아송 혼합 급수 (special) | $2^{18}$항 | 2421항 |
| 비중심 분포의 혼합 합(정점에서 나갔다 돌아오는 걷기) | $2^{18}$–$2^{19}$걸음 | 확률 2300·2701걸음, log 꼴과 역함수의 넓은 합 3805·4645걸음 |
| 비중심 카이제곱·F의 밀도 급수 | 한쪽 $2^{16}$항 | 10345항 |
| 비중심 역함수의 구간 넓히기 / Brent 반복 | 256회 / 200회 | 32회 / 16회 |
| 비중심 엔트로피의 적분 | 일 $2^{25}$단위 | |
| 이산 분위수 탐색 (배증과 이분) | 1100회 | |
| 이산 꼬리 합 (초기하, 베타이항) | 항별로 $2^{20}$항, 매끄러운 긴 꼬리는 적분 | |
| 이산 엔트로피 합 | $2^{25}$항, 분산이 $2^{42}$를 넘으면 시작하지 않아요 | |
| 이산 중심 모멘트의 합 | 4096항 | |
| 감마·베타·t·F의 깊은 꼬리 역함수 | 100걸음 | |
| 다변량 누적확률의 적응 구적 / 준몬테카를로 | 구간 200개 / 96단계와 `max_points` | |
| 다항 분포의 엔트로피 | 범주별 표준편차의 합 $2^{17}$, 한쪽 $2^{23}$항 | |
| 표본: 이항 역변환 / 초기하 | $k \le 1024$ / 최빈값에서 $2^{20}$ 안 | |

보장 영역 안에서 가장 느린 호출은 `NegativeBinomial(n=1e4, p=1e-4).entropy()`예요. 표준편차가 $10^6$이라 약 $1.9 \times 10^7$항을 더하고, 0.23초쯤 걸려요.

```python
>>> sd.stats.NoncentralChiSquared(df=3.5, nc=2.0).pdf(1e100)
0.0
>>> sd.stats.NoncentralChiSquared(df=3.5, nc=1e15).cdf(1e15)
nan
>>> sd.stats.Binomial(n=2.0**60, p=0.5).cdf(2.0**59)
nan
```

두 번째 호출은 비중심도가 너무 커서 혼합 급수가 $2^{18}$항 안에 끝나지 않는 경우이고, 세 번째는 $n > 2^{52}$라 불완전 베타에 넘길 $n - k$, $k + 1$이 float64로 정확하지 않은 경우예요. 분포마다 NaN이 되는 범위는 각 분포의 API 문서에 있어요.

<Callout title="NaN은 계약의 일부예요">
  NaN은 보장 영역 밖에서만 쓰는 출구예요. 영역 안에서는 참값 파일의 모든 점이 계약을 지켜야 하므로 NaN이 끼어들 자리가 없어요. 영역 밖은 극단 인자 묶음(중심 연속 분포 약 80만 호출, 다변량·행렬·표본·기술통계 약 13만 호출)으로 점검해요. 호출마다 시간 제한을 두고, 낸 값은 Arb 값이나 극한 꼴과 대조해요. 그 가운데 끝나지 않기 쉬운 극단 호출과 영역 밖 호출 몇 개는 시간 제한과 함께 테스트로 고정돼 있어요(`tests/stats/test_discrete.py`, `test_distributions.py`).
</Callout>

## 다른 영역과의 관계

### special

통계 영역의 누적분포와 역함수 대부분은 [sd.special](/internals/special/overview/)의 함수예요. 다만 Python 함수를 부르지 않고 C++ 헤더를 직접 포함해서, 원소 함수 안에서 `special::igam_detail::igam`, `special::Ndtr::chunk`, `special::Gammaincinv::f`, `special::Bdtr::f` 같은 함수를 인라인으로 불러요. 그래서 special의 함수가 내는 중간값(예: 불완전 감마의 $P$, $Q$와 함께 나오는 $x P'(x)$)도 받아 쓸 수 있어요.

- special에 더한 것: t·카이제곱·F·포아송·이항·음이항의 분포 함수(`stdtr`, `chdtr`, `fdtr`, `pdtr`, `bdtr`, `nbdtr`과 그 보수, `stdtrit`·`chdtri`·`fdtri`)와 비중심 분포 9개, `ndtri_exp`는 통계 영역이 쓰려고 special에 둔 함수예요([분포 함수](/internals/special/distributions/)).
- 같은 값일 때와 다른 값일 때: 표준화가 필요 없는 곳은 같은 함수라 비트가 같아요(`StudentT(df=3.5).cdf(t)`와 `stdtr(3.5, t)`, `Normal().cdf(x)`와 `ndtr(x)`). 척도로 나누는 곳은 위의 감마 예처럼 stats가 더 정확해요. 감마의 반정수 모양처럼 stats가 자기 경로(유한 합)를 쓰는 곳은 마지막 비트가 다를 수 있어요.
- 같은 엔진: n항 디스패처, 원소당 비용으로 정하는 병렬 기준, 결정성 규칙은 special의 것이에요([원소별 엔진과 병렬화](/internals/special/engine/)).

```python
>>> t = sd.asarray([-30.0, -2.5, 0.3, 4.0])
>>> bool(sd.all(sd.stats.StudentT(df=3.5).cdf(t) == sd.special.stdtr(3.5, t)))
True
>>> sd.stats.Gamma(a=2.5).cdf(2.5), sd.special.gammainc(2.5, 2.5)
(0.584119813004492, 0.5841198130044922)
```

두 번째 줄의 참값은 $0.584119813004492079\ldots$이에요. 둘 다 계약 안이고, stats 쪽은 반정수 $a$의 유한 합에서 나온 값이에요.

### random

`X.sample(shape, rng=rng)`의 난수는 [sd.random](/internals/random/generator/)의 Philox 스트림에서 받아요. `rng`는 꼭 줘야 해요(전역 생성기가 없어요). Python 층이 `rng`에서 원소 수만큼 스트림 위치를 예약하고(물리 메모리보다 큰 요청이면 위치를 움직이기 전에 `MemoryError`예요), C++ 커널은 호출의 원소 $i$(C 순서)를 스트림 원소 $\text{pos} + i$에 대응시켜요. 그 원소의 첫 단어는 sd.random과 같은 블록에서, 기각이나 조합에 필요한 추가 단어는 그 원소만의 블록에서 차례로 받아요. 그래서 표본 하나는 (키, 원소 번호, 매개변수)만으로 정해지고, 스레드 수나 호출을 나누어 부르는 방법과 무관해요. 분포별 방법은 [표본 뽑기](/internals/stats/sampling/)에 있어요.

### linalg와 배열

- **다변량·행렬 분포는 LAPACK 분해를 쓰지 않아요.** 공분산을 double로 촐레스키 분해하면 그 인수는 $A + E$($\lvert E \rvert \sim d \cdot \varepsilon \lvert A \rvert$)의 인수라서, 이차 형식이 $\kappa \varepsilon$만큼 움직여요. 그래서 double-double 촐레스키와 삼각 풀이(`stats/dd_linalg.hpp`)를 따로 두고, 오차가 $\kappa \cdot 10^{-32}$ 수준이 돼요. 행렬의 아래 삼각만 읽는 규칙은 [sd.linalg.cholesky](/api/linalg/cholesky/)와 같아요. 점이 많은 `logpdf`도 BLAS를 쓰지 않아요. BLAS는 합의 순서를 정해 주지 않아서 점마다 오차 상한을 셀 수도, 결과가 위치와 무관하다고 보장할 수도 없기 때문이에요([다변량 분포의 밀도](/internals/stats/multivariate/)).
- **기술통계는 배열 영역 위에 있어요.** 줄 모으기는 `sd.permute_dims`·`sd.reshape`, `iqr`은 `sd.quantile`(omit이면 `sd.nanquantile`), `entropy`는 `sd.special.entr`·`rel_entr`과 `sd.sum`이에요. 공분산·상관행렬(`sd.cov`, `sd.corrcoef`), 분위수와 NaN을 건너뛰는 리덕션은 numpy처럼 배열 영역에 있어요([기술통계](/internals/stats/descriptive/)).
