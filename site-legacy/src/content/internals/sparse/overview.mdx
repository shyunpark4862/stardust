## 한눈에 보기

희소 배열은 Python 클래스예요. 필드는 `sd.ndarray`이고(CSR·CSC는 `data`, `indices`, `indptr`, COO는 `data`와 `coords`), DOK만 C++의 해시 맵을 필드로 가져요. 계산은 거의 언제나 C++ 커널(`stardust._core.sparse`) 한 번 호출이에요. Python 층은 인자를 검사하고, 형식을 맞추고, 결과 배열을 다시 클래스로 감싸요.

층은 아래로만 기대요. `sparse/`는 배열, linalg, 스레드풀, Accelerate 래퍼 위에 서고, 다른 영역의 코드는 `sparse/`를 모르는 채로 있어요. 예외는 하나뿐이에요. 배열과 linalg의 함수가 희소 배열을 받았을 때 쓸 함수를 알려 주려고 받은 객체가 희소 배열인지 보는 판별이에요(아래 [다른 영역과 만나는 자리](#다른-영역과-만나는-자리)).

`stardust._core.sparse` 하위 모듈은 파일마다 하나씩 있는 `bind_*` 함수를 차례로 불러 만들어요. 그래서 커널의 공개 이름(`_compress`, `_spmv`, `_binop` …)은 모두 밑줄로 시작하는 내부 이름이고, 사용자는 Python 클래스와 함수만 봐요.

```python
>>> import stardust as sd
>>> A = sd.sparse.csr_array(sd.asarray([[1.0, 0.0, 2.0], [0.0, 0.0, 3.0]]))
>>> A
<csr_array of shape (2, 3), float64, 3 stored elements>
>>> type(A.data).__name__, A.data.dtype, A.indices.dtype
('ndarray', float64, int64)
>>> (A @ sd.asarray([1.0, 1.0, 1.0])).tolist()
[3.0, 3.0]
```

클래스는 네 형식(`coo_array`, `csr_array`, `csc_array`, `dok_array`)과 바탕 클래스 `sparray`예요. `csr_array`와 `csc_array`는 둘이 함께 쓰는 중간 클래스 `_compressed`를 거쳐요. 형식마다 바꾸는 것은 변환(`_tocsr` 등), 전치, 복사, 새 값으로 바꾸기, 모양 바꾸기, 세기 정도이고, 검사와 공통 규칙은 `sparray`의 메서드가 그 둘레에 둘러요.

```python
>>> sd.sparse.issparse(A), [c.__name__ for c in type(A).__mro__[1:3]]
(True, ['_compressed', 'sparray'])
```

### 메서드의 틀린 호출

모든 공개 메서드는 모듈을 들여올 때 한 번 감싸여요. 그래서 없는 키워드나 인자 개수가 틀린 호출도 다른 함수처럼 메서드 이름으로 시작하는 메시지가 돼요. `self`는 세지 않아요.

```python
>>> A.sum(x=1)
Traceback (most recent call last):
    ...
TypeError: sum(): unexpected keyword argument 'x'
>>> A.tocsr(1)
Traceback (most recent call last):
    ...
TypeError: tocsr(): takes 0 positional arguments but 1 was given
```

### 밀집으로 몰래 바뀌지 않아요

`sparray`는 numpy가 희소 배열을 밀집 배열로 바꾸려 할 때 쓰는 길을 모두 막아요. `__array_ufunc__ = None`이라 numpy는 자기 ufunc로 바꾸지 않고 이쪽 연산자에 맡기고, `__array__`는 `toarray()`를 짚는 `TypeError`, `__len__`·`__bool__`·`__iter__`도 `TypeError`예요.

```python
>>> import numpy as np
>>> np.asarray(A)
Traceback (most recent call last):
    ...
TypeError: a sparse array is not converted to a dense array implicitly; use A.toarray() (csr_array)
```

numpy 배열은 연산자의 피연산자도 아니에요. 그런데 이쪽 연산자가 `NotImplemented`만 돌려주면 numpy의 반사 연산이 대신 답하면서 `operand 'csr_array' does not support ufuncs` 같은 numpy의 글을 내요. 그래서 연산자는 상대가 numpy 배열이면 Python이 내는 것과 같은 `TypeError`를 직접 만들어 던져요(`_ops.py`의 `refused`). numpy 배열이 어느 쪽에 있어도 같은 글이고, `LinearOperator`도 같은 규칙이에요. 비교 연산은 numpy가 양보하므로 Python의 글이 그대로 나와요.

```python
>>> A * np.ones(3)
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for *: 'csr_array' and 'numpy.ndarray'
>>> np.ones(3) * sd.sparse.aslinearoperator(sd.eye(3))
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for *: 'numpy.ndarray' and 'LinearOperator'
```

## Accelerate가 주는 것과 없는 것

macOS SDK의 `vecLib.framework/Headers/Sparse/`에는 두 묶음이 있어요. 불투명한 행렬 객체에 원소를 넣고 곱하는 Sparse BLAS(`BLAS.h`)와, 투명한 열 압축 행렬을 분해하고 푸는 Sparse Solvers(`Solve.h`)예요.

| 묶음 | 내용 | 이 영역에서 |
|---|---|---|
| Sparse BLAS | 불투명 객체의 SpMV, SpMM, 희소 × 희소, 삼각 풀이, 노름 | 쓰지 않아요. 데이터를 그대로 보여 줄 수 없어 원소를 복사해 넣어야 해요 |
| Sparse Solvers, 직접 | Cholesky, LDLᵀ, QR, 그리고 complex를 포함한 LU. 순서 매기기 AMD, Metis, MTMetis, COLAMD | LU와 AMD 순서만 써요(`spsolve`, `splu`, `factorized`, `inv`, shift-invert의 역) |
| Sparse Solvers, 반복 | CG, GMRES, LSMR | 쓰지 않아요. 멈춤 판정과 반복 수, 전처리의 뜻이 scipy와 다르고 반복 수를 돌려주지 않아요 |

LU와 AMD만 쓰는 까닭은 결정성이에요. 같은 프로세스에서 같은 입력을 여러 번 분해해 결과의 바이트를 견주면, Cholesky·LDLᵀ와 기본 순서 MTMetis는 실행마다 끝자리가 달라지고, MTMetis는 여러 스레드에서 동시에 부르면 프로세스가 죽기도 해요. LU/AMD는 시험한 모든 행렬 꼴과 크기, complex, 두 스레드 모드, 동시 호출에서 언제나 같은 바이트였어요. Accelerate에 넘기는 행렬은 열 압축에 32비트 행 색인이라, 래퍼(`csrc/accelerate/sparse.hpp`)가 int64 색인을 한 번 좁혀 복사해요. 분해와 그 제약은 [Accelerate의 희소 LU](/internals/sparse/lu/)에서 따로 다뤄요.

그래서 이 라이브러리가 직접 짜는 것이 대부분이에요.

- 형식, 변환, 표준 꼴, 산술, 원소별 연산, 리덕션, 인덱싱, 만들기, SpMV·SpMM·SpGEMM: 이 영역의 C++ 커널. 크기로만 나누는 정해진 합의 순서를 이쪽이 정해야 하기 때문이에요.
- [삼각 풀이](/internals/sparse/triangular/): Solve.h의 투명한 행렬에는 없어서 짜요.
- `cg`, `gmres`, `minres`, `bicgstab`, `lsqr`, `lsmr`: scipy의 알고리즘과 멈춤 판정 그대로 짜요([반복법의 바탕](/internals/sparse/krylov/)).
- `eigsh`, `eigs`: [ARPACK의 암시적 재시작 Lanczos·Arnoldi](/internals/sparse/arpack/)를 옮겨요. `svds`는 [두꺼운 재시작 Golub–Kahan–Lanczos](/internals/sparse/svds/)예요. 작은 밀집 부분 문제는 linalg의 LAPACK 래퍼를 불러요.
- `expm`, `expm_multiply`, `onenormest`, `norm`: Python이 위의 커널(SpMV, SpGEMM, LU, 리덕션)을 불러 계산해요. C++는 `expm`이 삼각 행렬의 대각을 고치는 작은 함수 하나뿐이에요([행렬 지수와 그 곱](/internals/sparse/expm/)).

## 다른 영역과 만나는 자리

희소 배열은 다른 영역의 함수에 들어가지 않아요. `sd.linalg`와 배열의 함수는 밀집 `sd.ndarray`만 받고, 희소 배열을 받으면 쓸 함수를 짚는 `TypeError`예요. 판별은 실패한 호출에서만 해요. 배열 영역의 모든 입력이 지나는 `require_ndarray`가 받은 객체가 `sd.ndarray`가 아닐 때만 그것이 희소 배열인지 봐요.

```cpp
// csrc/bind/pyutil.cpp
NDArray& require_ndarray(nb::handle o, const char* what) {
    if (!is_ndarray(o)) {
        const std::string msg = std::string("'") + what + "' must be an sd.ndarray, not " + py_type_name(o);
        if (is_sparse_array(o)) throw SparseOperand(msg);  // rethrow_named adds what to use instead
        throw nb::type_error(msg.c_str());
    }
    return as_ndarray(o);
}
```

`is_sparse_array`는 객체 형의 `__module__`이 `stardust.sparse`로 시작하는지만 봐요. 그래서 배열 영역은 `sparse/`의 코드를 들이지 않아요. 함수 이름을 붙이는 `rethrow_named`가 표 `sparse_hint`에서 짝을 찾아 메시지 끝에 붙여요. 짝이 없으면 `toarray()`로 바꾸라는 글이에요. linalg는 자기 입력 검사(`csrc/linalg/input.cpp`)에서 같은 일을 하고, 짚을 함수가 `sd.sparse`에 있는지를 이름으로 확인해요.

```python
>>> sd.linalg.solve(A, sd.ones(2))
Traceback (most recent call last):
    ...
TypeError: solve(): 'a' must be an sd.ndarray, not csr_array; for a sparse array use sd.sparse.spsolve
>>> sd.sum(A)
Traceback (most recent call last):
    ...
TypeError: sum(): 'x' must be an sd.ndarray, not csr_array; for a sparse array use A.sum()
>>> sd.sort(A)
Traceback (most recent call last):
    ...
TypeError: sort(): 'x' must be an sd.ndarray, not csr_array; a sparse array has no sort: use sort(A.toarray())
```

`require_ndarray`를 쓰는 special, stats, htest의 함수도 같은 글을 받아요. 다른 입력의 메시지와 결과는 바뀌지 않아요.

반대 방향도 있어요. 희소 함수에 밀집 배열을 주면, 밀집 짝이 있는 함수는 그 짝을 짚어요.

```python
>>> sd.sparse.spsolve(sd.eye(2), sd.ones(2))
Traceback (most recent call last):
    ...
TypeError: spsolve(): 'A' must be a sparse array, not ndarray; for a dense array use sd.linalg.solve
```

그 밖의 영역과의 관계는 이래요.

- `sd.random`: `random_array`는 `rng=`(`sd.random.Generator`)를 꼭 받아요. 자리는 `rng.choice`, 값은 `rng.random` 등으로 뽑아요([만들기 함수](/internals/sparse/construct/)).
- `sd.optimize`, `sd.regression`, `sd.htest`는 지금 희소 배열을 받지 않아요.
- scipy: 생성자가 scipy의 희소 배열과 옛 행렬을 받고(언제나 복사), `A.to_scipy()`가 복사 없는 뷰를 내보내요([변환](/internals/sparse/conversion/)).

## 밀집 짝의 원칙

희소 영역의 기능은 밀집의 부분집합이거나 희소에만 필요한 것이에요. 희소 저장과 상관없는 기능(만들기, 판정, 옵션)은 밀집에도 있어요. 희소에만 필요한 것은 형식과 변환, 저장의 관리(`eliminate_zeros`, `sum_duplicates`, `nnz`, `explicit=`), 밀도와 자리(`random_array`), 희소 우변의 풀이 같은 것이에요. 희소에서만 되는 일이 있으면 밀집 문제를 풀려고 희소로 바꾸게 되고, 두 쪽을 견줄 기준도 없기 때문이에요.

짝 가운데 값이 입력의 복사이거나 같은 반올림 한 번인 것은 같은 입력에서 비트까지 같아요. 만들기, 인덱싱, 원소별 연산, `diagonal`, float의 `trace`, `kron`·`kronsum`, 대각 행렬과 2 × 2 삼각 행렬의 `expm`이 그래요. 밀집 함수의 결과는 희소 함수의 `toarray()`와 같고, 다를 수 있는 것은 0의 부호뿐이에요(희소는 0을 저장하지 않으니까요).

| sd.sparse | 밀집 짝 |
|---|---|
| `eye_array`, `tril`, `triu` | `sd.eye`, `sd.tril`, `sd.triu` |
| `diags_array` | `sd.diag` |
| `hstack`, `vstack`, `block_array` | `sd.concat`, `sd.stack`, `sd.block` |
| `kron`, `kronsum`, `block_diag` | `sd.linalg.kron`, `sd.linalg.kronsum`, `sd.linalg.block_diag` |
| 원소별 메서드, `power`, 리덕션 | 같은 이름의 배열 함수, `sd.pow` |
| `trace`, `diagonal` 메서드, `norm` | `sd.linalg.trace`, `sd.linalg.diagonal`, `sd.linalg.matrix_norm`·`vector_norm` |
| `spsolve`, `inv`, `spsolve_triangular`, `splu`, `expm` | `sd.linalg.solve`, `inv`, `solve_triangular`, `lu`, `expm` |
| `spbandwidth`, `is_sptriangular` | `sd.linalg.bandwidth` |

```python
>>> K = sd.sparse.csr_array(sd.asarray([[0.0, 1.0]]))
>>> B = sd.sparse.csr_array(sd.asarray([[-2.0]]))
>>> sd.sparse.kron(K, B).toarray().tolist()
[[0.0, -2.0]]
>>> sd.linalg.kron(K.toarray(), B.toarray()).tolist()
[[-0.0, -2.0]]
```

밀집의 0 × (−2)는 −0.0이고, 희소는 저장되지 않은 0과 곱하지 않아 그 자리가 +0.0이에요. 값이 같은 것은 희소 커널이 값을 만들 때 배열의 스칼라 연산(`array/kernels/scalar_ops.hpp`의 `ops::Multiply` 등)을 그대로 부르거나, Python 층이 `sd.multiply` 같은 배열 함수를 `data`에 부르기 때문이에요.

계산 순서가 다른 짝은 두 쪽 모두 정확도 계약 안에서 끝자리가 다를 수 있어요. 풀이(`spsolve`, `inv`, `spsolve_triangular`, `splu`)는 희소 LU의 AMD 순서와 반복 다듬기, 대입의 줄 합이 밀집과 달라요. 6 × 6 삼중대각 `T6`의 `spsolve(T6, ones(6))[-1]`은 3.0, `sd.linalg.solve`는 3.0000000000000004예요. 일반 행렬의 `expm`은 곱과 마지막 풀이의 순서가, 리덕션과 `norm`은 저장된 값만 더하는 합의 나눔이 밀집의 pairwise 트리와 달라요.

결과 dtype이 다른 짝도 있어요. bool·int 입력의 `A.trace()`, `kron`, `kronsum`은 배열 영역의 규칙(`sd.sum`, `sd.multiply`)이라 int64이고, 밀집 짝 `sd.linalg.trace`·`kron`·`kronsum`은 linalg의 규칙이라 float64예요. float64·complex128 입력에서는 두 쪽이 비트까지 같아요.

```python
>>> I = sd.sparse.csr_array(sd.asarray([[1, 0], [2, 3]]))
>>> I.trace(), sd.linalg.trace(I.toarray())
(4, 4.0)
```

`eigsh`, `svds`, 반복법, `LinearOperator`처럼 밀집 짝이 따로 없는 함수는 밀집 배열도 받아요.
