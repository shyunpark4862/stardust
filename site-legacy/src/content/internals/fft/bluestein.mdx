## 한눈에 보기

[Stockham 혼합 기수](/internals/fft/stockham/)는 소인수가 31 이하인 길이만 계산해요. 소수 1009나 $1147 = 31 \cdot 37$처럼 더 큰 소인수가 있는 길이는 Bluestein 알고리즘(chirp-z 변환이라고도 해요)으로 가요. 길이 $n$의 DFT를 길이 $m$의 원형 합성곱 하나로 바꾸고, 그 합성곱을 혼합 기수 FFT 두 번으로 계산하는 방법이에요.

- 안쪽 길이 $m$은 $2n - 1$ 이상인 가장 작은 $2^a 3^b 5^c$예요. 안쪽 변환은 기수 4, 2, 3, 5만 써요.
- 호출마다 하는 일은 chirp 곱, 길이 $m$의 정변환, 핵의 변환과의 곱, 길이 $m$의 역변환, chirp 곱의 다섯 단계예요.
- chirp와 핵의 변환은 계획을 만들 때 double-double(double 두 개로 약 106비트)로 계산해 한 번 반올림해 둬요. 이것이 오차 한계의 증명을 세우는 열쇠예요.

파일은 `csrc/fft/bluestein.hpp`(계획의 꼴), `csrc/fft/ddmath.hpp`(double-double 산술), `csrc/fft/plan.cpp`(계획 만들기와 실행)예요.

```python
>>> import stardust as sd
>>> C = sd._core.fft
>>> p = C._plan_info(1009)
>>> p["path"], p["m"], p["radices"], round(p["rho"], 4)
('bluestein', 2025, [3, 3, 3, 3, 5, 5], 2.082)
```

## 곱을 제곱의 차로

출발점은 정수 항등식 하나예요.

$$
jk = \frac{j^2 + k^2 - (k - j)^2}{2}
$$

이것을 DFT의 지수에 넣고 $w_\ell = e^{-\pi i \ell^2/n}$이라 두면

$$
y_k = \sum_{j=0}^{n-1} x_j\, e^{-2\pi i jk/n} = \sum_{j=0}^{n-1} x_j\, e^{-\pi i (j^2 + k^2 - (k-j)^2)/n} = w_k \sum_{j=0}^{n-1} (x_j w_j)\, \overline{w_{k-j}}
$$

예요. 합은 $a_j = x_j w_j$와 $b_\ell = \overline{w_\ell}$의 합성곱이에요. 곱 $jk$가 사라지고 차 $k - j$만 남았으니 길이 $n$에 아무 소인수가 있어도 상관없어요. 합성곱은 길이를 마음대로 고를 수 있는 FFT로 계산하면 돼요. $w_\ell$은 주파수가 $\ell$에 비례해 늘어나는 신호(chirp)라서 이런 이름이 붙었어요.

**왜 $m \ge 2n - 1$인가.** 길이 $m$의 원형 합성곱 $c_k = \sum_j a_j b_{(k - j) \bmod m}$으로 계산하려면 $b$를 길이 $m$의 배열에 놓아야 해요. $k, j \in [0, n)$이면 $k - j \in (-n, n)$이라 $b_\ell$이 $\ell = -(n-1), \dots, n - 1$의 $2n - 1$개 필요해요. 음수 $\ell$은 $m + \ell$ 자리에 가니, 그 자리 $[m - n + 1, m - 1]$이 양수 자리 $[0, n - 1]$과 겹치지 않으려면 $m - n + 1 \gt n - 1$, 곧 $m \ge 2n - 1$이어야 해요. $w_{-\ell} = w_\ell$이라 핵은 $b_\ell = b_{m - \ell}$로 놓여요. 그 밖의 자리는 0이에요.

**왜 5-매끄러운 $m$인가.** $2n - 1$ 이상이기만 하면 어떤 $m$도 되니, 혼합 기수 가운데 가장 싼 기수(4, 2, 3, 5)만 쓰는 길이를 골라요. 그런 수는 촘촘해서 $m$이 $2n - 1$보다 크게 벗어나지 않아요.

```cpp
// csrc/fft/plan.cpp
int64_t smooth5_at_least(int64_t target) {
    int64_t best = INT64_MAX;
    for (int64_t p5 = 1;; p5 *= 5) {
        for (int64_t p35 = p5;; p35 *= 3) {
            int64_t v = p35;
            while (v < target) v *= 2;
            best = std::min(best, v);
            if (p35 >= target) break;
        }
        if (p5 >= target) break;
    }
    return best;
}
```

$5^c$와 $3^b$의 곱마다 2를 곱해 `target`을 넘는 가장 작은 값을 만들고, 그 가운데 가장 작은 것을 골라요. 후보는 $\log_5 \times \log_3$개쯤이라 금방 끝나요.

## 계획: chirp와 핵의 변환

```cpp
// csrc/fft/plan.cpp
BluesteinPlan::BluesteinPlan(int64_t n) : n_(n), m_(smooth5_at_least(2 * n - 1)), inner_(m_) {
    const int64_t m = m_;
    const dd::CisTable cw(2 * n);
    std::vector<dd::DC> b(static_cast<size_t>(m)), f(static_cast<size_t>(m));
    chirp_.resize(static_cast<size_t>(2 * n));
    for (int64_t l = 0; l < n; ++l) {
        const auto sq = static_cast<unsigned __int128>(l) * static_cast<unsigned __int128>(l);
        const auto t = static_cast<int64_t>(sq % static_cast<unsigned __int128>(2 * n));
        const dd::DC w = cw(t);  // e^(-pi i l^2 / n) = e^(-2 pi i (l^2 mod 2n) / 2n)
        chirp_[static_cast<size_t>(2 * l)] = w.re.hi;
        chirp_[static_cast<size_t>(2 * l + 1)] = w.im.hi;
        b[static_cast<size_t>(l)] = dd::conj(w);
        if (l > 0) b[static_cast<size_t>(m - l)] = dd::conj(w);
    }
    {
        const dd::CisTable cm(m);
        dd::dft(b.data(), 1, f.data(), m, m, cm);
    }
    beta_.resize(static_cast<size_t>(2 * m));
    double big = 0.0;
    const double dm = static_cast<double>(m);
    for (int64_t k = 0; k < m; ++k) {
        const dd::DC& v = f[static_cast<size_t>(k)];
        beta_[static_cast<size_t>(2 * k)] = dd::div(v.re, dm).hi;
        beta_[static_cast<size_t>(2 * k + 1)] = dd::div(v.im, dm).hi;
        big = std::max(big, std::hypot(v.re.hi, v.im.hi));
    }
    rho_ = big / std::sqrt(static_cast<double>(n)) * (1.0 + 0x1p-40);  // rounded up
}
```

순서대로 읽으면 이래요.

1. **chirp의 지수는 정확한 정수예요.** $e^{-\pi i \ell^2/n} = e^{-2\pi i (\ell^2 \bmod 2n)/(2n)}$이라 필요한 것은 $\ell^2 \bmod 2n$뿐이에요. $\ell^2$은 $n$이 $2^{32}$쯤만 돼도 64비트를 넘으니 128비트 정수로 곱하고 나눠요. 각을 실수로 만들기 전에 주기를 정확히 걷어 내는 것은 [회전 인자](/internals/fft/stockham/)와 같은 생각이에요.
2. **chirp $w_\ell$과 핵 $b_\ell = \overline{w_\ell}$을 double-double로 구해요.** `cw`는 분모 $2n$의 $e^{-2\pi i t/(2n)}$을 답하는 표예요(아래). chirp는 높은 부분 `hi`만 남겨요. double-double의 낮은 부분은 높은 부분의 반 ULP 이하라서 `hi`가 곧 참값을 한 번 반올림한 double이에요.
3. **핵의 변환 $Fb$를 double-double로 구해요.** `dd::dft`는 길이 $m$의 DFT를 double-double로 하는 재귀 함수예요.
4. **$\beta = Fb / m$을 한 번 반올림해 저장해요.** 합성곱 정리의 $1/m$을 여기에 넣어 두니 호출 때의 역변환은 정규화가 없어요.
5. **$\rho = m \max_k \lvert \beta_k \rvert / \sqrt n$을 계산해요.** 오차 한계에 곱해지는 상수예요. 위로 조금 올려 둬요.

### double-double 산술

double-double은 값을 $\mathrm{hi} + \mathrm{lo}$($\lvert \mathrm{lo} \rvert \le \mathrm{ulp}(\mathrm{hi})/2$)로 들고 다녀요. 두 연산이 바탕이에요.

```cpp
// csrc/fft/ddmath.hpp
inline DD two_sum(double a, double b) {
    const double s = a + b;
    const double bb = s - a;
    return {s, (a - (s - bb)) + (b - bb)};
}
```

```cpp
// csrc/fft/ddmath.hpp
inline DD mul(DD a, DD b) {
    const double p = a.hi * b.hi;
    const double e = std::fma(a.hi, b.hi, -p);
    return quick_two_sum(p, e + (a.hi * b.lo + a.lo * b.hi));
}
```

- <strong>`two_sum`(Knuth)</strong>은 $s = \mathrm{fl}(a + b)$와 함께 $a + b - s$를 정확히 돌려줘요. 반올림으로 잃은 부분을 여섯 번의 연산으로 되찾는 오차 없는 변환이에요. `quick_two_sum`(Dekker)은 $\lvert a \rvert \ge \lvert b \rvert$를 알 때 세 번으로 같은 일을 해요.
- **곱의 반올림 오차는 FMA가 정확히 줘요.** $\mathrm{fma}(a, b, -\mathrm{fl}(ab)) = ab - \mathrm{fl}(ab)$가 정확히 표현되기 때문이에요. 여기에 교차항 $a_h b_l + a_l b_h$를 더해 정규화해요.

그래서 연산 하나가 결과의 약 $2^{-104}$ 안이에요(곱은 상대적으로, 덧셈은 큰 피연산자에 대해). 계획의 값은 노름으로만 오차 한계에 들어가니, 이 정도의 오차는 마지막에 double로 반올림하는 $u = 2^{-53}$에 비하면 보이지 않아요.

### 테일러 급수의 sin과 cos

`dd::cis(t, N)` $= e^{-2\pi i t/N}$은 `twiddle()`처럼 $t$를 정확한 정수 연산으로 $[0, \pi/4]$의 각에 접어요. 다른 점은 시스템의 `sin`, `cos`을 쓰지 않고 double-double의 테일러 급수로 구한다는 것이에요.

```cpp
    // csrc/fft/ddmath.hpp
    const double dn = static_cast<double>(num), dd = static_cast<double>(den);
    const double q = dn / dd;
    const double e = std::fma(-q, dd, dn) / dd;  // num - q den is exact
    const DD frac = quick_two_sum(q, e);
    const DD th = mul(frac, DD{kQuarterPiHi, kQuarterPiLo});
    const DD x2 = mul(th, th);
    constexpr int K = 15;  // terms through theta^31 / 31! and theta^30 / 30!
    DD ps{1.0, 0.0}, pc{1.0, 0.0};
    for (int k = K; k >= 1; --k) {
        ps = sub(DD{1.0, 0.0}, div(mul(x2, ps), static_cast<double>((2 * k) * (2 * k + 1))));
        pc = sub(DD{1.0, 0.0}, div(mul(x2, pc), static_cast<double>((2 * k - 1) * (2 * k))));
    }
    s = mul(th, ps);
    c = pc;
```

$\sin\theta = \theta\,(1 - \frac{\theta^2}{2\cdot 3}(1 - \frac{\theta^2}{4\cdot 5}(1 - \cdots)))$, $\cos\theta = 1 - \frac{\theta^2}{1\cdot 2}(1 - \frac{\theta^2}{3\cdot 4}(1 - \cdots))$를 안쪽부터 Horner 꼴로 계산해요. $\theta \le \pi/4$에서 $\theta^{31}/31!$까지 넣으면 버린 첫 항이 결과의 $2^{-110}$ 아래예요. 나누는 수 $(2k)(2k+1)$은 정확한 정수라 double-double을 double로 나누는 `div`를 써요.

### 제곱근 크기의 표 두 개

chirp는 $n$개, 핵의 변환은 길이 $m$의 DFT라 `cis`를 아주 많이 불러요. 매번 급수를 돌리는 대신 `CisTable`은 $B = \lceil \sqrt N \rceil$으로 $t = t_1 B + t_0$로 나눠 표 두 개(각각 약 $\sqrt N$칸)만 급수로 채워요.

```cpp
    // csrc/fft/ddmath.hpp
    DC operator()(int64_t t) const {
        const DC& c = coarse_[static_cast<size_t>(t / B_)];
        const DC& f = fine_[static_cast<size_t>(t % B_)];
        if (t % B_ == 0) return c;
        if (t < B_) return f;
        return cmul(c, f);
    }
```

$e^{-2\pi i t/N} = e^{-2\pi i t_1 B/N} \cdot e^{-2\pi i t_0/N}$이라 표에서 찾은 둘을 double-double 복소 곱 한 번으로 합쳐요. 한쪽이 1이면 곱하지 않아요.

### double-double DFT

`dd::dft`는 길이 $m$($2, 3, 4, 5$의 곱)의 DFT를 시간 솎음(decimation in time)으로 재귀해요. $m$을 4, 2, 3, 5 가운데 나누어지는 첫 기수 $r$로 쪼개 길이 $m/r$의 부분 DFT $r$개를 재귀로 구하고, 회전 인자 $W_m^{jk_1}$을 곱한 뒤 길이 $r$의 나비로 합쳐요. 회전 인자는 `CisTable`에서 찾고, 기수 3과 5의 나비는 $W_r^{jk}$를 곱하는 정의대로의 합이에요. 모든 연산이 double-double이에요.

### 왜 double-double인가

$\beta$를 double FFT로 구하면 안 되는 까닭이 있어요. 핵 $b$는 크기 1인 원소 $2n - 1$개이고, $\beta_k$는 그것들이 서로 상쇄하는 합이에요. double FFT의 오차는 노름으로만 묶여서 $\beta$ 원소 하나의 오차를 $u \log m \sqrt m \max\lvert\beta\rvert$ 정도로밖에 말할 수 없고, 그러면 아래 증명의 셋째 단계가 서지 않아요. double-double로 구한 뒤 한 번 반올림하면 $\hat\beta_k$는 $\beta_k$의 $u$ 안이에요(정확히는 $u\lvert\beta_k\rvert$ 더하기 $u \max\lvert\beta\rvert$보다 훨씬 작은 항). chirp도 같은 이유로 원소마다 $u$ 안이에요.

계획을 만드는 일은 혼합 기수의 계획보다 무거워요(double-double 연산은 double 연산 여러 개이고, 길이 $m$의 DFT를 한 번 해요). 그래서 계획은 캐시에 두고 다시 쓰며, 만드는 동안은 GIL을 놓아요([구조](/internals/fft/overview/)).

```cpp
// csrc/fft/plan.cpp
template <bool Swap>
void BluesteinPlan::run(const double* x, double* y, double* work) const {
    const int64_t n = n_, m = m_;
    double* const a = work;
    double* const b = work + 2 * m;
    double* const w = work + 4 * m;
    const double* const c = chirp_.data();
    const double* const be = beta_.data();
    // the products by chunks (a long line's on the pool; run_chunks: each entry alone, so no bit changes)
    run_chunks(n, [&](int64_t i0, int64_t i1) { cmul_line<Swap, false>(x + 2 * i0, c + 2 * i0, a + 2 * i0, i1 - i0); });
    std::memset(a + 2 * n, 0, static_cast<size_t>(2 * (m - n)) * sizeof(double));
    inner_.execute(a, b, w, false);
    run_chunks(m, [&](int64_t i0, int64_t i1) {
        cmul_line<false, false>(b + 2 * i0, be + 2 * i0, b + 2 * i0, i1 - i0);
    });
    inner_.execute(b, a, w, true);
    run_chunks(n, [&](int64_t i0, int64_t i1) { cmul_line<false, Swap>(a + 2 * i0, c + 2 * i0, y + 2 * i0, i1 - i0); });
}
```

- **작업 메모리는 $6m$개의 double이에요.** `a`와 `b`가 길이 $m$의 복소 배열 둘이고, `w`는 안쪽 계획의 작업 버퍼($2m$개)예요. 안쪽 변환은 `a`와 `b`를 번갈아 입력과 출력으로 써요.
- **복소 곱은 혼합 기수의 `cmul`과 같은 FMA 꼴이에요.** `cmul_line`은 이웃한 두 원소를 한 레지스터에 싣고, 길이가 홀수면 마지막 하나를 두 레인에 같은 값으로 실어요.
- **역변환은 바깥에서도 실수부와 허수부 바꾸기예요.** `Swap`이면 첫 곱이 읽을 때 입력을 바꾸고 마지막 곱이 쓸 때 결과를 바꿔요. 그 사이는 정변환과 같아요. 안쪽의 역변환(`execute(b, a, w, true)`)은 합성곱 정리의 $F^*$ 자리라 정변환이든 역변환이든 늘 같은 방향이에요.
- **긴 줄의 곱은 $2^{14}$칸씩 풀에서 나눠요.** 칸마다 따로 계산하는 일이라 어디서 끊어도 같은 비트예요. 안쪽 길이 $m$이 $2^{15}$ 이상이면 안쪽 변환이 4단계라 그 안도 풀에서 돌아요.

```python
>>> p = C._plan_info(65537)
>>> p["m"], p["n1"], p["radices"]
(131220, 324, [4, 3, 3, 3, 3, 3, 3, 3, 3, 5])
```

소수 65537은 $m = 131220 = 2^2 \cdot 3^8 \cdot 5$이고, 안쪽 변환이 $n_1 = 324$의 4단계예요.

### 사용자 수준에서 다시 해 보기

다섯 단계는 공개 함수로도 따라 할 수 있어요. $n = 37$이면 $2n - 1 = 73$ 이상인 가장 작은 5-매끄러운 수가 $m = 75 = 3 \cdot 5^2$이에요.

```python
>>> n, m = 37, 75
>>> rng = sd.random.default_rng(0)
>>> x = rng.random(n) + 1j * rng.random(n)
>>> j = sd.arange(n)
>>> w = sd.exp(-1j * sd.pi * (j * j % (2 * n)) / n)
>>> a = sd.zeros(m) + 0j
>>> a[:n] = x * w
>>> b = sd.zeros(m) + 0j
>>> b[:n] = sd.conj(w)
>>> b[m - n + 1:] = sd.conj(w[1:])[::-1]
>>> yb = w * sd.fft.ifft(sd.fft.fft(a) * sd.fft.fft(b))[:n]
>>> y = sd.fft.fft(x)
>>> nrm = lambda v: float(sd.sqrt(sd.sum(sd.abs(v) ** 2)))
>>> nrm(yb - y) / nrm(y) < 1e-14
True
```

라이브러리의 계획과 다른 점은 chirp와 핵의 변환을 double로 구했다는 것뿐이에요. 이 정도 길이에서는 결과가 거의 같지만, 그 차이가 증명할 수 있는 한계와 없는 한계를 가르는 차이예요.

## 오차 한계

정확한 분해를 행렬로 쓰면

$$
y = P\, D_w\, F^*\, D_\beta\, F\, E\, D_w\, x
$$

예요. $D_w$는 chirp의 대각, $E$는 0 채우기, $F$는 정규화 없는 길이 $m$의 DFT($F^*F = mI$), $D_\beta$는 $\beta$의 대각, $P$는 앞 $n$개를 고르는 것이에요. 계산은 이 다섯 사상을 차례로 반올림하며 지나가요. 단계마다 생기는 오차와 그것이 뒤의 사상을 지나며 커지는 배율을 모아요. $\lVert F \rVert = \lVert F^* \rVert = \sqrt m$, $\lVert D_\beta \rVert = \max\lvert\beta\rvert$이고, $\eta_m = \kappa\, u \log_2 m$은 길이 $m$의 혼합 기수가 지키는 상대오차예요.

1. **chirp 곱.** 저장한 chirp가 원소마다 $u$ 안이고 FMA 복소 곱이 $2u$라서 $\lVert \hat a - a \rVert \le 3.5u\, \lVert x \rVert$예요.
2. **정변환.** $\eta_m \sqrt m\, \lVert a \rVert$.
3. **$\beta$와의 곱.** $\hat\beta_k$가 $\beta_k$의 $u$ 안이고 복소 곱이 $2u$라서 $3u \max\lvert\beta\rvert\, \lVert Fa \rVert$. double-double로 구한 $\beta$의 오차는 계획을 만들 수 있는 길이에서 $2^{-80}\max\lvert\beta\rvert$ 아래라 이 $u$에 묻혀요.
4. **역변환.** $\eta_m \sqrt m\, \lVert D_\beta F a \rVert$.
5. **chirp 곱.** $3.5u\, \lVert y \rVert$.

앞 단계의 오차는 뒤의 사상을 지나며 $\sqrt m$, $\max\lvert\beta\rvert$, $\sqrt m$배 돼요. $\rho = m \max_k\lvert\beta_k\rvert / \sqrt n$으로 쓰고 $\lVert y \rVert = \sqrt n\,\lVert x \rVert$를 쓰면 모두가 $\lVert y \rVert$의 배수로 정리돼요.

$$
\lVert \hat y - y \rVert \le \big(\rho\,(2\kappa \log_2 m + 6.5) + 3.5\big)\, u\, \lVert y \rVert \le \rho\,\big(\kappa\,(2L(m) + 2) + c_0\big)\, u\, \lVert y \rVert
$$

계약은 오른쪽 꼴이에요. 혼합 기수의 $L(n)$ 자리에 $L_B(n) = 2L(m) + 2$가 오고 한계 전체에 $\rho$가 곱해져요. 역변환을 한 번 더 하니 수준 수가 두 배이고, $\rho$는 핵의 변환이 얼마나 큰지를 재요. $\rho \ge 1$은 늘 성립해요($\lVert y \rVert \le \lVert D_\beta \rVert\, m\, \lVert x \rVert$에서 나와요). 실제 값은 2 근처예요.

```python
>>> [(n, round(C._plan_info(n)["rho"], 3)) for n in (37, 1009, 4097, 10007)]
[(37, 2.195), (1009, 2.082), (4097, 2.145), (10007, 2.104)]
```

혼합 기수로 갈 수 있는 길이를 Bluestein으로 보내지 않는 까닭도 이 꼴에 있어요. 수준 수가 두 배에 $\rho \approx 2$가 곱해지니, 기수 31의 단이 있는 혼합 기수의 넓은 한계($\kappa = 17$)보다도 모든 길이에서 넓어요.

## 메모리와 비용

| 항목 | 크기 |
|---|---|
| chirp | $n$개의 복소수, $16n$바이트 |
| $\beta$ | $m$개의 복소수, $16m$바이트 |
| 안쪽 계획 | 길이 $m$의 혼합 기수 계획, 약 $16m$바이트 |
| 줄마다의 작업 버퍼 | $6m$개의 double |

$m \approx 2n$이라 계획은 $n$의 원소 하나에 약 81바이트예요. 한 줄의 비용은 계획이 구동기에 $2m\lceil\log_2 m\rceil + 4m$으로 알려 줘요(변환 둘과 곱 셋). 구동기는 그 값으로 줄을 태스크로 나눠요.

```python
>>> C._plan_info(1009)["bytes"], C._plan_info(1009)["cost"]
(81576, 52650)
```
