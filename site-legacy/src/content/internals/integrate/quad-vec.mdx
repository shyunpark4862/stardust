## 한눈에 보기

`quad_vec`은 수 또는 배열을 돌려주는 f의 적분이에요. 원소마다 `quad`를 따로 부르지 않고, 모든 원소가 한 벌의 구간을 함께 써요. 점 하나에서 f를 한 번 부르면 모든 원소의 값이 한꺼번에 오므로, 원소가 많고 모양이 비슷한 피적분 함수(매개변수만 다른 함수의 묶음)에서 호출이 크게 줄어요.

알고리즘은 scipy의 Python 판 `_quad_vec.py`이고, 커널(`csrc/integrate/adaptive.cpp`의 `quad_vec_solve`)이 그 걸음을 그대로 따라가요. 같은 21점·15점 Gauss–Kronrod 마디를 쓰지만 QUADPACK과는 몇 가지가 달라요.

| | `quad` (QAGS) | `quad_vec` |
|---|---|---|
| 값 | 수 하나 | 수 또는 배열 |
| 오차 어림 | \|K − G\|의 경험식과 반올림 하한 | 같은 경험식을 노름으로, 반올림 오차는 따로 쌓아 더함 |
| 한 바퀴에 나누는 구간 | 하나 | 오차가 큰 것부터 128개까지 |
| 외삽 | ε-알고리즘 | 없음 |
| 멈춤 | 오차 합 ≤ max(atol, rtol·\|I\|) | 오차 합 < max(atol, rtol·‖I‖)/8 |
| 산술 | QUADPACK C 판의 FMA 그대로 | numpy·Python의 것(FMA 없음) |
| 기본 허용오차 | atol = rtol = 1.49×10⁻⁸ | atol = 10⁻²⁰⁰, rtol = 10⁻⁸ |

```python
>>> import math
>>> r = sd.integrate.quad_vec(lambda x: [x, x * x, math.exp(x)], 0, 1)
>>> r
IntegrateResult(integral=[0.5, 0.333333, 1.71828], error=6.08947e-14, converged=True, nfev=63)
>>> r.n_intervals, r.message
(2, 'Target precision reached.')
```

## 한 구간의 규칙

`gk`는 scipy의 `_quadrature_gk`예요. 마디는 큰 것부터(scipy의 표 순서) 부르고, 값마다 원소 m개를 들어요.

```cpp
    // csrc/integrate/adaptive.cpp
    void gk(double a, double b, const double* x, const double* w, const double* v, std::size_t n, RuleOut& out) {
        const double c = 0.5 * (a + b), h = 0.5 * (b - a);
        nfev += static_cast<std::int64_t>(n);
        if (!evaluate(n, [&](std::size_t i) { return c + h * x[i]; })) {
            out.ig.clear();  // all 0 (scipy: the Python float 0.0)
            out.err = out.rnd = 0.0;
            return;
        }
        const std::size_t m = fn.m;
        vec sk(m, 0.0), ska(m, 0.0), sg(m, 0.0), sda(m, 0.0);
        for (std::size_t i = 0; i < n; ++i) {
            const double vv = v[i];
            const double* ff = vals[i].data();
            for (std::size_t j = 0; j < m; ++j) {
                sk[j] += vv * ff[j];
                ska[j] += vv * std::abs(ff[j]);
            }
        }
        for (std::size_t i = 0; i < n / 2; ++i) {
            const double* ff = vals[2 * i + 1].data();
            for (std::size_t j = 0; j < m; ++j) sg[j] += w[i] * ff[j];
        }
        for (std::size_t i = 0; i < n; ++i) {
            const double* ff = vals[i].data();
            for (std::size_t j = 0; j < m; ++j) sda[j] += v[i] * std::abs(ff[j] - sk[j] / 2.0);
        }
        double err = norm_by([&](std::size_t j) { return (sk[j] - sg[j]) * h; });
        const double dabs = norm_by([&](std::size_t j) { return sda[j] * h; });
        if (dabs != 0 && err != 0) err = dabs * pymin(1.0, std::pow(200 * err / dabs, 1.5));
        const double s = (50 * kEps) * h;
        const double rnd = norm_by([&](std::size_t j) { return s * ska[j]; });
        if (rnd > kTiny) err = pymax(err, rnd);
        out.ig.resize(m);
        for (std::size_t j = 0; j < m; ++j) out.ig[j] = h * sk[j];
        out.err = err;
        out.rnd = rnd;
    }
```

네 합은 [21점 규칙](/internals/integrate/gauss-kronrod/)의 `resk`, `resabs`, `resg`, `resasc`와 같은 뜻이에요. 다른 점은 셋이에요.

- **노름.** 원소마다의 |K − G|, ∫|f − 평균|, 50ε·∫|f|를 원소 m개의 벡터로 보고 노름 하나로 줄여요. `norm='2'`면 유클리드 노름, `'max'`면 최대 절댓값, 값이 수면 둘 다 절댓값이에요. 경험식 $R\min(1, (200E_0/R)^{3/2})$은 그 노름들 사이에서 계산해요.
- **반올림 오차를 따로.** 반올림 하한 `rnd`를 오차 어림의 하한으로 쓸 뿐 아니라, 구간마다의 값을 전체 반올림 오차 `re`로 따로 쌓아요. 결과의 `error`는 구간 오차의 합에 이 반올림 오차의 합을 더한 것이고, 구간 오차의 합이 반올림 오차의 합보다 작아지면 status 2로 멈춰요.
- **산술.** 곱과 합이 따로 반올림돼요. scipy 쪽이 Python의 `s_k += vv * ff`(numpy 배열이면 numpy의 원소별 연산)라서 FMA가 없어요. stardust의 빌드는 축약을 끄므로 위의 코드가 그대로 그 산술이에요.

```python
>>> pts = []
>>> def g(x):
...     pts.append(x)
...     return math.exp(x)
>>> r = sd.integrate.quad_vec(g, 0, 1)
>>> len(pts), pts[:3]
(63, [0.997828581512904, 0.9869532642585859, 0.9650787456778541])
```

QUADPACK의 `dqk21`이 가운데부터 부르는 것과 달리 가장 큰 마디부터 차례로 불러요. 매끄러운 exp인데도 63번인 것은 아래의 멈춤 판정이 구간이 둘 이상일 때만 보기 때문이에요. 첫 규칙 21번 뒤에 적어도 한 번은 나눠요.

## 한 바퀴: 힙에서 꺼내 나누기

구간은 Python `heapq`와 같은 힙에 (−오차, a, b)의 튜플로 들어 있어요. 한 바퀴는 오차가 큰 구간을 여럿 꺼내 모두 반으로 나눠요.

```cpp
        // csrc/integrate/adaptive.cpp
        while (!heap.empty() && static_cast<std::int64_t>(heap.size()) < limit) {
            double tol = pymax(epsabs, epsrel * norm_gi());
            jobs.clear();
            double err_sum = 0;
            for (int j = 0; j < 128; ++j) {
                if (heap.empty()) break;
                if (j > 0 && err_sum > ge - tol / 8) break;
                const Item it = heappop(heap, item_lt);
                Job jb{-it.ne, it.x1, it.x2, false, {}};
                jb.have = cache->pop(it.x1, it.x2, jb.old_int);
                err_sum += -it.ne;
                jobs.push_back(std::move(jb));
            }
```

꺼내기는 꺼낸 구간의 오차 합 `err_sum`이 전체 오차 `ge`에서 tol/8을 뺀 것을 넘으면 멈춰요. 남은 구간의 오차가 tol/8 아래라는 뜻이라, 꺼낸 것들만 줄이면 멈춤 판정에 닿을 수 있어요. 한 번에 128개까지라 오차가 고르게 퍼진 피적분 함수에서도 바퀴 수가 작아요.

꺼낸 구간마다 두 반쪽에 규칙을 쓰고, 전체 값 `gi`·전체 오차 `ge`·반올림 오차 `re`를 차이로 고쳐요(`gi += s₁ + s₂ − s_old`). QUADPACK처럼 끝에 구간 값을 다시 더하지 않아요. scipy도 고친 값을 그대로 결과로 내요. 한 바퀴가 끝나면 판정해요.

```cpp
            // csrc/integrate/adaptive.cpp
            if (heap.size() >= 2) {
                tol = pymax(epsabs, epsrel * norm_gi());
                if (ge < tol / 8) {
                    ier = 0;
                    break;
                }
                if (ge < re) {
                    ier = 2;
                    break;
                }
            }
            if (!(std::isfinite(ge) && std::isfinite(re))) {
                ier = 3;
                break;
            }
        }
```

| status | message | 조건 |
|---|---|---|
| 0 | `Target precision reached.` | 오차 합 < max(atol, rtol·‖I‖)/8 |
| 1 | `Target precision not reached.` | 구간 수가 `limit`에 닿음(한 바퀴에 여럿을 나누므로 조금 넘을 수 있어요) |
| 2 | `Target precision could not be reached due to rounding error.` | 오차 합 < 반올림 오차 합 |
| 3 | `Non-finite values encountered.` | 오차나 반올림 오차가 유한하지 않음 |

힙의 비교는 Python 튜플의 비교와 같아야 해요. 오차가 같으면 a, 그다음 b로 가르고, NaN이 섞이면 Python의 규칙대로 거짓이 되어야 같은 구간이 같은 차례로 나와요.

```cpp
// csrc/integrate/adaptive.cpp
struct Item {
    double ne, x1, x2;
};
inline bool item_lt(const Item& p, const Item& q) {
    if (!(p.ne == q.ne)) return p.ne < q.ne;
    if (!(p.x1 == q.x1)) return p.x1 < q.x1;
    if (!(p.x2 == q.x2)) return p.x2 < q.x2;
    return false;
}
```

`heappush`·`heappop`도 CPython의 C 모듈과 같은 `siftdown`·`siftup`이라, 같은 비교로 같은 자리를 골라요. 결과의 구간 필드는 끝에 힙에서 꺼내는 차례(오차가 큰 것부터)예요.

## 외삽이 없을 때

QAGS와 견주면 끝점 특이점에서 차이가 커요.

```python
>>> s = lambda x: x**-0.5 * math.log(1 / x)
>>> sd.integrate.quad(s, 0, 1)
IntegrateResult(integral=4, error=2.6823e-13, converged=True, nfev=315)
>>> r = sd.integrate.quad_vec(s, 0, 1)
>>> r, r.n_intervals
(IntegrateResult(integral=4, error=3.99145e-09, converged=True, nfev=2835), 68)
```

`quad`는 8구간에서 [ε-알고리즘](/internals/integrate/adaptive-extrapolation/)으로 극한을 어림하지만, `quad_vec`은 0 둘레를 실제로 잘게 나눠 오차를 줄여야 해서 68구간이 들어요. 특이점이 없는 좁은 봉우리에서는 둘이 비슷해요.

```python
>>> peak = lambda x: 1 / (x * x + 1e-6)
>>> sd.integrate.quad(peak, -1, 1).nfev, sd.integrate.quad_vec(peak, -1, 1).nfev
(819, 819)
```

## 무한 구간

무한 구간은 scipy의 치환으로 유한 구간이 돼요. 커널의 `VecFn`이 사용자 함수를 감싸 바꾼 피적분 함수를 내요.

```cpp
    // csrc/integrate/adaptive.cpp
    bool operator()(double t, vec& out) {
        if (transform == kFinite) {
            call(t, out);
            return true;
        }
        if (transform == kSemi) {
            if (t < tmin) return false;
            const double x = start + (sgn * (1 - t)) / t;
            call(x, out);
            for (auto& v : out) v = (sgn * (v / t)) / t;
            return true;
        }
        if (std::abs(t) < tmin) return false;
        const double x = (1 - std::abs(t)) / t;
        call(x, out);
        for (auto& v : out) v = (v / t) / t;
        return true;
    }
```

반무한 구간은 t ∈ (0, 1]에서 x = start ± (1 − t)/t, 실수 전체는 t ∈ [−1, 1]에서 x = (1 − |t|)/t이고 t = 0에서 처음 구간을 나눠요. |t|가 √(DBL_MIN)보다 작으면 f를 부르지 않고 값을 0으로 둬요(호출 수에는 세요). `points`도 같은 치환으로 t로 바꿔요. 무한 구간의 기본 규칙은 15점이에요.

```python
>>> r = sd.integrate.quad_vec(lambda x: math.exp(-x * x), -math.inf, math.inf)
>>> r
IntegrateResult(integral=1.77245, error=6.93253e-10, converged=True, nfev=330)
>>> print(r.intervals[:2])
[[ -0.25 -0.125]
 [ 0.125   0.25]]
```

## scipy의 구간 기억

scipy는 구간의 적분값을 크기가 정해진 LRU 사전에 기억해요. 구간을 나눌 때 옛 값 s_old가 있어야 `gi`를 차이로 고칠 수 있기 때문이에요. 크기는 100×10⁶바이트를 첫 적분값의 `sys.getsizeof`로 나눈 개수예요(Python float 24, numpy 수 32, 배열 96 + 16·차원 수 + 8·원소 수바이트). 넘치면 오래 쓰지 않은 것부터 버리고, 버린 구간을 나눌 차례가 오면 그 구간에 규칙을 한 번 더 써서 옛 값을 다시 계산해요(함숫값 21개나 15개 더).

커널의 `Lru`는 같은 크기, 같은 버리는 차례예요. 그래서 원소가 아주 많은 배열 값에서도 부르는 점과 호출 수가 scipy와 같고, 기억이 100 MB를 넘지 않아요. 결과의 `interval_integrals`에서 버린 구간의 칸은 NaN이에요.

```cpp
// csrc/integrate/adaptive.cpp
class Lru {
public:
    explicit Lru(std::int64_t max) : max_(max) {}
    void set(double x1, double x2, vec v) {
        const Key k{x1 + 0.0, x2 + 0.0};
```

열쇠에 0.0을 더하는 것은 −0.0을 0.0으로 바꾸려는 것이에요. Python의 float 열쇠는 −0.0과 0.0이 같은 열쇠이므로 비트로 견주는 C++의 해시도 그렇게 맞춰요.

## 사다리꼴 규칙

`quadrature='trapezoid'`는 구간 [x₁, x₂]에서 끝 둘과 가운데 x₃를 불러요. 패널 둘의 사다리꼴 $s_2 = \tfrac{x_2 - x_1}{4}(f_1 + 2f_3 + f_2)$가 값이고, 패널 하나의 $s_1 = \tfrac{x_2 - x_1}{2}(f_1 + f_2)$와의 차로 오차를 어림해요. 사다리꼴의 오차는 h²에 비례하므로 $s_2$의 오차는 $(s_1 - s_2)/3$쯤이에요(Richardson의 생각).

나눌 때 두 반쪽이 가운데 점을 함께 쓰고, 부모의 값을 다시 계산하면 같은 끝점들이 또 나와요. scipy는 나누기 하나마다 `lru_cache`로 같은 점을 한 번만 부르고, 커널도 나누기마다 부른 점의 목록을 들고 같은 점을 다시 부르지 않아요. 사다리꼴은 차수가 낮아서 매끄러운 함수에서도 구간이 많이 들어요.

```python
>>> r = sd.integrate.quad_vec(math.exp, 0, 1, quadrature='trapezoid')
>>> r.nfev, r.n_intervals
(20443, 4089)
```

## numpy의 산술

scipy의 `quad_vec`은 Python 코드라 그 산술은 numpy와 Python의 것이에요. 커널은 그 연산을 차례까지 따라 해요.

- 곱과 합은 따로 반올림해요(FMA 없음).
- `min`·`max`는 Python의 `min(a, b)`·`max(a, b)`처럼 b가 더 작을(클) 때만 b로 바꿔요(`pymin`·`pymax`). NaN이 섞일 때의 결과가 이것으로 정해져요.
- `norm='2'`는 numpy `linalg.norm`이에요. 원소 하나면 √(x·x), 둘 이상이면 √(0.0 + ddot(x, x))이고 ddot은 Accelerate의 `cblas_ddot`이에요. 이 함수는 원소 897개부터 벡터의 주소 정렬에 따라 끝자리가 달라져요. numpy의 임시 배열은 256바이트 정렬이라 scipy 자신도 실행마다 다를 수 있어요. 커널은 값을 페이지 정렬(4096바이트) 버퍼에 복사해 부르므로(`PageBuffer`) 결과가 결정적이고, numpy의 배열이 페이지 정렬일 때의 값과 같아요.
- 경험식의 `** 1.5`는 Python에서 넘치면 `OverflowError`인데, 커널은 inf로 이어 가서 min(1, inf) = 1이 돼요. scipy가 에러를 내는 드문 경우에도 값을 내요.

<Callout title="값의 모양은 첫 호출이 정해요">
f가 처음 돌려준 값이 수면 `integral`은 Python 수, 배열이면 그 모양의 읽기 전용 `sd.ndarray`예요. 다음 호출에서 모양이 바뀌면 `ValueError`예요. 값은 늘 float64로 계산해요.
</Callout>
