## 사용자 함수를 부르는 자리

f는 Python `float` 하나를 받아요. 돌려받은 값이 정확히 `float`이면 그대로 쓰고, 아니면 Python의 `_scalar_check`가 바꾸거나(numpy의 수, 0차원 배열) 에러를 내요(문자열, `None`, complex, bool, 길이 있는 배열). 대부분의 f는 `float`를 돌려주므로 확인 비용은 그 한 번의 형 검사뿐이에요.

```cpp
// csrc/optimize/scalar.cpp
struct Fn {
    nb::handle f, check;
    const char* what;
    std::int64_t n = 0;

    double operator()(double x) {
        nb::object r = f(x);
        ++n;
        if (PyFloat_CheckExact(r.ptr())) return PyFloat_AS_DOUBLE(r.ptr());
        nb::object c = check(r, what);
        return PyFloat_AsDouble(c.ptr());
    }
};
```

반복 전체가 GIL을 쥔 채 돌아요. 사용자 함수가 Python이라 GIL을 놓을 자리가 없고, 반복 사이의 계산은 몇 백 ns라 놓았다 다시 잡는 비용이 더 커요. f 안에서 난 예외는 그대로 위로 나가요.

## 이분법: bisect

근을 끼는 구간 [a, b]의 가운데 m에서 f의 부호를 보고, 근을 끼는 반을 남겨요. f가 연속이면 중간값 정리로 구간이 늘 근을 끼므로 반드시 수렴하고, 반복 k번 뒤 구간 폭이 정확히 $(b - a)/2^k$예요. f의 값은 부호만 쓰므로 f의 모양과 상관없이 걸음이 같아요. 대신 f 한 번에 1비트만 얻어서 느려요.

```cpp
    // csrc/optimize/scalar.cpp
    dm = xb - xa;
    for (std::int64_t i = 0; i < iter; i++) {
        o.iterations++;
        dm *= .5;
        xm = xa + dm;
        fm = f(xm);
        if (std::isnan(fm)) {
            o.x = xm;
            o.status = rValueErr;
            return o;
        }
        if (std::signbit(fm) == std::signbit(fa)) xa = xm;
        if (fm == 0 || std::abs(dm) < std::fma(rtol, std::abs(xm), xtol)) {
            o.x = xm;
            return o;
        }
    }
```

scipy의 C 코드를 그대로 옮긴 것이라 몇 가지가 교과서와 달라요.

- 가운데 점을 $(a + b)/2$로 계산하지 않고, 걸음 `dm`을 반씩 줄이며 $x_a + dm$으로 계산해요. 왼쪽 끝 `xa`만 움직이고 걸음의 크기는 정확히 2의 거듭제곱 분의 1로 줄어요.
- 부호의 비교는 곱 `fm * fa`가 아니라 두 값의 부호 비트(`std::signbit`)예요. 곱으로 보면 두 값이 아주 작을 때($\lvert f\rvert < 10^{-162}$ 남짓) 곱이 0으로 아래넘침해 같은 부호로 읽히고, 구간이 한쪽 끝으로만 줄어요. 부호 비트로 보면 그런 f에서도 맞게 갈라요. 처음 구간이 근을 끼는지도 같은 식으로 봐요. $f = 10^{-200}(x - 1.3)$을 (1, 2)에서 풀면 scipy와 같은 1.3000000000010914예요.
- 멈춤은 줄인 걸음 `dm`이 $\text{xtol} + \text{rtol}\cdot|x_m|$보다 작을 때예요. 근과의 거리는 많아야 남은 구간 폭이에요.

scipy는 이 C 파일을 clang의 기본값(`-ffp-contract=on`)으로 빌드해서 $\text{rtol}\cdot|x_m| + \text{xtol}$을 곱셈과 덧셈을 한 번에 반올림하는 FMA로 계산해요. stardust는 축약을 끄고 빌드하므로(`-ffp-contract=off`) 같은 자리를 `std::fma`로 적어요. 그래서 판정의 경계에 걸리는 경우에도 scipy와 같은 반복에서 멈춰요.

## Brent법: brentq

### 생각

이분법은 안전하지만 느리고, 할선법이나 보간은 빠르지만 구간 밖으로 튈 수 있어요. Brent법(Brent 1973, Dekker의 방법을 고친 것)은 둘을 섞어요. 세 점을 들고 다녀요.

- `xcur`(b): 지금까지 |f|가 가장 작은 점. 답의 후보예요.
- `xblk`(c, contrapoint): f의 부호가 `xcur`와 반대인 점. [xcur, xblk]가 늘 근을 껴요.
- `xpre`(a): 직전의 `xcur`.

반복마다 다음 걸음 후보를 보간으로 만들어요. `xpre`와 `xblk`가 같으면(점이 둘뿐) 두 점의 직선(할선), 다르면 세 점의 **역 2차 보간**이에요. 역 2차 보간은 x를 y의 2차식 $x = q(y)$로 세 점에 맞추고 $q(0)$을 근의 어림으로 삼아요. y의 함수로 맞추므로 근 $q(0)$이 늘 하나로 정해지고, 2차 방정식을 풀 필요가 없어요. 세 점의 나눗셈 차분으로 쓰면

$$
q(0) = x_c - \frac{f_c}{d_p} + \frac{f_c f_p (d_p - d_b)}{d_b\, d_p\, (f_b - f_p)},
\qquad d_p = \frac{f_p - f_c}{x_p - x_c},\quad d_b = \frac{f_b - f_c}{x_b - x_c}
$$

이고(c는 cur, p는 pre, b는 blk), 정리하면 걸음 $s = q(0) - x_c$가

$$
s = -f_c\,\frac{f_b d_b - f_p d_p}{d_b\, d_p\, (f_b - f_p)}
$$

예요. scipy의 C 코드가 쓰는 이 꼴은 교과서(Numerical Recipes의 p/q 꼴)와 식이 달라도 같은 다항식의 값이에요.

### 안전장치

보간 걸음은 두 조건을 모두 만족할 때만 받아요.

$$
2|s| < |s_{\text{prev}}|
\qquad\text{그리고}\qquad
2|s| < 3|s_{\text{bis}}| - \delta
$$

$s_{\text{prev}}$는 두 반복 전의 걸음, $s_{\text{bis}} = (x_b - x_c)/2$는 이분 걸음, δ는 허용오차의 반이에요. 첫 조건은 걸음이 두 반복마다 적어도 반으로 줄게 하고, 둘째는 새 점이 구간의 3/4 안쪽에 들게 해요. 하나라도 어기면 그 반복은 이분해요. 또 직전 걸음이 δ 이하였거나 |f|가 줄지 않았으면 보간을 시도하지 않고 이분해요. 그래서 보간이 잘 맞지 않는 함수에서도 걸음이 이분법보다 크게 느려지지 않아요. Brent는 이 방법의 f 계산이 이분법의 계산 수 N에 대해 많아야 대략 $N^2$이라고 보였어요.

걸음이 δ보다 작으면 δ만큼 움직여요. 근 바로 옆에서 걸음이 반올림 크기로 줄어 같은 점을 되풀이하지 않게 하는 장치예요. 멈춤은 근을 끼는 구간의 반 $|s_{\text{bis}}|$가 δ보다 작을 때예요.

```cpp
        // csrc/optimize/scalar.cpp
        delta = std::fma(rtol, std::abs(xcur), xtol) / 2;
        sbis = (xblk - xcur) / 2;
        if (fcur == 0 || std::abs(sbis) < delta) {
            o.x = xcur;
            return o;
        }
        if (std::abs(spre) > delta && std::abs(fcur) < std::abs(fpre)) {
            if (xpre == xblk) {
                stry = -fcur * (xcur - xpre) / (fcur - fpre);  // interpolate
            } else {
                dpre = (fpre - fcur) / (xpre - xcur);  // extrapolate
                dblk = (fblk - fcur) / (xblk - xcur);
                stry = -fcur * std::fma(fblk, dblk, -(fpre * dpre)) / (dblk * dpre * (fblk - fpre));
            }
            if (2 * std::abs(stry) < std::min(std::abs(spre), std::fma(3, std::abs(sbis), -delta))) {
                spre = scur;  // good short step
                scur = stry;
            } else {
                spre = sbis;  // bisect
                scur = sbis;
            }
        } else {
            spre = sbis;  // bisect
            scur = sbis;
        }
        xpre = xcur;
        fpre = fcur;
        if (std::abs(scur) > delta) xcur += scur;
        else xcur += (sbis > 0 ? delta : -delta);
```

### scipy와 같은 FMA의 자리

scipy의 `brentq.c`도 clang의 기본 빌드라 컴파일러가 a·b + c 꼴을 FMA로 묶어요. 보간의 분자 $f_b d_b - f_p d_p$가 그 자리예요. 이 자리를 `fma(fblk, dblk, -(fpre * dpre))`로 적어서, 지금 시험 문제 204개 모두에서 f를 부르는 점이 scipy와 비트까지 같아요. 축약 없이 계산하면 192개만 같고(12개는 호출점이 끝자리에서 갈리고, 그 가운데 7개는 근이 달라져요. 가장 큰 차이는 근이 10⁻¹⁶ 근처인 문제의 상대 10⁻¹⁰), 반대쪽 곱을 묶으면 185개만 같아요. 판정의 $\text{rtol}\cdot|x| + \text{xtol}$과 $3|s_{\text{bis}}| - \delta$도 clang이 같은 꼴로 묶으므로 `std::fma`로 적어요. 이 둘은 시험 문제에서는 결과를 바꾸지 않아요.

## TOMS 748: toms748

### 생각

Alefeld, Potra, Shi(1995, ACM TOMS 알고리즘 748)는 구간법의 효율을 끝까지 끌어올린 방법이에요. Brent법은 보간 걸음이 근에 빨리 다가가도 구간의 반대쪽 끝은 오래 남아 있을 수 있는데, 이 방법은 반복마다 구간 폭이 근에 다가가는 빠르기 그대로 줄도록 걸음을 짜요. 반복 하나는 이래요(k = 1, 알고리즘 4.1).

1. **보간 걸음**: 구간의 두 끝 a, b와 앞의 두 점 d, e, 네 점의 f가 서로 충분히 다르면(모두 0이 아니고 유한하며, 어느 둘도 32ε 안이 아니면) 네 점의 **역 3차 보간** $x = p(y)$의 $p(0)$을 써요. 그 점이 구간 밖이거나 점이 셋뿐이면, a, b, d를 지나는 2차식 $P(x)$의 근을 Newton법 몇 걸음으로 구해요(**Newton 이차 걸음**).
2. **두 배 할선 걸음**: |f|가 작은 끝 u에서 $c = u - 2 f(u)/A$로 가요($A$는 두 끝의 기울기). 보통의 할선보다 두 배 멀리 가서 근 너머로 넘어가게 하는 걸음이에요. 그래야 다음 반복에 근을 끼는 반대쪽 끝이 바뀌어 구간이 양쪽에서 줄어요.
3. **이분**: 이 반복의 걸음들이 구간을 반 넘게 줄이지 못했으면 가운데에서 한 번 더 계산해요.

k = 2(알고리즘 4.2)이면 1의 보간 걸음을 두 번 해요. 역 3차 보간은 Neville 알고리즘으로 계산하고, 그 합의 순서도 scipy(numpy)와 같아요.

```cpp
        // csrc/optimize/scalar.cpp
        // u is the end with the smaller |f|
        const int uix = std::abs(fab_[0]) < std::abs(fab_[1]) ? 0 : 1;
        const double u = ab_[uix], fu = fab_[uix];
        const double A = (fab_[1] - fab_[0]) / (ab_[1] - ab_[0]);
        c = u - 2 * fu / A;
        if (std::abs(c - u) > 0.5 * (ab_[1] - ab_[0])) {
            c = mid();
        } else if (isclose(c, u, kEps, 0)) {
            // c didn't change (much): the ends' f differ vastly, or the root is next to u
            int e0, e1;
            std::frexp(fab_[uix], &e0);
            std::frexp(fab_[1 - uix], &e1);
            if (e0 < e1 - 50) {
                c = (31 * ab_[uix] + ab_[1 - uix]) / 32;
            } else {
                const double mm = uix == 0 ? 1 : -1;
                const double adj = mm * std::abs(c) * rtol_ + mm * xtol_;
                c = u + adj;
            }
            if (!(ab_[0] < c && c < ab_[1])) c = mid();
        }
```

두 배 할선 걸음에는 두 가지 예외가 있어요. 걸음이 구간 폭의 반보다 크면 가운데로 가요. 걸음이 u에서 거의 움직이지 않으면(상대 ε 안), 두 끝의 f 크기가 2⁵⁰배 넘게 차이 날 때는 u 쪽으로 31:1인 점을, 아니면 u에서 허용오차만큼 떨어진 점을 써요. 근이 u에 바짝 붙었거나 반대쪽 끝의 f가 지나치게 커서 할선이 쓸모없을 때 구간을 확실히 줄이는 장치예요.

### 수렴

f가 네 번 연속 미분 가능하면, k = 1에서 수렴 차수가 적어도 2.7이고 반복마다 f를 점근적으로 두 번 불러서 효율 지수(차수의 (호출 수)제곱근)가 약 1.65예요. k = 2이면 차수 약 4.6, 호출 세 번, 효율 지수 1.66이고, 이것이 그런 함수에 대해 알려진 방법 가운데 점근적으로 가장 효율적이에요. k가 더 커지면 효율 지수가 $(3k - 2)^{1/k}$에 다가가 오히려 줄어요. 비교하면 할선법이 1.618, Newton법은 f와 f′를 각각 세어 √2 ≈ 1.414예요.

멈춤은 $|a - b| \le \text{xtol} + \text{rtol}\cdot|b|$(numpy `isclose`)일 때이고, 구간의 가운데를 돌려줘요. f가 구간의 한 점에서 정확히 0이면 그 점이에요.

### 유한하지 않은 값

toms748은 f의 값으로 보간하므로 NaN이나 ±inf가 섞이면 걸음을 정할 수 없어요. scipy는 NaN이면 그 점에서 멈춰 결과를 돌려주고(`_wrap_nan_raise`), ±inf이면 `ValueError`를 내요. stardust는 ±inf도 NaN처럼 그 점에서 멈추고 `status` −3을 돌려줘요. 구간의 끝에서 그래도 같아요. 커널은 이 멈춤을 C++ 예외 `Stop`으로 반복을 빠져나와 결과로 바꿔요.

## Newton, Halley, 할선법

### 걸음

$$
\text{Newton: } x_{k+1} = x_k - \frac{f}{f'}, \qquad
\text{Halley: } x_{k+1} = x_k - \frac{f/f'}{1 - \dfrac{f f''}{2f'^2}}, \qquad
\text{할선: } x_{k+1} = x_k - f_k\,\frac{x_k - x_{k-1}}{f_k - f_{k-1}}
$$

Newton법은 f를 그 점의 접선으로, Halley법은 2차 테일러 다항식(의 유리 근사)으로 바꿔 그 근으로 가요. 할선법은 접선의 기울기를 마지막 두 점의 차분으로 바꾼 것이에요.

근 $x^*$가 단순근($f'(x^*) \ne 0$)이고 f가 매끈하면, 오차 $e_k = x_k - x^*$는

$$
e_{k+1} \approx \frac{f''}{2f'}\,e_k^2 \;(\text{Newton}), \qquad
e_{k+1} \approx \frac{f''}{2f'}\,e_k e_{k-1} \;(\text{할선})
$$

으로 줄어요. 할선법의 차수는 $p^2 = p + 1$의 근 $p = (1 + \sqrt5)/2$예요. Halley법은 3차예요. 근이 m중근이면 Newton법은 1차로 떨어지고 비가 $(m-1)/m$이에요. 삼중근 $(x - 1)^3$에서는 오차가 반복마다 2/3배라 x0 = 3에서 45번이 걸려요.

```cpp
        // csrc/optimize/scalar.cpp
        if (fprime) {
            fder = (*fprime)(p0);
        } else {  // scipy's approx_derivative '2-point' (its f(p0) is fval)
            const double h = differentiate::absolute_step(p0, rstep, false, 0.0);
            const double x1 = p0 + h;
            fder = (f(x1) - fval) / (x1 - p0);
        }
        if (fder == 0) {
            o.x = p0;
            o.iterations = itr + 1;
            o.status = rConvErr;
            o.reason = kDerivZero;
            return o;
        }
        double newton_step = fval / fder;
        if (fprime2) {  // Halley's method, only when the denominator stays near 1
            const double fder2 = (*fprime2)(p0);
            const double adj = newton_step * fder2 / fder / 2;
            if (std::abs(adj) < 1) newton_step /= 1.0 - adj;
        }
        p = p0 - newton_step;
```

Halley 걸음은 보정 $\frac{f f''}{2f'^2}$의 절댓값이 1보다 작을 때만 Newton 걸음을 나눠요. 분모가 0이나 음수가 되어 걸음이 튀거나 방향이 바뀌는 것을 막는 scipy의 장치예요. 도함수가 정확히 0이면 걸음을 정할 수 없어 그 점에서 멈추고 `status` −2, `message` `'Derivative was zero.'`예요.

### 차분 도함수

`fprime` 없이 Newton법을 쓰면 도함수를 scipy `approx_derivative`의 2점 전진 차분으로 어림해요.

$$
f'(x) \approx \frac{f(x + h) - f(x)}{(x + h) - x}, \qquad h = \sqrt{\varepsilon}\,\operatorname{sign}(x)\max(1, |x|),\ \varepsilon = 2^{-52}
$$

간격 $\sqrt\varepsilon = 2^{-26}$은 절단 오차($\propto h$)와 반올림 오차($\propto \varepsilon/h$)의 합을 가장 작게 하는 크기예요. 분모를 $h$가 아닌 $(x + h) - x$로 쓰는 것은 $x + h$를 반올림한 실제 간격으로 나누기 위해서예요. 그래도 도함수는 상대 $10^{-8}$쯤의 오차를 품어서, 근 근처의 수렴이 2차에서 아주 빠른 1차로 바뀌어요. scipy는 차분 안에서 f(x)를 한 번 더 부르지만 반복이 이미 계산한 값과 같은 점, 같은 값이라 stardust는 그 값을 다시 써요. 그래서 반복 하나에 f를 두 번(f(x)와 f(x + h)) 불러요.

### 멈춤

세 방법 모두 마지막 걸음이 $|x_{k+1} - x_k| \le \text{xtol} + \text{rtol}\cdot|x_k|$(numpy `isclose`)이면 멈춰요. f가 정확히 0인 점에서도 멈춰요. 이 판정은 걸음의 크기라서 근과의 거리를 직접 보장하지 않아요. 2차 수렴이면 마지막 걸음 뒤의 오차가 대략 걸음의 제곱이라 xtol보다 훨씬 작지만, 1차 수렴(비 r)이면 오차가 대략 걸음 × r/(1 − r)이라 xtol보다 클 수 있어요. 위의 삼중근에서 r = 2/3이라 남은 오차(2.4×10⁻⁸)가 xtol(1.48×10⁻⁸)보다 커요.

할선법에서 두 점의 f가 같으면 직선이 x축과 만나지 않아요. 그때는 두 점의 가운데를 돌려주고 `status` −2, `message` `'Tolerance of {x1 − x0} reached.'`예요. 둘째 점을 주지 않으면 scipy처럼 $x_0(1 + 10^{-4})$에 그 부호 쪽으로 $10^{-4}$를 더한 점이에요.

## 멈춤 판정과 기본값

| method | 멈추는 때 | 기본 xtol, rtol, max_iter | rtol 하한 |
|---|---|---|---|
| bisect | 반으로 줄인 걸음 < xtol + rtol·\|x\| | 2×10⁻¹², 4ε, 100 | 4ε |
| brentq | 근을 끼는 구간의 반 < (xtol + rtol·\|x\|)/2 | 2×10⁻¹², 4ε, 100 | 4ε |
| toms748 | \|a − b\| ≤ xtol + rtol·\|b\| | 2×10⁻¹², 4ε, 100 | ε |
| newton, halley, secant | \|걸음\| ≤ xtol + rtol·\|x\| | 1.48×10⁻⁸, 0, 50 | 없음 |

기본값과 하한은 scipy의 것이에요. scipy는 `xtol=0`을 받지 않지만 stardust는 받아요. 그러면 구간법이 rtol만으로 멈춰서 끝자리 몇 개까지 가요. 근이 0이면 rtol·|x|도 0으로 가므로 구간이 가장 작은 정규수 근처까지 줄어야 해요. 그때는 `max_iter`를 bisect 1,100, brentq 200쯤으로 늘려요.

## 정확도

시험 문제 204개(scipy `_tstutils`의 기본 5개, Alefeld–Potra–Shi의 154개, Chandrupatla의 45개)마다 근을 Arb로 1 ULP까지 정해 두었어요. double x에서 f의 부호를 Arb로 정밀도를 올려 가며 확정하고, double의 비트 순서로 이분해서 근을 끼는 이웃한 두 double(154문제)이나 f가 정확히 0인 double(50문제)을 얻어요.

- 기본 허용오차로 수렴한 구간법의 근(brentq 185문제, toms748 204문제, bisect 204문제)은 모두 참 근에서 xtol + rtol·|x| 안이거나, double로 계산한 f가 정확히 0인 점이에요. 판정의 뜻이 곧 정확도의 계약이에요.
- `xtol=0`이면, f가 double로 정확히 0인 점에서 멈춘 경우를 빼고 brentq(`max_iter=200`)는 근을 끼는 두 double에서 3 ULP 안(171문제는 1 ULP 안), toms748(`rtol` = ε)은 1 ULP 안, bisect(`max_iter=1100`)는 4 ULP 안이에요.

f의 반올림이 이 정확도의 바닥이에요. 근 근처에서 f는 상쇄로 상대 오차가 커지고, 그 값의 부호가 틀리는 폭 안에서는 어떤 방법도 근을 더 좁히지 못해요.

## 비용

반복 자체(걸음 계산과 콜백을 부르는 고리)의 비용은 f 호출 하나에 0.17–1.6 µs예요(Apple M4 Pro, 1스레드, scipy 1.18.1·numpy 2.5.4). 문제는 $\sin x - x/2$(구간 (π/2, π), x0 = 2)와 $x^3 - 2x - 5$(구간 (2, 3), x0 = 2.5)이고, 두 라이브러리가 같은 Python f를 써요. scipy에서 C로 쓴 bisect와 brentq는 이 비용의 1.5–2.8배이고, Python으로 쓴 toms748, secant, newton, halley는 반복마다 Python과 numpy를 거쳐서 더 비싸요.

newton·halley의 비용에는 `fprime`·`fprime2`의 호출 시간이 들어 있어요(두 라이브러리 모두). 두 문제 모두 f를 부르는 횟수가 scipy와 같아서, 차이는 방법 자체의 비용뿐이에요. scipy의 toms748은 반복마다 numpy로 나눗셈 차분과 보간을 계산해서 그 비용이 커요. 다만 이 비용은 모두 µs 단위라, f가 조금만 무거워도 걸리는 시간은 f의 계산이 정해요.
