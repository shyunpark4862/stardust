사용자 결정 (2026-11-14, S7을 시작하기 전)
- 특수값은 참값·극한으로 한다: `hyp1f1(-1, 2, inf) = -inf`(scipy inf), `hyp1f1(0, 0, x) = 1`(scipy inf), `hyp2f1(a, b, c, -inf)`의 극한(a, b > 0이면 0, scipy NaN).

- S6에서 남은 두 건: Airy는 |x| ≤ 1e12로 보장을 좁히고(그 너머 느슨), Debye는 넣지 않는다.

## 2. Lambert W
- 분기점 −1/e 근처에서 W는 p = ±√(2(e·x + 1))의 급수다(DLMF 4.13.6). 계수는 `tools/gen_lambertw_branch.py`가 p(u) = u·√(2(1 + (u−1)eᵘ)/u²)를 뒤집어 만든다(맞춘 값이 아니다). 처음에는 (u−1)eᵘ의 계수 부호를 거꾸로 써서 c₂가 −1/3이 아니라 1/3으로 나왔다. 알려진 값과 맞춰 보고 찾았다.
- **e·x + 1**: x가 −1/e 근처이면 float64의 e·x + 1은 마지막 비트들만 남는다. scipy는 그곳에서 2e7 ULP(k = −1에서 3.8e11)를 잃는다. e를 hi + lo로 두고 `fma(e_hi, x, 1) + e_lo·x`로 계산한다. W의 조건수 1/|1+W|는 분기점에서 커지지만, 입력이 정확하므로 상대 정확도는 지킨다.
- 그 밖은 Halley 반복이다(초기값은 분기점 급수, log(1+x), 큰 x의 L₁ − L₂ + L₂/L₁). 전 영역 0.6 ULP 이하다.

## 3. hyp1f1
- **급수 항을 double-double로**: 양의 항 급수인데도 처음 잰 오차가 120–184 ULP였다. 항을 (a+k)x/((b+k)(k+1))로 연이어 곱하면 k번째 항이 k ULP쯤의 반올림을 지니고, x ≈ 500이면 합을 이루는 항이 k ≈ x 둘레에 있다. a + k도 반올림된다. 항과 a + k, b + k(two_sum)를 double-double로 하자 0.5 ULP가 됐다.
- **Kummer의 b − a**: x < 0은 M(a, b, x) = eˣ·M(b−a, b, −x)인데, b − a를 반올림하면 Γ(b−a)와 |x|^(−a)의 지수에 들어가 67 ULP가 됐다(S3의 "Γ의 인자를 반올림하지 않는다"를 다시 밟았다). b − a를 double-double로 넘기고, 점근식에서는 1/Γ(hi + lo) = (1/Γ(hi))(1 − ψ(hi)·lo)로 보정한다. 3.4 ULP가 됐다.
- **음의 b의 급수가 일찍 멈춤**: b < 0이면 k ≈ −b에서 분모 (b+k)가 0에 가까워져 항이 다시 커진다. 그 전에 작은 항을 보고 멈춰서, 상쇄가 없는 점(항 합/값 = 1.002)에서 1e-3이 틀렸다. k가 −b를 지나기 전에는 멈추지 않는다(hyp2f1의 −c도 같다).
- **b < 0의 상쇄**: 직접 급수와 Kummer 형태가 모두 크게 상쇄하면 양의 b′ = b + n에서 b에 대한 3항 재귀(DLMF 13.3.2)로 내려간다. a에 대한 재귀는 아래 방향이 불안정해서(시험에서 1e17까지 틀림) 쓰지 않았다.
- **남은 것**: a < 0이고 x > 0이 큰 곳은 급수의 항 합이 값보다 10²⁹배 클 정도로 상쇄한다. scipy는 다른 표현으로 2.3e3 ULP(상대 2.9e-13)인데 우리는 2.3e13 ULP(상대 3.9e-3)다(§6).

## 4. hyp2f1
- 급수 항을 double-double로 바꾸자 보장 영역이 24 ULP에서 7 ULP로, 매개변수 ±20 범위 전체가 4e13에서 586 ULP로 줄었다(c < 0의 이른 멈춤도 함께 고쳤다).
- **퇴화**: c − a − b가 정수 m이면 1 − z 변환의 Γ(±s)가 극점에 걸린다. AS 15.3.10–12의 digamma 극한식을 쓴다. Γ(m) = (m−1)!을 표에서 꺼낼 때 인덱스를 하나 잘못 써서 m ≥ 2에서 결과가 정확히 m배였다(m = 0, 1은 우연히 맞았다).
- **거의 퇴화**: 정수에 가깝지만 정수가 아닌 s는 두 항이 1/|s − m|만큼 상쇄한다(처음 2e16). 1 − z ≥ 1e-3이면 급수 자체를, |s − m| < 1e-8이면 정수 m의 극한식을 쓴다.
- z < 0은 Pfaff 변환에서 a, b 중 큰 쪽을 앞에 둔다. 그러면 c ≥ min(a, b)일 때 c − b ≥ 0이라 항이 모두 양수다.

- 초기하 두 함수는 1스레드에서 scipy보다 7–20배 느리다. 참값 입력을 구역별로 재면 보장 영역에서도 `hyp2f1` 2.1–2.8 µs(scipy 0.13–0.18 µs), `hyp1f1` 0.8–2.8 µs(scipy 0.2–0.6 µs)다. 급수 항 하나가 double-double 곱 셋과 나눗셈 하나라 float64의 10배쯤이고, z ≈ 0.9나 큰 x에서는 수백 항이 든다. 정확도(scipy 200 ULP대 → 7–11 ULP)와 맞바꾼 값이다.
- **속도 시도 하나를 되돌렸다**: 24항 안에 끝나는 급수는 float64로 먼저 계산하게 했는데, 시간은 긴 급수가 차지해서 빨라지지 않았다. 게다가 항이 상쇄하는 급수(c < 0인 Pfaff)에서는 "24항이면 24 ULP"라는 근거가 깨져 느슨한 영역이 6.6e-13에서 3.2e-12로 나빠졌다. 근거가 양의 항에서만 성립한다는 걸 놓쳤다.
- `lambertw`는 1스레드 3.8배, 10스레드 29배 빠르다(`k=-1`은 7.9배, 54배).
- 비용 상수(`cost.hpp`)를 잰 값으로 바꿨다: `hyp1f1` 1600, `hyp2f1` 2200 ns(가중치는 상한 256), `lambertw` 20, `k=-1` 43 ns. `k=-1`은 따로 상수를 둔다.

## 6. 확인 부탁
- **hyp1f1의 a < 0, x > 0 큰 상쇄**: 느슨한 영역 중 여기만 scipy보다 나쁘다(우리 상대 3.9e-3, scipy 2.9e-13). 큰 |a|용 Bessel형 전개(Tricomi, Buchholz)를 넣으면 고칠 수 있다. 후속으로 할지 여쭌다.
- **hyp1f1 b < 0의 재귀**: 느슨한 영역의 개선으로 넣은 구간이다(설계의 3구간 밖).
- **초기하의 속도** (§5): 1스레드에서 scipy보다 7–20배 느리다(10스레드에서 `hyp1f1` 1.3배 빠르고 `hyp2f1` 0.5배). 급수를 double-double로 한 대가다. 받아들일지, 정확도를 지키며 빠르게 하는 작업(예: 항의 비를 float64 + 오차 보정으로)을 후속으로 할지 여쭌다.
