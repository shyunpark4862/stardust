# S4. 불완전 감마와 베타

> `gammainc gammaincc gammaincinv gammainccinv betainc betaincc betaincinv betainccinv` 여덟 개다. 설계는 docs/design/special.md §5.3–5.5, API는 docs/api/special.md §4다. 핵심부는 `csrc/special/prefix.hpp`(앞 인자), `dd.hpp`(double-double), `ops/incgamma.hpp`, `ops/incbeta.hpp`다.

사용자 결정 (2026-11-14, S4를 시작하기 전)

측정 뒤의 사용자 결정 (2026-11-14)
- 불완전 베타의 큰 a, b 평균 근처에 점근전개 구간(BASYM)을 넣는다. 연분수만으로는 a, b ≈ 6만에서 82 ULP였다.
- 한쪽 모수가 아주 작고 다른 쪽이 큰 영역에 BGRAT 구간을 넣는다. 급수와 연분수로는 2800 ULP였다.

## 2. 앞 인자: 지수 하나에 모으고 double-double로 계산한다
- **문제**: 불완전 감마와 베타는 앞 인자 `D = x^a e^(−x)/Γ(a+1)`, `B = x^a (1−x)^b / B(a, b)`에 급수나 연분수를 곱한 꼴이다. scipy(Cephes)는 `a log x − x − lgamma(a)`를 float64로 만들고 exp한다. 지수가 E이면 지수의 상대오차 2⁻⁵³이 결과에 E·2⁻⁵³으로 옮겨 간다. 결과가 아직 정규수인 E ≈ 700에서는 수백 ULP다. 잰 scipy의 최대는 감마 꼬리 2,141 ULP, 큰 a, b 베타 1,104 ULP였다.
- **Stirling 정규화**: `Γ(z) = √(2π/z)·(z/e)^z·Γ*(z)`로 쓰면 큰 부분이 모두 지수 하나로 모인다.
  - `D = e^(−E) / (√(2πa)·Γ*(a))`, `E = a·μ(x/a − 1)`
  - `B = √(ab/(2πc))·Γ*(c)/(Γ*(a)Γ*(b))·e^(−E)`, `E = a·μ(xc/a − 1) + b·μ(yc/b − 1)`, c = a + b
  - μ(t) = t − log(1+t) ≥ 0이다. 두 항이 모두 0 이상이라 서로 상쇄하지 않는다. Γ*(z) = 1 + O(1/z)는 크기가 1 근처라 반올림이 해롭지 않다.
- **double-double** (`dd.hpp`): E를 hi + lo로 정확한 입력에서 만든다. 필요한 것은 합, 곱, 몫과 log 두 가지뿐이다.
  - `log(λ)`: λ = m·2^k, m ∈ [1/√2, √2)로 나누고 `log m = 2 atanh((m−1)/(m+1))`의 급수를 쓴다. 앞 두 항만 double-double, 나머지 꼬리는 float64다.
  - `μ(t)`: t ∈ [−½, 1]이면 s = t/(2+t)로 `μ = s·t − 2s³/3 − 2s⁵/5 − …`다. t − 2s = s·t가 정확한 항등식이라 큰 두 항의 상쇄가 처음부터 없다. λ가 이 범위 밖이면 |log λ| ≥ log 2라서 `a(λ−1) − a·log λ`의 빼기가 2비트 넘게 잃지 않는다.
  - 처음에는 s = −1/3(t = −½) 근처에서 급수를 너무 일찍 끊었다(s²⁰항까지, 오차 5e-13). gammainc(2, 1)이 946 ULP 틀려서 찾았다. s⁴⁵항까지 늘렸다.
- **결과는 m·2^e로 들고 있다가 한 번 반올림한다** (S3의 `Scaled`). 그래서 e^(−E)가 서브노멀이 되는 곳에서도 비트를 두 번 잃지 않는다.

## 3. 불완전 감마
- 갈래 넷 (Boost의 `gamma_incomplete_imp`와 같은 경계):
  - x < 1.1이고 a가 작으면 Q = (Γ(1+a) − 1 − (x^a − 1) − a·x^a·S)/Γ(1+a). Γ(1+a) − 1과 x^a − 1을 expm1로 계산해서 a → 0에서도 상대 정확도가 산다.
  - x가 a보다 작은 쪽은 급수로 P, 큰 쪽은 연분수로 Q
  - a > 20이고 |x − a| < 0.4a이면 Temme의 균등 점근전개. `Q = erfc(√E)/2 + e^(−E)/√(2πa)·Σ c_k(η)·a^(−k)`
- **Temme 계수**: Boost의 표를 쓰지 않고 DLMF 8.12의 정의(c₀ = 1/μ − 1/η, c_k = c′_(k−1)/η + (−1)^k g_k/μ)를 mpmath의 멱급수 연산으로 전개해 만들었다(`tools/gen_temme_igamma.py`). lgamma의 Taylor 계수(S3)와 같은 원칙으로, 맞춘 값이 아니라 급수 자체의 값이다. c₀ = −1/3 + η/12 − 2η²/135 …, c₁(0) = −1/540이 알려진 값과 맞는다. a가 크면 필요한 k가 줄어든다(a = 20이면 13, 1e6이면 3).
- **erfc(√E)**: z² = E가 정확하므로 S2의 `erfc_tail(z, exp(−E.hi), E.lo)`에 그대로 넣는다. S2의 exp(−x²) 분할과 같은 생각이다.
- **연분수는 거꾸로 계산한다** (`cf.hpp`의 `lentz_backward`): Lentz를 앞으로 돌리면 비 C_n·D_n의 반올림이 곱으로 쌓인다. 작은 a, x ≈ 1.5에서 60항 뒤 17 ULP였다. 같은 항을 꼬리부터 `t = a_k/(b_k + t)`로 계산하면 2 ULP 아래다. 각 걸음의 반올림이 다음 나눗셈에서 줄어들기 때문이다. 그래서 Lentz로 항 수만 찾고 값은 거꾸로 한 번 더 계산한다.

## 4. 불완전 베타: BRATIO
- 처음 계획은 NR의 `betacf` + 급수(2구간)였다. 재 보니 세 곳에서 무너졌다.
  1. **작은 a, b(U자형 분포)**: 연분수 쪽으로 고른 값이 0.985였다. 원하는 값 0.015를 1 − 0.985로 얻으니 66배의 상쇄가 생겼다(288 ULP).
  2. **큰 a, b의 평균 근처**: `betacf`의 첫 분모 1 + d₁/(…)이 0 근처로 줄어든다. 연분수의 값 a·I/B가 √a만큼 크면 그만큼 상쇄가 커진다(2,300 ULP).
  3. **a ≫ b이고 x ≈ 1**: 급수는 수렴비가 x라서 수천만 항이 걸린다.
- 그래서 DiDonato–Morris의 BRATIO(ACM TOMS 708, 1992) 구조로 바꿨다. scipy가 쓰는 Boost `ibeta_imp`도 같은 구조에서 나왔다.
  - **BPSER**: x의 멱급수. b ≤ 1이거나 b·x ≤ 0.7이면 항이 상쇄 없이 준다.
  - **BUP**: `I_x(a, b) − I_x(a+n, b)`는 항이 모두 양수인 유한합이다. a나 b를 다른 방법이 맞는 곳으로 옮긴다(예: b = n + b̄, b̄ ∈ (0, 1]).
  - **BGRAT**: a가 크고 b ≤ 1, x ≈ 1. `I = G·(Q(b, z) + r·Σ d_n J_n)`, z = −(a + (b−1)/2)·log x. S4의 `gammaincc`를 그대로 쓴다. z를 double-double로 두고 Q와 r을 1차 보정했다. TOMS의 J_n은 r로 나누는데, 여기서는 r을 곱해 둔 K_n = r·J_n으로 점화해서 r이 언더플로해도 나눗셈이 없다.
  - **BFRAC**: x가 평균 아래(λ = a − (a+b)x ≥ 0)일 때의 연분수. b₀ = a(λ+1)/(a+1)이라 분모가 0 근처로 가지 않는다.
  - **BASYM**: a, b > 100이고 λ ≤ 0.03·min(a, b)일 때의 Temme형 균등 점근전개. 계수는 재귀로 만든다(표가 없다). 앞항 `erfc(√E)/2`는 감마의 Temme와 같은 `erfc_sqrt(E)`로 계산한다.
- **1 − x의 하위 비트**: y = 1 − x는 double-double로 정확히 들고 다닌다. 역할을 바꾸면(I_y(b, a)) 변수의 하위 비트가 생긴다.
  - 급수에는 dS/dx로 1차 보정을 넣었다.
  - BFRAC에도 같은 보정(dF/dx)을 넣었더니 오히려 3,300 ULP가 됐다. 보정 없이는 5 ULP였다. BFRAC는 `a·y − b·x + 1`에서 작고 정확한 쪽 변수를 직접 쓰기 때문이다. x와 y를 따로 받는 함수에서 "x에 대한 도함수"는 y를 1 − x로 묶는다는 가정을 깐다. 그 가정이 이 식에는 맞지 않았다. 보정을 뺐다.

## 5. 역함수
- **작은 쪽을 푼다**: p와 1 − p 중 작은 것을 자기 함수에 대해 푼다. p ≥ ½이면 1 − p가 정확하다(Sterbenz). 베타는 근이 ½ 위이면 y = 1 − x를 변수로 삼는다. x ≈ 1에서 x의 상대 정확도를 잃지 않기 위해서다.
- **초기값**
  - 감마: 작은 x 근사 `x = (P·Γ(a+1))^(1/a)`는 근보다 작다. P ≤ x^a/Γ(a+1)이기 때문이다. 큰 x 점근식(a ≥ 1이면 하한)과 Wilson–Hilferty 중 큰 쪽에서 시작한다.
  - 베타: AS 109(Cran, Martin & Thomas 1977). u와 1 − u를 각자의 닫힌 식으로 구해 1 근처에서도 자릿수를 잃지 않는다.
- **Halley와 log 걸음** (`halley.hpp`): 꼬리에서 F는 지수함수처럼 변한다. 선형 Newton 걸음은 한 번에 F/F′ ≈ 1씩만 움직여서 근 548을 찾는 데 수백 번이 걸렸다. F가 목표의 두 배 넘게 떨어져 있는 동안은 log F에 대한 Newton 걸음 `x − log(F/t)·F/F′`를 쓴다. 가까워지면 Halley로 마무리한다. 걸음이 괄호 밖으로 나가면 이분법(괄호가 4배 넘게 넓으면 기하평균)을 쓴다.
- **멈춤**: 잔차가 반올림 수준(|F − t| ≤ 2⁻⁵⁰F)이 되면 마지막 걸음 하나를 더 하고 멈춘다. 정확도는 순방향 오차 × κ로 정해진다. 이것이 보장 기준 1e-14·max(1, κ)의 근거다.
- **잡은 버그**: 괄호의 위쪽 끝이 ∞일 때 `hi − lo ≤ 2⁻⁵³·hi`가 ∞ ≤ ∞로 참이 되어, 두 번째 반복에서 멈췄다. gammaincinv(0.526, 0.93)이 10% 틀렸다.

## 6. 정답지 도구
- mpmath의 `betainc(a, b, x, 1)`은 작은 보수에서 상쇄로 0을 낸다. 보수는 대칭식 `betainc(b, a, 0, 1−x)`로 구한다(mpmath 안에서 1 − x는 정확하다).
- mpmath는 `betainc(2, 1e300, 0, 5e-324)`을 1.2e-647로 낸다(참값 1.22e-47). 이 점은 닫힌 식 x²·b(b+1)/2로 확인했다.
- mpmath의 `gammainc`는 큰 a에서 초기하 급수의 항 수 한도에 걸린다. P는 `x^a e^(−x)/Γ(a+1)·₁F₁(1; a+1; x)`를 항 수 한도를 늘려 계산하고, Q는 1 − P를 두 배 정밀도로 구한다.
- a = b = 1e5의 평균 근처처럼 mpmath가 한 점에 수 분 걸리는 곳이 있다. 정답지 도구는 점마다 30초를 넘으면 그 점을 빼고 개수를 적는다.
- 역함수의 정답지는 우리 값에서 출발하는 log x에 대한 Newton이다(정밀도 두 배로 확인). 점마다 κ를 함께 저장하고(`scale` = max(1, κ)), 테스트와 정확도 표가 그 값으로 기준을 넓힌다.

## 7. 역함수의 반복 횟수
- 처음 잰 `gammaincinv`는 원소당 2.3 µs였다(scipy 0.25 µs). 반복을 세 보니 평균 15.7번, 꼬리 쪽 p의 절반이 20–45번이었다.
- 원인 셋을 고쳤다.
  1. 수렴한 마지막 걸음이 x와 같으면(xn == x), 방금 정한 괄호의 끝과도 같아서 "괄호 안" 검사가 거짓이 됐다. 그래서 이분법으로 빠져 x를 1이나 hi·2⁻²⁰으로 던졌다가 다시 찾아왔다. 수렴 검사를 괄호 검사보다 먼저 한다.
  2. a가 작고 x가 서브노멀이면 F′ = x^(a−1)e^(−x)/Γ(a)가 double을 넘는다(7e309). 그래서 반복이 F′ 대신 x·F′(감마는 a·D, 베타는 B/y)를 받는다. 나눗셈 없이 유한하다.
  3. 목표가 서브노멀(p = 1e-320)이면 근에서 F를 double로 반올림한 값이 몇 자리밖에 안 된다. t < 2⁻¹⁰⁰⁰이면 반올림 전 조각으로 log F를 만들고, 잔차 log F − log t를 double-double로 계산해(둘 다 −737 근처) log 공간에서 Newton을 푼다. 처음에는 1e9 ULP, 잔차를 double로 계산하면 57 ULP, double-double로 1 ULP였다.
- 지금은 평균 2.3번, 최악 6번이다(무작위 2만 점).

## 9. 스레드 분할 (`bench/special/s4/threads.md`)
- ROADMAP의 S4 항목: 원소마다 반복 횟수가 다를 때. 같은 입력을 비용 순으로 정렬한 것과 섞은 것을 견주었다. 차이는 2% 안이다. 풀이 원자 카운터 하나에서 다음 태스크를 주므로, 느린 태스크는 그것을 가져간 스레드만 붙잡는다(docs/design/array.md §10.1).
- 대신 다른 문제가 나왔다. 이터레이터는 태스크를 4096/가중치 원소로 자른다. S4 함수는 가중치가 800–8500이라 **태스크 하나가 원소 하나**였다. 10스레드가 카운터 하나를 두고 다투어 속도 향상이 4.8–7.8배에 그쳤다.
- 배열 영역은 건드리지 않고 special의 `weight_of`에 상한 `kMaxWeight` = 256을 두었다(태스크 16원소). 8.1–8.9배가 됐다. 64도 거의 같았지만 256이 병렬 시작 크기(128원소)를 작게 둔다.
- 이 상한은 S3의 무거운 함수(`polygamma` `beta` `betaln` `binom` `zeta`)의 분할도 바꾼다. 원소별 연산이라 결과 비트는 같다(골든 출력, 참값 테스트).

## 10. 작업 방식에서 고친 것
- scipy의 정확도를 재는 첫 실행이 출력 없이 13시간을 돌았다. mpmath가 큰 a, b의 몇 점에서 멈췄고, 출력이 버퍼에 묶여 보이지 않았다. 그 뒤로 오래 도는 측정은 점마다 시간 제한을 두고 영역마다 바로 출력한다.
- BFRAC 원형을 Python으로 흉내 내 재다가 30분을 썼다(사용자 지적). 시간은 원형이 아니라 mpmath가 두 점에서 멈춘 데서 갔다. 그 뒤로는 참값을 한 번만 구해 파일에 두고, 알고리즘 실험은 C++ 단독 프로그램(컴파일 포함 1.4초)으로 했다.

## 11. 확인 부탁
- **가중치 상한 256** (§9): special 전체의 분할 규칙이 바뀐다. 결과는 같고 S3 함수에도 적용된다.
- **불완전 감마의 갈래 수**: 설계는 3구간(급수, 연분수, Temme)이었다. 작은 a·x < 1.1의 Boost식 갈래가 하나 더 있다(근사 방식 넷). 베타는 측정 뒤 결정대로 다섯이다.
- **역함수의 서브노멀 목표값**: p가 서브노멀인 곳도 1e-14·max(1, κ)를 지킨다(§7의 3번). 결정 목록에 없던 곳이라 같은 기준을 그대로 적용했다.
- **베타 역함수 참값에서 빠진 점**: mpmath가 30초 안에 끝내지 못하거나 수렴하지 않은 점을 뺐다. `betaincinv` 62점(4%), `betainccinv` 248점(16%)이다. 큰 a, b(1e2–1e5) 쪽이 많다. 그 영역은 무작위 측정(참값을 점마다 구함, κ 보정 최대 0.81 ULP)으로 따로 확인했다.
- **1스레드 속도**: `betainc`, `betaincc`는 scipy의 0.29배, `gammainccinv` 0.49배다(§8). 정확도의 대가로 보고 두었다.
