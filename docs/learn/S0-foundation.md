# S0. 특수함수 영역의 기반

> sd.special의 첫 마일스톤이다. 공개 함수는 아직 없고, 함수들이 올라탈 엔진과 정답지·측정 도구를 만들었다. 배열 영역을 고치는 일은 이 마일스톤에만 있다(ROADMAP.md, 특수함수 영역 진행 원칙). 설계는 docs/design/special.md §3, §6이다.

## 2. n항 디스패처 (배열 영역)
배열에는 입력 하나(`unary`)와 둘(`binary`)의 디스패처만 있었다. `betainc(a, b, x)`는 셋, `hyp2f1(a, b, c, z)`는 넷이 필요하다. `airy(x)`는 결과가 넷이다.

- **Op 구조체**는 배열의 것(`array/kernels/scalar_ops.hpp`)과 같은 모양이다. 여기에 셋을 더 적는다.
  ```cpp
  struct Fma3 : Real {                                   // Real: float64 루프만 (special/common.hpp)
      static constexpr const char* name = "_fma3";
      static constexpr int nin = 3, nout = 1;
      static constexpr std::array<const char*, 3> args{"a", "b", "c"};  // 메시지의 인자 이름
      static constexpr double cost_ns = cost::kFma3;     // §4
      static double f(double a, double b, double c) { return a * b + c; }
  };
  ```
  출력이 여럿이면 `f`가 `std::array<double, nout>`를 돌려준다(`_powers4`).
- **루프** `nary_loop<Op, T>`(`array/kernels/elementwise.hpp`): `std::index_sequence`로 입력 `nin`개를 펼쳐 `Op::f(x[I][i]...)`를 부른다.
  - 모두 연속이면 인덱스 포인터를 쓴다. 이 경우만 컴파일러가 벡터화할 수 있다.
  - 그 밖에는 일반 strided 루프다.
  - `binary_loop`처럼 "배열 op 스칼라" 같은 배치마다 갈래를 두지 않았다. 원소 하나에 수십 ns 드는 함수라서, 스칼라 인자를 stride 0으로 읽는 값은 보이지 않는다.
- **디스패치** `run_nary`(`array/ops/ufunc.cpp`)는 `run_binary`를 입력 N개로 늘린 것이다. 네 단계(피연산자 → 루프 → 변환 → 실행)는 같다.
  - 입력 dtype을 모두 승격한 뒤 표에서 루프를 고른다. float64 루프만 있으니 bool과 int64는 버퍼 변환으로 float64가 된다. complex128은 루프가 없어 TypeError다.
  - Python int가 int64를 넘는 경우의 규칙(docs/api/array.md §1.5)도 같다.
- **`launch`를 넓혔다.** 출력 개수와 가중치를 받는다. 출력이 하나인 경로는 전과 같은 코드를 탄다. 그래서 골든 출력이 비트까지 같다.
- **메시지**: 입력이 셋 이상이면 `_fma3(): not supported for complex128, int64 and int64`처럼 쉼표로 잇는다. 둘일 때(`a and b`)는 전과 같다. 설계에 없던 작은 결정이라 §7에서 확인을 받는다.

## 3. `kMaxOperands` 4 → 5의 비용
- 이터레이터는 피연산자마다 stride 배열 하나를 고정 크기로 갖는다. 크기는 `kMaxNdim` = 32개의 int64, 즉 256바이트다.
  - 피연산자가 하나 늘면 `NdIter`가 약 1.3KB에서 1.6KB로 커진다.
  - 병렬 실행에서는 태스크마다 `NdIter`를 복사한다. 버퍼 변환(`BufferedLoop`)의 고정 배열도 한 칸씩 늘었다.
- **잰 방법** (`bench/special/s0_operands.py`)
  - M8 직후 커밋(a7ba5ee)을 worktree로 꺼내 wheel로 빌드했다. 편집 설치의 import hook을 건너뛰고 그 wheel을 불러온다(`common.use_build`).
  - 전과 후를 각각 자기 프로세스에서 번갈아 7라운드 돌렸다. 줄마다 가장 빠른 값을 남겼다.
  - 1스레드 짧은 호출 11줄과, 10스레드 10⁶개 `add` 한 줄을 쟀다.
- **결과** (`bench/special/s0/operands.md`, ns per call)

  | 호출 | 전 | 후 | 후/전 |
  |---|---:|---:|---:|
  | `add(1.0, 2.0)` 스칼라 | 166 | 166 | 1.00 |
  | `add` 크기 1 | 168 | 166 | 0.99 |
  | `add` 크기 16 | 169 | 186 | 1.10 (2차 측정 1.06) |
  | `x16 + y16` | 182 | 175 | 0.96 (2차 측정 1.05) |
  | `add` 크기 1000 | 275 | 284 | 1.03 |
  | `where` 크기 16 | 201 | 201 | 1.00 (2차 측정 1.04) |
  | `add` (8,8,8) 전치 | 471 | 469 | 1.00 |
  | `sum` 크기 1000 | 188 | 189 | 1.00 |
  | `add` 10⁶, 10스레드 | 36,315 | 37,428 | 1.03 |

- **읽기**
  - 같은 코드를 타는 두 줄(`add` 크기 16과 연산자 `x16 + y16`)이 1차 측정에서 반대 방향으로 갈렸다. 그래서 줄 하나의 5–10%는 이 측정의 잡음 폭이다.
  - 12줄의 기하평균은 1.013이다.
  - 2차 측정에서는 크기 16 줄이 모두 1.04–1.06이었다. 호출당 5–9ns가 실제 비용일 수도 있다. 다만 크기 1과 스칼라 줄은 1.00이고, 이 줄들도 같은 `NdIter`를 만든다. 이 둘은 서로 맞지 않는다.
  - 결론: 일관된 회귀는 확인되지 않았고, 있더라도 짧은 호출에서 수 ns 수준이다.

## 4. 원소당 비용: 병렬 분할의 가중치
- 배열의 이터레이터는 일의 양을 `가중치 × 바이트 × 원소 수`로 센다. 이것이 `8·2¹⁵`를 넘으면 병렬로 가고, 태스크 하나에 약 `8·2¹²`만큼 준다. 배열의 함수는 가중치가 1이다.
- 특수함수는 원소 하나에 add 수십~수천 번 값이 든다. 가중치 1로 두면 비싼 함수가 너무 늦게 병렬로 간다. 예를 들어 `_cf_tan` 3만 개는 0.5ms인데 1스레드로 돈다.
- 그래서 함수마다 원소당 비용(ns)을 `special/cost.hpp`에 적고, `add`의 원소당 비용(`kAddNs`, 잰 값 0.18ns)으로 나눠 가중치로 쓴다.
  - 가중치 `w`인 함수는 원소 `2¹⁵/w`개부터 병렬이 되고, 태스크 하나가 원소 약 `2¹²/w`개다.
  - `_cf_tan`(15.8ns, `w` = 84)은 원소 390개부터 병렬이 되고, 태스크 하나가 원소 49개(약 0.8µs)다.
- 가중치는 어디서 자르는지만 바꾼다. 결과의 비트는 바꾸지 않는다. 원소별 계산이라 분할과 무관하기 때문이다. 테스트가 스레드 1·3·10의 비트를 비교한다.
- `bench/special/cost.py`가 함수마다 잰 비용, 그 비용에서 나온 가중치, `cost.hpp`에 적힌 가중치를 나란히 보여 준다. 함수가 생길 때마다 이 표로 `cost.hpp`를 채운다.

## 5. 수정 Lentz 연분수와 그 함정
- `special/cf.hpp`의 `lentz(b0, term, max_terms)`는 연분수 `b0 + a1/(b1 + a2/(b2 + ...))`를 앞에서부터 계산한다.
  - 수렴값의 비 `C_n`과 `D_n`만 들고 간다. 그래서 항의 개수를 미리 몰라도 된다.
  - 분모가 0이 되면 작은 수(2⁻¹⁰⁰⁰)로 바꿔 계속한다. 이것이 "수정" Lentz다.
- 시험 함수 `_cf_tan`은 Lambert의 연분수 `tan x = x / (1 - x²/(3 - x²/(5 - …)))`다.
- **함정**
  - 처음에는 연분수 전체를 넘겼다(`b0 = 0`, `a1 = x`).
  - 그러면 시작값 `f`가 그 작은 수가 되고, 이후의 `f_n`은 모두 그 배수다.
  - `x = 5e-324`에서 `9.3e-302`가 나왔다. 결과가 2⁻¹⁰⁰⁰보다 작으면 틀린다.
  - mpmath 정답지의 경계 점(0 근처 부분정규수)이 이것을 잡았다.
- **고침**: 분모 `1 - x²/(3 - …)`를 자기 연분수(`b0 = 1`)로 계산하고 `x`를 그것으로 나눈다. Numerical Recipes도 같은 방법을 권한다. `cf.hpp`의 주석에 적었다. S4의 불완전 감마·베타도 이 형태로 쓴다.

## 6. 정확도 파이프라인
- **기준값** (`tools/special_ref.py`)
  - mpmath를 50자리로 돌린다.
  - 값을 `hi + lo`(double-double)로 저장한다. `hi`는 float64로 반올림한 값, `lo`는 그 나머지다. 그래서 테스트가 mpmath 없이 ULP의 소수점까지 잰다.
  - 입력 집합은 세 가지다: 보장 영역의 격자, 로그 균등 무작위, 경계 점 앞뒤 4 ULP. seed가 고정이라 다시 돌려도 같은 파일이 나온다.
  - 결과는 `tests/special/ref/<이름>.npz`이고 커밋한다.
- **오차** (`tests/special/refdata.py`)
  - ULP 오차 = `|(got − hi) − lo| / spacing(|hi|)`
  - 상대오차 = `|(got − hi) − lo| / |hi|`
  - NaN과 inf는 정확히 같으면 0, 아니면 inf다.
- **테스트** (`tests/special/test_reference.py`)
  - 기준값 파일이 있는 함수는 자동으로 검사된다. 보장 영역은 상대오차 1e-14 이하다(docs/api/special.md §1.4). 보장 영역 밖은 함수가 문서에 적은 느슨한 한계 이하다.
  - 기준값 입력 200개에서 스칼라 호출이 배열 결과와 같은 비트인지도 본다.
- **표** (`bench/special/accuracy.py`): 영역마다 최대 ULP와 99.9% ULP를 낸다. 비교 대상(기본은 `scipy.special.<이름>`)의 값도 같은 입력으로 함께 낸다.
- **`_cf_tan`의 결과** (`bench/special/s0/accuracy.md`)

  | 영역 | 점 | sd 최대 ULP | `numpy.tan` 최대 ULP |
  |---|---:|---:|---:|
  | 보장 (\|x\| ≤ 1) | 6,038 | 6.71 | 2.04 |
  | 느슨함 (1 < \|x\| < π/2) | 2,026 | 5.2e15 | 2.22 |

  - π/2 근처에서는 분모 `1 − x²/(3 − …)`가 0으로 소거된다. 남는 것은 `x²`를 반올림한 오차뿐이라 상대오차가 0.83까지 간다.
  - `numpy.tan`은 인수 축소(x를 π/2의 배수로 옮기기)를 하므로 이 문제가 없다.
  - 그래서 "보장 영역 밖도 계산하고 느슨함을 문서화한다"(Q9)가 실제로 어떻게 보이는지를 이 함수가 보여 준다. 공개 함수에서 이런 영역은 다른 근사로 넘어가는 경계가 된다(§4.2의 구간).

## 7. 측정 도구
| 도구 | 하는 일 |
|---|---|
| `tools/special_ref.py [이름…]` | mpmath 기준값 파일을 만든다. 함수는 `FUNCTIONS` 표에 입력 집합과 함께 등록한다 |
| `bench/special/accuracy.py` | 정확도 표 (§6) |
| `bench/special/speed.py` | scipy와 같은 자리 비교. 10⁶개(sd 1·10스레드, scipy 1스레드)와 스칼라 한 번 |
| `bench/special/cost.py` | 원소당 비용과 가중치 (§4) |
| `bench/special/s0_operands.py BASE` | 기준 빌드와 번갈아 짧은 호출을 잰다 (§3). 다른 마일스톤에서 배열을 건드리면 다시 쓴다 |

- `_cf_tan`의 속도(`bench/special/s0/speed.md`): 10⁶개에 1스레드 15.8ms, 10스레드 2.24ms(7.0배). `numpy.tan`은 2.18ms다. 스칼라 한 번은 0.126µs이고 `numpy.tan`은 0.086µs다.
  - 스칼라 호출에서 sd는 Python 인자를 해석하고 원소 1개짜리 배열을 거친다. 이 고정 비용이 약 0.1µs다. 배열의 스칼라 호출(`sd.add(1.0, 2.0)` 0.166µs)과 같은 경로다.
- `pyproject.toml`의 `test`에 mpmath를 더했다.
