# S2. 오차함수와 정규분포

> `erf erfc erfcx erfinv erfcinv ndtr log_ndtr ndtri` 여덟 개다. Cephes `ndtr.c`의 유리 근사와 Wichura의 AS241을 가져왔다(Q4). 설계는 docs/design/special.md §3.4, §5.1, API는 docs/api/special.md §2다.

## 2. 계수는 어디서 왔나
- `special/coeffs/cephes_ndtr.hpp`: Cephes 2.9의 `ndtr.c`(Moshier, scipy가 BSD로 포함)에서 가져왔다. 근사는 셋이다.
  - |x| < 1: `erf(x) = x·T(x²)/U(x²)`
  - 1 ≤ x < 8: `erfc(x) = exp(−x²)·P(x)/Q(x)`
  - x ≥ 8: `erfc(x) = exp(−x²)·R(x)/S(x)`
- `special/coeffs/as241.hpp`: Wichura(1988)의 PPND16이다. 중심 `|p − ½| ≤ 0.425`, 꼬리 `s = √(−log min(p, 1−p))`의 s ≤ 5와 s > 5, 셋이다.
- 계수는 원문의 십진 표기를 그대로 옮겼다. 직접 만들지 않는다(Q4). 이 계수들은 minimax 유리 근사다. 구간 안의 최대 상대오차가 가장 작도록 Remez 교대 정리로 맞춘 것이다. 구간을 나누는 이유는 한 식으로 넓은 범위를 맞추면 차수가 크게 오르기 때문이다.

## 3. x²의 반올림이 지수에 들어가는 문제
- `exp(−x²)`를 계산하려면 x²를 먼저 반올림한다(`hi`). 그 상대오차 2⁻⁵³은 지수에 들어가면 절대오차 `2⁻⁵³·x²`가 된다. 즉 결과의 상대오차가 x²배로 커진다.
- x = 19.6이면 x² ≈ 384배다. scipy의 `erfc`가 거기서 124 ULP(상대 2.7e-14)였다. 계약 1e-14를 넘는다.
- **고침**
  - 반올림 오차 자체가 float64로 정확히 표현된다: `lo = fma(x, x, −hi)`. FMA는 곱을 반올림하지 않고 더하기 때문이다.
  - 그러면 `exp(−x²) = exp(−hi)·exp(−lo) ≈ exp(−hi)·(1 − lo)`다. 버린 항은 lo² < 2⁻¹⁰⁶x⁴로 ULP보다 훨씬 작다.
  - Cephes의 `expx2()`는 같은 일을 지수 두 번으로 한다. 여기서는 FMA 하나와 곱셈 하나다. `-ffp-contract=off` 아래에서 FMA는 코드에 적은 곳에서만 생기고, 여기가 그런 곳이다.
- **`ndtr`에도 같은 함정이 하나 더 있다.** `ndtr(x) = erfc(−x/√2)/2`에서 `t = x/√2`를 반올림하면 같은 이유로 `2t²`배가 된다. scipy의 `ndtr`이 x = −17.5에서 61 ULP였다.
  - 그래서 지수는 t가 아니라 x에서 `exp(−x²/2)`로 만든다. 유리식 P/Q는 t의 반올림에 둔감하다(로그 미분 ≈ −1/t).
- `erfcx`의 음수 쪽 `2·exp(x²) − erfcx(−x)`도 같은 분할을 쓴다. scipy는 x ≈ −26에서 182 ULP였고, 우리는 6.1 ULP다.

## 4. 커널의 모양: 분기 없애기를 재 보니
설계(§3.4)는 NEON 레인 둘에 세 구간을 모두 계산하고 `vbslq`로 고르는 분기 없는 방식을 계획했다. 측정해서 정하기로 했던 부분이다.

- **세 단계**
  1. NEON으로 exp·log의 인자를 버퍼에 만든다.
  2. vForce를 한 번 부른다.
  3. 유리식을 계산한다. 3단계를 네 방식으로 짜서 C++에서 단계별로 쟀다.
- **erfc의 3단계** (`bench/special/s2/variants.md`, ns/원소, 1스레드, 1–2단계 1.1ns 포함)

  | 입력 | 원소마다 분기 (채택) | NEON, 모두 계산 후 고르기 | 같은 것, Estrin |
  |---|---:|---:|---:|
  | \|x\| < 1 | 2.29 | 4.15 | 4.03 |
  | 1 ≤ x < 8 | 3.83 | 4.17 | 4.14 |
  | x ≥ 8 | 3.26 | 4.17 | 4.07 |
  | 섞임, 정렬됨 | 3.51 | 4.16 | 4.02 |
  | 섞임, 무작위 | 4.72 | 4.20 | 4.06 |

- **시도해 본 다른 두 방식** (C++ 시제품으로 쟀고 코드에 남기지 않았다)
  - **계수 고르기**: 세 유리식을 앞쪽 0으로 채워 9항으로 맞춘다. 레인마다 계수를 골라 Horner 사슬 하나로 계산한다.
    - 0을 채운 Horner는 원래와 같은 반올림을 한다(`0·w + 0 = 0`, `0·w + c₀ = c₀`). 그래서 비트가 같다.
    - 결과는 4.1ns로 "모두 계산"과 같았다. 계수마다 고르기 두 번과 상수 로드가 붙어 명령 수가 줄지 않았다.
  - **두 레인이 같은 구간일 때만 NEON**: 2.46ns(|x| < 1), 무작위 섞임 5.98ns. 분기보다 낫지 않았다.
- **ndtri** (AS241, 세 구간 모두 차수 7/7): 분기가 모든 입력에서 빨랐다(중심 2.61 대 4.61, 꼬리 4.25 대 4.63, 무작위 3.67 대 4.64).
- **왜 그런가**
  - M4의 스칼라 부동소수 연산은 NEON과 같은 실행 유닛 4개를 쓴다. 레인 둘이 이득이 되려면 명령 수가 같아야 한다.
  - 고르기 방식은 남의 구간 계산과 고르기 명령이 붙어 명령 수가 두세 배다.
  - 분기 예측기는 같은 구간이 이어지는 입력에서 거의 틀리지 않는다. 넓은 비순차 실행이 원소 사이의 Horner 사슬을 겹쳐 실행해 지연을 숨긴다.
  - 구간이 무작위로 섞여야 예측이 틀리고, 그때만 고르기가 10% 빠르다.
- **결정**
  - 3단계를 원소마다 분기하도록 했다. 비트는 두 방식이 같으므로(테스트가 `_erfc_select`와 비트로 비교한다) 속도만 보고 골랐다.
  - 비교용 `_erfc_select`, `_erfc_estrin`은 비공개 함수로 남겼다.
  - S1의 `expit`, `logit`은 구간이 둘이고 식이 짧아 고르기가 맞았다. 언제 고르기가 이기는지는 식의 길이와 구간 수에 달려 있다.
- **Horner와 Estrin**
  - Estrin은 트리 모양이라 지연이 짧다. 그러나 이 커널은 원소 사이를 겹쳐 실행하는 처리량에 묶여 있어서 이득이 거의 없었다(4.03 대 4.15).
  - 반올림 순서가 달라 최대 오차가 9.1 ULP로 Horner(7.8)보다 조금 컸다. Horner로 둔다.
  - 처음 짠 Estrin은 계수 배열을 실행 중에 만들어 16.9ns였다. 컴파일 시점에 펼치게 고치고 나서 비교했다.

## 5. 함수별로 바꾸거나 고친 것
- **`erfcx`**
  - 처음에는 x ≥ 8에 Cephes R/S를 썼는데, x ≈ 10⁴에서 21 ULP였다. R/S는 erfc가 언더플로하는 26.64까지만 맞춘 식이다.
  - 설계대로 점근급수 `1/(x√π)·(1 − u + 3u² − 15u³ + …)`(u = 1/(2x²), 17항)로 바꾸니 6.1 ULP가 됐다. 구간은 셋 그대로다.
- **`log_ndtr`**
  - 설계의 세 구간(점근급수 포함) 대신 두 구간으로 했다.
    - x ≥ 0: `log1p(−ndtr(−x))`
    - x < 0: `−x²/2 + log(erfcx(−x/√2)/2)`
  - 두 항의 부호가 같아 소거가 없고, erfcx는 언더플로하지 않는다. 그래서 x = −10¹⁵⁰에서도 별도 급수가 필요 없다.
  - `−x²/2`는 `−(0.5x)·x`로 계산한다. x·x는 |x| > 1.34e154에서 넘치지만 −x²/2는 float64 안에 있다(x = −1.86e154에서 오차 inf가 나와 찾았다).
- **`erfinv`**
  - AS241에 `q = y/2`, `min(p, 1−p) = (1 − |y|)/2`를 넘긴다. (1 + y)를 만들지 않으므로 작은 y의 비트가 산다.
  - 처음에는 서브노멀 y에서 `y/2`가 마지막 비트를 잃어 `erfinv(5e-324) = 0`이었다. 중심 값을 `y·(비율/(2√2))`로 바꿨다.
- **`erfcinv`**
  - 꼬리는 `log(min(z, 2−z)) − log 2`로 계산해 z/2를 만들지 않는다. 그래서 5e-324에서 27.21이 나온다.
  - 부호를 맨 끝에 붙여 `erfcinv(1) = −0.0`(scipy와 같음)이다.
- **AS241의 바깥**: 세 번째 유리식은 s ≤ 27(p ≥ 2.5e-317)용이다. 서브노멀 p에서는 s가 27.28까지 간다. 그 구간을 포함해 쟀고, 최대 5.4 ULP라 계약 안이다.

## 6. 정답지
- 정방향 다섯 함수는 mpmath에 그대로 있다. 다만 아주 큰 x에서 mpmath의 erfc가 내부에서 float로 넘쳐서, 그 영역은 점근식으로 대신한다.
- 역함수 셋(`ndtri erfinv erfcinv`)은 mpmath에 정확한 도구가 없다. 그래서 50자리에서 Newton 반복으로 푼다.
  - 잔차를 log 공간에 둔다: `log ncdf(x) − log p`. 깊은 꼬리에서도 수렴한다.
  - 시작값은 우리 함수의 값이지만, Newton이 수렴하므로 결과는 시작값과 무관하다.
- 입력 집합은 구간 경계(1, 8, ±√2, ±8√2, 0.075, 0.925, e⁻²⁵)의 앞뒤 4 ULP를 포함한다.

## 7. 속도 (`bench/special/s2/speed.md`, 10⁶개, ms)
| 함수 | sd 1스레드 | sd 10스레드 | scipy | scipy / sd 1 | scipy / sd 10 |
|---|---:|---:|---:|---:|---:|
| `erf` | 5.44 | 0.770 | 11.1 | 2.04 | 14.4 |
| `erfc` | 5.66 | 0.803 | 10.0 | 1.77 | 12.5 |
| `erfcx` | 7.35 | 1.04 | 12.4 | 1.68 | 11.9 |
| `erfinv` | 7.14 | 0.994 | 14.9 | 2.09 | 15.0 |
| `erfcinv` | 8.78 | 1.24 | 16.6 | 1.90 | 13.5 |
| `ndtr` | 6.12 | 0.878 | 11.7 | 1.92 | 13.4 |
| `log_ndtr` | 14.8 | 2.08 | 15.5 | 1.05 | 7.46 |
| `ndtri` | 7.95 | 1.13 | 15.0 | 1.89 | 13.2 |

- 입력은 정답지의 입력(모든 크기, 구간이 섞임)에서 뽑았다. 구간이 한쪽에 몰린 입력이면 더 빠르다(§4).
- 1스레드의 차이는 대부분 vForce `exp`·`log`에서 온다(libm의 4분의 1 정도).
- `log_ndtr`이 가장 느리다. libm `log1p`·`log`와 erfcx를 원소마다 부르기 때문이다.
- 스칼라 한 번 호출은 sd 0.13–0.16µs, scipy 0.06–0.09µs다. S1과 같은 고정 비용이다.
