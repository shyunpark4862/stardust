# 그림 영역 설계 (sd.plot)

> 상태: **PL0–PL8 구현** (2026-11-22). 큰 결정(§1.1 PL1–PL17)은 사용자가 정했다. PL18–PL22는 추천안을 사용자가 승인했다. 사용자가 2026-11-22에 남은 결정을 위임했다(추천안으로 정하고, 꼭 사용자가 정해야 하는 것만 묻는다; 성능을 가장 앞에 둔다): PL23–PL40이 그렇게 정한 것이다. 구현한 것: 글자 엔진과 장면·세 출력(PL1, PL2), `Figure`와 기본 그림(PL3, PL4), 함수 그림(PL5), 통계 그림과 결과 객체의 그림(PL6), 3D(PL7), 성능 점검(PL8). 공개 이름과 시그니처는 [docs/api/plot.md](../api/plot.md)다. 커밋하지 않았다. 사용자가 눈으로 보고 고를 것은 §10에 남겼다.

`sd.plot`(수학 함수의 그림과 논문에 싣는 그림)의 확정 사항과 내부 구조의 안을 적는다.

- 공통 규칙은 [DESIGN.md](../../DESIGN.md), 층 구조는 [ARCHITECTURE.md](../../ARCHITECTURE.md), 모든 영역의 API 규칙은 [API.md](../../API.md)에 있다. 공개 함수와 시그니처의 안은 PL0에서 `docs/api/plot.md`로 쓴다.
- 견주는 대상은 정답지가 아니라 본보기다. 그림에는 참값이 없다. 논문 그림의 본보기는 R의 ggpubr(ggplot2 위의 한 줄 함수, 깔끔한 테마, 검정 결과를 그림에 얹기), 3D의 본보기는 MuPAD(부드러운 음영, 곡면 위의 격자선, 높이에 따른 색, 눈금 달린 상자 축), 함수 그림의 본보기는 Mathematica의 `Plot`(적응 표본, 자동 범위)이다. 그대로 베끼지 않는다. matplotlib은 쓰지 않고 견줄 때만 본다(설치되어 있지 않다).
- 바닥은 배열(`csrc/array/`), 스레드풀(`csrc/parallel/`), 그리고 이 기계의 TeX Live 2025(`xelatex`, `dvisvgm` 3.4.3)다. 위로는 모든 계산 영역의 결과 객체를 받는다.
- 이 문서의 잰 값은 Apple M4 Pro, macOS 26.6.2에서 본 것이다. 다른 작업과 기기를 나눠 썼다. PL0에서 다시 잰다.

| PL31 자료에서 온 글자 | 범주와 무리의 이름처럼 자료에서 온 문자열은 LaTeX 특수 문자를 숨겨 조판한다. 사용자가 직접 쓴 문자열(라벨, 제목)은 원문 그대로다(§10의 8의 (a)) (위임) |

| PL38 3D | 그물 120 × 120칸(PL41이 더 쪼갠다), 화소마다 3 × 3 표본의 깊이 버퍼. 빛은 고정이고 두 면이 같은 밝기다(값은 PL45). 격자선은 곡면의 제 색을 어둡게 한 선(0.42배, 알파 0.6)이고 깊이 검사를 받는다. 한 선의 마디가 겹치는 곳은 한 번만 칠한다. **기본 색**: 칸에 곡면이 하나면 높이에 따른 `cool`(사용자 결정 2026-11-23; 그 전날에는 viridis였다), 여럿이면 저마다 팔레트의 색(18% 옅게)이다. 칸을 그릴 때 정한다. **배치**: 상자의 투영이 칸의 그림 사각형을 꽉 채우고 눈금과 이름은 2D와 같은 여백에 선다. 3D 칸만 있는 줄은 상자의 투영 비율을 따른다. 2D 칸 옆에서는 위아래가 맞는다. 상자의 뒤쪽 세 면은 채우지 않고 옅은 격자와 테두리만 그린다. 그래프 z = f(x, y)의 상자는 1 : 1 : 0.72, 매개변수 곡면·공간 곡선·점은 자료의 비율이다. 높이가 달아나면(극점) PL33의 규칙으로 자른다. `zlabel`을 더했다 (위임) |

### 1.2 범위 (안)
**넣는 것**
- **바닥**: 장면(도형의 목록), 축·척도·눈금, 배치, 범례, 색과 테마, 글자(LaTeX), 출력 넷(PDF, SVG, PNG, 노트북).
- **기본 그림**: 선, 점, 막대, 영역, 오차 막대, 계단, 글자와 화살표 주석, 여러 칸(패널)과 칸 이름(A, B, C).
- **함수 그림 (2D)**: y = f(x), 매개변수 곡선, 극좌표 곡선, 음함수 곡선 f(x, y) = 0, 등고선, 밀도(색으로 보는 f(x, y)), 복소 함수의 위상 그림(domain coloring), 부등식의 영역.
- **통계 그림**: 히스토그램, 밀도 곡선, 경험 분포 함수, 상자 그림, 바이올린, 점 흩기(strip), 평균과 오차 막대, 산점도와 회귀선, QQ, 열지도, 짝 그림. **결과 객체의 그림**: 회귀의 진단 넷(잔차–적합값, QQ, 척도–위치, 지렛값), 계수와 구간, 검정 결과의 괄호와 p값, 분포의 pdf·cdf.
- **3D**: 곡면 z = f(x, y), 매개변수 곡면, 공간 곡선, 3D 점, 음함수 곡면은 나중 후보.

**빼는 것** (첫 판)
- 상호작용과 움직이는 그림(PL3), PGF/TikZ(PL10), 지도와 투영, 그래프(망) 그림, 벡터장·유선(ODE가 없다), 반투명 곡면, 볼륨 렌더링.

### 1.3 공통 원칙 (다른 영역에서 이어받는 것)
- **결정적이다.** 같은 기계, 같은 스레드 수, 같은 입력이면 같은 장면과 같은 픽셀이다(API.md §3). 점 흩기의 흩음도 `rng=`을 받는 결정적 계산이다. 시각, 난수 씨, 임시 파일 이름이 출력에 들어가지 않는다(PDF의 날짜 필드를 쓰지 않는다).
- **경고를 내지 않는다.** 그릴 수 없으면 에러다. 표본이 모자란 곳, 잘린 범위는 `Figure`의 속성으로 알린다(§2.4).
- **에러 메시지**는 API.md §2.1의 꼴이다(`function(): 'domain' must be ...`).
- **받는 입력**은 API.md §5의 상위 함수 입력이다(`sd.ndarray`, 수의 시퀀스, numpy 배열, frame의 열과 `DataFrame`).
- **별칭이 없다.** 한 그림에 한 이름이다.
- **옵션은 키워드만**, 자료와 주 인자는 `/` 앞이다(DESIGN §8.1).

### 1.4 다른 영역과의 관계
- `sd.plot`은 맨 위 층이다. 모든 영역을 쓰고, 어느 영역도 `sd.plot`을 모른다. `import stardust`가 다른 영역처럼 `sd.plot`을 읽지만 TeX를 찾는 일은 첫 그림에서 한다.
- 쓰는 것: `sd.histogram`·`sd.quantile`(배열), `sd.optimize`의 배치 근 찾기(극점과 영점 다듬기), `sd.differentiate`(곡률), `sd.stats`의 분포(QQ, 밀도), `sd.regression`·`sd.htest`의 결과 객체, `sd.random`(흩음), `sd.frame`.
- **부딪히는 이름**(§10에서 정한다): `sd.histogram`(값을 돌려주는 배열 함수)과 `sd.plot.histogram`(그림)은 같은 낱말이 다른 것을 돌려준다. `sd.quantile`과 QQ 그림, `sd.plot.function`의 `function`도 본다.
- **없는 계산** (PL15): 밀도 곡선과 바이올린에는 핵밀도추정(KDE)이 필요한데 `sd.stats`에 없다. 계산 영역에 생기면 그때 그 그림을 넣는다. 그 전에는 그 그림이 없다.
- **처음 생기는 바깥 의존**: 지금까지 라이브러리는 실행할 때 바깥 프로그램을 부르지 않았다. `sd.plot`은 `xelatex`와 `dvisvgm`을 하위 프로세스로 부른다. 이 영역에만 해당하고, 없으면 `sd.plot`의 그리기만 에러다.

## 2. API (안)

### 2.1 꼴
```python
fig = sd.plot.function(sd.special.gamma, -4, 4)          # 극점에서 끊고 범위를 알아서 잡는다
fig = sd.plot.boxplot(df, x="group", y="score")           # 논문 꼴의 상자 그림
fig.compare(sd.htest.ttest_ind(a, b))                     # 검정 결과를 괄호와 p값으로 얹는다
fig.save("fig1.pdf")                                      # 확장자가 형식을 정한다
```
- 그림 함수는 모두 `Figure`를 돌려준다. `Figure`는 칸(`Axes`)들을 갖고, 칸은 그림 요소(층)들을 갖는다.
- **겹치기**: 같은 이름의 메서드다. `fig.line(x, y)`, `fig.function(g)`는 `sd.plot.line`, `sd.plot.function`과 같은 인자를 받고 같은 칸에 층을 더한다. 모듈 함수는 "새 `Figure`를 만들고 그 메서드를 부른다"와 같다. 여러 칸의 그림에서는 `fig[0, 1].line(...)`처럼 칸을 고른다.
- **고치기**: `fig.title`, `fig.xlabel`, `fig.xlim`, `fig.xscale` 등은 속성 대입이 아니라 메서드다(`fig.xlabel(r"$x$")`). 메서드는 `fig` 자신을 돌려줘 이어 쓸 수 있다. 바꿀 수 있는 객체라는 것이 결과 객체(쓰기 금지, API.md §2.2)와 다르다. 그림은 계산의 결과가 아니라 짓는 대상이기 때문이다.
- **모으기**: `sd.plot.grid([fig1, fig2], ncols=2, labels="A")`가 그림들을 칸으로 모은다(ggpubr의 `ggarrange`에 해당).
- **내보내기**: `fig.save(path, *, dpi=300)`, `fig.to_svg()`, `fig.to_pdf()`, `fig.to_png(dpi=)`(bytes). 노트북은 `_repr_svg_`와 `_repr_png_`로 보인다(3D가 든 그림은 PNG).

### 2.2 크기와 단위
- 그림의 크기는 실제 길이다. 논문은 단 너비(mm)로 정해지므로 `width=`와 `height=`를 받고, 저장한 PDF의 크기가 정확히 그 값이다. 글자 크기는 pt다. 단위(mm, pt, 인치)는 §10에서 묻는다.
- 바깥 크기가 고정이고 안쪽(여백, 칸의 크기)을 배치가 푼다. 글자의 크기를 LaTeX로 먼저 재므로 라벨이 잘리지 않는 가장 작은 여백을 한 번에 구한다(§3.3). "tight" 옵션이 따로 없다.

### 2.3 테마와 색
- **기본 테마**는 논문 꼴이다: 왼쪽과 아래의 축 선만, 격자 없음, 눈금은 바깥쪽, 범례는 테두리 없이, 선 굵기와 글자 크기는 단 너비에서 읽히는 값. `theme=`으로 고른다(이름은 §10).
- **글꼴**은 `font='serif'`(TeX Gyre Termes + KoPubWorld 바탕 + newtxmath)와 `font='sans'`(TeX Gyre Heros + Apple SD Gothic Neo + newtxsf)다. 어느 쪽이 기본인지는 §10에서 묻는다.
- **색**: 기본 범주 색은 사용자가 고른 `'jco'`다(PL29). 학술지 꼴의 팔레트(ggsci의 npg, aaas, lancet, jco, nejm에 해당)를 `palette=`로 고른다. 연속 색은 지각적으로 고른 것(viridis 계열)과 발산형을 둔다. 색 값은 표로 코드에 넣는다.

### 2.4 `Figure`가 알려 주는 것
- 함수 그림은 무엇을 했는지를 속성으로 준다: 쓴 표본 수, 찾은 불연속과 극점의 자리, 자동으로 잡은 범위, 범위 밖이라 잘린 구간, 유한하지 않은 값이 나온 구간. 경고 대신이다(§1.3).

## 3. 바닥의 구조 (안)

### 3.1 흐름
```
그림 함수 ─▶ 층(자료 + 그리는 법) ─▶ 척도·눈금 ─▶ 글자 모으기 ─▶ LaTeX 한 번(크기 + 윤곽선)
                                                                        │
                    PDF ◀─┐                                             ▼
                    SVG ◀─┼── 장면(pt 좌표의 도형 목록) ◀── 배치(여백과 칸) ◀── 글자 상자
                    PNG ◀─┘       ▲
                                  └── 3D 칸: 래스터 그림 한 장 + 벡터 축
```
- **장면**이 가운데다. 장면은 pt 좌표의 도형 목록이다: 경로(채움·획·점선·자르기), 점 기호 묶음, 그림(래스터), 글자(윤곽선 경로의 참조). 출력 셋은 장면만 읽는다. 장면이 같으면 세 출력이 같은 그림이다.
- 장면은 골든의 단위다(§8). 사람이 읽는 글(JSON)로 떨어지고, 좌표는 float64의 비트 그대로 적는다.

### 3.2 글자 (PL7, PL8)
- 그림 하나의 모든 문자열을 모아 **`xelatex`를 한 번** 부른다. 문자열마다 상자 하나를 만들어 너비·높이·깊이를 로그로 받고(`\typeout`), 쪽마다 한 상자를 내보낸다. `dvisvgm --no-fonts`가 쪽을 윤곽선 경로로 바꾼다. 글꼴 파일을 읽거나 묶지 않는다.
- **두 길** (PL17). 한글이 없는 문자열은 pdfLaTeX(newtxtext + newtxmath, 머리말을 미리 구운 포맷 `mylatexformat`)이 조판한다. 한글이 든 문자열만 XeLaTeX(영문 TeX Gyre Termes의 OpenType 판 + KoPubWorld 바탕)가 조판한다. 한글 글꼴이 시스템 글꼴(OpenType)이라 pdfLaTeX이 바로 쓰지 못하기 때문이다. 두 길에서 같은 영문 문자열의 상자 크기가 같은지를 PL0에서 잰다.
- **잰 값** (PL0, `tools/plot_probe.py`; 문자열 14개, 세리프와 산세리프가 같다):

  | 단계 | 시간 |
  |---|---|
  | pdfLaTeX, 포맷 없이 | 123–153 ms |
  | pdfLaTeX, 미리 구운 포맷(굽기는 한 번 약 0.2초) | 92 ms (문자열 1개도 같다: 프로세스를 띄우는 값이다) |
  | XeLaTeX (한글 길, 문자열 18개) | 290–334 ms |
  | `dvisvgm`, DVI | 290 ms (1쪽), 310–340 ms (14쪽) |
  | `dvisvgm`, XDV | 455–670 ms (1쪽), 480–720 ms (18쪽) |

  `dvisvgm`은 쪽 수와 거의 무관하게 부를 때마다 약 0.29초가 든다(글꼴을 읽는 값이고 옵션으로 줄지 않았다). 그래서 그림 하나의 새 문자열은 모두 한 번에 넘긴다.
- **그림 한 장의 글자 시간** (위에서): 글자가 모두 캐시에 있거나 눈금 숫자뿐이면 0, 새 영문·수식 라벨이 있으면 약 0.4초(92 + 290 ms), 새 한글 라벨이 있으면 약 0.8–1.0초다. 표본과 래스터는 수 ms(추정)다.
- **구현한 길** (PL1, `src/stardust/plot/_text.py`; PL14, PL23). 탐침 뒤에 `dvisvgm`의 0.29초를 없애려고 구조를 바꿨다.
  1. **배치는 DVI에서 읽는다.** 문자열마다 TeX가 놓은 글리프(글꼴, 코드, 자리)와 괘선을 DVI(한글 길은 XDV)에서 직접 읽어 sp 정수로 둔다(`_dvi.py`: DVI·XDV의 명령과 TFM 너비, TeX의 `scaled` 곱). `dvisvgm`은 문자열에는 쓰지 않는다.
  2. **윤곽선은 글리프마다 한 번만 받는다.** 처음 보는 (글꼴, 코드)만 모아 한 쪽에 한 글리프씩 조판하고(TFM 글꼴은 plain TeX, 시스템 글꼴은 plain XeTeX의 `\XeTeXglyph`) `dvisvgm`으로 윤곽선을 받아 글꼴마다의 파일에 둔다. 가상 글꼴은 `dvisvgm`이 풀어 준다. 글꼴 파서는 여전히 없다(PL7).
  3. **숫자는 직접 늘어놓는다.** `$-1.5$`와 `$10^{-3}$` 꼴은 숫자·빼기표·소수점의 한 글자 배치(본문 크기와 첨자 크기)를 이어 붙인다. TeX의 배치와 글리프 하나하나의 자리까지 sp 단위로 같다(테스트가 본다). 처음 숫자를 만나면 한 글자 스물다섯을 한 번에 조판한다.
  4. **디스크 캐시** (PL22): 문자열의 배치는 글꼴 벌마다 `strings.jsonl`(덧붙이기만 한다), 윤곽선은 `glyphs/<글꼴>.json`이다. 폴더는 TeX 프로그램과 머리말의 도장으로 갈린다. 구운 포맷도 그 폴더에 있다.
  5. **함께 돌린다**: pdfLaTeX 길과 XeLaTeX 길, TFM 글리프와 시스템 글꼴 글리프의 윤곽선 받기가 각각 동시에 돈다.
- **잰 값** (PL1, 표본 그림 하나: 문자열 15개, 한글 라벨 하나, 수식 둘):

  | 경우 | 시간 |
  |---|---|
  | 캐시가 빈 첫 그림(포맷은 있음) | 0.95–1.2초 |
  | 같은 그림 다시(같은 프로세스) | 1 ms |
  | 새 프로세스, 캐시 있음 | 2 ms |
  | 아는 글리프로 된 새 영문·수식 라벨 | 약 0.1초 (pdfLaTeX 한 번) |
  | 아는 글리프로 된 새 한글 라벨 | 0.31–0.39초 (XeLaTeX 한 번) |
  | 새 숫자 200개 | 0.6–0.8 ms |

  새 라벨이 0.4초에서 0.1초로 줄었다. 남은 0.1초는 pdfLaTeX 프로세스를 띄우는 값이다. 더 줄이려면 TeX를 띄워 두고 `-ipc`(DVI를 소켓으로 내보내는 TeX Live의 옵션, 이 기계의 `latex`에 있다)로 쪽을 받는다(PL8의 후보).
- **조판 오류**: 한 묶음에서 실패한 문자열은 로그의 상자 줄 수로 가린다(문자열 하나를 마칠 때마다 한 줄을 쓴다). 묶음을 깨뜨리는 문자열(짝이 맞지 않는 중괄호, 숨기지 않은 `%`)은 TeX에 넘기기 전에 막는다. 실패한 묶음의 문자열은 하나도 캐시에 넣지 않는다.
- **`dvisvgm`의 별칭**: 두 글꼴이 같은 글리프를 쓰면 `<defs>`에 `<use id=…>`로 별칭을 적는다. 이것을 따라가지 않으면 빼기표와 근호가 빈다(PL1에서 겪었다).
- **두 길의 일치** (탐침): 같은 영문 문자열의 **너비는 두 길에서 같다**(세리프, 산세리프 모두). 높이와 깊이는 세리프에서 0.07 pt, 산세리프에서 0.15 pt까지 다르다(Type 1 판과 OpenType 판의 글자 상자가 다르다). 문자열 하나는 한 길로만 조판하므로(한글이 있는지로 정한다) 같은 글자가 두 크기를 갖지는 않는다. 산세리프의 `$\sin x$`는 0.43 pt 다르다(XeLaTeX 길에서 연산자 이름의 글꼴이 다르다). PL1에서 머리말을 맞춘다.
- **확인한 것**: newtxsf는 XeLaTeX에서 오류 없이 돈다. 시스템 글꼴은 이름이 아니라 파일 경로로 준다(newtx와 함께 쓰면 이름으로 찾지 못했다). `dvisvgm`은 pdfLaTeX 길의 쪽마다 PostScript special 하나를 무시한다고 알린다(Ghostscript 연결이 없다). 윤곽선에는 영향이 없어 보이나 PL1에서 눈으로 확인한다.
- **나중 후보**: TeX를 띄워 두고 `-ipc`로 쪽을 받기(새 영문 라벨 0.1초 → 수 ms), 자주 쓰는 한글 음절의 윤곽선을 미리 받아 두기.
- **XeLaTeX 길의 머리말**: newtxtext·newtxmath(산세리프는 newtxsf)를 먼저 읽고 `fontspec`(no-math)과 `xeCJK`로 한글 글꼴을 얹는다. 한글 사이의 띄어쓰기는 `xeCJK`의 `CJKspace`를 켜야 남는다. 탐침에 쓴 머리말이 `tools/plot_probe.py`에 있다.
- 수식은 문자열 안의 `$...$`다. 문자열은 LaTeX 원문 그대로 넘긴다(밑줄, `%` 같은 특수 문자를 숨겨 주지 않는다). 숨겨 줄지, 눈금 숫자를 수식 꼴(`$-1.5$`, 긴 빼기표)로 조판할지는 §10에서 묻는다.
- **대가**: PDF의 글자가 윤곽선이라 고르거나 찾을 수 없고 파일이 조금 크다. 논문 그림에서는 흔한 꼴이다(나중 후보: 글꼴을 묻는 PDF).

### 3.3 배치
- 순서: (1) 척도와 범위 → (2) 눈금 후보와 라벨 문자열 → (3) LaTeX로 크기 재기 → (4) 여백과 칸의 크기 풀기 → (5) 장면.
- 눈금의 수는 축의 길이에 달려 있고 축의 길이는 라벨의 너비에 달려 있다. 후보 눈금 집합 몇 개의 라벨을 (3)에서 한꺼번에 재고 (4)에서 고르면 LaTeX는 한 번이다.
- 여러 칸은 줄과 열의 여백을 함께 푼다(같은 열의 칸은 왼쪽 축이 한 줄에 선다). 칸 이름(A, B)과 함께 쓰는 축·범례도 여기서 자리를 받는다.

### 3.4 눈금과 척도
- 눈금은 Talbot·Lin·Hanrahan(2010)의 확장 Wilkinson 알고리즘을 추천한다(단순함, 범위 덮기, 밀도, 읽기 쉬움을 점수로 고른다). 라벨이 겹치지 않는지를 잰 너비로 본다.
- 척도: 선형, 로그, 대칭 로그, 범주, 날짜는 나중 후보(frame에 날짜 dtype이 없다).
- 눈금 숫자의 꼴(자릿수, 지수 표기 `10^{-3}`)은 한 축의 모든 눈금이 같은 자릿수가 되게 정한다.

### 3.5 래스터라이저 (C++, `csrc/plot/`)
- **2D**: 경로의 면적 덮임을 정확히 쌓는 주사선 방식(부호 있는 면적 누적)이다. 표본 무늬가 없어 결정적이고 안티에일리어싱이 매끄럽다. 획은 자신의 윤곽 다각형으로 바꿔 같은 방식으로 채운다(양쪽 변을 따라가며 바깥쪽 이음은 마이터·둥근 꼴, 안쪽은 두 변의 교점; PL26). 곡선은 0.05픽셀 허용오차로 선분으로 편다. 색은 sRGB 값 그대로 섞는다(PL27).
- **3D**: §6.
- 큰 그림은 줄 묶음으로 나눠 스레드풀이 그린다. 줄 묶음은 그림의 크기로만 정해지므로 결과는 스레드 수와 무관하다.
- PNG의 압축은 Python 표준 라이브러리의 `zlib`가 한다. 골든은 파일의 바이트가 아니라 **픽셀 버퍼의 해시**를 본다(zlib의 판이 바뀌어도 그림은 같다).

### 3.6 벡터 출력
- **SVG**: 장면을 그대로 적는다. 글자의 윤곽선은 `<defs>`에 한 번 두고 참조한다.
- **PDF**: 경로, 채움, 획, 자르기, 투명도, 그림(Flate)만 쓰는 작은 쓰기를 직접 짠다. 글꼴 객체가 없어 단순하다. 바깥 라이브러리를 쓰지 않는다.
- 벡터 출력의 획은 그 형식의 획 그대로다(다각형으로 바꾸지 않는다). 래스터라이저의 획과 눈에 보이는 차이가 없는지를 PL2에서 겹쳐 본다.

### 3.7 성능을 위해 포기하는 것 (PL14)
| 포기하는 것 | 얻는 것 | 남는 대가 |
|---|---|---|
| 글자마다 LaTeX를 돌리는 단순함 | 글자가 캐시에 있으면 LaTeX 호출이 0번(§3.2) | 처음 한 번의 준비 시간, 글자 길의 코드가 넷으로 늘어남 |
| 표본의 수학적 보증 | 구간 연산 없이 배치 호출 몇 번으로 끝남(§4) | 표본 사이의 좁은 뾰족점을 놓칠 수 있다. `Figure`가 쓴 표본 수를 알린다 |
| 화면보다 높은 정밀도 | 극점과 불연속을 0.1픽셀까지만 다듬는다 | `Figure`에 적는 자리는 그 정밀도의 값이다 |
| 점마다 부르는 함수 | 표본의 계산이 배열 연산 | 스칼라만 받는 함수는 느린 길이거나 받지 않는다(§10의 13) |
| 큰 자료의 완전한 벡터 | 점이 많은 층을 PDF·SVG 안에서 그림 한 장으로 굽는다(문턱은 PL8에서 잰다) | 그 층은 확대하면 픽셀이 보인다. 축과 글자는 벡터다 |

포기하지 않는 것: 글자의 품질, 결정성(비용이 거의 없다), 자동 기능의 품질(시간이 거의 들지 않는 곳이다).

## 4. 함수 그림의 방법 (안)

- **부르는 법**: `f`는 `sd.ndarray`를 받아 같은 모양의 배열을 돌려주는 함수다(`sd.sin`, `sd.special.gamma`, 람다). 원소별로만 되는 함수를 어떻게 받을지는 §10에서 묻는다(optimize·integrate의 원소별 무리와 같은 규칙이 후보다).
- **적응 표본**: 고른 격자에서 시작해, 이웃한 세 점이 화면에서 꺾이는 각이 기준보다 큰 구간을 반으로 나눈다. 기준은 자료 좌표가 아니라 화면 좌표(pt)에서 잰다. 나눈 점은 구간의 가운데라 결정적이다. 깊이와 표본 수에 상한이 있다.
- **불연속과 극점**: 나눠도 양 끝의 차이가 줄지 않는 구간은 뜀이고, 값이 커지며 부호가 바뀌는 구간은 극점이다. 그곳에서 선을 끊는다(세로선을 긋지 않는다). 자리는 배치 근 찾기로 다듬어 `Figure`에 적는다(§2.4).
- **점근선**: 극점에서는 곡선을 범위의 끝에서 자르고, 세로 점근선을 가는 점선으로 보일 수 있다(기본으로 보일지는 §10). 수평·사선 점근선은 찾지 않는다(나중 후보).
- **자동 범위**: 표본 값의 분위수로 본체를 잡고, 본체에서 멀리 나가는 값(극점 근처)을 자른다. 잘린 것은 `Figure`가 알린다. x의 범위를 주지 않은 호출을 받을지(영점, 극값, 주기에서 볼 만한 구간을 고른다)는 §10에서 묻는다.
- **너무 빠른 진동**: 표본 상한까지 나눠도 한 픽셀 안에서 여러 번 오르내리는 구간(sin(1/x)의 0 근처)은 선 대신 최솟값과 최댓값 사이의 띠로 채운다. 선이 뭉쳐 얼룩이 되는 것보다 옳은 그림이다.
- **여러 함수와 조각**: 함수의 목록을 주면 한 칸에 겹치고 색과 범례를 붙인다. 범위는 함께 잡는다. 정의역이 조각난 함수는 조각마다 선이 끊긴다(NaN 구간과 같은 규칙).
- **눈금**: 범위가 π의 배수에 맞으면 π 단위의 눈금을 고를 수 있다(자동으로 고를지는 §10).
- **유한하지 않은 값**: NaN 구간은 비우고, 정의역의 끝(√x의 0)은 끝점을 이분으로 다듬어 선이 끝까지 닿게 한다.
- **음함수 곡선과 등고선**: 사분 트리로 부호가 바뀌는 칸만 잘게 나눈 뒤 marching squares로 잇고, 꼭짓점을 근 찾기로 다듬는다. 고른 격자보다 적은 계산으로 뾰족한 곳과 교차점을 살린다.
- **복소 함수**: 위상을 색상으로, 크기를 밝기의 띠로 보인다. `sd.special`의 복소수 판과 잘 맞는다.
- 표본의 계산은 배치 호출 몇 번이다(점마다 Python 호출이 아니다).

## 5. 통계 그림과 결과 객체 (안)

- **자료를 받는 법**: 배열을 바로 주거나(`sd.plot.scatter(x, y)`), `DataFrame`과 열 이름을 준다(`sd.plot.scatter(df, x="a", y="b", color="g")`). 뒤의 꼴에서 `color=`·`shape=`가 열 이름이면 그 열의 값으로 무리를 나누고 범례를 만든다. 문법형(grammar)이 아니라 함수마다 정해진 인자다(PL6).
- **통계량은 계산 영역이 낸다.** 상자 그림의 사분위는 `sd.quantile`, 히스토그램은 `sd.histogram`, QQ는 분포의 `ppf`, 오차 막대는 `sd.stats`의 값이다. 그림 안에 다른 정의의 통계량을 두지 않는다. 그림이 보이는 수와 계산 함수가 주는 수가 같다.
- **검정 결과 얹기** (ggpubr의 `stat_compare_means`에 해당): `fig.compare(result)`가 `sd.htest`의 결과 객체를 받아 무리 사이의 괄호와 p값(또는 별)을 그린다. 그림이 검정을 스스로 고르지 않는다. 사용자가 한 검정의 결과를 그대로 보인다. 다중 비교의 결과는 괄호 여럿이 된다.
- **회귀 결과**: `sd.plot.scatter(...).fit(result)`가 회귀선과 신뢰 띠, 식과 R²를 얹는다. `sd.plot.diagnostics(result)`가 진단 넷을 2 × 2 칸으로 그린다. `sd.plot.coefficients(result)`가 계수와 구간을 그린다.
- **분포**: `sd.plot.distribution(dist, kind="pdf")`가 분포의 받침을 알아서 잡아 그린다. 이산 분포는 막대다.
- 수의 표기(p값의 자릿수 등)는 `summary()`의 규칙(API.md §2.3)과 같게 한다.

## 6. 3D (안)

- **곡면의 그물**: z = f(x, y)를 삼각형 그물로 만든다. 굽은 곳은 잘게 나눈다(§4의 사분 트리와 같은 부품). 극점과 범위 밖은 잘라 낸다.
- **렌더러**: C++ z-버퍼다. 삼각형마다 픽셀의 깊이를 견주므로 교차하는 곡면이 옳게 그려진다. 음영은 픽셀마다 법선을 보간해 계산한다(Phong). 색은 높이나 주어진 함수에서 온다. 안티에일리어싱은 고정된 무늬의 초과 표본이라 결정적이다.
- **격자선**: MuPAD처럼 매개변수 선을 곡면 위에 그린다. 삼각형의 변이 아니라 x와 y가 고른 선이고, 깊이 검사를 받는다.
- **축**: 상자의 뒤쪽 면과 눈금은 곡면 그림의 아래에, 앞쪽 모서리는 위에 벡터로 얹는다. 글자는 화면을 향한다.
- **카메라**: 방위각, 고도각, 원근·직교를 인자로 준다. 상호작용이 없으므로(PL3) 기본 시점이 좋아야 한다. 기본값을 본보기 그림들로 정한다.
- **출력**: 곡면 층은 정해진 dpi의 그림 한 장으로 PDF·SVG에 들어간다(PL9). PNG는 전체를 한 번에 굽는다.

## 8. 검증 (안)

- **장면 골든** (PL12): 대표 그림마다 장면의 JSON을 `tests/golden/`에 기록하고 비트까지 견준다. 글자는 문자열과 자리만 들어간다(윤곽선은 뺀다). 글자의 상자 크기는 **고정한 표**(`tests/plot/data/`의 기록)를 읽어 TeX 없이 돌게 한다. TeX의 판이 바뀌어도 장면 골든은 그대로다.
- **PNG 비트 골든**: 같은 그림을 자체 래스터라이저로 굽고 픽셀 버퍼의 해시를 견준다. 글자의 윤곽선도 고정한 표본을 쓴다. 눈으로 볼 기준 그림 몇 장을 함께 둔다.
- **LaTeX 길의 테스트**: 실제로 `xelatex`·`dvisvgm`을 불러, 고정한 표본과 상자 크기가 같은지 본다. TeX의 판이 바뀌면 이 테스트만 알려 준다. 등급은 deep이다(느리다).
- **성질 테스트**: 눈금이 범위를 덮고 고른 간격인지, 라벨이 겹치지 않는지, 저장한 PDF의 크기가 요청과 같은지, 적응 표본이 알려진 함수(tan, 1/x, Γ, sin(1/x))의 극점과 불연속을 찾는지, 장면이 스레드 수와 무관한지.
- **출력 사이의 일치**: SVG와 PDF를 바깥 도구(`dvisvgm`, Ghostscript: 설치되어 있다)로 구워 자체 PNG와 견주는 것은 허용오차 비교이고 deep 등급이다.
- **API 표면**: `docs/api/plot.md`의 시그니처 블록을 `tests/plot/test_api_surface.py`가 읽는다(다른 영역과 같다).
- **눈으로 보기**: 마일스톤마다 본보기 그림 묶음(갤러리)을 만들어 사용자가 본다. 예쁜지는 테스트가 판정하지 못한다.
