# 장 하나를 쓸 때의 절차와 점검표

지침이 장을 거듭하며 흐려지지 않게 하려는 문서다. **장 하나를 시작할 때마다 이 파일과 GUIDE.md 전체를 처음부터 다시 읽는다.** 요약본이나 기억에 기대지 않는다.

## 절차

1. **다시 읽기**: GUIDE.md 전체, 이 파일, OUTLINE.md의 해당 장 항목을 읽는다.
2. **계획 파일**: `textbook/plans/NN-이름.md`를 쓴다. 아래 점검표의 항목마다 이 장에서 어떻게 지킬지를 적는다. 특히 다음을 적는다.
   - 다룰 API 목록과 각 API를 설명할 절
   - Theory·Algorithms·Implementation 절 배치와 예상 분량(세 축이 대등한지)
   - 그림 목록(무엇을 보여 주는지, 데이터를 어떻게 얻는지)
   - 유사코드 목록
   - 직접 계산하거나 측정할 수치 목록
3. **재료 읽기**: 라이브러리 코드(`csrc/`, `src/`)와 설계 문서(`docs/`)를 읽기만 한다. 수치는 믿지 않고 직접 다시 얻는다.
4. **계산과 측정**: 스크립트와 C 코드는 scratchpad의 `chNN/`에 둔다. 그림 데이터와 그림을 만드는 스크립트는 `textbook/figures/NN/`에 커밋한다(다시 만들 수 있게).
5. **초고**: 계획 파일을 옆에 두고 쓴다.
6. **자동 점검**: `python3 tools/audit_chapter.py chapters/…tex`를 돌려 모든 항목을 통과시킨다.
7. **검토**: 수학 검토 에이전트와 깊이 검토 에이전트를 띄운다. 깊이 검토의 브리프에는 GUIDE.md §5와 이 점검표를 그대로 넣는다.
8. **윤문**: humanize-korean(진단 → 처방 적용 → 복원 스크립트 → 게이트).
9. **쪽 확인**: 빌드한 PDF를 pdftoppm으로 이미지로 떠서 상자, 그림, 표, 알고리즘, 여백을 눈으로 확인한다.
10. **기록**: 계획 파일 끝에 점검표 결과를 적고 커밋한다. 사용자에게 새로 받은 지침은 GUIDE.md에 더한다.

## 점검표

### 구성
- [ ] 개요(Abstract)가 5줄 이내이다.
- [ ] 장·절·소절 제목이 영어 Title Case이다.
- [ ] 주제마다 Theory → Algorithms → Implementation이 이어지고, 세 축의 분량과 깊이가 대등하다.
- [ ] 이 장이 맡은 API가 빠짐없이 본문에서 구현까지 설명된다. 장 끝 표(APIs in This Chapter)에 API와 그것을 설명한 절이 있다.
- [ ] instardust 상자는 짧은 기술 메모일 뿐이다. 알고리즘이나 구현 설명을 상자에 넣지 않았다.

### Theory
- [ ] 쓰는 결과는 증명하거나 유도했다. 싣지 않은 증명은 "싣지 않는다"는 변명 대신 핵심 아이디어와 줄거리를 소개하고 참고할 곳(책의 절, 논문)을 적었다.
- [ ] 인용으로 넘긴 핵심 결과가 없다.

### Algorithms
- [ ] 핵심 알고리즘마다 유사코드가 있다(주석은 `//`).
- [ ] 유사코드의 단계마다 본문 설명이 있다: 무엇을 왜 하는지, 불변식, 경계 처리.
- [ ] 복잡도(연산 수, 메모리 이동)와 수치적 성질(안정성, 오차)을 밝혔다.

### Implementation
- [ ] 자료 배치, 경계와 특수값(빈 입력, NaN·inf, 특이·퇴화), 반올림, 블록화·벡터화·병렬화를 다뤘다.
- [ ] stardust가 실제로 한 선택과 그 이유를 코드에서 확인해 썼다. 측정이 근거이면 직접 다시 쟀다.
- [ ] 검증 방법(무엇과 어떻게 견주는지)을 다뤘다.

### 그림과 수치
- [ ] 절마다 그림이나 표가 있고, 장 전체에 그림이 여럿 있다. 그림은 TikZ/pgfplots, 흑백, 캡션은 아래.
- [ ] 모든 수치를 직접 계산하거나 측정했고, 그 스크립트가 있다.

### 문체와 조판
- [ ] 한다체, 연결어미 뒤 쉼표를 남발하지 않음, 뚝뚝 끊기는 짧은 문장 나열이 없음.
- [ ] 인라인 `\frac` 없음, `\term{한글}{English}`의 영어가 비어 있지 않음.
- [ ] 참고문헌은 Crossref 등으로 확인한 것만, 중복 키 없음.
- [ ] 라벨이 책 전체에서 겹치지 않음(`tools/check_labels.py`).
- [ ] 빌드 경고 0, 쪽 이미지에서 상자·여백이 깨지지 않음.
