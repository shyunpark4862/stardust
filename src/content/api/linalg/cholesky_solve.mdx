## 한눈에 보기

`cholesky_solve`는 연립일차방정식 $Ax = b$를 두 단계로 나눠 풀 때의 둘째 단계예요.

1. [cholesky](/api/linalg/cholesky/)로 행렬 `a`를 삼각 행렬 `l`로 분해해요. 시간이 드는 일은 여기서 다 해요.
2. `cholesky_solve`에 그 `l`과 우변 `b`를 넘겨서 해를 구해요. 이 단계는 가벼워요.

```python
>>> import stardust as sd
>>> a = sd.asarray([[4.0, 2.0], [2.0, 5.0]])
>>> b = sd.asarray([8.0, 12.0])
>>> l = sd.linalg.cholesky(a)
>>> x = sd.linalg.cholesky_solve(l, b)
>>> x
array([1.0, 2.0], dtype=float64)
>>> a @ x
array([ 8.0, 12.0], dtype=float64)
```

[solve](/api/linalg/solve/)와 달리 첫 인자는 원래 행렬 `a`가 아니라 분해한 결과 `l`이에요. 답은 `solve(a, b)`와 같아요.

```python
>>> sd.linalg.solve(a, b)
array([1.0, 2.0], dtype=float64)
```

이 방법은 `a`가 대칭이고 양정치일 때만 쓸 수 있어요. 무슨 뜻인지는 바로 아래에서 설명해요.

## 어떤 행렬에 쓰나요

### 대칭이고 양정치인 행렬

**대칭 행렬**은 대각선을 기준으로 접었을 때 양쪽이 같은 행렬이에요. `a[i, j]`와 `a[j, i]`가 언제나 같아요. 복소수 행렬에서는 반대쪽이 켤레 복소수(허수부의 부호만 바꾼 수)인 **에르미트 행렬**이 같은 역할을 해요.

**양정치**(positive definite)는 숫자로 치면 "양수"에 해당하는 성질이에요. 0이 아닌 어떤 벡터 $v$를 넣어도 $v^{\mathsf T}Av$가 언제나 0보다 크다는 뜻이에요. 직관적으로는 "어느 방향으로 재도 크기가 양수로 나오는 행렬"이에요.

정의는 낯설어도 이런 행렬은 아주 흔해요.

- 변수 사이의 분산과 공분산을 모은 공분산 행렬([cov](/api/array/cov/))은 대칭이고, 변수끼리 겹치지 않으면 양정치예요.
- 데이터 행렬 `X`의 열이 서로 독립이면 $X^{\mathsf T}X$ 꼴의 행렬 `X.T @ X`는 대칭 양정치예요. 회귀 분석에서 계수를 구하는 식에 나와요.
- 거리나 유사도로 만든 행렬, 스프링·전기 회로처럼 에너지가 언제나 양수인 물리 문제의 행렬도 그래요.

### Cholesky 분해

대칭 양정치 행렬은 아래 삼각 행렬 $L$과 그 전치의 곱으로 나눌 수 있어요. 이 분해가 **Cholesky 분해**예요. 양수 $a$를 $\sqrt{a} \times \sqrt{a}$로 쓰는 것과 비슷해서, $L$을 행렬의 "제곱근"처럼 생각해도 좋아요.

$$
A = LL^{\mathsf T}
$$

<Fig caption="cholesky(a)는 a = L × Lᵀ가 되는 아래 삼각 행렬 L을 돌려줘요. cholesky_solve는 이 L을 받아요.">
  <ArrayFig name="a" data={[[4, 2], [2, 5]]} note="대칭 양정치" />
  <Op>=</Op>
  <ArrayFig name="L" data={[[2, 0], [1, 2]]} tones={[['a', 'm'], ['a', 'a']]} note="아래 삼각" />
  <Op>×</Op>
  <ArrayFig name="Lᵀ" data={[[2, 1], [0, 2]]} tones={[['a', 'a'], ['m', 'a']]} note="L의 전치" />
</Fig>

```python
>>> l
array([[2.0, 0.0],
       [1.0, 2.0]], dtype=float64)
>>> l @ l.T
array([[4.0, 2.0],
       [2.0, 5.0]], dtype=float64)
```

이렇게 나누고 나면 $Ax = b$는 $L(L^{\mathsf T}x) = b$가 돼요. 삼각 행렬이 계수인 문제 두 개를 차례로 풀면 되고, 삼각 행렬은 한 줄씩 대입만 하면 풀려요([solve_triangular](/api/linalg/solve_triangular/)). `cholesky_solve`가 하는 일이 바로 이 두 번의 대입이에요.

```python
>>> y = sd.linalg.solve_triangular(l, b, upper=False)
>>> sd.linalg.solve_triangular(l.T, y, upper=True)
array([1.0, 2.0], dtype=float64)
```

### 왜 `solve` 대신 이것을 쓰나요

- 더 빨라요. 대칭이라서 행렬의 절반만 계산하면 되기 때문에, 분해에 드는 계산이 일반 행렬 풀이의 절반쯤이에요.
- 분해를 다시 쓸 수 있어요. 같은 `a`로 우변만 바꿔 여러 번 풀어야 하면, `cholesky`는 한 번만 부르고 `cholesky_solve`만 되풀이하면 돼요.
- 양정치인지 확인이 돼요. `a`가 양정치가 아니면 `cholesky`가 에러를 내요. 양정치여야 하는 행렬(공분산 행렬 등)이 잘못 만들어졌을 때 바로 알 수 있어요.

`a`가 대칭 양정치가 아니거나, 그런지 확신이 없으면 [solve](/api/linalg/solve/)를 쓰세요.

## 분해 한 번, 풀이 여러 번

우변이 하나씩 차례로 생기는 경우가 이 함수의 대표적인 쓰임이에요. 분해한 `l`을 변수에 담아 두고 계속 써요.

```python
>>> sd.linalg.cholesky_solve(l, sd.asarray([6.0, 7.0]))
array([1.0, 1.0], dtype=float64)
>>> sd.linalg.cholesky_solve(l, sd.asarray([0.0, 8.0]))
array([-1.0,  2.0], dtype=float64)
```

우변이 처음부터 다 있으면 열로 묶어서 한 번에 넘기는 쪽이 더 간단해요. `b`를 읽는 방법은 `solve`와 똑같아요. 1차원이면 벡터 하나, 2차원 이상이면 열마다 우변 하나예요.

```python
>>> bs = sd.asarray([[8.0, 6.0],
...                  [12.0, 7.0]])
>>> sd.linalg.cholesky_solve(l, bs)
array([[1.0, 1.0],
       [2.0, 1.0]], dtype=float64)
```

첫 열 `[8, 12]`의 해가 결과의 첫 열 `[1, 2]`, 둘째 열 `[6, 7]`의 해가 `[1, 1]`이에요.

## `upper`: `cholesky`를 부를 때와 같은 값으로

Cholesky 분해는 위 삼각 행렬로도 받을 수 있어요. `cholesky(a, upper=True)`는 $A = U^{\mathsf T}U$가 되는 위 삼각 행렬 $U$를 돌려줘요. $U$는 $L$의 전치와 같아요.

```python
>>> u = sd.linalg.cholesky(a, upper=True)
>>> u
array([[2.0, 1.0],
       [0.0, 2.0]], dtype=float64)
```

위 삼각으로 분해했으면 `cholesky_solve`에도 `upper=True`를 줘요.

```python
>>> sd.linalg.cholesky_solve(u, b, upper=True)
array([1.0, 2.0], dtype=float64)
```

| `cholesky`를 이렇게 불렀으면 | 결과 | `cholesky_solve`는 이렇게 |
|---|:---:|---|
| `cholesky(a)` | 아래 삼각 $L$, $A = LL^{\mathsf H}$ | `cholesky_solve(l, b)` |
| `cholesky(a, upper=True)` | 위 삼각 $U$, $A = U^{\mathsf H}U$ | `cholesky_solve(u, b, upper=True)` |

표의 $L^{\mathsf H}$는 **켤레 전치**(전치한 뒤 켤레 복소수를 취한 것)예요. 실수 행렬에서는 그냥 전치와 같아요.

<Callout type="warn" title="두 곳의 upper가 다르면 에러 없이 틀린 답이 나와요">

`cholesky_solve`는 `upper`가 고른 쪽 삼각만 읽어요. 반대쪽은 들여다보지 않아요. 위 삼각으로 분해한 `u`를 `upper=True` 없이 넘기면 `u`의 아래쪽 삼각(대각선만 남아요)을 읽어서 엉뚱한 문제를 풀어요.

</Callout>

```python
>>> sd.linalg.cholesky_solve(u, b)
array([2.0, 3.0], dtype=float64)
```

정답은 `[1, 2]`인데 `[2, 3]`이 나왔어요. 에러도 경고도 없어요. `u`의 아래쪽 삼각은 대각선 `[2, 2]`뿐이라서, 대각 행렬 `[[4, 0], [0, 4]]`를 계수로 하는 문제를 푼 거예요.

어느 쪽을 쓰든 속도와 정확도는 같아요. 특별한 이유가 없으면 양쪽 모두 기본값(아래 삼각)으로 두는 것이 가장 안전해요.

## 배치: 여러 시스템을 한꺼번에

`cholesky`와 `cholesky_solve`는 모두 3차원 이상의 배열을 행렬 여러 장으로 봐요. 마지막 두 축이 행렬 한 장이고, 앞쪽 축은 배치예요.

```python
>>> stack = sd.asarray([[[4.0, 2.0], [2.0, 5.0]],
...                     [[1.0, 0.0], [0.0, 4.0]]])
>>> ls = sd.linalg.cholesky(stack)
>>> ls.shape
(2, 2, 2)
>>> sd.linalg.cholesky_solve(ls, b)
array([[1.0, 2.0],
       [8.0, 3.0]], dtype=float64)
```

1차원 `b`는 모든 행렬에 똑같이 써요. 결과의 0번째 행은 `stack[0]`으로, 1번째 행은 `stack[1]`로 푼 해예요. `l`과 `b`의 배치 축은 [브로드캐스팅](/api/array/broadcasting/)으로 맞춰요. 행렬마다 다른 우변 벡터를 짝지으려면 `b[..., None]`으로 끝에 길이 1인 축을 붙여요(이유는 [solve](/api/linalg/solve/) 문서에 있어요).

## 복소수 행렬

복소수 행렬은 에르미트 행렬(반대쪽 삼각이 켤레 복소수)로 보고 $A = LL^{\mathsf H}$로 분해해요. 쓰는 방법은 같아요.

```python
>>> h = sd.asarray([[4.0, 2j], [-2j, 5.0]])
>>> lh = sd.linalg.cholesky(h)
>>> lh
array([[(2+0j),     0j],
       [   -1j, (2+0j)]], dtype=complex128)
>>> sd.linalg.cholesky_solve(lh, sd.asarray([4 + 2j, 5 - 2j]))
array([(1+0j), (1+0j)], dtype=complex128)
```

`l`과 `b` 가운데 하나라도 복소수면 결과는 complex128이고, 아니면 float64예요.

## 조심할 점

### 원래 행렬 `a`를 넣으면 안 돼요

<Callout type="warn" title="첫 인자는 a가 아니라 cholesky(a)예요">

`solve(a, b)`에 익숙하면 `cholesky_solve(a, b)`라고 쓰기 쉬워요. 그러면 `a`의 아래 삼각을 분해 결과인 것처럼 읽어서 에러 없이 틀린 답이 나와요. `cholesky_solve`는 받은 삼각 행렬이 정말 `cholesky`에서 나온 것인지 알 수 없어요.

</Callout>

```python
>>> sd.linalg.cholesky_solve(a, b)
array([0.33999999999999997, 0.32000000000000006], dtype=float64)
```

정답 `[1, 2]`와 전혀 달라요. 분해와 풀이를 한 줄에 쓰면 이런 실수를 피할 수 있어요.

```python
>>> sd.linalg.cholesky_solve(sd.linalg.cholesky(a), b)
array([1.0, 2.0], dtype=float64)
```

### 양정치가 아니면 `cholesky`에서 에러가 나요

`a`가 양정치가 아닐 때의 에러는 `cholesky_solve`가 아니라 그 앞의 `cholesky`에서 나요.

```python
>>> sd.linalg.cholesky(sd.asarray([[1.0, 2.0], [2.0, 1.0]]))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: cholesky(): matrix is not positive definite
```

대칭이지만 양정치는 아닌 행렬은 [solve](/api/linalg/solve/)로 풀어요. 양정치일 수도 아닐 수도 있는 행렬이라면 먼저 Cholesky 분해를 해 보고, 실패하면 `solve`로 넘어가게 쓸 수 있어요.

```python
>>> def solve_spd(a, b):
...     try:
...         return sd.linalg.cholesky_solve(sd.linalg.cholesky(a), b)
...     except sd.linalg.LinAlgError:
...         return sd.linalg.solve(a, b)
>>> solve_spd(sd.asarray([[1.0, 2.0], [2.0, 1.0]]), sd.asarray([5.0, 4.0]))
array([1.0, 2.0], dtype=float64)
```

### `cholesky`는 대칭인지 확인하지 않아요

`cholesky`는 `a`의 아래 삼각만 읽어요. 위쪽 삼각에 무엇이 들어 있든 보지 않고, 대칭인지도 검사하지 않아요. 그래서 대칭이 아닌 행렬을 넣으면 "아래 삼각을 위로 접어 올린 대칭 행렬"의 문제를 풀게 돼요.

```python
>>> sd.linalg.cholesky(sd.asarray([[4.0, 99.0], [2.0, 5.0]]))
array([[2.0, 0.0],
       [1.0, 2.0]], dtype=float64)
```

위쪽의 `99`는 무시됐고 `[[4, 2], [2, 5]]`를 분해한 결과가 나왔어요.

### 대각선에 0이 있으면 `LinAlgError`

`cholesky`의 결과에는 대각선에 0이 나오지 않아요. 하지만 직접 만든 삼각 행렬을 넘겼고 그 대각선에 정확한 0이 있으면, 나눌 수 없으므로 `LinAlgError`예요.

```python
>>> sd.linalg.cholesky_solve(sd.asarray([[2.0, 0.0], [1.0, 0.0]]), b)
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: cholesky_solve(): singular matrix
```

`LinAlgError`는 `ValueError`의 한 종류예요. 자세한 것은 [실패와 에러](/api/linalg/errors/)에 있어요.

### NaN·inf는 읽는 쪽에 있을 때만 에러

읽는 쪽 삼각이나 `b`에 NaN이나 inf가 있으면 `ValueError`예요. 읽지 않는 쪽 삼각에 있는 것은 상관없어요.

```python
>>> sd.linalg.cholesky_solve(sd.asarray([[2.0, 0.0], [sd.nan, 2.0]]), b)
Traceback (most recent call last):
    ...
ValueError: cholesky_solve(): 'l' contains NaN or infinity
>>> sd.linalg.cholesky_solve(sd.asarray([[2.0, sd.nan], [1.0, 2.0]]), b)
array([1.0, 2.0], dtype=float64)
>>> sd.linalg.cholesky_solve(l, sd.asarray([8.0, sd.inf]))
Traceback (most recent call last):
    ...
ValueError: cholesky_solve(): 'b' contains NaN or infinity
```

### 모양과 타입

`l`은 정사각이어야 하고 `b`의 행 수가 `l`의 크기와 같아야 해요. 리스트는 받지 않아요. `upper`는 이름을 붙여서, `True`나 `False`로만 줘요.

```python
>>> sd.linalg.cholesky_solve(l, sd.asarray([8.0, 12.0, 1.0]))
Traceback (most recent call last):
    ...
ValueError: cholesky_solve(): 'l' is 2x2 but 'b' has 3 rows
>>> sd.linalg.cholesky_solve(sd.ones((2, 3)), b)
Traceback (most recent call last):
    ...
ValueError: cholesky_solve(): 'l' must be square in its last two dimensions, got 2x3
>>> sd.linalg.cholesky_solve([[1.0]], sd.asarray([8.0]))
Traceback (most recent call last):
    ...
TypeError: cholesky_solve(): 'l' must be an sd.ndarray, not list
>>> sd.linalg.cholesky_solve(l, b, upper=1)
Traceback (most recent call last):
    ...
TypeError: cholesky_solve(): 'upper' must be True or False, not int
```

### 빈 행렬

크기가 0인 시스템은 에러 없이 빈 배열을 돌려줘요.

```python
>>> sd.linalg.cholesky_solve(sd.zeros((0, 0)), sd.zeros((0,)))
array([], dtype=float64)
```

## 비슷한 함수와의 차이

| 함수 | 첫 인자 | 어떤 행렬에 | 다른 점 |
|---|---|---|---|
| `cholesky_solve(l, b)` | `cholesky(a)`의 결과 | 대칭(에르미트) 양정치 | 분해를 다시 쓸 수 있고 가장 빨라요. |
| [`solve(a, b)`](/api/linalg/solve/) | 원래 행렬 `a` | 정사각 행렬 아무것이나 | 한 번에 풀어요. 대칭이라는 점을 이용하지 않아요. |
| [`lu_solve(l, u, perm, b)`](/api/linalg/lu_solve/) | `lu(a)`의 결과 셋 | 정사각 행렬 아무것이나 | 같은 "분해 한 번, 풀이 여러 번" 방식의 일반 행렬 판이에요. |
| [`solve_triangular(l, b, upper=False)`](/api/linalg/solve_triangular/) | 삼각 행렬 | 삼각 행렬 | `l` 자체가 계수인 문제 $Lx = b$를 풀어요. `cholesky_solve`는 $LL^{\mathsf H}x = b$를 풀어요. |
| [`lstsq(a, b)`](/api/linalg/lstsq/) | 원래 행렬 `a` | 모양이 아무래도 되는 행렬 | 정사각이 아니거나 특이해도 돼요. |

같은 삼각 행렬 `l`을 `solve_triangular`와 `cholesky_solve`에 넘기면 서로 다른 문제의 답이 나와요.

```python
>>> sd.linalg.solve_triangular(l, b, upper=False)
array([4.0, 4.0], dtype=float64)
>>> sd.linalg.cholesky_solve(l, b)
array([1.0, 2.0], dtype=float64)
```

## numpy·scipy를 아는 분께

- `scipy.linalg.cho_solve`에 해당해요. numpy에는 이 함수가 없어요.
- **인자의 꼴이 달라요.** scipy는 `cho_factor`가 돌려준 튜플 `(c, lower)`를 통째로 받지만, 여기서는 삼각 행렬 배열 `l`과 `upper=` 옵션을 따로 줘요. `cho_factor`에 해당하는 함수가 따로 없고 `cholesky`의 결과를 그대로 써요.
- **기본 방향이 달라요.** `cho_factor`의 기본은 위 삼각(`lower=False`)이고, 여기서는 `cholesky`와 `cholesky_solve` 모두 아래 삼각(`upper=False`)이 기본이에요.
- `cholesky_solve`는 고른 삼각만 읽어요. 반대쪽 삼각에 무엇이 있어도 결과는 같아요.
- `check_finite=`, `overwrite_b=`가 없어요. 언제나 검사하고, NaN·inf가 있으면 `ValueError`예요.
- `b`의 규칙은 `sd.linalg.solve`와 같고(1차원일 때만 벡터), 배치를 받아요.
