## 한눈에 보기

**띠 행렬**(banded matrix)은 0이 아닌 값이 대각선과 그 가까운 몇 줄에만 모여 있는 정사각 행렬이에요. 값이 있는 부분이 대각선을 따라 띠처럼 보여서 붙은 이름이에요. 이 페이지의 두 함수는 계수 행렬 `A`가 띠 행렬인 연립방정식 `A @ x = b`를 풀어요.

| 함수 | 푸는 행렬 | 행렬을 넘기는 방법 |
|---|---|---|
| `solve_tridiagonal` | 대각선과 바로 위·아래 한 줄씩, 세 줄만 있는 **삼중대각 행렬** | 세 줄을 1차원 배열 세 개로 |
| `solve_banded` | 대각선 위·아래로 몇 줄이든 있는 띠 행렬 | 줄을 행으로 쌓은 2차원 배열 `ab` 하나로 |

두 함수 모두 N×N 행렬 전체가 아니라 띠만 받아요. 아래 식은 가장 간단한 삼중대각 연립방정식이에요.

$$\begin{bmatrix} 4 & 7 & 0 \\ 1 & 5 & 8 \\ 0 & 2 & 6 \end{bmatrix} \begin{bmatrix} x_0 \\ x_1 \\ x_2 \end{bmatrix} = \begin{bmatrix} 18 \\ 35 \\ 22 \end{bmatrix}$$

```python
>>> import stardust as sd
>>> dl = sd.asarray([1.0, 2.0])
>>> d = sd.asarray([4.0, 5.0, 6.0])
>>> du = sd.asarray([7.0, 8.0])
>>> b = sd.asarray([18.0, 35.0, 22.0])
>>> sd.linalg.solve_tridiagonal(dl, d, du, b)
array([1.0, 2.0, 3.0], dtype=float64)
```

## 왜 띠만 따로 푸나요

띠 행렬은 "가까운 것끼리만 영향을 주고받는" 문제에서 나와요.

- 막대를 여러 조각으로 나눠 온도를 계산할 때, 한 조각의 온도는 바로 옆 조각하고만 관계가 있어요.
- 점들을 부드러운 곡선으로 잇는 스플라인을 계산할 때, 한 구간의 곡선은 이웃 구간하고만 맞물려요.
- 시간 순서대로 놓인 값에서 오늘의 값이 어제·내일의 값하고만 얽힌 식을 풀 때도 그래요.

이런 문제는 미지수가 수만~수백만 개까지 커지는데, 행렬의 대부분은 0이에요. 행렬 전체를 만들어 [solve](/api/linalg/solve/)로 푸는 것과 띠만 넘겨 푸는 것은 답은 같지만 드는 비용이 크게 달라요.

| 미지수 N개, 삼중대각 | 행렬 전체로 풀기 | 띠만 넘겨 풀기 |
|---|:---:|:---:|
| 저장하는 숫자 | N × N개 | 약 3 × N개 |
| N = 10,000일 때 | 1억 개 (약 800MB) | 3만 개 |
| N이 10배가 되면 계산 시간은 | 약 1,000배 | 약 10배 |

행렬 전체를 만들어 풀어도 답은 같아요.

```python
>>> full = sd.asarray([[4.0, 7.0, 0.0],
...                    [1.0, 5.0, 8.0],
...                    [0.0, 2.0, 6.0]])
>>> sd.linalg.solve(full, b)
array([1.0, 2.0, 3.0], dtype=float64)
```

## 삼중대각 행렬: `solve_tridiagonal`

세 줄을 위에서 아래로 읽은 순서대로 1차원 배열에 담아 넘겨요.

| 인자 | 행렬의 어느 자리 | 길이 |
|:---:|---|:---:|
| `dl` | `A[1, 0]`, `A[2, 1]`, …, `A[N-1, N-2]` (대각선 바로 아래) | N-1 |
| `d` | `A[0, 0]`, `A[1, 1]`, …, `A[N-1, N-1]` (대각선) | N |
| `du` | `A[0, 1]`, `A[1, 2]`, …, `A[N-2, N-1]` (대각선 바로 위) | N-1 |

이름은 각각 아래 대각선(lower), 대각선(diagonal), 위 대각선(upper)의 머리글자예요. 순서가 `dl, d, du`, 곧 아래 줄이 먼저라는 것을 기억하세요.

### 예: 막대의 온도

양쪽 끝의 온도가 0도와 100도로 고정된 막대가 있어요. 막대 안쪽의 네 지점은 시간이 충분히 지나면 양옆 두 지점의 평균 온도가 돼요. 지점 `i`의 온도를 `T[i]`라고 하면 `T[i] = (T[i-1] + T[i+1]) / 2`이고, 정리하면 이래요.

$$-T_{i-1} + 2\,T_i - T_{i+1} = 0$$

안쪽 네 지점마다 이 식을 세우고, 이미 아는 양 끝 온도(0과 100)를 우변으로 넘기면 삼중대각 연립방정식이 돼요. 대각선은 모두 2, 위·아래 줄은 모두 -1이에요.

```python
>>> n = 4
>>> lower = -sd.ones(n - 1)
>>> main = 2.0 * sd.ones(n)
>>> upper = -sd.ones(n - 1)
>>> ends = sd.asarray([0.0, 0.0, 0.0, 100.0])
>>> temps = sd.linalg.solve_tridiagonal(lower, main, upper, ends)
>>> [round(v, 9) for v in temps.tolist()]
[20.0, 40.0, 60.0, 80.0]
```

네 지점의 온도가 20, 40, 60, 80도로, 0도에서 100도까지 고르게 올라가요. (마지막 자리의 반올림 오차를 `round`로 정리했어요.) 지점을 4개가 아니라 100만 개로 늘려도 같은 코드로 바로 풀려요.

### 우변이 여러 개일 때

`b`가 2차원이면 열마다 우변 하나로 보고 한꺼번에 풀어요. 결과도 열마다 해 하나예요.

```python
>>> two = sd.asarray([[18.0, 36.0],
...                   [35.0, 70.0],
...                   [22.0, 44.0]])
>>> sd.linalg.solve_tridiagonal(dl, d, du, two)
array([[1.0, 2.0],
       [2.0, 4.0],
       [3.0, 6.0]], dtype=float64)
```

`b`가 1차원이면 벡터 하나, 2차원 이상이면 열 묶음으로 보는 규칙은 [solve](/api/linalg/solve/)와 같아요. 자세한 것은 [선형대수의 기본](/api/linalg/basics/)에 있어요.

## 띠 저장 형식 `ab`: 대각선 한 줄이 행 하나

띠가 세 줄보다 넓으면 `solve_banded`를 써요. 이 함수는 행렬을 **띠 저장 형식**이라는 2차원 배열 `ab`로 받아요. 처음 보면 헷갈리기 쉬워요.

5×5 행렬의 대각선 아래 한 줄과 위 두 줄에 값이 있다고 해요. 대각선 아래 줄 수를 **아래 띠 폭**(`lower_bandwidth`), 위 줄 수를 **위 띠 폭**(`upper_bandwidth`)이라고 해요. 여기서는 1과 2예요. 아래 그림에서 칸에 적힌 두 자리 숫자는 그 칸의 위치예요. `12`는 1행 2열이에요.

`ab`의 모양은 `(lower_bandwidth + upper_bandwidth + 1, N)`이에요. 행의 수는 띠에 든 대각선의 수(아래 1줄 + 위 2줄 + 대각선 1줄 = 4)이고, 열의 수는 행렬의 크기 N이에요.

| `ab`의 행 | 담는 것 | 앞뒤 빈칸 |
|:---:|---|---|
| 0 | 대각선에서 두 칸 위의 줄 (`02, 13, 24`) | **앞**에 두 칸 |
| 1 | 대각선에서 한 칸 위의 줄 (`01, 12, 23, 34`) | **앞**에 한 칸 |
| 2 (= `upper_bandwidth`) | 대각선 (`00, 11, 22, 33, 44`) | 없음 |
| 3 | 대각선에서 한 칸 아래의 줄 (`10, 21, 32, 43`) | **뒤**에 한 칸 |

### 핵심 규칙: 열은 그대로, 행만 밀려요

빈칸이 앞에 붙는지 뒤에 붙는지를 외우는 것보다 이 규칙 하나를 기억하는 편이 쉬워요.

> 행렬의 j열에 있던 값은 `ab`에서도 j열에 있어요. 대각선의 값이 `upper_bandwidth`번 행에 오도록 열 전체를 위아래로 밀었을 뿐이에요.

식으로 쓰면 행렬의 `i`행 `j`열 값이 가는 자리는 이래요.

$$\texttt{ab}[\,\texttt{upper\_bandwidth} + i - j,\; j\,] = A[\,i,\; j\,]$$

대각선(`i = j`)은 `upper_bandwidth`번 행으로, 대각선 위(`i < j`)는 그보다 위쪽 행으로, 대각선 아래(`i > j`)는 아래쪽 행으로 가요.

### 행렬 전체에서 `ab` 만들기

작은 문제로 시험할 때는 행렬 전체에서 `ab`를 만들고 싶을 수 있어요. 위의 식을 그대로 옮기면 돼요.

```python
>>> def to_banded(rows, lower, upper):
...     n = len(rows)
...     out = [[0.0] * n for _ in range(lower + upper + 1)]
...     for i in range(n):
...         for j in range(n):
...             if -upper <= i - j <= lower:
...                 out[upper + i - j][j] = rows[i][j]
...     return sd.asarray(out)
...
>>> to_banded(A.tolist(), 1, 2)
array([[0.0, 0.0, 2.0, 2.0, 2.0],
       [0.0, 3.0, 1.0, 2.0, 1.0],
       [7.0, 9.0, 5.0, 7.0, 6.0],
       [3.0, 5.0, 5.0, 1.0, 0.0]], dtype=float64)
```

띠 폭을 모르면 [`bandwidth`](/api/linalg/bandwidth/)로 재요. 결과 두 값을 그대로 `to_banded`와 `solve_banded`의 띠 폭으로 쓸 수 있어요.

```python
>>> sd.linalg.bandwidth(A)
BandwidthResult(lower=1, upper=2)
```

실제로 큰 문제를 풀 때는 행렬 전체를 만들지 않고 처음부터 대각선 줄을 따로 계산해서 `ab`의 행으로 쌓아요. 행렬 전체를 만들면 메모리를 아끼는 의미가 없어지니까요.

### 띠 폭은 꼭 이름으로 넘겨요

`lower_bandwidth`와 `upper_bandwidth`는 생략할 수 없고, 이름을 붙여서만 넘길 수 있어요. `ab`의 행 수만 봐서는 4줄이 "아래 1 + 위 2"인지 "아래 2 + 위 1"인지 알 수 없기 때문이에요.

```python
>>> sd.linalg.solve_banded(ab, rhs)
Traceback (most recent call last):
    ...
TypeError: solve_banded(): incompatible function arguments. ...
```

메시지의 나머지 부분에는 함수가 받는 인자 목록이 나와요. `solve_banded(ab, rhs, 1, 2)`처럼 이름 없이 자리로 넘겨도 같은 `TypeError`예요.

두 띠 폭의 합에 1을 더한 값이 `ab`의 행 수와 다르면 에러예요.

```python
>>> sd.linalg.solve_banded(ab, rhs, lower_bandwidth=2, upper_bandwidth=2)
Traceback (most recent call last):
    ...
ValueError: solve_banded(): 'ab' must have lower_bandwidth + upper_bandwidth + 1 rows (2 + 2 + 1), got 4
```

## 삼중대각을 `solve_banded`로 쓰면

삼중대각 행렬은 위·아래 띠 폭이 모두 1인 띠 행렬이에요. 그래서 `solve_tridiagonal(dl, d, du, b)`는 다음 `ab`로 부른 `solve_banded`와 같은 일을 해요. 두 결과는 마지막 자리까지 같아요.

<Fig caption="du는 앞에 빈칸 하나, dl은 뒤에 빈칸 하나. 위 줄이 맨 위 행, 아래 줄이 맨 아래 행이에요.">
  <ArrayFig name="du" data={[7, 8]} tones={['a', 'a']} />
  <ArrayFig name="d" data={[4, 5, 6]} tones={['b', 'b', 'b']} />
  <ArrayFig name="dl" data={[1, 2]} />
  <Op>→</Op>
  <ArrayFig name="ab" data={[['·', 7, 8], [4, 5, 6], [1, 2, '·']]} tones={[['g', 'a', 'a'], ['b', 'b', 'b'], ['', '', 'g']]} note="shape (3, 3)" />
</Fig>

```python
>>> pad = sd.zeros(1)
>>> ab3 = sd.stack([sd.concat([pad, du]), d, sd.concat([dl, pad])])
>>> ab3
array([[0.0, 7.0, 8.0],
       [4.0, 5.0, 6.0],
       [1.0, 2.0, 0.0]], dtype=float64)
>>> sd.linalg.solve_banded(ab3, b, lower_bandwidth=1, upper_bandwidth=1)
array([1.0, 2.0, 3.0], dtype=float64)
```

두 함수는 줄 순서가 반대이니 조심하세요. `solve_tridiagonal`의 인자는 아래 줄 `dl`이 먼저인데, `ab`는 위 줄 `du`가 맨 위 행이에요.

띠 폭이 0이어도 돼요. 위·아래 모두 0이면 대각 행렬이고, `ab`는 대각선 한 줄뿐인 `(1, N)` 배열이에요. 이때 해는 `b`를 대각선으로 나눈 값이에요.

```python
>>> diag_only = sd.asarray([[4.0, 5.0, 6.0]])
>>> sd.linalg.solve_banded(diag_only, sd.asarray([8.0, 35.0, 24.0]), lower_bandwidth=0, upper_bandwidth=0)
array([2.0, 7.0, 4.0], dtype=float64)
```

## 여러 행렬을 한 번에

배열 인자의 앞쪽 축은 배치(여러 행렬의 묶음)로 봐요. `solve_tridiagonal`은 네 인자의, `solve_banded`는 `ab`와 `b`의 배치 축을 [브로드캐스팅](/api/array/broadcasting/)으로 맞춰요. 대각선만 다른 삼중대각 행렬 두 개를 같은 우변으로 한꺼번에 풀어요.

```python
>>> d2 = sd.asarray([[4.0, 5.0, 6.0],
...                  [8.0, 10.0, 12.0]])
>>> out = sd.linalg.solve_tridiagonal(dl, d2, du, b)
>>> out.shape
(2, 3)
>>> out[0]
array([1.0, 2.0, 3.0], dtype=float64)
```

`dl`, `du`, `b`는 하나씩이지만 `d2`의 두 행 각각에 함께 쓰였어요. `out[0]`은 처음 예제의 답과 같아요.

## 조심할 점

### 띠 폭을 바꿔 쓰거나 빈칸을 반대쪽에 두면 조용히 다른 문제를 풀어요

<Callout type="warn" title="모양이 맞으면 에러가 나지 않아요">

`ab`를 잘못 만들어도 행 수만 맞으면 에러 없이 다른 행렬의 답이 나와요. 가장 흔한 실수는 두 가지예요. 위·아래 띠 폭을 서로 바꿔 넘기는 것, 그리고 위 줄의 빈칸을 뒤에(또는 아래 줄의 빈칸을 앞에) 두는 것이에요.

</Callout>

삼중대각 예제에서 빈칸을 반대쪽에 두면 이렇게 돼요.

```python
>>> wrong = sd.stack([sd.concat([du, pad]), d, sd.concat([pad, dl])])
>>> wrong
array([[7.0, 8.0, 0.0],
       [4.0, 5.0, 6.0],
       [0.0, 1.0, 2.0]], dtype=float64)
>>> sd.linalg.solve_banded(wrong, b, lower_bandwidth=1, upper_bandwidth=1)
array([-9.5,  7.0,  2.5], dtype=float64)
```

답 `[1, 2, 3]`이 아닌 값이 에러 없이 나왔어요. 5×5 예제에서 띠 폭 둘을 바꿔 넘기면, 이번에는 우연히 풀 수 없는 행렬이 되어 에러가 나요. 하지만 언제나 에러로 알려 주는 것은 아니에요.

```python
>>> sd.linalg.solve_banded(ab, rhs, lower_bandwidth=2, upper_bandwidth=1)
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: solve_banded(): singular matrix
```

새로 만든 `ab`는 작은 크기에서 행렬 전체로 푼 답(`solve`)과 한 번 비교해 보는 것이 안전해요. 풀어 낸 `x`를 원래 식에 넣어 확인하는 방법도 있어요.

### 빈칸에 든 값은 읽지 않아요

`ab`의 모서리 빈칸(위쪽 행의 앞, 아래쪽 행의 뒤)은 행렬에 없는 자리예요. 그 값은 읽지도 검사하지도 않아서, NaN이 들어 있어도 결과가 같아요.

```python
>>> nan = float("nan")
>>> with_nan = sd.asarray([[nan, 7.0, 8.0],
...                        [4.0, 5.0, 6.0],
...                        [1.0, 2.0, nan]])
>>> sd.linalg.solve_banded(with_nan, b, lower_bandwidth=1, upper_bandwidth=1)
array([1.0, 2.0, 3.0], dtype=float64)
```

행렬 안의 자리에 NaN이나 inf가 있으면 계산하지 않고 `ValueError`예요. `solve_tridiagonal`도 같아요.

```python
>>> sd.linalg.solve_tridiagonal(dl, d, sd.asarray([7.0, nan]), b)
Traceback (most recent call last):
    ...
ValueError: solve_tridiagonal(): 'du' contains NaN or infinity
```

### 길이와 모양이 맞지 않을 때

`dl`과 `du`는 `d`보다 정확히 하나 짧아야 해요. 길이를 `d`와 같게 맞춰 넘기는 실수가 흔해요.

```python
>>> sd.linalg.solve_tridiagonal(sd.asarray([1.0, 2.0, 0.0]), d, du, b)
Traceback (most recent call last):
    ...
ValueError: solve_tridiagonal(): 'dl' must have length 2 (one less than 'd'), got 3
```

`b`의 길이(2차원이면 행 수)는 행렬의 크기 N과 같아야 해요.

```python
>>> sd.linalg.solve_tridiagonal(dl, d, du, sd.asarray([18.0, 35.0]))
Traceback (most recent call last):
    ...
ValueError: solve_tridiagonal(): the matrix is 3x3 but 'b' has 2 rows
```

`ab`는 띠가 대각선 한 줄뿐이어도 2차원이어야 해요.

```python
>>> sd.linalg.solve_banded(sd.asarray([4.0, 5.0, 6.0]), b, lower_bandwidth=0, upper_bandwidth=0)
Traceback (most recent call last):
    ...
ValueError: solve_banded(): 'ab' must have at least 2 dimensions, got 1
```

### 띠 폭에 줄 수 없는 값

띠 폭은 0 이상의 `int`예요. 음수는 `ValueError`, `1.0` 같은 float이나 `True`는 `TypeError`예요.

```python
>>> sd.linalg.solve_banded(ab3, b, lower_bandwidth=-1, upper_bandwidth=3)
Traceback (most recent call last):
    ...
ValueError: solve_banded(): the bandwidths must be >= 0, got lower_bandwidth=-1, upper_bandwidth=3
>>> sd.linalg.solve_banded(ab3, b, lower_bandwidth=1.0, upper_bandwidth=1)
Traceback (most recent call last):
    ...
TypeError: solve_banded(): 'lower_bandwidth' must be an int, not float
```

띠 폭이 행렬 크기보다 커도 돼요. 행렬 밖으로 나가는 줄은 전부 빈칸이라 읽지 않아요.

### 특이 행렬은 `LinAlgError`

해가 하나로 정해지지 않는 행렬이면 `LinAlgError`예요.

```python
>>> sd.linalg.solve_tridiagonal(sd.asarray([1.0, 0.0]), sd.ones(3), sd.ones(2), b)
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: solve_tridiagonal(): singular matrix
```

대각선에 0이 있다고 해서 꼭 특이 행렬인 것은 아니에요. 두 함수는 필요하면 방정식의 순서를 바꿔 가며 풀기 때문에, 풀 수 있는 행렬이면 대각선에 0이 있어도 답이 나와요.

```python
>>> sd.linalg.solve_tridiagonal(sd.ones(2), sd.asarray([0.0, 1.0, 1.0]), sd.ones(2), sd.asarray([2.0, 6.0, 5.0]))
array([1.0, 2.0, 3.0], dtype=float64)
```

"특이"로 보는 것은 계산 도중 정확한 0으로 나눠야 할 때뿐이에요. 거의 특이한 행렬은 에러 없이 아주 크거나 부정확한 값을 내요. 자세한 것은 [실패와 에러](/api/linalg/errors/)에 있어요.

### 정수를 넣어도 결과는 실수예요

정수와 bool 배열은 실수로 바꿔서 계산해요. 결과는 float64이고, 인자 가운데 복소수가 있으면 complex128이에요.

```python
>>> sd.linalg.solve_tridiagonal(sd.asarray([1, 2]), sd.asarray([4, 5, 6]), sd.asarray([7, 8]), sd.asarray([18, 35, 22]))
array([1.0, 2.0, 3.0], dtype=float64)
```

### 리스트는 받지 않아요

배열 인자는 모두 배열이어야 해요. 리스트는 [asarray](/api/array/asarray/)로 먼저 바꾸세요.

```python
>>> sd.linalg.solve_tridiagonal([1.0, 2.0], d, du, b)
Traceback (most recent call last):
    ...
TypeError: solve_tridiagonal(): 'dl' must be an sd.ndarray, not list
```

### 빈 행렬

크기가 0인 행렬도 받아요. 결과는 빈 배열이에요.

```python
>>> empty = sd.asarray([])
>>> sd.linalg.solve_tridiagonal(empty, empty, empty, empty)
array([], dtype=float64)
```

## 비슷한 함수와의 차이

`sd.linalg`는 행렬의 구조를 옵션이 아니라 함수 이름으로 골라요. 행렬이 어떤 모양인지는 쓰는 사람이 알고 있고, 함수는 그 말을 믿고 해당하는 자리만 읽어요.

| 행렬의 모양 | 쓸 것 | 행렬을 넘기는 방법 |
|---|---|---|
| 아무 구조 없는 정사각 행렬 | [solve](/api/linalg/solve/) | 행렬 전체 `(N, N)` |
| 대각선 한쪽이 모두 0인 삼각 행렬 | [solve_triangular](/api/linalg/solve_triangular/) | 행렬 전체. 고른 삼각만 읽어요. |
| 대각선과 위·아래 한 줄씩 | `solve_tridiagonal` | 1차원 배열 셋 |
| 대각선 근처 몇 줄 | `solve_banded` | 띠 저장 형식 `(줄 수, N)` |
| 대칭이고 양정치 | [cholesky_solve](/api/linalg/cholesky_solve/) | 먼저 [cholesky](/api/linalg/cholesky/)로 분해한 결과 |

- 삼중대각이면 `solve_banded`보다 `solve_tridiagonal`이 편해요. 빈칸을 채울 필요가 없고 줄마다 이름이 있어서 실수가 적어요. 답은 띠 폭 1, 1인 `solve_banded`와 완전히 같아요.
- 띠가 좁고 N이 크면 `solve`보다 띠 함수가 훨씬 빠르고 메모리를 적게 써요. 띠 폭이 N에 가까우면 얻는 것이 없으니 `solve`를 쓰세요. 행렬이 작으면(수십 정도) 어느 쪽이든 차이가 없어요.
- 행렬 전체에서 대각선 한 줄을 꺼낼 때는 [diagonal](/api/linalg/trace-diagonal/)의 `k`를 써요. `k=1`이 `du`, `k=0`이 `d`, `k=-1`이 `dl`이에요.

```python
>>> sd.linalg.diagonal(full, k=1)
array([7.0, 8.0], dtype=float64)
>>> sd.linalg.diagonal(full, k=-1)
array([1.0, 2.0], dtype=float64)
```

## numpy·scipy를 아는 분께

- `solve_banded`의 `ab`는 `scipy.linalg.solve_banded`의 `ab`와 같은 배치예요. 다만 띠 폭은 첫 인자인 튜플 `(l, u)`가 아니라 필수 키워드 `lower_bandwidth=`, `upper_bandwidth=`로 넘기고, 인자 순서는 `(ab, b)`예요.
- `solve_tridiagonal`은 scipy에 같은 이름의 함수가 없어요. `scipy.linalg.solve_banded((1, 1), ab, b)`와 같은 일을, 세 줄을 따로 받아서 해요.
- 대칭 양정치 띠 행렬 전용인 `solveh_banded`에 해당하는 함수는 없어요.
- `ab`의 모서리 빈칸은 NaN이어도 돼요. 행렬 안의 값은 언제나 NaN·inf를 검사하고, `check_finite=`로 끌 수 없어요. `overwrite_ab=`, `overwrite_b=`도 없어요.
- 앞쪽 축은 배치로 보고 한 번에 풀어요. 리스트와 numpy 배열은 받지 않아요.
- 정수 입력의 결과도 float64예요.
- 지금은 결과가 scipy와 비트까지 같아요(약속은 아니에요). 다만 행이 8개 이하인 `solve_banded`(띠 폭 (1, 1) 제외)는 계산 방법이 달라서 scipy와 마지막 자리가 다를 수 있어요.
