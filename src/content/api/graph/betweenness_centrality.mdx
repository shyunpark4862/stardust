## 무엇을 계산하나요

두 마을 무리를 잇는 도로망이 있어요. 어느 교차로가 막히면 가장 많은 사람이 돌아가야 할까요? 많은 사람이 가장 빠른 길로 다닌다면, 가장 빠른 길이 자주 지나가는 교차로가 그곳이에요.

**매개 중심성**(betweenness centrality)은 노드 $v$를 지나는 최단 경로가 얼마나 많은지를 세요. $v$가 아닌 두 노드 $s$, $t$마다, $s$에서 $t$로 가는 최단 경로 가운데 $v$를 지나는 경로의 몫을 구해서 모두 더해요.

$$
c(v) = \sum_{s \ne v \ne t} \frac{\sigma_{st}(v)}{\sigma_{st}}
$$

$\sigma_{st}$는 $s$에서 $t$로 가는 최단 경로의 수, $\sigma_{st}(v)$는 그 가운데 $v$를 지나는 경로의 수예요. 최단 경로가 여럿이면 몫을 나눠 가져요.

```python
>>> import stardust as sd
>>> roads = [(0, 1), (0, 2), (1, 2), (2, 3), (3, 4), (4, 5), (4, 6), (5, 6)]
>>> G = sd.zeros((7, 7))
>>> for i, j in roads:
...     G[i, j] = 1
>>> bc = sd.graph.betweenness_centrality(G, directed=False)
>>> bc
array([               0.0,                0.0, 0.5333333333333333,
                      0.6, 0.5333333333333333,                0.0,
                      0.0], dtype=float64)
```

두 삼각형을 잇는 노드 3이 가장 높아요. 왼쪽 무리 {0, 1, 2}와 오른쪽 무리 {4, 5, 6} 사이의 아홉 쌍이 모두 3을 지나요. 노드 2와 4가 그다음이고, 삼각형의 바깥 노드 0, 1, 5, 6은 어떤 최단 경로의 가운데에도 있지 않아서 0이에요.

## 결과 읽기: `normalized`

기본(`normalized=True`)으로는 값을 노드 쌍의 수로 나눠요. 유향 그래프는 $v$를 뺀 순서쌍의 수 $(n - 1)(n - 2)$로 나누고, 방향 없는 그래프는 쌍 $\{s, t\}$를 한 번씩 세어 $(n - 1)(n - 2)/2$로 나눠요. 그래서 값은 0과 1 사이이고, 노드 수가 다른 그래프끼리도 견줄 수 있어요. 1은 다른 모든 쌍의 최단 경로가 그 노드를 지난다는 뜻이에요(별 모양 그래프의 가운데 노드).

`normalized=False`면 몫을 더한 값 그대로예요. 방향 없는 그래프에서는 $(s, t)$와 $(t, s)$를 한 번만 세요.

```python
>>> sd.graph.betweenness_centrality(G, directed=False, normalized=False)
array([0.0, 0.0, 8.0, 9.0, 8.0, 0.0, 0.0], dtype=float64)
```

노드 3은 아홉 쌍, 노드 2는 0과 1에서 3, 4, 5, 6으로 가는 여덟 쌍이 지나가요. 노드 쌍이 $6 \cdot 5 / 2 = 15$개라 정규화한 값은 $9/15 = 0.6$과 $8/15$예요.

## 최단 경로가 여럿일 때

최단 경로가 여럿이면 몫을 나눠요. 네모 0–1–2–3–0에서 0과 2 사이의 최단 경로는 1을 지나는 것과 3을 지나는 것 둘이라, 1과 3이 저마다 1/2씩 가져요.

```python
>>> square = sd.zeros((4, 4))
>>> for i in range(4):
...     square[i, (i + 1) % 4] = 1
>>> sd.graph.betweenness_centrality(square, directed=False, normalized=False)
array([0.5, 0.5, 0.5, 0.5], dtype=float64)
```

노드마다 마주 보는 쌍 하나에서 1/2씩 받아 모두 0.5예요.

## 방향: `directed`

`directed=True`(기본값)면 변을 적힌 방향으로만 다녀요. 위 예제의 `G`는 위 삼각에만 변이 있어서 유향으로 읽으면 번호가 커지는 쪽으로만 갈 수 있어요.

```python
>>> sd.graph.betweenness_centrality(G)
array([                0.0,                 0.0, 0.26666666666666666,
                       0.3, 0.26666666666666666,                 0.0,
                       0.0], dtype=float64)
>>> sd.graph.betweenness_centrality(G + G.T)
array([               0.0,                0.0, 0.5333333333333333,
                      0.6, 0.5333333333333333,                0.0,
                      0.0], dtype=float64)
```

번호가 커지는 쪽으로만 가면 닿지 못하는 쌍이 많아져서 값이 작아져요. 닿지 못하는 쌍은 세지 않아요. 두 방향을 모두 적은 대칭 행렬(`G + G.T`)을 유향으로 읽으면 순서쌍을 둘 다 세면서 순서쌍의 수로 나누니, `directed=False`의 정규화한 값과 같아요.

## 무게: `unweighted`

기본으로는 변의 무게를 길이로 보고, 무게의 합이 가장 작은 경로를 최단 경로로 써요. 아래에서는 노드 1과 5를 바로 잇는 길이 5의 변을 놓았어요. 1에서 5로 2, 3, 4를 거쳐 가는 길은 변 넷이지만 길이의 합이 4라서 바로 가는 변보다 짧아요.

```python
>>> Gw = G + G.T
>>> Gw[1, 5] = Gw[5, 1] = 5.0
>>> sd.graph.betweenness_centrality(Gw)
array([               0.0,                0.0, 0.5333333333333333,
                      0.6, 0.5333333333333333,                0.0,
                      0.0], dtype=float64)
>>> sd.graph.betweenness_centrality(Gw, unweighted=True)
array([                0.0, 0.26666666666666666, 0.16666666666666666,
       0.13333333333333333, 0.16666666666666666, 0.26666666666666666,
                       0.0], dtype=float64)
```

무게를 읽으면 1–5 변이 어떤 최단 경로에도 쓰이지 않아서 처음 결과와 같아요. `unweighted=True`면 1–5가 변 하나짜리 길이라 두 무리 사이의 많은 경로가 그리로 가고, 노드 3의 값이 줄고 노드 1과 5의 값이 커져요.

무게는 모두 양수여야 해요. 무게 0의 변이 있으면 길이가 같은 경로가 끝없이 많아질 수 있어서 `ValueError`예요. 무게 0이나 음수가 있는 그래프에서 변의 수로 세려면 `unweighted=True`를 줘요.

```python
>>> Z = sd.sparse.coo_array(([0.0, 1.0], ([0, 1], [1, 2])), shape=(3, 3))
>>> sd.graph.betweenness_centrality(Z)
Traceback (most recent call last):
    ...
ValueError: betweenness_centrality(): edge weights must be positive; unweighted=True counts the edges
>>> sd.graph.betweenness_centrality(Z, unweighted=True)
array([0.0, 0.5, 0.0], dtype=float64)
```

## 끝점도 세기: `endpoints`

`endpoints=True`면 경로의 양 끝 노드도 그 경로를 지나간 것으로 세요. 모든 노드가 적어도 자기가 끝점인 경로만큼의 값을 가지게 돼요. 정규화도 끝점을 넣은 쌍의 수 $n(n - 1)$(방향 없는 그래프는 $n(n - 1)/2$)로 해요.

```python
>>> sd.graph.betweenness_centrality(G, directed=False, endpoints=True)
array([0.2857142857142857, 0.2857142857142857, 0.6666666666666666,
       0.7142857142857142, 0.6666666666666666, 0.2857142857142857,
       0.2857142857142857], dtype=float64)
```

## 정확도

최단 경로의 수와 몫을 반올림으로 계산하므로 결과에 반올림 오차가 있지만, 더하는 수가 모두 양수라 서로 지워지는 일이 없어요. 노드마다 상대오차가 반올림 몇 번 분량($\gamma_K$, $K$는 최단 경로의 길이와 차수로 정해지는 수)을 넘지 않고, 참값이 0인 노드는 정확히 0이에요. 무게가 정수이거나 `unweighted=True`면 최단 경로를 정확히 가려내요. 무게가 일반 실수면 정확한 합이 같은 두 경로가 반올림 때문에 다른 길이로 계산될 수 있어서, 그때는 계산한 길이로 최단 경로를 정해요.

같은 그래프와 인자면 스레드를 몇 개 쓰든 결과가 비트까지 같아요.

## 경계의 값

| 입력 | 결과 |
|---|---|
| 노드가 없는 (0, 0) 행렬 | 빈 배열 |
| 노드가 둘 이하 | 모두 0 (`endpoints=False`일 때) |
| 변이 없는 그래프 | 모두 0 |
| 무게 0이나 음수 무게 | `ValueError` (`unweighted=True`면 받아요) |
| 희소 배열에 저장된 NaN, ±inf | `ValueError` (`unweighted=True`면 받아요) |

```python
>>> sd.graph.betweenness_centrality(sd.zeros((0, 0)))
array([], dtype=float64)
>>> sd.graph.betweenness_centrality(sd.zeros((2, 2)))
array([0.0, 0.0], dtype=float64)
>>> sd.graph.betweenness_centrality(-G)
Traceback (most recent call last):
    ...
ValueError: betweenness_centrality(): edge weights must be positive; unweighted=True counts the edges
>>> sd.graph.betweenness_centrality(G, k=3)
Traceback (most recent call last):
    ...
TypeError: betweenness_centrality(): unexpected keyword argument 'k'
```

<Callout type="note" title="노드 수가 많으면 오래 걸려요">

모든 노드를 원점으로 삼아 최단 경로를 구하므로, 노드 $n$개와 변 $E$개인 그래프에서 무게가 없으면 $nE$, 무게가 있으면 $nE \log n$에 비례하는 시간이 걸려요. 원점 일부만 골라 어림하는 방법은 없어요.

</Callout>

## scipy·networkx를 아는 분께

- scipy에는 없는 함수예요. 이름과 뜻은 networkx의 `betweenness_centrality`를 따랐어요. `normalized`와 `endpoints`의 뜻, 방향 없는 그래프의 쌍을 한 번 세는 것, 정규화하는 수가 같아요.
- 무게의 기본값이 달라요. networkx는 `weight=None`이 기본이라 무게를 읽지 않아요. 여기서는 `unweighted=False`가 기본이라 무게를 읽어요. networkx의 기본과 같게 하려면 `unweighted=True`를 줘요. 0과 1로만 적은 행렬은 어느 쪽이든 같아요.
- 원점 일부만 골라 어림하는 `k`, `seed`가 없어요.
- 무게 0이나 음수인 변은 `ValueError`예요.
- networkx는 노드에서 값으로 가는 사전을 돌려줘요. 여기서는 노드 번호 차례의 배열을 돌려줘요.
