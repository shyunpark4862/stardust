## 한눈에 보기

`spsolve`는 계수 행렬이 [희소 행렬](/api/sparse/basics/)인 연립일차방정식 $Ax = b$를 풀어요. 하는 일은 밀집 배열의 [`sd.linalg.solve`](/api/linalg/solve/)와 같고, 받는 행렬이 희소 배열이라는 점만 달라요.

```python
>>> import stardust as sd
>>> A = sd.sparse.csr_array(sd.asarray([[4.0, -1.0, 0.0],
...                                     [-1.0, 4.0, -1.0],
...                                     [0.0, -1.0, 4.0]]))
>>> b = sd.asarray([3.0, 2.0, 3.0])
>>> x = sd.sparse.spsolve(A, b)
>>> x
array([1.0, 1.0, 1.0], dtype=float64)
>>> A @ x
array([3.0, 2.0, 3.0], dtype=float64)
```

`A`는 아홉 칸 가운데 일곱 칸에만 값이 있는 희소 배열이고, 해 `x`는 보통의 밀집 배열이에요. `A @ x`가 `b`와 같으니 맞게 풀렸어요.

## 희소 행렬로 푸는 이유

이렇게 작은 행렬이면 밀집 배열로 풀어도 아무 문제가 없어요. 희소 풀이가 필요한 것은 행렬이 아주 크고 그 원소의 대부분이 0일 때예요. 격자 위의 미분방정식, 회로, 연결망처럼 "각 미지수가 이웃 몇 개와만 엮인" 문제에서 이런 행렬이 나와요.

예를 들어 100 × 100 격자의 각 점에서 이웃 넷과의 차이를 따지는 2차원 라플라시안을 만들어 볼게요. 미지수가 10,000개라서 행렬은 10,000 × 10,000이에요.

```python
>>> m = 100
>>> T = sd.sparse.diags_array([-1.0, 2.0, -1.0], offsets=[-1, 0, 1], shape=(m, m))
>>> A2 = sd.sparse.kronsum(T, T)
>>> A2
<csr_array of shape (10000, 10000), float64, 49600 stored elements>
>>> A2.nnz / (A2.shape[0] * A2.shape[1])
0.000496
```

원소 1억 개 가운데 저장된 것은 49,600개, 0.05%예요. 밀집 배열로 만들면 float64 1억 개, 800MB가 들지만 희소 배열은 0이 아닌 원소와 그 자리만 저장해요. `spsolve`는 이 저장을 그대로 써서 풀어요.

```python
>>> b2 = sd.ones(A2.shape[0])
>>> x2 = sd.sparse.spsolve(A2, b2)
>>> x2.shape
(10000,)
>>> float(sd.max(sd.abs(A2 @ x2 - b2)))
2.2737367544323206e-12
```

해를 다시 넣은 잔차가 $10^{-12}$ 크기예요. 해의 원소가 수백 크기라는 것을 생각하면 반올림 오차 수준이에요(아래 [정확도](#정확도)).

희소 풀이는 행렬을 **분해**해서 풀어요. 행렬을 아래 삼각 행렬과 위 삼각 행렬의 곱(LU)으로 나누고, 두 삼각 행렬로 차례로 대입해요. 이때 0인 자리를 건너뛰고, 분해 결과에 0이 아닌 원소가 적게 생기도록 행과 열의 순서를 스스로 정해요. 그 순서가 왜 중요한지는 [splu](/api/sparse/splu/)에서 그림으로 볼 수 있어요.

## `b`의 모양과 결과

| `b` | 뜻 | 결과 |
|---|---|---|
| 밀집 `(n,)` | 우변 하나 | 밀집 `(n,)` |
| 밀집 `(n, k)` | 우변 k개를 열로 나란히 | 밀집 `(n, k)` |
| 희소 2차원 `(n, k)` | 우변 k개, 대부분 0 | 희소 `(n, k)`. A가 CSR이면 CSR, 그 밖에는 CSC |
| 희소 1차원 `(n,)` | 우변 하나 | 희소 1차원 CSR |

밀집 우변의 규칙은 [`sd.linalg.solve`](/api/linalg/solve/)와 같아요. 우변 하나는 1차원, 여럿은 **열**로 놓아요. 열이 하나뿐인 `(n, 1)`도 2차원이니 결과도 `(n, 1)`이에요.

```python
>>> sd.sparse.spsolve(A, sd.asarray([[3.0, 1.0],
...                                  [2.0, 0.0],
...                                  [3.0, 1.0]]))
array([[                1.0,  0.2857142857142857],
       [                1.0, 0.14285714285714285],
       [                1.0,  0.2857142857142857]], dtype=float64)
>>> sd.sparse.spsolve(A, sd.asarray([[3.0], [2.0], [3.0]])).shape
(3, 1)
```

우변을 하나씩 따로 부르는 것보다 열로 묶어 한 번에 넘기는 쪽이 빨라요. 시간이 많이 드는 분해를 한 번만 하기 때문이에요.

### 희소 우변

우변 자체가 대부분 0이면 희소 배열로 줄 수 있어요. 그러면 해도 희소 배열로 돌아오고, 해에서 정확히 0인 원소는 저장하지 않아요. 아래 행렬은 블록 둘로 나뉘어 있어서, 첫 블록에만 값이 있는 우변의 해는 둘째 블록이 0이에요.

```python
>>> D = sd.sparse.block_diag([sd.sparse.csr_array(sd.asarray([[2.0, 1.0], [1.0, 2.0]])),
...                           sd.sparse.csr_array(sd.asarray([[3.0]]))])
>>> e = sd.sparse.csc_array(sd.asarray([[1.0], [0.0], [0.0]]))
>>> r = sd.sparse.spsolve(D, e)
>>> r
<csc_array of shape (3, 1), float64, 2 stored elements>
>>> r.toarray()
array([[ 0.6666666666666666],
       [-0.3333333333333333],
       [                0.0]], dtype=float64)
```

결과의 형식은 `A`를 따라요. `A`가 CSR이면 CSR이고, CSC·COO·DOK이면 CSC예요. 우변이 1차원 희소 배열이면 결과는 1차원 CSR이에요(CSC는 1차원이 없어요).

```python
>>> sd.sparse.spsolve(A, sd.sparse.csc_array(sd.asarray([[3.0], [2.0], [3.0]])))
<csr_array of shape (3, 1), float64, 3 stored elements>
>>> sd.sparse.spsolve(A.tocoo(), sd.sparse.csc_array(sd.asarray([[3.0], [2.0], [3.0]])))
<csc_array of shape (3, 1), float64, 3 stored elements>
>>> sd.sparse.spsolve(A, sd.sparse.coo_array(b))
<csr_array of shape (3,), float64, 3 stored elements>
```

희소 우변은 해도 희소할 것으로 기대될 때 쓰세요. 해가 대부분 0이 아니면 결과를 희소로 받아도 저장이 줄지 않아요.

## 결과의 dtype

결과는 float64나 complex128이에요. bool과 int64 행렬과 우변은 float64로 바꿔서 풀고, `A`와 `b` 가운데 하나라도 복소수면 결과는 complex128이에요.

```python
>>> sd.sparse.spsolve(sd.sparse.csr_array(sd.asarray([[2, 1], [1, 3]])), sd.asarray([3, 4]))
array([1.0, 1.0], dtype=float64)
>>> sd.sparse.spsolve(A, sd.asarray([3.0 + 3j, 2.0 + 2j, 3.0 + 3j]))
array([(1+1j), (1+1j), (1+1j)], dtype=complex128)
```

## 정확도

희소 풀이의 정확도는 **정규화한 역오차**로 약속해요. 구한 해 $\hat x$를 다시 넣은 잔차를 행렬과 해의 크기로 나눈 값이에요.

$$
\frac{\lVert b - A\hat x \rVert_\infty}{\lVert A \rVert_\infty \lVert \hat x \rVert_\infty + \lVert b \rVert_\infty} \le 8u, \qquad u = 2^{-53}
$$

말로 하면 "구한 해는 $A$나 $b$를 반올림 몇 번만큼 흔든 문제의 정확한 해"라는 뜻이에요.

`spsolve`는 분해로 해를 한 번 구한 다음, 원소마다의 역오차 $|b - A\hat x|_i \,/\, (|A||\hat x| + |b|)_i$를 재요. 그 가장 큰 값이 $16u$를 넘을 때만 잔차 $b - A\hat x$로 한 번 더 다듬어요. 잘 조건된 행렬은 대개 첫 해에서 이미 이 문턱 안이라 풀이 한 번으로 끝나고, 분해 중의 피벗 선택 때문에 오차가 커진 행렬은 한 번 다듬으면 $2u$ 아래로 내려가요. 시험 행렬(격자의 라플라시안, 대류-확산, 띠, 안장점, 조건수가 나쁜 삼중대각, 무작위 실수·복소 행렬과 실제 응용에서 모은 SuiteSparse 행렬)에서 잰 값은 모두 약속 안이고, 가장 큰 것은 다듬지 않은 해의 약 $7u$예요. 위의 격자 문제로 재 보면 이래요.

```python
>>> inf = float("inf")
>>> err = float(sd.max(sd.abs(b2 - A2 @ x2))) / (sd.sparse.norm(A2, ord=inf) * float(sd.max(sd.abs(x2))) + 1.0)
>>> round(err / 2**-53, 2)
3.41
```

이 행렬은 첫 해의 원소별 역오차가 $4u$쯤이라 다듬지 않고 끝났고, 정규화한 역오차 $3.41u$는 약속한 $8u$ 안이에요.

역오차가 작아도 해 자체의 오차는 행렬의 [조건수](/api/linalg/cond/) $\kappa(A)$만큼 커질 수 있어요. 해의 상대오차는 대략 $\kappa(A) \cdot u$ 크기이고, 작은 행렬에서 Arb(구간 산술)로 만든 참값과 견주면 $8\kappa_\infty(A)\,u$ 안이에요. 조건수가 나쁜 행렬은 아래 [조심할 점](#조건수가-나쁜-행렬)에서 다뤄요.

## 특이 행렬은 `LinAlgError`

해가 하나로 정해지지 않는 행렬은 `sd.linalg.LinAlgError`를 내요. 밀집 풀이와 같은 예외이고, `ValueError`의 하위 클래스예요.

```python
>>> s = sd.sparse.csr_array(sd.asarray([[1.0, 2.0], [2.0, 4.0]]))
>>> sd.sparse.spsolve(s, sd.asarray([9.0, 8.0]))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: spsolve(): singular matrix
```

`spsolve`는 세 경우를 특이로 봐요.

1. **구조적으로 특이할 때.** 값과 상관없이 0의 자리만으로 특이한 행렬이에요. 한 행이나 한 열이 통째로 비어 있으면 그렇게 돼요.
2. **분해 중에 정확히 0인 피벗이 나올 때.**
3. **조건수가 너무 클 때.** 분해한 뒤 1-노름 조건수 $\kappa_1(A) = \lVert A\rVert_1 \lVert A^{-1}\rVert_1$을 어림해서 $\kappa_1 \cdot 2^{-52} \ge 1$이면 특이로 봐요.

셋째 경우가 중요해요. 수학적으로 특이한 행렬도 반올림 때문에 피벗이 정확히 0이 되지 않는 일이 흔하고, 그러면 분해는 성공한 것처럼 끝나고 $10^{16}$ 크기의 뜻 없는 해가 나와요. 조건수가 $2^{52}$을 넘는 행렬의 해에는 맞는 자리가 하나도 없으므로, `spsolve`는 그런 해를 돌려주지 않고 에러를 내요.

아래 행렬은 둘째 행이 첫째 행의 정확히 3배라서 수학적으로 특이하지만, `0.1`과 `0.3`이 이진수로 정확하지 않아서 피벗이 0이 되지 않아요. 밀집 `sd.linalg.solve`는 경고 없이 $10^{18}$ 크기의 답을 내지만 `spsolve`는 특이로 판정해요.

```python
>>> near = sd.asarray([[0.1, 0.2], [0.3, 0.6]])
>>> sd.linalg.solve(near, sd.asarray([9.0, 8.0]))
array([ 3.4227357168015775e+18, -1.7113678584007887e+18], dtype=float64)
>>> sd.sparse.spsolve(sd.sparse.csr_array(near), sd.asarray([9.0, 8.0]))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: spsolve(): singular matrix
```

양 끝의 대각 원소가 1인 라플라시안(경계에서 흐름이 없는 문제)도 마찬가지예요. 모든 행의 합이 0이라 상수 벡터를 0으로 보내는 특이 행렬이에요.

```python
>>> Nm = T.todok()
>>> Nm[0, 0] = 1.0
>>> Nm[m - 1, m - 1] = 1.0
>>> sd.sparse.spsolve(Nm.tocsr(), sd.ones(m))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: spsolve(): singular matrix
```

조건수의 어림값은 참값보다 작거나 같아요. 그래서 조건수가 경계 바로 위인 행렬은 특이로 잡히지 않고 풀릴 수 있어요. 특이할 수 있는 문제에서 그래도 가장 그럴듯한 해가 필요하면 최소제곱 풀이 [lsqr](/api/sparse/lsqr/)나 [lsmr](/api/sparse/lsmr/)을 쓰세요.

## 형식과 결정성

`A`의 형식은 결과에 영향을 주지 않아요. 어느 형식이든 같은 행렬이면 마지막 비트까지 같은 해예요.

```python
>>> x6 = sd.sparse.spsolve(T, sd.ones(m))
>>> all(bool(sd.all(sd.sparse.spsolve(T.asformat(f), sd.ones(m)) == x6)) for f in ["csc", "coo", "dok"])
True
```

같은 입력이면 실행마다 같은 비트이고, 여러 Python 스레드에서 동시에 불러도 같아요. 지금은 stardust의 [스레드](/api/array/threads/) 수와도 상관없이 같아요(약속은 아니에요). 분해는 운영체제의 행렬 계산 라이브러리에 맡기므로, 그 라이브러리가 몇 스레드로 도는지(환경 변수 `VECLIB_MAXIMUM_THREADS`)가 바뀌면 마지막 자리가 달라질 수 있어요. 밀집 선형대수와 같은 규칙이에요([선형대수의 기본](/api/linalg/basics/)).

우변을 열로 여럿 주면 여덟 열씩 묶어서 함께 풀어요. 그래서 한 열의 해는 우변의 열 수와 그 열이 묶음 안에서 놓인 자리에 따라 정해지고, 그 열만 따로 푼 해와 마지막 자리에서 다를 수 있어요. 같은 우변이면 언제나 같은 결과예요.

|---|---|
| 행렬이 작거나 0이 별로 없어요 | 밀집 배열로 [`sd.linalg.solve`](/api/linalg/solve/) |
| 큰 희소 행렬, 우변이 처음부터 다 있어요 | **`spsolve`**(우변 여럿은 열로 묶어서) |
| 같은 행렬로 여러 번 푸는데 우변이 나중에 하나씩 생겨요 | [splu](/api/sparse/splu/)나 [factorized](/api/sparse/factorized/)로 한 번 분해하고 되풀이해서 풀기 |
| 행렬이 위나 아래 삼각 | [spsolve_triangular](/api/sparse/spsolve_triangular/) |
| 분해의 채움이 감당 못 할 만큼 큰 문제(큰 3차원 격자 등), 행렬 없이 곱만 할 수 있는 문제 | 반복법 [cg](/api/sparse/cg/), [gmres](/api/sparse/gmres/) 등([반복법 고르기](/api/sparse/iterative/)) |
| 식과 미지수의 개수가 달라요 | [lsqr](/api/sparse/lsqr/), [lsmr](/api/sparse/lsmr/) |
| 역행렬을 구해서 곱하기 | 쓰지 마세요. [inv](/api/sparse/inv/)의 결과는 거의 밀집이에요 |

### 밀집 짝 `sd.linalg.solve`

밀집 짝은 [`sd.linalg.solve`](/api/linalg/solve/)예요. 같은 문제에 같은 답을 주지만, 푸는 방법이 달라서 마지막 자리는 다를 수 있어요.

```python
>>> T6 = sd.sparse.diags_array([-1.0, 2.0, -1.0], offsets=[-1, 0, 1], shape=(6, 6))
>>> sd.sparse.spsolve(T6, sd.ones(6))
array([2.9999999999999996,  4.999999999999999,  5.999999999999999,
                      6.0,                5.0,                3.0], dtype=float64)
>>> sd.linalg.solve(T6.toarray(), sd.ones(6))
array([2.9999999999999996,  4.999999999999999,  5.999999999999999,
                      6.0,                5.0, 3.0000000000000004], dtype=float64)
```

둘은 받는 입력으로 나뉘어요. `spsolve`에 밀집 배열을 주거나 `sd.linalg.solve`에 희소 배열을 주면 `TypeError`가 쓸 함수를 알려 줘요.

```python
>>> sd.sparse.spsolve(T6.toarray(), sd.ones(6))
Traceback (most recent call last):
    ...
TypeError: spsolve(): 'A' must be a sparse array, not ndarray; for a dense array use sd.linalg.solve
>>> sd.linalg.solve(T6, sd.ones(6))
Traceback (most recent call last):
    ...
TypeError: solve(): 'a' must be an sd.ndarray, not csr_array; for a sparse array use sd.sparse.spsolve
```

`sd.linalg.solve`는 행렬 여러 장을 한 번에 푸는 배치를 받지만, `spsolve`는 행렬 하나만 받아요.

## 조심할 점

### 조건수가 나쁜 행렬

<Callout type="warn" title="에러가 안 났다고 모든 자리가 맞는 것은 아니에요">

특이로 판정하는 경계는 "맞는 자리가 하나도 없는" 조건수예요. 그보다 조금 나은 행렬은 에러 없이 풀리지만, 해의 앞쪽 몇 자리만 맞아요.

</Callout>

아래 행렬은 두 행이 $10^{-14}$만큼만 달라서 조건수가 약 $4 \times 10^{14}$이에요. 정답은 `[1, 1]`인데, 구한 해는 2%쯤 틀려요. 조건수 × $2^{-53}$ ≈ 0.04이니 예상할 수 있는 크기예요.

```python
>>> ill = sd.asarray([[1.0, 1.0], [1.0, 1.0 + 1e-14]])
>>> sd.linalg.cond(ill, ord=1)
400319966877381.4
>>> sd.sparse.spsolve(sd.sparse.csr_array(ill), sd.asarray([2.0, 2.0 + 1e-14]))
array([0.9777777777777776, 1.0222222222222224], dtype=float64)
```

이 오차는 풀이 방법 탓이 아니라 문제 자체가 반올림에 민감한 탓이에요. 밀집 풀이도 같은 답을 내요.

### 모양과 형

`A`는 2차원 정사각 희소 배열이고, 밀집 `b`의 행 수는 `A`의 크기와 같아야 해요.

```python
>>> sd.sparse.spsolve(sd.sparse.csr_array(sd.ones((2, 3))), sd.ones(2))
Traceback (most recent call last):
    ...
ValueError: spsolve(): 'A' must be square, got 2x3
>>> sd.sparse.spsolve(A, sd.ones(4))
Traceback (most recent call last):
    ...
ValueError: spsolve(): 'A' is 3x3 but 'b' has 4 rows
```

`b`는 `sd.ndarray`나 희소 배열이어야 해요. 리스트와 numpy 배열은 먼저 [`sd.asarray`](/api/array/asarray/)로 바꾸세요.

```python
>>> sd.sparse.spsolve(A, [3.0, 2.0, 3.0])
Traceback (most recent call last):
    ...
TypeError: spsolve(): 'b' must be an sd.ndarray or a sparse array, not list
```

### NaN과 inf가 있으면 에러

`A`에 저장된 원소나 `b`에 NaN이나 무한대가 있으면 풀지 않고 `ValueError`를 내요.

```python
>>> sd.sparse.spsolve(sd.sparse.csr_array(sd.asarray([[sd.nan, 1.0], [1.0, 2.0]])), sd.ones(2))
Traceback (most recent call last):
    ...
ValueError: spsolve(): 'A' contains NaN or infinity
>>> sd.sparse.spsolve(A, sd.asarray([sd.inf, 2.0, 3.0]))
Traceback (most recent call last):
    ...
ValueError: spsolve(): 'b' contains NaN or infinity
```

### 빈 입력

0 × 0 행렬이나 열이 0개인 우변은 에러 없이 그 모양의 빈 결과를 돌려줘요.

```python
>>> sd.sparse.spsolve(sd.sparse.csr_array((0, 0)), sd.zeros(0))
array([], dtype=float64)
>>> sd.sparse.spsolve(A, sd.zeros((3, 0)))
array([], shape=(3, 0), dtype=float64)
```

## scipy를 아는 분께

- 이름공간이 평평해요. `scipy.sparse.linalg.spsolve`는 `sd.sparse.spsolve`이고, `sd.sparse.linalg`는 없어요.
- **우변 `(n, 1)`이 `(n,)`으로 펴지지 않아요.** scipy는 열이 하나인 밀집 우변의 해를 1차원으로 돌려주지만, 여기서는 `sd.linalg.solve`처럼 `(n, 1)`이에요. 열이 하나인 희소 우변과 1차원 희소 우변도 희소 결과예요(scipy는 밀집).
- 분해는 SuperLU가 아니에요. 순서는 근사 최소 차수(AMD)로 정해져 있고, `permc_spec`, `use_umfpack` 같은 옵션은 없어요(주면 `TypeError`). 해의 마지막 자리는 scipy와 다를 수 있어요.
- **특이 행렬은 경고가 아니라 `LinAlgError`예요.** scipy는 구조적으로 특이하면 `MatrixRankWarning`과 NaN 배열을 내고, 값으로 특이하거나 조건수가 $2^{52}$을 넘는 행렬에는 경고 없이 큰 해를 돌려줘요. 여기서는 모두 에러예요.
- scipy는 `A`가 CSC나 CSR이 아니면 `SparseEfficiencyWarning`을 내고 바꿔서 풀어요. 여기에는 경고가 없고, COO와 DOK도 그대로 받아요.
- 리스트와 numpy 배열은 우변으로 받지 않아요(`TypeError`). 저장된 NaN·inf는 `ValueError`예요.
- 실수 `A`와 복소 `b`를 주면 실수 분해로 실수부와 허수부를 함께 풀어요. scipy는 `A`를 복소로 바꿔 분해해요(반올림만 달라요).
