## 한눈에 보기

`splu`는 희소 행렬을 **LU 분해**해서 그 결과를 객체 하나에 담아 돌려줘요. 연립일차방정식을 푸는 일은 시간이 드는 분해와 가벼운 대입의 두 단계인데, `splu`는 첫 단계만 해 두는 함수예요. 돌아온 객체의 `solve`를 부르면 둘째 단계만 해서 답을 줘요.

```python
>>> import stardust as sd
>>> N = sd.sparse.csr_array(sd.asarray([[2.0, 1.0, 0.0],
...                                     [0.0, 2.0, 1.0],
...                                     [1.0, 0.0, 2.0]]))
>>> lu = sd.sparse.splu(N)
>>> lu
SparseLU(shape=(3, 3), dtype=float64)
>>> lu.solve(sd.asarray([4.0, 7.0, 7.0]))
array([1.0, 2.0, 3.0], dtype=float64)
>>> lu.solve(sd.asarray([5.0, 5.0, 8.0]))
array([2.0, 1.0, 3.0], dtype=float64)
```

우변을 바꿔 두 번 풀었지만 분해는 `splu`를 부를 때 한 번만 했어요.

## 분해를 다시 쓰는 이유

같은 행렬로 우변만 바꿔 가며 여러 번 푸는 일은 흔해요. 그런데 우변이 처음부터 다 있지 않고, 앞의 답으로 다음 우변을 만드는 경우가 많아요. 시간을 잘게 나눠 한 걸음씩 나아가는 계산이 대표적이에요.

막대의 열 전달을 예로 들어 볼게요. 막대를 50칸으로 나누고 가운데 10칸만 뜨겁게 한 다음, 한 걸음마다 $(I + 0.5\,T)\,u_{\text{다음}} = u_{\text{지금}}$을 풀어요. $T$는 이웃 칸과의 온도 차이를 재는 삼중대각 행렬이에요. 걸음마다 행렬은 같고 우변(지금의 온도)만 바뀌어요.

```python
>>> n = 50
>>> T = sd.sparse.diags_array([-1.0, 2.0, -1.0], offsets=[-1, 0, 1], shape=(n, n))
>>> A = sd.sparse.eye_array(n) + 0.5 * T
>>> step = sd.sparse.splu(A)
>>> u0 = sd.zeros(n)
>>> u0[20:30] = 1.0
>>> u = u0
>>> for _ in range(100):
...     u = step.solve(u)
>>> float(sd.max(u))
0.38424222435643735
```

백 걸음 뒤에 가장 뜨거운 곳의 온도가 1에서 0.38로 내려갔어요. 열이 양옆으로 퍼진 거예요. 걸음마다 [`spsolve(A, u)`](/api/sparse/spsolve/)를 불러도 답은 같지만, 그러면 같은 분해를 백 번 해요. `splu`로 한 번 분해해 두면 걸음마다 대입만 해요.

```python
>>> bool(sd.all(step.solve(u0) == sd.sparse.spsolve(A, u0)))
True
```

`spsolve`와 `splu(A).solve`는 같은 분해와 같은 풀이라서 마지막 비트까지 같아요.

<Callout type="tip" title="우변이 처음부터 다 있으면 spsolve 한 번">

우변 여러 개가 미리 다 있으면 `splu`로 나눌 필요가 없어요. 우변을 열로 묶어 `spsolve(A, B)`를 한 번 부르면 분해도 한 번이에요. `splu`가 필요한 것은 우변이 나중에 하나씩 생길 때예요.

</Callout>

## LU 분해와 채움

LU 분해는 행렬 $A$를 대각이 1인 아래 삼각 행렬 $L$과 위 삼각 행렬 $U$의 곱으로 나눠요. 그러면 $Ax = b$는 $Ly = b$와 $Ux = y$의 두 삼각 시스템이 되고, 삼각 시스템은 위나 아래에서부터 한 줄씩 대입하면 풀려요.

희소 행렬에서는 분해할 때 **채움**(fill-in)이 생겨요. $A$에서 0이던 자리가 $L$이나 $U$에서는 0이 아니게 되는 거예요. 채움이 많으면 분해가 저장도 많이 차지하고 시간도 오래 걸려요. 그리고 채움의 양은 행과 열을 어떤 순서로 늘어놓느냐에 따라 크게 달라요.

첫 행과 첫 열이 꽉 찬 "화살표" 행렬로 볼게요. 이 순서 그대로 분해하면 첫 행이 나머지 모든 행에 섞여 들어가서 $L$과 $U$가 꽉 차요. 같은 행렬의 행과 열을 거꾸로 늘어놓으면 꽉 찬 행과 열이 맨 끝으로 가고, 채움이 하나도 생기지 않아요.

밀집 [`sd.linalg.lu`](/api/linalg/lu/)로 두 순서를 직접 분해해서 0이 아닌 원소를 세어 보면 차이가 보여요.

```python
>>> arrow = 5.0 * sd.eye(5)
>>> arrow[0, :] = 1.0
>>> arrow[:, 0] = 1.0
>>> arrow[0, 0] = 5.0
>>> l, u_, p = sd.linalg.lu(arrow)
>>> int(sd.count_nonzero(l)) + int(sd.count_nonzero(u_))
30
>>> l, u_, p = sd.linalg.lu(arrow[::-1, ::-1])
>>> int(sd.count_nonzero(l)) + int(sd.count_nonzero(u_))
18
```

원래 행렬의 0이 아닌 원소는 13개예요. 첫 순서는 $L$과 $U$에 30개(대각은 둘 다 세서 5개가 겹쳐요), 거꾸로 한 순서는 18개로 채움이 없어요. 행렬이 수만 행이면 이 차이가 몇 배, 몇십 배의 저장과 시간이 돼요.

`splu`는 채움이 적게 생기도록 **행과 열의 순서를 스스로 정해요**(근사 최소 차수 순서). 계산 중의 반올림이 커지지 않도록 행을 바꾸기도 해요. 그래서 사용자는 순서를 신경 쓰지 않고 행렬을 그대로 넘기면 돼요. 순서를 고르는 옵션은 없어요.

## `solve(b, trans=)`

`solve`의 `b`는 밀집 배열이에요. `(n,)`이면 우변 하나, `(n, k)`면 우변 k개를 열로 놓은 것이고, 결과는 `b`와 같은 모양이에요. 규칙은 [spsolve](/api/sparse/spsolve/)의 밀집 우변과 같아요.

```python
>>> lu.solve(sd.asarray([[4.0, 5.0],
...                      [7.0, 5.0],
...                      [7.0, 8.0]]))
array([[1.0, 2.0],
       [2.0, 1.0],
       [3.0, 3.0]], dtype=float64)
```

### 전치와 켤레 전치

`trans`로 분해를 다시 하지 않고 전치 시스템을 풀 수 있어요. `'T'`는 $A^\mathsf{T} x = b$, `'H'`는 켤레 전치 $A^\mathsf{H} x = b$예요. 실수 행렬이면 `'H'`와 `'T'`는 같아요.

```python
>>> c = N.T @ sd.asarray([1.0, 2.0, 3.0])
>>> c
array([5.0, 5.0, 8.0], dtype=float64)
>>> lu.solve(c, trans="T")
array([1.0, 2.0, 3.0], dtype=float64)
```

복소 행렬이면 `'T'`와 `'H'`가 달라요.

```python
>>> C = sd.sparse.csr_array(sd.asarray([[2.0, 1j], [0.0, 3.0]]))
>>> lc = sd.sparse.splu(C)
>>> lc
SparseLU(shape=(2, 2), dtype=complex128)
>>> lc.solve(sd.ones(2), trans="T")
array([                                 (0.5+0j),
       (0.3333333333333333-0.16666666666666666j)], dtype=complex128)
>>> lc.solve(sd.ones(2), trans="H")
array([                                 (0.5-0j),
       (0.3333333333333333+0.16666666666666666j)], dtype=complex128)
```

전치 시스템이 필요한 곳은 생각보다 많아요. 수반 방정식으로 기울기를 구할 때, 최소제곱의 정규방정식을 두 단계로 풀 때, 조건수를 어림할 때처럼 $A$와 $A^\mathsf{T}$를 번갈아 푸는 계산이 그래요.

### 실수 분해에 복소 우변

실수 행렬의 분해에 복소 우변을 주면 실수부와 허수부를 함께 풀어서 complex128을 돌려줘요. 복소로 다시 분해하지 않아요.

```python
>>> lu.solve(sd.asarray([5.0 + 4j, 5.0 + 7j, 8.0 + 7j]))
array([(2+1j), (1+2j), (3+3j)], dtype=complex128)
```

## `SparseLU` 객체

`splu`가 돌려주는 `SparseLU`는 `solve`와 `shape`만 가진 작은 객체예요.

```python
>>> lu.shape
(3, 3)
```

- **분해의 내용(L, U, 치환)은 꺼낼 수 없어요.** 분해는 객체 안에 감춰져 있고, 할 수 있는 일은 그것으로 푸는 것뿐이에요. $L$과 $U$를 직접 보고 싶으면 밀집 배열로 바꿔 [`sd.linalg.lu`](/api/linalg/lu/)를 쓰세요.
- `SparseLU`는 `sd.sparse`의 공개 이름이 아니고, 직접 만들 수 없어요. 언제나 `splu`로 만들어요.
- 한 분해를 여러 Python 스레드에서 동시에 `solve`해도 돼요. 결과는 혼자 풀 때와 마지막 비트까지 같아요.
- 결과의 결정성은 [spsolve](/api/sparse/spsolve/#형식과-결정성)와 같아요. `A`의 형식이나 stardust의 스레드 수와 상관없이 같은 비트예요.

```python
>>> type(lu)(N)
Traceback (most recent call last):
    ...
TypeError: SparseLU(): use sd.sparse.splu(A)
```

## 특이 행렬은 `splu`에서 에러

특이한 행렬은 분해할 때 판정해요. 그래서 에러는 `solve`가 아니라 `splu`를 부르는 순간에 나요. 판정 방법은 [spsolve](/api/sparse/spsolve/#특이-행렬은-linalgerror)와 같아서, 정확히 0인 피벗뿐 아니라 조건수가 $2^{52}$ 이상인 행렬도 특이로 봐요.

```python
>>> sd.sparse.splu(sd.sparse.csr_array(sd.asarray([[0.1, 0.2], [0.3, 0.6]])))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: splu(): singular matrix
```

분해에 성공한 객체의 `solve`는 특이 때문에 실패하지 않아요.

## 밀집 짝 `sd.linalg.lu`와 `lu_solve`

밀집 배열의 짝은 [`sd.linalg.lu`](/api/linalg/lu/)와 [`sd.linalg.lu_solve`](/api/linalg/lu_solve/)예요. `lu_solve`도 같은 `trans` 값(`'N'`, `'T'`, `'H'`)을 받아요.

```python
>>> l, u_, p = sd.linalg.lu(N.toarray())
>>> sd.linalg.lu_solve(l, u_, p, c, trans="T")
array([1.0, 2.0, 3.0], dtype=float64)
```

| | `splu(A)` | `sd.linalg.lu(x)` |
|---|---|---|
| 받는 행렬 | 정사각 희소 배열 하나 | 밀집 배열, 정사각이 아니어도 되고 배치도 돼요 |
| 돌려주는 것 | 푸는 객체 `SparseLU` | `L`, `U`, `perm` 세 배열 |
| 풀기 | `lu.solve(b, trans=)` | `lu_solve(l, u, perm, b, trans=)` |
| 행과 열의 순서 | 채움이 적도록 행과 열을 모두 바꿔요 | 행만 바꿔요(부분 피벗) |
| 특이 행렬 | 분해할 때 `LinAlgError` | 분해는 되고, 풀 때 `LinAlgError` |

두 방법은 순서가 달라서 해의 마지막 자리가 다를 수 있어요.

## 조심할 점

### 밀집 배열은 받지 않아요

```python
>>> sd.sparse.splu(N.toarray())
Traceback (most recent call last):
    ...
TypeError: splu(): 'A' must be a sparse array, not ndarray; for a dense array use sd.linalg.lu
```

### `solve`의 우변

`b`는 밀집 `sd.ndarray`예요. 희소 우변을 풀려면 `toarray()`로 바꾸거나 [spsolve](/api/sparse/spsolve/)를 쓰세요. 행 수는 분해의 크기와 같아야 해요.

```python
>>> lu.solve(sd.sparse.csr_array(sd.ones(3)))
Traceback (most recent call last):
    ...
TypeError: solve(): 'b' must be an sd.ndarray, not csr_array
>>> lu.solve(sd.ones(2))
Traceback (most recent call last):
    ...
ValueError: solve(): the factor is 3x3 but 'b' has 2 rows
```

### `trans`는 키워드로, 문자 하나

`trans`는 키워드로만 받아요. 값은 대문자 `'N'`, `'T'`, `'H'` 가운데 하나예요.

```python
>>> lu.solve(c, "T")
Traceback (most recent call last):
    ...
TypeError: solve(): takes 1 positional argument but 2 were given
>>> lu.solve(c, trans="t")
Traceback (most recent call last):
    ...
ValueError: solve(): 'trans' must be 'N', 'T' or 'H', not 't'
>>> lu.solve(c, trans=1)
Traceback (most recent call last):
    ...
TypeError: solve(): 'trans' must be 'N', 'T' or 'H', not int
```

### 우변 여럿의 비트

`(n, k)` 우변은 열들을 함께 풀어요. 그래서 한 열의 해가 그 열만 따로 푼 해와 마지막 자리에서 다를 수 있어요. 같은 우변 묶음이면 언제나 같은 결과예요. `trans='T'`와 `'H'`는 열마다 따로 풀어요.

### 빈 행렬

0 × 0 행렬도 분해할 수 있고, 그 `solve`는 빈 배열을 돌려줘요.

```python
>>> e = sd.sparse.splu(sd.sparse.csr_array((0, 0)))
>>> e
SparseLU(shape=(0, 0), dtype=float64)
>>> e.solve(sd.zeros(0))
array([], dtype=float64)
```

## scipy를 아는 분께

- 결과는 scipy의 `SuperLU`가 아니라 `SparseLU`예요. `solve`와 `shape`만 있고 `L`, `U`, `perm_r`, `perm_c`, `nnz`는 없어요. 분해가 내부를 내보이지 않기 때문이에요.
- 분해는 SuperLU가 아니에요. 순서는 근사 최소 차수(AMD)로 정해져 있고(scipy의 기본은 COLAMD), 피벗은 문턱 부분 피벗이에요. `permc_spec`, `diag_pivot_thresh`, `relax`, `panel_size`, `options`는 없어요(주면 `TypeError`).
- `solve`의 `trans`는 scipy와 같은 문자 `'N'`, `'T'`, `'H'`이고 키워드로만 받아요.
- **특이 행렬은 `LinAlgError`예요.** scipy는 정확히 특이하면 `RuntimeError("Factor is exactly singular")`, 값으로 특이하거나 조건수가 $2^{52}$을 넘으면 경고 없이 분해해요. 여기서는 모두 `splu(): singular matrix`예요.
- 실수 분해에 복소 우변을 주면 풀어요. scipy의 `SuperLU.solve`는 `TypeError`예요.
- 분해 뒤에 잔차로 한 번 더 다듬어서 정규화 역오차가 작아요(시험 행렬에서 $1u$ 이하, $u = 2^{-53}$). 해의 마지막 자리는 scipy와 다를 수 있어요.
