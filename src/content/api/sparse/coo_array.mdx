## 한눈에 보기

COO(coordinate, 좌표) 형식은 희소 배열을 가장 곧이곧대로 적는 방법이에요. 0이 아닌 원소마다 행 번호, 열 번호, 값 세 가지를 적어요. 세 목록을 `(data, (row, col))`로 묶어 넘기면 배열이 돼요.

```python
>>> import stardust as sd
>>> row = [0, 1, 1, 2]
>>> col = [1, 0, 2, 2]
>>> data = [5.0, 1.0, 3.0, 2.0]
>>> A = sd.sparse.coo_array((data, (row, col)), shape=(3, 3))
>>> A
<coo_array of shape (3, 3), float64, 4 stored elements>
>>> A.toarray()
array([[0.0, 5.0, 0.0],
       [1.0, 0.0, 3.0],
       [0.0, 0.0, 2.0]], dtype=float64)
```

</Fig>

COO는 **만들기**의 형식이에요. 원소를 아무 순서로 늘어놓아도 되고, 같은 자리가 여러 번 나와도 돼요. 행렬을 조립하는 많은 계산(유한요소법, 그래프의 간선 목록 등)이 자연스럽게 이런 목록을 내요. 다 만들면 [`tocsr()`](/api/sparse/sparray/#형식-바꾸기)로 바꿔서 계산해요.

```python
>>> B = A.tocsr()
>>> B @ sd.asarray([1.0, 1.0, 1.0])
array([5.0, 4.0, 2.0], dtype=float64)
```

## 만드는 법

`arg`에 무엇을 넣는지에 따라 만드는 법이 다섯 가지예요.

| `arg` | 만들어지는 것 |
|---|---|
| `(data, (row, col))` | 좌표로 적은 2차원 배열 |
| `(data, (i,))` | 좌표로 적은 1차원 배열 |
| `(M, N)`이나 `(N,)` 같은 정수의 tuple | 아무것도 저장하지 않은 빈 배열 |
| 밀집 `sd.ndarray`, numpy 배열, 수의 리스트 | 0이 아닌 원소만 저장한 배열 |
| 다른 희소 배열, scipy의 희소 객체 | 같은 값의 COO 배열 |

tuple을 가르는 규칙은 이래요. 원소가 모두 정수면 모양이고, 둘째 원소가 배열들의 tuple이면 좌표예요. 그 밖의 tuple은 밀집 배열의 시퀀스로 읽어요.

```python
>>> sd.sparse.coo_array((2, 3))
<coo_array of shape (2, 3), float64, 0 stored elements>
>>> sd.sparse.coo_array([[0, 7], [0, 0]])
<coo_array of shape (2, 2), int64, 1 stored element>
>>> sd.sparse.coo_array(([1.0, 2.0], ([0, 5],)))
<coo_array of shape (6,), float64, 2 stored elements>
```

### 좌표

`data`, `row`, `col`은 같은 길이의 `sd.ndarray`, numpy 배열, 리스트예요. 좌표는 정수여야 해요(int32 같은 numpy의 좁은 정수는 int64로 넓혀요). float이나 bool 좌표는 `TypeError`예요.

```python
>>> sd.sparse.coo_array(([1.0], ([0.0], [0])))
Traceback (most recent call last):
    ...
TypeError: coo_array(): 'coords' must hold integers, not float64
>>> sd.sparse.coo_array(([1.0, 2.0], ([0], [0, 1])), shape=(2, 2))
Traceback (most recent call last):
    ...
ValueError: coo_array(): 'data' and the index arrays must have the same length, got 2 and 1
```

`shape`를 주지 않으면 축마다 가장 큰 좌표 + 1이 그 축의 길이예요. 행렬의 끝쪽 행이나 열이 비어 있으면 모양이 작게 잡히므로, 모양을 알면 주는 편이 안전해요.

```python
>>> sd.sparse.coo_array(([1.0, 2.0], ([0, 1], [1, 0])))
<coo_array of shape (2, 2), float64, 2 stored elements>
>>> sd.sparse.coo_array(([1.0, 2.0], ([0, 1], [1, 0])), shape=(3, 3))
<coo_array of shape (3, 3), float64, 2 stored elements>
```

좌표는 0 이상, 그 축의 길이 미만이어야 해요. 음수는 끝에서 세지 않고 범위 밖으로 봐요. 좌표가 하나도 없으면 모양을 정할 수 없어서 `shape`가 꼭 있어야 해요.

```python
>>> sd.sparse.coo_array(([1.0], ([-1], [0])), shape=(2, 2))
Traceback (most recent call last):
    ...
ValueError: coo_array(): index -1 is out of bounds for axis 0 with size 2
>>> sd.sparse.coo_array(([], ([], [])))
Traceback (most recent call last):
    ...
ValueError: coo_array(): cannot infer the shape from empty index arrays; pass 'shape'
```

좌표 배열은 언제나 복사하고 검사해요. 넘긴 리스트나 배열을 나중에 고쳐도 만든 배열은 바뀌지 않아요. 값 배열 `data`는 `copy`를 따라요. `copy=None`이면 dtype이 맞는 `sd.ndarray`는 그대로 나눠 써요.

```python
>>> d = sd.asarray([1.0, 2.0])
>>> X = sd.sparse.coo_array((d, ([0, 1], [1, 0])), shape=(2, 2))
>>> d[0] = 9.0
>>> X.data
array([9.0, 2.0], dtype=float64)
```

나누고 싶지 않으면 `copy=True`를 줘요. 리스트, 밀집 배열, scipy 객체처럼 복사가 꼭 필요한 입력에 `copy=False`를 주면 `ValueError`예요.

### dtype

값의 dtype은 [기본 개념](/api/sparse/basics/#dtype)의 규칙이에요. `dtype=`을 주면 그 dtype으로 바꿔요. 밀집 입력에서는 0이 아닌 자리를 원래 값으로 먼저 고른 뒤에 바꿔요. 그래서 0.4를 int64로 바꾸면 0이 되지만 저장된 원소로 남아요.

```python
>>> sd.sparse.coo_array([[0.4, 0.0], [0.0, 2.0]], dtype=sd.int64).data
array([0, 2], dtype=int64)
```

## 속성

| 속성 | 뜻 |
|---|---|
| `data` | 저장한 값의 1차원 배열. 쓸 수 있어요 |
| `coords` | 축마다 좌표 배열 하나씩의 tuple. 2차원이면 `(row, col)`. 읽기 전용이에요 |
| `has_canonical_format` | 원소가 행 우선 순서로 정렬되어 있고 같은 자리가 없는지 |

```python
>>> A.coords
(array([0, 1, 1, 2], dtype=int64), array([1, 0, 2, 2], dtype=int64))
>>> A.data
array([5.0, 1.0, 3.0, 2.0], dtype=float64)
>>> A.has_canonical_format
True
```

`row`와 `col`이라는 이름은 없어요. `A.coords[0]`, `A.coords[1]`로 읽어요. `data`를 고치는 법과 형식이 함께 가진 속성은 [공통 속성과 메서드](/api/sparse/sparray/)에 있어요.

## 같은 자리가 여러 번 나오면

COO는 같은 자리에 원소를 여러 번 저장할 수 있어요. 값은 그 자리끼리 더한 것으로 읽어요. `nnz`는 저장한 원소를 그대로 세므로 더하기 전의 수예요.

```python
>>> P = sd.sparse.coo_array(([3.0, 1.0, 2.0, 4.0], ([1, 0, 0, 1], [2, 1, 1, 0])), shape=(2, 3))
>>> P.nnz
4
>>> P.toarray()
array([[0.0, 3.0, 0.0],
       [4.0, 0.0, 3.0]], dtype=float64)
>>> P[0, 1]
3.0
>>> P.has_canonical_format
False
```

(0, 1)에 1.0과 2.0이 두 번 저장되어 3.0으로 읽혀요. 원소도 행 순서가 아니라서 `has_canonical_format`이 False예요. 이 값은 처음 물을 때 원소를 한 번 훑어서 알아내요. 정렬되어 있고 같은 자리가 없으면 어떻게 만들었든 True예요.

같은 자리의 값은 **넣은 순서대로 왼쪽부터** 더해요. CSR·CSC로 바꿀 때, `toarray()`, `sum_duplicates()`, 인덱싱이 모두 이 순서예요. 부동소수점 덧셈은 순서에 따라 끝자리가 달라질 수 있어서 이 순서를 정해 뒀어요.

`sum_duplicates()`는 **제자리에서** 원소를 행 우선 순서로 정렬하고 같은 자리를 더해 표준 꼴로 만들어요. None을 돌려줘요.

```python
>>> P.sum_duplicates()
>>> P.nnz, P.has_canonical_format
(3, True)
>>> P.coords
(array([0, 1, 1], dtype=int64), array([1, 0, 2], dtype=int64))
>>> P.data
array([3.0, 4.0, 3.0], dtype=float64)
```

중복을 직접 정리하지 않아도 계산은 맞아요. 리덕션, 원소별 함수, 다른 형식으로의 변환이 알아서 먼저 더해요. 다만 원소별 함수와 `astype`의 결과는 중복을 더한 새 배열이고 원래 배열은 그대로예요.

```python
>>> Q = sd.sparse.coo_array(([1.0, 2.0], ([0, 0], [0, 0])), shape=(1, 1))
>>> Q.sum()
3.0
>>> Q.sqrt().nnz, Q.nnz
(1, 2)
```

스칼라 곱처럼 패턴을 바꾸지 않는 선형 연산(`Q * 2`, `-Q`)은 중복을 그대로 둬요. 중복의 합에 곱해도 같은 값이기 때문이에요.

```python
>>> (Q * 2).nnz
2
```

## 저장된 0 지우기

`eliminate_zeros()`는 값이 0인 저장된 원소(−0.0 포함)를 **제자리에서** 지워요. 같은 자리에 저장된 원소들은 하나씩 따로 봐요. 중복을 더해 0이 되는 원소들을 지우려면 먼저 `sum_duplicates()`를 해요.

```python
>>> Z = sd.sparse.coo_array(([5.0, 0.0, 3.0], ([0, 1, 1], [0, 1, 1])), shape=(2, 2))
>>> Z.nnz, Z.count_nonzero()
(3, 2)
>>> Z.eliminate_zeros()
>>> Z.nnz
2
```

## COO를 돌려주는 연산

모양을 다시 정하는 연산은 COO를 돌려줘요. 어느 형식에서든 [`reshape`](/api/sparse/sparray/#모양-바꾸기)의 결과, 차원 수가 줄어드는 [인덱싱](/api/sparse/indexing/)(2차원의 `A[i]`, `A[:, j]`, 원소 고르기)의 결과가 COO예요. [`tril`](/api/sparse/tril/), [`triu`](/api/sparse/triu/), [`block_diag`](/api/sparse/block_diag/), [`random_array`](/api/sparse/random_array/)의 기본 형식도 COO예요.

```python
>>> M = sd.sparse.csr_array(sd.asarray([[1.0, 0.0], [2.0, 3.0]]))
>>> M[1]
<coo_array of shape (2,), float64, 2 stored elements>
>>> M.reshape((4,))
<coo_array of shape (4,), float64, 3 stored elements>
```

COO끼리 더하거나 곱한 결과는 CSR이에요([연산자](/api/sparse/operators/)). COO의 연산은 대부분 안에서 CSR로 바꿔서 하므로, 같은 배열로 여러 번 계산할 때는 처음에 한 번 `tocsr()`로 바꿔 두는 편이 빨라요.

## 다른 형식과 비교

| | COO | [CSR](/api/sparse/csr_array/) | [DOK](/api/sparse/dok_array/) |
|---|---|---|---|
| 만드는 법 | 좌표 목록을 한 번에 | 세 배열을 한 번에, 또는 다른 형식에서 | 원소를 하나씩 `A[i, j] = v` |
| 같은 자리 중복 | 돼요(더한 값으로 읽어요) | 없어요(생성자가 더해요) | 없어요(마지막에 넣은 값) |
| 순서 | 아무 순서 | 언제나 행 우선 | 없어요(바꿀 때 행 우선으로 정렬) |
| 잘하는 일 | 조립과 주고받기 | 계산 | 하나씩 넣고 고치기 |

원소를 한꺼번에 알면 COO, 반복문에서 하나씩 정해지면 DOK가 편해요.

## scipy를 아는 분께

- **`row`, `col` 속성이 없어요.** `coords[0]`, `coords[1]`만 있어요(scipy에서는 둘이 `coords`의 다른 이름이에요).
- **`has_canonical_format`은 실제로 확인한 값이에요.** scipy는 확인 없이 붙여 두는 표시라서 `(data, (row, col))`로 만들거나 전치·`astype`을 하면 정렬되어 있어도 False예요. 여기서는 처음 물을 때 훑어서 정해요.
- **같은 자리의 합은 넣은 순서로 왼쪽부터예요.** scipy의 `sum_duplicates()`는 첫 원소에 나머지의 numpy 합을 더해서 끝자리가 다를 수 있어요.
- **좌표 배열은 언제나 복사하고 검사해요.** scipy는 넘긴 배열을 검사 없이 그대로 써요.
- **좌표는 int64예요.** scipy는 크기에 따라 int32를 골라요.
- **원소별 함수와 `count_nonzero()`가 원래 배열을 바꾸지 않아요.** scipy는 제자리에서 `sum_duplicates()`를 먼저 해요.
- **`resize`는 차원 수를 바꾸지 않아요.** scipy의 COO는 바꿀 수 있어요.
- **3차원 이상의 COO는 없어요.** scipy의 n차원 COO에 해당하는 것이 없어요.
