## 무엇을 하나요

Nelder–Mead(1965)는 기울기 없이 **함수값의 크기 비교만으로** 내려가는 방법이에요. 변수가 n개면 점 n + 1개로 된 **단체**(simplex)를 들고 다녀요. 2차원에서는 삼각형, 3차원에서는 사면체예요.

반복마다 가장 나쁜(값이 가장 큰) 꼭짓점을 나머지 꼭짓점의 무게중심 너머로 옮겨 봐요. 나쁜 점의 반대쪽이 대체로 내리막이라는 생각이에요. 옮긴 점이 얼마나 좋은지에 따라 단체를 늘이거나 줄여요.

<Fig caption="2차원에서 Nelder–Mead가 시험하는 점. 가장 나쁜 꼭짓점 x3를 나머지 둘의 무게중심 x̄ 너머로 반사(r)하고, 결과에 따라 더 멀리 확장(e)하거나, 바깥(c)이나 안쪽(cc)으로 수축해요. 어느 것도 x3보다 낫지 않으면 단체 전체를 가장 좋은 꼭짓점 x1 쪽으로 반만큼 축소해요(점선).">

</Fig>

한 반복의 규칙은 이래요. 꼭짓점을 값 순서로 $f(x_1) \le \dots \le f(x_{n+1})$로 놓고, $x_{n+1}$을 뺀 무게중심을 $\bar x$라고 해요.

1. **반사** $x_r = \bar x + (\bar x - x_{n+1})$을 계산해요. $f(x_1) \le f(x_r) < f(x_n)$이면 $x_r$로 바꾸고 끝이에요.
2. $x_r$이 가장 좋은 꼭짓점보다도 좋으면 그쪽이 확실한 내리막이니 **확장** $x_e = \bar x + 2(\bar x - x_{n+1})$을 시험하고, 둘 가운데 나은 것을 받아요.
3. $x_r$이 두 번째로 나쁜 꼭짓점보다 나쁘면 너무 멀리 간 거예요. **수축**해요. $x_r$이 원래의 가장 나쁜 점보다는 나으면 바깥 수축 $\bar x + \tfrac12(\bar x - x_{n+1})$, 아니면 안쪽 수축 $\bar x - \tfrac12(\bar x - x_{n+1})$이에요.
4. 수축한 점도 받을 수 없으면 가장 좋은 꼭짓점만 두고 나머지를 그쪽으로 반만큼 당기는 **축소**를 해요.

반복 하나에 함수를 보통 한두 번 불러요. 축소할 때만 n + 2번이에요. 아래 그림은 Rosenbrock 함수에서 단체가 골짜기를 따라 기어가는 모습이에요. 골짜기 방향으로 길쭉해지며 나아가다가 바닥 근처에서 오그라들어요.

## 기본 사용

`sd.optimize.minimize`에 `method='nelder-mead'`를 줘요. 목적함수만 있으면 돼요.

```python
>>> import math
>>> import stardust as sd
>>> def rosen(x):
...     return 100.0 * (x[1] - x[0]**2)**2 + (1 - x[0])**2
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead')
>>> r
OptimizeResult(method='nelder-mead', converged=True, fun=8.17766e-10, n_iter=84, nfev=159, x=[1.0000220217835696 1.0000422197517715])
>>> r.message
'Optimization terminated successfully.'
```

`n_iter`는 반복한 수예요. 위 결과는 84번 반복하고 멈췄다는 뜻이에요. `nfev`는 처음 꼭짓점 n + 1개를 계산한 것을 포함한 함수 호출 수예요.

결과에는 기울기(`jac`)가 없고, 대신 마지막 단체 `final_simplex`가 있어요. 꼭짓점 (n + 1, n)과 그 값 (n + 1,)의 튜플이고 값이 작은 순서예요. `x`는 첫 꼭짓점, `fun`은 값의 최솟값이에요.

```python
>>> vertices, values = r.final_simplex
>>> vertices
array([[1.0000220217835696, 1.0000422197517715],
       [0.9999952919648114, 0.9999872894360756],
       [0.9999758857897321, 0.9999540990355993]], dtype=float64)
>>> values
array([ 8.177661197416674e-10, 1.1075489735209213e-09,
       1.1229296958589735e-09], dtype=float64)
```

## 언제 쓰나요

### 기울기가 없거나 f가 매끄럽지 않을 때

Nelder–Mead는 값의 크기만 비교하므로 f가 꺾이거나 계단이 있어도 움직여요. $\lvert x - 1\rvert + 2\lvert y + 0.5\rvert$는 최솟값 (1, −0.5)에서 뾰족해서 기울기가 정의되지 않아요. BFGS는 그 근처까지는 가지만 선 탐색이 걸음을 찾지 못해 status 2로 멈춰요.

```python
>>> def kink(x):
...     return abs(x[0] - 1) + 2 * abs(x[1] + 0.5)
>>> r = sd.optimize.minimize(kink, [3.0, 2.0], method='nelder-mead')
>>> r.converged, r.nfev, [round(v, 4) for v in r.x.tolist()]
(True, 108, [1.0, -0.5])
>>> r = sd.optimize.minimize(kink, [3.0, 2.0], method='bfgs')
>>> r.converged, r.status, r.nfev
(False, 2, 276)
```

### 값에 잡음이 있을 때

시뮬레이션이나 측정처럼 값에 작은 잡음이 섞이면, 차분으로 구한 기울기는 잡음에 지배돼요. Nelder–Mead의 단체는 잡음보다 큰 규모에서 값을 비교하므로 큰 모양을 따라가요. 아래는 Rosenbrock에 진폭 $10^{-4}$의 빠른 물결을 더한 함수예요.

```python
>>> def rippled(x):
...     return rosen(x) + 1e-4 * math.sin(1e4 * x[0]) * math.sin(1e4 * x[1])
>>> r = sd.optimize.minimize(rippled, [-1.2, 1.0], method='nelder-mead')
>>> r.converged, [round(v, 2) for v in r.x.tolist()]
(True, [1.0, 1.01])
>>> r = sd.optimize.minimize(rippled, [-1.2, 1.0], method='bfgs')
>>> r.converged, r.status, [round(v, 2) for v in r.x.tolist()]
(False, 2, [0.74, 0.55])
```

물결의 크기($10^{-4}$)보다 정확한 답은 어느 방법으로도 얻을 수 없어요. Nelder–Mead는 그 크기의 해까지 데려다줘요.

### 쓰지 않는 게 좋을 때

- **f가 매끄럽고 기울기를 구할 수 있을 때**: BFGS가 훨씬 적은 계산으로 더 정확한 해를 줘요. 기울기 함수가 없어도 차분의 BFGS가 대개 더 빨라요([`minimize`](/api/optimize/minimize/)의 그림).
- **변수가 많을 때**: 단체가 n차원을 채워야 해서 n이 커지면 계산이 급히 늘고, 멈추지 않는 듯 오래 돌거나 해가 아닌 곳에서 오그라들기도 해요. 10개 남짓이 실용적인 한계예요. 아래는 Rosenbrock을 0에서 풀 때 `fun`을 부른 수예요.

```python
>>> def rosen_n(x):
...     return float(sd.sum(100.0 * (x[1:] - x[:-1]**2)**2 + (1 - x[:-1])**2))
>>> for n in [2, 3, 5, 10]:
...     r = sd.optimize.minimize(rosen_n, sd.zeros(n), method='nelder-mead')
...     print(n, r.converged, r.status, r.nfev, f"{r.fun:.1e}")
2 True 0 146 3.7e-10
3 True 0 289 1.2e-09
5 True 0 883 5.9e-09
10 False 1 2000 5.5e+00
```

n = 10에서는 기본 상한(fun 200n = 2,000번)에 닿았어요. 상한을 늘리면 4,729번 만에 수렴해요. 같은 문제를 차분의 기울기로 푸는 L-BFGS-B는 825번 불러요(차분의 호출 포함).

## 옵션

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `xatol` | 0.0001 | 모든 꼭짓점이 가장 좋은 꼭짓점과 좌표마다 이만큼 안이면… |
| `fatol` | 0.0001 | …그리고 모든 값이 가장 좋은 값과 이만큼 안이면 멈춰요 |
| `max_iter` | None | 반복 수의 상한 |
| `max_nfev` | None | `fun`을 부르는 수의 상한 |
| `adaptive` | False | 계수를 차원에 맞춰요(Gao–Han) |
| `initial_simplex` | None | 처음 단체 (n + 1, n) |

`tol`을 주면 `xatol`과 `fatol`을 모두 그 값으로 정해요. `bounds`도 받아요.

### xatol, fatol: 언제 멈추나요

두 조건이 **모두** 서야 멈춰요. 단체가 좌표마다 `xatol` 안으로 오그라들었고, 꼭짓점의 값이 `fatol` 안으로 모였을 때예요. 둘 다 절대 기준이라 변수와 값의 크기에 맞춰 골라야 해요(변수가 $10^{-6}$ 크기면 기본값으로는 처음부터 멈춰요).

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead', tol=1e-10)
>>> r.nfev, [f"{v - 1:.1e}" for v in r.x.tolist()]
(249, ['-2.4e-11', '-4.8e-11'])
```

### max_iter, max_nfev: 상한

둘 다 주지 않으면 각각 200n이에요. 하나만 주면 다른 하나는 상한이 없어요. 상한에 닿으면 에러 없이 그때의 가장 좋은 점과 `converged=False`를 돌려줘요. `max_nfev`를 넘는 호출은 하지 않아요(그 반복은 중간에 끝나요). `max_iter`로 멈출 때는 `max_iter − 1`번 반복하고 멈춰요. `max_iter=30`이면 29번이에요.

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead', options={'max_nfev': 50})
>>> r.nfev, r.status, r.message
(50, 1, 'Maximum number of function evaluations has been exceeded.')
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead', options={'max_iter': 30})
>>> r.n_iter, r.status, r.message
(29, 2, 'Maximum number of iterations has been exceeded.')
```

### adaptive: 차원이 클 때

기본 계수(반사 1, 확장 2, 수축 1/2, 축소 1/2)는 차원이 커지면 단체가 너무 빨리 납작해져 해가 아닌 곳에서 멈출 수 있어요. `adaptive=True`이면 Gao와 Han(2012)의 계수(확장 $1 + 2/n$, 수축 $3/4 - 1/(2n)$, 축소 $1 - 1/n$)를 써요. n = 2에서는 두 계수가 같아서 결과도 같아요.

n = 20인 Rosenbrock에서는 기본 계수가 f = 11.8인 점에서 "수렴"하고, 적응 계수는 최솟값에 닿아요.

```python
>>> opts = {'max_nfev': 50000, 'max_iter': 50000}
>>> r = sd.optimize.minimize(rosen_n, sd.zeros(20), method='nelder-mead', options=opts)
>>> r.converged, round(r.fun, 2), r.nfev
(True, 11.83, 32304)
>>> r = sd.optimize.minimize(rosen_n, sd.zeros(20), method='nelder-mead', options={**opts, 'adaptive': True})
>>> r.converged, f"{r.fun:.1e}", r.nfev
(True, '1.4e-08', 22659)
```

<Callout type="warn">
Nelder–Mead의 `converged=True`는 "단체가 작아졌다"는 뜻이지 "최솟값에 닿았다"는 뜻이 아니에요. 단체가 해가 아닌 곳에서 오그라들 수도 있어요. 결과의 `x`에서 다시 시작하면 처음 단체가 새로 만들어져 더 내려가기도 해요. 위의 n = 20에서 기본 계수로 다시 시작할 때마다 f가 11.2, 8.4, 5.7, 2.3으로 내려가지만 느려요. 차원이 크면 `adaptive=True`가 나아요.
</Callout>

### initial_simplex: 처음 단체

주지 않으면 처음 단체는 `x0`와, `x0`의 좌표 하나씩을 5% 늘린 점 n개예요(0인 좌표는 0.00025로). 그래서 `x0`가 0이면 단체가 아주 작게 시작하고, 해가 멀면 확장을 여러 번 해야 해요. 문제의 크기를 알면 단체를 직접 줘요. 행이 꼭짓점이고 모양은 (n + 1, n)이에요.

```python
>>> def far(x):
...     return (x[0] - 300.0)**2 + (x[1] + 200.0)**2
>>> sd.optimize.minimize(far, [0.0, 0.0], method='nelder-mead').nfev
229
>>> big = [[0.0, 0.0], [100.0, 0.0], [0.0, 100.0]]
>>> sd.optimize.minimize(far, [0.0, 0.0], method='nelder-mead', options={'initial_simplex': big}).nfev
94
>>> sd.optimize.minimize(far, [0.0, 0.0], method='nelder-mead', options={'initial_simplex': [[0.0, 0.0], [1.0, 0.0]]})
Traceback (most recent call last):
    ...
ValueError: minimize(): 'initial_simplex' must have shape (N + 1, N), not (2, 2)
```

`initial_simplex`를 주면 `x0`는 변수의 수를 정하는 데만 써요. 단체의 첫 꼭짓점에서 `fun`이 유한해야 해요.

### bounds

`bounds=(lower, upper)`를 주면 새로 만드는 점마다 좌표를 경계로 잘라요(`numpy.clip`과 같아요). 기본 처음 단체에서 위 경계를 넘는 꼭짓점은 경계 안쪽으로 반사한 뒤 잘라요. `x0`는 경계 안이어야 해요.

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead', bounds=([-2.0, -2.0], [0.5, 2.0]))
>>> r.converged, r.x
(True, array([               0.5, 0.2500195980022476], dtype=float64))
```

경계로 자르면 단체가 경계 면에 납작하게 붙어 차원 하나를 잃을 수 있어요. 경계 위에 해가 있고 정확한 해가 필요하면 `'l-bfgs-b'`가 더 잘 맞아요.

## 결과의 status

| `status` | `message` | `converged` |
|---|---|---|
| 0 | `Optimization terminated successfully.` | True(마지막 값이 유한할 때) |
| 1 | `Maximum number of function evaluations has been exceeded.` | False |
| 2 | `Maximum number of iterations has been exceeded.` | False |

반복 중에 `fun`이 inf나 NaN을 돌려주면 그 꼭짓점이 가장 나쁜 것으로 정렬돼서 다음 반복에 바뀌어요. 영역 밖에서 `math.inf`를 돌려주면 단체가 그쪽으로 가지 않아요. 처음 꼭짓점(`x0`, 또는 `initial_simplex`의 첫 행)에서 유한하지 않으면 `ValueError`예요.

## 정확도와 비용

- 해는 멈춘 단체의 크기만큼 정확해요(`xatol` 안팎). Nelder–Mead는 해 근처에서도 빨라지지 않아서, 자릿수 하나를 더 얻는 데 드는 반복이 거의 일정해요(위 그림의 기울기). 기울기를 쓰는 방법은 해에 가까울수록 빨라져요.
- 반복 하나의 계산은 무게중심(n² 덧셈)과 비교뿐이라 작아요. 시간은 거의 `fun`을 부르는 데 들어요.
- scipy 1.18.1의 `method='Nelder-Mead'`와 같은 알고리즘이고, 지금은 같은 점에서 `fun`을 같은 차례로 불러 `x`, `fun`, `nfev`, `status`가 비트까지 같아요(약속은 아니에요). 자세한 계산은 [구현 글](/internals/optimize/nelder-mead/)에 있어요.

## scipy를 아는 분께

- 옵션 이름: `maxiter`는 `max_iter`, `maxfev`는 `max_nfev`예요. `xatol`, `fatol`, `adaptive`, `initial_simplex`는 같고 기본값도 같아요. `disp`, `return_all`은 없어요.
- `jac`를 주면 scipy는 경고하고 무시하지만 여기서는 `ValueError`예요.
- `bounds`는 `(lower, upper)` 꼴이고, `x0`가 경계 밖이면 `ValueError`예요(scipy는 경계 안으로 옮겨요).
- `n_iter`는 한 반복 수라 scipy의 `nit`보다 하나 작아요(scipy는 1에서 세요). 멈추는 곳은 같아서, `max_iter=k`이면 두 라이브러리 모두 k − 1번 반복하고 멈춰요.
