## 무엇을 하나요

도함수는 함수의 기울기예요. $x$를 아주 조금 움직였을 때 $f$가 얼마나 바뀌는지의 비율이에요. 식으로 미분하기 어렵거나 귀찮을 때는 실제로 조금 움직여 보고 비율을 재면 어림할 수 있어요. 이것을 **차분**이라고 해요. 가장 간단한 앞쪽 차분은

$$
f'(x) \approx \frac{f(x + h) - f(x)}{h}
$$

이에요. 변수가 여럿이면 변수 하나씩 움직여서 편도함수 $\partial f / \partial x_j$를 모아요. $f$가 실수 하나를 돌려주면 그 모음이 **기울기**(gradient), 값 $m$개를 돌려주면 $(m, n)$ 행렬인 **야코비안**이에요.

간격 $h$를 고르기가 까다로워요. $h$가 크면 곡선을 직선으로 본 오차(절단 오차)가 크고, $h$가 너무 작으면 $f(x + h)$와 $f(x)$가 거의 같아서 두 값의 반올림 오차가 비율을 망쳐요(반올림 오차). 앞쪽 차분은 $h \approx 10^{-8}$에서 두 오차가 맞먹고, 그때도 상대오차가 $10^{-8}$쯤이에요.

`approx_fprime`의 기본은 두 가지로 이 한계를 넘어요.

- **5점 중앙 차분**: $x \pm h$, $x \pm 2h$의 네 값으로
  $$f'(x) \approx \frac{f(x - 2h) - 8f(x - h) + 8f(x + h) - f(x + 2h)}{12h}$$
  을 계산해요. 절단 오차가 $h^4$에 비례해서 $h$를 조금만 줄여도 빠르게 작아져요.
- **변수마다 간격 고르기**: 큰 간격에서 시작해 4배씩 줄여 가며 추정을 거듭하고, 이웃한 두 추정이 충분히 빨리 가까워지는 동안(절단 오차가 앞서는 동안) 계속 줄여요. 반올림 오차가 앞서기 시작하면 멈추고 마지막으로 좋았던 추정을 써요. 처음 간격은 $\lvert x_j\rvert$에 비례하므로, $x_j$가 함수가 변하는 척도보다 훨씬 작으면(예: $10^{-12}$) 처음 추정부터 반올림에 묻혀요. 그때는 간격을 키워 가며 다시 찾아서, $x_j$가 0에 아주 가까워도 $x_j = 0$일 때와 같은 정확도를 내요.

## 기본 사용

$f(x_0, x_1) = e^{x_0}\sin x_1$의 기울기는 $(e^{x_0}\sin x_1,\ e^{x_0}\cos x_1)$이에요. $(1, 2)$에서 어림해서 견줘 볼게요.

```python
>>> import stardust as sd
>>> import math
>>> f = lambda x: math.exp(x[0]) * math.sin(x[1])
>>> g = sd.optimize.approx_fprime([1.0, 2.0], f)
>>> g
array([ 2.4717266720042517, -1.1312043837571462], dtype=float64)
>>> exact = [math.exp(1) * math.sin(2), math.exp(1) * math.cos(2)]
>>> [f'{abs(a - b) / abs(b):.1e}' for a, b in zip(g.tolist(), exact)]
['2.3e-13', '2.9e-13']
```

`f`가 실수 하나를 돌려주면 결과는 기울기 $(n,)$이에요. 값 여러 개를 돌려주면 야코비안 $(m, n)$이고, $i$행 $j$열이 $\partial f_i / \partial x_j$예요.

```python
>>> F = lambda x: [x[0] * x[1], x[0]**2, math.sin(x[1])]
>>> J = sd.optimize.approx_fprime([1.0, 2.0], F)
>>> J
array([[                  2.0,                   1.0],
       [                  2.0,                   0.0],
       [9.473903143468002e-15,   -0.4161468365471516]], dtype=float64)
```

참 야코비안은 $\begin{pmatrix} 2 & 1 \\ 2 & 0 \\ 0 & \cos 2 \end{pmatrix}$예요. 셋째 행 첫째 열은 정확히 0이어야 하지만 $9.5 \times 10^{-15}$가 나왔어요. 차분은 $f$ 값의 반올림을 $h$로 나누므로, 참값이 0인 자리에도 그만큼의 작은 수가 남아요. 결과를 0과 견줄 때는 정확한 0 대신 작은 문턱으로 견줘요.

값을 하나만 돌려줘도 리스트나 배열이면 야코비안 $(1, n)$이에요. 실수 하나로 돌려줄 때만 기울기 $(n,)$이에요.

```python
>>> sd.optimize.approx_fprime([1.0, 2.0], lambda x: x[0] * x[1])
array([2.0, 1.0], dtype=float64)
>>> sd.optimize.approx_fprime([1.0, 2.0], lambda x: [x[0] * x[1]])
array([[2.0, 1.0]], dtype=float64)
```

$x_j$가 0에 아주 가까워도 정확도는 같아요. $e^x$의 도함수를 $x = 0$과 $x = 10^{-300}$에서 구하면 같은 값이 나와요.

```python
>>> exp1 = lambda x: math.exp(x[0])
>>> sd.optimize.approx_fprime([0.0], exp1), sd.optimize.approx_fprime([1e-300], exp1)
(array([0.9999999999999621], dtype=float64), array([0.9999999999999621], dtype=float64))
```

`f` 안에서 `sd` 배열 연산을 써도 돼요. `f`가 받는 `x`는 `sd.ndarray`이고 호출마다 새 배열이라, 함수 안에서 고쳐도 다음 계산에 영향이 없어요. 5점 차분은 4차 이하의 다항식에서 절단 오차가 없어서, 아래의 $\lVert x\rVert^2$에서는 참값이 그대로 나와요.

```python
>>> norm2 = lambda x: float(sd.sum(x**2))
>>> sd.optimize.approx_fprime(sd.asarray([1.0, -2.0, 3.0]), norm2)
array([ 2.0, -4.0,  6.0], dtype=float64)
```

## epsilon: 정해진 간격의 앞쪽 차분

`epsilon`을 주면 간격을 고르지 않고 그 간격의 앞쪽 차분을 써요. 수 하나는 모든 변수에, $n$개는 변수마다 써요. 함수를 $n + 1$번만 불러서 빠르지만 정확도는 간격에 달려 있어요.

```python
>>> g1 = sd.optimize.approx_fprime([1.0, 2.0], f, epsilon=1e-6)
>>> g1
array([ 2.4717279078858048, -1.1312056196839175], dtype=float64)
>>> [f'{abs(a - b) / abs(b):.1e}' for a, b in zip(g1.tolist(), exact)]
['5.0e-07', '1.1e-06']
```

앞쪽 차분의 오차는 간격이 클 때는 간격에 비례하고, 너무 작을 때는 반올림 때문에 다시 커져요. $e^x$의 $x = 1$에서 재면 이래요.

```python
>>> for eps in (1e-4, 1e-6, 2**-26, 1e-10, 1e-12):
...     d = sd.optimize.approx_fprime([1.0], lambda x: math.exp(x[0]), epsilon=eps)[0]
...     print(f'{eps:.1e}  {abs(d - math.e) / math.e:.1e}')
1.0e-04  5.0e-05
1.0e-06  5.0e-07
1.5e-08  1.3e-08
1.0e-10  4.9e-07
1.0e-12  7.0e-05
```

$2^{-26} = \sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$($\varepsilon = 2^{-52}$, 기계 엡실론)은 scipy의 `approx_fprime`이 쓰는 기본 간격이에요. 이 값을 주면 scipy와 같은 점에서 `f`를 부르고, 지금은 결과도 비트까지 같아요(같은 `f`를 쓸 때; 약속은 아니에요).

```python
>>> import numpy as np
>>> import scipy.optimize as so
>>> a = so.approx_fprime(np.array([1.0, 2.0]), f)
>>> b = sd.optimize.approx_fprime([1.0, 2.0], f, epsilon=2**-26)
>>> a.tolist() == b.tolist()
True
```

$x_j$가 아주 커서 $x_j + h_j$($h_j$는 `epsilon`의 $j$번째 값)가 반올림으로 $x_j$와 같아지면 차분을 할 수 없어요. 그 변수만 간격을 $\sqrt{\varepsilon}\,\max(1, \lvert x_j\rvert)$($\varepsilon = 2^{-52}$은 기계 엡실론, $\sqrt\varepsilon = 2^{-26}$)로 바꿔요(scipy와 같아요). 분모는 언제나 실제로 움직인 거리 $(x_j + h_j) - x_j$예요.

```python
>>> sd.optimize.approx_fprime([1e10], lambda x: x[0]**2 / 1e10, epsilon=1e-8)
array([2.0000000128], dtype=float64)
```

## 정의역의 끝과 유한하지 않은 값

기본(`epsilon=None`)은 $f$가 한쪽에서 NaN이나 무한대이면 그쪽을 쓰지 않는 **한쪽 5점 차분**으로 바꿔요. $x \ge 1$에서만 정의된 함수를 $x = 1$에서 미분해도 오른쪽 값만으로 계산해요.

```python
>>> e1 = lambda x: math.exp(x[0]) if x[0] >= 1 else math.nan
>>> d = sd.optimize.approx_fprime([1.0], e1)[0]
>>> f'{abs(d - math.e) / math.e:.1e}'
'5.3e-13'
```

정의역의 끝에서 도함수가 빠르게 변하면 한쪽 차분도 정확도를 잃어요. $\sqrt{x - 1}$을 $x = 1.001$에서 미분하면 참값은 $1/(2\sqrt{0.001}) \approx 15.81$인데, 끝까지의 거리 0.001보다 큰 간격의 한쪽 차분을 쓰게 되어 14.50이 나와요. 이런 곳에서는 도함수를 식으로 주는 편이 좋아요.

```python
>>> s = lambda x: math.sqrt(x[0] - 1) if x[0] >= 1 else math.nan
>>> sd.optimize.approx_fprime([1.001], s)
array([14.497643524927717], dtype=float64)
```

`xk`에서 $f$가 유한하지 않거나, 어느 쪽으로도 유한한 차분을 얻지 못하면 `ValueError`예요.

```python
>>> sd.optimize.approx_fprime([0.0], lambda x: math.log(x[0]) if x[0] > 0 else -math.inf)
Traceback (most recent call last):
    ...
ValueError: approx_fprime(): 'f' is not finite at the point
>>> sd.optimize.approx_fprime([1.0], lambda x: 0.0 if x[0] == 1.0 else math.nan)
Traceback (most recent call last):
    ...
ValueError: approx_fprime(): 'f' is not finite near the point (the differences of variable 0)
```

`epsilon`을 주면 scipy처럼 이런 검사 없이 계산해요. 결과에 NaN이나 무한대가 들어갈 수 있어요.

```python
>>> sd.optimize.approx_fprime([0.0], lambda x: math.log(x[0]) if x[0] > 0 else -math.inf, epsilon=1e-8)
array([inf], dtype=float64)
```

마지막 예처럼 인자의 순서는 점 `xk`가 먼저, 함수 `f`가 다음이에요(scipy와 같아요). `check_grad`, `minimize`는 함수가 먼저라 헷갈리기 쉬워요.

## 정확도와 비용

기본은 정확하지만 함수를 많이 불러요. 변수마다 간격을 고르며 5점 차분을 두 번 이상 하므로, 변수 하나에 $f$를 8번 이상 불러요(점 `xk`에서 한 번 더). 처음 두 간격의 추정에 8번, 간격을 하나 더 볼 때마다 4번이에요. 시험 문제에서는 대개 8–28번이었고, $\sin$, $\cos$, $e^x$처럼 $\lvert x\rvert$가 클수록 간격을 많이 보는 함수에서 많아요. 앞쪽 차분은 변수 하나에 한 번이에요.

```python
>>> calls = []
>>> def counted(x):
...     calls.append(1)
...     return f(x)
>>> _ = sd.optimize.approx_fprime([1.0, 2.0], counted)
>>> len(calls)
37
>>> calls.clear()
>>> _ = sd.optimize.approx_fprime([1.0, 2.0], counted, epsilon=1e-6)
>>> len(calls)
3
```

| | 기본(`epsilon=None`) | 앞쪽 차분(`epsilon`) |
|---|---|---|
| 상대오차 | $10^{-11}$–$10^{-13}$ 안팎 | 가장 좋은 간격에서 $10^{-8}$ 안팎 |
| $f$를 부르는 수 | 변수 하나에 8번 이상(대개 8–28번) | 변수 하나에 1번 |
| `xk`에서 유한하지 않은 $f$ | `ValueError` | 그대로 계산 |
| 한쪽에서 유한하지 않은 $f$ | 한쪽 5점 차분 | 그대로 계산 |

Moré–Garbow–Hillstrom의 시험 문제 47경우에서 기본의 결과를 해석적 도함수와 견주면 상대 차이가 야코비안은 최대 $1.2 \times 10^{-11}$, 기울기는 최대 $6.4 \times 10^{-11}$이에요. 시간은 Rosenbrock 함수(scipy의 `rosen`)에서 이래요(Apple M4 Pro, 1스레드, scipy 1.18.1).

| $n$ | 기본 | `epsilon=2**-26` | scipy `approx_fprime` |
|---:|---:|---:|---:|
| 10 | 0.687 ms | 0.0669 ms | 0.0817 ms |
| 100 | 9.68 ms | 0.600 ms | 0.682 ms |
| 1000 | 184 ms | 8.59 ms | 9.59 ms |

반복 안에서 기울기를 여러 번 구해야 하는 최적화에는 앞쪽 차분이 알맞아요. `minimize`와 `least_squares`가 기울기를 주지 않았을 때 쓰는 차분도 앞쪽(또는 3점) 차분이에요. `approx_fprime`의 기본은 결과를 한 번 정확히 얻고 싶을 때, 예를 들어 직접 쓴 도함수를 확인하거나([`check_grad`](/api/optimize/check_grad/)) 해에서의 야코비안을 구할 때 좋아요.

## scipy를 아는 분께

- 인자의 이름과 순서(`xk`, `f`, `epsilon`)는 scipy와 같아요. 사용자 함수의 추가 인자 `*args`는 없어요. `lambda`로 묶어 주세요.
- **기본이 달라요.** scipy의 기본은 간격 $\sqrt{\varepsilon} = 2^{-26}$의 앞쪽 차분이고, 여기서는 간격을 고르는 5점 차분이에요. 결과가 scipy와 다르고(더 정확해요) 함수를 더 많이 불러요. `epsilon=2**-26`을 주면 scipy의 기본과 같은 차분이고, 지금은 비트까지 같아요(약속은 아니에요).
- `xk`에서 $f$가 유한하지 않으면 기본은 `ValueError`예요. `epsilon`을 주면 scipy처럼 계산해요.
- 값 $m$개를 돌려주는 `f`의 결과는 scipy처럼 $(m, n)$이에요. 결과는 numpy 배열이 아니라 float64 `sd.ndarray`예요.
