## 무엇을 하나요

`minimize`의 BFGS나 Newton-CG 같은 방법은 기울기 함수 `jac`을 받으면 훨씬 적은 계산으로 풀어요. 그런데 기울기를 손으로 미분해 쓰다 보면 실수하기 쉬워요. 틀린 기울기를 주면 방법이 엉뚱한 방향으로 가다가 멈추고, 에러 없이 이상한 결과만 남아요.

`check_grad`는 그 실수를 찾아요. 사용자의 `grad(x0)`와, 같은 점에서 `func`를 차분으로 미분한 기울기를 견주어 차이의 길이(2-노름)를 돌려줘요. 기울기를 맞게 썼다면 차분의 오차만큼만 달라서 아주 작은 수가 나오고, 틀렸다면 기울기의 크기에 견줄 만한 수가 나와요.

## 기본 사용

Rosenbrock 함수 $f(x) = (1 - x_0)^2 + 100(x_1 - x_0^2)^2$의 기울기는

$$
\nabla f = \bigl(-2(1 - x_0) - 400 x_0 (x_1 - x_0^2),\ \ 200(x_1 - x_0^2)\bigr)
$$

이에요. 둘째 성분의 200을 100으로 잘못 쓴 `bad`와 함께 확인해 봐요.

```python
>>> import stardust as sd
>>> rosen = lambda x: (1 - x[0])**2 + 100 * (x[1] - x[0]**2)**2
>>> grad = lambda x: [-2 * (1 - x[0]) - 400 * x[0] * (x[1] - x[0]**2), 200 * (x[1] - x[0]**2)]
>>> bad = lambda x: [-2 * (1 - x[0]) - 400 * x[0] * (x[1] - x[0]**2), 100 * (x[1] - x[0]**2)]
>>> sd.optimize.check_grad(rosen, grad, [-1.2, 1.0])
1.7896651901800357e-12
>>> sd.optimize.check_grad(rosen, bad, [-1.2, 1.0])
44.000000000000306
```

맞는 기울기는 $1.8 \times 10^{-12}$, 틀린 기울기는 44예요. 참 기울기는 $(-215.6, -88)$이라 둘째 성분을 반으로 쓴 차이가 정확히 44예요. 틀린 기울기를 `minimize`에 주면 이렇게 돼요.

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], jac=bad)
>>> r.converged, r.n_iter, r.message
(False, 3, 'Desired error not necessarily achieved due to precision loss.')
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], jac=grad).converged
True
```

선 탐색이 기울기가 가리키는 내리막을 찾지 못해 세 번 만에 멈췄어요. 메시지만으로는 기울기가 틀렸다는 것을 알기 어려우니, 기울기를 새로 썼으면 `check_grad`로 먼저 확인해 두는 편이 좋아요.

## 결과 읽기

결과는 절대 크기예요. "작다"의 기준은 기울기의 크기와 차분의 정확도로 정해요.

- 기본(`epsilon=None`)은 상대 $10^{-11}$ 안팎까지 맞는 5점 차분이에요([`approx_fprime`](/api/optimize/approx_fprime/)). 그래서 맞는 기울기면 결과가 대개 $\lVert \nabla f \rVert$의 $10^{-10}$배보다 작아요.
- `epsilon`을 주면 앞쪽 차분이라 맞는 기울기도 $\lVert \nabla f \rVert$의 $10^{-8}$–$10^{-6}$배쯤 나와요.

기울기의 크기로 나눈 상대 값을 보면 판단하기 쉬워요.

```python
>>> import math
>>> g0 = grad([-1.2, 1.0])
>>> norm = math.hypot(*g0)
>>> norm
232.86768775422664
>>> sd.optimize.check_grad(rosen, grad, [-1.2, 1.0]) / norm
7.685330701908653e-15
>>> sd.optimize.check_grad(rosen, bad, [-1.2, 1.0]) / norm
0.18894849871330716
```

### 여러 점에서 확인해요

틀린 기울기가 어떤 점에서는 우연히 맞을 수 있어요. 위의 `bad`는 $x_1 = x_0^2$인 점에서 틀린 항이 0이 되어 맞는 기울기와 같아져요.

```python
>>> sd.optimize.check_grad(rosen, bad, [2.0, 4.0])
0.0
```

그래서 특별하지 않은 점 몇 개에서 확인해요. 무작위 점을 쓰면 편해요.

```python
>>> rng = sd.random.default_rng(1)
>>> for _ in range(3):
...     x = sd.stats.Normal().sample((2,), rng=rng)
...     print(f'{sd.optimize.check_grad(rosen, bad, x):.3g}')
96.8
45.7
128
```

## direction='random': 방향 하나로 빨리 확인하기

`direction='all'`(기본)은 변수 $n$개 방향 모두의 차분이 필요해서, 기본 차분이면 `func`를 변수 하나에 8–20번쯤 불러요. 변수가 많으면 비싸요. `direction='random'`은 표준정규분포에서 뽑은 방향 $v$ 하나만 봐요. 기울기가 맞으면 $v$ 방향의 방향 도함수가

$$
\frac{d}{dw} f(x_0 + w v)\Big|_{w=0} = \nabla f(x_0) \cdot v
$$

여야 하니, 왼쪽을 변수 하나짜리 차분으로 어림해 오른쪽과의 차이 $\lvert \nabla f(x_0)\cdot v - \tfrac{d}{dw} f(x_0 + wv)\rvert$를 돌려줘요. 차분이 변수 하나뿐이라 $n$과 상관없이 `func`를 몇 번만 불러요.

방향을 뽑을 난수 생성기 `rng`를 꼭 줘야 해요. 같은 시드면 같은 값이 나와요.

```python
>>> sd.optimize.check_grad(rosen, grad, [-1.2, 1.0], direction='random', rng=sd.random.default_rng(42))
1.6285639503621496e-11
>>> sd.optimize.check_grad(rosen, bad, [-1.2, 1.0], direction='random', rng=sd.random.default_rng(42))
15.08373626701399
```

변수 100개의 Rosenbrock 함수에서 `func`를 부른 수를 세어 보면 차이가 커요.

```python
>>> n = 100
>>> def rosen_n(x):
...     return float(sd.sum(100 * (x[1:] - x[:-1]**2)**2 + (1 - x[:-1])**2))
>>> def grad_n(x):
...     g = sd.zeros(n)
...     g[1:-1] = 200 * (x[1:-1] - x[:-2]**2) - 400 * (x[2:] - x[1:-1]**2) * x[1:-1] - 2 * (1 - x[1:-1])
...     g[0] = -400 * x[0] * (x[1] - x[0]**2) - 2 * (1 - x[0])
...     g[-1] = 200 * (x[-1] - x[-2]**2)
...     return g
>>> calls = []
>>> def counted(x):
...     calls.append(1)
...     return rosen_n(x)
>>> x0 = sd.asarray([-1.2, 1.0] * 50)
>>> sd.optimize.check_grad(counted, grad_n, x0), len(calls)
(4.953007685757822e-09, 1201)
>>> calls.clear()
>>> sd.optimize.check_grad(counted, grad_n, x0, direction='random', rng=sd.random.default_rng(0)), len(calls)
(1.503508428868372e-09, 13)
```

방향 하나는 기울기의 오류를 그 방향의 성분으로만 보므로, 오류가 $v$와 거의 수직이면 놓칠 수 있어요. 시드를 바꿔 몇 번 확인하거나, 마지막에 `'all'`로 한 번 확인하세요.

## epsilon: 앞쪽 차분

`epsilon`을 주면 [`approx_fprime`](/api/optimize/approx_fprime/)의 `epsilon`처럼 그 간격의 앞쪽 차분으로 견줘요. 함수를 변수 하나에 한 번만 부르니 싸지만, 맞는 기울기에서도 결과가 커요. `epsilon=2**-26`은 scipy의 `check_grad`와 같은 계산이에요.

```python
>>> sd.optimize.check_grad(rosen, grad, [-1.2, 1.0], epsilon=2**-26)
9.737757311449259e-06
>>> import numpy as np
>>> import scipy.optimize as so
>>> float(so.check_grad(rosen, grad, np.array([-1.2, 1.0])))
9.737757311449259e-06
```

`direction='random'`에서는 방향을 따라 움직이는 거리 하나라서 수 하나만 받아요.

## scipy를 아는 분께

- **기본 차분이 달라요.** scipy는 간격 $\sqrt{\varepsilon} = 2^{-26}$($\varepsilon = 2^{-52}$, 기계 엡실론)의 앞쪽 차분이고, 여기서는 간격을 고르는 5점 차분이에요. 그래서 맞는 기울기에 대한 결과가 scipy보다 훨씬 작아요(위의 예에서 $1.8 \times 10^{-12}$ 대 $9.7 \times 10^{-6}$). `epsilon=2**-26`을 주면 scipy와 같은 값이에요.
- **`rng`**: `direction='random'`에서 scipy는 `rng`(numpy의 `Generator`)를 주지 않으면 새로 만들지만, 여기서는 `sd.random.Generator`를 꼭 줘야 해요. 난수가 달라서 같은 시드라도 scipy와 방향이 다르고 결과도 달라요.
- **`direction='all'`에 `rng`**: scipy는 무시하지만 여기서는 `ValueError`예요.
- 사용자 함수의 추가 인자 `*args`는 없어요. `lambda`로 묶어 주세요.
