## 무엇을 하나요

데이터에 곡선을 맞출 때는 점마다 "모형이 말하는 값과 실제로 잰 값의 차이"가 생겨요. 이 차이를 **잔차**라고 해요. 잔차가 25개면 25개 모두를 동시에 작게 만들고 싶은데, 하나를 줄이면 다른 하나가 커지는 일이 흔해요. 그래서 잔차를 제곱해 더한 값 하나를 기준으로 삼아요.

$$
\text{cost}(x) = \frac12 \sum_{i=1}^{m} f_i(x)^2 = \frac12 \lVert f(x)\rVert^2
$$

`least_squares`는 잔차 $f_1(x), \dots, f_m(x)$를 돌려주는 함수 `fun`을 받아, 이 값을 가장 작게 하는 변수 $x = (x_1, \dots, x_n)$을 찾아요. 앞의 ½은 미분을 깔끔하게 하려는 관례라 답에는 영향이 없어요.

잔차가 꼭 "모형 − 데이터"일 필요는 없어요. 여러 조건을 동시에 맞추고 싶을 때 각 조건이 얼마나 어긋났는지를 잔차로 쓰면 돼요. 이 함수는 한 번의 공식으로 답을 내지 않고, 시작점 `x0`에서 출발해 제곱합이 줄어드는 쪽으로 x를 조금씩 옮겨 가요(반복). 그래서 세 가지를 알아 두면 좋아요.

- **시작점이 필요해요.** 답이 여럿이거나 제곱합에 골짜기가 여럿이면 시작점에 따라 다른 곳에 닿아요(아래 [지역 최솟값](#지역-최솟값과-시작점)).
- **잔차가 0이 되지 않아도 돼요.** 측정에 잡음이 있으면 제곱합의 최솟값은 0보다 커요. 모든 잔차를 정확히 0으로 만드는 x를 찾는 일은 [root](/api/optimize/root/)예요.
- **잔차가 x에 대해 일차식(Ax − b)이면** 반복할 필요가 없어요. [lsq_linear](/api/optimize/lsq_linear/)가 정확하게 풀어요.

## 기본 사용

위 그림의 데이터예요. 참값 a = 5, k = 0.4, c = 0.5에 잡음을 조금 섞었어요. 잔차 함수는 모수 `p`(sd 배열)를 받아 25개 잔차를 한 번에 돌려줘요.

```python
>>> rng = sd.random.default_rng(1)
>>> t = sd.linspace(0, 10, 25)
>>> y = 5.0 * sd.exp(-0.4 * t) + 0.5 + 0.1 * sd.stats.Normal().sample(25, rng=rng)
>>> def resid(p):
...     return p[0] * sd.exp(-p[1] * t) + p[2] - y
>>> r = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0])
>>> r
OptimizeResult(method='trf', converged=True, cost=0.100514, n_iter=10, nfev=41, x=[ 5.030580695833325 0.4048766965148036 0.5239089557296326])
>>> r.converged, r.status, r.message
(True, 2, '`ftol` termination condition is satisfied.')
```

`x`가 답(a, k, c)이고 `cost`가 그 점의 ½Σf²예요. `status` 2는 "제곱합이 더는 거의 줄지 않아서" 멈췄다는 뜻이에요. 결과의 나머지 필드는 아래 [결과 읽기](#결과-읽기)에 있어요.

데이터가 없는 문제도 같은 꼴이에요. Rosenbrock 함수 $100(x_2 - x_1^2)^2 + (1 - x_1)^2$은 잔차 두 개 $10(x_2 - x_1^2)$, $1 - x_1$의 제곱합이라 `least_squares`로 바로 풀려요. 최솟값은 두 잔차가 모두 0인 (1, 1)이에요.

```python
>>> def rosen(x):
...     return [10 * (x[1] - x[0] ** 2), 1 - x[0]]
>>> sd.optimize.least_squares(rosen, [-1.2, 1.0])
OptimizeResult(method='trf', converged=True, cost=0, n_iter=18, nfev=61, x=[1.0 1.0])
```

## 잔차 함수 fun

- `fun(x)`의 x는 float64 `sd.ndarray` (n,)이에요. 부를 때마다 새 배열이라 함수 안에서 고쳐도 반복에는 영향이 없어요.
- 돌려주는 값은 길이 m의 1차원 값이에요. `sd.ndarray`, 실수의 리스트·튜플, numpy 배열 모두 돼요. 위의 `rosen`처럼 리스트를 돌려줘도 괜찮아요.
- m은 처음 `x0`에서 부른 결과로 정해져요. 그 뒤에 개수가 바뀌면 `ValueError`예요.
- 상수(데이터 같은)는 클로저로 넘겨요. 위의 `resid`가 바깥의 `t`, `y`를 쓰는 것처럼요. scipy의 `args=` 같은 추가 인자는 없어요. 함수가 따로 있으면 `lambda p: model(p, t, y)`처럼 감싸요.
- 잔차는 변수보다 적어도 돼요(m < n, `'trf'`만). 그때는 답이 하나로 정해지지 않고, 제곱합을 0으로 만드는 점 가운데 하나에 닿아요. 야코비안의 열이 서로 독립이 아니라서 걸음이 늘 신뢰 영역의 경계까지 가고, 근을 넘었다 돌아오기를 되풀이해요. 그래서 아래처럼 일차인 잔차 하나에도 반복이 여러 번 걸려요.

```python
>>> ru = sd.optimize.least_squares(lambda x: [x[0] + x[1] + x[2] - 3], [0.0, 0.0, 0.0])
>>> ru.converged, ru.n_iter, [round(v, 6) for v in ru.x.tolist()]
(True, 15, [1.0, 1.0, 1.0])
```

## 방법 고르기: method

두 방법 모두 **신뢰 영역** 방법이에요. 지금 점 근처에서 잔차를 일차식 $f(x + s) \approx f(x) + J s$로 어림하고($J$는 야코비안, 곧 $\partial f_i / \partial x_j$의 행렬), 그 어림을 믿을 만한 반지름 안에서 제곱합을 가장 작게 하는 걸음 $s$를 골라요. 걸음 뒤의 실제 감소가 어림이 예측한 감소와 비슷하면 반지름을 넓히고, 많이 다르면 좁혀요. 해에서 멀 때는 짧고 안전한 걸음을, 가까워지면 가우스–뉴턴 걸음(어림을 그대로 믿는 걸음)을 해서 끝에서 빨리 수렴해요.

| | `'trf'` (기본값) | `'lm'` |
|---|---|---|
| 방법 | 신뢰 영역 반사법(Trust Region Reflective) | Levenberg–Marquardt(MINPACK) |
| 경계 | 받아요 | 받지 않아요(`ValueError`) |
| 잔차 수 | m < n도 돼요 | m ≥ n이어야 해요 |

- **`'lm'`** 은 가장 오래 쓰여 온 방법이에요. 걸음 $(J^{\mathsf T}J + \lambda D^2)s = -J^{\mathsf T}f$에서 $\lambda$가 0이면 가우스–뉴턴, 크면 짧은 경사 하강 걸음이고, $\lambda$를 신뢰 영역의 반지름에 맞춰 정해요. 경계가 없고 잔차가 변수보다 적지 않은 문제에 써요.
- **`'trf'`** 는 경계가 있어도 되는 방법이에요. 경계 가까이에서는 그쪽 방향의 걸음을 줄이고, 걸음이 경계에 부딪히면 공이 벽에서 튕기듯 방향을 뒤집은 걸음(반사)도 후보로 봐요. 반복점은 늘 경계 안쪽에 있어요. 경계가 없으면 보통의 신뢰 영역 가우스–뉴턴과 같아요.

같은 문제를 두 방법으로 풀면 경로는 조금 다르지만 같은 곳에 닿아요.

```python
>>> sd.optimize.least_squares(rosen, [-1.2, 1.0], method='lm')
OptimizeResult(method='lm', converged=True, cost=0, n_iter=16, nfev=53, x=[1.0 1.0])
```

## 야코비안: jac와 diff_step

반복마다 야코비안 $J$가 필요해요. `jac`을 주지 않으면 차분으로 구해요. 차분은 변수 하나를 조금 움직여 잔차가 얼마나 바뀌는지 재는 거라, 야코비안 하나에 `fun`을 n번(`'2-point'`) 또는 2n번(`'3-point'`) 더 불러요.

| `jac` | 야코비안 하나의 비용 | 열의 상대 정확도(대략) |
|---|---|---|
| `'2-point'` (기본값) | `fun` n번 | $\sqrt{\varepsilon} \approx 10^{-8}$ |
| `'3-point'` | `fun` 2n번 | $\varepsilon^{2/3} \approx 10^{-11}$ |
| 호출 가능한 객체 | `jac` 1번 | 사용자의 식만큼 |

($\varepsilon = 2^{-52} \approx 2.2\times10^{-16}$은 float64의 기계 엡실론이에요. 정확도는 잔차가 매끄럽고 반올림만큼만 틀릴 때의 어림이에요.) 해석적 야코비안을 쓸 수 있으면 호출 수가 크게 줄어요. 위의 감쇠 모형이면 열은 $\partial f / \partial a = e^{-kt}$, $\partial f / \partial k = -a t e^{-kt}$, $\partial f / \partial c = 1$이에요.

```python
>>> def jac(p):
...     e = sd.exp(-p[1] * t)
...     return sd.stack([e, -p[0] * t * e, sd.ones(25)], axis=1)
>>> rj = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], jac=jac)
>>> rj.nfev, rj.njev
(11, 10)
>>> r3 = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], jac='3-point')
>>> r3.nfev, r3.njev
(71, 10)
```

반복 수는 셋 모두 10번이에요. 차분 야코비안 하나가 `'2-point'`는 3번, `'3-point'`는 6번의 `fun`이라 `nfev`가 41, 71이 됐어요. `jac`은 `fun`과 같은 x를 받아 (m, n)을 돌려줘요. n = 1이면 (m,)도 받아요. 모양이 틀리면 `ValueError`예요.

`diff_step`은 차분의 상대 간격이에요. 간격은 $h_j = \text{diff\_step}\cdot\lvert x_j\rvert$이고, 기본은 `'2-point'`가 $\sqrt{\varepsilon}\cdot\max(1, \lvert x_j\rvert)$, `'3-point'`가 $\varepsilon^{1/3}\cdot\max(1, \lvert x_j\rvert)$예요. 함수값에 잡음이 있어 기본 간격이 너무 작을 때 키워요. 호출 가능한 `jac`과 함께 주면 쓸 곳이 없어서 `ValueError`예요.

```python
>>> sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], diff_step=1e-6).nfev
41
>>> sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], jac=jac, diff_step=1e-6)
Traceback (most recent call last):
    ...
ValueError: least_squares(): 'diff_step' is only used when 'jac' is '2-point' or '3-point'
```

## 경계: bounds

변수에 물리적인 범위가 있으면 `bounds=(lower, upper)`로 줘요. 각각 수 하나(모든 변수에 같은 값)이거나 n개이고, `sd.inf`·`-sd.inf`는 그쪽에 경계가 없다는 뜻이에요. 감쇠 모형의 바닥값 c를 0.3 이하로 묶어 볼게요.

```python
>>> inf = sd.inf
>>> rb = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], bounds=([-inf, -inf, -inf], [inf, inf, 0.3]))
>>> rb
OptimizeResult(method='trf', converged=True, cost=0.191281, n_iter=9, nfev=36, x=[ 5.122035013537235 0.3496573956445815 0.2999999999999907])
>>> rb.active_mask
array([0, 0, 1], dtype=int64)
```

경계가 없을 때의 c는 0.524라서, 경계가 있으면 c가 위 경계 0.3에 붙고 a, k도 그에 맞춰 달라져요. `active_mask`는 변수마다 경계에 걸렸는지를 알려 줘요(−1 아래 경계, 0 안쪽, 1 위 경계). `'trf'`의 반복점은 늘 경계 안쪽이라 c도 0.3에 아주 가까운 안쪽 값(0.29999999999999)이에요. `active_mask`는 경계에서 `xtol`·max(1, |경계|) 안에 있으면 걸린 것으로 쳐요.

- `x0`은 경계 안에 있어야 해요(밖이면 `ValueError`). 경계 위에 있거나 $10^{-10}\cdot\max(1, \lvert\text{경계}\rvert)$ 안이면 그만큼 안쪽으로 옮겨서 시작해요.
- 경계에서 차분 간격이 경계를 넘으면 반대쪽(`'2-point'`)이나 한쪽 꼴(`'3-point'`)로 바꿔요. 그래서 `fun`은 경계 밖의 x를 받지 않아요.
- lower < upper여야 해요. 같은 값으로 변수를 고정하는 것은 안 돼요(그 변수를 상수로 빼서 풀어요).
- `method='lm'`은 무한한 경계(`(-inf, inf)`)만 받아요.
- 변수마다의 쌍 `[(l1, u1), (l2, u2), ...]`는 받지 않아요. 쌍이 셋 이상이면 `'bounds' must be a pair (lower, upper), not a sequence of (low, high) pairs`라는 `ValueError`이고, 쌍이 둘이면 `(lower, upper)`로 읽어요. 변수마다 범위를 줄 때는 `([l1, l2, l3], [u1, u2, u3])`로 써요.

```python
>>> sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], method='lm', bounds=(0, 10))
Traceback (most recent call last):
    ...
ValueError: least_squares(): method='lm' takes no 'bounds' (method='trf' does)
```

## 허용오차와 멈춤

반복은 걸음을 하나 받을 때마다 세 판정을 봐요. 하나라도 통과하면 멈춰요.

| 판정 | 뜻(대략) | 멈춘 `status` |
|---|---|---|
| `ftol` | 걸음 하나로 제곱합이 `ftol`의 비율보다 적게 줄었어요 | 2 |
| `xtol` | 걸음이 x의 크기에 비해 `xtol`의 비율보다 작아요 | 3 |
| `gtol` | 기울기 $J^{\mathsf T}f$(척도를 맞춘 것)가 `gtol`보다 작아요 | 1 |

`ftol`과 `xtol`이 함께 통과하면 4예요. 정확한 식은 방법마다 조금 달라요([구현](/internals/optimize/least-squares/)). 기본값 $10^{-8}$에서 멈춘 점은 해와 상대 $10^{-8}$ 남짓 떨어져 있을 수 있어요. 허용오차는 "언제 그만할지"이지 "답이 몇 자리 맞는지"가 아니라는 점을 기억해요. 더 작게 주면 반복이 조금 더 가요. 셋 다 0으로 끄면 끝나지 않을 수 있어서, 셋 가운데 하나는 $2.2\times10^{-16}$ 이상이어야 해요. `'lm'`은 셋 모두 그 이상이어야 해요. 그보다 작으면 MINPACK이 "허용오차가 너무 작다"로 멈추기 때문이에요.

```python
>>> sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], method='lm', gtol=0.0)
Traceback (most recent call last):
    ...
ValueError: least_squares(): 'ftol', 'xtol' and 'gtol' must each be >= 2.2e-16 (the machine epsilon) when method='lm'
```

`max_nfev`는 `fun`을 부르는 수의 상한이에요. 차분의 호출도 세요. 기본값은 반복 100n번쯤에 닿도록 정해져 있어요. 닿으면 그때의 점을 돌려주고 `status`가 0, `converged`가 False예요. 예외는 나지 않아요.

```python
>>> rc = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], max_nfev=10)
>>> rc.converged, rc.status, rc.nfev
(False, 0, 13)
>>> rc.message
'The maximum number of function evaluations is exceeded.'
```

상한은 걸음 사이에서 봐요. 받은 걸음 뒤에 그 점의 야코비안을 구하는 호출은 상한을 넘겨도 하기 때문에(차분이면 kn번까지, k는 `'2-point'` 1, `'3-point'` 2) `nfev`가 10보다 커요.

## 결과 읽기

| 필드 | 뜻 |
|---|---|
| `x` | 찾은 해 (n,) |
| `cost` | x에서의 ½‖f‖² (`float`) |
| `fun` | x에서의 잔차 (m,) |
| `jac` | x에서의 야코비안 (m, n). 차분이면 차분의 값이에요 |
| `grad` | 제곱합의 기울기 $J^{\mathsf T}f$ (n,) |
| `optimality` | 1차 최적성의 척도. `'lm'`은 ‖grad‖∞, `'trf'`는 경계까지의 거리를 곱한 기울기의 ‖·‖∞ |
| `active_mask` | 변수마다 경계에 걸렸는지 (n,) int64. −1, 0, 1 |
| `converged` | 멈춤 판정을 통과했고 `cost`가 유한한지 |
| `status`, `message` | 멈춘 이유(아래 표) |
| `n_iter` | 반복이 계산한 야코비안 수 |
| `nfev` | `fun`을 부른 수 전부(x0, 시험점, 차분 포함) |
| `njev` | 야코비안을 계산한 수(`jac` 호출이나 차분 야코비안) |
| `method` | `'trf'` 또는 `'lm'` |

| `status` | `message` |
|---:|---|
| 0 | `The maximum number of function evaluations is exceeded.` |
| 1 | `` `gtol` termination condition is satisfied.`` |
| 2 | `` `ftol` termination condition is satisfied.`` |
| 3 | `` `xtol` termination condition is satisfied.`` |
| 4 | ``Both `ftol` and `xtol` termination conditions are satisfied.`` |

`converged`는 `status > 0`이고 `cost`가 유한할 때 True예요. 판정을 통과했는데 제곱합이 넘쳐 inf인 경우(척도가 극단적인 문제)는 수렴으로 보지 않아요. 모든 필드는 읽기 전용이고, 배열 필드도 읽기 전용 배열이에요(고치려면 `.copy()`). `cost`, `grad`, `optimality`는 `fun`과 `jac`으로 다시 계산한 값이라, 같은 `fun`을 직접 제곱해 더한 값과 끝자리가 다를 수 있어요. 공통 규칙은 [결과 객체](/api/optimize/results/)에 있어요.

```python
>>> [f'{v:.1e}' for v in r.grad.tolist()]
['-1.6e-09', '-4.0e-06', '4.7e-10']
>>> f'{r.optimality:.1e}', r.active_mask
('4.0e-06', array([0, 0, 0], dtype=int64))
```

### 셈: nfev, njev, n_iter

첫 예의 `nfev=41`은 x0에서 1번, 시험점 10번, 차분 야코비안 10개 × 3번이에요. `'trf'`는 반복이 계산한 야코비안이 x의 야코비안이라 `njev`와 `n_iter`가 같아요. `'lm'`은 마지막 야코비안이 다른 점의 것이면 결과의 `jac`을 위해 x에서 한 번 더 계산하고 그것도 세요. 그래서 `njev`가 `n_iter`보다 하나 많을 수 있어요.

```python
>>> rl = sd.optimize.least_squares(resid, [1.0, 1.0, 0.0], method='lm')
>>> rl.n_iter, rl.njev, rl.nfev
(9, 10, 41)
```

## 특수한 경우

### 시작점에서 값이 유한하지 않을 때

`x0`에서 `fun`이 NaN이나 inf를 돌려주면 시작할 수 없어서 `ValueError`예요.

```python
>>> sd.optimize.least_squares(lambda x: sd.log(x), [-1.0, 2.0])
Traceback (most recent call last):
    ...
ValueError: least_squares(): 'fun' is not finite at 'x0'
```

### 시험점에서 값이 유한하지 않을 때

반복 중의 시험점에서 유한하지 않은 값이 나오면 그 걸음을 받지 않고 신뢰 영역을 줄여 다시 시도해요. 에러가 아니에요. log(x) = 0을 x0 = 3에서 풀면 첫 걸음이 x = 0까지 가서 log(0) = −inf가 나오지만, 반지름을 줄여 다시 가요.

```python
>>> calls = []
>>> def logres(x):
...     calls.append(float(x[0]))
...     return sd.log(x)
>>> rg = sd.optimize.least_squares(logres, [3.0], jac=lambda x: [[1 / float(x[0])]])
>>> rg.converged, rg.x
(True, array([0.9999999999999846], dtype=float64))
>>> [round(c, 4) for c in calls[:4]]
[3.0, 0.0, 2.25, 0.75]
```

`'trf'`에서 잔차가 유한해도 아주 크면(대략 $\lvert f\rvert \gtrsim 10^{154}$) 제곱합이나 기울기가 넘쳐 inf가 돼요. 그러면 더 나아갈 수 없으니 그 자리에서 `status` 0으로 멈추고, `cost`가 inf라 `converged`는 False예요. 이런 문제는 잔차의 척도를 줄여서 풀어요.

```python
>>> ro = sd.optimize.least_squares(lambda x: [1e160 * (x[0] - 1), x[1]], [0.0, 1.0])
>>> ro.converged, ro.status, ro.cost
(False, 0, inf)
```

반복 중에 **야코비안**이 유한하지 않으면 그 점을 적은 `ValueError`예요(`'jac' is not finite at x = [...]`, 차분이면 `the differences of 'fun' are not finite at x = [...]`). 야코비안 없이는 걸음을 정할 수 없기 때문이에요.

### 지역 최솟값과 시작점

제곱합에 골짜기가 여럿이면 시작점 근처의 골짜기 바닥에서 멈춰요. 그래도 그 점에서는 판정을 통과했으니 `converged`는 True예요. 사인파 $\sin(\omega t)$의 진동수 $\omega$를 데이터에서 맞추는 문제가 대표적이에요. 참값은 1.3이에요.

```python
>>> tt = sd.linspace(0, 10, 50)

...     rw = sd.optimize.least_squares(lambda w: sd.sin(w[0] * tt) - ys, [w0])
...     print(w0, rw.converged, round(float(rw.x[0]), 4), round(rw.cost, 3))
0.5 True 0.4258 20.284
1.0 True 1.3 0.0
2.0 True 2.0794 21.753
```

## nls와의 관계

[sd.regression.nls](/api/regression/nls/)는 곡선 맞추기 전용 함수예요. 반복은 `least_squares`와 같은 커널이고, 그 위에 통계가 붙어요.

| | `least_squares` | `nls` |
|---|---|---|
| 받는 것 | 잔차 함수 `fun(x)` | 모형 `f(x, *theta)`와 데이터 x, y |
| 결과 | 해와 반복 정보 | 모수, 표준오차, 신뢰구간, p값, 예측 구간, `summary()` |
| 정확도 | 멈춤 판정만큼(대략 $10^{-8}$) | 반복이 멈춘 뒤 정확한 야코비안으로 다듬어 반올림 수준 |
| 그 밖 | `'3-point'`, `diff_step`, m < n | 가중치, NaN 처리, `method=None`의 자동 선택 |

같은 데이터를 `nls`로 맞추면 반복이 멈춘 뒤의 다듬기 때문에 `least_squares`의 답과 $10^{-8}$ 남짓 달라요. 다듬은 쪽이 참 최소점에 더 가까워요.

```python
>>> fit = sd.regression.nls(lambda t, a, k, c: a * sd.exp(-k * t) + c, t, y, p0=[1.0, 1.0, 0.0])
>>> fit.params
array([ 5.030580751301966, 0.4048767917071542, 0.5239091983451125], dtype=float64)
>>> [f'{v:.1e}' for v in (r.x - fit.params).tolist()]
['-5.5e-08', '-9.5e-08', '-2.4e-07']
```

모수의 불확실성이나 예측이 필요하면 `nls`를, 잔차가 "모형 − 데이터" 꼴이 아니거나 반복 자체만 필요하면 `least_squares`를 써요. 두 함수가 커널을 어떻게 나눠 쓰는지는 [nls의 구현](/internals/regression/nls/)과 [최소제곱의 구현](/internals/optimize/least-squares/)에 있어요.

## 다른 함수와 비교

- [minimize](/api/optimize/minimize/): $\sum f_i^2$를 실수 하나로 돌려주는 함수를 줘도 최소화할 수 있어요. 하지만 `least_squares`는 잔차 하나하나와 야코비안을 알아서 가우스–뉴턴 걸음을 쓸 수 있고, 해 근처에서 훨씬 빨리 수렴해요. 목적함수가 제곱합이면 `least_squares`가 맞아요.
- [root](/api/optimize/root/): 식과 변수의 수가 같고(n개) 모든 식을 정확히 0으로 만드는 x를 찾을 때예요. `least_squares`는 잔차가 0이 될 수 없어도 되고, 잔차가 변수보다 많아도 돼요. 정방 문제에서 `root(method='lm')`은 `least_squares(method='lm')`과 같은 계산이에요.
- [lsq_linear](/api/optimize/lsq_linear/), [nnls](/api/optimize/nnls/): 잔차가 $Ax - b$로 일차일 때예요. 시작점도 반복 상한도 없이 정확하게 풀려요.

## 스레드와 GIL

`fun`과 `jac`은 Python 함수라, 반복은 GIL을 쥔 채 돌아요. 다른 Python 스레드에서 따로 푸는 문제들도 사용자 함수 부분은 번갈아 돌아요. 큰 야코비안의 분해 같은 큰 선형대수만 GIL을 놓고 여러 스레드로 나눠 해요. 사용자 함수 안의 sd 연산은 그 연산의 규칙대로 스레드를 써요. 같은 입력이면 스레드 수와 상관없이 결과가 비트까지 같아요.

## scipy를 아는 분께

- 이름과 꼴: `fun`, `x0`는 위치로만, 나머지는 키워드로만 받아요. `args`·`kwargs`는 없어요(클로저로 넘겨요). 결과는 `success` 대신 `converged`이고, `n_iter`와 `method`가 더 있어요. 결과는 dict처럼 쓸 수 없어요(`r['x']` 없음).
- 받지 않는 것: `method='dogbox'`, `jac='cs'`, `x_scale`, `loss`·`f_scale`, `tr_solver`·`tr_options`, `jac_sparsity`, `callback`, `workers`, `verbose`. `bounds`의 기본값은 `None`이에요(scipy는 `(-inf, inf)`). 방법 이름은 소문자만 받아요.
- 두 방법 모두 scipy 1.18.1과 같은 알고리즘과 멈춤 판정이에요. `'lm'`은 지금은 scipy와 같은 점에서 `fun`을 같은 순서로 불러 `x`, `fun`, `jac`, `status`가 비트까지 같아요(사용자 함수가 두 쪽에서 같은 값을 돌려줄 때; 약속은 아니에요). 다만 잔차가 변수보다 아주 많으면(m ≥ 10n이고 mn ≥ 2000) 더 빠른 계산 순서를 써서 끝자리가 다르고 반복 수가 가끔 하나 둘 달라요. `'trf'`는 같은 걸음을 하지만 첫 시험점부터 끝자리가 다를 수 있어요. 경계 없는 `'trf'`도 scipy의 경계 없는 판과 같은 걸음이에요. `cost`, `grad`, `optimality`는 `x`가 같아도 끝자리가 다를 수 있어요.
- **`nfev`가 차분의 호출을 세요.** scipy의 `least_squares`는 세지 않아서, 차분을 쓰면 scipy의 `nfev`는 이쪽의 `nfev − (2점 n, 3점 2n)·njev`예요. `max_nfev`도 차분의 호출을 센 상한이고, 기본값을 그만큼 키워서 상한에 닿는 반복 수가 scipy와 같아요. scipy는 `'lm'`에 차분을 쓰면 `njev`가 None인데, 여기서는 늘 수예요.

```python
>>> import math
>>> import numpy as np
>>> from scipy.optimize import least_squares as scipy_ls
>>> tl, yl = t.tolist(), y.tolist()
>>> def resid_py(p):
...     return [p[0] * math.exp(-p[1] * a) + p[2] - b for a, b in zip(tl, yl)]
>>> mine = sd.optimize.least_squares(resid_py, [1.0, 1.0, 0.0], method='lm')
>>> theirs = scipy_ls(resid_py, [1.0, 1.0, 0.0], method='lm')
>>> mine.x.tolist() == theirs.x.tolist(), mine.nfev, theirs.nfev, theirs.njev
(True, 41, 11, None)
```

- 시험점의 잔차가 유한하지 않으면 `'lm'`도 그 걸음을 거절하고 반지름을 줄여요(scipy의 `'lm'`은 NaN으로 계속 가요). 반복 중의 야코비안이 유한하지 않으면 `ValueError`예요(scipy는 계속 가요). `'trf'`에서 제곱합이 넘치면 바로 `status` 0으로 멈춰요(scipy는 진전 없이 `max_nfev`까지 같은 점에서 돌아요).
- 호출 가능한 `jac`과 `diff_step`을 함께 주면 `ValueError`예요(scipy는 `diff_step`을 버려요).
- 곡선 맞추기의 `curve_fit`은 없어요. [sd.regression.nls](/api/regression/nls/)가 추론까지 해요. `leastsq`도 없어요. `least_squares(method='lm')`이 같은 MINPACK 방법이에요.
