## 한눈에 보기

`rng.random()`은 **0 이상 1 미만의 실수**를 하나 뽑아요. 여기서 `rng`는 [`sd.random.default_rng(시드)`](/api/random/default_rng/)로 만든 생성기([Generator](/api/random/generator/))예요. stardust의 난수는 모두 이런 생성기의 메서드로 받아요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(42)
>>> rng.random()
0.4513007976393718
```

괄호 안에 모양(shape)을 주면 그 모양의 배열로 한꺼번에 받아요. 숫자 하나면 1차원, tuple이면 그 모양 그대로예요.

```python
>>> rng.random(3)
array([0.5280337747949365,  0.794826025358168, 0.7675771890620597], dtype=float64)
>>> rng.random((2, 3))
array([[0.08607763073528474, 0.14155732377913233, 0.27009303504774695],
       [ 0.8740378646728407, 0.17016452673096505,  0.5068124238377856]], dtype=float64)
```

"고르게 뽑는다"는 것은 0과 1 사이의 **어느 곳이든 길이가 같은 구간이면 값이 들어갈 확률이 같다**는 뜻이에요. 0.1에서 0.2 사이에 들어갈 확률도, 0.8에서 0.9 사이에 들어갈 확률도 똑같이 10%예요. 이런 뽑기를 **균등분포**(uniform distribution)를 따른다고 해요. 특정한 값 근처에 몰리지 않는, 가장 기본이 되는 난수예요.

이 값들은 진짜 우연이 아니라 정해진 규칙으로 계산한 **의사난수**(난수처럼 보이는 수)예요. 그래서 시드 `42`로 만든 생성기는 어느 컴퓨터에서 몇 번을 실행해도 위와 똑같은 값을 내요. 이 성질과 시드에 대한 자세한 이야기는 [난수의 기본](/api/random/basics/)에 있어요.

## 0은 나올 수 있고, 1은 나오지 않아요

결과의 범위는 수학 기호로 `[0, 1)`이에요. 대괄호 `[`는 "0을 포함", 소괄호 `)`는 "1은 포함하지 않음"이라는 뜻이에요. 1은 **절대** 나오지 않아요.

```python
>>> x = sd.random.default_rng(42).random(100_000)
>>> bool(sd.all(x >= 0.0)), bool(sd.all(x < 1.0))
(True, True)
```

컴퓨터의 실수는 아무 값이나 담을 수 없어서, `random`이 낼 수 있는 값은 사실 정해져 있어요. **0부터 1 바로 앞까지 2⁻⁵³ 간격으로 늘어선 2⁵³개(약 9×10¹⁵개)의 값** 가운데 하나를 똑같은 확률로 골라요. 그래서 결과에 2⁵³을 곱하면 언제나 정수가 돼요.

```python
>>> y = x * 2**53
>>> bool(sd.all(y == sd.floor(y)))
True
```

가장 큰 값은 $1 - 2^{-53}$(0.9999999999999999)이고, 가장 작은 값은 정확히 `0.0`이에요. 0이 나올 확률은 2⁵³분의 1이라 실제로 보기는 어렵지만, 나올 수는 있어요. `sd.log(x)`처럼 0에서 문제가 되는 계산에 넣을 때는 이 점을 기억해 두세요.

### 고르게 퍼져 있는지 확인하기

10만 개를 뽑아서 0.1 간격의 열 구간에 각각 몇 개가 들어갔는지 세 보면, 모든 구간에 1만 개 안팎이 들어가요. `x * 10`을 정수로 바꾸면 그 값이 몇 번째 구간인지가 되고, [`sd.bincount`](/api/array/bincount/)가 구간마다 개수를 세 줘요.

```python
>>> sd.bincount(sd.astype(x * 10, sd.int64))
array([ 9956, 10181,  9951,  9948,  9899,  9999,  9940,  9931, 10083, 10112], dtype=int64)
```

정확히 1만 개씩이 아닌 것은 정상이에요. 동전을 100번 던져도 앞면이 정확히 50번 나오지는 않는 것과 같아요. 표본이 클수록 각 구간의 비율이 10%에 가까워져요. 평균도 0과 1의 가운데인 0.5에 가까워요.

```python
>>> round(float(sd.mean(x)), 2)
0.5
```

## `shape`: 숫자 하나 또는 배열

`shape`는 결과를 어떤 모양으로 받을지 정해요.

| `shape` | 결과 | 예 |
|:---:|---|---|
| `None` (기본값) | Python `float` 하나 | `rng.random()` |
| int `n` | 길이 `n`인 1차원 배열 | `rng.random(5)` |
| int의 tuple | 그 모양의 배열 | `rng.random((2, 3))` |

결과 배열의 원소 종류(dtype)는 언제나 float64예요.

`shape=None`과 `shape=1`은 다르니 조심하세요. `None`이면 **배열이 아닌 Python 숫자**가 나오고, `1`이면 **원소가 하나인 배열**이 나와요.

```python
>>> type(sd.random.default_rng(42).random())
<class 'float'>
>>> sd.random.default_rng(42).random(1)
array([0.4513007976393718], dtype=float64)
```

값 자체는 같아요. 둘 다 생성기가 내는 첫 번째 값이에요. 반복문에서 값 하나씩 쓸 때는 `None`이 편하고, 다른 배열과 함께 계산할 때는 배열이 편해요.

길이가 0인 축도 쓸 수 있어요. 원소가 하나도 없는 배열이 나와요.

```python
>>> sd.random.default_rng(42).random((3, 0))
array([], shape=(3, 0), dtype=float64)
```

## 같은 시드면 같은 값, 나눠 뽑아도 같은 값

생성기는 미리 정해진 하나의 긴 수열을 앞에서부터 차례로 꺼내 준다고 생각하면 돼요. 부를 때마다 꺼낸 만큼 앞으로 나아가서, 다음에 부르면 그다음 값이 나와요.

그래서 **같은 시드로 만든 생성기**에서 다섯 개를 한 번에 뽑든, 두 개와 세 개로 나눠 뽑든 결과가 같아요.

```python
>>> a = sd.random.default_rng(42)
>>> a.random(5)
array([ 0.4513007976393718,  0.5280337747949365,   0.794826025358168,
        0.7675771890620597, 0.08607763073528474], dtype=float64)
>>> b = sd.random.default_rng(42)
>>> b.random(2)
array([0.4513007976393718, 0.5280337747949365], dtype=float64)
>>> b.random(3)
array([  0.794826025358168,  0.7675771890620597, 0.08607763073528474], dtype=float64)
```

## 다른 범위의 실수와 확률 사건

`random`은 `[0, 1)`만 내지만, 곱하고 더하면 원하는 범위로 옮길 수 있어요. `a`에서 `b` 사이의 실수가 필요하면 `a + (b - a) * u`예요. 예를 들어 -5 이상 5 미만이면 이렇게 해요.

```python
>>> u = sd.random.default_rng(42).random(2)
>>> -5.0 + 10.0 * u
array([-0.48699202360628213,  0.28033774794936495], dtype=float64)
```

**확률 `p`로 일어나는 일**을 흉내 낼 때도 `random`을 써요. `u < p`는 확률 `p`로 참이 돼요. 0.3 미만에 들어갈 구간의 길이가 0.3이기 때문이에요. 아래는 "30% 확률로 당첨"을 여덟 번 해 본 거예요.

```python
>>> sd.random.default_rng(42).random(8) < 0.3
array([False, False, False, False,  True,  True,  True, False], dtype=bool)
```

여러 번 해 보면 참의 비율이 0.3에 가까워져요. bool 배열의 평균은 참의 비율이에요.

```python
>>> round(float(sd.mean(sd.random.default_rng(42).random(100_000) < 0.3)), 2)
0.3
```

같은 원리로 넓이도 어림할 수 있어요. 한 변이 1인 정사각형 안에 점을 고르게 찍으면, 반지름 1인 사분원 안에 들어가는 비율은 넓이의 비 $\pi / 4$에 가까워져요. 그래서 비율에 4를 곱하면 원주율의 어림값이 돼요.

```python
>>> rng = sd.random.default_rng(7)
>>> px = rng.random(1_000_000)
>>> py = rng.random(1_000_000)
>>> round(4 * float(sd.mean(px * px + py * py < 1.0)), 2)
3.14
```

`px`와 `py`는 같은 생성기에서 차례로 뽑았으니 서로 다른 값이에요. 같은 생성기에서 두 번 부르면 수열의 다음 구간을 받기 때문이에요.

## 조심할 점

### 범위를 옮기면 끝값이 나올 수 있어요

`random` 자체는 1을 내지 않지만, `a + (b - a) * u`로 옮긴 결과는 **반올림 때문에 `b`와 같아질 수 있어요**. `random`이 낼 수 있는 가장 큰 값으로 계산해 보면 바로 보여요.

```python
>>> u_max = 1 - 2**-53
>>> 1.0 + (2.0 - 1.0) * u_max
2.0
```

`[1, 2)`를 원했는데 `2.0`이 나왔어요. `1.9999999999999999`는 실수로 정확히 나타낼 수 없어서 가장 가까운 `2.0`으로 반올림됐기 때문이에요. 이런 일은 아주 드물지만, `b`가 절대 나오면 안 되는 계산(배열의 인덱스로 쓰는 경우 등)이라면 결과를 따로 확인하세요. 정해진 개수 가운데 하나를 고르려는 것이라면 실수를 바꾸는 대신 처음부터 [`integers`](/api/random/integers/)를 쓰는 편이 정확해요.

### 시드 없이 만든 생성기는 실행할 때마다 달라요

`default_rng()`처럼 시드를 주지 않으면 운영체제가 주는 예측할 수 없는 값으로 시작해서, 실행할 때마다 다른 값이 나와요.

```python
>>> sd.random.default_rng().random() == sd.random.default_rng().random()
False
```

결과를 다시 만들어야 하는 실험이라면 시드를 꼭 정해 두세요.

### `shape`는 자리로만 넘겨요

`shape`는 이름을 붙여 넘길 수 없어요. 인자가 하나뿐이고 무엇인지 분명해서, `rng.random(3)`처럼 자리로 넘기게 돼 있어요.

```python
>>> rng.random(shape=3)
Traceback (most recent call last):
    ...
TypeError: Generator.random() got some positional-only arguments passed as keyword arguments: 'shape'
```

모양은 **tuple 하나**로 줘요. `rng.random(2, 3)`처럼 숫자를 따로따로 주면 에러예요. list도 받지 않아요.

```python
>>> rng.random(2, 3)
Traceback (most recent call last):
    ...
TypeError: Generator.random() takes from 1 to 2 positional arguments but 3 were given
>>> rng.random([2, 3])
Traceback (most recent call last):
    ...
TypeError: random(): 'shape' must be an int or a tuple of ints, not list
```

음수 길이는 `ValueError`예요.

```python
>>> rng.random(-1)
Traceback (most recent call last):
    ...
ValueError: random(): 'shape' must be non-negative
```

### 빈 tuple은 숫자 하나가 아니에요

stardust에는 차원이 0인 배열이 없어서 `shape=()`는 에러예요. 숫자 하나가 필요하면 `shape`를 비워 두세요(`None`).

```python
>>> rng.random(())
Traceback (most recent call last):
    ...
ValueError: 0-dimensional arrays are not supported (stardust has no 0-d arrays)
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 결과 |
|---|---|---|
| 0 이상 1 미만의 실수 | `rng.random` | float64 |
| 정해진 범위의 정수(주사위, 인덱스) | [`rng.integers`](/api/random/integers/) | int64 |
| 주어진 배열에서 원소 고르기, 확률을 달리해서 고르기 | [`rng.choice`](/api/random/choice/) | 배열의 원소 |
| 순서를 무작위로 섞기 | [`rng.permutation`](/api/random/permutation/) | 섞인 새 배열 |
| 정규분포처럼 다른 모양의 분포에서 뽑기 | `sd.stats`의 분포(`X.sample(shape, rng=rng)`) | 분포의 표본 |

정수가 필요할 때 `random`의 결과에 곱하고 내림해서 만드는 것보다 `integers`가 나아요. 범위의 정수가 모두 정확히 같은 확률로 나오고, 범위를 int64 전체까지 넓혀도 정확해요. 마찬가지로 배열의 원소를 고를 때는 인덱스를 직접 만들기보다 `choice`가 간단해요.

## numpy를 아는 분께

- 인자 이름이 `size`가 아니라 `shape`이고, 자리로만 넘겨요(`rng.random(size=3)`는 에러).
- `dtype=`과 `out=` 인자는 없어요. 결과는 언제나 float64예요.
- `shape=None`이면 numpy 스칼라가 아니라 Python `float`이에요.
- 실수로 바꾸는 방식(위 53비트에 2⁻⁵³을 곱함)은 numpy와 같지만, 생성기 종류가 달라서 **같은 시드여도 값은 numpy와 달라요**.
- `np.random.rand`, `np.random.random_sample` 같은 전역 함수는 없어요. 언제나 생성기를 만들어서 써요.
