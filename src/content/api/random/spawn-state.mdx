## 한눈에 보기

생성기([Generator](/api/random/generator/))는 시드가 정한 아주 긴 난수 수열 위의 한 위치라고 생각하면 쉬워요. 난수를 뽑을 때마다 그 자리에서 필요한 만큼 읽고 앞으로 나아가요. 시드가 같으면 수열도 같아서, 같은 순서로 뽑으면 언제나 같은 값이 나와요. 이 그림은 [난수의 기본](/api/random/basics/)에서 자세히 설명해요.

이 페이지는 그 생성기를 다루는 두 가지 도구를 설명해요.

- **`rng.spawn(n)`**: 생성기 하나에서 서로 다른 수열을 내는 새 생성기 `n`개를 만들어요. 일을 여러 갈래로 나눌 때 갈래마다 하나씩 줘요.
- **`rng.state`**: 생성기가 어느 수열의 어디쯤 있는지 담은 dict예요. 읽어 두었다가 대입하면 그 위치로 돌아가요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(42)
>>> kids = rng.spawn(3)
>>> [round(g.random(), 4) for g in kids]
[0.0371, 0.4283, 0.4093]
>>> rng.state
{'bit_generator': 'Philox4x64-10', 'entropy': 42, 'spawn_key': (), 'n_children_spawned': 3, 'position': 0}
```

`kids`의 세 생성기는 저마다 다른 수열을 읽어서 서로 다른 값을 내요. 그래도 부모의 시드(`42`)가 같으면 언제 다시 실행해도 똑같은 세 생성기가 만들어져요.

## `spawn`: 서로 독립된 생성기 만들기

### 독립이란

두 생성기가 **독립**이라는 것은 한쪽이 무엇을 내든 다른 쪽의 값을 짐작할 단서가 되지 않는다는 뜻이에요. 두 수열이 겹치지도 않고, 서로 닮은 꼴을 띠지도 않아요. 그래서 자식 생성기 여러 개로 각자 시뮬레이션을 돌리면, 서로 다른 시드로 따로 돌린 것처럼 믿고 결과를 합칠 수 있어요.

### 같은 부모, 같은 자식

부모의 시드가 같으면 자식도 언제나 같아요. 자식까지 포함해서 프로그램 전체가 시드 하나로 재현돼요.

```python
>>> a = sd.random.default_rng(42).spawn(2)
>>> b = sd.random.default_rng(42).spawn(2)
>>> a[0].random() == b[0].random(), a[1].random() == b[1].random()
(True, True)
```

### 다시 부르면 번호가 이어져요

`spawn`을 다시 부르면 앞에서 만든 것과 다른 새 자식이 나와요. 부모는 지금까지 자식을 몇 개 만들었는지 기억하고(`n_children_spawned`), 그다음 번호부터 만들어요. 그래서 실수로 같은 자식을 두 번 만들 일이 없어요.

```python
>>> rng = sd.random.default_rng(42)
>>> first = rng.spawn(2)
>>> second = rng.spawn(2)
>>> [g.state['spawn_key'] for g in first + second]
[(0,), (1,), (2,), (3,)]
>>> rng.state['n_children_spawned']
4
```

`spawn_key`는 그 생성기가 몇 번째 자식인지 적은 tuple이에요. 시드가 같아도 `spawn_key`가 다르면 다른 수열이에요. 거꾸로 말하면, 자식을 같은 순서로 만들어야 같은 자식을 얻어요. 재현이 필요한 코드에서는 `spawn`을 부르는 순서를 바꾸지 마세요.

자식도 생성기라서 또 `spawn`할 수 있어요. 손자의 `spawn_key`는 길이가 2예요.

```python
>>> first[0].spawn(2)[1].state['spawn_key']
(0, 1)
```

### 부모가 얼마나 뽑았는지와는 상관없어요

자식은 부모의 시드와 자식 번호로만 정해져요. 부모가 그 전에 난수를 얼마나 뽑았는지는 상관이 없어요. 반대로 `spawn`은 부모의 수열을 쓰지 않아서, 부모가 다음에 낼 값도 바뀌지 않아요.

```python
>>> p1 = sd.random.default_rng(42)
>>> p2 = sd.random.default_rng(42)
>>> _ = p2.random(1000)
>>> p1.spawn(1)[0].random() == p2.spawn(1)[0].random()
True
>>> p1.state['position']
0
```

### 쓰임: 용도마다 따로, 갈래마다 따로

`spawn`이 특히 쓸모 있는 때는 한쪽에서 뽑는 개수가 바뀌어도 다른 쪽의 값이 흔들리면 안 될 때예요. 생성기 하나로 잡음 만들기와 표본 고르기를 함께 하면, 잡음을 더 뽑기로 코드를 고친 순간 그 뒤에 고르는 표본까지 모두 달라져요. 용도마다 자식을 하나씩 주면 서로 영향이 없어요.

```python
>>> pick_rng, noise_rng = sd.random.default_rng(42).spawn(2)
>>> noise = noise_rng.random(5)
>>> pick_rng.choice(100, shape=4, replace=False)
array([ 3, 18, 29, 38], dtype=int64)
>>> pick_rng, noise_rng = sd.random.default_rng(42).spawn(2)
>>> noise = noise_rng.random(500)
>>> pick_rng.choice(100, shape=4, replace=False)
array([ 3, 18, 29, 38], dtype=int64)
```

잡음을 5개 뽑든 500개 뽑든 고른 표본은 같아요. 같은 이유로, 시뮬레이션을 여러 번 반복할 때 반복마다 자식 하나씩을 주면 어느 한 번의 반복이 난수를 더 쓰더라도 다른 반복의 결과는 그대로예요.

### 시드도 생성기도 받는 함수 만들기

[default_rng](/api/random/default_rng/)에 생성기를 넘기면 새로 만들지 않고 그 생성기를 그대로 돌려줘요. 이 성질을 이용하면 시드(정수)를 받든 생성기를 받든 똑같이 동작하는 함수를 쉽게 만들 수 있어요.

```python
>>> rng = sd.random.default_rng(42)
>>> sd.random.default_rng(rng) is rng
True
>>> def noisy(values, seed=None):
...     rng = sd.random.default_rng(seed)
...     return values + rng.random(values.shape)
>>> v = sd.asarray([10.0, 20.0])
>>> noisy(v, seed=7)
array([10.604379713042428, 20.348380586007366], dtype=float64)
>>> noisy(v, seed=sd.random.default_rng(7))
array([10.604379713042428, 20.348380586007366], dtype=float64)
```

정수를 넘기면 함수 안에서 새 생성기를 만들고, 생성기를 넘기면 그 생성기를 이어서 써요. `spawn`한 자식을 넘기면 함수마다 독립된 난수를 쓰게 할 수 있어요.

## 독립된 수열이 필요할 때 무엇을 쓸까

생성기를 "하나 더" 만드는 방법은 셋이에요. 결과가 크게 달라요.

### 복사본은 같은 난수를 다시 내요

`copy.copy`(또는 `copy.deepcopy`)는 지금 상태를 그대로 옮긴 생성기를 만들어요. 같은 수열의 같은 위치에 서 있으니, 원본과 복사본은 앞으로 똑같은 값을 내요.

```python
>>> import copy
>>> rng = sd.random.default_rng(42)
>>> twin = copy.copy(rng)
>>> rng.random(3)
array([0.4513007976393718, 0.5280337747949365,  0.794826025358168], dtype=float64)
>>> twin.random(3)
array([0.4513007976393718, 0.5280337747949365,  0.794826025358168], dtype=float64)
```

<Callout type="warn" title="복사해서 나눠 주면 모두 같은 난수를 써요">
  일을 여러 갈래로 나누면서 갈래마다 `copy.copy(rng)`를 주면 모든 갈래가 같은 난수를 써요. 시뮬레이션을 열 번 돌렸는데 실제로는 같은 실험을 열 번 반복한 셈이 돼요. 에러도 나지 않아서 알아차리기 어려워요. 독립된 생성기가 필요하면 `spawn`을 쓰세요.
</Callout>

복사는 "지금 이 위치로 나중에 돌아오고 싶다"처럼 같은 값을 다시 얻고 싶을 때 써요.

### 시드를 바꾼 새 생성기

`default_rng(43)`처럼 시드를 하나씩 바꿔 새 생성기를 만들 수도 있어요. 비슷한 시드라도 서로 무관한 수열이 나오기 때문에 이 방법도 잘 동작해요. 다만 어떤 시드를 이미 썼는지 직접 관리해야 해요.

시드를 손으로 짜 맞추다 보면 뜻밖의 겹침도 생겨요. 예를 들어 갈래마다 `default_rng([42, i])`를 주면, `i = 0`인 갈래는 `default_rng(42)`와 같은 수열이에요. 정수 몇 개로 된 짧은 시드는 끝에 0을 붙여도 같은 시드로 치기 때문이에요.

```python
>>> sd.random.default_rng([42, 0]).random() == sd.random.default_rng(42).random()
True
```

`spawn`의 자식은 이런 걱정이 없어요. 부모와도, 서로와도 수열이 다르게 정해져요.

```python
>>> sd.random.default_rng(42).spawn(1)[0].random() == sd.random.default_rng(42).random()
False
```

### 방법별 비교

| 방법 | 앞으로 내는 값 | 언제 쓰나요 |
|---|---|---|
| `rng.spawn(n)` | 부모와도, 서로와도 독립 | 일을 여러 갈래(스레드, 반복, 용도)로 나눌 때 |
| `copy.copy(rng)`, `copy.deepcopy(rng)` | 원본과 **똑같은** 값 | 지금 위치를 저장해 두고 같은 값을 다시 얻을 때 |
| `default_rng(다른 시드)` | 서로 무관 | 실험마다 시드를 따로 적어 두고 싶을 때. 시드 관리는 직접 해요. |
| `default_rng(rng)` | 원본과 **같은 객체** | 시드와 생성기를 둘 다 받는 함수 안에서 |

## `state`: 생성기의 지금 상태

### 무엇이 들어 있나요

`rng.state`를 읽으면 생성기의 상태를 담은 dict가 나와요. 이 다섯 가지만 알면 생성기를 똑같이 다시 만들 수 있어요.

```python
>>> rng = sd.random.default_rng(42)
>>> _ = rng.random(10)
>>> rng.state
{'bit_generator': 'Philox4x64-10', 'entropy': 42, 'spawn_key': (), 'n_children_spawned': 0, 'position': 10}
```

| 키 | 뜻 |
|---|---|
| `bit_generator` | 생성기 종류의 이름이에요. 언제나 `'Philox4x64-10'`이에요. |
| `entropy` | 처음에 준 시드예요. 시드 없이 만들었다면 그때 운영체제에서 받은 큰 정수예요. |
| `spawn_key` | 몇 번째 자식인지 적은 tuple이에요. `spawn`으로 만든 생성기가 아니면 `()`예요. |
| `n_children_spawned` | 지금까지 `spawn`으로 만든 자식 수예요. 다음 `spawn`은 이 번호부터 시작해요. |
| `position` | 수열 위의 지금 위치, 곧 지금까지 쓴 자리 수예요. 다음 난수는 이 위치부터 읽어요. |

위에서 `random(10)`으로 실수 10개를 뽑았더니 `position`이 `10`이 됐어요. `random`은 값 하나에 한 자리를 써요. 다른 메서드는 값 하나에 쓰는 자리 수가 다를 수 있으니, 위치를 손으로 계산하지 말고 `state`를 읽으세요.

### 저장해 두었다가 되돌리기

`state`를 읽어 두었다가 다시 대입하면 생성기가 그때의 위치로 돌아가요. 그 뒤로는 그때와 똑같은 값이 나와요.

```python
>>> saved = rng.state
>>> before = rng.random(3)
>>> rng.state = saved
>>> after = rng.random(3)
>>> sd.all(before == after)
True
```

다른 생성기에 대입해도 돼요. 대입받은 생성기는 시드와 위치가 모두 바뀌어서, 원래 생성기와 똑같은 값을 내요.

```python
>>> other = sd.random.default_rng(0)
>>> other.state = saved
>>> sd.all(other.random(3) == after)
True
```

`state`는 문자열, 정수, tuple만 담고 있어서 JSON 파일로 저장할 수도 있어요. JSON을 거치면 tuple이 리스트로 바뀌지만, 대입할 때 리스트도 받아요. 긴 계산을 중간에 멈췄다가 이어서 할 때 쓸모가 있어요.

```python
>>> import json
>>> text = json.dumps(rng.state)
>>> text
'{"bit_generator": "Philox4x64-10", "entropy": 42, "spawn_key": [], "n_children_spawned": 0, "position": 13}'
>>> restored = sd.random.default_rng(0)
>>> restored.state = json.loads(text)
>>> restored.random() == rng.random()
True
```

### 읽은 dict를 고쳐도 생성기는 그대로예요

`rng.state`는 읽을 때마다 새 dict를 만들어 줘요. 그 dict의 값을 바꿔도 생성기에는 아무 일도 일어나지 않아요. 바꾼 것을 적용하려면 다시 대입해야 해요.

```python
>>> st = rng.state
>>> st['position'] = 0
>>> rng.state['position']
14
>>> rng.state = st
>>> rng.state['position']
0
```

`position`을 바꾸면 수열의 그 위치로 곧장 건너뛸 수 있어요. `random`은 값 하나에 한 자리를 쓰므로, `position`을 4로 두면 처음부터 뽑았을 때의 다섯 번째 값부터 나와요.

```python
>>> sd.random.default_rng(9).random(6)
array([ 0.8902982883170586,  0.2559695842427645,  0.2356051353023948,
        0.5986809857825196, 0.37716812949962164, 0.03405089490109803], dtype=float64)
>>> jump = sd.random.default_rng(9)
>>> st = jump.state
>>> st['position'] = 4
>>> jump.state = st
>>> jump.random(2)
array([0.37716812949962164, 0.03405089490109803], dtype=float64)
```

### 잘못된 상태를 대입하면

대입하는 값은 다섯 키가 모두 든 dict여야 해요. dict가 아니면 `TypeError`, 키가 빠졌거나 값이 맞지 않으면 `ValueError`예요. 잘못된 대입은 생성기를 바꾸지 않아요.

```python
>>> rng.state = 42
Traceback (most recent call last):
    ...
TypeError: .state: must be a dict, not int
>>> rng.state = {'position': 0}
Traceback (most recent call last):
    ...
ValueError: .state: missing key 'bit_generator'
>>> bad = rng.state
>>> bad['position'] = -1
>>> rng.state = bad
Traceback (most recent call last):
    ...
ValueError: .state: 'position' must be an int in [0, 2**64)
```

`bit_generator`가 `'Philox4x64-10'`이 아니어도 `ValueError`예요. 다른 라이브러리의 생성기 상태는 넣을 수 없어요.

## 복사와 피클

`copy.copy`, `copy.deepcopy`, `pickle`은 모두 상태가 같은 독립된 생성기를 만들어요. 만들어진 순간에는 원본과 같은 위치에 있어서 같은 값을 내지만, 그 뒤로는 따로 움직여요. 한쪽에서 뽑아도 다른 쪽의 위치는 그대로예요.

```python
>>> import pickle
>>> rng = sd.random.default_rng(42)
>>> clone = pickle.loads(pickle.dumps(rng))
>>> clone is rng
False
>>> _ = rng.random(100)
>>> clone.state['position'], rng.state['position']
(0, 100)
```

`pickle`은 생성기를 파일에 저장하거나 다른 프로세스로 보낼 때 쓰여요. `multiprocessing`으로 일을 나눌 때 생성기가 인자로 넘어가면 이 방식으로 복사돼요.

<Callout type="warn" title="같은 생성기를 여러 프로세스에 보내면">
  프로세스마다 같은 상태의 복사본이 도착해서 모든 프로세스가 같은 난수를 써요. 앞의 `copy.copy` 함정과 같아요. 프로세스마다 `rng.spawn(n)`의 자식을 하나씩 보내세요.
</Callout>

## 여러 스레드에서 쓰기

### 한 생성기를 함께 쓰면: 안전하지만 순서는 그때그때

여러 스레드가 한 생성기를 동시에 불러도 깨지지 않아요. 호출마다 수열에서 자기 몫의 구간을 통째로 예약하기 때문에, 같은 난수를 두 스레드가 함께 쓰는 일도 없고 건너뛰는 자리도 없어요.

하지만 어느 스레드가 어느 구간을 받는지는 실행 순서가 정해요. 스레드는 운영체제가 그때그때 순서를 정해 돌리기 때문에, 같은 시드라도 실행할 때마다 스레드별 결과가 달라질 수 있어요.

아래에서는 네 스레드가 생성기 하나에서 1000개씩 뽑아요. 모두 합치면 앞의 4000자리를 빠짐없이 한 번씩 썼지만, 어느 스레드가 어느 1000개를 받았는지는 정해져 있지 않아요.

```python
>>> from concurrent.futures import ThreadPoolExecutor
>>> shared = sd.random.default_rng(7)
>>> with ThreadPoolExecutor(max_workers=4) as pool:
...     parts = list(pool.map(lambda _: shared.random(1000), range(4)))
>>> shared.state['position']
4000
>>> together = sd.concat(parts)
>>> sd.all(sd.sort(together) == sd.sort(sd.random.default_rng(7).random(4000)))
True
```

값의 모음은 언제나 같아서 정렬하면 일치하지만, `parts`의 순서는 실행마다 바뀔 수 있어요. 결과가 어느 스레드가 무엇을 받았는지에 좌우된다면, 이 방식으로는 재현할 수 없어요.

### 스레드마다 `spawn`한 생성기를: 언제나 같은 결과

재현이 필요하면 스레드마다 자기 생성기를 주세요. 각 스레드는 자기 수열만 읽으니, 어느 스레드가 먼저 돌든 결과가 같아요.

```python
>>> def work(g):
...     return round(float(sd.mean(g.random(100_000))), 4)
>>> rng = sd.random.default_rng(42)
>>> with ThreadPoolExecutor(max_workers=4) as pool:
...     results = list(pool.map(work, rng.spawn(4)))
>>> results
[0.4999, 0.5006, 0.4994, 0.4997]
```

같은 일을 스레드 없이 차례로 해도 똑같은 결과예요. 스레드 수나 실행 순서가 결과를 바꾸지 않아요.

```python
>>> [work(g) for g in sd.random.default_rng(42).spawn(4)]
[0.4999, 0.5006, 0.4994, 0.4997]
```

## 조심할 점

### `spawn`의 인자

`n`은 0 이상의 정수여야 해요. 음수는 `ValueError`, 실수나 bool은 `TypeError`예요. `n`은 이름 없이 써요.

```python
>>> rng = sd.random.default_rng(42)
>>> rng.spawn(-1)
Traceback (most recent call last):
    ...
ValueError: spawn(): 'n' must be non-negative
>>> rng.spawn(2.0)
Traceback (most recent call last):
    ...
TypeError: spawn(): 'n' must be an int, not float
>>> rng.spawn(0)
[]
```

`spawn(1)`도 생성기 하나가 아니라 원소 하나짜리 리스트를 돌려줘요. 생성기만 꺼내려면 `rng.spawn(1)[0]`이나 `child, = rng.spawn(1)`처럼 써요.

```python
>>> rng.spawn(1)
[Generator(Philox4x64-10)]
>>> child, = rng.spawn(1)
>>> child
Generator(Philox4x64-10)
```

### 자식의 상태를 부모에 대입하지 마세요

`state`에는 `spawn_key`까지 들어 있어서, 자식의 상태를 다른 생성기에 대입하면 그 생성기는 자식과 같은 수열을 내요. 앞의 복사 함정과 같은 일이 생기니, 상태를 대입하는 것은 "같은 값을 다시 얻고 싶을 때"만 하세요.

### `spawn`은 순서에 의존해요

자식 번호는 부른 순서대로 매겨져요. 같은 시드라도 `spawn`을 부르는 순서나 횟수가 달라지면 각 변수에 들어가는 자식이 달라져요. 재현이 필요한 코드에서는 필요한 자식을 처음에 한 번에 만들어 두고 나눠 주는 편이 안전해요.

## 비슷한 기능과의 차이

| 하고 싶은 일 | 쓸 것 |
|---|---|
| 갈래마다 독립된 난수 | `rng.spawn(n)` |
| 지금 위치를 저장했다가 되돌리기 | `saved = rng.state` → `rng.state = saved` |
| 같은 위치에 선 두 번째 생성기 | `copy.copy(rng)`, `copy.deepcopy(rng)` |
| 생성기를 파일에 저장하거나 프로세스로 보내기 | `pickle`, 또는 `json.dumps(rng.state)` |
| 시드나 생성기를 받아 생성기로 만들기 | [`default_rng(seed_or_rng)`](/api/random/default_rng/) |

## numpy를 아는 분께

- `rng.spawn(n)`은 numpy의 `Generator.spawn`과 같은 방식으로 자식 시드를 정해요(`SeedSequence.spawn`과 같은 `spawn_key`). 하지만 생성기 종류가 달라서 **값은 numpy와 달라요.**
- 상태는 `rng.bit_generator.state`가 아니라 **`rng.state`**예요. 키도 numpy와 달라서(`entropy`, `spawn_key`, `n_children_spawned`, `position`) 서로 바꿔 넣을 수 없어요.
- **`copy.copy`가 numpy와 달라요.** numpy의 `copy.copy(rng)`는 내부 상태를 원본과 함께 쓰는 얕은 복사라서 원본과 이어지는 값을 내지만, stardust의 `copy.copy`는 `deepcopy`처럼 **독립된 복사본**을 만들어 원본과 같은 값을 다시 내요.
- `SeedSequence`, `bit_generator`, `jumped()`, `advance()`는 없어요. 시드는 `default_rng`에 정수나 정수 시퀀스로 주고, 수열의 다른 위치로 가려면 `state`의 `position`을 바꿔요.
- numpy처럼 `default_rng([42, 0])`은 `default_rng(42)`와 같은 수열이에요.
- 한 생성기를 여러 스레드가 함께 써도 안전하고, 같은 난수를 두 번 쓰지 않아요.
