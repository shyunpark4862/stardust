## 한눈에 보기

`softmax`는 **점수 여러 개를 확률 분포로** 바꿔요. 결과는 모두 0과 1 사이이고, 다 더하면 1이에요. 점수가 클수록 큰 몫을 받고, 점수의 순서는 그대로 유지돼요. 각 원소를 exp로 바꾼 다음 그 합으로 나눈 것이에요.

$$\operatorname{softmax}(x)_i = \frac{e^{x_i}}{\sum_j e^{x_j}}, \qquad \operatorname{log\_softmax}(x)_i = x_i - \log \sum_j e^{x_j}$$

```python
>>> import stardust as sd
>>> s = sd.special
>>> z = sd.asarray([1.0, 2.0, 3.0])
>>> s.softmax(z)
array([0.09003057317038046, 0.24472847105479764,  0.6652409557748218], dtype=float64)
>>> sd.sum(s.softmax(z))
0.9999999999999999
```

합이 `1.0`이 아니라 `0.9999999999999999`인 것은 세 확률이 각각 반올림됐기 때문이에요. 각 확률은 마지막 자리까지 정확해요.

<Fig caption="점수 1, 2, 3을 softmax에 넣으면 합이 1인 확률이 나와요. 점수가 1 클 때마다 확률은 e배(약 2.7배)가 돼요.">

이름의 뜻은 "부드러운 최댓값 고르기"예요. 가장 큰 점수에 1, 나머지에 0을 주는 대신(이것이 딱딱한 argmax예요), 큰 점수에 많이, 작은 점수에도 조금씩 나눠 줘요.

어디에 쓰나요?

- **다중 분류**: 신경망의 마지막 층에서 갈래마다 나온 점수(로짓, logit)를 "각 갈래일 확률"로 바꿔요. 갈래가 둘이면 [`expit`](/api/special/expit/)와 같아요.
- **어텐션**: 트랜스포머의 어텐션은 단어 쌍의 점수를 softmax로 바꿔서 "어디에 얼마나 주목할지"의 가중치로 써요.
- **통계역학**: 에너지가 Eᵢ인 상태에 있을 확률(볼츠만 분포)이 `softmax(-E / kT)`예요.
- **강화학습·경제학**: 행동의 가치를 확률로 바꿔 행동을 고르거나(소프트맥스 정책), 선택지의 효용으로 선택 확률을 모형화해요(다항 로짓 모형).

## 점수에 같은 수를 더해도 결과는 같아요

모든 점수에 같은 수 c를 더하면 분자와 분모가 똑같이 e^c배가 되어서, 결과가 바뀌지 않아요. 확률은 **점수의 차이**로만 정해져요.

```python
>>> s.softmax(z + 100.0)
array([0.09003057317038046, 0.24472847105479764,  0.6652409557748218], dtype=float64)
```

이 성질 덕분에 `softmax`는 점수가 아무리 커도 넘치지 않아요. 식을 그대로 계산하면 `exp(1000)`이 무한대가 되어서 `inf / inf = nan`이 나오지만, `softmax`는 정확한 답을 내요.

```python
>>> big = sd.asarray([1000.0, 1001.0, 1002.0])
>>> e = sd.exp(big)
>>> e / sd.sum(e)
array([nan, nan, nan], dtype=float64)
>>> s.softmax(big)
array([0.09003057317038046, 0.24472847105479764,  0.6652409557748218], dtype=float64)
```

점수가 모두 같으면 고른 분포가 돼요. 확률의 로그를 넣으면 원래 확률(합이 1이 되게 맞춘 것)이 돌아와요.

```python
>>> s.softmax(sd.asarray([0.0, 0.0, 0.0, 0.0]))
array([0.25, 0.25, 0.25, 0.25], dtype=float64)
>>> s.softmax(sd.log(sd.asarray([1.0, 2.0, 5.0])))
array([0.125,  0.25, 0.625], dtype=float64)
```

### 두 갈래면 expit와 같아요

점수가 `[0, x]` 두 개면 둘째 확률은 `expit(x) = 1 / (1 + e⁻ˣ)`이에요. `softmax`는 로지스틱 함수를 갈래가 여럿인 경우로 넓힌 것이에요.

```python
>>> s.softmax(sd.asarray([0.0, 2.0]))
array([0.11920292202211755,  0.8807970779778823], dtype=float64)
>>> s.expit(2.0)
0.8807970779778823
```

### 온도: 점수를 나눠서 날카로움 조절하기

점수를 양수 T로 나눈 `softmax(z / T)`를 많이 써요. T를 **온도**라고 불러요. T가 작으면 가장 큰 점수에 확률이 몰리고(argmax에 가까워짐), T가 크면 고른 분포에 가까워져요. 언어 모델에서 다음 단어를 고를 때 "얼마나 과감하게 고를지"를 이것으로 정해요.

```python
>>> s.softmax(z / 0.1)
array([2.061060046209062e-09, 4.539786860886666e-05,     0.999954600070331], dtype=float64)
>>> s.softmax(z / 2.0)
array([0.1863237232258476, 0.3071958857184984,  0.506480391055654], dtype=float64)
>>> s.softmax(z / 100.0)
array([0.33000561097102177, 0.33332222249999355,  0.3366721665289847], dtype=float64)
```

## `axis`: 어느 방향으로 합이 1이 될까요

`axis`는 "합이 1이 되게 맞출 축"이에요. 축의 개념은 [sum](/api/array/sum/)과 같아요. 결과의 모양은 언제나 입력과 같아요(그래서 `keepdims` 옵션이 없어요).

<Callout type="warn" title="기본값은 배열 전체예요">

`axis`를 주지 않으면(`axis=None`) **배열의 모든 원소를 합쳐서** 합이 1이 되게 해요. 표본마다 한 행씩 점수를 담은 2차원 배열이라면 거의 언제나 `axis=1`(또는 `axis=-1`)이 필요해요. 빠뜨려도 에러가 나지 않으니 특히 조심하세요.

</Callout>

```python
>>> scores = sd.asarray([[2.0, 1.0, 0.1], [0.5, 0.5, 3.0]])
>>> s.softmax(scores, axis=1)
array([[ 0.6590011388859679, 0.24243297070471392, 0.09856589040931818],
       [0.07050946066120506, 0.07050946066120506,  0.8589810786775898]], dtype=float64)
>>> s.softmax(scores)
array([[0.21358438512872296, 0.07857330424410072,  0.0319455215712186],
       [0.04765711805897587, 0.04765711805897587,   0.580582552938006]], dtype=float64)
```

첫 결과는 행마다 합이 1이고, 둘째 결과는 여섯 원소를 모두 더해야 1이에요.

```python
>>> sd.sum(s.softmax(scores, axis=1), axis=1)
array([               1.0, 0.9999999999999999], dtype=float64)
```

`axis=0`이면 열마다 합이 1이에요. 음수 축은 뒤에서부터 세고, tuple이나 list로 여러 축을 한꺼번에 줄 수도 있어요. 모든 축을 적는 것은 `axis=None`과 같아요.

```python
>>> s.softmax(scores, axis=0)
array([[ 0.8175744761936437,  0.6224593312018546, 0.05215356307841774],
       [0.18242552380635632, 0.37754066879814546,  0.9478464369215823]], dtype=float64)
>>> s.softmax(scores, axis=-1).shape
(2, 3)
```

## log_softmax: 확률의 로그

`log_softmax(x)`는 `log(softmax(x))`와 같은 값이에요. 식으로 쓰면 `x - logsumexp(x)`예요([`logsumexp`](/api/special/logsumexp/)).

```python
>>> s.log_softmax(z)
array([-2.4076059644443806, -1.4076059644443804, -0.4076059644443804], dtype=float64)
>>> sd.exp(s.log_softmax(z))
array([0.09003057317038043, 0.24472847105479764,  0.6652409557748218], dtype=float64)
```

따로 있는 이유는 **아주 작은 확률**이에요. 점수 차이가 크면 작은 쪽의 확률이 float64로 담을 수 없을 만큼 작아져서 `softmax`의 결과가 0이 되고, 그 로그는 `-inf`가 돼요. `log_softmax`는 확률을 거치지 않고 로그를 바로 계산해서 정확한 값 `-800`을 내요.

```python
>>> s.softmax(sd.asarray([0.0, 800.0]))
array([0.0, 1.0], dtype=float64)
>>> sd.log(s.softmax(sd.asarray([0.0, 800.0])))
array([-inf,  0.0], dtype=float64)
>>> s.log_softmax(sd.asarray([0.0, 800.0]))
array([-800.0,    0.0], dtype=float64)
```

### 예: 분류 모델의 교차 엔트로피 손실

표본 두 개의 점수와 정답 갈래(0번, 2번)가 있을 때, 교차 엔트로피 손실은 "정답 갈래의 로그 확률"의 평균에 음의 부호를 붙인 것이에요. 행마다 `log_softmax`를 구하고 [인덱싱](/api/array/indexing/)으로 정답 칸을 골라요.

```python
>>> labels = sd.asarray([0, 2])
>>> lsm = s.log_softmax(scores, axis=1)
>>> lsm[sd.arange(2), labels]
array([-0.41703001627783354,  -0.1520083843911351], dtype=float64)
>>> -sd.mean(lsm[sd.arange(2), labels])
0.2845192003344843
```

`softmax`로 확률을 먼저 구한 다음 `log`를 취하면, 모델이 정답에 아주 낮은 점수를 준 표본 하나 때문에 손실이 `inf`가 될 수 있어요. 손실을 계산할 때는 언제나 `log_softmax`를 쓰세요.

## 특수값과 빈 배열

값 때문에 에러가 나는 일은 없어요. 점수에 `-inf`가 있으면 그 갈래의 확률은 0(로그 확률은 `-inf`)이에요. "절대 고르지 않을 갈래"를 표시할 때 흔히 써요.

```python
>>> s.softmax(sd.asarray([-sd.inf, 0.0, 0.0]))
array([0.0, 0.5, 0.5], dtype=float64)
>>> s.log_softmax(sd.asarray([-sd.inf, 0.0, 0.0]))
array([               -inf, -0.6931471805599453, -0.6931471805599453], dtype=float64)
```

나머지 경우는 표와 같아요. 결과에 NaN이 나오는 경우는 수학적으로 확률을 정할 수 없는 경우예요.

| 입력 (한 축 안에서) | `softmax` | `log_softmax` |
|---|:---:|:---:|
| `-inf`가 일부 섞임 | 그 칸은 `0.0` | 그 칸은 `-inf` |
| 모든 원소가 `-inf` | 모두 NaN | 모두 NaN |
| `+inf`가 있음 | 모두 NaN | `+inf` 칸은 NaN, 나머지는 `-inf` |
| NaN이 있음 | 모두 NaN | 모두 NaN |
| 빈 배열 | 빈 배열 | 빈 배열 |

```python
>>> s.softmax(sd.asarray([sd.inf, 1.0]))
array([nan, nan], dtype=float64)
>>> s.log_softmax(sd.asarray([sd.inf, 1.0]))
array([ nan, -inf], dtype=float64)
>>> s.softmax(sd.asarray([-sd.inf, -sd.inf]))
array([nan, nan], dtype=float64)
>>> s.softmax(sd.asarray([]))
array([], dtype=float64)
```

## 정확도

`softmax`는 **원소마다 상대오차 1e-14 이하**를 약속해요. 앞에서부터 대략 14자리가 맞는다는 뜻이고, 아주 작은 확률도 마찬가지예요(결과가 서브노멀 수일 때만 아주 작은 절대오차로 따져요). 아래 예에서 첫째 확률 `5.689641166240339e-131`은 참값과 끝자리까지 같아요.

```python
>>> s.softmax(sd.asarray([0.1, 300.0]))
array([5.689641166240339e-131,                    1.0], dtype=float64)
```

`log_softmax`는 오차가 `1e-14 × max(1, |결과|)` 이하예요. 결과의 크기가 1보다 크면 상대오차, 0에 가까우면 절대오차로 따진다는 뜻이에요. 가장 큰 점수의 로그 확률은 0에 가까울 수 있어서, 0 근처에서 상대오차를 따지는 것은 뜻이 없기 때문이에요. 실제로 잰 최대 오차는 `softmax` 2.1 ULP, `log_softmax` 1.3 ULP예요([특수함수의 기본](/api/special/basics/)).

## 조심할 점

### 배열만 받아요

`x`는 `sd.ndarray`여야 해요. Python 숫자와 리스트는 받지 않아요. 정수와 bool 배열은 float64로 바꿔서 계산하고, 복소수 배열은 `TypeError`예요.

```python
>>> s.softmax([1.0, 2.0])
Traceback (most recent call last):
    ...
TypeError: softmax(): 'x' must be an sd.ndarray, not list
>>> s.softmax(sd.asarray([1, 2, 3]))
array([0.09003057317038046, 0.24472847105479764,  0.6652409557748218], dtype=float64)
>>> s.softmax(sd.asarray([1 + 0j]))
Traceback (most recent call last):
    ...
TypeError: softmax(): not supported for complex128
```

### `keepdims`는 없어요

결과의 모양이 입력과 같으므로 `keepdims`가 필요 없어요. 넘기면 `TypeError`예요. `axis`도 이름을 붙여서 넘겨야 해요.

```python
>>> s.softmax(scores, keepdims=True)
Traceback (most recent call last):
    ...
TypeError: softmax(): incompatible function arguments. ...
```

### 없는 축

```python
>>> s.softmax(scores, axis=2)
Traceback (most recent call last):
    ...
ValueError: softmax(): axis 2 is out of bounds for an array of dimension 2
```

### log(softmax(x))와 exp(x - logsumexp(x))

`log(softmax(x))`는 작은 확률에서 `-inf`가 되니 `log_softmax`를 쓰세요. `exp(x - logsumexp(x))`도 수학적으로는 `softmax`와 같지만, `x - logsumexp(x)`의 반올림 오차가 exp를 거치며 커져서 마지막 자리가 달라져요. 큰 점수에서는 그 차이가 더 벌어지니 `softmax`를 쓰는 편이 정확해요.

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 설명 |
|---|---|---|
| 점수 여러 개를 확률로 | `softmax` | 결과의 모양이 입력과 같아요. |
| 점수 여러 개를 로그 확률로 | `log_softmax` | 손실 계산처럼 로그가 필요하면 이쪽이 정확해요. |
| 점수 하나를 확률로(두 갈래) | [`expit`](/api/special/expit/) | `softmax([0, x])`의 둘째 값과 같아요. |
| 정규화 상수의 로그 | [`logsumexp`](/api/special/logsumexp/) | `log_softmax(x) = x - logsumexp(x)`예요. 결과의 축이 줄어요. |
| 가장 큰 점수의 위치 | [`sd.argmax`](/api/array/argmin/) | 확률 대신 위치 하나를 돌려줘요. `softmax` 결과의 argmax는 점수의 argmax와 같아요. |
| `exp(x) / sum(exp(x))` 직접 계산 | 쓰지 마세요 | 점수가 크면 NaN, 작으면 0으로 나누기가 돼요. |

## scipy를 아는 분께

- 시그니처는 `softmax(x, /, *, axis=None)`, `log_softmax(x, /, *, axis=None)`이에요. scipy처럼 **기본값 `axis=None`은 배열 전체**예요. `axis`는 keyword-only예요.
- **`x`는 `sd.ndarray`만 받아요.** scipy는 리스트와 스칼라도 받지만, stardust는 `TypeError`예요.
- **빈 배열은 빈 배열을 돌려줘요.** scipy 1.18.1은 빈 배열에서 `ValueError`를 내요.
- 무한대와 NaN의 규칙(`softmax([inf, 1])`이 `[nan, nan]`, `log_softmax([inf, 1])`이 `[nan, -inf]` 등)은 scipy와 같아요.
- 아주 작은 확률의 뒷자리가 scipy와 다를 수 있어요. 예를 들어 `softmax([0.1, 300.0])`의 첫째 값은 stardust가 `5.689641166240339e-131`(참값과 같음), scipy가 `5.689641166240468e-131`이에요. 점수가 크게 벌어질 때 scipy는 마지막 자리 수백 칸까지 어긋나요.
