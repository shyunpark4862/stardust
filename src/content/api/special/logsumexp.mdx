## 한눈에 보기

`logsumexp(x)`는 이름 그대로 **log(sum(exp(x)))** 예요. 각 원소에 exp를 취하고, 모두 더한 다음, 다시 로그를 취해요.

$$\operatorname{logsumexp}(x) = \log \sum_i e^{x_i}$$

```python
>>> import stardust as sd
>>> s = sd.special
>>> s.logsumexp(sd.asarray([0.0, 0.0, 0.0, 0.0]))
1.3862943611198906
>>> sd.log(4.0)
1.3862943611198906
```

이 식을 그대로 계산하면 금방 문제가 생겨요. `exp`는 x가 약 710만 넘어도 무한대가 되고, x가 약 −745보다 작으면 0이 돼요. `logsumexp`는 결과가 float64로 나타낼 수 있는 크기라면 **중간 과정에서 넘치거나 0이 되지 않게** 계산해요.

```python
>>> big = sd.asarray([1000.0, 1000.0])
>>> sd.log(sd.sum(sd.exp(big)))
inf
>>> s.logsumexp(big)
1000.6931471805599
```

어디에 쓰나요?

- **로그 확률 더하기**: 아주 작은 확률은 로그로 저장해요(곱이 덧셈이 되고 0이 되지 않아요). 그 확률들을 **더해야** 할 때, 예를 들어 혼합 모형에서 성분별 가능도를 합칠 때나 은닉 마르코프 모형의 전방 알고리즘에서 `logsumexp`를 써요.
- **정규화 상수**: 점수를 확률로 바꾸는 소프트맥스의 분모 `Σ exp(xᵢ)`의 로그가 `logsumexp`예요. 베이즈 추론의 주변 가능도, 통계역학의 분배함수(자유 에너지)도 같은 꼴이에요.
- **부드러운 최댓값**: `logsumexp`는 최댓값과 아주 가까운 값이면서 어디서나 매끄러워요. 그래서 미분이 필요한 최적화에서 `max` 대신 써요.

## 로그 확률을 더해요

확률 0.25, 0.25, 0.5를 로그로 바꿔서 `logsumexp`로 더하면 `log(1) = 0`이에요. 로그 공간에서 "확률을 더한" 결과예요.

```python
>>> s.logsumexp(sd.log(sd.asarray([0.25, 0.25, 0.5])))
0.0
```

값이 아주 작을 때 차이가 드러나요. 로그 확률이 −1000 근처면 `exp`를 취하는 순간 모두 0이 되어서, 그대로 계산하면 `log(0) = -inf`예요.

```python
>>> lp = sd.asarray([-1000.0, -1001.0, -1002.0])
>>> sd.log(sd.sum(sd.exp(lp)))
-inf
>>> s.logsumexp(lp)
-999.5923940355556
```

### 예: 혼합 모형의 가능도

어떤 관측의 로그 가능도가 세 성분에서 각각 −1000, −999, −1001이고, 성분의 비중이 0.2, 0.3, 0.5라고 해 볼게요. 전체 가능도는 `Σ wᵢ · exp(ℓᵢ)`이고, 그 로그는 **비중의 로그를 더한 다음** `logsumexp`로 구해요.

```python
>>> w = sd.asarray([0.2, 0.3, 0.5])
>>> lik = sd.asarray([-1000.0, -999.0, -1001.0])
>>> s.logsumexp(lik + sd.log(w))
-999.8181583340657
```

## 부드러운 최댓값

`logsumexp`는 언제나 최댓값보다 크거나 같고, 최댓값에 `log n`(n은 원소 수)을 더한 것보다 작거나 같아요.

$$\max_i x_i \;\le\; \operatorname{logsumexp}(x) \;\le\; \max_i x_i + \log n$$

가장 큰 값이 나머지보다 훨씬 크면 `logsumexp`는 거의 그 최댓값이에요. 모든 값이 같으면 최댓값에 정확히 `log n`을 더한 값이에요.

```python
>>> x = sd.asarray([1.0, 2.0, 3.0])
>>> sd.max(x), s.logsumexp(x), sd.max(x) + sd.log(3.0)
(3.0, 3.4076059644443806, 4.098612288668109)
>>> s.logsumexp(sd.asarray([0.0, 10.0]))
10.000045398899218
```

## `axis`와 `keepdims`

`axis`와 `keepdims`는 [sum](/api/array/sum/)과 뜻이 같아요. `axis`는 "줄여서 없앨 축"이고, `None`(기본값)이면 모든 원소를 하나로 줄여요. 2차원 배열에서 `axis=1`은 **행마다**, `axis=0`은 **열마다** 하나씩 결과를 내요.

```python
>>> m = sd.asarray([[0.0, 1.0, 2.0], [10.0, 10.0, 10.0]])
>>> s.logsumexp(m, axis=1)
array([2.4076059644443806,  11.09861228866811], dtype=float64)
>>> s.logsumexp(m, axis=0)
array([10.000045398899218, 10.000123402189724, 10.000335406372896], dtype=float64)
>>> s.logsumexp(m)
11.098780365329686
```

음수 축은 뒤에서부터 세고, tuple이나 list로 여러 축을 한꺼번에 줄일 수 있어요.

```python
>>> s.logsumexp(m, axis=-1)
array([2.4076059644443806,  11.09861228866811], dtype=float64)
>>> s.logsumexp(m, axis=(0, 1))
11.098780365329686
>>> s.logsumexp(sd.reshape(sd.arange(24.0), (2, 3, 4)), axis=(0, 2)).shape
(3,)
```

`keepdims=True`면 줄인 축이 길이 1로 남아요. 결과를 원래 배열과 다시 계산할 때 모양이 맞아서 편해요. 예를 들어 행마다 `x - logsumexp(x)`를 구하면 행마다 로그 확률로 정규화돼요. 둘째 행은 세 값이 같아서 모두 `log(1/3) ≈ -1.0986`이에요. 이 계산은 [`log_softmax`](/api/special/softmax/)가 한 번에, 마지막 자리까지 더 정확하게 해 줘요.

```python
>>> s.logsumexp(m, axis=1, keepdims=True)
array([[2.4076059644443806],
       [ 11.09861228866811]], dtype=float64)
>>> m - s.logsumexp(m, axis=1, keepdims=True)
array([[-2.4076059644443806, -1.4076059644443806, -0.4076059644443806],
       [-1.0986122886681091, -1.0986122886681091, -1.0986122886681091]], dtype=float64)
```

### 결과는 배열일까요, 숫자일까요

줄이고 나서 남는 축이 없으면 결과는 배열이 아니라 Python `float`예요. 일부 축만 줄이거나 `keepdims=True`면 float64 배열이에요.

```python
>>> type(s.logsumexp(x))
<class 'float'>
>>> s.logsumexp(sd.asarray([5.0]))
5.0
```

## sd.max와 sd.sum으로 직접 쓰면

`logsumexp`가 넘치지 않는 원리는 수학적으로 간단해요. 최댓값 m을 빼고 계산한 뒤 다시 더하면 같은 값이에요.

$$\log \sum_i e^{x_i} = m + \log \sum_i e^{x_i - m}, \qquad m = \max_i x_i$$

`x - m`은 모두 0 이하라서 `exp`가 넘치지 않고, 적어도 하나(최댓값 자리)는 `exp(0) = 1`이라 합이 0이 되지 않아요. 이 식을 배열 함수로 직접 쓰면 보통의 값에서는 잘 돌아가요.

```python
>>> def lse(v):
...     m = sd.max(v)
...     return m + sd.log(sd.sum(sd.exp(v - m)))
...
>>> lse(lp)
-999.5923940355556
```

하지만 경계에서 문제가 생겨요.

```python
>>> lse(sd.asarray([sd.inf, 1.0]))
nan
>>> s.logsumexp(sd.asarray([sd.inf, 1.0]))
inf
>>> lse(sd.asarray([-sd.inf, -sd.inf]))
nan
>>> s.logsumexp(sd.asarray([-sd.inf, -sd.inf]))
-inf
>>> lse(sd.asarray([]))
Traceback (most recent call last):
    ...
ValueError: max(): undefined for an empty array (or along an empty axis)
>>> s.logsumexp(sd.asarray([]))
-inf
```

- **최댓값이 무한대면** `x - m`에 `inf - inf`가 생겨서 NaN이 돼요. 로그 확률에서 `-inf`(확률 0)는 흔한 값이라, 모든 칸이 확률 0인 행이 하나만 있어도 결과가 NaN으로 오염돼요.
- **빈 배열**에서는 `sd.max`가 에러를 내요. `logsumexp`는 빈 합 0의 로그인 `-inf`를 돌려줘요.
- **축마다 계산하려면** `sd.max(..., keepdims=True)`로 모양을 맞추고, 무한대인 최댓값을 따로 처리하는 코드가 더 필요해요.

`logsumexp`는 이런 경우를 모두 처리하고, 정확도도 약속해요(아래 정확도 절). 직접 쓸 이유가 없어요.

## 특수값과 빈 배열

값 때문에 에러가 나는 일은 없어요.

| 입력 | 결과 | 이유 |
|---|:---:|---|
| 빈 배열(줄이는 축의 길이가 0) | `-inf` | 빈 합은 0이고, log 0 = −∞ |
| 원소가 모두 `-inf` | `-inf` | 확률이 모두 0이면 합도 0 |
| `+inf`가 하나라도 있으면 | `inf` | `-inf`가 함께 있어도 |
| NaN이 하나라도 있으면 | NaN | |
| `-inf`가 일부 섞여 있으면 | 나머지만의 결과 | `-inf` 칸은 합에 0을 보태요 |

```python
>>> s.logsumexp(sd.asarray([sd.inf, -sd.inf]))
inf
>>> s.logsumexp(sd.asarray([sd.nan, 1.0]))
nan
>>> s.logsumexp(sd.asarray([-sd.inf, 0.0]))
0.0
>>> s.logsumexp(sd.zeros((2, 0)), axis=1)
array([-inf, -inf], dtype=float64)
```

## 정확도

`logsumexp`는 결과의 오차가 **`1e-14 × max(1, |결과|)` 이하**라고 약속해요. 결과가 1보다 크면 상대오차 1e-14(앞에서부터 대략 14자리가 맞음), 결과가 0에 가까우면 절대오차 1e-14라는 뜻이에요.

상대오차만으로 약속하지 않는 이유는 결과가 0을 지나갈 수 있기 때문이에요. 위의 로그 확률 예처럼 확률의 합이 1이면 결과가 정확히 0이어야 하는데, 입력 자체가 반올림된 값이라 아주 작은 수가 나올 수 있어요. 참값이 0인 곳에서는 "몇 자리가 맞는가"를 따질 수 없어서 절대오차로 따져요. 실제로 잰 최대 오차는 마지막 자리 한 칸(2⁻⁵² 단위로 0.69)보다 작아요.

```python
>>> s.logsumexp(sd.log(sd.asarray([[0.2, 0.3], [0.1, 0.4]])))
2.220446049250313e-16
```

0.2 + 0.3 + 0.1 + 0.4 = 1이라 참값은 0이지만, 0.2, 0.3 같은 수가 float64로 정확히 나타나지 않아서 2.2 × 10⁻¹⁶이 나왔어요. 약속한 절대오차 1e-14 안이에요.

## 조심할 점

### 배열만 받아요

`x`는 `sd.ndarray`여야 해요. 원소별 함수와 달리 Python 숫자도 받지 않아요. 리스트는 [`asarray`](/api/array/asarray/)로 먼저 바꾸세요.

```python
>>> s.logsumexp([1.0, 2.0])
Traceback (most recent call last):
    ...
TypeError: logsumexp(): 'x' must be an sd.ndarray, not list
>>> s.logsumexp(1.0)
Traceback (most recent call last):
    ...
TypeError: logsumexp(): 'x' must be an sd.ndarray, not float
```

정수와 bool 배열은 float64로 바꿔서 계산해요. 복소수 배열은 `TypeError`예요.

```python
>>> s.logsumexp(sd.asarray([1, 2, 3]))
3.4076059644443806
>>> s.logsumexp(sd.asarray([1 + 0j]))
Traceback (most recent call last):
    ...
TypeError: logsumexp(): not supported for complex128
```

### 옵션은 이름을 붙여서

`axis`와 `keepdims`는 이름과 함께 써야 해요. `s.logsumexp(m, 1)`처럼 자리로 넘기면 `TypeError`예요. `axis`는 정수나 정수의 tuple·list, `keepdims`는 `True`나 `False`만 받아요.

```python
>>> s.logsumexp(m, axis=1.0)
Traceback (most recent call last):
    ...
TypeError: logsumexp(): 'axis' must be an int or a tuple or list of ints, not float
>>> s.logsumexp(m, keepdims=1)
Traceback (most recent call last):
    ...
TypeError: logsumexp(): 'keepdims' must be True or False, not int
```

### 없는 축

배열의 차원보다 큰 축 번호를 주거나 같은 축을 두 번 쓰면 `ValueError`예요.

```python
>>> s.logsumexp(m, axis=2)

    ...
ValueError: logsumexp(): axis 2 is out of bounds for an array of dimension 2
>>> s.logsumexp(m, axis=(0, 0))
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | `logsumexp`와 다른 점 |
|---|---|---|
| 로그로 나타낸 **두 배열을 원소끼리** 더하기 | [`sd.logaddexp(a, b)`](/api/array/exp-log/) | 배열 하나를 줄이지 않고, 두 배열의 같은 자리끼리 계산해요. 원소 두 개짜리 `logsumexp`와 같은 값이에요. |
| 점수를 확률로 | [`softmax`](/api/special/softmax/) | `exp(x - logsumexp(x))`예요. 모양이 줄지 않아요. |
| 점수를 로그 확률로 | [`log_softmax`](/api/special/softmax/) | `x - logsumexp(x)`예요. 모양이 줄지 않아요. |
| 최댓값 | [`sd.max`](/api/array/min-max/) | 매끄럽지 않은 진짜 최댓값이에요. `logsumexp`는 그보다 크고 최대 `log n`까지 차이 나요. |
| 그냥 합 | [`sd.sum`](/api/array/sum/) | exp와 log를 거치지 않아요. |

```python
>>> s.logsumexp(sd.asarray([1.0, 5.0]))
5.0181499279178094
>>> sd.logaddexp(1.0, 5.0)
5.0181499279178094
```

## scipy를 아는 분께

- 시그니처가 `logsumexp(x, /, *, axis=None, keepdims=False)`예요. **`b=`(가중치)와 `return_sign=`이 없어요.** 양수 가중치는 위의 혼합 모형 예처럼 `logsumexp(x + sd.log(b))`로 계산하세요. 음수 가중치(결과의 부호)는 지원하지 않아요.
- `axis`, `keepdims`는 keyword-only예요.
- **`x`는 `sd.ndarray`만 받아요.** scipy는 리스트와 스칼라도 받지만, stardust는 `TypeError`예요. 복소수 배열도 받지 않아요.
- 모든 축을 줄인 결과는 numpy 스칼라가 아니라 Python `float`예요.
- 빈 배열이 `-inf`인 것, 무한대와 NaN의 규칙은 scipy와 같아요.
- 결과의 마지막 자리가 scipy와 다를 수 있어요(예: `logsumexp([1.0, 2.0, 3.0])`이 scipy는 `3.40760596444438`, stardust는 `3.4076059644443806`). 차이는 마지막 자리 한 칸 정도예요.
