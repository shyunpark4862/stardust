## 한눈에 보기

`xlogy(x, y)`는 이름 그대로 x 곱하기 log(y)예요. 그냥 `x * sd.log(y)`로 써도 될 것 같지만 한 가지가 달라요. **x가 0이면, y가 0이어도 결과가 0이에요.** 수학적으로 `0 · log 0`은 `0 × (-∞)`라서 정해진 값이 없고, 컴퓨터로 계산하면 NaN(숫자가 아님)이 나와요. `xlogy`는 이 경우를 0으로 정해 둔 함수예요.

`xlog1py(x, y)`는 x 곱하기 log(1 + y)예요. x = 0이면 0인 것은 같고, 덧붙여 y가 0에 아주 가까울 때도 정밀도를 잃지 않아요.

### 어디에 쓰나요

- 엔트로피와 정보량: 확률 분포의 엔트로피는 `-Σ p log p`예요. 확률이 0인 항이 하나라도 있으면 그대로 계산할 때 NaN이 되는데, 정보 이론에서는 그 항을 0으로 봐요. `xlogy(p, p)`가 바로 그 계산이에요.
- 로그 우도: 포아송·이항·다항 분포의 확률을 로그로 쓰면 `k · log p` 꼴의 항이 나와요. 관측 횟수 k가 0이고 확률 p도 0인 경우(일어날 수 없는 일이 일어나지 않음)는 확률 1, 로그 0이 맞는 답이에요.
- 교차 엔트로피, KL 발산: 머신러닝의 손실 함수에 나오는 `Σ y log q`도 같은 꼴이에요.

### 정의

$$
\operatorname{xlogy}(x, y) =
\begin{cases}
0 & x = 0 \\
x \log y & \text{그 밖}
\end{cases}
\qquad
\operatorname{xlog1py}(x, y) =
\begin{cases}
0 & x = 0 \\
x \log(1 + y) & \text{그 밖}
\end{cases}
$$

(어느 쪽이든 y가 NaN이면 결과는 NaN이에요.)

```python
>>> import stardust as sd
>>> s = sd.special
>>> s.xlogy(sd.asarray([1.0, 2.0, 3.0]), sd.e)
array([1.0, 2.0, 3.0], dtype=float64)
>>> s.xlogy(0.0, 0.0)
0.0
>>> 0.0 * sd.log(0.0)
nan
```

## xlogy(0, 0) = 0인 이유

확률 분포 `p = [0.5, 0.5, 0.0]`의 엔트로피를 계산해 볼게요. 셋째 사건은 일어나지 않으니, 동전 하나를 던지는 것과 같은 `log 2 ≈ 0.693`이 나와야 해요. 그런데 `p * log(p)`를 그대로 더하면 셋째 항의 `0 × (-inf)`가 NaN이 되고, 합 전체가 NaN이 돼요.

```python
>>> p = sd.asarray([0.5, 0.5, 0.0])
>>> -sd.sum(p * sd.log(p))
nan
>>> -sd.sum(s.xlogy(p, p))
0.6931471805599453
```

`0 · log 0 = 0`은 임의로 정한 규칙이 아니라, 위 그래프처럼 x·log x가 x → 0에서 0으로 다가가는 극한과 같은 값이에요. "일어나지 않는 사건은 정보량에 아무것도 보태지 않는다"는 뜻이기도 해요. 엔트로피만 필요하다면 이 계산을 한 번에 해 주는 [`entr`](/api/special/entr/)도 있어요.

### 예: 포아송 분포의 로그 확률

평균 λ인 포아송 분포에서 k번 일어날 확률의 로그는 `k·log λ − λ − log k!`예요. `log k!`는 [`gammaln`](/api/special/gamma/)`(k + 1)`로 구해요.

```python
>>> k = sd.asarray([0.0, 1.0, 2.0, 3.0])
>>> logp = s.xlogy(k, 2.0) - 2.0 - s.gammaln(k + 1)
>>> sd.exp(logp)
array([ 0.1353352832366127,  0.2706705664732254,  0.2706705664732254,
       0.18044704431548356], dtype=float64)
```

λ = 0인 분포(아무 일도 일어나지 않음)에서 0번 일어날 확률은 1, 그 로그는 0이어야 해요. `xlogy`로 쓰면 맞는 답이, 곱셈으로 쓰면 NaN이 나와요.

```python
>>> s.xlogy(0.0, 0.0) - 0.0 - s.gammaln(1.0)
0.0
>>> 0.0 * sd.log(0.0) - 0.0 - s.gammaln(1.0)
nan
```

## x = 0이면 y가 무엇이든 0이에요

`xlogy(0, y)`는 y가 0일 때만이 아니라 **음수나 무한대여도 0**이에요. log y가 NaN이나 무한대가 되는 곳에서도 x = 0이 이겨요. 단 y가 NaN이면 NaN이에요. "모르는 값"에 0을 곱한 결과는 알 수 없다고 보기 때문이에요. x가 `-0.0`이어도 결과는 `+0.0`이에요.

```python
>>> s.xlogy(sd.asarray([0.0, 0.0, 0.0, 0.0]), sd.asarray([0.0, -1.0, sd.inf, sd.nan]))
array([0.0, 0.0, 0.0, nan], dtype=float64)
>>> s.xlogy(-0.0, 5.0)
0.0
```

## xlog1py: y가 0에 가까울 때

`xlog1py(x, y)`는 `xlogy(x, 1 + y)`와 같은 값이지만, y가 0에 아주 가까우면 훨씬 정확해요. `1 + y`를 먼저 계산하면 float64의 자릿수 한계 때문에 y의 대부분이 반올림으로 사라지기 때문이에요. 배열 영역의 [`log1p`](/api/array/exp-log/)와 같은 이유예요.

예를 들어 확률 p로 일어나는 사건이 n번 시도에서 k번 일어났다면, 이항 분포의 로그 우도에 `(n − k)·log(1 − p)` 항이 들어가요. p가 아주 작으면 `1 - p`가 정확히 `1.0`으로 반올림돼서 이 항이 사라져요.

```python
>>> n, k, p = 1000.0, 3.0, 1e-20
>>> s.xlogy(n - k, 1 - p)
0.0
>>> s.xlog1py(n - k, -p)
-9.97e-18
```

참값은 `997 × log(1 − 10⁻²⁰) ≈ −9.97 × 10⁻¹⁸`이에요. `xlog1py`에는 `1 - p`가 아니라 `-p`를 넘긴다는 점을 기억하세요.

`xlog1py`도 x = 0이면 0이고, y = −1(1 + y = 0)에서는 x의 부호에 따라 ∓inf예요.

```python
>>> s.xlog1py(sd.asarray([1.0, 2.0]), sd.asarray([0.0, sd.e - 1]))
array([0.0, 2.0], dtype=float64)
>>> s.xlog1py(0.0, -1.0)
0.0
>>> s.xlog1py(1.0, -1.0)
-inf
```

## 특수값

값 때문에 에러가 나는 일은 없어요. 정의되지 않는 곳은 NaN, 무한대로 가는 곳은 ±inf예요.

| 입력 | 결과 | 이유 |
|---|:---:|---|
| `xlogy(0, y)`, `xlog1py(0, y)` | `0.0` | y가 0, 음수, ±inf여도. y가 NaN일 때만 NaN |
| `xlogy(x, 0)` | `x > 0`이면 `-inf`, `x < 0`이면 `inf` | log 0 = −∞에 x를 곱해요 |
| `xlog1py(x, -1)` | `x > 0`이면 `-inf`, `x < 0`이면 `inf` | 1 + y = 0이에요 |
| `xlogy(x, y)`, `y < 0`이고 `x != 0` | NaN | 음수의 로그는 실수가 아니에요 |
| `xlog1py(x, y)`, `y < -1`이고 `x != 0` | NaN | 같은 이유예요 |
| `xlogy(inf, 1)` | NaN | log 1 = 0이라 ∞ × 0이에요 |
| x나 y가 NaN | NaN | x = 0, y가 유한일 때만 0 |

```python
>>> s.xlogy(sd.asarray([1.0, -1.0]), 0.0)
array([-inf,  inf], dtype=float64)
>>> s.xlogy(1.0, -1.0)
nan
>>> s.xlogy(sd.inf, 1.0)
nan
```

## 입력과 결과

두 입력은 배열이나 Python 숫자예요. 모양이 다르면 [브로드캐스팅](/api/array/broadcasting/) 규칙으로 맞춰요. 정수와 bool은 float64로 바꿔서 계산하고, 결과는 언제나 float64예요. 둘 다 Python 숫자면 결과도 Python `float`예요.

```python
>>> s.xlogy(sd.asarray([[1.0], [2.0]]), sd.asarray([1.0, sd.e]))
array([[0.0, 1.0],
       [0.0, 2.0]], dtype=float64)
>>> s.xlogy(2, 8)
4.1588830833596715
```

모양이 맞지 않으면 `ValueError`예요.

```python
>>> s.xlogy(sd.asarray([1.0, 2.0]), sd.asarray([1.0, 2.0, 3.0]))
Traceback (most recent call last):
    ...
ValueError: xlogy(): shapes could not be broadcast together: (2,) (3,)
```

`out=`의 규칙은 [사칙연산](/api/array/arithmetic/)의 `out`과 같아요.

## 정확도

두 함수 모두 정의역 전체에서 상대오차 1e-14 이하를 약속해요(`xlogy`는 y > 0, `xlog1py`는 y > −1). 앞에서부터 대략 14자리가 맞는다는 뜻이에요. 실제로 잰 최대 오차는 둘 다 1.2 ULP(마지막 자리 한두 칸)예요. ULP의 뜻은 [특수함수의 기본](/api/special/basics/)에 있어요.

## 조심할 점

- **y가 NaN이면 x = 0이어도 NaN이에요.** 결측값을 NaN으로 표시해 두었다면, 확률이 0인 칸에도 NaN이 남아요.
- **x가 무한대고 y = 1이면 NaN이에요.** `log 1 = 0`이라 ∞ × 0이 되기 때문이에요. x = 0일 때와 달리 이 경우는 0으로 정하지 않아요.
- **`xlog1py`에는 1을 더하기 전의 값을 넘겨요.** `log(1 − p)`가 필요하면 `xlog1py(x, -p)`예요. `xlog1py(x, 1 - p)`라고 쓰면 전혀 다른 값이 나와요.
- **복소수는 받지 않아요.** 복소수 배열을 넣으면 `TypeError`예요.

```python
>>> s.xlogy(sd.asarray([1 + 0j]), 1.0)
Traceback (most recent call last):
    ...
TypeError: xlogy(): not supported for complex128 and float64
```

## 비슷한 함수와의 차이

| 쓸 것 | 계산 | `xlogy`와 다른 점 |
|---|:---:|---|
| `x * sd.log(y)` | x·log y | x = 0, y = 0에서 NaN이 나와요. |
| `xlog1py(x, y)` | x·log(1 + y) | y가 0에 가까울 때 정확해요. |
| [`entr(x)`](/api/special/entr/) | −x·log x | `-xlogy(x, x)`와 같아요. 엔트로피의 한 항이에요. 음수 x는 `-inf`예요. |
| [`rel_entr(x, y)`](/api/special/entr/) | x·log(x/y) | KL 발산의 한 항이에요. `xlogy(x, x) - xlogy(x, y)`와 같은 뜻이지만, 정의역 밖을 `inf`로 정하고 x와 y가 가까울 때도 정확해요. |

```python
>>> x = sd.asarray([0.0, 0.5, 1.0])
>>> x * sd.log(x)
array([                 nan, -0.34657359027997264,                  0.0], dtype=float64)
>>> s.xlogy(x, x)
array([                 0.0, -0.34657359027997264,                  0.0], dtype=float64)
```

## scipy를 아는 분께

- 정의와 특수값은 `scipy.special.xlogy`, `xlog1py`와 같아요(`xlogy(0, nan)`이 NaN인 것도 같아요).
- **복소수를 받지 않아요.** scipy는 복소수 입력도 계산하지만, stardust는 `TypeError`예요.
- 리스트와 numpy 배열은 받지 않아요. 둘 다 Python 숫자면 numpy 스칼라가 아니라 Python `float`가 나와요.
- `out`은 keyword-only예요. `where=` 같은 ufunc 인자는 없어요.
