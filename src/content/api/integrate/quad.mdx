## 무엇을 하나요

`quad`는 변수 하나인 함수 f의 적분 $\int_a^b f(x)\,dx$를 계산해요. 수십 년 동안 다듬어진 Fortran 적분 모음 QUADPACK의 방법이고, scipy의 `quad`와 같은 루틴을 같은 방식으로 골라요.

계산은 **적응 구적**이에요. 구간에 21점 규칙을 쓰고, 그 안에 든 10점 규칙과의 차이로 오차를 어림해요. 전체의 어림이 허용오차보다 크면 어림이 가장 큰 구간을 반으로 나누고 두 반쪽을 다시 계산해요. 그래서 함수가 쉬운 곳에서는 점을 적게, 봉우리나 특이점 둘레에서는 많이 써요.

나누기만으로는 끝점의 특이점($x^{-1/2}$, $\log x$)을 빨리 따라잡지 못해요. 그래서 `quad`는 나눌 때마다 바뀌는 적분값들의 흐름을 **외삽**해서(Wynn의 ε-알고리즘) 나누기를 끝까지 했을 때의 값을 어림해요. 무한 구간은 변수를 바꿔 (0, 1]의 적분으로 만들어요.

입력에 따라 QUADPACK의 루틴 일곱 가운데 하나를 써요.

| 입력 | 쓰는 방법 |
|---|---|
| 유한 구간 | 21점 규칙의 적응 나누기와 외삽 |
| 무한 구간 | (0, 1]로 바꾼 뒤 15점 규칙의 적응 나누기와 외삽 |
| `points` | 중단점으로 나눈 구간에서 시작하는 같은 방법 |
| `weight='cos'`·`'sin'`, 유한 구간 | 진동이 많은 구간은 모멘트를 쓰는 25점 Clenshaw–Curtis 규칙 |
| `weight='cos'`·`'sin'`, 반무한 구간 | 주기마다 적분하고 그 합을 외삽 |
| `weight='alg'`, `'alg-loga'`, `'alg-logb'`, `'alg-log'` | 끝점의 대수·로그 가중치를 정확히 적분하는 규칙 |
| `weight='cauchy'` | 1/(x − c)의 주값을 정확히 다루는 규칙 |

## 기본 사용

```python
>>> import math
>>> import stardust as sd
>>> r = sd.integrate.quad(math.exp, 0, 1)
>>> r
IntegrateResult(integral=1.71828, error=1.90768e-14, converged=True, nfev=21)
>>> r.integral - (math.e - 1)
2.220446049250313e-16
```

$\int_0^1 e^x\,dx = e - 1$을 21점 규칙 한 번으로 끝냈어요. 결과는 scipy의 튜플처럼 둘로 풀려요.

```python
>>> integral, error = sd.integrate.quad(math.exp, 0, 1)
>>> integral, error
(1.7182818284590453, 1.9076760487502457e-14)
```

f는 Python `float` 하나를 받아요. `math`의 함수나 `lambda`를 그대로 쓸 수 있어요. 상수가 필요하면 클로저로 넘겨요(`args`는 없어요).

```python
>>> k = 3.0
>>> sd.integrate.quad(lambda x: x**k, 0, 2)
IntegrateResult(integral=4, error=4.44089e-14, converged=True, nfev=21)
```

## 인자

### func, a, b

`a`와 `b`는 실수이고 ±inf를 받아요. `a > b`면 끝을 바꿔 계산하고 부호를 바꿔요(`error`는 그대로예요). `a == b`면 f를 부르지 않고 0이에요. 옵션의 검사는 그때도 해요.

```python
>>> sd.integrate.quad(math.exp, 1, 0)
IntegrateResult(integral=-1.71828, error=1.90768e-14, converged=True, nfev=21)
>>> sd.integrate.quad(math.exp, 1, 1)
IntegrateResult(integral=0, error=0, converged=True, nfev=0)
>>> sd.integrate.quad(math.exp, 1, 1, limit=0)
Traceback (most recent call last):
    ...
ValueError: quad(): 'limit' must be >= 1
```

f를 부르는 점은 늘 구간 안이에요. 21점과 15점 규칙에는 끝점이 없어서, 끝에서 정의되지 않는 함수($x^{-1/2}$의 0)도 그대로 줄 수 있어요. 가중 함수의 규칙(Clenshaw–Curtis)은 끝점도 부를 수 있으니, `weight`를 줄 때는 f가 끝에서도 유한한 값을 돌려주게 해요.

### atol, rtol

오차의 어림이 max(`atol`, `rtol`·|적분|) 이하가 되면 멈춰요. 둘 가운데 느슨한 쪽이 정하므로, 더 정확하게 하려면 둘 다 줄여요. 기본값은 둘 다 1.49×10⁻⁸이에요.

```python
>>> f = lambda x: x**-0.5 * math.log(1 / x)
>>> r = sd.integrate.quad(f, 0, 1)
>>> r.integral - 4, r.error
(-1.687538997430238e-14, 2.682298827494378e-13)
>>> sd.integrate.quad(math.sin, 0, 2 * math.pi, atol=0, rtol=1e-10).status
2
```

적분이 0에 가까우면 상대 허용오차만으로는 이룰 수 없어서 `status` 2(반올림)로 멈춰요. 허용오차의 뜻과 함수마다의 기본값은 [기본 개념](/api/integrate/basics/#atol과-rtol)에 있어요.

### limit

나눌 수 있는 구간 수의 상한이에요. 기본 50으로 모자라면 `status` 1이고 `message`가 그렇게 알려요. 빠르게 진동하거나 꺾인 곳이 많은 함수에서 늘려요.

```python
>>> g = lambda x: math.cos(200 * x) / (1 + x * x)
>>> sd.integrate.quad(g, 0, 10)
IntegrateResult(integral=0.000530163, error=0.060999, converged=False, nfev=2079)
>>> r = sd.integrate.quad(g, 0, 10, limit=500)
>>> r, r.n_intervals
(IntegrateResult(integral=4.60595e-05, error=1.4534e-08, converged=True, nfev=7917), 189)
```

구간 하나에 21점이라 `nfev`는 구간 수 × 42 − 21이에요. 이 함수는 [진동](#진동)의 가중 함수로 훨씬 싸게 풀려요.

### points

구간 안의 어려운 곳(특이점, 불연속, 꺾인 곳, 봉우리)의 자리를 알면 `points`로 줘요. `quad`는 그 점에서 구간을 처음부터 나눠 시작해서, 그 점이 늘 구간의 끝에 오게 해요. 21점 규칙은 끝점을 부르지 않으니 그 점에서 정의되지 않는 함수도 돼요.

```python
>>> h = lambda x: 1 / math.sqrt(abs(x - 0.5))
>>> sd.integrate.quad(h, 0, 1)
Traceback (most recent call last):
    ...
ZeroDivisionError: division by zero
>>> sd.integrate.quad(h, 0, 1, points=[0.5])
IntegrateResult(integral=2.82843, error=3.27294e-13, converged=True, nfev=462)
```

나누다가 가운데 0.5를 부른 첫 호출은 0으로 나눴고, `points`를 준 둘째 호출은 $2\sqrt2$를 맞혔어요. 점은 정렬하고 겹친 것을 빼고 (a, b) 안의 것만 써요. 리스트, `sd.ndarray`, numpy 배열을 받고, 수 하나는 받지 않아요.

```python
>>> step = lambda x: 1.0 if x < 1/3 else 0.0
>>> r = sd.integrate.quad(step, 0, 1, points=[0.9, 1/3, 1/3, 2.0, 0.0])
>>> r.intervals
array([[               0.0, 0.3333333333333333],
       [               0.9,                1.0],
       [0.3333333333333333,                0.9]], dtype=float64)
>>> sd.integrate.quad(step, 0, 1, points=0.5)
Traceback (most recent call last):
    ...
TypeError: quad(): 'points' must be a sequence of numbers or None, not float
```

남은 점은 `limit`보다 적어야 하고, `points`는 유한 구간만 받아요.

```python
>>> sd.integrate.quad(step, 0, 1, points=[0.1, 0.2, 0.3], limit=3)
Traceback (most recent call last):
    ...
ValueError: quad(): the number of break points (3) must be less than 'limit' (3)
>>> sd.integrate.quad(step, 0, math.inf, points=[1.0])
Traceback (most recent call last):
    ...
ValueError: quad(): 'points' cannot be used with an infinite range
```

### weight와 wvar

적분이 $\int_a^b w(x)\,f(x)\,dx$ 꼴이고 w가 아래의 가중 함수 가운데 하나면, w를 `weight`로 떼어 내고 f만 줘요. QUADPACK은 w를 정확히 적분하는 규칙을 써서, w가 빠르게 진동하거나 끝에서 무한대로 가도 f가 매끄러우면 쉽게 풀어요.

| `weight` | w(x) | `wvar` |
|---|---|---|
| `'cos'` | $\cos(\omega x)$ | ω |
| `'sin'` | $\sin(\omega x)$ | ω |
| `'alg'` | $(x - a)^\alpha (b - x)^\beta$ | (α, β), 둘 다 > −1 |
| `'alg-loga'` | $(x - a)^\alpha (b - x)^\beta \log(x - a)$ | (α, β) |
| `'alg-logb'` | $(x - a)^\alpha (b - x)^\beta \log(b - x)$ | (α, β) |
| `'alg-log'` | $(x - a)^\alpha (b - x)^\beta \log(x - a) \log(b - x)$ | (α, β) |
| `'cauchy'` | $1/(x - c)$ (주값) | c, a와 b가 아닌 수 |

- `'cos'`·`'sin'`은 유한 구간과 반무한 구간 $[a, \infty)$, $(-\infty, b]$를 받아요. 실수 전체는 받지 않으니 0에서 나눠 두 번 불러요.
- `'alg…'`와 `'cauchy'`는 유한 구간만 받아요.
- 가중 함수와 `points`는 함께 쓸 수 없어요.

끝점의 대수 특이점 $1/\sqrt{x(1 - x)}$의 적분은 π예요. 특이점을 w로 떼어 내면 f는 상수 1이에요.

```python
>>> r = sd.integrate.quad(lambda x: 1.0, 0, 1, weight='alg', wvar=(-0.5, -0.5))
>>> r, r.integral - math.pi
(IntegrateResult(integral=3.14159, error=1.01252e-13, converged=True, nfev=50), 8.881784197001252e-16)
>>> sd.integrate.quad(math.exp, 0, 1, weight='alg', wvar=(-0.5, 0.0))
IntegrateResult(integral=2.9253, error=4.80438e-14, converged=True, nfev=40)
>>> sd.integrate.quad(lambda x: math.exp(x) / math.sqrt(x), 0, 1)
IntegrateResult(integral=2.9253, error=4.11261e-10, converged=True, nfev=315)
```

같은 $\int_0^1 e^x/\sqrt x\,dx$를 가중 함수로는 40점, 그냥은 315점에 풀었고 오차의 어림도 네 자리 작아요. 로그 가중치도 같아요. $\int_0^1 \log x \log(1 - x)\,dx = 2 - \pi^2/6$이에요.

```python
>>> sd.integrate.quad(lambda x: 1.0, 0, 1, weight='alg-log', wvar=(0.0, 0.0))
IntegrateResult(integral=0.355066, error=7.81548e-14, converged=True, nfev=50)
>>> 2 - math.pi**2 / 6
0.3550659331517736
```

`'cauchy'`는 $\int_a^b f(x)/(x - c)\,dx$의 **코시 주값**이에요. c에서 피적분 함수가 양쪽으로 무한대로 가서 보통의 적분은 없지만, c 둘레를 대칭으로 비운 적분의 극한은 있어요. $\int_{-1}^{1} dx/(x - 0.3) = \log(0.7/1.3)$이에요.

```python
>>> sd.integrate.quad(lambda x: 1.0, -1, 1, weight='cauchy', wvar=0.3)
IntegrateResult(integral=-0.619039, error=0, converged=True, nfev=25)
>>> math.log(0.7 / 1.3)
-0.6190392084062235
```

`wvar`는 가중 함수와 맞는 꼴이어야 해요.

```python
>>> sd.integrate.quad(lambda x: 1.0, 0, 1, weight='alg', wvar=-0.5)
Traceback (most recent call last):
    ...
TypeError: quad(): 'wvar' must be a pair (alpha, beta) of real numbers, not float
>>> sd.integrate.quad(lambda x: 1.0, 0, 1, weight='alg', wvar=(-1.0, 0.0))
Traceback (most recent call last):
    ...
ValueError: quad(): 'wvar' (alpha, beta) must both be > -1 for weight='alg'
>>> sd.integrate.quad(math.exp, 0, 1, weight='cauchy', wvar=1.0)
Traceback (most recent call last):
    ...
ValueError: quad(): 'wvar' must not equal 'a' or 'b' with weight='cauchy'
>>> sd.integrate.quad(math.exp, 0, 1, weight='Cos', wvar=1.0)
Traceback (most recent call last):
    ...
ValueError: quad(): 'weight' must be one of 'cos', 'sin', 'alg', 'alg-loga', 'alg-logb', 'alg-log', 'cauchy', not 'Cos'
```

### max_p1과 limlst

`'cos'`·`'sin'`의 규칙은 구간마다 체비쇼프 모멘트를 계산하는데, 나누기의 수준마다 한 벌을 기억해 다시 써요. `max_p1`(기본 50)은 기억하는 수준 수의 상한이에요. 기본값이면 $|\omega|(b - a)$가 $2^{51}$을 넘는 구간에서만 닿아서, 바꿀 일은 거의 없어요.

`limlst`(기본 50, 3 이상)는 반무한 구간의 `'cos'`·`'sin'`이 쓰는 주기 수의 상한이에요. 닿으면 `status` 1이에요. f가 느리게 줄수록 주기가 많이 필요해요.

```python
>>> sd.integrate.quad(lambda x: 1 / (1 + x), 0, math.inf, weight='cos', wvar=1.0, limlst=3).status
1
```

둘 다 쓰이지 않는 곳에서는 기본값만 받아요.

```python
>>> sd.integrate.quad(math.exp, 0, 1, weight='alg', wvar=(0.0, 0.0), max_p1=10)
Traceback (most recent call last):
    ...
ValueError: quad(): 'max_p1' is only used with weight='cos' or 'sin'
>>> sd.integrate.quad(math.exp, 0, 1, weight='cos', wvar=1.0, limlst=10)
Traceback (most recent call last):
    ...
ValueError: quad(): 'limlst' is only used with weight='cos' or 'sin' on an infinite range
```

### complex_func

f가 복소수를 돌려주면 `complex_func=True`를 줘요. 실수부의 `quad`를 마친 뒤 허수부의 `quad`를 해서, 같은 점들에서 f를 두 번 불러요. `integral`과 `error`는 `complex`이고 두 부분의 결과는 `real`, `imag` 필드예요.

```python
>>> import cmath
>>> z = sd.integrate.quad(lambda x: cmath.exp(1j * x), 0, math.pi, complex_func=True)
>>> z.integral, z.nfev
((4.9225526349740854e-17+2j), 42)
>>> sd.integrate.quad(lambda x: cmath.exp(1j * x), 0, math.pi)
Traceback (most recent call last):
    ...
TypeError: quad(): 'func' must return a real number, not complex
```

## 무한 구간

끝이 ±inf면 변수를 바꿔 (0, 1]의 적분으로 만들어요. $[a, \infty)$는 $x = a + (1 - t)/t$, $(-\infty, b]$는 $x = b - (1 - t)/t$, 실수 전체는 양쪽을 함께 써요.

```python
>>> sd.integrate.quad(lambda x: math.exp(-x * x), -math.inf, math.inf)
IntegrateResult(integral=1.77245, error=1.42026e-08, converged=True, nfev=270)
>>> sd.integrate.quad(lambda x: 1 / x**2, 1, math.inf)
IntegrateResult(integral=1, error=1.11022e-14, converged=True, nfev=15)
>>> r = sd.integrate.quad(lambda x: 1 / x, 1, math.inf)
>>> r.converged, r.status
(False, 1)
```

$\int_1^\infty dx/x$는 발산해서 수렴하지 못해요. 결과의 `intervals`는 바꾼 변수 t의 구간이에요.

<Callout type="warn" title="0에서 먼 봉우리는 변환 뒤에 좁아져요">

변수를 바꾸면 x가 큰 곳이 t의 0 근처로 눌려요. 그래서 0에서 멀리 있는 봉우리는 t에서 아주 좁아지고, 처음 15점이 모두 놓치면 0을 수렴으로 알려요. 봉우리의 자리를 알면 유한 구간과 나머지로 나눠 불러요.

</Callout>

```python
>>> bump = lambda x: math.exp(-(x - 1000)**2)
>>> sd.integrate.quad(bump, 0, math.inf)
IntegrateResult(integral=0, error=0, converged=True, nfev=15)
>>> head = sd.integrate.quad(bump, 0, 2000)
>>> tail = sd.integrate.quad(bump, 2000, math.inf)
>>> head.integral + tail.integral, math.sqrt(math.pi)
(1.772453850905503, 1.7724538509055159)
```

반무한 구간의 진동하는 적분 $\int_0^\infty \cos(\omega x) f(x)\,dx$는 `weight='cos'`가 맞아요([진동](#진동)).

## 어려운 피적분 함수

### 끝점의 특이점

끝점에서 무한대로 가거나 도함수가 무한대인 함수($x^{-1/2}$, $\log x$, $\sqrt x$)는 그대로 줘도 돼요. 끝 쪽만 거듭 나누고 외삽으로 마무리해요.

```python
>>> sd.integrate.quad(lambda x: math.log(x)**2, 0, 1)
IntegrateResult(integral=2, error=9.76996e-15, converged=True, nfev=315)
```

특이점의 꼴이 $(x - a)^\alpha$나 로그로 정확히 알려져 있으면 `weight='alg…'`로 떼어 내는 편이 점을 훨씬 적게 써요([weight와 wvar](#weight와-wvar)). 같은 꼴의 적분이 많으면 끝점 특이점에 강한 [`tanhsinh`](/api/integrate/tanhsinh/)도 좋아요.

### 구간 안의 특이점, 불연속, 꺾인 곳

구간 **안**의 문제는 그 자리를 `points`로 주는 것이 가장 좋아요. 주지 않아도 `quad`가 그 둘레를 거듭 나눠 찾아가지만 점이 많이 들고, 정수마다 계단이 있는 $\lfloor x \rfloor$처럼 불연속이 많으면 구간 50개로 모자라요.

```python
>>> fl = lambda x: float(math.floor(x))
>>> r = sd.integrate.quad(fl, 0, 10.5)
>>> r.converged, r.status, r.integral
(False, 1, 49.87592114975874)
>>> sd.integrate.quad(fl, 0, 10.5, points=range(1, 11))
IntegrateResult(integral=50, error=5.55112e-13, converged=True, nfev=231)
```

참값은 $0 + 1 + \dots + 9 + 10 \times 0.5 = 50$이에요. 중단점을 주면 구간마다 상수라 한 번에 맞아요. `points`는 `range`도 받아요.

### 좁은 봉우리

`quad`는 처음 21점으로 함수를 봐요. 봉우리가 그 점들 사이에 숨을 만큼 좁으면 함수가 0인 줄 알고, 오차의 어림도 0이라 틀린 값을 **수렴**으로 알려요. 결과만으로는 알 수 없는 실패라 가장 조심할 곳이에요.

```python
>>> spike = lambda x: math.exp(-((x - 0.3) / 1e-4)**2)
>>> sd.integrate.quad(spike, 0, 1)
IntegrateResult(integral=0, error=0, converged=True, nfev=21)
>>> 1e-4 * math.sqrt(math.pi)
0.0001772453850905516
```

봉우리의 자리를 알면 봉우리 전체를 덮는 작은 구간을 `points`로 줘요. 점 하나만 주면 봉우리가 큰 구간의 끝에 붙어 여전히 놓쳐요. 작은 구간이 봉우리보다 좁으면 끝자락이 큰 구간에 남아서, 역시 틀린 값을 수렴으로 알려요.

```python
>>> sd.integrate.quad(spike, 0, 1, points=[0.3]).integral
6.52475293032788e-22
>>> sd.integrate.quad(spike, 0, 1, points=[0.2999, 0.3001]).integral
0.00014936482656248377
>>> sd.integrate.quad(spike, 0, 1, points=[0.299, 0.301])
IntegrateResult(integral=0.000177245, error=1.79419e-10, converged=True, nfev=273)
```

폭 $10^{-4}$의 봉우리에 [0.299, 0.301]을 주니 상대 $3 \times 10^{-13}$으로 맞았어요. 봉우리의 자리를 모르면 함수를 촘촘한 격자에서 먼저 계산해 보고 찾아요.

### 진동

$\cos(200x)$처럼 구간 안에서 수백 번 진동하는 함수는 21점 규칙 하나가 진동 몇 번만 따라갈 수 있어서 구간이 많이 필요해요. 위의 [`limit`](#limit)에서 $\cos(200x)/(1 + x^2)$은 기본 50개로 모자랐고 189개(7,917점)가 필요했어요. 진동이 $\cos(\omega x)$나 $\sin(\omega x)$의 꼴이면 `weight`로 떼어 내요.

```python
>>> sd.integrate.quad(lambda x: 1 / (1 + x * x), 0, 10, weight='cos', wvar=200.0)
IntegrateResult(integral=4.60595e-05, error=3.65951e-09, converged=True, nfev=125)
```

125점으로 같은 값을 냈어요. 반무한 구간에서도 돼요. $\int_0^\infty \cos x/(1 + x^2)\,dx = \pi/(2e)$, $\int_0^\infty \sin x / x\,dx = \pi/2$예요.

```python
>>> r = sd.integrate.quad(lambda x: 1 / (1 + x * x), 0, math.inf, weight='cos', wvar=1.0)
>>> r, r.integral - math.pi / (2 * math.e)
(IntegrateResult(integral=0.577864, error=1.37226e-08, converged=True, nfev=410), -3.3389957465601583e-12)
>>> head = sd.integrate.quad(lambda x: math.sin(x) / x if x else 1.0, 0, math.pi)
>>> tail = sd.integrate.quad(lambda x: 1 / x, math.pi, math.inf, weight='sin', wvar=1.0)
>>> head.integral + tail.integral - math.pi / 2, tail.n_cycles
(1.0763168134531043e-11, 14)
```

$\sin x/x$는 둘로 나눴어요. 가중 함수로 떼어 내면 f가 $1/x$인데, 이것은 0에서 무한대이고 Clenshaw–Curtis 규칙은 끝점도 부르기 때문이에요. 0 둘레의 $[0, \pi]$는 그냥 `quad`로, 나머지는 `weight='sin'`으로 계산했어요.

$\sin x/x$를 그냥 무한 구간으로 주면 수렴하지 못해요. 진동이 줄지 않고 이어지는 적분은 변수를 바꿔도 t = 0 둘레에서 끝없이 진동하기 때문이에요.

```python
>>> sd.integrate.quad(lambda x: math.sin(x) / x if x else 1.0, 0, math.inf).status
5
```

반무한 구간의 `'cos'`·`'sin'`은 주기마다 적분한 합을 외삽하는 방법이라 상대 허용오차를 쓰지 않아요. `atol`만 쓰고, `atol`은 0보다 커야 해요. 기본값이 아닌 `rtol`은 에러예요.

```python
>>> sd.integrate.quad(lambda x: 1 / (1 + x * x), 0, math.inf, weight='cos', wvar=1.0, rtol=1e-10)
Traceback (most recent call last):
    ...
ValueError: quad(): 'rtol' is not used with weight='cos' on an infinite range (QAWF uses 'atol' only)
>>> sd.integrate.quad(lambda x: 1 / (1 + x * x), -math.inf, math.inf, weight='cos', wvar=1.0)
Traceback (most recent call last):
    ...
ValueError: quad(): weight='cos' cannot be used on (-inf, inf)
```

### NaN과 inf

f가 NaN을 돌려주면 적분값이 NaN이 되고 `converged=False`예요. 그런데 f가 inf를 돌려주면 적분값 inf를 `converged=True`로 알려요(scipy와 같아요). 값을 쓰기 전에 유한한지 확인해요.

```python
>>> sd.integrate.quad(lambda x: math.nan, 0, 1).converged
False
>>> sd.integrate.quad(lambda x: math.inf, 0, 1)
IntegrateResult(integral=inf, error=inf, converged=True, nfev=21)
```

## 결과 읽기

결과는 `integral`, `error`, `converged`, `status`, `message`, `nfev`와 쓴 구간 `intervals`, `interval_integrals`, `interval_errors`, `n_intervals`예요. 구간은 오차의 어림이 큰 것부터라, 맨 앞이 `quad`가 다음에 나눴을 구간이에요. 봉우리 바로 옆 [0.3125, 0.375]가 그래요.

```python
>>> r = sd.integrate.quad(lambda x: 1 / ((x - 0.3)**2 + 1e-4), 0, 1)
>>> r.n_intervals, r.intervals[0]
(8, array([0.3125,  0.375], dtype=float64))
```

`status`의 번호와 글, 무한 구간 cos·sin의 주기 필드, `complex_func=True`의 `real`·`imag`, `summary()`의 표는 [결과 객체 읽기](/api/integrate/results/)에 있어요.

## 정확도와 비용

- **정확도**: 결과는 "오차의 어림이 허용오차 안"인 값이에요. 매끄러운 함수와 끝점 특이점에서 어림은 참 오차보다 대개 몇 자리 커요. 여러 무리의 시험 문제를 Arb(구간 산술)로 만든 참값과 견주면, 수렴했다고 알린 결과는 아주 좁은 봉우리를 놓친 경우와 실수의 끝으로 낸 문제를 정확한 끝의 적분으로 외삽한 한 경우 말고는 참 오차가 어림 안이에요. 가중 함수의 결과는 어림에 값의 끝자리 몇 ε|I|를 더한 것 안이에요(Clenshaw–Curtis 규칙의 어림에는 반올림의 하한이 없어서예요).
- **비용**: 구간 하나에 21점(무한 구간 15점, 가중 함수 15·25점)이고, f를 점 하나씩 Python으로 불러요. 시간은 대부분 f의 몫이라 `nfev`로 견줄 수 있어요. 같은 꼴의 적분을 많이 풀면 f를 배열로 부르는 [`tanhsinh`](/api/integrate/tanhsinh/)이나, 값이 여럿이면 [`quad_vec`](/api/integrate/quad_vec/)을 고려해요.
- **스레드**: f가 Python이라 GIL을 쥔 채 돌아요. 결과는 스레드 수와 상관없이 같은 비트예요.

## scipy를 아는 분께

`scipy.integrate.quad`와 같은 QUADPACK 루틴을 같은 방식으로 골라요. 지금은 f를 부르는 점과 차례, 적분값, 오차, `nfev`, `status`, 글, 구간이 scipy 1.18.1과 비트까지 같아요(약속은 아니에요).

- **이름**: `epsabs`·`epsrel`은 `atol`·`rtol`, `maxp1`은 `max_p1`이에요. scipy의 이름은 `TypeError`예요.
- **결과**: 튜플 `(y, abserr)` 대신 둘로 풀리는 결과 객체예요. `full_output`은 없고 `infodict`의 값은 필드예요. 경고 대신 `converged`·`status`·`message`예요.
- **없는 것**: `args`(클로저로 넘겨요), `full_output`, `wopts`(미리 계산한 모멘트; 한 호출 안에서는 모멘트를 이미 기억해 다시 써요)
- **검사가 엄격해요**: 음수 `epsabs`, 수 하나인 `points`는 받지 않아요. 가중 함수와 함께 준 `points`, 쓰이지 않는 `max_p1`·`limlst`, 무한 구간 cos·sin의 `rtol`은 scipy가 경고하거나 조용히 버리지만 여기서는 `ValueError`예요. `a == b`여도 옵션을 검사해요.
- **scipy가 틀리는 곳은 따르지 않아요**: `max_p1`의 모멘트를 다 쓴 뒤의 구간(scipy는 틀린 모멘트로 틀린 값을 수렴으로 알려요; 기본값에서는 $|\omega|(b - a) > 2^{51}$일 때만), 반무한 구간 cos의 ω = 0(scipy는 a와 상관없이 [0, ∞)를 적분해요), $|\omega| \ge 2^{30}$의 반무한 구간(scipy는 주기가 32비트로 넘쳐요).
