## 무엇을 하나요

`nquad`는 변수가 몇 개든 [`quad`](/api/integrate/quad/)를 겹쳐 적분해요. 가장 바깥 `quad`가 바깥 변수를 정할 때마다 그 안의 `quad`가 다음 변수를 적분하고, 가장 안쪽 `quad`만 f를 불러요.

$$\int_{\text{ranges}[n]} \cdots \int_{\text{ranges}[1]} \int_{\text{ranges}[0]} f(x_0, x_1, \dots, x_n)\,dx_0\,dx_1 \cdots dx_n$$

[`dblquad`](/api/integrate/dblquad/), [`tplquad`](/api/integrate/tplquad/)와 같은 계산이에요. 다른 점은 차원 수에 제한이 없고, 층마다 `quad`의 옵션을 따로 줄 수 있다는 것이에요.

## 기본 사용

`ranges`는 안쪽 변수부터예요. `func`의 인자 차례와 같아요.

```python
>>> import math
>>> import stardust as sd
>>> sd.integrate.nquad(lambda x, y: x * y, [(0, 1), (0, 2)])
IntegrateResult(integral=1, error=1.11022e-14, converged=True, nfev=441)
>>> sd.integrate.nquad(lambda x, y, z, w: x * y * z * w, [(0, 1)] * 4)
IntegrateResult(integral=0.0625, error=5.51503e-15, converged=True, nfev=194481)
```

첫 줄은 x ∈ [0, 1], y ∈ [0, 2]의 $\int\int xy = 1$이에요. 둘째 줄의 4차원은 $21^4 = 194{,}481$번 불렀어요. 층마다 점 수가 곱해지니 차원이 높으면 f를 아주 많이 불러요.

## 인자

### ranges

항목은 수의 쌍이거나 쌍을 돌려주는 함수예요. 함수는 **그보다 바깥 변수들을 가까운 것부터** 받아요. 3차원이면 `ranges[0](x1, x2)`, `ranges[1](x2)`이고 `ranges[2]`는 쌍이에요.

```python
>>> seen = []
>>> def inner(y, z):
...     seen.append((y, z))
...     return (0, y + z)
>>> r = sd.integrate.nquad(lambda x, y, z: x * y * z, [inner, lambda z: (0, z), (0, 1)])
>>> r
IntegrateResult(integral=0.118056, error=2.19168e-14, converged=True, nfev=9261)
>>> seen[:2]
[(0.25, 0.5), (0.006523367870707064, 0.5)]
```

x는 0에서 y + z까지, y는 0에서 z까지, z는 0에서 1까지예요. 범위 함수가 돌려준 것도 같은 규칙으로 검사해요.

```python
>>> sd.integrate.nquad(lambda x, y: x * y, [lambda y: (0, math.nan), (0, 1)])
Traceback (most recent call last):
    ...
ValueError: nquad(): the range of 'ranges[0]' must not be NaN
>>> sd.integrate.nquad(lambda x, y: x * y, (0, 1))
Traceback (most recent call last):
    ...
TypeError: nquad(): 'ranges[0]' must be a pair (lo, hi) of numbers, not int
```

둘째 호출은 `ranges` 자체를 쌍으로 줬어요. 변수 하나여도 `[(0, 1)]`처럼 쌍의 리스트로 줘요.

### opts

`opts`는 층마다의 `quad` 옵션이에요. 키는 `quad`의 이름 `atol`, `rtol`, `limit`, `points`, `weight`, `wvar`예요.

- `None`(기본값): 모든 층이 `quad`의 기본값이에요.
- dict 하나: 모든 층에 같은 옵션이에요.
- `ranges`와 길이가 같은 시퀀스: 층마다(안쪽부터) dict이거나, 범위 함수와 같은 인자를 받아 dict를 돌려주는 함수예요.

```python
>>> sd.integrate.nquad(lambda x, y: x * y, [(0, 1), (0, 1)], opts={'atol': 1e-12, 'rtol': 0})
IntegrateResult(integral=0.25, error=5.53906e-15, converged=True, nfev=441)
>>> sd.integrate.nquad(lambda x, y: x * y, [(0, 1), (0, 1)], opts={'epsabs': 1e-10})
Traceback (most recent call last):
    ...
ValueError: nquad(): 'opts' has no option 'epsabs' (scipy's 'epsabs' is 'atol'); the options are atol, rtol, limit, points, weight, wvar
>>> sd.integrate.nquad(lambda x, y: x * y, [(0, 1), (0, 1)], opts=[{}, {}, {}])
Traceback (most recent call last):
    ...
ValueError: nquad(): 'opts' must have one entry per range (2), not 3
```

### 옵션 함수: 바깥 변수에 따라 바뀌는 중단점

옵션을 함수로 주면 안쪽 적분의 어려운 곳을 바깥 변수에 따라 알려 줄 수 있어요. $|x - y|$는 x = y에서 꺾여요. 안쪽 x의 적분에 그 자리를 `points=[y]`로 주면 f를 50분의 1만 불러요.

```python
>>> kink = lambda x, y: abs(x - y)
>>> sd.integrate.nquad(kink, [(0, 1), (0, 1)])
IntegrateResult(integral=0.333333, error=1.48537e-08, converged=True, nfev=43365)
>>> sd.integrate.nquad(kink, [(0, 1), (0, 1)], opts=[lambda y: {'points': [y]}, {}])
IntegrateResult(integral=0.333333, error=5.52706e-15, converged=True, nfev=882)
```

오차의 어림도 $10^{-8}$에서 $10^{-15}$로 줄었어요. 옵션 함수가 돌려준 dict도 같은 규칙으로 검사해요.

### 층마다의 가중 함수

`weight`와 `wvar`도 층마다 받아요. 안쪽 적분이 빠르게 진동하면 그 층에만 가중 함수를 줘요.

```python
>>> osc = lambda x, y: math.cos(200 * x) / (1 + x * x)
>>> sd.integrate.nquad(osc, [(0, 10), (0, 1)]).status
1
>>> sd.integrate.nquad(lambda x, y: 1 / (1 + x * x), [(0, 10), (0, 1)],
...                    opts=[{'weight': 'cos', 'wvar': 200.0}, {}])
IntegrateResult(integral=4.60595e-05, error=3.65951e-09, converged=True, nfev=2625)
```

첫 호출은 안쪽 `quad`가 구간 50개로 모자라서 `status` 1이에요. 끝이 범위 함수로 바뀌는 층이면 가중 함수의 범위 검사(무한 구간의 `'alg'` 등)도 바깥 점마다 해요.

## 결과 읽기

필드는 `integral`, `error`, `converged`, `status`, `message`, `nfev`예요.

- `error`는 모든 층의 모든 `quad`가 낸 오차 어림 가운데 가장 큰 것이에요. 안쪽 적분의 오차가 바깥에 더해지는 것은 셈하지 않으니 엄밀한 상한이 아니에요.
- `nfev`는 f를 부른 수(가장 안쪽 `quad`들의 `nfev` 합)예요. 범위 함수와 옵션 함수의 호출은 세지 않아요.
- `converged`는 모든 `quad`가 수렴했을 때이고, `status`·`message`는 끝나는 차례로(안쪽이 먼저) 처음 수렴하지 못한 `quad`의 것이에요. 안쪽의 실패가 바깥 실패의 까닭인 경우가 많아서예요. 모든 `quad`가 정상으로 끝났어도 적분값이나 오차가 유한하지 않으면 `status` −3, `converged=False`예요.
- 구간 정보는 없어요.

```python
>>> r = sd.integrate.nquad(osc, [(0, 10), (0, 1)])
>>> r.converged, r.status, r.message.split('.')[0]
(False, 1, 'The maximum number of subdivisions (50) has been achieved')
```

## 언제 쓰나요

- 4차원 이상이거나, 층마다 다른 옵션이 필요하면 `nquad`예요. 2·3차원에서 옵션이 필요 없으면 [`dblquad`](/api/integrate/dblquad/), [`tplquad`](/api/integrate/tplquad/)가 같은 계산을 더 익숙한 꼴로 해요.
- 영역이 상자이고 f를 배열로 계산할 수 있으면 [`cubature`](/api/integrate/cubature/)가 대개 훨씬 빨라요. 겹친 적분은 f를 점 하나씩 Python으로 부르고, 그 수가 차원마다 곱해져요.

## 정확도와 비용

- **정확도**: 층마다 `quad`의 정확도예요. 시험 문제의 겹친 적분을 Arb(구간 산술)로 만든 참값과 견주면 상대오차가 $5 \times 10^{-15}$ 안이고, 참 오차는 오차 어림의 1% 안이에요.
- **비용**: 모든 층이 C++ 안에서 겹쳐 돌고 f, 범위 함수, 옵션 함수만 Python으로 불러요. 시간은 거의 `nfev` × f 한 번의 시간이에요.
- **스레드**: f가 Python이라 GIL을 쥔 채 돌아요. 결과는 스레드 수와 상관없이 같은 비트예요.

## scipy를 아는 분께

`scipy.integrate.nquad`와 같은 겹침, 같은 순서예요. 범위 함수와 옵션 함수도 scipy처럼 바깥 변수를 가까운 것부터 받아요. 지금은 f를 부르는 점과 차례, 적분값, 오차, `nfev`가 scipy 1.18.1과 비트까지 같아요(약속은 아니에요).

- `opts`의 키는 `quad`의 이름 `atol`·`rtol`이에요. `epsabs`·`epsrel`을 주면 이쪽 이름을 알려 주는 `ValueError`예요(scipy는 모르는 키에 `TypeError`예요).
- `args`와 `full_output`은 없어요. 상수는 클로저로 넘기고, `full_output`의 `neval`은 `nfev` 필드예요.
- 튜플 `(y, abserr)` 대신 둘로 풀리는 결과 객체예요. scipy가 안쪽 `quad`마다 내는 경고는 `converged`·`status`·`message`로 알려요.
- 적분값이나 오차가 유한하지 않으면 `status` −3이에요. scipy는 같은 경우에 경고 없이 `(inf, inf)` 같은 값을 돌려줘요.
- `opts`로 `'cos'`·`'sin'` 가중 함수를 준 층은 [`quad`](/api/integrate/quad/#scipy를-아는-분께)처럼 오차의 어림에 반올림의 하한이 있어서, 그 어림이 scipy보다 작지 않아요.

```python
>>> import scipy.integrate as si
>>> si.nquad(kink, [(0, 1), (0, 1)], opts=[lambda y: {'points': [y]}, {}])
(0.33333333333333337, 5.527059882783348e-15)
>>> tuple(sd.integrate.nquad(kink, [(0, 1), (0, 1)], opts=[lambda y: {'points': [y]}, {}]))
(0.33333333333333337, 5.527059882783348e-15)
```
