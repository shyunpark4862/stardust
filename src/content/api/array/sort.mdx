## 한눈에 보기

`sort`는 배열의 값을 작은 것부터 차례로 늘어놓은 **새 배열**을 돌려줘요. 원래 배열은 바뀌지 않아요.

```python
>>> import stardust as sd
>>> x = sd.asarray([30, 10, 20])
>>> sd.sort(x)
array([10, 20, 30], dtype=int64)
>>> x
array([30, 10, 20], dtype=int64)
```

`argsort`는 값이 아니라 **위치**를 돌려줘요. "정렬된 결과의 첫 자리에는 원래 배열의 몇 번째 원소가 오는가"를 차례로 적은 배열이에요.

```python
>>> sd.argsort(x)
array([1, 2, 0], dtype=int64)
```

가장 작은 값 `10`은 원래 1번 자리에, 그다음 `20`은 2번 자리에, 가장 큰 `30`은 0번 자리에 있다는 뜻이에요.

<Fig caption="argsort의 결과는 '가져올 자리'의 목록이에요. 그 순서대로 x에서 값을 꺼내면 정렬된 배열이 돼요.">
  <ArrayFig name="x" data={[30, 10, 20]} tones={['', 'b', '']} note="자리 0, 1, 2" />
  <Op note="argsort">→</Op>
  <ArrayFig name="sd.argsort(x)" data={[1, 2, 0]} tones={['b', '', '']} note="가져올 자리" />
  <Op note="x[...]">→</Op>
  <ArrayFig name="sd.sort(x)" data={[10, 20, 30]} tones={['b', '', '']} note="정렬된 값" />
</Fig>

그래서 `argsort`의 결과로 원래 배열을 인덱싱하면 `sort`와 같은 결과가 나와요.

```python
>>> x[sd.argsort(x)]
array([10, 20, 30], dtype=int64)
```

## argsort는 언제 쓰나요

값만 정렬하면 되는 경우에는 `sort`로 충분해요. `argsort`가 필요한 때는 **한 배열의 순서로 다른 배열까지 함께 늘어놓고 싶을 때**예요.

학생 네 명의 점수와 나이가 따로 들어 있다고 해 볼게요. 같은 자리의 값이 같은 학생의 것이에요.

```python
>>> score = sd.asarray([70, 90, 70, 80])
>>> age = sd.asarray([31, 25, 40, 25])
```

점수가 높은 순서로 나이를 보고 싶어요. `sort(score)`를 하면 점수는 정렬되지만 어느 점수가 누구 것인지를 잃어버려요. `argsort`로 순서를 한 번 구해 두면, 그 순서를 두 배열에 똑같이 적용할 수 있어요.

```python
>>> order = sd.argsort(score, descending=True)
>>> order
array([1, 3, 0, 2], dtype=int64)
>>> score[order]
array([90, 80, 70, 70], dtype=int64)
>>> age[order]
array([25, 25, 31, 40], dtype=int64)
```

2차원 표의 행을 특정 열 기준으로 정렬하는 것도 같은 방법이에요. 기준 열로 순서를 구하고, 그 순서로 행 전체를 골라요.

```python
>>> table = sd.asarray([[2, 1], [1, 9], [2, 0]])
>>> table[sd.argsort(table[:, 0])]
array([[1, 9],
       [2, 1],
       [2, 0]], dtype=int64)
```

<Callout type="tip" title="가장 큰 값 몇 개만">
  정렬한 뒤 앞이나 뒤를 잘라 내면 돼요. 값은 `sd.sort(v, descending=True)[:3]`, 그 값들이 있던 자리는 `sd.argsort(v, descending=True)[:3]`이에요. 가장 큰 값 하나의 자리만 필요하면 정렬할 것 없이 `sd.argmax(v)`가 더 빨라요.
</Callout>

## `descending`: 큰 값부터

`descending=True`를 주면 큰 값부터 늘어놓아요.

```python
>>> sd.sort(x, descending=True)
array([30, 20, 10], dtype=int64)
>>> sd.argsort(x, descending=True)
array([0, 2, 1], dtype=int64)
```

## `axis`: 여러 차원에서 정렬하기

2차원 이상의 배열에서는 **한 방향으로만** 정렬해요. 기본값 `axis=-1`은 마지막 축으로, 2차원 배열이라면 **각 행 안에서** 왼쪽에서 오른쪽으로 정렬한다는 뜻이에요. 행끼리는 서로 영향을 주지 않아요.

```python
>>> m = sd.asarray([[3, 1, 2], [0, 7, 1]])
>>> sd.sort(m)
array([[1, 2, 3],
       [0, 1, 7]], dtype=int64)
```

<Fig caption="axis=-1 (기본값): 각 행을 따로 정렬해요. 값은 자기 행을 벗어나지 않아요.">
  <ArrayFig name="m" data={[[3, 1, 2], [0, 7, 1]]} tones={[['a', 'a', 'a'], ['', '', '']]} axes />
  <Op note="axis=-1">→</Op>
  <ArrayFig name="sd.sort(m)" data={[[1, 2, 3], [0, 1, 7]]} tones={[['a', 'a', 'a'], ['', '', '']]} />
</Fig>

`axis=0`은 **각 열 안에서** 위에서 아래로 정렬해요.

```python
>>> sd.sort(m, axis=0)
array([[0, 1, 1],
       [3, 7, 2]], dtype=int64)
```

<Fig caption="axis=0: 각 열을 따로 정렬해요. 값은 자기 열을 벗어나지 않아요.">
  <ArrayFig name="m" data={[[3, 1, 2], [0, 7, 1]]} tones={[['a', '', ''], ['a', '', '']]} axes />
  <Op note="axis=0">→</Op>
  <ArrayFig name="sd.sort(m, axis=0)" data={[[0, 1, 1], [3, 7, 2]]} tones={[['a', '', ''], ['a', '', '']]} />
</Fig>

<Callout type="warn" title="행과 열의 짝이 흩어져요">
  위 결과를 보면 원래 한 행에 있던 `3, 1, 2`가 더는 같은 행에 있지 않아요. 열마다 따로 정렬했기 때문이에요. 각 행이 하나의 기록(한 사람의 점수와 나이처럼)이라면 `sort(m, axis=0)`은 기록을 뒤섞어 버려요. 행을 통째로 옮기며 정렬하려면 앞에서 본 `table[sd.argsort(기준 열)]` 방법을 쓰세요.
</Callout>

### 배열 전체를 한 줄로 정렬하려면

`axis`는 정수 하나만 받아요. "모든 원소를 한꺼번에"라는 뜻의 `axis=None`은 없어요. 여러 차원의 배열 전체를 크기순으로 늘어놓고 싶으면 먼저 `sd.ravel`로 한 줄로 편 다음 정렬해요.

```python
>>> sd.sort(sd.ravel(m))
array([0, 1, 1, 2, 3, 7], dtype=int64)
```

### 여러 차원에서의 argsort

`argsort`도 방향마다 따로 계산해요. 결과의 각 숫자는 **그 행(또는 열) 안에서의 위치**예요.

```python
>>> sd.argsort(m, axis=1)
array([[1, 2, 0],
       [0, 2, 1]], dtype=int64)
```

이 결과는 1차원 때처럼 `m[...]`에 바로 넣을 수 없어요. 행마다 가져올 자리가 다르기 때문이에요. 이럴 때 쓰는 함수가 `sd.take_along_axis`예요.

```python
>>> sd.take_along_axis(m, sd.argsort(m, axis=1), axis=1)
array([[1, 2, 3],
       [0, 1, 7]], dtype=int64)
```

## `stable`: 같은 값의 순서

값이 같은 원소가 여럿 있을 때 그들끼리의 순서를 어떻게 할지 정해요. 기본값 `stable=True`는 **원래 놓여 있던 순서를 그대로 지켜요.**

```python
>>> score = sd.asarray([70, 90, 70, 80])
>>> sd.argsort(score)
array([0, 2, 3, 1], dtype=int64)
```

70점이 0번과 2번 자리에 있는데, 결과에서도 0번이 2번보다 앞에 와요.

이 성질은 **여러 기준으로 정렬할 때** 쓸모가 있어요. 이름순으로 정렬해 둔 목록을 점수로 다시 정렬하면, 점수가 같은 사람들은 이름순을 유지해요.

`descending=True`일 때도 같은 값끼리는 원래 순서를 지켜요. 그래서 내림차순 결과는 오름차순 결과를 단순히 뒤집은 것과 달라요.

```python
>>> sd.argsort(score, descending=True)
array([1, 3, 0, 2], dtype=int64)
>>> sd.flip(sd.argsort(score))
array([1, 3, 2, 0], dtype=int64)
```

위쪽은 70점인 두 사람이 `0, 2` 순서(원래 순서)이고, 아래쪽은 뒤집힌 `2, 0` 순서예요.

`stable=False`를 주면 같은 값끼리의 순서를 보장하지 않아요. 결과가 안정 정렬과 똑같이 나올 때가 많지만, 그렇다는 약속은 없으니 순서가 필요하면 기본값을 쓰세요. 보장하지 않을 뿐 결과가 실행할 때마다 달라지지는 않아요. 같은 입력이면 언제나 같은 결과예요.

속도 차이는 크지 않아요. bool 배열이나 원소가 백 개 정도까지인 짧은 배열의 `argsort`는 `stable=False`가 더 빠를 수 있지만, 긴 정수·실수 배열에서는 거의 같아요. 그래서 따로 이유가 없다면 기본값 그대로 두면 돼요.

<Callout title="sort에서는 차이가 보이지 않아요">
  `sort`의 결과는 값뿐이라, 같은 값끼리 순서가 바뀌어도 결과가 똑같이 보여요. `stable`의 차이는 주로 `argsort`에서 드러나요.
</Callout>

## 조심할 점

### NaN은 가장 큰 값으로 쳐요

NaN(숫자가 아님)은 다른 값과 크기를 비교할 수 없어요. 하지만 정렬하려면 어딘가에는 놓아야 하므로, stardust는 **NaN을 무한대보다도 큰 값**으로 정했어요. 오름차순이면 맨 끝, 내림차순이면 맨 앞에 와요.

```python
>>> v = sd.asarray([2.0, sd.nan, 1.0, sd.inf, -sd.inf])
>>> sd.sort(v)
array([-inf,  1.0,  2.0,  inf,  nan], dtype=float64)
>>> sd.sort(v, descending=True)
array([ nan,  inf,  2.0,  1.0, -inf], dtype=float64)
```

내림차순으로 정렬해서 "가장 큰 값"을 꺼낼 때 NaN이 섞여 있으면 NaN이 먼저 나와요. NaN이 있을 수 있는 데이터라면 `sd.isnan`으로 먼저 걸러 내세요.

### 제자리 정렬은 없어요

`sort`는 언제나 새 배열을 돌려주고 원래 배열은 건드리지 않아요. `x.sort()` 같은 메서드도 없어요. 정렬된 결과를 계속 쓰려면 변수에 받아야 해요.

```python
>>> x = sd.asarray([30, 10, 20])
>>> x = sd.sort(x)
>>> x
array([10, 20, 30], dtype=int64)
```

### 복소수는 정렬할 수 없어요

복소수에는 크고 작음이 없어요. 복소수 배열을 정렬하려 하면 `TypeError`예요.

```python
>>> sd.sort(sd.asarray([1 + 1j, 0j]))
Traceback (most recent call last):
    ...
TypeError: sort(): not supported for complex128
```

크기 순서로 정렬하고 싶다면 `sd.abs`로 크기를 구해서 그 순서를 쓰면 돼요. `z[sd.argsort(sd.abs(z))]`처럼요.

### 옵션의 타입

`axis`에는 정수만, `descending`과 `stable`에는 `True`나 `False`만 쓸 수 있어요. 옵션은 모두 이름을 붙여서 써야 해요.

```python
>>> sd.sort(m, axis=None)
Traceback (most recent call last):
    ...
TypeError: sort(): 'axis' must be an int, not NoneType
>>> sd.sort(x, descending=1)
Traceback (most recent call last):
    ...
TypeError: sort(): 'descending' must be True or False, not int
```

### Python의 `sorted`와 헷갈리지 마세요

Python 내장 함수 `sorted`를 배열에 쓰면 에러는 나지 않지만 **배열이 아니라 리스트**가 나와요. 느리기도 하고, 2차원 이상에서는 뜻대로 동작하지 않아요. 배열에는 `sd.sort`를 쓰세요.

```python
>>> sorted(sd.asarray([30, 10, 20]))
[10, 20, 30]
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 정렬과 다른 점 |
|---|---|---|
| 가장 작은·큰 값 하나 | `min`, `max` | 정렬하지 않고 값 하나만 찾아요. 훨씬 빨라요. |
| 가장 작은·큰 값의 자리 | `argmin`, `argmax` | `argsort`의 첫·끝 원소와 같지만 훨씬 빨라요. |
| 겹치는 값을 없애고 정렬 | `unique_values` | 같은 값은 하나만 남겨요. |
| 정렬된 배열에서 값이 들어갈 자리 찾기 | `searchsorted` | 이미 정렬된 배열을 받아서 위치를 찾아요. |
| 순서만 거꾸로 뒤집기 | `flip` | 크기와 상관없이 놓인 순서를 뒤집어요. |
| 가운데 값 구하기 | `median` | 정렬해서 가운데를 고른 값 하나를 돌려줘요. |

`sort`와 `argsort`의 관계는 `max`와 `argmax`의 관계와 같아요. 앞의 것은 **값**을, `arg`가 붙은 것은 그 값이 있던 **자리**를 돌려줘요.

## numpy를 아는 분께

- **기본이 안정 정렬**이에요. numpy의 기본(`kind='quicksort'`)은 같은 값의 순서를 보장하지 않아요. `kind=` 인자는 없고 `stable=`로 골라요. numpy와 달리 `stable=False`로 바꿔도 긴 정수·실수 배열은 빨라지지 않아요.
- **`descending=`이 있어요.** `np.sort(x)[::-1]`로 뒤집는 것과 달리 같은 값의 원래 순서를 지켜요.
- `axis=None`(평탄화해서 정렬)은 없어요. `sd.sort(sd.ravel(x))`로 쓰세요.
- 제자리 정렬 메서드 `x.sort()`와 `x.argsort()`는 없어요.
- NaN은 numpy처럼 맨 끝(가장 큰 값)에 와요. 내림차순에서는 맨 앞이에요.
- 복소수는 numpy처럼 사전순으로 정렬하지 않고 `TypeError`예요.
- `order=`(구조체 필드 기준 정렬), `np.lexsort`, `np.partition`은 없어요.
