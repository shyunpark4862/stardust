## 한눈에 보기

모양이 다른 배열끼리 계산하면 stardust는 작은 쪽을 큰 쪽에 맞춰 늘린 것처럼 계산해요. 이 규칙을 [브로드캐스팅](/api/array/broadcasting/)이라고 해요. 평소에는 늘어난 배열이 눈에 보이지 않지만, `broadcast_to`를 쓰면 **늘어난 모습을 배열로 직접** 얻을 수 있어요.

```python
>>> import stardust as sd
>>> row = sd.asarray([10, 20, 30])
>>> b = sd.broadcast_to(row, (2, 3))
>>> b
array([[10, 20, 30],
       [10, 20, 30]], dtype=int64)
```

  <ArrayFig name="row" data={[10, 20, 30]} note="shape (3,)" />
  <Op note="(2, 3)">→</Op>
  <ArrayFig name="sd.broadcast_to(row, (2, 3))" data={[[10, 20, 30], [10, 20, 30]]} tones={[['a', 'a', 'a'], ['g', 'g', 'g']]} note="shape (2, 3)" />
</Fig>

`broadcast_arrays`는 여러 배열을 받아서 **모두 같은 모양으로** 늘린 결과를 tuple로 돌려줘요.

```python
>>> col = sd.asarray([[1], [2]])
>>> r, c = sd.broadcast_arrays(row, col)
>>> r
array([[10, 20, 30],
       [10, 20, 30]], dtype=int64)
>>> c
array([[1, 1, 1],
       [2, 2, 2]], dtype=int64)
```

<Fig caption="row는 아래로, col은 옆으로 늘어나서 둘 다 (2, 3)이 돼요. row + col을 계산할 때 속으로 일어나는 일이에요.">

</Fig>

## 언제 쓰나요

`row + col`처럼 연산자를 쓸 때는 브로드캐스팅이 저절로 일어나서 이 함수들이 필요 없어요. 이 함수들은 **늘어난 배열 자체가 필요할 때** 써요.

- 브로드캐스팅 결과가 어떤 모양이 될지, 어떤 값이 어디에 놓일지 **눈으로 확인할 때**
- 연산자가 아니라 배열을 인자로 받는 함수에 **같은 모양의 배열 여러 개**를 넘겨야 할 때
- 위치마다 좌표를 매기는 것처럼, 서로 다른 방향의 1차원 배열을 **표 모양으로 짝지을 때**

예를 들어 행 번호와 열 번호를 표의 모든 칸에 매겨 볼게요.

```python
>>> i = sd.expand_dims(sd.arange(2), axis=1)
>>> j = sd.arange(3)
>>> ii, jj = sd.broadcast_arrays(i, j)
>>> ii
array([[0, 0, 0],
       [1, 1, 1]], dtype=int64)
>>> jj
array([[0, 1, 2],
       [0, 1, 2]], dtype=int64)
```

`ii[r, k]`는 그 칸의 행 번호, `jj[r, k]`는 열 번호예요. 좌표 격자를 만드는 일은 [`meshgrid`](/api/array/meshgrid/)가 전문이지만, 원리는 이와 같아요.

## 규칙: 어떤 모양으로 늘릴 수 있나요

규칙은 연산자의 브로드캐스팅과 똑같아요. 두 모양을 **오른쪽 끝부터** 맞춰 보며, 각 자리의 길이가 같거나 원래 쪽이 1이면 통과예요. 원래 배열의 차원이 모자라면 왼쪽에 길이 1인 축이 있다고 봐요.

```python
>>> sd.broadcast_to(col, (2, 4))
array([[1, 1, 1, 1],
       [2, 2, 2, 2]], dtype=int64)
>>> sd.broadcast_to(row, (2, 1, 3)).shape
(2, 1, 3)
```

맞출 수 없는 모양이면 `ValueError`예요. 길이 3을 6으로 "늘리는" 것은 안 돼요. 브로드캐스팅은 **길이 1인 축만** 늘려요. 같은 값을 여러 번 이어 붙이려면 [`tile`](/api/array/repeat/)을 쓰세요.

```python
>>> sd.broadcast_to(row, (6,))
Traceback (most recent call last):
    ...
ValueError: broadcast_to(): cannot broadcast an array of shape (3,) to shape (6,)
>>> sd.broadcast_to(row, (2, 2))
Traceback (most recent call last):
    ...
ValueError: broadcast_to(): cannot broadcast an array of shape (3,) to shape (2, 2)
```

`broadcast_to`는 한쪽만 늘려요. 원래 배열보다 작은 모양이나 차원이 적은 모양으로는 바꿀 수 없어요.

```python
>>> sd.broadcast_to(sd.zeros((2, 3)), (3,))
Traceback (most recent call last):
    ...
ValueError: broadcast_to(): cannot broadcast an array of shape (2, 3) to shape (3,)
```

`broadcast_arrays`는 모든 배열을 서로 맞춰 본 뒤, 각 자리의 가장 긴 길이로 늘려요. 맞지 않는 짝이 하나라도 있으면 `ValueError`예요.

```python
>>> sd.broadcast_arrays(sd.zeros((2, 1, 3)), sd.zeros((4, 1)), sd.zeros((3,)))[0].shape
(2, 4, 3)
>>> sd.broadcast_arrays(row, sd.asarray([1, 2]))
Traceback (most recent call last):
    ...
ValueError: broadcast_arrays(): shapes could not be broadcast together: (3,) (2,)
```

## 결과는 읽기 전용이에요

늘어난 배열은 값을 복사해서 만든 것이 아니에요. `b`의 두 행은 **메모리 속 같은 세 칸을 두 번 보여 주는 것**이에요. 그래서 원소가 여섯 개처럼 보여도 실제로 저장된 값은 `row`의 세 개뿐이고, 큰 모양으로 늘려도 메모리가 거의 들지 않아요.

```python
>>> b.base is row
True
```

이런 배열의 한 칸을 고치면 같은 메모리를 보는 다른 칸까지 함께 바뀌어 버려요. 그런 사고를 막으려고 결과는 **읽기 전용**이에요. 대입이나 `+=` 같은 제자리 연산은 모두 `ValueError`예요.

```python
>>> b[0, 0] = 1
Traceback (most recent call last):
    ...
ValueError: assignment destination is read-only
>>> b += 1
Traceback (most recent call last):
    ...
ValueError: output array is read-only
```

`broadcast_arrays`의 결과도 마찬가지예요. 모양이 바뀌지 않은 배열이라도 읽기 전용이에요.

```python
>>> r[0, 0] = 1
Traceback (most recent call last):
    ...
ValueError: assignment destination is read-only
```

읽는 것은 자유로워요. 계산에 쓰면 결과는 새로 만든 보통 배열이라 고칠 수 있어요.

```python
>>> b * 2
array([[20, 40, 60],
       [20, 40, 60]], dtype=int64)
>>> sd.sum(b)
120
```

고칠 수 있는 진짜 배열이 필요하면 `.copy()`로 복사하세요. 이때는 여섯 칸이 모두 따로 저장돼요.

```python
>>> full = b.copy()
>>> full[0, 0] = 1
>>> full
array([[ 1, 20, 30],
       [10, 20, 30]], dtype=int64)
```

<Callout type="warn" title="원본을 고치면 결과도 바뀌어요">

  결과는 원본의 메모리를 그대로 보여 주기 때문에, **원본을 고치면** 늘린 결과에서도 바뀐 값이 보여요. 결과를 한동안 들고 있을 거라면 원본을 고치지 않거나, 결과를 `.copy()`해 두세요.

</Callout>

```python
>>> row[0] = 99
>>> b
array([[99, 20, 30],
       [99, 20, 30]], dtype=int64)
>>> row[0] = 10
```

## 조심할 점

### `broadcast_arrays`에는 배열을 하나씩 넘겨요

인자는 리스트로 묶지 않고 하나씩 넘겨요. Python 숫자나 리스트도 받지 않아요. 모두 `sd.ndarray`여야 해요.

```python
>>> sd.broadcast_arrays([row, col])
Traceback (most recent call last):
    ...
TypeError: broadcast_arrays(): every argument must be an sd.ndarray, not list
>>> sd.broadcast_arrays(row, 5)
Traceback (most recent call last):
    ...
TypeError: broadcast_arrays(): every argument must be an sd.ndarray, not int
```

이미 배열을 리스트에 담아 두었다면 `sd.broadcast_arrays(*arrays)`처럼 풀어서 넘기면 돼요. 인자가 하나도 없으면 빈 tuple `()`이 나와요.

```python
>>> sd.broadcast_arrays()
()
```

### dtype은 바꾸지 않아요

`broadcast_arrays`는 모양만 맞춰요. 원소 종류는 각자 그대로예요. 연산자로 계산할 때처럼 높은 쪽 dtype으로 맞춰 주지 않아요.

```python
>>> f, g = sd.broadcast_arrays(row, sd.asarray([1.5]))
>>> f
array([10, 20, 30], dtype=int64)
>>> g
array([1.5, 1.5, 1.5], dtype=float64)
```

### 모양은 tuple로, 0차원은 안 돼요

`shape`에는 int 하나나 int의 tuple만 쓸 수 있어요. 리스트는 받지 않아요. 차원이 0인 배열은 stardust에 없으므로 빈 모양 `()`도 안 돼요.

```python
>>> sd.broadcast_to(row, [2, 3])
Traceback (most recent call last):
    ...
TypeError: broadcast_to(): 'shape' must be an int or a tuple of ints, not list
>>> sd.broadcast_to(row, ())
Traceback (most recent call last):
    ...
ValueError: broadcast_to(): 0-dimensional arrays are not supported (stardust has no 0-d arrays)
```

### 길이 0으로도 늘어나요

길이 1인 축은 길이 0으로도 맞춰져요. 원소가 하나도 없는 배열이 돼요.

```python
>>> sd.broadcast_to(sd.zeros((1, 3)), (0, 3)).shape
(0, 3)
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 차이 |
|---|---|---|
| 길이 1인 축을 늘려 보기 | `broadcast_to` | 복사하지 않아요. 읽기 전용이에요. |
| 같은 내용을 여러 번 이어 붙인 진짜 배열 | `tile` | 길이 1이 아닌 축도 몇 배로 늘려요. 새 배열이라 고칠 수 있어요. |
| 원소마다 여러 번 되풀이하기 | `repeat` | `[1, 1, 2, 2]`처럼 원소 단위로 되풀이해요. |
| 길이 1인 축을 넣기 | `expand_dims` | 축의 길이가 아니라 개수를 바꿔요. 늘리기 전에 자주 함께 써요. |
| 좌표 격자 만들기 | `meshgrid` | 1차원 배열 여러 개로 바로 격자를 만들어요. |

`broadcast_to(row, (2, 3))`와 `tile(row, (2, 1))`은 값이 똑같아 보여요. 차이는 `tile`이 여섯 칸을 실제로 만든 **새 배열**이라 고칠 수 있다는 점, `broadcast_to`는 세 칸을 두 번 보여 줄 뿐이라 **메모리를 쓰지 않는 대신 고칠 수 없다**는 점이에요. 읽기만 할 거라면 `broadcast_to`가, 고칠 거라면 `tile`이 맞아요.

## numpy를 아는 분께

- `broadcast_to`의 결과가 읽기 전용인 점은 numpy와 같아요.
- **`broadcast_arrays`의 결과도 언제나 읽기 전용이에요.** numpy는 경고와 함께 쓰기를 허용하지만, stardust는 `ValueError`예요.
- `broadcast_arrays`는 numpy 2처럼 tuple을 돌려줘요. 인자는 `sd.ndarray`만 받아요(리스트나 숫자는 `TypeError`).
- `shape`에 리스트를 받지 않아요. 빈 모양 `()`(0차원)은 `ValueError`예요.
- `np.broadcast_shapes`와 `np.broadcast` 객체는 없어요.
