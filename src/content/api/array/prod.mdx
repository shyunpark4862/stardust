## 한눈에 보기

`prod`는 배열의 원소를 곱해요(prod는 product, 곧 "곱"의 줄임말이에요). 아무 옵션 없이 부르면 **모든 원소의 곱** 하나를 돌려줘요.

```python
>>> import stardust as sd
>>> x = sd.asarray([[1, 2, 3], [4, 5, 6]])
>>> sd.prod(x)
720
```

`1 × 2 × 3 × 4 × 5 × 6 = 720`이에요. 쓰는 법은 [`sum`](/api/array/sum/)과 똑같고, 더하는 대신 곱한다는 점만 달라요.

`axis`를 주면 그 방향으로만 곱해요. 2차원 배열에서 `axis=0`은 **열마다**, `axis=1`은 **행마다** 곱한 결과예요.

```python
>>> sd.prod(x, axis=0)
array([ 4, 10, 18], dtype=int64)
>>> sd.prod(x, axis=1)
array([  6, 120], dtype=int64)
```

<Fig caption="axis=1: 각 행 안에서 왼쪽에서 오른쪽으로 곱해요. 열 방향이 사라지고 행마다 값이 하나씩 남아요.">
  <ArrayFig name="x" data={[[1, 2, 3], [4, 5, 6]]} tones={[['a', 'a', 'a'], ['', '', '']]} axes note="shape (2, 3)" />
  <Op note="axis=1">→</Op>
  <ArrayFig name="sd.prod(x, axis=1)" data={[6, 120]} tones={['b', '']} note="shape (2,)" />

같은 일을 하는 메서드도 있어요.

```python
>>> x.prod(axis=1)
array([  6, 120], dtype=int64)
```

언제 쓸까요? 해마다의 성장률을 곱해 전체 성장률을 구할 때, 서로 독립인 확률을 곱할 때, 팩토리얼(1부터 n까지의 곱)을 구할 때 같은 경우예요.

```python
>>> growth = sd.asarray([1.05, 1.02, 0.97])
>>> sd.prod(growth)
1.0388700000000002
```

5% 오르고, 2% 오르고, 3% 내렸다면 처음보다 약 3.9% 오른 셈이에요.

## `axis`와 `keepdims`

`axis`와 `keepdims`의 뜻은 `sum`과 똑같아요. `axis`는 "곱해서 없앨 축"이고, 정수 하나 대신 tuple이나 list를 주면 여러 축을 한꺼번에 곱해요. `keepdims=True`면 곱한 축이 길이 1로 남아요. 자세한 설명과 그림은 [`sum`](/api/array/sum/)과 [배열의 기본](/api/array/basics/)에 있어요.

```python
>>> sd.prod(x, axis=1, keepdims=True)
array([[  6],
       [120]], dtype=int64)
>>> sd.prod(x, axis=(0, 1))
720
```

남는 축이 하나도 없으면 결과는 배열이 아니라 Python 숫자(`int`, `float`, `complex`)예요. `keepdims=True`면 언제나 배열이에요.

## 결과의 dtype

곱은 기본적으로 **입력과 같은 dtype**으로 계산해요. 정수 배열의 곱은 정수, 실수 배열의 곱은 실수예요.

| `x`의 dtype | 곱의 dtype |
|---|---|
| bool | int64 |
| int64 | int64 |
| float64 | float64 |
| complex128 | complex128 |

bool은 `True`를 1, `False`를 0으로 보고 곱해서 정수가 돼요. 그래서 "모두 `True`면 1, 하나라도 `False`면 0"이에요.

```python
>>> sd.prod(sd.asarray([True, True, False]))
0
```

하지만 "모두 참인가"가 궁금한 것이라면 `prod`보다 [`all`](/api/array/any-all/)이 뜻이 분명하고 결과도 `True`/`False`로 나와요.

```python
>>> sd.all(sd.asarray([True, True, False]))
False
```

복소수도 곱할 수 있어요.

```python
>>> sd.prod(sd.asarray([1 + 1j, 1 - 1j]))
(2+0j)
```

### `dtype`으로 계산할 종류 정하기

`dtype=`을 주면 원소를 **먼저 그 종류로 바꾼 다음** 곱해요. 바꾸는 것이 먼저, 곱하는 것이 나중이에요.

```python
>>> sd.prod(x, dtype=sd.float64)
720.0
>>> sd.prod(sd.asarray([1.5, 2.5]), dtype=sd.int64)
2
```

둘째 예는 `3.75`를 정수로 바꾼 `3`이 아니라, `1.5`와 `2.5`를 각각 `1`과 `2`로 자른 뒤 곱한 `2`예요.

`dtype=sd.bool`은 쓸 수 없어요. 곱셈에는 참·거짓으로 하는 계산이 없기 때문이에요. 복소수 배열을 실수로 바꾸는 것도 허수부를 잃어버리므로 에러예요.

```python
>>> sd.prod(x, dtype=sd.bool)
Traceback (most recent call last):
    ...
TypeError: prod(): cannot accumulate in bool; use any() or all()
>>> sd.prod(sd.asarray([1 + 1j]), dtype=sd.float64)
Traceback (most recent call last):
    ...
TypeError: prod(): cannot convert complex128 to float64: the imaginary part would be lost (take the real part explicitly)
```

## 빈 배열의 곱은 1이에요

곱할 것이 하나도 없으면 결과는 `1`이에요. 에러가 아니에요.

```python
>>> sd.prod(sd.asarray([]))
1.0
>>> sd.prod(sd.asarray([], dtype=sd.int64))
1
```

`0`이 아니라 `1`인 이유는 이렇게 생각하면 쉬워요. 곱을 구할 때는 `1`에서 시작해서 원소를 하나씩 곱해 나가요. 곱할 원소가 없으면 시작한 `1`이 그대로 남아요. 합이 `0`에서 시작해서 빈 배열의 합이 `0`인 것과 같은 이치예요. 이렇게 정해 두면 "배열을 둘로 나눠 각각 곱한 다음 다시 곱해도 전체 곱과 같다"는 규칙이 한쪽이 비어 있을 때도 깨지지 않아요.

일부 축의 길이가 0일 때도 마찬가지로, 곱할 원소가 없는 자리는 `1`이 돼요.

```python
>>> sd.prod(sd.zeros((2, 0)), axis=1)
array([1.0, 1.0], dtype=float64)
```

## 조심할 점

곱은 합보다 훨씬 빨리 커지고 훨씬 빨리 작아져요. 그래서 `prod`에서는 수의 범위를 넘는 일이 자주 생겨요.

### 정수 곱이 너무 커지면

int64는 약 ±9.2 × 10¹⁸까지 담아요. 곱이 이 범위를 넘으면 에러가 나지 않고, **반대쪽 끝으로 넘어가서** 엉뚱한 값이 돼요. 1부터 20까지의 곱(20!)은 아슬아슬하게 들어가지만, 21까지 곱하면 넘쳐요.

```python
>>> sd.prod(sd.arange(1, 21))
2432902008176640000
>>> sd.prod(sd.arange(1, 22))
-4249290049419214848
```

양수만 곱했는데 음수가 나왔어요. 더 고약한 경우도 있어요. 넘친 결과가 **우연히 그럴듯한 값**이 되면 알아채기 어려워요.

```python
>>> sd.prod(sd.asarray([2**32, 2**32]))
0
```

0이 하나도 없는데 곱이 `0`이에요. 2⁶⁴가 int64 범위를 한 바퀴 돌아 정확히 0에 떨어졌기 때문이에요.

<Callout type="warn" title="정수 곱은 금방 넘쳐요">

int64로 담을 수 있는 곱은 생각보다 작아요. 원소 수십 개만 곱해도 넘칠 수 있고, 넘쳐도 아무 경고가 없어요. 값이 클 수 있다면 `dtype=sd.float64`로 실수 계산을 하세요. 마지막 자리까지 정확하지는 않지만 크기는 맞아요.

</Callout>

```python
>>> sd.prod(sd.arange(1, 22), dtype=sd.float64)
5.109094217170944e+19
```

### 실수 곱이 너무 커지거나 작아지면

실수(float64)는 약 10³⁰⁸까지 담아요. 이보다 커지면 `inf`(무한대)가 되고, 약 10⁻³⁰⁸보다 작아지면 `0.0`이 돼요. 에러는 나지 않아요.

```python
>>> sd.prod(sd.asarray([1e200, 1e200]))
inf
>>> sd.prod(sd.asarray([1e-200, 1e-200]))
0.0
```

작은 확률을 여러 개 곱할 때 이 일이 흔히 생겨요. 0.01을 400번 곱한 값(10⁻⁸⁰⁰)은 실수로 나타낼 수 없어서 `0.0`이 돼요.

```python
>>> p = sd.full(400, 0.01)
>>> sd.prod(p)
0.0
```

이럴 때는 곱 대신 **로그의 합**을 구하는 방법을 써요. 곱의 로그는 로그의 합과 같아서, 아주 작거나 큰 곱도 범위를 넘지 않는 크기로 다룰 수 있어요.

```python
>>> sd.sum(sd.log10(p))
-800.0
```

"곱은 10의 -800제곱"이라는 뜻이에요.

### 곱하는 순서에 따라 결과가 달라질 수 있어요

아주 큰 값과 아주 작은 값이 섞여 있으면, 어떤 순서로 곱하느냐에 따라 중간값이 범위를 넘기도 하고 넘지 않기도 해요.

```python
>>> w = sd.asarray([1e200, 1e-200] * 8)
>>> sd.prod(w)
nan
```

수학적으로는 `1e200 × 1e-200 = 1`을 여덟 번 곱한 `1`이지만, 큰 값끼리 먼저 곱해져서 `inf`가 되고 작은 값끼리 곱해져서 `0`이 된 다음 `inf × 0`이 `nan`이 됐어요. 이런 입력에서는 `prod`의 결과를 믿기 어려워요. 위에서 본 로그의 합을 쓰면 순서와 상관없이 안전해요.

```python
>>> sd.exp(sd.sum(sd.log(w)))
1.0
```

결과가 실행할 때마다 달라지지는 않아요. 같은 배열이면 언제나 같은 결과이고, 계산에 쓰는 스레드 수를 바꿔도 같아요.

### NaN이 하나라도 있으면

NaN(숫자가 아님)이 하나라도 섞이면 곱 전체가 NaN이에요. `0`과 `inf`를 곱해도 NaN이 나와요.

```python
>>> sd.prod(sd.asarray([1.0, sd.nan, 2.0]))
nan
>>> sd.prod(sd.asarray([0.0, sd.inf]))
nan
```

NaN을 빼고 나머지만 곱하고 싶으면 [`nanprod`](/api/array/nan-reductions/)를 써요.

```python
>>> sd.nanprod(sd.asarray([1.0, sd.nan, 2.0]))
2.0
```

### 옵션은 이름을 붙여서

`axis`, `dtype`, `keepdims`는 반드시 이름과 함께 써야 해요. `sd.prod(x, 0)`이 아니라 `sd.prod(x, axis=0)`이에요. 없는 축을 주면 `ValueError`예요.

```python
>>> sd.prod(x, axis=2)
Traceback (most recent call last):
    ...
ValueError: prod(): axis 2 is out of bounds for an array of dimension 2
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | `prod`와 다른 점 |
|---|---|---|
| 원소를 모두 더하기 | `sum` | 곱하는 대신 더해요. 빈 배열의 결과는 `0`이에요. |
| 처음부터 차례로 쌓인 곱 | `cumulative_prod` | 값 하나가 아니라 중간 곱들이 모두 담긴 배열을 돌려줘요. |
| 두 배열을 원소끼리 곱하기 | `multiply` 또는 `*` | 배열 하나를 줄이는 것이 아니라 두 배열의 같은 자리끼리 곱해요. |
| NaN을 빼고 곱하기 | `nanprod` | NaN을 1로 보고 곱해요. |
| 모두 참인지 확인 | `all` | 결과가 `True`/`False`예요. |

`cumulative_prod`의 마지막 값이 `prod`와 같아요. 중간 과정까지 필요하면 [누적 곱](/api/array/cumulative/)을 쓰세요.

```python
>>> sd.cumulative_prod(growth)
array([              1.05, 1.0710000000000002, 1.0388700000000002], dtype=float64)
```

`sd.prod`와 `sd.multiply`도 헷갈리기 쉬워요. `prod`는 **배열 하나의 원소들을** 곱해서 더 작은 결과를 만들고, [`multiply`](/api/array/arithmetic/)는 **두 배열의 같은 자리끼리** 곱해서 같은 크기의 배열을 만들어요.

```python
>>> sd.multiply(sd.asarray([1, 2, 3]), sd.asarray([4, 5, 6]))
array([ 4, 10, 18], dtype=int64)
```

## numpy를 아는 분께

- `axis`, `dtype`, `keepdims`는 keyword-only예요. `np.prod(x, 0)`처럼 자리로 넘길 수 없어요.
- 모든 축을 곱한 결과는 numpy 스칼라가 아니라 Python `int`·`float`·`complex`예요.
- `out=`, `where=`, `initial=` 인자는 없어요.
- **실수 곱의 순서가 numpy와 달라요.** 중간값이 실수 범위를 넘는 입력에서는 결과가 크게 다를 수 있어요. 예를 들어 `[1e200, 1e-200] * 8`의 곱은 stardust에서 `nan`, numpy에서 `1.0`이에요. 반대로 numpy가 `inf`나 `nan`을 낼 때 stardust가 유한한 값을 내는 경우도 있어요.
- `dtype=bool`은 에러예요. 복소수 배열에 `dtype=float64`를 주면 numpy처럼 허수부를 버리지 않고 `TypeError`예요.
- 넘침이나 `inf`가 생겨도 경고가 없어요.
