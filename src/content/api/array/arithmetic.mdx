## 한눈에 보기

`add`, `subtract`, `multiply`, `divide`는 **원소별 함수**예요. 두 배열에서 같은 자리에 있는 원소끼리 계산해서, 같은 모양의 배열을 돌려줘요.

```python
>>> import stardust as sd
>>> a = sd.asarray([1, 2, 3])
>>> b = sd.asarray([10, 20, 30])
>>> sd.add(a, b)
array([11, 22, 33], dtype=int64)
```

평소에는 함수 이름보다 **연산자**를 더 많이 써요. `a + b`와 `sd.add(a, b)`는 같은 계산이에요.

```python
>>> a + b
array([11, 22, 33], dtype=int64)
>>> a - b
array([ -9, -18, -27], dtype=int64)
>>> a * b
array([10, 40, 90], dtype=int64)
>>> a / b
array([0.1, 0.1, 0.1], dtype=float64)
```

| 연산자 | 함수 | 하는 일 |
|:---:|:---:|---|
| `x1 + x2` | `sd.add(x1, x2)` | 더하기 |
| `x1 - x2` | `sd.subtract(x1, x2)` | 빼기 (`x1`에서 `x2`를 빼요) |
| `x1 * x2` | `sd.multiply(x1, x2)` | 곱하기 (행렬곱이 아니에요) |
| `x1 / x2` | `sd.divide(x1, x2)` | 나누기 (결과는 언제나 실수) |

`a / b`는 정수끼리 나눴는데도 결과가 실수(float64)예요. 이유는 [divide 결과는 언제나 실수예요](#divide-결과는-언제나-실수예요)에서 설명해요.

## 숫자 하나와 계산하기

한쪽에 배열 대신 Python 숫자를 놓으면, 그 숫자를 모든 원소에 똑같이 계산해요. 숫자가 왼쪽에 있어도 돼요.

```python
>>> a * 10
array([10, 20, 30], dtype=int64)
>>> 2 - a
array([ 1,  0, -1], dtype=int64)
>>> 1 / a
array([               1.0,                0.5, 0.3333333333333333], dtype=float64)
```

함수로 쓸 때도 마찬가지예요. 두 입력이 모두 Python 숫자면 결과도 배열이 아니라 **Python 숫자**예요.

```python
>>> sd.multiply(2, 3.0)
6.0
>>> sd.divide(1, 2)
0.5
```

## 모양이 다른 배열끼리

두 입력의 모양이 다르면 [브로드캐스팅](/api/array/broadcasting/) 규칙으로 맞춰요. 길이가 1인 축이 상대 쪽 길이만큼 늘어난다고 보면 돼요. 세로 모양 `(2, 1)`과 가로 모양 `(3,)`을 더하면 `(2, 3)`이 나와요.

```python
>>> col = sd.asarray([[100], [200]])
>>> col + a
array([[101, 102, 103],
       [201, 202, 203]], dtype=int64)
```

맞출 수 없는 모양이면 `ValueError`예요. 함수로 쓰면 메시지 앞에 함수 이름이 붙어요.

```python
>>> a + sd.asarray([1, 2])
Traceback (most recent call last):
    ...
ValueError: shapes could not be broadcast together: (3,) (2,)
>>> sd.add(a, sd.asarray([1, 2]))
Traceback (most recent call last):
    ...
ValueError: add(): shapes could not be broadcast together: (3,) (2,)
```

## 결과의 dtype

### 더하기, 빼기, 곱하기

두 입력 중 **더 넓은 종류**를 따라요. 종류의 순서는 `bool` → `int64` → `float64` → `complex128`이에요. 정수와 실수를 섞으면 실수, 실수와 복소수를 섞으면 복소수가 나와요. Python 숫자도 `int`는 int64, `float`는 float64처럼 같은 순서로 쳐요.

```python
>>> a + 1.5
array([2.5, 3.5, 4.5], dtype=float64)
>>> a + 1j
array([(1+1j), (2+1j), (3+1j)], dtype=complex128)
```

| `x1` \ `x2` | bool | int64 | float64 | complex128 |
|---|:---:|:---:|:---:|:---:|
| **bool** | int64 | int64 | float64 | complex128 |
| **int64** | int64 | int64 | float64 | complex128 |
| **float64** | float64 | float64 | float64 | complex128 |
| **complex128** | complex128 | complex128 | complex128 | complex128 |

### bool은 int64가 돼요

표의 왼쪽 위 칸을 보세요. bool끼리 더해도 결과는 bool이 아니라 **int64**예요. 계산할 때 `True`는 1, `False`는 0으로 쳐요. Python에서 `True + True`가 `2`인 것과 같아요.

```python
>>> sd.asarray([True, False]) + sd.asarray([True, True])
array([2, 1], dtype=int64)
>>> sd.add(True, True)
2
>>> sd.asarray([True, False]) - True
array([ 0, -1], dtype=int64)
```

"둘 중 하나라도 참"처럼 참·거짓으로 계산하고 싶었다면 `+`가 아니라 `sd.logical_or`나 `|`를 써야 해요.

### divide 결과는 언제나 실수예요

`divide`와 `/`는 정수끼리 나눠떨어지더라도 **언제나 float64**를 돌려줘요. 나눠떨어질 때만 정수가 나온다면 값에 따라 결과의 dtype이 달라져서, 코드만 보고는 결과를 알 수 없기 때문이에요.

```python
>>> sd.asarray([6, 9]) / 3
array([2.0, 3.0], dtype=float64)
>>> sd.asarray([-7]) / 2
array([-3.5], dtype=float64)
```

정수 몫이 필요하면 [`//`(floor_divide)](/api/array/floor-divide/)를 써요. `/`의 결과를 정수로 바꾸는 것과는 음수에서 결과가 달라요.

```python
>>> sd.asarray([7, -7]) // 2
array([ 3, -4], dtype=int64)
```

복소수가 섞이면 결과는 complex128이에요.

```python
>>> sd.asarray([1 + 2j]) / 2
array([(0.5+1j)], dtype=complex128)
```

## 0으로 나누기

`divide`는 0으로 나눠도 에러가 나지 않아요. 결과가 실수라서, 실수 계산의 약속대로 **무한대(`inf`)나 NaN(숫자가 아님)** 이 나와요. 정수 배열을 나눠도 마찬가지예요.

```python
>>> sd.asarray([1.0, -1.0, 0.0]) / 0
array([ inf, -inf,  nan], dtype=float64)
>>> sd.asarray([5, 0]) / sd.asarray([0, 0])
array([inf, nan], dtype=float64)
```

| 나누는 값 | 나눠지는 값 | 결과 |
|---|---|:---:|
| 0 | 양수 | `inf` |
| 0 | 음수 | `-inf` |
| 0 | 0 | `nan` |

경고도 없기 때문에, 결과에 `inf`나 `nan`이 섞였는지 확인하려면 `sd.isfinite`로 따로 검사해야 해요.

```python
>>> sd.isfinite(sd.asarray([1.0, 0.0]) / sd.asarray([2.0, 0.0]))
array([ True, False], dtype=bool)
```

## `out`: 결과를 기존 배열에 쓰기

`out=`에 배열을 주면 새 배열을 만들지 않고 그 배열에 결과를 적은 다음, 그 배열을 돌려줘요. 같은 크기의 계산을 여러 번 되풀이할 때 메모리를 아낄 수 있어요. `out`은 `sd.add(a, b, buf)`처럼 자리로 넘길 수 없고, 반드시 `out=`으로 이름을 붙여야 해요.

```python
>>> buf = sd.zeros(3, dtype=sd.int64)
>>> sd.add(a, b, out=buf) is buf
True
>>> buf
array([11, 22, 33], dtype=int64)
```

`out`의 dtype은 결과를 손실 없이 담을 수 있어야 해요. 정수 결과를 실수 배열에 담는 것처럼 더 넓은 dtype에 담는 것은 괜찮지만, 좁은 dtype에 담는 것은 값을 잃을 수 있어서 `TypeError`예요. `divide`의 결과는 실수라서 정수 배열에는 담을 수 없어요. 어떤 dtype에 담을 수 있는지는 [원소 종류(dtype)](/api/array/dtypes/)에 있어요.

```python
>>> sd.add(a, b, out=sd.zeros(3))
array([11.0, 22.0, 33.0], dtype=float64)
>>> sd.divide(a, b, out=sd.zeros(3, dtype=sd.int64))
Traceback (most recent call last):
    ...
TypeError: divide(): cannot implicitly convert float64 to int64 (that would lose information); convert explicitly with astype
```

`out`의 모양이 결과와 맞지 않아도 에러예요.

```python
>>> sd.add(a, b, out=sd.zeros(2))
Traceback (most recent call last):
    ...
ValueError: add(): operand of shape (3,) cannot be broadcast to (2,)
```

입력과 `out`이 같은 메모리를 써도 괜찮아요. 결과는 **입력을 모두 읽은 다음에 쓴 것**과 같아요. 아래는 이웃한 두 원소의 합을 자기 자신에게 덮어쓰는 예예요.

```python
>>> x = sd.asarray([1, 2, 3, 4])
>>> _ = sd.add(x[:-1], x[1:], out=x[1:])
>>> x
array([1, 3, 5, 7], dtype=int64)
```

## `+=` 같은 제자리 연산자

`x += y`는 `out=x`를 준 것처럼 결과를 **`x`에 직접 써요.** 새 배열을 만들지 않아요. 그래서 같은 배열을 가리키는 다른 이름에도 변화가 보여요. `x = x + y`는 새 배열을 만들어 이름만 옮기기 때문에 다르게 동작해요.

```python
>>> p = sd.asarray([1.0, 2.0])
>>> q = p
>>> p += 1
>>> q
array([2.0, 3.0], dtype=float64)
>>> p = p + 1
>>> q
array([2.0, 3.0], dtype=float64)
>>> p
array([3.0, 4.0], dtype=float64)
```

`+=`, `-=`, `*=`, `/=` 모두 `out`과 같은 규칙을 따라요. 결과가 `x`의 dtype에 손실 없이 들어가야 해요. 그래서 정수 배열에 `/=`나 `+= 0.5`는 할 수 없어요. `x`의 모양도 바뀌지 않아요.

```python
>>> n = sd.asarray([1, 2, 3])
>>> n /= 2
Traceback (most recent call last):
    ...
TypeError: cannot implicitly convert float64 to int64 (that would lose information); convert explicitly with astype
```

<Callout type="warn" title="정수 배열에 /= 하기">

정수 배열을 반으로 나누고 싶다면 `n = n / 2`처럼 새 실수 배열을 만들거나, 정수 몫이면 충분할 때 `n //= 2`를 쓰세요.

</Callout>

## 조심할 점

### 정수는 넘치면 반대쪽으로 넘어가요

int64는 약 ±9.2 × 10¹⁸까지 담아요. 계산 결과가 이 범위를 넘으면 에러가 나지 않고, **반대쪽 끝으로 넘어가서**(wrap) 엉뚱한 값이 돼요. 양수끼리 더했는데 음수가 나올 수 있어요.

```python
>>> sd.asarray([2**62]) + 2**62
array([-9223372036854775808], dtype=int64)
>>> sd.asarray([9223372036854775807]) * 2
array([-2], dtype=int64)
>>> sd.add(2**62, 2**62)
-9223372036854775808
```

마지막 예처럼 Python 숫자끼리 계산해도 int64 규칙을 따라요. Python의 `2**62 + 2**62`와 결과가 달라요. 아주 큰 수를 다룬다면 실수로 바꿔서 계산하세요. 정확한 정수는 아니지만 크기는 맞아요.

```python
>>> sd.asarray([2**62]).astype(sd.float64) * 4
array([1.8446744073709552e+19], dtype=float64)
```

### 너무 큰 Python 정수는 받지 않아요

정수 배열에 int64 범위를 벗어난 Python 정수를 더하려 하면 `OverflowError`예요. 그 정수를 int64로 바꿀 수 없기 때문이에요. 실수 배열이라면 그 정수를 실수로 읽어서 정상적으로 계산해요.

```python
>>> a + 2**70
Traceback (most recent call last):
    ...
OverflowError: Python int too large to convert to int64
>>> sd.asarray([1.0]) + 2**70
array([1.1805916207174113e+21], dtype=float64)
```

### 아주 큰 정수를 나누면 정밀도를 잃어요

`/`는 실수로 계산하는데, float64는 2⁵³(약 9 × 10¹⁵)보다 큰 정수를 모두 정확히 나타내지 못해요. 그래서 큰 정수는 1로 나누기만 해도 값이 바뀔 수 있어요. 정수로 정확하게 나눠야 한다면 `//`를 써요.

```python
>>> sd.asarray([2**53 + 1]) / 1
array([9007199254740992.0], dtype=float64)
>>> sd.asarray([2**53 + 1]) // 1
array([9007199254740993], dtype=int64)
```

### 실수 계산의 작은 오차

컴퓨터의 실수는 0.1 같은 수를 정확히 나타내지 못해서, 결과의 마지막 자리가 어긋날 수 있어요. stardust만의 문제가 아니라 Python의 `float`도 똑같아요.

```python
>>> sd.asarray([0.1]) + 0.2
array([0.30000000000000004], dtype=float64)
>>> 0.1 + 0.2
0.30000000000000004
```

그래서 실수 계산 결과를 `==`로 비교하기보다는 차이가 충분히 작은지로 판단하세요.

### 무한대와 NaN이 섞이면

NaN이 들어간 계산은 언제나 NaN이에요. 무한대끼리 빼거나 무한대에 0을 곱하는 것처럼 답을 정할 수 없는 계산도 NaN이에요.

```python
>>> sd.asarray([1.0, sd.nan]) + 1
array([2.0, nan], dtype=float64)
>>> sd.asarray([sd.inf]) - sd.inf
array([nan], dtype=float64)
>>> sd.asarray([0.0]) * sd.inf
array([nan], dtype=float64)
```

### 리스트와는 계산하지 않아요

계산할 값은 stardust 배열이나 Python 숫자(`bool`, `int`, `float`, `complex`)여야 해요. 리스트나 numpy 배열은 받지 않아요. 먼저 [`asarray`](/api/array/asarray/)로 배열로 바꾸세요. 이유는 [배열의 기본](/api/array/basics/)에 있어요.

```python
>>> sd.add(a, [1, 2, 3])
Traceback (most recent call last):
    ...
TypeError: add(): 'x2' must be an sd.ndarray or a bool, int, float or complex, not list
>>> a + [1, 2, 3]
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for +: 'ndarray' and 'list'
>>> a + sd.asarray([1, 2, 3])
array([2, 4, 6], dtype=int64)
```

## 비슷한 함수와의 차이

| 헷갈리는 것 | 차이 |
|---|---|
| `add`와 [`sum`](/api/array/sum/) | `add(a, b)`는 **두 배열의 같은 자리끼리** 더해서 같은 크기의 배열을 만들어요. `sum(x)`는 **배열 하나의 원소들을** 모두 더해서 더 작은 결과를 만들어요. |
| `multiply`(`*`)와 [`matmul`](/api/array/matmul/)(`@`) | `*`는 같은 자리끼리 곱해요. 행렬곱은 `@`예요. |
| `divide`(`/`)와 [`floor_divide`](/api/array/floor-divide/)(`//`) | `/`는 언제나 실수, `//`는 내림한 몫이고 정수끼리면 정수예요. |
| `subtract`와 [`negative`](/api/array/sign/) | `subtract(x1, x2)`는 두 값의 차, `negative(x)`는 부호만 뒤집어요(`-x`). |
| `multiply`와 [`pow`](/api/array/pow/), `square` | 같은 값을 여러 번 곱할 때는 `x ** n`이나 `sd.square(x)`가 편해요. |

2×2 행렬로 `*`와 `@`를 비교해 볼게요.

```python
>>> m = sd.asarray([[1, 2], [3, 4]])
>>> m * m
array([[ 1,  4],
       [ 9, 16]], dtype=int64)
>>> m @ m
array([[ 7, 10],
       [15, 22]], dtype=int64)
```

## numpy를 아는 분께

- 계산할 값으로는 stardust 배열과 Python 숫자(numpy 스칼라 포함)만 받아요. 리스트나 numpy 배열과 섞어 쓰면 어느 쪽이 왼쪽이든 `TypeError`예요. numpy처럼 리스트를 자동으로 배열로 바꾸지 않아요.
- dtype은 bool, int64, float64, complex128 넷뿐이고, Python 숫자도 배열과 똑같이 승격해요. numpy의 "값에 따라 작은 dtype을 고르는" 규칙은 없어요.
- bool끼리의 `+`, `-`, `*`는 int64예요. numpy는 `+`가 논리합, `-`는 에러예요.
- 정수 오버플로와 0으로 나누기에 경고가 없어요. `errstate`도 없어요.
- `true_divide` 별칭과 `divmod`는 없어요. `out`은 keyword-only이고 `where=` 인자는 없어요.
- 결과가 하나뿐인 계산(두 인자가 모두 Python 숫자)은 numpy 스칼라가 아니라 Python 숫자를 돌려줘요.
