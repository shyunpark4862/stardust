## 한눈에 보기

이 페이지의 세 함수는 배열의 원소 종류(dtype)에 관한 질문 세 가지에 답해요.

| 질문 | 함수 | 답 |
|---|---|---|
| A 종류의 값을 B 종류 배열에 저절로 넣어도 되나요? | `can_cast(A, B)` | `True` / `False` |
| 이것들을 섞어 계산하면 결과는 어떤 종류인가요? | `result_type(...)` | dtype |
| 이 종류는 정수인가요, 실수인가요? | `isdtype(dtype, kind)` | `True` / `False` |

```python
>>> import stardust as sd
>>> sd.can_cast(sd.int64, sd.float64)
True
>>> sd.result_type(sd.int64, sd.float64)
float64
>>> sd.isdtype(sd.float64, "real floating")
True
```

세 함수 모두 dtype 객체(`sd.float64`) 대신 이름(`"float64"`)도 받아요.

## 바탕: 네 종류의 순서

세 함수의 답은 모두 하나의 순서에서 나와요. stardust의 dtype은 네 가지이고, 좁은 것부터 넓은 것까지 **한 줄로** 늘어서 있어요.

<Fig caption="오른쪽 종류는 왼쪽 종류의 값을 모두 담을 수 있어요. 섞어 계산하면 더 오른쪽 종류가 돼요.">
  <ArrayFig data={['bool', 'int64', 'float64', 'complex128']} tones={['', '', '', '']} note="좁음 → 넓음" />
</Fig>

- 참·거짓은 정수 0과 1로, 정수는 실수로, 실수는 허수부가 0인 복소수로 나타낼 수 있어요.
- 거꾸로 바꾸면 정보를 잃어요. 정수 `2`를 참·거짓으로 바꾸면 값이 2였다는 것을, 실수 `2.5`를 정수로 바꾸면 `.5`를 잃어요.

네 종류와 이 순서에 관한 설명은 [원소 종류(dtype)](/api/array/dtypes/)에 있어요.

## `can_cast`: 저절로 바꿔 넣어도 되나요

`can_cast(from_, to)`는 `from_` 종류의 값을 `to` 종류로 **저절로**(암묵적으로) 바꿀 수 있는지 알려 줘요. 위 순서에서 **같거나 오른쪽으로 갈 때만** `True`예요.

```python
>>> sd.can_cast(sd.float64, sd.int64)
False
>>> sd.can_cast(sd.bool, sd.complex128)
True
>>> sd.can_cast(sd.int64, sd.int64)
True
>>> sd.can_cast("int64", "bool")
False
```

네 종류의 조합을 모두 적으면 아래 표와 같아요. 행이 `from_`, 열이 `to`예요.

| `from_` \\ `to` | bool | int64 | float64 | complex128 |
|:---:|:---:|:---:|:---:|:---:|
| bool | ✓ | ✓ | ✓ | ✓ |
| int64 | | ✓ | ✓ | ✓ |
| float64 | | | ✓ | ✓ |
| complex128 | | | | ✓ |

dtype이 저절로 바뀌는 곳은 결과를 이미 있는 배열에 써 넣는 자리예요. 대입(`x[0] = ...`), 제자리 연산자(`x += ...`), `out=` 인자가 그래요. `can_cast`가 `False`인 방향으로 써 넣으려 하면 `TypeError`가 나요.

```python
>>> counts = sd.asarray([1, 2, 3])
>>> sd.can_cast(sd.float64, counts)
False
>>> counts += 0.5
Traceback (most recent call last):
    ...
TypeError: cannot implicitly convert float64 to int64 (that would lose information); convert explicitly with astype
```

위의 `counts`처럼 배열을 주면 그 배열의 dtype으로 봐요. `from_`과 `to` 어느 쪽에든 배열을 줄 수 있어요.

<Callout title="값이 아니라 종류만 봐요">

`can_cast`는 실제 값을 보지 않아요. `2.0`처럼 정수와 같은 실수라도 float64 → int64는 `False`예요. 값에 따라 될 때도 있고 안 될 때도 있으면 결과를 예측하기 어렵기 때문이에요.

</Callout>

`can_cast`는 저절로 바뀌는지만 답해요. `False`여도 [`astype`](/api/array/astype/)으로 **직접** 바꿀 수는 있어요(복소수 → 실수·정수만 빼고).

## `result_type`: 섞으면 어떤 종류가 되나요

`result_type`은 받은 것들을 **함께 계산했을 때의 dtype**을 알려 줘요. 받은 것들 가운데 위 순서에서 가장 오른쪽에 있는 종류가 답이에요. 이렇게 넓은 쪽으로 맞추는 것을 **승격**이라고 해요.

```python
>>> i = sd.asarray([1, 2, 3])
>>> f = sd.asarray([0.5])
>>> sd.result_type(i, f)
float64
>>> (i + f).dtype
float64
>>> sd.result_type(sd.bool, sd.int64, sd.float64)
float64
```

배열, dtype, dtype 이름을 몇 개든 섞어서 줄 수 있어요. 하나만 주면 그 종류가 그대로 나와요.

### Python 숫자도 받아요

Python 숫자는 **그 타입에 대응하는 dtype**으로 봐요. `bool`은 bool, `int`는 int64, `float`는 float64, `complex`는 complex128이에요. 값의 크기는 보지 않아요.

```python
>>> sd.result_type(i, 1.5)
float64
>>> b = sd.asarray([True, False])
>>> sd.result_type(b, 1)
int64
>>> sd.result_type(b, True)
bool
>>> sd.result_type(1, 2.0)
float64
```

`sd.result_type(b, 1)`이 int64라는 것은 bool 배열에 `1`을 더하면 int64 배열이 된다는 뜻이에요.

```python
>>> (b + 1).dtype
int64
```

### 결과는 dtype 객체예요

`result_type`은 `sd.float64` 같은 dtype 객체를 돌려줘요. 그래서 `is`나 `==`로 비교하거나, 다른 함수의 `dtype=`에 바로 넘길 수 있어요.

```python
>>> sd.result_type(i, f) is sd.float64
True
>>> sd.zeros(2, dtype=sd.result_type(i, f))
array([0.0, 0.0], dtype=float64)
```

### 함수의 결과 dtype과 같지는 않을 수 있어요

`result_type`은 입력들을 한 종류로 맞췄을 때의 dtype이에요. 함수에 따라서는 결과의 종류가 그와 달라요. 예를 들어 나눗셈 `/`의 결과는 언제나 실수이고, 비교의 결과는 언제나 bool이에요.

```python
>>> sd.result_type(i, i)
int64
>>> (i / i).dtype
float64
>>> (i < i).dtype
bool
```

함수마다의 결과 종류는 각 함수의 문서에 있어요.

## `isdtype`: 어떤 부류의 종류인가요

`isdtype(dtype, kind)`는 `dtype`이 `kind`라는 **부류**에 드는지 알려 줘요. 부류 이름은 일곱 가지예요.

| `kind` | 드는 dtype |
|---|---|
| `"bool"` | bool |
| `"signed integer"` | int64 |
| `"unsigned integer"` | 없음 (언제나 `False`) |
| `"integral"` | int64 |
| `"real floating"` | float64 |
| `"complex floating"` | complex128 |
| `"numeric"` | int64, float64, complex128 (bool은 빠져요) |

```python
>>> sd.isdtype(sd.int64, "integral")
True
>>> sd.isdtype(sd.int64, "real floating")
False
>>> sd.isdtype(sd.bool, "numeric")
False
>>> sd.isdtype(sd.complex128, "numeric")
True
```

`"unsigned integer"`(음수가 없는 정수)는 stardust에 없는 종류라서 언제나 `False`예요. 다른 배열 라이브러리와 같은 코드를 쓸 수 있도록 이름은 받아요.

### 여러 부류 중 하나라도

`kind`에 tuple을 주면 **그중 하나에라도** 들면 `True`예요. "실수나 복소수인가"처럼 묻고 싶을 때 써요.

```python
>>> sd.isdtype(sd.float64, ("real floating", "complex floating"))
True
>>> sd.isdtype(sd.int64, ("real floating", "complex floating"))
False
```

`kind` 자리에 dtype을 써도 돼요. 그러면 "그 dtype과 같은가"라는 뜻이에요. 부류 이름과 dtype을 tuple에 섞어도 돼요.

```python
>>> sd.isdtype(sd.int64, sd.int64)
True
>>> sd.isdtype(sd.int64, ("bool", sd.int64))
True
```

### 배열은 `.dtype`으로

`isdtype`의 첫 인자는 dtype이에요. 배열을 그대로 넣으면 `TypeError`라서, 배열의 `.dtype`을 넘겨요.

```python
>>> sd.isdtype(i.dtype, "integral")
True
>>> sd.isdtype(i, "integral")
Traceback (most recent call last):
    ...
TypeError: isdtype(): 'dtype' must be sd.bool, sd.int64, sd.float64 or sd.complex128 (or their names), not ndarray
```

`isdtype`은 함수 안에서 입력을 확인할 때 자주 써요. 실수 배열만 받는 함수라면 이렇게 확인할 수 있어요.

```python
>>> def check_float(x):
...     if not sd.isdtype(x.dtype, "real floating"):
...         raise TypeError(f"expected a float64 array, got {x.dtype}")
...     return x
>>> check_float(sd.asarray([1.0]))
array([1.0], dtype=float64)
>>> check_float(i)
Traceback (most recent call last):
    ...
TypeError: expected a float64 array, got int64
```

## 조심할 점

### 부류 이름은 정확히

부류 이름은 위 표의 일곱 가지만 받아요. `"integer"`, `"float"`, `"int32"` 같은 이름은 `ValueError`예요.

```python
>>> sd.isdtype(sd.int64, "integer")
Traceback (most recent call last):
    ...
ValueError: isdtype(): 'kind' must be 'bool', 'signed integer', 'unsigned integer', 'integral', 'real floating', 'complex floating' or 'numeric', not 'integer'
```

`"int64"`나 `"float64"` 같은 dtype 이름은 dtype 객체와 같은 뜻으로 `kind`에 쓸 수 있어요. 여러 부류는 tuple로 묶어야 해요. 리스트는 `TypeError`예요.

```python
>>> sd.isdtype(sd.int64, ["integral"])
Traceback (most recent call last):
    ...
TypeError: isdtype(): 'kind' must be a dtype, a str or a tuple of them, not list
```

### 네 가지 dtype만 받아요

Python의 `float`, numpy의 dtype, `"float32"` 같은 이름은 받지 않아요. 데이터프레임에서 쓰는 `sd.string`도 배열의 dtype이 아니라서 `TypeError`예요.

```python
>>> sd.can_cast(float, sd.int64)
Traceback (most recent call last):
    ...
TypeError: can_cast(): 'from_' must be sd.bool, sd.int64, sd.float64 or sd.complex128 (or their names) or an sd.ndarray, not <class 'float'>
```

`can_cast`는 Python 숫자를 받지 않아요(`result_type`만 받아요). 숫자의 종류를 확인하려면 `sd.result_type(숫자)`로 먼저 dtype을 얻으세요.

```python
>>> sd.can_cast(sd.result_type(2.5), sd.int64)
False
```

### `result_type`에는 하나 이상

아무것도 주지 않으면 `ValueError`, 리스트나 `None`을 주면 `TypeError`예요.

```python
>>> sd.result_type()
Traceback (most recent call last):
    ...
ValueError: result_type(): at least one array, dtype or scalar is required
>>> sd.result_type(i, [1])
Traceback (most recent call last):
    ...
TypeError: result_type(): 'arrays_and_dtypes' must be sd.ndarray, dtypes or Python scalars, not list
```

### dtype 객체와 이름 문자열은 `==`로 같지 않아요

dtype을 받는 함수는 이름 문자열도 받아 주지만, **dtype 객체와 문자열을 직접 비교하면 같지 않아요.** 배열의 종류를 확인할 때는 dtype 객체와 비교하거나 `isdtype`을 쓰세요.

```python
>>> i.dtype == "int64"
False
>>> i.dtype == sd.int64
True
>>> str(i.dtype) == "int64"
True
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 |
|---|---|
| 배열의 dtype 알아보기 | `x.dtype` |
| 실제로 dtype 바꾸기 | `astype` |
| 저절로 바꿔 넣을 수 있는지 미리 확인 | `can_cast` |
| 섞어 계산한 결과의 dtype | `result_type` |
| 정수·실수 같은 부류 확인 | `isdtype` |
| 그 dtype이 담을 수 있는 가장 큰 수, 가장 작은 간격 | `finfo`, `iinfo` |

`finfo`와 `iinfo`는 [수의 한계](/api/array/finfo/) 문서에 있어요.

## numpy를 아는 분께

- 함수 이름과 부류 이름은 Python 배열 API 표준을 따라요(numpy 2의 `np.isdtype`과 같아요).
- `can_cast`에 `casting=` 인자가 없어요. 언제나 "저절로 바꿔도 되는가"(numpy의 `'safe'`와 같은 방향)만 답해요. Python 숫자는 받지 않아요.
- `result_type`은 값의 크기를 보지 않아요. 종류마다 dtype이 하나라서 Python 숫자는 같은 종류의 배열과 똑같이 승격해요.
- 결과는 numpy dtype이 아니라 stardust의 dtype 객체예요. numpy dtype이나 Python 타입(`float`)을 넣으면 `TypeError`예요.
- `isdtype`의 첫 인자에 배열을 넣을 수 없어요.
