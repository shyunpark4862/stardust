## 한눈에 보기

네 함수는 모두 실수를 **정수 값**으로 맞추지만, 어느 쪽 정수로 맞출지가 달라요.

| 함수 | 어느 쪽으로 | `1.7` | `-1.7` | `1.2` | `-1.2` |
|---|---|:---:|:---:|:---:|:---:|
| `floor` | 더 작은 쪽(내림) | 1 | -2 | 1 | -2 |
| `ceil` | 더 큰 쪽(올림) | 2 | -1 | 2 | -1 |
| `trunc` | 0 쪽(소수 부분 버림) | 1 | -1 | 1 | -1 |
| `round` | 가장 가까운 쪽 | 2 | -2 | 1 | -1 |

```python
>>> import stardust as sd
>>> y = sd.asarray([-1.7, -1.2, 1.2, 1.7])
>>> sd.floor(y)
array([-2.0, -2.0,  1.0,  1.0], dtype=float64)
>>> sd.ceil(y)
array([-1.0, -1.0,  2.0,  2.0], dtype=float64)
>>> sd.trunc(y)
array([-1.0, -1.0,  1.0,  1.0], dtype=float64)
>>> sd.round(y)
array([-2.0, -1.0,  1.0,  2.0], dtype=float64)
```

결과가 `2.0`처럼 **여전히 실수**라는 점을 눈여겨보세요. [결과의 dtype](#결과의-dtype)에서 자세히 설명해요.

## floor, ceil, trunc

수직선 위에서 생각하면 쉬워요.

- **`floor`**(바닥): 왼쪽으로 가서 만나는 첫 정수. 언제나 원래 값 이하예요.
- **`ceil`**(천장): 오른쪽으로 가서 만나는 첫 정수. 언제나 원래 값 이상이에요.
- **`trunc`**(잘라 내기): 소수점 아래를 그냥 버려요. 양수에서는 `floor`, 음수에서는 `ceil`과 같아요.

양수만 다룬다면 `floor`와 `trunc`는 같아요. **음수가 섞이면 달라지니** 어느 쪽이 필요한지 생각해서 고르세요.

```python
>>> sd.floor(sd.asarray([[1.5, -1.5], [2.5, -2.5]]))
array([[ 1.0, -2.0],
       [ 2.0, -3.0]], dtype=float64)
```

`ceil`은 "몇 개가 필요한가"를 셀 때 자주 써요. 23명을 10명씩 태우려면 차가 `ceil(23 / 10) = 3`대 필요해요.

```python
>>> sd.ceil(sd.asarray([23, 30, 31]) / 10)
array([3.0, 3.0, 4.0], dtype=float64)
```

## round: 가장 가까운 정수로

`round`는 가장 가까운 정수로 맞춰요. 그런데 `0.5`, `1.5`, `2.5`처럼 **두 정수의 딱 중간**이면 어떻게 될까요? stardust는 **짝수 쪽**으로 보내요. 이것을 "짝수 반올림"(half-to-even, 은행원 반올림)이라고 해요.

```python
>>> sd.round(sd.asarray([0.5, 1.5, 2.5, 3.5, 4.5]))
array([0.0, 2.0, 2.0, 4.0, 4.0], dtype=float64)
>>> sd.round(sd.asarray([-2.5, -1.5, -0.5, 0.5, 1.5, 2.5]))
array([-2.0, -2.0, -0.0,  0.0,  2.0,  2.0], dtype=float64)
```

| x | 0.5 | 1.5 | 2.5 | 3.5 | 4.5 | -0.5 | -1.5 | -2.5 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `round(x)` | 0 | 2 | 2 | 4 | 4 | -0 | -2 | -2 |
| 학교에서 배운 반올림 | 1 | 2 | 3 | 4 | 5 | -1 | -2 | -3 |

중간이 아니면 그냥 가까운 쪽이에요. `2.5`는 `2`가 되지만 `2.5000001`은 `3`이 돼요.

<Callout type="warn" title="2.5는 3이 아니라 2예요">

학교에서 배운 "5 이상이면 올림"과 달라요. 중간값을 늘 위로 올리면 많은 수를 반올림해서 더했을 때 합이 조금씩 커지는 치우침이 생겨요. 짝수 쪽으로 보내면 올림과 내림이 반반씩 일어나서 치우침이 없어요. Python의 내장 `round()`도 같은 규칙이에요.

</Callout>

```python
>>> sd.round(2.5)
2.0
>>> round(2.5)
2
```

### 학교식 반올림이 필요하면

중간값을 0에서 먼 쪽으로 보내는 반올림이 필요하면, 중간인 자리만 골라서 직접 처리하세요.

```python
>>> v = sd.asarray([-2.5, -0.5, 0.5, 1.5, 2.5, 2.4])
>>> t = sd.trunc(v)
>>> sd.where(sd.abs(v - t) == 0.5, t + sd.sign(v), sd.round(v))
array([-3.0, -1.0,  1.0,  2.0,  3.0,  2.0], dtype=float64)
```

흔히 쓰는 `floor(x + 0.5)`는 간단하지만, 0.5를 더하는 순간 반올림 오차가 생겨서 `0.49999999999999994` 같은 값을 `1`로 만들어요. 위 방법은 그런 문제가 없어요.

```python
>>> sd.floor(sd.asarray([0.49999999999999994]) + 0.5)
array([1.0], dtype=float64)
```

## 소수 n자리로 반올림하려면

`round`에는 **자릿수 인자가 없어요.** `sd.round(x, 2)`처럼 쓰면 에러예요.

```python
>>> sd.round(sd.asarray([3.14159]), 2)
Traceback (most recent call last):
    ...
TypeError: round(): incompatible function arguments. ...
```

대신 **10의 거듭제곱을 곱하고, 반올림하고, 다시 나눠요.** 소수 둘째 자리라면 100을 곱했다가 100으로 나눠요.

```python
>>> p = sd.asarray([3.14159, 2.71828])
>>> sd.round(p * 100) / 100
array([3.14, 2.72], dtype=float64)
```

반대로 십의 자리, 백의 자리처럼 정수 쪽 자리에서 반올림하려면 먼저 나누고 나중에 곱해요.

```python
>>> sd.round(sd.asarray([1234.5678]) / 100) * 100
array([1200.0], dtype=float64)
```

<Callout type="warn" title="소수는 정확히 나타나지 않아요">

`1.005`는 실수로 정확히 나타낼 수 없어서 실제로는 `1.00499999...`예요. 100을 곱하면 `100.49999999999999`가 되어 `1.0`으로 반올림돼요. Python의 `round(x, 2)`와도 결과가 다를 수 있어요(예: `2.675`는 이 방법으로 `2.68`, Python의 `round(2.675, 2)`는 `2.67`). 돈처럼 소수 자릿수가 정확해야 하는 값은 정수 단위(원, 센트)로 바꿔서 다루세요.

</Callout>

```python
>>> sd.asarray([1.005]) * 100
array([100.49999999999999], dtype=float64)
>>> sd.round(sd.asarray([1.005]) * 100) / 100
array([1.0], dtype=float64)
```

## 결과의 dtype

네 함수 모두 **입력과 같은 dtype**을 돌려줘요.

| 입력 | `floor`, `ceil`, `trunc` | `round` |
|---|:---:|:---:|
| bool | bool | bool |
| int64 | int64 | int64 |
| float64 | float64 | float64 |
| complex128 | `TypeError` | complex128 |

### 실수는 실수로 남아요

`floor(2.7)`은 정수 `2`가 아니라 실수 `2.0`이에요. 실수 배열에는 `inf`나 NaN처럼 정수로 나타낼 수 없는 값이 있을 수 있고, int64 범위를 넘는 큰 값도 있을 수 있어서, 결과의 종류를 바꾸지 않아요. Python의 `math.floor()`가 `int`를 돌려주는 것과 다르니 조심하세요.

```python
>>> sd.floor(2.7)
2.0
>>> sd.floor(sd.asarray([sd.nan, sd.inf, -sd.inf]))
array([ nan,  inf, -inf], dtype=float64)
```

정수 배열이 필요하면 **반올림한 다음** `astype(sd.int64)`로 바꾸세요. `astype`만 쓰면 0 쪽으로 버리기 때문에(`trunc`와 같아요) 음수에서 결과가 달라요.

```python
>>> w = sd.asarray([7.9, -7.9])
>>> sd.floor(w).astype(sd.int64)
array([ 7, -8], dtype=int64)
>>> w.astype(sd.int64)
array([ 7, -7], dtype=int64)
```

### 정수와 bool은 그대로예요

정수는 이미 정수 값이라 바뀌지 않고, dtype도 int64 그대로예요. bool도 bool 그대로예요.

```python
>>> sd.floor(sd.asarray([1, -2, 3]))
array([ 1, -2,  3], dtype=int64)
>>> sd.round(sd.asarray([True, False]))
array([ True, False], dtype=bool)
>>> sd.floor(7)
7
```

### 복소수

`round`는 복소수의 실수부와 허수부를 **각각** 반올림해요. `floor`, `ceil`, `trunc`는 복소수에서 "더 작은 쪽"을 정할 수 없어서 `TypeError`예요.

```python
>>> sd.round(sd.asarray([1.5 + 2.5j, -0.5 - 1.7j]))
array([ (2+2j), (-0-2j)], dtype=complex128)
>>> sd.floor(sd.asarray([1 + 1j]))
Traceback (most recent call last):
    ...
TypeError: floor(): not supported for complex128
```

## `out`: 결과를 기존 배열에 쓰기

`out=`에 배열을 주면 그 배열에 결과를 적고, 그 배열을 돌려줘요. 결과의 dtype이 `out`에 손실 없이 들어가야 해요. 실수 결과는 값이 정수여도 정수 배열에 담을 수 없어요(값이 아니라 dtype으로 판단하기 때문이에요).

```python
>>> sd.floor(sd.asarray([2, 3]), out=sd.zeros(2))
array([2.0, 3.0], dtype=float64)
>>> sd.floor(sd.asarray([2.7]), out=sd.zeros(1, dtype=sd.int64))
Traceback (most recent call last):
    ...
TypeError: floor(): cannot implicitly convert float64 to int64 (that would lose information); convert explicitly with astype
```

## 조심할 점

### 곱한 결과가 정수에서 살짝 모자라면

`0.29 * 100`은 `29`처럼 보이지만 실수 계산으로는 `28.999999999999996`이에요. 여기에 `floor`를 쓰면 `28`이 돼요. 계산 결과에 `floor`나 `ceil`을 쓸 때는 이런 오차를 생각하세요. 가까운 정수가 목적이라면 `round`가 안전해요.

```python
>>> sd.asarray([0.29]) * 100
array([28.999999999999996], dtype=float64)
>>> sd.floor(sd.asarray([0.29]) * 100)
array([28.0], dtype=float64)
>>> sd.round(sd.asarray([0.29]) * 100)
array([29.0], dtype=float64)
```

### `-0.0`이 나올 수 있어요

음수를 0으로 맞추면 결과가 `-0.0`이에요. 값은 `0.0`과 같아서(`==`로 비교하면 같아요) 계산에는 문제가 없지만, 출력에 `-0.0`이 보여서 놀랄 수 있어요. 자세한 것은 [부호와 절댓값](/api/array/sign/)을 보세요.

```python
>>> sd.ceil(sd.asarray([-0.5]))
array([-0.0], dtype=float64)
>>> sd.round(-0.4)
-0.0
```

### 리스트는 받지 않아요

먼저 [`asarray`](/api/array/asarray/)로 배열로 바꾸세요.

```python
>>> sd.round([1.5])
Traceback (most recent call last):
    ...
TypeError: round(): 'x' must be an sd.ndarray or a bool, int, float or complex, not list
```

## 비슷한 함수와의 차이

| 헷갈리는 것 | 차이 |
|---|---|
| `floor(x1 / x2)`와 [`x1 // x2`](/api/array/floor-divide/) | 값은 같지만, `//`는 정수끼리면 정수를 돌려주고 큰 정수에서도 정확해요. `floor(x1 / x2)`는 언제나 실수예요. |
| `trunc(x)`와 [`x.astype(sd.int64)`](/api/array/astype/) | 둘 다 0 쪽으로 버려요. `trunc`는 실수 dtype 그대로, `astype`은 int64로 바꿔요. NaN은 `astype`에서 0, 범위 밖은 끝값이 돼요. |
| `sd.round(x)`와 Python `round(x)` | 둘 다 짝수 반올림이에요. Python은 `int`를 돌려주고 자릿수 인자가 있어요. |
| `round`와 [`clip`](/api/array/clip/) | `clip`은 정수로 맞추지 않고 범위 밖의 값만 잘라요. |

```python
>>> sd.asarray([7]) // 2
array([3], dtype=int64)
>>> sd.floor(sd.asarray([7]) / 2)
array([3.0], dtype=float64)
```

## numpy를 아는 분께

- `round`에 `decimals` 인자가 없어요. `round(x * 10**n) / 10**n`으로 계산하세요. `around`, `rint`, `fix` 별칭은 없어요.
- 반올림 규칙은 numpy처럼 짝수 반올림이에요.
- 정수 입력은 numpy 2처럼 int64 그대로예요. bool 입력은 네 함수 모두 bool이에요(numpy의 `round`는 bool을 float16으로 바꿔요).
- `floor`, `ceil`, `trunc`에 복소수를 넣으면 `TypeError`예요. `round`는 복소수를 받아요.
- `out`은 keyword-only이고 `where=` 인자는 없어요. Python 숫자를 넣으면 numpy 스칼라가 아니라 Python 숫자를 돌려줘요.
