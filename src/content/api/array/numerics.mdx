## 한눈에 보기

stardust의 원소 계산(덧셈, 나눗셈, 제곱근 같은 원소별 함수와 연산자, 그리고 합이나 곱 같은 집계)은 **원소의 값 때문에 실패하지 않아요.** 0으로 나누든, 음수의 제곱근을 구하든, 정수가 범위를 넘든, 정해진 결과를 내고 계속 계산해요. 에러는 **타입이나 모양이 맞지 않을 때만** 나요.

```python
>>> import stardust as sd
>>> sd.asarray([7, -7, 0]) // 0
array([0, 0, 0], dtype=int64)
>>> sd.asarray([1.0, -1.0, 0.0]) / 0
array([ inf, -inf,  nan], dtype=float64)
>>> sd.asarray([2**63 - 1]) + 1
array([-9223372036854775808], dtype=int64)
```

배열 하나에 원소가 백만 개 있을 때, 그중 하나가 0이라고 계산 전체가 멈추면 곤란해요. 그래서 문제가 되는 원소에도 결과를 정해 두고, 나머지 원소는 정상적으로 계산해요. 결과에 이상한 값이 섞였는지는 나중에 [`isnan`, `isinf`, `isfinite`](/api/array/isnan/)로 확인하면 돼요.

규칙을 dtype별로 정리하면 이래요.

| 상황 | 정수 (int64, bool) | 실수·복소수 (float64, complex128) |
|---|---|---|
| 결과가 담을 수 있는 범위를 벗어남 | 반대쪽 끝으로 넘어가요 | 너무 크면 `inf`, 너무 작으면 `0.0` |
| `a / 0` | 실수로 계산해서 `inf`, `-inf`, `nan` | `inf`, `-inf`, `nan` |
| `a // 0` | `0` | `inf`, `-inf`, `nan` |
| `a % 0` | `a` | `nan` |
| 음수 지수 `a ** -n` | 정수 결과 (`1`, `-1`, `0`) | 보통의 실수 결과 |
| 정의되지 않는 계산 (`sqrt(-1.0)` 등) | 해당 없음 (실수로 계산해요) | `nan` |
| 경고 | 없어요 | 없어요 |

## 정수가 범위를 넘으면: 반대쪽으로 넘어가요

int64는 -9,223,372,036,854,775,808(-2⁶³)부터 9,223,372,036,854,775,807(2⁶³ - 1)까지 담아요. 계산 결과가 이 범위를 넘으면 에러도 경고도 없이 **반대쪽 끝으로 넘어가요.** 자동차의 주행 거리계가 99999 다음에 00000이 되는 것과 비슷해요. 이것을 wraparound(감아 돌기)라고 해요.

```python
>>> big = sd.asarray([2**63 - 1])
>>> big + 1
array([-9223372036854775808], dtype=int64)
>>> sd.asarray([-2**63]) - 1
array([9223372036854775807], dtype=int64)
```

<Fig caption="int64의 수는 원처럼 이어져 있어요. 가장 큰 수(MAX) 다음은 가장 작은 수(MIN)예요.">
  <ArrayFig data={['MAX-1', 'MAX', 'MIN', 'MIN+1']} tones={['', 'b', 'b', '']} note="MAX + 1 = MIN" />
</Fig>

곱셈이나 거듭제곱처럼 값이 빨리 커지는 계산에서 특히 조심해야 해요. 결과가 엉뚱한 양수일 수도 있어서 넘어갔다는 것을 알아채기 어려워요.

```python
>>> sd.asarray([9_000_000_000]) * 9_000_000_000
array([7213023705161793536], dtype=int64)
>>> sd.asarray([10]) ** 19
array([-8446744073709551616], dtype=int64)
>>> sd.asarray([2**62]) * 4
array([0], dtype=int64)
```

합과 곱 같은 집계도 같은 규칙이에요.

```python
>>> sd.sum(sd.asarray([2**62, 2**62]))
-9223372036854775808
```

넘어가는 규칙 때문에 **수학적으로는 이상한 결과**가 몇 가지 있어요. 가장 작은 수 -2⁶³은 부호를 바꾼 2⁶³을 int64로 담을 수 없어서, 부호를 바꿔도 절댓값을 구해도 자기 자신이에요.

```python
>>> lo = sd.asarray([-2**63])
>>> -lo
array([-9223372036854775808], dtype=int64)
>>> sd.abs(lo)
array([-9223372036854775808], dtype=int64)
>>> lo // -1
array([-9223372036854775808], dtype=int64)
```

<Callout type="warn" title="큰 정수를 다룰 때">
  결과가 2⁶³(약 9.2 × 10¹⁸)에 가까워질 수 있다면 정수 대신 실수로 계산하세요. `x.astype(sd.float64)`로 바꾸거나 `sd.sum(x, dtype=sd.float64)`처럼 `dtype=`을 주면 돼요. 실수는 유효숫자가 약 16자리라 정확한 정수는 아니지만, 크기가 엉뚱하게 넘어가지는 않아요. int64의 범위는 `sd.iinfo(sd.int64)`로 확인할 수 있어요.
</Callout>

```python
>>> sd.asarray([9_000_000_000]).astype(sd.float64) * 9_000_000_000
array([8.1e+19], dtype=float64)
>>> sd.iinfo(sd.int64).max
9223372036854775807
```

배열에서 **꺼낸 Python 숫자**는 범위가 없는 Python `int`라서 넘어가지 않아요. 반대로 stardust 함수에 Python 숫자만 넣어도 계산은 int64 규칙을 따라요. 자세한 것은 [배열의 기본](/api/array/basics/)에 있어요.

```python
>>> big[0] + 1
9223372036854775808
>>> sd.add(2**63 - 1, 1)
-9223372036854775808
```

## 정수를 0으로 나누면

Python에서 `7 // 0`은 `ZeroDivisionError`지만, stardust의 정수 배열은 0으로 나눠도 에러가 아니에요. 결과는 이렇게 정해져 있어요.

| 계산 | 결과 |
|---|---|
| `a // 0` (몫) | `0` |
| `a % 0` (나머지) | `a` 그대로 |
| `a / 0` (나눗셈) | 실수로 계산해서 `inf`, `-inf`, `nan` (아래 실수 절) |

```python
>>> a = sd.asarray([7, -7, 0, 5])
>>> a // 0
array([0, 0, 0, 0], dtype=int64)
>>> a % 0
array([ 7, -7,  0,  5], dtype=int64)
>>> a / 0
array([ inf, -inf,  nan,  inf], dtype=float64)
```

몫을 0, 나머지를 `a`로 정한 이유는 **몫과 나머지의 관계** `a == (a // b) * b + a % b`가 `b`가 0일 때도 성립하게 하기 위해서예요. `(a // 0) * 0 + a % 0`은 `0 + a`, 곧 `a`예요.

배열 중간에 0이 섞여 있어도 나머지 원소는 정상적으로 계산돼요.

```python
>>> num = sd.asarray([10, 7, 3])
>>> den = sd.asarray([2, 0, 3])
>>> num // den
array([5, 0, 1], dtype=int64)
```

<Callout type="warn" title="몫 0이 진짜 0인지 구별하세요">
  위 결과의 가운데 `0`은 7을 0으로 나눈 결과예요. 진짜 몫이 0인 경우(`3 // 5`)와 겉으로 구별되지 않아요. 0으로 나눈 자리를 다른 값으로 표시하고 싶으면 `sd.where`로 직접 골라 주세요.
</Callout>

```python
>>> sd.where(den == 0, -1, num // den)
array([ 5, -1,  1], dtype=int64)
```

## `//`와 `%`의 부호

정수의 몫 `//`는 **내림 나눗셈**이에요. 나눈 결과를 0 쪽이 아니라 **더 작은 쪽(음의 무한대 쪽)** 으로 내려요. 그래서 `-7 // 2`는 `-3`이 아니라 `-4`예요(-3.5보다 작은 정수 중 가장 큰 것).

나머지 `%`의 부호는 **나누는 수(오른쪽)의 부호**를 따라요. 이 두 규칙은 Python의 `//`, `%`와 같아요.

```python
>>> a = sd.asarray([7, -7, 7, -7])
>>> d = sd.asarray([2, 2, -2, -2])
>>> a // d
array([ 3, -4, -4,  3], dtype=int64)
>>> a % d
array([ 1,  1, -1, -1], dtype=int64)
>>> (a // d) * d + a % d
array([ 7, -7,  7, -7], dtype=int64)
```

| `a` | `d` | `a / d` | `a // d` | `a % d` |
|:---:|:---:|:---:|:---:|:---:|
| 7 | 2 | 3.5 | 3 | 1 |
| -7 | 2 | -3.5 | -4 | 1 |
| 7 | -2 | -3.5 | -4 | -1 |
| -7 | -2 | 3.5 | 3 | -1 |

나누는 수가 양수이면 나머지는 언제나 0 이상이에요. 그래서 `%`는 "주기"를 계산할 때 편해요. 예를 들어 `days % 7`은 음수 날짜에서도 0부터 6 사이의 요일 번호를 줘요.

0 쪽으로 버린 몫(`-7`을 2로 나눠 `-3`)이 필요하면 `sd.trunc(a / d)`를 써요. 결과는 실수예요.

```python
>>> sd.trunc(a / d)
array([ 3.0, -3.0, -3.0,  3.0], dtype=float64)
```

실수의 `//`와 `%`도 같은 부호 규칙이에요. 실수를 0으로 나누면 아래의 IEEE 규칙을 따라요.

```python
>>> sd.asarray([7.5, -7.5]) % 2.0
array([1.5, 0.5], dtype=float64)
>>> sd.asarray([7.0]) // 0.0
array([inf], dtype=float64)
>>> sd.asarray([7.0]) % 0.0
array([nan], dtype=float64)
```

몫과 나머지 함수의 자세한 내용은 [몫과 나머지](/api/array/floor-divide/)에 있어요.

## 정수의 음수 거듭제곱

정수끼리의 거듭제곱 결과는 정수예요. 그런데 `2 ** -1`은 수학적으로 0.5라서 정수로 나타낼 수 없어요. stardust는 이때도 **정수 결과를 내요.** 실수로 바꾸지 않아요.

| 밑 | `밑 ** -n`의 결과 | 이유 |
|---|---|---|
| `1` | `1` | 1의 역수는 1이에요. |
| `-1` | `n`이 짝수면 `1`, 홀수면 `-1` | -1의 역수는 -1이에요. |
| `0` | `0` | 0으로 나누기 규칙(`1 // 0 == 0`)을 따라요. |
| 그 밖의 정수 | `0` | 절댓값이 1보다 작은 수를 0 쪽으로 버린 값이에요. |

```python
>>> p = sd.asarray([1, -1, 2, 0, -2])
>>> p ** -1
array([ 1, -1,  0,  0,  0], dtype=int64)
>>> p ** -2
array([1, 1, 0, 0, 0], dtype=int64)
```

<Callout type="warn" title="Python의 2 ** -1과 결과가 달라요">
  Python에서는 `2 ** -1`이 `0.5`(float)지만, stardust의 정수 거듭제곱은 `0`이에요. Python 숫자만 넣은 `sd.pow(2, -1)`도 `0`이에요. 실수 결과가 필요하면 밑이나 지수 중 하나를 실수로 주세요(`2.0 ** -1`).
</Callout>

```python
>>> sd.pow(2, -1)
0
>>> sd.asarray([2.0]) ** -1
array([0.5], dtype=float64)
>>> sd.asarray([2]) ** -1.0
array([0.5], dtype=float64)
```

정수 거듭제곱도 범위를 넘으면 넘어가요(`2 ** 63`은 -2⁶³, `2 ** 64`는 0). `0 ** 0`은 `1`이에요. 거듭제곱 함수는 [거듭제곱과 제곱근](/api/array/pow/)에 있어요.

## 실수: IEEE 754 규칙

실수(float64)와 복소수(complex128)의 계산은 컴퓨터 실수의 국제 표준인 **IEEE 754**를 따라요. 이 표준에는 보통의 수 말고도 특별한 값이 세 가지 있어요.

| 값 | 뜻 | 쓰는 법 |
|---|---|---|
| `inf`, `-inf` | 무한대. 너무 커서 담을 수 없는 값이나 0으로 나눈 값 | `sd.inf`, `-sd.inf` |
| `nan` | NaN(숫자가 아님). 값을 정할 수 없는 계산의 결과 | `sd.nan` |
| `-0.0` | 음의 0. 값은 0과 같지만 부호를 기억해요 | `-0.0` |

어떤 계산이 이런 값을 내는지 보면 이래요.

| 계산 | 결과 | 이유 |
|---|---|---|
| `1.0 / 0`, `-1.0 / 0` | `inf`, `-inf` | 0에 가까운 수로 나누면 한없이 커져요. |
| `0.0 / 0` | `nan` | 정할 수 없어요. |
| `1e308 * 10` | `inf` | float64의 최댓값(약 1.8 × 10³⁰⁸)을 넘었어요. |
| `5e-324 / 2` | `0.0` | 너무 작아서 0이 됐어요. |
| `inf - inf`, `inf * 0` | `nan` | 정할 수 없어요. |
| `sqrt(-1.0)`, `log(-1.0)` | `nan` | 실수 안에는 답이 없어요. |
| `log(0.0)` | `-inf` | 0에 가까워질수록 한없이 작아져요. |

```python
>>> f = sd.asarray([1.0, -1.0, 0.0])
>>> f / 0
array([ inf, -inf,  nan], dtype=float64)
>>> sd.asarray([1e308]) * 10
array([inf], dtype=float64)
>>> sd.asarray([sd.inf]) - sd.inf
array([nan], dtype=float64)
>>> sd.log(sd.asarray([0.0, -1.0]))
array([-inf,  nan], dtype=float64)
```

정수 배열을 `/`로 나누면 먼저 실수로 바꿔서 계산하므로 위와 같은 규칙이에요. 정수 몫 `//`와는 결과가 다르니 주의하세요.

```python
>>> sd.asarray([1, -1, 0]) / 0
array([ inf, -inf,  nan], dtype=float64)
```

### 실수에서 답이 없어도 복소수에서는 있어요

`sqrt(-1.0)`이 NaN인 것은 **실수 배열**이기 때문이에요. 같은 값을 복소수 배열로 넣으면 복소수 답이 나와요. 결과의 종류는 값이 아니라 입력의 dtype으로 정해지기 때문이에요.

```python
>>> sd.sqrt(sd.asarray([-1.0]))
array([nan], dtype=float64)
>>> sd.sqrt(sd.asarray([-1.0 + 0j]))
array([1j], dtype=complex128)
```

### 음의 0

`-0.0`은 `0.0`과 **같은 값**이에요. `==`로 비교하면 같아요. 다만 부호를 기억하고 있어서, 1을 나누면 `-inf`가 되는 등 몇몇 계산에서 차이가 드러나요.

```python
>>> z = sd.asarray([0.0, -0.0])
>>> z == 0
array([True, True], dtype=bool)
>>> 1 / z
array([ inf, -inf], dtype=float64)
>>> sd.signbit(z)
array([False,  True], dtype=bool)
```

음의 0은 아주 작은 음수가 0으로 반올림되거나(`-1e-300 * 1e-300`), 0에 음수를 곱하거나(`0.0 * -5`), 음수를 반올림할 때(`round(-0.4)`) 생겨요. 보통은 신경 쓰지 않아도 되지만, 출력에 `-0.0`이 보여도 놀라지 마세요. 부호 비트를 직접 확인하려면 `sd.signbit`을 써요.

### 실수는 작은 오차를 품고 있어요

float64는 대부분의 소수를 정확히 담지 못해요. `0.1`은 실제로는 0.1에 아주 가까운 다른 수예요. 그래서 계산 결과의 마지막 자리가 조금 어긋날 수 있어요.

```python
>>> sd.asarray([0.1]) + 0.2
array([0.30000000000000004], dtype=float64)
>>> sd.asarray([0.1]) + 0.2 == 0.3
array([False], dtype=bool)
```

stardust만의 문제가 아니라 컴퓨터 실수 전반의 성질이에요. 실수 결과를 `==`로 비교하지 말고 `abs(a - b) < 1e-9`처럼 **충분히 가까운지**로 판단하세요.

## NaN과의 비교

NaN은 "모르는 값"이라 **어떤 값과도 같지 않고, 크지도 작지도 않아요.** 자기 자신과도 같지 않아요.

| 비교 | 결과 |
|---|---|
| `nan == nan` | `False` |
| `nan != nan` | `True` |
| `nan < 1`, `nan > 1`, `nan <= nan` | 모두 `False` |

```python
>>> n = sd.asarray([1.0, sd.nan])
>>> n == n
array([ True, False], dtype=bool)
>>> n != n
array([False,  True], dtype=bool)
>>> n > 0
array([ True, False], dtype=bool)
```

<Callout type="warn" title="NaN을 찾을 때 == 를 쓰면 안 돼요">
  `x == sd.nan`은 NaN이 있어도 언제나 `False`예요. NaN인지는 반드시 `sd.isnan(x)`로 확인하세요.
</Callout>

```python
>>> n == sd.nan
array([False, False], dtype=bool)
>>> sd.isnan(n)
array([False,  True], dtype=bool)
>>> sd.any(sd.isnan(n))
True
```

NaN은 계산에 섞이면 결과도 NaN으로 만들어요(전파). 합, 평균, 최댓값도 NaN이 하나라도 있으면 NaN이에요. NaN을 건너뛰고 계산하려면 `nansum`, `nanmax` 같은 [NaN을 건너뛰는 집계](/api/array/nan-reductions/)를 써요. 정렬에서는 NaN을 가장 큰 값으로 쳐서 맨 끝에 놓아요([정렬](/api/array/sort/)).

```python
>>> sd.max(sd.asarray([1.0, sd.nan, 3.0]))
nan
```

## 정수와 실수의 비교

정수와 실수를 비교하면 **정수를 float64로 바꾼 다음** 비교해요. 보통은 생각대로 동작해요.

```python
>>> sd.asarray([1, 2, 3]) == sd.asarray([1.0, 2.5, 3.0])
array([ True, False,  True], dtype=bool)
>>> sd.asarray([1, 2, 3]) < 2.5
array([ True,  True, False], dtype=bool)
```

다만 2⁵³(약 9 × 10¹⁵)보다 큰 정수는 float64로 정확히 바뀌지 않아서, 다른 정수가 같은 실수로 바뀔 수 있어요. 이때는 수학적으로 다른 두 수가 같다고 나와요.

```python
>>> sd.asarray([2**53 + 1]) == 2.0**53
array([True], dtype=bool)
>>> 2**53 + 1 == 2.0**53
False
```

Python의 `==`는 정수와 실수를 정확히 비교해서 `False`지만, stardust는 `True`예요. 정수끼리 비교하면 정확해요.

```python
>>> sd.asarray([2**53 + 1]) == 2**53
array([False], dtype=bool)
```

비교 함수는 [비교](/api/array/comparison/)에 있어요.

## 복소수에는 크기 순서가 없어요

복소수는 평면 위의 점이라 "어느 쪽이 더 큰가"가 정해져 있지 않아요. 그래서 **크기 순서가 필요한 연산에 복소수를 넣으면 `TypeError`** 예요.

| 복소수를 받지 않는 것 (`TypeError`) | 복소수를 받는 것 |
|---|---|
| `<` `<=` `>` `>=`, `less` 등 크기 비교 | `==`, `!=`, `equal`, `not_equal` |
| `maximum`, `minimum`, `clip` | `abs` (크기를 실수로 돌려줘요) |
| `min`, `max`, `argmin`, `argmax` | `round` (실수부·허수부를 각각) |
| `sort`, `argsort` | `unique_values` 등 고유한 값 |
| `floor`, `ceil`, `trunc` | 사칙연산, `sqrt`, `exp` 등 |
| `//`, `%` (`floor_divide`, `remainder`) | |
| `atan2` | |

```python
>>> cz = sd.asarray([1 + 1j, 2 + 0j])
>>> cz == 2
array([False,  True], dtype=bool)
>>> cz < 2
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for <: complex128 and int64
>>> sd.max(cz)
Traceback (most recent call last):
    ...
TypeError: max(): not supported for complex128
```

연산자로 쓰면 `unsupported operand dtypes for <: ...`, 함수로 쓰면 `max(): not supported for ...`처럼 메시지 모양이 조금 달라요. 복소수의 **크기**로 비교하고 싶다면 `sd.abs`로 크기를 구한 다음 그것을 비교하거나 정렬해요.

```python
>>> sd.abs(cz)
array([1.4142135623730951,                2.0], dtype=float64)
>>> sd.argmax(sd.abs(cz))
1
```

## 경고는 없어요

stardust는 **경고를 하나도 내지 않아요.** 0으로 나누거나 NaN이 생겨도 화면에 아무것도 나오지 않아요. 경고를 켜고 끄는 설정(`errstate` 같은 것)도 없어요. 문제가 있으면 에러로 멈추고, 문제가 아니면 조용히 결과를 내요.

그래서 결과에 특별한 값이 생겼는지는 직접 확인해야 해요.

```python
>>> r = sd.asarray([1.0, 2.0, 0.0]) / sd.asarray([2.0, 0.0, 0.0])
>>> r
array([0.5, inf, nan], dtype=float64)
>>> sd.isfinite(r)
array([ True, False, False], dtype=bool)
>>> sd.all(sd.isfinite(r))
False
```

| 확인하고 싶은 것 | 쓸 것 |
|---|---|
| NaN인가 | `sd.isnan(x)` |
| 무한대(`inf`, `-inf`)인가 | `sd.isinf(x)` |
| 보통의 수인가 (NaN도 무한대도 아님) | `sd.isfinite(x)` |
| 하나라도 문제가 있는가 | `not sd.all(sd.isfinite(x))` |

정수의 넘침은 결과만 봐서는 알 수 없어요. 큰 값이 나올 수 있는 계산이라면 미리 실수로 계산하거나, 입력의 크기를 `sd.max(sd.abs(x))`처럼 확인해 두세요.

## 스레드 수와 상관없이 같은 결과

stardust는 큰 배열을 여러 스레드(동시에 일하는 일꾼)로 나눠 계산할 수 있어요. 스레드 수는 `sd.set_num_threads`로 바꿀 수 있지만, **결과는 스레드 수와 상관없이 마지막 비트까지 같아요.** 실수 합처럼 더하는 순서에 따라 마지막 자리가 달라질 수 있는 계산도 마찬가지예요.

```python
>>> n_before = sd.get_num_threads()
>>> v = sd.linspace(0.0, 1.0, 1_000_001) ** 3
>>> sd.set_num_threads(1)
>>> one = sd.sum(v)
>>> sd.set_num_threads(4)
>>> four = sd.sum(v)
>>> sd.set_num_threads(n_before)
>>> one == four
True
```

같은 데이터를 넣으면 언제, 몇 번을 실행해도 같은 결과가 나와요. 실험 결과를 다시 만들어 내거나 테스트에서 결과를 정확히 비교할 때 이 약속에 기댈 수 있어요. 스레드 설정은 [스레드 수](/api/array/threads/)에 있어요.

## numpy를 아는 분께

- **경고가 없어요.** numpy가 `RuntimeWarning`(0으로 나누기, 잘못된 값, 넘침)을 내는 자리에서 stardust는 조용히 같은 결과(`inf`, `nan`)를 내요. `np.errstate`, `np.seterr`에 해당하는 것은 없어요.
- **정수를 0으로 나누면** `a // 0 == 0`, `a % 0 == a`예요. numpy는 경고와 함께 0을 내요(`%`도 0).
- **정수의 음수 거듭제곱이 에러가 아니에요.** numpy는 `ValueError: Integers to negative integer powers are not allowed`를 내지만, stardust는 `1`, `-1`, `0` 중 하나를 내요.
- 정수 넘침은 numpy처럼 감아 돌아요. numpy 스칼라 연산에서 나오는 넘침 경고도 없어요.
- **정수와 실수의 비교**는 정수를 float64로 바꿔서 해요. numpy와 같고, Python의 `==`와는 달라요.
- **복소수의 순서 비교는 `TypeError`예요.** numpy는 `<`, `max`, `sort`, `maximum`에서 복소수를 사전순(실수부 먼저, 같으면 허수부)으로 비교하지만 stardust는 받지 않아요.
- 결과는 스레드 수와 무관하게 비트까지 같아요. 다만 실수 합의 더하는 순서가 numpy와 같다고 보장하지 않으므로 numpy와 마지막 자리가 다를 수 있어요.
