## 한눈에 보기

`reshape`는 배열의 **원소는 그대로 두고 모양만** 바꿔요. 원소 여섯 개짜리 1차원 배열을 2행 3열로 만들 수도, 3행 2열로 만들 수도 있어요.

```python
>>> import stardust as sd
>>> x = sd.arange(6)
>>> x
array([0, 1, 2, 3, 4, 5], dtype=int64)
>>> sd.reshape(x, (2, 3))
array([[0, 1, 2],
       [3, 4, 5]], dtype=int64)
>>> sd.reshape(x, (3, 2))
array([[0, 1],
       [2, 3],
       [4, 5]], dtype=int64)
```

<Fig caption="원소를 앞에서부터 차례로 새 모양의 칸에 채워 넣어요. 왼쪽에서 오른쪽으로 한 행을 다 채우면 다음 행으로 내려가요.">
  <ArrayFig name="x" data={[0, 1, 2, 3, 4, 5]} tones={['a', 'a', 'a', 'b', 'b', 'b']} note="shape (6,)" />
  <Op note="(2, 3)">→</Op>
  <ArrayFig name="sd.reshape(x, (2, 3))" data={[[0, 1, 2], [3, 4, 5]]} tones={[['a', 'a', 'a'], ['b', 'b', 'b']]} axes note="shape (2, 3)" />
</Fig>

`ravel`은 반대로 어떤 모양이든 **1차원 한 줄로 펴요.**

```python
>>> m = sd.asarray([[1, 2, 3], [4, 5, 6]])
>>> sd.ravel(m)
array([1, 2, 3, 4, 5, 6], dtype=int64)
```

배열에는 같은 일을 하는 메서드 `x.reshape`도 있어요. `ravel`은 메서드가 없고 `sd.ravel(x)`로만 써요.

```python
>>> x.reshape((2, 3))
array([[0, 1, 2],
       [3, 4, 5]], dtype=int64)
```

## 원소 수는 같아야 해요

모양만 바꿀 뿐 원소를 만들거나 버리지 않으므로, **새 모양의 원소 수(각 길이를 모두 곱한 값)가 원래와 같아야** 해요. 원소 6개는 `(2, 3)`, `(3, 2)`, `(1, 6)`, `(6, 1)`, `(6,)` 같은 모양이 될 수 있지만 `(4, 2)`는 될 수 없어요.

```python
>>> sd.reshape(x, (4, 2))
Traceback (most recent call last):
    ...
ValueError: reshape(): cannot reshape array of size 6 into shape (4, 2)
```

차원 수는 자유롭게 늘리고 줄일 수 있어요. 3차원도 돼요.

```python
>>> t = sd.reshape(sd.arange(24), (2, 3, 4))
>>> t.shape
(2, 3, 4)
>>> sd.reshape(t, (6, 4)).shape
(6, 4)
```

## `-1`: 한 자리는 알아서 계산하기

새 모양의 한 자리에 `-1`을 쓰면 "**나머지는 알아서 맞춰 달라**"는 뜻이에요. 원소 수가 맞도록 그 자리의 길이를 계산해 줘요.

```python
>>> sd.reshape(x, (3, -1))
array([[0, 1],
       [2, 3],
       [4, 5]], dtype=int64)
>>> sd.reshape(x, (-1, 2)).shape
(3, 2)
>>> sd.reshape(t, (2, -1)).shape
(2, 12)
```

`(3, -1)`은 "3행인데 열은 몇 개든 좋다"는 뜻이에요. 원소가 6개이니 열은 2개가 돼요. 데이터의 전체 길이를 일일이 세지 않아도 돼서 편해요. 특히 "행 수만 정하고 싶다", "한 행에 4개씩 끊고 싶다" 같은 경우에 자주 써요.

`-1` 하나만 쓰면 1차원으로 펴는 것이 돼요. `sd.ravel(m)`과 같은 결과예요.

```python
>>> sd.reshape(m, -1)
array([1, 2, 3, 4, 5, 6], dtype=int64)
```

`-1`은 한 번만 쓸 수 있어요. 두 자리를 모두 맡기면 어떻게 나눠야 할지 정할 수 없기 때문이에요. 계산해도 나누어떨어지지 않으면 역시 에러예요.

```python
>>> sd.reshape(x, (-1, -1))
Traceback (most recent call last):
    ...
ValueError: reshape(): can only specify one unknown dimension
>>> sd.reshape(x, (4, -1))
Traceback (most recent call last):
    ...
ValueError: reshape(): cannot reshape array of size 6 into shape (4, -1)
```

`-1`이 아닌 음수는 쓸 수 없어요.

```python
>>> sd.reshape(x, (-2, 3))
Traceback (most recent call last):
    ...
ValueError: reshape(): negative dimensions are not allowed
```

## 원소는 어떤 순서로 옮겨지나요

`reshape`와 `ravel`은 원소를 **행 순서**로 읽어요. 배열을 화면에 찍었을 때 보이는 순서, 곧 첫 행의 왼쪽부터 오른쪽으로, 그다음 행으로 내려가는 순서예요. 읽은 원소를 같은 순서로 새 모양에 채워요.

3차원 이상도 같아요. **마지막 축이 가장 빨리 바뀌어요.** `t`를 펴면 `0, 1, 2, ..., 23`이 그대로 나오는 것도 그래서예요.

  <Op note="한 줄로">→</Op>
  <ArrayFig data={[1, 2, 3, 4, 5, 6]} tones={['a', 'a', 'b', 'b', 'm', 'm']} />

  <ArrayFig name="sd.reshape(m, (3, 2))" data={[[1, 2], [3, 4], [5, 6]]} tones={[['a', 'a'], ['b', 'b'], ['m', 'm']]} note="shape (3, 2)" />

### reshape는 전치(뒤집기)가 아니에요

`(2, 3)` 배열을 `(3, 2)`로 바꾸면 "행과 열이 바뀐 것"처럼 생각하기 쉬운데, 그렇지 않아요. 행과 열을 맞바꾸는 것은 **전치**라고 하고, `m.T`나 [`sd.permute_dims`](/api/array/permute_dims/)가 해요.

```python
>>> sd.reshape(m, (3, 2))
array([[1, 2],
       [3, 4],
       [5, 6]], dtype=int64)
>>> m.T
array([[1, 4],
       [2, 5],
       [3, 6]], dtype=int64)
```

<Fig caption="모양은 둘 다 (3, 2)지만 내용이 달라요. reshape는 순서를 유지한 채 다시 끊고, 전치는 첫 행을 첫 열로 세워요.">
  <ArrayFig name="m" data={[[1, 2, 3], [4, 5, 6]]} tones={[['a', 'a', 'a'], ['', '', '']]} />
  <Op note="reshape">→</Op>
  <ArrayFig name="(3, 2)" data={[[1, 2], [3, 4], [5, 6]]} tones={[['a', 'a'], ['a', ''], ['', '']]} />
  <Op note=".T">→</Op>
  <ArrayFig name="m.T" data={[[1, 4], [2, 5], [3, 6]]} tones={[['a', ''], ['a', ''], ['a', '']]} />
</Fig>

<Callout type="warn" title="모양이 맞는다고 뜻이 맞는 것은 아니에요">

  `reshape`는 원소 수만 맞으면 언제나 성공해요. 행이 사람, 열이 과목인 표를 `(과목 수, 사람 수)`로 `reshape`하면 에러 없이 뒤죽박죽인 표가 나와요. 축의 **뜻**을 바꾸고 싶다면(행과 열을 맞바꾸기 등) `reshape`가 아니라 `permute_dims`를 쓰세요.

</Callout>

전치한 배열을 펴면 **보이는 순서대로** 펴져요. 메모리 속 배치와 상관없이 언제나 화면에 찍힌 행 순서예요.

```python
>>> sd.ravel(m.T)
array([1, 4, 2, 5, 3, 6], dtype=int64)
```

## 원본과 메모리를 함께 쓸까요

`reshape`는 가능하면 **값을 복사하지 않고 원본의 메모리를 다른 모양으로 보여 주는 배열**(뷰)을 돌려줘요. 큰 배열도 모양을 바꾸는 비용이 거의 없어요. 대신 결과를 고치면 원본도 함께 바뀌어요.

```python
>>> y = sd.reshape(x, (2, 3))
>>> y.base is x
True
>>> y[0, 0] = 100
>>> x
array([100,   1,   2,   3,   4,   5], dtype=int64)
```

`y.base is x`는 "`y`의 메모리 주인이 `x`다"라는 뜻이에요. 뷰가 무엇이고 언제 생기는지는 [뷰와 복사](/api/array/views/)에 자세히 있어요.

그런데 원소가 메모리에 행 순서대로 놓여 있지 않은 배열은 다른 모양으로 "보여 주기"만으로는 안 될 때가 있어요. 전치한 배열(`m.T`)이 대표적이에요. 이럴 때는 조용히 **복사해서** 새 배열을 만들어요. 결과의 값은 어느 쪽이든 같아요.

```python
>>> sd.reshape(m.T, (6,)).base is None
True
```

`.base`가 `None`이면 자기 메모리를 가진 독립된 배열이라는 뜻이에요. `ravel`도 같은 규칙이에요. 가능하면 뷰, 아니면 복사예요.

### `copy`로 정하기

복사 여부를 직접 정하고 싶으면 `copy`를 써요.

| `copy` | 뜻 |
|---|---|
| `None` (기본값) | 가능하면 뷰, 안 되면 복사해요. |
| `True` | 언제나 복사해요. 결과를 고쳐도 원본은 그대로예요. |
| `False` | 절대 복사하지 않아요. 뷰로 만들 수 없으면 `ValueError`예요. |

```python
>>> x[0] = 0
>>> z = sd.reshape(x, (2, 3), copy=True)
>>> z[0, 0] = 99
>>> x
array([0, 1, 2, 3, 4, 5], dtype=int64)
>>> sd.reshape(m.T, (6,), copy=False)
Traceback (most recent call last):
    ...
ValueError: reshape(): copy=False, but this reshape cannot be done without copying
```

`copy=False`는 "이 결과를 고쳐서 원본까지 바꾸려고 한다"처럼 메모리를 반드시 함께 써야 할 때 안전장치로 써요. `copy`에는 `True`, `False`, `None`만 쓸 수 있어요.

```python
>>> sd.reshape(x, (2, 3), copy=1)
Traceback (most recent call last):
    ...
TypeError: reshape(): 'copy' must be True, False or None, not int
```

<Callout type="tip" title="독립된 결과가 필요할 때">

  결과를 고칠 계획이라면 `copy=True`를 주거나 결과에 `.copy()`를 붙이세요. 뷰인지 복사인지 따져 볼 필요가 없어져요.

</Callout>

## 조심할 점

### 모양은 tuple로 주세요

`shape`에는 int 하나나 int의 tuple만 쓸 수 있어요. 리스트는 받지 않아요.

```python
>>> sd.reshape(x, [2, 3])
Traceback (most recent call last):
    ...
TypeError: reshape(): 'shape' must be an int or a tuple of ints, not list
```

메서드도 모양을 **인자 하나**로 받아요. `x.reshape(2, 3)`처럼 길이를 여러 인자로 나눠 주면 에러예요. 괄호를 하나 더 써서 `x.reshape((2, 3))`으로 쓰세요.

```python
>>> x.reshape(2, 3)
Traceback (most recent call last):
    ...
TypeError: reshape(): incompatible function arguments. The following argument types are supported:
    ...
```

`shape`은 이름을 붙여 넘길 수도 없어요. `sd.reshape(x, shape=(2, 3))`도 에러예요. 늘 두 번째 자리에 그대로 쓰세요.

### 0차원으로는 바꿀 수 없어요

stardust에는 차원이 0인 배열이 없어요. 원소가 하나뿐인 배열이라도 빈 모양 `()`으로는 바꿀 수 없어요. 그 값 하나가 필요하면 `v[0]`처럼 꺼내면 Python 숫자가 나와요.

```python
>>> sd.reshape(sd.asarray([7]), ())
Traceback (most recent call last):
    ...
ValueError: reshape(): 0-dimensional arrays are not supported (stardust has no 0-d arrays)
>>> sd.asarray([7])[0]
7
```

### 길이 0인 축

원소가 하나도 없는 배열도 모양을 바꿀 수 있어요. 원소 수 0이 맞기만 하면 돼요.

```python
>>> sd.reshape(sd.zeros((0, 3)), (3, 0)).shape
(3, 0)
```

### 리스트는 받지 않아요

다른 stardust 함수처럼 `x`에는 배열만 받아요. 리스트는 먼저 `sd.asarray`로 바꾸세요.

```python
>>> sd.ravel([[1, 2], [3, 4]])
Traceback (most recent call last):
    ...
TypeError: ravel(): 'x' must be an sd.ndarray, not list
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | `reshape`와 다른 점 |
|---|---|---|
| 1차원으로 펴기 | `ravel` | `reshape(x, -1)`과 같아요. 이름만으로 뜻이 드러나요. |
| 행과 열 맞바꾸기, 축 순서 바꾸기 | `permute_dims`, `.T`, `moveaxis` | 원소를 다시 끊는 것이 아니라 축의 뜻을 바꿔요. |
| 길이 1인 축만 넣거나 빼기 | `expand_dims`, `squeeze` | 어느 축을 넣고 빼는지 이름으로 드러나서 실수가 적어요. |
| 같은 원소를 되풀이해 크게 만들기 | `repeat`, `tile` | 원소 수가 늘어나요. `reshape`는 원소 수가 그대로예요. |
| 다른 모양에 맞춰 늘려 보기 | `broadcast_to` | 길이 1인 축을 늘려요. 결과는 읽기 전용이에요. |

길이 1인 축 하나를 넣는 일은 `reshape`로도 할 수 있어요(`sd.reshape(v, (3, 1))`). 하지만 원래 길이를 알아야 하고, 어디에 축을 넣는지가 잘 보이지 않아요. 이럴 때는 [`expand_dims`](/api/array/squeeze/)나 `v[:, sd.newaxis]`가 읽기 쉬워요.

## numpy를 아는 분께

- `order=` 인자가 없어요. 언제나 행 순서(numpy의 `order='C'`)로 읽고 채워요.
- 메서드 `x.reshape(2, 3)`처럼 길이를 여러 인자로 나눠 줄 수 없어요. `x.reshape((2, 3))`으로 써요.
- `shape`에 리스트(`[2, 3]`)를 받지 않아요. int나 tuple만 받아요.
- `copy=` 인자가 있어요(numpy 2.1의 `copy=`와 같은 뜻).
- `ravel`의 메서드(`x.ravel()`)와 `flatten`은 없어요. 언제나 새 배열이 필요하면 `sd.reshape(x, -1, copy=True)`를 쓰세요.
- `reshape(x, ())`로 0차원 배열을 만들 수 없어요.
