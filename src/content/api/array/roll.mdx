## 한눈에 보기

`roll`은 원소를 한쪽으로 밀어요. 끝에서 밀려난 원소는 사라지지 않고 반대편으로 돌아와요. 원형으로 늘어선 자리에서 모두가 한 칸씩 옆으로 옮겨 앉는 모습이에요.

```python
>>> import stardust as sd
>>> v = sd.asarray([1, 2, 3, 4, 5])
>>> sd.roll(v, 1)
array([5, 1, 2, 3, 4], dtype=int64)
>>> sd.roll(v, 2)
array([4, 5, 1, 2, 3], dtype=int64)
```

<Fig caption="roll(v, 2): 모두 오른쪽으로 두 칸씩 가고, 끝에서 넘친 4, 5가 앞으로 돌아와요.">
  <ArrayFig name="v" data={[1, 2, 3, 4, 5]} tones={['', '', '', 'b', 'b']} />
  <Op note="shift=2">→</Op>
  <ArrayFig name="sd.roll(v, 2)" data={[4, 5, 1, 2, 3]} tones={['b', 'b', '', '', '']} />
</Fig>

원형으로 보면 원소의 순서는 그대로예요. 1 다음에 2, 2 다음에 3이 오는 관계는 유지되고 시작점만 달라져요.

## `shift`: 몇 칸, 어느 쪽으로

`shift`가 양수면 인덱스가 커지는 쪽(오른쪽)으로, 음수면 작아지는 쪽(왼쪽)으로 밀어요.

```python
>>> sd.roll(v, -1)
array([2, 3, 4, 5, 1], dtype=int64)
```

<Fig caption="roll(v, -1): 모두 왼쪽으로 한 칸 가고, 맨 앞의 1이 맨 뒤로 가요.">
  <ArrayFig name="v" data={[1, 2, 3, 4, 5]} tones={['b', '', '', '', '']} />
  <Op note="shift=-1">→</Op>
  <ArrayFig name="sd.roll(v, -1)" data={[2, 3, 4, 5, 1]} tones={['', '', '', '', 'b']} />
</Fig>

길이만큼 밀면 한 바퀴 돌아 제자리예요. 길이보다 많이 밀면 몇 바퀴를 돈 뒤 남은 만큼만 밀린 결과가 나와요. 길이 5인 배열에서 7칸은 2칸과, -6칸은 -1칸과 같아요.

```python
>>> sd.roll(v, 5)
array([1, 2, 3, 4, 5], dtype=int64)
>>> sd.roll(v, 7)
array([4, 5, 1, 2, 3], dtype=int64)
>>> sd.roll(v, -6)
array([2, 3, 4, 5, 1], dtype=int64)
```

`shift`는 자리로 넘겨도 되고 `shift=1`처럼 이름을 붙여도 돼요.

## `axis`: 어느 방향으로 밀까요

2차원 이상에서는 `axis`로 미는 방향을 골라요. `axis=0`은 행을 통째로 아래로, `axis=1`은 각 행 안에서 원소를 오른쪽으로 밀어요.

```python
>>> m = sd.asarray([[1, 2, 3], [4, 5, 6]])
>>> sd.roll(m, 1, axis=0)
array([[4, 5, 6],
       [1, 2, 3]], dtype=int64)
>>> sd.roll(m, 1, axis=1)
array([[3, 1, 2],
       [6, 4, 5]], dtype=int64)
```

<Fig caption="axis=1: 행마다 따로 한 칸씩 오른쪽으로 밀어요. 각 행의 마지막 원소가 그 행의 맨 앞으로 와요.">
  <ArrayFig name="m" data={[[1, 2, 3], [4, 5, 6]]} tones={[['', '', 'b'], ['', '', 'a']]} axes />
  <Op note="axis=1">→</Op>
  <ArrayFig name="sd.roll(m, 1, axis=1)" data={[[3, 1, 2], [6, 4, 5]]} tones={[['b', '', ''], ['a', '', '']]} />
</Fig>

### `axis=None`(기본값): 한 줄로 펴서 밀기

`axis`를 주지 않으면 배열을 행 순서로 한 줄로 편 다음 밀고, 원래 모양으로 되돌려요. 그래서 원소가 행의 경계를 넘어 다음 행으로 넘어가요.

```python
>>> sd.roll(m, 1)
array([[6, 1, 2],
       [3, 4, 5]], dtype=int64)
```

<Fig caption="axis=None: 1, 2, 3, 4, 5, 6을 한 줄로 보고 한 칸 밀어요. 첫 행 끝의 3이 둘째 행 앞으로, 맨 끝의 6이 맨 앞으로 가요.">
  <ArrayFig name="m" data={[[1, 2, 3], [4, 5, 6]]} tones={[['', '', 'a'], ['', '', 'b']]} />
  <Op note="한 줄로 밀기">→</Op>
  <ArrayFig name="sd.roll(m, 1)" data={[[6, 1, 2], [3, 4, 5]]} tones={[['b', '', ''], ['a', '', '']]} />
</Fig>

<Callout type="warn" title="2차원에서는 axis를 꼭 적으세요">

  `sd.roll(m, 1)`은 행마다 미는 것이 아니에요. 원소가 다른 행으로 넘어가요. 각 행 안에서만 돌리려면 `axis=1`, 행을 통째로 돌리려면 `axis=0`을 적어야 해요.

</Callout>

### 여러 축을 한꺼번에

`shift`와 `axis`에 같은 길이의 tuple(또는 리스트)을 주면 같은 자리끼리 짝이 돼요. 아래 예는 행 방향으로 1칸, 열 방향으로 2칸 밀어요.

```python
>>> sd.roll(m, (1, 2), axis=(0, 1))
array([[5, 6, 4],
       [2, 3, 1]], dtype=int64)
```

`shift`가 int 하나이고 `axis`가 tuple이면 모든 축을 같은 칸 수만큼 밀어요.

```python
>>> sd.roll(m, 1, axis=(0, 1))
array([[6, 4, 5],
       [3, 1, 2]], dtype=int64)
```

## 결과는 새 배열이에요

`roll`은 언제나 원소를 옮겨 담은 새 배열을 만들어요. [`flip`](/api/array/flip/)과 달리 원본과 메모리를 함께 쓰지 않아서, 결과를 고쳐도 원본은 그대로예요.

```python
>>> r = sd.roll(v, 1)
>>> r[0] = 0
>>> v
array([1, 2, 3, 4, 5], dtype=int64)
```

## 조심할 점

### 이웃과 비교할 때는 끝이 돌아와요

"바로 앞 원소와의 차이"를 구하려고 `v - sd.roll(v, 1)`을 쓸 때가 많아요. 나머지 칸은 맞지만 첫 칸이 문제예요. 첫 칸의 "앞 원소"로 맨 끝 원소가 돌아와 있기 때문이에요.

```python
>>> price = sd.asarray([100, 102, 101, 105])
>>> price - sd.roll(price, 1)
array([-5,  2, -1,  4], dtype=int64)
```

첫 값 `-5`는 `100 - 105`라서 뜻이 없는 값이에요. 이웃 사이의 차이가 필요하면 끝이 돌아오지 않는 [`diff`](/api/array/diff/)를 쓰세요. 결과가 한 칸 짧아요.

```python
>>> sd.diff(price)
array([ 2, -1,  4], dtype=int64)
```

끝이 돌아오지 않게 한쪽으로 밀고 빈자리를 다른 값으로 채우려면 슬라이싱과 [`concat`](/api/array/concat/)을 함께 써요.

```python
>>> sd.concat([sd.asarray([0]), price[:-1]])
array([  0, 100, 102, 101], dtype=int64)
```

### 한 줄로 밀 때 `shift`는 int 하나예요

`axis=None`이면 축이 하나뿐인 것처럼 다루므로 `shift`에 tuple을 줄 수 없어요. `shift`를 tuple로 주면 `axis`도 같은 길이의 tuple이나 리스트로 줘야 해요.

```python
>>> sd.roll(m, (1, 2))
Traceback (most recent call last):
    ...
TypeError: roll(): 'shift' must be an int when 'axis' is None
>>> sd.roll(m, (1, 2), axis=0)
Traceback (most recent call last):
    ...
ValueError: roll(): 'shift' and 'axis' must have the same length when both are sequences
```

### 같은 축을 두 번 쓸 수 없어요

`axis`에 같은 축을 두 번 적으면 `ValueError`예요. 한 축을 3칸 밀고 싶다면 `(1, 2)`로 나누지 말고 3을 한 번에 주세요.

```python
>>> sd.roll(m, (1, 2), axis=(1, 1))
Traceback (most recent call last):
    ...
ValueError: roll(): repeated axis
```

### 칸 수는 정수, `axis`는 이름을 붙여서

`shift`에는 정수만 써요. 실수나 `True` 같은 bool은 받지 않아요.

```python
>>> sd.roll(v, 1.5)
Traceback (most recent call last):
    ...
TypeError: roll(): 'shift' must be an int or a tuple or list of ints, not float
```

`axis`는 `axis=0`처럼 이름을 붙여 써야 해요. `sd.roll(m, 1, 0)`은 `TypeError`예요. 빈 배열은 에러 없이 빈 배열을 돌려줘요.

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | `roll`과 다른 점 |
|---|---|---|
| 순서를 거꾸로 | `flip` | 원형으로 미는 것이 아니라 거꾸로 읽어요. 뷰예요. |
| 이웃 원소끼리의 차이 | `diff` | 끝이 돌아오지 않아요. 결과가 짧아져요. |
| 밀고 빈자리를 다른 값으로 채우기 | 슬라이싱 + `concat` | 끝이 돌아오지 않아요. |
| 크기순으로 늘어놓기 | `sort` | 값을 비교해서 순서를 정해요. |

`roll`과 `flip`은 둘 다 원소의 자리를 바꾸지만, `roll`은 이웃 관계를 지키고 시작점만 옮기는 반면 `flip`은 이웃 관계를 뒤집어요. `[1, 2, 3, 4, 5]`를 `roll`하면 `3` 다음에는 여전히 `4`가 오지만, `flip`하면 `3` 다음에 `2`가 와요.

## numpy를 아는 분께

- numpy의 `np.roll`과 같은 결과예요. 기본값 `axis=None`에서 평탄화해서 미는 것도 같아요.
- `axis`는 keyword-only예요. `np.roll(m, 1, 0)`처럼 자리로 넘길 수 없어요.
- 같은 축을 두 번 쓸 수 없어요. numpy는 `axis=(1, 1)`이면 두 `shift`를 더해서 밀지만, stardust는 `ValueError`예요.
- `axis=None`일 때 `shift`에 tuple을 주면 `TypeError`예요.
