## 한눈에 보기

엑셀에서 "가격 열 × 수량 열"을 계산할 때는 첫 행에 수식을 쓰고 아래로 끝까지 채워요. 데이터프레임에서는 그럴 필요가 없어요. **컬럼(열) 전체에 연산자를 한 번 쓰면, 모든 행이 한꺼번에 계산돼요.**

과일 가게의 하루 판매 기록으로 매출을 계산해 볼게요. 자두의 판매량은 아직 집계되지 않아서 비어 있어요(`None`은 결측값 `NA`로 읽혀요).

```python
>>> import stardust as sd
>>> df = sd.frame.DataFrame({
...     "fruit": ["apple", "pear", "plum"],
...     "price": [1200, 800, 1500],
...     "qty": [3, 5, None],
... })
>>> df
   fruit  price  qty
0  apple   1200    3
1   pear    800    5
2   plum   1500 <NA>
>>> df["price"] * df["qty"]
0    3600
1    4000
2    <NA>
dtype: int64
```

<Fig caption="같은 라벨(0, 1, 2)의 값끼리 곱해요. 한쪽이 NA인 행은 결과도 NA예요.">
  <FrameFig name='df["price"]' data={[1200, 800, 1500]} rowTones={['a', '', '']} note="dtype: int64" />
  <Op>×</Op>
  <FrameFig name='df["qty"]' data={[3, 5, null]} rowTones={['a', '', '']} note="dtype: int64" />
  <Op>=</Op>
  <FrameFig data={[3600, 4000, null]} rowTones={['b', '', '']} note="dtype: int64" />
</Fig>

판매량을 모르는 자두는 매출도 알 수 없으니 결과가 `NA`예요. 0이나 엉뚱한 숫자가 나오지 않아서, 결과만 보고도 "여기는 값이 없었다"를 알 수 있어요. 결측값이 무엇인지는 [NA와 NaN](/api/frame/na/)에 자세히 있어요.

쓸 수 있는 연산자는 이래요. 모두 행마다 따로 계산해요.

| 연산자 | 하는 일 | 예 (`x`가 7, `y`가 2일 때) |
|:---:|---|:---:|
| `x + y` | 더하기 (string끼리는 이어 붙이기) | `9` |
| `x - y` | 빼기 | `5` |
| `x * y` | 곱하기 | `14` |
| `x / y` | 나누기 (결과는 언제나 float64) | `3.5` |
| `x // y` | 내림한 몫 | `3` |
| `x % y` | 나머지 (나누는 수의 부호를 따라요) | `1` |
| `x ** y` | 거듭제곱 | `49` |
| `-x`, `+x` | 부호 뒤집기, 그대로 | `-7`, `7` |
| `abs(x)` | 절댓값 | `7` |

`add`, `mul`, `div` 같은 메서드는 없어요. 연산은 연산자로만 해요. 같은 일을 하는 이름이 여럿 있으면 읽는 사람이 둘이 같은지 따로 확인해야 하기 때문이에요. 이 원칙은 [데이터프레임의 기본](/api/frame/basics/)에 있어요.

## 무엇과 무엇을 계산할 수 있나요

연산자의 양쪽에 올 수 있는 것(피연산자)의 조합은 이래요.

| 왼쪽 | 오른쪽 | 결과 | 어떻게 짝짓나요 |
|---|---|:---:|---|
| Series | Series | Series | 행 라벨로 맞춰요 |
| Series | 스칼라 | Series | 모든 행에 같은 값 |
| 스칼라 | Series | Series | 모든 행에 같은 값 |
| DataFrame | 스칼라 (양쪽 어디든) | DataFrame | 모든 칸에 같은 값 |
| DataFrame | DataFrame | DataFrame | 컬럼은 이름으로, 행은 라벨로 맞춰요 |
| DataFrame | Series | `TypeError` | 지원하지 않아요 |
| Series, DataFrame | list, tuple, `None`, 배열 | `TypeError` | 지원하지 않아요 |

**스칼라**는 값 하나를 말해요. Python의 `bool`, `int`, `float`, `str`, numpy 스칼라(`numpy.int64(2)` 같은 것), 결측값 `NA`가 스칼라예요. 스칼라는 왼쪽에 와도 돼요.

```python
>>> price = df["price"]
>>> price * 2
0    2400
1    1600
2    3000
Name: price, dtype: int64
>>> 10000 - price
0    8800
1    9200
2    8500
Name: price, dtype: int64
>>> price / 1000
0    1.2
1    0.8
2    1.5
Name: price, dtype: float64
```

리스트, 튜플, `None`, numpy 배열, stardust 배열(`sd.ndarray`)과는 계산하지 않아요. 리스트에는 라벨이 없어요. 먼저 Series로 만들면 라벨로 맞춰서 계산해요.

```python
>>> price + [100, 100, 100]
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for +: 'Series' and 'list'
>>> price + sd.frame.Series([100, 100, 100])
0    1300
1     900
2    1600
dtype: int64
```

DataFrame과 Series를 함께 계산하는 것도 지원하지 않아요. 컬럼 하나를 골라서 Series끼리 계산하세요.

```python
>>> df[["price", "qty"]] * df["qty"]
Traceback (most recent call last):
    ...
TypeError: operations between a DataFrame and a Series are not supported
```

## 라벨로 맞춰서 계산해요

Series끼리 계산할 때는 **같은 자리**가 아니라 **같은 라벨**의 값끼리 계산해요. 이걸 정렬(alignment)이라고 해요. 월요일과 화요일의 판매량을 더해 볼게요. 두 날의 과일 순서가 다르고, 자두는 월요일에만, 키위는 화요일에만 팔렸어요.

```python
>>> mon = sd.frame.Series([3, 5, 2], index=["apple", "pear", "plum"], name="qty")
>>> tue = sd.frame.Series([4, 1, 6], index=["pear", "apple", "kiwi"], name="qty")
>>> mon + tue
apple       4
pear        9
plum     <NA>
kiwi     <NA>
Name: qty, dtype: int64
```

<Fig caption="apple은 apple끼리, pear는 pear끼리 더해요. 한쪽에만 있는 라벨은 NA이고, 왼쪽 라벨이 먼저, 오른쪽에만 있는 라벨이 뒤에 와요.">
  <FrameFig name="mon" data={[3, 5, 2]} index={['apple', 'pear', 'plum']} rowTones={['1', '2', '']} />
  <Op>+</Op>
  <FrameFig name="tue" data={[4, 1, 6]} index={['pear', 'apple', 'kiwi']} rowTones={['2', '1', '']} />
  <Op>=</Op>
  <FrameFig data={[4, 9, null, null]} index={['apple', 'pear', 'plum', 'kiwi']} rowTones={['1', '2', 'g', 'g']} />
</Fig>

- `apple`은 3 + 1, `pear`는 5 + 4예요. 위치로는 첫 행끼리가 `apple`과 `pear`지만, 라벨이 같은 행끼리 더했어요.
- 결과의 라벨 순서는 **왼쪽(`mon`)의 순서**를 먼저 따르고, 오른쪽에만 있는 `kiwi`를 뒤에 붙여요.
- 한쪽에만 있는 라벨(`plum`, `kiwi`)은 짝이 없으니 결과가 `NA`예요.

두 Series의 라벨이 처음부터 같으면(순서까지) 그냥 위치대로 계산해요. 같은 표에서 꺼낸 컬럼끼리 계산하는 흔한 경우가 이래요. 이때는 라벨이 중복돼도 괜찮아요.

라벨이 다르면 양쪽 라벨이 모두 **고유해야** 해요. 같은 라벨이 두 번 있으면 어느 것과 짝지을지 정할 수 없어서 에러예요. 또 int 라벨과 string 라벨은 서로 맞출 수 없어요.

```python
>>> dup = sd.frame.Series([1, 2], index=["apple", "apple"])
>>> dup + mon
Traceback (most recent call last):
    ...
ValueError: cannot align indexes with duplicate labels
>>> price + mon
Traceback (most recent call last):
    ...
TypeError: cannot align int64 labels with string labels
```

<Callout type="warn" title="길이가 달라도 에러가 나지 않아요">

배열은 위치로 짝지어서 길이가 다르면 에러예요. Series는 라벨로 맞추기 때문에, 길이가 다른 두 Series를 더해도 에러 없이 짝이 없는 행이 `NA`가 돼요. 결과에 예상하지 못한 `NA`가 보이면 두 Series의 라벨을 먼저 확인하세요.

</Callout>

```python
>>> sd.frame.Series([1, 2, 3]) + sd.frame.Series([10, 20])
0      11
1      22
2    <NA>
dtype: int64
```

정렬 규칙 전체(어디서 일어나는지, Index의 종류)는 [라벨과 정렬](/api/frame/alignment/)에 있어요. 배열에서는 같은 계산이 위치로 짝짓는 [브로드캐스팅](/api/array/broadcasting/)이에요.

## DataFrame의 산술

DataFrame에 스칼라를 계산하면 **모든 컬럼에** 같은 계산을 해요. 컬럼마다 dtype을 따로 지켜요.

```python
>>> nums = sd.frame.DataFrame({"a": [1, 2], "b": [0.5, None]})
>>> nums + 1
   a    b
0  2  1.5
1  3 <NA>
>>> -nums
   a    b
0 -1 -0.5
1 -2 <NA>
```

DataFrame끼리 계산하면 **컬럼은 이름으로 짝짓고**, 행은 Series처럼 라벨로 맞춰요. 컬럼 순서가 달라도 이름이 같은 컬럼끼리 계산하고, 결과는 왼쪽의 컬럼 순서를 따라요.

```python
>>> nums * sd.frame.DataFrame({"b": [2.0, 2.0], "a": [10, 20]})
    a    b
0  10  1.0
1  40 <NA>
```

한쪽에만 있는 컬럼은 다른 쪽에 같은 dtype의 `NA` 컬럼이 있는 것처럼 계산해요. 그래서 그 컬럼은 모두 `NA`예요. 오른쪽에만 있는 컬럼은 뒤에 붙어요.

```python
>>> nums + sd.frame.DataFrame({"a": [1, 2], "c": [1, 1]})
   a    b     c
0  2 <NA>  <NA>
1  4 <NA>  <NA>
```

계산할 수 없는 컬럼이 하나라도 있으면 전체가 에러예요. 예를 들어 string 컬럼이 섞인 DataFrame에 `+ 1`을 하면 `TypeError`예요. 숫자 컬럼만 골라서(`df[["price", "qty"]]`) 계산하세요.

```python
>>> df + 1
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for +: string and int64 (strings support + and comparisons)
>>> df[["price", "qty"]] + 1
   price  qty
0   1201    4
1    801    6
2   1501 <NA>
```

## 결과의 dtype

dtype은 넷이에요: `bool`, `int64`, `float64`, `string`. 산술의 결과 dtype은 배열 영역과 같은 순서 **bool < int64 < float64**로 정해요. 두 쪽 중 더 넓은 쪽을 따르고, bool은 계산할 때 int64로 올라가요. 스칼라도 `int`는 int64, `float`는 float64, `bool`은 bool, `str`은 string으로 쳐요.

`+`, `-`, `*`, `//`, `%`, `**`의 결과예요.

| 왼쪽 \ 오른쪽 | bool | int64 | float64 | string |
|---|:---:|:---:|:---:|:---:|
| **bool** | int64 | int64 | float64 | `TypeError` |
| **int64** | int64 | int64 | float64 | `TypeError` |
| **float64** | float64 | float64 | float64 | `TypeError` |
| **string** | `TypeError` | `TypeError` | `TypeError` | string (`+`만) |

- `/`는 이 표와 달리 숫자끼리면 **언제나 float64**예요. 정수끼리 나눠떨어져도 그래요. 값에 따라 dtype이 바뀌면 코드만 보고 결과를 알 수 없기 때문이에요.
- 단항 `-`, `+`, `abs()`는 bool을 int64로 바꾸고, int64와 float64는 그대로 둬요. string은 `TypeError`예요.
- 결과에 `NA`가 생겨도 dtype은 바뀌지 않아요. 위 예처럼 `NA`가 섞인 int64 결과는 그대로 int64예요.

```python
>>> qty = df["qty"]
>>> qty + 0.5
0    3.5
1    5.5
2   <NA>
Name: qty, dtype: float64
>>> qty / 1
0    3.0
1    5.0
2   <NA>
Name: qty, dtype: float64
```

### bool의 산술은 int64의 산술이에요

bool 값에 산술을 하면 `True`를 1, `False`를 0으로 바꿔서 int64로 계산해요. Python에서 `True + True`가 `2`인 것과 같고, 배열 영역의 [사칙연산](/api/array/arithmetic/)과도 같아요. 그래서 조건에 맞는 행의 수를 더하는 데 쓸 수 있어요.

```python
>>> passed = sd.frame.Series([True, False, None])
>>> passed + sd.frame.Series([True, True, True])
0       2
1       1
2    <NA>
dtype: int64
>>> -sd.frame.Series([True, False])
0   -1
1    0
dtype: int64
>>> sd.frame.Series([True, False]) * 2.5
0    2.5
1    0.0
dtype: float64
```

"둘 중 하나라도 참"을 계산하고 싶었다면 `+`가 아니라 `|`를 써요([논리와 비트 연산](/api/frame/logical/)).

### string은 `+`만 돼요

string끼리 `+`는 문자열을 이어 붙여요. 스칼라 문자열은 어느 쪽에 와도 돼요. 그 밖의 산술(`-`, `*`, 단항 `-` 등)과 숫자와의 산술은 `TypeError`예요.

```python
>>> fruit = df["fruit"]
>>> fruit + "!"
0    apple!
1     pear!
2     plum!
Name: fruit, dtype: string
>>> "fresh " + fruit
0    fresh apple
1     fresh pear
2     fresh plum
Name: fruit, dtype: string
>>> fruit * 2
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for *: string and int64 (strings support + and comparisons)
>>> fruit + 1
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for +: string and int64 (strings support + and comparisons)
```

숫자를 문자열로 붙이고 싶다면 먼저 [`astype`](/api/frame/astype/)으로 string으로 바꿔요.

```python
>>> fruit + ":" + price.astype("string")
0    apple:1200
1      pear:800
2     plum:1500
dtype: string
```

## 정수 계산의 규칙

### `/`는 실수, `//`는 내림한 몫이에요

`7 / 2`는 `3.5`이고, `7 // 2`는 `3`이에요. `//`와 `%`는 Python처럼 **내림(floor)** 규칙이라서, 음수에서는 몫이 더 작은 쪽으로 가고 나머지는 나누는 수의 부호를 따라요.

```python
>>> x = sd.frame.Series([7, -7])
>>> x // 2
0    3
1   -4
dtype: int64
>>> x % 2
0    1
1    1
dtype: int64
```

### 넘치면 반대쪽으로 넘어가요

int64는 약 ±9.2 × 10¹⁸까지 담아요. 계산 결과가 이 범위를 넘으면 에러가 나지 않고 반대쪽 끝으로 넘어가요(wrap). 배열 영역과 같아요. 가장 작은 정수를 `-1`로 나누거나 그 절댓값을 구해도 그 자신이 나와요.

```python
>>> sd.frame.Series([2**62]) * 4
0    0
dtype: int64
>>> abs(sd.frame.Series([-2**63]))
0   -9223372036854775808
dtype: int64
```

아주 큰 수를 다룬다면 [`astype`](/api/frame/astype/)으로 float64로 바꿔서 계산하세요.

### 0으로 나눈 몫과 나머지는 `NA`예요

정수를 0으로 `//`하거나 `%`하면 결과가 `NA`예요. 에러가 나지 않고 그 행만 `NA`가 돼요.

```python
>>> sd.frame.Series([7, 8, 9]) // sd.frame.Series([2, 0, 3])
0       3
1    <NA>
2       3
dtype: int64
>>> sd.frame.Series([7, 8, 9]) % 0
0    <NA>
1    <NA>
2    <NA>
dtype: int64
```

**배열과 다른 점이에요.** 배열의 [`//`와 `%`](/api/array/floor-divide/)는 정수를 0으로 나누면 몫이 `0`, 나머지가 나눠지는 값 자신이에요. 배열에는 "값이 없다"를 나타낼 방법이 없어서 정해진 숫자를 하나 골라야 했어요. 데이터프레임에는 `NA`가 있으니, 답이 없는 계산을 그럴듯한 숫자로 채우는 대신 `NA`로 표시해요. 그러면 평균을 내거나 합을 구할 때 그 행이 진짜 0처럼 섞여 들어가지 않아요.

bool도 int64로 계산하므로 같은 규칙이에요. `False`로 `//`하면 0으로 나누는 것이라 `NA`예요.

실수는 0으로 나눠도 `NA`가 되지 않아요. 실수 계산의 약속(IEEE 754)대로 무한대(`inf`)나 NaN이 나와요. `/`는 정수끼리도 실수로 계산하므로 이쪽이에요.

```python
>>> sd.frame.Series([1, -1, 0]) / 0
0    inf
1   -inf
2    NaN
dtype: float64
>>> sd.frame.Series([5.0, 0.0]) // 0
0    inf
1    NaN
dtype: float64
```

여기서 `NaN`은 결측값이 아니라 "숫자가 아님"을 뜻하는 평범한 실수 값이에요. 출력에서 `<NA>`와 `NaN`이 다르게 보이는 이유예요. 둘의 차이는 [NA와 NaN](/api/frame/na/)에 있어요.

### 음수 지수는 `NA`예요

정수의 음수 거듭제곱(`2 ** -1`)은 결과가 `NA`예요. 참값 `0.5`는 정수가 아니라서, int64 결과로는 나타낼 수 없기 때문이에요. `0 ** 0`은 `1`이에요.

```python
>>> sd.frame.Series([2, 3, 2]) ** sd.frame.Series([3, 2, -1])
0       8
1       9
2    <NA>
dtype: int64
>>> sd.frame.Series([0]) ** 0
0    1
dtype: int64
```

**이것도 배열과 달라요.** 배열의 [`**`](/api/array/pow/)는 정수끼리면 결과도 정수라서 `2 ** -1`이 `0`이에요. 0은 진짜 답과 거리가 멀지만 그럴듯한 숫자처럼 보이므로, 데이터프레임에서는 `NA`로 표시해요. 소수 결과를 원하면 밑을 실수로 바꿔요.

```python
>>> sd.frame.Series([2, 4]).astype("float64") ** -1
0    0.50
1    0.25
dtype: float64
```

### 너무 큰 Python 정수

int64 범위를 벗어난 Python 정수를 int64 컬럼과 계산하면 `OverflowError`예요. 그 정수를 int64로 바꿀 수 없기 때문이에요. float64 컬럼과는 그 정수를 실수로 읽어서 계산해요. 배열과 같은 규칙이에요.

```python
>>> price + 2**70
Traceback (most recent call last):
    ...
OverflowError: Python int too large to convert to int64
>>> price.astype("float64") + 2**70
0    1.180592e+21
1    1.180592e+21
2    1.180592e+21
Name: price, dtype: float64
```

## `NA`가 들어가면

`NA`가 들어간 계산의 결과는 **예외 없이** `NA`예요. "모르는 값"에 무엇을 해도 결과를 알 수 없기 때문이에요. `NA ** 0`처럼 수학적으로 답이 하나뿐인 것 같은 계산도 `NA`예요.

```python
>>> qty ** 0
0       1
1       1
2    <NA>
Name: qty, dtype: int64
>>> sd.frame.NA + 1
<NA>
>>> qty + sd.frame.NA
0    <NA>
1    <NA>
2    <NA>
Name: qty, dtype: int64
```

스칼라 `NA`는 상대 컬럼의 dtype을 따르는 결측값처럼 계산돼요. 그래서 위의 `qty + sd.frame.NA`는 int64 결과예요.

NaN은 결측값이 아니라 실수 값이라서, 실수 계산의 규칙대로 결과가 NaN이에요. 한 Series 안에 둘이 함께 있으면 따로 남아요.

```python
>>> sd.frame.Series([1.0, float("nan"), None]) + 1
0    2.0
1    NaN
2   <NA>
dtype: float64
```

`NA`를 0처럼 계산하고 싶다면 먼저 [`fillna`](/api/frame/fillna/)로 채운 뒤 계산해요.

```python
>>> df["price"] * df["qty"].fillna(0)
0    3600
1    4000
2       0
dtype: int64
```

## 결과의 이름

Series에는 이름(`name`)이 있을 수 있어요. 결과의 이름은 이렇게 정해져요.

- 두 Series의 이름이 같으면 그 이름을 지켜요. 위의 `mon + tue`가 `qty`인 이유예요.
- 이름이 다르면 `None`(이름 없음)이에요. 맨 처음 예 `df["price"] * df["qty"]`의 결과에 `Name:` 줄이 없는 이유예요.
- 스칼라와 계산하면 Series의 이름을 지켜요.

```python
>>> (price * 2).name
'price'
>>> (price * qty).name is None
True
```

행 라벨(Index)의 이름도 같은 규칙이에요.

## 조심할 점

### `+=`는 새 Series를 만들어요

`s += 1`은 `s = s + 1`과 같아요. 새 Series를 만들어서 `s`라는 이름을 그쪽으로 옮겨요. 같은 Series를 가리키던 다른 이름은 바뀌지 않아요.

```python
>>> s = sd.frame.Series([1, 2])
>>> t = s
>>> s += 10
>>> s.tolist()
[11, 12]
>>> t.tolist()
[1, 2]
```

배열의 `x += 1`은 `x`의 원소를 제자리에서 바꾸므로 다른 이름에도 보여요. 데이터프레임은 값을 고친 쪽만 바뀌어요([대입과 복사](/api/frame/assign/)). 그래서 `+=`가 정수 컬럼을 실수 결과로 바꿔도(`s /= 2`) 에러가 아니에요. 새 Series를 만들기 때문이에요.

### `divmod`와 `@`는 없어요

몫과 나머지는 `//`와 `%`로 따로 구해요. 행렬곱 `@`도 지원하지 않아요. 행렬 계산이 필요하면 [`to_array`](/api/frame/to-array/)로 배열로 바꾸세요.

```python
>>> divmod(price, 7)
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for divmod(): 'Series' and 'int'
```

### 실수 계산의 작은 오차

실수는 0.1 같은 수를 정확히 나타내지 못해서 마지막 자리가 어긋날 수 있어요. Python의 `float`와 같아요. 출력은 유효숫자 6자리까지만 보여 주므로, 어긋남이 화면에 보이지 않을 수 있어요.

```python
>>> (sd.frame.Series([0.1]) + 0.2).tolist()
[0.30000000000000004]
```

## 배열의 산술과 다른 점

데이터프레임의 산술은 배열 영역([사칙연산](/api/array/arithmetic/), [몫과 나머지](/api/array/floor-divide/), [거듭제곱](/api/array/pow/))과 같은 규칙을 따르고, 다른 곳은 아래뿐이에요. 대부분 데이터프레임에 결측값 `NA`가 있어서 생긴 차이예요.

| | 배열 | 데이터프레임 |
|---|---|---|
| 짝짓는 방법 | 위치 (브로드캐스팅) | 라벨 (정렬) |
| 길이(모양)가 다르면 | `ValueError` | 짝 없는 행이 `NA` |
| 정수 `x // 0` | `0` | `NA` |
| 정수 `x % 0` | `x` | `NA` |
| 정수 `x ** 음수` | 정수 결과 (`2 ** -1`은 `0`) | `NA` |
| `+=` | 제자리에서 바꿔요 | 새 객체를 만들어요 |
| string | 없어요 | `+`로 이어 붙여요 |
| 결과 dtype, bool의 산술, wrap, `/`는 float64 | 같아요 | 같아요 |

## pandas를 아는 분께

- `add`, `sub`, `mul`, `div`, `truediv`, `floordiv`, `mod`, `pow` 메서드가 없어요. `fill_value=`가 필요하면 먼저 `fillna`를 해요.
- 라벨이 다른 두 Series의 결과 라벨 순서는 **왼쪽 먼저, 오른쪽에만 있는 것을 뒤에**예요. pandas는 합집합을 정렬해요(`apple, kiwi, pear, plum`).
- 라벨이 다르고 중복이 있으면 `ValueError`예요. pandas는 중복 라벨끼리 모든 짝을 만들어요.
- int 라벨과 string 라벨은 맞추지 않고 `TypeError`예요. pandas는 두 라벨을 합친 Index를 만들고 값을 모두 NaN으로 채워요.
- DataFrame과 Series의 연산이 없어요. pandas는 Series의 라벨을 컬럼 이름에 맞춰 각 행에 계산해요.
- 결측값이 생겨도 int64는 int64예요. pandas의 기본 int64 컬럼은 결측이 생기면 float64(NaN)가 돼요.
- 정수 `// 0`과 `% 0`은 `NA`예요. pandas의 기본 int64는 float64로 바뀌어 `inf`와 `NaN`, nullable `Int64`는 `0`이에요.
- 정수의 음수 거듭제곱은 `NA`예요. pandas는 `ValueError`예요.
- `NA ** 0`과 `1 ** NA`도 `NA`예요. pandas는 `1`이에요.
- bool끼리의 `+`는 int64 합이에요. pandas는 bool의 `+`가 논리합이고 결과가 bool이며, `-`는 `TypeError`, 단항 `-`는 논리 부정이에요.
- list, tuple과는 계산하지 않아요. pandas는 같은 길이의 리스트를 위치대로 계산해요.
