## 한눈에 보기

주문 기록과 상품 가격표가 따로 있어요. 주문 기록에는 무엇을 몇 개 샀는지만 있고, 가격은 가격표에 있어요. 주문마다 가격을 붙이려면 두 표에서 상품 이름이 같은 행끼리 짝지어 옆으로 이어 붙이면 돼요.

`merge`가 이 일을 해요. 두 표에 함께 있는 **키 컬럼**(여기서는 `item`)의 값이 같은 행끼리 짝지어 한 행으로 만들어요. 이런 작업을 **조인**(join)이라고 해요. 엑셀의 `VLOOKUP`으로 다른 시트에서 값을 찾아오는 것, SQL의 `JOIN`과 같은 일이에요.

```python
>>> import stardust as sd
>>> orders = sd.frame.DataFrame({"order": [101, 102, 103, 104],
...                              "item": ["pen", "cup", "pen", "hat"],
...                              "qty": [2, 1, 5, 3]})
>>> items = sd.frame.DataFrame({"item": ["cup", "pen", "bag"],
...                             "price": [4.5, 1.25, 20.0]})
>>> sd.frame.merge(orders, items, on="item")
   order item  qty  price
0    101  pen    2   1.25
1    102  cup    1   4.50
2    103  pen    5   1.25
```

  <FrameFig name="items" columns={['item', 'price']}

`pen`은 가격표의 한 행과 짝지어지는데, 주문에 `pen`이 두 번 있으니 그 가격이 두 주문에 모두 붙어요. 결과는 새 DataFrame이고, 라벨은 언제나 `0, 1, 2, …`(RangeIndex)예요.

이럴 때 써요.

- 거래 기록에 상품 정보, 고객 정보를 붙일 때
- 같은 대상을 다른 곳에서 모은 두 표(성적표와 출석부)를 하나로 모을 때
- 한쪽에만 있는 대상(주문이 없는 상품, 가격이 없는 주문)을 찾을 때

메서드로도 써요. `orders.merge(items, on="item")`은 `sd.frame.merge(orders, items, on="item")`과 같아요. 메서드를 부른 쪽이 왼쪽 표예요.

## `how`: 짝이 없는 행을 어떻게 할까

위에서 `hat`은 주문에만 있고, `bag`은 가격표에만 있어요. 이렇게 짝이 없는 행을 결과에 남길지 `how`로 정해요.

| `how` | 결과에 남는 행 |
|:---:|---|
| `"inner"` (기본) | 짝이 있는 행만 |
| `"left"` | 왼쪽 표의 행 전부. 짝이 없으면 오른쪽 값은 `NA` |
| `"right"` | 오른쪽 표의 행 전부. 짝이 없으면 왼쪽 값은 `NA` |
| `"outer"` | 양쪽 표의 행 전부 |

```python
>>> orders.merge(items, how="left", on="item")
   order item  qty  price
0    101  pen    2   1.25
1    102  cup    1   4.50
2    103  pen    5   1.25
3    104  hat    3   <NA>
>>> orders.merge(items, how="right", on="item")
   order item   qty  price
0    102  cup     1   4.50
1    101  pen     2   1.25
2    103  pen     5   1.25
3   <NA>  bag  <NA>  20.00
>>> orders.merge(items, how="outer", on="item")
   order item   qty  price
0    101  pen     2   1.25
1    102  cup     1   4.50
2    103  pen     5   1.25
3    104  hat     3   <NA>
4   <NA>  bag  <NA>  20.00
```

`left`는 "주문은 하나도 빠뜨리지 말고, 가격이 있으면 붙여 줘"예요. 가장 자주 써요. 가격이 `NA`인 행을 보면 가격표에 빠진 상품을 찾을 수 있어요.

짝이 없어서 생긴 칸은 `NA`이고, 컬럼의 dtype은 그대로예요. 위에서 `order`와 `qty`는 `NA`가 생겨도 int64예요([NA와 NaN](/api/frame/na/)).

```python
>>> orders.merge(items, how="outer", on="item").dtypes
{'order': int64, 'item': string, 'qty': int64, 'price': float64}
```

## 키 정하기: `on`, `left_on`과 `right_on`

키는 꼭 줘야 해요. 같은 이름의 컬럼이 있어도 알아서 키로 쓰지 않아요.

```python
>>> sd.frame.merge(orders, items)
Traceback (most recent call last):
    ...
ValueError: merge(): the keys are required: on= or left_on= and right_on=
```

### 이름이 같으면 `on`

키 컬럼이 양쪽에 같은 이름으로 있으면 `on`에 그 이름을 줘요. 결과에서 키 컬럼은 하나로 합쳐져요. 자리는 왼쪽 표에서의 자리이고, 값은 왼쪽 행이 있으면 왼쪽 값, 없으면(오른쪽에만 있는 행) 오른쪽 값이에요. 위 `outer` 결과의 `bag`이 오른쪽에서 온 값이에요.

키가 여러 컬럼이면 리스트로 줘요. 모든 키 값이 같은 행끼리 짝지어요. 도시와 연도가 모두 같아야 같은 기록이라면 이렇게 해요.

```python
>>> temp = sd.frame.DataFrame({"city": ["rome", "rome", "oslo"], "year": [2024, 2025, 2025],
...                            "temp": [21.0, 22.5, 7.0]})
>>> rain = sd.frame.DataFrame({"city": ["rome", "oslo", "rome"], "year": [2025, 2025, 2024],
...                            "rain": [60, 80, 55]})
>>> temp.merge(rain, on=["city", "year"])
   city  year  temp  rain
0  rome  2024  21.0    55
1  rome  2025  22.5    60
2  oslo  2025   7.0    80
```

### 이름이 다르면 `left_on`과 `right_on`

양쪽의 키 컬럼 이름이 다르면 `left_on`에 왼쪽 이름을, `right_on`에 오른쪽 이름을 줘요. 이때는 키 컬럼이 합쳐지지 않고 둘 다 남아요. 짝지어진 행에서는 두 키의 값이 같지만, `how="left"`처럼 짝이 없는 행이 남으면 한쪽 키가 `NA`가 돼요.

```python
>>> colors = sd.frame.DataFrame({"name": ["cup", "pen"], "color": ["red", "blue"]})
>>> orders.merge(colors, how="left", left_on="item", right_on="name")
   order  item  qty  name color
0    101   pen    2   pen  blue
1    102   cup    1   cup   red
2    103   pen    5   pen  blue
3    104   hat    3  <NA>  <NA>
```

`left_on`과 `right_on`은 개수가 같아야 해요. `on`과 함께 쓸 수는 없어요.

### 키의 dtype은 양쪽이 같아야 해요

키 컬럼의 dtype이 양쪽에서 다르면 `TypeError`예요. 정수 `1`과 실수 `1.0`처럼 값이 같아 보여도 그래요. 한쪽을 [`astype`](/api/frame/astype/)으로 맞춘 뒤 합쳐요.

```python
>>> people = sd.frame.DataFrame({"cust": [1, 2, 3], "name": ["ann", "bob", "cy"]})
>>> cities = sd.frame.DataFrame({"cust": [2.0, 1.0], "city": ["rome", "oslo"]})
>>> people.merge(cities, on="cust")
Traceback (most recent call last):
    ...
TypeError: merge(): join keys must have one dtype, got int64 and float64
>>> people.merge(cities.astype({"cust": "int64"}), how="left", on="cust")
   cust name  city
0     1  ann  oslo
1     2  bob  rome
2     3   cy  <NA>
```

## 한 키에 여러 행이 짝지어지면

한쪽의 한 행이 다른 쪽의 여러 행과 키가 같으면, 만들 수 있는 모든 짝이 결과의 행이 돼요. 가게마다 가격이 다른 가격표를 붙이면 이렇게 돼요.

```python
>>> prices = sd.frame.DataFrame({"item": ["pen", "cup", "pen"], "shop": ["X", "X", "Y"],
...                              "price": [1.25, 4.5, 1.0]})
>>> orders.merge(prices, on="item")
   order item  qty shop  price
0    101  pen    2    X   1.25
1    101  pen    2    Y   1.00
2    102  cup    1    X   4.50
3    103  pen    5    X   1.25
4    103  pen    5    Y   1.00
```

`pen` 주문 두 개가 `pen` 가격 두 개와 각각 짝지어져서 `2 × 2 = 4`행이 됐어요. 키가 겹치는 행이 많으면 결과가 원래 표보다 훨씬 커질 수 있어요. 결과의 행 수가 예상과 다르면 키 컬럼에 중복이 있는지 먼저 확인하세요([중복 찾기와 지우기](/api/frame/duplicated/)).

## NA 키는 짝을 찾지 않아요

키가 `NA`인 행은 어떤 행과도 짝지어지지 않아요. 상대 쪽 키가 `NA`여도 그래요.

```python
>>> left = sd.frame.DataFrame({"k": ["a", None, "b"], "x": [1, 2, 3]})
>>> right = sd.frame.DataFrame({"k": [None, "a"], "y": [10, 20]})
>>> sd.frame.merge(left, right, on="k")
   k  x   y
0  a  1  20
>>> sd.frame.merge(left, right, how="outer", on="k")
      k     x     y
0     a     1    20
1  <NA>     2  <NA>
2     b     3  <NA>
3  <NA>  <NA>    10
```

`outer` 결과에서 두 NA 행은 서로 짝지어지지 않고 따로따로 남았어요.

`NA`는 "값을 모른다"는 뜻이기 때문이에요. 고객 번호를 모르는 주문과 고객 번호를 모르는 고객 정보는, 둘 다 모른다고 해서 같은 고객이라고 할 수 없어요. 짝지어 버리면 번호 없는 주문마다 번호 없는 고객이 모두 붙어서, 있지도 않은 관계가 결과에 생겨요. `NA == NA`가 `True`가 아니라 `NA`인 것과 같은 생각이에요. SQL의 `JOIN`도 같아요.

이 점에서 `merge`는 데이터프레임의 다른 함수와 달라요. [`groupby`](/api/frame/groupby/)(`dropna=False`), [`drop_duplicates`](/api/frame/duplicated/), [`value_counts`](/api/frame/value_counts/)는 NA끼리를 같은 키로 쳐요. 같은 키 규칙에서 예외는 `merge` 하나예요.

반면 NaN은 값이라서 NaN끼리 짝지어져요. `0.0`과 `-0.0`도 같은 키예요.

```python
>>> fl = sd.frame.DataFrame({"k": [1.0, sd.nan, -0.0], "x": [1, 2, 3]})
>>> fr = sd.frame.DataFrame({"k": [sd.nan, 0.0], "y": [10, 20]})
>>> fl.merge(fr, on="k")
     k  x   y
0  NaN  2  10
1 -0.0  3  20
```

## 결과 컬럼과 `suffixes`

결과의 컬럼은 왼쪽 표의 컬럼이 왼쪽 순서대로 먼저 오고, 그다음 오른쪽 표의 컬럼이 오른쪽 순서대로 와요. `on`의 키 컬럼은 왼쪽에서의 자리에 하나만 있어요.

키가 아닌 컬럼 가운데 양쪽에 같은 이름이 있으면, 구별하려고 이름 뒤에 접미사를 붙여요. 기본은 왼쪽 `_x`, 오른쪽 `_y`예요.

```python
>>> mid = sd.frame.DataFrame({"id": [1, 2], "score": [80, 90]})
>>> final = sd.frame.DataFrame({"id": [2, 1], "score": [70, 60]})
>>> mid.merge(final, on="id")
   id  score_x  score_y
0   1       80       60
1   2       90       70
>>> mid.merge(final, on="id", suffixes=("_mid", "_final"))
   id  score_mid  score_final
0   1         80           60
1   2         90           70
```

한쪽 접미사를 빈 문자열로 두면 그쪽은 원래 이름 그대로예요.

```python
>>> mid.merge(final, on="id", suffixes=("", "_final"))
   id  score  score_final
0   1     80           60
1   2     90           70
```

접미사를 붙인 뒤에도 이름이 겹치면 `ValueError`예요. `suffixes`는 str 두 개의 tuple로 줘요. 리스트는 `TypeError`예요.

```python
>>> mid.merge(final, on="id", suffixes=("", ""))
Traceback (most recent call last):
    ...
ValueError: merge(): result column 'score' appears twice; choose other suffixes
>>> mid.merge(final, on="id", suffixes=["_mid", "_final"])
Traceback (most recent call last):
    ...
TypeError: merge(): 'suffixes' must be a tuple of two str
```

`left_on`/`right_on`으로 합치면 양쪽 키 컬럼도 남으므로, 이름이 같으면 키 컬럼에도 접미사가 붙어요.

```python
>>> mid.merge(final, left_on="id", right_on="id")
   id_x  score_x  id_y  score_y
0     1       80     1       60
1     2       90     2       70
```

## 행 순서와 `sort`

결과의 행 순서는 다음과 같이 정해져 있어요.

- `inner`, `left`, `outer`는 왼쪽 표의 행 순서를 따라요.
- 한 행이 여러 행과 짝지어지면, 그 안에서는 오른쪽 표의 순서예요(위 `prices` 예에서 `X` 다음 `Y`).
- `outer`에서 짝이 없는 오른쪽 행은 오른쪽 순서대로 맨 뒤에 붙어요.
- `right`는 위 규칙을 좌우를 바꿔서 적용해요. 오른쪽 표의 행 순서를 따라요(위 `how="right"` 결과의 `cup, pen, pen, bag`).

`sort=True`면 결과 행을 키의 오름차순으로 늘어놓아요. 안정 정렬이라 키가 같은 행은 위 순서를 지켜요. NA 키는 맨 뒤예요. 순서 규칙은 [`sort_values`](/api/frame/sort_values/)와 같아요.

```python
>>> orders.merge(items, how="outer", on="item", sort=True)
   order item   qty  price
0   <NA>  bag  <NA>  20.00
1    102  cup     1   4.50
2    104  hat     3   <NA>
3    101  pen     2   1.25
4    103  pen     5   1.25
>>> sd.frame.merge(left, right, how="outer", on="k", sort=True)
      k     x     y
0     a     1    20
1     b     3  <NA>
2  <NA>     2  <NA>
3  <NA>  <NA>    10
```

`left_on`/`right_on`으로 합쳤다면 왼쪽 키로 정렬하고, 왼쪽 행이 없는 행(오른쪽에만 있는 행)은 오른쪽 키 값으로 자리를 정해요.

## 합친 다음에

결과는 보통 DataFrame이라 바로 이어서 계산할 수 있어요. 아래는 주문에 가격을 붙이고, 금액을 계산하고, 상품별로 더해요.

```python
>>> m = orders.merge(items, on="item")
>>> m["amount"] = m["qty"] * m["price"]
>>> m.groupby("item")["amount"].sum()
  item  amount
0  cup    4.50
1  pen    8.75
```

## 조심할 점

### 두 표 모두 DataFrame이어야 해요

Series는 합칠 수 없어요. 두 표와 옵션 말고는 인자가 없고, 옵션은 이름을 붙여서 줘요.

```python
>>> sd.frame.merge(orders, items["price"], on="item")
Traceback (most recent call last):
    ...
TypeError: merge(): 'left' and 'right' must be DataFrames
>>> orders.merge(items, "item")
Traceback (most recent call last):
    ...
TypeError: DataFrame.merge() takes 2 positional arguments but 3 were given
```

### 키와 `how`의 값

없는 컬럼 이름은 `KeyError`예요. `how`는 네 값 중 하나예요. 모든 짝을 만드는 `"cross"`는 없어요.

```python
>>> orders.merge(items, on="name")
Traceback (most recent call last):
    ...
KeyError: "merge(): no column 'name'"
>>> orders.merge(items, how="full", on="item")
Traceback (most recent call last):
    ...
ValueError: merge(): 'how' must be 'inner', 'left', 'right' or 'outer', not 'full'
```

### 라벨로는 합치지 않아요

`merge`는 언제나 컬럼의 값으로 짝지어요. 행 라벨로 합치는 기능은 없고, 결과의 라벨은 언제나 새 RangeIndex예요. 라벨이 같은 행끼리 맞추는 것은 Series끼리의 연산이나 `df["c"] = s` 대입에서 일어나는 [정렬(alignment)](/api/frame/alignment/)이에요.

## merge 대 concat

| | `merge` | [`concat`](/api/frame/concat/) |
|---|---|---|
| 방향 | 옆으로(컬럼이 늘어요) | 아래로(행이 늘어요) |
| 무엇으로 맞추나 | 키 컬럼의 값 | 컬럼 이름 |
| 표의 수 | 두 개 | 여러 개 |
| 예 | 주문에 가격 붙이기 | 1월 판매와 2월 판매 잇기 |
| 결과 라벨 | 언제나 RangeIndex | 원래 라벨을 이어 붙여요(`ignore_index=True`면 RangeIndex) |

"같은 종류의 기록이 더 있다"면 `concat`, "같은 대상의 정보가 더 있다"면 `merge`예요.

## pandas를 아는 분께

- 키를 꼭 줘야 해요. pandas는 키를 생략하면 공통 컬럼 전체를 키로 써요.
- NA 키는 짝지어지지 않아요. pandas는 NA(`None`, NaN)끼리도 짝지어요. stardust에서 NaN은 값이라서 NaN끼리는 짝지어져요.
- 키의 dtype이 같아야 해요. pandas는 int64 키와 float64 키를 그대로 합쳐요.
- `outer`의 행 순서가 다르게 정해져요. pandas 3.1.1의 `outer`는 `sort=False`여도 키를 정렬해서 내지만, stardust는 왼쪽 순서에 오른쪽에만 있는 행을 뒤에 붙여요. 키로 정렬하려면 `sort=True`를 줘요.
- 짝이 없어서 생긴 칸은 `NA`이고 dtype은 그대로예요. pandas는 int 컬럼을 float64로 바꾸고 NaN을 넣어요.
- `suffixes`는 tuple만 받아요. `left_index`, `right_index`, `indicator`, `validate`, `how="cross"`, `copy`는 없어요.
