## 한눈에 보기

데이터프레임(data frame)은 **이름 붙은 열(컬럼)들을 나란히 놓은 표**예요. 엑셀 시트를 떠올리면 돼요. 맨 위 줄에 "과일", "가격", "수량" 같은 열 이름이 있고, 그 아래로 한 줄에 기록 하나씩 쌓여 있는 모양이에요.

엑셀 시트와 다른 점이 둘 있어요.

- 열마다 값의 종류(dtype)가 하나로 정해져 있어요. 가격 열에는 정수만, 과일 열에는 문자열만 들어가요. 그래서 열 전체를 한 번에 계산할 수 있어요.
- 행마다 라벨(label)이 붙어 있어요. 엑셀의 행 번호처럼 보이지만, 행을 고르거나 두 표를 맞출 때 쓰는 이름표예요. 행의 순서를 바꿔도 라벨은 행을 따라가요.

stardust의 데이터프레임은 `sd.frame`에 있어요. 과일 가게의 판매 기록을 DataFrame으로 만들면 이래요.

```python
>>> import stardust as sd
>>> df = sd.frame.DataFrame({
...     "fruit": ["apple", "banana", "cherry", "apple"],
...     "price": [1200, 800, 3000, 1100],
...     "qty": [3, 5, 1, 2],
... })
>>> df
    fruit  price  qty
0   apple   1200    3
1  banana    800    5
2  cherry   3000    1
3   apple   1100    2
```

열 이름을 키로, 열의 값 리스트를 값으로 하는 dict를 넣었어요. 출력의 맨 위 줄은 열 이름, 왼쪽의 `0 1 2 3`은 행 라벨이에요. 라벨을 따로 주지 않으면 0부터 차례로 붙어요.

데이터프레임을 쓰면 표 전체를 다루는 작업을 한 줄로 할 수 있어요. 판매 기록을 받으면 보통 이런 일을 해요.

```python
>>> df["revenue"] = df["price"] * df["qty"]
>>> df[df["qty"] >= 2]
    fruit  price  qty  revenue
0   apple   1200    3     3600
1  banana    800    5     4000
3   apple   1100    2     2200
>>> df.groupby("fruit")[["qty", "revenue"]].sum()
    fruit  qty  revenue
0   apple    5     5800
1  banana    5     4000
2  cherry    1     3000
>>> df["price"].mean()
1525.0
```

차례로 이런 뜻이에요.

1. 가격 열과 수량 열을 행마다 곱해서 매출 열 `revenue`를 새로 만들었어요. 반복문은 쓰지 않았어요. [산술 연산](/api/frame/arithmetic/), [대입과 복사](/api/frame/assign/)에서 자세히 다뤄요.
2. 수량이 2 이상인 행만 골랐어요. [조건으로 행 거르기](/api/frame/mask/)에서 다뤄요.
3. 같은 과일끼리 묶어서 수량과 매출을 더했어요. 엑셀의 피벗 테이블이나 SQL의 `GROUP BY`와 같은 일이에요. [groupby](/api/frame/groupby/)에서 다뤄요.
4. 가격 열의 평균을 구했어요. 결과는 Python `float`예요. [합, 평균, 개수](/api/frame/sum-mean/)에서 다뤄요.

## Series, DataFrame, Index

데이터프레임 영역에는 세 가지 객체가 있어요. 서로 맞물려 있어서 하나를 알면 나머지도 쉬워요.

- **Series**: 값이 한 줄로 늘어선 열 하나예요. 모든 값의 dtype이 같고, 값마다 라벨이 붙어 있어요. 열 이름(`name`)도 붙일 수 있어요.
- **DataFrame**: 같은 라벨을 공유하는 Series 여러 개를 나란히 놓은 표예요. 열마다 dtype이 달라도 돼요.
- **Index**: 라벨의 목록이에요. 행 라벨(`df.index`, `s.index`)도, 열 이름의 목록(`df.columns`)도 Index예요.

DataFrame에서 열 하나를 꺼내면 Series가 나와요. 그 Series의 라벨은 DataFrame의 행 라벨과 같아요.

```python
>>> s = df["price"]
>>> s
0    1200
1     800
2    3000
3    1100
Name: price, dtype: int64
>>> type(s).__name__
'Series'
>>> s.name
'price'
>>> s.index
RangeIndex(start=0, stop=4, step=1)
>>> df.index
RangeIndex(start=0, stop=4, step=1)
>>> df.columns
Index(['fruit', 'price', 'qty', 'revenue'], dtype=string)
```

`RangeIndex(start=0, stop=4, step=1)`은 "0부터 4 앞까지 1씩"이라는 뜻이에요. 라벨을 따로 주지 않았을 때 붙는 기본 라벨이고, 정수 라벨의 Index처럼 다뤄요. 라벨을 직접 줄 수도 있어요.

```python
>>> sd.frame.Series([10, 20, 30])
0    10
1    20
2    30
dtype: int64
>>> sd.frame.Series([10, 20, 30], index=["a", "b", "c"], name="score")
a    10
b    20
c    30
Name: score, dtype: int64
```

크기는 `shape`와 `len`으로 봐요. 배열처럼 `shape`는 tuple이고, DataFrame은 (행, 열)이에요.

```python
>>> df.shape
(4, 4)
>>> s.shape
(4,)
>>> len(df)
4
```

| 객체 | 무엇 | 예 | 자세히 |
|---|---|---|---|
| Series | 라벨 붙은 열 하나 | `df["price"]` | [Series](/api/frame/series/) |
| DataFrame | 라벨을 공유하는 열들의 표 | `df` | [DataFrame](/api/frame/dataframe/) |
| Index | 라벨의 목록 (바뀌지 않아요) | `df.index`, `df.columns` | [Index와 RangeIndex](/api/frame/index/) |

### 라벨과 위치

행을 가리키는 방법은 두 가지예요. **라벨**(이름표)로 가리키거나, **위치**(위에서 몇째인지, 0부터)로 가리켜요. 기본 라벨 0, 1, 2…는 위치와 같아 보이지만, 행을 거르거나 정렬하면 서로 달라져요. 그래서 라벨로 고를 때는 `.loc`, 위치로 고를 때는 `.iloc`으로 도구를 나눠 써요.

```python
>>> s.iloc[1]
800
>>> df.loc[2, "fruit"]
'cherry'
```

라벨이 왜 있고 연산에서 어떻게 쓰이는지는 [라벨과 정렬](/api/frame/alignment/)에, 고르는 방법은 [대괄호로 고르기](/api/frame/selection/)와 [loc과 iloc](/api/frame/loc-iloc/)에 있어요.

## 출력 읽는 법

Series와 DataFrame을 출력하면 표 모양으로 나와요.

- **왼쪽**: 행 라벨이에요. Index에 이름이 있으면 열 이름 줄 아래에 따로 한 줄로 나와요.
- **맨 위 줄**(DataFrame): 열 이름이에요.
- **값**: 오른쪽으로 정렬해요.
- **마지막 줄**(Series): `Name: price, dtype: int64`처럼 이름과 dtype이에요. 이름이 없으면 `dtype:`만 나와요.

```python
>>> sd.frame.DataFrame({"a": [1.5, None]}, index=sd.frame.Index(["x", "y"], name="key"))
       a
key     
x    1.5
y   <NA>
```

### `<NA>`와 `NaN`

빈칸처럼 보이는 표시가 두 가지 있는데, 뜻이 달라요.

- **`<NA>`**: 값이 없다는 표시예요(결측값). 어느 dtype에서나 이렇게 나와요.
- **`NaN`**: float 값의 하나인 "숫자가 아님"(Not a Number)이에요. `0.0 / 0.0`처럼 계산에서 나오는 엄연한 값이에요.

```python
>>> sd.frame.Series([12.5, float("nan"), None], name="temp")
0    12.5
1     NaN
2    <NA>
Name: temp, dtype: float64
```

둘의 차이는 이 영역에서 가장 중요한 이야기라서 [NA와 NaN](/api/frame/na/)에서 따로 다뤄요.

### float의 표기

float 열은 유효숫자 6자리까지 보여 주고, 한 열 안에서 소수점 아래 자릿수를 맞춰요. 값이 아주 크거나 작으면 그 열 전체를 지수 표기(`1.000000e-10`은 1×10⁻¹⁰)로 바꿔요. 줄어드는 것은 출력뿐이고 값은 그대로예요.

```python
>>> sd.frame.Series([0.5, 2.25, 100.0])
0      0.50
1      2.25
2    100.00
dtype: float64
>>> sd.frame.Series([1 / 3, 2 / 3])
0    0.333333
1    0.666667
dtype: float64
>>> sd.frame.Series([1e-10, 1.0, 3.0])
0    1.000000e-10
1    1.000000e+00
2    3.000000e+00
dtype: float64
```

### 긴 표의 생략

60행이 넘으면 앞 5행과 뒤 5행만 보여 주고 가운데를 `..`로 줄여요. Series는 마지막 줄에 `Length: 100`처럼 전체 길이를 적고, DataFrame은 끝에 `[70 rows x 2 columns]`처럼 크기를 적어요. 20열이 넘으면 앞 10열과 뒤 10열만 보여 주고 가운데를 `...`로 줄여요.

```python
>>> sd.frame.Series(range(100))
0      0
1      1
2      2
3      3
4      4
      ..
95    95
96    96
97    97
98    98
99    99
Length: 100, dtype: int64
```

필요한 부분만 보려면 [head와 tail](/api/frame/head-tail/)로 꺼내고, 값이 모두 필요하면 [`tolist`](/api/frame/to-numpy/)로 리스트를 받아요. 줄이 터미널 폭보다 길어도 표를 접지 않아요.

## dtype은 넷이에요

열에 담을 수 있는 값의 종류는 네 가지예요. 배열 영역과 같은 dtype 객체를 써요.

| dtype | 담는 값 | 꺼내면 나오는 Python 타입 |
|---|---|---|
| `sd.bool` | 참·거짓 | `bool` |
| `sd.int64` | 정수 (약 ±9.2×10¹⁸) | `int` |
| `sd.float64` | 실수, `inf`, `NaN` | `float` |
| `sd.string` | 문자열 | `str` |

```python
>>> df.dtypes
{'fruit': string, 'price': int64, 'qty': int64, 'revenue': int64}
>>> s.dtype
int64
>>> s.dtype is sd.int64
True
```

`df.dtypes`는 열 이름에서 dtype으로 가는 dict예요. 한 열의 dtype은 `.dtype`으로 보고, `is`로 비교할 수 있어요.

### 리스트에서 dtype이 정해지는 규칙

리스트로 만들면 값을 보고 dtype을 정해요. 숫자끼리 섞이면 **`bool < int64 < float64`** 순서로 넓은 쪽을 따라요. 배열의 [`asarray`](/api/array/asarray/)와 같은 규칙이에요([원소 종류(dtype)](/api/array/dtypes/)).

```python
>>> sd.frame.Series([True, False]).dtype
bool
>>> sd.frame.Series([1, 2]).dtype
int64
>>> sd.frame.Series([1, 2.5]).dtype
float64
>>> sd.frame.Series(["a", "b"]).dtype
string
>>> sd.frame.Series([True, 1])
0    1
1    1
dtype: int64
```

문자열은 다른 종류와 섞을 수 없어요. 아무 값이나 담는 "객체" dtype이 없기 때문이에요. 빈 리스트와 값이 모두 비어 있는 리스트는 float64가 돼요.

```python
>>> sd.frame.Series(["apple", 1])
Traceback (most recent call last):
    ...
TypeError: Series(): str values cannot be mixed with int values (there is no object dtype)
>>> sd.frame.Series([]).dtype
float64
```

dtype을 직접 정하려면 `dtype=`을 줘요. dtype 객체나 그 이름 문자열(`"bool"`, `"int64"`, `"float64"`, `"string"`)을 받아요. Python 타입(`float` 등)은 받지 않아요. 이미 만든 열의 dtype을 바꾸는 방법은 [astype](/api/frame/astype/)에 있어요.

```python
>>> sd.frame.Series([1, 2], dtype="float64")
0    1.0
1    2.0
dtype: float64
>>> sd.frame.Series([1, 2], dtype=float)
Traceback (most recent call last):
    ...
TypeError: Series(): 'dtype' must be sd.bool, sd.int64, sd.float64 or sd.string (or their names), not float
```

### 문자열 dtype은 데이터프레임에만 있어요

배열 영역의 dtype은 `sd.bool`, `sd.int64`, `sd.float64`, `sd.complex128`이고, 데이터프레임 영역은 `sd.complex128` 대신 `sd.string`을 써요. 배열은 수를 계산하는 도구라서 문자열을 담지 않지만, 표에는 과일 이름이나 도시 이름 같은 문자열 열이 꼭 필요해요. 그래서 `sd.string`은 데이터프레임에서만 쓸 수 있어요. 데이터프레임에는 복소수 dtype이 없어요.

```python
>>> sd.asarray(["apple", "banana"])
Traceback (most recent call last):
    ...
TypeError: asarray(): cannot store an object of type 'str' in an array (only bool, int, float and complex)
>>> sd.zeros(3, dtype=sd.string)
Traceback (most recent call last):
    ...
TypeError: zeros(): 'dtype' must be sd.bool, sd.int64, sd.float64 or sd.complex128 (or their names), not sd.string
```

## 결측값은 `NA` 하나예요

기록에는 빈칸이 있기 마련이에요. 리스트에 `None`을 넣으면 그 자리는 **결측값 `NA`**가 되고, 출력에는 `<NA>`로 나와요. 정수 열에 빈칸이 있어도 dtype은 int64 그대로예요. 합계 같은 계산은 기본으로 `NA`를 건너뛰어요.

```python
>>> sd.frame.Series([1200, None, 3000])
0    1200
1    <NA>
2    3000
dtype: int64
>>> sd.frame.Series([1200, None, 3000]).sum()
4200
```

결측값은 모든 dtype에서 같은 값 `sd.frame.NA` 하나로 나타내요. `NA`가 계산에서 어떻게 움직이는지, `NaN`과 어떻게 다른지는 [NA와 NaN](/api/frame/na/)에 있어요.

## 인자를 넘기는 방법

배열 영역과 같은 약속이에요. 인자는 두 가지로 나뉘어요.

- **주 인자**: 그 함수의 핵심 입력이에요. 시그니처에서 `/` 앞에 있고, 자리로만 넘겨요. 예: `head(n)`의 `n`, `sort_values(by)`의 `by`, `astype(dtype)`의 `dtype`, `merge(left, right)`의 두 표.
- **옵션**: 시그니처에서 `*` 뒤에 있고, 이름을 붙여서만 넘겨요. 예: `descending=True`, `skipna=False`, `how="left"`.

```python
>>> s.head(2)
0    1200
1     800
Name: price, dtype: int64
>>> s.head(n=2)
Traceback (most recent call last):
    ...
TypeError: Series.head() got some positional-only arguments passed as keyword arguments: 'n'
>>> df.sort_values("price", True)
Traceback (most recent call last):
    ...
TypeError: DataFrame.sort_values() takes 2 positional arguments but 3 were given
>>> df.sort_values("price", descending=True)
    fruit  price  qty  revenue
2  cherry   3000    1     3000
0   apple   1200    3     3600
3   apple   1100    2     2200
1  banana    800    5     4000
```

자리와 이름을 잘못 넘긴 호출의 에러는 위처럼 Python이 만드는 메시지 그대로예요. 다만 생성자(`Series`, `DataFrame`, `Index`, `RangeIndex`)와 `read_csv`, `merge`, `concat`, `groupby`의 메시지는 다른 에러처럼 함수 이름으로 시작해요. 호출 한 번이 아주 짧은 메서드에는 메시지를 바꾸는 비용을 더하지 않아서 둘이 달라요.

```python
>>> sd.frame.Series([1200], "int64")
Traceback (most recent call last):
    ...
TypeError: Series(): takes from 0 to 1 positional arguments but 2 were given
>>> df.groupby(by="fruit")
Traceback (most recent call last):
    ...
TypeError: groupby(): got some positional-only arguments passed as keyword arguments: 'by'
```

`df.sort_values("price", True)`만 보고는 `True`가 무슨 뜻인지 알 수 없어요. 옵션에 이름을 붙이게 하면 코드를 읽는 사람이 헷갈리지 않아요. 주 인자의 이름(`n`, `by`)은 설명할 때 부르는 이름일 뿐이라서 코드에는 쓰지 않아요.

## 옵션의 타입을 엄격하게 검사해요

옵션에 맞지 않는 타입을 주면 알아서 바꿔 주지 않고 에러를 내요. 같은 종류의 옵션은 같은 방식으로 검사하므로, 같은 실수를 하면 어느 함수에서든, 배열 영역에서도 같은 모양의 메시지가 나와요. 메시지는 언제나 부른 함수의 이름(`sum(): `)으로 시작하고, 메서드로 불러도 클래스 이름 없이 메서드 이름만 써요.

### 참·거짓 옵션

`skipna`, `descending`, `stable`, `ignore_index`, `sort`, `dropna`처럼 기본값이 `True`나 `False`인 옵션은 **`True`와 `False`만** 받아요. `1`, `0`, `None`도 안 돼요.

```python
>>> s.sum(skipna=0)
Traceback (most recent call last):
    ...
TypeError: sum(): 'skipna' must be True or False, not int
>>> s.sort_values(stable=None)
Traceback (most recent call last):
    ...
TypeError: sort_values(): 'stable' must be True or False, not NoneType
```

### 정수 인자

`head(n)`, `tail(n)`, `read_csv`의 `nrows=`, `RangeIndex`의 세 인자는 정수예요. Python `int`와 numpy 정수(`np.int64(1)`)를 받고, `bool`과 `float`는 값이 정수여도 받지 않아요. int64 범위를 넘으면 `OverflowError`예요.

```python
>>> import numpy as np
>>> s.head(np.int64(1))
0    1200
Name: price, dtype: int64
>>> s.head(2.0)
Traceback (most recent call last):
    ...
TypeError: head(): 'n' must be an int, not float
>>> s.head(True)
Traceback (most recent call last):
    ...
TypeError: head(): 'n' must be an int, not bool
>>> s.head(2**70)
Traceback (most recent call last):
    ...
OverflowError: head(): 'n' is out of range
```

### 문자열 옵션

`keep`, `how`, `join`, `na_position`, `sep`은 정해진 문자열 가운데 하나를 받아요. 문자열이 아니면 `TypeError`, 받지 않는 문자열이면 `ValueError`예요. 메시지에 받을 수 있는 값이 모두 나와요.

```python
>>> df.duplicated(keep=False)
Traceback (most recent call last):
    ...
TypeError: duplicated(): 'keep' must be 'first', 'last' or 'none', not bool
>>> df.sort_values("price", na_position="middle")
Traceback (most recent call last):
    ...
ValueError: sort_values(): 'na_position' must be 'first' or 'last', not 'middle'
```

중복을 하나도 남기지 않을 때는 `keep=False`가 아니라 `keep="none"`이에요. `keep`은 문자열 옵션이라서 `True`, `False`를 받지 않아요.

### 리스트를 받는 인자

열 이름 여러 개를 받는 자리(`by`, `subset`, `on`, `usecols` 등)에는 list나 tuple을 줘요. 열 이름 하나는 문자열로 줘도 돼요. set이나 generator처럼 다른 묶음은 받지 않아요. set은 순서가 없어서, 정렬 키처럼 순서가 중요한 자리에 쓰면 결과가 실행마다 달라질 수 있어요.

```python
>>> df.sort_values(("fruit", "price"))
    fruit  price  qty  revenue
3   apple   1100    2     2200
0   apple   1200    3     3600
1  banana    800    5     4000
2  cherry   3000    1     3000
>>> df.sort_values({"fruit", "price"})
Traceback (most recent call last):
    ...
TypeError: sort_values(): 'by' must be a column name or a list of them, not set
```

## 이름은 하나씩만 있어요

같은 일을 하는 이름을 여러 개 두지 않아요. 기능마다 이름이 하나라서 코드를 읽을 때 "이 둘이 다른가?"를 고민하지 않아도 돼요. 이름은 배열 영역과 같아요.

| 쓰는 이름 | 없는 이름 |
|---|---|
| `tolist()` | `to_list()` |
| `unique_values()` | `unique()` |
| `isna()`, `notna()` | `isnull()`, `notnull()` |
| `descending=` | `ascending=` |
| 연산자 `+ - * / // % **` | `add`, `sub`, `mul`, `div`, `truediv`, `floordiv`, `mod`, `pow` 메서드 |
| 연산자 `== != < <= > >=` | `eq`, `ne`, `lt`, `le`, `gt`, `ge` 메서드 |
| `abs(s)` | `s.abs()` |

```python
>>> s.tolist()
[1200, 800, 3000, 1100]
>>> s.to_list()
Traceback (most recent call last):
    ...
AttributeError: 'Series' object has no attribute 'to_list'. Did you mean '.tolist' instead of '.to_list'?
>>> s.isnull()
Traceback (most recent call last):
    ...
AttributeError: 'Series' object has no attribute 'isnull'
```

계산은 연산자로만 해요. `s + 1`이 있으니 `s.add(1)`은 두지 않아요. 절댓값은 Python의 `abs()`예요.

```python
>>> s + 1
0    1201
1     801
2    3001
3    1101
Name: price, dtype: int64
>>> s.add(1)
Traceback (most recent call last):
    ...
AttributeError: 'Series' object has no attribute 'add'
>>> abs(sd.frame.Series([-3, 4]))
0    3
1    4
dtype: int64
```

빈 자리를 어떤 값으로 여기고 계산하고 싶으면, 먼저 [fillna](/api/frame/fillna/)로 채운 다음 연산자를 써요.

예외는 `merge` 하나예요. 함수 `sd.frame.merge(left, right)`와 메서드 `df.merge(right)`가 둘 다 있고, 둘은 완전히 같은 일을 해요.

## 의미 없는 인자는 두지 않아요

이 영역에서 아무 일도 하지 않을 인자는 시그니처에 없어요. 주면 에러예요.

| 없는 인자 | 이유 |
|---|---|
| `inplace` | 모든 함수가 새 결과를 돌려줘요. 원래 객체를 바꾸려면 다시 대입해요(`df = df.sort_values("price")`). |
| `copy` | 결과가 원래 객체와 메모리를 함께 써도, 한쪽을 고치면 고친 쪽만 바뀌어요([대입과 복사](/api/frame/assign/)). 그래서 복사할지 고를 필요가 없어요. numpy 배열을 주는 `to_numpy`, `to_array`에만 있어요. |
| Series 메서드의 `axis` | Series는 방향이 하나뿐이에요. |
| `level` | 여러 층의 라벨(MultiIndex)이 없어요. |
| `kind` | 정렬은 언제나 안정 정렬이에요. |
| `errors` | 문제가 있으면 언제나 에러를 내요. |

```python
>>> df.sort_values("price", inplace=True)
Traceback (most recent call last):
    ...
TypeError: DataFrame.sort_values() got an unexpected keyword argument 'inplace'
>>> s.head(2, axis=0)
Traceback (most recent call last):
    ...
TypeError: Series.head() got an unexpected keyword argument 'axis'
```

## 결과는 Python 값이에요

리덕션(합, 평균처럼 여러 값을 하나로 줄이는 계산)의 결과와 원소 하나를 꺼낸 값은 **평범한 Python 값**이에요. dtype에 따라 `bool`, `int`, `float`, `str`이고, 값이 없으면 `NA`예요. 배열 영역에서 0차원 배열 대신 Python 숫자를 돌려주는 것과 같아요.

```python
>>> s.sum()
6100
>>> type(s.sum())
<class 'int'>
>>> type(s.mean())
<class 'float'>
>>> type(df.loc[0, "fruit"])
<class 'str'>
```

DataFrame의 리덕션은 열마다 값이 하나씩이라서, 리덕션 이름을 라벨로 하는 **1행짜리 DataFrame**이에요. 열마다 자기 dtype을 지켜요.

```python
>>> df[["price", "qty"]].sum()
     price  qty
sum   6100   11
```

## 경고는 없고, 에러만 있어요

stardust는 경고(warning)를 하나도 내지 않아요. 문제가 있으면 에러로 멈추고, 문제가 아니면 조용히 계산해요.

값 때문에 생기는 일은 에러가 아니에요. float를 0으로 나누면 `inf`나 `NaN`이 나오고, 정수를 0으로 나누면 답이 없다는 뜻으로 `NA`가 나와요([NA와 NaN](/api/frame/na/)).

```python
>>> sd.frame.Series([7.0, -7.0, 0.0]) / 0
0    inf
1   -inf
2    NaN
dtype: float64
>>> sd.frame.Series([7, 7]) // sd.frame.Series([2, 0])
0       3
1    <NA>
dtype: int64
```

타입이나 구조가 맞지 않으면 에러예요. 어떤 에러를 낼지는 어느 함수에서나 같은 기준으로 정해요.

| 에러 | 언제 | 예 |
|---|---|---|
| `TypeError` | 타입이 틀렸어요. 계산할 수 없는 dtype끼리의 연산, 옵션의 타입, 정보를 잃는 암묵적 변환 | `s.sum(skipna=0)` |
| `ValueError` | 타입은 맞지만 값이 틀렸어요. 길이가 다른 열, 받지 않는 옵션 문자열 | `na_position="middle"` |
| `KeyError` | 없는 라벨이나 열 이름을 찾았어요 | `s.loc[10]`, `df.sort_values("weight")` |
| `IndexError` | 위치가 범위 밖이거나 위치로 쓸 수 없는 값이에요 | `s.iloc[10]` |
| `OverflowError` | int64에 담을 수 없는 큰 정수예요 | `s.head(2**70)` |

```python
>>> sd.frame.Series([1, 2]) + sd.frame.Series(["a", "b"])
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for +: int64 and string (strings support + and comparisons)
>>> sd.frame.DataFrame({"a": [1, 2], "b": [1]})
Traceback (most recent call last):
    ...
ValueError: DataFrame(): all columns must have the same length
>>> df.sort_values("weight")
Traceback (most recent call last):
    ...
KeyError: "sort_values(): no column 'weight'"
>>> s.iloc[10]
Traceback (most recent call last):
    ...
IndexError: position 10 is out of range for 4 rows
```

## `bool(df)`는 에러예요

Series, DataFrame, Index를 `if`에 바로 쓰거나 `bool()`로 바꾸면 `TypeError`예요. 배열도 같아요.

```python
>>> bool(df)
Traceback (most recent call last):
    ...
TypeError: the truth value of a DataFrame is ambiguous
>>> bool(s)
Traceback (most recent call last):
    ...
TypeError: the truth value of a Series is ambiguous
```

표가 "참"이라는 말의 뜻이 하나로 정해지지 않기 때문이에요. 비어 있지 않다는 뜻일 수도, 모든 값이 참이라는 뜻일 수도, 하나라도 참이라는 뜻일 수도 있어요. 짐작해서 하나를 고르면 틀린 쪽을 고른 코드가 조용히 잘못 돌아가요. 비었는지 알고 싶으면 길이를 봐요.

```python
>>> len(df) == 0
False
>>> len(sd.frame.DataFrame()) == 0
True
```

## pickle로 저장할 수 있어요

Series, DataFrame, Index는 Python의 `pickle`로 저장하고 되살릴 수 있어요. 값은 비트까지 그대로예요. `NA`, `NaN`, `-0.0`도 그대로 돌아와요. 배열(`sd.ndarray`)은 pickle할 수 없어요.

```python
>>> import pickle
>>> back = pickle.loads(pickle.dumps(df))
>>> back
    fruit  price  qty  revenue
0   apple   1200    3     3600
1  banana    800    5     4000
2  cherry   3000    1     3000
3   apple   1100    2     2200
>>> pickle.dumps(sd.asarray([1, 2]))
Traceback (most recent call last):
    ...
TypeError: cannot pickle 'ndarray' object
```

그래서 `multiprocessing`처럼 객체를 pickle로 주고받는 도구에도 Series와 DataFrame을 그대로 넘길 수 있어요.

## 결과는 스레드 수와 상관없이 같아요

큰 표의 계산은 여러 CPU 코어로 나눠서 해요. 코어 수는 라이브러리 공통의 `sd.set_num_threads`로 정해요([스레드](/api/array/threads/)). 몇 개의 스레드로 계산하든 **결과는 비트까지 같아요.** float 합의 마지막 자리, 행의 순서, 에러 메시지까지 같아요.

```python
>>> x = sd.frame.Series([0.1] * 1_000_000)
>>> n = sd.get_num_threads()
>>> sd.set_num_threads(1)
>>> one = x.sum()
>>> sd.set_num_threads(n)
>>> one == x.sum()
True
```

float 덧셈은 순서에 따라 마지막 자리가 달라질 수 있어서, 나눠 계산하는 방식에 따라 결과가 흔들리기 쉬워요. stardust는 언제나 같은 순서로 더하도록 나눠서, 같은 데이터면 몇 번을 실행해도 같은 답이 나와요.

## 배열 영역과의 관계

데이터프레임의 열 하나는 배열 하나와 많이 닮았어요. 그래서 이름과 규칙도 되도록 배열 영역과 같아요.

**같은 것**

| 무엇 | 자세히 |
|---|---|
| dtype 객체(`sd.bool`, `sd.int64`, `sd.float64`)와 승격 순서 `bool < int64 < float64` | [원소 종류(dtype)](/api/array/dtypes/) |
| `astype`의 숫자 변환 규칙(float → int는 0 쪽으로 자르기 등) | [astype](/api/array/astype/) |
| 정수 나눗셈 `/`의 결과는 float64, `//`와 `%`는 floor 규칙, 정수 넘침은 반대쪽 끝으로 | [계산 규칙](/api/array/numerics/) |
| 정렬의 `descending`, `stable` | [sort](/api/array/sort/) |
| 고유값은 `unique_values`, 정렬한 순서 | [unique](/api/array/unique/) |
| `std`, `var`의 기본 `correction=0` | [var](/api/array/var/) |
| 주 인자는 자리로, 옵션은 이름으로, 옵션 타입 검사와 메시지 | [배열의 기본](/api/array/basics/) |
| 경고 없음, Python 값으로 된 결과, `bool()`은 `TypeError`, 스레드와 무관한 결과 | [배열의 기본](/api/array/basics/) |

**다른 것**

| 무엇 | 배열 | 데이터프레임 | 이유 |
|---|---|---|---|
| 문자열 | 없음 | `sd.string` | 표에는 이름 같은 문자열 열이 필요해요 |
| 복소수 | `sd.complex128` | 없음 | |
| 결측값 | 없음 | `NA` | 빈칸을 값과 구별해야 해요 |
| 정수 `// 0`, `% 0`, `** 음수` | 정해진 정수(`0`, 원래 값 등) | `NA` | 결측값이 있으니 "답이 없음"을 그대로 나타내요 |
| 값이 모자란 `std`, `var` | `NaN` | `NA` | 위와 같아요 |
| 두 객체의 연산 | 자리끼리 ([브로드캐스팅](/api/array/broadcasting/)) | 라벨끼리 ([라벨과 정렬](/api/frame/alignment/)) | 행에 라벨이 있어요 |
| 함수 모양 | 모듈 함수 `sd.sum(x)`가 기본 | 메서드 `s.sum()`가 기본 | |
| pickle | 안 됨 | 됨 | |

둘 사이는 쉽게 오가요. 배열 함수는 `sd.ndarray`만 받으므로, Series를 배열 함수에 넣으려면 먼저 [`to_array`](/api/frame/to-array/)로 바꿔요. 반대로 배열을 `Series`에 넣으면 열이 돼요. 기술통계(`sd.stats.describe` 등)와 회귀 함수처럼 자료를 처음 받는 함수는 Series를 그대로 받아요.

```python
>>> sd.sum(s)
Traceback (most recent call last):
    ...
TypeError: sum(): 'x' must be an sd.ndarray, not Series
>>> sd.sum(s.to_array())
6100
>>> sd.frame.Series(sd.asarray([1.5, 2.5]))
0    1.5
1    2.5
dtype: float64
```

## pandas를 아는 분께

이름과 동작은 대부분 pandas를 따르지만, 다른 곳이 있어요.

- 주 인자는 자리로만, 옵션은 이름으로만 넘겨요. pandas의 `s.head(n=2)`는 여기서 `TypeError`예요.
- 별칭이 없어요. `to_list`, `unique`, `isnull`, `notnull`, `add`·`sub`·`eq` 같은 연산자 메서드, `abs()` 메서드가 없어요. `ascending=` 대신 `descending=`이에요.
- `inplace`, `copy`(`to_numpy`·`to_array` 말고), Series 메서드의 `axis`, `level`, `kind`, `errors`가 없어요.
- 결과는 Python 값이에요. pandas는 `s.sum()`과 `s.iloc[0]`에 `numpy.int64` 같은 numpy 스칼라를 돌려줘요.
- 참·거짓 옵션에 `0`을 주면 `TypeError`예요. pandas는 `skipna=0`에 `ValueError`를 내고, `ascending=0`은 그대로 받아요.
- 결측값이 dtype을 바꾸지 않아요. pandas의 기본 dtype은 `Series([1, None])`을 float64와 `NaN`으로 만들지만, 여기서는 int64와 `NA`예요. 문자열 열의 빈칸도 `NaN`이 아니라 `<NA>`로 보여요.
- `df.dtypes`는 dict예요. DataFrame의 리덕션(`df.sum()`)은 Series가 아니라 1행짜리 DataFrame이에요. 열마다 dtype을 지키기 위해서예요.
- `bool(df)`, `bool(s)`, `bool(index)`는 `TypeError`예요. pandas는 `ValueError`예요.
- 경고가 없어요. pandas가 경고를 내고 계속하는 자리에서 stardust는 에러를 내거나, 정해진 규칙대로 조용히 계산해요.
- float의 합, 평균, 분산처럼 반올림이 끼는 결과는 pandas·numpy와 반올림 오차 안에서 같고, 마지막 자리는 다를 수 있어요. 지금 비트까지 같은 경우가 있어도 그것을 약속하지는 않아요. 약속하는 것은 스레드 수와 상관없이 같은 비트, 같은 값을 담은 배열의 결과(`sd.sum`, `sd.mean`, `sd.var` 등)와 같은 비트, 그리고 정확도예요. 반올림과 상관없는 동작(dtype 규칙, 정수 연산, 정렬 순서, NaN과 `-0.0`)은 pandas·numpy와 같고, 다르게 정한 곳은 각 페이지의 끝에 이유와 함께 적어 두었어요.
- Index의 출력은 `Index([1, 2], dtype=int64)`예요. pandas는 `dtype='int64'`처럼 따옴표를 붙여요. 넓은 표를 터미널 폭에 맞춰 접지 않아요.
