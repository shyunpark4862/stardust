## 한눈에 보기

평균이 같아도 값이 모여 있는 정도는 다를 수 있어요. 두 학생의 네 번 시험 점수가 있어요. 둘 다 평균은 70점이지만, `a`는 언제나 70점이고 `b`는 55점에서 85점까지 오르내려요.

```python
>>> import stardust as sd
>>> a = sd.frame.Series([70, 70, 70, 70])
>>> b = sd.frame.Series([55, 65, 75, 85])
>>> a.mean(), b.mean()
(70.0, 70.0)
>>> a.std(), b.std()
(0.0, 11.180339887498949)
>>> b.var()
125.0
```

이 "흩어진 정도"를 재는 값이 **분산**(`var`)과 **표준편차**(`std`)예요. 값이 평균 가까이 모여 있을수록 작고, 넓게 퍼져 있을수록 커요. 모든 값이 같으면 0이에요. "점수가 고른 학생은 누구인가", "어느 가게의 하루 매출이 더 들쭉날쭉한가" 같은 질문에 써요.

## 어떻게 계산할까요

분산은 "평균에서 떨어진 거리의 제곱"의 평균이에요. 표준편차는 그 제곱근이에요.

1. 평균을 구해요. `b`는 70이에요.
2. 각 값에서 평균을 빼서, 평균에서 얼마나 떨어져 있는지 구해요.
3. 그 차이를 제곱해서 평균을 내면 분산이에요.

```python
>>> dev = b - b.mean()
>>> dev
0   -15.0
1    -5.0
2     5.0
3    15.0
dtype: float64
>>> (dev ** 2).mean()
125.0
```

차이를 제곱했기 때문에 분산의 단위는 원래 단위의 제곱(점²)이에요. 제곱근을 씌운 표준편차는 원래 단위(점)로 돌아와서 "평균에서 대략 11점쯤 떨어져 있다"고 읽을 수 있어요. 그래서 결과를 해석할 때는 보통 표준편차를 써요. 두 메서드는 옵션도 동작도 같고, `std`가 마지막에 제곱근을 씌운다는 점만 달라요.

분산을 더 자세히 알고 싶다면 배열의 [`sd.var`, `sd.std`](/api/array/var/) 페이지를 보세요. 정의와 `correction`의 뜻이 똑같아요.

## `correction`: N으로 나눌까요, N - 1로 나눌까요

위에서는 제곱한 차이의 합 `500`을 값의 개수 `4`로 나눴어요. 그런데 N - 1로 나누는 방법도 널리 쓰여요. `correction`은 나누는 수를 `N - correction`으로 정하는 옵션이에요.

| `correction` | 나누는 수 | 이름 | 이럴 때 |
|:---:|:---:|---|---|
| `0` (기본값) | N | 모분산 | 가진 데이터가 관심 대상의 **전부**일 때 |
| `1` | N - 1 | 표본 분산 | 가진 데이터가 더 큰 집단에서 뽑은 **일부**이고, 그 집단의 퍼짐을 짐작하고 싶을 때 |

```python
>>> score = sd.frame.Series([2, 4, 4, 4, 5, 5, 7, 9])
>>> score.var(), score.std()
(4.0, 2.0)
>>> score.var(correction=1), score.std(correction=1)
(4.571428571428571, 2.138089935299395)
```

우리 반 학생 모두의 점수라면 그 자체가 전부라서 N으로 나눠요. 전국 학생 가운데 몇 명만 뽑아서 전국의 퍼짐을 짐작한다면 사정이 달라요. 뽑힌 학생의 평균이 그 학생들에게 딱 맞춰져 있어서 퍼짐이 조금 작게 나오는 경향이 있어요. 그래서 N - 1로 나눠 조금 키워 줘요. 데이터가 많을수록 둘의 차이는 작아져요.

`correction`에는 실수도 쓸 수 있어요. 나누는 수가 `N - 1.5`가 될 뿐이에요.

```python
>>> score.var(correction=1.5)
4.923076923076923
```

기본값 `correction=0`과 이 옵션의 이름은 배열의 `sd.var`, `sd.std`와 같아요. 라이브러리 어디에서 분산을 구하든 기본값이 같아서, Series로 구한 값과 배열로 구한 값이 다를 일이 없어요.

<Callout type="warn" title="다른 도구의 기본값은 N - 1일 때가 많아요">

스프레드시트의 `STDEV.S`, R의 `sd`, pandas의 `std`는 기본으로 N - 1로 나눠요. 다른 도구와 결과가 조금 다르면 이 차이부터 확인하고, 같은 값이 필요하면 `correction=1`을 주세요.

</Callout>

## `NA`는 건너뛰고, N은 `NA`가 아닌 값의 개수예요

기본값 `skipna=True`에서는 결측값 `NA`를 빼고 계산해요. 평균도, 나누는 수의 N도 `NA`가 아닌 값만으로 정해요. N은 [`count()`](/api/frame/sum-mean/)와 같아요.

```python
>>> m = sd.frame.Series([80, None, 90, 70], name="math")
>>> m.count()
3
>>> m.var()
66.66666666666667
>>> m.std()
8.16496580927726
```

`80, 90, 70`의 평균 80에서 차이의 제곱 `0, 100, 100`을 더한 200을 3으로 나눴어요. `skipna=False`를 주면 `NA`가 하나라도 있을 때 결과가 `NA`예요.

```python
>>> m.var(skipna=False)
<NA>
```

## 값이 모자라면 `NA`예요

나누는 수 `N - correction`이 0이거나 음수가 되면 분산을 정할 수 없어요. 이때 결과는 `NA`예요. 가장 흔한 경우는 값이 하나뿐인데 `correction=1`을 준 때예요. 값 하나로는 더 큰 집단의 퍼짐을 짐작할 수 없다는 뜻이에요.

```python
>>> one = sd.frame.Series([88.0, None])
>>> one.var()
0.0
>>> one.var(correction=1)
<NA>
>>> sd.frame.Series([None, None], dtype="int64").std()
<NA>
```

`one`은 행이 둘이지만 `NA`가 아닌 값은 하나라서 N이 1이에요. 값이 하나도 없으면 `correction=0`이어도 N이 0이라 `NA`예요.

<Callout type="warn" title="배열은 같은 경우에 NaN이에요">

배열의 `sd.var`, `sd.std`는 같은 경우에 NaN을 돌려줘요. 데이터프레임만 `NA`예요.

</Callout>

```python
>>> sd.var(sd.asarray([88.0]), correction=1)
nan
```

배열에는 결측값이 없어서 "구할 수 없음"을 float 값 NaN으로 나타내요. 데이터프레임에는 "값이 없다"는 뜻의 `NA`가 따로 있어서 `NA`로 돌려줘요. 그래서 데이터에 있던 NaN이 퍼져서 나온 결과(NaN)와 값이 모자라서 못 구한 결과(`NA`)가 구별돼요. 모두 `NA`인 컬럼의 `mean()`이 `NA`인 것과 같은 규칙이고, 결과를 [`isna()`](/api/frame/isna/)나 [`dropna()`](/api/frame/dropna/)로 다룰 수 있어요.

## NaN은 결과로 퍼져요

NaN(Not a Number, 숫자가 아님)은 결측값이 아니라 평범한 float 값이라서 `skipna`가 건너뛰지 않아요. NaN이 하나라도 있으면 결과도 NaN이에요. 무한대가 있어도 평균과의 차이를 정할 수 없어서 NaN이에요. 배열과 같아요.

```python
>>> sd.frame.Series([1.0, float("nan"), 3.0]).std()
nan
>>> sd.frame.Series([1.0, float("inf")]).std()
nan
```

NaN을 빼고 계산하려면 `s[~s.isnan()]`처럼 NaN이 아닌 행만 남긴 뒤 부르세요([NA와 NaN](/api/frame/na/)).

## 결과는 언제나 실수예요

| 컬럼 dtype | `std`, `var` |
|:---:|---|
| int64 | float64 |
| float64 | float64 |
| bool | float64: `True`를 1, `False`를 0으로 보고 계산 |
| string | `TypeError` |

bool 컬럼의 분산은 bool 배열에 `sd.var`를 쓴 것과 비트까지 같아요.

```python
>>> sd.frame.Series([True, False, True, True]).var()
0.1875
>>> sd.var(sd.asarray([True, False, True, True]))
0.1875
```

## DataFrame은 1행짜리 DataFrame을 돌려줘요

DataFrame에 쓰면 컬럼마다 따로 계산해서, 행 라벨이 `std`나 `var`인 1행짜리 표로 돌려줘요. 결과는 모든 컬럼이 float64예요.

```python
>>> exam = sd.frame.DataFrame({
...     "math": [70, 85, 90],
...     "eng": [88.5, 92.0, 79.5],
...     "passed": [True, True, False],
... })
>>> exam.std()
         math      eng    passed
std  8.498366  5.26519  0.471405
>>> exam.var(correction=1)
           math        eng    passed
var  108.333333  41.583333  0.333333
>>> exam.std().loc["std", "eng"]
5.265189666310438
```

표 출력은 자리를 아끼려고 소수점 아래를 줄여서 보여 줘요. 값 하나를 꺼내면 전체 자릿수가 나와요. 결과가 왜 Series가 아니라 1행짜리 DataFrame인지는 [합, 평균, 개수](/api/frame/sum-mean/)에 있어요.

string 컬럼이 하나라도 있으면 `TypeError`예요. 숫자 컬럼만 골라서 부르세요.

```python
>>> sd.frame.DataFrame({"name": ["a", "b"], "x": [1, 2]}).std()
Traceback (most recent call last):
    ...
TypeError: std(): cannot compute std of a string column
```

## 배열의 `sd.var`와 결과가 같아요

`NA`가 없는 컬럼이면 `s.var()`와 `s.std()`는 배열의 `sd.var`, `sd.std`와 비트 하나까지 같아요. 평균을 구하는 덧셈과 차이의 제곱을 더하는 덧셈이 배열과 같은 순서로 이뤄지기 때문이에요. 정수 컬럼도 그래요.

```python
>>> s = sd.frame.Series([1.5, 2.5, 4.0, 8.0])
>>> s.var() == sd.var(s.to_array())
True
>>> s.std(correction=1) == sd.std(s.to_array(), correction=1)
True
```

결과는 계산에 쓰는 스레드 수와도 상관없어요.

## 조심할 점

### `correction`의 타입

`correction`에는 int나 float만 써요. `True`/`False`, `None`, 문자열은 `TypeError`예요. 옵션은 모두 이름을 붙여서 줘야 해요.

```python
>>> score.var(correction=True)
Traceback (most recent call last):
    ...
TypeError: var(): 'correction' must be an int or a float, not bool
>>> score.var(correction=None)
Traceback (most recent call last):
    ...
TypeError: var(): 'correction' must be an int or a float, not NoneType
```

실수로 바꿀 수 없을 만큼 큰 정수는 `OverflowError`예요. 배열의 `sd.var`와 같은 메시지예요.

```python
>>> score.var(correction=10**400)
Traceback (most recent call last):
    ...
OverflowError: var(): 'correction' is out of range
```

### 아주 큰 정수

정수는 실수로 바꿔서 계산해요. 약 9 × 10¹⁵보다 큰 정수는 실수로 바뀌면서 작은 차이가 사라질 수 있어요. 크고 서로 가까운 값이라면 공통된 큰 값을 먼저 빼고 계산하세요. 분산은 모든 값에 같은 수를 더하거나 빼도 변하지 않아요.

```python
>>> big = sd.frame.Series([2**62, 2**62 + 2])
>>> big.var()
0.0
>>> (big - 2**62).var()
1.0
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 다른 점 |
|---|---|---|
| 가운데가 어디인지 | [`mean`](/api/frame/sum-mean/) | 퍼짐이 아니라 중심을 재요. |
| 가장 작은 값과 큰 값의 간격 | [`min`, `max`](/api/frame/min-max/) | 양 끝 두 값만 봐서 튀는 값 하나에 크게 흔들려요. |
| 그룹마다 퍼짐 | [`groupby(...).std()`](/api/frame/groupby-agg/) | 키 값이 같은 행끼리 따로 계산해요. `correction` 기본값과 `NA` 규칙은 이 페이지와 같아요. |
| 배열의 퍼짐 | [`sd.var`, `sd.std`](/api/array/var/) | `axis`를 골라 행별·열별로 계산할 수 있어요. 값이 모자라면 NaN이에요. |

## pandas를 아는 분께

- 기본값이 `correction=0`(N으로 나누기)이에요. pandas의 기본값은 `ddof=1`이에요. 같은 값이 필요하면 `correction=1`을 주세요. 인자 이름도 `ddof`가 아니라 `correction`이고, `ddof=`는 받지 않아요.
- 값이 모자라면(`N - correction`이 0 이하) `NA`예요. pandas는 float 컬럼에서 `nan`이에요.
- NaN을 건너뛰지 않아요. pandas는 NaN을 건너뛰고 계산하지만 stardust는 결과가 `nan`이에요. `skipna`는 `NA`만 건너뛰어요.
- DataFrame의 결과는 1행짜리 DataFrame이에요. pandas는 Series예요.
- `NA`도 NaN도 없는 float 컬럼이면 `var(correction=1)`, `std(correction=1)`이 pandas의 `var()`, `std()`와 반올림 오차 안에서 같아요. 마지막 자리는 다를 수 있어요. 위 예의 `eng` 열 표준편차가 stardust는 `5.265189666310438`, pandas(`ddof=0`)와 numpy는 `5.265189666310437`이에요.
- `axis`, `numeric_only` 인자는 없어요.
