## 한눈에 보기

Series와 DataFrame의 행에는 **라벨**(label)이 붙어 있어요. 행의 이름표예요. 두 Series를 더하면 위에서 몇째 행인지가 아니라 라벨이 같은 행끼리 더해요. 이렇게 라벨로 행을 맞추는 일을 **정렬**(alignment)이라고 해요.

과일 가게의 1월과 2월 판매량을 과일별로 더해요. 두 달의 기록은 과일 순서가 다르고, 2월에는 cherry가 없는 대신 durian이 새로 들어왔어요.

```python
>>> import stardust as sd
>>> jan = sd.frame.Series([120, 80, 50], index=["apple", "banana", "cherry"], name="sales")
>>> feb = sd.frame.Series([30, 100, 90], index=["banana", "apple", "durian"], name="sales")
>>> jan + feb
apple      220
banana     110
cherry    <NA>
durian    <NA>
Name: sales, dtype: int64
```

apple은 120 + 100, banana는 80 + 30으로, 순서가 달라도 같은 과일끼리 더해졌어요. 한쪽 달에만 있는 cherry와 durian은 더할 짝이 없어서 결과가 `<NA>`(값 없음)예요.

  <Op>+</Op>

  <Op>=</Op>

엑셀이라면 두 시트의 행 순서를 먼저 맞추고 나서 더해야 해요. 순서가 어긋난 채로 더하면 apple의 1월 판매량에 banana의 2월 판매량이 더해지는 실수가 생겨요. 라벨이 있으면 그런 실수가 생기지 않아요.

<Callout title="두 가지 '정렬'">
  이 페이지의 정렬은 라벨끼리 행을 맞추는 일(alignment)이에요. 값을 크기 순서로 늘어놓는 정렬(sort)은 [sort_values](/api/frame/sort_values/)와 [sort_index](/api/frame/sort_index/)에 있어요.
</Callout>

## 라벨은 무엇이고 왜 있나요

라벨은 행을 가리키는 이름이에요. 행의 라벨 목록을 **Index**라고 해요. 라벨을 따로 주지 않으면 0부터 차례로 번호가 붙는데, 이런 Index를 `RangeIndex`라고 해요.

```python
>>> s = sd.frame.Series([10, 20, 30])
>>> s.index
RangeIndex(start=0, stop=3, step=1)
>>> s.index.tolist()
[0, 1, 2]
>>> jan.index
Index(['apple', 'banana', 'cherry'], dtype=string)
```

행은 라벨로도, 위치(위에서 몇째인지, 0부터)로도 가리킬 수 있어요. Series의 `s[x]`는 라벨이고, 위치는 `.iloc`으로 써요([대괄호로 고르기](/api/frame/selection/), [loc과 iloc](/api/frame/loc-iloc/)).

```python
>>> jan["banana"]
80
>>> jan.iloc[1]
80
```

라벨은 행을 따라다녀요. 값을 정렬하거나 행을 걸러서 위치가 바뀌어도, 각 값의 라벨은 그대로예요. 그래서 순서를 바꾼 결과를 원래 Series와 계산해도 같은 과일끼리 계산돼요.

```python
>>> jan.sort_values()
cherry     50
banana     80
apple     120
Name: sales, dtype: int64
>>> jan.sort_values() + jan
cherry    100
banana    160
apple     240
Name: sales, dtype: int64
```

위치는 행의 순서가 바뀌면 다른 행을 가리키지만, 라벨은 언제나 같은 행을 가리켜요. 학생 번호, 상품 코드, 도시 이름처럼 기록마다 고유한 이름이 있으면 그 값을 라벨로 삼으면 좋아요.

## 라벨로 쓸 수 있는 것

라벨의 dtype은 int64와 string 둘이에요. `RangeIndex`는 int64 라벨로 쳐요. float나 bool 값, 결측값 `NA`는 라벨이 될 수 없어요.

```python
>>> sd.frame.Series([1, 2], index=[1.5, 2.5])
Traceback (most recent call last):
    ...
TypeError: Series(): index labels must be int64 or string, not float64
>>> sd.frame.Series([1, 2], index=[True, False])
Traceback (most recent call last):
    ...
TypeError: Series(): index labels must be int64 or string, not bool
>>> sd.frame.Series([1, 2], index=["a", None])
Traceback (most recent call last):
    ...
ValueError: Series(): an index cannot hold NA
>>> sd.frame.Series([1, 2], index=[1, "a"])
Traceback (most recent call last):
    ...
TypeError: Series(): str values cannot be mixed with int values (there is no object dtype)
```

float나 bool 값, 결측값이 든 데이터는 라벨 대신 보통 열로 두고 써요. [groupby](/api/frame/groupby/)와 [value_counts](/api/frame/value_counts/)가 키를 라벨이 아닌 열로 돌려주는 것도 이 때문이에요. 키를 라벨로 돌려주면 float나 bool 키를 담을 수 없으니까요.

### 중복 라벨

라벨이 겹쳐도 만들 수 있어요. 겹치는지는 `index.is_unique`로 봐요. 겹친 라벨 하나만 주어 고르면 어느 행인지 모호해서 에러이고, 리스트로 고르면 그 라벨의 행이 모두 나와요.

```python
>>> d = sd.frame.Series([10, 20, 30], index=["a", "a", "b"])
>>> d
a    10
a    20
b    30
dtype: int64
>>> d.index.is_unique
False
>>> d["a"]
Traceback (most recent call last):
    ...
KeyError: "label 'a' is not unique; select with a list (['a']) to get every row"
>>> d.loc[["a"]]
a    10
a    20
dtype: int64
```

중복 라벨이 정렬에서 어떻게 되는지는 아래 "라벨이 고유하지 않으면 에러예요"에 있어요.

## 정렬이 일어나는 곳

두 객체의 행을 짝지어야 하는 곳에서는 언제나 라벨로 맞춰요.

| 상황 | 예 | 결과의 라벨 |
|---|---|---|
| Series끼리의 연산 (산술, 비교, 논리) | `jan + feb`, `jan > feb` | 두 라벨의 합집합 |
| DataFrame끼리의 연산 | `left + right` | 행도 열도 합집합 |
| Series를 담은 dict로 DataFrame 만들기 | `DataFrame({"jan": jan, "feb": feb})` | 합집합 (`index=`를 주면 그 라벨) |
| 열 대입 | `df["c"] = s` | `df`의 라벨 그대로 |
| 행 대입 | `s.loc[["a", "c"]] = t` | 고른 행의 라벨 그대로 |
| 마스크로 거르기 | `s[mask]` | 라벨 집합이 같아야 해요 |
| 다른 라벨로 다시 늘어놓기 | `s.reindex(labels)`, `Series(s, index=labels)` | 준 라벨 그대로 |

정렬하지 않는 곳도 있어요.

- 스칼라와의 연산(`s + 1`)은 모든 행에 같은 값을 써요.
- [concat](/api/frame/concat/)은 라벨을 맞추지 않고, 표와 라벨을 그대로 아래로 이어 붙여요.
- [merge](/api/frame/merge/)는 라벨이 아니라 지정한 열(키)의 값으로 행을 짝지어요. 결과 라벨은 새로 0부터 붙어요.

## 두 Index가 같으면 위치대로

두 객체의 라벨이 순서까지 완전히 같으면 맞출 필요가 없으니 위치대로 계산해요. 이때는 라벨이 겹쳐도 괜찮아요. 같은 위치의 행끼리 짝이 분명하니까요. `RangeIndex`와 같은 정수를 담은 `Index`도 라벨이 같으면 같은 Index예요.

```python
>>> d + d
a    20
a    40
b    60
dtype: int64
>>> s + sd.frame.Series([1, 2, 3], index=sd.frame.Index([0, 1, 2]))
0    11
1    22
2    33
dtype: int64
```

같은 DataFrame에서 꺼낸 열끼리는 언제나 Index가 같아서, 이 경우가 가장 흔해요. `df["price"] * df["qty"]`가 그래요.

## 다르면 라벨로 맞춰요

두 Index가 다르면 이렇게 계산해요.

1. 결과의 라벨을 정해요. 왼쪽 피연산자의 라벨을 왼쪽 순서대로 먼저 놓고, 오른쪽에만 있는 라벨을 오른쪽 순서대로 뒤에 붙여요.
2. 결과의 라벨마다 양쪽에서 같은 라벨의 값을 찾아 계산해요.
3. 한쪽에 그 라벨이 없으면 그 행의 결과는 `NA`예요. dtype은 바뀌지 않아요.

결과의 라벨은 크기 순서로 정렬하지 않아요. 그래서 피연산자의 순서를 바꾸면 값은 같아도 행의 순서가 달라져요.

```python
>>> feb + jan
banana     110
apple      220
durian    <NA>
cherry    <NA>
Name: sales, dtype: int64
```

기본 라벨(0, 1, 2…)에서도 같아요. `s.tail(2)`의 라벨은 1, 2이고 `s.head(2)`의 라벨은 0, 1이라서, 겹치는 라벨 1만 짝이 있어요. 결과는 왼쪽의 1, 2 다음에 오른쪽에만 있는 0이 붙은 순서예요.

```python
>>> s.tail(2)
1    20
2    30
dtype: int64
>>> s.head(2)
0    10
1    20
dtype: int64
>>> s.tail(2) + s.head(2)
1      40
2    <NA>
0    <NA>
dtype: int64
```

<Fig caption="왼쪽의 라벨(1, 2)이 먼저, 오른쪽에만 있는 라벨(0)이 뒤에 와요. 짝이 있는 라벨 1만 값이 있어요.">
  <FrameFig name="s.tail(2)" data={[20, 30]} index={[1, 2]} rowTones={['1', 'a']} />
  <Op>+</Op>
  <FrameFig name="s.head(2)" data={[10, 20]} index={[0, 1]} rowTones={['b', '1']} />
  <Op>=</Op>
  <FrameFig data={[40, null, null]} index={[1, 2, 0]} rowTones={['1', 'a', 'b']} />
</Fig>

라벨 집합은 같은데 순서만 다르면 결과는 왼쪽의 순서를 따라요.

```python
>>> sd.frame.Series([1, 2, 3], index=[2, 0, 1]) + sd.frame.Series([10, 20, 30])
2    31
0    12
1    23
dtype: int64
```

비교와 논리 연산도 같은 방법으로 맞춰요. 짝이 없는 행은 비교할 수 없으니 `NA`예요.

```python
>>> jan > feb
apple     True
banana    True
cherry    <NA>
durian    <NA>
Name: sales, dtype: bool
```

### 없는 쪽을 0으로 보고 싶을 때

"2월에 cherry가 없으면 0개 팔린 것"처럼 없는 쪽을 어떤 값으로 여기고 싶을 때가 있어요. 그럴 때는 먼저 양쪽을 같은 라벨로 늘어놓고([reindex](/api/frame/reindex/)) 빈칸을 채운 다음([fillna](/api/frame/fillna/)) 계산해요.

```python
>>> total = jan + feb
>>> total.index
Index(['apple', 'banana', 'cherry', 'durian'], dtype=string)
>>> jan.reindex(total.index).fillna(0) + feb.reindex(total.index).fillna(0)
apple     220
banana    110
cherry     50
durian     90
Name: sales, dtype: int64
```

계산 결과의 `NA`를 나중에 `fillna(0)`로 채우는 것과는 달라요. 그러면 cherry가 50이 아니라 0이 돼요.

### 결과의 이름

결과 Series의 이름은 두 Series의 이름이 같으면 그 이름이고, 다르면 `None`이에요. Index의 이름도 같은 규칙이에요.

```python
>>> a = sd.frame.Series([1, 2], index=sd.frame.Index(["x", "y"], name="key"), name="v")
>>> b = sd.frame.Series([3, 4], index=sd.frame.Index(["y", "z"], name="key"), name="v")
>>> a + b
key
x    <NA>
y       5
z    <NA>
Name: v, dtype: int64
>>> c = sd.frame.Series([3, 4], index=["y", "z"], name="w")
>>> a + c
x    <NA>
y       5
z    <NA>
dtype: int64
```

## 라벨이 고유하지 않으면 에러예요

두 Index가 다를 때, 어느 쪽이든 라벨이 겹치면 `ValueError`예요.

```python
>>> d + sd.frame.Series([1, 2], index=["a", "b"])
Traceback (most recent call last):
    ...
ValueError: cannot align indexes with duplicate labels
```

`d`에는 라벨 `a`인 행이 둘이고, 상대에는 하나예요. 둘 다에 1을 더할지, 첫 행에만 더할지, 행을 늘려서 모든 조합을 만들지 라벨만으로는 하나로 정해지지 않아요. 그래서 계산하지 않고 에러를 내요. 라벨을 고유하게 만든 다음 계산하세요. 위치대로 계산하는 것이 의도라면 두 Series의 Index를 같게 만들면 돼요.

## int 라벨과 string 라벨은 맞출 수 없어요

한쪽은 정수 라벨, 다른 쪽은 문자열 라벨이면 `TypeError`예요. `0`과 `"0"`은 같은 라벨이 아니라서, 맞춘다면 모든 행이 짝을 잃고 `NA`가 될 거예요. 그렇게 조용히 `NA`로 채우지 않고 에러를 내요. 한쪽은 CSV에서 문자열로 읽은 번호, 다른 쪽은 정수 번호일 때 이런 에러를 만나기 쉬워요.

```python
>>> sd.frame.Series([1, 2], index=[0, 1]) + sd.frame.Series([1, 2], index=["0", "1"])
Traceback (most recent call last):
    ...
TypeError: cannot align int64 labels with string labels
```

## DataFrame끼리: 행과 열 모두

DataFrame끼리 계산하면 행은 라벨로, 열은 이름으로 맞춰요. 규칙은 Series와 같아요. 결과의 열은 왼쪽의 열 순서를 먼저 따르고, 오른쪽에만 있는 열을 뒤에 붙여요.

```python
>>> left = sd.frame.DataFrame({"price": [1200, 800], "qty": [3, 5]}, index=["apple", "banana"])
>>> right = sd.frame.DataFrame({"qty": [1, 2], "price": [100, 50]}, index=["banana", "cherry"])
>>> left + right
        price   qty
apple    <NA>  <NA>
banana    900     6
cherry   <NA>  <NA>
```

한쪽에만 있는 열은 다른 쪽을 같은 dtype의 `NA` 열로 보고 계산해요. 그래서 그 열은 모두 `NA`예요.

```python
>>> sd.frame.DataFrame({"a": [1, 2], "b": [3, 4]}) + sd.frame.DataFrame({"b": [10, 20], "c": [100, 200]})
      a   b     c
0  <NA>  13  <NA>
1  <NA>  24  <NA>
```

### DataFrame과 Series는 함께 계산하지 않아요

DataFrame과 스칼라는 모든 칸에 같은 값을 써서 계산해요. 하지만 DataFrame과 Series의 연산은 `TypeError`예요. 열 하나와 계산하려면 `df["price"] * s`처럼 Series끼리 계산해요.

```python
>>> left + 1
        price  qty
apple    1201    4
banana    801    6
>>> left + sd.frame.Series([1, 2])
Traceback (most recent call last):
    ...
TypeError: operations between a DataFrame and a Series are not supported
```

## 마스크도 라벨로 맞춰요

`s[mask]`처럼 bool Series로 행을 거를 때도 라벨로 맞춰요. 그래서 마스크의 행 순서가 달라도 돼요. 다만 마스크와 대상의 라벨 집합이 같아야 해요. 대상의 라벨이 마스크에 없거나 마스크에만 있는 라벨이 있으면 `ValueError`예요. 덕분에 다른 Series로 만든 마스크를 잘못 쓰면 에러로 드러나요.

```python
>>> jan[jan > 60]
apple     120
banana     80
Name: sales, dtype: int64
>>> mask = sd.frame.Series([True, False, True], index=["cherry", "banana", "apple"])
>>> jan[mask]
apple     120
cherry     50
Name: sales, dtype: int64
>>> jan[feb > 60]
Traceback (most recent call last):
    ...
ValueError: the mask's labels must be the index's labels
```

결과의 행은 대상(`jan`)의 순서를 따라요. 자세한 내용은 [조건으로 행 거르기](/api/frame/mask/)에 있어요.

## 대입과 생성에서의 정렬

열에 Series를 대입하면 DataFrame의 라벨에 맞춰 넣어요. DataFrame에 없는 라벨(아래의 kiwi)은 버리고, Series에 없는 라벨(banana)은 `NA`가 돼요. 결과의 라벨은 DataFrame의 라벨 그대로예요.

```python
>>> shop = sd.frame.DataFrame({"price": [1200, 800, 3000]}, index=["apple", "banana", "cherry"])
>>> shop["stock"] = sd.frame.Series([5, 0, 9], index=["cherry", "apple", "kiwi"])
>>> shop
        price  stock
apple    1200      0
banana    800   <NA>
cherry   3000      5
```

행에 대입할 때도 고른 행의 라벨에 맞춰 넣어요.

```python
>>> t = sd.frame.Series([1, 2, 3], index=["a", "b", "c"])
>>> t.loc[["a", "c"]] = sd.frame.Series([100, 300], index=["c", "a"])
>>> t
a    300
b      2
c    100
dtype: int64
```

Series를 담은 dict로 DataFrame을 만들면 모든 Series의 라벨을 합집합으로 맞춰요. `index=`를 주면 그 라벨에 맞춰요. 대입과 생성의 자세한 규칙은 [대입과 복사](/api/frame/assign/)와 [DataFrame](/api/frame/dataframe/)에 있어요.

```python
>>> sd.frame.DataFrame({"jan": jan, "feb": feb})
         jan   feb
apple    120   100
banana    80    30
cherry    50  <NA>
durian  <NA>    90
>>> sd.frame.DataFrame({"jan": jan, "feb": feb}, index=["apple", "banana"])
        jan  feb
apple   120  100
banana   80   30
```

## 배열의 브로드캐스팅과 무엇이 다른가요

배열에는 라벨이 없어요. 배열끼리의 연산은 위치로 짝을 지어요. 모양이 다르면 길이가 1인 축을 늘려서 맞추는데, 이것을 [브로드캐스팅](/api/array/broadcasting/)이라고 해요. Series끼리의 연산은 라벨로 짝을 지어요.

같은 숫자를 배열과 Series로 더해 보면 차이가 보여요.

```python
>>> x = sd.asarray([120, 80, 50])
>>> y = sd.asarray([30, 100, 90])
>>> x + y
array([150, 180, 140], dtype=int64)
>>> jan + feb
apple      220
banana     110
cherry    <NA>
durian    <NA>
Name: sales, dtype: int64
```

| 길이가 다르면 | 브로드캐스팅할 수 없으면 `ValueError` | 합집합으로 맞추고 빈 쪽은 `NA` |

```python
>>> sd.asarray([1, 2, 3]) + sd.asarray([1, 2])

    ...
ValueError: shapes could not be broadcast together: (3,) (2,)
```

Series와 배열은 바로 섞어서 계산할 수 없어요(`TypeError`). 위치대로 계산하려면 [`to_array`](/api/frame/to-array/)로 둘 다 배열로 바꿔요. 이때 라벨은 사라지니, 정말 위치대로 짝지어도 되는지 확인하세요.

```python
>>> jan + y
Traceback (most recent call last):
    ...
TypeError: unsupported operand type(s) for +: 'Series' and 'ndarray'
>>> jan.to_array() + feb.to_array()
array([150, 180, 140], dtype=int64)
```

## pandas를 아는 분께

- 결과의 라벨을 정렬하지 않아요. pandas는 두 Index가 다르면 합집합을 크기 순서로 정렬해서 `jan + feb`와 `feb + jan`이 같은 순서이고, `s.tail(2) + s.head(2)`의 라벨이 0, 1, 2예요. 여기서는 왼쪽 라벨 다음에 오른쪽에만 있는 라벨이에요.
- 짝이 없는 행은 dtype을 지킨 채 `NA`예요. pandas의 기본 dtype은 int64 결과를 float64와 `NaN`으로 바꿔요.
- 중복 라벨이 있으면 맞추지 않고 에러예요. pandas는 중복 라벨이 있어도 맞춰서 계산해요.
- int 라벨과 string 라벨을 맞추면 `TypeError`예요. pandas는 두 라벨을 모두 담은 object Index를 만들고 모든 값을 `NaN`으로 채워요.
- DataFrame과 Series의 연산이 없어요. pandas는 Series의 라벨을 DataFrame의 열 이름에 맞춰서 행마다 계산해요.
- 마스크에만 있는 라벨도 에러예요. pandas는 대상에 없는 마스크의 라벨을 조용히 무시해요. 대상의 라벨이 마스크에 없으면 pandas도 에러예요.
- float와 bool은 라벨이 될 수 없어요. pandas는 `index=[1.5, 2.5]`, `index=[True, False]`도 받아요.
