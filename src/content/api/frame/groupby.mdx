## 한눈에 보기

과일 가게의 판매 기록이 있다고 해 볼게요. 한 행이 한 번의 판매예요. "과일마다 모두 몇 개 팔렸나"를 알고 싶으면, 같은 과일의 행끼리 모은 다음 묶음마다 개수를 더하면 돼요.

`groupby`가 바로 이 일을 해요. **키 컬럼의 값이 같은 행끼리 묶어서**(이 묶음을 **그룹**이라고 해요), **그룹마다 계산**하고, 그 결과를 **그룹 하나가 한 행인 표**로 모아 줘요. 엑셀의 피벗 테이블이나 "부분합", SQL의 `GROUP BY`와 같은 일이에요.

```python
>>> import stardust as sd
>>> df = sd.frame.DataFrame({"fruit": ["apple", "pear", "apple", "kiwi", "pear", "apple"],
...                          "qty": [3, 1, 5, 2, 4, 2]})
>>> df.groupby("fruit").sum()
   fruit  qty
0  apple   10
1   kiwi    2
2   pear    5
```

<Fig caption="같은 fruit 값을 가진 행이 한 그룹이 되고(같은 색), 그룹마다 qty를 더해서 그룹 하나가 한 행이 돼요.">
  <FrameFig name="df" columns={['fruit', 'qty']} dtypes={['string', 'int64']}
    data={[['apple', 3], ['pear', 1], ['apple', 5], ['kiwi', 2], ['pear', 4], ['apple', 2]]}
    rowTones={['1', '3', '1', '2', '3', '1']} />
  <Op note='groupby("fruit").sum()'>→</Op>
  <FrameFig columns={['fruit', 'qty']} dtypes={['string', 'int64']}
    data={[['apple', 10], ['kiwi', 2], ['pear', 5]]}
    rowTones={['1', '2', '3']} />
</Fig>

`apple`은 `3 + 5 + 2 = 10`, `pear`는 `1 + 4 = 5`, `kiwi`는 `2`예요.

이럴 때 써요.

- 과일별 판매량, 지점별 매출, 반별 평균 점수처럼 **"~별"로 요약**할 때
- 그룹마다 몇 행이 있는지 셀 때
- 그룹마다 가장 크거나 작은 값, 처음이나 마지막 값을 볼 때

`df.groupby("fruit")` 자체는 아직 아무것도 계산하지 않아요. 어떻게 묶을지만 기억한 **GroupBy 객체**(이 문서에서는 `g`라고 불러요)를 돌려줘요. 여기에 `sum()`, `mean()`, `size()` 같은 **집계 메서드**를 불러야 결과 표가 나와요. 한 번 만든 `g`로 여러 집계를 할 수 있어요.

```python
>>> g = df.groupby("fruit")
>>> g.mean()
   fruit       qty
0  apple  3.333333
1   kiwi  2.000000
2   pear  2.500000
>>> g.size()
   fruit  size
0  apple     3
1   kiwi     1
2   pear     2
```

집계 메서드 하나하나는 [그룹 집계](/api/frame/groupby-agg/)에, 여러 집계를 한 번에 하는 방법은 [GroupBy.agg](/api/frame/agg/)에 있어요.

## 결과는 키를 일반 컬럼으로 둔 DataFrame이에요

집계 결과는 언제나 **DataFrame**이에요. 컬럼은 **키 컬럼이 먼저**, 그다음 집계한 값 컬럼이 와요. 행 라벨은 `0, 1, 2, …`(RangeIndex)이고, 키는 라벨이 아니라 **보통 컬럼**으로 들어가요.

```python
>>> r = g.sum()
>>> r.columns
Index(['fruit', 'qty'], dtype=string)
>>> r.index
RangeIndex(start=0, stop=3, step=1)
```

키를 라벨로 두지 않는 이유는 키 컬럼이 실수(float64)나 bool일 수도 있는데, 라벨(Index)로는 정수와 문자열만 쓸 수 있기 때문이에요. 키를 언제나 컬럼으로 두니 키의 dtype과 상관없이, 키가 하나든 여럿이든 결과의 모양이 같아요. [`value_counts`](/api/frame/value_counts/)의 결과도 같은 모양이에요.

키가 보통 컬럼이라서, 결과를 정렬하고, 거르고, 다른 표와 [합칠](/api/frame/merge/) 때 키도 다른 컬럼과 똑같이 다뤄요.

```python
>>> r.sort_values("qty", descending=True)
   fruit  qty
0  apple   10
2   pear    5
1   kiwi    2
>>> r[r["qty"] > 3]
   fruit  qty
0  apple   10
2   pear    5
```

## 값 컬럼 고르기

키가 아닌 컬럼은 **모두** 값 컬럼이 돼서 집계돼요. 그런데 집계할 수 없는 컬럼이 하나라도 있으면 에러가 나요. 예를 들어 문자열 컬럼은 더할 수 없어요.

```python
>>> sales = sd.frame.DataFrame({"fruit": ["apple", "pear", "apple", "kiwi", "pear", "apple"],
...                             "store": ["A", "A", "B", "B", "B", "A"],
...                             "qty": [3, 1, 5, 2, 4, 2],
...                             "price": [1.5, 2.0, 1.25, 0.5, 2.25, 1.5]})
>>> sales.groupby("fruit").sum()
Traceback (most recent call last):
    ...
TypeError: sum(): cannot compute sum of a string column
```

`store`는 문자열이라 합을 구할 수 없어요. 이럴 때는 `g["컬럼"]`이나 `g[["컬럼", ...]]`로 **집계할 컬럼만 골라요.** 고른 결과도 GroupBy라서, 그 위에 집계 메서드를 불러요. 결과에는 언제나 키 컬럼이 함께 들어가요.

```python
>>> sales.groupby("fruit")["qty"].sum()
   fruit  qty
0  apple   10
1   kiwi    2
2   pear    5
>>> sales.groupby("fruit")[["qty", "price"]].mean()
   fruit       qty     price
0  apple  3.333333  1.416667
1   kiwi  2.000000  0.500000
2   pear  2.500000  2.125000
```

`g["qty"]` 하나만 골라도 결과는 Series가 아니라 키 컬럼과 `qty` 컬럼이 있는 DataFrame이에요.

문자열 컬럼도 `max`, `min`, `first`처럼 크기 비교나 고르기만 하는 집계에는 그대로 쓸 수 있어요. 문자열의 크기는 글자의 코드 순서예요.

```python
>>> sales.groupby("fruit").max()
   fruit store  qty  price
0  apple     B    5   1.50
1   kiwi     B    2   0.50
2   pear     B    4   2.25
```

<Callout type="warn" title="max는 행 단위가 아니에요">
  위 결과의 `apple` 행은 "가장 많이 팔린 판매 기록 한 행"이 아니에요. 컬럼마다 따로 가장 큰 값을 고른 것이라, `store`의 `B`와 `price`의 `1.50`은 서로 다른 판매 기록에서 왔어요. 그룹마다 특정 기준으로 한 행을 통째로 고르려면 그 기준으로 [`sort_values`](/api/frame/sort_values/)를 한 뒤 키로 [`drop_duplicates`](/api/frame/duplicated/)를 하세요.
</Callout>

키 컬럼은 값 컬럼으로 고를 수 없어요.

```python
>>> sales.groupby("fruit")["fruit"]
Traceback (most recent call last):
    ...
ValueError: 'fruit' is a key column, not a value column
```

## 여러 컬럼으로 묶기

`by`에 컬럼 이름의 리스트를 주면 **값의 조합**이 같은 행끼리 묶어요. "지점마다, 과일마다" 판매량을 볼 수 있어요. 결과에는 키 컬럼이 `by`의 순서대로 앞에 와요.

```python
>>> sales.groupby(["store", "fruit"])["qty"].sum()
  store  fruit  qty
0     A  apple    5
1     A   pear    1
2     B  apple    5
3     B   kiwi    2
4     B   pear    4
```

지점 `A`의 `apple`은 0번 행과 5번 행(`3 + 2`), 지점 `B`의 `apple`은 2번 행 하나예요. 순서를 바꾸면 결과의 컬럼 순서와 행 순서도 바뀌어요.

```python
>>> sales.groupby(["fruit", "store"])["qty"].sum()
   fruit store  qty
0  apple     A    5
1  apple     B    5
2   kiwi     B    2
3   pear     A    1
4   pear     B    4
```

## 그룹의 순서: `sort`

기본값 `sort=True`면 그룹이 **키의 오름차순**으로 나와요. 순서 규칙은 [`sort_values`](/api/frame/sort_values/)와 같아요.

- 정수와 실수는 수의 순서예요. NaN은 +inf 뒤에 와요. `0.0`과 `-0.0`은 같은 키예요.
- 문자열은 글자의 코드 순서, bool은 `False`가 먼저예요.
- 키가 여러 개면 앞의 키부터 차례로 비교해요.
- NA 키 그룹(`dropna=False`일 때)은 맨 뒤에 와요.

`sort=False`면 그룹이 **데이터에 처음 나타난 순서**로 나와요. 원래 데이터의 순서에 뜻이 있을 때(예: 먼저 온 손님 순) 써요.

```python
>>> df.groupby("fruit", sort=False).sum()
   fruit  qty
0  apple   10
1   pear    5
2   kiwi    2
```

`apple`(0번 행), `pear`(1번 행), `kiwi`(3번 행) 순서로 처음 나왔어요.

## 키에 NA가 있을 때: `dropna`

키 값이 `NA`인 행은 "어느 그룹인지 모르는" 행이에요. 기본값 `dropna=True`면 이런 행을 **버리고** 묶어요. 키가 여러 개면 그중 하나라도 NA인 행을 버려요.

```python
>>> visits = sd.frame.DataFrame({"city": ["rome", None, "oslo", "rome", None],
...                              "temp": [21.0, 15.0, 8.5, 23.0, 11.0]})
>>> visits.groupby("city").mean()
   city  temp
0  oslo   8.5
1  rome  22.0
```

`dropna=False`면 NA 키 행들도 **하나의 그룹**이 돼요. NA끼리는 같은 키로 쳐요. `sort=True`면 이 그룹은 맨 뒤에 와요.

```python
>>> visits.groupby("city", dropna=False).mean()
   city  temp
0  oslo   8.5
1  rome  22.0
2  <NA>  13.0
```

`sort=False`와 함께 쓰면 NA 그룹도 처음 나타난 자리에 와요.

```python
>>> visits.groupby("city", dropna=False, sort=False).mean()
   city  temp
0  rome  22.0
1  <NA>  13.0
2  oslo   8.5
```

**NaN은 결측이 아니라 값이에요.** 그래서 `dropna=True`여도 버리지 않고, NaN끼리 한 그룹이 돼요. NaN 그룹은 +inf보다 뒤, NA 그룹보다는 앞에 와요. ([NA와 NaN](/api/frame/na/))

```python
>>> k = sd.frame.DataFrame({"k": [2.0, sd.nan, 1.0, None, sd.nan], "v": [1, 2, 3, 4, 5]})
>>> k.groupby("k").sum()
     k  v
0  1.0  3
1  2.0  1
2  NaN  7
>>> k.groupby("k", dropna=False).sum()
     k  v
0  1.0  3
1  2.0  1
2  NaN  7
3 <NA>  4
```

키가 여러 개일 때 `dropna=False`면 키마다 같은 규칙을 적용해요. NA는 그 키 자리에서 맨 뒤예요.

```python
>>> m = sd.frame.DataFrame({"a": ["x", None, "x", "y"], "b": [2, 1, None, 1], "v": [1, 2, 3, 4]})
>>> m.groupby(["a", "b"], dropna=False).sum()
      a     b  v
0     x     2  1
1     x  <NA>  3
2     y     1  4
3  <NA>     1  2
>>> m.groupby(["a", "b"]).sum()
   a  b  v
0  x  2  1
1  y  1  4
```

## 집계 메서드

GroupBy에서 부를 수 있는 집계는 아래가 전부예요. 인자와 규칙은 Series의 같은 이름 메서드와 같아요. 자세한 내용은 [그룹 집계](/api/frame/groupby-agg/)에 있어요.

| 메서드 | 그룹마다 구하는 것 |
|---|---|
| `sum()` | 합 |
| `mean()` | 평균 |
| `min()`, `max()` | 가장 작은 값, 가장 큰 값 |
| `std()`, `var()` | 표준편차, 분산 (`correction=0`) |
| `count()` | 값 컬럼마다 NA가 아닌 값의 개수 |
| `size()` | 그룹의 행 수 |
| `first()`, `last()` | NA가 아닌 처음, 마지막 값 |
| `agg(...)` | 위 집계를 이름으로 골라 한 번에 |

## 조심할 점

### 키는 컬럼 이름으로만

`by`에는 컬럼 이름(또는 그 리스트·튜플)만 줘요. Series나 함수로는 묶을 수 없어요. 다른 값으로 묶고 싶으면 먼저 그 값을 컬럼으로 넣은 뒤 그 이름으로 묶어요. ([대입과 복사](/api/frame/assign/))

```python
>>> sales.groupby(sales["fruit"])
Traceback (most recent call last):
    ...
TypeError: groupby(): 'by' must be a column name or a list of them, not Series
>>> sales["big"] = sales["qty"] >= 3
>>> sales.groupby("big")["qty"].sum()
     big  qty
0  False    5
1   True   12
```

`by`는 이름 없이 첫 인자로, `sort`와 `dropna`는 이름을 붙여서 줘요. `sort`, `dropna`에는 `True`나 `False`만 써요.

```python
>>> sales.groupby(by="fruit")
Traceback (most recent call last):
    ...
TypeError: DataFrame.groupby() got some positional-only arguments passed as keyword arguments: 'by'
>>> sales.groupby("fruit", sort=1)
Traceback (most recent call last):
    ...
TypeError: groupby(): 'sort' must be True or False, not int
```

없는 컬럼은 `KeyError`, 빈 리스트는 `ValueError`예요.

```python
>>> sales.groupby("color")
Traceback (most recent call last):
    ...
KeyError: "groupby(): no column 'color'"
>>> sales.groupby([])
Traceback (most recent call last):
    ...
ValueError: groupby(): 'by' must name at least one column
```

### GroupBy에는 집계만 있어요

GroupBy로는 위 표의 집계만 할 수 있어요. 그룹을 하나씩 꺼내 보는 반복, 임의의 Python 함수를 적용하는 기능, 그룹마다 앞의 몇 행을 고르는 기능은 없어요. 그룹 하나를 보고 싶으면 [마스크](/api/frame/mask/)로 그 행들을 골라요.

```python
>>> sales[sales["fruit"] == "pear"]
  fruit store  qty  price    big
1  pear     A    1   2.00  False
4  pear     B    4   2.25   True
```

### GroupBy는 만든 순간의 표를 봐요

`g = df.groupby(...)`를 만든 뒤 `df`를 고쳐도, `g`의 집계는 **`g`를 만든 순간의 값**으로 계산해요. 고친 값으로 집계하려면 `groupby`를 다시 불러요. 대입은 고친 쪽만 바꾸고 이미 만든 객체에는 번지지 않기 때문이에요(Copy-on-Write, [대입과 복사](/api/frame/assign/)).

```python
>>> g = df.groupby("fruit")
>>> df["qty"] = [0, 0, 0, 0, 0, 0]
>>> g.sum()
   fruit  qty
0  apple   10
1   kiwi    2
2   pear    5
>>> df.groupby("fruit").sum()
   fruit  qty
0  apple    0
1   kiwi    0
2   pear    0
```

## 비슷한 함수와의 차이

| 하고 싶은 일 | 쓸 것 | 다른 점 |
|---|---|---|
| 그룹마다 행 수 | `groupby(...).size()` | 키의 순서(기본은 오름차순)로 나와요. 결과 컬럼 이름은 `size`예요. |
| 값마다 개수, 많은 것부터 | [`value_counts`](/api/frame/value_counts/) | 개수의 내림차순으로 나와요. 결과 컬럼 이름은 `counts`예요. |
| 어떤 키 값이 있는지만 | [`unique_values`](/api/frame/unique_values/) | 값만 정렬해서 줘요. 집계는 없어요. |
| 그룹마다 첫 행 통째로 | [`drop_duplicates`](/api/frame/duplicated/) | 키가 처음 나온 행을 모든 컬럼 그대로 남겨요. |
| 행을 키 순서로 늘어놓기 | [`sort_values`](/api/frame/sort_values/) | 행을 줄이지 않고 순서만 바꿔요. |
| 전체를 하나로 요약 | [`df.sum()`](/api/frame/sum-mean/) 등 | 그룹 없이 표 전체를 1행으로 요약해요. |

`size()`와 `value_counts`는 같은 개수를 주지만 순서와 컬럼 이름이 달라요.

```python
>>> fruits = sd.frame.DataFrame({"fruit": ["apple", "pear", "apple", "kiwi", "pear", "apple"]})
>>> fruits.groupby("fruit").size()
   fruit  size
0  apple     3
1   kiwi     1
2   pear     2
>>> fruits.value_counts("fruit")
   fruit  counts
0  apple       3
1   pear       2
2   kiwi       1
```

## pandas를 아는 분께

- **키는 결과의 보통 컬럼이 되고, 라벨은 RangeIndex예요.** pandas의 `as_index=False`와 비슷한 모양이 언제나 나와요. `as_index` 인자는 없어요. 키가 float나 bool이어도 같은 모양이에요.
- **`dropna=True`는 NA만 버려요.** pandas는 NaN도 결측으로 보고 버리고, `dropna=False`면 NaN과 `None`을 한 그룹으로 합쳐요. 여기서는 NaN 그룹과 NA 그룹이 따로 있어요.
- `by`는 컬럼 이름이나 그 리스트만 받아요. Series, 함수, `level`로 묶기와 `Series.groupby`는 없어요. `by`는 위치로만 받아요.
- 그룹 반복(`for key, part in g`), `apply`, `transform`, `filter`, `head`, `median`, `nunique` 같은 메서드는 없어요.
- 문자열 컬럼의 `sum`은 `TypeError`예요. pandas는 문자열을 이어 붙여요.
- `observed`, `group_keys`는 없어요.
