## 한눈에 보기

비교 연산자는 Series의 행마다 "이 조건이 맞는가"를 묻고, 그 답(`True` 또는 `False`)을 같은 라벨에 적은 **bool Series**를 돌려줘요. 엑셀에서 `=B2>30` 같은 수식을 열 전체에 채운 것과 같아요.

도시별 낮 기온에서 30도가 넘는 곳을 찾아요. 부산은 관측값이 빠져 있어요.

```python
>>> import stardust as sd
>>> df = sd.frame.DataFrame({
...     "city": ["Seoul", "Daegu", "Busan", "Incheon"],
...     "temp": [28.5, 31.0, None, 25.0],
... })
>>> df
      city  temp
0    Seoul  28.5
1    Daegu  31.0
2    Busan  <NA>
3  Incheon  25.0
>>> hot = df["temp"] > 30
>>> hot
0    False
1     True
2     <NA>
3    False
Name: temp, dtype: bool
```

이렇게 만든 bool Series는 주로 조건에 맞는 행만 골라낼 때 써요. DataFrame에 대괄호로 넣으면 `True`인 행만 남아요. `NA`인 행은 "맞는지 모름"이라 버려요. 자세한 것은 [조건으로 행 거르기](/api/frame/mask/)에 있어요.

```python
>>> df[hot]
    city  temp
1  Daegu  31.0
```

비교는 여섯 가지예요.

| 연산자 | 참이 되는 때 |
|:---:|---|
| `x == y` | 두 값이 같을 때 |
| `x != y` | 두 값이 다를 때 |
| `x < y` | `x`가 더 작을 때 |
| `x <= y` | `x`가 작거나 같을 때 |
| `x > y` | `x`가 더 클 때 |
| `x >= y` | `x`가 크거나 같을 때 |

`eq`, `lt` 같은 메서드는 없어요. 비교는 연산자로만 해요.

## 무엇과 무엇을 비교할 수 있나요

피연산자의 조합은 [산술 연산](/api/frame/arithmetic/)과 같아요.

| 왼쪽 | 오른쪽 | 결과 |
|---|---|---|
| Series | Series | bool Series. 행 라벨로 맞춰서 비교해요 |
| Series | 스칼라 | bool Series |
| 스칼라 | Series | bool Series |
| DataFrame | 스칼라 | bool DataFrame |
| 스칼라 | DataFrame | bool DataFrame |
| DataFrame | DataFrame | bool DataFrame. 컬럼은 이름으로, 행은 라벨로 맞춰요 |
| DataFrame | Series | `TypeError` |
| Series, DataFrame | list, tuple, `None`, 배열 | `TypeError` (`==`, `!=`도) |

스칼라는 왼쪽에 와도 돼요. `1 < s`는 `s > 1`과 같아요.

```python
>>> temp = df["temp"]
>>> 30 <= temp
0    False
1     True
2     <NA>
3    False
Name: temp, dtype: bool
```

Series끼리 비교할 때는 같은 라벨의 값끼리 비교해요. 아래 두 Series는 순서가 다르지만 `b`는 `b`끼리, `a`는 `a`끼리 비교해서 모두 같아요. 라벨을 맞추는 규칙은 [라벨과 정렬](/api/frame/alignment/)에 있어요.

```python
>>> left = sd.frame.Series([3, 1], index=["b", "a"])
>>> right = sd.frame.Series([1, 3], index=["a", "b"])
>>> left == right
b    True
a    True
dtype: bool
```

DataFrame은 컬럼마다 비교해서 같은 모양의 bool DataFrame을 돌려줘요.

```python
>>> scores = sd.frame.DataFrame({"math": [90, 55], "eng": [70.0, None]})
>>> scores >= 60
    math   eng
0   True  True
1  False  <NA>
```

## 결과는 bool이고, `NA`인 행은 `NA`예요

비교의 결과는 언제나 bool이에요. 어느 한쪽이 `NA`인 행은 결과도 `NA`예요. 모르는 값과 비교하면 답도 모르기 때문이에요.

이 규칙 때문에 `NA`를 `==`로 찾을 수는 없어요. `s == NA`는 모든 행이 `NA`예요. `NA`끼리의 비교도 `NA`예요. 결측값인지는 [`isna`](/api/frame/isna/)로 확인하고, 값 하나가 `NA`인지는 `x is sd.frame.NA`로 확인해요.

```python
>>> temp == sd.frame.NA
0    <NA>
1    <NA>
2    <NA>
3    <NA>
Name: temp, dtype: bool
>>> sd.frame.NA == sd.frame.NA
<NA>
>>> temp.isna()
0    False
1    False
2     True
3    False
Name: temp, dtype: bool
```

`NA`가 왜 자기 자신과도 같지 않은지는 [NA와 NaN](/api/frame/na/)에 자세히 있어요.

## 다른 dtype끼리의 비교

### 정수와 실수는 실수로 바꿔서 비교해요

int64와 float64를 비교하면 int를 float64로 바꾼 뒤 비교해요. 배열 영역과 같아요. 2⁵³(약 9 × 10¹⁵)을 넘는 정수는 float64로 바꿀 때 반올림되므로, 실제로는 다른 두 수가 같다고 나올 수 있어요.

```python
>>> sd.frame.Series([2, 3]) == 2.0
0     True
1    False
dtype: bool
>>> sd.frame.Series([2**53 + 1]) == 2.0**53
0    True
dtype: bool
```

### bool은 숫자로 비교해요

bool끼리는 `False < True`예요. bool과 숫자를 비교하면 bool을 int64(0과 1)로 올려서 비교해요. 산술에서 bool이 int64로 계산되는 것과 같은 승격이에요.

```python
>>> flag = sd.frame.Series([True, False, None])
>>> flag == 1
0     True
1    False
2     <NA>
dtype: bool
>>> flag < 0.5
0    False
1     True
2     <NA>
dtype: bool
```

### string은 글자 코드 순서예요

string끼리는 사전처럼 앞 글자부터 비교하는데, 글자의 순서는 유니코드 코드포인트(글자마다 붙은 번호) 순서예요. Python의 문자열 비교와 같아요. 이 순서에서는 대문자가 소문자보다 앞이라서 `"Banana" < "apple"`이에요.

```python
>>> fruit = sd.frame.Series(["apple", "Banana", "cherry"])
>>> fruit < "b"
0     True
1     True
2    False
dtype: bool
```

### 비교할 수 없는 dtype은 `==`도 에러예요

string과 숫자, string과 bool은 비교할 수 없어요. `<`뿐 아니라 `==`와 `!=`도 `TypeError`예요. `"1"`과 `1`처럼 겉보기에 같은 값이어도 그래요.

```python
>>> sd.frame.Series(["1", "2"]) == 1
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for ==: string and int64 (these dtypes cannot be compared)
>>> flag == "True"
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for ==: bool and string (these dtypes cannot be compared)
```

덕분에 CSV에서 숫자가 문자열로 읽힌 줄 모르고 `== 1`로 걸러도, 모든 행이 `False`가 되어 결과가 조용히 비는 일 없이 그 자리에서 에러가 나요. 값을 숫자로 바꾸려면 [`astype`](/api/frame/astype/)을 써요.

```python
>>> sd.frame.Series(["1", "2"]).astype("int64") == 1
0     True
1    False
dtype: bool
```

dtype 조합별로 보면 이래요.

| 왼쪽 \ 오른쪽 | bool | int64 | float64 | string |
|---|:---:|:---:|:---:|:---:|
| **bool** | bool끼리 | int64로 | float64로 | `TypeError` |
| **int64** | int64로 | int64끼리 | float64로 | `TypeError` |
| **float64** | float64로 | float64로 | float64끼리 | `TypeError` |
| **string** | `TypeError` | `TypeError` | `TypeError` | 코드포인트 순서 |

### 받지 않는 피연산자도 `==`가 에러예요

list, tuple, `None`, numpy 배열, stardust 배열과 비교하면 `==`, `!=`도 `TypeError`예요. Python은 보통 모르는 것끼리 `==`하면 조용히 `False`를 돌려주는데, 그러면 `s == None`처럼 결측값을 찾으려던 코드가 아무 말 없이 틀린 답을 내요. 그래서 `<`와 똑같이 에러를 내요.

```python
>>> temp == None
Traceback (most recent call last):
    ...
TypeError: '==' not supported between instances of 'Series' and 'NoneType'
>>> sd.frame.Series([1, 2]) == [1, 2]
Traceback (most recent call last):
    ...
TypeError: '==' not supported between instances of 'Series' and 'list'
```

Series에는 두 Series 전체가 같은지(값, 라벨, dtype)를 한 번에 확인하는 메서드가 없어요. 라벨이 같은지는 `s.index.equals(t.index)`로 확인해요. Index는 `==`로 비교할 수 없어요([Index와 RangeIndex](/api/frame/index/)).

## NaN은 무엇과도 같지 않아요

NaN("숫자가 아님")은 결측값이 아니라 평범한 실수 값이고, 비교는 실수 계산의 약속(IEEE 754)을 따라요. `NaN == NaN`은 `False`, `NaN != NaN`은 `True`예요. 크기 비교도 모두 `False`예요. `NA`와 달리 결과가 `NA`가 되지 않아요.

```python
>>> v = sd.frame.Series([1.0, float("nan"), None])
>>> v == v
0    True
1   False
2    <NA>
dtype: bool
>>> v != v
0    False
1     True
2     <NA>
dtype: bool
```

그래서 NaN도 `==`로 찾을 수 없어요. NaN은 [`isnan`](/api/frame/isna/)으로 찾아요.

## 조심할 점

### `if s == 1:`은 쓸 수 없어요

비교의 결과는 행마다 답이 있는 Series라서, 하나의 참·거짓으로 바꿀 수 없어요. `if`나 `and`, `or`, `not`에 넣으면 `TypeError`예요. 행이 몇 개인지 세려면 `.sum()`을 쓰세요. bool은 더하면 `True`의 개수예요.

```python
>>> if temp > 30:
...     print("hot")
Traceback (most recent call last):
    ...
TypeError: the truth value of a Series is ambiguous
>>> (temp > 30).sum()
1
```

### `20 < s < 30`처럼 이어 쓸 수 없어요

Python은 `a < b < c`를 `(a < b) and (b < c)`로 바꿔서 실행하므로, 위와 같은 이유로 `TypeError`예요. 두 비교를 괄호로 감싸고 `&`로 묶어요([논리와 비트 연산](/api/frame/logical/)).

```python
>>> 20 < temp < 30
Traceback (most recent call last):
    ...
TypeError: the truth value of a Series is ambiguous
>>> (20 < temp) & (temp < 30)
0     True
1    False
2     <NA>
3     True
Name: temp, dtype: bool
```

### 실수는 `==`로 비교하지 마세요

실수 계산은 마지막 자리가 어긋날 수 있어서, `0.1 + 0.2 == 0.3`이 `False`예요. 계산한 실수는 차이가 충분히 작은지로 비교하세요.

```python
>>> x = sd.frame.Series([0.1]) + 0.2
>>> x == 0.3
0    False
dtype: bool
>>> abs(x - 0.3) < 1e-9
0    True
dtype: bool
```

## 배열의 비교와 다른 점

데이터프레임의 비교는 배열 영역의 [비교](/api/array/comparison/)와 승격 규칙(int와 float는 float64로, bool은 int64로), NaN 규칙, 받지 않는 피연산자의 `TypeError`까지 같아요. 다른 곳은 이래요.

| | 배열 | 데이터프레임 |
|---|---|---|
| 짝짓는 방법 | 위치 (브로드캐스팅) | 라벨 (정렬) |
| 결측값 | 없어요 | `NA`와 비교한 행은 `NA` |
| string | 없어요 | 코드포인트 순서. 숫자, bool과는 `TypeError` |
| 함수 이름 | `sd.equal`, `sd.less` 등이 있어요 | 연산자로만 비교해요 |

## pandas를 아는 분께

- 라벨이 다른 두 Series를 비교하면 라벨로 맞춰서 비교해요. pandas는 `Can only compare identically-labeled Series objects`라는 `ValueError`예요(산술은 맞춰 주는데 비교는 하지 않아요).
- string과 숫자를 `==`로 비교하면 `TypeError`예요. pandas는 모두 `False`예요.
- `s == None`, `s == [1, 2]`는 `TypeError`예요. pandas는 `None`과 비교하면 모두 `False`, 리스트와는 위치대로 비교해요.
- 결측값이 있는 행은 결과가 `NA`이고 dtype은 bool이에요. pandas의 기본 dtype에서는 결측값(NaN)과의 비교가 `!=`만 `True`이고 나머지는 `False`예요.
- `eq`, `ne`, `lt`, `le`, `gt`, `ge` 메서드가 없어요.
- DataFrame과 Series의 비교가 없어요.
