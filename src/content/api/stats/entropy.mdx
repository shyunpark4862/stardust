## 한눈에 보기

**엔트로피**는 "결과를 미리 알기가 얼마나 어려운가"를 재는 값이에요. 앞뒤가 반반인 동전은 결과를 전혀 짐작할 수 없고, 앞면이 90% 나오는 동전은 대개 앞면이라 짐작하기 쉬워요. 언제나 앞면만 나오는 동전은 놀랄 일이 하나도 없어요.

```python
>>> import stardust as sd
>>> sd.stats.entropy([0.5, 0.5], base=2)
1.0
>>> sd.stats.entropy([0.9, 0.1], base=2)
0.46899559358928117
>>> sd.stats.entropy([1.0, 0.0], base=2)
0.0
```

`base=2`로 재면 단위가 **비트**예요. 공정한 동전 한 번은 정확히 1비트, 곧 "예/아니요 질문 하나"만큼의 불확실성이에요.

## 엔트로피는 무엇인가요

범주가 $k$개이고 각 범주의 확률이 $p_1, \dots, p_k$인 분포의 섀넌 엔트로피는

$$
H(p) = -\sum_{i} p_i \log p_i
$$

예요. $p_i = 0$인 항은 0으로 쳐요. 몇 가지 성질이 있어요.

- 언제나 0 이상이에요. 한 범주의 확률이 1이면(결과가 정해져 있으면) 0이에요.
- 범주가 $k$개일 때 가장 큰 값은 모든 확률이 같을 때의 $\log k$예요. 네 범주가 고르면 2비트예요.
- 한 범주로 쏠릴수록 작아져요.

```python
>>> sd.stats.entropy([0.25, 0.25, 0.25, 0.25], base=2)
2.0
>>> sd.stats.entropy([0.7, 0.1, 0.1, 0.1], base=2)
1.3567796494470397
```

### `base`: 단위 고르기

기본값 `base=None`은 자연로그를 써요. 단위는 **나트**(nat)예요. `base=2`면 비트, `base=10`이면 하틀리(자릿수)예요. 단위만 다르고 비율은 같아서, 나트 값을 $\ln 2$로 나누면 비트 값이에요.

```python
>>> sd.stats.entropy([0.5, 0.5])
0.6931471805599453
>>> sd.log(2.0)
0.6931471805599453
```

`base`는 양수여야 해요. 수가 아닌 값(문자열 등)은 `TypeError`예요.

```python
>>> sd.stats.entropy([0.5, 0.5], base=0)
Traceback (most recent call last):
    ...
ValueError: entropy(): 'base' must be a positive number or None
>>> sd.stats.entropy([0.5, 0.5], base='e')
Traceback (most recent call last):
    ...
TypeError: entropy(): 'base' must be a positive number or None, not str
```

`base=1`은 양수라 받지만, 결과를 $\ln 1 = 0$으로 나누는 셈이라 inf예요. 엔트로피가 0이면 0/0이라 NaN이에요.

```python
>>> sd.stats.entropy([0.5, 0.5], base=1)
inf
>>> sd.stats.entropy([1.0, 0.0], base=1)
nan
```

## 개수를 넣어도 돼요

`pk`는 합이 1이 아니어도 돼요. `entropy`가 먼저 **합으로 나눠서** 확률로 만들기 때문이에요. 그래서 범주마다 센 횟수를 그대로 넣을 수 있어요.

```python
>>> votes = sd.asarray([30.0, 10.0, 10.0, 10.0])
>>> sd.stats.entropy(votes, base=2)
1.7924812503605778
>>> sd.stats.entropy([3, 1, 1, 1], base=2)
1.7924812503605778
```

비율이 같으면 엔트로피도 같아요.

<Callout type="warn" title="데이터 값을 그대로 넣지 마세요">
`entropy`는 **분포**(범주마다의 확률이나 횟수)를 받아요. 측정값 목록 `[3.2, 5.1, 4.8, …]`을 그대로 넣으면 그 값들을 "횟수"로 보고 계산해서 뜻이 없는 값이 나와요. 값이 범주라면 먼저 [`sd.unique_counts`](/api/array/unique/)로 세어서 횟수를 넣고, 연속적인 측정값의 엔트로피를 어림하려면 [`differential_entropy`](/api/stats/differential-entropy/)를 쓰세요.

```python
>>> colors = sd.asarray([1, 2, 2, 3, 1, 2, 2, 2])
>>> sd.stats.entropy(sd.unique_counts(colors).counts, base=2)
1.2987949406953987
```
</Callout>

## `qk`: 두 분포의 차이(KL 발산)

두 번째 분포 `qk`를 주면 엔트로피 대신 **KL 발산**(Kullback–Leibler divergence, 상대 엔트로피)을 구해요.

$$
D(p \,\|\, q) = \sum_i p_i \log \frac{p_i}{q_i}
$$

"실제 분포가 $p$인데 $q$라고 잘못 믿었을 때 생기는 손해"로 읽을 수 있어요. 두 분포가 같으면 0이고, 다를수록 커져요. 언제나 0 이상이에요.

```python
>>> p = sd.asarray([0.5, 0.5])
>>> q = sd.asarray([0.9, 0.1])
>>> sd.stats.entropy(p, q)
0.5108256237659906
>>> sd.stats.entropy(p, p)
0.0
```

**순서가 중요해요.** $D(p\,\|\,q)$와 $D(q\,\|\,p)$는 다른 값이에요. 그래서 KL 발산은 "거리"가 아니에요.

```python
>>> sd.stats.entropy(q, p)
0.3680642071684971
```

$p_i > 0$인데 $q_i = 0$인 범주가 있으면 $p$에서 일어나는 일을 $q$는 불가능하다고 본 셈이라 `inf`예요. 반대로 $p_i = 0$인 범주는 더하지 않아요.

```python
>>> sd.stats.entropy([0.5, 0.5], [1.0, 0.0])
inf
>>> sd.stats.entropy([1.0, 0.0], [0.5, 0.5])
0.6931471805599453
```

`qk`도 합으로 나눠서 확률로 만들어요. `qk`는 **위치로만** 줘요. `qk=`로 이름을 붙이면 `TypeError`예요.

```python
>>> sd.stats.entropy(p, qk=q)
Traceback (most recent call last):
    ...
TypeError: entropy() got some positional-only arguments passed as keyword arguments: 'qk'
```

### 교차 엔트로피

$p$의 엔트로피와 KL 발산을 더하면 **교차 엔트로피** $-\sum_i p_i \log q_i$예요. 분류 모델의 손실로 많이 쓰는 값이에요.

```python
>>> sd.stats.entropy(p, base=2) + sd.stats.entropy(p, q, base=2)
1.736965594166206
>>> -(0.5 * sd.log2(0.9) + 0.5 * sd.log2(0.1))
1.736965594166206
```

## `axis`: 여러 분포를 한꺼번에

기본값 `axis=None`은 배열의 **모든 원소를 하나의 분포**로 봐요(`sd.sum`, `sd.mean`과 같은 규칙이에요). 2차원 표를 넣으면 칸 전체를 하나의 결합 분포로 보고 엔트로피를 구해요.

```python
>>> table = sd.asarray([[10.0, 10.0],
...                     [ 0.0, 20.0]])
>>> sd.stats.entropy(table, base=2)
1.5
```

행마다 다른 분포라면 `axis=1`을 줘요. 행마다 합으로 나누고, 행마다 엔트로피가 하나씩 나와요. 여러 축에 걸친 분포는 `axis=(1, 2)`나 `axis=[1, 2]`처럼 tuple이나 리스트로 줘요.

```python
>>> rows = sd.asarray([[0.5, 0.5],
...                    [0.9, 0.1],
...                    [1.0, 0.0]])
>>> sd.stats.entropy(rows, axis=1, base=2)
array([                1.0, 0.46899559358928117,                 0.0], dtype=float64)
```

<Callout type="warn" title="2차원 입력은 axis를 꼭 확인하세요">
여러 분포를 행으로 쌓아 넣고 `axis`를 빠뜨리면, 모든 행을 한 분포로 섞은 엔트로피가 나와요. 에러가 나지 않으니 결과가 숫자 하나로 나오면 의심해 보세요.
</Callout>

`pk`와 `qk`는 서로 브로드캐스트돼요. 여러 분포를 같은 기준 분포 하나와 비교할 수 있어요.

```python
>>> sd.stats.entropy(sd.asarray([[0.5, 0.5], [0.9, 0.1]]), [0.5, 0.5], axis=1)
array([               0.0, 0.3680642071684971], dtype=float64)
```

## NaN이 있으면: `nan_policy`

```python
>>> sd.stats.entropy([0.5, sd.nan, 0.5])
nan
>>> sd.stats.entropy([0.5, sd.nan, 0.5], nan_policy='omit')
0.6931471805599453
```

`'omit'`은 NaN인 범주를 없는 범주처럼 빼고 나머지를 다시 합으로 나눠요. `qk`가 있으면 `pk`나 `qk` 중 **어느 한쪽이라도** NaN인 범주를 양쪽에서 함께 빼요. `'raise'`는 NaN이 있으면 `ValueError`예요.

```python
>>> sd.stats.entropy([0.25, 0.25, 0.5], [0.5, sd.nan, 0.5], nan_policy='omit')
0.056633012265132426
```

## 조심할 점

### 확률은 0 이상이어야 해요

음수를 넣어도 에러는 나지 않지만, 합으로 나눈 뒤 음수인 항이 있으면 결과가 `-inf`예요. 결과가 음수나 `-inf`로 나오면 입력을 확인하세요.

```python
>>> sd.stats.entropy([-1.0, 2.0])
-inf
```

### 모두 0이거나 비어 있으면

합이 0이면 0을 0으로 나누게 돼서 NaN이에요. 빈 입력은 더할 항이 없어서 0이에요.

```python
>>> sd.stats.entropy([0.0, 0.0])
nan
>>> sd.stats.entropy([])
0.0
```

## 분포 객체의 `entropy()`와 다른 점

`sd.stats.Poisson`, `sd.stats.Normal` 같은 분포 객체에도 `X.entropy()`가 있어요.

| | `sd.stats.entropy(pk)` | `X.entropy()` |
|---|---|---|
| 입력 | 확률(또는 개수)을 담은 배열 | 없음(분포의 매개변수로 정해져요) |
| 무엇의 엔트로피 | 넘겨준 이산 분포 | 그 분포 자체(이산이면 엔트로피, 연속이면 미분 엔트로피) |

이산 분포라면 확률질량을 늘어놓아 `entropy`에 넣은 값과 `X.entropy()`가 같아요(꼬리를 충분히 넣으면).

```python
>>> P = sd.stats.Poisson(mu=3.0)
>>> P.entropy()
1.9314701981485687
>>> sd.stats.entropy(P.pmf(sd.arange(0, 100).astype(sd.float64)))
1.931470198148569
```

연속 분포의 `X.entropy()`는 밀도로 정의하는 **미분 엔트로피**라서 `entropy`와 다른 양이에요. 연속적인 데이터에서 그 값을 어림하는 함수는 [`differential_entropy`](/api/stats/differential-entropy/)예요.

## 비슷한 함수와의 차이

| 쓸 것 | `entropy`와 다른 점 |
|---|---|
| [`sd.special.entr`](/api/special/entr/) | 한 항 $-x\log x$를 원소별로 계산해요. 합으로 나누지도, 더하지도 않아요. |
| [`sd.special.rel_entr`](/api/special/entr/) | KL 발산의 한 항 $x\log(x/y)$를 원소별로 계산해요. |
| [`differential_entropy`](/api/stats/differential-entropy/) | 연속적인 표본에서 미분 엔트로피를 어림해요. |

`entropy`는 `entr`, `rel_entr`의 결과를 축을 따라 더한 것과 같아요(확률을 합으로 나눈 뒤).

```python
>>> sd.sum(sd.special.rel_entr(p, q))
0.5108256237659906
```

## scipy를 아는 분께

- `axis`의 기본값이 `None`(전체)이에요. scipy는 `axis=0`이라 2차원 입력을 열마다 계산해요.
- `qk`는 위치로만, `base`부터는 이름으로만 받아요.
- 합으로 나누는 것, `base`(`base=1`의 inf 포함), `inf`·`-inf`·NaN이 되는 경우, `nan_policy`의 동작은 scipy와 같아요.
- 결과는 numpy 스칼라가 아니라 Python `float`예요.
