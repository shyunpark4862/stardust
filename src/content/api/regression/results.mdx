## 한눈에 보기

회귀 함수는 계산한 값을 모두 **결과 객체** 하나에 담아 돌려줘요. 이 페이지는 [`ols`](/api/regression/ols/)의 결과 `OLSResult`를 예로 들어 필드를 하나씩 읽어요. 같은 이름의 필드는 다른 결과 객체에서도 같은 뜻이에요. 어느 결과에 어떤 필드가 있는지는 [마지막 표](#다른-결과-객체)에 있어요.

예로 쓸 데이터는 어느 아이스크림 가게의 30일치 기록이에요. 그날의 기온(`temp`, ℃), 강수량(`rain`, mm), 매출(`sales`)이 있어요. 매출은 기온에 따라 오르고 비와는 상관이 없도록 만들었어요. 참 모형은 매출 = 20 + 3 × 기온 + 오차(표준편차 8)예요.

```python
>>> rng = sd.random.default_rng(42)
>>> n = 30
>>> temp = sd.stats.Uniform(a=15.0, b=35.0).sample(n, rng=rng)
>>> rain = sd.stats.Uniform(a=0.0, b=10.0).sample(n, rng=rng)
>>> noise = sd.stats.Normal(sigma=8.0).sample(n, rng=rng)
>>> sales = 20.0 + 3.0 * temp + noise
>>> df = sd.frame.DataFrame({'temp': temp, 'rain': rain, 'sales': sales})
>>> r = sd.regression.ols(df['sales'], df[['temp', 'rain']])
>>> r
OLSResult(nobs=30, rank=3, rsquared=0.816592, params=[  19.708601395933567    2.997447946508792 -0.03789720249661012])
```

## 계수: params

`params`는 계수의 배열이에요. 절편이 있으면 `params[0]`이 절편이고, 그 뒤가 `X`의 열 순서대로예요. 각 자리의 이름은 `param_names`에 있어요.

```python
>>> r.param_names
['const', 'temp', 'rain']
>>> r.params
array([  19.708601395933567,    2.997447946508792, -0.03789720249661012], dtype=float64)
```

기온의 계수 3.00은 "비가 같은 날끼리 보면, 기온이 1℃ 오를 때 매출이 평균 3.00 오른다"는 뜻이에요. 설명변수가 여럿이면 각 계수는 다른 변수를 그대로 둘 때 그 변수 하나의 효과예요. 참값 3에 아주 가깝고, 강수량의 계수 −0.04도 참값 0에 가까워요.

계수가 정확히 0이면 언제나 `0.0`(+0.0)이에요. 계산의 반올림이 남긴 부호는 데이터에 뜻이 없어서 −0.0으로 내지 않아요.

```python
>>> sd.regression.ols([5.0, 1, 1, 5], [1.0, 2, 3, 4]).params
array([3.0, 0.0], dtype=float64)
```

## 표준오차: bse

같은 가게에서 다른 30일을 골라 다시 맞추면 계수는 조금씩 달라져요. 오차가 날마다 우연히 다르기 때문이에요. **표준오차**(`bse`, standard error)는 그 흔들림의 크기, 곧 "다시 모으면 계수가 대략 이 정도 흔들린다"는 어림이에요. 계수의 표준편차를 데이터 한 벌에서 어림한 값이에요.

```python
>>> r.bse
array([ 7.377396007961325, 0.2734514180132633, 0.4095086489870254], dtype=float64)
```

정말 그런지 실험해 볼 수 있어요. 기온과 강수량은 그대로 두고 오차만 새로 뽑아 매출을 2,000벌 만든 다음, [배치](/api/regression/basics/#배치-회귀-여러-개를-한-번에)로 한 번에 맞춰요.

```python
>>> X = sd.stack([temp, rain], axis=1)
>>> E = sd.stats.Normal(sigma=8.0).sample((2000, n), rng=rng)
>>> many = sd.regression.ols(20.0 + 3.0 * temp + E, X)
>>> slopes = many.params[:, 1]
>>> round(float(sd.mean(slopes)), 3), round(float(sd.std(slopes)), 3)
(2.99, 0.282)
```

2,000개의 기온 계수는 참값 3 둘레에 퍼져 있고, 그 표준편차는 0.282예요. 참 오차의 표준편차 8을 알 때 계산되는 이론값 0.281, 데이터 한 벌만 보고 어림한 표준오차 0.273과 거의 같아요. 표준오차는 이 실험을 하지 않고도 퍼짐을 알려 주는 값이에요.

표준오차는 데이터가 많을수록, 설명변수가 넓게 퍼져 있을수록, 오차가 작을수록 작아져요. 설명변수끼리 비슷하면 커져요([겹친 열](/api/regression/collinearity/)).

<Callout type="note" title="표준오차가 기대는 가정">

기본 표준오차(`cov_type='nonrobust'`)는 오차가 관측마다 같은 크기로, 서로 독립으로 흔들린다고 보고 계산해요. 오차의 크기가 관측마다 다르거나 시간·묶음 안에서 이어지면 이 값은 실제 흔들림보다 작게 나올 수 있어요. 그때 쓰는 다른 표준오차는 [표준오차의 종류](/api/regression/covariance/)에 있어요. 계수 자체는 어느 쪽이든 같아요.

</Callout>

## t값과 p값

**t값**(`tvalues`)은 계수를 표준오차로 나눈 값이에요. 계수가 0에서 표준오차 몇 개만큼 떨어져 있는지를 재요.

```python
>>> r.tvalues
array([   2.671484813159685,   10.961537403193887, -0.09254310645295023], dtype=float64)
>>> bool(sd.all(r.tvalues == r.params / r.bse))
True
```

**p값**(`pvalues`)은 "참 계수가 0이라면, 우연만으로 이만큼(또는 더) 0에서 먼 t값이 나올 확률"이에요. 작을수록 "이 변수는 효과가 없다"고 보기 어려워요. 흔히 0.05를 기준으로 써요.

```python
>>> r.pvalues
array([ 0.012640757146940481, 1.911539897240063e-11,    0.9269498031232929], dtype=float64)
```

- 기온의 p값은 $1.9 \times 10^{-11}$이에요. 효과가 없는데 t값이 11이나 나올 일은 거의 없어요.
- 강수량의 p값은 0.93이에요. 계수 −0.04는 우연으로 충분히 설명돼요. 실제로 강수량은 매출과 상관이 없게 만든 데이터예요.

p값이 크다는 것은 "효과가 없다는 증거"가 아니라 "효과가 있다고 말할 근거가 부족하다"는 뜻이에요. 데이터가 적으면 진짜 효과도 p값이 클 수 있어요.

p값은 자유도 `df_resid_inference`인 [t 분포](/api/stats/student-t/)의 두 꼬리 확률 $2 \cdot P(T > |t|)$로 계산해요. 위꼬리 확률을 직접 계산하므로 아주 작은 p값도 앞자리가 맞아요.

```python
>>> T = sd.stats.StudentT(df=r.df_resid_inference)
>>> 2 * T.ccdf(abs(r.tvalues[2])) == r.pvalues[2]
True
```

## 신뢰구간: conf_int

`conf_int(*, alpha=0.05)`는 계수마다 **신뢰구간**의 두 끝을 돌려줘요. 모양은 (k, 2)이고, 각 행이 [아래 끝, 위 끝]이에요. 구간은 계수 ± q × 표준오차이고, q는 t 분포의 위쪽 alpha/2 분위수(여기서는 약 2.05)예요.

```python
>>> r.conf_int()
array([[  4.571435134638685,   34.84576765722845],
       [ 2.4363719822543715,  3.5585239107632125],
       [-0.8781395452508023,  0.8023451402575821]], dtype=float64)
>>> q = T.iccdf(0.025)
>>> r.params[1] - q * r.bse[1] == r.conf_int()[1, 0]
True
```

95% 신뢰구간의 "95%"는 구간을 만드는 방법의 성질이에요. 데이터를 새로 모아 구간을 만드는 일을 여러 번 하면, 그 구간들 가운데 95%가 참값을 품어요. 위에서 만든 2,000벌로 세어 보면 그래요.

```python
>>> ci = many.conf_int()[:, 1, :]
>>> float(sd.mean((ci[:, 0] <= 3.0) & (3.0 <= ci[:, 1])))
0.9495
```

`alpha`를 바꾸면 신뢰수준이 1 − alpha가 돼요. 90% 구간은 95% 구간보다 좁아요. `alpha`는 0과 1 사이여야 하고, 이름을 붙여 키워드로만 줘요. `conf_int(0.1)`처럼 위치로 주면 `TypeError`이고, 메시지는 메서드 이름으로 시작해요. 여기의 `alpha`는 유의수준이고, 정규화 함수의 `alpha`(벌점의 세기)와는 뜻이 달라요([같은 이름, 다른 뜻](/api/regression/basics/#같은-이름-다른-뜻)).

```python
>>> r.conf_int(alpha=0.1)[1]
array([2.5316813057404692, 3.4632145872771147], dtype=float64)
>>> r.conf_int(alpha=1.5)
Traceback (most recent call last):
    ...
ValueError: conf_int(): 'alpha' must be between 0 and 1 (exclusive)
>>> r.conf_int(0.1)
Traceback (most recent call last):
    ...
TypeError: conf_int(): takes 0 positional arguments but 1 was given
```

`ols`, `wls`, `gls`에서는 두 끝을 적합 안의 단위에서 계산한 뒤 데이터의 단위로 옮겨요. 그래서 데이터의 크기가 극단이라 계수와 표준오차가 inf로 넘쳐도, 구간은 inf − inf의 NaN이 아니라 끝마다 제 부호의 inf(아래로 넘치면 0)예요([`ols`의 정확도](/api/regression/ols/#정확도)).

## 공분산 행렬: cov_params

`cov_params()`는 계수의 **공분산 행렬**(k × k)이에요. 대각선은 각 계수의 분산이라서, 그 제곱근이 `bse`예요. 대각선 밖의 값은 두 계수가 함께 흔들리는 정도예요. 음수면 한쪽이 크게 나올 때 다른 쪽이 작게 나오는 경향이 있다는 뜻이에요.

```python
>>> V = r.cov_params()
>>> V.shape
(3, 3)
>>> bool(sd.all(sd.sqrt(sd.linalg.diagonal(V)) == r.bse))
True
>>> round(V[0, 1] / (r.bse[0] * r.bse[1]), 3)
-0.938
```

절편과 기온 계수의 상관이 −0.94예요. 기온이 15–35℃에만 있어서, 직선을 기울이면 0℃에서의 높이(절편)가 반대로 크게 움직이기 때문이에요. 계수 두 개를 함께 쓰는 계산(예: 두 계수의 차의 표준오차)에는 이 행렬이 필요해요.

`bse`, `tvalues`, `pvalues`, `conf_int()`는 모두 이 행렬에서 나와요. 그래서 [`cov_type`](/api/regression/covariance/)으로 공분산을 바꾸면 이 넷이 함께 바뀌어요.

## 적합값과 잔차

`fittedvalues`는 각 관측에서 모형이 내는 값 $\hat y_i = x_i \hat\beta$, `resid`는 잔차 $y_i - \hat y_i$예요. 둘 다 길이 n이에요.

```python
>>> r.fittedvalues[:3]
array([ 91.70607707970228,  96.31415604561023, 112.21621822761861], dtype=float64)
>>> r.resid[:3]
array([13.883151715150095, -2.451511719013796,  17.49127198429389], dtype=float64)
>>> float(sd.max(sd.abs(r.resid - (sales - r.fittedvalues))))
7.105427357601002e-15
```

`resid`는 $y - \hat y$를 `fittedvalues`보다 정밀한 값에서 구해요. 그래서 두 배열을 직접 빼면 마지막 자리에서 다를 수 있어요. 절편이 있으면 잔차의 합은 0이에요(계산에서는 반올림 수준의 값).

- `ssr`: 잔차 제곱합 $\sum_i e_i^2$이에요.
- `scale`: 오차 분산의 어림 $\hat\sigma^2 = \text{ssr} / \text{df\_resid}$예요. 그 제곱근은 오차의 표준편차 어림(잔차 표준오차)이에요. 여기서는 7.77로, 참값 8에 가까워요. `df_resid`가 0이면(관측 수 = 계수 수) 어림할 자유도가 없어 NaN이고, 표준오차와 t, p, 구간도 함께 NaN이에요([자유도가 없을 때](/api/regression/collinearity/#열이-행보다-많을-때)).

```python
>>> r.ssr, r.scale
(1631.156784688493, 60.41321424772196)
>>> round(r.scale ** 0.5, 2)
7.77
```

`nan_policy='omit'`으로 뺀 행은 적합값과 잔차에도 없어요. `wls`에서 가중치가 0인 행은 적합에는 쓰지 않지만 적합값과 잔차는 계산해요([wls](/api/regression/wls/)).

## 결정계수

**결정계수** R²(`rsquared`)는 반응의 흩어짐 가운데 모형이 설명한 몫이에요. 0이면 모형이 아무것도 설명하지 못한 것이고, 1이면 모든 점이 모형 위에 있는 것이에요.

$$R^2 = 1 - \frac{\text{SSR}}{\text{TSS}}$$

TSS(전체 제곱합)는 절편이 있는지에 따라 달라요.

| 모형 | TSS | 필드 | 비교하는 기준 |
|---|---|---|---|
| 절편 있음(기본) | $\sum (y_i - \bar y)^2$ | `centered_tss` | 평균 하나로 어림한 것 |
| `intercept=False` | $\sum y_i^2$ | `uncentered_tss` | 0으로 어림한 것 |

결과에는 모형과 상관없이 두 TSS가 다 들어 있고, `rsquared`는 모형에 맞는 쪽을 써요. `ess`는 모형이 설명한 제곱합 TSS − SSR이에요.

```python
>>> r.rsquared
0.8165915058688261
>>> r.centered_tss, r.uncentered_tss
(8893.572745447049, 285620.3036521983)
>>> r.ess
7262.415960758556
```

비중심 TSS는 평균을 빼지 않아서 아주 커요. 그래서 절편 없는 모형의 R²는 1에 가깝게 나오기 쉬워요. 절편이 있는 모형과 없는 모형의 R²는 기준이 달라서 서로 비교하지 않아요.

### 수정 결정계수

R²는 설명변수를 하나 더 넣으면, 쓸모없는 변수라도 줄지 않아요. **수정 결정계수**(`rsquared_adj`)는 변수 수만큼 벌점을 줘요. 쓸모없는 변수를 넣으면 오히려 줄어요.

$$R^2_{\text{adj}} = 1 - \frac{n - 1}{\text{df\_resid}}(1 - R^2)$$

(절편이 없으면 n − 1 대신 n이에요.) 강수량을 빼고 기온만으로 맞춰 보면, R²는 거의 그대로이고 수정 결정계수는 오히려 커요.

```python
>>> r1 = sd.regression.ols(df['sales'], df['temp'])
>>> r.rsquared, r1.rsquared
(0.8165915058688261, 0.8165333298727041)
>>> r.rsquared_adj, r1.rsquared_adj
(0.8030056914887391, 0.8099809487967293)
```

### 설명할 것이 없을 때

절편만 있는 모형(설명변수가 없음)은 설명한 것이 없으니 `ess`와 `rsquared`가 0이에요.

반응이 모두 같은 값 $y_0$이면 TSS가 0이에요. 설명할 흩어짐이 처음부터 없으니 R²는 0/0이라 `rsquared`와 `rsquared_adj`가 NaN이고, `ess`는 0이에요.

절편이 있으면 이때의 해는 정확히 $(y_0, 0, \dots, 0)$이에요(겹친 열은 그대로 NaN). 적합값이 모두 $y_0$이고 잔차가 0인 [완전 적합](/api/regression/collinearity/#완전-적합)이라서, 다른 필드도 정해진 값이 돼요.

- `scale`과 `bse`는 0이에요. 강건 공분산도 0이고, `cov_type='cluster'`에 군집이 하나뿐이면 [군집의 규칙](/api/regression/covariance/#groups)대로 NaN이에요.
- `tvalues`는 절편이 ±inf($y_0 = 0$이면 0 ÷ 0이라 NaN)이고, 기울기는 0 ÷ 0이라 NaN이에요.
- `llf`는 +inf, 스튜던트화 잔차는 NaN이에요.

`wls`는 가중치가 0보다 큰 행의 `y`가 모두 같을 때 같은 규칙을 따르고, 가중치가 0인 행의 잔차는 $y - y_0$이에요. [`rlm`](/api/regression/rlm/)도 같은 정확한 해를 내요. 절편이 있고 offset이 없는 [`glm`](/api/regression/glm/)은 정규분포·identity 링크에서 이 해를 그대로 내고, 다른 분포족과 링크에서도 절편이 $g(y_0)$(링크로 옮긴 $y_0$)이고 기울기가 0인 정확한 해를 내요([glm의 상수 y](/api/regression/glm/#상수-y와-완전-적합)).

```python
>>> rc = sd.regression.ols([3.0, 3, 3, 3, 3], [1.0, 2, 3, 4, 5])
>>> rc.centered_tss, rc.ess
(0.0, 0.0)
>>> rc.rsquared, rc.rsquared_adj, rc.fvalue, rc.f_pvalue
(nan, nan, nan, nan)
>>> rc.params, rc.bse, rc.tvalues
(array([3.0, 0.0], dtype=float64), array([0.0, 0.0], dtype=float64), array([inf, nan], dtype=float64))
>>> rc.scale, rc.llf
(0.0, inf)
>>> rc.resid_studentized_internal
array([nan, nan, nan, nan, nan], dtype=float64)
```

## F 검정: fvalue와 f_pvalue

`fvalue`와 `f_pvalue`는 "절편을 뺀 계수가 모두 0인가"를 한꺼번에 따지는 F 검정의 통계량과 p값이에요. t값과 p값이 계수 하나씩을 본다면, F 검정은 모형 전체가 평균 하나보다 나은지를 봐요. p값은 [F 분포](/api/stats/f/)(자유도 `df_model`, `df_resid_inference`)의 위꼬리 확률이에요.

```python
>>> r.fvalue, r.f_pvalue
(60.10618745577177, 1.1380530555581697e-10)
>>> sd.stats.F(dfn=r.df_model, dfd=r.df_resid).ccdf(r.fvalue) == r.f_pvalue
True
```

절편만 있는 모형은 검정할 계수가 없어서 둘 다 NaN이에요. 반응이 모두 같아서 TSS가 0일 때도 둘 다 NaN이에요(위의 `rc`). 강건 표준오차(`cov_type`)를 쓰면 `fvalue`는 그 공분산으로 만든 Wald 검정의 F예요([표준오차의 종류](/api/regression/covariance/)).

## 로그우도와 정보 기준

- `llf`: 오차가 정규분포라고 볼 때 데이터의 **로그우도**의 최댓값이에요. 클수록 모형이 데이터를 잘 설명해요. 선형 모형에서는 $-\tfrac{n}{2}\left(\log 2\pi + \log(\text{ssr}/n) + 1\right)$이에요.
- `aic` = −2·`llf` + 2·`rank`, `bic` = −2·`llf` + log(`nobs`)·`rank`예요(오차 분산 `scale`은 계수로 세지 않아요). 설명을 잘할수록 작아지고, 계수가 많을수록 벌점을 받아요. 같은 데이터에 맞춘 모형 둘을 견줄 때 작은 쪽이 나아요. 값 하나만으로는 뜻이 없어요. `bic`가 계수에 주는 벌점이 더 커서 작은 모형을 더 좋아해요.

```python
>>> r.llf, r.aic, r.bic
(-102.50586616049192, 211.01173232098384, 215.2153244659703)
>>> r1.aic, r1.bic
(209.02124661940636, 211.82364138273067)
```

기온만 쓴 모형 `r1`의 AIC와 BIC가 더 작아요. 강수량은 넣을 값어치가 없다는 판단이에요.

## 관측 수와 자유도

| 필드 | 뜻 | 이 예에서 |
|---|---|---|
| `nobs` | 적합에 쓰인 관측 수 | 30.0 |
| `rank` | 실제로 쓰인 계수 수(절편 포함). 겹친 열은 세지 않아요 | 3 |
| `df_model` | `rank` − 절편 수. 기울기의 수예요 | 2.0 |
| `df_resid` | `nobs` − `rank`. 잔차의 자유도예요 | 27.0 |
| `df_resid_inference` | p값과 구간의 t 분포, F의 분모에 쓰는 자유도 | 27.0 |

```python
>>> r.nobs, r.rank, r.df_model, r.df_resid, r.df_resid_inference
(30.0, 3, 2.0, 27.0, 27.0)
```

`df_resid_inference`는 보통 `df_resid`와 같아요. 다른 경우가 둘 있어요.

- `cov_type='cluster'`이면 군집 수 − 1이에요. 군집이 적으면 표준오차의 어림이 불안정해서 더 두꺼운 꼬리의 t 분포를 써요([cluster](/api/regression/covariance/#cluster-묶음-안의-상관)).
- [`glm`](/api/regression/glm/)에서 척도를 고정하는 분포족(이항, 포아송)은 t 분포 대신 정규분포로 검정해서 `inf`예요.

`df_resid`가 0이면 오차의 크기를 어림할 자유도가 없어요. 그때는 `scale`, `bse`, `tvalues`, `pvalues`, `conf_int()`, `cov_params()`가 모두 NaN이에요(척도를 고정하는 `glm`의 분포족은 빼고요). 예는 [열이 행보다 많을 때](/api/regression/collinearity/#열이-행보다-많을-때)에 있어요.

## 예측: predict와 predict_interval

### predict

`predict(X_new)`는 새 설명변수에서 모형의 값 $x_{\text{new}}\hat\beta$를 계산해요. `X_new`는 적합에 쓴 `X`와 열이 같아야 하고, 절편 열은 넣지 않아요. 설명변수가 하나인 모형은 1차원으로 줘도 돼요.

```python
>>> r.predict([[20.0, 5.0], [30.0, 5.0]])
array([ 79.46807431362636, 109.44255377871427], dtype=float64)
>>> r1.predict([20.0, 30.0])
array([ 79.46400526402923, 109.43083550768553], dtype=float64)
>>> r.predict([20.0, 30.0])
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have 2 columns like the fit's 'X', not 1-dimensional
```

적합에 쓴 `X`를 그대로 주면 `fittedvalues`와 비트까지 같은 값이에요.

`DataFrame`으로 적합하고 `X_new`도 `DataFrame`으로 주면, `X_new`의 컬럼 이름과 순서가 적합할 때와 같아야 해요. 순서만 다르거나 이름이 다르면 `ValueError`예요. 어느 열이 어느 계수에 맞는지 짐작하지 않고, 틀린 값 대신 에러로 알려 줘요. 순서가 다르면 `new[['temp', 'rain']]`처럼 적합 때의 순서로 골라서 주세요.

```python
>>> new = sd.frame.DataFrame({'rain': [5.0, 5.0], 'temp': [20.0, 30.0]})
>>> r.predict(new)
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have the columns ['temp', 'rain'] in the fit's order, not ['rain', 'temp']
>>> r.predict(new[['temp', 'rain']])
array([ 79.46807431362636, 109.44255377871427], dtype=float64)
>>> r.predict(sd.frame.DataFrame({'temp': [20.0], 'snow': [5.0]}))
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have the columns ['temp', 'rain'] like the fit's 'X', not ['temp', 'snow']
```

한쪽만 `DataFrame`이면(배열로 적합하고 `DataFrame`으로 예측하거나, 그 반대) 비교할 이름이 없으니 열을 위치로 맞춰요. 위의 `[[20.0, 5.0], [30.0, 5.0]]`처럼 리스트나 배열로 줄 때는 적합 때의 열 순서대로 값을 넣어요.

`X_new`에 inf가 있으면 적합의 입력처럼 `ValueError`예요. NaN이 있는 행은 그 행의 예측만 NaN이에요.

```python
>>> r.predict([[20.0, sd.inf]])
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' contains infinity
>>> r.predict([[20.0, sd.nan], [30.0, 5.0]])
array([               nan, 109.44255377871427], dtype=float64)
```

모형에 든 열은 계수가 정확히 0이어도 예측에 들어가요. 그래서 그 열이 NaN이면 예측도 NaN이에요. 값이 없는 것을 0으로 어림하지 않아요. [겹친 열](/api/regression/collinearity/)로 빠진 열만 예측에 쓰지 않으니, 그 열의 NaN은 예측에 닿지 않아요. `predict_interval()`도 같은 행에서 NaN이에요.

```python
>>> rz = sd.regression.ols([3.0, 3, 3, 3, 3], [1.0, 2, 3, 4, 5])
>>> rz.params
array([3.0, 0.0], dtype=float64)
>>> rz.predict([sd.nan, 6.0])
array([nan, 3.0], dtype=float64)
```

[배치](/api/regression/basics/#배치-회귀-여러-개를-한-번에) 결과로 예측하면, `X_new`도 마지막 두 축(행, 열) 앞의 배치 모양이 적합의 배치 모양과 브로드캐스트해야 해요. 회귀마다 같은 `X_new`를 쓰려면 배치 축 없이 주면 돼요.

```python
>>> hours = [1.0, 2, 3, 4, 5, 6, 7, 8]
>>> Y = sd.asarray([[51.0, 58, 57, 66, 64, 73, 75, 80],
...                 [50.0, 54, 57, 63, 66, 71, 73, 78],
...                 [60.0, 59, 62, 61, 63, 62, 64, 63]])
>>> rb = sd.regression.ols(Y, hours)
>>> rb.predict([10.0, 20.0])
array([[ 87.36904761904762, 127.13095238095238],
       [              86.0,              126.0],
       [ 64.89285714285714,  70.60714285714286]], dtype=float64)
>>> rb.predict(sd.ones((2, 4, 1)))
Traceback (most recent call last):
    ...
ValueError: predict(): the batch shapes of 'X_new' (2,) and the fit (3,) do not broadcast
```

### predict_interval

`predict_interval(X_new, *, alpha=0.05, kind='mean')`는 예측의 구간을 (m, 2) 배열로 돌려줘요. 각 행이 [아래 끝, 위 끝]이에요. `kind`에 따라 묻는 것이 달라요.

| `kind` | 묻는 것 | 구간에 드는 불확실성 |
|---|---|---|
| `'mean'`(기본) | 기온이 30℃인 날들의 **평균** 매출은 어디쯤인가 | 계수의 흔들림 |
| `'observation'` | 기온이 30℃인 **어느 하루**의 매출은 어디쯤인가 | 계수의 흔들림 + 그날의 오차($\hat\sigma^2$) |

하루의 매출은 평균 둘레에서 오차만큼 더 흔들리니, `'observation'` 구간이 늘 더 넓어요. 데이터가 아무리 많아도 `'mean'` 구간은 0으로 좁아지지만 `'observation'` 구간은 오차의 폭 아래로 좁아지지 않아요.

```python
>>> X_new = [[20.0, 5.0], [30.0, 5.0]]
>>> r.predict_interval(X_new)
array([[ 75.21216980825892,   83.7239788189938],
       [105.59246897687397, 113.29263858055457]], dtype=float64)
>>> r.predict_interval(X_new, kind='observation')
array([[ 62.96192798134915,  95.97422064590357],
       [ 93.03635688348278, 125.84875067394576]], dtype=float64)
>>> r.predict_interval(X_new, kind='x')
Traceback (most recent call last):
    ...
ValueError: predict_interval(): 'kind' must be 'mean' or 'observation', not 'x'
```

`predict_interval`의 t 분포 자유도도 `df_resid_inference`예요. 그래서 `cov_type='cluster'`이면 `conf_int()`와 같은 군집 수 − 1을 써요.

`rlm`, `quantreg`, `nls`의 `predict_interval(X_new, *, alpha=0.05)`은 `kind='mean'`에 해당하는 구간, 곧 적합한 값(평균이나 분위)의 신뢰구간만 내요. 하루의 값에 대한 구간(`'observation'`)은 없어요. 강건한 척도는 오차의 표준편차가 아니고, 분위 하나는 분포의 퍼짐을 말하지 않아서, 하루의 오차를 더할 근거가 없기 때문이에요.

```python
>>> rr = sd.regression.rlm(df['sales'], df[['temp', 'rain']])
>>> rr.predict_interval([[20.0, 5.0], [30.0, 5.0]])
array([[ 75.36863139543865,  83.49631325144964],
       [105.64035934011257, 112.99303004702246]], dtype=float64)
```

## summary

`summary(*, alpha=0.05)`는 [맨 위](#한눈에-보기)의 표를 글(`str`)로 돌려줘요. `alpha`는 계수 표의 구간 칸을 바꿔요. 위의 반쪽은 모형과 적합의 요약, 가운데는 계수 표, 아래는 진단 값이고, 끝의 Notes는 공분산의 종류와 겹친 열을 적어요. 날짜와 시각은 넣지 않아서 같은 결과면 늘 같은 글이에요.

```python
>>> print(r.summary(alpha=0.1).splitlines()[10])
                 coef    std err          t      P>|t|     [0.050     0.950]
>>> print(r.summary(alpha=0.1).splitlines()[14])
rain          -0.0379      0.410     -0.093      0.927     -0.735      0.660
```

`alpha`는 여기서도 키워드로만 받아요. 결과의 메서드(`conf_int`, `cov_params`, `predict`, `predict_interval`, `summary` 등)를 틀린 꼴로 부르면 모두 메서드 이름으로 시작하는 `TypeError`예요.

```python
>>> r.summary(0.1)
Traceback (most recent call last):
    ...
TypeError: summary(): takes 0 positional arguments but 1 was given
>>> r.predict()
Traceback (most recent call last):
    ...
TypeError: predict(): missing 1 required positional argument: 'X_new'
```

`summary()`는 회귀 하나의 결과만 받아요. 배치 결과에서는 `ValueError`예요([배치](/api/regression/basics/#배치의-규칙)).

## 설정 필드는 읽기 전용

결과에는 계산한 값 말고도 적합을 어떻게 했는지 적은 필드가 있어요. `param_names`, `cov_type`과 함수에 따라 `family`, `link`, `alpha`, `l1_ratio`, `standardize`, `method`, `norm`, `q`예요. 이 필드에는 대입할 수 없어요. 결과의 다른 값은 모두 그 설정으로 계산한 것이라, 설정만 바꾸면 결과 안의 값끼리 어긋나기 때문이에요. 다른 설정이 필요하면 그 설정으로 다시 맞추세요.

리스트나 배열인 필드(`param_names`, 배열로 준 `alpha`·`q`)는 읽을 때마다 새 복사본을 돌려줘요. 돌려받은 리스트나 배열을 고쳐도 결과는 그대로예요.

```python
>>> r.cov_type = 'HC3'
Traceback (most recent call last):
    ...
AttributeError: property 'cov_type' of 'OLSResult' object has no setter
>>> sd.regression.ols(df['sales'], df[['temp', 'rain']], cov_type='HC3').cov_type
'HC3'
>>> names = r.param_names
>>> names[0] = 'intercept'
>>> names, r.param_names
(['intercept', 'temp', 'rain'], ['const', 'temp', 'rain'])
```

## 처음 읽을 때 계산하는 필드

적합할 때는 계수, 공분산, 적합값, 잔차와 몇 가지 합만 계산해요. 표준오차, p값, R², 로그우도, `condition_number` 같은 필드는 처음 읽을 때 계산해 두고, 다음부터는 그 값을 그대로 돌려줘요. 계수만 필요하면 나머지 계산을 하지 않아요.

```python
>>> r.pvalues is r.pvalues
True
```

[지렛대와 Cook 거리](/api/regression/diagnostics/) 같은 진단 필드는 처음 읽을 때 적합에 준 설명변수로 계산을 한 번 더 해요. 적합 한 번쯤 드는 계산이에요.

이 계산에 쓰려고 결과 객체는 적합할 때 `y`, `X`, 가중치를 복사해 둬요. 그래서 적합한 뒤에 넘긴 배열을 제자리에서 고쳐도 결과는 그대로예요. 대신 결과 객체 하나가 `X`의 크기(n × k × 8바이트)와 `y`·가중치만큼 메모리를 더 써요.

```python
>>> X = sd.stack([temp, rain], axis=1)
>>> ra = sd.regression.ols(sales, X)
>>> X[0, 0] = 100.0
>>> float(ra.leverage[0]) == float(r.leverage[0])
True
```

## 다른 결과 객체

같은 이름의 필드는 어느 결과 객체에서나 같은 뜻이에요. 결과 객체마다 어떤 필드가 있는지 표로 모았어요. ○는 있음, 빈칸은 없음이에요.

| 필드 | OLS·WLS·GLS | GLM | RLM | QuantReg | NLS | 정규화 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| `params`, `param_names`, `nobs`, `df_model`, `predict()` | ○ | ○ | ○ | ○ | ○ | ○ |
| `bse`, `tvalues`, `pvalues`, `conf_int()`, `cov_params()`, `df_resid_inference` | ○ | ○ | ○ | ○ | ○ | |
| `df_resid`, `rank`, `condition_number`, `cov_type`, `summary()` | ○ | ○ | ○ | ○ | ○ | |
| `fittedvalues` | ○ | ○ | ○ | ○ | ○ | ○ |
| `resid` | ○ | | ○ | ○ | ○ | 선형만 |
| `predict_interval()` | ○ | ○ | 평균만 | 평균만 | 평균만 | |
| `ssr` | ○ | | | | ○ | 선형만 |
| `rsquared` | ○ | | | | | 선형만 |
| `rsquared_adj`, `ess`, `centered_tss`, `uncentered_tss`, `fvalue`, `f_pvalue` | ○ | | | | | |
| `llf`, `aic`, `bic` | ○ | ○ | | | ○ | |
| `scale` | ○ | ○ | ○ | | ○ | |

- GLM(`GLMResult`)은 잔차가 네 가지(`resid_response`, `resid_pearson`, `resid_deviance`, `resid_working`)라서 `resid`가 없어요. R² 대신 편차(`deviance`, `null_deviance`), 우도비(`llr`), 의사 결정계수 `pseudo_rsquared()`가 있어요. [glm](/api/regression/glm/)을 보세요.
- RLM(`RLMResult`)의 `scale`은 오차 분산이 아니라 강건한 척도(표준편차의 단위)예요. OLS·GLM·NLS의 `scale`은 분산(제곱의 단위)이라서, 같은 데이터면 RLM의 `scale`은 그 제곱근에 견줄 값이에요. 관측마다의 무게 `weights`가 있어요. [rlm](/api/regression/rlm/)을 보세요.
- QuantReg(`QuantRegResult`)는 R² 대신 `prsquared`, 목적함수 `objective`가 있어요. [quantreg](/api/regression/quantreg/)을 보세요.
- NLS(`NLSResult`)의 `param_names`는 모형 함수의 인자 이름이에요. [nls](/api/regression/nls/)를 보세요.
- 정규화(`RidgeResult`, `LassoResult`, `ElasticNetResult`와 교차검증 결과, `PenalizedGLMResult`)는 예측이 목적이라 표준오차·p값·구간과 `summary()`가 없어요. `resid`, `ssr`, `rsquared`는 선형(`ridge`, `lasso`, `elastic_net`)에만 있고, `penalized_glm`은 `resid_response`와 편차를 줘요. [ridge](/api/regression/ridge/)를 보세요.
- `linregress`, `theilslopes`, `siegelslopes`의 결과는 이름 붙은 튜플이에요. 필드는 [linregress](/api/regression/linregress/), [theilslopes](/api/regression/theilslopes/), [siegelslopes](/api/regression/siegelslopes/)에 있어요.

```python
>>> rr.scale, r.scale ** 0.5
(5.646710246149384, 7.772593791503707)
```

반복으로 푸는 결과(GLM, RLM, QuantReg, NLS, lasso 등)에는 `converged`, `n_iter`처럼 반복의 상태를 알려 주는 필드가 더 있어요. 어느 함수에서나 같은 규칙이에요.

- `converged`는 멈춤 판정을 통과하고 그 뒤에 해를 반올림 수준까지 다듬는 일까지 끝났을 때만 True예요. 판정과 다듬기가 끝나기 전에 반복 상한(`max_iter` 등)에 닿으면 False예요. 마지막 다듬기가 마침 상한째 반복에서 끝나면 `n_iter`가 상한과 같고 `converged`는 True예요. False인 결과의 계수는 멈춤 허용오차의 정밀도까지만 믿을 수 있어요.
- `n_iter`는 `max_iter`를 넘지 않아요.
- 쓸 행이 없으면 `converged`는 False, `n_iter`는 0이에요([쓸 행이 없을 때](/api/regression/basics/#쓸-행이-없을-때)).

```python
>>> rng = sd.random.default_rng(0)
>>> xg = sd.stats.Normal().sample(50, rng=rng)
>>> yg = sd.stats.Poisson(mu=3.0).sample(50, rng=rng) * 1.0
>>> g = sd.regression.glm(yg, xg, family='poisson')
>>> g.converged, g.n_iter
(True, 6)
>>> g3 = sd.regression.glm(yg, xg, family='poisson', max_iter=3)
>>> g3.converged, g3.n_iter
(False, 3)
>>> g6 = sd.regression.glm(yg, xg, family='poisson', max_iter=6)
>>> g6.converged, g6.n_iter
(True, 6)
```

각 함수의 반복과 멈춤 규칙은 그 함수의 페이지에 있어요.

## statsmodels를 아는 분께

- 필드 이름은 statsmodels의 결과와 같아요(`params`, `bse`, `tvalues`, `pvalues`, `fittedvalues`, `resid`, `rsquared`, `rsquared_adj`, `fvalue`, `f_pvalue`, `llf`, `aic`, `bic`, `scale`, `ssr`, `ess`, `centered_tss`, `uncentered_tss`, `df_model`, `df_resid`, `condition_number`). 위 예의 계수, 표준오차, 수정 결정계수, `llf`, `aic`, `bic`는 statsmodels 0.15.0의 `OLS(...).fit()`과 같은 값이에요.
- `conf_int()`와 `cov_params()`는 statsmodels처럼 메서드이고, 결과는 numpy 배열이 아니라 `sd.ndarray`예요. statsmodels의 `conf_int(0.1)`처럼 `alpha`를 위치로 주는 꼴은 받지 않아요. `conf_int(alpha=0.1)`로 주세요. statsmodels는 pandas 입력이면 이름 붙은 표를 돌려주지만, 여기서는 이름을 `param_names`로 따로 읽어요.
- 예측 구간은 statsmodels의 `get_prediction(X_new).summary_frame()`에 해당해요. `kind='mean'`이 `mean_ci_lower`·`mean_ci_upper`, `kind='observation'`이 `obs_ci_lower`·`obs_ci_upper`와 같은 값이에요. statsmodels와 달리 `X_new`에 절편 열을 넣지 않아요.
- 강건 공분산(`cov_type='HC3'` 등)에서 statsmodels의 기본은 p값과 구간을 정규분포로 계산해요(`use_t=False`). 여기서는 늘 t 분포예요. statsmodels의 `fit(cov_type=..., use_t=True)`와 같은 값이에요([표준오차의 종류](/api/regression/covariance/)).
- `summary()`의 꼴은 statsmodels의 OLS summary와 같지만 날짜와 시각 줄이 없어요.
- 진단 필드(`leverage`, `cooks_distance` 등)는 statsmodels처럼 `get_influence()`를 거치지 않고 결과에서 바로 읽어요([회귀 진단](/api/regression/diagnostics/)). statsmodels는 모형이 들고 있는 설계 행렬로 나중에 계산해서, 적합 뒤에 그 배열을 고치면 진단 값이 바뀌어요. 여기서는 적합할 때 복사해 둔 값으로 계산해요.
- 반응이 모두 같으면 statsmodels는 R²와 수정 결정계수에 −inf, F에 음수 같은 반올림의 값을 내요. 여기서는 `rsquared`, `rsquared_adj`, `fvalue`, `f_pvalue`가 NaN이고 `ess`는 0이에요.
- statsmodels의 `predict`는 pandas `DataFrame`을 받아도 컬럼 이름을 보지 않고 위치로 곱해서, 순서가 다르면 에러 없이 다른 값을 내요. 여기서는 둘 다 `DataFrame`이면 이름과 순서를 확인해요. `X_new`의 inf도 statsmodels는 inf 예측을 내지만 여기서는 `ValueError`예요.
