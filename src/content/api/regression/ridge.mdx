## 한눈에 보기

최소제곱 회귀([`ols`](/api/regression/ols/))는 잔차(실제 값과 맞춘 값의 차이)의 제곱합이 가장 작은 계수를 찾아요. 데이터에 가장 잘 맞는 계수지만, 열 둘이 거의 같은 정보를 담고 있으면 문제가 생겨요. 데이터만으로는 두 열에 효과를 어떻게 나눌지 정할 수 없어서, 계수가 엉뚱하게 크게 나오고 데이터가 조금만 바뀌어도 크게 흔들려요.

릿지 회귀는 잔차의 제곱합에 **계수의 제곱합에 비례하는 벌점**을 더해서 최소화해요. 계수가 커지면 벌점이 커지니, 데이터가 분명히 요구하지 않는 큰 계수는 나오지 않아요.

예를 들어 볼게요. `x2`는 `x1`에 작은 잡음을 더한 열이라 둘이 거의 같아요. 참값은 절편 1, `x1`과 `x2`의 계수 1씩, `x3`의 계수 0.5예요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(1)
>>> Z = sd.stats.Normal().sample((40, 3), rng=rng)
>>> x1 = Z[:, 0]
>>> x2 = x1 + 0.05 * Z[:, 1]
>>> x3 = Z[:, 2]
>>> X = sd.stack([x1, x2, x3], axis=1)
>>> y = 1.0 + x1 + x2 + 0.5 * x3 + sd.stats.Normal().sample(40, rng=rng)
>>> o = sd.regression.ols(y, X)
>>> [round(v, 3) for v in o.params.tolist()]
[1.022, -5.817, 7.802, 0.161]
>>> [round(v, 3) for v in o.bse.tolist()]
[0.179, 3.752, 3.696, 0.174]
```

최소제곱의 `x1`, `x2` 계수는 −5.8과 7.8이에요. 둘의 합(약 2)은 맞지만 나눔이 엉뚱하고, 표준오차(계수가 데이터의 잡음 때문에 흔들리는 정도)가 3.7이나 돼요. 릿지는 이렇게 나와요.

```python
>>> r = sd.regression.ridge(y, X, alpha=0.1)
>>> r
RidgeResult(alpha=0.1, nobs=40, df_model=1.84954, params=[ 1.1364487002130905  0.9011101673863711    1.05074620606917
 0.11963673541278859])
>>> [round(v, 3) for v in r.params.tolist()]
[1.136, 0.901, 1.051, 0.12]
```

두 계수가 참값 1에 가까운 0.90과 1.05로 나뉘었어요. 아래 그림은 `alpha`를 바꿔 가며 세 계수를 그린 것(**경로**)이에요. `alpha`가 아주 작으면 최소제곱처럼 `x1`과 `x2`가 반대 방향으로 벌어지고, 커질수록 둘이 같은 값으로 모였다가 함께 0으로 줄어요.

## 왜 벌점을 줄까요

벌점이 쓸모 있는 때는 크게 셋이에요.

- **열이 서로 겹칠 때**(공선성): 위의 예처럼 최소제곱 계수가 크고 불안정해져요. 겹친 열 이야기는 [겹친 열과 완전 적합](/api/regression/collinearity/)에 더 있어요.
- **열이 많을 때**: 행에 비해 열이 많으면 최소제곱은 잡음까지 외워 버려요(과적합). 학습한 데이터에는 잘 맞지만 새 데이터에서는 예측이 나빠요. 열이 행보다 많으면 최소제곱의 해가 하나로 정해지지도 않아요.
- **예측이 목적일 때**: 계수 하나하나의 값보다 새 데이터에서의 예측 오차가 중요하면, 계수를 조금 당겨서 흔들림을 줄이는 편이 대개 이득이에요.

이것을 **편향과 분산의 맞바꿈**이라고 해요. 벌점은 계수를 0 쪽으로 당기므로, 같은 실험을 여러 번 되풀이해 평균을 내도 참값보다 조금 작게 나와요(편향). 그 대신 데이터의 잡음에 덜 흔들려요(분산이 작아요). 흔들림이 줄어드는 몫이 당겨지는 몫보다 크면 예측이 좋아져요.

같은 `X`에 잡음만 새로 뽑은 반응 200개를 만들어 확인해 볼게요. `y`를 (200, 40)으로 주면 회귀 200개를 한 번에 풀어요([배치](/api/regression/basics/)).

```python
>>> g = sd.random.default_rng(2)
>>> Y = 1.0 + x1 + x2 + 0.5 * x3 + sd.stats.Normal().sample((200, 40), rng=g)
>>> ols200 = sd.regression.ols(Y, X)
>>> ridge200 = sd.regression.ridge(Y, X, alpha=0.1)
>>> ridge200.params.shape
(200, 4)
>>> b1 = ols200.params[:, 1]
>>> round(float(sd.mean(b1)), 3), round(float(sd.std(b1)), 3)
(1.316, 3.304)
>>> b1 = ridge200.params[:, 1]
>>> round(float(sd.mean(b1)), 3), round(float(sd.std(b1)), 3)
(0.925, 0.089)
```

최소제곱의 `x1` 계수는 200번의 표준편차가 3.3이라 한 번의 결과를 믿기 어려워요. 릿지는 평균이 0.925로 참값 1보다 조금 작지만(편향), 표준편차가 0.089예요. 새 점 1,000개에서 참값과의 예측 오차도 릿지가 작아요.

```python
>>> Znew = sd.stats.Normal().sample((1000, 3), rng=g)
>>> Xnew = sd.stack([Znew[:, 0], Znew[:, 0] + 0.05 * Znew[:, 1], Znew[:, 2]], axis=1)
>>> truth = 1.0 + Xnew[:, 0] + Xnew[:, 1] + 0.5 * Xnew[:, 2]
>>> round(float(sd.mean((ols200.predict(Xnew) - truth) ** 2)), 4)
0.1123
>>> round(float(sd.mean((ridge200.predict(Xnew) - truth) ** 2)), 4)
0.0995
```

예측 오차의 차이는 계수의 차이만큼 크지 않아요. 새 데이터에서도 `x1`과 `x2`가 거의 같으면, 두 계수의 합만 맞으면 예측이 맞기 때문이에요. 릿지의 이득은 계수가 덜 엉뚱하고, 열이 많을 때 과적합이 덜하다는 데 있어요.

## 목적함수

`ridge`는 다음을 최소화하는 절편 $b_0$와 계수 $\beta$를 찾아요.

$$
\frac{1}{2\,s_w}\sum_{i=1}^{n} w_i\,\bigl(y_i - b_0 - x_i^\top\beta\bigr)^2 \;+\; \frac{\alpha}{2}\,\lVert S\beta\rVert_2^2
$$

- $w_i$는 `weights`이고, 없으면 모두 1이에요. $s_w = \sum_i w_i$라서 가중치가 없으면 $s_w = n$이에요. 첫 항은 잔차 제곱의 (가중) **평균**의 절반이라, 행 수가 늘어도 같은 `alpha`가 비슷한 세기를 뜻해요.
- $\lVert S\beta\rVert_2^2$는 계수의 제곱합이에요. $S$는 `standardize=False`(기본)이면 단위행렬이고, `True`면 열의 표준편차를 대각에 놓은 행렬이에요(아래 `standardize` 절).
- **절편 $b_0$는 벌점 밖이에요.** 절편은 반응의 평균 수준일 뿐이라 0으로 당길 이유가 없어요.

이 식은 [`elastic_net`](/api/regression/elastic-net/)의 목적함수에서 `l1_ratio = 0`인 경우예요. 그래서 결과의 `l1_ratio`는 0.0이에요.

양 끝을 보면 뜻이 분명해요. `alpha=0`이면 벌점이 없으니 최소제곱이에요.

```python
>>> [round(v, 6) for v in sd.regression.ridge(y, X, alpha=0.0).params.tolist()]
[1.022164, -5.817149, 7.802495, 0.16056]
>>> [round(v, 6) for v in o.params.tolist()]
[1.022164, -5.817149, 7.802495, 0.16056]
```

`alpha`가 아주 크면 계수가 모두 0에 가까워지고, 절편은 `y`의 평균이 돼요.

```python
>>> big = sd.regression.ridge(y, X, alpha=1e8)
>>> [round(v, 6) for v in big.params.tolist()]
[1.146716, 0.0, 0.0, -0.0]
>>> round(float(sd.mean(y)), 6)
1.146716
```

릿지는 계수를 작게 만들 뿐 **정확히 0으로 만들지는 않아요**. 쓸모없는 열을 아예 빼고 싶으면 [`lasso`](/api/regression/lasso/)를 쓰세요.

## `alpha`와 경로

`alpha`는 벌점의 세기예요. 0 이상의 유한한 수이고, 기본값이 없어서 꼭 줘야 해요. 어떤 값이 좋은지는 데이터마다 달라요. 보통 여러 값을 시험해서 고르고, 그 일을 자동으로 하는 것이 [교차검증](/api/regression/cross-validation/)(`ridge_cv`)이에요.

`alpha`에 1차원 배열을 주면 그 값마다 푼 결과가 한 번에 나와요. 이것을 **경로**라고 해요. 결과의 필드마다 길이 L(alpha의 개수)인 축이 붙어요.

```python
>>> p = sd.regression.ridge(y, X, alpha=[10.0, 1.0, 0.1, 0.01])
>>> p
RidgeResult(shape (4,), 4 parameters)
>>> p.params.shape, p.fittedvalues.shape, p.rsquared.shape
((4, 4), (4, 40), (4,))
>>> [[round(v, 3) for v in row] for row in p.params.tolist()]
[[1.15, 0.139, 0.142, -0.023], [1.152, 0.615, 0.638, -0.015], [1.136, 0.901, 1.051, 0.12], [1.123, 0.405, 1.659, 0.158]]
>>> p.alpha
array([10.0,  1.0,  0.1, 0.01], dtype=float64)
```

| 필드 | alpha 하나 | alpha 배열(길이 L) |
|---|---|---|
| `params` | (k + 1,) | (L, k + 1) |
| `nobs`, `df_model`, `ssr`, `rsquared` | Python `float` | (L,) |
| `fittedvalues`, `resid` | (n,) | (L, n) |
| `predict(X_new)` | (m,) | (L, m) |
| `alpha` | 준 수 | 준 배열(준 순서 그대로) |

경로의 각 행은 그 `alpha` 하나로 따로 부른 것과 비트까지 같아요. 값의 순서는 아무렇게나 줘도 돼요.

```python
>>> one = sd.regression.ridge(y, X, alpha=0.1)
>>> p.params[2].tolist() == one.params.tolist()
True
```

릿지는 `alpha`가 많아도 비용이 크게 늘지 않아요. 배치와 함께 쓰면 경로 축은 배치 축 뒤에 와요. 예를 들어 `y`가 (3, n)이고 `alpha`가 길이 4면 `params`는 (3, 4, k + 1)이에요.

## 열의 척도: `standardize`

벌점 $\lVert\beta\rVert^2$는 계수의 크기를 보는데, 계수의 크기는 열의 단위에 달려 있어요. 같은 길이를 미터로 쓰면 계수가 c이고 킬로미터로 쓰면 1000c예요. 그래서 `standardize=False`(기본)에서는 **단위가 작은 숫자로 적힌 열일수록 계수가 커야 해서 벌점을 더 세게 받아요.**

`x3`을 1000으로 나눠(단위를 바꿔) 볼게요.

```python
>>> Xkm = sd.stack([x1, x2, x3 / 1000], axis=1)
>>> [round(v, 3) for v in sd.regression.ridge(y, X, alpha=0.1).params.tolist()]
[1.136, 0.901, 1.051, 0.12]
>>> [round(v, 3) for v in sd.regression.ridge(y, Xkm, alpha=0.1).params.tolist()]
[1.151, 0.885, 1.035, 0.001]
```

원래라면 `x3`의 계수가 120 남짓이어야 하는데, 그만큼 큰 계수는 벌점이 너무 커서 0.001로 눌렸어요. 단위 하나 바꿨다고 `x3`이 모형에서 사실상 빠진 거예요.

`standardize=True`로 하면 각 열을 표준편차로 나눈 척도에서 벌점을 줘요. 계수는 원래 척도로 돌려주므로 해석은 그대로이고, **열에 상수를 곱해도 예측이 바뀌지 않아요.**

```python
>>> a = sd.regression.ridge(y, X, alpha=0.1, standardize=True)
>>> b = sd.regression.ridge(y, Xkm, alpha=0.1, standardize=True)
>>> [round(v, 3) for v in a.params.tolist()]
[1.136, 0.911, 1.065, 0.125]
>>> [round(v, 3) for v in b.params.tolist()]
[1.136, 0.911, 1.065, 125.028]
>>> float(sd.max(sd.abs(a.fittedvalues - b.fittedvalues))) < 1e-12
True
```

정확히는 열 $j$의 척도 $s_j$가 가중 모표준편차 $\sqrt{\sum_i w_i (x_{ij} - \bar x_j)^2 / s_w}$예요(n − 1이 아니라 $s_w$로 나눠요). 절편이 없으면 평균을 빼지 않은 RMS $\sqrt{\sum_i w_i x_{ij}^2 / s_w}$예요. 벌점은 $\sum_j (s_j \beta_j)^2$이 돼요.

<Callout type="tip">
열의 단위가 서로 다르거나(키는 cm, 몸무게는 kg, 소득은 원) 단위를 임의로 정한 데이터라면 `standardize=True`를 쓰는 것이 좋아요. 모든 열이 같은 단위이고 그 크기 차이에 뜻이 있으면 기본값 그대로 써도 돼요.
</Callout>

## 가중치 `weights`

`weights`는 행마다 얼마나 중요하게 볼지를 정해요. 목적함수의 첫 항이 가중 평균이 되므로, 가중치를 모두 같은 배수로 키워도 해는 같아요(반올림 차이 안). 가중치 2는 그 행을 두 번 넣은 것과 같은 계수를 줘요(`nobs`는 다르게 세요: 가중치가 0보다 큰 행의 수예요).

가중치가 0인 행은 적합에서 빠지고 `nobs`에도 세지 않아요. 적합값과 잔차는 그 행에도 계산해요.

```python
>>> w = sd.where(sd.arange(40) < 5, 0.0, 1.0)
>>> c = sd.regression.ridge(y, X, alpha=0.1, weights=w)
>>> d = sd.regression.ridge(y[5:], X[5:], alpha=0.1)
>>> c.nobs, c.params.tolist() == d.params.tolist()
(35.0, True)
>>> c.fittedvalues.shape
(40,)
```

음수 가중치는 `ValueError`이고, 가중치의 NaN은 `nan_policy`를 따라요. 가중치가 모두 0이면 적합할 행이 없어서 `nobs`가 0이고 계수는 NaN이에요.

## 절편 `intercept`

기본값 `intercept=True`는 절편을 넣고 `params[0]`에 둬요. `X`에 1의 열을 직접 넣을 필요가 없어요(넣으면 상수 열이라 계수 0이 돼요, 아래 특수한 경우). 절편은 벌점을 받지 않으므로, 열의 가중 평균에서 계산돼요: $b_0 = \bar y - \bar x^\top \beta$.

`intercept=False`면 절편 없이 원점을 지나는 모형이에요. 이때 `standardize`의 척도는 RMS이고, `rsquared`는 평균을 빼지 않은 비중심 R²예요([`ols`](/api/regression/ols/)와 같은 규칙).

```python
>>> g0 = sd.regression.ridge(y, X, alpha=0.1, intercept=False)
>>> g0.param_names
['x1', 'x2', 'x3']
>>> [round(v, 3) for v in g0.params.tolist()]
[0.826, 1.156, 0.253]
```

## 결과 읽기: `RidgeResult`

| 필드 | 뜻 |
|---|---|
| `params` | 계수. 절편이 있으면 `params[0]`이 절편이에요. |
| `param_names` | 계수의 이름. `['const', 'x1', ...]`, frame 입력이면 열 이름이에요. |
| `alpha` | 준 `alpha`(수 또는 배열) |
| `l1_ratio` | 언제나 0.0(벌점이 모두 제곱합이라는 뜻) |
| `standardize` | 준 `standardize` |
| `nobs` | 적합에 쓴 행 수(가중치가 0보다 큰 행). `float`예요. |
| `df_model` | 유효 자유도(아래). 절편은 세지 않아요. |
| `fittedvalues` | 적합값 $b_0 + x_i^\top\beta$. 가중치 0인 행에도 있어요. |
| `resid` | 잔차 `y - fittedvalues` |
| `ssr` | 적합에 쓴 행의 $\sum_i w_i r_i^2$ |
| `rsquared` | 결정계수 1 − `ssr`/TSS. TSS는 가중 평균에 대한 $\sum_i w_i (y_i - \bar y)^2$(절편이 없으면 $\sum_i w_i y_i^2$). TSS가 0이면 NaN이에요(아래 특수한 경우). |
| `predict(X_new, /)` | 새 행의 예측 |

R²(결정계수)는 반응의 흩어짐 가운데 모형이 설명한 몫이에요. 1이면 완전히 맞고 0이면 평균만큼만 맞아요. 자세한 풀이는 [결과 객체 읽기](/api/regression/results/)에 있어요.

```python
>>> r.param_names
['const', 'x1', 'x2', 'x3']
>>> r.nobs, round(r.ssr, 4), round(r.rsquared, 4)
(40.0, 44.178, 0.7517)
>>> r.l1_ratio, r.standardize
(0.0, False)
```

frame의 `DataFrame`을 주면 열 이름이 `param_names`가 돼요.

```python
>>> df = sd.frame.DataFrame({'height': x1, 'weight': x3})
>>> sd.regression.ridge(y, df, alpha=0.1).param_names
['const', 'height', 'weight']
```

### 유효 자유도 `df_model`

최소제곱에서 자유도는 계수의 수예요. 릿지의 계수는 벌점에 묶여 있어서 그만큼 자유롭지 않아요. `df_model`은 그 정도를 연속적인 수로 나타낸 **유효 자유도**예요.

$$
\text{df} = \sum_{j} \frac{s_j^2}{s_j^2 + \alpha}
$$

여기서 $s_j$는 평균을 뺀 설계 행렬(가중치는 $w_i/s_w$로 곱하고, `standardize`면 표준화한 것)의 특이값이에요. `alpha=0`이면 열의 수(정확히는 랭크)이고, `alpha`가 커지면 0으로 줄어요.

```python
>>> [round(v, 3) for v in p.df_model.tolist()]
[0.226, 1.093, 1.85, 2.074]
>>> sd.regression.ridge(y, X, alpha=0.0).df_model
3.0
```

`alpha=0.1`의 1.85는 "계수 세 개가 대략 두 개만큼의 자유를 쓴다"는 뜻이에요. 거의 같은 `x1`과 `x2`가 사실상 하나처럼 움직이기 때문이에요.

### 표준오차와 p값이 없는 까닭

`RidgeResult`에는 `bse`, `pvalues`, `conf_int()`, `summary()`가 없어요. 정규화 회귀의 결과는 **예측을 위한 것**이에요. 벌점은 계수를 일부러 0 쪽으로 당기므로 계수가 참값을 중심으로 흩어지지 않고, `alpha`를 데이터로 골랐다면 그 선택도 불확실성에 들어가요. 그래서 최소제곱의 표준오차·p값 공식이 뜻하는 바가 그대로 성립하지 않아요. 계수 하나하나를 검정하거나 신뢰구간이 필요하면 [`ols`](/api/regression/ols/)를 쓰세요.

```python
>>> hasattr(r, 'bse'), hasattr(r, 'summary')
(False, False)
```

반복 계산이 아니라 닫힌 꼴로 풀기 때문에 [`lasso`](/api/regression/lasso/)에 있는 `converged`, `n_iter`, `dual_gap`도 없어요.

## 예측: `predict`

`predict(X_new)`는 새 행에서 $b_0 + x^\top\beta$를 계산해요. `X_new`의 열 수는 적합의 `X`와 같아야 해요.

```python
>>> new = sd.asarray([[0.0, 0.0, 0.0], [1.0, 1.0, 1.0]])
>>> [round(v, 4) for v in r.predict(new).tolist()]
[1.1364, 3.2079]
>>> [[round(v, 3) for v in row] for row in p.predict(new).tolist()]
[[1.15, 1.408], [1.152, 2.39], [1.136, 3.208], [1.123, 3.345]]
```

경로면 결과가 (L, m)이에요. 열 수가 다르면 `ValueError`예요.

```python
>>> r.predict(sd.ones((2, 2)))
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have 3 columns like the fit's 'X', not 2
```

`DataFrame`으로 적합하고 `DataFrame`으로 예측하면 열 이름과 순서가 적합과 같아야 해요. 순서만 달라도 알아서 맞추지 않고 `ValueError`를 내요. 어느 쪽이 맞는지 짐작하지 않기 위해서예요. 한쪽만 `DataFrame`이면 열을 위치로 맞춰요. `X_new`에 inf가 있으면 `ValueError`이고, NaN이 있는 행은 예측이 NaN이에요.

```python
>>> rdf = sd.regression.ridge(y, df, alpha=0.1)
>>> rdf.predict(sd.frame.DataFrame({'weight': [0.0], 'height': [1.0]}))
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have the columns ['height', 'weight'] in the fit's order, not ['weight', 'height']
>>> rdf.predict(sd.frame.DataFrame({'height': [1.0], 'w': [0.0]}))
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' must have the columns ['height', 'weight'] like the fit's 'X', not ['height', 'w']
>>> rdf.predict(sd.frame.DataFrame({'height': [1.0], 'weight': [0.0]})).tolist() == rdf.predict([[1.0, 0.0]]).tolist()
True
>>> rdf.predict([[float('inf'), 0.0]])
Traceback (most recent call last):
    ...
ValueError: predict(): 'X_new' contains infinity
```

## 특수한 경우

### 상수 열

모든 행에서 값이 같은 열은 절편과 구별할 수 없어서 적합에서 빠지고, 그 계수는 0이에요. 절편이 없으면 0인 열만 빠지고, 0이 아닌 상수 열은 보통 열처럼 쓰여요.

```python
>>> Xc = sd.stack([x1, x3, sd.ones(40) * 2.5], axis=1)
>>> sd.regression.ridge(y, Xc, alpha=0.1).params[3]
0.0
>>> sd.regression.ridge(y, Xc, alpha=0.1, intercept=False).params[2] != 0.0
True
```

### `y`가 모두 같을 때

`y`가 모두 같으면 설명할 흩어짐이 없어요(TSS가 0). 그래서 `rsquared`는 0/0이라 NaN이에요. 계수는 그대로 구해져서, 절편이 `y`의 값이고 나머지는 0이에요.

```python
>>> yc = sd.ones(40) * 2.0
>>> fc = sd.regression.ridge(yc, X, alpha=0.1)
>>> fc.params, fc.rsquared
(array([2.0, 0.0, 0.0, 0.0], dtype=float64), nan)
```

### 똑같은 열

최소제곱에서는 똑같은 두 열의 계수가 하나로 정해지지 않아요([`ols`](/api/regression/ols/)는 뒤의 열을 NaN으로 둬요). 릿지는 `alpha > 0`이면 해가 하나라서, 똑같은 열에 효과를 똑같이 나눠요. `alpha=0`이어도 둘을 똑같이 나눈 해(계수의 제곱합이 가장 작은 최소제곱 해)를 내요.

```python
>>> Xd = sd.stack([x1, x1, x3], axis=1)
>>> [round(v, 4) for v in sd.regression.ridge(y, Xd, alpha=0.1).params.tolist()]
[1.1538, 0.978, 0.978, 0.1175]
>>> [round(v, 4) for v in sd.regression.ridge(y, Xd, alpha=0.0).params.tolist()]
[1.15, 1.0462, 1.0462, 0.161]
>>> sd.regression.ridge(y, Xd, alpha=0.0).df_model
2.0
```

### 열이 행보다 많을 때

열이 행보다 많아도 풀 수 있어요. `alpha=0`이면 데이터를 완전히 지나는(R² = 1) 계수 가운데 제곱합이 가장 작은 것이고, 유효 자유도는 n − 1이에요. `alpha > 0`이면 완전 적합에서 물러나요.

```python
>>> rw = sd.random.default_rng(5)
>>> Xw = sd.stats.Normal().sample((10, 30), rng=rw)
>>> yw = Xw[:, 0] + sd.stats.Normal().sample(10, rng=rw)
>>> f0 = sd.regression.ridge(yw, Xw, alpha=0.0)
>>> f0.df_model, round(f0.rsquared, 12)
(9.0, 1.0)
>>> f1 = sd.regression.ridge(yw, Xw, alpha=0.1)
>>> round(f1.df_model, 3), round(f1.rsquared, 3)
(8.532, 0.996)
```

### NaN과 inf

`nan_policy`는 회귀 영역의 공통 규칙([기본 개념](/api/regression/basics/))을 따라요. 기본 `'propagate'`면 `y`, `X`, `weights`에 NaN이 하나라도 있는 회귀는 모든 값이 NaN이에요(`nobs`, `df_model`도요).

```python
>>> import math
>>> yn = sd.where(sd.arange(40) == 3, math.nan, y)
>>> sd.regression.ridge(yn, X, alpha=0.1)
RidgeResult(alpha=0.1, nobs=nan, df_model=nan, params=[nan nan nan nan])
>>> sd.regression.ridge(yn, X, alpha=0.1, nan_policy='omit').nobs
39.0
>>> sd.regression.ridge(yn, X, alpha=0.1, nan_policy='raise')
Traceback (most recent call last):
    ...
ValueError: ridge(): the input contains NaN (nan_policy='raise')
```

`'omit'`이면 적합값과 잔차도 남은 행만큼(여기서는 39개)이에요. inf는 `nan_policy`와 상관없이 에러예요.

```python
>>> sd.regression.ridge(y, X + sd.asarray([math.inf, 0.0, 0.0]), alpha=0.1)
Traceback (most recent call last):
    ...
ValueError: ridge(): 'X' contains infinity
```

## 배치

`y`, `X`, `weights`의 앞 축은 배치예요. 같은 모양의 회귀 여러 개를 한 번에 풀고, 결과 필드의 앞에 배치 모양이 붙어요. 배치의 각 결과는 하나씩 부른 것과 비트까지 같아요. 공통 규칙은 [기본 개념](/api/regression/basics/)에 있어요.

```python
>>> Yb = sd.stack([y, 2 * y, -y])
>>> b = sd.regression.ridge(Yb, X, alpha=0.1)
>>> b.params.shape, b.nobs.shape
((3, 4), (3,))
>>> b.params[1].tolist() == sd.regression.ridge(2 * y, X, alpha=0.1).params.tolist()
True
```

배치에서는 회귀마다 NaN이 있는 행이 달라질 수 있어서 `nan_policy='omit'`을 쓸 수 없어요(`ValueError`).

## 정확도

계수는 정확한 해(Arb 구간 산술로 만든 참값)와 견줘 상대오차(벡터 노름)가 조건이 좋은 문제에서 1.7e-15 안이에요. 설계 행렬의 조건수가 10¹⁰이고 `alpha`가 1e-18(거의 최소제곱)인 어려운 문제에서도 1.7e-15 안이에요. 해가 나쁜 조건에 가까우면 잔차를 더 높은 정밀도로 구해 해를 다듬기 때문이에요. 같은 입력이면 스레드 수와 상관없이 같은 비트예요. 풀이의 자세한 내용은 [정규화의 구현](/internals/regression/penalized/)에 있어요.

## scikit-learn·glmnet을 아는 분께

- **`alpha`의 척도가 달라요.** scikit-learn의 `Ridge`는 $\sum_i w_i r_i^2 + \alpha\lVert\beta\rVert^2$을 풀어서, 그 `alpha`는 여기 `alpha`의 $s_w$배(가중치가 없으면 n배)예요. 여기의 목적함수는 scikit-learn의 `ElasticNet`에서 `l1_ratio=0`인 것과 같아요.

  ```python
  >>> import numpy as np
  >>> from sklearn.linear_model import Ridge
  >>> Xn, yn = np.array(X.tolist()), np.array(y.tolist())
  >>> m = Ridge(alpha=0.1 * 40).fit(Xn, yn)
  >>> bool(np.allclose(np.r_[m.intercept_, m.coef_], r.params.tolist(), rtol=1e-12))
  True
  >>> round(m.score(Xn, yn), 10) == round(r.rsquared, 10)
  True
  ```

- `y`가 모두 같으면 `rsquared`가 NaN이에요. scikit-learn의 `score`는 이때 NaN 대신 1.0(예측이 정확할 때)이나 0.0을 내요.
- 절편은 둘 다 벌점 밖이고 기본으로 넣어요. scikit-learn에는 `standardize`가 없어서, 같은 일을 하려면 `StandardScaler`로 열을 바꾼 뒤 계수를 되돌려야 해요(그때 척도도 모표준편차예요).
- 결과는 `coef_`, `intercept_` 대신 `params` 하나(절편이 `params[0]`)이고, `alpha`에 배열을 주면 경로가 나와요(scikit-learn의 `Ridge`는 배열 `alpha`를 반응 열마다의 값으로 읽어요).
- R의 glmnet(`alpha = 0`)은 정규분포에서 `y`를 모표준편차 $s_y$로 나눠 풀고 되돌리므로, glmnet의 `lambda`는 여기의 `alpha = lambda / s_y`에 해당해요(같은 표준화 설정에서). glmnet은 기본으로 열을 표준화하고(`standardize = TRUE`), 여기는 기본이 표준화하지 않음이에요.
