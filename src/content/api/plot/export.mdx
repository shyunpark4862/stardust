## 한눈에 보기

`fig.save(path)`는 확장자를 보고 형식을 골라 파일을 써요. 논문에는 PDF, 웹에는 SVG, 슬라이드나 메신저에는 PNG를 흔히 써요.

```python
>>> import pathlib, tempfile
>>> import stardust as sd
>>> x = sd.linspace(0, 4, 200)
>>> fig = sd.plot.line(x, x * sd.exp(-x), label="response")
>>> fig = fig.area(x, x * sd.exp(-x) * 0.9, x * sd.exp(-x) * 1.1, color="C0", alpha=0.2)
>>> fig = fig.xlabel(r"time $t$ (h)").ylabel("level")
>>> out = pathlib.Path(tempfile.mkdtemp())
>>> _ = fig.save(out / "fig1.pdf")
>>> _ = fig.save(out / "fig1.svg")
>>> _ = fig.save(out / "fig1.png", dpi=600)
>>> sorted(p.name for p in out.iterdir())
['fig1.pdf', 'fig1.png', 'fig1.svg']
```

`save`는 `fig` 자신을 돌려줘요. 여기서는 셸에 repr이 찍히지 않게 `_`에 받았어요.

## 세 형식

| 형식 | 무엇이 들어가나요 | 어디에 |
|---|---|---|
| PDF | 선, 채움, 글자가 모두 벡터. 쪽의 크기가 그림의 크기(mm) 그대로예요 | LaTeX 논문(`\includegraphics`), 인쇄 |
| SVG | PDF와 같은 벡터. 크기는 pt로 적혀요 | 웹 페이지, 벡터 편집기 |
| PNG | 화소의 그림. 너비는 `width / 25.4 × dpi` 화소예요 | 슬라이드, 문서 편집기, 메신저 |

세 파일은 모두 같은 장면(그리기 전의 도형 목록)에서 나와요. 그래서 PDF와 PNG 사이에 선의 굵기나 글자의 자리가 달라지는 일이 없어요.

- **글자는 윤곽선이에요.** 모든 글자를 글리프의 윤곽선(경로)으로 넣어요. 글꼴 파일을 묶지 않으므로 어느 컴퓨터에서 열어도 같은 모양이지만, PDF 뷰어에서 글자를 고르거나 찾을 수는 없어요.
- **벡터 파일 안의 그림.** 3D 곡면과 2만 개가 넘는 점 묶음은 PDF와 SVG 안에 화소의 그림으로 들어가요. 그 해상도가 `dpi`예요. 축과 글자는 그 위에 벡터로 얹혀서 확대해도 또렷해요.
- **아주 긴 선.** 점이 8천 개가 넘는 선은 화면의 아주 좁은 세로 띠마다 처음, 가장 낮은, 가장 높은, 마지막 점만 남겨 적어요. 보이는 모양은 같고 파일이 작아요.
- **시각을 적지 않아요.** PDF의 만든 날짜 같은 필드가 없어서, 같은 그림을 다시 저장해도 파일이 바이트까지 같아요([같은 그림, 같은 바이트](#같은-그림-같은-바이트)).

```python
>>> fig.save(out / "fig1.jpg")
Traceback (most recent call last):
    ...
ValueError: save(): 'path' must end in '.pdf', '.svg' or '.png', not '.jpg'
```

## 파일 대신 값으로: to_svg, to_pdf, to_png

파일을 쓰지 않고 내용만 받을 때는 `to_svg()`(str), `to_pdf()`(bytes), `to_png(dpi=)`(bytes)예요. 웹 서버가 그림을 바로 돌려주거나, 다른 문서에 끼워 넣을 때 써요. `save`가 쓰는 내용과 바이트까지 같아요.

```python
>>> svg = fig.to_svg()
>>> svg[:40]
'<svg xmlns="http://www.w3.org/2000/svg" '
>>> pdf = fig.to_pdf()
>>> pdf[:8]
b'%PDF-1.4'
>>> pdf == (out / "fig1.pdf").read_bytes()
True
```

PDF의 쪽 크기는 그림의 크기 그대로예요. 89 mm는 252.28 pt(1 pt = 1/72 인치)예요.

```python
>>> import re
>>> re.search(rb"/MediaBox \[[^\]]*\]", pdf).group()
b'/MediaBox [0 0 252.2835 193.5838]'
>>> round(fig.width / 25.4 * 72, 4), round(fig.height / 25.4 * 72, 4)
(252.2835, 193.5838)
```

## dpi

`dpi`는 인치당 화소 수예요. PNG의 화소 수가 `dpi`로 정해지고, 그림의 크기(mm)는 그대로예요. 89 mm 너비의 그림은 300 dpi에서 1051 화소, 600 dpi에서 2102 화소예요.

```python
>>> import struct
>>> png = fig.to_png()
>>> struct.unpack(">II", png[16:24])
(1051, 807)
>>> struct.unpack(">II", fig.to_png(dpi=600)[16:24])
(2102, 1613)
```

PNG 파일의 앞 24바이트에 너비와 높이(화소)가 적혀 있어서 위처럼 읽었어요. 학술지가 화소 그림을 받을 때는 흔히 300 dpi 이상, 선 그림은 600 dpi 이상을 바라요. 같은 그림을 더 크게 보이려면 `dpi`가 아니라 그림의 크기(`width`)를 바꿔요. 그래야 글자와 선이 함께 커져요.

## 노트북에서 보기

Jupyter 노트북에서 셀의 마지막 값이 `Figure`면 그림이 보여요. `Figure`가 SVG와 PNG 두 꼴을 다 내주고, 노트북은 보통 SVG를 골라 보여요. 이때 3D 곡면처럼 그림으로 들어가는 부분은 200 dpi로 구워요.

```python
fig = sd.plot.function(sd.special.gamma, -4, 4)
fig.xlabel(r"$x$")          # 셀의 마지막 줄: 그림이 보여요
```

그림을 고치는 메서드도 `fig`를 돌려주므로, 셀의 마지막 줄이 고치는 메서드여도 고친 그림이 바로 보여요.

## 언제 그리나요

`line`, `xlabel` 같은 메서드는 그림에 할 일을 적어 둘 뿐이에요. 출력(`save`, `to_svg`, `to_pdf`, `to_png`, `scene`, 노트북 표시)을 처음 부를 때 한꺼번에 해요.

1. 칸마다 범위와 눈금을 정해요.
2. 그림의 모든 글자를 모아 LaTeX로 한 번에 조판해요(캐시에 있는 글자는 건너뛰어요).
3. 잰 글자의 크기로 여백과 칸의 크기를 풀어요.
4. 장면을 만들어요.
5. 장면을 요청한 형식으로 적어요.

장면은 그림을 고치는 메서드를 부를 때까지 남아 있어서, 같은 그림을 PDF와 PNG로 잇달아 내보내도 1–4는 한 번이에요. 조판 오류와 TeX가 없다는 에러도 이때 나고, 메시지 앞에는 부른 출력 메서드의 이름이 붙어요.

```python
>>> bad = sd.plot.line([0, 1], [0, 1]).xlabel("50% of")
>>> _ = bad.save(out / "bad.pdf")
Traceback (most recent call last):
    ...
ValueError: save(): LaTeX could not typeset '50% of': an unescaped % (write \%)
```

## 같은 그림, 같은 바이트

같은 기계, 같은 스레드 수에서 같은 입력으로 지은 그림은 몇 번을 내보내도 같은 바이트예요. 파일에 시각, 임시 파일 이름, 난수가 들어가지 않아요. 그림 파일을 버전 관리에 넣거나 테스트에서 견줄 수 있어요.

```python
>>> def make():
...     f = sd.plot.line(x, x * sd.exp(-x), label="response")
...     return f.xlabel(r"time $t$ (h)")
>>> make().to_pdf() == make().to_pdf(), make().to_png() == make().to_png()
(True, True)
```

지금은 스레드 수가 달라도 같은 바이트가 나와요(약속은 아니에요).

## scene: 그리기 전의 장면

`fig.scene()`은 배치를 마친 그림을 도형의 목록(dict)으로 줘요. 세 출력이 읽는 것이 바로 이 장면이에요. 그림이 무엇을 어디에 그렸는지 테스트에서 확인하거나, 배치를 살펴볼 때 써요.

```python
>>> sc = fig.scene()
>>> sorted(sc)
['font', 'height', 'items', 'width']
>>> round(sc["width"], 4), sc["font"]
(252.2835, 'serif')
>>> sorted({item["type"] for item in sc["items"]})
['path', 'text']
>>> [item["s"] for item in sc["items"] if item["type"] == "text"][-3:]
['time $t$ (h)', 'level', 'response']
```

- 길이의 단위는 bp(1/72 인치)예요. 원점은 왼쪽 위이고 y는 아래로 자라요.
- `items`는 그리는 순서대로이고, 도형의 종류(`type`)는 넷이에요. `'path'`는 경로(채움, 획, 점선, 자르기), `'markers'`는 같은 점 기호를 여러 자리에 찍은 묶음, `'image'`는 화소의 그림, `'text'`는 글자(LaTeX 원문 `s`, 자리, 크기, 맞춤, 회전, 색)예요.
- 색은 0과 1 사이의 (r, g, b, a)예요.

## matplotlib을 아는 분께

| matplotlib | sd.plot |
|---|---|
| `fig.savefig("a.pdf", dpi=300)` | `fig.save("a.pdf", dpi=300)` |
| `bbox_inches="tight"` | 없어요. 바깥 크기를 고정하고 여백을 언제나 글자에 맞춰 풀어요 |
| `format="pdf"` | 없어요. 확장자가 정해요. 값으로 받으려면 `to_pdf()` |
| `.jpg`, `.eps`, `.pgf` | 없어요. PDF, SVG, PNG만 |
| PDF에 글꼴을 묶어 넣어요 | 글자는 윤곽선이에요. 글꼴을 묶지 않아요 |
| `metadata={"CreationDate": None}`로 날짜를 빼야 같은 파일 | 늘 같은 바이트 |
