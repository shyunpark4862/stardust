## 한눈에 보기

집 여섯 채와 정류장 네 곳의 위치가 있을 때, 집마다 걸어갈 만한 거리(여기서는 0.3) 안의 정류장을 모두 찾아볼게요. 두 집합을 각각 [`KDTree`](/api/spatial/KDTree/)로 만들고, 집의 트리에서 정류장의 트리로 `query_ball_tree`를 불러요.

```python
>>> import stardust as sd
>>> homes = sd.spatial.KDTree([[0.1, 0.1], [0.2, 0.8], [0.5, 0.5], [0.8, 0.2], [0.9, 0.9], [0.5, 0.95]])
>>> stops = sd.spatial.KDTree([[0.0, 0.0], [0.3, 0.7], [0.7, 0.3], [0.6, 0.9]])
>>> res = homes.query_ball_tree(stops, 0.3)
>>> res
RadiusResult(shape=(6, 4), nnz=6)
>>> for i in range(res.shape[0]):
...     a, b = res.indptr[i], res.indptr[i + 1]
...     print(i, res.indices[a:b], res.distances[a:b])
0 [0] [0.14142135623730953]
1 [1] [0.14142135623730956]
2 [1 2] [0.282842712474619 0.282842712474619]
3 [2] [0.14142135623730956]
4 [] []
5 [3] [0.11180339887498944]
```

결과의 행 i는 집 i의 답이에요. 열 번호(`indices`)는 정류장의 색인이고, 같은 자리의 `distances`가 그 정류장까지의 거리예요. 행 안은 색인 오름차순이에요. 정류장이 반경 안에 하나도 없는 4번 집은 빈 행이에요.

## 무엇과 같나요

`homes.query_ball_tree(stops, r)`는 집의 좌표 하나하나로 정류장 트리에 [`query_ball_point`](/api/spatial/query_ball_point/)를 부른 것과 같아요. 함수로 쓰면 [`radius_neighbors(homes.data, stops.data, r)`](/api/spatial/radius_neighbors/)예요. 세 결과는 색인, 거리, `indptr`가 바이트까지 같아요.

```python
>>> A = homes.query_ball_tree(stops, 0.3)
>>> B = stops.query_ball_point(homes.data, 0.3)
>>> C = sd.spatial.radius_neighbors(homes.data, stops.data, 0.3)
>>> all(bool(sd.all(X.indices == A.indices)) and bool(sd.all(X.distances == A.distances)) for X in (B, C))
True
```

다른 점은 찾는 방법이에요. `query_ball_tree`는 두 트리를 함께 내려가면서 서로 멀리 떨어진 상자의 짝을 통째로 건너뛰어요. 두 집합이 모두 크고 이미 트리로 쥐고 있을 때 알맞아요.

방향을 바꾸면 결과는 전치예요. `stops.query_ball_tree(homes, r)`의 행은 정류장이고 열은 집이에요. 희소 행렬로 바꿔 보면 서로 전치 관계인 것을 볼 수 있어요.

```python
>>> S1 = homes.query_ball_tree(stops, 0.3).tocsr().toarray()
>>> S2 = stops.query_ball_tree(homes, 0.3).tocsr().toarray()
>>> bool(sd.all(S1 == S2.T))
True
```

## 자기 자신과

`other`에 자기 자신을 주면 점마다 같은 집합 안에서 반경 안의 점을 찾아요. 자기 자신(거리 0)도 결과에 들어가요.

```python
>>> res = homes.query_ball_tree(homes, 0.5)
>>> res.indices[res.indptr[2]:res.indptr[3]]
array([1, 2, 3, 5], dtype=int64)
```

2번 집(0.5, 0.5)의 행에 자기 자신인 2가 들어 있어요.

같은 집합 안의 짝을 한 번씩만 원하면(자기 자신 없이, $(i, j)$와 $(j, i)$ 가운데 하나만) [`query_pairs`](/api/spatial/query_pairs/)가 더 알맞아요.

## 경계와 반경

거리가 r과 꼭 같은 짝도 들어가요($d \le r$). 판정은 결과의 `distances`에 담기는 거리 그대로로 해요. `r`은 수 하나예요. 행마다 다른 반경이 필요하면 `query_ball_point`에 반경 배열을 줘요.

```python
>>> homes.query_ball_tree(stops, [0.3])
Traceback (most recent call last):
    ...
TypeError: query_ball_tree(): 'r' must be an int or a float, not list
>>> homes.query_ball_tree(stops, -0.1)
Traceback (most recent call last):
    ...
ValueError: query_ball_tree(): 'r' must be a nonnegative number or inf, not -0.1
```

결과는 트리의 `leafsize`, [스레드 수](/api/array/threads/)와 상관없이 언제나 같아요.

## 조심할 점

### 상대도 KDTree여야 해요

`other`에 좌표 배열을 주면 에러예요. 좌표가 있으면 `query_ball_point`에 바로 주거나 트리로 만들어서 줘요. 두 트리는 차원이 같아야 해요.

```python
>>> homes.query_ball_tree([[0.0, 0.0]], 0.3)
Traceback (most recent call last):
    ...
TypeError: query_ball_tree(): 'other' must be a KDTree, not list
>>> homes.query_ball_tree(sd.spatial.KDTree([[0.0, 0.0, 0.0]]), 0.3)
Traceback (most recent call last):
    ...
ValueError: query_ball_tree(): 'other' must have the same m as this tree (2), not 3
```

### 결과의 크기

결과는 찾은 짝의 수에 비례해요. 두 집합이 크고 반경이 크면 짝이 아주 많아질 수 있어요. 짝의 목록이 이 컴퓨터의 물리 메모리를 넘을 만큼 커지면 찾기를 멈추고 `MemoryError`로 알려 줘요. 짝의 수만 필요하면 [`count_neighbors`](/api/spatial/count_neighbors/)가 목록을 만들지 않고 세어요.

## scipy·sklearn을 아는 분께

- 결과는 `RadiusResult`예요. scipy는 list의 list(행마다 색인의 list)를 돌려줘요. 행 i의 list는 `res.indices[res.indptr[i]:res.indptr[i+1]]`로 꺼내요.
- 행 안은 언제나 색인 오름차순이고 거리도 함께 담겨요. scipy의 결과에는 거리가 없어요.
- 음수나 NaN 반경은 `ValueError`예요. scipy는 반경을 제곱해서 비교해 $r = -1$이 $r = 1$처럼 동작해요.
- `p`는 이름으로만 받고 `eps`는 없어요. 결과는 언제나 정확해요.
- `other`가 `KDTree`가 아니면 `TypeError`, 차원이 다르면 `ValueError`예요.
- 희소 행렬이 필요하면 `res.tocsr()`나 [`sparse_distance_matrix`](/api/spatial/sparse_distance_matrix/)를 써요. 둘은 같은 행렬이에요.
