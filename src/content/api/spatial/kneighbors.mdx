## 한눈에 보기

`kneighbors`는 질의점마다 데이터에서 **가장 가까운 k개**를 찾아요. k-최근접 이웃 분류, 추천에서 비슷한 항목 고르기, 가장 가까운 시설 찾기, 군집의 중심에 점 배정하기처럼 "가까운 것 몇 개"가 필요한 곳은 대부분 이 질문이에요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(7)
>>> XB = rng.random((40, 2))
>>> XA = sd.asarray([[0.3, 0.7], [0.75, 0.35]])
>>> d, i = sd.spatial.kneighbors(XA, XB, k=4)
>>> i
array([[24, 30, 19, 13],
       [23,  0,  7, 32]], dtype=int64)
>>> d
array([[0.09648183758079247, 0.10131936228143196, 0.12245073195627522,
         0.1671599230922664],
       [0.10093524495672283, 0.14562929126822277, 0.18527244108012905,
        0.19710422543131256]], dtype=float64)
```

질의점 (0.3, 0.7)에서 가장 가까운 점은 `XB`의 24번 점이고 거리가 약 0.096이에요. 그다음이 30, 19, 13번이에요. 행마다 가까운 순서로 줄을 서요.

```python
>>> xs, ys = [], []
>>> for a in range(2):
...     for j in i[a].tolist():
...         xs += [float(XA[a, 0]), float(XB[j, 0]), sd.nan]
...         ys += [float(XA[a, 1]), float(XB[j, 1]), sd.nan]
>>> fig = sd.plot.Figure(width=80, height=76)
>>> fig = fig.line(xs, ys, color="gray")
>>> fig = fig.scatter(XB[:, 0], XB[:, 1], label="XB")
>>> fig = fig.scatter(XA[:, 0], XA[:, 1], shape="s", size=4, label="XA")
>>> fig = fig.xlim(0, 1).ylim(0, 1).legend(loc="top")
```

## 결과 읽기

결과는 [`QueryResult`](/api/spatial/results/#queryresult)예요. `distances`와 `indices` 두 필드가 있고, `d, i = ...`처럼 거리, 색인 순서로 풀려요. 둘 다 쓰기 금지 배열이에요.

- 행 r은 질의점 `XA[r]`의 이웃이고, 열은 가까운 순서예요. `indices[r, c]`는 `XB`의 행 번호, `distances[r, c]`는 그 점까지의 거리예요.
- 거리가 같으면 색인이 작은 점이 먼저예요. 순서는 언제나 (거리, 색인)이고, 실행이나 스레드 수에 따라 바뀌지 않아요.
- 결과의 모양은 `k`가 정해요. 정수 k면 (mA, k), `k=1`(기본값)이면 마지막 축을 없앤 (mA,), 시퀀스면 (mA, 시퀀스 길이)예요.

```python
>>> X = sd.asarray([[0.0, 0.0], [3.0, 4.0], [6.0, 8.0], [0.0, 1.0], [0.0, 1.0]])
>>> sd.spatial.kneighbors(X[:3], X)
QueryResult(distances=array([0.0, 0.0, 0.0], dtype=float64), indices=array([0, 1, 2], dtype=int64))
```

`X`의 점 3과 점 4는 같은 자리 (0, 1)에 있어요. 아래 예제들이 이 다섯 점을 써요.

### 정의로 정해지는 결과

`kneighbors(XA, XB, k=k)`의 행 r은 [`cdist(XA, XB)`](/api/spatial/cdist/)의 행 r에서 거리가 `distance_upper_bound`보다 작은 칸을 (거리, 열 번호)로 정렬해 앞 k개를 고른 것과 같아요. 돌려주는 거리는 `cdist`의 그 칸과 마지막 비트까지 같아요. 계산 방법(모든 짝을 재기, 행렬 곱으로 후보 추리기, KD 트리)은 입력의 모양으로 고르고 빠르기만 바꿔요. 같은 입력이면 어느 방법으로 계산해도, 스레드가 몇 개여도 결과가 바이트까지 같아요.

```python
>>> C = sd.spatial.cdist(XA, XB)
>>> bool(sd.all(sd.min(C, axis=1) == sd.spatial.kneighbors(XA, XB).distances))
True
```

## k: 몇 개, 또는 몇째

정수 k는 가까운 순서로 k개예요. 데이터 점보다 많이 달라고 하면 모자라는 자리를 거리 inf, 색인 mB(데이터 점의 수)로 채워요. mB는 실제 행 번호가 될 수 없어서 채움 자리를 가리는 표시가 돼요.

```python
>>> sd.spatial.kneighbors(X[:1], X[:3], k=5)
QueryResult(distances=array([[ 0.0,  5.0, 10.0,  inf,  inf]], dtype=float64), indices=array([[0, 1, 2, 3, 3]], dtype=int64))
```

시퀀스를 주면 **순위의 목록**이에요. 1부터 세고, 준 순서 그대로 그 순위의 이웃을 돌려줘요. 셋째 이웃만 필요할 때 `k=3`으로 셋을 다 받지 않아도 돼요.

```python
>>> sd.spatial.kneighbors(X, X, k=[1, 3]).indices
array([[0, 4],
       [1, 4],
       [2, 3],
       [3, 0],
       [3, 0]], dtype=int64)
>>> sd.spatial.kneighbors(X[:1], X, k=[3, 1])
QueryResult(distances=array([[1.0, 0.0]], dtype=float64), indices=array([[4, 0]], dtype=int64))
```

`k=[3, 1]`은 셋째 이웃을 먼저, 첫째를 다음에 줘요. 같은 순위를 두 번 써도 되고, 데이터 점 수보다 큰 순위는 채움 값이에요. `k`는 1 이상의 정수만 받아요. 0, 음수, 빈 시퀀스는 `ValueError`, `True`나 `2.0`은 `TypeError`예요.

```python
>>> sd.spatial.kneighbors(X, X, k=0)
Traceback (most recent call last):
    ...
ValueError: kneighbors(): 'k' must be at least 1, not 0
>>> sd.spatial.kneighbors(X, X, k=2.0)
Traceback (most recent call last):
    ...
TypeError: kneighbors(): 'k' must be an int or a sequence of ints, not float
```

## 자기 자신을 빼고 찾기

`XA`와 `XB`가 같은 점 집합이면 모든 점의 가장 가까운 점은 거리 0인 자기 자신이에요. 그래서 "각 점의 가장 가까운 **다른** 점"은 흔히 `k=2`로 찾고 첫 열을 버려요. 그런데 같은 자리의 점이 있으면 이 방법이 틀려요.

```python
>>> d, i = sd.spatial.kneighbors(X, X, k=2)
>>> i
array([[0, 3],
       [1, 3],
       [2, 1],
       [3, 4],
       [3, 4]], dtype=int64)
```

점 4의 행이 `[3, 4]`예요. 점 3과 점 4는 점 4에서 둘 다 거리 0인 동점이라 색인이 작은 3이 먼저 와요. 첫 열을 버리면 점 4의 "가장 가까운 다른 점"이 자기 자신 4가 돼요. 첫 열이 자기 자신인지 확인해서 골라야 해요.

```python
>>> own = i[:, 0] == sd.arange(5)
>>> sd.where(own, i[:, 1], i[:, 0])
array([3, 3, 1, 4, 3], dtype=int64)
>>> sd.where(own, d[:, 1], d[:, 0])
array([              1.0, 4.242640687119285,               5.0,
                     0.0,               0.0], dtype=float64)
```

같은 자리의 점이 세 개 이상이면 자기 자신이 셋째 자리 뒤로 밀릴 수도 있어요. 그런 데이터에서 다른 점 k개가 필요하면 `k`를 같은 자리의 점 수만큼 넉넉히 주고 행마다 자기 색인을 걸러 내요.

## distance_upper_bound: 이보다 가까운 것만

`distance_upper_bound`를 주면 거리가 그 값보다 **작은** 이웃만 돌려줘요. 경계와 거리가 꼭 같은 점은 빠져요. 모자라는 자리는 k보다 점이 적을 때처럼 (inf, mB)예요. "가까운 k개를 찾되 너무 먼 것은 이웃으로 치지 않는다"는 질문이에요.

```python
>>> sd.spatial.kneighbors(X[2:3], X, k=2, distance_upper_bound=5.0)
QueryResult(distances=array([[0.0, inf]], dtype=float64), indices=array([[2, 5]], dtype=int64))
>>> sd.spatial.kneighbors(X[2:3], X, k=2, distance_upper_bound=5.5)
QueryResult(distances=array([[0.0, 5.0]], dtype=float64), indices=array([[2, 1]], dtype=int64))
```

점 2 (6, 8)에서 점 1까지는 꼭 5라서 상한 5에서는 빠지고 5.5에서는 들어가요. 경계를 넣고 싶으면(d ≤ r) 반경 안의 모든 점을 찾는 [`radius_neighbors`](/api/spatial/radius_neighbors/)를 쓰세요.

기본값 inf에서도 같은 규칙이라, 거리가 inf이거나 NaN인 짝은 이웃으로 나오지 않아요. 넘치는 `sqeuclidean`, 영벡터와의 `cosine`, 분모가 0인 `braycurtis` 같은 것이에요.

```python
>>> A = sd.asarray([[1.0, 0.0]])
>>> B = sd.asarray([[0.0, 0.0], [1.0, 1.0], [2.0, 0.0]])
>>> sd.spatial.cdist(A, B, metric="cosine")
array([[               nan, 0.2928932188134524,                0.0]], dtype=float64)
>>> sd.spatial.kneighbors(A, B, k=3, metric="cosine")
QueryResult(distances=array([[               0.0, 0.2928932188134524,                inf]], dtype=float64), indices=array([[2, 1, 3]], dtype=int64))
```

영벡터 (0, 0)과의 `cosine` 거리는 NaN이라 순위에 들지 못하고, 셋째 자리는 채움 값이에요.

상한은 0 이상의 수나 inf여야 해요. 음수와 NaN은 `ValueError`예요.

## 거리 고르기

`metric`과 그 인자(`p`, `w`, `V`, `VI`)는 [`cdist`](/api/spatial/cdist/)와 같은 규칙이에요. 열네 가지 거리를 모두 받아요. 거리를 바꾸면 이웃도 바뀌어요.

```python
>>> sd.spatial.kneighbors(X[:1], X, k=3, metric="chebyshev")
QueryResult(distances=array([[0.0, 1.0, 1.0]], dtype=float64), indices=array([[0, 3, 4]], dtype=int64))
>>> sd.spatial.kneighbors(X[:1], X, k=2, metric="cityblock", w=[1.0, 0.0])
QueryResult(distances=array([[0.0, 0.0]], dtype=float64), indices=array([[0, 3]], dtype=int64))
```

둘째 예는 가중치로 첫 열(가로 좌표)만 본 거리라, 가로 좌표가 같은 점 3이 거리 0이에요.

### 지도 위의 이웃: haversine

위도와 경도로 적은 점은 `metric='haversine'`으로 찾아요. 입력은 (위도, 경도)의 두 열이고 단위는 라디안이에요. 거리는 반지름 1인 구 위의 중심각이라 지구 반지름(평균 약 6371 km)을 곱하면 km예요.

```python
>>> names = ["서울", "부산", "도쿄", "베이징", "상하이", "오사카"]
>>> lat = [37.5665, 35.1796, 35.6762, 39.9042, 31.2304, 34.6937]
>>> lon = [126.9780, 129.0756, 139.6503, 116.4074, 121.4737, 135.5023]
>>> P = sd.deg2rad(sd.asarray([lat, lon]).T)
>>> d, i = sd.spatial.kneighbors(P, P, k=2, metric="haversine")
>>> for a, b, km in zip(names, i[:, 1].tolist(), (d[:, 1] * 6371.0).tolist()):
...     print(a, "→", names[b], round(km), "km")
서울 → 부산 325 km
부산 → 서울 325 km
도쿄 → 오사카 392 km
베이징 → 서울 952 km
상하이 → 부산 832 km
오사카 → 도쿄 392 km
```

도시마다 가장 가까운 다른 도시예요(첫 열은 거리 0인 자기 자신이라 둘째 열을 읽었어요). 점이 많아도 지구 전체를 다 재지 않고 가까운 후보만 재서 빨라요. 돌려주는 거리는 언제나 [`haversine`](/api/spatial/haversine/)의 값 그대로예요. 위도와 경도를 도 단위로 넣으면 틀린 이웃이 나오니 꼭 라디안으로 바꿔요.

## 큰 데이터에서

`kneighbors`는 (mA, mB)의 거리 행렬을 만들지 않아요. 질의점 10만 개와 데이터 점 100만 개면 거리 행렬은 800 GB지만, `kneighbors`의 작업 메모리는 입력의 크기와 상관없는 상한 안이고 결과는 mA × k × 16바이트(거리 8 + 색인 8)예요. 결과 자체가 물리 메모리보다 크면 할당 전에 `MemoryError`예요.

```python
>>> sd.spatial.kneighbors(X, X, k=10**12)
Traceback (most recent call last):
    ...
MemoryError: kneighbors(): cannot allocate 80000000000000 bytes: more than this machine's physical memory
```

좌표가 몇 개뿐인 데이터에서는 안에서 `XB`로 KD 트리를 만들어 먼 점들을 재지 않고 건너뛰어요. 같은 `XB`에 질의를 여러 번 한다면 [`KDTree`](/api/spatial/KDTree/)를 한 번 만들어 [`query`](/api/spatial/query/)를 되풀이하는 편이 트리를 매번 만들지 않아 나아요. 두 쪽의 답은 같아요.

```python
>>> tree = sd.spatial.KDTree(XB)
>>> a = tree.query(XA, k=4)
>>> b = sd.spatial.kneighbors(XA, XB, k=4)
>>> bool(sd.all(a.indices == b.indices)), bool(sd.all(a.distances == b.distances))
(True, True)
```

`KDTree`는 Minkowski 계열 거리(`p`로 고르는 `euclidean`, `cityblock`, `chebyshev`, `minkowski`)만 받아요. 다른 거리의 이웃은 `kneighbors`로 찾아요.

## 조심할 점

### XA도 2차원으로

점 하나를 찾을 때도 `XA`는 (1, n)이에요. 1차원은 `ValueError`예요. 점 하나의 결과를 스칼라로 받고 싶으면 `KDTree.query`에 1차원 점을 줘요.

```python
>>> sd.spatial.kneighbors(XA[0], XB)
Traceback (most recent call last):
    ...
ValueError: kneighbors(): 'XA' must have 2 dimensions, not 1
```

### NaN·inf가 있으면 에러

데이터나 질의점에 NaN이나 inf가 있으면 `ValueError`예요. NaN과는 크기를 견줄 수 없어 "가장 가까운"이 정해지지 않기 때문이에요. 결측이 있는 행을 먼저 걸러 내요([공간 영역의 기본](/api/spatial/basics/#nan과-inf)).

```python
>>> sd.spatial.kneighbors(XA, sd.asarray([[0.0, sd.inf]]))
Traceback (most recent call last):
    ...
ValueError: kneighbors(): 'XB' must be finite
```

### k는 키워드로

`kneighbors(XA, XB, 3)`은 `TypeError`예요. `k=3`으로 넘겨요.

```python
>>> sd.spatial.kneighbors(XA, XB, 3)
Traceback (most recent call last):
    ...
TypeError: kneighbors(): takes 2 positional arguments but 3 were given
```

### 동점은 반올림한 거리로 견줘요

순서는 돌려준 float64 거리의 순서예요. 참 거리가 아주 조금 다른 두 점이 반올림 뒤에 같은 값이면 색인 순서를 따라요. 정수 좌표처럼 거리가 정확히 계산되는 데이터에서는 참 거리의 순서와 정확히 같아요.

## scipy·sklearn을 아는 분께

- scipy에는 이 함수가 없어요. `KDTree(XB).query(XA, k=k)`와 같은 결과이고(Minkowski 계열), 다른 거리도 받아요. 이름은 sklearn `NearestNeighbors`의 메서드에서 왔어요. `NearestNeighbors(n_neighbors=k).fit(XB).kneighbors(XA)`는 `kneighbors(XA, XB, k=k)`이고, 반환 순서 (거리, 색인)도 같아요. 클래스는 없어요.
- sklearn의 `pairwise_distances_argmin_min(X, Y)`는 `kneighbors(X, Y)`예요. sklearn은 `(argmin, distances)`, 여기서는 `(distances, indices)` 순서로 풀려요. `pairwise_distances_argmin(X, Y)`는 `kneighbors(X, Y).indices`예요.
- **거리는 언제나 직접 계산한 값이에요.** sklearn은 유클리드 거리를 ‖x‖² + ‖y‖² − 2x·y로 펼쳐 구해서, 원점에서 먼 가까운 점들(1e8 + [0, 1)³ 같은 자료)에서 거리를 모두 0으로 내고 가장 가까운 점을 틀리게 고를 수 있어요.
- **동점은 (거리, 색인) 순서로 약속해요.** scipy와 sklearn은 약속하지 않고 실제로도 달라요.
- k가 데이터 점보다 크면 (inf, mB)로 채워요(scipy와 같아요). sklearn은 에러예요.
- `k`는 키워드로만 받고 bool·실수는 `TypeError`, 0·음수·`k=[0]`은 `ValueError`예요.
- `distance_upper_bound`의 음수와 NaN은 `ValueError`예요. scipy는 상한을 제곱해 견주어 −1이 1처럼 동작하고, NaN이면 모든 자리를 채움 값으로 줘요.
- `workers`, `eps`, 호출 가능한 `metric`은 없어요. 결과는 언제나 정확한 이웃이에요.
- 데이터의 NaN·inf는 `ValueError`예요(scipy의 `KDTree`, sklearn과 같아요).
