## 한눈에 보기

`tree.query_pairs(r)`는 트리의 점들 가운데 서로 거리가 r 이하인 짝을 모두 찾아요. 짝 $(i, j)$와 $(j, i)$는 같은 짝이라 $i \lt j$인 쪽으로 한 번만 나오고, 자기 자신과의 짝 $(i, i)$는 나오지 않아요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(21)
>>> pts = rng.random((40, 2))
>>> tree = sd.spatial.KDTree(pts)
>>> P = tree.query_pairs(0.12)
>>> P.shape
(28, 2)
>>> P[:4]
array([[ 0,  1],
       [ 2, 33],
       [ 3,  6],
       [ 5, 24]], dtype=int64)
```

점 40개 사이의 짝 780개 가운데 거리 0.12 이하인 짝이 28개예요. 0번과 1번, 2번과 33번이 가까이 붙어 있어요. 짝마다 두 점을 선으로 이으면 가까운 점들이 어떻게 이어지는지 보여요.

## 결과 읽기

결과는 (짝의 수, 2) int64 배열이에요. 첫째 열이 i, 둘째 열이 j이고 언제나 $i \lt j$예요. 행은 i가 작은 순서로, i가 같으면 j가 작은 순서로 놓여요. 그래서 같은 입력이면 결과의 배열이 바이트까지 언제나 같아요.

짝의 거리가 필요하면 두 열로 좌표를 꺼내 거리 함수에 주면 돼요. 거리 함수는 행마다 따로 거리를 구해요. 같은 짝이면 `query_pairs`가 판정에 쓴 거리, [`pdist`](/api/spatial/pdist/)의 값과 비트까지 같아요.

```python
>>> d = sd.spatial.euclidean(pts[P[:, 0]], pts[P[:, 1]])
>>> d[:4]
array([ 0.1045733353778853, 0.09984763880505017, 0.04467410600106486,
       0.07468835499671406], dtype=float64)
>>> bool(sd.all(d <= 0.12))
True
```

## 무엇과 같나요

결과는 [`pdist(data)`](/api/spatial/pdist/)의 원소 가운데 r 이하인 짝과 정확히 같아요. `pdist`는 짝 $n(n-1)/2$개의 거리를 모두 만들지만, `query_pairs`는 트리로 먼 짝을 건너뛰고 가까운 짝만 봐요. 점이 많고 반경 안의 짝이 드물수록 그 차이가 커요.

```python
>>> D = sd.spatial.pdist(pts)
>>> int(sd.sum(D <= 0.12))
28
>>> sq = sd.spatial.squareform(D)
>>> bool(sd.all(sq[P[:, 0], P[:, 1]] == d))
True
```

`p`가 1, 2, inf면 `pdist`의 `metric='cityblock'`, `'euclidean'`, `'chebyshev'`, 그 밖의 p는 `metric='minkowski', p=p`와 같아요. 같은 반경이라도 거리의 종류에 따라 짝의 수가 달라요. 같은 두 점 사이에서 맨해튼 거리가 가장 길고 체비쇼프 거리가 가장 짧기 때문이에요.

```python
>>> tree.query_pairs(0.12, p=1).shape, tree.query_pairs(0.12, p=float("inf")).shape
((15, 2), (36, 2))
```

결과는 트리의 `leafsize`, [스레드 수](/api/array/threads/)와 상관없이 언제나 같아요.

## 겹친 점 찾기: `r=0`

경계가 들어가므로($d \le r$) `r=0`이면 좌표가 똑같은 점의 짝을 찾아요. 자료에 중복된 행이 있는지 볼 때 편해요.

```python
>>> dup = sd.spatial.KDTree([[1.0, 2.0], [3.0, 4.0], [1.0, 2.0], [5.0, 6.0], [3.0, 4.0], [1.0, 2.0]])
>>> dup.query_pairs(0.0)
array([[0, 2],
       [0, 5],
       [1, 4],
       [2, 5]], dtype=int64)
```

0번, 2번, 5번이 같은 점이라 그 셋의 짝 셋이, 1번과 4번이 같은 점이라 그 짝 하나가 나왔어요. 짝이 없으면 모양 (0, 2)의 빈 배열이에요.

```python
>>> tree.query_pairs(0.0).shape
(0, 2)
```

## 조심할 점

### 반경은 수 하나예요

`r`은 0 이상의 수 하나나 `inf`예요. 음수나 NaN은 에러예요. 반경을 여럿 바꿔 가며 짝의 수만 보려면 [`count_neighbors`](/api/spatial/count_neighbors/)에 반경 배열을 줘요. 목록을 만들지 않고 모든 반경의 수를 한 번에 세어요.

```python
>>> tree.query_pairs(-1)
Traceback (most recent call last):
    ...
ValueError: query_pairs(): 'r' must be a nonnegative number or inf, not -1
>>> tree.query_pairs([0.1, 0.2])
Traceback (most recent call last):
    ...
TypeError: query_pairs(): 'r' must be an int or a float, not list
```

### 반경이 크면 짝이 아주 많아요

짝의 수는 반경이 커질수록 빠르게 늘어나 많게는 $n(n-1)/2$개예요. 결과가 이 컴퓨터의 물리 메모리를 넘을 만큼 커지면 찾기를 멈추고 `MemoryError`로 알려 줘요. 짝의 수만 필요하면 `count_neighbors`가 목록을 만들지 않고 세어요.

## scipy·sklearn을 아는 분께

- 결과는 언제나 $(i, j)$의 사전 순서로 정렬된 (k, 2) int64 배열이에요. scipy의 기본은 순서 없는 `set`이고, `output_type='ndarray'`로 받아도 scipy가 돈 순서 그대로라 정렬되어 있지 않아요. `output_type` 인자는 없어요.
- 음수나 NaN 반경은 `ValueError`예요. scipy는 반경을 제곱해서 비교해 $r = -1$이 $r = 1$처럼 동작해요.
- 경계의 판정은 짝의 거리 그 자체로 해요. 그래서 결과는 `pdist`의 원소가 r 이하인 짝과 언제나 같아요.
- `p`는 이름으로만 받고 `eps`는 없어요. 결과는 언제나 정확해요.
