## 한눈에 보기

[BFGS와 L-BFGS-B](/api/optimize/quasi-newton/)는 반복마다 방향 $p_k$를 정하고, 그 직선 위에서 걸음 $\alpha_k$를 고르고(선 탐색), 걸음 $s_k = x_{k+1} - x_k$와 기울기의 변화 $y_k = g_{k+1} - g_k$로 곡률의 근사를 고쳐요.

| 무엇 | BFGS | L-BFGS-B |
|---|---|---|
| 곡률의 근사 | 헤시안 역행렬 $H_k$ (n × n) | 최근 쌍 $(s_i, y_i)$ m개의 압축 표현 |
| 방향 | $p_k = -H_k g_k$ | 일반화 Cauchy 점과 부분 공간 최소화 |
| 선 탐색 | scipy `_line_search_wolfe12`: dcsrch(Python 판), 실패하면 zoom | L-BFGS-B 3.0의 `lnsrlb`: dcsrch(C 판) |
| scipy와 | 같은 알고리즘, 반올림만큼 다름(갱신의 계산 순서) | 같은 알고리즘, 지금은 사용자 함수를 부르는 점이 비트까지 같음 |
| 파일 | `csrc/optimize/bfgs.cpp`, `wolfe.hpp` | `csrc/optimize/lbfgsb.cpp` |

두 방법 모두 기울기를 scipy의 `ScalarFunction`처럼 다뤄요(`csrc/optimize/objective.hpp`). 마지막 점의 f와 기울기를 기억해 같은 점에서는 다시 부르지 않고, 기울기는 사용자 `jac`, `jac=True`(fun의 두 번째 값), 차분 가운데 하나예요. 차분과 기억의 자세한 내용은 [구조](/internals/optimize/overview/)와 [수치 미분](/internals/optimize/derivatives/)에 있어요.

## BFGS

### 갱신

뉴턴 걸음 $-\nabla^2 f(x)^{-1} g$의 헤시안 역행렬을 $H_k$로 어림해요. 새 $H_{k+1}$은 두 조건을 만족해요.

- **할선 조건** $H_{k+1} y_k = s_k$: 방금 지나온 방향에서 기울기의 변화와 걸음이 맞도록 해요. 이차 함수라면 참 헤시안 역행렬이 꼭 만족하는 식이에요.
- $H_k$에 가장 가까운 대칭 행렬(가중 Frobenius 노름에서)이어야 해요.

그 답이 BFGS 갱신이에요($\rho_k = 1/(y_k^{\mathsf T} s_k)$).

$$
H_{k+1} = (I - \rho_k s_k y_k^{\mathsf T})\, H_k\, (I - \rho_k y_k s_k^{\mathsf T}) + \rho_k s_k s_k^{\mathsf T}
$$

$H_k$가 양정치이고 곡률 조건 $y_k^{\mathsf T} s_k > 0$이 서면 $H_{k+1}$도 양정치예요. 그래서 $p = -H g$는 늘 내리막 방향이에요. 곡률 조건은 선 탐색의 Wolfe 조건이 보장해요(아래). 볼록하고 두 번 미분 가능한 함수에서는 Wolfe 선 탐색으로 최솟값에 수렴하고, 해 근처에서 초선형으로 수렴해요(Powell 1976). Rosenbrock를 풀 때 해와의 거리 $e_k = \lVert x_k - x^*\rVert$의 비 $e_{k+1}/e_k$는 마지막 반복들에서 0.15, 0.60, 0.072, 0.015, 0.011로 줄었어요.

### O(n²)의 계산 순서

scipy는 위 식을 그대로 행렬곱 두 번($n^3$)으로 계산해요. 식을 펼치면 $n^2$만으로 같은 행렬이 나와요. $H$가 대칭이므로 $v = H y$라고 두면

$$
H_{k+1} = H - \rho\,(s v^{\mathsf T} + v s^{\mathsf T}) + (\rho^2\, y^{\mathsf T} v + \rho)\, s s^{\mathsf T}
$$

예요. 행렬·벡터 곱 하나(dgemv)와 원소마다의 갱신이에요. (i, j)와 (j, i) 원소는 대칭인 항의 순서만 바꾼 같은 식이라 반올림도 같아서, $H$는 비트까지 대칭으로 남아요.

```cpp
                    // csrc/optimize/bfgs.cpp
                    cblas_dgemv(
                        CblasRowMajor, CblasNoTrans, ln, ln, 1.0, Hk.data(), ln, yk.data(), 1, 0.0, Hy.data(), 1
                    );
                    double yHy = 0;
                    for (std::size_t i = 0; i < n; ++i) yHy += yk[i] * Hy[i];
                    const double c = rhok * rhok * yHy + rhok;
                    // entry (i, j) and (j, i) are the same expression with its symmetric terms
                    // swapped (s_i v_j + v_i s_j, s_i s_j), so a symmetric H stays symmetric
                    for (std::size_t i = 0; i < n; ++i) {
                        const double si = sk[i], vi = Hy[i];
                        double* row = Hk.data() + i * n;
                        for (std::size_t j = 0; j < n; ++j)
                            row[j] = row[j] - rhok * (si * Hy[j] + vi * sk[j]) + c * (si * sk[j]);
                    }
```

50차원 Rosenbrock를 풀고 난 $H$도 비트까지 대칭이고 양정치예요.

```python
>>> import stardust as sd
>>> def rosen_n(x):
...     return float(sd.sum(100.0 * (x[1:] - x[:-1]**2)**2 + (1 - x[:-1])**2))
>>> H = sd.optimize.minimize(rosen_n, sd.full(50, 0.5)).hess_inv
>>> bool(sd.all(H == H.T)), float(sd.min(sd.linalg.eigvalsh(H))) > 0
(True, True)
```

같은 행렬을 다른 순서로 계산하므로 끝자리가 scipy와 달라요. 그 차이가 다음 방향과 선 탐색을 거쳐 커지면 반복 수가 달라질 수 있어요. BFGS가 scipy와 비트까지 같지 않은 이유예요. scipy 1.18.1과 견준 결과(MGH 110경우와 Rosenbrock n = 2, 10, 50, 100의 114경우)는 이래요.

| 같은 것 | 경우 |
|---|---:|
| x의 비트 | 13 |
| 반복 수와 `nfev` | 80 |
| `status` | 113 |
| x가 상대 $10^{-6}$ 안 | 89 |

`status`가 다른 하나는 scipy가 수렴하고 여기서는 같은 최솟값 근처에서 선 탐색이 걸음을 찾지 못해(status 2) 멈춘 경우예요. 수렴한 실행은 모두 $\lVert g\rVert_\infty \le$ `gtol`을 만족해요. 갱신 한 번 뒤의 $H$는 scipy의 것과 상대 $1.7 \times 10^{-15}$ 안이에요.

**n = 1은 곱의 꼴이에요.** 1차원에서 펼친 식은 $v = Hy$, $\rho = 1/(sy)$이므로

$$
H - 2\rho\, s H y + (\rho^2 y H y + \rho) s^2 = H - 2H + H + s/y
$$

를 계산해요. $s/y \ll H$이면 $H - 2H + H$의 상쇄가 $s/y$를 지워 곡률 정보를 잃어요. 펼친 식으로 계산하면 MGH의 Chebyquad n = 1에서 10x0·100x0이 이 때문에 반복 1–2번 만에 멈춰요. 그래서 n = 1에서는 scipy의 꼴 $(1 - \rho s y) H (1 - \rho y s) + \rho s^2$를 1 × 1 dgemm 두 번으로 계산해요(지금 scipy와 비트까지 같아요). n ≥ 2에서도 극단적인 척도(Brown almost-linear의 100x0)에서는 같은 상쇄로 scipy와 다를 수 있어요.

$y^{\mathsf T} s = 0$이면 scipy처럼 $\rho = 1000$으로 두고, 갱신의 계산량 $8n^2$이 $2 \times 10^5$를 넘으면(대략 n > 160) 방향 $Hg$와 갱신을 계산하는 동안 GIL을 놓아요.

### 선 탐색: Wolfe 조건

$\phi(\alpha) = f(x_k + \alpha p_k)$라고 하면, 받는 걸음은 강한 Wolfe 조건을 만족해요($0 < c_1 < c_2 < 1$, 기본 $c_1 = 10^{-4}$, $c_2 = 0.9$).

$$
\phi(\alpha) \le \phi(0) + c_1\, \alpha\, \phi'(0), \qquad \lvert\phi'(\alpha)\rvert \le c_2\, \lvert\phi'(0)\rvert
$$

첫째(Armijo 조건)는 f가 걸음에 비례해 충분히 줄라는 것이고, 둘째(곡률 조건)는 기울기가 충분히 평평해질 만큼 멀리 가라는 것이에요. 둘째에서 $\phi'(\alpha) \ge c_2 \phi'(0)$이 나오고, 이것이 $y^{\mathsf T} s = \alpha(\phi'(\alpha) - \phi'(0)) > 0$을 보장해 BFGS 갱신이 양정치를 지켜요.

처음 시험할 걸음은 지난 반복의 감소가 되풀이된다고 보고 정해요(Nocedal–Wright 식 3.60에 scipy의 1.01배).

$$
\alpha_1 = \min\!\Bigl(1,\ 1.01 \cdot \frac{2\,(f_k - f_{k-1})}{\phi'(0)}\Bigr)
$$

음수가 나오면 1이에요. 첫 반복에는 $f_{k-1}$이 없어서 scipy처럼 $f_{k-1} = f_0 + \lVert g_0\rVert/2$로 둬요. 그러면 $\alpha_1 = 1.01/\lVert g_0\rVert$이고, 첫 시험점은 $x_0$에서 거리 1.01만큼 떨어진 점이에요.

```cpp
        // csrc/optimize/wolfe.hpp
        const double derphi0 = dot(gfk, pk);
        double alpha1;
        if (has_old_old && derphi0 != 0) {
            alpha1 = pymin(1.0, 1.01 * 2 * (old_fval - old_old_fval) / derphi0);
            if (alpha1 < 0) alpha1 = 1.0;
        } else {
            alpha1 = 1.0;
        }
```

#### dcsrch: Moré–Thuente

먼저 scipy의 `line_search_wolfe1`이에요. MINPACK-2의 `dcsrch`(Moré와 Thuente, 1994)를 scipy가 Python으로 옮긴 판(`_dcsrch.py`)이고, 같은 식을 같은 차례로 계산해요. 받는 걸음의 범위는 BFGS가 $[10^{-100}, 10^{100}]$, Newton-CG가 $[10^{-8}, 50]$이고, 시험은 100번까지예요.

dcsrch는 불확실 구간 $[\alpha_x, \alpha_y]$를 줄여 가며 시험 걸음을 고르는 방법이에요. 구간을 고르는 데 처음에는 바꾼 함수

$$
\psi(\alpha) = \phi(\alpha) - \phi(0) - c_1\, \alpha\, \phi'(0)
$$

를 써요(단계 1에서 시험점의 값이 Armijo 직선보다 위에 있지만 지금까지의 가장 좋은 값보다 작을 때). $\psi \le 0$이고 $\phi' \ge 0$인 걸음을 찾으면 그 뒤로는 $\phi$ 자체를 써요(단계 2). 이렇게 하면 Armijo 조건을 만족하는 걸음들 가운데 곡률 조건도 만족하는 걸음이 있는 구간을 놓치지 않아요.

```cpp
        // csrc/optimize/wolfe.hpp
        if (stage == 1 && f <= fx && f > ftest) {
            const double fm = f - stp * gtest;
            double fxm = fx - stx * gtest;
            double fym = fy - sty * gtest;
            const double gm = g - gtest;
            double gxm = gx - gtest;
            double gym = gy - gtest;
            dcstep(stx, fxm, gxm, sty, fym, gym, stp, fm, gm, brackt, stmin, stmax);
            fx = fxm + stx * gtest;
            fy = fym + sty * gtest;
            gx = gxm + gtest;
            gy = gym + gtest;
        } else {
            dcstep(stx, fx, gx, sty, fy, gy, stp, f, g, brackt, stmin, stmax);
        }
```

다음 시험 걸음은 `dcstep`이 네 경우로 나눠 고르는 보호된 보간이에요. ① 시험점의 값이 가장 좋은 끝 $\alpha_x$의 값보다 크면(최솟값을 넘어섬) 두 점의 값과 기울기로 만든 3차 보간점이 2차 보간점보다 $\alpha_x$에 가까울 때 3차, 아니면 둘의 가운데예요. ② 도함수의 부호가 바뀌었으면 3차와 할선 보간 가운데 시험점에서 먼 쪽이에요. ③ 같은 부호로 도함수의 크기가 줄었으면 3차와 할선 보간에서 고른 뒤, 구간이 있으면 시험점에서 다른 끝까지의 66% 안으로, 없으면 늘이는 범위 안으로 제한해요. ④ 그 밖에는 다른 끝 $\alpha_y$의 정보로 만든 3차 보간점, 구간이 없으면 늘이는 범위의 끝이에요. 구간이 아직 없을 때는 걸음을 $[\alpha + 1.1(\alpha - \alpha_x),\ \alpha + 4(\alpha - \alpha_x)]$ 안으로 늘려 구간을 찾아요. 구간의 폭이 두 번의 시험 동안 0.66배보다 덜 줄면 가운데로 이분해서, 구간이 반드시 줄어들게 해요.

dcsrch가 100번 안에 수렴하지 못하거나 경고(구간이 `xtol`보다 좁아짐 등)로 끝나면 `line_search_wolfe2`로 넘어가요.

#### zoom: Nocedal–Wright

`line_search_wolfe2`는 Nocedal–Wright의 알고리즘 3.5와 3.6이에요. 걸음을 두 배씩 늘리며(10번까지) Armijo 조건을 어기거나 값이 커지거나 도함수가 양수가 되는 걸음을 찾으면, 그 구간에서 `zoom`을 해요. 10번을 늘려도 그런 걸음이 없으면 마지막 걸음을 그대로 받아요. `zoom`은 구간의 한 끝 $\alpha_{lo}$의 값과 기울기, 다른 끝과 직전 끝의 값을 맞추는 3차식의 최솟점을 시험하고(첫 시험은 건너뛰어요), 그 점이 없거나 구간의 양 끝에서 폭의 20% 안이면 $\alpha_{lo}$의 값·기울기와 다른 끝의 값을 맞추는 2차식의 최솟점을, 그것도 끝에서 10% 안이면 가운데를 써요. 10번 안에 강한 Wolfe 조건을 만족하는 걸음을 찾지 못하면 실패예요.

scipy는 보간을 `np.errstate(divide='raise', over='raise', invalid='raise')` 안에서 하고, 그 예외가 나면 그 보간을 버려요. 여기서는 연산마다 numpy의 판정을 그대로 해요. 유한한 0이 아닌 수를 0으로 나누기, 유한한 값끼리의 연산에서 넘침, NaN이 아닌 값에서 NaN이 나오면 그 보간을 버리고 다음 꼴로 가요.

```cpp
        // csrc/optimize/wolfe.hpp
        double div(double a, double b) {
            const double r = a / b;
            if (b == 0 && std::isfinite(a) && a != 0) ok = false;  // divide
            return flag(r, a, b);
        }
```

두 선 탐색이 모두 실패하면 BFGS는 status 2로 멈춰요. 받은 걸음 뒤에 f가 유한하지 않아도 status 2예요.

### 멈춤

반복마다 걸음 뒤에 판정해요. `norm`의 기울기 노름(기본은 $\max_i \lvert g_i\rvert$)이 `gtol` 이하이면 status 0, 걸음 $\alpha \lVert p\rVert_2$가 `xrtol`·(`xrtol` + $\lVert x\rVert_2$) 이하이면 status 0이에요. 노름은 scipy의 `vecnorm`처럼 numpy의 쌍별 합으로 해요. `max_iter`에 닿으면 status 1이고, 끝에 기울기 노름, f, x 가운데 NaN이 있으면 status 3이에요.

## L-BFGS-B

L-BFGS-B(Byrd, Lu, Nocedal, Zhu 1995; 3.0판은 Morales–Nocedal 2011)는 경계 $l \le x \le u$ 안에서 최소화해요. scipy 1.15부터 이 Fortran 코드를 옮긴 C 판(`scipy/optimize/src/lbfgsb.c`)을 쓰고, 이 라이브러리는 그 C 판의 `setulb`·`mainlb`와 하위 루틴(cauchy, hpsolb, bmv, freev, formk, cmprlb, subsm, lnsrlb, dcsrch, dcstep, matupd, formt, projgr)과 scipy의 드라이버 고리(`_minimize_lbfgsb`)를 계산 순서까지 그대로 따라요. 다른 곳은 둘이에요. `max_iter=0`이면 x0의 판정 뒤 첫 반복 전에 멈추고(scipy는 상한을 첫 반복 뒤에 봐서 한 번 반복해요), 상대 감소 판정이 걸음 없이 통과하면 `converged=False`예요(아래).

### 압축 표현

L-BFGS는 헤시안 근사 $B_k$를 행렬로 들지 않고 최근 쌍 m개($S_k = [s_{k-m}, \dots, s_{k-1}]$, $Y_k$도 같은 꼴)로 나타내요. Byrd, Nocedal, Schnabel(1994)의 압축 표현은

$$
B_k = \theta I - W_k M_k W_k^{\mathsf T}, \qquad
W_k = \begin{bmatrix} Y_k & \theta S_k \end{bmatrix}, \qquad
M_k = \begin{bmatrix} -D_k & L_k^{\mathsf T} \\ L_k & \theta S_k^{\mathsf T} S_k \end{bmatrix}^{-1}
$$

이에요. $D_k$는 $s_i^{\mathsf T} y_i$의 대각, $L_k$는 $S_k^{\mathsf T} Y_k$의 순 아래 삼각 부분이고, 척도 $\theta = y^{\mathsf T} y / s^{\mathsf T} y$는 마지막 쌍의 것이에요. $W_k$는 n × 2m, $M_k$는 2m × 2m이라 $B_k$와 벡터의 곱이 $O(mn)$이에요. 가운데 행렬은 $\theta S^{\mathsf T} S + L D^{-1} L^{\mathsf T}$의 Cholesky 분해(`formt`)로 다뤄요.

쌍 $(s, y)$는 곡률이 충분히 양수일 때만 기억해요. $s^{\mathsf T} y \le \varepsilon\,(-g^{\mathsf T} s)$이면 건너뛰어서 $B_k$가 양정치로 남아요.

```cpp
        // csrc/optimize/lbfgsb.cpp
        if (stp == 1.0) {
            dr = gd - gdold;
            ddum = -gdold;
        } else {
            dr = (gd - gdold) * stp;
            dscal(n, stp, d.data());
            ddum = -gdold * stp;
        }
        if (dr <= epsmach * ddum) {
            nskip += 1;
            updatd = false;
            return false;
        }
```

### 일반화 Cauchy 점

경계가 있으면 방향 하나로는 부족해요. 지금 점에서 이차 모형

$$
m_k(x) = f_k + g_k^{\mathsf T}(x - x_k) + \tfrac12 (x - x_k)^{\mathsf T} B_k (x - x_k)
$$

을 가장 가파른 내리막을 상자로 투영한 꺾인 길 $x(t) = P(x_k - t g_k)$ 위에서 처음으로 지역 최소가 되는 점을 찾아요. 이것이 **일반화 Cauchy 점** $x^c$예요(`cauchy`). 변수 i는 $t_i$에서 경계에 닿고(꺾이는 점), 그 뒤로는 고정이에요. 꺾이는 점들 사이에서 길은 직선이고 모형은 t의 2차식이라, 구간마다 1차 도함수 $f'$와 2차 도함수 $f''$만 알면 그 구간 안의 최솟점 $-f'/f''$를 바로 구해요. 다음 구간의 $f'$, $f''$는 경계에 닿은 변수 하나만큼의 차이라 $W$, $M$으로 $O(m)$에 고쳐요. 꺾이는 점은 힙(`hpsolb`)에 넣어 작은 것부터 꺼내므로 모든 점을 정렬하지 않아요.

```cpp
        // csrc/optimize/lbfgsb.cpp
        dibp2 = std::pow(dibp, 2.0);
        f1 = f1 + dt * f2 + dibp2 - theta * dibp * zibp;
        f2 = f2 - theta * dibp2;
```

`cauchy`의 마지막 구간 판정 `nleft == -1 && nbreak == n`은 0부터 세는 번호에서는 결코 참이 될 수 없는 조건이지만(Fortran 원본은 1부터 센 번호로 판정해요) scipy의 C 판 그대로예요.

### 부분 공간 최소화

Cauchy 점에서 경계에 걸린 변수는 고정하고, 나머지(자유 변수)로 모형을 다시 최소화해요(`formk`, `cmprlb`, `subsm`). 자유 변수의 축소 헤시안 $Z^{\mathsf T} B Z$의 역을 Sherman–Morrison–Woodbury로 2m × 2m 행렬 K의 분해만으로 써서, 뉴턴 걸음 $\hat d = -(Z^{\mathsf T} B Z)^{-1} \hat r$을 $O(mn)$에 구해요(직접 주된 방법, direct primal method).

L-BFGS-B 3.0은 이 걸음을 상자로 투영해요. 투영한 점이 내리막 방향(기울기와의 내적이 0 이하)이면 그대로 받고, 아니면 2.x판처럼 경계에 닿을 때까지 걸음을 줄여요(Morales–Nocedal 2011). 그렇게 얻은 점 $\bar x$로 방향 $d = \bar x - x_k$를 정해요.

### 선 탐색과 반복

방향 $d$ 위에서 dcsrch(C 판)로 $c_1 = 10^{-3}$, $c_2 = 0.9$, `xtol` 0.1의 강한 Wolfe 조건을 찾아요. 걸음의 상한은 경계 안에 머무는 가장 큰 걸음이고(경계가 있는 첫 반복은 1, 경계가 없으면 $10^{10}$), 모든 변수에 양쪽 경계가 있지는 않은 문제의 첫 반복에서는 첫 시험 걸음이 $\min(1/\lVert d\rVert, \text{상한})$, 그 밖에는 1이에요. 시험점은 다시 상자로 투영해요.

선 탐색이 `max_ls`번 안에 끝나지 않거나 방향이 내리막이 아니면 점을 되돌려요. 기억이 있으면 기억을 비우고 다시 시작하고(가장 가파른 내리막의 Cauchy 점부터), 기억이 이미 비었으면 `ABNORMAL`로 멈춰요. 결과의 `x`, `jac`, `fun`은 되돌린 점의 것이에요. scipy는 `setulb`에 f를 값으로 넘기므로 이때 결과의 `fun`이 마지막 시험점의 값이에요. 걸음은 같고 결과의 `fun`만 달라요.

반복이 끝날 때마다 scipy의 드라이버처럼 반복 수를 세고 `max_iter`와 `max_nfev`(초과 여부, 반복 끝에서)를 본 뒤, 투영된 기울기의 최대 성분이 `gtol` 이하이거나 $(f_k - f_{k+1}) / \max(\lvert f_k\rvert, \lvert f_{k+1}\rvert, 1) \le$ `factr`·ε(= `ftol`)이면 멈춰요.

```cpp
                // csrc/optimize/lbfgsb.cpp
                // the driver at NEW_X (_minimize_lbfgsb)
                n_iterations += 1;
                if (n_iterations >= maxiter) {
                    task = STOP;
                    task_msg = STOP_ITERC;
                    return;
                }
                if (obj.nfev > maxfun) {
                    task = STOP;
                    task_msg = STOP_ITER;
                    return;
                }
```

`max_nfev`는 반복이 끝날 때 보므로 반복 하나만큼 넘을 수 있어요. 차분 기울기면 선 탐색의 시험점마다 $n + 1$번이라 많이 넘기도 해요($n = 200$, `max_nfev=1`이면 603번). scipy와 같은 판정이에요.

상대 감소 판정은 걸음이 없어도 통과할 수 있어요. 시험점의 값이 유한하지 않으면 선 탐색이 앞 반복점으로 돌아와 끝나고, 그러면 $f_k - f_{k+1} = 0$이라 판정이 서요. scipy는 이것을 수렴으로 알리지만 해가 아니에요(투영된 기울기는 `gtol`보다 커요). 여기서는 `status`와 `message`는 scipy의 것(`CONVERGENCE: RELATIVE REDUCTION OF F <= FACTR*EPSMCH`) 그대로 두고 `converged`를 False로 해요.

```cpp

            const double ddum = std::fmax(std::fmax(std::fabs(fold), std::fabs(f)), 1.0);
            if ((fold - f) <= tol * ddum) {
                task = CONVERGENCE;
                task_msg = CONV_F;
                if (iback >= 10) info = -5;
                // no step was taken (the line search ended at the previous iterate, e.g. after
                // a non-finite trial value) and the projected gradient is above pgtol: scipy's
                // test passes on fold - f = 0, but this is no convergence
                stalled = std::equal(x.begin(), x.end(), t.data());

```

### scipy와 같은 계산의 세부

C 판을 같은 순서로 옮겨도 두 가지가 다르면 끝자리가 갈려요. 지금은 두 가지 모두 scipy와 같게 계산해서 호출점이 비트까지 같아요.

**FMA 축약.** scipy는 `lbfgsb.c`를 clang의 기본값 `-ffp-contract=on`으로 빌드해서, 한 식 안의 `a * b + c`를 FMA 하나(반올림 한 번)로 계산해요. 이 라이브러리는 전체를 `-ffp-contract=off`로 빌드하지만 이 파일만 같은 축약을 켜고, 식을 scipy의 꼴 그대로 적어요. 축약을 끄면 경계 없는 114경우 가운데 13경우만 호출점이 비트까지 같아요.

```cpp
// csrc/optimize/lbfgsb.cpp
#pragma clang fp contract(on)
```

**ddot의 합 순서.** Accelerate의 `ddot`은 둘째 인자가 16바이트 정렬인지에 따라 합의 순서가 달라서, 길이 5 이상에서 끝자리가 달라져요. scipy는 작업 배열 `wa` 하나를 `setulb`가 나눠 쓰므로 부분마다 정렬이 달라요. 여기서도 작업 공간 하나를 scipy와 같은 위치로 나눠요. 따로 잡은 배열을 쓰면 상자 경계 51경우 가운데 43경우만 같아요.

```cpp
    // csrc/optimize/lbfgsb.cpp
    // scipy's workspace wa, partitioned as setulb does: the parts start where scipy's do, so they
    // have scipy's 16-byte alignment (Accelerate's ddot sums in an order that depends on it).
    // Zeroed by calloc as scipy's np.zeros: pages not written (most of 11 m^2 for a large maxcor)
    // take no memory.
    std::unique_ptr<double[], decltype(&std::free)> buf{nullptr, &std::free};
    Part ws, wy, sy, ss, wt, wn, snd, z, r, d, t, xp, wa;
```

작업 공간 $2mn + 5n + 11m^2 + 8m$개는 scipy의 `np.zeros`처럼 `calloc`으로 잡아서, 쓰지 않는 부분은 메모리를 차지하지 않아요(`maxcor`가 아주 클 때 $11m^2$의 대부분).

그래서 지금은 scipy가 기록한 114경우(MGH 110경우, Rosenbrock n = 2·5, 최대 엔트로피, driver1)와 차분 기울기의 114경우, x0 둘레의 상자 경계 51경우(해석적·차분)에서 사용자 함수를 부른 점이 차례대로 비트까지 같고, 결과의 필드도 `ABNORMAL`의 `fun`(위)을 빼고 같아요. L-BFGS-B 3.0의 Fortran 원본을 gfortran으로 돌린 83경우와 견주면 scipy의 C 판과 같은 거리예요. 호출 수와 반복 수가 같은 것이 74, x가 $10^{-12}$ 안인 것이 62, $10^{-6}$ 안인 것이 79경우예요. C 판은 원본과 같은 알고리즘이지만 반올림이 달라서 이만큼 떨어져 있어요. driver1(m = 5)은 원본 드라이버처럼 23번 반복, 28번 계산이에요.

### hess_inv

결과의 `hess_inv`는 scipy의 `LbfgsInvHessProduct(s, y).todense()`와 같은 행렬이에요. 기억한 쌍을 저장 순서로(기억이 한 바퀴 돈 뒤에는 시간 순서가 아니에요; scipy와 같아요) 두 고리 재귀를 단위행렬에 적용해요($H_0 = I$). n × n 행렬이라 처음 읽을 때 만들어요.

```python
# src/stardust/optimize/_minimize.py
def _lbfgs_inverse_hessian(S, Y):
    """scipy's LbfgsInvHessProduct(S, Y).todense(): the two-loop recursion applied to the
    identity, the pairs in the order given."""
    nc, n = S.shape
    Q = _sd.eye(n)
    if nc == 0:
        return Q
    s = [S[i] for i in range(nc)]
    y = [Y[i] for i in range(nc)]
    rho = [1.0 / float(_linalg.vecdot(s[i], y[i])) for i in range(nc)]
    alpha = [None] * nc
    for i in range(nc - 1, -1, -1):
        alpha[i] = rho[i] * (s[i] @ Q)
        Q = Q - _sd.reshape(y[i], (n, 1)) * _sd.reshape(alpha[i], (1, n))
    R = Q
    for i in range(nc):
        beta = rho[i] * (y[i] @ R)
        R = R + _sd.reshape(s[i], (n, 1)) * _sd.reshape(alpha[i] - beta, (1, n))
    return R
```

`maxcor` 10·3의 220경우(기억이 한 바퀴 돈 185경우 포함)에서 scipy의 것과 상대 $2.8 \times 10^{-14}$ 안이에요. L-BFGS-B가 반복에 쓰는 $B_k$의 척도 $\theta$는 이 행렬에 없어요(scipy와 같아요).

## GIL과 스레드

사용자 함수를 부르는 동안 GIL을 쥐어요. BFGS의 방향 $Hg$와 갱신($8n^2 > 2 \times 10^5$)과 L-BFGS-B의 방향 계산·기억 갱신($10\,n(m + 1) > 2 \times 10^5$)은 sd.linalg의 10 µs 규칙대로 GIL을 놓아요. BFGS의 dgemv와 L-BFGS-B의 BLAS 호출은 Accelerate가 하고, 결과는 스레드 수와 상관없이 같아요.

## 속도

Apple M4 Pro, scipy 1.18.1·numpy 2.5.4, 일반화된 Rosenbrock, x0 = (−1.2, 1, −1.2, 1, …), 해석적 기울기, 1스레드에서 견줘요. "자기 비용"은 사용자 함수 밖의 시간을 반복 수로 나눈 값이에요.

- 작은 n에서는 반복 하나의 자기 비용이 scipy의 1/2–1/20이에요.
- BFGS는 반복 하나의 자기 비용이 n = 100에서 0.0062 ms, n = 1000에서 0.29 ms예요. n = 1000에서 40회를 돌리는 전체 시간은 12 ms예요(scipy 441 ms).
- L-BFGS-B는 n = 10⁴에서 scipy와 거의 같아요.

BFGS n = 1000의 차이는 갱신의 계산량($n^3$ 대 $n^2$)이에요. scipy의 BFGS는 반복마다 1000 × 1000 행렬곱 두 번을 해요. L-BFGS-B는 scipy도 반복의 계산이 C라 차이가 작고, 큰 n에서는 같은 BLAS 호출이 시간 대부분이에요. 차분 기울기에서는 scipy가 변수마다 Python에서 배열을 만들어 차이가 더 커요(반복당 자기 비용이 scipy의 1/3–1/12).
