## 한눈에 보기

[`minimize(method='nelder-mead')`](/api/optimize/nelder-mead/)는 Nelder와 Mead(1965)의 단체법이에요. 함수값의 크기 비교만으로 꼭짓점 n + 1개의 단체를 옮겨 가요. 계산은 scipy 1.18.1의 `_minimize_neldermead`와 같은 순서로 해서, 같은 문제에서 사용자 함수를 부르는 점이 차례대로 비트까지 같아요.

| 무엇 | 어디 |
|---|---|
| 입력 검사, 옵션의 기본값(`max_iter`·`max_nfev`), 결과 객체 | `src/stardust/optimize/_minimize.py`의 `_nelder_mead` |
| 처음 단체, 반복, 정렬, 멈춤 | `csrc/optimize/nelder_mead.cpp`의 `nelder_mead_solve` |
| 사용자 함수 부르기와 반환값 검사 | `csrc/optimize/objective.hpp`의 `Objective::call_f` |

반복 전체가 C++이고 `fun`만 Python으로 불러요. 반복 하나의 자기 비용은 n = 2에서 0.46 µs(scipy 6.9 µs)예요(아래 [속도](#속도)).

## 한 반복

꼭짓점을 값 순서로 $x_1, \dots, x_{n+1}$($f_1 \le \dots \le f_{n+1}$)로 두고, 가장 나쁜 점을 뺀 무게중심을 $\bar x = \frac1n \sum_{i=1}^{n} x_i$라고 해요. 시험점은 모두 $x_{n+1}$에서 $\bar x$를 지나는 직선 위에 있어요.

$$
x(t) = \bar x + t\,(\bar x - x_{n+1}), \qquad
x_r = x(\rho),\ x_e = x(\rho\chi),\ x_c = x(\psi\rho),\ x_{cc} = x(-\psi)
$$

계수는 반사 $\rho = 1$, 확장 $\chi = 2$, 수축 $\psi = 1/2$, 축소 $\sigma = 1/2$예요.

  <Moves label="Nelder-Mead의 시험점 다섯 가지" />

받는 규칙은 Lagarias, Reeds, Wright, Wright(1998)가 정리한 표준형이에요.

| 조건 | 하는 일 | f 호출 |
|---|---|---|
| $f_r < f_1$ | 확장점을 계산해 $f_e < f_r$이면 $x_e$, 아니면 $x_r$을 받아요 | 2 |
| $f_1 \le f_r < f_n$ | $x_r$을 받아요 | 1 |
| $f_n \le f_r < f_{n+1}$ | 바깥 수축. $f_c \le f_r$이면 $x_c$를 받고, 아니면 축소 | 2 |
| $f_r \ge f_{n+1}$ | 안쪽 수축. $f_{cc} < f_{n+1}$이면 $x_{cc}$를 받고, 아니면 축소 | 2 |
| 축소 | $x_i \leftarrow x_1 + \sigma(x_i - x_1)$, $i = 2, \dots, n+1$ | + n |

확장에서 $f_e$와 $f_r$ 가운데 작은 쪽을 받는 것(greedy minimization)이 Nelder와 Mead의 원래 규칙(확장점이 $f_1$보다 좋으면 받음)과 다른 점이에요. 같은 값의 비교는 scipy의 비교 그대로예요(`<`와 `<=`가 자리마다 달라요). NaN은 모든 비교에서 거짓이라, 반사점이 NaN이면 마지막 줄(안쪽 수축)로 가요.

Rosenbrock를 (−1.2, 1)에서 풀 때 84번의 반복은 이렇게 나뉘었어요. 축소는 한 번도 없었고, 함수 호출은 처음 꼭짓점 3번 + 84 + 72 = 159번이에요.

| 확장 | 반사(확장 시험 뒤) | 반사 | 바깥 수축 | 안쪽 수축 | 축소 |
|---:|---:|---:|---:|---:|---:|
| 18 | 12 | 12 | 12 | 30 | 0 |

### 적응 계수

`adaptive=True`이면 Gao와 Han(2012)의 계수를 써요.

$$
\rho = 1, \qquad \chi = 1 + \frac2n, \qquad \psi = \frac34 - \frac1{2n}, \qquad \sigma = 1 - \frac1n
$$

n이 커지면 확장은 1에, 수축은 3/4에, 축소는 1에 다가가요. 고정 계수에서는 차원이 커질수록 확장이 단체를 지나치게 늘이고 수축과 축소가 지나치게 줄여 단체가 납작해지기 쉬운데, 이 계수는 한 번의 변형을 차원에 맞춰 약하게 해요. n = 2에서는 $\chi = 2$, $\psi = 1/2$, $\sigma = 1/2$로 표준 계수와 같아요.

```cpp
        // csrc/optimize/nelder_mead.cpp
        double rho, chi, psi, sigma;
        if (adaptive) {
            const double dim = static_cast<double>(N);
            rho = 1;
            chi = 1 + 2 / dim;
            psi = 0.75 - 1 / (2 * dim);
            sigma = 1 - 1 / dim;
        } else {
            rho = 1;
            chi = 2;
            psi = 0.5;
            sigma = 0.5;
        }
```

차원이 큰 Rosenbrock(0에서 시작, 상한 50,000번)에서 두 계수의 차이는 이래요.

| n | 표준 계수 nfev, f | 적응 계수 nfev, f |
|---:|---|---|
| 10 | 4,729, 1.4×10⁻⁸ | 3,534, 1.5×10⁻⁸ |
| 20 | 32,304, 11.8(해가 아닌 점에서 멈춤) | 22,659, 1.4×10⁻⁸ |

## 수렴에 대해 알려진 것

Nelder–Mead에는 기울기를 쓰는 방법 같은 일반적인 수렴 정리가 없어요.

- Lagarias 등(1998)은 1차원의 강볼록 함수에서 최솟값으로 수렴함을 보였고, 2차원의 강볼록 함수에서는 단체의 지름이 0으로 줄어들고 꼭짓점의 값이 같은 값으로 수렴함을 보였어요. 그 값이 최솟값이라는 것은 2차원에서도 보이지 못했어요.
- McKinnon(1998)은 2차원의 강볼록하고 매끄러운(한 번 연속 미분 가능한) 함수에서, 단체가 안쪽 수축만 되풀이하며 **정류점이 아닌 점**으로 수렴하는 예를 만들었어요.

$$
f(x, y) = \begin{cases} \theta\phi\,\lvert x\rvert^{\tau} + y + y^2 & x \le 0 \\ \theta\, x^{\tau} + y + y^2 & x > 0 \end{cases}, \qquad (\tau, \theta, \phi) = (2, 6, 60)
$$

처음 단체가 (0, 0), (1, 1), $\left(\frac{1 + \sqrt{33}}{8}, \frac{1 - \sqrt{33}}{8}\right)$이면 가장 좋은 꼭짓점 (0, 0)은 그대로이고 나머지 둘이 안쪽 수축으로 (0, 0)에 다가가요. (0, 0)의 기울기는 (0, 1)이라 정류점이 아니고, 최솟값은 (0, −0.5)예요.

같은 계산을 하므로 이 라이브러리도 그대로 따라가요. 기본 허용오차에서는 (0, 0)에서 `converged=True`로 멈추고, 결과에서 다시 시작하면 새 단체가 최솟값을 찾아요.

```python
>>> import math
>>> import stardust as sd
>>> def mckinnon(x):
...     a, b = x[0], x[1]
...     if a <= 0:
...         return 360.0 * a**2 + b + b * b
...     return 6.0 * a**2 + b + b * b
>>> s = math.sqrt(33)
>>> simplex = [[1.0, 1.0], [(1 + s) / 8, (1 - s) / 8], [0.0, 0.0]]
>>> r = sd.optimize.minimize(mckinnon, [1.0, 1.0], method='nelder-mead', options={'initial_simplex': simplex})
>>> r.converged, r.x, r.fun
(True, array([0.0, 0.0], dtype=float64), 0.0)
>>> r2 = sd.optimize.minimize(mckinnon, r.x, method='nelder-mead')
>>> [round(v, 4) for v in r2.x.tolist()], r2.fun
([0.0, -0.5], -0.24999999796930122)
```

허용오차를 0으로 두면 안쪽 수축이 244번째 반복까지 이어져 꼭짓점이 $10^{-18}$ 크기가 되고, 그때 반올림 때문에 새 꼭짓점의 값이 (0, 0)의 값보다 작게 계산되어 패턴이 깨져요. 그 뒤 단체가 다시 커져서 800번 반복 안에 최솟값 (0, −0.5)에 닿아요.

## 처음 단체

`initial_simplex`가 없으면 scipy의 규칙으로 만들어요. 첫 꼭짓점은 `x0`이고, k번째 꼭짓점은 `x0`의 k번째 좌표를 $1.05$배 한 점이에요(그 좌표가 0이면 0.00025). 그래서 단체의 크기는 `x0`의 크기에 비례하고, `x0`가 0이면 아주 작게 시작해요.

```cpp
            // csrc/optimize/nelder_mead.cpp
            for (std::size_t j = 0; j < N; ++j) S.pool[j] = x0[j];
            for (std::size_t k = 0; k < N; ++k) {
                double* y = S.pool.data() + (k + 1) * N;
                for (std::size_t j = 0; j < N; ++j) y[j] = x0[j];
                y[k] = y[k] != 0 ? (1 + nonzdelt) * y[k] : zdelt;
            }
```

`initial_simplex`를 주면 Python 층에서 모양 (N + 1, N), 열의 수, 유한함을 검사하고 그대로 써요.

경계가 있으면 위 경계를 넘는 꼭짓점을 $2u - v$로 경계 안에 반사한 뒤 잘라요. `x0`가 위 경계에 아주 가까우면 1.05배 한 좌표가 경계를 넘고, 그냥 자르면 그 꼭짓점이 `x0`와 겹쳐 단체가 납작해지기 때문이에요. 반복 중의 모든 시험점(축소한 꼭짓점 포함)도 계산 전에 잘라요. 자르기는 numpy의 `clip`과 같아요. NaN은 그대로 두고, `max(x, lo)` 다음 `min(·, hi)`예요.

```cpp
// csrc/optimize/nelder_mead.cpp
// numpy's clip for doubles: NaN stays, max(x, lo) then min(., hi) with numpy's comparisons.
inline double np_clip(double x, double lo, double hi) {
    if (x != x) return x;
    const double t = x > lo ? x : lo;
    return t < hi ? t : hi;
}
```

## 멈춤과 상한

반복을 시작할 때마다 두 조건을 봐요. 모든 꼭짓점이 가장 좋은 꼭짓점과 좌표마다 `xatol` 안이고, 모든 값이 가장 좋은 값과 `fatol` 안이면 멈춰요. scipy는 $N \times N$의 차이를 모두 만든 뒤 최댓값을 보지만, 여기서는 처음으로 허용오차를 넘는 원소에서 그쳐요. 판정의 결과는 같아요(NaN은 허용오차 안이 아니에요).

```cpp
                // csrc/optimize/nelder_mead.cpp
                const double* s0 = S.row(0);
                bool small = true;
                for (std::size_t k = 1; k <= N && small; ++k) {
                    const double* sk = S.row(k);
                    for (std::size_t j = 0; j < N; ++j)
                        if (!(std::abs(sk[j] - s0[j]) <= xatol)) {
                            small = false;
                            break;
                        }
                }
                for (std::size_t k = 1; k <= N && small; ++k) small = std::abs(S.fsim[0] - S.fsim[k]) <= fatol;
```

상한은 둘이에요. `max_iter`와 `max_nfev`를 모두 주지 않으면 각각 200n이고, 하나만 주면 다른 하나는 상한이 없어요(scipy의 규칙).

```python
    # src/stardust/optimize/_minimize.py
    # scipy: 200 n each when neither is given; one given leaves the other uncapped
    if max_iter is None and max_nfev is None:
        max_iter = max_nfev = 200 * n
    elif max_iter is None:
        max_iter = -1
    elif max_nfev is None:
        max_nfev = -1
```

scipy는 사용자 함수를 감싸서, 호출 수가 `maxfev`에 닿은 뒤의 호출은 하지 않고 예외(`_MaxFuncCallError`)로 그 반복을 빠져나와요. 그 반복은 세지 않고, 꼭짓점을 정렬한 뒤 바깥 고리의 조건으로 끝나요. 여기서는 같은 일을 예외 없이 해요. `call`이 false를 돌려주면 그 반복을 그만두고(`limit`), 반복 수를 늘리지 않고 정렬해요.

```cpp
        // csrc/optimize/nelder_mead.cpp
        double fcalls = 0;
        // scipy's _wrap_scalar_function_maxfun_validation: no call past max_nfev
        auto call = [&](const double* v, double& out) -> bool {
            if (fcalls >= maxfun) return false;
            fcalls += 1;
            out = obj.call_f(v);
            return true;
        };
```

반복 수 `iterations`는 scipy처럼 1에서 시작해요. 그래서 결과의 `n_iter`는 실제로 한 반복 수보다 하나 많아요(scipy의 `nit`와 같은 수). `status`는 scipy의 `warnflag`로, 호출 수가 `max_nfev` 이상이면 1, 아니고 반복 수가 `max_iter` 이상이면 2예요. 결과의 `x`는 정렬된 첫 꼭짓점, `fun`은 값의 최솟값(numpy의 `min`이라 NaN이 하나라도 있으면 NaN)이에요.

## scipy와 같은 점을 부르려면

같은 시험점을 만들려면 같은 꼭짓점이 같은 자리에 있어야 해요. 갈릴 수 있는 곳은 둘이에요.

**정렬.** scipy는 반복마다 `np.argsort(fsim)`으로 꼭짓점을 정렬해요. numpy의 기본 `argsort`('quicksort')는 introsort이고, 원소가 17개 미만인 구간은 삽입 정렬이라 같은 값의 순서가 그대로지만 그보다 큰 구간은 피벗 분할이라 같은 값의 순서가 바뀔 수 있어요. 같은 값의 순서는 어느 꼭짓점이 "가장 나쁜" 것인지를 정해서 다음 시험점을 바꿔요. 그래서 numpy의 `aquicksort_`(세 값의 중앙값 피벗, 깊이 한도 $2\lfloor\log_2 n\rfloor$를 넘으면 힙 정렬, NaN을 맨 뒤로 보내는 비교)를 그대로 따라 해요. 처음 꼭짓점을 계산한 뒤 scipy가 두 번 정렬하는 것도 같아요.

정렬할 때 scipy는 `np.take`로 단체의 행을 새 배열에 옮기지만, 여기서는 행이 있는 자리를 그대로 두고 행 번호(`order`)만 옮겨요. 계산하는 값은 같고, n이 클 때 반복마다의 $(n+1) \times n$ 복사가 없어요.

**무게중심의 덧셈 순서.** scipy의 `np.add.reduce(sim[:-1], 0) / N`은 C 순서 2차원 배열을 축 0으로 줄이므로 +0.0에서 시작해 행을 차례로 더해요(쌍별 합이 아니에요). 같은 순서로 더하고 N으로 나눠요. 시험점의 식 $(1 + \rho\chi)\bar x - \rho\chi\, x_{n+1}$도 scipy의 식 그대로, 계수를 먼저 곱한 뒤 빼요. numpy의 원소별 연산에는 FMA가 없고, 이 라이브러리도 `-ffp-contract=off`로 빌드해서 곱과 덧셈을 따로 반올림해요.

```cpp
                    // csrc/optimize/nelder_mead.cpp
                    double* __restrict xb = xbar.data();
                    for (std::size_t j = 0; j < N; ++j) xb[j] = 0.0;
                    for (std::size_t k = 0; k < N; ++k) {
                        const double* __restrict sk = S.row(k);
                        for (std::size_t j = 0; j < N; ++j) xb[j] = xb[j] + sk[j];
                    }
                    const double dN = static_cast<double>(N);
                    for (std::size_t j = 0; j < N; ++j) xb[j] = xb[j] / dN;
```

이렇게 해서 scipy 1.18.1이 기록한 MGH 110경우와 Rosenbrock(n = 2, 5)·최대 엔트로피·L-BFGS-B driver1 문제(114번)에서 결과의 모든 필드(x의 비트, `fun`, `nfev`, `nit`, `status`, `message`)가 같고, scipy를 실행하며 `fun`을 부른 점을 차례대로 견주면 x0 둘레의 상자 경계를 준 51경우도 모두 비트까지 같아요. 옵션(`adaptive`, `initial_simplex`, `max_iter`, `max_nfev`, `tol`, 반쪽 경계, 시험점의 inf·NaN)을 바꾼 경우도 같아요.

## 유한하지 않은 값

처음 꼭짓점 $x_1$(= `x0`, 또는 `initial_simplex`의 첫 행)에서 `fun`이 유한하지 않으면 출발할 수 없어서 `ValueError`예요. 나머지 꼭짓점과 반복 중의 시험점은 scipy처럼 그대로 다뤄요. inf는 가장 나쁜 값으로 정렬되고, NaN은 numpy의 정렬에서 맨 뒤로 가요. 반사·확장·수축의 비교에서는 NaN이 언제나 지므로 NaN인 시험점은 받지 않아요(축소한 꼭짓점은 값과 상관없이 받아요).

## GIL과 스레드

`fun`을 부르는 동안 GIL을 쥐어요. 반복 안의 계산은 무게중심($n^2$ 덧셈)과 멈춤 판정뿐이고, $n^2 > 2 \times 10^5$(대략 n > 450)이면 그동안 GIL을 놓아요(sd.linalg와 같은 10 µs 규칙). 계산은 한 스레드라 결과는 스레드 수와 상관없이 같아요.
