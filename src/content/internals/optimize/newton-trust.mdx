## 한눈에 보기

세 방법 모두 점 $x_k$에서 f를 이차 모형

$$
m_k(p) = f_k + g_k^{\mathsf T} p + \tfrac12\, p^{\mathsf T} H_k p
$$

으로 어림하고 그 모형으로 걸음을 정해요. 다른 것은 걸음의 길이를 다루는 방법과 모형을 푸는 방법이에요.

| | Newton-CG | trust-ncg | trust-exact |
|---|---|---|---|
| 걸음의 길이 | 선 탐색(Wolfe) | 신뢰 영역 $\lVert p\rVert \le \Delta$ | 신뢰 영역 |
| 모형 풀기 | 공액 기울기(CG), 부정확 | Steihaug–Toint CG | Moré–Sorensen(Cholesky) |
| 헤시안 | 곱 $H p$만 | 곱 $H p$만 | 행렬 |
| scipy 1.18.1 | `_minimize_newtoncg` | `_minimize_trust_region` + `CGSteihaugSubproblem` | 같은 고리 + `IterativeSubproblem` |
| 파일 | `csrc/optimize/newton_cg.cpp` | `csrc/optimize/trust.cpp` | 같은 파일 |

기울기는 [준뉴턴 방법](/internals/optimize/quasi-newton/)과 같은 `ScalarFunction`의 기억(`objective.hpp`)으로, 헤시안은 `hessian.hpp`가 다뤄요. 사용자의 `hess`는 처음에 x0에서(f와 기울기 다음) 한 번 부르고, 그 뒤로는 새 점에서 처음 필요할 때 불러요. 돌려받은 행렬은 언제나 C 순서로 복사해 둬요. scipy는 `np.asarray`로 그 배열을 그대로 쥐는데, 그러면 버퍼 하나를 다시 채워 돌려주는 `hess`가 앞 점의 행렬을 덮어써서 trust-exact가 거절한 걸음 뒤에 틀린 헤시안으로 계산해요. 값은 같으므로 C 순서 행렬의 호출점은 그대로예요. F 순서 행렬은 scipy가 그 배치 그대로 곱하고 더해서 끝자리가 다를 수 있어요. 헤시안은 대칭이어야 해요. trust-exact는 위 삼각으로 분해하고, 경계와 노름과 곱에는 행렬 전체를 써요(scipy와 같아요).

세 방법은 scipy 1.18.1과 같은 알고리즘, 같은 멈춤 판정이에요. 성공 경로에서는 지금 사용자 함수(`fun`, `jac`, `hess`, `hessp`)를 부르는 점까지 차례대로 비트까지 같아요(`hess`와 `hessp`가 없는 newton-cg는 빼고, 아래). 다른 곳은 결과의 셈과, scipy가 끝나지 않거나 예외를 내거나 해가 아닌 점에서 수렴을 알리는 자리예요(아래).

## Newton-CG

### 부정확한 뉴턴 걸음

반복마다 뉴턴 방정식 $H_k p = -g_k$를 0에서 시작하는 공액 기울기법으로 풀어요. CG는 행렬을 분해하지 않고 곱 $H_k d$만 쓰고, 양정치 행렬이면 j번째 걸음이 j차원 Krylov 공간에서 모형 $m_k$의 최솟점이에요. 끝까지 풀 필요는 없어서 잔차가 충분히 작아지면 멈춰요.

$$
\sum_i \lvert r_i\rvert \le \eta_k \sum_i \lvert g_i\rvert, \qquad \eta_k = \min\!\Bigl(\tfrac12,\ \sqrt{\textstyle\sum_i \lvert g_i\rvert}\Bigr)
$$

$\eta_k \to 0$이 $\lVert g_k\rVert^{1/2}$의 빠르기로 줄어드는 이 규칙에서 부정확한 뉴턴 방법은 해 근처에서 초선형(1.5차)으로 수렴해요(Dembo, Eisenstat, Steihaug 1982). 해에서 멀면 대충 풀어 반복 하나의 비용을 아끼고, 가까우면 정확히 풀어 뉴턴 방법의 빠르기를 얻는 것이에요. 1-노름은 scipy(`np.linalg.norm(b, ord=1)`과 `np.add.reduce(np.abs(r))`)를 따른 것이고, 합은 numpy의 쌍별 합 순서예요.

CG가 곡률 $d^{\mathsf T} H d$를 계산할 때 그 값이 음수면 $H$가 양정치가 아니라는 뜻이라 거기서 멈춰요. 첫 걸음에서 음수면 가장 가파른 내리막 $-g$를 $g^{\mathsf T} g / \lvert g^{\mathsf T} H g\rvert$만큼, 그 뒤면 그때까지의 $p$를 써요. 곡률이 $[0, 3\varepsilon]$이면(거의 0) 역시 멈춰요. CG는 20n번까지예요. 그 안에 멈추지 않으면 status 3이에요.

두 곳은 scipy를 일부러 따르지 않아요. 첫 CG 걸음의 곡률이 $[0, 3\varepsilon]$이고 $3\varepsilon\lVert g\rVert_2^2$ 이하이면(기울기가 작아서가 아니라 그 방향의 곡률이 0이면: 안장점, 함수가 선형인 부분) scipy는 걸음 0을 내고 다음 판정에서 수렴을 알려요. 여기서는 $-g$를 방향으로 선 탐색에 넘겨요(걸음의 크기는 선 탐색이 정해요). 다만 기울기 차분의 시험점 $x + h\,p$가 반올림으로 $x$와 같아진 경우(`vanished`)는 곱이 곡률에 대해 아무것도 말하지 않으니 빼요. 곡률이 NaN이면 CG를 바로 멈추고 status 3 `NaN result encountered.`예요(scipy는 NaN을 품은 채 CG를 20n번 돌아요).

```cpp
                // csrc/optimize/newton_cg.cpp
                const double curv = np_dot(psupi.data(), Ap.data(), n);
                if (std::isnan(curv)) {
                    nan_curv = true;
                    break;
                }
                if (0 <= curv && curv <= eps3) {
                    // no curvature along -g at the first step (also relative to |g|^2, so not a
                    // tiny g near the solution): -g, the line search sizes it
                    if (i == 0 && curv <= eps3 * dri0 && !vanished) {
                        for (std::size_t j = 0; j < n; ++j) xsupi[j] = b[j];
                    }
                    converged = true;
                    break;
                } else if (curv < 0) {
                    if (i == 0) {  // fall back to the steepest descent direction
                        const double t = dri0 / (-curv);
                        for (std::size_t j = 0; j < n; ++j) xsupi[j] = t * b[j];
                    }
                    converged = true;
                    break;
                }
                const double alphai = dri0 / curv;
                for (std::size_t j = 0; j < n; ++j) {
                    xsupi[j] = xsupi[j] + alphai * psupi[j];
                    ri[j] = ri[j] + alphai * Ap[j];
                }
                const double dri1 = np_dot(ri.data(), ri.data(), n);
                const double betai = dri1 / dri0;
                for (std::size_t j = 0; j < n; ++j) psupi[j] = -ri[j] + betai * psupi[j];
```

[Rosenbrock에서 Newton-CG가 처음 40번쯤 머무는 곳](/api/optimize/newton-methods/)은 헤시안의 고유값이 −0.9 안팎과 1,000 안팎인 점들이에요. 그곳에서는 반복 둘에 하나꼴로 CG의 두 번째 방향이 음의 곡률(−4에서 −10)을 만나 첫 걸음(기울기 방향)만으로 멈추고, 나머지 반복도 CG 한 걸음으로 끝나요. 방향이 기울기 쪽에 머물러서 선 탐색이 받는 걸음이 짧아요.

### 헤세 곱

곱 $H d$는 네 가지 가운데 하나예요.

- `hess`의 행렬: 반복을 시작할 때 한 번 계산하고, CG 걸음마다 numpy처럼 row-major dgemv로 곱해요.
- `hessp(x, d)`: 사용자 함수를 곱마다 불러요.
- `hess='2-point'`: scipy `approx_derivative`가 만드는 선형 연산자예요. $(g(x + h d) - g(x))/h$, $h = \sqrt{\varepsilon}/\lVert d\rVert$. `'3-point'`는 $(g(x + \tfrac h2 d) - g(x - \tfrac h2 d))/h$, $h = 2\varepsilon^{1/3}/\lVert d\rVert$예요. 이 기울기는 기억을 거치지 않고 부르고 `njev`에 세요.
- 둘 다 없음: scipy의 `approx_fhess_p`, 곧 변수마다 $(g_j(x + h \circ d) - g_j(x))/h_j$이고 간격 $h$는 옵션 `eps`예요. $g(x)$는 그 반복의 기울기를 그대로 써요. scipy는 `ScalarFunction`의 기억을 거쳐 두 번째 곱부터 곱마다 $g(x)$를 다시 계산하므로, 여기서는 기울기 호출이 scipy의 절반쯤이고 부르는 점이 scipy와 달라요([수치 미분](/internals/optimize/derivatives/#헤시안의-차분)).

### 선 탐색과 멈춤

CG의 방향으로 BFGS와 같은 `_line_search_wolfe12`([준뉴턴 방법](/internals/optimize/quasi-newton/#선-탐색-wolfe-조건))를 해요. 인자는 scipy의 Newton-CG가 넘기는 값 그대로라, dcsrch의 걸음 범위가 $[10^{-8}, 50]$이고 zoom 쪽은 상한이 없어요. 첫 반복에는 앞의 값이 없어서 첫 시험 걸음이 1이에요(뉴턴 걸음 그대로). 걸음 $\alpha p$의 1-노름이 n·`xtol` 이하이면 멈춰요. 이 기준은 걸음의 크기라서 해의 정확도와 직접 이어지지 않아요.

선 탐색이 f가 NaN인 점에서 끝나면(wolfe2가 걸음을 NaN 영역까지 키울 때) 그 걸음을 받지 않고 마지막 유한한 반복점을 결과로 status 3 `NaN result encountered.`예요(L-BFGS-B의 규칙과 같아요).

결과의 `jac`는 돌려주는 x에서의 기울기예요. 마지막 선 탐색이 그 점의 기울기를 계산했으면 기억에서 꺼내고, 아니면(wolfe2가 기울기 없이 걸음을 받았거나 기울기 차분의 곱이 기억을 다른 점의 것으로 바꿔 놓았을 때) 한 번 더 부르고 `njev`에 세요. scipy의 `jac`은 마지막 반복을 시작한 점의 것이에요.

## 신뢰 영역 고리

trust-ncg와 trust-exact는 scipy의 `_minimize_trust_region`을 따라요. 반지름 $\Delta$ 안에서 부분문제

$$
\min_{\lVert p\rVert_2 \le \Delta} m_k(p)
$$

를 (대략) 풀고, 실제 감소와 예측 감소의 비를 봐요.

$$
\rho_k = \frac{f(x_k) - f(x_k + p)}{m_k(0) - m_k(p)}
$$

- 예측 감소가 0 이하이면(모형이 내려가지 않는 걸음) status 2로 멈춰요. 헤시안이나 기울기가 틀렸을 때 흔해요.
- $\rho < 1/4$이면 반지름을 1/4로 줄여요. 모형을 믿을 수 없다는 뜻이에요.
- $\rho > 3/4$이고 걸음이 경계에 닿았으면 반지름을 두 배로(`max_trust_radius`까지) 넓혀요.
- $\rho > \eta$이면 걸음을 받아요.

받은 뒤 기울기의 2-노름이 `gtol`보다 작으면 status 0, 반복 수가 `max_iter`에 닿으면 status 1이에요. `max_iter=0`이면 반복 없이 x0에서 멈춰요. scipy는 상한을 첫 반복 뒤에 보아 반복 하나를 하지만, 여기서는 newton-cg·BFGS·L-BFGS-B와 같은 뜻(반복 0번)이에요. 고리가 기울기 판정을 먼저 보므로 x0가 이미 해이면 status 0, 아니면 status 1이에요.

```cpp
                // csrc/optimize/trust.cpp
                const double rho = actual_reduction / predicted_reduction;
                // a NaN rho (f is NaN at the trial point) shrinks the radius as -inf does
                // (scipy's rho < 0.25 is false for NaN: the same subproblem again until max_iter)
                if (!(rho >= 0.25)) tr *= 0.25;
                else if (rho > 0.75 && hits) tr = pymin(2 * tr, max_trust_radius);
                if (rho > eta) m = std::move(mp);
```

시험점 $x_k + p$의 f가 +inf면 ρ = −inf라 걸음을 버리고 반지름을 줄여요. NaN이면 ρ도 NaN인데, scipy의 `rho < 0.25`는 NaN에서 거짓이라 반지름이 그대로이고 같은 부분문제를 `max_iter`까지 되풀이해요. 여기서는 `!(rho >= 0.25)`로 적어 NaN도 −inf처럼 반지름을 1/4로 줄여요. f가 정의되지 않는 곳을 NaN으로 알리는 함수에서도 반복이 그 둘레를 피해 가요.

trust-exact는 시험점의 부분문제를 만들 때 그 점의 헤시안을 먼저 계산해요(아래). 그 헤시안이 유한하지 않으면 scipy는 `scipy.linalg`의 검사로 예외를 내지만, 여기서는 그 걸음을 ρ = −inf처럼 거절하고 반지름을 줄여요. 그 점의 f는 부르지 않아요.

## trust-ncg: Steihaug–Toint CG

부분문제를 CG로 풀되(Nocedal–Wright 알고리즘 7.2), 두 경우에 신뢰 영역의 경계에서 멈춰요(Steihaug 1983, Toint 1981).

1. $z_0 = 0$, $r_0 = g$, $d_0 = -g$에서 시작해요. 허용오차는 $\min(\tfrac12, \sqrt{\lVert g\rVert})\,\lVert g\rVert$예요(2-노름).
2. 곡률 $d^{\mathsf T} H d \le 0$이면 직선 $z + \tau d$가 경계와 만나는 두 점을 구해 모형 값이 작은 쪽을 걸음으로 해요.
3. CG 걸음 $z + \alpha d$가 경계 밖이면 직선이 경계와 만나는 양의 $\tau$로 경계 위의 점을 걸음으로 해요.
4. 새 잔차가 허용오차보다 작으면 그 점이 걸음이에요(경계 안).

CG의 반복점은 0에서 시작해 노름이 단조로 커지므로, 경계 밖으로 나가는 첫 걸음에서 멈추는 것이 Krylov 공간 안의 최선에 가까워요. 모형 값도 반복마다 줄어서, 경계에서 멈춘 걸음도 Cauchy 점 이상의 감소를 줘요. 이것이 전체 방법의 수렴을 보장하는 조건이에요.

경계와의 교점은 $\lVert z + \tau d\rVert^2 = \Delta^2$, 곧 $a\tau^2 + b\tau + c = 0$($a = d^{\mathsf T} d$, $b = 2 z^{\mathsf T} d$, $c = z^{\mathsf T} z - \Delta^2$)의 두 근이에요. 상쇄를 피하는 근의 공식(b와 같은 부호로 $\sqrt{b^2 - 4ac}$를 더함)으로 계산해요.

```cpp
    // csrc/optimize/trust.cpp
    static std::pair<double, double> intersections(const vec& z, const vec& d, double r) {
        const double a = ddot(d, d);
        const double b = 2 * ddot(z, d);
        const double c = ddot(z, z) - r * r;
        const double disc = b * b - 4 * a * c;
        if (disc < 0) throw Stop{trSubproblemNotFinite};  // math.sqrt raises
        const double sd = std::sqrt(disc);
        const double aux = b + std::copysign(sd, b);
        const double ta = -aux / (2 * a);
        const double tb = -2 * c / aux;
        if (tb < ta) return {tb, ta};
        return {ta, tb};
    }
```

여기서 b의 **부호**가 근의 식을 고르므로 0의 부호가 걸음을 바꿔요. scipy의 `np.dot(z, d)`는 길이가 2 이상이면 `0.0 + cblas_ddot(...)`이라, BLAS가 −0.0을 돌려줘도 +0.0이 돼요. z = 0(첫 CG 걸음)에서 이 차이가 `copysign`의 결과를 바꿔요. 그래서 numpy의 `np.dot`과 같은 함수를 따로 둬요. BLAS의 값을 그대로 쓰면 MGH 8경우의 trust-ncg 걸음이 scipy와 끝자리에서 갈려요.

```cpp
// csrc/optimize/hessian.hpp
inline double np_dot(const double* a, const double* b, std::size_t n) {
    if (n == 1) return a[0] * b[0];
    return 0.0 + cblas_ddot(static_cast<linalg::lint>(n), a, 1, b, 1);
}
```

scipy의 Steihaug CG에는 반복 상한이 없어요. 헤시안이 대칭이면 CG는 n번 남짓(Rosenbrock n = 1000에서 8번, MGH에서 많아야 1.2n번)에 끝나지만, 대칭이 아닌 `hess`에서는 끝나지 않는 경우가 있어요(무작위 비볼록 문제 하나가 26번째 부분문제에서 돌아요). 여기서는 Newton-CG와 같은 20n번에서 멈추고 status 3이에요.

## trust-exact: Moré–Sorensen

부분문제의 해 $p^*$는 이런 λ ≥ 0과 함께 있어요(Moré, Sorensen 1983).

$$
(H + \lambda I)\, p^* = -g, \qquad H + \lambda I \succeq 0, \qquad \lambda\,(\Delta - \lVert p^*\rVert) = 0
$$

$H$가 양정치이고 뉴턴 걸음이 반지름 안이면 λ = 0이에요. 아니면 $\lVert p(\lambda)\rVert = \Delta$인 λ를 찾아야 하는데, $p(\lambda) = -(H + \lambda I)^{-1} g$의 노름은 λ의 유리함수라 그대로 풀면 뉴턴 방법이 잘 듣지 않아요. 그 역수는 거의 일차라서

$$
\phi(\lambda) = \frac1{\lVert p(\lambda)\rVert} - \frac1\Delta = 0
$$

에 뉴턴 방법을 써요. $H + \lambda I = U^{\mathsf T} U$(Cholesky)이고 $U^{\mathsf T} w = p$이면 뉴턴 걸음은

$$
\lambda_{\text{new}} = \lambda + \Bigl(\frac{\lVert p\rVert}{\lVert w\rVert}\Bigr)^2 \frac{\lVert p\rVert - \Delta}{\Delta}
$$

예요.

```cpp
                // csrc/optimize/trust.cpp
                w = p;  // solve_triangular(U, p, trans='T')
                if (triangular('T', U, w) > 0) throw Stop{trLinAlg};
                const double w_norm = nrm2(w);
                const double q = p_norm / w_norm;
                const double delta_lambda = q * q * (p_norm - tr) / tr;
                const double lambda_new = lambda_current + delta_lambda;
```

λ는 $[\lambda_{lb}, \lambda_{ub}]$에 가둬서 찾아요. 처음 구간은 Conn, Gould, Toint(2000)의 경계예요. Gershgorin 원으로 구한 고유값의 하한 $\ell_G$·상한 $u_G$와 $\lVert H\rVert_F$, $\lVert H\rVert_\infty$로

$$
\lambda_{ub} = \max\!\Bigl(0,\ \frac{\lVert g\rVert}{\Delta} + \min(-\ell_G, \lVert H\rVert_F, \lVert H\rVert_\infty)\Bigr), \quad
\lambda_{lb} = \max\!\Bigl(0,\ -\min_i H_{ii},\ \frac{\lVert g\rVert}{\Delta} - \min(u_G, \lVert H\rVert_F, \lVert H\rVert_\infty)\Bigr)
$$

이고, 반지름이 앞의 것보다 작아졌으면 앞에서 얻은 하한도 써요. 처음 λ는 $\lambda_{lb} = 0$이면 0, 아니면 $\max(\sqrt{\lambda_{lb}\lambda_{ub}},\ \lambda_{lb} + 0.01(\lambda_{ub} - \lambda_{lb}))$예요. 반복마다 세 경우가 있어요.

- **분해가 실패**(H + λI가 양정치가 아님): LAPACK `potrf`가 k번째에서 멈추면, 앞 k − 1 블록의 인자로 $H + \lambda I + \delta e_k e_k^{\mathsf T}$가 특이해지는 δ와 그 영벡터 v를 구해요. 그러면 $\lambda + \delta / \lVert v\rVert^2$가 λ의 새 하한이에요. λ를 구간 안에서 다시 골라요.
- **분해가 되고 ‖p‖ > Δ**(경계 밖): $\lvert\lVert p\rVert - \Delta\rvert / \Delta \le$ `k_easy` = 0.1이면 받아요. 아니면 하한을 λ로 올리고 뉴턴 걸음으로 가요.
- **분해가 되고 ‖p‖ < Δ, λ > 0**(경계 안): **어려운 경우**의 징후예요. g가 가장 작은 고유값의 고유벡터와 (거의) 수직이면 어떤 λ에서도 $\lVert p(\lambda)\rVert = \Delta$가 되지 않을 수 있어요. 그래서 U의 가장 작은 특이값 $s_{\min}$과 그 벡터 $z$를 어림하고(Cline, Moler, Stewart, Wilkinson 1979의 LINPACK 조건수 추정), $p + \tau z$가 경계에 닿는 τ 가운데 작은 쪽을 골라요. 이 걸음이 만드는 모형 값의 오차 $\tau^2 s_{\min}^2 / (p^{\mathsf T}(H + \lambda I)p + \lambda\Delta^2)$가 `k_hard` = 0.2 이하이면 받아요. 아니면 상한을 λ로, 하한을 $\lambda - s_{\min}^2$로 좁히고 뉴턴 걸음의 λ로 분해해 봐요.

`subproblem_max_iter`(기본 25)번 안에 끝나지 않으면 그때의 걸음을 써요. 걸음을 하나도 만들지 못했으면 scipy는 `UnboundLocalError`로 끝나지만 여기서는 status 3이에요. 기울기가 $n\varepsilon\lVert H\rVert_\infty$보다 작으면 위의 식이 0에 가까운 수로 나누므로 따로 다뤄요(λ = 0이면 걸음 0, 아니면 $\Delta z$를 시험).

### scipy.linalg와 같은 배치

같은 λ의 차례가 나오는 것은 Cholesky의 반올림까지 scipy와 같은 꼴로 계산하기 때문이에요. scipy의 `cho_factor`·`cholesky`는 `H + λ np.eye(n)`을 열 우선으로 복사해 `potrf('U')`에 넘기고, 래퍼가 아래 삼각을 0으로 지워요. potrf는 위 삼각만 읽으므로 그것만 열 우선으로 옮기고(64 × 64 타일의 전치) 아래 삼각을 0으로 둬요. 그 밖에 `scipy.linalg.norm`은 `dnrm2`, $\lVert H\rVert_\infty$는 `lange('1', Hᵀ)`(행 우선 행렬을 열 우선으로 읽은 것), Frobenius 노름은 numpy처럼 $\sqrt{\text{ravel} \cdot \text{ravel}}$, 합은 쌍별 합, 최대·최소는 Python의 `max`·`min`이에요. 실패한 분해의 앞 블록 $U_{1:k-1, 1:k-1}$은 scipy에서 연속이 아닌 조각이라 `solve_triangular`가 전치를 복사해 아래 삼각·전치 꼴(`trtrs('L', 'T')`)로 풀고, 여기서도 그대로 해요.

trust-exact는 시험점의 부분문제를 만들 때 그 점의 헤시안을 f보다 먼저 계산해요(scipy의 `IterativeSubproblem.__init__`이 그 점의 Gershgorin 경계와 노름을 미리 구하기 때문이에요). 호출 순서도 scipy와 같아요. `triangular`는 `trtrs`를 부르는 작은 함수로, 행렬이 크면 GIL을 놓고 풀어요.

## 유한하지 않은 값과 예외

scipy가 `scipy.linalg`의 `check_finite`로 `ValueError`를 내는 곳(받아들인 점의 기울기 노름, 부분문제 안의 벡터)과 `math.sqrt`의 음수(교점의 판별식)에서는 커널이 음의 상태와 그 점을 돌려주고, Python 층이 그 점을 적은 `ValueError`를 내요. trust-ncg에서 헤시안의 곱(또는 `hessp`)이 유한하지 않으면 그것을 짚어요(`'hess' is not finite at x = [...]`, `'hessp' is not finite at x = [...]`). 시험점의 값이나 trust-exact 시험점의 헤시안이 유한하지 않은 것은 에러가 아니라 거절한 걸음이에요(위).

```python
>>> import math
>>> import stardust as sd
>>> def f(x):
...     return (x[0] - 1)**2 + (x[1] - 2)**2
>>> def grad(x):
...     return [2 * (x[0] - 1), 2 * (x[1] - 2) if x[0] < 0.5 else math.nan]
>>> def hess(x):
...     return [[2.0, 0.0], [0.0, 2.0]]
>>> sd.optimize.minimize(f, [0.0, 0.0], method='trust-exact', jac=grad, hess=hess)
Traceback (most recent call last):
    ...
ValueError: minimize(): 'jac' is not finite at x = [0.9999999999999999, 1.9999999999999998]
```

## 셈

`nfev`, `njev`는 `ScalarFunction`의 셈이라 scipy와 같아요(newton-cg의 끝 기울기 하나는 예외). `nhev`는 실제로 부른 수예요. 호출 가능한 `hess`는 x0의 것을 포함한 호출 수, `hessp`와 차분 연산자는 곱의 수, 기울기 차분의 곱은 0이에요. scipy는 `hessp`만 준 trust-ncg에서 부르지 않은 자리 채움 `hess`의 1을 더하고, trust-ncg가 결과의 `hess`를 위해 끝에 부르는 것과 `max_iter=0`인 newton-cg가 x0에서 부른 `hess`는 세지 않아요.

## 같은 점을 부른다는 것

같은 알고리즘을 같은 계산 순서로 해서, 지금은 성공 경로의 호출점이 scipy와 비트까지 같아요. scipy 1.18.1이 기록한 MGH 110경우와 Rosenbrock n = 2·5, 최대 엔트로피(헤시안은 2차 전진 자동 미분의 정확한 값)에서 세 방법 113번씩 모두 결과의 필드(x의 비트, `fun`, `nfev`, 반복 수, `status`, `message`)가 같아요. scipy를 실행하며 부른 점(곱의 p까지)을 차례대로 견주면 열 묶음(Newton-CG의 `hess`·`hessp`·`'2-point'`·`'3-point'`·없음, trust-ncg의 `hess`·`hessp`·`'2-point'`·`'3-point'`, trust-exact) 1,130번이 모두 비트까지 같아요. 옵션과 가장자리를 바꾼 525번(시험점의 inf 포함; NaN의 경로는 위처럼 일부러 달라요), 무작위 비볼록 사차 함수 $\sum a_i x_i^4 + x^{\mathsf T} B x/2 + c^{\mathsf T} x$(n = 2–12, 넷에 하나는 대칭이 아닌 헤시안) 300문제 × 7가지, Rosenbrock n = 64–200의 28번도 같아요. trust-exact의 실패한 분해(앞 블록 k = 2–12)와 어려운 경우, $\lVert g\rVert \le n\varepsilon\lVert H\rVert_\infty$의 가지도 이 경우들에서 지나가요.
