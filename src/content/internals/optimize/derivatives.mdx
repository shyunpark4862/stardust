## 한눈에 보기

사용자가 기울기나 야코비안을 주지 않으면 이 영역의 함수들은 차분으로 어림해요. 차분은 한 가지가 아니에요. 반복 안에서 쓰는 차분은 scipy와 같은 점에서 함수를 부르도록 scipy의 것을 그대로 따르고, `approx_fprime`의 기본은 한 번의 정확한 결과를 위해 따로 만든 5점 차분이에요.

| 어디서 | 차분 | 간격 | 코드 |
|---|---|---|---|
| `approx_fprime`, `check_grad`의 기본 | 5점 중앙(못 쓰면 한쪽 5점) | 변수마다 $2^{-8}\lvert x_j\rvert$부터 4배씩 줄이며 골라요 | `_diff.py`의 `Differences` |
| `approx_fprime`, `check_grad`의 `epsilon` | 앞쪽 | `epsilon` | `_diff.py`의 `_forward` |
| `minimize`의 `jac=None` | 앞쪽 | 절대 간격 `eps`(BFGS $\sqrt\varepsilon$, L-BFGS-B $10^{-8}$) | `objective.hpp` |
| `minimize`, `least_squares`의 `'2-point'` | 앞쪽 | $\sqrt\varepsilon\,\max(1, \lvert x_j\rvert)$ 또는 상대 간격 | `diff.hpp`, `objective.hpp`, `lsq.cpp` |
| `minimize`, `least_squares`의 `'3-point'` | 중앙(경계에서는 한쪽 3점) | $\varepsilon^{1/3}\max(1, \lvert x_j\rvert)$ 또는 상대 간격 | 같은 파일 |
| `minimize`의 `hess='2-point'`·`'3-point'` | 기울기의 방향 차분 | 방향 $p$를 따라 거리 $\sqrt\varepsilon$, $\varepsilon^{1/3}$ | `hessian.hpp` |
| `newton-cg`의 `hess`·`hessp` 없음 | 기울기의 방향 차분 | `eps`$\cdot p$ | `newton_cg.cpp` |
| `root('hybr')`의 `jac=None` | MINPACK `fdjac1`(앞쪽, 띠 묶음) | $\sqrt{\max(\text{eps}, \varepsilon)}\,\lvert x_j\rvert$ | `hybrd.cpp` |
| `root('lm')`의 `jac=None`, nls의 반복 | MINPACK `fdjac2`(앞쪽) | 같은 꼴 | `lsq.cpp` |
| `root_scalar` newton의 `fprime=None` | 앞쪽 | $\sqrt\varepsilon\,\max(1, \lvert x\rvert)$ | `scalar.cpp` |

이 글에서 $\varepsilon = 2^{-52}$은 기계 엡실론, $u = 2^{-53}$은 단위 반올림이에요. scipy의 기본 간격 $\sqrt\varepsilon = 2^{-26} \approx 1.49 \times 10^{-8}$과 $\varepsilon^{1/3} \approx 6.06 \times 10^{-6}$이 여기저기 나와요.

## 차분의 오차: 절단과 반올림

$f$를 $x$ 둘레에서 Taylor 전개하면 세 차분의 오차가 나와요.

$$
\frac{f(x + h) - f(x)}{h} = f'(x) + \frac{h}{2} f''(x) + O(h^2)
$$

$$
\frac{f(x + h) - f(x - h)}{2h} = f'(x) + \frac{h^2}{6} f'''(x) + O(h^4)
$$

$$
\frac{f(x - 2h) - 8f(x - h) + 8f(x + h) - f(x + 2h)}{12h} = f'(x) - \frac{h^4}{30} f^{(5)}(x) + O(h^6)
$$

마지막 식은 $f(x \pm h)$, $f(x \pm 2h)$의 전개를 $8[f(x + h) - f(x - h)] - [f(x + 2h) - f(x - 2h)]$로 합치면 $h^3$ 항이 $\tfrac{8}{3} - \tfrac{8}{3} = 0$으로 지워지고 $h^5$ 항이 $\tfrac{8}{60} - \tfrac{32}{60} = -\tfrac{2}{5}$로 남아서 나와요. 이것이 **절단 오차**예요.

반대쪽에는 **반올림 오차**가 있어요. 계산한 함숫값이 상대 $\delta$(적어도 $u$, 함수가 복잡하면 그 몇 배)만큼 틀리면, 차분의 분자에 그 오차가 가중치를 곱해 더해지고 $h$로 나뉘어요. 가중치의 절댓값 합은 앞쪽 차분이 2, 중앙 차분이 1(분모의 2를 넣어), 5점 차분이 $18/12 = 1.5$예요.

$$
E_{\text{앞}}(h) \approx \frac{h}{2}\lvert f''\rvert + \frac{2\delta\lvert f\rvert}{h},\quad
E_{\text{중앙}}(h) \approx \frac{h^2}{6}\lvert f'''\rvert + \frac{\delta\lvert f\rvert}{h},\quad
E_{5}(h) \approx \frac{h^4}{30}\lvert f^{(5)}\rvert + \frac{1.5\,\delta\lvert f\rvert}{h}
$$

$f$와 그 도함수가 1 근처의 크기라고 보면, 두 항이 맞먹는 간격과 그때의 오차는 앞쪽 차분이 $h \sim \delta^{1/2}$에서 $\delta^{1/2} \approx 10^{-8}$, 중앙 차분이 $h \sim \delta^{1/3}$에서 $\delta^{2/3} \approx 10^{-11}$, 5점 차분이 $h \sim \delta^{1/5} \approx 10^{-3}$에서 $\delta^{4/5} \approx 10^{-13}$이에요. scipy의 `'2-point'`와 `'3-point'`가 $\sqrt\varepsilon$과 $\varepsilon^{1/3}$을 쓰는 것이 이 계산에서 나와요.

두 가지가 모든 차분에 공통이에요.

- **간격의 척도.** $x$가 크면 같은 $h$라도 $x + h$의 반올림이 커져요. 그래서 간격을 $\lvert x\rvert$에 비례하게 잡아요. scipy는 $\max(1, \lvert x\rvert)$에 비례하게 잡아 $x$가 0 근처일 때 간격이 0으로 줄지 않게 하고, MINPACK은 $\lvert x\rvert$에 비례하게 잡되 $x = 0$이면 상수를 써요.
- **실제로 움직인 거리.** $x + h$는 반올림되므로 실제로 움직인 거리는 $h$가 아니라 $(x + h) - x$예요. $\lvert h\rvert \le \lvert x\rvert/2$이면(또는 $x = 0$이면) 이 뺄셈은 Sterbenz 보조정리로 정확해요. scipy의 차분은 분모에 이 값을 써서 $x + h$의 반올림이 몫에 들어가지 않게 해요. MINPACK은 $h$로 나눠요. 이 영역은 각각을 따르는 방법에 맞춰 그대로 써요.

## scipy approx_derivative의 2점과 3점

반복 안의 차분(`minimize`의 `jac`, `least_squares`의 `jac`)은 scipy 1.18.1 `approx_derivative`의 계산을 C++로 같은 순서로 적은 것이에요. 간격은 `_compute_absolute_step`, 경계 조정은 `_adjust_scheme_to_bounds`와 같아요.

```cpp
// csrc/optimize/diff.hpp
// sqrt(eps) = 2^-26: the relative step of fdjac2 (epsfcn = eps) and of scipy's '2-point'.
inline double rel_step_2point() { return std::sqrt(std::numeric_limits<double>::epsilon()); }
// eps^(1/3): scipy's '3-point'.
inline double rel_step_3point() { return std::pow(std::numeric_limits<double>::epsilon(), 1.0 / 3.0); }

// scipy's _compute_absolute_step for one variable: rstep sign(x) max(1, |x|) by default
// (sign(0) = 1); with a relative step r, r sign(x) |x|, unless that step vanishes in x + h.
inline double absolute_step(double x, double rstep, bool has_rel, double rel) {
    const double sign = x >= 0 ? 1.0 : -1.0;
    const double dflt = rstep * sign * std::max(1.0, std::abs(x));
    if (!has_rel) return dflt;
    const double h = rel * sign * std::abs(x);
    return (x + h) - x == 0 ? dflt : h;
}
```

`'2-point'`의 상대 간격은 $\sqrt\varepsilon$, `'3-point'`는 $\varepsilon^{1/3}$이에요. 사용자가 상대 간격 $r$(`least_squares`의 `diff_step`, `minimize`의 `finite_diff_rel_step`)을 주면 $h = r\,\mathrm{sign}(x)\lvert x\rvert$이고, 그것이 $x + h$에서 사라지면($x = 0$일 때 등) 기본 간격으로 돌아가요.

### 경계에서의 조정

`l-bfgs-b`와 경계 있는 `least_squares`에서는 차분의 점이 경계 밖으로 나가면 안 돼요. 함수가 경계 밖에서 정의되지 않을 수도 있어서예요. 앞쪽 차분은 경계를 넘는 걸음을 반대로 돌리고, 반대쪽도 맞지 않으면 먼 쪽 경계까지의 거리를 써요.

```cpp
// csrc/optimize/diff.hpp
// scipy's _adjust_scheme_to_bounds, '1-sided' with one step: the step turned back when
// it leaves [lb, ub] and fits on the other side, else the distance to the farther bound.
inline double adjust_one_sided(double x, double h, double lb, double ub) {
    const double lower = x - lb, upper = ub - x;
    const double xh = x + h;
    const bool violated = xh < lb || xh > ub;
    const bool fitting = std::abs(h) <= std::max(lower, upper);
    if (violated && fitting) return -h;
    if (!fitting) return upper >= lower ? upper : -lower;
    return h;
}
```

중앙 차분은 $x \pm h$가 모두 안쪽이면 그대로 쓰고, 아니면 먼 쪽으로 가는 한쪽 3점 차분

$$
f'(x) \approx \frac{-3f(x) + 4f(x + h) - f(x + 2h)}{2h} = f'(x) - \frac{h^2}{3} f'''(x) + O(h^3)
$$

로 바꿔요. $h$는 그쪽 거리의 절반을 넘지 않게 줄이고, 그렇게 줄인 간격이 가까운 쪽 거리보다 짧으면 차라리 가까운 쪽 거리로 중앙 차분을 해요.

```cpp
// csrc/optimize/diff.hpp
inline double adjust_two_sided(double x, double h, double lb, double ub, bool& one_sided) {
    h = std::abs(h);
    one_sided = false;
    const double lower = x - lb, upper = ub - x;
    if (lower >= h && upper >= h) return h;
    double ha;
    if (upper >= lower) ha = std::min(h, 0.5 * upper);
    else ha = -std::min(h, 0.5 * lower);
    one_sided = true;
    const double min_dist = std::min(upper, lower);
    if (std::abs(ha) <= min_dist) {
        ha = min_dist;
        one_sided = false;
    }
    return ha;
}
```

`l-bfgs-b`의 시작점이 위 경계에 있으면 그 변수의 차분이 아래로 가는 것을 볼 수 있어요.

```python

>>> pts = []
>>> def f(x):

>>> [(p[0] - 1.0, p[1] - 0.5) for p in pts[1:5]]

```

`jac=None`인 L-BFGS-B는 절대 간격 `eps=1e-8`의 앞쪽 차분이에요. 첫 변수는 위 경계 1.0에 있어서 $-10^{-8}$로 돌렸고(실제로 움직인 거리는 반올림으로 $-1.0000000050 \times 10^{-8}$), 둘째 변수는 안쪽이라 $+10^{-8}$이에요. `'3-point'`에서는 첫 변수가 $(x - h, x - 2h)$의 한쪽 3점, 둘째 변수가 $x \pm h$의 중앙 차분이에요.

### 유한하지 않은 한쪽

`least_squares`의 `'2-point'`는 한쪽의 잔차가 유한하지 않으면 경계 안에서 반대쪽으로 한 번 더 해 봐요. scipy는 NaN으로 계속 가지만, 이 영역의 최소제곱은 nls의 규칙을 따라요.

```cpp
    // csrc/optimize/lsq.cpp
    bool two_point(vec& x, const double* r, double* J, double* wa) {
        const double rstep = rel_step_2point();
        for (lint j = 0; j < p; ++j) {
            const auto uj = static_cast<std::size_t>(j);
            const double t = x[uj];
            double h = adjust_one_sided(t, step(j, t, rstep), (*lb)[uj], (*ub)[uj]);
            bool ok = false;
            for (int attempt = 0; attempt < 2 && !ok; ++attempt) {
                if (attempt == 1) {
                    h = -h;
                    if (t + h < (*lb)[uj] || t + h > (*ub)[uj]) break;
                }
                x[uj] = t + h;
                ok = eval(x, wa);
                x[uj] = t;
                const double dx = (t + h) - t;
                if (ok)
                    for (lint i = 0; i < m; ++i) J[i + j * m] = (wa[i] - r[i]) / dx;
            }
            if (!ok) return false;
        }
        return true;
    }
```

`'3-point'`는 다시 해 보지 않고 바로 실패를 알려요(`least_squares(): the differences of 'fun' are not finite at x = [...]`). `minimize`의 차분은 scipy처럼 유한하지 않은 값을 따로 다루지 않고 그대로 기울기에 넣어요. 그다음은 방법의 처리를 따르고(선 탐색이 걸음을 줄이는 등), 시작점의 차분이 유한하지 않으면 `ValueError`예요.

### minimize의 jac=None

`jac=None`은 scipy의 `minimize`처럼 **절대** 간격 `eps`의 앞쪽 차분이에요(`'2-point'`가 상대 간격인 것과 달라요). BFGS의 기본은 $\sqrt\varepsilon$, L-BFGS-B는 $10^{-8}$이에요. $x_j$가 커서 $x_j + \text{eps}$가 $x_j$로 반올림되면 그 변수만 기본 상대 간격으로 바꿔요.

```cpp
        // csrc/optimize/objective.hpp
        const double rstep = rel_step_2point();
        for (std::size_t j = 0; j < n; ++j) {
            const double t = x[j];
            double h;
            if (mode == kGradAbsolute) {
                // approx_derivative's abs_step: eps, unless it vanishes in x + h
                h = steps[j];
                if ((t + h) - t == 0) h = rstep * (t >= 0 ? 1.0 : -1.0) * std::max(1.0, std::abs(t));
            } else {
                h = absolute_step(t, rstep, !steps.empty(), steps.empty() ? 0.0 : steps[j]);
            }
            h = adjust_one_sided(t, h, lb[j], ub[j]);
            xt[j] = t + h;
            const double f1 = call_f(xt.data());
            xt[j] = t;
            g[j] = (f1 - f0) / ((t + h) - t);
        }
        nfev += static_cast<std::int64_t>(n);
```

셈은 차분 하나에 $n$(3점은 $2n$)을 `nfev`에 더하고, 차분 기울기 하나를 `njev`에 하나 세요. scipy의 `ScalarFunction`도 같은 셈이에요.

## 헤시안의 차분

`hess='2-point'`나 `'3-point'`는 헤시안 행렬을 만들지 않고 **헤시안과 벡터의 곱**만 기울기의 차분으로 계산해요. 기울기 $g$의 방향 $p$로의 방향 도함수가 $Hp$예요.

$$
Hp \approx \frac{g(x + dx\,p) - g(x)}{dx},\quad dx = \frac{\sqrt\varepsilon}{\lVert p\rVert}
\qquad\text{또는}\qquad
Hp \approx \frac{g(x + \tfrac{dx}{2}p) - g(x - \tfrac{dx}{2}p)}{dx},\quad dx = \frac{2\varepsilon^{1/3}}{\lVert p\rVert}
$$

$dx$를 $\lVert p\rVert$로 나누므로 $x$가 실제로 움직이는 거리는 $p$의 크기와 상관없이 $\sqrt\varepsilon$(또는 양쪽으로 $\varepsilon^{1/3}$)이에요. scipy `approx_derivative`가 선형 연산자를 만들 때의 간격과 같아요.

```cpp
    // csrc/optimize/hessian.hpp
    void difference_product(const double* p, double* out) {
        bool zero = true;
        for (std::size_t i = 0; i < n && zero; ++i) zero = p[i] == 0;
        if (zero) {
            for (std::size_t i = 0; i < n; ++i) out[i] = 0.0;
            return;
        }
        const double norm = std::sqrt(np_dot(p, p, n));  // numpy's norm: sqrt(p . p)
        if (mode == kHessTwoPoint) {
            const double dx = rel_step_2point() / norm;
            for (std::size_t i = 0; i < n; ++i) xt[i] = hx[i] + dx * p[i];
            obj.raw_gradient(xt.data(), g1.data());
            for (std::size_t i = 0; i < n; ++i) out[i] = (g1[i] - hg[i]) / dx;
            return;
        }
        const double dx = 2 * rel_step_3point() / norm;
        for (std::size_t i = 0; i < n; ++i) xt[i] = hx[i] - (dx / 2) * p[i];
        obj.raw_gradient(xt.data(), g1.data());
        for (std::size_t i = 0; i < n; ++i) xt[i] = hx[i] + (dx / 2) * p[i];
        obj.raw_gradient(xt.data(), g2.data());
        for (std::size_t i = 0; i < n; ++i) out[i] = (g2[i] - g1[i]) / dx;
    }
```

## MINPACK의 fdjac1과 fdjac2

`root`의 두 방법은 MINPACK의 차분이에요. `'hybr'`은 `hybrd`의 `fdjac1`, `'lm'`은 `lmdif`의 `fdjac2`이고, nls의 반복도 `fdjac2`예요. 간격은

$$
h_j = \sqrt{\max(\text{epsfcn}, \varepsilon)}\;\lvert x_j\rvert \quad(x_j = 0\text{이면 } \sqrt{\max(\text{epsfcn}, \varepsilon)})
$$

이고, `epsfcn`(`root`의 옵션 `eps`)은 "함숫값의 상대 오차"예요. 함수에 반올림보다 큰 오차가 있으면 그 크기를 알려 간격을 키우라는 뜻이에요. 앞의 오차 분석에서 $\delta$를 `epsfcn`으로 둔 것과 같아요. MINPACK은 $h$로 나누고(scipy와 같아야 하는 `root`가 그렇게 해요), nls는 실제로 움직인 거리 $(x_j + h) - x_j$로 나눠요.

```cpp
    // csrc/optimize/lsq.cpp
        // MINPACK's fdjac2: h = sqrt(max(epsfcn, eps)) |x_j| (that at 0), the step actually
        // taken ((x_j + h) - x_j) in the quotient (nls) or h itself (MINPACK; root); backwards
        // when forwards leaves the bounds or the model is not finite there.
        const double eps = std::sqrt(std::max(epsfcn, kEps));
        for (lint j = 0; j < p; ++j) {
            const double t = x[j];
            double h = eps * std::abs(t);
            if (h == 0) h = eps;
            if (ub && t + h > (*ub)[j]) h = -h;
            bool ok = false;
            for (int attempt = 0; attempt < 2 && !ok; ++attempt) {
                if (attempt == 1) {
                    h = -h;
                    if (lb && (t + h < (*lb)[j] || t + h > (*ub)[j])) break;
                }
                x[j] = t + h;
                const double hh = minpack_h ? h : x[j] - t;
                ok = eval(x, wa);
                x[j] = t;
                if (ok)
                    for (lint i = 0; i < m; ++i) J[i + j * m] = (wa[i] - r[i]) / hh;
            }
            if (!ok) return false;
        }
        return true;
    }
```

### 띠 야코비안의 묶음

`fdjac1`에는 띠 구조를 쓰는 길이 있어요. 식 $i$가 변수 $i - m_l, \dots, i + m_u$에만 기대면 야코비안은 아래 띠 너비 $m_l$, 위 띠 너비 $m_u$의 띠 행렬이에요. 그러면 변수 $j$와 $j + (m_l + m_u + 1)$은 같은 식에 함께 나타나지 않으니, 둘을 동시에 움직여도 각 식의 변화가 어느 변수 때문인지 가를 수 있어요. 그래서 $j, j + s, j + 2s, \dots$($s = m_l + m_u + 1$)를 한 번에 움직이고 함수를 한 번만 불러요. 야코비안 하나에 $n$번 대신 $s$번이에요(Curtis, Powell, Reid의 열 묶음과 같은 생각이에요).

```cpp
        // csrc/optimize/hybrd.cpp
        for (lint k = 0; k < msum; ++k) {
            double sign = 1;
            bool ok = false;
            for (int side = 0; side < 2 && !ok; ++side) {
                if (side == 1) sign = -1;
                for (lint j = k; j < n; j += msum) {
                    wa2[j] = x[j];
                    double h = eps * std::abs(wa2[j]);
                    if (h == 0) h = eps;
                    x[j] = wa2[j] + sign * h;
                }
                ok = eval(x, wa1);
                for (lint j = k; j < n; j += msum) x[j] = wa2[j];
            }
            if (!ok) return false;
            for (lint j = k; j < n; j += msum) {
                double h = eps * std::abs(wa2[j]);
                if (h == 0) h = eps;
                h = sign * h;
                for (lint i = 0; i < n; ++i) {
                    fjac[i + j * n] = 0;
                    if (i >= j - mu && i <= j + ml) fjac[i + j * n] = (wa1[i] - fvec[i]) / h;
                }
            }
        }
        return true;
```

변수 20개의 삼중 대각 계(Broyden tridiagonal)에서 `band=(1, 1)`을 주면 야코비안 하나에 함수를 3번만 불러요. 결과는 같아요.

```python
>>> n = 20
>>> def F(x):
...     v = x.tolist()
...     out = []
...     for i in range(n):
...         left = v[i - 1] if i > 0 else 0.0
...         right = v[i + 1] if i < n - 1 else 0.0
...         out.append((3 - 2 * v[i]) * v[i] - left - 2 * right + 1)
...     return out
>>> a = sd.optimize.root(F, [-1.0] * n)
```

## approx_fprime의 기본: 간격을 고르는 5점 차분

`approx_fprime`과 `check_grad`의 기본은 반복 안에서 쓰는 것이 아니라 한 번의 정확한 결과를 위한 차분이에요. 그래서 scipy와 같을 필요가 없고, 함수를 더 불러서라도 오차를 줄여요. `sd.regression.nls`가 해에서의 야코비안을 구할 때도 같은 코드를 써요. 세 가지로 이뤄져요.

**5점 스텐실.** 중앙 5점 차분은 절단 오차가 $h^4$이에요. 경계(nls)나 한쪽에서 함수가 유한하지 않을 때는 한쪽 5점 차분

$$
f'(x) \approx \frac{-25f(x) + 48f(x + h) - 36f(x + 2h) + 16f(x + 3h) - 3f(x + 4h)}{12h}
$$

(또는 그 거울)을 써요. 이것도 절단 오차가 $h^4$이지만 계수가 $\tfrac15$로 중앙의 $\tfrac{1}{30}$보다 크고, 가중치의 절댓값 합 $128/12$도 중앙의 $18/12$보다 7배쯤 커서 반올림에 그만큼 약해요.

```python
    # src/stardust/optimize/_diff.py
    _STENCILS = (
        ((-2, -1, 1, 2), (1.0, -8.0, 8.0, -1.0)),
        ((0, 1, 2, 3, 4), (-25.0, 48.0, -36.0, 16.0, -3.0)),
        ((0, -1, -2, -3, -4), (25.0, -48.0, 36.0, -16.0, 3.0)),
    )
```

**2의 거듭제곱 간격.** $h = 2^{b + e}$이고 $2^b$는 $\lvert x_j\rvert < 2^b \le 2\lvert x_j\rvert$인 2의 거듭제곱(`math.frexp`의 지수)이에요. $e \le -8$이라 $kh$($k \le 4$)가 $\lvert x_j\rvert$보다 훨씬 작고, $e \ge -30$이라 $h$가 $x_j$의 끝자리 단위의 배수예요. 그래서 $x_j \pm kh$가 반올림 없이 정확하고 분모 $12h$도 정확해요. 몫에 들어가는 반올림은 함숫값의 것뿐이에요.

**변수마다 간격 고르기.** $2^{-8}$에서 시작해 지수를 2씩(간격을 4배씩) 줄이며 추정 $c_k$를 거듭해요. 절단 오차가 앞서면 간격이 1/4이 될 때 오차가 $4^4 = 256$배 줄어서, 이웃한 두 추정의 차이 $d_k = \max\lvert c_k - c_{k-1}\rvert / \max\lvert c_k\rvert$도 256배 가까이 줄어요. 반올림 오차가 앞서기 시작하면 $d_k$가 더 줄지 않거나 커져요. 그래서 $d_k < d_{k-1}/8$인 동안 이어 가고, 그렇지 않으면 멈추고 마지막으로 받아들인 추정을 써요.

```python
    # src/stardust/optimize/_diff.py
    def choose_step(self, x, j, g0):
        """The step of variable j, chosen once: from 2^-8 |x_j| down by factors of 4 while
        consecutive estimates get closer by more than 8 times; the last such estimate and its
        step."""
        base = math.frexp(abs(x[j]) if x[j] != 0 else 1.0)[1]
        best = hbest = None
        dprev = math.inf
        prev = None
        for e in range(_FD_START, _FD_END - 1, -2):
            h = math.ldexp(1.0, base + e)
            col = self.column(x, j, h, g0)
            if col is None:
                if best is not None:
                    break
                continue
            if prev is None:
                best, hbest = col, h
            else:
                sc = float(_sd.max(_sd.abs(col)))
                dd = float(_sd.max(_sd.abs(col - prev))) / sc if sc > 0 else 0.0
                if dd >= dprev / 8:
                    break
                best, hbest = col, h
                dprev = dd
                if dd == 0:
                    break
            prev = col
        return best, hbest
```

$e^x$의 $x = 1$에서 같은 규칙을 따라가 보면 $e = -12$($h = 2^{-11}$)를 골라요.

### 반올림 수준의 열

`Differences`는 열마다 반올림 수준도 재요. 스텐실의 값 $f_i(x + oh)$마다 최대 $u\lvert f_i\rvert$의 반올림이 있으니, 원소 $i$의 불확실성은 $\tfrac{\sum_o \lvert w_o\rvert}{12h}\,u\max_o\lvert f_i(x + oh)\rvert$이고 그 2-노름이 `noise`예요. nls는 열의 노름이 `noise`의 16배 이하이면 그 열을 0으로 둬요(`zero_noise`). `approx_fprime`은 이것을 하지 않고 계산한 값을 그대로 돌려줘요. 그래서 참값이 0인 열에도 $10^{-14}$쯤의 수가 남아요.

```python

>>> D = Differences(g, 2, [-math.inf] * 2, [math.inf] * 2)
>>> J, _ = D.jacobian([1.0, 2.0], g([1.0, 2.0]))

array([[ 9.473903143468002e-15,    -0.4161468365471516],

>>> D.noise[0]

array([ 0.0, -0.0], dtype=float64)
```

$x_0$이 함수에 나오지 않으니 첫 열은 참값이 0이에요. 그런데도 $9.5 \times 10^{-15}$가 나오는 것은 $f - 8f + 8f - f$에서 $7f$가 반올림되기 때문이에요. 열의 노름 $1.2 \times 10^{-14}$가 반올림 수준 $3.4 \times 10^{-13}$보다 작으니 nls라면 0으로 둬요. nls가 이렇게 하는 이유는 반올림 잡음뿐인 열이 제 방향을 가져서 다른 모수의 열 자리를 차지할 수 있어서예요. `approx_fprime`은 값을 바꾸지 않아요.

## approx_fprime의 epsilon

`epsilon`을 주면 scipy `approx_fprime`과 같은 앞쪽 차분이에요. scipy가 `approx_derivative(method='2-point', abs_step=epsilon)`로 하는 계산을 그대로 적었어요.

```python
# src/stardust/optimize/_diff.py
def _forward(f, x, f0, eps, m, func, what):
    """scipy's approx_fprime: (f(x + h_j e_j) - f(x)) / ((x_j + h_j) - x_j) with h_j = eps_j,
    or sqrt(u) sign(x_j) max(1, |x_j|) where x_j + eps_j rounds to x_j (approx_derivative's
    abs_step)."""
    xl = x.tolist()
    cols = []
    for j, (t, h) in enumerate(zip(xl, eps)):
        if (t + h) - t == 0:
            h = 2.0**-26 * (1.0 if t >= 0 else -1.0) * max(1.0, abs(t))
        xj = x.copy()
        xj[j] = t + h
        dx = (t + h) - t
        cols.append((_f_values(f(xj), func, what, m)[0] - f0) / dx)
    return _sd.stack(cols, axis=1)
```

같은 함수라면 scipy와 부르는 점이 같고 결과가 비트까지 같아요. MGH 47경우의 기울기와 야코비안에서 `epsilon=2**-26`(scipy의 기본)의 결과가 scipy와 모두 같아요. 기본과 달리 `xk`에서 함수가 유한하지 않아도 계산해요.

## check_grad

`direction='all'`은 `grad(x0)`와 `approx_fprime(x0, func, epsilon=epsilon)`의 차이의 2-노름이에요. `direction='random'`은 표준정규분포에서 뽑은 방향 $v$ 하나로 변수 하나짜리 함수 $w \mapsto f(x_0 + wv)$를 만들어, 그 $w = 0$에서의 도함수를 같은 차분으로 구하고 $\nabla f(x_0)\cdot v$와 견줘요.

```python
    # src/stardust/optimize/_diff.py
    v = Normal().sample((n,), rng=rng)
    analytic = float(_linalg.vecdot(g0, v))
    J, _ = _derivative(fn, "func", lambda w: value(x + float(w[0]) * v), _sd.asarray([0.0]), epsilon)
    return abs(analytic - float(J[0][0]))
```

변수가 하나뿐인 차분이라 $n$과 상관없이 함수를 8–20번쯤 불러요. 방향은 `sd.stats.Normal().sample`로 뽑으므로 같은 시드면 같은 방향이에요. scipy는 numpy의 난수로 뽑아서 방향이 달라요. `epsilon`은 이 한 변수 함수의 간격이라 수 하나만 받아요.
