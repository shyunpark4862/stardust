## 한눈에 보기

[`haversine`](/api/spatial/haversine/)은 (위도 φ, 경도 λ)를 라디안으로 받아 단위 구 위 두 점의 중심각을 돌려줘요. 이 거리로 가까운 이웃을 찾을 때 위도·경도 평면에 KD 트리를 바로 세울 수는 없어요. 경도는 ±π에서 이어 붙어 있어 평면의 상자가 날짜 변경선 건너편의 이웃을 멀다고 보고, 중심각은 Minkowski 거리가 아니라서 상자까지의 거리가 하한이 되지도 않아요. sklearn은 이 거리에 `BallTree`를 써요.

sd는 다른 길을 가요. 점을 단위 구 위의 3차원 점으로 옮기면 두 점 사이의 직선 거리(현)가 중심각의 단조 함수라서, 이미 있는 KD 트리와 `euclidean` 커널로 후보를 고를 수 있어요. 돌려주는 거리와 넣을지·순서를 정하는 모든 판정은 `haversine`의 짝 커널(`cdist(metric='haversine')`의 그 원소와 같은 비트)이 하고, 트리는 후보를 고르기만 해요. 반올림 때문에 현의 순서와 `haversine`의 순서가 아주 조금 어긋날 수 있어서, 그 어긋남보다 넉넉한 여유로 고르고 그 여유가 이웃과 동점을 하나도 놓치지 않는다는 것을 증명해요.

1. `XA`와 `XB`의 행마다 cos φ와 3차원 점 P̂ = (cos φ cos λ, cos φ sin λ, sin φ)를 구해요. 이때 모든 점이 정의역 |φ| ≤ fl(π/2), |λ| ≤ 8 안인지도 봐요.
2. 밖의 점이 하나라도 있으면 전수로 가요. 안이면 `XB`의 P̂로 `leafsize` 10의 KD 트리를 만들어요.
3. `XA`의 행마다 트리를 내려가며 3차원 거리의 하한이 `cut(T)`보다 큰 노드를 쳐요. 남은 점은 원래의 (위도, 경도)로 `haversine`을 계산해 (d̂, 색인)으로 판정해요.

`kneighbors`와 `radius_neighbors`는 `metric='haversine'`이고 mB ≥ 128, mA ≥ 16, 8k ≤ mB이면 이 길을 타요(그보다 작으면 트리를 만드는 비용이 찾기에서 아끼는 것보다 커요). 길은 빠르기만 바꾸고 답은 전수와 같아요.

```python
    # src/stardust/spatial/_neighbors.py
    if _use_tree(path, tp, ma, mb, A.shape[1], kc):
        out = _core._KDTree(B, 10).query(A, sd.arange(1, kc + 1, dtype=sd.int64), tp, ub)
    elif _use_sphere(path, km, ma, mb, kc):
        out = _core._sphere_kneighbors(_rows(A), _rows(B), kc, ub)
    if out is None:
        out = _core._kneighbors(A, B, km, pv, wv, aux, kc, ub, 0 if path == 3 else path)
```

네이티브 함수가 정의역 밖의 점을 보면 `None`을 돌려주고, 그러면 마지막 줄의 전수가 답해요.

## haversine 공식

구면 코사인 법칙 cos d = sin φ₁ sin φ₂ + cos φ₁ cos φ₂ cos Δλ로 d를 구하면 작은 d에서 자릿수를 잃어요. cos d ≈ 1 − d²/2라 d = 10⁻⁸이면 cos d가 1로 반올림되기 때문이에요. 1 − cos x = 2 sin²(x/2)로 양변을 바꾸면 haversine 공식이 나와요.

$$
h = \sin^2\frac{\Delta\varphi}{2} + \cos\varphi_1\cos\varphi_2\,\sin^2\frac{\Delta\lambda}{2}, \qquad d = 2\arcsin\sqrt h
$$

h = sin²(d/2)이고, 작은 d에서는 두 항이 모두 작은 수의 제곱이라 상쇄가 없어요. 그래도 수치 문제가 두 곳에 남아요.

### 대척점

d가 π에 가까우면 h가 1에 가까워요. arcsin은 1 둘레에서 기울기가 무한대라 h의 반올림 오차 u가 d에 √u 크기로 들어가고, d = π − δ에서 h = cos²(δ/2) ≈ 1 − δ²/4라 δ < 2√u ≈ 2×10⁻⁸이면 h가 아예 1로 반올림돼요. 커널은 h ≤ 1/2(d ≤ π/2)일 때만 2 arcsin √h를 쓰고, 그보다 크면 g = 1 − h를 **빼지 않고** 직접 구해 d = π − 2 arcsin √g로 가요. S = φ₁ + φ₂로 두면

$$
\cos\varphi_1\cos\varphi_2 = \cos^2\frac{\Delta\varphi}{2} - \sin^2\frac{S}{2}
$$

이고(곱을 합으로 바꾸는 공식), 이것을 1 − h에 넣어 정리하면

$$
g = 1 - h = \cos^2\frac{\Delta\varphi}{2}\cos^2\frac{\Delta\lambda}{2} + \sin^2\frac{S}{2}\sin^2\frac{\Delta\lambda}{2}
$$

예요. 음이 아닌 두 항의 합이라 1 − h의 상쇄가 없고, g ≤ 1/2인 갈래에서 쓰므로 arcsin의 기울기도 √2 이하예요.

```python
>>> import math
>>> S = sd.spatial
>>> x, y = [0.5, 0.0], [-0.5 + 2.0**-30, math.pi]
>>> d = S.haversine(x, y)
>>> math.pi - d, 2.0**-30
(9.313225746154785e-10, 9.313225746154785e-10)
>>> h = math.sin((y[0] - x[0]) / 2)**2 + math.cos(x[0]) * math.cos(y[0]) * math.sin((y[1] - x[1]) / 2)**2
>>> h, math.pi - 2 * math.asin(math.sqrt(h))
(1.0, 0.0)
```

y는 x의 대척점에서 위도로 2⁻³⁰만큼 비킨 점이라 참 거리는 π − 2⁻³⁰이에요(경도 fl(π)와 π의 차이는 2차로만 들어가요). 2 arcsin √h를 그대로 쓰면 h가 1이 되어 이 차이가 통째로 사라져요.

### 날짜 변경선

경도 λ₁ ≈ −π, λ₂ ≈ π인 두 점은 서로 가까워요. 그런데 Δλ = fl(λ₂ − λ₁) ≈ 2π의 반올림 오차는 절대 u|Δλ|/2 둘레이고, sin(Δλ/2) = sin(π − ε) ≈ ε라 이 절대 오차가 작은 sin 값에 그대로 얹혀요. 상대오차가 약 uπ/d로 d에 반비례해 커져요. 커널은 TwoSum으로 반올림 오차 e를 정확히 구해(Δλ + e = λ₂ − λ₁가 정확히 서요) sin((Δλ + e)/2)와 cos((Δλ + e)/2)를 e/2의 1차까지 fma 하나씩으로 고쳐요. 남는 2차 항은 e²/8 아래라 무시할 만해요.

```python
>>> from decimal import Decimal, getcontext
>>> getcontext().prec = 60
>>> PI = Decimal("3.14159265358979323846264338327950288419716939937510582097494")
>>> l1, l2 = -3.1415926535897, 3.14159265358979
>>> float(2 * PI - (Decimal(l2) - Decimal(l1)))
9.661228789729306e-14
>>> S.haversine([0.0, l1], [0.0, l2])
9.661228789729306e-14
>>> 2 * math.asin(abs(math.sin((l2 - l1) / 2)))
9.6168198687443e-14
```

참값은 입력 double 두 개의 차이를 `decimal`로 정확히 구해 2π에서 뺀 것이에요(적도 위라 중심각이 곧 경도 차이예요). TwoSum 없이 fl(λ₂ − λ₁)로 바로 구하면 상대 4.6×10⁻³을 잃어요.

h가 2⁻⁹⁶⁸보다 작으면 사인 두 개를 2⁶⁰⁰배 해(2의 거듭제곱이라 정확해요) 제곱의 언더플로 없이 다시 구하고 2⁻⁶⁰⁰배로 되돌려요.

```cpp
// csrc/spatial/metric.hpp
inline double haversine_pair(double f1, double l1, double c1, double f2, double l2, double c2) {
    const SinCos a = sincos((f2 - f1) * 0.5);
    const double dl = l2 - l1, lv = dl + l1, bv = dl - lv;
    const double he = ((l2 - lv) + (-l1 - bv)) * 0.5;  // e / 2
    const SinCos b = sincos(dl * 0.5);
    const double bs = std::fma(he, b.c, b.s);
    const double cc = c1 * c2;
    const double h = a.s * a.s + cc * (bs * bs);
    if (h <= 0.5) {
        if (h >= kTiny) return 2.0 * std::asin(std::sqrt(h));
        const double x = a.s * 0x1p600, y = bs * 0x1p600;  // the careful path (h = 0 stays 0)
        return 2.0 * std::asin(std::sqrt(x * x + cc * (y * y)) * 0x1p-600);
    }
    const double bc = std::fma(-he, b.s, b.c);
    const double ss = std::sin((f1 + f2) * 0.5);
    const double ac = a.c * bc, sd_ = ss * bs;
    const double g = ac * ac + sd_ * sd_;
    return 0x1.921fb54442d18p+1 - 2.0 * std::asin(std::sqrt(g));
}
```

`lv`, `bv`, `he`의 세 줄이 Knuth의 TwoSum이에요. dl = fl(l2 − l1)일 때 `(l2 - lv) + (-l1 - bv)`는 반올림 없이 정확한 오차 e이고, 0.5배도 정확해요. cos φ는 행마다 한 번 구해 `c1`, `c2`로 받아요. 마지막 상수는 fl(π)예요.

### 보조정리 H(커널의 오차)

**보조정리 H.** 정의역 |φ| ≤ fl(π/2), |λ| ≤ 8에서, libm의 sin·cos·asin이 상대 2u 안이고 √가 올바르게 반올림된다고 하면(가정 L)

- 가까운 갈래(ĥ ≤ 1/2): |d̂ − d| ≤ 16u·d + 2⁻⁹⁹,
- 먼 갈래(ĥ > 1/2): |d̂ − d| ≤ 43u

이고, 둘 다 2⁻⁴⁶(1 + d) = 128u(1 + d) 안이에요.

*증명.* 가까운 갈래부터 봐요.

1. Δφ̂ = fl(φ₂ − φ₁) = Δφ(1 + δ), |δ| ≤ u예요. 정의역에서 |Δφ/2| ≤ π/2이고 그 범위에서 a·cot a ≤ 1이라, 인자의 상대 섭동 δ는 sin(Δφ̂/2)에 상대 u 안으로만 들어가요. libm의 2u를 더해 첫 성분의 상대오차가 3u 안이에요.
2. Δλ는 TwoSum으로 정확하고, 1차 보정의 나머지는 e²/8 + u|e|예요. |λ| ≤ 8이면 |Δλ| ≤ 16이라 |e| ≤ 8u이고 나머지는 2⁻¹⁰¹ 아래예요.
3. √h = ‖(sin(Δφ/2), √(cos φ₁ cos φ₂)·sin(Δλ/2))‖이고 h의 두 항이 모두 음이 아니에요. 성분마다의 상대오차(첫 성분 3u, 둘째 성분 5.5u)가 합과 √의 반올림을 거쳐 그대로 노름의 상대오차가 되어 |fl(√ĥ) − √h| ≤ 9.5u√h + 2⁻¹⁰¹이에요.
4. arcsin의 기울기는 √(1/2) 둘레까지 1.415 이하이고 arcsin x ≥ x예요. 그래서 √h의 상대오차가 arcsin 값의 상대오차를 1.415배 넘게 키우지 않아요. arcsin 자신의 2u와 그 반올림을 더하고 2배(정확)를 하면 |d̂ − d| ≤ 16u·d + 2⁻⁹⁹예요.
5. h < 2⁻⁹⁶⁸은 2⁶⁰⁰배의 정확한 비율로 다시 구하므로 언더플로의 몫이 없어요. h ≥ 2⁻⁹⁶⁸에서 언더플로하는 항은 상대 2⁻¹⁰⁶ 아래예요.

먼 갈래(ĥ > 1/2이라 d ≥ π/2 − O(u))는 절대오차로 봐요. √g = ‖(cos(Δφ/2)cos(Δλ/2), sin(S/2) sin(Δλ/2))‖의 성분마다 Δφ̂와 Ŝ의 반올림(πu 안)이 기울기 1/2로, libm이 2u, 곱이 u만큼 들어가 절대오차가 7.6u 안이에요. 그래서 |fl(√ĝ) − √g| ≤ 12.6u이고, arcsin의 기울기 1.415, fl(π)의 0.55u, 마지막 뺄셈의 πu를 더하면 |d̂ − d| ≤ 43u예요. ∎

이 영역이 `haversine`에 거는 정확도 계약은 20u·d이고, Arb(구간 산술)로 만든 참값과 견준 최대는 그 계약 안이에요([정확도와 성능](/internals/spatial/accuracy-performance/)). 보조정리 H의 한계는 계약과 모양이 달라요. 가까운 갈래에서는 d가 10⁻¹⁴보다 크면 계약보다 조이고, 먼 갈래에서는 d < 2.15일 때 계약보다 넉넉해요. 아래의 여유는 시험으로 지키는 계약이 아니라 가정 L만으로 증명되는 이 한계를 다시 네 배로 잡아 써요.

## 현과 중심각

단위 구 위의 점 P(φ, λ) = (cos φ cos λ, cos φ sin λ, sin φ)로 옮기면 두 점의 현 C = ‖P(x) − P(y)‖는

$$
C^2 = 2 - 2\,P(x)\cdot P(y) = 2 - 2(\cos\varphi_1\cos\varphi_2\cos\Delta\lambda + \sin\varphi_1\sin\varphi_2) = 4h
$$

예요(마지막 등호는 haversine 공식을 유도한 것과 같은 계산이에요). 그래서 C = 2√h = 2 sin(d/2), d = 2 arcsin(C/2)이고, d ∈ [0, π]에서 C는 d의 늘어나는 함수예요. 이 항등식은 모든 실수 φ, λ에서 서요. 경도가 2π 다른 두 표현은 같은 P로 가니 날짜 변경선도 저절로 이어져요. 정확한 산술이면 현으로 고른 k개가 중심각으로 고른 k개와 같다는 뜻이에요.

```python
>>> d = sd.linspace(0.0, math.pi, 200)
>>> fig = sd.plot.Figure(width=89, height=60).line(d, 2 * sd.sin(d / 2), label=r"$C = 2\sin(d/2)$")
>>> fig = fig.line(d, d, style="--", color="C7", label=r"$C = d$")
>>> fig = fig.xlabel(r"$d$").ylabel(r"$C$").legend(loc="upper left")
```

## 반올림 뒤의 어긋남

계산한 값에서는 현의 순서와 `haversine`의 순서가 어긋날 수 있어요. 오차의 출처는 셋이에요.

- **(H) `haversine` 커널.** 보조정리 H의 |d̂ − d| ≤ 2⁻⁴⁶(1 + d)예요.
- **(P) 옮기기.** P̂의 성분마다 libm 값 하나나 둘과 곱 하나라 |P̂ᵢ − Pᵢ| ≤ (1 + 2u)²(1 + u) − 1 ≤ 5.1u이고 ‖P̂ − P‖ ≤ 7.5u예요.
- **(E) 3차원 `euclidean` 커널.** 깊이 3의 합이라 |b̂ − D| ≤ κD + 2⁻¹⁰⁷⁴, κ = γ₆/2 + u예요.

옮기기는 `XA`와 `XB`의 행마다 한 번 해요. 트리의 점은 사인·코사인을 한 번에 구하는 `sincos`로, `haversine`에 넘기는 cos φ는 `cdist`가 쓰는 `std::cos`로 따로 구해요. 앞의 것은 오차 (P)에만 들어가고, 뒤의 것은 거리의 비트를 `cdist`와 같게 해요.

```cpp
    // csrc/spatial/sphere.cpp
    run_tasks(chunks, split, [&](int64_t c) {
        for (int64_t i = c * kRowChunk, e = std::min(s.rows, (c + 1) * kRowChunk); i < e; ++i) {
            const double f = s.geo[2 * i], l = s.geo[2 * i + 1];
            if (!(std::fabs(f) <= kLatMax && std::fabs(l) <= kLonMax)) ok[static_cast<size_t>(c)] = 0;
            s.cosv[static_cast<size_t>(i)] = std::cos(f);
            const SinCos a = sincos(f), b = sincos(l);
            double* p = s.pts.data() + 3 * i;
            p[0] = a.c * b.c;
            p[1] = a.c * b.s;
            p[2] = a.s;
        }
    });
```

## 여유의 정리

점이 이겨야 하는 거리를 T라 할 때(kNN에서 힙이 덜 찼으면 상한, 찼으면 맨 위의 거리, 반경 질의에서는 r) 3차원의 문턱은

$$
t = \mathrm{fl}\bigl(\mathrm{fl}(T\cdot c) + 2^{-42}\bigr),\qquad
\mathrm{cut}(T) = \mathrm{fl}\Bigl(\mathrm{fl}\bigl(2\,\widehat{\sin}(t/2)\cdot c\bigr) + 2^{-46}\Bigr),\qquad c = 1 + 2^{-41}
$$

이고, t ≥ 3.14이거나 T = ∞면 cut(T) = ∞예요.

```cpp
// csrc/spatial/sphere.cpp
// The threshold a 3-D bound must exceed so that every point behind it has d^ > T (the top of this file).
inline double sphere_cut(double T) {
    constexpr double c = 1.0 + 0x1p-41;
    const double t = T * c + 0x1p-42;
    if (!(t < 3.14)) return kInf;
    return (2.0 * std::sin(t * 0.5)) * c + 0x1p-46;
}
```

상수는 증명한 오차를 모두 네 배 넘게 잡아요. 커널은 2⁻⁴⁶ 대신 2⁻⁴⁴, 옮기기는 7.5u 대신 2⁻⁴⁸이에요. 그래서 libm의 sin·cos·asin이 가정 L보다 네 배 나빠도 증명이 서요.

**정리 4(단위 구의 여유).** d̂(x, y) ≤ T이면, P̂(y)를 담는 모든 상자(점 하나도 폭 0의 상자로 봐요)에서 P̂(x)까지의 한계 b̂는 cut(T) 이하예요. 거꾸로 말해 b̂ > cut(T)인 노드와 점의 모든 y는 d̂ > T예요.

*증명.*

1. 보조정리 H를 네 배로 잡은 |d̂ − d| ≤ 2⁻⁴⁴(1 + d)와 d̂ ≤ T에서 d ≤ T′ = (T + 2⁻⁴⁴)/(1 − 2⁻⁴⁴) ≤ T(1 + 2⁻⁴³) + 2⁻⁴³이에요.
2. fl(T·c) ≥ Tc(1 − u) − 2⁻¹⁰⁷⁵이고, 2⁻⁴¹ − 2u ≥ 2⁻⁴³, 2⁻⁴²(1 − u) ≥ 2⁻⁴³이라 T′ ≤ t예요. 곧 d ≤ t예요.
3. t < 3.14 < π면 d/2 ≤ t/2 < π/2이고 sin은 [0, π/2]에서 늘어나니 C = 2 sin(d/2) ≤ 2 sin(t/2)예요.
4. 옮기기 오차를 점마다 2⁻⁴⁸로 잡으면 ‖P̂(x) − P̂(y)‖ ≤ C + 2⁻⁴⁷이에요.
5. 상자에서 P̂(x)에 가장 가까운 점은 P̂(y)보다 멀지 않아요([상자 보조정리](/internals/spatial/kdtree/)). 3차원 커널의 계약으로 b̂ ≤ (1 + κ)(2 sin(t/2) + 2⁻⁴⁷) + 2⁻¹⁰⁷⁴이에요.
6. 계산한 sin이 상대 2⁻⁴⁴ 안이면 fl(2ŝ·c)(1 − u) ≥ 2 sin(t/2)(1 − 2⁻⁴⁴)(1 + 2⁻⁴¹)(1 − u)² ≥ 2 sin(t/2)(1 + 2⁻⁴²)이고, κ ≈ 4u는 2⁻⁴²보다 훨씬 작아 (1 + κ)배를 덮어요. 마지막 덧셈의 2⁻⁴⁶(1 − u)는 (1 + κ)2⁻⁴⁷ + 2⁻¹⁰⁷⁴을 덮어요. 그래서 b̂ ≤ cut(T)예요. ∎

친 노드의 점은 모두 d̂ > T로 **엄격히** 멀어서, 같은 d̂에 색인이 작은 동점도 빠지지 않아요. 여유는 작은 T에서 단위 구 위 2.4×10⁻¹³ 남짓이에요. 지구 반지름 6371 km를 곱하면 2 µm가 안 되니, 여유 때문에 `haversine`을 더 계산하는 점은 거의 없어요.

```python
>>> c = 1 + 2**-41
>>> for T in (1e-6, 1e-3, 1.0):
...     t = T * c + 2**-42
...     print(T, (2 * math.sin(t / 2)) * c + 2**-46 - 2 * math.sin(T / 2))
```

## 찾기

트리는 `XB`의 P̂로 만든 보통의 `KdTree`이고(`kd_build` 그대로), 잎 순서 자리마다 원래의 (위도, 경도, cos 위도)를 따로 쥐어 잎의 점과 `haversine`을 잴 때 이어 읽어요. kNN의 걸음은 [`KdSearch`](/internals/spatial/queries/)와 같고 다른 것은 셋이에요.

- 노드의 한계는 3차원 `euclidean` 커널의 거리이고 문턱은 `KdCut` 대신 `cut(T)`예요. 제곱합 지름길도 그대로 써서 합이 보통 범위이고 above(cut(T))보다 크면 √ 없이 쳐요.
- cut(T)는 sin 하나가 들어 비싸요. T는 힙의 맨 위가 바뀔 때만 바뀌니 그때만 다시 구해 둬요(`retarget`).
- 잎의 점은 3차원 제곱합으로 먼저 거르고, 남은 점만 원래 행으로 `haversine_pair`를 불러 (d̂, j)로 힙에 넣어요. 점 하나를 폭 0의 상자로 보면 이 거르기도 정리 4 그대로예요.

```cpp
    // csrc/spatial/sphere.cpp
    // T: the distance a point must beat; T1, above: its cut and the cut's squared-sum test (cached: the
    // cut takes a sine, and T only moves when the heap's top does).
    void retarget() {
        T_ = static_cast<int64_t>(heap_.size()) < k_ ? ub_ : heap_.front().first;
        T1_ = sphere_cut(T_);
        above_ = KdEuclid::above(T1_);
    }

    void offer(int64_t i) {
        const double* y = t_.data.data() + 3 * i;
        const double s = e_.raw(q_.p, y);
        if (KdEuclid::plain(s) && s > above_) return;  // d^ > T: neither below ub nor before the top
        const double* gy = g_.geo.data() + 3 * i;
        const std::pair<double, int64_t> e{
            haversine_pair(q_.f, q_.l, q_.c, gy[0], gy[1], gy[2]), t_.idx[static_cast<size_t>(i)]
        };
        if (static_cast<int64_t>(heap_.size()) < k_) {
            if (!(e.first < ub_)) return;
            heap_.push_back(e);
            std::push_heap(heap_.begin(), heap_.end());
            if (static_cast<int64_t>(heap_.size()) == k_) retarget();
        } else if (e < heap_.front()) {
            std::pop_heap(heap_.begin(), heap_.end());
            heap_.back() = e;
            std::push_heap(heap_.begin(), heap_.end());
            if (heap_.front().first != T_) retarget();
        }
    }
```

`haversine_pair`는 `cdist`가 부르는 것과 같은 인자 순서(x가 `XA`의 행, y가 `XB`의 행)로 불러서 거리가 `cdist`의 그 원소와 같은 비트예요.

반경 질의(`Within`)는 T = r로 고정이라 cut을 한 번만 구해요. 노드마다 3차원 한계로 치고, 잎의 점은 제곱합으로 거른 뒤 d̂ ≤ r로 넣어요.

```cpp
    // csrc/spatial/sphere.cpp
    void visit(int64_t node) {
        const double s = b_.sum(q_.p, node);
        if (b_.beyond(s, q_.p, T1_, above_)) return;
        const KdNode& nd = t_.nodes[static_cast<size_t>(node)];
        if (nd.right >= 0) {
            visit(node + 1);
            visit(nd.right);
            return;
        }
        for (int64_t i = nd.start; i < nd.end; ++i) {
            const double sy = e_.raw(q_.p, t_.data.data() + 3 * i);
            if (KdEuclid::plain(sy) && sy > above_) continue;  // d^ > r
            const double* gy = g_.geo.data() + 3 * i;
            const double d = haversine_pair(q_.f, q_.l, q_.c, gy[0], gy[1], gy[2]);
            if (!(d <= r_)) continue;
            ++count_;
            if (out_) out_->push_back({t_.idx[static_cast<size_t>(i)], d});
        }
    }
```

`return_length=True`도 잎에서 하나씩 세요. 평면의 반경 질의처럼 먼 한계로 노드를 통째로 세려면 "현이 이만큼 작으면 `haversine`도 r 이하"라는 반대 방향의 여유를 따로 증명해야 해서, 이 길에는 그 지름길이 없어요.

모양이 맞으면 트리 길의 답은 `cdist`를 (거리, 색인)으로 정렬한 것과 같아요. 아래는 구 위에 고르게 뿌린 점에서 mA = 64, mB = 2000, k = 5라 트리 길을 타요.

```python
>>> rng = sd.random.default_rng(4)
>>> def sphere_points(n):
...     return sd.stack([sd.asin(2 * rng.random(n) - 1), math.pi * (2 * rng.random(n) - 1)], axis=1)
>>> XA, XB = sphere_points(64), sphere_points(2000)
>>> res = S.kneighbors(XA, XB, k=5, metric="haversine")
>>> D = S.cdist(XA, XB, metric="haversine")
>>> order = sd.argsort(D, axis=1, stable=True)[:, :5]
>>> bool(sd.all(order == res.indices))
True
>>> bool(sd.all(sd.take_along_axis(D, order, axis=1) == res.distances))
True
```

안정 정렬은 같은 거리에서 열 번호가 작은 쪽을 먼저 두니 (거리, 색인)의 순서예요.

## 정의역을 벗어나면 전수로

여유의 증명은 정의역 |φ| ≤ fl(π/2), |λ| ≤ 8에서만 서요. 위도가 그보다 크면 위도 차의 반이 π/2를 넘어 보조정리 H의 1번 걸음(a·cot a ≤ 1)이 무너지고, 경도가 크면 날짜 변경선 보정의 2차 항(|e|에 비례)과 먼 갈래의 φ₁ + φ₂ 반올림이 입력의 크기와 함께 커져요. 그래서 옮기기를 하면서 모든 행을 검사하고, 하나라도 벗어나면 네이티브 함수가 `None`을 돌려 전수(`cdist`의 구동기로 블록마다 거리를 구해 고르는 길)가 답해요.

이 정의역은 흔히 쓰는 경도 범위 [−π, π], [0, 2π), [−2π, 2π]를 모두 담아요. 도 단위를 라디안으로 잘못 준 자료는 대개 정의역을 벗어나 전수로 가요. 답은 같고 느릴 뿐이에요.

```python
>>> deg = 180 / math.pi
>>> res_deg = S.kneighbors(XA * deg, XB * deg, k=3, metric="haversine")
>>> D_deg = S.cdist(XA * deg, XB * deg, metric="haversine")
>>> bool(sd.all(sd.argsort(D_deg, axis=1, stable=True)[:, :3] == res_deg.indices))
True
```

## 시험과 정확도

트리 길의 테스트는 결과를 전수와 색인·거리·`indptr`의 바이트까지 견줘요. 자료는 여유가 실제로 일을 하는 곳에 둬요. 퍼짐 10⁻¹⁵–10⁻⁶의 거의 같은 점과 중복, 좌표의 마지막 비트만 다른 점, 대척점에서 10⁻¹⁴–10⁻³ 비킨 점과 π 바로 아래의 반경, 극(위도 ±fl(π/2), 경도 −8–8), 날짜 변경선, 거울상이라 거리가 정확히 같은 동점, 계산한 거리와 그 앞뒤 double을 반경으로 준 1 ULP 껍질, 정의역 밖의 점, 그리고 극과 날짜 변경선 둘레에 무작위 군집을 만드는 hypothesis 시험이에요. 1, 3, 10스레드의 결과도 같아야 해요. cut의 여유를 지우고 상대 2⁻⁵⁰만큼 줄이면 이 시험 열 가운데 여섯이 실패해요. 여유가 장식이 아니라는 뜻이에요.

Arb(구간 산술)로 만든 참값에서는 단위 구 위의 점 집합 여섯(균등, 거의 같은 점의 군집, 대척점, 극, 날짜 변경선, 거울상의 동점)에서 돌려준 k = 5 이웃이 계약 20u 안의 참 이웃인지를 재요. 정확도 기준선에서 그 최대는 계약의 0.096이에요([정확도와 성능](/internals/spatial/accuracy-performance/)).
