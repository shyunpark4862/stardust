## 한눈에 보기

가중 함수 루틴은 피적분 함수가 f(x)·w(x) 꼴이고 w가 어려운 경우를 맡아요. w는 빠르게 진동하거나(cos ωx), 끝에서 무한하거나((x − a)^α), 구간 안에서 극을 가져요(1/(x − c)). f·w 전체를 다항식으로 어림하기는 어렵지만, 매끄러운 f만이면 쉬워요. 그래서 이 루틴들은 f를 체비쇼프 급수 $\sum a_k T_k$로 어림하고, 각 항과 w의 곱 $\int T_k(t)\,w\,dt$("수정 모멘트")를 해석적으로 구해 정확히 적분해요. Piessens와 Branders의 수정 Clenshaw–Curtis 방법이에요.

| `weight` | 루틴 | 규칙 | 모멘트를 쓰는 때 |
|---|---|---|---|
| `'cos'`, `'sin'`, 유한 구간 | QAWO (`dqawoe`) | `dqc25f` | \|ω h\| > 2인 구간. 그 밖은 15점 Gauss–Kronrod |
| `'cos'`, `'sin'`, 반무한 구간 | QAWF (`dqawfe`) | 주기마다 QAWO | (QAWO와 같음) |
| `'alg'`, `'alg-loga'`, `'alg-logb'`, `'alg-log'` | QAWS (`dqawse`) | `dqc25s` | 끝 a 또는 b에 닿은 구간. 그 밖은 15점 Gauss–Kronrod |
| `'cauchy'` | QAWC (`dqawce`) | `dqc25c` | c가 구간 안이나 가까이 있는 구간. 그 밖은 15점 Gauss–Kronrod |

h는 구간의 반 길이예요. 모멘트를 쓰지 않는 구간에서는 `dqk15w`가 f(x)·w(x)의 값을 그대로 15점 규칙에 넣어요. 그 구간에서는 w가 매끄러워서 보통의 규칙으로 충분하기 때문이에요.

## 25점 Clenshaw–Curtis 규칙

### 끝점을 부르는 규칙

모멘트를 쓰는 세 규칙은 모두 25점 $t_k = \cos(k\pi/24)$, k = 0, …, 24에서 f를 불러요. 이 점들은 차수 24의 체비쇼프 보간점이고 양 끝 t = ±1을 포함해요. Gauss–Kronrod 규칙과 달리 구간의 끝에서 f를 부르므로, 가중 함수를 줄 때의 f는 끝에서도 값을 내야 해요.

```python
>>> import math
>>> pts = []
>>> def lg(x):
...     pts.append(x)
...     return math.log(x) if x > 0 else 0.0
>>> sd.integrate.quad(lg, 0, 1, weight='sin', wvar=10 * math.pi)
IntegrateResult(integral=-0.128137, error=6.87503e-12, converged=True, nfev=305)
>>> pts[:3]
[1.0, 0.5, 0.0]
```

첫 구간 [0, 1]의 25점 가운데 처음 셋이 오른쪽 끝, 가운데, 왼쪽 끝이에요. log를 그대로 넘기면 x = 0에서 Python의 에러가 나요.

```python
>>> sd.integrate.quad(math.log, 0, 1, weight='sin', wvar=10 * math.pi)
Traceback (most recent call last):
    ...
ValueError: expected a positive input, got 0.0
```

### 체비쇼프 계수: dqcheb

25개 값에서 $f(c + ht) \approx \sum_{k=0}^{24}{}'' a_k T_k(t)$의 계수는 이산 코사인 합 $a_k = \tfrac{2}{24}\sum_j{}'' f(t_j)\cos(jk\pi/24)$이에요(′′는 처음과 마지막 항을 반으로). 한 점씩 건너뛴 13개 값으로는 차수 12의 계수를 얻어요. `qcheb`는 두 급수를 함께 내는데, 행렬·벡터 곱을 하지 않고 값의 대칭(f(tᵢ) ± f(t₂₄₋ᵢ))과 코사인 값의 겹침을 이용해 손으로 펼친 FFT처럼 계산해요(원본 `dqcheb`의 식 그대로).

규칙의 값은 차수 24 급수의 적분, 오차 어림은 차수 24와 12의 차 |I₂₄ − I₁₂|예요. 15점 Gauss–Kronrod 규칙의 오차 어림에는 반올림 하한(50ε·∫|f|)이 있지만, QAWS·QAWC의 이 어림에는 하한이 없어서 f가 급수로 정확히 나타나면 오차 어림이 0이 될 수 있어요. QAWO·QAWF의 어림에는 아래의 [반올림의 바닥](#반올림의-바닥)이 있어요.

```python
>>> r = sd.integrate.quad(lambda x: 1.0, -1, 1, weight='cauchy', wvar=0.3)
>>> r.integral - math.log(0.7 / 1.3), r.error
(0.0, 0.0)
```

값은 맞지만 오차 어림 0은 끝자리의 반올림까지 덮지는 않아요. 그래서 이 루틴들의 정확도 계약은 "수렴한 결과의 참 오차는 오차 어림 + 8ε|I| 안"이에요. 정확도 스윕에서 오차 어림만으로 참 오차를 덮지 못한 것은 QAWC의 9개이고, 모두 5ε|I| 안이에요.

## 진동 가중: dqc25f

### 두 모멘트로 나누기

[a, b]에서 x = c + ht로 바꾸고 p = ωh라 하면

$$
\int_a^b f(x)\cos(\omega x)\,dx = h\cos(\omega c)\int_{-1}^{1} f\cos(pt)\,dt - h\sin(\omega c)\int_{-1}^{1} f\sin(pt)\,dt
$$

이에요. f를 체비쇼프 급수로 바꾸면 필요한 것은 $\int T_k(t)\cos(pt)\,dt$와 $\int T_k(t)\sin(pt)\,dt$예요. cos(pt)는 짝함수이므로 앞의 것은 짝수 k에서만, sin(pt)는 홀함수이므로 뒤의 것은 홀수 k에서만 0이 아니에요. 그래서 한 구간에 모멘트 25개(cos 13개, sin 12개)가 필요하고, 표 `chebmo`의 한 행에 홀수 칸은 cos, 짝수 칸은 sin의 모멘트로 번갈아 둬요.

```cpp
    // csrc/integrate/quadpack.hpp
    estc = std::abs(resc24 - resc12);
    ests = std::abs(ress24 - ress12);
    resabs = resabs * std::abs(hlgth);
    if (integr == 2) {
        result = std::fma(conc, ress24, cons * resc24);
        abserr = std::abs(conc * ests) + std::abs(cons * estc);
    } else {
        result = std::fma(conc, resc24, -(cons * ress24));
        abserr = std::abs(conc * estc) + std::abs(cons * ests);
    }
```

`conc`·`cons`는 h cos(ωc)·h sin(ωc)이고, `resc24`·`ress24`는 cos·sin 모멘트와 계수의 합이에요. sin 가중치는 sin(ωc + pt) = sin(ωc)cos(pt) + cos(ωc)sin(pt)라서 두 합이 자리를 바꿔요. 오차 어림은 두 부분의 차수 24·12 차를 더해요. ω는 늘 |ω|로 계산하고, sin이고 ω < 0이면 QAWO가 끝에서 부호를 바꿔요.

|p| ≤ 2면 구간에 진동이 한 번도 다 들어 있지 않아 15점 Gauss–Kronrod 규칙(`dqk15w`, 함숫값 15개)을 쓰고, 그보다 크면 25점 규칙(함숫값 25개)이에요.

### 반올림의 바닥

두 급수의 차는 체비쇼프 계수와 모멘트의 반올림을 보지 못해요. 그 반올림은 값에 대략 ε·∫|f| 크기로 남는데, ω가 커서 |∫f cos ωx| ≪ ∫|f|이면 이것이 값보다 훨씬 커요. 차만 쓰면 $e^{-x}\cos\omega x$의 [0, ∞)에서 참 오차가 오차 어림 + 8ε|I|의 13배(ω = 1.37·2²⁰), 4×10⁸배(ω = 1.37·2⁴⁸)까지 돼요. 그래서 어림을 ε·resabs 아래로 내리지 않아요. resabs는 차수 24 계수의 절댓값 합에 h를 곱한 것으로 ∫|f|의 어림이고, 15점 규칙의 하한 50ε·resabs와 같은 꼴에 계수만 ε예요.

```cpp
    // csrc/integrate/quadpack.hpp
    if (resabs > kUflow / kEpmach) abserr = std::max(abserr, kEpmach * resabs);
```

이 바닥은 QUADPACK 원본과 scipy에는 없어요. 그래서 QAWO·QAWF의 오차 어림은 scipy보다 작지 않고, 바닥이 멈춤 판정이나 나눌 구간을 바꾸는 드문 입력에서는 부르는 점과 status도 달라요. 정확도 스윕에서 QAWO의 계약 대비는 최대 0.075, QAWF는 0.0042이고, 모두 오차 어림만으로 참 오차를 덮어요.

### 모멘트의 점화식

첫 모멘트는 닫힌 꼴이에요. $\int_{-1}^{1}\cos(pt)\,dt = 2\sin p/p$이고, 다음 둘도 sin p, cos p의 식이에요. 그다음은 부분적분에서 나오는 세 항 점화식이에요. 짝수 차 cos 모멘트를 $v_j$라 하면 $v_j$는 $v_{j-1}$, $v_{j-2}$와 sin p, cos p의 항으로 이어져요. 문제는 안정성이에요. 앞으로 푸는 점화식은 차수 n이 |p|보다 작을 때만 안정하고, n이 |p|를 넘으면 반올림 오차가 지수적으로 자라요. 원본은 두 길로 나눠요.

- **|p| > 24**: 25개 모멘트의 차수가 모두 |p| 아래라 앞으로 풀어요.
- **|p| ≤ 24**: 점화식을 경계값 문제로 바꿔요. 처음 값 하나(닫힌 꼴)와 훨씬 높은 차수의 끝 값 하나(점근 전개 `asap`)를 주고, 그 사이의 모멘트 25개를 삼중대각 연립방정식으로 한꺼번에 풀어 앞쪽의 것만 써요. 이 풀이가 LINPACK의 `dgtsl`이에요.

```cpp
// csrc/integrate/quadpack.hpp
inline void dgtsl(int n, double* c, double* d, double* e, double* b) {
    for (int k = 1; k <= n - 2; ++k) {
        if (std::abs(d[k]) < std::abs(c[k + 1])) {
            const double t = -d[k] / c[k + 1];
            const double dk1 = d[k + 1];
            d[k] = c[k + 1];
            d[k + 1] = std::fma(t, dk1, e[k]);
            c[k + 1] = e[k + 1];
            e[k] = dk1;
            e[k + 1] = t * e[k + 1];
            const double bk = b[k];
            b[k] = b[k + 1];
            b[k + 1] = std::fma(t, b[k + 1], bk);
        } else {
            const double t = -c[k + 1] / d[k];
            d[k + 1] = std::fma(t, e[k], d[k + 1]);
            b[k + 1] = std::fma(t, b[k], b[k + 1]);
            c[k + 1] = 0.0;
        }
    }
    b[n] = b[n] / d[n];
    b[n - 1] = std::fma(-e[n - 1], b[n], b[n - 1]) / d[n - 1];
    for (int k = n - 2; k >= 1; --k) b[k] = std::fma(-c[k + 1], b[k + 2], std::fma(-e[k], b[k + 1], b[k])) / d[k];
}
```

부분 피벗의 가우스 소거예요. 아래 대각 성분이 더 크면 두 줄을 바꾸고, 바꾼 줄은 위로 두 칸 떨어진 성분(`c[k + 1]`에 둠)을 가져요. 이 꼴은 scipy의 C 판과 같아요. LINPACK의 원본은 크기가 같을 때도 줄을 바꾸고 소거를 마지막 줄까지 하는데, scipy의 판은 크기가 같으면 바꾸지 않고 소거를 n − 2번째 줄에서 멈춰 마지막 줄의 아래 대각 성분을 0으로 보고 풀어요. 두 꼴 모두 모멘트를 같은 정확도로 내요. Arb로 계산한 모멘트와 견주면 두 꼴의 오차가 모두 2×10³ ULP 안이고, 그 차이는 모멘트 방법 자체의 오차예요. scipy와 같은 비트를 내는 쪽이라 scipy의 꼴을 써요.

### 모멘트를 수준마다 기억하기

QAWO는 구간을 반으로 나누므로, 나눈 수준 L의 구간은 모두 길이가 (b − a)/2^L이고 p = ωh도 같아요. 모멘트는 p에만 달려 있으므로 수준마다 한 번 계산하면 돼요. 구간마다 수준 `nnlog`를 들고, `w.momcom`은 지금까지 계산한 수준의 수예요.

```cpp
    // csrc/integrate/quadpack.hpp
    if (nrmom < w.momcom) m = nrmom + 1;
    if (w.momcom < (maxp1 - 1) && nrmom >= w.momcom) w.momcom = w.momcom + 1;
    const double* mo = w.chebmo.data() + static_cast<std::size_t>(m - 1) * 25;
```

이미 계산한 수준이면 그 행 `nrmom + 1`을 쓰고, 처음 보는 수준이면 바로 앞에서 그 행을 계산해 채워요. 한 구간을 나눈 두 반쪽은 같은 수준이라, 둘째 반쪽(`ksave = 1`)은 첫째 반쪽이 계산한 행을 그대로 써요.

`max_p1`은 기억하는 수준 수의 상한이에요. `max_p1` − 1개 수준을 채운 뒤에는 그보다 깊은 수준이 올 때마다 마지막 행을 다시 계산해 덮어쓰고, 둘째 반쪽은 그 행 번호 m을 앞의 호출에서 이어받아요. 원본은 m을 호출 사이에 남는 지역 변수에 기대고, stardust는 그것을 `Work`의 `mom_row`에 둬요. scipy의 C 판은 m을 호출마다 1행에서 시작해서, 이 경우 둘째 반쪽이 수준 0의 모멘트를 써요. 그러면 틀린 값을 수렴으로 알려요. log x · cos 300x의 [0, 1]에 `max_p1=2`를 주면 scipy는 0.0094를 내는데 참값은 −0.00524예요.

```python
>>> lgc = lambda x: math.log(x) if x > 0 else 0.0
>>> sd.integrate.quad(lgc, 0, 1, weight='cos', wvar=300.0, max_p1=2)
IntegrateResult(integral=-0.00523627, error=1.06219e-11, converged=True, nfev=505)
>>> sd.integrate.quad(lgc, 0, 1, weight='cos', wvar=300.0)
IntegrateResult(integral=-0.00523627, error=1.06219e-11, converged=True, nfev=505)
```

기본 `max_p1` = 50이면 이 일은 수준 49보다 깊은 구간, 곧 |ω|(b − a) > 2⁵¹에서만 생겨요.

## QAWO의 고리: dqawoe

`dqawoe`의 고리는 [QAGS](/internals/integrate/adaptive-extrapolation/)와 같은 꼴이에요. 구간을 반으로 나누고, 순위 목록을 고치고, ε-알고리즘으로 외삽해요. 다른 곳은 외삽을 시작하는 때예요. 구간이 아직 진동을 여러 번 품을 만큼 크면 나누어서 생기는 어림들이 등비 꼴의 수열이 되지 않아요. 그래서 나눌 구간의 반쪽이 15점 규칙의 범위(|ω|·폭/4 ≤ 2)에 들 만큼 작아진 뒤에야(`extall`) 외삽의 단계를 시작해요. `small`의 시작도 0.75|b − a|예요.

구간이 너무 작아 나눌 수 없다는 판정은 다른 루틴과 한 군데가 달라요.

```cpp
        // csrc/integrate/quadpack.hpp
        // the interval is too small: scipy's C port of dqawoe has epmach where the original has uflow
        // (1000 epmach = 2.2e-13; the other routines have 1000 uflow), and its stopping is kept
        if (std::max(std::abs(a1), std::abs(b2)) <= (1.0 + 100.0 * kEpmach) * (std::abs(a2) + 1000.0 * kEpmach))
            ier = 4;
```

원본의 1000·u_min(가장 작은 정규수의 1000배) 자리에 scipy의 C 판 `dqawoe`만 1000ε가 있어요. 멈춤 판정은 scipy를 따르므로 그대로 둬요. 0 둘레에서 계단을 향해 나눌 때 원본보다 일찍(폭 2×10⁻¹³ 남짓) status 3으로 멈추지만, 수렴하지 않았다고 알리므로 값이 틀리지는 않아요.

첫 규칙 한 번에 끝나면 원본은 구간 수 `last`를 0으로 두는데, `quad`의 결과는 그 구간 하나를 구간 필드로 줘요.

## 반무한 진동: QAWF

$\int_a^\infty f(x)\cos(\omega x)\,dx$에서 QAGI처럼 변수를 바꾸면 진동이 t = 0 둘레로 몰려 끝없이 빨라져요. `dqawfe`는 대신 [a, ∞)를 같은 길이의 주기로 잘라요.

```cpp
    // csrc/integrate/quadpack.hpp
    {
        const auto l = static_cast<std::int64_t>(std::abs(omega));  // the original's integer l = dabs(omega)
        dl = static_cast<double>(2 * l + 1);
    }
    cycle = dl * pi / std::abs(omega);
```

주기의 길이는 $(2\lfloor|\omega|\rfloor + 1)\pi/|\omega|$로 반주기의 홀수 배예요. 그래서 f가 천천히 변하면 이웃한 주기의 적분이 부호를 바꿔 가며 줄고, 부분합이 교대급수가 돼요. 주기마다 QAWO로 적분하고, 부분합의 수열을 ε-알고리즘으로 외삽해요. 교대급수의 부분합은 ε-알고리즘이 특히 잘 가속하는 수열이에요.

```python
>>> r = sd.integrate.quad(lambda x: x**-0.5 if x > 0 else 0.0, 0, math.inf, weight='cos', wvar=math.pi / 2)
>>> r
IntegrateResult(integral=1, error=2.95451e-09, converged=True, nfev=615)
>>> r.n_cycles, r.integral - 1
(13, 1.1046719095020308e-11)
>>> print(r.cycle_integrals[:4])
[     1.013283128125233   -0.01810857954748602   0.007466754034900932
 -0.0043603125267865014]
```

QUADPACK이 QAWF의 예로 드는 $\int_0^\infty x^{-1/2}\cos(\pi x/2)\,dx = 1$이에요. ω = π/2면 주기가 (2·1 + 1)π/(π/2) = 6이고, 주기 13개의 값이 부호를 바꿔 가며 $x^{-1/2}$처럼 천천히 줄어요. 첫 주기에는 x = 0의 특이점도 있지만, 그 주기의 QAWO가 외삽으로 다뤄요.

허용오차는 주기마다 나눠 줘요. k번째 주기는 $\text{atol}\cdot(1 - p)\,p^{k-1}$(p = 0.9)이라 모두 더해도 atol을 넘지 않아요. 상대 허용오차는 주기마다 0이에요. 원본이 `epsabs`만 받으므로 `quad`도 이 길에서 `rtol`을 받지 않아요. 주기의 길이가 모두 같으므로 수준마다의 모멘트는 주기 사이에도 그대로 다시 써요(`icall > 1`이면 `momcom`을 지우지 않아요).

멈춤은 넷이에요. 오차 합과 마지막 주기 값의 50배가 atol 안이면(주기 여섯 개 이상) 부분합으로 끝나고, 외삽 값의 오차가 atol 안이면 외삽 값으로 끝나요. 주기의 QAWO가 실패하면 status 7, 주기 수가 `limlst`에 닿으면 1, 외삽이 열다섯 번 잇달아 나아지지 않으면 4예요. 결과의 `cycle_status`가 주기마다의 QAWO status예요.

원본의 뜻을 지키는 곳이 셋 있어요.

- **ω = 0.** cos의 가중이 1이므로 [a, ∞)의 QAGI예요. 원본(과 scipy)은 이때 `dqagie(f, 0, 1, …)`를 불러 a와 상관없이 [0, ∞)를 적분해요. stardust는 [a, ∞)를 적분해요. sin이면 가중이 0이라 f를 부르지 않고 0이에요.
- **큰 ω.** $\lfloor|\omega|\rfloor$를 64비트 정수로 계산해요. scipy의 C 판은 32비트라 |ω| ≥ 2³⁰에서 2⌊|ω|⌋ + 1이 넘쳐 주기의 길이가 음수가 돼요.
- **(−∞, b].** scipy처럼 x → −x로 [−b, ∞)의 적분으로 바꾸고, cos는 f(−x), sin은 −f(−x)를 적분해요. 사용자 함수는 −x에서 불려요.

```python
>>> sd.integrate.quad(lambda x: math.exp(-x), 1, math.inf, weight='cos', wvar=0.0)
IntegrateResult(integral=0.367879, error=2.14937e-11, converged=True, nfev=135)
```

## 끝점의 대수·로그 가중: QAWS

QAWS의 가중 함수는 $w(x) = (x - a)^\alpha (b - x)^\beta$와 그 곱에 log(x − a), log(b − x), 또는 둘 다를 곱한 것이에요(α, β > −1). 특이점은 양 끝에만 있어요.

### 모멘트: dqmomo

[−1, 1]의 수정 체비쇼프 모멘트 넷을 한 번만 계산해 두고 모든 구간에서 써요.

$$
r_i^{(\alpha)} = \int_{-1}^{1}(1 + t)^\alpha T_i(t)\,dt,\qquad
g_i^{(\alpha)} = \int_{-1}^{1}(1 + t)^\alpha \log\frac{1 + t}{2}\,T_i(t)\,dt
$$

와 β 쪽의 $(1 - t)^\beta$ 판이에요(코드의 `ri`, `rg`, `rj`, `rh`). 첫 값은 $r_0 = 2^{\alpha+1}/(\alpha + 1)$, $r_1 = r_0\,\alpha/(\alpha + 2)$이고, 그다음은 앞으로 푸는 점화식이에요. 이 점화식은 안정해서 경계값 문제로 바꿀 필요가 없어요. β 쪽은 $T_i(-t) = (-1)^i T_i(t)$라서 같은 점화식에 홀수 차의 부호만 바꿔요.

### 끝에 닿은 구간: dqc25s

끝 a에 닿은 구간 [a, r]에서는 (b − x)^β가 매끄러우므로 그것을 f에 붙여 $g(x) = f(x)(b - x)^\beta$의 체비쇼프 급수를 만들어요. 남은 (x − a)^α는 모멘트가 맡아요. x − a = h(1 + t)이므로

$$
\int_a^r f(x)(x - a)^\alpha (b - x)^\beta\,dx = h^{\alpha+1}\sum_i c_i\, r_i^{(\alpha)}
$$

이고, 로그가 있으면 log(x − a) = log(2h) + log((1 + t)/2)로 갈라 $h^{\alpha+1}\left(\log(2h)\sum c_i r_i + \sum c_i g_i\right)$예요. 끝 b에 닿은 구간은 같은 일을 거울처럼 해요. 양 끝 어느 쪽에도 닿지 않은 구간은 w가 매끄러우므로 15점 Gauss–Kronrod 규칙에 w를 곱한 값을 넣어요.

```cpp
            // csrc/integrate/quadpack.hpp
            if (integr != 1) {
                dc = std::log(br - bl);
                result = res24 * dc;
                abserr = std::abs((res24 - res12) * dc);
                res12 = 0.0;
                res24 = 0.0;
                for (int i = 1; i <= 13; ++i) {
                    res12 = std::fma(cheb12[i], rg[i], res12);
                    res24 = std::fma(cheb24[i], rg[i], res24);  // the original: res12 + cheb24(i) rg(i)
                }
                for (int i = 14; i <= 25; ++i) res24 = std::fma(cheb24[i], rg[i], res24);
            }
```

`dc = log(br − bl)`가 log(2h)예요. netlib의 Fortran 원본에는 이 고리에 오타가 있어요. 24차 합을 `res24 = res12 + cheb24(i)*rg(i)`로 12차 합에서 다시 시작해요. scipy의 C 판과 stardust는 바른 식 `res24 + …`로 더해요. 원본으로 계산한 QAWS의 로그 가중 예제는 참값과 6.6×10⁻⁹ 떨어지고, 바른 식은 2.5×10⁻⁹예요.

`dqawse`는 처음부터 [a, b]를 가운데에서 둘로 나눠 두 반쪽이 저마다 한 끝에 닿게 해요. 특이점은 모멘트가 정확히 다루므로 외삽이 필요 없고, 고리는 오차가 큰 구간을 나누기만 해요. 반올림의 판정을 셀 때 끝에 닿은 구간은 빼요.

```python
>>> r = sd.integrate.quad(math.exp, 0, 1, weight='alg', wvar=(-0.5, -0.5))
>>> r
IntegrateResult(integral=5.50843, error=1.9007e-13, converged=True, nfev=50)
>>> r.n_intervals
2
```

$\int_0^1 e^x/\sqrt{x(1 - x)}\,dx = \pi e^{1/2} I_0(1/2)$는 처음 두 반쪽의 25점 규칙 두 번으로 끝나요.

## Cauchy 주값: QAWC

QAWC는 $\mathrm{PV}\!\int_a^b f(x)/(x - c)\,dx$를 계산해요. c를 구간의 [−1, 1] 좌표로 나타낸 값 $c' = (2c - a - b)/(b - a)$가 |c′| ≥ 1.1이면 c가 구간에서 충분히 멀어 15점 Gauss–Kronrod 규칙에 1/(x − c)를 곱해 넣어요. 아니면 25점 규칙과 모멘트 $\mu_n = \mathrm{PV}\!\int_{-1}^{1} T_n(t)/(t - c')\,dt$예요.

모멘트의 점화식은 $T_{n+1} = 2tT_n - T_{n-1}$에서 바로 나와요. 양변을 t − c′로 나누면 $tT_n/(t - c') = c'T_n/(t - c') + T_n$이므로

$$
\mu_0 = \log\left|\frac{1 - c'}{1 + c'}\right|,\qquad \mu_1 = 2 + c'\mu_0,\qquad
\mu_{n+1} = 2c'\mu_n - \mu_{n-1} + 2\int_{-1}^{1}T_n\,dt
$$

이고, 마지막 항은 짝수 n에서 $-4/(n^2 - 1)$, 홀수 n에서 0이에요.

```cpp
    // csrc/integrate/quadpack.hpp
    for (int k = 3; k <= 13; ++k) {
        amom2 = std::fma(2.0 * cc, amom1, -amom0);
        ak22 = static_cast<double>((k - 2) * (k - 2));
        if ((k / 2) * 2 == k) amom2 = amom2 - 4.0 / (ak22 - 1.0);
        res12 = std::fma(cheb12[k], amom2, res12);
        res24 = std::fma(cheb24[k], amom2, res24);
        amom0 = amom1;
        amom1 = amom2;
    }
```

배열이 1부터라 `k`번째 칸이 $\mu_{k-1}$이고, n = k − 2가 짝수인 것이 k가 짝수인 것과 같아요.

`dqawce`는 c가 나눈 점이 되지 않게 나눠요. c가 왼쪽 반에 있으면 c와 오른쪽 끝의 가운데에서, 오른쪽 반에 있으면 왼쪽 끝과 c의 가운데에서 나눠요.

```cpp
        // csrc/integrate/quadpack.hpp
        if (c <= b1 && c > a1) b1 = 0.5 * (c + b2);
        if (c > b1 && c < b2) b1 = 0.5 * (a1 + c);
```

그래서 c를 품은 구간에서 c′가 ±1에 다가가지 않고, 모멘트의 log가 무한으로 가지 않아요.

```python
>>> r = sd.integrate.quad(lambda x: 1 / (5 * x**3 + 6), -1, 5, weight='cauchy', wvar=0.0)
>>> r
IntegrateResult(integral=-0.089944, error=1.30319e-08, converged=True, nfev=245)
>>> print(r.intervals[0])
[ -0.5 0.625]
```

QUADPACK이 QAWC의 예로 드는 적분이에요. 오차 어림이 가장 큰 구간 [−0.5, 0.625]가 c = 0을 안쪽에 품고 있어요.

## FMA의 자리

가중 함수 루틴에는 21점 규칙보다 곱과 합이 한 식에서 만나는 곳이 훨씬 많아요. scipy의 C 판은 clang의 기본 축약으로 그 모두를 FMA로 합치므로, stardust는 그 자리마다 `std::fma`를 적어요. `dqk15w`의 네 누적, `dqcheb`의 조합, `dqc25f`의 점 centr ± hlgth·x와 모멘트의 식·점화식·합·결과, `dgtsl`의 소거와 뒤 대입, `dqmomo`의 점화식, `dqc25s`·`dqc25c`의 급수의 합과 c의 사상, `dqawfe`의 abserr + 10·correc이에요. 두 쪽이 모두 곱이면 clang은 왼쪽 곱을 합쳐요.

같은 점의 계산도 루틴마다 달라요. `dqc25f`는 원본에서 `f(centr+hlgth*x(i))`가 한 식이라 점이 FMA이고, `dqc25s`·`dqc25c`는 `u = hlgth*x(i)`를 따로 계산하는 두 문장이라 FMA가 아니에요. 코드도 원본의 문장 나눔을 그대로 따라요.

```cpp
        // csrc/integrate/quadpack.hpp
        fval[i] = f(std::fma(hlgth, kXcc[i - 1], centr));
        fval[isym] = f(std::fma(-hlgth, kXcc[i - 1], centr));
```

그래서 가중치 시험 모음과 만든 경우 수백 개에서 부르는 점, 값, 구간(QAWF는 주기)이 지금은 scipy와 비트까지 같아요(약속은 아니에요). QAWS·QAWC는 오차 어림도 같아요. 다른 것은 원본의 뜻을 따르는 위의 셋(모멘트 행, ω = 0, 큰 ω)과 QAWO·QAWF의 [반올림의 바닥](#반올림의-바닥)이에요. 바닥은 오차 어림을 키우고, 만든 경우 400개 가운데 하나(rtol 10⁻¹⁴)에서는 경로를 바꿔 부르는 점과 status도 달라요.

<Callout title="15점 규칙의 상수">
`dqk15w`의 상수는 16자리 리터럴이라, 무한 구간의 `dqk15i`가 쓰는 33자리 리터럴과 double로도 끝자리가 달라요(Kronrod 가중치 8개 가운데 7개). 원본이 두 루틴에 따로 적은 값을 저마다 그대로 둬요.
</Callout>
