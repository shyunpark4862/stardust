## 한눈에 보기

적분의 결과에는 두 종류가 있어요.

- **적응 방법**(`quad` 계열, `quad_vec`, `cubature`, `tanhsinh`, `nsum`)의 결과는 "멈춤 판정을 통과한 값"이에요. 오차 어림은 QUADPACK이든 tanh-sinh이든 경험적이고 엄밀한 상계가 아니에요. 그래서 두 가지를 봐요. 하나는 같은 문제에서 scipy와 같은 걸음을 밟는지(부른 점, `nfev`, status, 값의 비트), 다른 하나는 수렴이라고 알린 결과의 참 오차가 오차 어림 안에 드는지예요.
- **표본 규칙과 고정 규칙**(`trapezoid` 등, `fixed_quad`, `newton_cotes`)은 식이 정해져 있어요. 구적 자체의 이산화 오차는 계약이 아니고, 그 식을 정확히 계산한 값과의 거리가 계약이에요.

## 시험 적분 모음

`tests/integrate/problems.py`의 피적분 함수는 식을 한 번만 적고 세 이름공간에서 돌아요. Python의 float와 `math`(`quad`가 점마다 부를 때), 배열(`tanhsinh`·`nsum`·`cubature`가 배열로 부를 때), Arb의 `acb`(참값)예요. 같은 식이 세 곳에서 다르게 적혀 생기는 실수가 없어요. 문제의 상수와 끝($\pi/4$, 상한 $\pi$, 중단점, 가중 함수의 매개변수)은 코드가 쓰는 double 그대로이고, 참값은 그 double로 낸 문제의 정확한 적분이에요.

| 무리 | 수 | 무엇을 시험하나요 |
|---|---:|---|
| QUADPACK 책의 세 무리 | 62 | $\int_0^1 x^\alpha\log(1/x)$(끝점 특이점, 30), $4^{-\alpha}/((x - \pi/4)^2 + 16^{-\alpha})$(좁은 봉우리, 21), $\cos(2^\alpha\sin x)$의 $[0, \pi]$(진동, 11) |
| QUADPACK 루틴의 예제 | 7 | QAGS, QAGP(중단점), QAGI(무한 구간), QAWO, QAWF, QAWS, QAWC |
| scipy의 시험 | 34 | `test_quadpack.py`의 1차원 경우 14, `test_tanhsinh.py`의 f1–f15와 정규 밀도의 변환 다섯 |
| 어려운 적분 | 13 | $x^{-1/2}$, $x^{-0.9}$, $x^{-1/2}\log x$, $\cos(100x)$, $[0.01, 1]$의 $\sin(1/x)$, $e^{-x^2}$, $1/(x^2 + 10^{-6})$, $\lvert x - 1/3\rvert^\alpha$ |
| 가중 함수의 스윕 | 99 | QAWO 18, QAWF 17, QAWS 40, QAWC 24 |
| 겹친 적분, 벡터 값, 급수 | 7, 2, 9 | 단위 정사각형·평면·정육면체의 가우스, $\zeta(2)$, $\zeta(3)$, $\zeta(1.5)$, 양쪽 무한의 $e^{-k^2}$ 등 |

## 참값

### 세 가지 방법

참값은 모두 `tools/integrate_ref.py`가 만들어요. 값은 `tools/arbref.py`가 정밀도를 두 배씩 올리며 공의 반지름이 값의 $2^{-110}$ 아래가 될 때까지 계산한 Arb의 공이고, double-double로 저장해요. 방법은 셋이에요.

1. **닫힌 꼴**: Arb의 함수(atan, $J_0$, Si·Ci, 감마와 그 도함수, 지타, erf 등)로 적은 정확한 적분. 116개 가운데 103개의 참값이에요.
2. **`acb.integral`**: 구간의 근방에서 해석적이고 유계인 피적분 함수의 엄밀한 수치 적분(가지 자름이 있는 함수는 `analytic` 깃발을 넘겨요). 13개의 참값이에요.
3. **치환**: 끝에서 유계가 아니면 `acb.integral`이 무한한 공을 돌려주므로($x^{-1/2}$, $x^{-0.9}$, $\log x/\sqrt x$), 특이점을 없애는 치환($x = t^{1/(1+\alpha)}$, $x = u^2$, $x = e^{-u}$) 뒤에 적분하고, 무한해진 구간은 잘라 꼬리의 엄밀한 상계를 공의 반지름에 더해요.

문제가 허락하는 방법은 모두 계산하고 공이 겹쳐야 해요. 겹치지 않으면 도구가 멈춰요. 1차원 116개에서 18개는 `acb.integral`이, 5개는 치환이 함께 맞춰 봤어요. 이 맞춰 보기가 실제로 잘못을 잡기도 해요. $x^{-0.9}$의 치환 상수를 double로 적으면 닫힌 꼴과 겹치지 않아요.

### double 상한의 차이

문제는 코드가 쓰는 double 그대로라서, 그 double이 수학적 상수와 다르면 참값도 달라요. 상한 `math.pi / 2`는 $\pi/2$보다 $6.1 \times 10^{-17}$ 작아서 $\int_0^{\pi/2}\log(\cos t)\,dt$(f9)와 $\sqrt{\tan t}$(f10)의 참값은 닫힌 꼴과 각각 $2 \times 10^{-15}$, $1.6 \times 10^{-8}$ 달라요. $\sqrt{\tan t}$는 끝에서 무한히 커져 남는 조각이 커요. 그 조각을 엄밀한 상계와 함께 빼서 참값을 만들어요. $\cos(2^\alpha\sin x)$의 상한 $\pi$도 같은 까닭으로 `acb.integral`의 값이 참값이에요.

### 표본과 고정 규칙의 참값

- **표본 규칙**: 식이 유리 연산뿐이라 같은 double에서 `fractions.Fraction`으로 정확히 계산해요. 누적은 줄의 모든 값이고, 항목마다 표본의 해시를 적어요.
- **Gauss–Legendre**: n ≤ 100의 표는 생성 도구가 Arb로 만들고 테스트가 Arb로 다시 계산해 견줘요. 그 위의 n = 101, 128, 150, 200, 256, 500, 1,000은 Arb의 영점과 가중치를 반올림한 값을 참값 파일로 둬요.
- **Newton–Cotes**: 정확한 유리수를 반올림한 값이에요. 테스트는 다른 알고리즘(모멘트 방정식 $\sum a_i r_i^k = N^{k+1}/(k + 1)$의 유리수 소거)과도 견줘요.

참값 파일의 항목마다 문제 정의(끝, 중단점, 가중 함수, 출처)의 해시가 있어서, 문제를 바꾸면 테스트가 낡은 참값을 알려요.

## 계약

| 함수 | 수렴한 결과의 계약 | 계약에서 뺀 것 |
|---|---|---|
| `quad`(가중 함수 없음), `dblquad`·`tplquad`·`nquad` | 참 오차 ≤ 오차 어림 | scipy도 같은 셋(봉우리 $\alpha = 19, 20$, f10) |
| `quad`(가중 함수) | 참 오차 ≤ 오차 어림 + $8\varepsilon\lvert I\rvert$ | 없음 |
| `tanhsinh` | 참 오차 ≤ 오차 어림 | scipy도 같은 여덟(봉우리 $\alpha = 0, 2, 4$, 진동 $\alpha = 6, 7, 9, 10$, f9) |
| `nsum` | 참 오차 ≤ 오차 어림 | 없음 |
| `quad_vec` | 참 오차 ≤ 오차 어림 + $8\varepsilon\lvert I\rvert$(그 노름으로) | 다섯(봉우리 $\alpha = 15$–18, f10) |
| `cubature` | 참 오차 ≤ 오차 어림 + $8\varepsilon\lvert I\rvert$(원소마다) | 규칙·모음마다 3–8개 |
| 표본 규칙 | $\lvert\text{값} - \text{정확한 식}\rvert \le c\,\varepsilon\,S$ | |
| `fixed_quad` | 마디·가중치 0 ULP, 합은 $(\lceil\log_2 n\rceil + 4)\,\varepsilon\,\lvert\tfrac{b-a}{2}\rvert\sum\lvert w_i f_i\rvert$ 안 | |
| `newton_cotes` | 정확한 값의 한 번 반올림 | |

적응 방법의 계약은 판정의 뜻이지 증명된 상계가 아니에요. 오차 어림이 짧은 경우가 모음 안에도 있고, scipy도 같은 비트로 같은 경우에서 짧아요. 그 경우는 `tests/integrate/`의 목록(`QUAD_SHORT`, `TANHSINH_SHORT`, `QUAD_VEC_SHORT`, `CUBATURE_SHORT`)에 이름으로 적고, 목록이 늘거나 줄면 테스트가 실패해요.

- QUADPACK의 짧은 경우는 첫 21점이 좁은 봉우리를 놓친 것이에요([적응 분할과 ε-알고리즘](/internals/integrate/adaptive-extrapolation/)). 값이 거의 0인데 참값은 $\pi$이고 `ier = 0`이에요. 봉우리의 반폭이 $4^{-19}$만큼 좁으면 봉우리 자리를 `points`로 줘도 둘레를 거듭 나누다 status 5로 멈추고, 변수를 바꿔 봉우리를 넓혀야 풀려요([`quad`의 좁은 봉우리](/api/integrate/quad/#좁은-봉우리)).
- 가중 함수 루틴과 `quad_vec`·`cubature`의 $8\varepsilon\lvert I\rvert$는 반올림의 바닥이에요. QAWS·QAWC의 Clenshaw–Curtis 어림과 `quad_vec`·`cubature`의 $\lvert K - G\rvert$에는 반올림 하한이 없어서, 끝자리까지 맞은 값에서 어림이 참 오차보다 작을 수 있어요. 가중치 스윕에서 그런 것은 QAWC의 9개이고 모두 $5\varepsilon\lvert I\rvert$ 안이에요. QAWO·QAWF의 어림에는 대략 $\varepsilon\int\lvert f\rvert$의 바닥이 있어서, $\lvert I\rvert \ll \int\lvert f\rvert$인 큰 ω에서도 계약을 지켜요([가중 함수 루틴](/internals/integrate/weight-routines/#반올림의-바닥)).
- 표본 규칙의 $S = \sum\lvert d_i\rvert(\lvert y_i\rvert + \lvert y_{i+1}\rvert)$는 항의 크기이고, $c$는 합이면 $\lceil\log_2 n\rceil + 10$, 누적의 k번째 값이면 $k + 10$이에요.

### 정직함

오차 어림이 얼마나 넉넉한지는 $\rho$ = 오차 어림 / 참 오차로 봐요. `tanhsinh`이 수렴한 76개에서 짧은 여덟을 빼면 참 오차가 0인 것이 둘이고, 나머지는 $\rho$가 최소 1.28, 가운데값 34, 최대 5,124예요. `nsum`의 아홉은 1.12(직접 합의 어림 $\varepsilon\lvert S\rvert$)에서 $5.2 \times 10^5$까지예요. 모음 밖에서는 어림이 더 자주 짧아요. $e^{-cx^2}$의 $[0, 2]$를 $c \in [0.5, 3]$의 40,001개로 부르면 모두 수렴하고 1,093개가 참 오차보다 작은 어림을 내요(가장 나쁜 것이 상대 $1.1 \times 10^{-8}$). 이것도 scipy와 같은 비트예요.

## 잰 결과

아래 표는 정확도 스윕의 기준선이에요. 영역 열은 모음(`book`, `quadpack`, `scipy`, `hard`)이나 규칙, 표본 규칙의 이름이에요. `complex`는 `complex_func=True`, `log`는 `log=True`, `boxes`는 `cubature`의 상자, `variants`는 표본의 변형, `an`·`B`는 `newton_cotes`의 가중치와 오차 계수예요. 계약 대비는 계약의 척도로 잰 가장 큰 오차를 한계로 나눈 값이고 1 이하가 계약 안이에요.

<AccuracySummary area="integrate" caption="sd.integrate의 정확도. 최대 상대오차가 inf나 1 근처인 줄은 수렴하지 못한 경우(봉우리, 끝점 특이점)를 함께 잰 것이고, 계약 대비는 수렴한 결과만 봐요. fixed_quad는 규칙 자체의 오차라 계약 없이 기록만 해요." />

같은 점에서 scipy 1.18.1을 재면 대부분의 줄이 sd와 같은 값이에요. 같은 걸음을 밟아 같은 비트를 내기 때문이에요. 다른 줄은 다섯이에요.

- **표본 규칙**: 합의 순서(numpy의 누산기 8개와 sd의 16개)만 달라 끝자리가 달라요. 둘 다 계약 안이에요.
- **QAWO**(유한 구간의 cos·sin 가중): 값은 같고 오차 어림만 달라요. 반올림의 바닥이 없는 scipy는 계약 대비가 0.46이고, sd는 0.075예요.
- **QAWF**(반무한 푸리에 적분): 가중 함수 루틴에서 scipy가 틀린 값을 내는 자리(QAWF의 주파수 0과 큰 주파수, 진동 모멘트의 행)에서 sd는 QUADPACK 원본의 뜻을 따라요([가중 함수 루틴](/internals/integrate/weight-routines/)). 그래서 이 줄은 scipy의 계약 대비가 $10^{10}$을 넘어요.
- **`cubature`의 $(-\infty, b]$**: scipy는 $[-b, \infty)$를 적분해요. sd는 문서의 치환을 따라 참값과 오차 어림 안이에요.
- **`newton_cotes`**: sd는 정확한 유리수를 한 번 반올림해 모든 가중치와 오차 계수가 0 ULP예요. scipy는 N이 크면 Vandermonde 풀이가 크게 틀려 가중치가 최대 상대 $9.2 \times 10^{10}$, 오차 계수가 $8.6 \times 10^{34}$까지 벗어나요.

QAGS·QAGI는 R 4.6.2의 `stats::integrate`(같은 QUADPACK 루틴)와도 같은 점에서 견줘요. `book`, `quadpack`, `hard`에서는 최대 오차와 계약 대비가 sd와 같고, `scipy` 모음에서는 R이 한 점에서 유한하지 않은 값을 내고 나머지 점의 계약 대비가 $4 \times 10^8$이에요.

## scipy와 같은 걸음

적응 방법은 scipy의 계산 순서를 원소 하나 안에서 그대로 따라가요. 그래서 scipy로 기록한 모음과 기록 밖의 경우에서 부른 점(호출 차례대로의 SHA-256), 값, 오차 어림, `nfev`, status, 글, 구간·영역까지 지금은 비트까지 같아요(약속은 아니에요). QAWO·QAWF의 오차 어림은 반올림의 바닥 때문에 scipy 이상이에요. 무엇을 맞추었는지는 함수마다 달라요.

| 함수 | 맞춘 것 |
|---|---|
| `quad` | QUADPACK 규칙의 10진 리터럴, scipy 빌드의 곱셈·덧셈 축약 자리(Kronrod 누적 넷의 FMA) |
| `tanhsinh`, `nsum` | libm으로 만든 점의 표, numpy의 pairwise 합과 NaN 규칙, logsumexp의 단계 |
| `quad_vec`, `cubature` | Python·numpy의 산술(FMA 없음), `heapq`의 차례, 합의 배치 규칙, 페이지 정렬 버퍼의 BLAS 내적 |

QUADPACK은 scipy만이 아니라 Fortran 원본과도 견줘요. 원본 소스를 따로 빌드해 같은 모음을 돌린 기록이 `tests/integrate/data/`에 있어요. 어디서 왜 같은지는 [영역의 구조](/internals/integrate/overview/)와 각 알고리즘의 글에 있어요.

scipy와 다른 동작은 scipy가 틀린 결과를 내거나 틀린 수렴을 알리는 자리(가중 함수 루틴의 세 자리, QAWO·QAWF 오차 어림의 바닥, `cubature`의 $(-\infty, b]$, NaN을 수렴으로 알리는 `cubature`의 판정, 유한하지 않은 `quad` 결과의 status −3), 정해진 메모리 안에서 끝나야 하는 자리(`cubature`의 크기 상한)와, 원소의 결과가 배치와 상관없어야 하는 자리(`nsum`의 log 오차의 합 순서)예요. `fixed_quad`는 올바로 반올림한 마디를 써서 n = 20부터 부르는 점이 scipy와 다르고, `newton_cotes`는 N ≥ 15에서 scipy보다 정확해요.

## 스레드와 비트

모든 결과는 스레드 수와 상관없어요. 원소별 무리는 원소마다의 산술이 어느 스레드에서나 같고 남은 원소의 차례를 지켜요. 표본 규칙은 줄의 합이 같은 나무로 더해져요. Gauss–Legendre는 마디마다 따로 계산해요. 골든 테스트가 모든 공개 함수를 1·3·10스레드로 돌려 같은 결과인지 봐요.

## 성능

시간의 대부분은 사용자의 Python 함수예요. 그래서 성능은 세 가지로 봐요. 같은 문제의 `nfev`(scipy와 같아요), 호출 사이의 일, 원소별 무리의 처리량이에요.

- **`quad` 계열**: scipy처럼 점마다 Python을 불러요. 호출 사이의 일은 QUADPACK의 몇 줄이라 함숫값 몇 개짜리 적분에서도 scipy와 비슷하고, 함숫값이 많아지면 결과의 구간 배열을 만드는 고정 비용이 작아져요. GIL은 쥔 채예요(호출 사이의 일이 너무 짧아 놓는 비용이 더 커요).
- **원소별 무리**(`tanhsinh`, `nsum`): scipy는 반복마다 numpy 연산 수십 개를 해서, 원소가 적은 배치에서는 그 고정 비용이 시간을 차지해요. sd는 반복 사이의 일이 C++의 원소 패스 한두 번이라 작은 배치에서 차이가 커요. 큰 배치에서는 사용자 함수 자체가 시간을 정하고, 원소 패스는 일이 $2^{15}$점을 넘으면 스레드에 나눠요.
- **`cubature`, `quad_vec`**: 힙, 규칙의 합, 구간 기억이 C++라 함숫값이 싼 경우 scipy의 Python 고리보다 여러 배 빨라요. 값이 큰 배열이면 사용자 함수와 값 읽기가 시간을 정해요.
- **표본 규칙**: 배열의 리덕션과 같은 커널이라 임시 배열이 없고, 긴 줄이나 많은 줄은 스레드에 나눠요.
- **처음 한 번 비싼 것**: 표 밖의 Gauss–Legendre(마디 계산이 $n^2$에 비례, 최근 8개의 n을 기억)와 `newton_cotes`의 정확한 유리수(대략 $N^3$, 64개를 기억)예요. 두 번째 호출부터는 표를 읽는 것과 같아요.

scipy보다 느리거나 비슷한 곳도 있어요. 함숫값이 아주 적은 `quad`는 결과의 구간 배열을 만드는 만큼 scipy와 거의 같고, `nsum`의 큰 배치를 1스레드로 돌리면 시간의 대부분인 사용자 함수의 sd `**`가 numpy보다 조금 느린 만큼 뒤져요. 원소가 아주 많은 `tanhsinh`의 첫 호출은 큰 새 배열의 페이지를 채우는 데 시간이 들어요.
