## 역 Cuthill–McKee

희소 행렬을 분해하거나 풀 때는 0이 아닌 원소가 대각 가까이 모여 있을수록 좋아요. 띠 폭은 저장된 원소 $(i, j)$의 $\lvert i - j \rvert$ 가운데 가장 큰 값이에요. Cuthill과 McKee의 방법은 노드를 너비 우선 순서로 다시 번호 매겨 이것을 줄여요.

너비 우선 순서가 띠 폭을 줄이는 까닭은 간단해요. 너비 우선은 시작 노드에서의 거리(층)대로 노드를 늘어놓으니 같은 층의 노드가 이어진 번호를 가져요. 그리고 변은 같은 층이나 이웃한 층의 노드만 이어요(두 층 이상 건너뛰는 변이 있으면 층의 정의에 어긋나요). 그래서 변 $(i, j)$의 두 번호 차이는 이웃한 두 층의 크기의 합보다 작아요. 띠 폭이 가장 넓은 층의 두 배 안으로 묶이는 것이에요. 층 안에서 차수가 작은 이웃을 먼저 넣으면 다음 층으로 이어지는 변이 적은 노드가 앞에 와서 층이 덜 퍼져요. 마지막에 순서를 뒤집는 것은 George의 관찰이에요. 띠 폭은 같지만 촐레스키 분해에서 채워지는 원소(외곽선 안의 자리)가 줄어요.

### 코드

```cpp
        // csrc/graph/ordering.cpp
        // The degrees: the row length of the pattern read, a stored diagonal counted twice.
        std::vector<int64_t> degree(static_cast<size_t>(n), 0);
        int64_t max_degree = 0;
        for (int64_t i = 0; i < n; ++i) {
            int64_t d = 0;
            neighbours(i, [&](int64_t j) { d += 1 + (j == i); });
            degree[static_cast<size_t>(i)] = d;
            max_degree = std::max(max_degree, d);
        }
        // The seed order: the nodes by (degree, index), a counting sort (stable, so ties keep index order).
        std::vector<int64_t> start(static_cast<size_t>(max_degree) + 2, 0), seeds(static_cast<size_t>(n));
        for (int64_t i = 0; i < n; ++i) ++start[static_cast<size_t>(degree[static_cast<size_t>(i)]) + 1];
        for (size_t d = 1; d < start.size(); ++d) start[d] += start[d - 1];
        for (int64_t i = 0; i < n; ++i)
            seeds[static_cast<size_t>(start[static_cast<size_t>(degree[static_cast<size_t>(i)])]++)] = i;
        std::vector<uint8_t> seen(static_cast<size_t>(n), 0);
        auto by_degree = [&](int64_t a, int64_t b) {
            const int64_t da = degree[static_cast<size_t>(a)], db = degree[static_cast<size_t>(b)];
            return da < db || (da == db && a < b);
        };
        int64_t found = 0;
        for (int64_t s : seeds) {
            if (found == n) break;
            if (seen[static_cast<size_t>(s)]) continue;
            seen[static_cast<size_t>(s)] = 1;
            order[found++] = s;
            for (int64_t head = found - 1; head < found; ++head) {
                const int64_t i = order[head], first = found;
                neighbours(i, [&](int64_t j) {
                    if (!seen[static_cast<size_t>(j)]) {
                        seen[static_cast<size_t>(j)] = 1;
                        order[found++] = j;
                    }
                });
                std::sort(order + first, order + found, by_degree);
            }
        }
        std::reverse(order, order + n);
```

- **차수.** 읽는 패턴의 줄 길이에 저장된 대각이면 1을 더해요(자기 고리는 끝이 둘이라 두 번 세요). 그래서 `j == i`면 2를 더해요.
- **시작 노드의 순서.** 모든 노드를 (차수, 번호)로 줄 세워요. 차수는 작은 정수라 계수 정렬 한 번이고, 계수 정렬은 안정이라 같은 차수 안에서는 번호 순서가 남아요. 이 줄을 앞에서부터 보며 아직 방문하지 않은 노드가 나오면 그 요소의 시작 노드로 써요. 그래서 요소마다 차수가 가장 작고 그 가운데 번호가 가장 작은 노드에서 시작하고, 요소는 그 시작 노드의 순서로 이어져요.
- **너비 우선.** 결과 배열(`order`)을 그대로 큐로 써요. 노드 하나를 펼칠 때 처음 만난 이웃들을 큐 끝에 넣고, 그 묶음만 (차수, 번호)로 정렬해요. 묶음은 대개 짧아서 정렬이 싸요.
- 끝에서 `std::reverse`로 뒤집어요.

이 규칙에는 동점이 없어요. 차수가 같은 노드는 번호로 갈리니 결과는 입력으로만 정해지고, 정의를 그대로 옮긴 파이썬 구현과 바이트까지 같아요. 시작 노드는 차수가 가장 작은 노드예요. 더 좋은 시작점(지름의 끝에 가까운 노드)을 찾는 George–Liu의 방법도 있지만, 차수가 가장 작은 노드를 쓰는 널리 쓰이는 꼴을 따랐어요.

### 두 방향의 패턴

`symmetric_mode=False`이면 $A$와 $A^{\mathsf T}$의 패턴의 합집합을 읽어요. 먼저 패턴이 자기 전치와 같은지를 전치를 만들지 않고 한 번 훑어 봐요. 같으면 $A$만 읽고, 다르면 전치 CSR을 한 번 만든 뒤 노드마다 두 줄을 합치며 읽어요. 합친 CSR을 따로 만들지 않아요.

```cpp
// csrc/graph/ordering.cpp
// The neighbours of node i in the union of two canonical rows (ascending, each once), fn(j) for each.
template <class F>
inline void each_union(const int64_t* a, const int64_t* ae, const int64_t* b, const int64_t* be, F&& fn) {
    while (a < ae && b < be) {
        if (*a < *b) fn(*a++);
        else if (*b < *a) fn(*b++);
        else {
            fn(*a++);
            ++b;
        }
    }
    while (a < ae) fn(*a++);
    while (b < be) fn(*b++);
}
```

두 줄이 모두 오름차순이고 한 줄 안에 같은 번호가 없으니, 두 커서로 한 번 걸으며 같은 번호는 한 번만 내보내면 합집합의 오름차순이에요. 차수를 셀 때와 너비 우선으로 펼칠 때 모두 이 함수를 써요. 대칭 확인과 탐색은 직렬이고, $n + \mathrm{nnz}$가 $2^{15}$ 이상이면 GIL을 놓아요.

## 구조적 랭크

구조적 랭크는 패턴만으로 정해지는 랭크예요. 저장된 자리에 어떤 값을 넣어도 행렬의 랭크는 이것을 넘지 못하고, "일반적인" 값(거의 모든 값)을 넣으면 랭크가 정확히 이것이에요. 그 값이 패턴의 이분 그래프(행과 열이 노드, 저장된 원소가 변)에서 가장 큰 매칭의 크기와 같다는 것이 König과 Edmonds로 이어지는 결과예요.

증명은 행렬식의 전개에서 나와요. $k \times k$ 부분행렬의 행렬식은 $\sum_\sigma \mathrm{sgn}(\sigma) \prod_i a_{i\sigma(i)}$이고, 곱 $\prod_i a_{i\sigma(i)}$가 0이 아니려면 $i \mapsto \sigma(i)$가 모두 저장된 자리여야 해요. 곧 그 부분행렬의 행과 열 사이의 완전 매칭이에요. 매칭이 없으면 모든 항이 0이라 행렬식이 0이고, 크기 $k$의 매칭이 있으면 원소를 변수로 본 다항식에서 매칭마다 서로 다른 단항식이 나와 지워지지 않으니 다항식이 0이 아니에요. 0이 아닌 다항식은 거의 모든 값에서 0이 아니므로 그런 값에서 랭크가 $k$ 이상이에요.

그래서 함수는 [매칭과 배정](/internals/graph/matching/)의 Hopcroft–Karp를 불러 짝지은 행을 세요.

```python
>>> sd.graph.structural_rank(sd.asarray([[1, 1, 0], [1, 1, 0], [0, 0, 0]]))
2
>>> sd.graph.structural_rank(sd.asarray([[1, 0, 0], [1, 0, 0], [1, 1, 1]]))
2
```

두 번째 행렬은 셋째 행이 꽉 차 있지만 첫 두 행이 모두 열 0에만 원소가 있어서, 두 행 가운데 하나만 짝을 얻어요.

## 라플라시안

라플라시안은 $L = D - A$예요. $D$는 대각에 차수를 놓은 행렬이고, 차수는 들어오는 무게의 합(열 합)이에요. `use_out_degree=True`면 나가는 무게의 합(행 합), `symmetrized=True`면 $M = A + A^{\mathsf T}$를 먼저 만들고 그 행 합이에요. 어느 경우든 $A$의 대각은 차수에도 원소에도 쓰지 않아요.

```python
>>> W = sd.asarray([[0, 2.0, 0], [1, 0, 3], [0, 0, 0]])
>>> sd.graph.laplacian(W)
array([[ 1.0, -2.0, -0.0],
       [-1.0,  2.0, -3.0],
       [-0.0, -0.0,  3.0]], dtype=float64)
>>> sd.graph.laplacian(W, use_out_degree=True)
array([[ 2.0, -2.0, -0.0],
       [-1.0,  4.0, -3.0],
       [-0.0, -0.0,  0.0]], dtype=float64)
>>> sd.graph.laplacian(W, symmetrized=True)
array([[ 3.0, -3.0, -0.0],
       [-3.0,  6.0, -3.0],
       [-0.0, -3.0,  3.0]], dtype=float64)
```

밀집 입력에서 0은 "변 없음"이 아니라 값 0이라, 부호를 바꾼 대각 밖은 $-0.0$이에요.

### 차수는 고정된 합

차수 하나는 항상 같은 순서의 합이에요. 0에서 시작해 대각을 뺀 항을 색인 오름차순으로 하나씩 더해요.

```cpp
        // csrc/graph/ordering.cpp
        if (out_degree || symmetrized) {
            blocks(n, per, split, [&](int64_t lo, int64_t hi) {
                for (int64_t i = lo; i < hi; ++i) {
                    T acc = T(0);
                    for (int64_t k = m.ip[i]; k < m.ie[i]; ++k)
                        if (m.ix[k] != i) acc = add(acc, m.v[k]);
                    degree[static_cast<size_t>(i)] = acc;
                }
            });
        } else {
            // a column's terms arrive in ascending row order: one sum from zero per column
            std::fill(degree.begin(), degree.end(), T(0));
            for (int64_t i = 0; i < n; ++i)
                for (int64_t k = m.ip[i]; k < m.ie[i]; ++k) {
                    const int64_t j = m.ix[k];
                    if (j != i) degree[static_cast<size_t>(j)] = add(degree[static_cast<size_t>(j)], m.v[k]);
                }
        }
```

행 합(나가는 차수, 대칭화)은 행 하나가 태스크 하나의 일이라 행 구간으로 나눠도 합이 같아요. 열 합(들어오는 차수)은 CSR에서 열의 항이 행마다 흩어져 있어, 행을 오름차순으로 훑으며 열마다 더하는 직렬 흩뿌림이에요. 열 $j$의 항은 행 번호 오름차순으로 도착하니 이것도 "색인 오름차순의 차례 합"이에요. 밀집 입력은 열 32개 묶음마다 누산기를 두고 행을 차례로 읽어 같은 합을 만들어요. 그래서 희소와 밀집, 스레드 수에 상관없이 차수의 비트가 같아요.

int64 입력은 int64로 계산하고 넘치면 2의 보수로 감겨요(`ops::wrap_add`). bool은 int64로 바꿔 계산하니 정확한 개수예요.

template <class T>
inline T neg(T a) {
    if constexpr (std::is_same_v<T, int64_t>) return static_cast<int64_t>(0 - static_cast<std::uint64_t>(a));

### 대칭화: 합치기 한 번

$A + A^{\mathsf T}$는 전치 CSR을 만든 뒤 행마다 두 줄을 합쳐 만들어요. 합이 정확히 0인 자리는 저장하지 않아요(희소 배열의 덧셈과 같은 규칙이고, NaN은 남겨요). 보통은 먼저 행마다 결과 원소의 수를 세고 자리를 정한 다음 다시 합치며 쓰지만, 여기서는 한 번만 합쳐요.

```cpp
    // csrc/graph/ordering.cpp
    for (int64_t i = 0; i <= n; ++i) s.ip[static_cast<size_t>(i)] = a.ip[i] + t.ip[i];
    s.ie.resize(static_cast<size_t>(n));
    const size_t room = static_cast<size_t>(s.ip[static_cast<size_t>(n)]);
    s.ix.reset(new int64_t[room]);
    s.v.reset(new T[room]);
    const int64_t per = std::max<int64_t>(1, kBlockWork * n / std::max<int64_t>(1, 2 * a.ip[n] + n));
    blocks(n, per, split, [&](int64_t lo, int64_t hi) {
        for (int64_t i = lo; i < hi; ++i) {
            size_t k = static_cast<size_t>(s.ip[static_cast<size_t>(i)]);
            merge(i, [&](int64_t j, T x) {
                s.ix[k] = j;
                s.v[k++] = x;
            });
            s.ie[static_cast<size_t>(i)] = static_cast<int64_t>(k);
        }
    });
```

행 $i$의 결과는 많아야 $A$의 행 $i$와 $A^{\mathsf T}$의 행 $i$의 원소 수의 합만큼이에요. 그래서 행 $i$를 "앞 행들이 가질 수 있는 가장 많은 원소 수"의 자리, 곧 `a.ip[i] + t.ip[i]`에서 시작하게 하면 어떤 행도 다음 행의 자리를 침범하지 않아요. 행의 끝은 `ie`에 따로 적어요. 세는 훑기가 없어지는 대신 $\mathrm{nnz}(A) + \mathrm{nnz}(A^{\mathsf T})$칸을 잡아요. 그 뒤의 차수와 원소 쓰기는 이 `(ip, ie)` 꼴을 그대로 읽어요.

```python
>>> Z = sd.sparse.csr_array((sd.asarray([0.0, 1.0, -1.0]), (sd.asarray([0, 1, 2]), sd.asarray([1, 2, 1]))), shape=(3, 3))
>>> L = sd.graph.laplacian(Z)
>>> L.indices, L.data
(array([0, 1, 1, 2, 1, 2], dtype=int64), array([ 0.0, -0.0, -1.0, -1.0,  1.0,  1.0], dtype=float64))
>>> L = sd.graph.laplacian(Z, symmetrized=True)
>>> L.indptr, L.indices, L.data
(array([0, 1, 2, 3], dtype=int64), array([0, 1, 2], dtype=int64), array([0.0, 0.0, 0.0], dtype=float64))
```

첫째는 저장된 0이 $-0.0$으로 남은 것이에요. 둘째는 $M$에서 합이 정확히 0인 자리가 모두 빠져서 대각만 남은 것이에요. $(1, 2)$와 $(2, 1)$은 $1 + (-1)$이고, $(0, 1)$과 $(1, 0)$은 저장된 0 하나뿐인 합이에요.

### 결과의 꼴

희소 결과는 표준 꼴 CSR이에요. 행마다 대각 밖 원소의 수에 1(대각)을 더해 자리를 정하고, 원소를 오름차순으로 쓰다가 처음으로 $j \gt i$인 원소를 만나기 직전에 대각을 끼워요. 밀집 입력은 밀집 결과예요. 한 스레드에서는 원소를 한 번 읽으며 차수에 더하고 부호를 바꿔 쓰는 한 번의 훑기이고, 스레드 풀이 있으면 차수와 원소를 따로 훑어요. 두 꼴이 같은 합을 같은 순서로 하니 비트가 같아요.

`form='lo'`는 만든 행렬을 `sd.sparse.aslinearoperator`로 감싸요. 곱은 감싼 행렬의 곱이라 `laplacian(G) @ x`와 비트가 같아요. `dtype`은 계산한 뒤에 바꿔요.

### 정규화와 그 오차

`normed=True`면 $w_i = \sqrt{d_i}$($d_i = 0$이면 1)를 한 번 구하고 대각 밖을 $-((M_{ij}/w_i)/w_j)$로, 대각을 $d_i \ne 0$이면 1, 아니면 0으로 써요.

```python
>>> r = sd.graph.laplacian(W, normed=True, symmetrized=True, return_diag=True)
>>> r.laplacian
array([[                1.0, -0.7071067811865477,                -0.0],
       [-0.7071067811865477,                 1.0, -0.7071067811865477],
       [               -0.0, -0.7071067811865477,                 1.0]], dtype=float64)
>>> r.diag
array([1.7320508075688772,  2.449489742783178, 1.7320508075688772], dtype=float64)
```

반올림의 한계는 이렇게 세요. $\gamma_k = ku/(1 - ku)$, $u = 2^{-53}$이에요.

- **차수.** 항 $m$개를 0부터 차례로 더하면 각 항이 많아야 $m$번 반올림을 거쳐 $\lvert \hat d - d \rvert \le \gamma_m s$예요. $s$는 그 항들을 이루는 $\lvert A \rvert$의 합이에요. 대칭화면 항 하나($A_{ij} + A_{ji}$)가 이미 한 번 반올림되어 $\gamma_{m+1}$이에요.
- **비정규화의 대각 밖**은 부호 바꾸기라 정확해요. 대칭화면 덧셈 하나라 $\gamma_1(\lvert A_{ij} \rvert + \lvert A_{ji} \rvert)$예요.
- **정규화의 대각 밖.** $\rho_i = \gamma_k s_i / \lvert d_i \rvert$로 두면 $\hat d_i = d_i(1 + \theta_i)$, $\lvert \theta_i \rvert \le \rho_i$예요. $\hat w_i = \mathrm{fl}(\sqrt{\hat d_i})$와 $\hat w_j$의 반올림 둘, 나눗셈 둘, 모두 네 번(대칭화면 $M_{ij}$를 만든 덧셈 하나를 더해 다섯 번)의 반올림이 곱으로 들어와서
$$
\hat L_{ij} = L_{ij}\,\frac{\prod_{k=1}^{c}(1 + \delta_k)^{\pm 1}}{\sqrt{(1 + \theta_i)(1 + \theta_j)}}, \qquad \lvert \delta_k \rvert \le u,\ c = 4\ (\text{대칭화면 } 5)
$$
예요. 분자는 $1 + \gamma_c$ 안이고 분모는 $\sqrt{(1 - \rho_i)(1 - \rho_j)}$ 이상이니
$$
\lvert \hat L_{ij} - L_{ij} \rvert \le \lvert L_{ij} \rvert\left(\frac{1 + \gamma_c}{\sqrt{(1 - \rho_i)(1 - \rho_j)}} - 1\right)
$$
이에요. 차수가 상쇄 없이 더해진 값이면($A \ge 0$) $\rho \le \gamma_k$라 상대오차가 몇 $u$예요. 음수 무게가 섞여 차수가 상쇄되면 $\rho$가 커져 한계도 커져요.
- **정규화의 대각**은 1이나 0이라 정확해요.

이 한계를 Arb(구간 산술)로 만든 참값과 견준 결과는 [정확도와 성능](/internals/graph/accuracy-performance/)에 있어요. 모든 원소가 한계 안이에요.
