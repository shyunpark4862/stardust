## 한눈에 보기

`sd.linalg`의 함수 대부분은 LAPACK을 감싸지만, 몇 개는 LAPACK이 필요 없어요. 원소를 곱하고, 더하고, 옮기고, 살펴보는 것이 전부인 함수들이에요. 이 함수들은 `csrc/linalg/ops/basic.cpp`(기본 연산)와 `ops/norms.cpp`, `ops/vnorm.hpp`(노름)에 직접 짠 루프로 있어요.

| 함수 | 계산하는 것 | 구현 | numpy·scipy와의 관계 |
|---|---|---|---|
| `vecdot` | $\sum_i \overline{x_i}\, y_i$ | 곱을 잎에 융합한 pairwise 합(FMA) | `np.sum(np.conj(x) * y, axis)`와 끝 비트가 다를 수 있음 |
| `outer` | $x_i y_j$ | 원소 곱 | `x[..., :, None] * y[..., None, :]`와 같음 |
| `kron` | $a_{ij} B$ 블록 | 원소 곱 | `np.kron`(1·2차원)과 같음 |
| `kronsum` | $I \otimes A + B \otimes I$ | 값을 제자리에 놓기, 주대각만 덧셈 한 번 | numpy에 없음 |
| `block_diag` | 블록을 대각에 차례로 | 복사 | `scipy.linalg.block_diag`와 같음 |
| `cross` | $u \times v$ | 곱 두 개의 차 | `np.cross`와 같음 |
| `trace` | $\sum_i a_{ii}$ | 대각을 pairwise 합 | `np.trace`와 같음 |
| `diagonal` | $a_{i,i+k}$ | 복사 | 같음 (dtype 유지) |
| `bandwidth` | 아래·위 띠 폭 | 바깥쪽부터 훑다가 멈추기 | `scipy.linalg.bandwidth`와 같은 값 |
| `matrix_power` | $A^e$ | 이진 거듭제곱, `gemm` | $e = 0$–4에서 같음 |
| `vector_norm` | $\lVert x\rVert_p$ | pairwise 합(2-노름은 제곱을 잎에 융합), 필요할 때만 다시 스케일 | 1-노름과 $p$-노름은 넘치지 않는 범위에서 지금 같음. 2-노름은 끝 비트가 다를 수 있음 |
| `matrix_norm` (fro, ±1, ±inf) | 행렬 노름 | 줄마다 pairwise 합 | 레이아웃에 따라 끝 비트가 다를 수 있음 |

요점은 다섯 가지예요.

1. 원소 곱은 numpy와 같은 식이에요. complex 곱셈을 numpy처럼 FMA로 계산해요. 그래서 `outer`, `kron`, `cross`가 지금 numpy와 비트까지 같아요.
2. 부동소수점 합은 모두 배열과 같은 pairwise 트리예요. 그냥 합(`trace`, 1-노름)은 배열의 잎을 쓰고, 곱의 합(`vecdot`, 2-노름, 'fro')은 곱을 잎 안에서 합에 융합해요. 항을 논리적 C 순서로 넣으므로 결과가 메모리 레이아웃과 상관없어요([배치와 병렬화](/internals/linalg/batch/)).
3. NaN을 그대로 전파해요. LAPACK을 부르는 함수는 입력에 NaN이나 inf가 있으면 `ValueError`를 내지만, 이 함수들은 계산이 잘 정의되므로 검사하지 않아요. 예외는 음수 지수의 `matrix_power`(역행렬을 LAPACK으로 구해요)와 SVD로 계산하는 `matrix_norm`의 2, −2, nuc예요.
4. 노름은 빠른 한 번의 패스가 기본이고, 넘쳤을 때만 다시 스케일해요. 그래서 numpy가 inf나 0을 내는 극단값에서도 올바른 값을 내요.
5. 배치 드라이버를 그대로 써요. 비용 계열 `kStream`(합)과 `kCopy`(복사)로 나눌지를 정해요.

## 원소 곱: numpy와 같은 FMA 식

### complex 곱셈의 두 가지 계산

복소수 $a = a_r + i a_i$와 $b = b_r + i b_i$의 곱은

$$
ab = (a_r b_r - a_i b_i) + i\,(a_r b_i + a_i b_r)
$$

예요. 부동소수점에서는 이 식을 계산하는 방법이 둘이에요.

- **곱마다 반올림:** $a_r b_r$를 반올림하고, $a_i b_i$를 반올림하고, 그 차를 반올림해요. 반올림이 세 번이에요.
- **FMA:** FMA(fused multiply-add)는 $x \cdot y + z$를 **한 번만** 반올림하는 명령이에요(IEEE 754-2008부터 있는 연산 [5]). 실수부를 $\operatorname{fma}(a_r, b_r, -(a_i b_i))$로 계산하면 $a_i b_i$만 반올림하고, $a_r b_r$는 정확한 값 그대로 빼서 마지막에 한 번 반올림해요. 반올림이 두 번이에요.

두 방법은 마지막 비트가 자주 달라요. numpy 바이너리는 컴파일러의 FMA 축약(`a*b - c*d`를 FMA로 바꾸기)이 켜진 채 빌드돼 있어서 complex 곱셈이 두 번째 방법으로 계산돼요. 반면 C++의 `std::complex`의 `operator*`는 축약하지 않아요. 그리고 stardust는 컴파일러가 몰래 FMA를 만들지 않도록 `-ffp-contract=off`로 빌드해요(같은 식이 컴파일러 판단에 따라 다른 비트를 내지 않게 하려는 것이에요). FMA를 쓰는 자리는 코드에 직접 적어요. complex 곱셈은 numpy에서 축약이 일어나는 자리와 같은 곳에 적어서, 지금은 numpy와 비트까지 같아요.

```cpp
// linalg/types.hpp
inline double mul(double a, double b) { return a * b; }
inline cplx mul(cplx a, cplx b) {
    const double ar = a.real(), ai = a.imag(), br = b.real(), bi = b.imag();
    return {std::fma(ar, br, -(ai * bi)), std::fma(ar, bi, ai * br)};
}
```

배열 영역의 complex 곱셈(`array/kernels/scalar_ops.hpp`의 `cmul`)과 같은 식이에요([원소별 커널](/internals/array/elementwise/)). 무작위 복소수 2000쌍을 곱해 보면 곱마다 반올림한 값과 numpy 2.5.4의 값이 852쌍(43%)에서 마지막 비트가 달라요. 다음은 그런 쌍 하나예요.

```python
>>> import math
>>> import numpy as np
>>> a = complex(-0.29829145782149374, 0.9464980014362936)
>>> b = complex(0.051829038691168366, -0.549596157288264)
>>> a.real * b.imag + a.imag * b.real          # 허수부, 곱마다 반올림
0.21299592050816246
>>> math.fma(a.real, b.imag, a.imag * b.real)  # 허수부, FMA
0.21299592050816243
>>> (np.array([a]) * np.array([b]))[0].imag    # numpy
np.float64(0.21299592050816243)
>>> sd.linalg.outer(sd.asarray([a]), sd.asarray([b]))
array([[(0.5047315049617336+0.21299592050816243j)]], dtype=complex128)
```

`mul`을 쓰는 곳은 `vecdot`, `outer`, `kron`, `cross`예요. 실수 곱은 반올림이 한 번뿐이라 어느 방법이든 같아요.

### 곱의 순서도 비트를 정해요

FMA 식은 두 피연산자에 대칭이 아니에요. $\operatorname{fma}(a_r, b_i, a_i b_r)$에서 $a_i b_r$는 반올림하고 $a_r b_i$는 반올림하지 않으므로, $a \cdot b$와 $b \cdot a$의 허수부가 다를 수 있어요. 그래서 `kron`은 numpy처럼 **왼쪽 인자의 원소를 왼쪽에** 두고 곱해요(`mul(a[i, j], b[k, l])`).

## vecdot

### 수학

두 벡터의 내적(dot product)은 짝지은 원소의 곱을 모두 더한 값이에요.

$$
\langle x, y \rangle = \sum_{i=1}^{n} \overline{x_i}\, y_i
$$

실수 벡터에서는 $\langle x, y\rangle = \lVert x\rVert_2 \lVert y\rVert_2 \cos\theta$예요. $\theta$는 두 벡터 사이의 각이고, 내적은 "$y$를 $x$ 방향에 비춘 그림자의 길이 × $x$의 길이"예요. 0이면 두 벡터가 수직이에요.

complex에서는 첫 인자에 켤레를 취해요. 그래야 $\langle x, x\rangle = \sum |x_i|^2$가 음이 아닌 실수(길이의 제곱)가 돼요. 켤레가 없으면 $x = (i)$일 때 $x \cdot x = -1$이 되어 길이로 쓸 수 없어요. Array API 표준도 첫 인자에 켤레를 취해요.

### 축 규칙

`vecdot(x1, x2, axis=-1)`은 두 인자를 브로드캐스트한 모양에서 `axis`를 따라 내적해요. `axis`는 **브로드캐스트된 모양 기준**으로 세고, 그 축 자체는 브로드캐스트하지 않아요. 두 인자의 그 축 길이가 같아야 하고, 다르면 `ValueError`예요(Array API 규칙). 구현은 두 인자를 왼쪽에 길이 1인 축을 붙여 같은 차원으로 맞춘 뒤(`Padded`), 내적하는 축을 떼어 낸 나머지를 `Batch`로 브로드캐스트해요. 배치 원소 하나가 출력 하나예요.

### 구현

내적은 곱 $\overline{x_i} y_i$를 항으로 하는 pairwise 합이에요. 트리는 배열의 합과 같고(`base/pairwise.hpp`), 잎만 내적의 것이에요. 잎은 곱을 합에 바로 융합해요. NEON 레지스터 8개(레인 16개)에 `vfmaq`로 곱-덧셈을 반올림 한 번에 하고, 레인은 pairwise로 더해요(`fma_dot_leaf`).

```cpp
// linalg/pairwise.hpp (발췌)
inline double fma_dot_leaf(const double* a, const double* b, std::int64_t n) {
    std::int64_t i = 0;
    double r = 0.;
    if (n >= 16) {
        float64x2_t acc[8];
        for (int j = 0; j < 8; ++j) acc[j] = vmulq_f64(vld1q_f64(a + 2 * j), vld1q_f64(b + 2 * j));
        for (i = 16; i + 16 <= n; i += 16)
            for (int j = 0; j < 8; ++j) acc[j] = vfmaq_f64(acc[j], vld1q_f64(a + i + 2 * j), vld1q_f64(b + i + 2 * j));
        const float64x2_t s = vaddq_f64(
            vaddq_f64(vaddq_f64(acc[0], acc[1]), vaddq_f64(acc[2], acc[3])),
            vaddq_f64(vaddq_f64(acc[4], acc[5]), vaddq_f64(acc[6], acc[7]))
        );
        r = vgetq_lane_f64(s, 0) + vgetq_lane_f64(s, 1);
    }
    for (; i < n; ++i) r = std::fma(a[i], b[i], r);
    return r;
}
```

complex `vecdot`(`fma_cdot_leaf`)은 complex 4개를 레지스터 쌍으로 둬요. `x·y`의 두 레인 합이 실수부($x_r y_r + x_i y_i$), `x·swap(y)`의 두 레인 차가 허수부($x_r y_i - x_i y_r$)예요. 켤레는 이 식 안에 들어 있어요.

잎이 입력을 읽는 길은 둘이에요.

```cpp
// linalg/ops/basic.cpp의 vecdot (발췌)
auto leaf = [&](std::int64_t b0, std::int64_t k) -> T {
    if constexpr (direct_type) {
        if (direct) {
            const T* a = reinterpret_cast<const T*>(p) + b0;
            const T* c = reinterpret_cast<const T*>(q) + b0;
            if constexpr (std::is_same_v<T, cplx>) return detail::fma_cdot_leaf(a, c, k);
            else return detail::fma_dot_leaf(a, c, k);
        }
    }
    alignas(16) double ra[kPairwiseBlock], rc[kPairwiseBlock];  // no constructor runs
    T* a = reinterpret_cast<T*>(ra);
    T* c = reinterpret_cast<T*>(rc);
    const std::byte* pp = p + b0 * sx;
    const std::byte* qq = q + b0 * sy;
    for (std::int64_t i = 0; i < k; ++i) {
        a[i] = convert<T>(load<SX>(pp + i * sx));
        c[i] = convert<T>(load<SY>(qq + i * sy));
    }
    if constexpr (std::is_same_v<T, cplx>) return detail::fma_cdot_leaf(a, c, k);
    else return detail::fma_dot_leaf(a, c, k);
};
return pairwise_tree_mt<T>(len, leaf);  // on the pool when long (docs/design/linalg.md §8.3)
```

- 두 입력이 계산 타입(float64 또는 complex128)이고 연속이면 버퍼 없이 입력을 바로 읽어요.
- 그 밖(strided, 다른 dtype)은 잎 하나 분량을 두 버퍼에 바꿔 채운 뒤 같은 잎을 불러요. `SX`, `SY`는 두 입력이 메모리에 저장된 타입이에요(bool, int64, float64, complex128). 템플릿 람다 두 겹(`visit_storage`)으로 조합마다 루프를 만들어서, 원소마다 dtype을 묻지 않아요.
- 잎은 항의 값만의 함수라서 두 길의 비트가 같아요. 그래서 결과가 레이아웃과 상관없어요.
- 길이가 2¹⁵ 이상이면 합 하나를 트리의 잎 단위로 풀에서 나눠요([배치와 병렬화](/internals/linalg/batch/)). 계획과 합치는 순서는 배열의 합과 같아요.

곱마다의 반올림 하나가 없어서 오차는 곱을 먼저 반올림해 더할 때와 같거나 작아요. 대신 `sd.sum(sd.conj(x1) * x2, axis=-1)`과는 끝 비트가 다를 수 있어요. numpy와의 비트도 약속하지 않아요(numpy 2.5.4의 `np.vecdot`은 BLAS 내적 `np.dot`과 같은 값을 내요).

비용은 곱-덧셈 $n$번이고, 원소 하나를 한 번 읽고 끝나므로 긴 벡터에서는 메모리 대역폭이 시간을 정해요.

## outer

### 수학

외적(outer product) $xy^{T}$는 $x$의 원소마다 $y$ 전체를 곱해 행 하나를 만든 행렬이에요. $(xy^{T})_{ij} = x_i y_j$이고, 모양은 $m \times n$이에요.

모든 행이 같은 벡터 $y$의 배수이므로 랭크가 1인 행렬이에요(0 벡터가 아니면). 거꾸로 랭크 1인 행렬은 모두 외적 하나로 쓸 수 있어요. SVD는 행렬을 이런 랭크 1 행렬들의 합 $\sum_k \sigma_k u_k v_k^{H}$로 나타내요([특이값 분해](/internals/linalg/svd/)).

### 구현

`outer(x1, x2)`는 `(..., M)`과 `(..., N)`을 받아 `(..., M, N)`을 돌려줘요. 배치 축은 브로드캐스트해요. 결과는 다른 행렬 함수처럼 열 우선이라서 열 하나씩 채워요.

```cpp
// linalg/ops/basic.cpp의 outer (발췌)
T* xv = s.get<T>(m);                                   // x1을 한 번만 계산 타입으로
for (std::int64_t r = 0; r < m; ++r) xv[r] = convert<T>(load<SX>(x.data() + off[0] + r * sx));
T* o = res + i * m * n;
for (std::int64_t c = 0; c < n; ++c) {
    const T yc = convert<T>(load<SY>(y.data() + off[1] + c * sy));
    for (std::int64_t r = 0; r < m; ++r) o[c * m + r] = mul(xv[r], yc);   // 연속 쓰기
}
```

`x1`은 열마다 다시 읽으므로 `Scratch`에 한 번 변환해 두고, `x2`의 원소는 열마다 하나만 읽어요. 안쪽 루프는 연속한 메모리에 쓰는 곱셈이라 벡터화돼요. 결과는 `x[..., :, None] * x2[..., None, :]`와 비트까지 같아요(같은 `mul`, `x1`이 왼쪽).

## kron

### 수학

크로네커 곱(Kronecker product) $A \otimes B$는 $A$의 원소 하나하나를 "$B$ 전체에 그 원소를 곱한 블록"으로 바꾼 행렬이에요 [4][6].

$$
A \otimes B = \begin{bmatrix} a_{11}B & a_{12}B & \cdots & a_{1n}B \\ \vdots & & \ddots & \vdots \\ a_{m1}B & a_{m2}B & \cdots & a_{mn}B \end{bmatrix}
$$

$A$가 $m \times n$, $B$가 $p \times q$이면 결과는 $mp \times nq$예요. 원소로 쓰면 $(A \otimes B)_{(i-1)p + k,\ (j-1)q + l} = a_{ij} b_{kl}$이에요.

</Fig>

```python
>>> sd.linalg.kron(sd.asarray([[1, 2], [3, 4]]), sd.asarray([[0, 1], [1, 0]]))
array([[0.0, 1.0, 0.0, 2.0],
       [1.0, 0.0, 2.0, 0.0],
       [0.0, 3.0, 0.0, 4.0],
       [3.0, 0.0, 4.0, 0.0]], dtype=float64)
```

크로네커 곱이 쓸모 있는 이유는 행렬 방정식을 보통의 연립방정식으로 바꿔 주기 때문이에요. 행렬 $X$의 열을 차례로 쌓은 벡터를 $\operatorname{vec}(X)$라고 하면

$$
\operatorname{vec}(AXB) = (B^{T} \otimes A)\,\operatorname{vec}(X)
$$

예요 [4]. 예를 들어 Sylvester 방정식 $AX + XB = C$는 $(I \otimes A + B^{T} \otimes I)\operatorname{vec}(X) = \operatorname{vec}(C)$가 돼요. 또 $(A \otimes B)(C \otimes D) = AC \otimes BD$(혼합곱 성질)가 성립해서, 큰 크로네커 곱을 실제로 만들지 않고 작은 인자들로 계산하는 알고리즘의 바탕이 돼요.

### 배치 규칙

`kron`은 다른 행렬 함수처럼 **행렬 묶음**을 받아서 `(..., M, N) ⊗ (..., P, Q) → (..., M·P, N·Q)`를 계산해요. 앞의 배치 축은 브로드캐스트해요. `np.kron`은 이와 달리 모든 축에 크로네커 곱을 해요. `(2, 2, 3)`과 `(2, 4, 5)`를 넣으면 numpy 2.5.4는 `(4, 8, 15)`, stardust는 `(2, 8, 15)`를 돌려줘요. 1·2차원 입력에서는 둘이 같아요.

1차원 입력 `(N,)`은 한 행 `(1, N)`으로 읽고, 배치 축이 없다고 봐요. 둘 다 1차원이면 결과도 1차원 `(N·Q,)`이고, 하나만 1차원이면 결과는 행렬이에요. `np.kron`과 `sd.sparse.kron`이 1차원 입력을 읽는 방법과 같아요.

```python
>>> sd.linalg.kron(sd.asarray([1, 2]), sd.asarray([1, 10, 100]))
array([  1.0,  10.0, 100.0,   2.0,  20.0, 200.0], dtype=float64)
>>> sd.linalg.kron(sd.asarray([1.0, 2.0]), sd.asarray([[1.0], [3.0]]))
array([[1.0, 2.0],
       [3.0, 6.0]], dtype=float64)
>>> sd.linalg.kron(sd.ones((3, 2, 2)), sd.asarray([1.0, 2.0])).shape
(3, 2, 4)
```

마지막 예에서 1차원 `[1, 2]`는 `(1, 2)` 행렬 하나라서, `(3, 2, 2)`의 배치 축 3과 브로드캐스트돼요.

정수 입력은 float64로 계산해요(`np.kron`은 정수를 유지해요). 계산하는 linalg 함수의 공통 규칙이에요.

### 구현

피연산자 하나를 행렬로 읽는 방법은 `KronOperand`가 정해요. 1차원이면 행 수 1, 행 간격 0, 배치 축 없음이에요.

```cpp
// csrc/linalg/ops/basic.cpp
struct KronOperand {
    std::int64_t rows, cols, rs, cs;
    std::span<const std::int64_t> bshape, bstrides;
    explicit KronOperand(const Input& x)
        : rows(x.ndim() == 1 ? 1 : x.shape(-2)),
          cols(x.shape(-1)),
          rs(x.ndim() == 1 ? 0 : x.stride(-2)),
          cs(x.stride(-1)),
          bshape(x.ndim() == 1 ? std::span<const std::int64_t>{} : x.batch_shape(2)),
          bstrides(x.ndim() == 1 ? std::span<const std::int64_t>{} : x.batch_strides(2)) {}
};
```

`kron`은 두 피연산자를 이렇게 읽고 결과의 모양을 정해요.

```cpp
    // csrc/linalg/ops/basic.cpp
    // A 1-D operand is one row; two 1-D operands give the 1-D (N*Q,).
    const KronOperand ox(x), oy(y);
    const std::int64_t m = ox.rows, n = ox.cols, p = oy.rows, q = oy.cols;
    const bool vector = x.ndim() == 1 && y.ndim() == 1;
    Batch b({{ox.bshape, ox.bstrides}, {oy.bshape, oy.bstrides}}, "kron");
    // M*P and N*Q of broadcast views can pass int64; the rest is checked by alloc_matrices.
    std::int64_t rows, cols;
    if (__builtin_mul_overflow(m, p, &rows) || __builtin_mul_overflow(n, q, &cols))
        throw nb::value_error("array is too big");
    const bool complex = computes_complex(x.dtype()) || computes_complex(y.dtype());
    return with_type(complex, [&]<class T>(std::type_identity<T>) -> nb::object {
        // (1, N*Q) column-major is the contiguous vector (N*Q,)
        Out out = vector ? alloc_vectors(b.shape(), cols, dtype_of<T>())
                         : alloc_matrices(b.shape(), rows, cols, dtype_of<T>());
```

두 피연산자의 배치 축을 `Batch`에 넘기면 브로드캐스트한 배치 모양이 나와요. 1차원 피연산자는 배치 축이 비어 있으니 다른 쪽의 배치를 그대로 따라가요. $M \cdot P$, $N \cdot Q$는 브로드캐스트된 뷰에서 int64를 넘을 수 있어서 `__builtin_mul_overflow`로 따로 검사해요. 둘 다 1차원이면 결과를 `(1, N·Q)` 행렬 대신 길이 $N \cdot Q$의 벡터로 만들어요. 열 우선 `(1, N·Q)`가 메모리에서 곧 연속 벡터라서 채우는 루프는 같아요.

배치 원소 하나는 두 인자를 `Scratch`에 열 우선으로 패킹한 뒤, 결과를 메모리 순서대로 채워요.

```cpp
            // csrc/linalg/ops/basic.cpp
            // both operands converted into scratch once, column-major; NaN passes through
            T* a = s.get<T>(static_cast<std::size_t>(m * n), 0);
            T* c = s.get<T>(static_cast<std::size_t>(p * q), 1);
            pack(x.dtype(), x.data() + off[0], m, n, ox.rs, ox.cs, a, m, false);
            pack(y.dtype(), y.data() + off[1], p, q, oy.rs, oy.cs, c, p, false);
            T* o = res + i * block;
            // result column j*q + l, row block i: a[i, j] * c[:, l], with a on the left as
            // np.kron's multiply (the complex product's bits depend on the order)
            for (std::int64_t j = 0; j < n; ++j)
                for (std::int64_t l = 0; l < q; ++l) {
                    T* col = o + (j * q + l) * rows;
                    const T* cl = c + l * p;
                    for (std::int64_t r = 0; r < m; ++r) {
                        const T arj = a[j * m + r];
                        T* dst = col + r * p;
                        for (std::int64_t k = 0; k < p; ++k) dst[k] = mul(arj, cl[k]);
                    }
                }
            return 0;
```

- 루프 순서는 결과의 열 우선 순서와 같아요. 결과의 열 $jq + l$은 $a_{\cdot j} \otimes b_{\cdot l}$이고, 그 안에서 $A$의 행 $r$마다 길이 $p$짜리 조각 $a_{rj} \cdot b_{\cdot l}$을 연속으로 써요. 결과 전체를 한 번, 순서대로 써요.
- 패킹의 마지막 인자 `false`는 유한성 검사를 끈다는 뜻이에요. NaN은 그대로 결과로 가요. 1차원 피연산자는 행 간격 `rs`가 0이지만 행이 하나뿐이라 그 값을 쓰지 않아요.
- 곱셈은 결과 원소 수 $mnpq$번이고, 결과를 쓰는 것이 시간의 대부분이에요. 그래서 비용 계열은 `kCopy`이고 $w$는 결과 원소 수예요.

결과는 지금 `np.kron`(1·2차원)과 비트까지 같아요(약속은 아니에요). 배치 입력은 numpy의 브로드캐스트 곱을 모양만 바꾼 `(a[..., :, None, :, None] * b[..., None, :, None, :]).reshape(...)`와 같아요.

## kronsum

### 수학

크로네커 합(Kronecker sum)은 $m \times m$ 행렬 $A$와 $n \times n$ 행렬 $B$로

$$
A \oplus B = I_n \otimes A + B \otimes I_m
$$

을 만든 $mn \times mn$ 행렬이에요 [4][6]. $m \times m$ 블록이 $n \times n$ 격자로 놓인 모양이고, 대각 블록 $(i, i)$는 $A + b_{ii} I$, 나머지 블록 $(i, j)$는 $b_{ij} I$예요. 원소로 쓰면

$$
(A \oplus B)_{im + p,\ jm + q} = a_{pq}\,\delta_{ij} + b_{ij}\,\delta_{pq}
$$

이에요(번호는 0부터). 그래서 원소마다 $A$의 값, $B$의 값, 0 가운데 하나이고, 두 값이 겹치는 곳은 주대각의 $a_{pp} + b_{ii}$뿐이에요.

```python
>>> A = sd.asarray([[1.0, 2.0], [3.0, 4.0]])
>>> B = sd.asarray([[10.0, 20.0], [30.0, 40.0]])
>>> sd.linalg.kronsum(A, B)
array([[11.0,  2.0, 20.0,  0.0],
       [ 3.0, 14.0,  0.0, 20.0],
       [30.0,  0.0, 41.0,  2.0],
       [ 0.0, 30.0,  3.0, 44.0]], dtype=float64)
```

크로네커 합은 1차원 격자의 연산자 둘로 2차원 격자의 연산자를 만들 때 나와요. $\operatorname{vec}(X)$에 곱하면 $\operatorname{vec}(AX + XB^{\mathsf T})$가 되므로, $A$가 $x$ 방향, $B$가 $y$ 방향으로 따로 작용하는 연산자예요. 고유값은 $A$의 고유값과 $B$의 고유값의 모든 합 $\lambda_p + \mu_i$예요 [6].

규칙은 `kron`과 같아요. `x1`은 `(..., M, M)`, `x2`는 `(..., N, N)`이고 정사각이어야 해요(아니면 `ValueError`). 배치 축은 브로드캐스트하고, bool과 int64는 float64로 계산해요.

### 구현: 곱하지 않고 놓기

식대로 `kron(I, A) + kron(B, I)`를 만들면 단위 행렬의 0을 $A$, $B$의 원소와 곱하게 돼요. 원소에 inf가 있으면 $0 \cdot \infty = \text{NaN}$이 블록 곳곳에 생겨요. `kronsum`은 곱하지 않고 값을 제자리에 놓아요.

```cpp
            // csrc/linalg/ops/basic.cpp
            // column J = j*m + q (column-major): A's column q in block row j, then b_ij at
            // row i*m + q of every block row i (added to a_qq on block row j)
            for (std::int64_t j = 0; j < n; ++j)
                for (std::int64_t q = 0; q < m; ++q) {
                    T* col = o + (j * m + q) * size;
                    std::fill(col, col + size, T(0));
                    std::copy(a + q * m, a + (q + 1) * m, col + j * m);
                    const T* cj = c + j * n;
                    for (std::int64_t r = 0; r < n; ++r) {
                        if (r == j) col[r * m + q] = col[r * m + q] + cj[r];  // kron(I, A) + kron(B, I)
                        else col[r * m + q] = cj[r];
                    }
                }
            return 0;
```

결과의 열 $J = jm + q$ 하나를 위에서 아래로 채워요. 먼저 열 전체를 +0으로 채우고, 블록 행 $j$ 자리에 $A$의 $q$열을 복사해요(대각 블록). 그다음 블록 행 $r$마다 그 블록의 대각 자리(행 $rm + q$)에 $b_{rj}$를 놓아요. $r = j$이면 그 자리에 이미 $a_{qq}$가 있으므로 더해요. 원소 하나에 덧셈은 많아야 한 번이고, $A$ 쪽이 먼저예요.

```python
>>> Ai = sd.asarray([[float('inf'), 0.0], [0.0, 1.0]])
>>> sd.linalg.kronsum(Ai, B)
array([[ inf,  0.0, 20.0,  0.0],
       [ 0.0, 11.0,  0.0, 20.0],
       [30.0,  0.0,  inf,  0.0],
       [ 0.0, 30.0,  0.0, 41.0]], dtype=float64)
>>> I = sd.eye(2)
>>> sd.linalg.kron(I, Ai) + sd.linalg.kron(B, I)
array([[ inf,  0.0,  nan,  0.0],
       [ 0.0, 11.0,  0.0, 20.0],
       [ nan,  0.0,  inf,  0.0],
       [ 0.0, 30.0,  0.0, 41.0]], dtype=float64)
```

- inf와 NaN은 제자리에만 있어요. 위의 `kron` 식에서는 $(0, 2)$ 자리가 $0 \cdot \infty + 20 = \text{NaN}$이 돼요.
- 패킹은 `kron`처럼 유한성 검사를 끈 채(`false`) 두 인자를 `Scratch`에 열 우선으로 옮겨요. 결과를 한 번, 열 순서대로 써요.
- $m \cdot n$은 `__builtin_mul_overflow`로 검사해요. 비용 계열은 `kCopy`, $w$는 결과 원소 수 $(mn)^2$예요.
- `sd.sparse.kronsum(A, B).toarray()`와는 float64와 complex128에서 0의 부호만 다를 수 있어요. 희소 쪽도 곱하지 않고 같은 자리에 같은 값을 놓고, 주대각의 덧셈도 $A$ 쪽이 먼저예요. 희소 쪽의 `toarray()`는 0에 저장된 값을 더해 밀집 배열을 만들므로, −0.0(complex면 허수부의 −0.0)이 +0.0으로 나와요. 정수 입력이면 희소 쪽은 int64를 유지해요.

## block_diag

### 규칙

`block_diag(arrays)`는 행렬 여러 개를 대각선을 따라 차례로 놓고 나머지를 0으로 채워요. 블록 $(..., M_i, N_i)$들에서 $(..., \sum M_i, \sum N_i)$가 나와요. 인자는 `sd.ndarray`의 list나 tuple 하나예요(`concat`, `sd.sparse.block_diag`처럼). 빈 목록은 `ValueError`예요.

```python
>>> sd.linalg.block_diag([sd.asarray([[1, 2], [3, 4]]), sd.asarray([5, 6, 7])])
array([[1, 2, 0, 0, 0],
       [3, 4, 0, 0, 0],
       [0, 0, 5, 6, 7]], dtype=int64)
>>> sd.linalg.block_diag([sd.zeros((0, 2)), sd.asarray([[1.0]])])
array([[0.0, 0.0, 1.0]], dtype=float64)
```

- 1차원 블록 `(N,)`은 `kron`처럼 한 행 `(1, N)`이에요. 같은 `KronOperand`로 읽어요.
- 빈 블록도 자리를 차지해요. 위의 `(0, 2)` 블록은 행은 없지만 열 두 개를 차지해요.
- 값을 옮기기만 하므로 결과 dtype은 입력들의 승격이에요. int64 블록끼리는 int64이고, bool끼리는 bool이에요. `diagonal`과 같은 예외예요.
- 배치 축은 모든 블록 사이에서 브로드캐스트해요.

```python
>>> sd.linalg.block_diag([sd.ones((2, 1, 1)), sd.asarray([[5.0]])])
array([[[1.0, 0.0],
        [0.0, 5.0]],

       [[1.0, 0.0],
        [0.0, 5.0]]], dtype=float64)
>>> sd.linalg.block_diag([sd.ones((2, 1, 1)), sd.ones((3, 1, 1))])
Traceback (most recent call last):
    ...
ValueError: block_diag(): batch shapes do not broadcast: (2,) (3,)
```

### 구현

다른 함수는 피연산자의 배치 축을 `Batch`에 넘겨 브로드캐스트하지만, `Batch`가 받는 피연산자는 4개(`kMaxOperands`)까지예요. 블록 수에는 한계가 없으므로 `block_diag`는 브로드캐스트한 배치 모양을 직접 구하고, 블록마다 배치 축의 바이트 간격을 따로 들고 가요.

```cpp
    // csrc/linalg/ops/basic.cpp
    // the broadcast batch shape (right-aligned, size-1 axes stretch), as Batch's
    std::vector<std::int64_t> bshape(nd, 1);
    for (const KronOperand& o : ops) {
        const std::size_t lead = nd - o.bshape.size();
        for (std::size_t d = 0; d < o.bshape.size(); ++d) {
            std::int64_t& r = bshape[lead + d];
            if (o.bshape[d] == r || o.bshape[d] == 1) continue;
            if (r == 1) {
                r = o.bshape[d];
                continue;
            }
            std::string msg = "block_diag(): batch shapes do not broadcast:";
            for (const KronOperand& q : ops) msg += " " + shape_str(q.bshape);
            throw nb::value_error(msg.c_str());
        }
    }
    // each operand's byte stride per broadcast batch axis (0 where it broadcasts)
    std::vector<std::int64_t> bstride(ops.size() * nd, 0);
    for (std::size_t j = 0; j < ops.size(); ++j) {
        const std::size_t lead = nd - ops[j].bshape.size();
        for (std::size_t d = 0; d < ops[j].bshape.size(); ++d)
            if (ops[j].bshape[d] != 1) bstride[j * nd + lead + d] = ops[j].bstrides[d];
    }
    const std::vector<std::int64_t> zero(nd, 0);
    Batch b({{bshape, zero}}, "block_diag");  // walks the batch (and checks its size)
```

`Batch`에는 이렇게 구한 모양과 간격 0인 가짜 피연산자 하나만 넘겨요. 배치를 걷고 배치 크기를 검사하는 데만 써요. 배치 원소 하나의 몸체는 원소 번호를 배치 좌표로 풀어 블록마다 자기 위치를 구해요.

```cpp
            // csrc/linalg/ops/basic.cpp
            R* o = res + i * block;
            std::fill(o, o + block, R(0));
            std::int64_t coord[kMaxNdim];
            for (std::int64_t d = static_cast<std::int64_t>(nd) - 1, t = i; d >= 0; --d) {
                coord[d] = t % bshape[d];
                t /= bshape[d];
            }
            std::int64_t r0 = 0, c0 = 0;
            for (std::size_t j = 0; j < ops.size(); ++j) {
                const KronOperand& op = ops[j];
                std::int64_t off = 0;
                for (std::size_t d = 0; d < nd; ++d) off += coord[d] * bstride[j * nd + d];
                const std::byte* p = in[j].data() + off;
                visit_storage(in[j].dtype(), [&]<class S>(std::type_identity<S>) {
                    if constexpr (!(std::is_same_v<S, cplx> && !std::is_same_v<R, cplx>)) {
                        for (std::int64_t c = 0; c < op.cols; ++c) {
                            R* dst = o + (c0 + c) * rows + r0;
                            for (std::int64_t r = 0; r < op.rows; ++r)
                                dst[r] = convert<R>(load<S>(p + r * op.rs + c * op.cs));
                        }
                    }
                    return 0;
                });
                r0 += op.rows;
                c0 += op.cols;
            }
```

- 결과를 먼저 0으로 채우고, 블록을 결과의 열 우선 순서로 하나씩 복사해요. `r0`, `c0`가 다음 블록이 놓일 왼쪽 위 자리예요.
- 원소마다 하는 일은 저장 타입을 읽어 결과 dtype으로 바꾸는 `convert<R>(load<S>(...))`뿐이에요. 계산이 없으므로 값이 그대로 가고, NaN도 그대로 복사해요.
- 결과는 지금 `scipy.linalg.block_diag`와 바이트까지 같아요(약속은 아니에요). `sd.sparse.block_diag(arrays).toarray()`와는 0의 부호만 다를 수 있어요.
- 비용 계열은 `kCopy`, $w$는 결과 원소 수예요.

## cross

### 수학

3차원 벡터 $u$, $v$의 외적(cross product, 벡터곱) $u \times v$는 세 가지 성질로 정해지는 벡터예요.

- **방향:** $u$와 $v$에 모두 수직이에요. 오른손의 검지를 $u$, 중지를 $v$ 쪽으로 펴면 엄지가 $u \times v$ 방향이에요(오른손 법칙).
- **길이:** $\lVert u \times v\rVert = \lVert u\rVert \lVert v\rVert \sin\theta$, 곧 $u$와 $v$가 만드는 평행사변형의 넓이예요. 평행하면 0이에요.
- **순서:** $v \times u = -(u \times v)$예요.

성분으로 쓰면

$$
u \times v = \begin{bmatrix} u_1 v_2 - u_2 v_1 \\ u_2 v_0 - u_0 v_2 \\ u_0 v_1 - u_1 v_0 \end{bmatrix}
$$

이에요(성분 번호 0, 1, 2). 성분 $k$는 $u$와 $v$에서 $k$번째 성분을 지운 2×2 행렬식이에요(부호는 순환 순서를 따라요).

### 축과 결과 배치

`cross(x1, x2, axis=-1)`의 `axis` 규칙은 `vecdot`과 같아요. 브로드캐스트된 모양에서 세고, 그 축은 브로드캐스트하지 않으며, 두 인자 모두 그 축의 길이가 3이어야 해요(2차원 외적은 받지 않아요).

결과는 브로드캐스트된 모양에 길이 3인 축을 원래 자리에 넣은 C 순서 배열이에요. 그래서 결과 벡터 하나의 세 성분이 메모리에서 `inner` 간격으로 떨어져 있어요. `inner`는 그 축 뒤에 오는 축들의 길이 곱이에요.

```cpp
// linalg/ops/basic.cpp의 cross (발췌)
std::int64_t inner = 1;                    // 결과 벡터 하나의 두 성분 사이 원소 수
for (std::size_t d = ax; d < b.ndim(); ++d) inner *= b.shape()[d];
// 배치 원소 i의 결과 자리: 앞쪽 인덱스 (i / inner), 뒤쪽 인덱스 (i % inner)
T* o = res + (i / inner) * 3 * inner + i % inner;
o[0]         = mul(u[1], v[2]) - mul(u[2], v[1]);   // numpy처럼 곱마다 반올림한 뒤 빼요
o[inner]     = mul(u[2], v[0]) - mul(u[0], v[2]);
o[2 * inner] = mul(u[0], v[1]) - mul(u[1], v[0]);
```

`(1000, 3)`에 `axis=-1`이면 `inner = 1`이라 결과 벡터가 연속이고, `(3, 1000)`에 `axis=0`이면 `inner = 1000`이라 성분 $k$가 행 $k$에 놓여요.

numpy의 `np.cross`는 Python 수준에서 `multiply`로 곱을 만들고 `-=`로 빼요. 곱 하나하나가 따로 반올림된 배열이 된 뒤에 빼는 거예요. stardust도 FMA 축약이 꺼진 빌드에서 `mul(...) - mul(...)`로 같은 순서를 지켜요. 그래서 지금은 `np.cross`와 비트까지 같아요. 정수 입력은 float64로 계산해요(`np.cross`는 정수를 유지해요).

<Callout type="warn" title="거의 평행한 벡터">
$u_1 v_2 - u_2 v_1$은 거의 같은 두 수의 차가 될 수 있어요. 두 벡터가 거의 평행하면 결과가 작아지면서 상대오차가 커져요(소거). 곱마다 반올림하므로 오차 한계는 $|u_1 v_2| + |u_2 v_1|$에 단위 반올림의 몇 배를 곱한 정도예요. numpy와 같은 식을 쓰므로 같은 오차를 내요.
</Callout>

## trace와 diagonal

### 대각선 고르기

$m \times n$ 행렬의 $k$번째 대각선은 원소 $a_{i, i+k}$들이에요. $k = 0$이 주대각, $k > 0$은 위쪽, $k < 0$은 아래쪽이에요. 시작 위치와 길이를 `Diag`가 계산해요.

```cpp
// linalg/ops/basic.cpp
struct Diag {
    std::int64_t len, r0, c0;
    Diag(std::int64_t m, std::int64_t n, std::int64_t k) {
        if (k >= n || k <= -m) { len = r0 = c0 = 0; return; }   // 행렬 밖: 빈 대각선
        r0 = k >= 0 ? 0 : -k;
        c0 = k >= 0 ? k : 0;
        len = std::max<std::int64_t>(0, std::min(m - r0, n - c0));
    }
};
```

행렬 밖을 가리키는 오프셋을 먼저 걸러 내는 이유는 정수 오버플로예요. $k = -2^{63}$이면 `-k`가 int64로 표현되지 않고, 아주 큰 $|k|$에서는 `r0 * stride`가 넘쳐요. C++에서 부호 있는 정수의 오버플로는 정의되지 않은 동작이라, 계산하기 전에 빈 대각선으로 돌려보내요. 대각선을 걷는 간격은 `stride(-2) + stride(-1)`(한 행 아래, 한 열 오른쪽)이에요.

### trace

`trace`는 대각선의 pairwise 합이에요. 배열의 잎과 트리를 그대로 써서 `sum(diagonal(x))`와 비트까지 같아요. numpy의 `np.trace`와는 잎의 크기가 달라 끝 비트가 다를 수 있어요.

- 계산 dtype은 float64(complex 입력이면 complex128)예요. 정수 행렬의 대각합도 float64예요.
- `dtype=`은 `sd.sum(dtype=)`과 같은 명시적 변환이에요. 각 원소를 그 dtype으로 바꾼 뒤 누적해요. `dtype=sd.int64`이면 정수로 누적하고, 넘치면 wrap해요(부호 없는 정수로 더한 뒤 되돌려요). float → int는 0 방향으로 자르고 int64 범위로 포화시켜요.
- complex → 실수는 허수부를 버리게 되므로 `TypeError`예요. 실수부의 대각합은 `trace(sd.real(x))`로 구해요. `dtype=bool`도 `TypeError`예요.

### diagonal

`diagonal`은 계산하지 않고 원소를 꺼내기만 하므로 **입력 dtype을 유지해요**(int64 행렬의 대각선은 int64예요). 결과는 뷰가 아니라 복사본이에요. 다른 linalg 함수처럼 결과가 언제나 새 배열이에요. 복사는 저장 타입을 아는 루프로 해요(원소마다 `memcpy`를 부르지 않아요).

## bandwidth: 띠 폭 재기

### 정의

`bandwidth(x)`는 0이 아닌 원소가 주대각선에서 얼마나 멀리 퍼져 있는지를 재요. 아래 띠 폭 `lower`는 0이 아닌 $x_{ij}$($i > j$) 가운데 $i - j$의 최댓값, 위 띠 폭 `upper`는 $j > i$인 것 가운데 $j - i$의 최댓값이고, 없으면 0이에요. 정사각이 아니어도 돼요.

```python
>>> T = sd.asarray([[2.0, -1.0, 0.0, 0.0],
...                 [-1.0, 2.0, -1.0, 0.0],
...                 [0.0, -1.0, 2.0, -1.0],
...                 [0.0, 0.0, -1.0, 2.0]])
>>> sd.linalg.bandwidth(T)
BandwidthResult(lower=1, upper=1)
>>> sd.linalg.bandwidth(sd.triu(T))
BandwidthResult(lower=0, upper=1)
>>> sd.linalg.bandwidth(sd.stack([T, sd.triu(T)]))
BandwidthResult(lower=array([1, 0], dtype=int64), upper=array([1, 1], dtype=int64))
```

- "0이 아니다"는 `!= 0`이에요. NaN은 0이 아니고, −0.0은 0이에요. complex는 실수부나 허수부가 0이 아니면 0이 아니에요.
- 결과는 namedtuple `BandwidthResult(lower, upper)`예요. 2차원이면 두 필드가 Python `int`이고, 배치면 배치 모양의 int64 배열이에요(행렬마다 하나). 입력 dtype과 상관없이 정수예요.
- `upper == 0`이면 아래 삼각, `lower == 0`이면 위 삼각이에요. 두 값을 `solve_banded`의 `lower_bandwidth`, `upper_bandwidth`에 그대로 넘길 수 있어요.
- NaN을 그대로 셀 뿐이라 유한성 검사를 하지 않아요.

```python
>>> sd.linalg.bandwidth(sd.asarray([[1.0, -0.0, float('nan')], [0.0, 1.0, 0.0]]))
BandwidthResult(lower=0, upper=2)
```

### 구현: 바깥쪽부터 훑기

```cpp
// csrc/linalg/ops/basic.cpp
template <class S>
inline bool nonzero_at(const std::byte* p) {
    const S v = load<S>(p);
    if constexpr (std::is_same_v<S, cplx>) return v.real() != 0 || v.imag() != 0;
    else return v != S(0);
}

template <class S>
std::pair<std::int64_t, std::int64_t> band_of(
    const std::byte* p, std::int64_t m, std::int64_t n, std::int64_t rs, std::int64_t cs
) {
    std::int64_t lower = 0, upper = 0;
    auto at = [&](std::int64_t r, std::int64_t c) { return nonzero_at<S>(p + r * rs + c * cs); };
    if ((rs < 0 ? -rs : rs) <= (cs < 0 ? -cs : cs)) {  // columns are contiguous-ish: scan down columns
        for (std::int64_t c = 0; c < n; ++c) {
            for (std::int64_t r = m - 1; r > c + lower; --r)  // below: from the bottom up
                if (at(r, c)) {
                    lower = r - c;
                    break;
                }
            for (std::int64_t r = 0; r < std::min(m, c - upper); ++r)  // above: from the top down
                if (at(r, c)) {
                    upper = c - r;
                    break;
                }
        }
    } else {  // rows are: scan along rows
        for (std::int64_t r = 0; r < m; ++r) {
            for (std::int64_t c = 0; c < std::min(n, r - lower); ++c)  // below: from the left
                if (at(r, c)) {
                    lower = r - c;
                    break;
                }
            for (std::int64_t c = n - 1; c > r + upper; --c)  // above: from the right
                if (at(r, c)) {
                    upper = c - r;
                    break;
                }
        }
    }
    return {lower, upper};
}
```

- **메모리가 빠른 축을 따라 훑어요.** 행 간격 `rs`가 열 간격 `cs`보다 작으면(F 순서처럼 열이 연속이면) 열마다 위아래로, 아니면 행마다 좌우로 훑어요. 패킹하지 않고 입력을 stride로 바로 읽고, 저장 타입 그대로 비교해요(`visit_storage`). dtype 변환도 없어요.
- **바깥쪽부터 보고, 찾으면 멈춰요.** 열 $c$의 아래쪽은 맨 아래 행부터 올라오며 지금의 띠 바로 바깥(`r > c + lower`)까지만 봐요. 처음 만난 0이 아닌 원소가 이 열에서 가장 먼 것이라, 그 거리로 `lower`를 늘리고 멈춰요. 위쪽은 맨 위 행부터 내려오며 같은 일을 해요. 이미 찾은 띠 안의 원소는 다시 읽지 않아요.
- 그래서 읽는 양은 행렬 모양에 따라 크게 달라요. 꽉 찬 행렬은 모서리의 원소에서 곧바로 가장 넓은 띠가 정해지고, 그 뒤로는 열마다 원소 하나 정도만 읽고 끝나요. 반대로 띠가 좁은 행렬(삼중대각 등)과 0 행렬은 띠 바깥의 0을 하나하나 확인해야 해서 원소 거의 전부를 읽어요. 띠가 좁다는 결론은 바깥이 모두 0이라는 것을 다 봐야 내릴 수 있기 때문이에요.
- 배치면 행렬마다 따로 재요. 비용 계열은 `kStream`, $w$는 행렬 원소 수 $mn$이에요. 꽉 찬 행렬에서는 이 추정이 실제보다 커요.

결과는 지금 `scipy.linalg.bandwidth`와 같은 값이에요. `sd.sparse.spbandwidth`는 저장된 0도 0이 아닌 칸으로 세므로, 저장된 0이 없는 희소 배열 `A`에서만 `bandwidth(A.toarray())`와 같아요.

## matrix_power: 이진 거듭제곱

### 알고리즘

$A^{13}$을 구할 때 $A$를 12번 곱할 필요는 없어요. $13 = 1101_2$이므로 $A^{13} = A^8 A^4 A$이고, $A^2, A^4, A^8$은 제곱을 거듭해서 얻어요. 이 방법이 이진 거듭제곱(binary powering, square-and-multiply)이에요 [3].

stardust는 **최상위 비트부터** 해요. $r = A$로 시작해서 그다음 비트마다 $r \leftarrow r^2$을 하고, 그 비트가 1이면 $r \leftarrow rA$를 해요.

지수 $e$에서 제곱은 $\lfloor \log_2 e \rfloor$번, 곱은 $\operatorname{popcount}(e) - 1$번이에요($\operatorname{popcount}$는 1인 비트의 수). 행렬 곱 하나가 $2m^3$ flop이므로 전체는

$$
\bigl(\lfloor \log_2 e \rfloor + \operatorname{popcount}(e) - 1\bigr) \cdot 2m^3 \ \text{flop}
$$

이고, $e - 1$번 곱하는 단순한 방법의 $(e-1) \cdot 2m^3$보다 훨씬 적어요. $e = 2^{63} - 1$이어도 곱은 124번이에요.

### 구현

```cpp
// linalg/ops/basic.cpp의 matrix_power (발췌)
// |n|: INT64_MIN에서도 넘치지 않게 부호 없는 정수로
const std::uint64_t e = n < 0 ? std::uint64_t(0) - static_cast<std::uint64_t>(n) : static_cast<std::uint64_t>(n);
// ... 몸체 안에서
if (e == 0) { /* 단위행렬. x의 값은 보지 않아요 */ }
T* base = s.get<T>(mm, 1);
if (n < 0) {   // x^-e = (x^-1)^e. 역행렬은 inv와 같은 경로
    if (const int code = lu_factor<T>(x, off[0], m, s, lu, ipiv)) return code;   // 패킹·유한성 검사 + getrf
    lu_inverse(lu, ipiv, m, base);                                                 // getrs(I)
} else {
    pack(x.dtype(), x.data() + off[0], m, m, x.stride(-2), x.stride(-1), base, m, false);
}
int top = 63;
while (!((e >> top) & 1)) --top;                       // 최상위 비트
if (top == 0) { std::copy(base, base + mm, o); return 0; }   // x^1, x^-1
const int total = top + std::popcount(e) - 1;          // gemm 수
LapackSlot<T> os(o, mm, s, Scratch::kAlign0);          // 결과 자리(정렬이 아니면 대역)
T* buf[2] = {s.get<T>(mm, 2), s.get<T>(mm, 3)};
const T* r = base;
int done = 0, next = 0;
auto product = [&](const T* lhs, const T* rhs) {
    T* dst = ++done == total ? os.get() : buf[next];   // 마지막 곱은 결과 자리에 바로
    lapack::gemm_square(m, lhs, rhs, dst);             // cblas_dgemm / cblas_zgemm
    next ^= 1;
    r = dst;
};
for (int bit = top - 1; bit >= 0; --bit) {
    product(r, r);
    if ((e >> bit) & 1) product(r, base);
}
```

- **곱의 결과는 버퍼 두 개를 번갈아 써요.** `gemm`은 결과를 입력과 같은 메모리에 쓸 수 없으므로($C = AB$에서 $C$가 $A$를 덮으면 안 돼요) 최소 두 개가 필요해요. 최상위 비트부터 하면 곱의 한쪽은 언제나 직전 결과 $r$ 아니면 처음 행렬 `base`라서 두 개로 충분해요. `std::popcount`(C++20 `<bit>`)로 곱의 총수를 미리 알기 때문에 **마지막 곱을 결과 자리에 바로** 쓰고, 마지막에 복사하지 않아요.
- **행렬 곱은 `cblas_dgemm`/`cblas_zgemm`을 직접 불러요.** 작업 버퍼가 이미 C++ 안에 열 우선으로 있으므로 `sd.matmul`을 거칠 이유가 없어요. 넘기는 배열은 모두 16바이트 정렬이에요(`LapackSlot`).
- **음수 지수는 `inv`와 같은 경로로 역행렬을 구해요.** `getrf`로 분해하고 단위행렬을 우변으로 `getrs`를 불러요. 그래서 `matrix_power(x, -1)`은 `inv(x)`와 비트까지 같고, 특이 행렬이면 같은 `LinAlgError`, NaN 입력이면 같은 `ValueError`예요. 이 경로에만 [태스크 수 상한](/internals/linalg/batch/)을 둬요.
- **$e = 0$은 $x$의 값과 상관없이 단위행렬이에요.** NaN이 든 행렬의 0제곱도 단위행렬이에요(numpy도 같아요).
- 비용 계열은 `kLU`예요.

### numpy와 비트

numpy 2.5.4의 `matrix_power`는 $e \le 3$을 따로 처리하고($A$, $AA$, $(AA)A$), 그보다 크면 **최하위 비트부터** 이진 거듭제곱을 해요. 제곱한 $z$를 결과 쪽에 오른쪽에서 곱해요(`result = result @ z`). 두 방법은 곱의 수가 같지만 곱하는 순서가 달라요. $e = 5$에서 stardust는 $A^4 \cdot A$, numpy는 $A \cdot A^4$를 계산해요. 행렬 곱은 결합법칙은 성립해도 부동소수점에서는 순서에 따라 반올림이 달라요. 그래서 $e = 2, 3, 4$는 지금 numpy와 비트까지 같고(같은 순서), $e \ge 5$는 마지막 비트들이 다를 수 있어요. 무작위 3×3, 8×8, 32×32, 100×100 행렬로 비교하면 $e = 2, 3, 4$는 모두 같고 $e = 5, 6, 7, 13$은 모두 달랐어요.

## 노름

### 벡터 노름: 길이를 재는 방법들

노름(norm)은 벡터의 "크기"를 재는 함수예요. 가장 익숙한 것은 유클리드 길이 $\sqrt{x_1^2 + \cdots + x_n^2}$이지만, 다른 잣대도 쓸모가 있어요. 예를 들어 도시의 바둑판 길에서는 직선 거리보다 가로·세로로 걸은 거리 $|x_1| + |x_2|$가 실제 거리예요.

$p$-노름은 이것들을 하나로 묶어요.

$$
\lVert x\rVert_p = \Bigl(\sum_{i} |x_i|^p\Bigr)^{1/p}, \qquad \lVert x\rVert_\infty = \max_i |x_i|
$$

$p = 2$가 유클리드 길이, $p = 1$이 바둑판 거리, $p \to \infty$이면 가장 큰 성분만 남아요. "노름이 1 이하인 점들의 모임"(단위 공)을 그리면 잣대마다 모양이 달라요.

    { f: (x) => (x <= 1 ? 1 : NaN), label: 'p = ∞ (정사각형)', dashed: true },

위 그림은 2차원 단위 공의 경계를 1사분면만 그린 거예요(나머지는 대칭). $p$가 커질수록 경계가 바깥으로 부풀어 정사각형에 가까워져요. 모든 $x$에 대해 $\lVert x\rVert_\infty \le \lVert x\rVert_2 \le \lVert x\rVert_1$이에요.

`vector_norm(x, ord=...)`이 받는 `ord`는 이래요.

| `ord` | 값 | 비고 |
|:---:|---|---|
| `2` (기본) | $\sqrt{\sum \lvert x_i\rvert^2}$ | 넘치면 다시 스케일 |
| `1` | $\sum \lvert x_i\rvert$ | |
| `inf` | $\max \lvert x_i\rvert$ | |
| `-inf` | $\min \lvert x_i\rvert$ | 노름이 아니에요 |
| `0` | 0이 아닌 원소의 수 | 노름이 아니에요. NaN도 세요 |
| 그 밖의 $p > 0$ | $(\sum \lvert x_i\rvert^p)^{1/p}$ | 넘치면 다시 스케일 |
| $p < 0$ | $(\sum \lvert x_i\rvert^p)^{1/p}$ | 노름이 아니에요. 다시 스케일하지 않아요 |

노름이라고 부르려면 세 성질이 필요해요. $\lVert x\rVert \ge 0$이고 $x = 0$일 때만 0, $\lVert \alpha x\rVert = |\alpha| \lVert x\rVert$, 삼각부등식 $\lVert x + y\rVert \le \lVert x\rVert + \lVert y\rVert$. $p \ge 1$이면 성립하고, $p < 1$이나 `0`, `-inf`는 Array API와 numpy가 같은 이름으로 정의하는 값이라 받아요.

`axis`는 정수 하나, 튜플, 또는 `None`(전체)이에요. 여러 축을 한꺼번에 줄이면 그 축들의 원소를 하나의 벡터로 봐요.

### 행렬 노름

행렬의 크기를 재는 방법은 두 갈래예요.

**원소를 한 줄로 펴서 재기.** 프로베니우스 노름은 행렬의 원소를 모두 한 벡터로 보고 2-노름을 잰 것이에요.

$$
\lVert A\rVert_F = \sqrt{\sum_{i,j} |a_{ij}|^2}
$$

**행렬이 벡터를 얼마나 늘리는지 재기.** 행렬 $A$는 벡터 $x$를 $Ax$로 보내요. 그때 길이가 가장 많이 늘어나는 비율을 행렬의 노름으로 삼아요(유도된 노름, induced norm).

$$
\lVert A\rVert_p = \max_{x \ne 0} \frac{\lVert Ax\rVert_p}{\lVert x\rVert_p}
$$

$p = 1$이면 이 최댓값이 **열의 절댓값 합 중 가장 큰 것**이 돼요. $\lVert Ax\rVert_1 = \sum_i \bigl|\sum_j a_{ij} x_j\bigr| \le \sum_j |x_j| \sum_i |a_{ij}| \le \bigl(\max_j \sum_i |a_{ij}|\bigr) \lVert x\rVert_1$이고, 가장 큰 열 $j$의 단위벡터 $e_j$를 넣으면 등호가 돼요. 같은 방법으로 $p = \infty$이면 **행의 절댓값 합 중 가장 큰 것**이에요 [4].

$p = 2$이면 가장 큰 특이값 $\sigma_1$이에요. `matrix_norm`의 `ord`는 이래요.

| `ord` | 값 | 계산 |
|:---:|---|---|
| `'fro'` (기본) | $\sqrt{\sum \lvert a_{ij}\rvert^2}$ | 원소의 2-노름, 이 글의 루프 |
| `1`, `-1` | 열 절댓값 합의 최대, 최소 | 이 글의 루프 |
| `inf`, `-inf` | 행 절댓값 합의 최대, 최소 | 이 글의 루프 |
| `2`, `-2` | 가장 큰, 가장 작은 특이값 | SVD (`gesdd`) |
| `'nuc'` | 특이값의 합 | SVD (`gesdd`) |

`2`, `−2`, `nuc`는 특이값이 필요하므로 LAPACK을 불러요. 그래서 NaN·inf 입력에 `ValueError`를 내고, 나머지 `ord`는 NaN을 전파해요. SVD 쪽은 [특이값 분해](/internals/linalg/svd/)에서 다뤄요. `-1`, `-2`, `-inf`는 노름의 성질을 만족하지 않지만 numpy와 같은 이름으로 정의된 값이라 받아요.

### 구현: 논리적 C 순서로 걷기

노름은 원소를 **논리적 C 순서**(마지막 축이 가장 빨리 변하는 순서)로 걸어 pairwise 합에 넣어요. 메모리 레이아웃과 상관없는 순서라서 같은 행렬을 C 순서, F 순서, 뒤집은 뷰로 넣어도 결과가 비트까지 같아요. 걷는 일은 `vnorm.hpp`의 `Walk`가 해요.

```cpp
// linalg/ops/vnorm.hpp의 Walk (발췌)
inline constexpr int kMaxWalkDims = 33;   // 배열의 최대 32축 + complex 분할 1축

template <class S, class Mag>
class Walk {
public:
    // fill: 평평한 위치 begin … begin+len-1의 |x|를 out에
    void operator()(std::int64_t begin, std::int64_t len, double* out) const {
        std::int64_t idx[kMaxWalkDims];
        const std::byte* p = base_;
        std::int64_t rem = begin;                       // begin을 다차원 인덱스로
        for (int d = nd_; d-- > 0;) { idx[d] = rem % shape_[d]; rem /= shape_[d]; p += idx[d] * strides_[d]; }
        const int last = nd_ - 1;
        std::int64_t k = 0;
        while (true) {
            const std::int64_t run = std::min(len - k, shape_[last] - idx[last]);   // 마지막 축의 한 줄
            for (std::int64_t t = 0; t < run; ++t) out[k + t] = mag_(load<S>(p + t * strides_[last]));
            k += run;
            if (k == len) return;
            /* 마지막 축 끝: 바깥 축으로 올림(carry) */
        }
    }
private:
    const std::byte* base_;
    int nd_;
    std::int64_t shape_[kMaxWalkDims], strides_[kMaxWalkDims];   // 힙 할당 없음
    Mag mag_;
};
```

- 마지막 축을 따라 한 줄씩(`run`) 연속으로 처리하고, 줄 끝에서만 바깥 축 인덱스를 올려요. 원소마다 다차원 인덱스를 계산하지 않아요.
- 모양과 strides를 고정 크기 배열에 둬요. 노름 하나마다(배치면 출력마다) `Walk`를 하나 만들기 때문에, 힙 할당이 있으면 짧은 노름이 많은 배치에서 할당이 시간을 차지해요.
- `Mag`는 원소 하나를 크기(`double`)로 바꾸는 람다예요. bool은 0/1, int64와 float64는 `fabs`, complex는 `std::abs`(`hypot`로 넘치지 않게 계산한 절댓값)예요. 람다 타입을 템플릿 인자로 받아 인라인돼요.
- **complex의 2-노름(과 프로베니우스 노름)은 실수부와 허수부를 따로 항으로 넣어요.** $|z|^2 = \operatorname{re}^2 + \operatorname{im}^2$이므로 절댓값을 계산할 필요가 없어요. 걷는 축 맨 안쪽에 "길이 2, stride 8바이트"인 축을 하나 더 붙여 complex 하나를 double 두 개로 걸어요. 그래서 축이 하나 늘어 최대 33축이에요. 항의 순서는 $\operatorname{re}_0^2, \operatorname{im}_0^2, \operatorname{re}_1^2, \dots$예요.

`vnorm(ord, count, fill)`이 `ord`에 따라 합, 최대, 최소, 개수를 골라요. 1-노름은 `|x|`의 pairwise 합, $p$-노름은 `|x|^p`의 pairwise 합에 이어 아래의 마무리(`finish_pnorm`)예요. 최댓값은 레인 4개로 구해요. 비교 사슬 하나면 루프가 비교의 지연에 묶이기 때문이에요. max는 정확한 연산이라 레인 순서가 결과를 바꾸지 않아요.

2-노름의 제곱합은 `vecdot`과 같은 융합 잎(`fma_dot_leaf(x, x, n)`)으로 더해요. 크기 `|x|`를 버퍼에 채운 뒤 잎을 부르는데, 논리적 C 순서로 float64가 이어진 입력은 버퍼 없이 값을 바로 읽어요(`sq_leaf_in_place`). 이 잎은 같은 패스에서 최댓값과 NaN도 구해요. $x \cdot x$와 $|x| \cdot |x|$는 정확히 같으므로 두 길의 비트가 같아요.

```cpp
// linalg/ops/vnorm.hpp (발췌)
template <class Fill>
inline double two_leaf(Fill& fill, const double* direct, std::int64_t b, std::int64_t len, NormSide& sd) {
    if (direct) return sq_leaf_in_place(direct + b, len, sd);
    double buf[kPairwiseBlock];
    fill(b, len, buf);
    max_and_nan(buf, len, sd.m, sd.nan);
    return detail::fma_dot_leaf(buf, buf, len);
}

// vnorm_serial 안
case Ord::Two: {
    NormSide sd;
    const double s = 0. + pairwise::tree(0, count, [&](std::int64_t b, std::int64_t len) {
                         return two_leaf(fill, direct, b, len, sd);
                     });
    return finish_pnorm(true, 2.0, s, sd.m, sd.nan, count, fill);
}
```

### 넘침과 언더플로: 제곱이 문제예요

2-노름의 정의를 그대로 계산하면 **결과는 표현할 수 있는데 중간값이 표현 범위를 벗어나는** 일이 생겨요. float64의 가장 큰 값은 약 $1.8 \times 10^{308}$이에요. $x = (10^{200}, 10^{200})$의 2-노름은 $\sqrt{2} \times 10^{200}$으로 충분히 표현되지만, 중간의 $x_i^2 = 10^{400}$이 넘쳐서 inf가 돼요. $|x_i| > \sqrt{1.8 \times 10^{308}} \approx 1.34 \times 10^{154}$이면 제곱이 넘쳐요.

반대쪽도 마찬가지예요. $x = (3 \times 10^{-200}, 4 \times 10^{-200})$의 2-노름은 $5 \times 10^{-200}$인데, 제곱 $9 \times 10^{-400}$은 표현할 수 있는 가장 작은 수(약 $4.9 \times 10^{-324}$)보다 작아서 0이 돼요. $|x_i| < 2^{-511} \approx 1.49 \times 10^{-154}$이면 제곱이 정규수 범위 아래(subnormal)로 내려가 유효 숫자를 잃기 시작하고, 약 $1.6 \times 10^{-162}$ 아래에서는 0이 돼요.

### 다시 스케일하기

해결책은 가장 큰 크기 $M = \max_i |x_i|$로 나눈 뒤 계산하고 다시 곱하는 거예요.

$$
\lVert x\rVert_p = M \cdot \Bigl(\sum_i \Bigl(\frac{|x_i|}{M}\Bigr)^p\Bigr)^{1/p}
$$

이 식은 노름의 동차성($\lVert \alpha x\rVert = |\alpha| \lVert x\rVert$)에서 바로 나와요. 나눈 뒤의 항은 모두 1 이하이고, 가장 큰 항이 정확히 1이에요. 그래서 합은 1 이상 $n$ 이하라 넘치지 않아요. 아주 작은 항이 0으로 언더플로해도, 그 항은 1보다 $2^{-1074}$배 이상 작으니 합에 영향을 주지 않아요. 마지막의 $M$ 곱셈은 결과가 표현 범위 안이면 넘치지 않아요.

다만 나눗셈은 항마다 반올림을 하나 더 하고, 패스를 한 번 더 돌아요. 그래서 stardust는 **필요할 때만** 다시 스케일해요.

1. 먼저 스케일 없이 한 번 계산해요. 이 패스에서 `|x|^p`의 합과 함께 최댓값 $M$과 NaN 여부를 구해요.
2. 다음 둘 중 하나일 때만 $M$으로 나눈 두 번째 패스를 돌아요.
   - 합이 inf로 넘쳤어요.
   - $M^p$가 $2^{-969}$(`kTiny`) 미만이에요.

```cpp
// linalg/ops/vnorm.hpp
inline constexpr double kTiny = 0x1p-969;    // DBL_MIN · 2^53

template <class Fill>
inline double finish_pnorm(bool two, double p, double s, double amax, bool nan, std::int64_t count, Fill& fill) {
    if (nan) return kNaN;
    if (p > 0) {
        if (amax == kInf) return kInf;
        const double top = two ? amax * amax : std::pow(amax, p);
        if (std::isinf(s) || (amax > 0 && top < kTiny)) {
            auto scaled = [&](std::int64_t b, std::int64_t len, double* out) {
                fill(b, len, out);
                for (std::int64_t k = 0; k < len; ++k) {
                    const double r = out[k] / amax;           // 모든 항이 1 이하
                    out[k] = two ? r * r : std::pow(r, p);
                }
            };
            const double t = pairwise_sum_mt<double>(count, scaled);
            return amax * (two ? std::sqrt(t) : std::pow(t, 1 / p));
        }
    }
    return two ? std::sqrt(s) : std::pow(s, 1 / p);
}
```

$2^{-969}$의 뜻은 이래요. 정규수의 가장 작은 값 `DBL_MIN`은 $2^{-1022}$이고, 그보다 작은 수(subnormal)는 유효 숫자 53비트를 다 갖지 못해요. 항들의 합에서 결과의 마지막 비트에 영향을 줄 수 있는 항은 대략 가장 큰 항의 $2^{-53}$배까지예요. 가장 큰 항 $M^p$가 $2^{-1022} \cdot 2^{53} = 2^{-969}$ 이상이면 그런 항들이 모두 정규수라서 비트를 잃지 않아요. 그보다 작으면 의미 있는 항 일부가 subnormal이 되어 정밀도를 잃으므로 다시 스케일해요. 2-노름에서는 $M < 2^{-484.5} \approx 1.4 \times 10^{-146}$일 때예요.

```python
>>> sd.linalg.vector_norm(sd.asarray([1e200, 1e200]))
1.414213562373095e+200
>>> sd.linalg.vector_norm(sd.asarray([3e-200, 4e-200]))
5e-200
```

numpy 2.5.4의 `np.linalg.vector_norm`은 이 처리를 하지 않아서 같은 입력에 inf(넘침 경고와 함께)와 0.0을 내요.

### 왜 늘 스케일하지 않나

LAPACK·BLAS 쪽에는 한 패스로 넘침을 피하는 방법이 있어요. 참조 BLAS의 `dnrm2`는 Blue의 방법 [1]을 따라 원소를 크기에 따라 세 누산기(아주 큰 것은 줄여서, 아주 작은 것은 키워서, 나머지는 그대로)에 나눠 더해요 [2]. 이렇게 하면 늘 안전하지만 원소마다 크기를 보고 누산기를 골라야 하고, 더하는 항이 정의의 제곱과 달라요.

stardust의 방법은 보통 입력(넘치지도, 아주 작지도 않은 값)에서 정의의 제곱을 `vecdot`과 같은 융합 잎과 pairwise 트리로 더하는 한 번의 패스예요. 두 번째 패스는 정의 그대로의 계산이 inf나 0을 내는 입력에서만 돌아요. numpy는 그 입력에서 inf나 0을 내요.

$p < 0$은 다시 스케일하지 않아요. 음수 거듭제곱에서는 작은 원소가 큰 항을 만들어서 위의 분석이 그대로 적용되지 않고, 이 값은 노름이 아니라 쓰임이 드물어요.

### 특수값

| 입력 | 결과 |
|---|---|
| 빈 집합 (원소 0개) | 모든 `ord`에서 0 |
| NaN이 있음 | `ord=0`은 개수(NaN도 0이 아니므로 세요), 나머지는 NaN |
| NaN 없이 inf가 있음 | $p > 0$과 `inf`는 inf |

```python
>>> sd.linalg.vector_norm(sd.asarray([1.0, float('nan'), float('inf')]))
nan
>>> sd.linalg.vector_norm(sd.asarray([0.0, float('nan'), 2.0]), ord=0)
2.0
```

빈 행렬의 노름을 0으로 두는 것은 "원소가 없으면 합은 0, 최댓값은 0(크기는 음수가 아니므로)"이라는 정의에서 나와요. `-inf`(최솟값)도 빈 집합에서는 0이에요.

### `matrix_norm`의 1과 inf

1-노름은 열마다 `|a_ij|`의 pairwise 합을 구하고, 그 최댓값(−1이면 최솟값)을 골라요. inf는 행마다 같은 것을 해요. 줄의 합 하나는 `pairwise_sum`(잎 하나면 트리를 부르지 않는 경로)이고, NaN이 나온 줄이 있으면 결과는 NaN이에요.

```cpp
// linalg/ops/norms.cpp의 matrix_norm (발췌)
const bool cols = ord == MatOrd::One || ord == MatOrd::NegOne;
const std::int64_t lines = cols ? n : m, len = cols ? m : n;
const std::int64_t line_step = cols ? cs : rs, elem_step = cols ? rs : cs;
auto line_sum = [&](std::int64_t l) {
    const std::byte* line = base + l * line_step;
    return pairwise_sum<double>(len, [&](std::int64_t b0, std::int64_t k, double* out) {
        for (std::int64_t t = 0; t < k; ++t) out[t] = magnitude(load<S>(line + (b0 + t) * elem_step));
    });
};
if (lines * len >= kSumParallelMin && lines > 1 && detail::begin_parallel()) {
    // 큰 행렬 하나: 줄들을 태스크로. 줄 하나의 합은 직렬과 같고, max/min은 순서 무관
    ...
} else {
    const parallel::Unlocked unlocked(lines * len >= kSumParallelMin);  // 나누지 않아도 크면 GIL 없이
    for (std::int64_t l = 0; l < lines; ++l) take(line_sum(l));
}
```

줄의 합은 그 줄의 원소를 줄 방향으로, 논리적 순서대로 더해요. 메모리에서 연속이든 아니든 같은 순서예요. 그래서 결과가 레이아웃과 상관없어요.

프로베니우스 노름은 행렬 전체를 2차원 `Walk`로 걸어 2-노름을 계산해요. 넘치면 다시 스케일하는 것까지 `vector_norm`과 같아요.

```python
>>> sd.linalg.matrix_norm(sd.asarray([[1.0, -2.0], [3.0, 4.0]]), ord=1)
6.0
>>> sd.linalg.matrix_norm(sd.asarray([[1e200, 1e200], [1e200, 1e200]]))
2e+200
```

## 배치와 병렬

이 함수들은 모두 배치 드라이버(`run_batch`)를 거쳐요. 비용 계열은 둘이에요([배치와 병렬화](/internals/linalg/batch/)).

| 계열 | $a$, $c$ (ns) | 함수 | $w$ |
|---|:---:|---|---|
| `kStream` | 12, 0.3 | `vecdot`, `trace`, `vector_norm`, `matrix_norm`(fro, ±1, ±inf), `bandwidth` | 출력 하나에 더하는 원소 수 (`bandwidth`는 행렬 원소 수) |
| `kCopy` | 2, 0.5 | `diagonal`, `outer`, `kron`, `kronsum`, `block_diag`, `cross` | 출력 하나가 쓰는 원소 수 (`cross`는 6) |
| `kLU` | 70, 3 | `matrix_power` | $m^2$ |

원소 하나의 일이 아주 작아서, 배치가 커야 나눠요. 예를 들어 (1000, 3, 3)의 `diagonal`은 원소 하나가 3.5ns로 추정되어 배치 전체가 3.5µs라 직렬로 돌아요. `vecdot`의 행(3000개, 원소 하나 12.9ns)은 태스크 8개로 나눠요.

배치를 나누는 것과 별개로, **출력 하나의 합이 2¹⁵항 이상**이면 그 합을 pairwise 트리의 잎 단위로 나눠요(`vecdot`, `trace`, `vector_norm`의 모든 `ord`, 프로베니우스 노름). 노름은 합과 함께 최댓값, NaN, 0이 아닌 개수를 잎마다 **자기 칸**에 기록하고 마지막에 합쳐요. 공유 변수 하나에 여러 스레드가 쓰면 경쟁이 생기기 때문이에요. 최댓값·개수는 순서와 상관없고 합은 같은 트리 순서로 합치므로(`pairwise_tree_mt`, 곱의 합도 같은 계획), 결과가 직렬과 비트까지 같아요. 다시 스케일하는 두 번째 패스도 같은 방식으로 나눠요.

## 성능

시간을 좌우하는 것은 이래요.

- **작은 호출은 고정비가 정해요.** 3×3의 `trace`, `diagonal`은 계산이 몇 ns라서 인자 해석과 결과 배열을 만드는 비용이 시간의 대부분이에요. stardust는 Python 래퍼 없이 C++에서 바로 바인딩되고 배열을 직접 읽어요([선형대수 영역의 구조](/internals/linalg/overview/)).
- **짧은 합이 많은 배치**(`(1000, 3, 3)`의 `matrix_norm`, `vecdot`의 행)는 합 하나마다 `Walk`나 `fill`을 준비하는 고정비가 붙어요. numpy는 이런 경우 배열 전체를 한 번에 처리하는 ufunc(`x*x` 뒤 `sum(axis=...)`)를 쓰므로 원소당 비용이 작을 수 있어요.
- **`diagonal` (1000, 3, 3)**은 numpy가 뷰에 `.copy()` 한 번을 하는 것과 달리 배치 드라이버를 거쳐서, 그만큼 고정비가 더 붙어요.
- **`matrix_power`의 큰 행렬**은 입력을 작업 버퍼에 패킹한 뒤 `gemm`에 넘겨요. numpy는 입력을 그대로 `gemm`에 넘기므로 패킹만큼의 차이가 있어요. 열 우선 입력을 패킹 없이 넘기면 이 차이가 없어지지만(결과는 같아요), 지금 구현은 그렇게 하지 않아요.
- **긴 합의 1스레드**는 잎 버퍼에 항을 채우고 다시 읽는 두 단계라서 numpy보다 느릴 수 있어요. 10스레드에서는 트리의 잎을 나눠 돌아요.

함수별 복잡도는 이래요.

| 함수 | flop | 메모리 |
|---|---|---|
| `vecdot` | $2n$ | 입력 $2n$ 읽기 |
| `outer` | $mn$ | 출력 $mn$ 쓰기 |
| `kron` | $mnpq$ | 출력 $mnpq$ 쓰기 |
| `kronsum` | $mn$ (주대각의 덧셈) | 출력 $(mn)^2$ 쓰기 |
| `block_diag` | 0 | 출력 $(\sum M_i)(\sum N_i)$ 쓰기 |
| `bandwidth` | 0 | 많아야 $mn$ 읽기 (꽉 찬 행렬은 $O(m + n)$) |
| `cross` | 9 (곱 6, 뺄셈 3) | 6 읽기, 3 쓰기 |
| `trace`, `diagonal` | $\min(m, n)$ | 대각선 읽기 |
| `matrix_power` | $(\lfloor \log_2 e\rfloor + \operatorname{popcount}(e) - 1)\cdot 2m^3$ | 작업 버퍼 $3m^2$ |
| `vector_norm`, `matrix_norm` fro | $2n$ (넘치면 원소마다 나눗셈을 포함한 한 패스 더) | 입력 1회(넘치면 2회) |
| `matrix_norm` ±1, ±inf | $mn$ | 입력 1회 |

## 정확도

### numpy·scipy와의 비트 관계

numpy 2.5.4(numpy에 없는 것은 scipy 1.18.1)와 비교한 지금의 관계예요. "같음"은 결과 바이트가 같다는 뜻이고, 약속은 아니에요. 약속하는 것은 레이아웃·배치 위치·스레드 수와 상관없는 같은 비트, 아래에 적은 우리 함수끼리의 관계(`trace(x) == sum(diagonal(x))` 등), 그리고 오차 한계예요.

| 함수 | numpy와 | 이유 |
|---|---|---|
| `outer` | `x[..., :, None] * y[..., None, :]`와 같음 | 같은 FMA 곱 (배열의 곱과도 같음) |
| `kron` | `np.kron`(1·2차원)과 같음 | 같은 FMA 곱, 왼쪽 인자가 왼쪽 |
| `kronsum` | numpy에 없음. `kron(I, A) + kron(B, I)`와는 inf·NaN이 있으면 다름 | 단위 행렬과 곱하지 않음 |
| `block_diag` | `scipy.linalg.block_diag`와 같음 | 복사 |
| `bandwidth` | `scipy.linalg.bandwidth`와 같은 값 | 정수 결과 |
| `cross` | `np.cross`와 같음 | 곱마다 반올림한 뒤 빼기 |
| `vecdot` | 끝 비트가 다를 수 있음 | 곱을 잎 안에서 합에 융합(FMA). `sd.sum(conj(x) * y)`와도 끝 비트가 다를 수 있음. `np.vecdot`은 BLAS 내적 |
| `trace` | `sd.sum(diagonal(x), axis=-1)`과 같음, numpy와는 끝 비트가 다를 수 있음 | 대각선을 배열의 잎과 트리로 더함 |
| `vector_norm` (1, $p$) | 넘치지 않으면 `sd.sum`의 값과 같음 | 같은 항, 배열의 잎과 트리 |
| `vector_norm` (2) | 끝 비트가 다를 수 있음 | 제곱을 잎에 융합(FMA) |
| `matrix_norm` fro | 끝 비트가 다를 수 있음 | 제곱을 잎에 융합, 논리적 C 순서 |
| `matrix_norm` ±inf | 줄마다 `sd.sum`과 같음 | 행을 논리적 순서의 pairwise로 |
| `matrix_norm` ±1 | 줄마다 `sd.sum`과 같음 | 열을 논리적 순서의 pairwise로 |
| `matrix_power` | $e = 0$–4에서 같음, 5 이상과 음수는 다를 수 있음 | 이진 거듭제곱의 방향이 반대. 음수 지수는 역행렬이 `inv`의 값이라 numpy의 역행렬과 다를 수 있어요 |

`matrix_norm`의 ±1, ±inf는 설명이 필요해요. numpy는 열 합을 `sum(abs(x), axis=-2)`로 구해요. C 순서 행렬에서 축 −2는 메모리상 바깥 축이라, numpy는 행을 위에서부터 차례로 더해요(행을 행에 더하는 리덕션). F 순서에서는 열이 연속이라 pairwise로 더해요. **numpy의 결과가 레이아웃에 따라 바뀌는 것이고, stardust는 레이아웃과 상관없이 같은 값이에요.** stardust는 줄마다 논리적 순서의 pairwise 합이라, 그 줄을 연속 벡터로 꺼내 `sd.sum`으로 더한 값과 비트까지 같아요. 테스트가 이 관계를 C·F 순서 모두에서 고정해요. numpy와의 차이는 반올림 수준이에요(pairwise 쪽의 오차 한계가 더 작아요).

fro는 원소를 논리적 C 순서로 걸어 제곱을 융합 잎으로 더해요. 그래서 C·F 순서에서 같은 값이고, numpy와 `sqrt(sum(x * x))`와는 끝 비트가 다를 수 있어요.

complex의 2-노름은 실수부와 허수부를 따로 항으로 넣어요(`re0², im0², re1², …`). 1-노름과 inf-노름의 complex 크기는 `std::abs`라서 `np.abs`와 마지막 비트가 다를 수 있어요. 합과는 무관한 차이예요.

### 오차 한계

- **곱(`outer`, `kron`):** 실수는 반올림 한 번이라 상대오차 $u = 2^{-53}$ 이하예요. complex 곱은 FMA 덕분에 성분마다 반올림이 두 번이에요.
- **`kronsum`:** 주대각의 원소만 덧셈 한 번이라 올바르게 반올림한 값이에요(상대오차 $u$ 이하). 나머지 원소는 입력의 값 그대로예요.
- **`block_diag`, `bandwidth`:** 계산이 없어서 오차가 없어요.
- **합(`vecdot`, `trace`, 노름):** pairwise 트리라서 $|\hat s - s| \le \gamma_h \sum |x_i|$, $h \lesssim 49 + \lceil \log_2(n/512)\rceil$이에요 [7]. 원소 100만 개면 $h \le 60$ 정도예요. 내적은 곱을 합에 융합해서 대부분의 항에 곱의 반올림이 따로 없어요(레인의 첫 항만 곱을 반올림해요). 한계는 $\gamma_{h+1} \sum |x_i y_i|$ 이하예요. 이 한계는 $\sum |x_i y_i|$를 기준으로 한 것이라서, 결과가 소거로 작아지면 상대오차는 커질 수 있어요.
- **노름:** 2-노름은 제곱의 합이라 모든 항이 음이 아니고, 소거가 없어요. 그래서 상대오차가 작아요. 제곱의 반올림과 합의 $\gamma_h$, 제곱근이 오차를 절반으로 줄이는 것과 제곱근 자체의 반올림을 합치면 대략 $(h/2 + 2)u$ 이하예요. 다시 스케일할 때는 나눗셈 하나의 반올림이 더해져요.
- **`cross`:** 성분 하나가 곱 두 개의 차라서 소거가 생길 수 있어요(위의 주의).
- **`matrix_power`:** `gemm`의 오차가 곱마다 쌓여요. 곱은 $O(\log e)$번이지만 $\lVert A\rVert > 1$이면 값이 지수적으로 커지므로 절대오차도 함께 커져요. 넘치면 inf가 되고, 경고는 내지 않아요.
