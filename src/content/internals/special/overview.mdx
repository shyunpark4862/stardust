## 한눈에 보기

`sd.special`은 scipy.special의 함수 89개를 다시 만든 영역이에요. 오차함수, 감마와 베타, 불완전 감마·베타와 그 역함수, 로지스틱 함수, 제타와 지수적분, Bessel 함수와 Airy 함수, 타원적분, 초기하 함수, Lambert W, 복소수 Faddeeva 함수, t·카이제곱·F·포아송·이항 분포와 비중심 분포의 누적 확률과 분위수가 들어 있어요. 코드는 C++ 코어 `csrc/special/`에 있고, Python 쪽 `src/stardust/special/__init__.py`는 이름을 다시 내보내기만 해요.

이 영역의 뼈대는 다섯 가지예요.

1. **엔진은 배열 영역의 것을 그대로 써요.** 86개는 원소별 함수예요. 브로드캐스팅, `out=`, dtype 변환, 스레드 분할을 배열 영역의 원소별 엔진이 맡고, 특수함수 쪽은 "원소 하나를 어떻게 계산하는가"만 적어요. 엔진에 더한 것은 입력이 넷까지인 n항 디스패처, 함수마다 다른 원소당 비용, 그리고 NEON과 vForce를 섞는 청크 커널이에요([원소별 엔진과 병렬화](/internals/special/engine/)).
2. **함수마다 알고리즘이 정해져 있고, 구간은 원소의 값으로만 골라요.** 급수를 쓸지, 연분수를 쓸지, 점근전개를 쓸지는 그 원소의 인자 값이 정해요. 배열의 크기, 위치, 스레드 수는 경로를 바꾸지 않아요. 그래서 `f(x)[i]`는 언제나 `f(x[i])`와 비트까지 같아요.
3. **정확도는 계약으로 약속해요.** 함수마다 정한 보장 영역 안에서 mpmath로 50자리까지 계산한 참값과의 상대오차가 $10^{-14}$ 이하예요. 테스트는 이 계약을 저장해 둔 참값 파일의 모든 점에서 확인해요.
4. **특수값은 scipy를 따르되, scipy가 틀린 값을 내는 곳은 참값을 내요.** 서브노멀 꼬리를 0으로 버리는 곳, 정수가 아닌 차수를 잘라 쓰는 곳, 복소수가 참값인데 inf를 내는 곳 등이에요.
5. **외부 코드는 검증된 곳에만 써요.** 유리 근사의 계수는 Cephes와 논문에서 원본의 십진 표기 그대로 가져오고, Boost.Math는 "바꿔도 정확도와 속도에서 손해가 없는" 구간에서만 직접 불러요. 나머지는 이 저장소의 코드예요.

| 분포 함수 | `stdtr`, `stdtrit`, `chdtr`, `chdtrc`, `chdtri`, `fdtr`, `fdtrc`, `fdtri`, `pdtr`, `pdtrc`, `bdtr`, `bdtrc`, `nbdtr`, `nbdtrc`, `ndtri_exp` | `distr.hpp` |
| 비중심 분포 | `chndtr`, `chndtrc`, `chndtrix`, `nctdtr`, `nctdtrc`, `nctdtrit`, `ncfdtr`, `ncfdtrc`, `ncfdtri` | `noncentral.hpp` |

모든 함수가 지키는 겉의 규칙은 [특수함수의 기본](/api/special/basics/)에 있어요. 줄이면 이래요.

- **원소별 함수예요.** 리덕션 셋(`logsumexp`, `softmax`, `log_softmax`)과 결과가 넷인 `airy`를 빼면, 모두 입력을 브로드캐스트해서 원소마다 따로 계산해요.
- **float64로 계산해요.** bool과 int64 입력은 float64로 바꿔 계산하고, 결과는 float64예요. complex128 입력은 `TypeError`예요(복소수를 받는 여섯 함수는 예외). 정수 차수 인자(`expn`의 `n`, `polygamma`의 `n`)도 float64로 받아서, 정수가 아니거나 음수이면 그 원소만 NaN이에요.
- **입력은 위치 전용, `out=`은 키워드 전용이에요.** 출력이 넷인 `airy`에는 `out=`이 없고, 결과는 이름 있는 튜플 `AiryResult(ai, aip, bi, bip)`예요.
- **값 때문에 실패하지 않아요.** 정의역 밖은 NaN, 극점은 ±inf예요. 에러도 경고도 내지 않아요(scipy의 `errstate`, `SpecialFunctionWarning`에 해당하는 것이 없어요).
- **함수 하나에 이름 하나예요.** scipy의 별칭 `psi`(= `digamma`), `jn`(= `jv`)은 없어요. sd에 이미 있는 `expm1`, `log1p`, `exp2`, `cbrt` 등은 여기에 다시 두지 않아요.

- **의존은 한 방향이에요.** `special/`은 `array/`를 쓰지만 `array/`는 `special/`을 몰라요. 배열 영역에 더한 n항 디스패처(`nary_loop`, `run_nary`)도 특수함수를 위한 이름이나 분기를 갖지 않는 일반 장치예요. 원소 함수 하나를 템플릿 인자로 받을 뿐이에요.
- **함수는 헤더에 있어요.** `ops/*.hpp`의 Op 구조체는 모두 `inline` 함수예요. 바인딩 파일 하나(`bind/special_bind.cpp`)가 이 헤더들을 포함하고, `nary_loop<Op, double>`을 함수마다 한 번씩 인스턴스화해요. 그래서 원소 함수 `Op::f`가 루프 안으로 인라인되고, 원소마다 함수 포인터를 거치지 않아요. 컴파일 단위로 따로 떨어진 것은 배열의 리덕션 드라이버를 부르는 `reduce.cpp`뿐이에요.
- **Python 코드를 거치지 않아요.** `sd.special.erf`는 nanobind로 등록한 C++ 함수 그 자체예요. 원소 하나짜리 호출에서는 계산보다 호출 경로가 더 오래 걸리기 때문이에요. `erf`의 스칼라 호출 한 번이 ⟦SPEED erf scalar⟧µs예요.
- **컴파일 옵션이 결과의 일부예요.** 모든 코드는 `-ffp-contract=off`로 빌드돼요. 컴파일러가 `a + b*c`를 FMA 하나로 합치지 못하게 막아서, 반올림이 일어나는 자리가 소스 코드에 적힌 대로예요. FMA가 필요한 곳은 `std::fma`로 적어요. 같은 파일에 포함되는 Boost.Math 헤더도 같은 옵션으로 컴파일돼요.

함수 하나는 이런 모양이에요. 두 입력을 받는 `xlogy`예요.

```cpp
// special/ops/logistic.hpp (발췌)
struct Xlogy : Real {                                     // Real: float64 루프만 있음
    static constexpr const char* name = "xlogy";
    static constexpr int nin = 2, nout = 1;               // 입력 둘, 출력 하나
    static constexpr std::array<const char*, 2> args{"x", "y"};   // 에러 메시지의 인자 이름
    static constexpr double cost_ns = cost::kXlogy;       // 원소당 비용 (special/cost.hpp의 상수)
    static double f(double x, double y) {                 // 원소 하나: 순수 함수
        if (x == 0.0 && !std::isnan(y)) return 0.0;       // scipy의 규약: x = 0이면 0
        return x * std::log(y);
    }
};
```

이 구조체 하나가 함수 하나의 전부예요. 바인딩은 `def_naries<Expit, Logit, LogExpit, Xlogy, ...>(m)` 한 줄로 이름과 인자 수와 `out=`을 만들어요. 구조체의 각 필드가 무엇에 쓰이는지, 그리고 `f` 대신 `chunk`를 갖는 NEON 함수는 [원소별 엔진과 병렬화](/internals/special/engine/)에서 다뤄요.

## 공통 원칙

### 함수마다 알고리즘 하나, 구간은 원소의 값으로

특수함수는 정의역 전체에서 잘 맞는 식 하나가 거의 없어요. 예를 들어 오차함수 $\operatorname{erfc}(x)$는 0 근처에서는 거듭제곱급수가 빠르게 수렴하지만, $x$가 커지면 급수의 항이 크게 자랐다가 상쇄돼서 쓸 수 없어요. 큰 $x$에서는 대신 $e^{-x^2}$을 꺼낸 나머지를 유리식으로 근사해요. 그래서 정의역을 **구간**으로 나누고 구간마다 다른 방법을 써요.

stardust는 이 구간을 **그 원소의 인자 값으로만** 골라요. 이것은 함수의 정의의 일부예요. C 라이브러리의 `exp`도 인자의 크기를 보고 내부 경로를 고르는데, 같은 인자에는 언제나 같은 경로라서 결과가 정해져 있는 것과 같아요. 반대로 다음은 경로를 바꾸지 않아요.

- 배열의 크기 (원소가 많으면 빠른 근사를 쓰는 식의 선택 없음)
- 원소의 위치와 메모리 정렬, stride, 레이아웃
- 스레드 수와 스레드가 배열을 자른 방식

그래서 `f(x)[i] == f(x[i])`가 비트까지 성립하고, 결과는 스레드 수와 무관해요. 테스트는 연속, 스칼라 브로드캐스트, strided, 제자리(`out=x`) 레이아웃과 1·3·10스레드를 비트로 비교해요.

```python
>>> x = sd.asarray([0.25, 1.5, 3.0, 9.0])
>>> sd.special.erfc(x)
array([    0.7236736098317631,    0.03389485352468927,
       2.2090496998585445e-05,  4.137031746513809e-37], dtype=float64)
>>> sd.special.erfc(1.5) == sd.special.erfc(x)[1]
True
```

### 구간은 적게

구간 경계는 비용이에요. 경계마다 양쪽 방법이 모두 정확해야 하고, 경계 바로 앞뒤의 값이 이어져야 하고, 테스트할 점이 늘어요. 그래서 **근사 방식이 바뀌는 갈래를 함수마다 두세 개로** 잡고 출발해요. 세는 방법은 이래요.

- **세는 것**: 근사 방식이 바뀌는 갈래. 거듭제곱급수에서 연분수로, 연분수에서 점근전개로, 또는 다른 계수 표로 넘어가는 경계예요.
- **세지 않는 것**: 정의역을 옮기는 정확한 변환. 반사 공식 $\Gamma(x)\Gamma(1-x) = \pi/\sin \pi x$, 점화식 $\Gamma(x+1) = x\Gamma(x)$, 대칭 $I_x(a,b) = 1 - I_{1-x}(b,a)$, Kummer·Pfaff 변환, 초기하 함수의 선형 변환이에요. 이것들은 새 근사를 들이지 않고 이미 있는 구간으로 문제를 옮기기만 해요.
- **퇴화 경우는 극한 공식 하나로**: 일반 공식이 $0/0$이 되는 매개변수(예: `hyp2f1`에서 $c-a-b$가 정수)는 정수 거리마다 따로 짜지 않고, 디감마가 들어간 극한 공식 하나로 처리해요.

이 한도를 넘는 함수도 있어요. 측정에서 두세 갈래로는 계약을 지킬 수 없다는 것이 드러난 곳이에요. 불완전 베타(`betainc`)는 DiDonato와 Morris의 BRATIO 구조를 따라 다섯 방법(급수, 유한합 이동, BGRAT, 연분수, 균등 점근전개)을 쓰고 [1], 실수 차수 Bessel 함수는 네 구간(급수, Temme와 Steed, 위로 가는 점화식, Hankel 점근)을 써요. 이유는 각 함수의 글에 있어요. 반대로 Boost와 Cephes가 극단 영역마다 둔 특수 분기, 상수 미세 조정, 매개변수 범위마다의 fast path는 가져오지 않아요.

### 후보를 고르는 순서

한 함수에 쓸 수 있는 방법이 여럿이면 이 순서로 견줘요.

1. 보장 영역에서 정확도 계약을 지키는가
2. 구간이 적은가
3. 빠른가 (1스레드, 원소 $10^6$개)

정확도가 먼저예요. 예를 들어 `wofz`(Faddeeva 함수)는 scipy가 쓰는 Faddeeva Package의 방법 대신 0.1 간격 격자점 둘레의 Taylor 급수를 골랐어요. 같은 참값 파일에서 scipy 1.18.1의 `wofz`는 최대 255 ULP, stardust는 2.01 ULP예요. 정확도가 같으면 속도로 정해요. 완전 타원적분 `ellipk`, `ellipe`는 산술-기하 평균(AGM)과 Carlson 대칭형으로도 계산할 수 있지만, Cephes 다항식 $P(y) - \log(y)\,Q(y)$($y = 1-m$)가 정확도는 같은 수준이고 1스레드 원소 $10^6$개에서 AGM·Carlson 판보다 4–7배 빨라서 공개 함수는 Cephes 쪽이에요. 두 비교용 함수는 비공개 `_ellipk_agm`, `_ellipe_carlson`으로 남아 있어요.

## 정확도 계약

### ULP와 상대오차

부동소수점 수는 띄엄띄엄 있어요. float64는 $[1, 2)$ 사이에 $2^{52}$개의 수가 같은 간격 $2^{-52} \approx 2.2 \times 10^{-16}$으로 있고, $[2, 4)$에서는 간격이 두 배예요. **ULP**(unit in the last place)는 그 자리의 간격 하나예요 [2]. 계산값 $\hat y$와 참값 $y$의 차이를 $y$ 자리의 간격으로 나누면 "몇 ULP 틀렸나"가 돼요.

$$
\text{ULP 오차} = \frac{\lvert \hat y - y \rvert}{\operatorname{ulp}(y)}, \qquad \text{상대오차} = \frac{\lvert \hat y - y \rvert}{\lvert y \rvert}
$$

가장 잘 반올림한 결과도 0.5 ULP까지는 틀려요. 참값이 두 float 사이에 있기 때문이에요. 두 척도의 관계는 $y$가 간격 구간의 어디에 있느냐에 따라 달라요. $y$가 $[2^e, 2^{e+1})$에 있으면 $\operatorname{ulp}(y) = 2^{e-52}$이므로, 1 ULP는 상대오차 $2^{-53}$(구간 끝)에서 $2^{-52}$(구간 시작) 사이예요.

stardust의 계약은 **상대오차 $10^{-14}$**예요. ULP로 바꾸면 $10^{-14} / 2^{-52} \approx 45$에서 $10^{-14}/2^{-53} \approx 90$ ULP 사이예요. 그래서 측정표에서 최대 ULP가 45를 넘는 줄도 계약 안일 수 있어요. 예를 들어 `beta`는 최대 52.8 ULP, `hyp1f1`의 보장 영역은 78.6 ULP인데 상대오차로는 둘 다 $10^{-14}$ 안이에요. 실제 목표는 이보다 훨씬 작아서, 보장 영역 96줄 가운데 65줄이 최대 10 ULP 아래예요.

### 무엇과 비교하나

참값은 mpmath [3]로 유효숫자 50자리까지 계산하고, float64 두 개의 합 $\text{hi} + \text{lo}$로 저장해요(`tests/special/ref/*.npz`). float64 하나로 저장하면 참값 자체가 0.5 ULP 틀리므로, 1 ULP 안팎의 오차를 잴 수 없어요. 합으로 저장하면 약 106비트라 ULP의 작은 분수까지 잴 수 있어요. 오차는 $\lvert (\hat y - \text{hi}) - \text{lo} \rvert / \operatorname{ulp}(\text{hi})$로 계산해요(`tests/special/refdata.py`).

scipy는 정답지가 아니에요. scipy와의 차이는 허용치가 아니라 보고 대상이에요. scipy도 같은 참값으로 재서 나란히 적어요. scipy가 틀리는 곳이 적지 않아서예요. 예를 들어 `erfc`는 scipy 1.18.1이 $x \approx 26.7$부터 0을 내는 꼬리(참값은 서브노멀)에서 $2.3 \times 10^{13}$ ULP까지 벌어지고, stardust의 `erfc`는 같은 참값 파일 전체에서 최대 7.77 ULP예요.

### 보장 영역과 느슨한 영역

- **보장 영역**: 함수마다 [API 문서](/api/special/basics/)에 적힌 입력 범위예요. 여기서 상대오차 $10^{-14}$ 이하예요. 오차함수 계열, 로지스틱, 0·1차 변형 Bessel처럼 정의역 전체가 보장 영역인 함수가 많아요.
- **느슨한 영역**: 정의역 안이지만 보장 영역 밖이에요. 값을 계산하고, 잰 최대 오차를 문서에 적어요. 예를 들어 `hyp1f1`, `hyp2f1`은 모든 항이 양수인 형태가 있는 곳만 보장하고, 그 밖은 측정한 한계 $10^{-12}$를 적어요. NaN은 수학적 정의역 밖에서만 나와요.
- **서브노멀 결과**: 결과가 $2^{-1022}$보다 작으면 상대오차 대신 절대오차 $45 \times 2^{-1074}$를 봐요. 서브노멀은 유효 비트가 줄어든 수라서 상대오차가 의미를 잃기 때문이에요. 정상 범위의 바닥에서 상대오차 $10^{-14}$와 같은 크기예요.
- **오버플로·언더플로**: 참값이 float64 범위를 넘으면 ±inf, 서브노멀보다 작으면 0이에요.

### 값이 0을 지나는 함수: 혼합 한계와 포락선

상대오차는 참값이 0에 가까우면 의미를 잃어요. 참값이 정확히 0이면 정의되지 않고, 0 바로 옆이면 아주 작은 절대오차도 큰 상대오차가 돼요. 그래서 0을 지나는 함수에는 다른 기준을 써요.

**혼합 한계.** `gammaln`, `digamma`, `polygamma`, `beta`, `betaln`, `binom`, Hurwitz `zeta`의 보장 영역 밖과 리덕션 `logsumexp`, `log_softmax`는

$$
\lvert \hat y - y \rvert \le 10^{-14} \cdot \max(1, \lvert y \rvert)
$$

이에요. 값이 크면 상대오차, 0 근처에서는 절대오차예요. 예를 들어 $\log \Gamma(x)$는 $x = 1, 2$에서 0이에요.

**포락선(진동 함수).** Bessel 함수 $J_0(x)$는 끝없이 진동하면서 0을 지나요. 영점에서 계산값이 참값과 $10^{-17}$만 달라도 상대오차는 무한대예요. 그래서 `j0 j1 y0 y1 jv yv jve yve`와 $x < 0$의 `airy`는 오차를 진폭과 비교해요.

$$
\lvert \hat y - y \rvert \le 10^{-14} \cdot M(x), \qquad M(x) = \sqrt{J_\nu(x)^2 + Y_\nu(x)^2} \approx \sqrt{\tfrac{2}{\pi x}}
$$

$M(x)$는 진동의 **포락선**이에요. $J_\nu$와 $Y_\nu$는 위상이 90도 어긋난 짝이라 둘의 제곱합은 진동하지 않고 매끈하게 줄어요. 첫 영점의 0.99배까지는 상대오차 $10^{-14}$를 그대로 보장하고, 그 뒤부터 포락선 기준이에요.

영점 근처의 상대 정확도를 얻는 방법도 있어요. Cephes는 $J_0$의 첫 영점들 $r_k$를 인수 $(x^2 - r_k^2)$로 빼 두고 나머지를 근사해요. stardust는 이 방법을 모든 영점에 확장하지 않아요. 영점은 무한히 많고, 포락선 기준이면 Hankel 점근 하나로 모든 큰 $x$를 덮을 수 있기 때문이에요.

**역함수.** `gammaincinv`, `betaincinv`, `stdtrit` 같은 역함수는 출력 $x$의 상대오차를

$$
\left\lvert \frac{\Delta x}{x} \right\rvert \le 10^{-14} \cdot \max(1, \kappa), \qquad \kappa = \left\lvert \frac{F(x)}{x\,F'(x)} \right\rvert
$$

로 봐요. $\kappa$는 확률 $p$의 상대 변화가 $x$의 상대 변화로 몇 배 커지는지를 나타내는 **조건수**예요. 입력 $p$ 자체가 float64라서 이미 0.5 ULP의 불확실성을 갖고, 그 불확실성이 $x$에서 $\kappa$배로 커지는 것은 어떤 알고리즘도 피할 수 없어요. 예를 들어 불완전 감마에서 $a$가 작으면 $x \approx (p\,\Gamma(a+1))^{1/a}$라서 $p$의 1 ULP가 $x$를 $1/a$ ULP 움직여요. 이 기준은 "입력의 마지막 비트가 허락하는 만큼 정확하다"는 뜻이에요.

**복소수.** 복소 결과의 상대오차는 $\lvert \hat w - w \rvert / \lvert w \rvert$로, 실수부와 허수부를 따로 보지 않고 크기로 재요. `wofz`의 아래쪽 반평면처럼 영점이 있는 곳은 계산식의 두 항 크기를 포락선으로 써요.

## 특수값과 scipy와 다른 곳

특수값(±0, ±inf, NaN, 극점, 정의역 끝)은 **scipy 1.18.1을 따르는 것이 기본**이에요. `gamma(0.0)`은 `inf`, `gamma(-0.0)`은 `-inf`, `gamma(-1.0)`은 NaN, `rgamma(-1.0)`은 0, `logit(0.0)`은 `-inf`예요. 이 값들은 scipy와 비트까지 같아요.

scipy와 다르게 하는 곳은 정해진 목록이에요. 큰 줄기는 "scipy가 참값과 다른 값을 내는 곳은 참값이나 극한을 낸다"예요.

| 유형 | 예 (stardust / scipy 1.18.1) | 이유 |
|---|---|---|
| 서브노멀 꼬리를 0으로 버림 | `erfc(27.0)`: 5.24e-319 / 0.0, `expit(-720.0)`: 2.03e-313 / 0.0 | 서브노멀도 값이에요. 앞 인자를 지수와 가수로 나눠 계산해 끝까지 들고 가요 |
| 인자가 언더플로해서 inf | `erfcinv(5e-324)`: 27.21 / inf, `k0(5e-324)`: 744.56 / inf, `gammaln(5e-324)`: 744.44 / inf | $z/2$나 $x/2$를 만들지 않고 계산해요 |
| 넘치기 전에 inf | `i0(713.5)`: 1.105e308 / inf | $e^x$를 가수와 지수로 나눠 곱해요 |
| 정수가 아닌 차수를 잘라 씀 | `expn(1.5, 1.0)`: NaN / 0.2194 (= $E_1(1)$) | 정수 차수 인자는 정수가 아니면 NaN이에요 |
| 참값이 복소수인데 inf | `hyp2f1(0.5, 0.5, 1.5, 2.0)`: NaN / inf | 실수 함수는 실수 값이 없으면 NaN이에요 |
| 정의는 있는데 NaN | `binom(-5, 2)`: 15.0 / NaN | 정수 $k \ge 0$이면 $n(n-1)\cdots(n-k+1)/k!$이 모든 실수 $n$에서 정의돼요 |
| 0의 부호 | `erfinv(-0.0)`: −0.0 / 0.0 | 홀함수는 $-0$에서 $-0$이에요 |
| 무한대 인자 | `j0(inf)`: 0 / NaN | 극한값이 있으면 극한을 내요 |

그 밖에 겉모양이 다른 곳이 있어요. 배열 인자는 `sd.ndarray`만 받고, `out=`은 키워드 전용이고, `airy`의 결과는 튜플 대신 `AiryResult`예요. `lambertw`는 실수 입력이면 float64를 돌려주고(scipy는 언제나 complex) `tol=` 인자가 없어요. 결과의 정확도는 함수가 정하는 것이지 호출하는 쪽이 고르는 것이 아니기 때문이에요. 비중심 카이제곱 `chndtr(df, nc, x)`는 다른 분포 함수처럼 `x`가 맨 뒤이고, 비중심 분포에는 scipy에 없는 위꼬리 함수(`chndtrc`, `nctdtrc`, `ncfdtrc`)가 있어요. 위꼬리를 `1 - chndtr`로 만들면 작은 꼬리 확률이 상쇄로 사라지기 때문이에요.

```python
>>> sd.special.erfc(sd.asarray([26.0, 27.0, 28.0]))
array([5.663192408856145e-296,           5.23705e-319,
                          0.0], dtype=float64)
>>> sd.special.expn(1.5, 1.0)
nan
>>> sd.special.binom(-5.0, 2.0)
15.0
```

## 외부 코드와 계수

### 계수를 직접 만들지 않아요

특수함수의 구간 근사는 대부분 **유리 근사** $R(x) = P(x)/Q(x)$예요. 다항식 $P$, $Q$의 계수는 구간 위의 최대 상대오차를 가장 작게 만들도록(minimax) Remez 알고리즘으로 맞춘 값이에요. 이런 계수를 새로 만들려면 고정밀 산술로 수십 번 반복하고, 경계와 반올림 효과까지 검증해야 해요. stardust는 계수를 직접 만들지 않고, **출처가 분명한 공개 계수를 원본의 십진 표기 그대로** 옮겨요. 각 계수 파일의 머리에 출처, 판, 라이선스, 원 논문이 적혀 있어요. minimax와 Remez 교대 정리 자체는 [공통 수치 기법](/internals/special/techniques/)에서 설명해요.

예외는 맞춘(fitted) 값이 아니라 **수학적으로 정해진 급수의 계수**예요. Taylor 계수, 점근전개의 계수, 격자점의 함숫값은 정의에서 mpmath로 직접 계산해 반올림한 것이라, 생성 스크립트(`tools/gen_*.py`)와 함께 저장소에 있어요.

### Boost.Math를 부르는 구간

Boost.Math [6]는 C++ 특수함수 라이브러리예요. stardust는 계수만이 아니라 Boost의 함수를 **직접 불러요**. 다만 구간마다 다음 두 조건을 모두 지킬 때만이에요.

1. 그 구간의 참값 파일 **모든 점**에서 Boost의 결과가 정확도 계약($10^{-14}$, 특수값은 stardust 규칙)을 지킨다.
2. 1스레드에서 이 저장소의 코드보다 느리지 않다(10% 안은 같은 것으로 봐요).

더 정확해도 느리면 바꾸지 않아요. 일부 점만 틀리면 구간을 잘게 나눠 지키는 쪽만 바꿔요. 헤더는 쓰는 것만 `third_party/boost_math/`에 옮겨 두었어요(boostorg/math 커밋 `4682f44`, 헤더 125개, 2.7MB, Boost Software License 1.0). `BOOST_MATH_STANDALONE`으로 빌드해서 다른 Boost 라이브러리는 필요 없어요.

Boost를 부르는 모양은 함수마다 같아요.

```cpp
// Gamma::f (special/ops/gamma.hpp, 줄인 발췌)
static double f(double x) {
    if (std::isnan(x)) return x;                         // 1. 특수값은 stardust가 먼저 정해요
    if (x == kInf) return x;
    if (x == 0.0) return std::copysign(kInf, x);         //    gamma(±0) = ±inf
    if (x > 171.62437695630272) return kInf;
    if (x > -170.0 && (x > 0.0 || !is_nonpos_int(x))) {  // 2. Boost 구간이면 Boost
        const double r = bst::tgamma(x);
        if (bst::normal(r)) return r;                    // 3. 정상 범위의 결과만 받아요
    }
    if (x > 0.0) return gamma_cephes_pos(x);             // 4. 나머지는 이 저장소의 코드
    if (is_nonpos_int(x)) return kNaN;
    return gamma_neg_direct(x);                          //    서브노멀 꼬리까지
}
```

- **특수값은 Boost를 부르기 전에** 정해요. Boost의 특수값 규약은 scipy·stardust와 다른 곳이 있어서예요.
- **Boost의 결과가 정상 범위가 아니면**(서브노멀, 0, inf, NaN) 버리고 이 저장소의 코드로 다시 계산해요. Boost가 측정에서 정확했던 범위는 정상 범위이고, 서브노멀 꼬리와 넘침 근처는 stardust가 따로 다루는 영역이에요.
- **에러 정책**(`special/boost.hpp`의 `Policy`)은 Boost의 모든 에러를 예외 대신 값(NaN, inf, 0)으로 돌려주게 해요. 그래도 예외가 나오면 NaN으로 바꿔요. 값 때문에 실패하지 않는다는 규칙을 Boost 구간에서도 지키기 위해서예요.
- **결정성은 그대로예요.** Boost의 코드는 헤더라 stardust의 컴파일 단위 안에서 같은 옵션(`-ffp-contract=off`)으로 컴파일되고, 원소 함수 안에서 불려요. 원소의 값만 보고 경로를 고른다는 성질이 유지돼요.

아래 표는 Boost가 맡는 구간과 그 구간에서 **Boost가 실제로 쓰는 방법**이에요. 방법은 옮겨 둔 헤더의 소스(`include/boost/math/special_functions/`)와 Boost 문서의 Implementation 절을 따라 적었어요. 각 방법의 수학은 해당 함수의 글에서 이 저장소의 방법과 같은 깊이로 다뤄요.

| 함수 | Boost 구간 | Boost가 그 구간에서 쓰는 방법 | stardust 코드의 구간 (이유) |
|---|---|---|---|
| `gamma` | $x > -170$, 극점 제외 | $-20 < z < 0$은 $\Gamma(z) = \Gamma(z+1)/z$로 양수까지 올리고 $z \le -20$은 반사 공식, 정수는 팩토리얼 표, $z < \sqrt{\varepsilon}$는 $1/z - \gamma$, 그 밖은 Lanczos 근사 `lanczos13m53` [8]. 넘칠 만하면 거듭제곱을 반으로 나눠 곱해요 | 서브노멀 꼬리와 깊은 음수 |
| `digamma` | $x > 0$ | $x \ge 10$은 $\log(x-1) + \tfrac{1}{2(x-1)} - \sum$(Bernoulli 계수) 점근급수, 그 아래는 점화식으로 $[1, 2]$로 옮긴 뒤 $(x - x_0)(Y + R(x-1))$ 유리식($x_0$는 양의 영점을 세 조각으로 저장) | $x < 0$ (Boost는 극점 근처에서 틀려요) |
| `beta`, `betaln` | $a, b > 0$, $a + b < 40$ | Lanczos 합의 비 $L(a)L(b)/L(c)$에 $(a_g/c_g)^{a-1/2-b}$, $(a_g b_g / c_g^2)^b$를 곱하는 한 식. 밑이 1에 가까우면 `log1p`로 | 큰 인자 (Boost 1.8e3 ULP) |
| `zeta` (Riemann) | $x > -60$, 자명한 영점 제외 | 양의 짝수는 Bernoulli 수의 닫힌식, 홀수 정수는 표, 그 밖은 $(0,1), [1,2], (2,4], (4,7], (7,15), [15,36)$ 구간마다 minimax 유리식(일부는 $1 + e^{R}$ 꼴), $s \ge 36$은 $1 + 2^{-s}$. 음수는 함수방정식 | $x \le -60$ (Boost 1.7e3 ULP) |
| `expi` | $x \ge -700$ | $x < 0$은 $-E_1(-x)$의 유리식($\lvert x \rvert \le 1$과 그 위 두 갈래), $x > 0$은 $(0,6], (6,10], (10,20], (20,40], (40,\infty)$ 구간마다 유리식. $(0,6]$은 양의 영점을 인수로 빼 둔 꼴 | 서브노멀 꼬리, 넘침 근처 |
| `i0 i1 k0 k1` | 전부 (결과가 정상 범위일 때) | $I$: $x < 7.75$는 $x^2/4$의 다항식, $x < 500$은 $e^x P(1/x)/\sqrt{x}$, 그 위는 $e^{x/2}$를 두 번 곱해 넘침을 늦춰요. $K$: $x \le 1$은 다항식과 $\log x$ 항, $x > 1$은 $e^{-x}(Y + R(1/x))/\sqrt{x}$. 모두 minimax 근사 | 넘치거나 서브노멀인 결과 |
| `i0e i1e k0e k1e` | $0 < x < 700$ | 위 값에 $e^{\mp x}$를 곱해요(반올림 한 번 더) | 그 밖 |
| `iv`, `ive` | $\lvert \nu \rvert < 30$, $x > 0$ | $\nu = 0, 1$은 위 유리식, $x/\nu < 1/4$는 거듭제곱급수, 그 밖은 Temme 방법 [9]: $\nu = n + \mu$로 나눠 $x \le 2$는 Temme 급수, $x > 2$는 Steed 방법 [10]으로 $K_\mu, K_{\mu+1}$, CF1로 $I_{\nu+1}/I_\nu$, Wronskian으로 $I$를 맞춰요. 큰 $x$는 점근전개 | 큰 차수 (Debye 균등 점근전개) |
| `kv`, `kve` | $\lvert \nu \rvert < 400$, $x > 0$ | 정수 차수는 $K_0, K_1$에서 앞으로 가는 점화식, 그 밖은 위와 같은 Temme·Steed 방법 | 그 밖 |
| `gammaincinv`, `gammainccinv` | $p \ge 10^{-300}$이고 근 $\ge 10^{-300}$ / 결과가 정상 범위 전부 | DiDonato–Morris [11]의 초기값(영역마다 다른 근사식 여러 개) 뒤에 Halley 반복으로 남은 비트를 정리해요 | 서브노멀 근 |
| `betainc`, `betaincc` | $a, b \le 6$ | DiDonato–Morris의 구조 [1]: 거듭제곱급수, $a$를 정수 칸만큼 옮기는 유한합, 큰 $a$·작은 $b$의 BGRAT, 연분수. 작은 정수 매개변수는 이항 합 | 큰 $a$, $b$ (Boost 911 ULP) |
| `betaincinv` / `betainccinv` | $a, b \ge 10$ / $a, b \ge 1$ | $a + b$가 크면 Temme의 세 균등 근사 중 하나($a$, $b$가 비슷하면 erfc형 두 가지, 크게 다르면 불완전 감마를 거꾸로 푸는 것), 그 밖은 밀도의 변곡점 어느 쪽에 근이 있는지 보고 꼬리의 거듭제곱 근사로 초기값을 잡은 뒤 Halley 반복 | 작은 $a$, $b$ (Boost가 언더플로를 틀려요) |
| `lambertw` (실수, $k = 0$) | $\lvert x + 1/e \rvert \ge 0.05$ | $x \ge 0.05$는 $[0.05, 0.5), [0.5, 2), [2, 6), [6, 18)$의 minimax 유리식, 그 위는 $\log x$의 유리식. $\lvert x \rvert < 0.05$는 Taylor 급수, 음수는 구간별 유리식. 반복 없이 끝나요 | 분기점 근처 (Boost 2e7 ULP) |
| `lambertw` ($k = -1$) | $\lvert x + 1/e \rvert \ge 0.05$ | Fukushima의 방법 [12]: $W$의 정수 부분을 표에서 찾고, 지수 함수 없이 이분법으로 소수 부분을 8–11번 좁힌 뒤, 5차 Schröder 갱신 한 번. $\lvert x \rvert$가 아주 작으면 $L_1 - L_2 + L_2/L_1$에서 Halley 반복 | 분기점 근처 |
| `hyp1f1` | 보장 영역의 $x \ge 0$이고 $b < 11$, 느슨한 영역 전부 | 매개변수 영역마다 거듭제곱급수(넘침을 지수로 따로 세는 판), Kummer 변환, 큰 인자의 점근전개, Bessel 함수 전개, $a$·$b$에 대한 점화식과 함수 비율 중 하나를 골라요 | 보장 영역의 나머지 (Boost 208 ULP). Boost도 값을 못 내는 큰 음의 $a$는 Tricomi 전개 |

Boost를 쓰지 않는 함수도 이유가 있어요. `erf` 계열, `gammaln`, `j0 j1 y0 y1`은 Boost가 더 정확해도 느려서 이 저장소의 코드예요. `airy`는 stardust가 값 넷을 한 번에 계산하고 Boost는 넷을 따로 불러야 해서, 1스레드 원소당 시간이 stardust는 넷을 합쳐 약 277ns, Boost는 값 하나에 143–218ns였어요. Boost는 게다가 $x \approx -10^{11}$ 같은 큰 음수에서 위상을 잃어 $10^{16}$ ULP까지 틀려요. 불완전 감마, `expn`, `polygamma`, 타원적분, `jv`·`yv`도 Boost가 느리거나 틀려요. 비중심 분포는 scipy 1.18이 쓰는 Boost 구현이 깊은 꼬리에서 0을 내거나 수천 ULP가 틀려서 직접 계산해요. Boost에 없는 함수(복소수 전부, `erfcx`, 정규분포 함수, `hyp2f1`, Hurwitz 제타, 리덕션)도 이 저장소의 코드예요. 구간을 고른 측정은 `bench/special/boost/routing.md`에 있고 [정확도와 성능](/internals/special/accuracy-performance/)에서 정리해요.

<Callout type="warn" title="Boost 구간은 betainc와 betaincc가 같아야 해요">
  `betainc`와 `betaincc`는 더하면 1이에요. 한쪽만 Boost이고 다른 쪽이 BRATIO인 점이 있으면, 두 구현의 오차가 따로 놀아서 합이 1에서 3 ULP 넘게 벗어나요. 그래서 두 함수의 Boost 구간을 $a, b \le 6$으로 맞춰 두었어요. BRATIO 구간에서는 한 호출이 $I$와 $1 - I$를 함께 내므로 합이 2 ULP 안이에요.
</Callout>

## 정답지: mpmath 참값 파일

정확도 측정과 테스트는 모두 `tools/special_ref.py`가 만든 참값 파일을 써요.

- **입력 집합**: 함수마다 보장 영역의 격자, 로그 균등 무작위 점(정의역에 부호가 둘이면 양쪽), 보장 영역 둘레의 느슨한 영역 점, 그리고 **경계 점**이에요. 경계 점은 구간 경계, 극점, 영점, 0, 정의역 끝마다 그 값과 양옆의 float64 이웃 네 개씩이에요(`around()`). 구간 경계의 앞뒤 ULP에서 두 방법이 이어지는지 보는 점이에요.
- **계산**: mpmath로 유효숫자 50자리. 결과를 $\text{hi} + \text{lo}$로 저장하고, 보장 영역에 속하는지, 역함수면 조건수 배율 $\max(1, \kappa)$도 함께 저장해요.
- **재현성**: 난수 시드가 고정이라 다시 돌리면 같은 파일이 나와요. 파일은 저장소에 커밋돼 있고, 테스트는 mpmath를 부르지 않아요(느리기 때문이에요).
- **참값 계산의 함정**: mpmath도 모든 곳에서 정확하지는 않아요. 예를 들어 mpmath의 불완전 베타는 인자가 1에 가까우면 자릿수를 잃어서 $x$와 $1-x$ 중 작은 쪽에서 계산하고, 값이 $2^{-1074}$보다 훨씬 작으면 수렴을 포기해서 선두 항으로 0인지 판단해요. 비중심 분포의 반대쪽 꼬리는 급수가 상쇄하므로 mpmath의 수치 적분으로 정의 그대로 계산해요.

이 파일을 쓰는 곳은 셋이에요.

| 어디 | 무엇을 |
|---|---|
| `tests/special/test_reference.py` | 모든 함수가 모든 점에서 계약을 지키는지 (보장 영역 $10^{-14}$, 느슨한 영역은 문서에 적은 한계) |
| `bench/special/accuracy.py` | 함수마다 보장·느슨한 영역의 최대와 99.9% ULP, 같은 점에서 scipy의 값 |
| `bench/special/boost/` | Boost를 부를 구간을 고를 때 계약 위반 점을 찾기 |

정확도 표 전체와 scipy와 비교한 결과는 [정확도와 성능](/internals/special/accuracy-performance/)에 있어요.

## 함수에서 알고리즘으로

함수마다 어떤 방법을 쓰는지 한 줄로 정리했어요. 구간은 모두 원소의 값으로 골라요. "Boost"는 위 표의 구간에서 Boost.Math를 부른다는 뜻이에요.

| 함수 | 방법 | 글 |
|---|---|---|
| `erf`, `erfc` | Cephes 유리식 세 구간($\lvert x \rvert < 1$, $< 8$, $\ge 8$), $e^{-x^2}$는 $x^2 = \text{hi} + \text{lo}$로 나눠 계산, NEON + vForce 청크 커널 | [오차함수와 감마](/internals/special/erf-gamma/) |
| `erfcx` | $\lvert x \rvert < 1$은 $e^{x^2}(1 - \operatorname{erf} x)$, $1 \le x < 8$은 Cephes $P/Q$, $x \ge 8$은 점근급수 18항, $x \le -1$은 $2e^{x^2} - \operatorname{erfcx}(-x)$ | 같은 글 |
| `ndtr`, `log_ndtr` | $\operatorname{erfc}(-x/\sqrt2)/2$를 $x$에서 직접, $\log$는 $x \ge 0$에서 `log1p`, $x < 0$에서 $-x^2/2 + \log(\operatorname{erfcx}(-x/\sqrt2)/2)$ | 같은 글 |
| `ndtri`, `erfinv`, `erfcinv` | Wichura AS 241의 유리식 세 구간, $q = p - \tfrac12$와 $\log \min(p, 1-p)$에서 | 같은 글 |
| `gamma`, `rgamma` | Boost(Lanczos), 그 밖은 Cephes $[2, 3]$ 유리식 + 점화식, $x \ge 33$은 Stirling, 음수는 정확한 인자의 반사, 넘치는 곳은 지수 분리 값 | 같은 글 |
| `gammaln` | 2 둘레의 Taylor 급수(계수 $\zeta(k) - 1$, 28항)와 점화식, $x \ge 13$은 Stirling, 음수는 반사 | 같은 글 |
| `digamma`, `polygamma` | Boost($x > 0$), 음수는 $\pi \cot \pi x$ 반사. `polygamma`는 $(-1)^{n+1} n!\,\zeta(n+1, x)$ | 같은 글 |
| `beta`, `betaln`, `binom` | Boost($a + b < 40$), 그 밖은 Γ 셋의 곱, 지수 분리 값, 큰 인자의 Stirling 비. `binom`은 정수 $k$면 곱 | 같은 글 |
| `loggamma` (복소수) | Stirling 8항, 1–2 둘레의 상쇄 없는 꼴, 반사(분기 $2\pi i k$), 점화식 | 같은 글 |
| `gammainc`, `gammaincc` | 작은 $a$의 $\Gamma(1+a) - 1$ 꼴, 거듭제곱급수 $P$, Lentz 연분수 $Q$, $a > 20$이고 $\lvert x - a \rvert < 0.4a$는 Temme 균등 점근전개. 앞 인자는 double-double 지수 | [불완전 감마와 베타](/internals/special/incomplete/) |
| `betainc`, `betaincc` | Boost($a, b \le 6$), 그 밖은 BRATIO 구조(BPSER, BUP, BGRAT, BFRAC, BASYM) | 같은 글 |
| `gammaincinv`, `gammainccinv` | Boost, 그 밖은 초기값(작은 $x$ 근사, 큰 $x$ 점근, Wilson–Hilferty) + Halley | 같은 글 |
| `betaincinv`, `betainccinv` | Boost($a, b \ge 10$ / $\ge 1$), 그 밖은 AS 109 [13] 초기값 + Halley | 같은 글 |
| `i0 i1 k0 k1` (와 e-스케일 판) | Boost, 결과가 정상 범위 밖이면 Cephes Chebyshev 전개 두 구간 | [Bessel과 Airy](/internals/special/bessel-airy/) |
| `j0 j1 y0 y1` | Cephes: $x \le 5$는 유리식, $x > 5$는 Hankel 진폭·위상 유리식(위상은 반올림하지 않음) | 같은 글 |
| `jv yv jve yve` | 거듭제곱급수, Temme 급수와 Steed CF2 + CF1과 Wronskian, 위로 가는 점화식, Hankel 점근의 네 구간. 음의 차수는 반사 | 같은 글 |
| `iv kv ive kve` | Boost(작은 차수), 그 밖은 Temme·Steed, $\nu \ge 30$은 Debye 균등 점근전개 | 같은 글 |
| `airy` | $-2 \le x \le 1$은 Maclaurin 급수, $x > 1$은 $K_{1/3}, I_{1/3}$, $-9.7 < x < -2$는 $J_{1/3}, Y_{1/3}$, $x \le -9.7$은 진동 점근전개. 위상은 double-double | 같은 글 |
| `zeta` | Riemann은 Boost($x > -60$), 그 밖은 함수방정식. Hurwitz는 Euler–Maclaurin(Cephes `zeta.c`) | [제타, 지수적분, …](/internals/special/more-functions/) |
| `expi`, `expn` | `expi`는 Boost, 그 밖은 영점 둘레 Taylor, 양의 항 급수, 점근급수. `expn`은 $x \le 1$ 급수, $x > 1$ Lentz 연분수 | 같은 글 |
| `ellipk`, `ellipe` | Cephes $P(y) - \log(y)\,Q(y)$, $y = 1 - m$ | 같은 글 |
| `hyp1f1` | Boost(일부), 그 밖은 Maclaurin 급수(float64 첫 패스 + 오차 보정), Kummer 변환, 점근전개 | 같은 글 |
| `hyp2f1` | $0 \le z \le 0.9$ 급수, 음의 $z$는 Pfaff 변환, $z > 0.9$는 $1 - z$ 변환과 정수 $c - a - b$의 극한식 | 같은 글 |
| `lambertw` | Boost(분기점에서 먼 곳), 분기점 근처는 $p = \pm\sqrt{2(ex+1)}$의 급수, 복소수는 Halley 반복 | 같은 글 |
| `expit`, `logit`, 로지스틱·정보 | 부호에 따라 고르는 두 식, 중심의 $2\operatorname{atanh}(2p-1)$, `log1p`와 정확한 빼기 | 같은 글 |
| `wofz`, 복소 `erf erfc erfcx` | 0.1 격자 둘레 Taylor 급수, 그 밖은 Laplace 연분수, 대칭으로 옮기기 | 같은 글 |
| `logsumexp`, `softmax`, `log_softmax` | 최댓값으로 옮긴 두 패스(`max`, pairwise 합), $x - m$은 TwoSum | [원소별 엔진과 병렬화](/internals/special/engine/) |
| `stdtr` … `nbdtrc`, `ndtri_exp` | 불완전 감마·베타의 조합, 인자는 double-double, 작은 쪽 꼬리를 직접, 역함수는 작은 쪽을 풀기 | [분포 함수](/internals/special/distributions/) |
| 비중심 분포 9개 | 포아송 혼합을 먼 끝에서 한 번 걷기, t의 반대쪽 꼬리는 적분, 역함수는 브래킷과 Brent | 같은 글 |
