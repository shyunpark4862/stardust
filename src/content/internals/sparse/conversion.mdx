## 표준 꼴 만들기: 하나의 함수, 세 길

COO → CSR, COO → CSC, `sum_duplicates`, 정렬되지 않은 `(data, indices, indptr)`, DOK → CSR은 모두 `canonical.cpp`의 `compress` 하나로 가요. 입력은 원소 (major, minor, 값)의 목록이고, 출력은 (major, minor) 순서의 `indptr`·`indices`·`data`예요. 같은 자리는 하나로 합치는데, 그 값은 **입력에 나온 순서대로 왼쪽부터 차례로 더한 합**이에요.

```python
>>> import stardust as sd
>>> E = sd.sparse.coo_array(([1.0, 1e16, 1.0, -1e16], ([0, 0, 0, 0], [0, 0, 0, 0])), shape=(1, 1))
>>> E.nnz, E.tocsr().data.tolist()
(4, [0.0])
```

((1 + 10¹⁶) + 1) − 10¹⁶에서 두 번의 1은 10¹⁶에 더해질 때 반올림으로 사라져 0이 돼요. 다른 순서로 더하면 2가 될 수 있는 값이라, 순서를 정의로 못 박아 두었어요. 이 규칙이 있어서 결과는 입력만으로 정해지고, 크기에 따라 길을 바꿔도 비트가 같아요.

길은 셋이에요. 모든 정렬이 안정적이고 중복의 합이 입력 순서라서 셋은 같은 함수를 계산해요. 그래서 어느 길을 탈지는 속도만 보고 크기로 고르고, 테스트(`tests/sparse/test_canonical.py`)는 길과 1·2·3·7·10스레드 사이에서 결과의 바이트를 견줘요.

```cpp
// csrc/sparse/canonical.cpp
bool use_buckets(int64_t nnz, bool presorted) {
    if (nnz >= (presorted ? int64_t(1) << 20 : int64_t(1) << 21)) return true;
    return nnz >= (int64_t(1) << 16) && parallel::available();
}
```

`parallel::available()`은 스레드풀이 실제로 나눠 돌 수 있을 때(스레드가 둘 이상이고, 다른 Python 스레드가 풀을 쓰고 있지 않을 때) 참이에요. 풀이 바쁘면 한 스레드의 길을 타요. 결과가 같으니 이것도 속도만의 선택이에요.

| 길 | 언제 | 하는 일 |
|---|---|---|
| 양동이 길 | 풀을 쓸 수 있으면 2¹⁶개부터, 한 스레드에서는 2²¹개부터 | major를 묶은 양동이로 안정적으로 흩은 뒤 양동이마다 줄을 만들어요. 양동이끼리 병렬 |
| LSD 길 | 한 스레드, 그 아래, 가장 큰 minor가 2·nnz + 2¹⁶ 이하 | minor로 안정 계수 정렬, 그다음 major로 안정 계수 정렬 |
| 곧은 길 | 그 밖 | major로 계수 정렬, 줄마다 minor로 안정 정렬 |

### 곧은 길

scipy의 `coo_tocsr`과 같은 꼴이에요. `indptr`을 계수기로 써서 원소를 줄로 나누고(계수 정렬), 줄마다 (minor, 값) 쌍을 minor로 안정 정렬한 뒤 같은 minor를 차례로 더해요. 줄에 놓을 때 입력 위치가 아니라 값을 함께 옮겨, 나중에 값을 흩어 읽는 패스가 없어요.

줄 하나를 정렬하는 `emit_line`은 길이에 따라 셋으로 나뉘어요. 16개까지는 키 minor·16 + 위치의 순위 정렬이에요. 키가 모두 다르므로(위치가 섞여 있어서) 순위 정렬이 곧 안정 정렬이고, 원소마다 자기보다 작은 키의 수를 NEON 비교로 세어 그 자리에 놓으므로 데이터에 따른 분기가 없어요.

```cpp
            // csrc/sparse/canonical.cpp
            for (int64_t i = 0; i < n; ++i) {
                const uint64x2_t ki = vdupq_n_u64(key[i]);
                uint64x2_t a0 = vcltq_u64(vld1q_u64(key), ki), a1 = vcltq_u64(vld1q_u64(key + 2), ki);
                uint64x2_t a2 = vcltq_u64(vld1q_u64(key + 4), ki), a3 = vcltq_u64(vld1q_u64(key + 6), ki);
                if (n > 8) {
                    a0 = vaddq_u64(a0, vcltq_u64(vld1q_u64(key + 8), ki));
                    a1 = vaddq_u64(a1, vcltq_u64(vld1q_u64(key + 10), ki));
                    a2 = vaddq_u64(a2, vcltq_u64(vld1q_u64(key + 12), ki));
                    a3 = vaddq_u64(a3, vcltq_u64(vld1q_u64(key + 14), ki));
                }
                const uint64x2_t a = vaddq_u64(vaddq_u64(a0, a1), vaddq_u64(a2, a3));
                // each true lane is all ones (-1): the rank is minus the lane sum
                sorted[-static_cast<int64_t>(vgetq_lane_u64(a, 0) + vgetq_lane_u64(a, 1))] = key[i];
            }
```

빈 칸은 가장 큰 키 `~0`으로 채워 세는 데 들지 않게 해요. 키에 minor를 4비트 올려 담으므로 minor가 2⁵⁹ 아래일 때만 이 길이고, 넘으면 다음 길로 가요. 32개까지는 삽입 정렬, 더 길면 `std::stable_sort`예요.

### LSD 길

한 스레드에서 정렬과 합이 필요한 변환이 2²¹개 아래면 비교 정렬을 아예 쓰지 않아요. 먼저 minor로 안정 계수 정렬하고, 그 순서대로 major의 줄에 바로 놓아요. 두 정렬이 모두 안정이므로 줄 안은 minor 순서이고, 같은 자리의 원소는 입력 순서대로 만나요. 그래서 줄의 마지막 원소와 자리가 같은 원소는 도착할 때 거기에 더하면 왼쪽부터 차례로 더한 합이 돼요.

```cpp
    // csrc/sparse/canonical.cpp
    for (int64_t k = 0; k < nnz; ++k) tmp[cmin[minor[k]]++] = {major ? major[k] : 0, val[k]};
    // cmin[m] is now the end of minor m's entries
    bool dups = false;
    for (int64_t m = 0, p = 0; m < n_minor; ++m) {
        for (const int64_t e = cmin[m]; p < e; ++p) {
            Line& d = line[tmp[p].major];
            if (d.last == m) {
                out_val[d.pos - 1] = add_value(out_val[d.pos - 1], tmp[p].v);
                dups = true;
                continue;
            }
            d.last = m;
            out_idx[d.pos] = m;
            out_val[d.pos] = tmp[p].v;
            ++d.pos;
        }
    }
```

minor마다 계수기가 하나씩 들어서, 가장 큰 minor가 2·nnz + 2¹⁶을 넘으면(열이 원소보다 훨씬 많으면) 이 길을 포기하고 곧은 길로 가요. 중복이 있었으면 줄마다 생긴 빈자리를 당겨 붙여요.

### 양동이 길

큰 입력은 major를 2^s개씩 묶은 양동이(64–1024개, nnz와 줄 수로만 정해요)로 원소를 먼저 흩어요. 입력을 2¹⁴개씩의 고정 조각으로 나눠 조각마다 양동이별 개수를 세고, 그 개수를 양동이 순서, 그 안에서 조각 순서로 누적해 자리를 정해요. 그래서 흩기가 병렬이어도 한 양동이 안의 원소는 입력 순서 그대로예요. 그 뒤 양동이마다 줄의 계수 정렬과 `emit_line`을 따로 해요. 양동이가 캐시 크기라 한 스레드에서도 큰 입력에서 빠르고, 양동이끼리는 서로 독립이라 스레드풀에서 나눠 돌아요.

양동이가 64개보다 적으면 10스레드에서 몇 스레드가 늦게 끝나 이득이 없어서, 양동이 수의 아래쪽을 64로 두었어요.

이미 표준 꼴인 COO(`has_canonical_format`)는 이 가운데 어느 것도 타지 않아요. `indptr`만 만들고 값과 minor 색인을 그대로 써요.

## CSR ↔ CSC: 전치

CSR을 CSC로 바꾸는 일은 같은 행렬의 전치를 CSR로 만드는 일과 같아요. 줄 안이 이미 정렬되어 있어서 정렬과 합이 없고, minor(열)로 계수 정렬만 하면 돼요. scipy의 `csr_tocsc`과 같은 꼴이에요.

```cpp
// csrc/sparse/canonical.cpp
template <class T>
void transpose_serial(
    int64_t n_major, int64_t n_minor, const int64_t* ip, const int64_t* ix, const T* v, int64_t* op, int64_t* ox, T* ov
) {
    const int64_t nnz = ip[n_major];
    std::fill(op, op + n_minor + 1, 0);
    for (int64_t k = 0; k < nnz; ++k) ++op[ix[k] + 1];
    for (int64_t c = 0; c < n_minor; ++c) op[c + 1] += op[c];
    for (int64_t r = 0; r < n_major; ++r)
        for (int64_t k = ip[r]; k < ip[r + 1]; ++k) {
            const int64_t p = op[ix[k]]++;
            ox[p] = r;
            ov[p] = v[k];
        }
    for (int64_t c = n_minor; c > 0; --c) op[c] = op[c - 1];
    op[0] = 0;
}
```

행을 차례로 훑으며 흩으므로 새 줄(열) 안의 행 번호는 저절로 오름차순이에요. 다만 원소마다 n_minor개 가운데 아무 곳에나 쓰므로 열이 많으면 캐시를 놓쳐요. 그래서 한 스레드에서 2¹⁵개부터는 열 블록 길을 타요. 원소를 열 2^s개(블록마다 원소 약 2048개)의 블록으로 행 순서대로 먼저 흩고(키 = 행·2^s + 블록 안의 열), 블록마다 열을 세어 자리에 놓아요. 무작위 n열로 한 번 흩어 쓰는 대신 차례로 두 번 쓰는 셈이에요. 키가 64비트에 들지 않으면 계수 정렬로 돌아가요. 스레드풀을 쓸 수 있으면 표준 꼴 만들기의 양동이 길에 "줄 안이 이미 정렬됨"(`presorted`) 표시를 주어 넘겨요.

`.T`는 이 변환을 하지 않아요. CSR의 `.T`는 같은 세 배열의 CSC예요([형식과 표준 꼴](/internals/sparse/formats/)).

## 밀집 배열과 오가기

밀집 → 희소(`_from_dense`)는 두 패스예요. 줄마다 `is_nonzero`인 원소를 세어 `indptr`을 만들고, 다시 훑어 채워요. 줄 구간으로 병렬이고 임의의 strides를 받으므로 전치된 뷰도 복사 없이 읽어요. `dtype=`을 주면 패턴을 먼저 고른 뒤 값을 바꿔요. 그래서 0.4가 int64의 0이 되어도 저장된 원소로 남아요(scipy와 같아요).

```python
>>> X = sd.asarray([[0.4, 0.0], [0.0, 2.0]])
>>> H = sd.sparse.csr_array(X, dtype=sd.int64)
>>> H.nnz, H.data.tolist()
(2, [0, 2])
```

희소 → 밀집은 0으로 채운 C 순서 배열에 저장된 값을 써요. 0에 값을 더한 것이라 저장된 −0.0은 +0.0이 돼요. 중복이 있을 수 있는 COO만 저장 순서로 더해야 하므로 한 스레드이고, 이미 표준 꼴인 COO는 그 걱정이 없어 병렬이에요.

## DOK에서, DOK로

DOK → 다른 형식은 해시 맵의 살아 있는 칸을 칸 순서로 모은 뒤 키 (i, j)의 행 우선 순서로 정렬해요. DOK → CSR(`to_csr`)은 모은 원소를 COO → CSR의 계수 정렬(`compress`)에 그대로 넘겨요. 키가 서로 다르니 더할 것이 없고 값은 바뀌지 않고 옮겨지기만 해요. DOK → COO(`to_coo`)도 행 수가 원소 수에 비해 크지 않으면(행 수 ≤ 2 × 원소 수 + 65536) 같은 계수 정렬 뒤 `indptr`을 펼쳐 행 색인을 만들고, 행이 아주 많으면 모양만큼의 `indptr`을 만들지 않으려고 키를 비교 정렬해요. 두 길 모두 행 우선 순서라 결과가 같아요. 그래서 결과가 키를 넣은 순서와 무관하고, 그 COO는 표준 꼴이에요.

칸을 모으는 일은 원소가 병렬 기준값 이상이면 칸을 고정 크기(2¹⁶칸) 묶음으로 나눠 스레드풀에서 해요. 묶음마다 살아 있는 키를 센 뒤 앞에서부터 누적해 자리를 정하므로 칸 순서가 그대로이고 스레드 수와 상관없어요. 다른 형식 → DOK는 중복을 더한 표준 꼴 COO의 원소를 맵에 넣어요(`from_coo`). 이때는 저장된 0도 키로 남아요. 맵을 만들고 읽는 일은 Python 객체를 건드리지 않으므로 크면 GIL을 놓고 해요.

```python
>>> K = sd.sparse.dok_array((3, 3))
>>> for (i, j) in [(2, 1), (0, 2), (1, 0), (0, 0)]:
...     K[i, j] = float(i + j + 1)
>>> C = K.tocoo()
>>> C.coords[0].tolist(), C.coords[1].tolist(), C.has_canonical_format
([0, 0, 1, 2], [0, 2, 0, 1], True)
```

## 나누는 것과 복사하는 것

`copy=`는 배열의 규칙이에요. None은 필요할 때만 복사하고, True는 언제나, False는 복사가 필요하면 `ValueError`예요. 변환은 나눌 수 있는 배열을 나눠요.

| 변환 | 나누는 배열 | 만드는 배열 |
|---|---|---|
| CSR → COO | `data`, `indices`(열 색인) | 행 색인(`indptr`을 펼친 것) |
| 표준 꼴 COO → CSR | `data`, 열 색인 | `indptr` |
| CSR ↔ CSC(`.T`가 아닌 변환) | 없음 | 셋 다 |
| `.T` | 셋 다 | 없음 |
| DOK와 오가기 | 없음 | 모두 |
| 같은 형식의 생성자(`dok_array(D)` 등) | 모두(DOK는 해시 맵) | 없음 |

```python
>>> A = sd.sparse.csr_array(sd.asarray([[1.0, 0.0], [0.0, 2.0]]))
>>> C = A.tocoo()
>>> C.data is A.data, C.coords[1] is A.indices
(True, True)
>>> A.tocsc(copy=False)
Traceback (most recent call last):
    ...
ValueError: tocsc(): copy=False, but converting csr to csc requires a copy
```

색인 배열은 쓰기 금지라 나눠도 문제가 없어요. 값 배열을 나눈 둘은 `A.data[0] = 5`처럼 한쪽에서 값을 바꾸면 다른 쪽에도 보여요.

같은 형식의 희소 배열을 생성자에 주면 배열을 나누는 새 객체예요. DOK는 해시 맵 자체를 나눠서(scipy와 같아요) 원소 쓰기가 서로 보여요. 그런데 맵은 자기 모양을 들고 있으므로, 한쪽의 `resize`가 맵을 제자리에서 바꾸면 다른 쪽이 자기 모양 밖의 키를 받게 돼요. 그래서 `resize`는 맵을 고치지 않고 새 모양 안의 키만 담은 새 맵을 만들어 자기에게 달아요(`resized`). 다른 쪽은 옛 맵과 옛 모양을 그대로 갖고, 그 뒤로 둘은 맵을 나누지 않아요. `resize`는 어차피 모든 칸을 훑으므로 새 맵을 만드는 비용이 같은 차수예요. 변환은 맵의 모양이 객체의 모양과 같은지를 불변식으로 확인해요.

```python
>>> D = sd.sparse.dok_array((2, 2))
>>> D[0, 0] = 1.0
>>> D2 = sd.sparse.dok_array(D)
>>> D[1, 1] = 2.0
>>> D2.nnz
2
>>> D.resize((1000, 1000))
>>> D[999, 999] = 7.0
>>> D2.shape, D2.nnz, D2.tocsr().indices.tolist()
((2, 2), 2, [0, 1])
```

## scipy와 주고받기

들여오기는 **언제나 복사**예요. scipy의 객체는 나중에 제자리에서 바뀔 수 있고(`sum_duplicates`, `sort_indices`는 제자리 정렬이에요) int32 색인은 어차피 넓혀야 하기 때문이에요. 같은 형식의 CSR·CSC는 `(data, indices, indptr)` 꼴로 위의 검사를 거치고, 다른 형식(BSR, DIA, LIL 포함)은 scipy의 `tocoo()`를 거쳐요.

내보내기 `to_scipy()`는 복사 없는 뷰예요. 빈 scipy 배열을 만든 뒤 세 배열의 numpy 뷰(버퍼 프로토콜)를 대입해요. 생성자에 넘기면 scipy가 색인을 int32로 줄이며 복사하기 때문이에요.

```python
    # src/stardust/sparse/_interop.py
    cls = sp.csr_array if fmt == "csr" else sp.csc_array
    S = cls(A.shape, dtype=np.asarray(A._data).dtype)
    S.indptr = view(A._indptr)
    S.indices = view(A._indices)
    S.data = view(A._data)
    S.has_canonical_format = True
    return S
```

색인 뷰는 원래 배열이 쓰기 금지라 읽기 전용이고, scipy의 제자리 메서드(`eliminate_zeros` 등)는 그 뷰에서 `ValueError`예요. 값 뷰는 쓸 수 있고 이쪽 배열과 메모리를 나눠요. DOK는 scipy의 `dict`로 옮겨야 해서 언제나 복사예요.

## scipy를 아는 분께

- 중복을 더하는 순서가 scipy는 하나가 아니에요. `tocsr()`는 줄의 원소가 15개 이하일 때 입력 순서와 같지만, 더 긴 줄에서는 불안정 정렬(`csr_sort_indices`) 때문에 순서가 바뀌고, COO의 `sum_duplicates()`는 첫 원소에 나머지의 `np.add.reduce`를 더해요. 이쪽은 언제나 입력 순서이므로 중복이 많은 줄에서는 scipy와 끝자리가 다를 수 있어요.
- scipy의 `copy=False`는 "복사하지 않을 수 있으면"의 뜻이에요. 이쪽의 `copy=False`는 복사가 필요하면 `ValueError`이고, 변환의 기본은 `copy=None`이에요.
