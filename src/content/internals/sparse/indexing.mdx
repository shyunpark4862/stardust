키의 에러와 메시지는 배열의 것과 같아요. 테스트가 `A.toarray()[key]`의 에러와 글자까지 견줘요. 결과가 3차원 이상이 되는 키(`A[None, :]` 같은 것)는 희소 배열이 1·2차원뿐이라 `IndexError`예요.

```python
>>> import stardust as sd
>>> A = sd.sparse.csr_array(sd.asarray([[1.0, 0.0, 2.0, 0.0], [0.0, 3.0, 0.0, 4.0], [5.0, 0.0, 6.0, 0.0]]))
>>> A[1, 3], A[1, 0]
(4.0, 0.0)
>>> A[None, :]
Traceback (most recent call last):
    ...
IndexError: this index gives a result of 3 dimensions; a sparse array has 1 or 2
```

## 축 하나의 고르기

커널에 넘기는 축 하나의 고르기는 셋 가운데 하나예요. None(축 전체), `(start, step, count)`(slice), 정수 배열(반복과 아무 순서). C++의 `AxisMap`이 이것을 감싸 두 가지 물음에 답해요. "결과 자리 t는 원래 색인 몇을 고르나"와, 그 반대인 "원래 색인 c를 고르는 결과 자리는 어디어디인가"예요. CSR 줄을 훑으며 저장된 원소마다 둘째 물음을 하므로 이것이 빨라야 해요.

- slice는 산수로 답해요. step의 절댓값이 축 길이보다 크면 원소 하나만 고르므로 `parse`가 step을 ±길이로 줄여 int64에 담아요(`A[::2**64]`는 `A[::3]`과 같은 결과예요). step이 ±1이 아니고 축이 너무 길지 않으면(16 × 고른 수 + 65,536 이하) 원래 색인마다 결과 자리를 적은 표를 미리 만들어 나눗셈을 한 번의 읽기로 바꿔요.
- 정수 배열은 같은 크기 조건이면 계수 정렬로 표를 만들어요. 원래 색인 c를 고르는 결과 자리들이 `pos[table[c]]`부터 `pos[table[c + 1]]` 앞까지예요. 축이 그보다 길면 결과 자리를 원래 색인으로 안정 정렬해 두고 이분 탐색해요.
- 그 표 옆에 원래 색인마다 고른 횟수를 1바이트(255에서 포화)로 적은 표를 하나 더 둬요. 저장된 원소 대부분은 고르지 않은 열에 있으므로 "고르지 않음"을 캐시에 머무는 작은 표에서 답하면 넓은 표를 읽지 않아도 돼요.

```cpp
            // csrc/sparse/index.cpp
            hits_.resize(static_cast<std::size_t>(n_));
            for (int64_t c = 0; c < n_; ++c) {
                const int64_t h = table_[static_cast<std::size_t>(c + 1)] - table_[static_cast<std::size_t>(c)];
                if (h >= 255) saturated_ = true;
                hits_[static_cast<std::size_t>(c)] = static_cast<std::uint8_t>(std::min<int64_t>(255, h));
            }
```

## 바깥 고르기: 줄마다 다시 표준 꼴로

CSR·CSC의 바깥 고르기 `_select_compressed`는 결과 줄 t마다 원래 줄 하나(줄 축의 고르기가 정한 것)를 훑어요. 두 패스예요. 첫 패스는 결과 줄마다 원소 수를 세어 `indptr`을 만들고, 둘째 패스가 색인과 값을 채워요. 줄 축의 고르기는 원래 줄을 고르기만 하므로 반복도 순서도 문제가 되지 않고, 결과가 표준 꼴이 되려면 줄 안의 순서만 맞추면 돼요. 그래서 줄 안의 고르기 꼴에 따라 길을 나눠요.

| 줄 안의 고르기 | 하는 일 |
|---|---|
| 전부, step 1인 slice | 줄 안의 구간을 통째로 옮겨요. 짧은 줄(32개 이하)은 앞에서 훑고, 긴 줄은 이분 탐색으로 구간의 두 끝을 찾아요 |
| 양의 step, 오름차순 배열 | 줄을 앞에서부터 훑어요. 결과 자리가 원래 색인과 함께 늘어나요 |
| 음의 step | 줄을 거꾸로 훑어요 |
| 정렬되지 않은 배열 | 줄의 결과 (자리, 원소)를 모아 자리로 정렬해요. 한 줄의 결과 자리는 서로 달라 안정성이 필요 없어요. 고른 것이 없는 줄은 건너뛰고, 하나뿐인 줄은 정렬하지 않아요 |

```python
>>> s = A[:, [3, 0, 0]]
>>> s.format, s.indptr.tolist(), s.indices.tolist(), s.data.tolist()
('csr', [0, 2, 3, 5], [1, 2, 0, 1, 2], [1.0, 1.0, 4.0, 5.0, 5.0])
>>> A[::-1, 1:].toarray().tolist() == A.toarray()[::-1, 1:].tolist()
True
```

`[3, 0, 0]`은 정렬되지 않은 배열이라 줄마다 자리로 정렬했어요. 열 0을 두 번 골랐으므로 그 값이 두 번 저장되었어요. 결과는 다시 표준 꼴이고, `A[key].toarray()`는 `A.toarray()[key]`와 비트까지 같아요. 값을 옮기기만 하고 계산하지 않기 때문이에요.

COO는 저장된 원소와 순서를 그대로 가져가요(scipy와 같아요). 원소마다 그것을 고르는 결과 자리 쌍마다 하나씩, 원소 순서, 행 자리, 열 자리 순서로 내보내요. 중복도 그대로 남아요. DOK는 키를 정렬한 COO를 거쳐 같은 일을 하고 DOK로 돌아가요.

## 원소 고르기

두 축에 배열이 있으면(정수와 배열이 함께여도 배열의 규칙으로 브로드캐스트해요) 쌍 (rows[k], cols[k])마다 값 하나를 골라요. CSR·CSC는 쌍마다 줄 안을 탐색하고(짧은 줄은 분기 없는 세기, 긴 줄은 이분 탐색), 찾은 쌍만 k 순서로 내보내요. 결과는 1차원 COO이고, 저장되지 않은 쌍은 결과에도 저장되지 않아요.

```python
>>> p = A[[0, 2, 2], [2, 0, 1]]
>>> p.format, p.shape, p.coords[0].tolist(), p.data.tolist()
('coo', (3,), [0, 1], [2.0, 5.0])
```

쌍 (2, 1)은 저장되지 않은 자리라 결과의 자리 2에 아무것도 없어요.

## 결과의 형식

결과의 차원 수가 A와 같으면 A의 형식(CSR은 CSR, DOK는 DOK)이고, 다르면 COO예요. 2차원의 `A[i]`·`A[:, j]`, 원소 고르기, 1차원에 None을 붙인 것이 COO예요.

```python
>>> type(A[1]).__name__, A[1].shape
('coo_array', (4,))
```

## 대입

`A[key] = v`도 같은 `parse`로 키를 읽고, 고른 영역의 모양에 v를 배열의 대입 규칙으로 맞춰요. 원소 하나의 자리에는 Python 스칼라만, 그 밖에는 영역의 모양으로 엄격하게 브로드캐스트되는 값이나 희소 배열이에요. 값은 배열의 규칙으로 A의 dtype이 되고(암묵적 하향 변환은 `TypeError`), 같은 자리가 여러 번 나오면 마지막 값이에요. 무엇이 저장되는지는 형식마다 scipy의 규칙이에요.

### CSR·CSC

`_assign_compressed`가 고른 자리들을 (줄, 자리)로 안정 정렬해 같은 자리의 마지막 값만 남기고, 자리마다 줄 안을 탐색해 이미 저장된 자리인지 봐요.

- 모든 자리가 이미 저장되어 있으면 `data`를 **제자리에서** 바꿔요. 같은 값 배열을 나누는 다른 배열(`.T`, `to_scipy()`의 뷰)에도 보여요.
- 새 자리가 하나라도 있으면 먼저 이미 저장된 자리를 옛 `data`에서 제자리로 바꾸고(새 자리가 없을 때와 같아요), 줄마다 옛 원소와 새 자리를 병합해 세 배열을 다시 만들어요. O(nnz)이고 경고는 없어요. 그래서 옛 값 배열을 보던 뷰에도 기존 자리의 새 값은 보이고, 새 자리는 새 배열에만 있어요(scipy의 `_set_many`와 같아요).

대입한 0도 저장된 원소로 남아요(scipy와 같아요).

```python
>>> T = A.T
>>> A[0, 0] = 9.0
>>> T[0, 0]
9.0
>>> A[0, 1] = 7.0
>>> T[1, 0], A.nnz
(0.0, 7)
>>> A[2, 2] = 0.0
>>> A.nnz, A.count_nonzero()
(7, 6)
```

`A[0, 1] = 7.0`은 새 자리라 A가 새 배열을 받았고, 옛 배열을 보던 `T`는 그대로예요. 한 번의 대입에 두 자리가 섞이면 기존 자리의 값은 뷰에도 보여요.

```python
>>> B = sd.sparse.csr_array(sd.asarray([[1.0, 0.0], [0.0, 2.0]]))
>>> V = B.T
>>> B[[0, 0], [0, 1]] = sd.asarray([10.0, 20.0])
>>> V.toarray().tolist(), B.toarray().tolist()
([[10.0, 0.0], [0.0, 2.0]], [[10.0, 20.0], [0.0, 2.0]])
```

### DOK와 COO

- DOK: 원소 하나는 해시 맵에 바로 넣어요. 0(−0.0 포함)을 넣으면 그 키를 지워요. 여러 자리는 `set_many`로 차례로 넣어 마지막 값이 남아요. 희소 값은 그 밀집 값으로 영역 전체를 넣어요.
- COO: 영역의 자리에 저장된 원소를 중복까지 모두 지우고(`_coo_remove`), 새 값을 행 우선 순서로 뒤에 붙여요. 배열 대입의 0은 붙이지 않지만 원소 하나의 대입과 희소 값의 저장된 원소는 0이어도 붙여요. 붙인 뒤에는 `has_canonical_format`을 다시 알아내도록 비워 둬요.

```python
>>> C = A.tocoo()
>>> n0 = C.nnz
>>> C[0, 3] = 0.0
>>> C.nnz - n0, C.has_canonical_format
(1, False)
```

## 대각

`diagonal(k=)`는 `A.toarray()`의 k번째 대각과 비트까지 같은 밀집 1차원 배열이에요. CSR·CSC는 줄마다 대각 자리를 줄 안에서 찾고, COO는 원소를 훑어 0에 더해요. 그래서 저장된 −0.0은 +0.0이 되고, COO의 중복은 저장 순서로 더해져요. `trace(k=)`는 그 대각의 `sd.sum`이에요(bool·int64는 int64). `setdiag`은 대각의 자리들을 위의 대입 규칙으로 써요.

```python
>>> A.diagonal().tolist(), A.trace()
([9.0, 3.0, 0.0], 12.0)
```

## scipy를 아는 분께

- scipy의 CSR·CSC는 1차원 원소 고르기와 2차원 마스크에 밀집 numpy 배열을, 2차원 원소 고르기에 밀집 값에서 다시 만든 배열(저장된 0이 빠져요)을 돌려줘요. 이쪽은 네 형식 모두 같은 규칙의 희소 배열이에요.
- scipy의 DOK는 경로에 따라 고른 결과에서 저장된 0을 빼기도 두기도 해요. 이쪽은 언제나 둬요.
- scipy는 원소 하나의 자리에 `[3]`도 받고, 2.5를 int64에 2로 넣어요. scipy의 COO 대입은 같은 자리의 첫 값이 남아요. 이쪽은 배열의 규칙이에요.
