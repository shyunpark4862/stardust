## 한눈에 보기

Krylov 반복법은 행렬을 분해하지 않고 행렬과 벡터의 곱만으로 $Ax = b$에 다가가요. $k$번째 반복점은 처음 잔차 $r_0$가 만드는 Krylov 공간

$$
\mathcal K_k(A, r_0) = \operatorname{span}\{r_0,\ Ar_0,\ A^2r_0,\ \ldots,\ A^{k-1}r_0\}
$$

안에서 고른 것이고, 방법마다 "무엇을 가장 작게 하는가"와 "기저를 어떻게 만드는가"가 달라요. 반복 하나의 일은 곱 한두 번과 내적·노름·벡터 갱신 몇 번이에요.

## 왜 직접 짜나요

Accelerate의 Sparse Solvers에는 CG, GMRES, LSMR이 있어요. 그래도 쓰지 않는 이유는 이래요.

- **멈춤 판정과 상태를 scipy와 맞출 수 없어요.** Accelerate의 판정은 $\lVert b - Ax\rVert_2 < \text{rtol}\cdot\lVert b - Ax_0\rVert_2 + \text{atol}$(처음 잔차에 대한 상대, rtol 기본 √ε)이고, scipy는 $\lVert b\rVert$에 대한 상대(rtol 기본 10⁻⁵)예요. `SparseSolve`는 반복 수를 돌려주지 않고, GMRES의 기본은 재시작 GMRES가 아니라 DQGMRES예요. 한 걸음씩 부르는 `SparseIterate`로 판정을 직접 하면 판정은 맞출 수 있지만 그 안의 직교화·Givens 회전·내적의 순서는 열어 볼 수 없어요.
- **MINRES, BiCGSTAB, LSQR은 없어요.** 어차피 짜야 해요.
- **비용이 이 라이브러리의 커널이에요.** 반복법의 일은 SpMV와 내적·axpy예요. 이 라이브러리의 SpMV와 결정적인 내적을 쓰면 결과가 sd의 스레드 수와 무관해요.

알고리즘과 멈춤 판정은 scipy 1.18.1의 Python 판(`scipy/sparse/linalg/_isolve`의 `iterative.py`, `minres.py`, `lsqr.py`, `lsmr.py`)을 계산 순서까지 옮겼어요. 스칼라는 numpy의 산술을 따라요. 복소인 양은 복소로 두고(실수로 나누는 것도 numpy처럼 복소 나눗셈), 복소끼리의 비교는 numpy의 순서(실수부, 다음 허수부)예요.

## 연산자가 커널에 가는 길

A와 전처리기 M은 희소 배열, 2차원 `sd.ndarray`, [`LinearOperator`](/api/sparse/linearoperator/) 가운데 하나예요. Python 층의 `_Operand`가 이것을 둘로 나눠요.

```python
    # src/stardust/sparse/_iterative.py, _Operand
    def native(self, dtype, adjoint=False):
        """The operator for the kernel: the CSR arrays (indptr, indices, data) of the matrix (or
        of its adjoint) in dtype, or a Python function of a vector."""
        A = self.matrix
        if A is None:
            return _python(self.op.rmatvec if adjoint else self.op.matvec, dtype)
        if isinstance(A, sparray):
            if adjoint:
                A = A.tocsr().T.tocsr()  # the transpose's CSR (its values in A's order of columns)
                if A.dtype == _sd.complex128:
                    A = A.conj()
            else:
                A = A.tocsr()
            data = A.data if A.data.dtype == dtype else A.data.astype(dtype)
            if not C.contiguous(data):
                data = data.copy()
            return (A.indptr, A.indices, data)
        # a dense matrix: the CSR of all its entries (zeros stored), so its products are SpMVs
        if adjoint:
            A = _sd.conj(A.mT) if A.dtype == _sd.complex128 else A.mT
        m, n = A.shape
        indptr = _sd.arange(0, m * n + 1, max(n, 1), dtype=_sd.int64) if n else _sd.zeros(m + 1, dtype=_sd.int64)
        indices = _sd.reshape(_sd.tile(_sd.arange(n, dtype=_sd.int64), (m,)), (m * n,))
        data = _sd.reshape(A.astype(dtype), (m * n,)).copy()
        return (indptr, indices, data)
```

- **행렬**(어느 형식이든)은 CSR 배열 셋으로 C++에 가요. 형식이 무엇이든 같은 CSR이 되므로 결과의 비트가 형식과 무관해요. `lsqr`·`lsmr`가 쓰는 $A^{\mathsf H}$는 $A^{\mathsf T}$의 CSR(복소는 켤레)을 한 번 만들어 둔 것이에요.
- **밀집 행렬**은 모든 원소(0까지)를 저장한 CSR로 바꿔요. 그래서 곱이 SpMV이고, 밀집 `A @ x`(BLAS의 `gemv`)와는 끝자리가 다를 수 있어요.
- **`aslinearoperator(A)`**로 감싼 연산자는 감싼 행렬을 `_matrix`로 들고 있어서, `_Operand`가 그 행렬을 꺼내 위의 길로 보내요. 감싸도 Python을 거치지 않아요.
- **다른 `LinearOperator`**는 곱마다 Python의 `matvec`(`lsqr`·`lsmr`의 $A^{\mathsf H}$는 `rmatvec`)을 불러요. 결과가 계의 dtype이 아니면 맞추고(실수 결과는 복소로 넓히고, 실수 계에서 복소 결과는 `TypeError`), 연속이 아니면 복사해요.

계의 dtype은 A, b, x0, M 가운데 하나라도 복소면 complex128, 아니면 float64예요. bool과 int64는 float64가 돼요.

C++ 쪽에서 연산자는 셋 중 하나예요.

```cpp
    // csrc/sparse/krylov.hpp, Op
    // y = op(x); x has cols entries, y rows.
    void apply(const T* x, T* y) const {
        if (kind == Identity) {
            std::memcpy(y, x, static_cast<std::size_t>(rows) * sizeof(T));
            return;
        }
        if (kind == Matrix) {
            const int64_t nt = static_cast<int64_t>(bounds.size()) - 1;
            for_tasks(nt, work(), [&](int64_t t) {
                std::vector<T> parts;
                for (int64_t r = bounds[t]; r < bounds[t + 1]; ++r) {
                    auto step = [this, x](int64_t p, T acc) { return madd(v[p], x[ix[p]], acc); };
                    y[r] = ordered_sum<T>(ip[r], ip[r + 1], step, parts);
                }
            });
            return;
        }
        nb::gil_scoped_acquire gil;
        const int64_t shape[] = {cols};
        NDArray in = new_array(dtype_of<T>, shape);
        std::memcpy(in.data, x, static_cast<std::size_t>(cols) * sizeof(T));
        nb::object out = fn(wrap(std::move(in)));
        if (!is_ndarray(out)) throw nb::type_error("the operator's function did not return an sd.ndarray");
        const NDArray& o = as_ndarray(out);
        if (o.dtype != dtype_of<T> || o.ndim != 1 || o.shape[0] != rows || !o.c_contiguous)
            throw nb::value_error("the operator's function returned an array of the wrong shape or dtype");
        std::memcpy(y, o.data, static_cast<std::size_t>(rows) * sizeof(T));
    }
```

`Matrix`의 곱은 희소 영역의 SpMV([곱](/internals/sparse/products/)) 그대로예요. 출력 행마다 열 번호 오름차순으로 `fma(a, x, acc)`를 더하고, 4096개 넘는 줄은 고정 조각과 쌍 트리로 더해요. 행 구간(`bounds`)은 `indptr`만으로 정해 nnz 약 2¹⁴개씩이고, 행 하나는 한 태스크가 계산하므로 스레드 수와 무관하게 `A @ x`와 비트가 같아요. `Python`은 곱마다 반복의 벡터를 새 배열에 복사해 사용자 함수에 넘기고, GIL을 잡고 불러요.

그래서 같은 행렬을 어떻게 넘기든 해가 비트까지 같아요. Python 함수로 감싼 `A @ v`도 같은 SpMV를 부르기 때문이에요.

```python
>>> g = 30
>>> T = sd.sparse.diags_array([-sd.ones(g - 1), 2 * sd.ones(g), -sd.ones(g - 1)], offsets=[-1, 0, 1], format="csr")
>>> A = sd.sparse.kronsum(T, T, format="csr")          # 2차원 라플라시안, 900 × 900
>>> b = sd.ones(g * g)
>>> x1 = sd.sparse.cg(A, b).x
>>> op = sd.sparse.LinearOperator(A.shape, lambda v: A @ v)
>>> op
LinearOperator(shape=(900, 900), dtype=float64)
>>> [bool(sd.all(x1 == sd.sparse.cg(B, b).x)) for B in (op, sd.sparse.aslinearoperator(A), A.tocsc(), A.toarray())]
[True, True, True, True]
```

밀집 행렬도 같은 이유예요. 0인 원소의 항 `fma(0, x, acc)`는 acc를 바꾸지 않으므로, 0까지 저장한 CSR의 줄 합이 0을 빼고 더한 합과 같아요.

### LinearOperator

[`LinearOperator`](/api/sparse/linearoperator/)는 scipy의 인터페이스를 sd 배열에 옮긴 순수 Python 클래스예요(`_interface.py`). 함수를 키워드로 받거나, 하위 클래스가 `_matvec`·`_matmat`(과 `_rmatvec`·`_rmatmat`)을 정의해요. 없는 쪽은 있는 쪽으로 채워요. `matmat`이 없으면 열마다 `matvec`을 불러 쌓고, `matvec`이 없으면 (N, 1) 행렬로 `matmat`을 불러요. `dtype=None`이면 scipy처럼 0 벡터로 `matvec`을 한 번 불러 결과의 dtype을 써요.

조합(`A + B`, `A @ B`, `c * A`, `A ** p`, `A.T`, `A.H`)은 Python 람다로 만든 새 연산자예요. 예를 들어 전치는 $A^{\mathsf T}x = \overline{A^{\mathsf H}\bar x}$로 `rmatvec`에서 만들어요.

```python
# src/stardust/sparse/_interface.py
def _transposed(A):
    m, n = A._shape
    return _make(
        (n, m), A._dtype,
        lambda x: _conj(A._rmatvec(_conj(x))), lambda x: _conj(A._matvec(_conj(x))),
        lambda X: _conj(A._rmatmat(_conj(X))), lambda X: _conj(A._matmat(_conj(X))),
    )  # fmt: skip
```

조합한 연산자는 감싼 행렬이 없으므로 반복법에서 곱마다 Python을 거쳐요. `2.0 * A`(희소 배열)와 `op + op`의 해는 같은 비트지만, 앞의 것은 GIL 없이 C++에서 돌고 뒤의 것은 곱마다 Python을 불러요. 큰 문제에서는 행렬을 먼저 만들어 넘기는 쪽이 빨라요.

### 전처리기

전처리기 M은 $A^{-1}$에 가까운 연산자이고, A와 같은 길(행렬이면 CSR, 아니면 Python)로 가요. 넘기지 않으면 항등(`Identity`, 복사)이에요. 방법마다 M을 쓰는 자리는 scipy와 같아요.

| 방법 | M을 쓰는 곳 | 뜻 |
|---|---|---|
| `cg` | $z = Mr$, $\rho = r^{\mathsf H}z$ | 전처리한 CG(M은 에르미트 양정치) |
| `bicgstab` | $\hat p = Mp$, $\hat s = Ms$ | 오른쪽 전처리 |
| `gmres` | $w = M(Av)$, $v_0 = Mr$ | 왼쪽 전처리, 안쪽 판정은 $\lVert M(b - Ax)\rVert$에 대해 |
| `minres` | $y = Mr$, $\beta = \sqrt{r^{\mathsf H}y}$ | M은 에르미트 양정치, $r^{\mathsf H}My < 0$이면 `LinAlgError` |

`lsqr`·`lsmr`에는 전처리기 인자가 없어요(scipy와 같아요). 연산자를 바꾸고 싶으면 `LinearOperator`로 감싸 넘겨요. 반복마다 부르는 `callback`도 없어요. 그 대신 결과에 반복 수와 잔차의 어림이 있어요.

## 결정적인 벡터 연산

반복법의 결과가 sd의 스레드 수와 무관하려면 곱뿐 아니라 내적과 노름도 나누는 방법이 스레드 수와 무관해야 해요.

```cpp
// csrc/sparse/krylov.hpp
// sum_i a_i b_i (real) or sum_i conj(a_i) b_i (complex): sd.linalg.vecdot's sum.
template <class T>
T dot(const T* a, const T* b, int64_t n) {
    if constexpr (kComplex<T>) {
        return linalg::pairwise_tree_mt<complex128>(n, [a, b](int64_t b0, int64_t m) {
            return linalg::detail::fma_cdot_leaf(a + b0, b + b0, m);
        });
    } else {
        return linalg::pairwise_tree_mt<double>(n, [a, b](int64_t b0, int64_t m) {
            return linalg::detail::fma_dot_leaf(a + b0, b + b0, m);
        });
    }
}

// ||x||_2: sd.linalg.vector_norm's (a complex vector as the real vector of its parts).
template <class T>
double nrm2(const T* x, int64_t n) {
    const double* d = reinterpret_cast<const double*>(x);
    const int64_t count = kComplex<T> ? 2 * n : n;
    auto fill = [d](int64_t b, int64_t len, double* out) {
        for (int64_t k = 0; k < len; ++k) out[k] = std::fabs(d[b + k]);
    };
    return linalg::vnorm(linalg::VecOrd{linalg::Ord::Two, 2.0}, count, fill, d);
}
```

- **내적**은 `sd.linalg.vecdot`과 같은 합이에요. n을 고정 길이의 잎으로 나눠 잎마다 NEON 레인의 FMA로 더하고, 잎 합들을 n으로만 정해지는 쌍 트리로 더해요. 복소는 첫 벡터에 켤레를 씌워요(numpy의 `vdot` 자리). 트리가 크면 잎들을 스레드풀이 나눠 계산하지만 트리의 모양은 같아요.
- **2-노름**은 `sd.linalg.vector_norm`의 것이에요. 제곱합을 융합해 더하고, 넘침이 나면 척도를 맞춰 다시 계산해요. 복소 벡터는 실수부·허수부를 한 실수 벡터로 봐요.
- **갱신**($y \mathrel{+}= ax$ 등)은 원소마다 독립이라 고정 조각(2¹⁴개)으로 나눠요. 실수는 `std::fma(a, x[i], y[i])`, 복소는 numpy의 복소 곱(`ops::cmul`) 뒤 덧셈이에요.

GMRES의 Gram–Schmidt처럼 기저 벡터 여럿과 내적하는 자리에는 여러 벡터를 한 번에 훑는 판(`dots`, `axpy_dot`, `gaxpy`)이 있어요. 잎의 경계를 내적과 똑같이 잡고 잎 합을 같은 트리로 합치므로, 한 벡터씩 부른 것과 비트가 같아요. 메모리를 덜 훑을 뿐이에요.

모든 연산이 크기만으로 태스크를 나누므로(2¹⁵ 단위부터 스레드풀, [결정성과 병렬 분할](/internals/sparse/determinism/)) 같은 입력이면 스레드 수와 상관없이 같은 비트예요. numpy의 `dot`·`norm`과는 합의 순서가 달라 끝자리가 다르고, 그것이 scipy와 반복점이 끝자리부터 갈라지는 출발점이에요.

## GIL

```cpp
// csrc/sparse/iterative.cpp
// The two operators' GIL: without it for the whole solve when both are native and a step is
// large; with it (the kernels release it on their own) otherwise.
template <class T>
bool solve_unlocked(const Op<T>& a, const Op<T>& b, int64_t n) {
    return a.native() && b.native() && a.work() + b.work() + n >= kParallelThreshold;
}
```

두 연산자(A와 M, 또는 A와 $A^{\mathsf H}$)가 모두 행렬이나 항등이고 한 걸음의 일(저장 수 + 길이)이 2¹⁵ 이상이면 풀이 전체가 GIL 없이 돌아요. Python 연산자가 있으면 GIL을 쥔 채 돌고(곱마다 Python을 불러야 하므로), 그 사이의 SpMV·내적 커널이 스스로 GIL을 놓아요.

## 결과

C++ 풀이는 사전 하나를 돌려줘요. x, status, 반복 수, 방법의 어림(노름, 조건수), 그리고 `history`예요. `history`는 방법이 단계마다 쓴 잔차 노름의 열이에요(cg·bicgstab: 반복 첫머리의 $\lVert r\rVert$, gmres: 안쪽 반복마다의 어림, minres: $\bar\phi$, lsqr: `r1norm`, lsmr: `normr`). 공개 결과에는 넣지 않고, 시험이 비공개 `_iterative._run`으로 꺼내 scipy와 견줘요. 이 사이트의 그림도 그것으로 그려요.

```python
>>> from stardust.sparse import _iterative
>>> r, hist = _iterative._run("cg", A, b, rtol=1e-8)
>>> r
CgResult(converged=True, status=0, n_iter=55, normr=2.8713e-07, x=<array of shape (900,)>)
>>> hist.shape
(56,)
```

Python 층은 그 사전으로 결과 객체(`CgResult` … `LsmrResult`)를 만들어요. 필드는 읽기 전용이고, scipy의 튜플로 풀려요(`x, info = cg(A, b)`, `lsqr`은 열 개, `lsmr`은 여덟 개). `converged`는 `cg`·`bicgstab`·`gmres`·`minres`에서 status 0이고, `lsqr`·`lsmr`에서 status가 0, 1, 2, 4, 5 가운데 하나일 때예요(3은 조건수 한계, 6은 기계 정밀도의 조건수, 7은 반복 상한). 메시지는 scipy의 것을 이 라이브러리의 말로 옮겼어요.

<Callout type="note" title="b = 0">
`cg`·`bicgstab`·`gmres`·`minres`는 $\lVert b\rVert = 0$이면 반복 없이 x = b(0 벡터)와 status 0을 돌려줘요(scipy와 같아요). 메시지는 "the right-hand side is zero: x = 0"이에요.
</Callout>

## scipy와 견준 것

scipy 1.18.1의 기록 40개(여섯 함수 × 행렬 서너 개 × 기본·조인 허용오차)에서 상태는 40개 모두, 반복 수는 36개가 같아요. 단계마다의 잔차 노름은 상대 10⁻⁶ 안이고 대부분 10⁻¹⁵ 크기예요. 다른 넷은 모두 `bicgstab`이고, 그 이유는 [CG와 BiCGSTAB](/internals/sparse/cg-bicgstab/#scipy와-다른-점)에 있어요. 전처리(Jacobi), `x0`, `gmres`의 `restart`·`max_iter`, `minres`의 `shift`, `lsqr`·`lsmr`의 `damp`·`x0`, 붕괴, 상한, b = 0도 상태와 반복 수가 scipy와 같아요.

정확도 체계는 Arb(구간 산술)로 검증한 해 30점(최소제곱 2점)을 rtol 10⁻¹⁰으로 풀어, 멈춤 판정이 약속하는 앞오차를 계약으로 써요. 정방 계는 $|\hat x_i - x_i| \le \lVert A^{-1}\rVert_\infty \cdot \text{rtol}\cdot\lVert b\rVert_2$예요. 여섯 방법 모두 계약 안이고 가장 큰 것은 bicgstab 0.39, gmres 0.31, cg 0.10, minres 0.081, lsqr·lsmr 0.051(계약 단위)이에요.
