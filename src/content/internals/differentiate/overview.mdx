## 한눈에 보기

`sd.differentiate`의 공개 함수 셋(`derivative`, `jacobian`, `hessian`)은 Python에서 입력을 검사하고 차분 공식의 가중치를 정한 뒤, 반복 전체를 C++ 커널 `stardust._core.differentiate`에 맡겨요. 사용자 함수는 Python이라 커널이 반복마다 Python으로 되돌아와 불러요. 다만 한 번 부를 때 점을 여러 개 담은 배열 하나를 넘기므로, 호출 수는 반복 수와 같고 점의 수와는 상관없어요. 함수의 쓰임새는 [기본 개념](/api/differentiate/basics/), [derivative](/api/differentiate/derivative/), [jacobian](/api/differentiate/jacobian/), [hessian](/api/differentiate/hessian/)에 있어요.

이 영역에는 공개 함수가 쓰지 않는 커널도 둘 있어요. `sd.optimize`의 차분 기울기와 야코비안이 쓰는 고정 간격(`csrc/differentiate/steps.hpp`)과, `approx_fprime`과 `sd.regression.nls`가 쓰는 간격을 고르는 5점 차분(`src/stardust/differentiate/_differences.py`)이에요. 차분의 간격은 미분의 일이라 이 영역에 두고, 부르는 쪽이 저마다의 셈과 에러를 맡아요.

```python
# src/stardust/differentiate/_derivative.py
def derivative(
    f, x, /, *, args=(), atol=None, rtol=None, max_iter=10, order=8, initial_step=0.5, step_factor=2.0, step_direction=0
):
    """The derivative of the elementwise f at each x by repeated high-order differences
    (scipy.differentiate.derivative; docs/api/differentiate.md §2)."""
    func = "derivative"
    _callable(f, func, "f")
    atol, rtol = _tolerances(atol, rtol, func)
    max_iter = _check_int(max_iter, func, "max_iter", 1)
    n, c, wc = _stencil(order, step_factor, func)
    named = [("x", x), ("initial_step", initial_step), ("step_direction", step_direction)]
    (xs, h0, d), extra, shape = _inputs(func, named, _args(args, func))
    wr = _one_sided(n, c, d)
    df, err, status, nit, nfev = _k.derivative_solve(
        func, f, _values(func), extra, xs, h0, d, wc, wr, n, c, atol, rtol, max_iter
    )
    return DifferentiateResult._make(batch=shape, **_fields(shape, df, err, status, nit, nfev), x=_shaped(xs, shape))
```

커널에 넘기는 것은 원소 n개의 1차원 배열(`xs`, `h0`, `d`와 사용자 `args`), 가중치 두 벌(중앙 `wc`, 한쪽 `wr`; 한쪽 공식을 쓰는 원소가 없으면 `wr`은 빈 배열), 그리고 `_values(func)`가 만든 확인 함수예요. 커널이 돌려주는 것도 원소 n개의 1차원 배열 다섯이고, Python이 그것을 입력의 브로드캐스트 모양으로 되돌려요. 기본 `atol`은 가장 작은 정규수 $2^{-1022}$, 기본 `rtol`은 $\sqrt\varepsilon = 2^{-26}$이에요(scipy의 기본값).

가중치는 `central_weights(n, c)`와 `one_sided_weights(n, c)`가 정확한 유리수 계산으로 만들어 (n, c)마다 따로 기억해 둬요(`functools.lru_cache`). 같은 `order`와 `step_factor`로 여러 번 부르면 처음 한 번만 계산해요. 한쪽 가중치는 $\mathbb{Q}(\sqrt c)$의 계산이라 처음 비용의 대부분이어서, 어느 원소가 한쪽 공식을 쓸 때만 계산해요(`_one_sided`). `hessian`은 늘 중앙 공식이라 빈 배열을 넘겨요. `order`는 18까지예요. 까닭은 [차수의 상한](/internals/differentiate/derivative/#차수의-상한)에 있어요. 계산하는 방법은 [derivative의 알고리즘](/internals/differentiate/derivative/#가중치를-정확하게)에 있어요.

## 사용자 함수를 부르는 꼴

### derivative: 원소별 함수

`derivative`의 f는 원소별 함수예요. `f(x)[i]`가 `f(x[i])`라는 scipy의 계약이에요. 그래서 원소마다 점을 여러 개 계산해야 할 때도 한 번에 부를 수 있어요. 첫 호출은 모든 원소의 x를 담은 (k,)이고, 그 뒤는 아직 멈추지 않은 원소만 모아 원소마다 p개의 점을 담은 (k, p)예요. p는 첫 반복에 스텐실의 점 수 2n(기본 `order=8`이면 8), 그 뒤 반복마다 2예요.

```python
>>> shapes = []
>>> def f(x):
...     shapes.append(tuple(x.shape))
...     return sd.exp(x)
>>> r = sd.differentiate.derivative(f, sd.asarray([0.0, 1.0, 2.0]))
>>> shapes
[(3,), (3, 8), (3, 2)]
>>> r.n_iter, r.nfev
(array([2, 2, 2], dtype=int64), array([11, 11, 11], dtype=int64))
```

셋 모두 둘째 반복에 멈췄으니 호출은 세 번이에요. 원소마다의 `nfev`는 그 원소의 값을 계산한 점의 수라 1 + 8 + 2 = 11이에요. 사용자의 `args`는 Python에서 배치 모양으로 브로드캐스트해 원소 n개로 펴 두고, 호출마다 남은 원소의 값만 모아 첫 호출에는 (k,), 그 뒤에는 (k, 1)로 넘겨요. (k, 1)이라 사용자 함수 안에서 `x * a` 같은 식이 (k, p)로 브로드캐스트돼요.

돌려받은 값은 C++가 먼저 봐요. 그 호출의 점과 같은 모양의 float64 `sd.ndarray`이면 그대로 읽어요. 아니면 Python의 확인 함수를 불러요. 확인 함수는 수의 시퀀스나 numpy 배열을 `sd.asarray`로 바꾸고, 정수 배열은 float64로 바꾸고, 모양이 틀리거나 실수가 아니면 함수 이름으로 시작하는 에러를 내요.

```python
# src/stardust/differentiate/_derivative.py
def _values(func):
    """check(value, shape) for derivative's kernel: what f returned, as a float64 sd.ndarray of
    its argument's shape, (k,) (an int) or (k, p) (a tuple), or the error (optimize's form)."""

    def check(v, shape):
        want = (shape,) if isinstance(shape, int) else tuple(shape)
        a = _real_array(v, func, "f")
        if a is None:
            raise ValueError(f"{func}(): 'f' must return shape {_shape_text(want)} like its argument, not a scalar")
        if tuple(a.shape) != want:
            raise ValueError(
                f"{func}(): 'f' must return shape {_shape_text(want)} like its argument, not {_shape_text(a.shape)}"
            )
        return a if a.dtype == _sd.float64 else a.astype(_sd.float64)

    return check
```

```python
>>> sd.differentiate.derivative(lambda x: x[..., :1] if x.ndim == 2 else x, [1.0, 2.0])
Traceback (most recent call last):
    ...
ValueError: derivative(): 'f' must return shape (2, 8) like its argument, not (2, 1)
```

사용자 함수가 낸 예외는 감싸지 않고 그대로 나가요. 커널 바깥 틀(`call_named`)은 커널 자신이 낸 에러에만 함수 이름을 붙여요.

### jacobian과 hessian: 벡터화된 함수

`jacobian`과 `hessian`의 f는 원소별이 아니에요. 출력 하나가 모든 변수에 달려 있으니까요. 대신 점 N개를 열로 쌓은 (m, N) 배열을 받아 출력을 열마다 계산한 (k, N)(스칼라 함수면 (N,))을 돌려주는 벡터화된 함수예요. 첫 호출은 열 m개가 모두 x인 (m, m)이고, 반복마다 변수마다 그 변수만 움직인 p개의 열을 이어 붙인 (m, m·p)예요.

```python
>>> shapes = []
>>> def F(X):
...     shapes.append(tuple(X.shape))
...     return sd.stack([X[0] ** 2 * X[1], sd.sin(X[0]) + X[1]])
>>> r = sd.differentiate.jacobian(F, [1.0, 2.0])
>>> shapes
[(2, 2), (2, 16), (2, 4)]
```

첫 호출의 꼴이 (k, N)인지 (N,)인지를 정하고, 그 뒤의 호출은 같은 꼴이어야 해요. 이 판정은 C++의 `Vectorized` 클래스가 해요. `hessian`의 f는 처음부터 스칼라 함수의 꼴 (N,)만 받아요. 틀린 모양의 에러에는 받은 인자의 모양도 적어요.

```python
>>> sd.differentiate.jacobian(lambda X: X[:, :1], [1.0, 2.0])
Traceback (most recent call last):
    ...
ValueError: jacobian(): 'f' must return shape (2,) or (k, 2) for its argument of shape (2, 2), not (2, 1)
```

이 두 함수의 반복은 [야코비안과 헤시안](/internals/differentiate/jacobian-hessian/)에 있어요.

## 원소별 고리

`derivative`의 반복은 `sd.optimize`의 배치 스칼라 함수(`find_root` 등)와 `sd.integrate`의 `tanhsinh`·`nsum`이 함께 쓰는 고리 `csrc/elementwise/loop.hpp`로 돌아요. scipy의 `eim._loop`에 해당하는 이 고리는 남은 원소만 모아 사용자 함수를 한 번 부르고, 원소를 한 번 지나가며 갱신, 판정, 압축을 해요. 고리의 부품(`Progress`, `advance`, `gather`, `Call`)과 원소의 상태를 구조체 하나에 모아 두는 까닭은 [배치 스칼라](/internals/optimize/batched/)에 있어요. 여기서는 `derivative`가 그 고리를 쓰는 모습을 봐요.

```cpp
        // csrc/differentiate/derivative.cpp
        Progress P(n);
        std::int64_t nit = 0, nfev = 1;
        std::vector<std::uint32_t> on;
        while (nit < max_iter && !P.active.empty()) {
            const bool first = nit == 0;
            const std::size_t k = P.active.size(), p = S.points(first);
            F.start(k, p);
            for_weighted(k, p, [&](std::size_t r0, std::size_t r1) {
                vec pts(p);
                for (std::size_t r = r0; r < r1; ++r) {
                    const E& e = el[static_cast<std::size_t>(P.active[r])];
                    points(S, e.side, e.x, e.h, first, pts.data());
                    for (std::size_t q = 0; q < p; ++q) F.put(r, q, pts[q]);
                }
            });
            F.run(P.active.data());
            nfev += static_cast<std::int64_t>(p);
            nit += 1;
            advance_weighted(P, on, p, [&](std::size_t r) {
                const auto i = static_cast<std::size_t>(P.active[r]);
                E& e = el[i];
                const int st = update(
                    S, e.side, e.x, e.h, &V[i * w], [&](std::size_t q) { return F.value(r, q); }, first, e.e, atol, rtol
                );
                e.h /= S.c;
                if (st == sInProgress) return true;
                P.status[i] = st;
                P.stopped(i, nit, nfev);
                return false;
            });
        }
        P.finish(nit, nfev);
```

반복 하나는 세 패스예요. 남은 원소 r마다 이번 반복의 점 p개를 (k, p) 배열의 r번째 줄에 쓰고(`points`), 사용자 함수를 한 번 부르고(`F.run`), 남은 원소마다 돌려받은 줄로 추정을 갱신해 멈춤을 판정해요(`update`). 간격 `e.h`는 갱신 뒤에 `step_factor`로 나눠 다음 반복의 간격이 돼요. `max_iter`에 닿을 때까지 남은 원소는 `P.finish`가 status −2로 멈춰요.

원소 하나의 상태는 `E`(x, 간격, 지금의 추정과 오차, 스텐실의 쪽)이고, 스텐실의 함숫값 2n + 1개는 원소마다 `V`의 한 토막(`w = 2n + 1`칸)에 둬요. 반복마다 바깥쪽 두 값이 빠지고 안쪽 두 값이 들어와요. 이 밀어 넣기도 `update`에 있어요.

### 점이 여러 개인 원소의 패스

optimize의 배치 함수는 원소마다 점이 하나라 남은 원소의 수로 스레드에 나눌지를 정해요. `derivative`는 원소마다 점이 2–`order`개라, 원소 수에 점 수를 곱한 일의 양으로 정해요. 그 판정이 `for_weighted`와 `advance_weighted`예요.

```cpp
// csrc/elementwise/loop.hpp
template <class Fn>
void for_weighted(std::size_t k, std::size_t w, Fn&& fn) {
    const std::size_t work = k * std::max<std::size_t>(w, 1);
    if (work >= kParallel && k > 1 && parallel::available()) {
        std::size_t per = std::max<std::size_t>(kTask / std::max<std::size_t>(w, 1), 1);  // elements a piece
        per = std::min(per, std::max<std::size_t>(k / kWoken, 1));
        const auto tasks = static_cast<std::int64_t>((k + per - 1) / per);
        parallel::parallel_for(tasks, [&](std::int64_t t) {
            const std::size_t r0 = static_cast<std::size_t>(t) * per;
            fn(r0, std::min(k, r0 + per));
        });
    } else {
        parallel::Unlocked u(work >= kParallel);
        fn(std::size_t{0}, k);
    }
}
```

일이 $2^{15}$점 이상이면 패스를 조각으로 나눠 스레드풀에 맡기고 그동안 GIL을 놓아요. 조각 하나는 $2^{13}$점쯤(적어도 원소 하나)이고, 조각이 17개보다 적으면 더 잘게 나눠요. 스레드풀은 일이 16개를 넘을 때 자는 일꾼을 깨우므로, 이렇게 해야 원소가 수천 개인 배치에서도 모든 일꾼이 함께 일해요. 첫 반복은 원소마다 8점이라 원소 4,096개부터, 그 뒤 반복은 2점이라 16,384개부터 나뉘어요.

원소의 산술은 어느 스레드에서 하든 같고, 계속 가는 원소는 압축한 뒤에도 원래 차례대로 남아요. 그래서 원소 하나의 결과는 스레드 수, 배치의 크기, 배치 안의 위치와 상관없이 비트까지 같아요.

```python
>>> x = sd.linspace(0.0, 2.0, 20001)
>>> r = sd.differentiate.derivative(sd.exp, x)
>>> one = sd.differentiate.derivative(sd.exp, float(x[12345]))
>>> one.df == float(r.df[12345]), one.nfev == int(r.nfev[12345])
(True, True)
```

scipy는 스텐실의 합을 행렬·벡터 곱(`fc @ wc`, BLAS)으로 해서, 같은 원소라도 배치의 행 수에 따라 끝자리가 달라질 수 있어요. 여기서는 원소마다 정해진 순서로 더해요([짝으로 더하기](/internals/differentiate/derivative/#짝으로-더하기)).

### 점의 사본을 두지 않는 호출

고리의 `Call`은 사용자 함수에 넘길 배열에 점을 쓰면서 커널 안에도 사본을 둘 수 있어요. 사용자 함수가 인자를 고쳐도 반복이 그 점을 다시 읽을 수 있게요. optimize의 배치 함수는 다음 걸음을 그 점에서 계산하므로 사본이 필요해요. `derivative`는 점을 다시 읽지 않고 원소의 x와 간격에서 언제든 다시 계산하므로, 사본을 두지 않는 `CallPoints`(`CallT<false>`)를 써요. 원소가 많고 점이 여러 개일 때 사본을 쓰는 일과 메모리가 들지 않아요. 사용자 함수가 받은 배열을 고쳐도 결과는 그대로예요.

```python
>>> def g(x):
...     y = sd.exp(x)
...     x[...] = 0.0
...     return y
>>> sd.differentiate.derivative(g, 1.0).df == sd.differentiate.derivative(sd.exp, 1.0).df
True
```

## jacobian과 hessian의 고리

`jacobian`은 원소별 고리를 쓰지 않아요. f가 원소별이 아니어서, 어느 항목(출력 i, 변수 j)이 멈췄다고 그 열만 빼고 부를 수 없기 때문이에요. 열 하나가 k개의 출력을 함께 내니까요. 그래서 모든 항목이 멈출 때까지 반복마다 모든 열을 부르고(scipy의 `preserve_shape=True`와 같아요), 항목마다 따로 판정해요. 갱신과 판정은 고리의 `Progress`와 `advance`를 그대로 써서, 항목이 $2^{15}$개 이상이면 그 패스가 스레드에 나뉘어요.

`hessian`은 기울기를 `jacobian`으로 계산하는 함수의 `jacobian`이에요. 바깥 `jacobian`의 "사용자 함수"가 C++ 객체 `Gradient`이고, 그 객체가 바깥 호출의 열마다 안쪽 `jacobian`을 한 번에 돌려요. 사용자 f를 부르는 것은 안쪽뿐이에요. 자세한 것은 [야코비안과 헤시안](/internals/differentiate/jacobian-hessian/)에 있어요.

## 결과 객체

`DifferentiateResult`는 `sd.optimize`의 `OptimizeResult`, `sd.integrate`의 `IntegrateResult`와 같은 바탕 클래스 `_FieldResult` 위의 클래스예요. 필드의 고정된 목록과 dict 하나로 되어 있고, 함수가 주지 않는 필드를 읽으면 `AttributeError`, 배열 필드는 복사하지 않는 읽기 전용 배열이에요. 바탕 클래스의 규칙은 [최적화의 결과 객체](/internals/optimize/overview/#결과-객체)에 있어요.

```python
# src/stardust/differentiate/_result.py
FIELDS = ("df", "ddf", "error", "converged", "status", "n_iter", "nfev", "x")
_REPR = ("df", "ddf", "error", "converged", "n_iter", "nfev")
```

세 함수가 같은 클래스를 쓰고 주는 필드가 달라요. `derivative`는 `df error converged status n_iter nfev x`, `jacobian`은 `x` 없이 같은 것, `hessian`은 `ddf error converged status nfev`예요. 결과는 커널이 막 만든 배열을 `_make`로 복사 없이 받아요. `converged`는 따로 계산하지 않고 `status == 0`에서 만들어요. 사용자가 부르는 공개 생성자 `DifferentiateResult(**fields)`는 다른 길이에요. 넘긴 `sd.ndarray`, numpy 배열, 수의 리스트를 결과 자신의 배열로 한 번 복사하고, 공통 필드의 종류(`converged`는 bool, `status`·`n_iter`·`nfev`는 정수)를 검사해요. 키워드로만 받으므로 위치 인자는 `DifferentiateResult(): takes 0 positional arguments but 1 was given`이에요.

```python
# src/stardust/differentiate/_derivative.py
def _fields(shape, df, err, status, nit, nfev):
    return dict(
        df=_shaped(df, shape),
        error=_shaped(err, shape),
        converged=_shaped(status == 0, shape),
        status=_shaped(status, shape),
        n_iter=_shaped(nit, shape),
        nfev=_shaped(nfev, shape),
    )
```

배치 모양은 `derivative`면 입력의 브로드캐스트 모양이고, 입력이 모두 수면 `()`라 필드가 Python 수예요. `jacobian`과 `hessian`의 결과는 항목마다 따로 멈춘 배치라 배치 모양이 `df`·`ddf`의 모양((k, m) 또는 (m,); (m, m))이에요. 그래서 `repr`과 `summary()`도 배치의 꼴(모양과 수렴한 수, 항목마다 한 줄)이에요. `summary()`의 상자는 다른 영역과 같은 그리기 함수로 만들어요.

## 차분 간격의 커널: steps.hpp와 _differences.py

### steps.hpp: 반복 안의 고정 간격

`sd.optimize`의 함수들은 사용자가 기울기나 야코비안을 주지 않으면 반복마다 차분으로 어림해요. 이때의 간격은 scipy `approx_derivative`(`'2-point'`, `'3-point'`)와 MINPACK `fdjac2`의 것을 그대로 따라야 scipy와 같은 점에서 함수를 불러요. 그 간격의 식이 `steps.hpp`의 다섯 함수예요.

| 함수 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `rel_step_2point`, `rel_step_3point` | 상대 간격 $\sqrt\varepsilon = 2^{-26}$, $\varepsilon^{1/3}$ | 아래 모두 |
| `absolute_step` | 변수 하나의 간격 $r\,\operatorname{sign}(x)\max(1, \lvert x\rvert)$, 상대 간격을 주면 $r\,\operatorname{sign}(x)\lvert x\rvert$ | `minimize`의 차분 기울기(`objective.hpp`), `least_squares`(`lsq.cpp`), `root_scalar` newton(`scalar.cpp`) |
| `adjust_one_sided` | 앞쪽 차분이 경계를 넘으면 뒤로 돌리거나 먼 경계까지로 | `objective.hpp`, `lsq.cpp`(nls의 'trf' 포함) |
| `adjust_two_sided` | 중앙 차분이 경계를 넘으면 안쪽 한쪽 3점으로 | `objective.hpp`, `lsq.cpp` |

헤더 하나이고 표준 라이브러리 말고는 아무것도 include하지 않아요. 반복의 셈(호출 수), 한쪽이 유한하지 않을 때 반대쪽을 다시 해 보는 일, 같은 점의 기억은 부르는 쪽마다 다르므로 부르는 쪽에 있어요. 식과 계산 순서, 경계에서의 조정은 [수치 미분](/internals/optimize/derivatives/)에서 코드와 함께 설명해요.

### _differences.py: 한 번의 정확한 차분

`approx_fprime`과 `check_grad`의 기본, 그리고 `sd.regression.nls`가 해에서 야코비안을 구할 때는 반복 안이 아니라 한 번의 정확한 결과가 필요해요. 그래서 scipy의 간격을 따르지 않고, 변수마다 간격을 골라 5점 차분으로 계산해요. 그 클래스가 `Differences`예요. 공개 이름은 아니라 `sd.differentiate.__all__`에 없어요.

```python
>>> from stardust.differentiate._differences import Differences
>>> from stardust.optimize import _diff
>>> from stardust.regression import _nls
>>> _diff.Differences is Differences, _nls._Differences is Differences
(True, True)
```

`Differences`는 `g(x)`를 부르는 일, 간격을 고르는 일, 반올림 수준을 재는 일만 해요. 호출 수를 세고 에러의 글을 쓰는 것은 부르는 쪽(`_diff.py`, `_nls.py`)이에요. nls만 반올림 수준에 묻힌 열을 0으로 두는 처리(`zero_noise`)를 켜요. 간격을 고르는 방법, 시작이 반올림 수준일 때 간격을 키우는 고리, 셈은 [수치 미분](/internals/optimize/derivatives/)에 있고, `derivative`의 차분과 견준 모습은 [derivative의 알고리즘](/internals/differentiate/derivative/#approx_fprime의-차분과-견주면)에 있어요.

<Callout type="note" title="두 차분이 따로 있는 까닭">
`derivative`는 간격을 반복마다 줄이며 오차를 어림하는 적응 방법이고, 원소별 배치를 한 번의 호출로 계산해요. `Differences`는 간격을 변수마다 한 번 고르고 nls의 반복 사이에서 그 간격을 다시 쓰며, 경계 안에서만 함수를 불러요. 부르는 꼴(점 하나씩의 벡터 함수)과 경계, 간격의 재사용이 달라서 한쪽으로 합치지 않아요.
</Callout>
