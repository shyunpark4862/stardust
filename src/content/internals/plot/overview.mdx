## 한눈에 보기

`sd.plot`은 다른 그림 라이브러리 위에 얹지 않고 자기 렌더러로 그려요. 그림 함수는 모두 `Figure`를 돌려주고, `Figure`는 칸들을, 칸은 층들을 가져요. 층은 그릴 자료와 그리는 법을 쥔 객체예요. 그림 함수와 고치는 메서드는 층과 설정만 바꾸고 아무것도 그리지 않아요. 출력을 달라고 할 때 그림 전체를 한 번 배치해 **장면**을 짓고, SVG·PDF·PNG 쓰기가 그 장면만 읽어요.

다른 영역은 "얇은 Python, 두꺼운 C++"인데 이 영역은 Python이 두꺼워요. 배치, 눈금, 범례, 장면 짓기는 다루는 도형이 수십에서 수백 개라서 Python으로 충분해요. 반복이 화소나 표본의 수만큼 도는 곳만 C++예요. 화소를 칠하는 래스터라이저와 깊이 버퍼, 격자를 넘기는 marching squares, 걸음마다 장을 읽으며 자라는 유선, 수만 개의 좌표를 글자로 쓰는 경로 쓰기가 그래요.

장면은 `fig.scene()`으로 dict로 볼 수 있어요. 쪽 크기는 bp(1/72인치)이고, 항목은 칠하는 차례대로 놓여요.

```python
>>> import math, collections
>>> fig = sd.plot.function(sd.sin, 0, 2 * math.pi)
>>> fig.xlabel(r"$x$").ylabel(r"$\sin x$") is fig
True
>>> scene = fig.scene()
>>> round(scene['width'], 3), fig.width
(252.283, 89.0)
>>> collections.Counter(i['type'] for i in scene['items'])
Counter({'path': 15, 'text': 14})
>>> scene['items'][0]['ops'], scene['items'][0]['fill']
('MLLLZ', [1.0, 1.0, 1.0, 1.0])
>>> [i['s'] for i in scene['items'] if i['type'] == 'text'][-4:]
['$0.5$', '$1.0$', '$x$', '$\\sin x$']
```

89 mm는 252.283 bp예요. 첫 항목은 쪽 전체를 덮는 흰 사각형이고, 경로 15개는 그 바탕, 곡선, 축 선, 눈금 12개예요. 글자는 문자열 그대로 남아 있어요. 글자가 윤곽선이 되는 것은 출력이 장면을 읽을 때예요([장면과 세 출력](/internals/plot/scene-outputs/)).

## 모듈 함수는 새 그림의 메서드예요

공개 그림 함수는 손으로 쓰지 않아요. `Figure`의 메서드를 하나 쓰고, 모듈을 읽을 때 `install`이 그 메서드를 `Figure`에 붙이면서 같은 이름의 모듈 함수를 만들어요.

```python
# src/stardust/plot/_basic.py
def module_function(name, method):
    """The module function of a Figure method: a new figure, then the method. A wrong call shape
    is reported as the other areas report it ("line(): unexpected keyword argument 'foo'")."""
    sig = inspect.signature(method)
    params = list(sig.parameters.values())[1:]
    public = inspect.Signature(params + [inspect.Parameter("figure", inspect.Parameter.VAR_KEYWORD)])
    names = {p.name for p in params if p.kind is inspect.Parameter.KEYWORD_ONLY}
    bound = _calls.method(name)(method)

    def f(*args, **kw):
        options = {k: kw.pop(k) for k in list(kw) if k in FIGURE_OPTIONS and k not in names}
        return bound(new_figure(name, options), *args, **kw)

    f.__name__ = f.__qualname__ = name
    f.__signature__ = public
    f.__doc__ = method.__doc__
    return f
```

모듈 함수의 시그니처는 메서드의 인자 뒤에 `**figure`를 붙인 것이에요. 부르면 키워드 가운데 그림 옵션(`FIGURE_OPTIONS`의 `width height font theme palette`)을 떼어 새 그림을 만들고, 남은 인자로 메서드를 불러요. 인자의 수나 이름이 맞지 않으면 Python이 내는 `TypeError`를 `_calls.method`가 다른 영역과 같은 꼴(`line(): unexpected keyword argument 'foo'`)로 바꿔요. 메서드 안에서 난 `TypeError`는 그대로 지나가요. 메서드 하나에서 둘이 나오므로 메서드와 모듈 함수의 인자, 기본값, 에러가 따로 놀 수 없어요. API 표면 테스트도 이것을 봐요([검증](/internals/plot/verification/)).

메서드 자신이 같은 이름의 키워드를 가지면 그 키워드는 메서드로 가요(`k not in names`). `line`의 `width`는 선 굵기라서 `sd.plot.line(x, y, width=1.0)`은 1 pt 선이고 그림 너비는 기본 89 mm 그대로예요. 이런 함수로 만든 그림의 크기는 `fig.size(...)`로 바꿔요.

```python
>>> fig = sd.plot.line([0.0, 1.0], [0.0, 1.0], width=1.0)
>>> fig.width
89.0
>>> fig.size(60).width
60.0
```

`grid`, `diagnostics`, `pairs`, `facet`처럼 칸 여럿을 스스로 만드는 함수는 메서드가 없고 모듈 함수만 있어요. 거꾸로 `compare`와 `fit`은 이미 있는 그림 위에 그리므로 메서드만 있어요.

## 칸과 보기

`fig[i, j]`는 칸을 복사하지 않아요. 뿌리 그림과 칸의 번호만 쥔 `Figure`를 하나 더 만들어요.

```python
    # src/stardust/plot/_figure.py
    def _view(self, index):
        v = object.__new__(Figure)
        v._root, v._index = self._root, index
        return v

    @property
    def _base(self):
        """The cell itself: what the title, the x axis, the legend and the insets belong to."""
        return self._root._cells[self._index]

    @property
    def _cell(self):
        """The cell the plotting methods and the y settings act on: of a twin() view, the cell of
        the second y axis."""
        c = self._base
        return c.twin if self.__dict__.get("_twinned") else c
    # ...
    def _touch(self):
        self._root._scene = None
        return self
```

메서드는 칸에 쓰고 `self._touch()`를 돌려줘요. 보기에서 부르면 그 칸에, 뿌리에서 부르면 첫 칸에 쓰고, 어느 쪽이든 뿌리가 지어 둔 장면을 버려요. 그래서 다음 출력이 장면을 다시 지어요. 크기, 글꼴, 테마, 팔레트, 장면 같은 그림 전체의 값은 뿌리에만 있어요.

칸을 내주는 속성은 둘이에요. `_base`는 칸 자체이고, `_cell`은 그림 메서드와 y축 설정이 쓸 칸이에요. 보통의 보기에서는 둘이 같은 칸이에요. `fig.twin()`이 돌려주는 것도 같은 보기인데 `_twinned` 표시가 붙어 있어서, `_cell`이 칸 대신 그 칸의 두 번째 y축 칸(`cell.twin`)을 내줘요. 그래서 그림 메서드와 `ylabel`·`ylim`·`yscale`·`yticks`가 한 줄도 바뀌지 않고 오른쪽 축에 쓰여요. 두 축이 함께 쓰는 것(`title`, `xlabel`·`xlim`·`xscale`·`xticks`, `legend`, `inset`)은 `_base`에 쓰므로, twin 보기에서 불러도 칸의 것이 돼요([배치](/internals/plot/layout/)).

```python
>>> fig = sd.plot.Figure(ncols=2)
>>> right = fig[0, 1]
>>> right.line([0.0, 1.0], [1.0, 0.0]) is right
True
>>> [len(c.layers) for c in fig._cells], right.shape
([0, 1], (1, 2))
```

`sd.plot.grid`는 받은 그림들의 칸을 복사해 새 그림의 칸 자리에 넣어요. 보기를 받으면 그 칸 전체(`_base`)를 복사하므로, twin 보기를 주어도 두 y축이 함께 들어가요. `Cell.copy`가 칸의 설정과 층 목록을 따로 만들므로, 모은 뒤에 원래 그림을 고쳐도 모은 그림은 그대로이고 거꾸로도 같아요. 남는 자리는 축이 없는 빈 칸이에요.

```python
>>> a = sd.plot.line([0.0, 1.0], [0.0, 1.0])
>>> g = sd.plot.grid([a, a], ncols=2)
>>> a.line([0.0, 1.0], [1.0, 0.0]) is a
True
>>> len(a._cells[0].layers), [len(c.layers) for c in g._cells]
(2, [1, 1])
```

## 그릴 때까지 미루기

그림 함수가 하는 계산은 표본까지예요. 함수 그림은 메서드를 부를 때 함수를 불러 표본을 고르고([곡선의 표본](/internals/plot/sampling/)), 그 결과를 층에 넣어요. 축의 범위, 눈금, 글자의 크기, 여백은 출력할 때 한 번에 정해요. 라벨 하나를 바꿀 때마다 배치를 다시 할 까닭이 없고, 라벨에 따라 여백이 달라지므로 미리 정할 수도 없어요.

```python
    # src/stardust/plot/_figure.py
    def _build(self, who, dpi=300.0):
        r = self._root
        # a figure with a 3D cell holds a picture made for one resolution
        if r._scene is not None and getattr(r, "_scene_dpi", dpi) != dpi and any(not c.frame for c in r._cells):
            r._scene = None
        if r._scene is None:
            try:
                r._scene = _layout(r, dpi)
                r._scene_dpi = dpi
            except _text.TypesetError as e:
                raise ValueError(f"{who}(): {e}") from None
            except _text.MissingTool as e:
                raise RuntimeError(f"{who}(): {e}") from None
        return r._scene
```

지은 장면은 뿌리에 남아 있다가 다음 출력이 그대로 써요. 3D 칸이 있는 그림은 장면 안에 정해진 해상도로 구운 그림이 들어 있어서 다른 `dpi`를 달라고 하면 다시 지어요. 2D만 있는 그림의 장면은 해상도와 무관해요.

조판이 장면을 짓는 중에 일어나므로 조판 오류는 그 출력 메서드의 이름으로 나요. TeX가 실패하면 `ValueError`, TeX 프로그램이 없으면 `RuntimeError`예요. 묶음을 깨뜨리는 문자열은 TeX에 넘기기 전에 막아요.

```python
>>> sd.plot.line([0.0, 1.0], [0.0, 1.0]).xlabel("50% of").to_svg()
Traceback (most recent call last):
    ...
ValueError: to_svg(): LaTeX could not typeset '50% of': an unescaped % (write \%)
```

## 3D 칸

3D 그림 함수는 칸에 `Space` 층 하나를 두고, 그 칸의 `frame`을 끄고, 곡면·곡선·점을 그 `Space`에 모아요. 한 칸에 2D 층과 3D 층을 섞을 수 없어요. `install`이 `Figure`에 붙이는 2D 그림 메서드를 `flat_only`로 감싸서 `Space`가 든 칸에 부르면 `ValueError`를 내고(새 그림을 만드는 모듈 함수는 감쌀 까닭이 없어요), 3D 메서드는 2D 층이 있는 칸을 거절해요. 축 설정(`xlim ylim xscale yscale xticks yticks`)도 3D 칸에서는 `ValueError`예요. 3D 상자의 범위는 자료가 정해요.

```python
>>> sd.plot.surface(lambda x, y: x * y, -1, 1, -1, 1).line([0.0, 1.0], [0.0, 1.0])
Traceback (most recent call last):
    ...
ValueError: line(): the cell already holds a 3D plot
```

배치는 3D 칸을 축이 없는 칸으로 다뤄요. 대신 `Space`가 두 가지를 알려 줘요. `margins`는 상자 둘레의 눈금 숫자와 축 이름이 차지할 여백이고, `aspect`는 상자를 화면에 투영한 모양의 세로 대 가로예요. 그림의 높이를 주지 않으면 3D 칸만 있는 줄은 이 비율로 높이를 정하고, 2D 칸이 섞인 줄은 2D 칸의 4:3을 따라요.

그릴 때 `Space`는 장면에 세 겹을 쌓아요. 먼저 상자의 뒤쪽 세 면과 그 격자를 벡터 경로로, 그 위에 곡면·곡선·점을 깊이 버퍼로 구운 그림(`Image`) 한 장을, 맨 위에 앞쪽 모서리의 축과 눈금과 이름을 벡터로 그려요. 그래서 3D 그림의 PDF·SVG에서도 글자와 축은 벡터예요. 시점 고르기는 [카메라](/internals/plot/camera/), 그림을 굽는 깊이 버퍼는 [깊이 버퍼](/internals/plot/zbuffer/)에서 다뤄요.

```python
>>> left = sd.plot.function(sd.special.gamma, -4, 4).xlabel(r"$x$").ylabel(r"$\Gamma(x)$")
>>> right = sd.plot.surface(lambda x, y: x * y * sd.exp(-(x * x + y * y)), -2, 2, -2, 2)
>>> fig = sd.plot.grid([left, right], ncols=2, labels="A")
>>> fig.shape, fig.width
((1, 2), 178.0)
>>> [c.frame for c in fig._cells]
[True, False]
```

## C++이 맡는 것

C++ 쪽은 `stardust._core.plot` 하나로 묶여 있어요.

| 이름 | 하는 일 | 부르는 곳 |
|---|---|---|
| `Canvas` | 2D 래스터라이저. `fill`, `stroke`, `markers`, `image`로 칠하고 `rgba8`로 화소를 내줘요 | PNG 출력, 큰 점 묶음의 그림, 범례 자리를 고를 때의 잉크 지도 |
| `render3` | 삼각형, 선, 원판을 깊이 버퍼로 그린 그림 한 장 | 3D 칸 |
| `view_scores` | 시점 후보마다 곡면이 보이는 넓이의 점수 | 3D 칸의 시점 고르기 |
| `Levels` | 격자 위의 수준선(marching squares): 변의 교점, 곡선 잇기, 안쪽 다각형 | 음함수, 영역, 등고선 |
| `streamlines` | 격자에 잰 벡터장의 유선을 상자에 고르게 퍼뜨려 따라가기 | 유선 그림 |
| `path_text` | 경로의 좌표를 SVG 경로 글이나 PDF 연산자로 쓰기 | SVG, PDF |
| `decimate` | 점이 아주 많은 선을 열마다 네 점으로 줄이기 | 긴 선 |
| `simplify` | 꺾은선에서 곧은 줄 위의 점을 빼기(Ramer–Douglas–Peucker) | 선 층, 윤곽선 |
| `colormap`, `phase_colors` | 값을 색띠의 색으로, 복소수를 위상의 색으로 | 밀도, 열지도, 위상 그림 |

Python은 경로를 `ops` 바이트(`"MLQCZ"` 위의 글자)와 float64를 이어 붙인 바이트로 넘기고, 행렬과 색과 자르기 사각형은 수로 넘겨요. 바인딩은 개수가 맞지 않거나 모르는 연산이 오면 `ValueError`를 내요. 사용자의 값은 이미 Python 쪽에서 검사했으므로, 여기서 나는 에러는 영역 안의 실수예요. 화소를 칠하는 방법은 [래스터라이저](/internals/plot/raster/)에서 다뤄요.

## 다른 영역과의 관계

`sd.plot`은 맨 위 층이에요. 다른 영역을 쓰기만 하고, 어느 영역도 `sd.plot`을 가져오지 않아요.

- **배열**: 자료는 모두 float64 `sd` 배열로 바꿔 쓰고, 좌표 변환과 표본 계산은 배열 연산이에요. 히스토그램의 막대는 `sd.histogram`, 상자 그림의 사분위와 자동 범위의 분위수는 `sd.quantile`이 내요.
- **frame**: `data=`에 `DataFrame`을 주면 열 이름으로 자료를 꺼내요.
- **random**: `strip`의 흩음은 `sd.random`의 생성기예요. 씨를 주지 않으면 0으로 고정해 같은 호출이 같은 그림이에요.
- **stats**: `qq`의 기본 분포는 표준정규분포이고 분위수는 분포의 `icdf`예요. `distribution`은 분포 객체를 받아요. 수 하나를 받는 인자(오차 막대의 `xerr`·`yerr`, `area`의 `y2`)와 함수가 돌려준 상수는 stats의 `_real_option`으로 가려요. numpy의 정수·실수 스칼라도 수로 받고, `bool`과 `numpy.bool`은 수로 보지 않아요. 개수를 받는 인자(`samples`, `refine`, `levels`의 개수, `mesh`, `contours`, `strip`의 `rng` 씨)도 같은 뜻으로 `numbers.Integral`을 받아 `operator.index`로 바꿔요.
- **regression, htest**: `fit`, `compare`, `diagnostics`, `coefficients`는 결과 객체의 속성(`params`, `predict`, `pvalue` 등)을 읽어요. 검정이나 회귀를 그림 안에서 다시 하지 않아요.
- **optimize**: 인자 검사 함수(`_check_choice`, `_check_bool`)를 함께 써서 메시지의 꼴이 같아요.

통계 그림이 계산을 계산 영역에 맡기는 자세한 모습은 [통계 그림](/internals/plot/stat/)에서 다뤄요.

## 바깥 프로그램 TeX

라이브러리에서 실행 중에 바깥 프로그램을 부르는 영역은 `sd.plot`뿐이에요. 글자를 모두 LaTeX가 조판하기 때문이에요. 쓰는 프로그램은 TeX Live의 `latex`(pdfLaTeX 길), `xelatex`(한글 길), `tex`·`xetex`(글리프 하나씩의 쪽), `dvisvgm`(윤곽선), `kpsewhich`(글꼴 파일 찾기)예요.

`import stardust`가 `sd.plot`도 읽지만 TeX는 찾지 않아요. 프로그램은 처음 필요할 때 `PATH`에서, 없으면 `/Library/TeX/texbin`에서 찾고 찾은 경로를 기억해요. 그래서 TeX가 없는 기계에서도 다른 영역은 그대로 쓰고, `sd.plot`은 그림을 만들고 고치는 것까지는 되며 출력할 때 `RuntimeError`가 나요. 문자열의 배치와 글리프의 윤곽선은 디스크 캐시에 남으므로, 한 번 본 글자로 된 그림은 TeX를 부르지 않아요([글자](/internals/plot/text/)).

<Callout type="note">
테스트는 TeX를 부르지 않아요. 테스트 그림이 쓰는 모든 문자열의 배치와 윤곽선을 저장소에 기록해 두고 그 기록만 읽어요. TeX를 실제로 부르는 테스트는 따로 있어요([검증](/internals/plot/verification/)).
</Callout>
