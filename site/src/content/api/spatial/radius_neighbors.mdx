## 한눈에 보기

`radius_neighbors`는 질의점마다 데이터에서 **거리가 r 이하인 점을 모두** 찾아요. "가까운 것 k개"가 아니라 "이 거리 안에 있는 것 전부"를 묻는 질문이에요. 반경 1 km 안의 가게, 비슷도가 일정 수준을 넘는 문서, 밀도 기반 군집(DBSCAN)의 이웃처럼 기준 거리가 정해진 문제에 맞아요.

```python
>>> import stardust as sd
>>> rng = sd.random.default_rng(3)
>>> XB = rng.random((60, 2))
>>> XA = sd.asarray([[0.3, 0.65], [0.7, 0.3]])
>>> res = sd.spatial.radius_neighbors(XA, XB, 0.2)
>>> res
RadiusResult(shape=(2, 60), nnz=13)
>>> res.indptr
array([ 0,  5, 13], dtype=int64)
>>> res.indices
array([25, 30, 33, 42, 53, 11, 19, 22, 26, 34, 47, 50, 54], dtype=int64)
```

반경 0.2 안에 첫 질의점은 다섯 점(25, 30, 33, 42, 53), 둘째 질의점은 여덟 점이 있어요. 이웃의 수가 질의점마다 다르므로, 결과는 목록을 이어 붙인 `indices`와 행마다 어디서 시작하는지 적은 `indptr`로 와요.

## 결과 읽기

결과는 [`RadiusResult`](/api/spatial/results/#radiusresult)예요. 질의점 i의 이웃은 `indices[indptr[i]:indptr[i+1]]`이고, 그 거리는 `distances`의 같은 범위예요. 행 안은 **색인 오름차순**이에요. 반경 안의 점은 모두 답이라 순위가 없어서, 언제나 같은 순서가 되도록 색인으로 세워요.

```python
>>> for row in range(res.shape[0]):
...     s, e = res.indptr[row], res.indptr[row + 1]
...     print(row, res.indices[s:e].tolist())
0 [25, 30, 33, 42, 53]
1 [11, 19, 22, 26, 34, 47, 50, 54]
```

모든 배열은 쓰기 금지이고, 읽을 때 복사하지 않아요. 결과를 행렬로 다루고 싶으면 `tocsr()`로 희소 행렬을 받아요(아래 [이웃 그래프로](#이웃-그래프로-tocsr)).

### 정의로 정해지는 결과

행 i는 [`cdist(XA, XB)`](/api/spatial/cdist/)의 행 i에서 거리가 r 이하인 열 번호 전부(오름차순)와 그 거리예요. 거리는 `cdist`의 그 칸과 마지막 비트까지 같고, 반경 안인지 판정할 때 쓰는 거리도 돌려주는 거리 그 자체예요. 계산 방법(모든 짝 재기, 행렬 곱으로 후보 추리기, KD 트리)은 입력의 모양으로 고르고 결과를 바꾸지 않아요. 스레드 수와도 상관없이 같은 결과예요.

## r: 반경

### 경계는 넣어요

거리가 꼭 r인 점도 이웃이에요($d \le r$). 판정하는 거리가 돌려주는 거리 그대로라서, 돌려준 거리가 r과 같으면 언제나 들어가고 r보다 크면 언제나 빠져요.

```python
>>> X = sd.asarray([[0.0, 0.0], [3.0, 4.0], [6.0, 8.0], [0.0, 1.0], [0.0, 1.0]])
>>> b = sd.spatial.radius_neighbors(X[1:2], X, 5.0)
>>> b.indices, b.distances
(array([0, 1, 2, 3, 4], dtype=int64), array([              5.0,               0.0,               5.0,
       4.242640687119285, 4.242640687119285], dtype=float64))
```

점 1 (3, 4)에서 점 0과 점 2까지는 꼭 5라서 반경 5에 들어가요. 경계를 빼고 싶으면($d \lt r$) 반경을 그보다 조금 작은 값으로 주거나, 가까운 k개를 엄격한 상한으로 찾는 [`kneighbors`의 `distance_upper_bound`](/api/spatial/kneighbors/#distance_upper_bound-이보다-가까운-것만)를 써요.

### 질의점마다 다른 반경

`r`에 배열을 주면 질의점마다 반경이 달라요. 길이는 mA여야 하고, 길이 1인 배열은 모든 질의점에 같이 써요.

```python
>>> sd.spatial.radius_neighbors(XA, XB, [0.1, 0.3], return_length=True)
array([ 2, 13], dtype=int64)
```

길이가 맞지 않으면 `ValueError`예요.

```python
>>> sd.spatial.radius_neighbors(X, X, [1.0, 2.0])
Traceback (most recent call last):
    ...
ValueError: radius_neighbors(): 'r' of shape (2,) does not broadcast to the 5 rows of 'XA'
```

### r = 0과 r = inf

`r=0`은 같은 자리의 점만 찾아요. 중복된 점을 찾는 데 쓸 수 있어요.

```python
>>> z = sd.spatial.radius_neighbors(X, X, 0.0)
>>> sd.diff(z.indptr)
array([1, 1, 1, 2, 2], dtype=int64)
```

점 3과 점 4는 서로 같은 자리라 이웃이 둘(자기 자신과 상대)이에요.

`r=inf`면 거리가 inf인 짝도 들어가요($\infty \le \infty$). 거리가 NaN인 짝은 어떤 r에도 들어가지 않아요. NaN은 어떤 수와도 크기를 견줄 수 없기 때문이에요.

```python
>>> big = sd.asarray([[0.0], [1e200], [3.0]])
>>> sd.spatial.radius_neighbors(big[:1], big, sd.inf, metric="sqeuclidean").indices
array([0, 1, 2], dtype=int64)
>>> A = sd.asarray([[1.0, 0.0]])
>>> B = sd.asarray([[0.0, 0.0], [1.0, 1.0], [2.0, 0.0]])
>>> sd.spatial.radius_neighbors(A, B, sd.inf, metric="cosine").indices
array([1, 2], dtype=int64)
```

첫 예에서 0과 1e200의 제곱 거리는 float64의 범위를 넘어 inf지만 반경 inf에는 들어가요. 둘째 예에서 영벡터 (0, 0)과의 `cosine` 거리는 NaN이라 빠져요.

반경은 0 이상의 수나 inf여야 해요. 음수와 NaN은 `ValueError`, `True` 같은 bool은 `TypeError`예요.

```python
>>> sd.spatial.radius_neighbors(X, X, -1)
Traceback (most recent call last):
    ...
ValueError: radius_neighbors(): 'r' must be a number >= 0 or inf, not -1
```

## return_length: 개수만

이웃이 누구인지는 필요 없고 몇 개인지만 필요하면 `return_length=True`를 줘요. 목록을 모으지 않으니 메모리가 거의 들지 않고, 결과는 보통의 int64 배열이에요.

```python
>>> sd.spatial.radius_neighbors(XA, XB, 0.2, return_length=True)
array([5, 8], dtype=int64)
```

목록을 받은 뒤 `sd.diff(res.indptr)`로 세도 같은 값이에요. 반경 안의 점 수는 그 자리의 밀도를 재는 가장 단순한 방법이에요. 반경이 여럿이거나 두 점 집합 사이의 짝 전체를 세려면 [`KDTree.count_neighbors`](/api/spatial/count_neighbors/)가 한 번에 세요.

## 이웃 그래프로: tocsr()

`res.tocsr()`는 (mA, mB)의 [`sd.sparse.csr_array`](/api/sparse/csr_array/)예요. 행 i, 열 j에 질의점 i와 데이터 점 j의 거리가 있고, 반경 밖의 칸은 저장하지 않아요. 점을 꼭짓점, 이웃 짝을 변으로 본 **이웃 그래프**라서 희소 행렬의 계산으로 그대로 넘길 수 있어요.

```python
>>> G = sd.spatial.radius_neighbors(X, X, 1.0).tocsr()
>>> G
<csr_array of shape (5, 5), float64, 11 stored elements>
>>> G.nnz, G.count_nonzero()
(11, 4)
```

저장한 원소는 11개인데 0이 아닌 값은 4개예요. 자기 자신과의 짝과 같은 자리의 점 3, 4의 짝은 거리가 0이라 **저장된 0**으로 들어 있어요. 거리가 0이어도 이웃은 이웃이라서 변을 지우지 않아요. 값으로만 계산할 때는 `eliminate_zeros()`로 지워요. 이 규칙과 `tocsr()`의 결과를 고치는 법은 [결과 객체 읽기](/api/spatial/results/#희소-행렬로-tocsr)에 있어요.

## 거리 고르기

`metric`과 그 인자(`p`, `w`, `V`, `VI`)는 [`cdist`](/api/spatial/cdist/)와 같은 규칙이에요. 같은 반경이라도 거리에 따라 "반경 안"의 모양이 달라요. 유클리드 거리의 반경은 원, `cityblock`은 마름모, `chebyshev`는 정사각형이에요.

```python
>>> sd.spatial.radius_neighbors(X, X, 1.0, metric="cityblock", return_length=True)
array([3, 1, 1, 3, 3], dtype=int64)
```

### 지도 위의 반경: haversine

`metric='haversine'`의 거리는 반지름 1인 구 위의 중심각이에요. 지구 위의 반경 R km는 $R / 6371$(지구의 평균 반지름)로 바꿔서 줘요. 아래는 서울에서 900 km 안의 도시예요.

```python
>>> names = ["서울", "부산", "도쿄", "베이징", "상하이", "오사카"]
>>> lat = [37.5665, 35.1796, 35.6762, 39.9042, 31.2304, 34.6937]
>>> lon = [126.9780, 129.0756, 139.6503, 116.4074, 121.4737, 135.5023]
>>> P = sd.deg2rad(sd.asarray([lat, lon]).T)
>>> near = sd.spatial.radius_neighbors(P[:1], P, 900 / 6371.0, metric="haversine")
>>> [names[j] for j in near.indices.tolist()]
['서울', '부산', '상하이', '오사카']
>>> near.distances * 6371.0
array([              0.0, 325.1112588497627, 866.4505561170181,
       829.1197922569398], dtype=float64)
```

베이징(약 952 km)과 도쿄(약 1149 km)는 반경 밖이에요. 판정은 [`haversine`](/api/spatial/haversine/)이 돌려주는 중심각 그대로로 해요. 위도와 경도는 라디안으로 넣어요.

## 큰 데이터에서

`radius_neighbors`는 (mA, mB)의 거리 행렬을 만들지 않아요. 작업 메모리는 입력의 크기와 상관없는 상한 안이고, 결과만 찾은 짝의 수에 비례해요(짝 하나에 색인 8바이트와 거리 8바이트). 반경을 크게 잡으면 짝의 수가 mA × mB에 가까워질 수 있으니 조심해요. 찾은 짝이 물리 메모리를 넘을 만큼 많아지면 그 자리에서 찾기를 멈추고 `MemoryError`를 내요. 개수만 필요하면 `return_length=True`가 목록을 모으지 않아요.

같은 데이터 점에 반경 질의를 여러 번 한다면 [`KDTree`](/api/spatial/KDTree/)를 한 번 만들어 [`query_ball_point`](/api/spatial/query_ball_point/)를 되풀이하는 편이 나아요. 두 점 집합 모두로 트리를 만들어 함께 내려가는 [`query_ball_tree`](/api/spatial/query_ball_tree/)도 있어요. 세 함수의 결과는 같은 `RadiusResult`이고 바이트까지 같아요(Minkowski 계열 거리에서).

```python
>>> tree = sd.spatial.KDTree(XB)
>>> q = tree.query_ball_point(XA, 0.2)
>>> bool(sd.all(q.indices == res.indices)), bool(sd.all(q.indptr == res.indptr))
(True, True)
```

## 조심할 점

### 자기 자신도 들어가요

`XA`와 `XB`가 같은 집합이면 모든 점이 자기 자신을 이웃으로 가져요(거리 $0 \le r$). 다른 점만 세려면 행마다 1을 빼거나, 행의 목록에서 자기 색인을 걸러 내요. 같은 자리의 점은 서로를 이웃으로 가지니 함께 빠지지 않게 조심해요.

```python
>>> sd.spatial.radius_neighbors(X, X, 1.0, return_length=True) - 1
array([2, 0, 0, 2, 2], dtype=int64)
```

### r은 자리로

`r`은 옵션이 아니라 질문의 일부라 자리로 받아요. `r=1.0`처럼 이름을 붙이면 `TypeError`예요. 반대로 `metric`, `return_length` 같은 옵션은 이름을 붙여야 해요.

```python
>>> sd.spatial.radius_neighbors(X, X, r=1.0)
Traceback (most recent call last):
    ...
TypeError: radius_neighbors(): got some positional-only arguments passed as keyword arguments: 'r'
```

### NaN·inf가 있으면 에러

데이터와 질의점의 NaN·inf는 `ValueError`예요. 거리 함수와 달리 이웃 찾기는 NaN을 내보내지 않아요([공간 영역의 기본](/api/spatial/basics/#nan과-inf)).

## scipy·sklearn을 아는 분께

- scipy에는 이 함수가 없어요. `KDTree(XB).query_ball_point(XA, r)`, `KDTree(XA).query_ball_tree(KDTree(XB), r)`와 같은 결과이고(Minkowski 계열), 다른 거리도 받아요. 이름은 sklearn `NearestNeighbors`의 메서드에서 왔고, `NearestNeighbors(radius=r).fit(XB).radius_neighbors(XA)`가 이것이에요. 클래스는 없어요.
- 결과는 언제나 `RadiusResult`이고 행 안은 색인 오름차순이에요. sklearn은 행마다 배열을 담은 object 배열 둘을 주고 기본으로 정렬하지 않아요(`sort_results=False`). scipy의 `query_ball_point`는 점 하나면 list, 여럿이면 list의 object 배열이에요.
- sklearn의 `radius_neighbors_graph(X, r, mode='distance')`는 `radius_neighbors(X, X, r).tocsr()`예요. 거리가 0인 짝은 저장된 0으로 남아요.
- 경계를 넣어요($d \le r$, scipy와 같아요). 판정은 돌려주는 거리 그대로예요. scipy는 제곱한 자리에서 견주어, 돌려줄 거리가 r과 같은 짝의 판정이 $\sqrt{\ }$를 씌운 값과 갈릴 수 있어요.
- 음수와 NaN 반경은 `ValueError`예요. scipy는 $r = -1$을 $r = 1$처럼, NaN을 빈 목록으로 다뤄요.
- `workers`, `eps`, `return_sorted`, 호출 가능한 `metric`은 없어요. 결과는 언제나 정확해요.
