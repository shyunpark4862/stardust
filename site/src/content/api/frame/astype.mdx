## 한눈에 보기

`astype`은 컬럼의 값 종류(dtype)를 바꿔요. 원래 표는 그대로 두고, 종류가 바뀐 새 표를 돌려줘요. 데이터프레임의 dtype은 `sd.bool`, `sd.int64`, `sd.float64`, `sd.string` 넷이에요([모양, 이름, dtype](/api/frame/attributes/)).

가장 흔한 장면은 숫자가 문자열로 들어 있을 때예요. 다른 프로그램에서 받은 데이터나 손으로 만든 표에서는 `"12.5"`처럼 숫자가 글자로 들어 있곤 해요. 이대로는 평균도 덧셈도 할 수 없어요.

```python
>>> import stardust as sd
>>> raw = sd.frame.DataFrame({
...     "city": ["Seoul", "Busan", "Jeju"],
...     "temp": ["12.5", "15.0", None],
...     "rain": ["0", "3", "1"],
... })
>>> raw.dtypes
{'city': string, 'temp': string, 'rain': string}
>>> raw["temp"].mean()
Traceback (most recent call last):
    ...
TypeError: mean(): cannot compute mean of a string column
```

`astype`으로 숫자 컬럼으로 바꾸면 계산할 수 있어요. DataFrame에는 `{컬럼 이름: dtype}` dict를 줘서 컬럼마다 다른 종류로 바꿔요. dict에 없는 컬럼(`city`)은 그대로예요.

```python
>>> df = raw.astype({"temp": "float64", "rain": sd.int64})
>>> df
    city  temp  rain
0  Seoul  12.5     0
1  Busan  15.0     3
2   Jeju  <NA>     1
>>> df.dtypes
{'city': string, 'temp': float64, 'rain': int64}
>>> df["temp"].mean()
13.75
```

비어 있던 `Jeju`의 `temp`는 바뀐 뒤에도 `NA`예요. `NA`는 어떤 종류로 바꿔도 `NA`로 남아요.

Series는 dtype 하나를 받아요. dtype은 객체(`sd.float64`)로 써도, 이름(`"float64"`)으로 써도 돼요.

```python
>>> s = sd.frame.Series([3, None, 5], name="qty")
>>> s.astype(sd.float64)
0     3.0
1    <NA>
2     5.0
Name: qty, dtype: float64
```

## 변환 규칙

네 종류 사이에서는 어느 쪽으로든 바꿀 수 있어요. 숫자끼리(bool, int64, float64)의 규칙은 배열의 [`astype`](/api/array/astype/)과 같아요. 문자열이 끼는 변환은 데이터프레임에만 있어요.

| 바꾸기 전 → 후 | 어떻게 바뀌나요 |
|---|---|
| bool → int64, float64 | `True`는 1, `False`는 0 |
| int64 → float64 | 같은 값. 단, 2⁵³보다 큰 정수는 가장 가까운 실수로 |
| float64 → int64 | 소수점 아래를 버려요(0 쪽으로). NaN은 0, 범위 밖과 ±inf는 int64의 최댓값·최솟값 |
| int64, float64 → bool | 0이면 `False`, 아니면 `True`. NaN은 `True` |
| 무엇이든 → string | Python의 `str()`로 쓴 글자 |
| string → int64 | 정수 문법에 맞아야 해요. 아니면 `ValueError` |
| string → float64 | 실수 문법에 맞아야 해요. 아니면 `ValueError` |
| string → bool | `"True"`와 `"False"`만. 나머지는 `ValueError` |
| `NA` → 무엇이든 | `NA` |

숫자끼리의 변환은 값이 달라져도 에러를 내지 않아요. 문자열에서 바꾸는 변환만 에러가 날 수 있어요. 글자가 숫자로 읽히지 않으면 바꿀 값 자체가 없기 때문이에요.

### 넓은 쪽으로: 값이 그대로예요

`bool < int64 < float64` 순서에서 오른쪽으로 바꾸면 값을 잃지 않아요.

```python
>>> sd.frame.Series([True, False, None]).astype("int64")
0       1
1       0
2    <NA>
dtype: int64
```

예외가 하나 있어요. float64는 2⁵³(약 9 × 10¹⁵)보다 큰 정수를 모두 정확히 담지는 못해서, 그런 정수는 가장 가까운 실수로 바뀌어요. 보통 쓰는 크기의 정수에서는 생기지 않는 일이에요.

```python
>>> sd.frame.Series([2**53 + 1]).astype("float64").tolist()
[9007199254740992.0]
```

### 실수 → 정수: 버림이에요

실수를 정수로 바꾸면 소수점 아래를 버려요. 0 쪽으로 자르기 때문에 양수는 내려가고 음수는 올라가요. 반올림이 아니에요.

```python
>>> x = sd.frame.Series([1.7, -1.7, 0.5, None])
>>> x.astype("int64")
0       1
1      -1
2       0
3    <NA>
dtype: int64
```

NaN(숫자가 아님)과 무한대는 정수로 나타낼 수 없어요. 이때도 에러를 내지 않아요. NaN은 `0`으로, int64가 담을 수 없을 만큼 크거나 작은 값은 int64의 최댓값이나 최솟값으로 바꿔요(포화).

```python
>>> sd.frame.Series([sd.nan, sd.inf, -sd.inf, 1e300]).astype("int64")
0                      0
1    9223372036854775807
2   -9223372036854775808
3    9223372036854775807
dtype: int64
```

<Callout type="warn" title="NaN은 조용히 0이 되고, NA만 NA로 남아요">

NaN과 `NA`는 다른 것이에요. `NA`는 "값이 없음"이라서 정수 컬럼에서도 `NA`로 남지만, NaN은 float의 한 값이라서 정수로 바꾸면 에러 없이 `0`이 돼요. 진짜 0과 구별할 수 없게 되니, 바꾸기 전에 [`isnan`](/api/frame/isna/)으로 NaN이 있는지 확인하세요. 두 결측의 차이는 [NA와 NaN](/api/frame/na/)에 있어요.

</Callout>

### 숫자 → bool: 0인가 아닌가

bool로 바꾸면 0이면 `False`, 0이 아니면 `True`예요. `-0.0`은 0이라서 `False`, NaN은 0이 아니라서 `True`예요.

```python
>>> sd.frame.Series([0.0, -0.0, sd.nan, 0.1, None]).astype("bool")
0    False
1    False
2     True
3     True
4     <NA>
dtype: bool
```

### → string: Python의 `str()`과 같아요

어느 종류든 문자열로 바꾸면, 값을 Python의 `str()`로 쓴 글자가 돼요. 실수는 늘 소수점이나 지수가 붙고(`1.0`, `1e+20`), 정수는 소수점 없이, bool은 `True`·`False`예요.

```python
>>> f = sd.frame.Series([1.0, 2.5, 1e20, sd.nan, None]).astype("string")
>>> f
0      1.0
1      2.5
2    1e+20
3      nan
4     <NA>
dtype: string
>>> f.tolist()
['1.0', '2.5', '1e+20', 'nan', <NA>]
>>> sd.frame.Series([True, False]).astype("string").tolist()
['True', 'False']
```

NaN은 글자 `'nan'`이 되고, `NA`는 `NA`로 남아요. `'nan'`은 이제 평범한 문자열이라서 결측으로 보지 않아요.

화면에 보이는 모습과 바뀐 글자는 다를 수 있어요. float 컬럼을 출력하면 자릿수를 맞춰 보여 주지만, `astype("string")`은 값 하나하나를 `str()`로 써요. 정수 모양의 글자를 원하면 먼저 int64로 바꾼 뒤 문자열로 바꿔요.

```python
>>> sd.frame.Series([1.0, 2.0]).astype("int64").astype("string").tolist()
['1', '2']
```

## 문자열을 숫자로: 엄격하게 읽어요

문자열을 int64나 float64로 바꿀 때는 정해진 문법에 꼭 맞는 글자만 숫자로 읽어요. 앞뒤 공백, 천 단위 구분자, 단위 같은 것이 붙어 있으면 에러예요. 그래서 데이터에 섞인 이상한 값이 조용히 숫자가 되지 않고 바로 에러로 드러나요.

같은 문법을 [`read_csv`](/api/frame/read_csv/)가 컬럼 종류를 추론할 때와 `dtype=`으로 읽을 때도 써요. 그래서 파일에서 숫자로 읽히는 값과 `astype`으로 숫자가 되는 값이 같아요.

### int64의 문법

부호(`+`나 `-`, 없어도 됨) 뒤에 ASCII 숫자가 하나 이상 와야 해요. 앞의 0은 괜찮아요.

```python
>>> sd.frame.Series(["7", "+7", "-0", "007", None]).astype("int64")
0       7
1       7
2       0
3       7
4    <NA>
dtype: int64
```

소수점이나 지수가 있으면 값이 정수여도 int64 문법이 아니에요. int64 범위를 넘는 수도 에러예요.

```python
>>> sd.frame.Series(["1.0"]).astype("int64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string '1.0' to int64
>>> sd.frame.Series(["9223372036854775808"]).astype("int64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string '9223372036854775808' to int64
```

`"1.0"`이나 `"1e3"` 같은 글자를 정수로 만들려면 float64로 읽은 뒤 int64로 바꿔요.

```python
>>> sd.frame.Series(["1.0", "1e3"]).astype("float64").astype("int64")
0       1
1    1000
dtype: int64
```

### float64의 문법

부호 뒤에 다음 중 하나가 와요.

- 숫자, 그 뒤에 소수점과 숫자(소수점 뒤 숫자는 없어도 돼요): `"7"`, `"1."`, `"2.50"`
- 소수점으로 시작하는 숫자: `".5"`
- 위의 것 뒤에 지수(`e`나 `E`, 부호, 숫자): `"1E+05"`, `"-.5e2"`

```python
>>> sd.frame.Series(["7", "1.", ".5", "+.5", "-.5e2", "1E+05"]).astype("float64")
0         7.0
1         1.0
2         0.5
3         0.5
4       -50.0
5    100000.0
dtype: float64
```

숫자가 하나도 없으면 에러예요.

```python
>>> sd.frame.Series(["."]).astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string '.' to float64
>>> sd.frame.Series(["e5"]).astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string 'e5' to float64
```

float64는 NaN과 무한대를 나타내는 글자 `nan`, `inf`, `infinity`도 읽어요. 대소문자는 가리지 않고, 앞에 부호를 붙일 수 있어요. `"-nan"`은 부호가 켜진 NaN이에요.

```python
>>> sd.frame.Series(["NaN", "nAn", "-nan", "INF", "+inf", "Infinity", "-INFINITY"]).astype("float64")
0    NaN
1    NaN
2    NaN
3    inf
4    inf
5    inf
6   -inf
dtype: float64
```

이 세 단어에 정확히 맞아야 해요. `"infinit"`이나 `"nan(1)"`은 에러예요.

```python
>>> sd.frame.Series(["infinit"]).astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string 'infinit' to float64
```

결과는 그 글자에 가장 가까운 float64 값이에요(Python의 `float()`와 같아요). float64가 담을 수 없을 만큼 크면 `±inf`, 아주 작으면 `±0.0`이나 그 근처의 아주 작은 수가 돼요. 이 경우는 에러가 아니에요.

```python
>>> sd.frame.Series(["1e309", "1e-400", "-1e-400", "5e-324"]).astype("float64").tolist()
[inf, 0.0, -0.0, 5e-324]
```

### 두 문법이 모두 받지 않는 것

다음은 int64로도 float64로도 읽지 않아요.

| 글자 | 왜 안 되나요 |
|---|---|
| `" 1"`, `"1 "` | 앞뒤 공백 |
| `"1_000"`, `"1,000"` | 자릿수 구분자 |
| `"0x10"` | 16진수 접두사 |
| `"١٢"` | ASCII가 아닌 숫자 |
| `""` | 빈 문자열 |

```python
>>> sd.frame.Series([" 1"]).astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string ' 1' to float64
>>> sd.frame.Series(["1_000"]).astype("int64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string '1_000' to int64
>>> sd.frame.Series([""]).astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string '' to float64
```

빈 문자열은 `NA`가 아니에요. 비어 있는 칸을 `NA`로 두고 싶으면 처음부터 `None`으로 넣거나, 파일이라면 `read_csv`가 빈 필드를 `NA`로 읽게 두세요.

### string → bool: `"True"`와 `"False"`만

bool로는 Python이 bool을 글자로 쓴 모양 그대로인 `"True"`와 `"False"`만 읽어요. `"true"`, `"1"`, `"yes"`, 빈 문자열은 모두 에러예요.

```python
>>> sd.frame.Series(["True", "False", None]).astype("bool")
0     True
1    False
2     <NA>
dtype: bool
>>> sd.frame.Series(["true"]).astype("bool")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string 'true' to bool
```

다른 표기라면 비교 연산으로 bool 컬럼을 만들어요([비교 연산](/api/frame/comparison/)).

```python
>>> answer = sd.frame.Series(["yes", "no", "yes"])
>>> answer == "yes"
0     True
1    False
2     True
dtype: bool
```

### 하나라도 실패하면 전체가 실패해요

값 하나가 문법에 맞지 않으면 `astype` 전체가 `ValueError`이고, 결과는 없어요. 일부만 바꾸고 나머지를 `NA`로 두는 일은 없어요. 메시지에는 행 순서로 처음 실패한 글자가 나와요.

```python
>>> sd.frame.Series(["12", "x", "y"]).astype("int64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string 'x' to int64
```

## DataFrame에서

DataFrame의 `astype`에는 dtype 하나나 dict를 줘요.

- dtype 하나를 주면 모든 컬럼을 그 종류로 바꿔요.
- `{컬럼 이름: dtype}` dict를 주면 적은 컬럼만 바꾸고 나머지는 그대로 둬요.

```python
>>> nums = sd.frame.DataFrame({"a": [1, 2], "b": [1.5, 2.5]})
>>> nums.astype("float64")
     a    b
0  1.0  1.5
1  2.0  2.5
>>> nums.astype("string").dtypes
{'a': string, 'b': string}
```

dtype 하나를 주면 정말 모든 컬럼에 적용돼요. 위의 `raw`처럼 문자열 컬럼(`city`)이 섞인 표를 통째로 float64로 바꾸면 그 컬럼에서 에러가 나요. 그럴 때는 dict로 바꿀 컬럼만 적어요.

```python
>>> raw.astype("float64")
Traceback (most recent call last):
    ...
ValueError: astype(): cannot convert string 'Seoul' to float64
```

dict에 없는 컬럼 이름이 있으면 `KeyError`예요. 오타를 조용히 무시하지 않아요.

```python
>>> raw.astype({"tmp": "float64"})
Traceback (most recent call last):
    ...
KeyError: "astype(): no column 'tmp'"
```

## 명시적 변환과 암묵적 변환

데이터프레임에서 dtype이 바뀌는 길은 두 가지이고, `astype`은 명시적 변환이에요. 배열과 같은 구분이에요([dtype](/api/array/dtypes/)).

- **명시적 변환**: 코드에 바꿀 종류를 직접 적은 것이에요. `astype`, 생성자의 `dtype=`, `read_csv`의 `dtype=`, `to_numpy`와 `to_array`의 `dtype=`이 여기에 들어가요. 직접 요청했으니 값이 달라지는 변환(실수 → 정수)도 해 줘요.
- **암묵적 변환**: 이미 있는 컬럼에 값을 넣느라 저절로 바뀌는 것이에요. [`fillna`](/api/frame/fillna/)와 행 대입(`s.iloc[0] = ...`, [대입과 복사](/api/frame/assign/))이 여기에 들어가요. 이때는 `bool → int64 → float64` 쪽으로만 바꾸고, 값을 잃을 수 있는 방향은 `TypeError`예요. 값이 아니라 dtype만 보고 판단해서, `2.0`처럼 정수와 같은 값도 정수 컬럼에 넣을 수 없어요.

예를 들어 정수 컬럼의 빈칸을 평균값 `2.5`로 채우려 하면 `fillna`가 거절해요. 컬럼을 먼저 float64로 바꾸면 채울 수 있어요.

```python
>>> s.fillna(2.5)
Traceback (most recent call last):
    ...
TypeError: fillna(): cannot implicitly convert float64 to int64 (that would lose information); convert explicitly with astype
>>> s.astype("float64").fillna(2.5)
0    3.0
1    2.5
2    5.0
Name: qty, dtype: float64
```

에러 메시지의 "convert explicitly with astype"가 바로 이 방법을 가리켜요.

생성자의 `dtype=`은 일단 데이터대로 컬럼을 만든 뒤 `astype`한 것과 같아요. 그래서 문자열 리스트를 바로 숫자 컬럼으로 만들 수 있고, 같은 문법 규칙을 따라요.

```python
>>> sd.frame.Series(["1", "2"], dtype="int64")
0    1
1    2
dtype: int64
>>> sd.frame.Series([1.5, None], dtype="int64")
0       1
1    <NA>
dtype: int64
```

## 결과는 언제나 새 객체예요

`astype`은 언제나 새 Series나 DataFrame을 돌려줘요. 종류가 이미 같아서 바꿀 것이 없어도 그래요. 결과를 고쳐도 원래 것은 바뀌지 않아요.

```python
>>> p = sd.frame.Series([1, 2, 3], index=["x", "y", "z"], name="n")
>>> q = p.astype("int64")
>>> q is p
False
>>> q.iloc[0] = 100
>>> p
x    1
y    2
z    3
Name: n, dtype: int64
```

종류가 같을 때는 값을 바로 복사하지 않고, 한쪽을 고치는 순간에 그쪽만 복사해요(Copy-on-Write). 그래서 배열의 `astype`과 달리 `copy` 인자가 없어요. 언제 복사할지 고를 필요가 없기 때문이에요. 자세한 내용은 [대입과 복사](/api/frame/assign/)에 있어요.

## 조심할 점

### dtype은 네 가지만, 자리로만

`dtype`에는 `sd.bool`, `sd.int64`, `sd.float64`, `sd.string`과 그 이름만 쓸 수 있어요. Python의 `float`, `"float32"` 같은 다른 이름, numpy의 dtype, `None`은 `TypeError`예요. `sd.complex128`도 안 돼요. 데이터프레임에는 복소수 컬럼이 없어요.

```python
>>> s.astype(float)
Traceback (most recent call last):
    ...
TypeError: astype(): 'dtype' must be sd.bool, sd.int64, sd.float64 or sd.string (or their names), not float
>>> s.astype(sd.complex128)
Traceback (most recent call last):
    ...
TypeError: astype(): 'dtype' must be sd.bool, sd.int64, sd.float64 or sd.string (or their names), not sd.complex128
```

`dtype`은 이름 없이 자리로 넘겨요. `astype(dtype="float64")`는 에러예요. `copy`나 `errors` 같은 다른 인자도 없어요.

```python
>>> s.astype(dtype="float64")
Traceback (most recent call last):
    ...
TypeError: Series.astype() got some positional-only arguments passed as keyword arguments: 'dtype'
```

### 버림이 필요한 게 맞는지 확인해요

실수 → 정수는 반올림이 아니라 버림이에요. `2.9`는 `2`가 돼요. 반올림한 정수가 필요하면 반올림을 먼저 한 뒤 바꿔요. [`to_array`](/api/frame/to-array/)로 꺼내 배열의 [`round`](/api/array/rounding/)를 쓰면 돼요.

### NaN과 `'nan'` 글자

float → string에서 NaN은 글자 `'nan'`이 되고, string → float에서 `'nan'`은 NaN이 돼요. 어느 쪽이든 `NA`가 되지는 않아요. `NA`만 `NA`로 남아요.

## 비슷한 기능과의 차이

| 하고 싶은 일 | 쓸 것 | 값을 잃는 변환 |
|---|---|---|
| 컬럼의 종류 바꾸기 | `astype` | 해 줘요 |
| 만들면서 종류 정하기 | 생성자의 `dtype=` ([Series](/api/frame/series/), [DataFrame](/api/frame/dataframe/)) | 해 줘요 (`astype`과 같아요) |
| 파일을 읽으면서 종류 정하기 | [`read_csv`](/api/frame/read_csv/)의 `dtype=` | 같은 문법으로 읽어요 |
| 빈칸 채우기 | [`fillna`](/api/frame/fillna/) | `TypeError` (넓은 쪽으로만) |
| 행에 값 넣기 | [대입](/api/frame/assign/) | `TypeError` (넓은 쪽으로만) |
| numpy 배열로 꺼내면서 바꾸기 | [`to_numpy(dtype=...)`](/api/frame/to-numpy/) | 해 줘요 (`astype`과 같아요) |
| 배열의 종류 바꾸기 | 배열의 [`astype`](/api/array/astype/) | 해 줘요 (숫자 규칙이 같아요) |

배열의 `astype`과 비교하면, 숫자끼리의 규칙은 같고 다음이 달라요.

- 데이터프레임에는 문자열 dtype이 있어서 문자열 ↔ 숫자 변환이 있어요. 배열에는 복소수가 있어서 복소수 변환이 있어요.
- `NA`가 `NA`로 남아요. 배열에는 `NA`가 없어요.
- `copy` 인자가 없어요. 결과는 언제나 새 객체이고, 복사는 고칠 때 일어나요.

## pandas를 아는 분께

- float → int64에서 NaN은 0, ±inf는 int64의 최댓값·최솟값이에요. pandas는 `IntCastingNaNError`를 내요.
- string → bool은 `"True"`, `"False"`만 받아요. pandas의 `astype(bool)`은 빈 문자열만 `False`이고 나머지(`"False"`도)는 `True`예요.
- 문자열을 숫자로 읽는 문법이 엄격해요. pandas는 `" 1"`, `"1_000"`, `"١٢"`를 int로도 float로도 읽어요. stardust에서는 모두 `ValueError`예요.
- dtype은 네 가지와 그 이름만 받아요. pandas의 `astype(float)`, `astype("Int64")`, `astype("category")`에 해당하는 것은 없어요. 정수 컬럼은 `NA`가 있어도 `int64`예요.
- `copy=`, `errors=` 인자가 없어요. pandas 3.1도 Copy-on-Write라서 `copy=`를 주면 폐기 예정 경고를 내요.
- dict에 없는 컬럼은 `KeyError`인 점은 pandas와 같아요.
