## 한눈에 보기

실제 데이터에는 빈칸이 있어요. 시험을 보지 않은 학생의 점수, 고장 난 센서의 기온, 설문에서 답하지 않은 문항처럼요. 이런 칸을 **결측값**(missing value)이라고 해요. "값이 있는데 0"이 아니라 "값이 없음"이에요.

빈칸을 0으로 채워 두면 계산이 조용히 틀려요. 예를 들어 네 학생 가운데 한 명이 시험을 보지 않았어요.

```python
>>> import stardust as sd
>>> NA = sd.frame.NA
>>> score = sd.frame.Series([80, None, 95, 70], index=["amy", "ben", "cara", "dan"], name="score")
>>> score
amy       80
ben     <NA>
cara      95
dan       70
Name: score, dtype: int64
>>> score.mean()
81.66666666666667
>>> score.count()
3
>>> sd.frame.Series([80, 0, 95, 70]).mean()
61.25
```

`None`을 넣은 자리는 결측값 <strong>`NA`</strong>가 되고, 출력에는 `<NA>`로 나와요. 평균은 `NA`를 건너뛰고 점수가 있는 세 명으로 계산해요. 0을 넣으면 ben이 0점을 받은 것처럼 계산돼서 평균이 크게 낮아져요.

<Fig caption="ben의 칸은 값이 없어요(점선). 평균은 값이 있는 세 칸으로만 계산해요.">

    data={[80, null, 95, 70]} rowTones={['a', '', 'a', 'a']} note="dtype: int64" />
  <Op note="mean()">→</Op>
  <FrameFig columns={['mean']} index={false} data={[81.66666666666667]} tones={[['b']]} note="(80 + 95 + 70) / 3" />

그런데 float에는 이름이 비슷한 **`NaN`**(Not a Number, "숫자가 아님")이라는 값이 따로 있어요. `0.0 / 0.0`처럼 답이 정해지지 않은 계산에서 나오는 float 값이에요. stardust의 데이터프레임은 둘을 분명히 나눠요.

| | `NA` | `NaN` |
|---|---|---|
| 뜻 | 값이 없음 (결측값) | 계산 결과로 나온 float 값 |
| 쓰는 dtype | 모든 dtype | float64만 |
| 출력 | `<NA>` | `NaN` |
| 찾는 법 | `isna()` | `isnan()` |
| 리덕션에서 | 기본으로 건너뜀 | 결과로 퍼짐 |

## NA는 하나뿐이에요

결측값은 `sd.frame.NA`라는 값 하나로 나타내요. 정수 열이든 문자열 열이든 같은 `NA`예요. 열에서 빈칸을 꺼내면 이 `NA`가 나오고, 꺼낸 값이 `NA`인지는 `is`로 확인해요.

```python
>>> score["ben"]
<NA>
>>> score["ben"] is NA
True
>>> NA
<NA>
>>> type(NA).__name__
'NAType'
>>> score.tolist()
[80, <NA>, 95, 70]
>>> sd.frame.Series(["x", None]).iloc[1] is NA
True
```

`NA`를 직접 넣어서 만들어도 돼요. `None`을 넣은 것과 같아요.

```python
>>> sd.frame.Series([1.5, NA])
0    1.5
1   <NA>
dtype: float64
```

### NA가 있어도 dtype은 그대로예요

빈칸이 있어도 열의 dtype은 바뀌지 않아요. 정수 점수 열에 빈칸이 하나 생겼다고 float 열이 되지 않고, 참·거짓 열이나 문자열 열도 그대로예요.

```python
>>> score.dtype
int64
>>> sd.frame.Series([True, None]).dtype
bool
>>> sd.frame.Series(["a", None]).dtype
string
```

값이 모두 비어 있으면 값을 보고 dtype을 정할 수 없어서 float64가 돼요. 원하는 dtype이 있으면 `dtype=`으로 줘요.

```python
>>> sd.frame.Series([None, None]).dtype
float64
```

## NA가 들어간 계산은 NA예요

모르는 값에 5를 더하면 결과도 모르는 값이에요. 그래서 산술과 비교에 `NA`가 들어가면 그 행의 결과는 `NA`예요.

```python
>>> score + 5
amy       85
ben     <NA>
cara     100
dan       75
Name: score, dtype: int64
>>> score > 75
amy      True
ben      <NA>
cara     True
dan     False
Name: score, dtype: bool
```

`score > 75`에서 ben의 행이 `False`가 아니라 `<NA>`인 점을 눈여겨보세요. 점수를 모르니 75보다 큰지도 몰라요. 이 마스크로 행을 거르면 `NA`인 행은 버려져요([조건으로 행 거르기](/api/frame/mask/)).

스칼라 `NA`도 같아요. `NA ** 0`처럼 수학적으로는 답이 1로 정해질 것 같은 계산도 `NA`예요. "`NA`가 들어가면 `NA`"라는 규칙에는 예외가 없어요.

```python
>>> NA + 1
<NA>
>>> 2.5 * NA
<NA>
>>> NA < 3
<NA>
>>> NA ** 0
<NA>
```

스칼라 `NA`는 상대편 값의 dtype을 따라서, 그 dtype의 열이 할 수 있는 연산만 해요. 문자열끼리는 `+`(이어 붙이기)만 되므로 `NA + "a"`는 `NA`이고 `NA - "a"`는 에러예요.

```python
>>> NA + "a"
<NA>
>>> NA - "a"
Traceback (most recent call last):
    ...
TypeError: unsupported operand dtypes for -: string and string (strings support + and comparisons)
```

## 참·거짓과 NA: 3값 논리

`&`(그리고), `|`(또는)는 조금 달라요. `NA`를 "참인지 거짓인지 모름"으로 읽으면, 모르는 값이 무엇이든 답이 정해지는 경우가 있어요.

- `True | 모름`: 한쪽이 이미 참이니 **참**이에요.
- `False & 모름`: 한쪽이 이미 거짓이니 **거짓**이에요.
- `True & 모름`, `False | 모름`: 모르는 쪽에 따라 답이 달라지니 **모름**(`NA`)이에요.

이렇게 참, 거짓, 모름 세 값으로 하는 논리를 **3값 논리**(Kleene 논리)라고 해요. SQL의 `NULL`도 같은 규칙이에요.

| `a & b` | b = True | b = False | b = `NA` |
|:---:|:---:|:---:|:---:|
| **a = True** | True | False | `NA` |
| **a = False** | False | False | False |
| **a = `NA`** | `NA` | False | `NA` |

| `a \| b` | b = True | b = False | b = `NA` |
|:---:|:---:|:---:|:---:|
| **a = True** | True | True | True |
| **a = False** | True | False | `NA` |
| **a = `NA`** | True | `NA` | `NA` |

```python
>>> a = sd.frame.Series([True, True, True, False, False, False, None, None, None])
>>> b = sd.frame.Series([True, False, None, True, False, None, True, False, None])
>>> a & b
0     True
1    False
2     <NA>
3    False
4    False
5    False
6     <NA>
7    False
8     <NA>
dtype: bool
>>> a | b
0     True
1     True
2     True
3     True
4    False
5     <NA>
6     True
7     <NA>
8     <NA>
dtype: bool
>>> True | NA
True
>>> False & NA
False
>>> True & NA
<NA>
```

`^`(배타적 또는)와 `~`(부정)는 모르는 값이 무엇이냐에 따라 언제나 답이 달라지므로, `NA`가 들어가면 `NA`예요. 정수의 비트 연산(`&`, `|`, `^`)도 3값 논리를 쓰지 않고 `NA`가 들어가면 `NA`예요. 3값 논리는 bool끼리의 `&`, `|`에서만 써요([논리와 비트 연산](/api/frame/logical/)).

```python
>>> NA ^ True
<NA>
>>> ~NA
<NA>
>>> sd.frame.Series([6, None]) & sd.frame.Series([3, 3])
0       2
1    <NA>
dtype: int64
```

## `NA == NA`는 `NA`예요

"`NA`가 들어간 비교는 `NA`"라는 규칙은 `NA`끼리 비교할 때도 그대로예요. 모르는 값 둘이 같은지는 알 수 없으니까요. 두 학생의 점수를 모두 모른다고 해서 두 점수가 같다고 할 수는 없어요.

```python
>>> NA == NA
<NA>
>>> NA != NA
<NA>
```

그래서 어떤 값이 `NA`인지는 `==`가 아니라 `is`로 확인해요. `x == NA`는 언제나 `NA`이고, `NA`는 참·거짓으로 바꿀 수 없어서 `if`에 쓰면 `TypeError`예요.

```python
>>> x = score["ben"]
>>> x is NA
True
>>> x == NA
<NA>
>>> if x == NA:
...     print("missing")
Traceback (most recent call last):
    ...
TypeError: the truth value of NA is ambiguous
>>> bool(NA)
Traceback (most recent call last):
    ...
TypeError: the truth value of NA is ambiguous
```

`NA`가 조용히 `False`로 바뀌지 않으니, `if x == NA:`처럼 잘못 쓴 코드가 조용히 지나가지 않고 바로 에러로 드러나요.

<Callout type="warn" title="열에서 NA를 찾을 때도 ==는 쓰지 않아요">
  `score == NA`는 모든 행이 `<NA>`인 열이 돼요. 열에서 빈칸을 찾을 때는 [`isna()`](/api/frame/isna/)를 써요.
</Callout>

```python
>>> score == NA
amy     <NA>
ben     <NA>
cara    <NA>
dan     <NA>
Name: score, dtype: bool
>>> score.isna()
amy     False
ben      True
cara    False
dan     False
Name: score, dtype: bool
```

### `in`과 dict, set

`NA`는 해싱할 수 있어서 dict의 키나 set의 원소가 될 수 있어요. Python의 `in`은 먼저 같은 객체인지(`is`)를 보고, 아니면 `==`로 비교해요. 그래서 `NA in [NA]`는 같은 객체를 찾아서 `True`이지만, `NA in [1, 2]`는 `NA == 1`을 참·거짓으로 바꾸려다 `TypeError`예요.

```python
>>> NA in [NA]
True
>>> NA in {NA: "missing"}
True
>>> NA in [1, 2]
Traceback (most recent call last):
    ...
TypeError: the truth value of NA is ambiguous
```

`None`과는 비교할 수 없어요. `NA`는 `None`이 아니에요.

```python
>>> NA == None
Traceback (most recent call last):
    ...
TypeError: '==' not supported between instances of 'NAType' and 'NoneType'
```

## NaN은 결측값이 아니에요

`NaN`은 IEEE 754(컴퓨터가 실수를 다루는 국제 표준)가 정한 float 값이에요. `0.0 / 0.0`, `inf / inf`처럼 답을 하나로 정할 수 없는 계산이 내놓는 결과예요. 값이 없는 게 아니라, 계산이 "정해지지 않음"이라는 값을 낸 거예요.

```python
>>> import math
>>> sd.frame.Series([0.0, math.inf]) / sd.frame.Series([0.0, math.inf])
0   NaN
1   NaN
dtype: float64
```

그래서 데이터프레임은 `NaN`을 결측값으로 보지 않고 평범한 float 값으로 다뤄요. 측정하지 못한 기온(`NA`)과 계산에서 나온 `NaN`이 한 열에 함께 있어도 서로 구별돼요.

```python
>>> t = sd.frame.Series([21.5, None, 19.0, math.nan], name="temp")
>>> t
0    21.5
1    <NA>
2    19.0
3     NaN
Name: temp, dtype: float64
```

### `isna`와 `isnan`

`isna()`는 `NA`만 찾고, `isnan()`은 `NaN`만 찾아요. `isnan()`의 결과에서 `NA` 행은 `<NA>`예요. 값이 없으니 그 값이 `NaN`인지도 알 수 없어서예요.

```python
>>> t.isna()
0    False
1     True
2    False
3    False
Name: temp, dtype: bool
>>> t.isnan()
0    False
1     <NA>
2    False
3     True
Name: temp, dtype: bool
```

### 리덕션: `skipna`는 NA만 건너뛰어요

합, 평균, 최댓값 같은 리덕션은 기본(`skipna=True`)으로 `NA`를 건너뛰어요. 하지만 `NaN`은 값이라서 건너뛰지 않고, 계산에 들어가서 결과를 `NaN`으로 만들어요. 배열의 [`sd.sum`](/api/array/sum/)에 `NaN`이 있으면 결과가 `NaN`인 것과 같아요.

```python
>>> t.sum()
nan
>>> t.max()
nan
>>> t.iloc[:3].sum()
40.5
```

`skipna=False`이면 `NA`가 하나라도 있을 때 결과가 `NA`예요. `NaN`과 `NA`가 함께 있으면 `NA`가 먼저예요.

```python
>>> t.iloc[:3].sum(skipna=False)
<NA>
>>> t.sum(skipna=False)
<NA>
```

`count()`는 `NA`가 아닌 값의 개수라서 `NaN`도 세요.

```python
>>> t.count()
3
```

`NaN`을 빼고 계산하고 싶으면 `NaN`을 먼저 `NA`로 바꾸면 돼요. 방법은 아래 "NaN과 NA를 서로 바꾸기"에 있어요.

### 정렬: NaN은 가장 큰 값, NA는 `na_position`

정렬에서 `NaN`은 `+inf`보다도 큰 값으로 쳐요. 그래서 오름차순에서는 뒤쪽에, 내림차순에서는 맨 앞에 와요. `NA`는 값이 아니라서 크기를 비교하지 않고, `na_position`이 정하는 자리(기본은 맨 뒤)에 방향과 상관없이 놓여요.

```python
>>> t.sort_values()
2    19.0
0    21.5
3     NaN
1    <NA>
Name: temp, dtype: float64
>>> t.sort_values(descending=True)
3     NaN
0    21.5
2    19.0
1    <NA>
Name: temp, dtype: float64
>>> t.sort_values(na_position="first")
1    <NA>
2    19.0
0    21.5
3     NaN
Name: temp, dtype: float64
```

### 키로 비교할 때: NaN끼리는 같은 키

`==` 비교는 IEEE 754를 따라서 `NaN == NaN`이 `False`예요. 하지만 "같은 값끼리 묶는" 기능에서는 `NaN`끼리 같은 키로 쳐요. `NaN`을 하나의 값으로 보니까요. `NA`끼리도 같은 키예요.

```python
>>> k = sd.frame.Series([math.nan, 1.0, math.nan, None, None])
>>> k == k
0    False
1     True
2    False
3     <NA>
4     <NA>
dtype: bool
>>> k.unique_values()
0    1.0
1    NaN
2   <NA>
dtype: float64
>>> k.nunique()
2
>>> k.value_counts(dropna=False)
   values  counts
0     NaN       2
1    <NA>       2
2     1.0       1
>>> k.duplicated()
0    False
1    False
2     True
3    False
4     True
dtype: bool
>>> math.nan in k
True
```

`nunique()`와 `value_counts()`는 기본(`dropna=True`)으로 `NA`를 빼고 세지만, `NaN`은 값이라서 빼지 않아요. 그래서 `k.nunique()`는 `1.0`과 `NaN`을 세어 2예요. 같은 규칙으로 groupby에서도 `NaN`은 하나의 그룹이고, `NA` 키의 행은 기본으로 버려요.

```python
>>> g = sd.frame.DataFrame({"k": [math.nan, 1.0, math.nan, None], "v": [1, 2, 3, 4]})
>>> g.groupby("k").sum()
     k  v
0  1.0  2
1  NaN  4
>>> g.groupby("k", dropna=False).sum()
     k  v
0  1.0  2
1  NaN  4
2 <NA>  4
```

예외는 merge 하나예요. merge에서 `NA` 키는 아무것과도, 다른 `NA`와도 짝이 되지 않아요. `NA == NA`가 `NA`인 것과 같은 생각으로, 모르는 고객 번호 둘이 같은 고객인지는 알 수 없기 때문이에요. SQL의 조인도 같아요. `NaN` 키는 값이라서 `NaN`끼리 짝이 돼요.

```python
>>> left = sd.frame.DataFrame({"k": [1.0, math.nan, None], "x": [10, 20, 30]})
>>> right = sd.frame.DataFrame({"k": [1.0, math.nan, None], "y": [100, 200, 300]})
>>> left.merge(right, on="k")
     k   x    y
0  1.0  10  100
1  NaN  20  200
```

### NaN과 NA를 서로 바꾸기

`NaN`을 결측값으로 다루고 싶으면 `isnan()`을 마스크로 써서 `NA`를 대입해요. `isnan()`의 `NA` 행은 마스크에서 버려지므로 원래 `NA`인 행은 그대로예요. 반대로 `NA`를 `NaN`으로 채우려면 `fillna`에 `math.nan`을 줘요.

```python
>>> u = sd.frame.Series([21.5, math.nan, 19.0])
>>> u.loc[u.isnan()] = NA
>>> u
0    21.5
1    <NA>
2    19.0
dtype: float64
>>> sd.frame.Series([21.5, None]).fillna(math.nan)
0    21.5
1     NaN
dtype: float64
```

## `None`은 만들 때 NA로 읽어요

`None`은 Series나 DataFrame을 **만들 때** 넣으면 `NA`가 돼요. numpy의 object 배열에 든 `None`도 같아요. float 배열의 `NaN`은 `NaN` 그대로예요.

```python
>>> sd.frame.Series([1.0, math.nan, None])
0    1.0
1    NaN
2   <NA>
dtype: float64
>>> import numpy as np
>>> sd.frame.Series(np.array([1.0, np.nan]))
0    1.0
1    NaN
dtype: float64
>>> sd.frame.Series(np.array([1, None], dtype=object))
0       1
1    <NA>
dtype: int64
```

만든 뒤에는 `None`이 값으로 쓰이지 않아요. 연산자에 `None`을 주면 `TypeError`이고, `fillna(None)`은 아무것도 채우지 않아요.

```python
>>> sd.frame.Series([1, None]) == None
Traceback (most recent call last):
    ...
TypeError: '==' not supported between instances of 'Series' and 'NoneType'
>>> sd.frame.Series([1, None]).fillna(None)
0       1
1    <NA>
dtype: int64
```

## NA를 밖으로 꺼낼 때

`tolist()`는 빈칸을 `NA`로 돌려줘요. numpy 배열에는 `NA`를 담을 수 없어서, `to_numpy()`와 `to_array()`는 빈칸을 채울 값(`na_value=`)을 받아야 해요. 주지 않으면 에러예요([리스트와 numpy 배열로](/api/frame/to-numpy/)).

```python
>>> qty = sd.frame.Series([3, None, 5])
>>> qty.tolist()
[3, <NA>, 5]
>>> qty.to_numpy()
Traceback (most recent call last):
    ...
ValueError: to_numpy(): cannot convert an int64 column with NA to numpy; pass na_value= to fill the NA rows
>>> qty.to_numpy(na_value=0)
array([3, 0, 5], dtype=int64)
```

dtype을 바꿔도 `NA`는 `NA`예요.

```python
>>> qty.astype("float64")
0    3.0
1   <NA>
2    5.0
dtype: float64
```

## 정수 계산에서 NA가 생기는 곳

정수끼리의 계산에는 정수로 된 올바른 답이 없는 경우가 셋 있어요. 데이터프레임은 이때 가짜 숫자를 내지 않고 `NA`를 내요.

| 계산 | 데이터프레임 | 배열 |
|---|:---:|:---:|
| `a // 0` | `NA` | `0` |
| `a % 0` | `NA` | `a` |
| `a ** 음수` | `NA` | 정수 결과(`7 ** -1`은 `0`) |

```python
>>> n = sd.frame.Series([7, 7, 7, 7])
>>> d = sd.frame.Series([2, 0, -1, 3])
>>> n // d
0       3
1    <NA>
2      -7
3       2
dtype: int64
>>> n % d
0       1
1    <NA>
2       0
3       1
dtype: int64
>>> n ** d
0      49
1       1
2    <NA>
3     343
dtype: int64
```

배열 영역에는 결측값이 없어서 이런 자리에도 무언가 정수를 내야 해요. 그래서 정해진 값을 내고 계속 계산해요([정수 나눗셈](/api/array/floor-divide/), [거듭제곱](/api/array/pow/)). 데이터프레임에는 "답이 없음"을 나타낼 `NA`가 있으니 `NA`를 내요. 그래서 결과에 나온 `0`이 진짜 답인지, 답이 없어서 채운 값인지 헷갈릴 일이 없어요.

```python
>>> sd.asarray([7, 7, 7]) // sd.asarray([2, 0, -1])
array([ 3,  0, -7], dtype=int64)
>>> sd.asarray([7, 7, 7]) % sd.asarray([2, 0, -1])
array([1, 7, 0], dtype=int64)
>>> sd.asarray([7, 7]) ** sd.asarray([2, -1])
array([49,  0], dtype=int64)
```

bool의 산술은 0과 1의 정수 산술이라서 `False`로 나누는 것도 0으로 나누기예요. 반면 `/`의 결과는 float라서 0으로 나누면 `NA`가 아니라 `inf`예요.

```python
>>> sd.frame.Series([True]) // sd.frame.Series([False])
0    <NA>
dtype: int64
>>> n / d
0    3.500000
1         inf
2   -7.000000
3    2.333333
dtype: float64
```

## 값이 모두 NA일 때의 리덕션

값이 하나도 없는 열(모두 `NA`이거나 길이가 0)을 리덕션하면 이렇게 돼요.

| 리덕션 | 결과 | 이유 |
|---|:---:|---|
| `sum` | `0` | 아무것도 더하지 않은 합은 0이에요 |
| `count` | `0` | 센 값이 없어요 |
| `mean`, `min`, `max`, `std`, `var` | `NA` | 값이 없으면 평균이나 최댓값을 정할 수 없어요 |

```python
>>> empty = sd.frame.Series([None, None], dtype="int64")
>>> empty.sum()
0
>>> empty.count()
0
>>> empty.mean()
<NA>
>>> empty.max()
<NA>
>>> empty.std()
<NA>
```

`std`와 `var`는 값이 있어도 모자라면 `NA`예요. `NA`가 아닌 값의 개수에서 `correction`을 뺀 수가 0 이하이면 나눌 수가 없기 때문이에요. 배열의 [`var`](/api/array/var/)는 같은 경우에 `NaN`을 내요. 배열에는 `NA`가 없어서예요.

```python
>>> sd.frame.Series([4.0, None]).var(correction=1)
<NA>
>>> sd.var(sd.asarray([4.0]), correction=1)
nan
```

## 함수마다 NA와 NaN을 다루는 방법

| 기능 | `NA` | `NaN` |
|---|---|---|
| [산술](/api/frame/arithmetic/), [비교](/api/frame/comparison/) | 결과가 `NA` | IEEE 754대로 (`NaN == NaN`은 False) |
| [논리](/api/frame/logical/) `&`, `\|` | 3값 논리 | bool에는 없음 |
| [`isna`, `notna`](/api/frame/isna/) | 결측으로 봄 | 결측으로 보지 않음 |
| [`isnan`](/api/frame/isna/) | 결과가 `NA` | True |
| [`fillna`](/api/frame/fillna/) | 채움 | 그대로 둠 |
| [`dropna`](/api/frame/dropna/) | 행을 지움 | 그대로 둠 |
| [`sum`, `mean`](/api/frame/sum-mean/), [`min`, `max`](/api/frame/min-max/), [`std`, `var`](/api/frame/std-var/) | `skipna=True`면 건너뜀 | 결과가 `NaN` |
| [`count`](/api/frame/sum-mean/) | 세지 않음 | 셈 |
| [`sort_values`](/api/frame/sort_values/) | `na_position`의 자리 | `+inf`보다 뒤 |
| [`unique_values`](/api/frame/unique_values/) | 하나로, 맨 뒤 | 하나로, `+inf` 뒤 |
| [`nunique`](/api/frame/unique_values/), [`value_counts`](/api/frame/value_counts/) | `dropna=True`면 뺌 | 하나의 값으로 셈 |
| [`duplicated`, `drop_duplicates`](/api/frame/duplicated/) | `NA`끼리 같음 | `NaN`끼리 같음 |
| [`groupby`](/api/frame/groupby/) | `dropna=True`면 행을 버림 | 하나의 그룹 |
| [`merge`](/api/frame/merge/) | 아무것과도 짝이 안 됨 | `NaN`끼리 짝이 됨 |
| [마스크](/api/frame/mask/) | 그 행을 버림 | (마스크는 bool이라 없음) |
| [`astype`](/api/frame/astype/) | `NA` 그대로 | int로는 0, bool로는 True, string으로는 `"nan"` |
| [`to_numpy`, `to_array`](/api/frame/to-numpy/) | `na_value=`가 필요 | 그대로 |
| [`read_csv`](/api/frame/read_csv/) | 빈 필드(와 `na_values=`) | 텍스트 `NaN`, `nan` |
| [`x in s`](/api/frame/iteration/) | `NA`를 찾음 | `NaN`을 찾음 |

CSV에서 텍스트 `NA`나 `NaN`은 결측값이 아니에요. 따옴표 없는 빈 필드만 `NA`로 읽고, float 열의 `NaN`은 `NaN` 값, 문자열 열의 `NA`는 문자열 `"NA"`예요. 따옴표로 감싼 빈 필드(`""`)는 빈 문자열이라서 결측값과 구별돼요.

```python
>>> import os, tempfile
>>> path = os.path.join(tempfile.mkdtemp(), "weather.csv")
>>> with open(path, "w") as f:
...     _ = f.write('city,temp,note\nseoul,21.5,sunny\nbusan,,""\njeju,NaN,NA\n')
>>> w = sd.frame.read_csv(path)
>>> w
    city  temp   note
0  seoul  21.5  sunny
1  busan  <NA>       
2   jeju   NaN     NA
>>> w["note"].isna()
0    False
1    False
2    False
Name: note, dtype: bool
```

## pandas를 아는 분께

- `NaN`은 결측값이 아니에요. pandas의 기본 dtype은 `NaN`(과 `None`)을 결측으로 보고, `isna()`가 `NaN`에 True이며, `sum()`이 `NaN`을 건너뛰어요. 여기서는 `isna()`가 `NA`만 찾고, `NaN`은 리덕션 결과로 퍼져요. nullable dtype(`Float64`)의 pandas도 `np.nan`을 넣거나 `0.0 / 0`을 계산하면 `<NA>`로 다루지만, 여기서는 `NaN` 그대로예요.
- `NA`가 dtype을 바꾸지 않아요. pandas의 기본 dtype은 `Series([1, None])`을 float64로, `Series([True, None])`을 object로 만들어요. 여기서는 int64와 bool 그대로예요. 결측값은 모든 dtype에서 `<NA>`로 보여요.
- `NA`는 `pd.NA`와 비슷하지만 예외가 없어요. pandas는 `pd.NA ** 0`과 `1 ** pd.NA`를 `1`로 만들지만, 여기서는 둘 다 `NA`예요. `NA - "a"`처럼 그 dtype이 받지 않는 연산은 pandas와 달리 `TypeError`예요.
- 정수 `// 0`, `% 0`, `** 음수`는 `NA`예요. pandas는 int64에서 `7 // 0`을 float `inf`로, nullable `Int64`에서 `0`으로 만들고, 음수 거듭제곱은 `ValueError`예요.
- 정렬에서 `NaN`은 가장 큰 값이에요. pandas는 `NaN`을 결측처럼 `na_position`의 자리에 놓아서, 내림차순에서도 맨 뒤에 와요.
- `nunique`, `value_counts`, groupby는 `NaN`을 하나의 값으로 세요. pandas는 `NaN`을 결측으로 보고 기본으로 빼요.
- merge에서 `NA` 키는 짝이 되지 않아요. pandas는 결측 키(`NaN`)끼리도 짝을 지어요.
- 값이 모자란 `std`, `var`는 `NA`예요. pandas는 `NaN`이에요. 기본 `correction=0`(pandas의 `ddof=0`)이라서 값 하나의 `std()`는 `0.0`이에요. pandas의 기본은 `ddof=1`이라 `NaN`이에요.
