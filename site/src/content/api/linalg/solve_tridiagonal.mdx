`solve_tridiagonal` solves `a @ x = b` when the square matrix `a` is tridiagonal: its only nonzero elements lie on
the main diagonal and on the diagonals just below and just above it. The matrix is given by these three diagonals,
not as an `n`-by-`n` array, so no zeros are stored and the work grows only linearly with `n`. Tridiagonal systems
arise from finite differences of second derivatives and from cubic spline interpolation.

The matrix need not be symmetric or diagonally dominant. Rows are exchanged during the elimination when that keeps it
stable, so a zero on the main diagonal is no obstacle as long as the matrix is nonsingular. For a matrix with more
nonzero diagonals, use [`solve_banded`](/api/linalg/solve_banded/).

## Examples

A 4-by-4 system with 4 on the main diagonal and -1 on the two diagonals next to it:

```python
>>> import stardust as sd
>>> dl = sd.asarray([-1.0, -1.0, -1.0])
>>> d = sd.asarray([4.0, 4.0, 4.0, 4.0])
>>> du = sd.asarray([-1.0, -1.0, -1.0])
>>> x = sd.linalg.solve_tridiagonal(dl, d, du, sd.asarray([3.0, 2.0, 2.0, 3.0]))
>>> x
array([1.0, 1.0, 1.0, 1.0], dtype=float64)
```

The full matrix that the three diagonals describe, built with [`sd.diag`](/api/array/diag/):

```python
>>> a = sd.diag(d) + sd.diag(dl, k=-1) + sd.diag(du, k=1)
>>> a
array([[ 4.0, -1.0,  0.0,  0.0],
       [-1.0,  4.0, -1.0,  0.0],
       [ 0.0, -1.0,  4.0, -1.0],
       [ 0.0,  0.0, -1.0,  4.0]], dtype=float64)
>>> a @ x
array([3.0, 2.0, 2.0, 3.0], dtype=float64)
```

Two right-hand sides as the columns of `b`, and a stack of two matrices that share their off-diagonals:

```python
>>> b = sd.asarray([[3.0, 13.0], [2.0, 6.0], [2.0, 4.0], [3.0, 2.0]])
>>> sd.linalg.solve_tridiagonal(dl, d, du, b)
array([[1.0, 4.0],
       [1.0, 3.0],
       [1.0, 2.0],
       [1.0, 1.0]], dtype=float64)
>>> sd.linalg.solve_tridiagonal(dl, sd.stack([d, d + 1.0]), du, sd.asarray([3.0, 2.0, 2.0, 3.0])).shape
(2, 4)
```

Zeros on the main diagonal are handled by exchanging rows. A singular matrix raises `LinAlgError`, and diagonals of
the wrong length raise `ValueError`:

```python
>>> sd.linalg.solve_tridiagonal(sd.asarray([1.0]), sd.asarray([0.0, 0.0]), sd.asarray([1.0]), sd.asarray([2.0, 3.0]))
array([3.0, 2.0], dtype=float64)
>>> sd.linalg.solve_tridiagonal(sd.asarray([1.0]), sd.asarray([1.0, 1.0]), sd.asarray([1.0]), sd.asarray([2.0, 3.0]))
Traceback (most recent call last):
```

## Notes

The three diagonals define the $n \times n$ matrix $A$ with

$$
A_{ii} = d_i, \qquad A_{i+1,\,i} = \mathit{dl}_i, \qquad A_{i,\,i+1} = \mathit{du}_i ,
$$

and zeros everywhere else. The function solves $A x = b$ by Gaussian elimination with partial pivoting, adapted to
the tridiagonal structure: at each step the row with the larger element in the current column becomes the pivot row.
Only an exact zero pivot raises `LinAlgError`. A matrix that is nearly singular gives a solution with large errors and
no warning; [`cond`](/api/linalg/cond/) of the full matrix measures how close it is to singular.

`solve_tridiagonal(dl, d, du, b)` equals [`solve_banded`](/api/linalg/solve_banded/) with both bandwidths 1 bit for
bit, for real and complex input. The results of [`solve`](/api/linalg/solve/) on the full matrix agree with it only up
to rounding.

## Comparison with other libraries

`numpy.linalg` and `scipy.linalg` have no function that takes the three diagonals. The nearest equivalent is
`scipy.linalg.solve_banded((1, 1), ab, b)`, which needs the diagonals packed into one band array `ab` first (see
[`solve_banded`](/api/linalg/solve_banded/)).

- The diagonals are separate arguments, so there are no unused corner elements to fill.
- `scipy.linalg.solve_banded` raises `ValueError` for NaN anywhere in `ab`, including its two unused corners.
