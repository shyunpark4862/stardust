`solve` computes the solution of a square system of linear equations. Row `i` of `a` holds the coefficients of
equation `i`, and the matching entry of `b` is its right-hand side. The result `x` satisfies `a @ x == b` up to
rounding.

The function treats every matrix as general and factors it with LU decomposition. For matrices with known structure,
[`solve_triangular`](/api/linalg/solve_triangular/), [`cholesky_solve`](/api/linalg/cholesky_solve/) and
[`solve_banded`](/api/linalg/solve_banded/) use that structure. To solve with the same matrix again later, factor it
once with [`lu`](/api/linalg/lu/) and pass the factors to [`lu_solve`](/api/linalg/lu_solve/). Systems with more
equations than unknowns, or with a singular matrix, have no unique solution; [`lstsq`](/api/linalg/lstsq/) returns
the least-squares solution instead.

## Examples

Two equations in two unknowns:

```python
>>> import stardust as sd
>>> a = sd.asarray([[3.0, 1.0], [1.0, 2.0]])
>>> b = sd.asarray([9.0, 8.0])
>>> x = sd.linalg.solve(a, b)
>>> x
array([2.0, 3.0], dtype=float64)
>>> a @ x
array([9.0, 8.0], dtype=float64)
```

Several right-hand sides, one per column of `b`. Column `j` of the result solves column `j` of `b`:

```python
>>> B = sd.asarray([[9.0, 5.0], [8.0, 5.0]])
>>> sd.linalg.solve(a, B)
array([[2.0, 1.0],
       [3.0, 2.0]], dtype=float64)
```

A stack of two systems. The 1-D right-hand side is shared by both matrices:

```python
>>> stack = sd.asarray([[[3.0, 1.0], [1.0, 2.0]],
...                     [[2.0, 0.0], [0.0, 4.0]]])
>>> sd.linalg.solve(stack, b)
array([[2.0, 3.0],
       [4.5, 2.0]], dtype=float64)
```

A singular matrix raises `LinAlgError`. In a stack, the message names the failing matrix:

```python
>>> s = sd.asarray([[1.0, 2.0], [2.0, 4.0]])
>>> sd.linalg.solve(s, b)
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: solve(): singular matrix
>>> sd.linalg.solve(sd.stack([a, s]), b)
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: solve(): singular matrix (at batch index (1,))
```

## Notes

The function computes the LU factorization with partial pivoting, $P A = L U$, where $P$ is a permutation matrix, $L$
is unit lower triangular and $U$ is upper triangular, and then solves the two triangular systems $L y = P b$ and
$U x = y$.

A matrix counts as singular only when a pivot is exactly zero (see [singular matrices](/api/linalg/#singular-matrices)).
A matrix that is singular in exact arithmetic often produces small nonzero pivots after rounding; `solve` then returns a
solution with large errors and raises no error. The error of the computed solution grows with the condition number of
`a`, which [`cond`](/api/linalg/cond/) computes.

`solve(a, b)` equals `lu_solve(*lu(a), b)` bit for bit, except when `a` is real and `b` is complex; the two then
agree only up to rounding. `inv(a)` equals `solve(a, sd.eye(n))` bit for bit. The result is a new, writable array.

## Comparison with other libraries

**NumPy.** The nearest equivalent is `numpy.linalg.solve`.

- `a` and `b` must be `sd.ndarray`; lists raise `TypeError`.
- NaN or infinity in `a` or `b` raises `ValueError`. `numpy.linalg.solve` returns NaN.

**SciPy.** The nearest equivalent is `scipy.linalg.solve`.

- NaN or infinity in `a` or `b` raises `ValueError`, as in `scipy.linalg.solve` by default.
- There is no `assume_a=` option: the factorization is always the general LU. Triangular and positive definite
  matrices have their own functions, `solve_triangular` and `cholesky_solve`.
