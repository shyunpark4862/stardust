`cholesky_solve` solves `a @ x = b` for a symmetric (or, if complex, Hermitian) positive definite matrix `a`, given
its Cholesky factor from [`cholesky`](/api/linalg/cholesky/). The factor is described under
[factor format](/api/linalg/cholesky/#factor-format) on that page, and when it exists under
[positive definiteness](/api/linalg/cholesky/#positive-definiteness).

For such a matrix the Cholesky factorization takes less work than the LU factorization used by
[`solve`](/api/linalg/solve/), and the factor can be kept to solve for further right-hand sides with two triangular
solves each.

`upper` must agree with the factor. The function reads only the triangle that `upper` selects, so a lower factor
passed with `upper=True` gives a wrong solution without an error.

## Examples

Factor a positive definite matrix, then solve:

```python
>>> import stardust as sd
>>> a = sd.asarray([[4.0, 2.0], [2.0, 5.0]])
>>> c = sd.linalg.cholesky(a)
>>> c
array([[2.0, 0.0],
       [1.0, 2.0]], dtype=float64)
>>> x = sd.linalg.cholesky_solve(c, sd.asarray([10.0, 13.0]))
>>> x
array([1.5, 2.0], dtype=float64)
>>> a @ x
array([10.0, 13.0], dtype=float64)
```

The upper factor works the same way when `upper=True` is given to both functions:

```python
>>> cu = sd.linalg.cholesky(a, upper=True)
>>> sd.linalg.cholesky_solve(cu, sd.asarray([10.0, 13.0]), upper=True)
array([1.5, 2.0], dtype=float64)
```

With the identity matrix as `b`, each column of the result solves for one column, so the result is the inverse of the
matrix:

```python
>>> s = sd.asarray([[4.0, 2.0, 2.0], [2.0, 5.0, 3.0], [2.0, 3.0, 6.0]])
>>> sd.linalg.cholesky_solve(sd.linalg.cholesky(s), sd.eye(3))
array([[0.328125, -0.09375,  -0.0625],
       [-0.09375,   0.3125,   -0.125],
       [ -0.0625,   -0.125,     0.25]], dtype=float64)
```

A lower factor passed with `upper=True` is read as its diagonal only, and the result is wrong. A zero on the
diagonal raises `LinAlgError`:

```python
>>> sd.linalg.cholesky_solve(c, sd.asarray([10.0, 13.0]), upper=True)
array([ 2.5, 3.25], dtype=float64)
>>> sd.linalg.cholesky_solve(sd.zeros((2, 2)), sd.asarray([10.0, 13.0]))
Traceback (most recent call last):
    ...
stardust.linalg.LinAlgError: cholesky_solve(): singular matrix
```

## Notes

For `upper=False` the matrix is $A = L L^H$ and the function solves $L y = b$, then $L^H x = y$. For `upper=True` it
is $A = U^H U$, and the function solves $U^H y = b$, then $U x = y$. For real factors, $L^H$ and $U^H$ are the
transposes.

The function does not check that `l` came from `cholesky`. Any triangular `l` with a nonzero diagonal defines the
matrix $L L^H$ (or $U^H U$), and the system with that matrix is solved. The triangle that is not read is ignored and
may also be NaN.

## Comparison with other libraries

The nearest equivalent is `scipy.linalg.cho_solve`. NumPy has no Cholesky solver.

- `scipy.linalg.cho_solve((c, lower), b)` takes the factor and a flag in one tuple. Here the flag is the
  keyword-only `upper`, and its default `False` matches the lower factor that `cholesky` returns by default.
  `scipy.linalg.cho_factor` returns the upper factor by default.
- An exact zero on the diagonal of `l` raises `LinAlgError`. `scipy.linalg.cho_solve` returns NaN or infinity
  without an error.
