## 무엇을 하나요

방정식 $f(x) = 0$을 만족하는 x를 f의 **근**이라고 해요. 그림으로는 곡선 $y = f(x)$가 x축을 지나는 점이에요. $x^3 - 2x - 5 = 0$처럼 공식으로 풀 수 없는 방정식이 대부분이라, f를 몇 번 계산해 보면서 근에 다가가요. 이렇게 같은 계산을 되풀이하며 답을 고쳐 가는 것을 **반복**이라고 해요.

`root_scalar`는 변수가 하나(스칼라)인 f의 근 하나를 찾아요. 방법은 크게 두 갈래예요.

- **구간법**(`'brentq'`, `'toms748'`, `'bisect'`): f(a)와 f(b)의 부호가 다른 두 점 a, b를 줘요. f가 연속이면 그 사이 어딘가에서 반드시 0을 지나요. 구간 안의 점에서 f를 계산해 부호를 보고, 근이 있는 쪽만 남기며 구간을 좁혀요. 구간이 늘 근을 끼고 있으니 **반드시 수렴**해요.
- **시작점에서 출발하는 방법**(`'newton'`, `'halley'`, `'secant'`): 시작점 x0 하나에서, 그 점의 접선(또는 두 점을 잇는 직선)이 x축과 만나는 곳으로 옮겨 가요. 근 가까이에서는 아주 빠르지만, 시작점이 멀거나 기울기가 0에 가까운 곳을 지나면 엉뚱한 곳으로 가거나 제자리를 돌아요.

```python
(2.094551481542327, True)
```

방법을 고르지 않고 `bracket`을 주면 `'brentq'`(Brent법)예요. `nfev`는 f를 부른 횟수로, 여기서는 8번이에요. 결과의 필드는 [결과 객체 읽기](/api/optimize/results/)에서 공통으로 다루고, 이 함수의 필드는 아래 [결과 읽기](#결과-읽기)에 있어요.

f는 Python `float` 하나를 받아 실수 하나를 돌려주면 돼요. 그래서 `math`의 함수를 그대로 써도 돼요. 도함수 f′를 알면 시작점과 함께 줘서 Newton법으로 풀 수도 있어요.

```python
>>> r = sd.optimize.root_scalar(f, x0=2.5, fprime=lambda x: 3*x**2 - 2)
>>> r
OptimizeResult(method='newton', converged=True, n_iter=5, nfev=5, x=2.09455)
>>> r.x, r.njev
(2.0945514815423265, 5)
```

`njev`는 도함수를 계산한 횟수예요. 두 답은 끝자리에서 조금 달라요. 이 차이는 아래 [허용오차](#허용오차와-반복-상한)에서 설명해요.

## 방법 고르기

| method | 줘야 하는 것 | 늘 수렴하나요 | 근 가까이의 빠르기 |
|---|---|---|---|
| `'brentq'` | `bracket` | 예 | 보통 할선법만큼 빨라요. 나쁜 함수에서도 이분법보다 크게 느려지지 않아요. |
| `'toms748'` | `bracket` (a < b) | 예 | 매끈한 함수에서 f 한 번당 효율이 가장 좋은 구간법이에요. 반복마다 구간 폭도 줄어요. |
| `'bisect'` | `bracket` | 예 | 한 번에 구간이 반이 돼요(f 한 번에 1비트). 느리지만 예측할 수 있어요. |
| `'newton'` | `x0`, `fprime`(없으면 차분) | 아니요 | 2차 수렴이에요. 맞는 자리 수가 반복마다 두 배쯤 돼요. |
| `'halley'` | `x0`, `fprime`, `fprime2` | 아니요 | 3차 수렴이에요. 맞는 자리 수가 세 배쯤 돼요. |
| `'secant'` | `x0`(그리고 `x1`) | 아니요 | 약 1.618차. 도함수가 필요 없어요. |

"p차 수렴"은 근과의 거리가 e일 때 다음 반복의 거리가 대략 $e^p$에 비례한다는 뜻이에요. 1차(이분법)는 거리가 일정한 비율로 줄고, 2차는 $10^{-3}$ 다음이 $10^{-6}$, 그다음이 $10^{-12}$인 식이에요. 다만 이 빠르기는 근 가까이에 왔을 때의 이야기이고, 거기까지 가는 길은 함수 모양과 시작점에 달려 있어요.

`bisect`는 f를 부를 때마다 거리가 평균 반씩 줄어서 51번이 걸렸고, `brentq`는 8번, `newton`은 5번이에요. newton은 f′도 5번 불렀어요. 고르는 요령이에요.

- 부호가 바뀌는 구간을 알면 구간법을 써요. 기본인 `'brentq'`가 대부분 좋아요.
- 구간은 모르지만 근 가까이의 시작점과 싼 도함수가 있으면 `'newton'`을 써요. 실패했는지는 `converged`로 꼭 확인해요.
- 시작점만 있고 도함수가 없으면 `'secant'`(또는 `fprime` 없는 `'newton'`)를 써요.

`method=None`(기본값)이면 준 인자로 골라요.

1. `bracket`이 있으면 `'brentq'`
2. 없고 `x0`와 `fprime`이 있으면, `fprime2`도 있을 때 `'halley'`, 아니면 `'newton'`
3. `x0`와 `x1`이 있으면 `'secant'`
4. `x0`만 있으면 `'newton'`(도함수는 차분)
5. 둘 다 없으면 `ValueError`

```python
>>> sd.optimize.root_scalar(f, x0=2.5).method
'newton'
>>> sd.optimize.root_scalar(f, x0=2.5, x1=3.0).method
'secant'
>>> sd.optimize.root_scalar(f, x0=2.5, fprime=lambda x: 3*x**2 - 2, fprime2=lambda x: 6*x).method
'halley'
>>> sd.optimize.root_scalar(f)
Traceback (most recent call last):
    ...
ValueError: root_scalar(): give 'bracket' or 'x0'
```

방법마다 받는 인자가 정해져 있어요. 쓰지 않는 인자를 주면 무시하지 않고 `ValueError`예요. 잘못 고른 방법을 일찍 알려 주기 위해서예요.

```python
>>> sd.optimize.root_scalar(f, bracket=(2, 3), x0=2.5)
Traceback (most recent call last):
    ...
ValueError: root_scalar(): method='brentq' takes no 'x0'
>>> sd.optimize.root_scalar(f, method='newton')
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'x0' is required when method='newton'
>>> sd.optimize.root_scalar(f, bracket=(2, 3), method='Brentq')
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'method' must be lowercase: 'brentq', not 'Brentq'
```

## 구간법

세 방법 모두 `bracket=(a, b)`를 받고, f(a)와 f(b)의 부호가 달라야 해요. 구간 안에 근이 여럿이면 그 가운데 하나를 찾아요. 어느 것일지는 방법이 정해요.

```python
>>> for m in ['brentq', 'toms748', 'bisect']:
...     r = sd.optimize.root_scalar(f, bracket=(2, 3), method=m)
...     print(m, r.x, r.n_iter, r.nfev)
brentq 2.094551481542327 7 8
toms748 2.0945514815425765 5 11
bisect 2.0945514815412025 39 41
```

### brentq: Brent법

구간의 끝과 그 앞의 점으로 근을 어림하는 방법이에요. 두 점이면 그 둘을 잇는 직선이 x축과 만나는 점(할선), 세 점이면 세 점을 지나는 곡선 $x = q(y)$의 $q(0)$(역 2차 보간)으로 다음 점을 정해요. 어림이 구간 밖으로 나가거나 구간이 충분히 빨리 줄지 않으면 그 걸음 대신 이분해요. 그래서 매끈한 함수에서는 할선법만큼 빠르고, 어림이 잘 맞지 않는 함수에서도 f 계산 횟수가 이분법 횟수의 제곱을 넘지 않아요. 구간법의 기본값이에요.

### toms748: Alefeld–Potra–Shi

역 3차 보간과 이차식의 Newton 걸음으로 근을 어림하고, 반복마다 구간 폭이 적어도 반으로 줄도록 이분을 섞어요. Brent법은 마지막에야 구간이 크게 줄 수 있지만, toms748은 근에 다가가는 빠르기 그대로 구간도 매번 좁혀요. f가 네 번 연속 미분 가능하면 수렴 차수가 적어도 2.7이고 반복마다 f를 두 번쯤 부르므로, f 계산 하나당 효율(효율 지수, 차수의 (계산 수)제곱근)이 약 1.65예요. 할선법은 1.618, Newton법은 f와 f′를 한 번씩 세어 √2 ≈ 1.41이에요.

`options={'k': k}`는 반복 하나에서 보간 걸음을 몇 번 할지예요. 기본 1이고, 2이면 반복당 f를 세 번쯤 부르며 수렴 차수가 약 4.6, 효율 지수가 1.66이 돼요. k = 2는 네 번 연속 미분 가능한 함수의 근을 찾는 알려진 방법 가운데 점근적으로 가장 효율적이에요. k가 더 크면 효율 지수가 $(3k-2)^{1/k}$에 다가가 오히려 줄어서 1이나 2가 보통 알맞아요. 100보다 크면 `ValueError`예요.

```python
>>> sd.optimize.root_scalar(f, bracket=(2, 3), method='toms748', options={'k': 2})
OptimizeResult(method='toms748', converged=True, n_iter=3, nfev=9, x=2.09455)
>>> sd.optimize.root_scalar(f, bracket=(3, 2), method='toms748')
Traceback (most recent call last):
    ...
ValueError: root_scalar(): method='toms748' needs a < b in 'bracket', not (3.0, 2.0)
```

toms748은 a < b여야 해요. brentq와 bisect는 (b, a) 순서도 받아요.

### bisect: 이분법

가운데 점에서 f의 부호를 보고 반을 버리기만 해요. f의 값은 부호만 쓰므로 f가 아무리 이상한 모양이어도 걸음이 같아요. 구간 폭 L을 허용오차 δ까지 줄이는 데 약 $\log_2(L/\delta)$번이 걸려요. 위에서 폭 1을 $2 \times 10^{-12}$ 아래로 줄이는 데 39번이에요.

부호는 두 값을 곱하지 않고 값마다 따로 봐요. 그래서 f의 값이 아주 작아 두 값의 곱이 0으로 내려갈 때($\lvert f\rvert < 10^{-162}$ 남짓)도 맞게 갈라요.

```python
>>> sd.optimize.root_scalar(lambda x: 1e-200 * (x - 1.3), bracket=(1.0, 2.0), method='bisect').x
1.3000000000010914
```

### 어떤 구간법이 언제 나은가요

매끈한 함수에서는 brentq와 toms748이 이분법보다 몇 배 적게 f를 불러요. 근에서 f가 아주 평평하면(중근) 보간이 잘 맞지 않아 차이가 드러나요. $x^3$의 근 0은 삼중근이에요.

```python
>>> for m in ['brentq', 'toms748', 'bisect']:
...     r = sd.optimize.root_scalar(lambda x: x**3, bracket=(-1, 2), method=m)
...     print(m, r.converged, r.n_iter, r.nfev)
brentq False 100 102
toms748 True 31 89
bisect True 41 43
```

brentq는 할선과 보간 걸음이 근에 아주 천천히 다가가다 이분으로 넘어가기를 되풀이해서, 상한 100번 안에 끝나지 않았어요. 이런 함수에서는 bisect나 toms748이 나아요. `max_iter`를 늘려도 돼요.

## 시작점에서 출발하는 방법

### newton: Newton법

시작점 $x_0$에서 곡선의 접선을 긋고, 접선이 x축과 만나는 점으로 옮겨 가요.

$$
x_{k+1} = x_k - \frac{f(x_k)}{f'(x_k)}
$$

근 가까이에서는 맞는 자리 수가 반복마다 두 배쯤 돼요. `fprime`을 주지 않으면 도함수를 차분 $(f(x + h) - f(x))/h$로 어림해요($h = 2^{-26} \cdot \operatorname{sign}(x) \cdot \max(1, |x|)$). 그러면 반복마다 f를 한 번 더 불러요.

```python
>>> r = sd.optimize.root_scalar(f, x0=2.5)
>>> r.nfev, r.njev, r.x
(10, 5, 2.0945514815423265)
```

`njev`는 도함수를 구한 횟수(`fprime`을 부른 횟수 또는 차분의 수)이고, 차분이 부른 f는 `nfev`에 들어가요.

Newton법은 수렴을 보장하지 않아요. 위 그림 아래쪽처럼 제자리를 돌기도 하고, 기울기가 0에 가까운 곳을 지나면 아주 멀리 튀기도 해요. 실패해도 예외는 없으니 `converged`를 확인해요.

```python
>>> def g(x):
...     return x**3 - 2*x + 2
>>> sd.optimize.root_scalar(g, x0=0.0, fprime=lambda x: 3*x**2 - 2)
OptimizeResult(method='newton', converged=False, n_iter=50, nfev=50, x=0)
>>> sd.optimize.root_scalar(g, bracket=(-3, 0)).x
-1.7692923542386343
>>> import math
>>> r = sd.optimize.root_scalar(math.atan, x0=1.5, fprime=lambda x: 1 / (1 + x*x))
>>> r.converged, r.message, r.x
(False, 'Derivative was zero.', -9.459476350342017e+216)
>>> sd.optimize.root_scalar(math.atan, x0=1.3, fprime=lambda x: 1 / (1 + x*x)).x
0.0
```

arctan은 근이 0 하나뿐인데, 1.5에서 시작하면 걸음이 점점 커지며 멀어지다가 도함수 $1/(1 + x^2)$가 0으로 내려앉아 멈췄어요. 1.3에서 시작하면 수렴해요. 같은 함수라도 시작점이 성패를 가르니, 구간을 알 수 있으면 구간법이 안전해요.

### halley: Halley법

이계도함수까지 써서 접선 대신 근처의 곡률을 반영한 걸음이에요.

$$
x_{k+1} = x_k - \frac{f/f'}{1 - \dfrac{f\,f''}{2 f'^2}}
$$

근 가까이에서 3차로 수렴해요. 분모의 보정 $\frac{f f''}{2f'^2}$가 절댓값 1 이상이면 그 반복은 보정 없이 Newton 걸음을 해요. `fprime`과 `fprime2`를 모두 줘야 하고, `nhev`가 `fprime2`를 부른 횟수예요.

```python
>>> r = sd.optimize.root_scalar(f, x0=2.5, fprime=lambda x: 3*x**2 - 2, fprime2=lambda x: 6*x)
>>> r.n_iter, r.nfev, r.njev, r.nhev
(4, 4, 4, 4)
```

반복이 하나 줄었지만 함수 셋을 네 번씩 불렀어요. 이계도함수가 싸게 나올 때만 이득이에요.

### secant: 할선법

도함수 대신 마지막 두 점을 잇는 직선이 x축과 만나는 점으로 가요. 도함수가 없어도 되고 반복마다 f를 한 번만 불러요. 근 가까이에서 약 1.618차로 수렴해요. 둘째 시작점 `x1`을 주지 않으면 $x_0(1 + 10^{-4}) \pm 10^{-4}$(앞의 값이 음수면 −)예요.

```python
>>> sd.optimize.root_scalar(f, x0=2.5, x1=3.0)
OptimizeResult(method='secant', converged=True, n_iter=7, nfev=8, x=2.09455)
>>> sd.optimize.root_scalar(f, x0=2.5, method='secant')
OptimizeResult(method='secant', converged=True, n_iter=6, nfev=7, x=2.09455)
```

## 허용오차와 반복 상한

`xtol`(절대)과 `rtol`(상대)은 "이만하면 멈춰도 된다"는 판정의 크기예요. 멈춤의 뜻은 방법마다 조금 달라요.

| method | 멈추는 때 | 기본 xtol | 기본 rtol | 기본 max_iter |
|---|---|---|---|---|
| `'brentq'` | 근을 끼는 구간의 반이 (xtol + rtol·\|x\|)/2보다 작을 때 | 2e-12 | 4ε ≈ 8.88e-16 | 100 |
| `'toms748'` | 구간 폭이 xtol + rtol·\|b\| 이하일 때 | 2e-12 | 4ε | 100 |
| `'bisect'` | 반으로 줄인 걸음이 xtol + rtol·\|x\|보다 작을 때 | 2e-12 | 4ε | 100 |
| `'newton'`, `'halley'`, `'secant'` | 마지막 걸음이 xtol + rtol·\|x\| 이하일 때 | 1.48e-8 | 0 | 50 |

어느 방법이든 f가 정확히 0인 점을 만나면 거기서 멈춰요. 몇 가지를 조심해요.

**기본값은 "끝자리까지"가 아니에요.** 구간법의 기본 `xtol=2e-12`는 절대 크기라, 근이 1 근처면 12자리쯤에서 멈춰요. 위에서 bisect의 답이 참 근 2.0945514815423265와 $1.1 \times 10^{-12}$ 달랐던 까닭이에요. 끝자리까지 원하면 `xtol=0`을 줘요. 그러면 상대 기준 rtol만 남아요.

```python
>>> root = 2.0945514815423265
>>> for m in ['toms748', 'bisect']:
...     a = sd.optimize.root_scalar(f, bracket=(2, 3), method=m)
...     b = sd.optimize.root_scalar(f, bracket=(2, 3), method=m, xtol=0)
...     print(m, abs(a.x - root), a.nfev, abs(b.x - root), b.nfev)
toms748 2.5002222514558525e-13 11 8.881784197001252e-16 9
bisect 1.1239897901305085e-12 41 4.440892098500626e-16 51
```

**근이 작으면 xtol이 상대적으로 커요.** 근이 $10^{-9}$이면 기본 `xtol`은 근의 0.2%예요.

```python
>>> sd.optimize.root_scalar(lambda x: x - 1e-9, bracket=(-1, 1), method='bisect').x
9.986251825466752e-10
>>> sd.optimize.root_scalar(lambda x: x - 1e-9, bracket=(-1, 1), method='bisect', xtol=0).x
9.999999999999999e-10
```

**근이 0이면 xtol=0일 때 오래 걸려요.** 상대 기준 rtol·|x|가 x와 함께 0으로 가서, 구간이 가장 작은 정규수 근처까지 줄어야 멈춰요. 이분법이면 1,000번 넘게 걸리니 `max_iter`를 함께 늘려요.

```python
>>> sd.optimize.root_scalar(math.sin, bracket=(-1, 2), method='bisect', xtol=0)
OptimizeResult(method='bisect', converged=False, n_iter=100, nfev=102, x=-7.88861e-31)
>>> sd.optimize.root_scalar(math.sin, bracket=(-1, 2), method='bisect', xtol=0, max_iter=1100)
OptimizeResult(method='bisect', converged=True, n_iter=1076, nfev=1078, x=0)
```

**newton·halley·secant의 xtol은 걸음의 크기예요.** 마지막 걸음이 작다는 것이지 근과의 거리가 xtol 안이라는 보장이 아니에요. 근에서 f가 평평하면(중근) 걸음이 느리게 줄어서, 걸음이 xtol 아래로 내려갔을 때도 근과의 거리는 그보다 커요.

```python
>>> r = sd.optimize.root_scalar(lambda x: (x - 1)**3, x0=3.0, fprime=lambda x: 3*(x - 1)**2)
>>> r.converged, r.n_iter, r.x - 1
(True, 45, 2.3818989669521784e-08)
```

`rtol`은 구간법에서 하한이 있어요(brentq·bisect 4ε, toms748 ε). 그보다 작은 상대 정확도는 double로 나타낼 수 없기 때문이에요. 허용오차는 0 이상의 유한한 수여야 해요.

```python
>>> sd.optimize.root_scalar(f, bracket=(2, 3), rtol=1e-16)
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'rtol' must be >= 8.9e-16 (4 times the machine epsilon) when method='brentq'
```

**max_iter**에 닿으면 마지막 점을 돌려주고 `converged=False`, `status` −2예요. 예외는 없어요.

```python
>>> r = sd.optimize.root_scalar(f, bracket=(2, 3), max_iter=3)
>>> r.converged, r.status, r.message, r.x
(False, -2, 'convergence error', 2.094528891117347)
```

## 결과 읽기

| 필드 | 뜻 |
|---|---|
| `x` | 근(Python `float`) |
| `converged` | 멈춤 판정을 통과했는지(`status == 0`) |
| `status`, `message` | 멈춘 이유의 번호와 글(아래) |
| `n_iter` | 반복 수 |
| `nfev` | f를 부른 횟수(newton의 차분이 부른 f 포함) |
| `njev` | 도함수를 구한 횟수. `fprime`을 부른 횟수 또는 차분의 수예요(newton, halley만) |
| `nhev` | `fprime2`를 부른 횟수(halley만) |
| `method` | 쓴 방법의 이름 |

`fun`(근에서의 f 값)은 없어요. 대부분의 방법이 돌려주는 x에서 f를 따로 계산하지 않기 때문이에요. 없는 필드를 읽으면 `AttributeError`이니, 필요하면 직접 계산해요.

```python
>>> r = sd.optimize.root_scalar(f, bracket=(2, 3))
>>> r.fun
Traceback (most recent call last):
    ...
AttributeError: 'OptimizeResult' object has no attribute 'fun' (its method does not give it)
>>> f(r.x)
3.552713678800501e-15
```

`n_iter`와 `nfev`의 관계도 방법마다 달라요. brentq와 bisect는 처음에 두 끝을 계산하고 반복마다 한 번씩(nfev = n_iter + 2, brentq는 마지막 반복이 f를 부르지 않아 + 1), toms748은 반복마다 두세 번, newton은 반복마다 f 한 번과 f′ 한 번이에요.

| status | message | 뜻 |
|---|---|---|
| 0 | `'converged'` | 멈춤 판정을 통과했어요 |
| −2 | `'convergence error'` | `max_iter`에 닿았어요 |
| −2 | `'Derivative was zero.'` | newton·halley에서 f′가 0이 되어 걸음을 못 정했어요 |
| −2 | `'Tolerance of ... reached.'` | secant에서 두 점의 f가 같아 직선이 x축과 만나지 않아요(… 는 두 점의 차이) |
| −3 | `'The function value at x=... is NaN; solver cannot continue.'` | 구간법에서 f가 NaN이었어요(toms748은 inf도). `x`는 그 점이에요 |

## 특수한 경우

### 근을 끼지 않는 구간

f(a)와 f(b)의 부호가 같으면 시작하지 않고 `ValueError`예요. 두 값이 메시지에 나와요. 구간 안에 근이 둘(짝수 개) 있어도 그래요.

```python
>>> sd.optimize.root_scalar(f, bracket=(3, 4))
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'bracket' does not enclose a root: f(a) and f(b) have the same sign (f(3.0) = 16.0, f(4.0) = 51.0)
>>> sd.optimize.root_scalar(lambda x: (x - 1)*(x - 2), bracket=(0, 3))
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'bracket' does not enclose a root: f(a) and f(b) have the same sign (f(0.0) = 2.0, f(3.0) = 2.0)
```

구간의 끝에서 f가 정확히 0이면 그 끝이 근이고, 반복 없이 끝나요(`n_iter` 0). 그래서 a == b인 구간은 f(a) = 0일 때만 받아요.

```python
>>> sd.optimize.root_scalar(lambda x: x - 2.0, bracket=(2.0, 3.0))
OptimizeResult(method='brentq', converged=True, n_iter=0, nfev=2, x=2)
```

### 연속이 아닌 함수

구간법은 f의 부호가 바뀌는 점을 찾아요. f가 연속이 아니면 그 점이 근이 아닐 수 있어요. $\tan x$는 (1, 2)에서 $\pi/2$를 지나며 +∞에서 −∞로 뛰는데, brentq는 그 점을 근으로 돌려줘요. 답을 f에 넣어 확인해요.

```python
>>> r = sd.optimize.root_scalar(math.tan, bracket=(1, 2))
>>> r.converged, r.x, math.tan(r.x)
(True, 1.570796326793586, 763027653393.732)
```

### NaN과 inf

구간법은 f가 NaN을 돌려주면 그 점에서 멈추고 `status` −3이에요. `x`가 그 점이라 어디서 NaN이 났는지 알 수 있어요. brentq와 bisect는 ±inf를 부호로만 쓰고 계속 가요. toms748은 값을 보간에 쓰므로 ±inf에서도 멈춰요.

```python
>>> def h(x):
...     return float('nan') if x > 2.4 else x - 3
>>> r = sd.optimize.root_scalar(h, bracket=(2, 3))
>>> r.status, r.message
(-3, 'The function value at x=3.0 is NaN; solver cannot continue.')
>>> r = sd.optimize.root_scalar(lambda x: float('inf') if x > 2.4 else x - 3, bracket=(2, 3), method='toms748')
>>> r.status, r.message
(-3, 'The function value at x=3.0 is inf; solver cannot continue.')
```

newton·halley·secant는 NaN을 만나도 그대로 계속 가고, 보통 `max_iter`에서 `status` −2로 멈춰요.

### f가 돌려주는 값

f는 실수 하나를 돌려줘야 해요. Python·numpy의 수와 0차원 numpy 배열은 받고, 길이가 있는 배열은 `ValueError`, 수가 아닌 것은 `TypeError`예요. f 안에서 난 에러는 그대로 나와요.

```python
>>> sd.optimize.root_scalar(lambda x: [x - 2], bracket=(1, 3))
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'f' must return a real number, not shape (1,)
>>> sd.optimize.root_scalar(lambda x: None, bracket=(1, 3))
Traceback (most recent call last):
    ...
TypeError: root_scalar(): 'f' must return a real number, not NoneType
```

f에 상수를 넘기려면 클로저나 `lambda`를 써요(`args` 인자는 없어요).

```python
>>> c = 7.0
>>> sd.optimize.root_scalar(lambda x: x**3 - 2*x - c, bracket=(0, 3)).x
2.258258883402597
```

## 여러 문제를 한꺼번에 풀 때

c가 1,000개쯤 있어 $x^3 - 2x - c = 0$을 c마다 풀어야 하면, `root_scalar`를 1,000번 부르는 대신 [find_root](/api/optimize/find_root/)를 써요. 둘은 이렇게 달라요.

| | `root_scalar` | `find_root` |
|---|---|---|
| 푸는 것 | 문제 하나 | 같은 꼴의 문제 여럿(원소마다 따로) |
| f가 받는 것 | Python `float` 하나 | 아직 끝나지 않은 원소의 1차원 배열 |
| f를 부르는 횟수 | 문제마다 반복 수만큼 | 모든 원소를 합쳐 반복 수만큼 |
| 방법 | 여섯 가지(구간법, Newton류) | Chandrupatla의 구간법 하나 |
| 결과 | Python 수 | 배치 모양의 배열 |

10⁴개의 문제에서 `find_root` 한 번은 원소마다 `root_scalar`(brentq)를 부르는 고리의 약 1/50 시간이 걸려요(1.19 ms 대 61.3 ms, Apple M4 Pro). Python 함수를 부르는 비용이 원소 수만큼에서 반복 수만큼으로 줄기 때문이에요.

## 사용자 함수와 스레드

반복은 C++에서 돌고 f는 그 사이사이에 Python으로 불려요. f가 Python이라 반복은 GIL을 쥔 채 돌아요. 반복 자체의 비용은 f 호출 하나에 0.2–1.6 µs로 작아서, 걸리는 시간은 대부분 f의 계산이에요. 같은 f면 같은 점에서 같은 순서로 f를 불러 실행마다 같은 비트의 답을 내요. 반복은 한 스레드라 지금은 스레드 수와도 상관없어요(약속은 아니에요).

## 정확도와 비용

- `converged=True`는 위 표의 멈춤 판정을 통과했다는 뜻이에요. 구간법은 그 판정이 곧 근과의 거리의 한계라서, 기본값으로 수렴한 근은 참 근에서 xtol + rtol·|x| 안이에요. 시험 문제 204개(Alefeld–Potra–Shi, Chandrupatla 등)의 근을 Arb(구간 산술)로 만든 참값과 견주면 모두 그 안이거나, double로 계산한 f가 정확히 0인 점이에요.
- `xtol=0`이면 구간법은 끝자리 몇 개까지 가요. 같은 시험 문제에서 brentq(`max_iter=200`)는 근을 끼는 두 double에서 3 ULP 안, toms748(`rtol` = ε)은 1 ULP 안, bisect(`max_iter=1100`)는 4 ULP 안이에요.
- 근 근처의 f는 반올림 오차를 품고 계산돼요. f의 값이 반올림 크기로 흔들리는 범위 안에서는 부호를 믿을 수 없으니, 답의 정확도는 f를 계산하는 정확도를 넘지 못해요.
- 비용은 거의 f를 부르는 횟수예요. 방법 자체는 f 호출 하나에 brentq 0.6 µs, bisect 0.2 µs, toms748 0.5 µs, newton 0.8–1.1 µs쯤이에요(Apple M4 Pro). 자세한 방법은 [스칼라 근의 구현](/internals/optimize/scalar-roots/)에 있어요.

## scipy를 아는 분께

- scipy의 `brentq`, `toms748`, `bisect`, `newton` 같은 개별 함수는 없어요. `root_scalar(method=...)`로 골라요. `'brenth'`와 `'ridder'`는 없어요.
- 여섯 방법 모두 scipy 1.18.1과 같은 알고리즘과 멈춤 판정이고, 지금은 같은 점에서 f를 불러 같은 근, 같은 `n_iter`와 `nfev`를 내요(같은 f일 때; 비트까지 같지만 약속은 아니에요). 위의 예들도 scipy와 같아요.
- 결과는 scipy의 `RootResults` 대신 [OptimizeResult](/api/optimize/results/)예요. `root`는 `x`, `iterations`는 `n_iter`, `flag`는 `message`이고 `status`가 더 있어요. scipy의 `function_calls`는 세 함수의 호출을 합한 수라, newton·halley에서는 `nfev + njev + nhev`예요(차분 newton은 `nfev`와 같아요).
- `maxiter`는 `max_iter`예요. 사용자 함수의 `args`는 없어요(클로저로 넘겨요). `fprime=True`(f가 (f, f′)를 돌려주는 꼴)도 없어요.
- scipy는 방법이 쓰지 않는 인자(예: brentq의 `x0`)를 무시하지만 여기서는 `ValueError`예요. 방법 이름은 소문자만 받아요.
- scipy는 `xtol=0`을 받지 않아요(`ValueError: xtol too small (0 <= 0)`). 여기서는 받아요.
- toms748에서 f가 inf이면 scipy는 `ValueError`를 내고, 여기서는 NaN처럼 `status` −3의 결과를 돌려줘요. `k`가 100보다 크면 scipy는 경고하고 100으로 줄이지만 여기서는 `ValueError`예요.
- newton의 도함수가 0일 때와 secant의 두 f가 같을 때 scipy는 `RuntimeWarning`을 내고 `flag`는 `'convergence error'`예요. 여기서는 경고 없이 그 글이 `message`에 들어가요(`status`는 −2).
