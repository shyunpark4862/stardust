## 무엇을 하나요

연립방정식 $Ax = b$에서 식(행)이 변수(열)보다 많으면 보통 모든 식을 맞추는 x가 없어요. 그래서 어긋남 $Ax - b$의 제곱합을 가장 작게 하는 x를 고르는데, 이것이 선형 최소제곱이에요.

$$
\min_x \ \tfrac12 \lVert Ax - b\rVert^2 \quad \text{s.t.} \quad l \le x \le u
$$

경계가 없으면 [sd.linalg.lstsq](/api/linalg/lstsq/)가 한 번에 풀어요. 그런데 변수에 뜻이 있는 범위가 있을 때가 많아요. 섞인 성분의 비율은 0과 1 사이, 농도나 질량은 0 이상이어야 하죠. 경계 없는 해가 그 범위를 벗어나면, 벗어난 성분만 잘라 내는 것으로는 최소제곱 해가 되지 않아요. 다른 성분도 함께 다시 맞춰야 해요. `lsq_linear`는 상자 모양의 경계 $l \le x \le u$ 안에서 제곱합이 가장 작은 x를 구해요.

## 기본 사용

성분 세 개의 스펙트럼(A의 열)을 섞어 잰 스펙트럼 b를 얻었다고 해요. 각 성분의 비율 x는 0과 1 사이여야 해요.

```python
>>> A = sd.asarray([[1.0, 0.2, 0.0], [0.8, 0.5, 0.1], [0.3, 1.0, 0.3],
...                 [0.1, 0.6, 0.9], [0.0, 0.2, 1.0], [0.4, 0.4, 0.4]])
>>> b = sd.asarray([0.95, 1.05, 0.80, 0.35, 0.05, 0.55])
>>> sd.linalg.lstsq(A, b).solution
array([  0.8801086725575231,   0.5760754771218956, -0.07716907675194648], dtype=float64)
```

경계 없는 최소제곱 해는 셋째 비율이 음수예요. 경계를 주면 이렇게 돼요.

```python
>>> r = sd.optimize.lsq_linear(A, b, bounds=(0, 1))
>>> r
OptimizeResult(method='trf', converged=True, cost=0.00686803, n_iter=7, x=[0.901376, 0.511059, 5.73514e-13])
>>> r.status, r.message
(1, 'The first-order optimality measure is less than `tol`.')
>>> r.active_mask
array([ 0,  0, -1], dtype=int64)
```

셋째 비율은 아래 경계 0에 붙었고(`active_mask`의 −1), 나머지 둘도 경계 없는 해의 0.88, 0.58이 아니라 0.90, 0.51이에요. 음수를 0으로 자르기만 했다면 두 비율은 그대로였을 거예요. `cost`는 경계 없는 해의 0.0035보다 커요. 경계가 답을 제한한 만큼이에요.

## 경계가 없을 때와 lstsq

`lsq_linear`는 먼저 경계 없는 최소제곱 해를 구하고, 그 해가 경계 안이면 그대로 돌려줘요. 그때 `status`는 3, `n_iter`는 0이에요. `bounds`를 주지 않으면 늘 이 경우라서 [sd.linalg.lstsq](/api/linalg/lstsq/)와 같은 해예요.

```python
>>> r0 = sd.optimize.lsq_linear(A, b)
>>> r0.status, r0.n_iter, r0.message
(3, 0, 'The unconstrained solution is optimal.')
>>> r0.x.tolist() == sd.linalg.lstsq(A, b).solution.tolist()
True
```

경계가 필요 없으면 `lstsq`가 더 알맞아요. 우변 여러 개, 배치, 랭크와 특이값, 특이값을 0으로 볼 기준 `rtol`을 받아요. `lsq_linear`의 첫 풀이는 기계 정밀도 수준의 아주 작은 특이값만 0으로 봐요. 거의 겹치는 열이 있으면 두 함수의 해가 다를 수 있어요.

## 방법 고르기: method

| | `'trf'` (기본값) | `'bvls'` |
|---|---|---|
| 생각 | 상자 안쪽에서 출발해 안쪽에 머물며 다가가요(신뢰 영역 반사법) | 경계에 붙일 변수와 풀 변수를 나눠, 풀 변수만의 최소제곱을 되풀이해요(활성 집합법) |
| 경계 위의 해 | 경계 바로 안쪽(위의 5.7e-13) | 정확히 경계값 |
| 멈춤 | 1차 최적성 < `tol` 또는 비용의 상대 감소 < `tol` | 같아요(KKT 조건의 위반 < `tol`) |
| `max_iter` 기본 | 100 | n(처음 단계의 반복에 더해요) |

- **`'trf'`** 는 경계 없는 해를 상자 안으로 반사한 점에서 출발해요. 반복마다 경계까지의 거리로 척도를 맞춘 뉴턴 걸음을 하고, 걸음이 경계를 넘으면 경계 바로 앞에서 멈춘 걸음, 경계에서 반사한 걸음, 기울기 방향의 걸음 가운데 가장 좋은 것을 골라요. 반복점은 경계에 닿지 않고 경계를 향해 빠르게 다가가요(위 그림의 파란 선).
- **`'bvls'`** 는 경계에 붙은 변수를 그 값으로 고정하고 나머지만으로 `lstsq`를 풀어요. 그 해가 경계를 넘으면 넘는 변수를 경계에 붙이고, 고정한 변수 가운데 풀어 주면 제곱합이 줄어드는 것이 있으면 하나씩 풀어 줘요. 끝나면 최적성 조건(KKT)이 반올림 안에서 서요.

같은 문제를 `'bvls'`로 풀면 셋째 비율이 정확히 0이에요.

```python
>>> rb = sd.optimize.lsq_linear(A, b, bounds=(0, 1), method='bvls')
>>> rb
OptimizeResult(method='bvls', converged=True, cost=0.00686803, n_iter=2, x=[0.901376, 0.511059, 0])
>>> abs(rb.cost - r.cost) / rb.cost < 1e-11
True
```

두 방법의 `cost`는 상대 $10^{-11}$ 안에서 같아요. 경계 위의 값이 필요하거나(이 값을 다른 계산에 넘길 때), `active_mask`를 정확히 읽고 싶으면 `'bvls'`를 써요. 걸음 $x + \alpha(z - x)$로 경계에 닿은 변수는 반올림으로 경계를 아주 조금 넘을 수 있는데, `'bvls'`는 끝에 그 변수를 경계값으로 옮기고 `fun`, `cost`, `optimality`를 옮긴 x에서 다시 계산해요. 그래서 돌려주는 x는 언제나 경계 안이고, 경계에 걸린 변수(`active_mask`가 ±1)는 정확히 경계값이에요. 경계가 x ≥ 0뿐이면 [nnls](/api/optimize/nnls/)도 0인 성분을 정확히 0.0으로 줘요. 알고리즘의 자세한 내용은 [선형 최소제곱의 구현](/internals/optimize/linear-least-squares/)에 있어요.

## tol과 max_iter

`tol`(기본 $10^{-10}$)은 두 판정에 같이 써요. 1차 최적성의 척도(`optimality`)가 `tol`보다 작으면 `status` 1, 한 반복의 비용 감소가 `tol`·`cost`보다 작으면 `status` 2로 멈춰요. `'trf'`는 경계를 향해 다가가는 방법이라 `tol`이 작을수록 경계에 더 가까이 가요.

```python
>>> [f'{sd.optimize.lsq_linear(A, b, bounds=(0, 1), tol=t).x[2]:.1e}' for t in (1e-2, 1e-6, 1e-10, 1e-14)]
['1.9e-02', '2.1e-07', '5.7e-13', '4.3e-24']
```

`max_iter`에 닿으면 그때의 점을 돌려주고 `status`가 0, `converged`가 False예요. 예외는 나지 않아요.

```python
>>> r2 = sd.optimize.lsq_linear(A, b, bounds=(0, 1), max_iter=2)
>>> r2.converged, r2.status, r2.message
(False, 0, 'The maximum number of iterations is exceeded.')
```

## 결과 읽기

| 필드 | 뜻 |
|---|---|
| `x` | 해 (n,) |
| `cost` | ½‖Ax − b‖² (`float`) |
| `fun` | 잔차 Ax − b (m,) |
| `optimality` | 1차 최적성의 척도. `'trf'`는 경계까지의 거리를 곱한 기울기의 ‖·‖∞, `'bvls'`와 경계 없는 해는 KKT 조건의 최대 위반 |
| `active_mask` | 변수마다 경계에 걸렸는지 (n,) int64. −1 아래, 0 안쪽, 1 위 |
| `converged` | `status > 0`이고 `cost`가 유한한지 |
| `status`, `message` | 멈춘 이유(아래 표) |
| `n_iter` | 반복 수. 경계 없는 해로 끝나면 0 |
| `method` | `'trf'` 또는 `'bvls'` |

| `status` | `message` |
|---:|---|
| −1 | `The algorithm was not able to make progress on the last iteration.` |
| 0 | `The maximum number of iterations is exceeded.` |
| 1 | ``The first-order optimality measure is less than `tol`.`` |
| 2 | ``The relative change of the cost function is less than `tol`.`` |
| 3 | `The unconstrained solution is optimal.` |

`'trf'`의 `active_mask`는 경계에서 `tol`·max(1, |경계|) 안에 있는 변수만 걸린 것으로 쳐요. 해가 경계 바로 안쪽이라, 판정이 그 거리보다 먼저 통과하면 경계에 붙은 변수도 0으로 나올 수 있어요. 위 그림의 문제가 그래요. 해는 모서리 (1, 0)인데 `'trf'`는 두 경계에서 각각 $1.1\times10^{-10}$, $1.3\times10^{-10}$ 떨어진 곳에서 멈춰서, `tol` = $10^{-10}$의 거리 안에 들지 않아요.

```python
>>> A2 = sd.asarray([[1.0, 0.4], [0.3, 1.0], [0.8, -0.5], [0.2, 0.3]])
>>> b2 = sd.asarray([1.2, -0.1, 1.5, 0.2])
>>> sd.optimize.lsq_linear(A2, b2, bounds=(0, 1)).active_mask
array([0, 0], dtype=int64)
>>> sd.optimize.lsq_linear(A2, b2, bounds=(0, 1), method='bvls').active_mask
array([ 1, -1], dtype=int64)
```

어느 변수가 경계에 붙었는지가 중요하면 `'bvls'`를 쓰거나, `x`와 경계의 거리를 직접 봐요.

## 특수한 경우

- **열이 겹칠 때**(A의 랭크가 n보다 작을 때): 최소제곱 해가 하나로 정해지지 않아요. 경계 없는 해는 노름이 가장 작은 해이고, 경계가 있으면 최적인 해 가운데 하나에 닿아요. `cost`는 어느 해든 같아요.
- **입력**: A와 b는 유한해야 해요. b는 1차원만 받아요. 희소 행렬이나 연산자(행렬 없이 곱만 주는 것)는 받지 않아요.

```python
>>> sd.optimize.lsq_linear(A, b[:5])
Traceback (most recent call last):
    ...
ValueError: lsq_linear(): 'b' must have 6 values (one per row of 'A'), not 5
>>> sd.optimize.lsq_linear(A, b, bounds=(1, 0))
Traceback (most recent call last):
    ...
ValueError: lsq_linear(): each lower bound must be less than its upper bound
>>> sd.optimize.lsq_linear(A, b, bounds=([0, 0], [1, 1]))
Traceback (most recent call last):
    ...
ValueError: lsq_linear(): 'bounds' must have 3 values (one per column of 'A'), not 2
```

`bounds`는 `(lower, upper)` 꼴이에요. 변수마다의 쌍 `[(0, 1), (0, 1), (0, 1)]`은 `ValueError`이고(쌍이 둘이면 `(lower, upper)`로 읽어요), 변수마다 범위를 줄 때는 `([l1, l2, l3], [u1, u2, u3])`로 써요.

## 다른 함수와 비교

- [sd.linalg.lstsq](/api/linalg/lstsq/): 경계가 없을 때. 배치와 우변 여러 개를 받아요.
- [nnls](/api/optimize/nnls/): 경계가 x ≥ 0뿐일 때의 전용 함수예요. `lsq_linear(A, b, bounds=(0, sd.inf))`와 같은 문제이고, 해를 정확히 0에 둬요.
- [least_squares](/api/optimize/least_squares/): 잔차가 x에 대해 일차가 아닐 때예요. 일차 문제도 풀 수 있지만 시작점, 반복, Python 함수 호출이 필요하고 답이 허용오차만큼만 맞아요.

## 스레드와 GIL

사용자 함수가 없어서 계산 전체가 C++에서 돌아요. 큰 문제(대략 $2mn^2 > 2\times10^5$)는 GIL을 놓고 풀어서, 다른 Python 스레드가 그동안 돌 수 있어요.

## scipy를 아는 분께

- 같은 알고리즘이고, 지금은 결과가 scipy 1.18.1과 비트까지 같아요(`x`, `cost`, `fun`, `optimality`, `active_mask`, `status`, `message`, 반복 수; 약속은 아니에요). 다만 `'bvls'`에서 scipy의 x가 경계를 반올림만큼 넘는 경우는 여기서 x를 경계로 옮기므로 `x`, `fun`, `cost`, `optimality`의 끝자리가 달라요(반복 수와 `status`는 같아요).
- 이름: `nit`는 `n_iter`, `success`는 `converged`예요. `A`, `b`는 위치로만, 나머지는 키워드로만 받아요.
- 받지 않는 것: `lsq_solver='lsmr'`, `lsmr_tol`, `lsmr_maxiter`, `verbose`, 희소 행렬과 `LinearOperator`. 결과에 `unbounded_sol`이 없어요. `bounds`의 기본값은 `None`이에요.
- `active_mask`는 늘 int64예요(scipy는 `'bvls'`와 경계 없는 해에서 float).
- A와 b가 유한하지 않으면 `ValueError`예요(scipy는 보지 않아요).

```python
>>> import numpy as np
>>> from scipy.optimize import lsq_linear as scipy_lsq_linear
>>> s = scipy_lsq_linear(np.array(A.tolist()), np.array(b.tolist()), bounds=(0, 1), method='bvls')
>>> s.x.tolist() == rb.x.tolist(), s.nit, s.active_mask
(True, 2, array([ 0.,  0., -1.]))
```
