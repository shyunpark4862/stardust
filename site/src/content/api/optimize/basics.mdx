## 최적화가 푸는 문제

`sd.optimize`는 함수를 넣으면 그 함수가 어떤 조건을 만족하는 점을 찾아 주는 함수들의 모음이에요. 찾는 점의 종류에 따라 네 가지로 나뉘어요.

| 문제 | 찾는 것 | 예 |
|---|---|---|
| 근 찾기 | $f(x) = 0$인 $x$ | 이자율, 손익분기점, 방정식의 해 |
| 최솟값 찾기 | $f(x)$가 가장 작은 $x$ | 비용을 가장 적게, 이익을 가장 크게 하는 설정 |
| 최소제곱 | 잔차의 제곱합 $\tfrac12\sum_i r_i(x)^2$이 가장 작은 $x$ | 데이터에 곡선 맞추기 |
| 방정식계 | 식 $n$개 $F_1(x) = \dots = F_n(x) = 0$을 함께 만족하는 $x$ | 평형점, 교점 |

네 문제 모두 답을 식으로 바로 적을 수 없을 때가 많아요. 그래서 함수들은 **반복**으로 풀어요. 시작점(또는 답을 끼고 있는 구간)에서 출발해 함수를 여러 번 불러 보며 답에 다가가고, 정해 둔 **멈춤 판정**을 통과하면 그 점을 돌려줘요. 결과에는 찾은 점과 함께 판정을 통과했는지(`converged`), 함수를 몇 번 불렀는지(`nfev`) 같은 정보가 들어 있어요.

### 근 찾기

$x^3 - 2x - 5 = 0$의 근을 찾아요. $x = 2$에서 $-1$, $x = 3$에서 $16$이라 부호가 바뀌니 그 사이에 근이 있어요. 이렇게 부호가 바뀌는 구간을 **근을 끼는 구간**(bracket)이라고 해요.

```python
>>> import stardust as sd
>>> f = lambda x: x**3 - 2*x - 5
>>> r = sd.optimize.root_scalar(f, bracket=(2.0, 3.0))
>>> r
OptimizeResult(method='brentq', converged=True, n_iter=7, nfev=8, x=2.09455)
>>> f(r.x)
3.552713678800501e-15
```

[`root_scalar`](/api/optimize/root_scalar/)는 Brent법(`'brentq'`)으로 구간을 좁혀 근 2.0945…를 찾았어요. 함수를 8번 불렀어요. 어디서 불렀는지 기록해 보면 반복이 다가가는 모습이 보여요.

```python
>>> calls = []
>>> def logged(x):
...     calls.append(x)
...     return x**3 - 2*x - 5
>>> r = sd.optimize.root_scalar(logged, bracket=(2.0, 3.0))
>>> [round(x, 6) for x in calls]
[2.0, 3.0, 2.058824, 2.095659, 2.094529, 2.094551, 2.094551, 2.094551]
>>> len(calls) == r.nfev
True
```

구간의 두 끝을 먼저 계산하고, 그다음부터는 지금까지의 값으로 근의 자리를 어림해 그 점을 계산해요. 어림이 맞을수록 다음 점이 근에 훨씬 가까워져요. 근과의 거리가 0.036, 0.0011, 2.3×10⁻⁵, 1.4×10⁻⁸로 줄어요.

### 최솟값 찾기

가로세로 20cm인 종이의 네 귀퉁이에서 한 변이 $x$인 정사각형을 잘라 내고 접으면 뚜껑 없는 상자가 돼요. 부피는 $V(x) = x(20 - 2x)^2$이에요. 부피가 가장 큰 $x$를 찾으려면 $-V$의 최솟값을 찾으면 돼요. 최댓값을 찾는 함수는 따로 없고, 언제나 부호를 바꿔 최솟값으로 풀어요.

```python
>>> volume = lambda x: x * (20 - 2*x)**2
>>> r = sd.optimize.minimize_scalar(lambda x: -volume(x), bounds=(0.0, 10.0))
>>> r
OptimizeResult(method='bounded', converged=True, fun=-592.593, n_iter=10, nfev=10, x=3.33333)
>>> r.x
3.333333308782097
>>> round(volume(r.x), 4)
592.5926
```

참값은 $x = 10/3$이에요. 찾은 점은 $2.5 \times 10^{-8}$만큼 떨어져 있어요. `bounds`를 주면 [`minimize_scalar`](/api/optimize/minimize_scalar/)는 그 범위 안에서만 찾고, 범위가 `xatol=1e-5` 정도로 좁아지면 멈춰요. 최솟값 근처에서는 함수가 평평해서 위치를 아주 정확히 정하기 어렵다는 점도 기억해 두세요. 이 이야기는 [허용오차](#허용오차는-멈춤-판정이에요)에서 다시 해요.

변수가 여러 개면 [`minimize`](/api/optimize/minimize/)를 써요. 최적화 방법을 시험할 때 흔히 쓰는 Rosenbrock 함수 $(1 - x_0)^2 + 100(x_1 - x_0^2)^2$은 $(1, 1)$에서 가장 작아요. 그 둘레가 길고 휘어진 골짜기라 찾기가 까다로워요.

```python
>>> rosen = lambda x: (1 - x[0])**2 + 100 * (x[1] - x[0]**2)**2
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0])
>>> r
OptimizeResult(method='bfgs', converged=True, fun=2.69158e-11, n_iter=31, nfev=114, x=[0.999995, 0.99999])
```

`minimize`의 `x`는 길이 $n$인 `sd.ndarray`예요. 기울기를 주지 않았으니 BFGS가 차분으로 기울기를 어림했고, 그 계산도 `nfev`에 들어가요.

### 최소제곱

어떤 물질의 양을 1시간마다 8번 쟀어요. 양은 $a e^{-bt}$ 꼴로 줄어든다고 보고 $a$와 $b$를 정하고 싶어요. 각 측정에서 모형과 데이터의 차이 $r_i = a e^{-b t_i} - y_i$를 **잔차**라고 하고, 잔차의 제곱합이 가장 작은 $(a, b)$를 찾는 것이 **최소제곱**이에요.

```python
>>> t = sd.asarray([0.0, 1, 2, 3, 4, 5, 6, 7])
>>> y = sd.asarray([5.1, 3.0, 1.9, 1.1, 0.72, 0.38, 0.27, 0.13])
>>> r = sd.optimize.least_squares(lambda p: p[0] * sd.exp(-p[1] * t) - y, [1.0, 1.0])
>>> r
OptimizeResult(method='trf', converged=True, cost=0.00562354, n_iter=7, nfev=21, x=[5.07832, 0.504554])
```

[`least_squares`](/api/optimize/least_squares/)에 주는 함수는 제곱합이 아니라 잔차 8개를 돌려줘요. 함수가 잔차 하나하나를 알려 주면 각 잔차가 $a$, $b$에 따라 어떻게 바뀌는지(야코비안)를 쓸 수 있어서, 제곱합 하나만 아는 `minimize`보다 대개 적은 계산으로 풀어요. 결과의 `cost`는 $\tfrac12\sum r_i^2$이에요.

### 방정식계

원 $x^2 + y^2 = 4$와 곡선 $y = 1 - e^x$이 만나는 점을 찾아요. 두 식을 $F(x, y) = 0$ 꼴로 쓰고 [`root`](/api/optimize/root/)에 줘요. 변수 $(x, y)$는 배열 하나로 받아요.

```python
>>> F = lambda v: [v[0]**2 + v[1]**2 - 4, sd.exp(v[0]) + v[1] - 1]
>>> r = sd.optimize.root(F, [1.0, -1.0])
>>> r
OptimizeResult(method='hybr', converged=True, n_iter=8, nfev=11, x=[1.00417, -1.72964])
>>> r2 = sd.optimize.root(F, [-2.0, 1.0])
>>> r2.x
array([-1.8162640688252603,  0.8373677998912576], dtype=float64)
```

교점이 둘이라 시작점에 따라 다른 교점을 찾아요. 반복 방법은 시작점 가까이의 답을 찾을 뿐, 답이 몇 개인지는 알려 주지 않아요.

함수마다 고를 수 있는 방법(`method`)과 사용자가 줘야 하는 것을 모으면 이래요.

| 문제 | 함수 | `method` | 주는 것 |
|---|---|---|---|
| 변수 하나의 근 | [`root_scalar`](/api/optimize/root_scalar/) | `'brentq'`, `'toms748'`, `'bisect'`(구간), `'newton'`, `'halley'`, `'secant'`(시작점) | `f`와 `bracket`, 또는 `x0`(와 도함수 `fprime`, `fprime2`) |
| 같은 꼴의 근 여러 개 | [`find_root`, `bracket_root`](/api/optimize/find_root/) | 하나(Chandrupatla의 구간법) | 배열을 받는 `f`, 구간, 원소마다 다른 상수 `args` |
| 변수 하나의 최솟값 | [`minimize_scalar`](/api/optimize/minimize_scalar/) | `'brent'`, `'golden'`, `'bounded'` | `f`, 필요하면 `bracket`이나 `bounds` |
| 같은 꼴의 최솟값 여러 개 | [`find_minimum`, `bracket_minimum`](/api/optimize/find_minimum/) | 하나(Chandrupatla) | 배열을 받는 `f`, 세 점 |
| 변수 여러 개의 최솟값 | [`minimize`](/api/optimize/minimize/) | `'nelder-mead'`, `'bfgs'`, `'l-bfgs-b'`, `'newton-cg'`, `'trust-ncg'`, `'trust-exact'` | `fun`, `x0`, 필요하면 기울기 `jac`, 헤시안 `hess`, `bounds` |
| 비선형 최소제곱 | [`least_squares`](/api/optimize/least_squares/) | `'trf'`, `'lm'` | 잔차를 돌려주는 `fun`, `x0`, 필요하면 `jac`, `bounds` |
| 범위가 있는 선형 최소제곱 | [`lsq_linear`](/api/optimize/lsq_linear/) | `'trf'`, `'bvls'` | 행렬 `A`, 벡터 `b`, `bounds` |
| 음이 아닌 선형 최소제곱 | [`nnls`](/api/optimize/nnls/) | 하나(Lawson–Hanson) | `A`, `b` |
| 방정식계 | [`root`](/api/optimize/root/) | `'hybr'`, `'lm'` | 값 $n$개를 돌려주는 `fun`, `x0`, 필요하면 `jac` |
| 기울기, 야코비안 | [`approx_fprime`](/api/optimize/approx_fprime/), [`check_grad`](/api/optimize/check_grad/) | | 함수와 점 |

목록에 없는 것도 있어요. 제약식이 있는 최적화(SLSQP 같은 것), 선형계획법, 전역 최적화(여러 지역 최솟값 가운데 가장 작은 것을 찾는 방법), 확률적 경사 하강법은 `sd.optimize`에 없어요. 범위가 없는 선형 최소제곱은 [`sd.linalg.lstsq`](/api/linalg/lstsq/)나 [`sd.regression.ols`](/api/regression/ols/)가 더 알맞아요.

### 나머지 함수도 한 줄씩

같은 꼴의 문제를 원소마다 다른 상수로 여러 번 풀 때는 배치 함수가 편해요. $x^2 = c$를 $c = 2, 3, 5$에 대해 한 번에 풀어요. 사용자 함수는 원소 하나가 아니라 아직 풀리지 않은 원소들을 모은 배열을 받아요.

```python
>>> c = sd.asarray([2.0, 3.0, 5.0])
>>> r = sd.optimize.find_root(lambda x, c: x**2 - c, (0.0, 10.0), args=(c,))
>>> r
OptimizeResult(batch shape (3,), 3 of 3 converged)
>>> r.x
array([ 1.414213562373095, 1.7320508075688774,   2.23606797749979], dtype=float64)
```

잔차가 $x$에 대해 일차식 $Ax - b$이면 시작점 없이 정확히 풀어요. 직선 $y = x_0 + x_1 t$를 네 점에 맞추되 두 계수가 0 이상이어야 한다고 해 봐요.

```python
>>> A = sd.asarray([[1.0, 0.0], [1, 1], [1, 2], [1, 3]])
>>> b = sd.asarray([1.0, 0.4, -0.3, -0.9])
>>> sd.optimize.nnls(A, b)
OptimizeResult(method='nnls', converged=True, cost=1.025, n_iter=1, x=[0.05, 0])
>>> sd.optimize.lsq_linear(A, b, bounds=([0.0, -0.5], [2.0, 0.0]), method='bvls')
OptimizeResult(method='bvls', converged=True, cost=0.05, n_iter=2, x=[0.8, -0.5])
```

기울기를 손으로 쓰기 어렵거나, 쓴 것이 맞는지 확인하고 싶을 때는 수치 미분을 써요.

```python
>>> import math
>>> h = lambda x: math.exp(x[0]) * math.sin(x[1])
>>> sd.optimize.approx_fprime([1.0, 2.0], h)
array([ 2.4717266720042517, -1.1312043837571462], dtype=float64)
>>> dh = lambda x: [math.exp(x[0]) * math.sin(x[1]), math.exp(x[0]) * math.cos(x[1])]
>>> sd.optimize.check_grad(h, dh, [1.0, 2.0])
6.574515403815037e-13
```

참 기울기는 $(e \sin 2, e \cos 2) = (2.4717266720048…, -1.1312043837568…)$이에요. `approx_fprime`은 상대 $10^{-12}$ 안으로 맞혔고, `check_grad`는 두 기울기의 차이가 그만큼 작다고 알려 줘요.

### minimize의 방법 고르기

`minimize`의 여섯 방법은 함수에 대해 무엇을 알고 있느냐로 골라요. 자세한 것은 각 방법의 페이지에 있어요.

| `method` | 쓰는 것 | `bounds` | 이럴 때 |
|---|---|---|---|
| `'nelder-mead'` | 함숫값만 | 받아요 | 기울기를 구할 수 없거나 함수가 매끄럽지 않을 때, 변수가 적을 때 |
| `'bfgs'`(기본) | 함숫값, 기울기(없으면 차분) | 안 받아요 | 매끄러운 함수의 첫 선택 |
| `'l-bfgs-b'`(`bounds`가 있을 때 기본) | 함숫값, 기울기(없으면 차분) | 받아요 | 변수에 범위가 있을 때, 변수가 아주 많을 때 |
| `'newton-cg'` | 함숫값, 기울기(꼭), 헤시안이나 헤시안과 벡터의 곱 | 안 받아요 | 헤시안을 곱으로만 싸게 구할 수 있을 때 |
| `'trust-ncg'` | 함숫값, 기울기(꼭), `hess`나 `hessp`(꼭) | 안 받아요 | 위와 같은 정보로 신뢰 영역 방법을 쓰고 싶을 때 |
| `'trust-exact'` | 함숫값, 기울기(꼭), 헤시안 행렬(꼭) | 안 받아요 | 변수가 적고 헤시안 행렬을 구할 수 있을 때 |

방법의 생각은 [Nelder–Mead](/api/optimize/nelder-mead/), [준뉴턴 방법](/api/optimize/quasi-newton/), [뉴턴 방법](/api/optimize/newton-methods/)에서 설명해요.

### 헷갈리기 쉬운 짝

**`root_scalar`와 `find_root`.** 둘 다 변수 하나의 근을 찾아요. `root_scalar`는 문제 하나를 풀고 방법 여섯 가지와 도함수를 쓸 수 있어요. `find_root`는 같은 꼴의 문제 많은 개(수천에서 수백만)를 한 번에 푸는 배치 함수예요. 사용자 함수를 원소마다 부르지 않고 남은 원소를 모은 배열로 한 번에 불러서, 함수가 배열 연산이면 원소 하나당 비용이 아주 작아요. `minimize_scalar`와 `find_minimum`도 같은 관계예요.

**`minimize_scalar`와 변수 하나짜리 `minimize`.** `minimize_scalar`는 시작점이나 도함수 없이 구간만으로 찾고, 함수는 Python `float`를 받아요. `minimize`는 길이 1이어도 배열을 넘겨서, `x**4` 대신 `x[0]**4`처럼 원소를 꺼내 써야 해요.

```python
>>> g = lambda x: x**4 - 3*x**2 + x
>>> sd.optimize.minimize(g, [0.5])
Traceback (most recent call last):
    ...
ValueError: minimize(): 'fun' must return a real number, not shape (1,)
>>> sd.optimize.minimize(lambda x: g(x[0]), [0.5]).x
array([1.1309010848006542], dtype=float64)
```

**`minimize`와 `least_squares`.** 목적함수가 제곱합이면 `least_squares`에 잔차를 주는 편이 나아요. 위의 감쇠 데이터를 두 함수로 풀면 같은 점을 찾지만 `least_squares`가 함수를 덜 불러요.

```python
>>> resid = lambda p: p[0] * sd.exp(-p[1] * t) - y
>>> sd.optimize.least_squares(resid, [1.0, 1.0]).nfev
21
>>> sd.optimize.minimize(lambda p: float(sd.sum(resid(p)**2)), [1.0, 1.0]).nfev
42
```

**`least_squares`와 `lsq_linear`·`nnls`.** 잔차가 일차식이면 `lsq_linear`이나 `nnls`가 시작점 없이 정확한 해를 줘요. `least_squares`로도 풀 수 있지만 반복으로 다가가므로 끝자리가 조금 다르고 함수를 여러 번 불러요.

**`root`와 `least_squares`.** `root`는 식과 변수의 수가 같은 방정식계만 받아요. 식이 더 많으면 모든 식을 정확히 만족하는 점이 대개 없으니, 제곱합을 가장 작게 하는 `least_squares`를 써요.

```python
>>> eqs = lambda v: [v[0] - 1, v[1] - 2, v[0] + v[1] - 3.5]
>>> sd.optimize.root(eqs, [0.0, 0.0])
Traceback (most recent call last):
    ...
ValueError: root(): 'fun' must return 2 values (one per variable), not 3
>>> sd.optimize.least_squares(eqs, [0.0, 0.0]).x
array([1.1666666666666665, 2.1666666666666665], dtype=float64)
```

**`least_squares`와 `sd.regression.nls`.** 둘은 같은 커널로 반복해요. `least_squares`는 최소화만 하고, `nls`는 모형 $f(x, \theta)$와 데이터 $(x, y)$를 받아 표준오차, p값, 예측 구간 같은 통계 추론을 더해요.

`minimize_scalar`는 구간을 주지 않으면 0과 1에서 내리막을 따라 구간을 찾아요. 그래서 오른쪽 골짜기에 머물러요. `converged=True`는 "판정을 통과했다"는 뜻일 뿐, 가장 깊은 골짜기라는 뜻이 아니에요.

```python
>>> sd.optimize.minimize_scalar(g)
OptimizeResult(method='brent', converged=True, fun=-1.07023, n_iter=13, nfev=16, x=1.1309)
>>> sd.optimize.minimize_scalar(g, bracket=(-2.0, -1.0))
OptimizeResult(method='brent', converged=True, fun=-3.51391, n_iter=11, nfev=14, x=-1.30084)
```

어디가 가장 깊은지 모를 때는 시작점을 여러 개 써 보고 가장 작은 값을 고르세요. 변수가 하나면 배치 함수로 한 번에 할 수 있어요. 시작점 다섯 개에서 [`bracket_minimum`](/api/optimize/find_minimum/)으로 구간을 찾고 `find_minimum`으로 좁혀요.

```python
>>> b = sd.optimize.bracket_minimum(g, sd.linspace(-2.0, 2.0, 5))
>>> m = sd.optimize.find_minimum(g, b.bracket)
>>> m.x
array([-1.3008395596534363,  -1.300839570936242, -1.3008395596534363,
         1.130901121320221,   1.130901125772359], dtype=float64)
>>> float(sd.min(m.fun))
-3.5139050389347886
```

근도 마찬가지예요. 근이 여러 개인 함수에서는 구간이나 시작점이 어느 근을 찾을지 정해요. [방정식계의 예](#방정식계)처럼 시작점을 바꾸면 다른 답이 나와요.

### 척도

허용오차는 값의 크기와 상관없이 고정된 수라서, 함수나 변수의 크기가 아주 크거나 작으면 판정의 뜻이 달라져요. BFGS는 기울기의 크기가 `gtol=1e-5` 이하이면 멈춰요. Rosenbrock 함수에 $10^{-8}$을 곱하면 최솟값의 자리는 그대로인데 시작점에서 이미 기울기가 $10^{-5}$보다 작아서, 한 걸음도 가지 않고 "수렴"해요.

```python
>>> sd.optimize.minimize(lambda x: 1e-8 * rosen(x), [-1.2, 1.0])
OptimizeResult(method='bfgs', converged=True, fun=2.42e-07, n_iter=0, nfev=3, x=[-1.2, 1])
```

이럴 때는 함수와 변수가 1 근처의 크기가 되도록 단위를 바꾸거나, 허용오차를 그 척도에 맞춰 주세요.

```python
>>> sd.optimize.minimize(lambda x: 1e-8 * rosen(x), [-1.2, 1.0], options={'gtol': 1e-13}).x
array([0.9999955227207727, 0.9999910379874495], dtype=float64)
```

반대로 아주 큰 값을 곱하면 기울기가 반올림 때문에 `gtol`까지 내려가지 못하고 `converged=False`로 멈출 수 있어요. 그때도 `x`는 답 가까이에 있을 수 있으니 `status`와 `message`를 읽고 판단해요.

```python
>>> r = sd.optimize.minimize(lambda x: 1e4 * rosen(x), [-1.2, 1.0])
>>> r.converged, r.status, r.message
(False, 2, 'Desired error not necessarily achieved due to precision loss.')
>>> r.x
array([0.9999955225150067, 0.9999910376489757], dtype=float64)
```

## 공통 규칙

여기부터는 `sd.optimize`의 모든 함수가 함께 따르는 약속이에요. 함수마다 다른 것은 그 함수의 페이지에 있어요.

### 사용자 함수

사용자가 주는 함수(`fun`, `f`, `jac`, `hess` 등)는 Python에서 부를 수 있는 객체면 돼요. 넘겨받는 값은 이래요.

| 함수 | 사용자 함수가 받는 x | 돌려줘야 하는 것 |
|---|---|---|
| `root_scalar`, `minimize_scalar` | Python `float` | 실수 하나 |
| `minimize` | float64 `sd.ndarray` $(n,)$ | 실수 하나. 기울기 `jac`은 $n$개, 헤시안 `hess`는 $(n, n)$ |
| `least_squares` | float64 `sd.ndarray` $(n,)$ | 잔차 $m$개(1차원). `jac`은 $(m, n)$ |
| `root` | float64 `sd.ndarray` $(n,)$ | 값 $n$개. `jac`은 $(n, n)$ |
| `find_root` 등 배치 함수 | 아직 풀리지 않은 원소를 모은 float64 `sd.ndarray` $(k,)$ | 값 $k$개 |
| `approx_fprime`, `check_grad` | float64 `sd.ndarray` $(n,)$ | 실수 하나, 또는 값 $m$개 |

```python
>>> seen = []
>>> def fun(x):
...     seen.append((type(x).__name__, str(x.dtype), x.shape))
...     return float(sd.sum((x - 1.0)**2))
>>> r = sd.optimize.minimize(fun, [0, 0])
>>> seen[0]
('ndarray', 'float64', (2,))
```

- `x0`를 정수 리스트 `[0, 0]`로 줘도 float64로 바꿔서 계산해요.
- 사용자 함수가 받는 `x`는 호출마다 새로 만든 배열이에요. 함수 안에서 고쳐도 반복에는 영향이 없어요.
- 실수 하나는 Python 수, numpy 수, 0차원 numpy 배열로 돌려주면 돼요. 값 여러 개는 `sd.ndarray`, 실수의 리스트, numpy 배열로 돌려주면 돼요.
- 사용자 함수가 낸 에러는 바꾸지 않고 그대로 나와요.

```python
>>> sd.optimize.minimize(lambda x: math.log(x[0]), [-1.0])
Traceback (most recent call last):
    ...
ValueError: expected a positive input, got -1.0
```

모양이 틀린 값을 돌려주면 `ValueError`예요. 메시지에 기대한 모양과 받은 모양이 함께 나와요.

```python
>>> sd.optimize.minimize(lambda x: x, [1.0, 2.0, 3.0])
Traceback (most recent call last):
    ...
ValueError: minimize(): 'fun' must return a real number, not shape (3,)
>>> sd.optimize.least_squares(lambda x: [[1.0, 2.0]], [1.0, 2.0])
Traceback (most recent call last):
    ...
ValueError: least_squares(): 'fun' must return a 1-dimensional array, not shape (1, 2)
```

#### 상수는 클로저로 넘겨요

사용자 함수에 더 넘길 상수가 있어도 `args=` 인자는 없어요. `lambda`나 클로저로 묶어 주세요. 배치 함수만 예외예요. 원소마다 다른 상수를 넘겨야 해서 `args`를 받아요(위의 [`find_root` 예](#나머지-함수도-한-줄씩)).

```python
>>> dist = lambda x, a: float(sd.sum((x - a)**2))
>>> sd.optimize.minimize(dist, [0.0, 0.0], args=(1.0,))
Traceback (most recent call last):
    ...
TypeError: minimize(): unexpected keyword argument 'args'
>>> sd.optimize.minimize(lambda x: dist(x, 1.0), [0.0, 0.0]).converged
True
```

### 입력은 위치로, 옵션은 키워드로

함수와 시작점(`fun`, `x0`, `A`, `b` 등)은 이름 없이 위치로만 주고, 나머지는 모두 키워드로만 줘요.

```python
>>> sd.optimize.minimize(rosen, x0=[-1.2, 1.0])
Traceback (most recent call last):
    ...
TypeError: minimize(): got some positional-only arguments passed as keyword arguments: 'x0'
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], 'bfgs')
Traceback (most recent call last):
    ...
TypeError: minimize(): takes 2 positional arguments but 3 were given
```

`x0`는 1차원이고 비어 있지 않고 유한해야 해요. 실수의 리스트, `sd.ndarray`, numpy 배열, `sd.frame`의 `Series`를 받고, bool과 정수는 float64로 바꿔요. 복소수는 받지 않아요. `Series`의 빠진 값은 NaN이라 유한하지 않아서 `ValueError`예요.

```python
>>> sd.optimize.minimize(rosen, [1.0, sd.nan])
Traceback (most recent call last):
    ...
ValueError: minimize(): 'x0' must be finite
>>> sd.optimize.minimize(rosen, 1.0)
Traceback (most recent call last):
    ...
ValueError: minimize(): 'x0' must be 1-dimensional, not a scalar
>>> sd.optimize.minimize(rosen, [1 + 2j, 1.0])
Traceback (most recent call last):
    ...
TypeError: minimize(): 'x0' must be real, not a complex128 array
```

### method는 소문자 이름

방법 이름은 소문자만 받아요. 대소문자만 다르면 맞는 이름을 알려 줘요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], method='BFGS')
Traceback (most recent call last):
    ...
ValueError: minimize(): 'method' must be lowercase: 'bfgs', not 'BFGS'
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], method='cg')
Traceback (most recent call last):
    ...
ValueError: minimize(): 'method' must be 'nelder-mead', 'bfgs', 'l-bfgs-b', 'newton-cg', 'trust-ncg' or 'trust-exact', not 'cg'
```

방법과 맞지 않는 인자도 에러예요. 그 방법이 쓰지 않는 인자는 무시되지 않고 에러로 알려 줘요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], method='bfgs', bounds=(0.0, 2.0))
Traceback (most recent call last):
    ...
ValueError: minimize(): method='bfgs' takes no 'bounds' (method='l-bfgs-b' and method='nelder-mead' do)
>>> sd.optimize.root_scalar(f, method='newton')
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'x0' is required when method='newton'
```

### 방법마다의 옵션은 options

`minimize`, `minimize_scalar`, `root`, `root_scalar`는 방법마다 다른 옵션을 `options=` dict로 받아요. 방법이 모르는 키는 `ValueError`예요. 철자가 틀린 옵션이 조용히 무시되지 않아요.

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], options={'gtol': 1e-8, 'max_iter': 100})
>>> r.converged, r.n_iter
(True, 32)
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], options={'xatol': 1e-3})
Traceback (most recent call last):
    ...
ValueError: minimize(): method='bfgs' has no option 'xatol'
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], options=[('max_iter', 3)])
Traceback (most recent call last):
    ...
TypeError: minimize(): 'options' must be a dict or None, not list
```

반복 상한의 이름은 어디서나 `max_iter`(반복 수)와 `max_nfev`(함수 계산 수)예요. scipy의 `maxiter`, `maxfev`, `maxfun`을 쓰면 이쪽 이름을 알려 줘요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], options={'maxiter': 10})
Traceback (most recent call last):
    ...
ValueError: minimize(): method='bfgs' has no option 'maxiter' (the iteration cap is 'max_iter')
```

`tol=`은 방법의 주된 허용오차를 정하는 지름길이에요(BFGS는 `gtol`, Nelder–Mead는 `xatol`과 `fatol`). 같은 것을 `options`에도 주면 어느 쪽을 쓸지 모호하니 에러예요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], tol=1e-8, options={'gtol': 1e-8})
Traceback (most recent call last):
    ...
ValueError: minimize(): give 'tol' or options['gtol'], not both
```

어느 옵션이든 값이 `None`이면 그 옵션의 기본값을 써요. 그래서 `tol`과 함께 준 같은 키가 `None`이면 충돌이 아니에요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], tol=1e-8, options={'gtol': None}).converged
True
```

옵션 값의 검사는 다른 영역과 같은 꼴이에요. 정수 옵션에 float를, bool 옵션에 정수를 주면 `TypeError`이고, 허용오차는 0 이상의 유한한 수여야 해요.

```python
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], options={'max_iter': 2.0})
Traceback (most recent call last):
    ...
TypeError: minimize(): 'max_iter' must be an int, not float
>>> sd.optimize.minimize(rosen, [-1.2, 1.0], options={'gtol': -1.0})
Traceback (most recent call last):
    ...
ValueError: minimize(): 'gtol' must be a finite number >= 0
```

### 허용오차는 멈춤 판정이에요

`xtol`, `rtol`, `ftol`, `gtol`, `xatol` 같은 허용오차는 반복을 언제 멈출지 정하는 판정의 문턱이에요. 결과가 참값에서 그만큼 안이라는 보장이 아니에요. 판정이 보는 것도 방법마다 달라요.

| 판정이 보는 것 | 예 |
|---|---|
| 근을 끼는 구간의 폭 | `root_scalar`의 구간법: 폭이 $\text{xtol} + \text{rtol}\,\lvert x\rvert$ 정도가 되면 멈춰요 |
| 마지막 걸음의 크기 | `root_scalar`의 newton·secant, `root`의 hybr(`xtol`) |
| 기울기의 크기 | `minimize`의 BFGS·trust 방법(`gtol`) |
| 함숫값의 상대 감소 | L-BFGS-B, `least_squares`(`ftol`) |
| 단체의 크기 | Nelder–Mead(`xatol`, `fatol`) |

구간법은 판정이 곧 근의 위치에 대한 보장이라 이해하기 쉬워요. $\sqrt 2$를 찾으면 기본값 `xtol=2e-12`로는 $4 \times 10^{-14}$만큼 떨어진 점에서 멈추고, `xtol=0`이면 끝자리까지 가요.

```python
>>> s = lambda x: x*x - 2
>>> r = sd.optimize.root_scalar(s, bracket=(0.0, 2.0))
>>> r.x - math.sqrt(2), r.nfev
(4.1300296516055823e-14, 9)
>>> r = sd.optimize.root_scalar(s, bracket=(0.0, 2.0), xtol=0.0)
>>> r.x - math.sqrt(2), r.nfev
(-2.220446049250313e-16, 10)
```

기울기나 함숫값의 판정은 해의 위치와 간접적으로만 이어져요. 최솟값 근처에서는 함수가 $f(x^*) + \tfrac12 f''(x^*)(x - x^*)^2$처럼 평평하니, $x$가 $\delta$만큼 떨어져도 함숫값은 $\delta^2$만큼만 달라요. 그래서 함숫값만 보는 방법은 위치를 상대 $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$보다 정확히 정하기 어려워요($\varepsilon = 2^{-52}$, 기계 엡실론). Rosenbrock의 결과 `x`가 $1$에서 $10^{-5}$쯤 떨어진 것도 `gtol=1e-5`의 판정에서 멈췄기 때문이에요. 더 정확한 해가 필요하면 허용오차를 줄이고, 결과의 기울기(`r.jac`)나 잔차로 확인해요.

### 상한에 닿으면 멈춰요

모든 호출은 정해진 시간 안에 끝나요. 반복 방법에는 반복 수와 함수 계산 수의 상한이 있고, 기본값은 방법마다 정해져 있어요. 상한에 닿으면 예외를 내지 않고 마지막 점을 `converged=False`와 함께 돌려줘요.

```python
>>> r = sd.optimize.minimize(rosen, [-1.2, 1.0], options={'max_iter': 10})
>>> r.converged, r.status, r.message
(False, 1, 'Maximum number of iterations has been exceeded.')
>>> r.x
array([ 0.02110044764894023, -0.02556639756941664], dtype=float64)
>>> r = sd.optimize.root_scalar(s, bracket=(0.0, 2.0), max_iter=3)
>>> r.converged, r.status, r.message
(False, -2, 'convergence error')
```

상한에 닿은 결과는 답이 아닐 수 있어요. 그대로 쓰기 전에 `converged`를 확인하고, 필요하면 상한을 늘리거나 결과의 `x`를 시작점으로 다시 풀어요.

### 경고 대신 converged, status, message

`sd.optimize`는 경고(`warnings`)를 내지 않고 화면에 아무것도 쓰지 않아요. 수렴했는지, 상한에 닿았는지, 유한하지 않은 값을 만났는지는 모두 결과의 세 필드로 알려 줘요.

- `converged`: 방법의 멈춤 판정을 통과했는지(bool)
- `status`: 멈춘 이유의 번호. 번호의 뜻은 함수와 방법마다 달라요.
- `message`: 멈춘 이유의 글

그래서 반복의 결과를 쓰기 전에는 언제나 `converged`를 확인하는 습관이 좋아요. 세 필드를 읽는 법과 함수마다의 번호는 [결과 객체 읽기](/api/optimize/results/)에 있어요.

### 유한하지 않은 값

시작점에서 함수가 NaN이나 무한대이면 반복을 시작할 수 없으니 `ValueError`예요.

```python
>>> sd.optimize.least_squares(lambda x: [math.inf], [1.0])
Traceback (most recent call last):
    ...
ValueError: least_squares(): 'fun' is not finite at 'x0'
```

반복 중에 만난 유한하지 않은 값은 방법마다 다르게 다뤄요. 신뢰 영역 방법은 그 걸음을 거절하고 걸음을 줄여 다시 시도하고, 선 탐색 방법은 걸음을 줄이고, 구간법은 NaN을 만나면 그 자리에서 멈추고 `status`로 알려요. 함수가 정의되지 않는 곳이 있으면 거기서 NaN을 돌려주는 것이 예외를 내는 것보다 나아요. 예외는 그대로 나와 반복이 끝나지만, NaN은 방법이 다른 걸음을 시도할 기회를 줘요.

```python
>>> safe_log = lambda x: math.log(x[0]) if x[0] > 0 else math.nan
>>> r = sd.optimize.minimize(lambda x: x[0]**2 - safe_log(x), [3.0])
>>> r.converged, r.x
(True, array([0.7071087060480787], dtype=float64))
```

### 에러의 꼴

`sd.optimize`가 내는 에러의 메시지는 `함수 이름(): `으로 시작하고, 어떤 인자가 왜 틀렸는지 적어요. 다른 영역과 같은 규칙이에요.

- `TypeError`: 인자의 종류가 틀렸을 때. 호출할 수 없는 `fun`, dict가 아닌 `options`, 정수 자리의 float, 복소수 입력, 사용자 함수가 돌려준 bool(비교식을 돌려준 실수 같은 것), 모르는 키워드나 빠진 인자 같은 호출 모양의 잘못
- `ValueError`: 종류는 맞는데 값이 틀렸을 때. 모양, 범위, 모르는 방법 이름이나 옵션 키, 방법과 맞지 않는 인자, 근을 끼지 않는 구간, 시작점에서 유한하지 않은 값

```python
>>> sd.optimize.minimize(1, [1.0])
Traceback (most recent call last):
    ...
TypeError: minimize(): 'fun' must be callable, not int
>>> sd.optimize.root_scalar(lambda x: x, bracket=(1.0, 2.0))
Traceback (most recent call last):
    ...
ValueError: root_scalar(): 'bracket' does not enclose a root: f(a) and f(b) have the same sign (f(1.0) = 1.0, f(2.0) = 2.0)
```

반복이 상한에 닿거나 판정을 통과하지 못한 것은 에러가 아니에요. 그것은 결과의 `converged`로 알려요.

### 같은 입력이면 같은 비트

같은 기계, 같은 스레드 수, 같은 입력이면 실행마다 결과가 비트까지 같아요. 사용자 함수가 같은 입력에 같은 값을 돌려주면, 반복점도 셈도 결과도 늘 같아요. 지금은 스레드 수와도 상관없이 같아요(약속은 아니에요).

```python
>>> calls = []
>>> def rec(x):
...     calls.append(x.tolist())
...     return rosen(x)
>>> r = sd.optimize.minimize(rec, [-1.2, 1.0], method='l-bfgs-b')
>>> r.n_iter, r.nfev, len(calls)
(37, 138, 138)
>>> first = list(calls)
>>> calls.clear()
>>> r2 = sd.optimize.minimize(rec, [-1.2, 1.0], method='l-bfgs-b')
>>> calls == first, r2.x.tolist() == r.x.tolist()
(True, True)
```

결과의 정확도는 멈춤 판정이 정해요([허용오차](#허용오차는-멈춤-판정이에요)). 이 영역이 약속하는 것은 같은 기계, 같은 스레드 수에서 실행마다 같은 비트, 그리고 그 판정을 통과한 결과의 정확도예요. scipy와 견주면 어디까지 같은지는 [scipy를 아는 분께](#scipy와-같은-알고리즘-끝자리는-다를-수-있어요)에 있어요.

### 스레드와 GIL

사용자 함수는 Python이에요. 그래서 반복은 GIL(Python 인터프리터의 전역 잠금)을 쥔 채 돌고, 사용자 함수를 부를 때도 쥐고 있어요.

- 반복 안의 큰 선형대수(BFGS의 역헤시안 갱신, `least_squares`의 QR과 SVD, `trust-exact`의 분해 등)는 [linalg의 기준](/api/linalg/basics/)처럼 계산 시간이 10µs 이상일 만큼 크면 GIL을 놓고 계산해요. 그동안 다른 Python 스레드가 돌 수 있어요.
- 사용자 함수 안에서 하는 `sd` 연산(`sd.exp`, `sd.sum` 등)은 그 연산의 규칙대로 GIL을 놓고 여러 스레드를 써요.
- 배치 함수(`find_root` 등)는 사용자 함수를 부르는 사이에 원소마다 다음 점을 계산해요. 남은 원소가 32,768개 이상이면 이 계산을 여러 스레드에 나누고, 그동안 GIL을 놓아요. 원소 하나에 수 ns라 보통은 사용자 함수의 계산이 시간의 대부분이에요.
- 사용자 함수가 GIL을 쥐고 도는 Python 코드라서, Python 스레드 여러 개에서 최적화를 동시에 돌려도 사용자 함수의 Python 부분은 한 번에 하나씩 돌아요.

지금은 스레드 수를 바꿔도 결과가 같은 비트예요(약속은 아니에요).

```python
>>> cube = lambda x, c: x**3 - c
>>> c = sd.linspace(1.0, 2.0, 40000)
>>> n = sd.get_num_threads()
>>> sd.set_num_threads(1)
>>> a = sd.optimize.find_root(cube, (0.0, 10.0), args=(c,))
>>> sd.set_num_threads(n)
>>> b = sd.optimize.find_root(cube, (0.0, 10.0), args=(c,))
>>> bool(sd.all(a.x == b.x)), bool(sd.all(a.nfev == b.nfev))
(True, True)
```

## scipy를 아는 분께

함수와 인자의 이름은 `scipy.optimize`의 것이고 각 방법의 계산도 scipy 1.18.1과 같은 걸음이에요. 다른 것은 입력과 결과의 꼴이에요.

- **결과의 이름**: `success`는 `converged`, `nit`는 `n_iter`예요. `root_scalar`의 결과도 `RootResults`가 아니라 같은 `OptimizeResult`라서 `root`·`iterations`·`function_calls`·`flag` 대신 `x`·`n_iter`·`nfev`·`message`예요. 결과는 dict가 아니라 `r['x']`, `r.keys()`가 없고, 방법이 주지 않는 필드를 읽으면 `AttributeError`예요.
- **상한의 이름**: `maxiter`는 `max_iter`, `maxfev`·`maxfun`은 `max_nfev`, L-BFGS-B의 `maxls`는 `max_ls`예요.
- **method는 소문자만**: `'BFGS'`, `'Nelder-Mead'`가 아니라 `'bfgs'`, `'nelder-mead'`예요.
- **모르는 옵션은 에러**: scipy는 `OptimizeWarning`만 내고 무시하지만, 여기서는 `ValueError`예요. 방법과 맞지 않는 인자(BFGS의 `bounds`, Nelder–Mead의 `jac`)도 scipy는 경고하고 무시하지만 여기서는 에러예요.
- **없는 것**: 사용자 함수의 `args`(배치 함수만 받아요), `callback`, `disp`·`verbose`·`iprint`·`return_all`, scipy의 개별 함수(`brentq`, `newton`, `fmin`, `fmin_bfgs`, `fsolve`, `leastsq` 등; `method=`로 골라요), `curve_fit`(`sd.regression.nls`가 해요), 제약 최적화와 전역 최적화.
- **경계 밖의 x0**: scipy의 `minimize`는 말없이 경계 안으로 옮기지만 여기서는 `ValueError`예요.
- **셈**: `least_squares`의 `nfev`는 차분 야코비안의 호출도 세고(scipy는 세지 않아요), `root`의 `nfev`는 scipy보다 2 적어요(scipy는 시작점에서 두 번 더 부르고 그것을 세요). 자세한 것은 [결과 객체 읽기](/api/optimize/results/#scipy를-아는-분께)에 있어요.

### scipy와 같은 알고리즘, 끝자리는 다를 수 있어요

각 방법은 scipy 1.18.1의 같은 이름의 방법과 같은 알고리즘, 같은 멈춤 판정을 써요. `status`의 번호와 뜻, 옵션의 기본값도 scipy의 것이에요. 그래서 같은 문제에서 반복점, 반복 수, 멈춘 이유가 scipy와 같아요. 다만 반올림 크기의 결과는 정확도 안이면 되고 scipy와 끝자리가 다를 수 있어요. 반복 방법에서는 그 끝자리 차이로 반복 경로와 반복 수가 조금 달라질 수 있어요.

지금은 대부분의 방법이 scipy와 사용자 함수를 부르는 점까지 차례대로 비트까지 같아요. Nelder–Mead, L-BFGS-B, `hess`나 `hessp`를 준 newton-cg, trust-ncg, trust-exact, `root_scalar`와 `minimize_scalar`, 배치 함수, `root`, `lsq_linear`, 잔차가 변수보다 아주 많지는 않은 `least_squares(method='lm')`이 그래요. 다만 약속하는 것은 아니에요(약속은 같은 기계, 같은 스레드 수에서 실행마다 같은 비트, 그리고 정확도예요). 다음은 반올림만큼 달라요.

- BFGS: 역헤시안을 더 싼 순서로 갱신해요. 그 차이로 반복 수와 `nfev`가 가끔 몇 번 달라요. 위의 [Rosenbrock](#최솟값-찾기)을 scipy는 32번 반복, `nfev` 117로 풀어요.
- `least_squares`의 `'trf'`: 야코비안을 분해하는 순서가 달라요. 잔차가 변수보다 아주 많은 `'lm'`도 그래요.
- `hess`와 `hessp`가 없는 newton-cg: 헤시안과 벡터의 곱을 기울기의 차분으로 만들 때 기울기를 덜 불러서 부르는 점이 달라요.
- `nnls`: 0인 성분의 자리는 scipy와 같고, 나머지 성분은 더하는 순서가 달라서 끝자리가 달라요. 그 차이는 남은 열들의 조건수에 비례해서, 열끼리 비슷한 문제에서는 수백 ULP까지 벌어질 수 있어요.

scipy를 일부러 따르지 않는 곳도 있어요. 유한하지 않은 값을 만났거나 scipy가 해가 아닌 점에서 수렴을 알리는 경로, 몇 가지 셈, `max_iter=0`, `bracket_root`의 구간 정렬, `lsq_linear(method='bvls')`의 경계 밖 반올림이에요. 각 함수 페이지의 scipy 절에 있어요.

아래는 Nelder–Mead를 두 라이브러리로 푼 거예요. 부르는 점과 결과가 같아요. 반복 수만 세는 법이 달라서, scipy의 `nit`는 한 반복 수보다 하나 많아요.

```python
>>> import numpy as np
>>> import scipy.optimize as so
>>> a = so.minimize(rosen, np.array([-1.2, 1.0]), method='Nelder-Mead')
>>> b = sd.optimize.minimize(rosen, [-1.2, 1.0], method='nelder-mead')
>>> (a.nit, a.nfev, a.success), (b.n_iter, b.nfev, b.converged)
((85, 159, True), (84, 159, True))
>>> a.x.tolist() == b.x.tolist()
True
```
