`arange` returns the 1-D array `start, start + step, start + 2 * step, ...`, stopping before `stop`. With one argument
it counts from 0, like Python's `range`; with two it counts by 1. It is the usual way to create index arrays and
integer sequences.

The arguments are positional-only. Integer arguments give an `int64` array and any `float` argument gives a `float64`
array. For a fixed number of floating-point values between two endpoints, [`linspace`](/api/array/linspace/) is more
reliable, because the length of a floating-point `arange` depends on rounding (see the last example).

## Examples

One, two and three arguments:

```python
>>> import stardust as sd
>>> sd.arange(5)
array([0, 1, 2, 3, 4], dtype=int64)
>>> sd.arange(2, 8)
array([2, 3, 4, 5, 6, 7], dtype=int64)
>>> sd.arange(10, 0, -3)
array([10,  7,  4,  1], dtype=int64)
```

A floating-point step gives a `float64` array. A range that runs the wrong way is empty:

```python
>>> sd.arange(0, 1, 0.25)
array([ 0.0, 0.25,  0.5, 0.75], dtype=float64)
>>> sd.arange(5, 2)
array([], dtype=int64)
```

`dtype` converts the values after they are computed. Conversion to `int64` truncates toward zero:

```python
>>> sd.arange(0, 3, 0.5, dtype=sd.int64)
array([0, 0, 1, 1, 2, 2], dtype=int64)
>>> sd.arange(3, dtype=sd.float64)
array([0.0, 1.0, 2.0], dtype=float64)
```

With a floating-point step, rounding can add a value close to `stop`. Here `(1.3 - 1) / 0.1` is slightly above 3 in
floating point, so the result has four values instead of three:

```python
>>> sd.arange(1, 1.3, 0.1)
array([1.0, 1.1, 1.2, 1.3], dtype=float64)
>>> sd.linspace(1, 1.2, 3)
array([1.0, 1.1, 1.2], dtype=float64)
```

## Notes

The length is

$$
n = \max\left(0, \left\lceil \frac{\mathrm{stop} - \mathrm{start}}{\mathrm{step}} \right\rceil\right),
$$

computed in floating point when any argument is a `float`. Element $i$ is $\mathrm{start} + i \cdot \mathrm{step}$.

When every argument is an `int` within the `int64` range, the values are computed exactly as integers and then
converted to the result dtype. With `dtype=sd.float64` or `sd.complex128`, integer arguments outside the `int64` range
are accepted: all arguments are then rounded to `float64` and the values are computed in floating point.

NaN or infinite arguments raise `ValueError`, because the length is undefined. `bool` arguments count as the
integers 0 and 1.

## Comparison with other libraries

The nearest equivalents are `numpy.arange` and Python's `range`.

- The arguments are positional-only: `numpy.arange(start=1, stop=3)` has no counterpart here.
- Complex arguments raise `TypeError`, and NaN or infinite arguments raise `ValueError`.
- The values of a floating-point range are computed as `start + i * step`. They can differ slightly from those of
  `numpy.arange`, most visibly for values close to zero.
