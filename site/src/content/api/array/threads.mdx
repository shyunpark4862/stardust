## 한눈에 보기

요즘 컴퓨터의 CPU에는 동시에 일할 수 있는 코어가 여러 개 있어요. stardust는 원소가 많은 배열을 계산할 때 일을 여러 조각으로 나눠 여러 코어가 동시에 처리하게 해요. 이때 동시에 일하는 작업 줄기 하나를 **스레드**(thread)라고 불러요.

`get_num_threads`는 지금 설정된 스레드 수를 알려 주고, `set_num_threads`는 그 수를 바꿔요.

```python
>>> import stardust as sd
>>> default = sd.get_num_threads()
>>> sd.set_num_threads(4)
>>> sd.get_num_threads()
4
```

`set_num_threads`는 아무것도 돌려주지 않아요(`None`). 바꾼 값은 다시 바꿀 때까지 프로그램 전체에 적용돼요.

기본값은 이 컴퓨터의 고성능 코어 수라서 컴퓨터마다 달라요. 위 예제에서 처음 값을 `default`에 받아 둔 것은 나중에 되돌리기 위해서예요.

## 같은 설정이면 결과가 비트까지 같아요

같은 컴퓨터에서 같은 스레드 수로 같은 데이터를 계산하면, 몇 번을 돌려도 결과가 비트 하나까지 똑같아요. 이것이 stardust가 약속하는 재현성이에요. 실수의 합처럼 마지막 자리가 흔들리기 쉬운 계산도 그래요.

스레드 수가 달라도 같은 결과인지는 약속하지 않아요. 더 빠른 계산을 위해 스레드 수에 따라 마지막 자리가 달라지는 방법을 쓸 수도 있게 열어 둔 거예요. 다만 지금은 일을 나누는 방법을 데이터의 크기로만 정해서, 스레드 수를 바꿔도 결과가 같아요.

```python
>>> data = sd.sin(sd.arange(1_000_000) * 0.001)
>>> results = []
>>> for n in [1, 2, 4, 8]:
...     sd.set_num_threads(n)
...     results.append(sd.sum(data))
>>> results
[437.20744747064714, 437.20744747064714, 437.20744747064714, 437.20744747064714]
```

지금은 1스레드든 8스레드든 합의 마지막 자리까지 같아요. 평균, 분산, 정렬, 행렬곱 등 다른 계산도 마찬가지예요.

```python
>>> m = sd.reshape(data[:250_000], (500, 500))
>>> sd.set_num_threads(1)
>>> p1, s1 = m @ m, sd.std(data)
>>> sd.set_num_threads(8)
>>> p8, s8 = m @ m, sd.std(data)
>>> sd.all(p1 == p8)
True
>>> s1 == s8
True
```

### 같은 결과가 당연하지 않은 이유

실수의 덧셈은 더하는 순서에 따라 결과가 아주 조금 달라질 수 있어요. 실수는 자릿수가 한정돼 있어서, 더할 때마다 생기는 작은 반올림 오차가 순서에 따라 다르게 쌓이기 때문이에요.

```python
>>> (0.1 + 0.2) + 0.3
0.6000000000000001
>>> 0.1 + (0.2 + 0.3)
0.6
```

같은 백만 개의 수도 더하는 순서가 다르면 끝자리가 달라져요. Python 내장 `sum`은 앞에서부터 하나씩 더해서 `sd.sum`과 끝자리가 달라요.

```python
>>> sum(data.tolist())
437.2074474706434
>>> sd.sum(data)
437.20744747064714
```

어느 쪽이 틀린 것이 아니라 더한 순서가 다를 뿐이에요. 여러 스레드로 나눠 더하면 조각을 어떻게 나누는지에 따라 순서가 바뀌어서, 일을 나누는 방법이 실행마다 달라지면 끝자리도 실행마다 달라져요. stardust는 같은 설정이면 언제나 같은 순서로 더해요. 지금은 조각을 데이터의 크기로만 나눠서, 스레드 수가 달라도 순서가 같아요.

### 이 약속이 주는 것

- 오늘 돌린 분석을 내일 같은 컴퓨터, 같은 설정으로 다시 돌려도 숫자가 똑같아요.
- 계산 결과를 저장해 둔 값과 `==`로 정확히 비교할 수 있어서, 실행할 때마다 테스트가 가끔 실패하는 일이 없어요.
- 저장해 둔 값과 비트까지 비교한다면 스레드 수도 저장할 때와 같게 두세요. 지금은 스레드 수를 바꿔도 결과가 같지만, 그것까지 약속하지는 않아요.
- [난수](/api/random/basics/)는 따로예요. 시드가 같으면 스레드 수와 상관없이 같은 값이 나오는 것을 약속해요.

## 언제 바꾸나요

대부분은 기본값 그대로 두면 돼요. 다음과 같은 때는 바꾸는 것이 좋아요.

- 같은 컴퓨터에서 다른 무거운 프로그램이 돌고 있다면 스레드를 줄여서 CPU를 양보할 수 있어요.
- Python 프로세스를 여러 개 동시에 돌릴 때 프로세스마다 코어 수만큼 스레드를 쓰면, 코어보다 훨씬 많은 스레드가 서로 다투느라 오히려 느려져요. 프로세스 수 × 스레드 수가 코어 수 정도가 되도록 줄이세요. 각 프로세스에서 `sd.set_num_threads(1)`로 두는 것이 가장 간단해요. 다만 실수 행렬곱과 `cov`는 이 설정과 상관없이 여러 코어를 쓸 수 있어요(아래 [행렬곱과 cov는 따로예요](#행렬곱과-cov는-따로예요) 참고).
- 속도를 잴 때 1스레드와 여러 스레드를 비교해 볼 수 있어요.

코어 수보다 크게 정해도 에러는 나지 않지만 더 빨라지지는 않아요. 원소가 적은 작은 계산은 스레드 수를 바꿔도 차이를 느끼기 어려워요.

### 설정은 라이브러리 전체에 하나예요

`sd.set_num_threads`는 배열(`sd`)뿐 아니라 선형대수(`sd.linalg`), 데이터프레임(`sd.frame`)의 계산에도 똑같이 적용돼요. 영역마다 따로 정하는 함수는 없어요. 실수 행렬곱처럼 운영체제의 행렬 계산 라이브러리에 맡기는 계산만 예외예요(바로 아래에서 설명해요).

```python
>>> hasattr(sd.linalg, "set_num_threads")
False
```

환경 변수로 정하는 방법도 없어요. 스레드 수를 바꾸려면 코드에서 `sd.set_num_threads`를 불러야 해요. 보통은 프로그램 맨 앞에서 한 번 불러요.

### 행렬곱과 cov는 따로예요

실수(float64)와 복소수(complex128) 배열의 행렬곱(`@`, `sd.matmul`, `sd.tensordot`)과 `sd.cov`, `sd.corrcoef`, 그리고 `sd.linalg`의 분해·풀이 대부분은 운영체제가 제공하는 행렬 계산 라이브러리에 맡겨요. 이 라이브러리는 몇 개의 스레드를 쓸지 스스로 정하고, `sd.set_num_threads`는 그 수를 바꾸지 않아요. 그래서 `sd.set_num_threads(1)`로 두어도 큰 실수 행렬의 곱은 여러 코어를 쓸 수 있고, 스레드 수를 늘린다고 더 빨라지지도 않아요.

그래서 이 계산의 결과는 `sd.set_num_threads`에 따라 달라지지 않아요. 다만 이 라이브러리가 혼자 계산할지 여러 스레드로 나눌지는 환경 변수 `VECLIB_MAXIMUM_THREADS`로 정해지고, 이 설정이 다르면(1스레드와 여러 스레드) 마지막 자리 몇 개가 달라질 수 있어요. 설정이 같으면 언제나 같은 결과예요. stardust는 이 설정을 바꾸지 않아요. 사용자가 정한 값을 덮어쓰지 않고, 큰 행렬곱이 느려지지 않게 하려는 거예요.

다만 두 경우는 `sd.set_num_threads`를 따라요. 작은 행렬을 여러 개 쌓아 한꺼번에 곱할 때는 stardust가 행렬을 스레드에 나눠 맡겨요. 정수와 bool 행렬의 곱은 stardust가 직접 계산해요. 곱셈-덧셈이 512번 이하인 아주 작은 실수 행렬 두 개의 곱도 stardust가 직접 계산해요.

### 잠깐만 바꾸고 되돌리기

어떤 구간에서만 스레드 수를 바꾸고 싶다면, 원래 값을 받아 두었다가 끝나면 되돌려요. 중간에 에러가 나도 되돌아가도록 `try`/`finally`를 쓰면 안전해요.

```python
>>> before = sd.get_num_threads()
>>> sd.set_num_threads(1)
>>> try:
...     total = sd.sum(data)
... finally:
...     sd.set_num_threads(before)
>>> sd.get_num_threads() == before
True
```

### 여러 Python 스레드에서 함께 쓸 때

Python의 `threading`으로 여러 스레드를 만들어 각각 stardust를 불러도 돼요. 동시에 부른 계산은 CPU를 나눠 쓰기 때문에 속도는 달라질 수 있어요. 다른 Python 스레드가 이미 여러 코어로 계산하고 있으면 나중에 부른 계산은 혼자(1스레드로) 계산해요. 지금은 결과가 스레드 수와 상관없으므로 혼자 불렀을 때와 같은 결과예요.

다만 Python은 GIL(전역 인터프리터 잠금)이라는 잠금 때문에 한 번에 한 스레드만 Python 코드를 돌려요. stardust의 계산이 이 잠금을 내려놓는지에 따라 다른 Python 스레드가 기다릴지가 정해져요.

- 큰 계산은 스레드 수와 상관없이 계산하는 동안 잠금을 내려놓아요. `sd.set_num_threads(1)`이어도 그동안 다른 Python 스레드가 계속 돌아요. "큰"의 기준은 여러 스레드로 나누기 시작하는 크기와 같아요. 원소 하나의 계산이 무거운 함수(`exp` 등)는 더 적은 원소부터, 원소가 1바이트인 bool 배열의 원소별 연산과 집계는 더 많은 원소부터 내려놓아요. 선형대수는 아주 짧게 끝나는 작은 행렬이 아니면 내려놓아요.
- 원소가 적은 계산은 잠금을 쥔 채 계산해요. 잠금을 놓았다 다시 잡는 비용이 계산보다 클 수 있어서예요. 계산이 끝날 때까지 다른 Python 스레드는 기다려요.
- `cov`, `corrcoef`의 행렬곱과 난수의 `permutation`은 크기와 상관없이 잠금을 내려놓아요.
- 반대로 크기와 상관없이 잠금을 쥔 채 도는 것도 있어요. 리스트를 받는 `asarray`와 `tolist`처럼 Python 객체를 읽거나 만드는 변환, 인덱스 배열로 하는 대입 `x[idx] = v`, `zeros`와 `eye`예요.

그래서 Python 스레드 여러 개가 각자 큰 배열 계산을 부르면 실제로 동시에 돌아요. 다만 한 계산을 빨리 끝내려면 Python 스레드를 늘리기보다 `sd.set_num_threads`로 stardust의 스레드 수를 늘리는 쪽이 간단해요.

## 조심할 점

### 1 이상 1024 이하의 정수만

범위를 벗어나면 `ValueError`예요. 0이나 음수로 "자동"을 뜻하게 하는 기능은 없어요.

```python
>>> sd.set_num_threads(0)
Traceback (most recent call last):
    ...
ValueError: set_num_threads(): 'n' must be between 1 and 1024
>>> sd.set_num_threads(1025)
Traceback (most recent call last):
    ...
ValueError: set_num_threads(): 'n' must be between 1 and 1024
```

다른 함수에서는 int64 범위를 넘는 아주 큰 정수가 `OverflowError`를 내지만, `set_num_threads`는 크기와 상관없이 범위 밖이면 모두 `ValueError`예요.

```python
>>> sd.set_num_threads(2**70)
Traceback (most recent call last):
    ...
ValueError: set_num_threads(): 'n' must be between 1 and 1024
```

정수가 아니면 `TypeError`예요. `2.0`처럼 값이 정수인 실수도, `True`도 받지 않아요. numpy 정수(`np.int64(2)` 등)는 받아요.

```python
>>> sd.set_num_threads(2.0)
Traceback (most recent call last):
    ...
TypeError: set_num_threads(): 'n' must be an int, not float
>>> sd.set_num_threads(True)
Traceback (most recent call last):
    ...
TypeError: set_num_threads(): 'n' must be an int, not bool
```

`n`은 자리로만 넘겨요. `sd.set_num_threads(n=2)`처럼 이름을 붙이면 `TypeError`예요. `get_num_threads`는 인자를 받지 않아요.

### 에러가 나면 설정은 그대로예요

잘못된 값으로 부르면 에러만 나고, 이전 설정은 바뀌지 않아요.

```python
>>> sd.set_num_threads(2)
>>> try:
...     sd.set_num_threads(-1)
... except ValueError:
...     pass
>>> sd.get_num_threads()
2
```

마지막으로 처음 값으로 되돌려 둬요.

```python
>>> sd.set_num_threads(default)
>>> sd.get_num_threads() == default
True
```

## numpy를 아는 분께

- numpy에는 스레드 수를 정하는 함수가 없어요. 보통 `OMP_NUM_THREADS` 같은 환경 변수나 별도 패키지로 조절해요. stardust는 반대로 함수로만 정하고, 환경 변수는 읽지 않아요.
- 같은 컴퓨터, 같은 스레드 수, 같은 입력이면 실행마다 비트까지 같아요. 지금은 스레드 수가 달라도 같아요(약속은 아니에요).
- 실수 합은 더하는 순서가 numpy와 달라서 마지막 자리가 다를 수 있어요.
