These functions are [`cumulative_sum` and `cumulative_prod`](/api/array/cumulative/) with every NaN element of `x`
left out. At a NaN position the result repeats the running value reached so far, as if the element were 0 for the sum
and 1 for the product. Before the first non-NaN element, that value is 0 or 1.

A complex element counts as NaN when its real or its imaginary part is NaN. `bool` and `int64` arrays hold no NaN, so
for them each function returns exactly what `cumulative_sum` or `cumulative_prod` returns. The last element of a
running sum along an axis agrees with [`nansum`](/api/array/nan-reductions/) along that axis up to rounding, since
the two add the elements in different orders.

## Examples

The plain running sum stays NaN after the first NaN. The `nan` form carries the last value over each NaN:

```python
>>> import stardust as sd
>>> y = sd.asarray([1.0, sd.nan, 2.0, sd.nan, 3.0])
>>> sd.cumulative_sum(y)
array([1.0, nan, nan, nan, nan], dtype=float64)
>>> sd.nancumulative_sum(y)
array([1.0, 1.0, 3.0, 3.0, 6.0], dtype=float64)
>>> sd.nancumulative_prod(y)
array([1.0, 1.0, 2.0, 2.0, 6.0], dtype=float64)
```

With `include_initial=True` the result starts with the initial value. Leading NaN elements keep that value:

```python
>>> sd.nancumulative_sum(y, include_initial=True)
array([0.0, 1.0, 1.0, 3.0, 3.0, 6.0], dtype=float64)
>>> sd.nancumulative_prod(sd.asarray([sd.nan, sd.nan, 5.0]))
array([1.0, 1.0, 5.0], dtype=float64)
```

A 2-D array needs `axis`:

```python
>>> m = sd.asarray([[1.0, sd.nan, 3.0],
...                 [sd.nan, 5.0, 6.0]])
>>> sd.nancumulative_sum(m, axis=1)
array([[ 1.0,  1.0,  4.0],
       [ 0.0,  5.0, 11.0]], dtype=float64)
>>> sd.nancumulative_sum(m, axis=0)
array([[1.0, 0.0, 3.0],
       [1.0, 5.0, 9.0]], dtype=float64)
>>> sd.nancumulative_sum(m)
Traceback (most recent call last):
    ...
ValueError: nancumulative_sum(): 'axis' is required for arrays with more than one dimension
```

## Notes

Along the axis, with elements $x_0, x_1, \dots$, the running sum is

$$
s_k = \sum_{i \le k,\ x_i \ne \mathrm{NaN}} x_i ,
$$

and the running product is defined in the same way. Only NaN elements of `x` are skipped. A NaN that arises during
the computation, such as $\infty + (-\infty)$, stays and makes the later running values NaN:

```python
>>> sd.nancumulative_sum(sd.asarray([sd.inf, sd.nan, -sd.inf, 1.0]))
array([inf, inf, nan, nan], dtype=float64)
```

## Comparison with other libraries

The nearest equivalents are `numpy.nancumsum` and `numpy.nancumprod`.

- `axis=None` is accepted only for 1-D input. NumPy flattens an array of more dimensions; here it raises `ValueError`.
- `include_initial` has no counterpart in `numpy.nancumsum` and `numpy.nancumprod`.
- There is no `out=` argument.
- Long `float64` accumulations can differ from NumPy's in the last digits.
