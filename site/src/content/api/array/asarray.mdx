`asarray` builds an array from Python data. A nested list or tuple becomes an array with one axis per level of
nesting: the outer list runs along axis 0, the lists inside it along axis 1, and so on. Every list on one level must
have the same length.

Without `dtype`, the result takes the highest kind among the elements in the order `bool` < `int64` < `float64` <
`complex128` (see [Data type of a new array](/api/array/dtypes/#data-type-of-a-new-array)). Python `bool`, `int`,
`float` and `complex` map to these four dtypes, and NumPy scalars count as the Python scalar of the same kind. An empty
list gives a `float64` array.

`asarray` also wraps memory owned by other objects. An `ndarray` with the requested dtype is returned as it is, and a
buffer whose elements already have one of the four array dtypes is used without copying, so the result and the source
see each other's changes. `copy=True` gives an independent array. [Views and copies](/api/array/views/) describes
shared memory in general.

## Examples

Lists, nested lists and ranges:

```python
>>> import stardust as sd
>>> sd.asarray([1, 2, 3])
array([1, 2, 3], dtype=int64)
>>> sd.asarray([[1, 2], [3, 4.5]])
array([[1.0, 2.0],
       [3.0, 4.5]], dtype=float64)
>>> sd.asarray(range(4))
array([0, 1, 2, 3], dtype=int64)
```

A requested dtype converts the values. Floating-point values become integers by truncation toward zero:

```python
>>> sd.asarray([1.5, -2.7], dtype=sd.int64)
array([ 1, -2], dtype=int64)
>>> sd.asarray([0, 1, 2], dtype="bool")
array([False,  True,  True], dtype=bool)
```

An array with the requested dtype is returned without a copy. `copy=True` makes an independent array:

```python
>>> x = sd.asarray([1.0, 2.0, 3.0])
>>> sd.asarray(x) is x
True
>>> y = sd.asarray(x, copy=True)
>>> y[0] = 100.0
>>> x
array([1.0, 2.0, 3.0], dtype=float64)
```

A NumPy array of 64-bit floats is wrapped, not copied. A 32-bit integer array needs a widening copy, which
`copy=False` refuses:

```python
>>> import numpy as np
>>> a = np.array([1.0, 2.0, 3.0])
>>> s = sd.asarray(a)
>>> a[0] = 50.0
>>> s
array([50.0,  2.0,  3.0], dtype=float64)
>>> s.base is a
True
>>> sd.asarray(np.array([1, 2], dtype=np.int32), copy=False)
Traceback (most recent call last):
    ...
ValueError: asarray(): copy=False, but this buffer can only be converted by copying
```

A single number is not converted, because stardust has no 0-D arrays. Ragged lists are an error:

```python
>>> sd.asarray(5)
Traceback (most recent call last):
    ...
ValueError: asarray(): 0-dimensional arrays are not supported: a scalar is already the result (stardust has no 0-d arrays)
>>> sd.asarray([[1, 2], [3]])
Traceback (most recent call last):
    ...
ValueError: asarray(): inhomogeneous nested sequence: expected every level to match shape (2, 2)
```

## Notes

**Nested sequences.** Only `list` and `tuple` count as levels of nesting; a `range` is accepted only as `obj` itself,
not inside a list. An `ndarray` inside a list counts as nested data and is copied into the result. `[]` gives shape
`(0,)` and `[[]]` gives shape `(1, 0)`. Sequences are always copied, so `copy=False` with a list, tuple or `range`
raises `ValueError`.

**Large integers.** A Python `int` outside the `int64` range raises `OverflowError` only when it has to become an
`int64`. In a `float64` or `complex128` result it is rounded to the nearest float: `sd.asarray([2**70, 0.5])` is a
`float64` array.

**Buffers.** An object that exposes the buffer protocol is read according to its element type:

| Element type of the buffer | Result |
|---|---|
| bool, signed 64-bit integer, 64-bit float, 128-bit complex | shared without a copy |
| signed and unsigned integers of 8, 16 or 32 bits | copied to `int64` |
| 16- and 32-bit floats | copied to `float64` |
| 64-bit complex | copied to `complex128` |
| unsigned 64-bit integers, strings, others | `TypeError` |

Buffers in big-endian byte order are copied. A shared buffer keeps its strides, including negative ones, and its
`base` is the source object. A read-only buffer gives a read-only array. Bool bytes other than 0 and 1 are normalized
in a copy.

## Comparison with other libraries

The nearest equivalent is `numpy.asarray`.

- A scalar or a 0-D NumPy array raises `ValueError`; `numpy.asarray(5)` returns a 0-D array.
- Strings, `None`, generators and sets raise `TypeError` instead of giving string or object arrays. Python integers
  outside the `int64` range raise `OverflowError`; NumPy stores them in an object array.
- `dtype` takes only the four array dtypes or their names. Python types such as `float` and NumPy dtypes such as
  `numpy.float32` raise `TypeError`. NumPy arrays of unsigned 64-bit integers are refused.
- There are no `order=`, `device=` or `like=` arguments.
