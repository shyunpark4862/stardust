These functions are the reductions [`sum`](/api/array/sum/), [`prod`](/api/array/prod/),
[`min`, `max`](/api/array/min-max/), [`mean`](/api/array/mean/), [`var`, `std`](/api/array/var-std/) and
[`argmin`, `argmax`](/api/array/argmin-argmax/) with every NaN element of `x` left out. They take the same arguments,
follow the same `axis` and `keepdims` rules and return the same dtype. The plain reductions propagate NaN (see
[missing values](/start/conventions/#missing-values)); these give the result for the remaining elements.

A complex element counts as NaN when its real or its imaginary part is NaN. `bool` and `int64` arrays hold no NaN, so
for them each function returns exactly what the function without the prefix returns. For a `float64` or `complex128`
input without NaN the result is also the same, to the last bit.

An output element whose elements are all NaN has no value to report. `nansum` returns 0, `nanprod` returns 1,
`nanmean`, `nanvar`, `nanstd`, `nanmin` and `nanmax` return NaN, and `nanargmin` and `nanargmax` raise `ValueError`.
No case issues a warning.

## Examples

NaN makes the plain sum NaN. The `nan` forms use the three other elements:

```python
>>> import stardust as sd
>>> y = sd.asarray([1.0, sd.nan, 3.0, 4.0])
>>> sd.sum(y)
nan
>>> sd.nansum(y)
8.0
>>> sd.nanmean(y)
2.6666666666666665
>>> sd.nanmin(y), sd.nanmax(y)
(1.0, 4.0)
>>> sd.nanargmax(y)
3
>>> sd.nanvar(y, correction=1)
2.3333333333333335
```

Along an axis, each output element skips its own NaN elements. The second row has nothing but NaN:

```python
>>> m = sd.asarray([[1.0, sd.nan, 3.0],
...                 [sd.nan, sd.nan, sd.nan]])
>>> sd.nansum(m, axis=1)
array([4.0, 0.0], dtype=float64)
>>> sd.nanmean(m, axis=1)
array([2.0, nan], dtype=float64)
>>> sd.nanmax(m, axis=1, keepdims=True)
array([[3.0],
       [nan]], dtype=float64)
>>> sd.nanargmax(m)
2
>>> sd.nanargmax(m, axis=1)
Traceback (most recent call last):
    ...
ValueError: nanargmax(): All-NaN slice encountered
```

Integer input gives the results of the plain functions. A complex element with a NaN part is skipped:

```python
>>> k = sd.asarray([3, 1, 2])
>>> sd.nansum(k), sd.nanmean(k)
(6, 2.0)
>>> z = sd.asarray([1 + 1j, complex(1, sd.nan), 3 + 3j])
>>> sd.nanmean(z)
(2+2j)
>>> sd.nanvar(z)
2.0
```

An empty array is reduced as by the plain functions, and `nanmin` rejects complex input:

```python
>>> e = sd.zeros(0)
>>> sd.nansum(e), sd.nanprod(e), sd.nanmean(e)
(0.0, 1.0, nan)
>>> sd.nanmin(e)
Traceback (most recent call last):
    ...
ValueError: nanmin(): undefined for an empty array (or along an empty axis)
>>> sd.nanmin(z)
Traceback (most recent call last):
    ...
TypeError: nanmin(): not supported for complex128
```

## Notes

For one output element, let $S$ be the set of its elements that are not NaN and $m$ the number of them. With the
correction $c$,

$$
\operatorname{nanmean} = \frac{1}{m} \sum_{x \in S} x, \qquad
\operatorname{nanvar} = \frac{1}{m - c} \sum_{x \in S} \lvert x - \operatorname{nanmean} \rvert^2,
$$

and `nanstd` is the square root of `nanvar`. When $m - c \le 0$ the variance is NaN. `nansum` and `nanprod` equal
`sum` and `prod` with each NaN replaced by 0 and 1.

| Function | Result dtype | All elements NaN | No elements |
|---|---|---|---|
| `nansum`, `nanprod` | `int64` for `bool` input, else the dtype of `x` (or `dtype`) | 0, 1 | 0, 1 |
| `nanmin`, `nanmax` | dtype of `x` | NaN | `ValueError` |
| `nanmean` | `float64`, or `complex128` for complex input | NaN | NaN |
| `nanvar`, `nanstd` | `float64` | NaN | NaN |
| `nanargmin`, `nanargmax` | `int64` | `ValueError` | `ValueError` |

Only NaN elements of `x` are skipped. A NaN that arises during the computation, such as $\infty + (-\infty)$, stays in
the result:

```python
>>> sd.nansum(sd.asarray([sd.inf, -sd.inf, sd.nan]))
nan
```

`nanargmin` reads a NaN as $+\infty$ and `nanargmax` reads it as $-\infty$, and both return the first position of the
extreme value. When that value is itself infinite and a NaN comes before it, the result is the position of the NaN:

```python
>>> sd.nanargmin(sd.asarray([sd.nan, sd.inf]))
0
```

## For NumPy, SciPy and R users

The nearest equivalents are `numpy.nansum`, `numpy.nanprod`, `numpy.nanmin`, `numpy.nanmax`, `numpy.nanmean`,
`numpy.nanvar`, `numpy.nanstd`, `numpy.nanargmin` and `numpy.nanargmax`, and R's `sum`, `prod`, `min`, `max`, `mean`,
`var` and `sd` with `na.rm = TRUE`, and `which.min` and `which.max`.

- An output element with only NaN gives NaN (or 0 and 1 for sums and products) without a warning. NumPy issues a
  `RuntimeWarning` ("All-NaN slice encountered", "Mean of empty slice").
- `nanmin`, `nanmax`, `nanargmin` and `nanargmax` reject complex input; NumPy accepts it.
- There is no `ddof=` argument; `correction` takes its place, with NumPy's default 0.
- There are no `out=`, `initial=`, `where=` or `mean=` arguments, `dtype=` exists for `nansum` and `nanprod` only, and
  there are no methods: `x.nansum()` does not exist.
- R's `min` and `max` with `na.rm = TRUE` return `Inf` and `-Inf` with a warning when nothing remains; here the result
  is NaN. R's `var` and `sd` divide by $m - 1$, which is `correction=1`.
