`ravel` flattens an array: it returns its elements in one row, in row-major order (the last axis varies fastest). It is
the same as `reshape(x, -1)`.

The result is a [view](/api/array/views/) of `x` when the elements already lie in memory in that order, as they do in a
newly created array, and a new array otherwise, for example for a transposed matrix or for the first two columns `m[:, :2]` of a
matrix `m`. Writing to a view changes `x`. To always get an independent array, use `reshape(x, -1, copy=True)`.

## Examples

A 2-D and a 3-D array:

```python
>>> import stardust as sd
>>> m = sd.asarray([[1, 2, 3], [4, 5, 6]])
>>> sd.ravel(m)
array([1, 2, 3, 4, 5, 6], dtype=int64)
>>> sd.ravel(sd.reshape(sd.arange(8), (2, 2, 2)))
array([0, 1, 2, 3, 4, 5, 6, 7], dtype=int64)
```

The order follows the shape, not the memory. Flattening the transpose reads it row by row, and needs a copy:

```python
>>> t = sd.ravel(m.T)
>>> t
array([1, 4, 2, 5, 3, 6], dtype=int64)
>>> t.base is None
True
```

The result for `m` is a view, so writing to it changes `m`:

```python
>>> r = sd.ravel(m)
>>> r.base is m
True
>>> r[0] = 10
>>> m
array([[10,  2,  3],
       [ 4,  5,  6]], dtype=int64)
```

## Comparison with other libraries

The nearest equivalent is `numpy.ravel`.

- There is no `order` argument: the order is always row-major.
- There is no `flatten` method. `reshape(x, -1, copy=True)` always returns a copy.
- `x` must be an `sd.ndarray`; lists raise `TypeError`.
