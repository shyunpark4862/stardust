`min` returns the smallest element of `x` along the axes given by `axis`, and `max` the largest. The reduced axes are
removed from the shape, or kept with length 1 when `keepdims=True` (see
[`axis` and `keepdims`](/start/conventions/#axis-and-keepdims)). With the default `axis=None`, the result is one
Python number. The methods `x.min(...)` and `x.max(...)` are the same functions.

The result has the dtype of `x`. For Booleans, `False` is smaller than `True`, so `max` is true when any element is
true and `min` when all are. Complex numbers have no order and raise `TypeError`.

NaN propagates: if a reduced group contains NaN, its minimum and maximum are NaN.
[`nanmin` and `nanmax`](/api/array/nan-reductions/) skip NaN. A minimum or maximum of no elements is not defined and
raises `ValueError`. To compare two arrays element by element instead, use
[`minimum` and `maximum`](/api/array/maximum-minimum/).

## Examples

The smallest and largest element, and the largest of each column and row:

```python
>>> import stardust as sd
>>> x = sd.asarray([[3, 8, 1], [5, 2, 9]])
>>> sd.min(x), sd.max(x)
(1, 9)
>>> sd.max(x, axis=0)
array([5, 8, 9], dtype=int64)
>>> x.min(axis=1)
array([1, 2], dtype=int64)
>>> sd.max(x, axis=1, keepdims=True)
array([[8],
       [9]], dtype=int64)
```

With `keepdims=True` the result broadcasts against `x`, here to scale each row by its maximum:

```python
>>> x / sd.max(x, axis=1, keepdims=True)
array([[             0.375,                1.0,              0.125],
       [0.5555555555555556, 0.2222222222222222,                1.0]], dtype=float64)
```

NaN propagates, and Boolean arrays keep their dtype:

```python
>>> f = sd.asarray([[1.0, sd.nan], [2.0, 0.5]])
>>> sd.max(f, axis=1)
array([nan, 2.0], dtype=float64)
>>> sd.max(sd.asarray([False, True, False]))
True
```

An empty reduction raises `ValueError`, unless the result itself has no elements. Complex input raises `TypeError`:

```python
>>> e = sd.zeros((3, 0))
>>> sd.max(e, axis=0)
array([], dtype=float64)
>>> sd.max(e, axis=1)
Traceback (most recent call last):
    ...
ValueError: max(): undefined for an empty array (or along an empty axis)
>>> sd.min(sd.asarray([1 + 1j, 2 + 0j]))
Traceback (most recent call last):
    ...
TypeError: min(): not supported for complex128
```

## Notes

The results are exact: each one is an element of `x`. `-inf` and `inf` are ordinary values. `-0.0` counts as smaller
than `0.0`, so the minimum of `0.0` and `-0.0` is `-0.0` and their maximum is `0.0`, whatever their order in `x`.

## For NumPy, SciPy and R users

The nearest equivalents are `numpy.min` and `numpy.max` (also called `numpy.amin` and `numpy.amax`), the methods
`numpy.ndarray.min` and `numpy.ndarray.max`, and R's `min`, `max` and `range`.

- Complex input raises `TypeError`. NumPy orders complex numbers by real part, then imaginary part.
- There are no `out=`, `initial=` or `where=` arguments, so an empty reduction always raises `ValueError`.
- A reduction over all axes is a Python `bool`, `int` or `float`, not a NumPy scalar.
- R's `min` and `max` return a single number for any array. For an empty argument they return `Inf` and `-Inf` with
  a warning; here they raise `ValueError`.
