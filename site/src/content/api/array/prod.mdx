`prod` multiplies the elements of `x` along the axes given by `axis` and removes those axes from the shape, or keeps
them with length 1 when `keepdims=True` (see [`axis` and `keepdims`](/start/conventions/#axis-and-keepdims)). With the
default `axis=None`, the result is the product of all elements, returned as a Python number. The method `x.prod(...)`
is the same function.

The product has the dtype of `x`, except that Booleans count as 0 and 1 and give `int64`. `dtype=` converts every
element before the multiplication, as for [`sum`](/api/array/sum/). The product of no elements is 1, in the result
dtype.

`int64` products wrap around when they leave the `int64` range, without an error (see
[integer overflow](/api/array/dtypes/#integer-overflow)). `float64` products that overflow become infinite, and a
product that involves both infinity and zero, or a NaN element, is NaN.
[`nanprod`](/api/array/nan-reductions/) skips NaN.

## Examples

The product of all elements, and of each row and column:

```python
>>> import stardust as sd
>>> x = sd.asarray([[1, 2, 3], [4, 5, 6]])
>>> sd.prod(x)
720
>>> sd.prod(x, axis=0)
array([ 4, 10, 18], dtype=int64)
>>> x.prod(axis=1)
array([  6, 120], dtype=int64)
```

The product of the numbers 1 to 20 fits in `int64`; up to 21 it wraps around. `dtype=sd.float64` multiplies in
floating point instead:

```python
>>> n = sd.arange(1, 22)
>>> sd.prod(n[:20])
2432902008176640000
>>> sd.prod(n)
-4249290049419214848
>>> sd.prod(n, dtype=sd.float64)
5.109094217170944e+19
```

Products of complex numbers, and the empty product:

```python
>>> sd.prod(sd.asarray([1j, 1j, 1 + 1j]))
(-1-1j)
>>> sd.prod(sd.zeros((0,)))
1.0
>>> sd.prod(sd.zeros((2, 0)), axis=1)
array([1.0, 1.0], dtype=float64)
```

An intermediate product can overflow even when the exact result is moderate:

```python
>>> sd.prod(sd.asarray([1e200, 1e200, 1e-200]))
inf
```

## Notes

The order of the multiplications is fixed by the shape and memory layout of `x`, so the same input gives the same
bits on every run (see [Determinism and threads](/start/conventions/#determinism-and-threads)). When partial products
leave the `float64` range, the result depends on that order: it can be infinite or NaN although some other order
would give a finite value.

For a product of many positive values, the sum of their logarithms, `sd.sum(sd.log(x))`, stays in range where the
product itself would overflow or underflow.

## Comparison with other libraries

The nearest equivalents are `numpy.prod` and the method `numpy.ndarray.prod`.

- The multiplications are done in a different order from NumPy's, so results for `float64` and `complex128` input
  can differ from NumPy's in the last digit. When partial products overflow, the results can differ completely:
  `sd.prod(sd.asarray([1e200, 1e-200] * 8))` is `nan`, while NumPy returns `1.0`.
- Overflow to infinity and the NaN of `0 * inf` occur without a warning. NumPy issues a `RuntimeWarning`.
- There are no `out=`, `initial=` or `where=` arguments, and `dtype=sd.bool` raises `TypeError`.
