`linspace` divides the interval from `start` to `stop` into equal steps and returns the points. The number of points
is given directly, so the length of the result never depends on rounding, unlike a floating-point
[`arange`](/api/array/arange/). It is the usual way to create a grid of points at which to evaluate a function.

With the default `endpoint=True`, both ends are included and the result has `num - 1` steps. With `endpoint=False`,
the result has `num` steps and stops one step short of `stop`, which suits periodic grids where `stop` is the same
point as `start`.

## Examples

Five points from 0 to 1, with and without the endpoint:

```python
>>> import stardust as sd
>>> sd.linspace(0, 1, 5)
array([ 0.0, 0.25,  0.5, 0.75,  1.0], dtype=float64)
>>> sd.linspace(0, 1, 4, endpoint=False)
array([ 0.0, 0.25,  0.5, 0.75], dtype=float64)
```

A decreasing range, and a complex one:

```python
>>> sd.linspace(1, 0, 3)
array([1.0, 0.5, 0.0], dtype=float64)
>>> sd.linspace(0, 1j, 3)
array([  0j, 0.5j,   1j], dtype=complex128)
```

Values of a function on a grid:

```python
>>> t = sd.linspace(0, 2, 5)
>>> t
array([0.0, 0.5, 1.0, 1.5, 2.0], dtype=float64)
>>> t ** 2 - 1
array([ -1.0, -0.75,   0.0,  1.25,   3.0], dtype=float64)
```

`num` is required and must be an `int`:

```python
>>> sd.linspace(0, 1, 2.0)
Traceback (most recent call last):
    ...
TypeError: linspace(): 'num' must be an int, not float
```

## Notes

With `endpoint=True` and `num` of at least 2, the last value is exactly `stop`. The values in between are
$\mathrm{start} + i \cdot \mathrm{step}$ and can differ from the exact decimal points by rounding.
With `num` equal to 1, the result is `[start]`; with `num` equal to 0, it is empty.

When both ends are finite but `stop - start` overflows, the step is computed as $\mathrm{stop}/d - \mathrm{start}/d$
(with $d$ the number of steps), so every value stays finite: `linspace(-1e308, 1e308, 5)` is
`[-1e308, -5e307, 0.0, 5e307, 1e308]`.

NaN or infinite ends raise no error. A NaN end makes every value NaN. An infinite end makes the step infinite, and
the first value becomes NaN even when `start` is finite: `linspace(0, inf, 3)` is `[nan, inf, inf]`.

A `dtype` of `int64` truncates the computed values toward zero: `linspace(-1, 0, 3, dtype=sd.int64)` is `[-1, 0, 0]`.

## Comparison with other libraries

The nearest equivalent is `numpy.linspace`.

- `num` is required; NumPy defaults to 50. All three main arguments are positional-only.
- `start` and `stop` must be scalars. NumPy also accepts arrays and has `axis=` and `retstep=` arguments.
- Conversion to `int64` truncates toward zero; `numpy.linspace(-1, 0, 3, dtype=int)` rounds down and gives
  `[-1, -1, 0]`.
- Finite ends whose difference overflows give finite values; NumPy returns infinities and NaN there.
