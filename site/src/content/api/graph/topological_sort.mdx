## 한눈에 보기

어떤 일은 다른 일이 끝나야 시작할 수 있어요. 미적분을 들어야 해석학을 듣고, 라이브러리를 빌드해야 그것을 쓰는 프로그램을 빌드해요. 이런 선후 관계를 "$i$가 $j$보다 먼저"라는 변 $i \to j$로 적으면 방향 있는 그래프가 돼요. `topological_sort`는 모든 변에서 출발 노드가 도착 노드보다 앞에 오도록 노드를 한 줄로 늘어놓아요. 이 줄을 **위상 순서**라고 불러요.

```python
>>> import stardust as sd
>>> def directed(n, edges):
...     A = sd.zeros((n, n), dtype=sd.int64)
...     for i, j in edges:
...         A[i, j] = 1
...     return A
>>> C = directed(6, [(5, 0), (5, 2), (4, 0), (4, 1), (2, 3), (3, 1)])
>>> order = sd.graph.topological_sort(C)
>>> order
array([4, 5, 0, 2, 3, 1], dtype=int64)
```

들어오는 변이 없는 4와 5는 먼저 할 수 있는 일이에요. 4를 하고, 5를 하면 0과 2가 풀려요. 0, 2, 3, 1의 차례로 이어서 모든 선후 관계를 지켜요.

## 결과 읽기

결과는 노드 $n$개를 모두 한 번씩 담은 int64 배열이에요. `order[k]`가 $k$번째로 할 노드예요. 반대로 노드마다 몇 번째인지가 필요하면 자리를 뒤집은 배열을 만들어요. 그 배열로 모든 변이 앞에서 뒤로 가는지 확인할 수 있어요.

```python
>>> pos = sd.empty(6, dtype=sd.int64)
>>> pos[order] = sd.arange(6)
>>> pos
array([2, 5, 3, 4, 0, 1], dtype=int64)
>>> rows, cols = sd.nonzero(C)
>>> bool(sd.all(pos[rows] < pos[cols]))
True
```

### 사전 순서로 가장 작은 순서

위상 순서는 보통 여럿이에요. 위 그래프에서 5를 4보다 먼저 해도 되고, 0을 2 뒤에 해도 돼요. 이 함수는 그 가운데 **사전 순서로 가장 작은** 것 하나를 줘요. 매 단계에서 지금 할 수 있는 일(남은 선행 일이 없는 노드) 가운데 번호가 가장 작은 것을 고르는 셈이에요. 그래서 답은 그래프만으로 정해지고, 노드 번호를 우선순위로 쓸 수 있어요. 급한 일에 작은 번호를 주면 선후 관계가 허락하는 한 먼저 나와요.

```python
>>> sd.graph.topological_sort(sd.zeros((4, 4)))
array([0, 1, 2, 3], dtype=int64)
```

변이 없으면 모든 순서가 위상 순서이고, 가장 작은 것은 0, 1, 2, 3이에요.

## 순환이 있으면

0 → 1 → 2 → 0처럼 순환이 있으면 순환 위의 어느 노드도 먼저 할 수 없어서 위상 순서가 없어요. 이때는 `ValueError`예요.

```python
>>> sd.graph.topological_sort(directed(3, [(0, 1), (1, 2), (2, 0)]))
Traceback (most recent call last):
    ...
ValueError: topological_sort(): the graph has a cycle
```

대각의 자기 고리(자기가 자기보다 먼저)도 순환이에요. 그리고 이 함수는 언제나 방향 있는 그래프로 읽으므로, 대칭 행렬로 적은 방향 없는 변은 $i \to j$와 $j \to i$의 순환 둘이에요.

```python
>>> sd.graph.topological_sort(sd.asarray([[1, 0], [0, 0]]))
Traceback (most recent call last):
    ...
ValueError: topological_sort(): the graph has a cycle
>>> sd.graph.topological_sort(sd.asarray([[0, 1], [1, 0]]))
Traceback (most recent call last):
    ...
ValueError: topological_sort(): the graph has a cycle
```

어디에 순환이 있는지 찾으려면 [`connected_components`](/api/graph/connected_components/)의 강한 연결 요소를 봐요. 크기가 2 이상인 요소가 순환을 품은 노드들이에요.

```python
>>> cyc = directed(5, [(0, 1), (1, 2), (2, 1), (2, 3), (3, 4)])
>>> n, lab = sd.graph.connected_components(cyc, connection="strong")
>>> lab
array([0, 1, 1, 2, 3], dtype=int64)
>>> sd.nonzero(sd.bincount(lab)[lab] > 1)[0]
array([1, 2], dtype=int64)
```

노드 1과 2가 서로를 가리켜 순환이에요.

## 경계의 값

노드가 없는 그래프는 빈 배열이에요. 이 함수에는 옵션이 없어요. 언제나 방향 있는 그래프로 보므로 `directed` 같은 키워드는 `TypeError`예요.

```python
>>> sd.graph.topological_sort(sd.zeros((0, 0)))
array([], dtype=int64)
>>> sd.graph.topological_sort(C, directed=True)
Traceback (most recent call last):
    ...
TypeError: topological_sort(): unexpected keyword argument 'directed'
```

## scipy·networkx를 아는 분께

- scipy에는 이 함수가 없어요. 이름과 뜻은 networkx의 `topological_sort`이고, 돌려주는 순서는 networkx의 `lexicographical_topological_sort`(키 없이)와 같아요. networkx의 `topological_sort`는 위상 순서 하나를 주지만 어느 것인지 약속하지 않아요.
- networkx는 생성기를 주고, 여기서는 int64 배열 하나를 줘요.
- 순환이면 `ValueError`예요. networkx는 `NetworkXUnfeasible`을 내요. 모든 위상 순서를 나열하는 `all_topological_sorts`는 없어요.
