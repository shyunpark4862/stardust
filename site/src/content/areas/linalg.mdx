## Concepts

### Matrices and stacks

The last two axes of an array form a matrix; any leading axes index a stack (also called a batch) of matrices. Shapes
are written `(..., m, n)`, where `...` stands for zero or more leading axes. Every function treats each matrix of a
stack independently and returns the results stacked in the same order. When a function takes several arrays, their
leading axes broadcast against each other: an `a` of shape `(2, 1, 3, 3)` and a `b` of shape `(4, 3, 2)` give a
solution of shape `(2, 4, 3, 2)`. Arguments that are vectors use the last axis only.

### Right-hand sides

Functions that solve $A x = b$ read `b` by its number of dimensions. A 1-D `b` of shape `(m,)` is one right-hand side,
shared by every matrix in the stack, and the solution has shape `(..., n)`. A `b` with two or more dimensions,
`(..., m, k)`, holds `k` right-hand sides as columns, and the solution has shape `(..., n, k)`.

### Result types

Computations run in `float64`, or in `complex128` when any array argument is complex. Integer and boolean inputs are
converted to `float64` first, so the values computed from them are floating point as well. `eig` and `eigvals` always
return complex results. Counts and indices, such as `matrix_rank` and the permutation of `lu`, are integers. Only
`diagonal` and `block_diag`, which copy elements without computing, keep the dtype of their input. A result that
would be a single number for a single matrix, such as `det` or `matrix_rank`, is a Python scalar; for a stack it is
an array, even when the stack holds one matrix.

### Named tuples

Functions with several results return a named tuple, such as `LUResult(L, U, perm)`, whose fields are read by name or
by position. The arrays inside such a tuple are read-only; call `.copy()` on a field to get a writable array. Functions
with a single array result, such as `inv` and `eigvals`, return a writable array.

### Finite values

Functions that factor a matrix (solvers, factorizations, eigenvalues, `det`, `cond`, `expm` and others) raise
`ValueError` if the part of an argument they read contains NaN or infinity. Functions that only multiply or add, such
as `vecdot`, `outer` and `trace`, propagate NaN and infinity instead.

### Singular matrices

A matrix is treated as singular only when its factorization produces an exact zero pivot. Solvers and `inv` then raise
`LinAlgError`, a subclass of `ValueError`. A matrix that is singular in exact arithmetic but not after rounding gives a
result with large errors and no warning; `cond` measures how close a matrix is to singular.

### Errors in a stack

The matrices of a stack are processed in order. For each one, a matrix argument is checked for NaN and infinity
before it is used, and the right-hand side `b` is checked last, after the test for a singular matrix: a singular `a`
raises `LinAlgError` even when `b` contains NaN. In a stack, the first matrix that fails determines the exception,
whatever the failure (NaN or infinity, a singular or not positive-definite matrix, no convergence), and the message
ends with its index, as in `(at batch index (1,))`. The same matrix is reported for any number of threads.

### Symmetric and Hermitian input

Functions for symmetric or Hermitian matrices (`cholesky`, `eigh`, `eigvalsh`, `ldl`) read only the lower triangle and
ignore the imaginary part of the diagonal. The upper triangle is never read or checked.

## For NumPy, SciPy and R users

| stardust | NumPy / SciPy | R |
|---|---|---|
| `solve(a, b)` | `numpy.linalg.solve`, `scipy.linalg.solve` | `solve(a, b)` |
| `lstsq(a, b)` | `numpy.linalg.lstsq` | `qr.solve(a, b)` |
| `inv(x)` | `numpy.linalg.inv` | `solve(a)` |
| `det(x)` | `numpy.linalg.det` | `det(a)` |
| `cholesky(x)` | `numpy.linalg.cholesky` | `chol(a)` |
| `eigh(a)` | `numpy.linalg.eigh` | `eigen(a, symmetric = TRUE)` |
| `svd(x)` | `numpy.linalg.svd` | `svd(a)` |
| `qr(x)` | `numpy.linalg.qr` | `qr(a)` |
| `lu(x)` | `scipy.linalg.lu` | |
| `expm(x)` | `scipy.linalg.expm` | |

- Array arguments must be `sd.ndarray`. Lists and NumPy arrays raise `TypeError`; convert them with `sd.asarray`.
- NaN or infinity in the input of a factoring function raises `ValueError`. `numpy.linalg.solve` returns NaN instead;
  `scipy.linalg.solve` raises `ValueError` by default, as here.
- The matrix structure is chosen by the function name, not by an option: `solve` always uses a general LU
  factorization, and there is no `assume_a=`. Use `solve_triangular`, `cholesky_solve` or `solve_banded` for structured
  matrices.
- `svd` returns the reduced factorization by default (`mode="reduced"`); `numpy.linalg.svd` defaults to
  `full_matrices=True`.
- `eig` and `eigvals` sort eigenvalues by real part, then imaginary part; NumPy leaves the order unspecified. `eigh`
  sorts in ascending order, while R's `eigen` returns decreasing order.
- `lstsq` returns `(solution, rank, singular_values)` and takes `rtol=`; `numpy.linalg.lstsq` also returns the residuals
  and takes `rcond=`. `trace` of an integer matrix is a `float` (`numpy.trace` keeps the integer type), and `cholesky`
  returns the lower factor by default (R's `chol` returns the upper one).
