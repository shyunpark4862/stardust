## 한눈에 보기

`sd.interpolate`는 점에서 주어진 값을 지나는 함수를 만들고, 그 함수를 다른 점에서 계산해요. 한 변수의 보간(꺾은선, 3차 계열의 조각 다항식, B-스플라인), 점 전체를 지나는 다항식과 유리식(무게중심 꼴, Krogh, Floater–Hormann, AAA), 격자 위의 여러 변수 보간, 흩어진 점의 보간(RBF, 가장 가까운 점, Delaunay 삼각분할 위의 선형과 Clough–Tocher)이 여기 있어요. 꺾은선을 계산하는 최상위 함수 `sd.interp`는 배열 영역의 함수이지만 이 영역과 커널을 함께 써요.

모든 보간은 두 단계로 나뉘어요. **만들기**는 자료에서 계수(기울기, 조각 다항식의 계수, B-스플라인의 계수, 무게)를 구해 객체에 담고, **평가**는 그 계수가 나타내는 함수를 평가점에서 계산해요. 정확도의 약속도 이 두 겹으로 적혀 있어요. 만들기는 "같은 자료의 정확한 계수"와, 평가는 "계산한 계수가 나타내는 함수의 정확한 값"과 견줘요.

이 영역의 설계는 두 문장으로 모여요. **점 하나의 값은 커널 하나가 정하고, 그 점이 든 구간은 규칙 하나가 정해요.** 구간을 어떤 탐색으로 찾았든, 평가점을 어떻게 태스크로 나눴든, 몇 스레드로 돌렸든 같은 점은 같은 구간에서 같은 연산으로 계산돼요. 그래서 결과가 스레드 수와 무관하게 같은 비트예요.

층은 아래로만 기대요. `csrc/interpolate/`는 배열, 스레드풀, `base/`의 공용 커널, linalg의 LAPACK 래퍼, spatial의 거리 커널과 삼각분할 위에 서고, 다른 영역의 C++ 코드는 `interpolate/`를 몰라요. 한 변수의 보간(이 글과 [선형 커널](/internals/interpolate/linear/), [3차 계열](/internals/interpolate/cubic/), [띠 풀이](/internals/interpolate/banded/), [B-스플라인](/internals/interpolate/bspline/))은 LAPACK을 부르지 않아요. 스플라인의 연립방정식은 이 영역의 띠 풀이가 풀고, LAPACK은 RBF의 전역 풀이와 AAA에만 쓰여요.

`sd.interp`는 배열 영역의 `csrc/array/ops/interp.cpp`에 있어요. 배열 영역은 다른 영역을 include하지 않으니, 둘이 함께 쓰는 선형 커널과 구간 찾기는 `interpolate/`가 아니라 바닥 층 `base/`에 있어요.

C++ 하위 모듈 `stardust._core.interpolate`는 소스 파일마다 하나씩 있는 `bind_*`(`bind_linear`, `bind_cubic`, `bind_ppoly`, `bind_bspline`, `bind_polyint`, `bind_aaa`, `bind_grid`, `bind_rbf`, `bind_scattered`)를 차례로 불러 만들어요. 네이티브 이름은 모두 내부 이름이고 사용자는 Python 클래스와 함수만 봐요. 이 글들이 다루는 한 변수 쪽의 네이티브 함수는 이래요.

만들기는 네이티브 호출 두 번, 평가는 한 번이에요. 객체가 쥐는 것은 계수 배열과 중단점뿐이고 둘 다 쓰기 금지라, 만든 뒤에는 객체의 함수가 바뀌지 않아요. `PPoly.extend`만 객체를 고치는데, 그것도 배열을 고치지 않고 이어 붙인 새 배열로 바꿔 끼워요.

```python
>>> x = sd.linspace(0.0, 10.0, 2001)
>>> cs = sd.interpolate.CubicSpline(x, sd.sin(x))
>>> cs
CubicSpline(degree=3, pieces=2000, extrapolate=True)
>>> cs.c.shape, cs.c._flags()["writeable"], cs.x._flags()["writeable"]
((4, 2000), False, False)
```

배치도 같은 길이에요. `y`가 여러 차원이면 `axis`를 뺀 나머지 축을 열 $K$개로 펴서 한 번에 넘기고, 커널은 열마다 같은 연산을 해요. complex128 값은 실수부와 허수부를 나란한 double 열 둘로 봐요. 한 변수 쪽의 식은 모두 값에 대해 실수 계수의 선형이라 복소수 열 하나가 실수 열 둘과 같기 때문이에요(실근만 찾는 `roots`만 예외라 실수 계수만 받아요).

## 구간 찾기

조각으로 된 보간은 평가점마다 그 점이 든 구간부터 찾아야 해요. 규칙은 하나예요. 엄격히 증가하는 중단점 $x_0 \lt \dots \lt x_{n-1}$에서 점 $v$의 구간은 **오른쪽이 열린** $x_i \le v \lt x_{i+1}$이고, 마지막 구간만 오른쪽 끝 $x_{n-1}$을 품어요. 정의역 밖의 점은 가장 가까운 끝 구간이에요.

구간은 수 하나로 정해져요. <strong>$v$ 아래(같은 값 포함)에 있는 노드의 수 $c$</strong>예요. `base/interval.hpp`가 이 $c$를 세고, `search.hpp`가 구간 번호로 바꿔요.

```cpp
// csrc/interpolate/search.hpp
// The interval of a point from its count c of breakpoints at or below it (n >= 2): c - 1 clamped to the
// first and the last interval.
inline std::int64_t interval_of(std::int64_t c, std::int64_t n) { return std::clamp<std::int64_t>(c - 1, 0, n - 2); }
```

$x_i \le v \lt x_{i+1}$이면 $c = i + 1$이라 구간 $i$예요. $v = x_{n-1}$이면 $c = n$이고 자르기가 $n - 2$, 곧 마지막 구간으로 보내요. 왼쪽 밖은 $c = 0$이라 구간 0, 오른쪽 밖은 $c = n$이라 마지막 구간이에요. 불연속인 조각 다항식에서 중단점의 값이 오른쪽 조각의 값이라는 것이 이 규칙에서 나와요.

```python
>>> step = sd.interpolate.PPoly([[1.0, 2.0, 3.0]], [0.0, 1.0, 2.0, 3.0])
>>> step([0.0, 0.5, 1.0, 2.0, 3.0]).tolist()
[1.0, 1.0, 2.0, 3.0, 3.0]
>>> step([-1.0, 3.5]).tolist()
[1.0, 3.0]
```

### 세는 방법 둘

$c$를 세는 탐색이 둘 있어요. 하나는 구간을 반씩 줄이는 이분 탐색을 갈래 없이 적은 것이에요.

```cpp
// csrc/base/interval.hpp
// out[l] = the number of xp[i] <= v[l], for l < L (n >= 1).
template <int L>
inline void count_le_lanes(const double* xp, std::int64_t n, const double* v, std::int64_t* out) {
    std::int64_t base[L] = {};
    for (std::int64_t len = n; len > 1;) {
        const std::int64_t half = len / 2;
        for (int l = 0; l < L; ++l) base[l] = (xp[base[l] + half] <= v[l]) ? base[l] + half : base[l];
        len -= half;
    }
    for (int l = 0; l < L; ++l) out[l] = base[l] + (xp[base[l]] <= v[l]);
}
```

`base`는 "여기까지는 $v$ 아래"인 자리이고 남은 길이 `len`이 1이 될 때까지 반씩 줄어요. 비교의 결과를 갈래가 아니라 값의 고르기(조건부 이동)로 쓰니 평가점이 무작위 순서여도 갈래 예측이 틀릴 일이 없어요. 걸음 수는 $n$으로만 정해져 있어서 $L$개의 점이 같은 걸음을 나란히 밟아요. 한 걸음에서 $L$개의 점이 읽는 자리는 서로 독립이라, 노드 배열이 캐시보다 클 때 캐시 미스 $L$개가 겹쳐서 기다려요. 배열 영역의 `searchsorted`가 쓰는 탐색과 같은 꼴이고 묶음의 크기는 8이에요.

다른 하나는 앞 점의 답에서 출발하는 질주 탐색이에요.

```cpp
// csrc/base/interval.hpp
// The number of xp[i] <= v, given that it is at least `from` (xp[from - 1] <= v, or from == 0).
inline std::int64_t count_le_from(const double* xp, std::int64_t n, double v, std::int64_t from) {
    std::int64_t lo = from, hi = n;  // the count is in [lo, hi]
    for (std::int64_t step = 1;; step *= 2) {
        const std::int64_t probe = lo + step - 1;
        if (probe >= n) break;
        if (!(xp[probe] <= v)) {
            hi = probe;
            break;
        }
        lo = probe + 1;
    }
    // xp[lo - 1] <= v < xp[hi] (as far as they exist): halve [lo, hi)
    for (std::int64_t len = hi - lo; len > 0;) {
        const std::int64_t half = len / 2;
        const bool below = xp[lo + half] <= v;
        lo = below ? lo + half + 1 : lo;
        len = below ? len - half - 1 : half;
    }
    return lo;
}
```

평가점이 정렬되어 있으면 다음 점의 $c$는 앞 점의 $c$보다 작지 않아요. 그 자리에서 1, 2, 4, …칸씩 뛰어 $v$를 넘는 노드를 찾고, 마지막으로 뛴 구간만 반씩 줄여요. 이웃한 평가점이 가까우면 한두 걸음에 끝나고, 멀리 떨어져 있어도 떨어진 거리의 로그만큼만 걸려요.

### 블록마다 고르기

평가점은 **위치만으로** 256점 블록으로 끊어요. 블록이 정렬되어 있고 NaN이 없으면 질주하고, 아니면 8점씩 나란히 반씩 줄여요.

```cpp
// csrc/base/interval.hpp
inline void count_le_block(
    const double* xp, std::int64_t n, const double* v, std::int64_t m, std::int64_t* c, GallopState& s
) {
    constexpr int kLanes = 8;
    bool sorted = v[0] == v[0];
    for (std::int64_t i = 1; i < m; ++i) sorted &= v[i - 1] <= v[i];  // a NaN breaks it
    if (sorted) {
        std::int64_t from = s.x <= v[0] ? s.c : 0;
        for (std::int64_t i = 0; i < m; ++i) c[i] = from = count_le_from(xp, n, v[i], from);
        s.x = v[m - 1];
        s.c = c[m - 1];
        return;
    }
    std::int64_t i = 0;
    for (; i + kLanes <= m; i += kLanes) count_le_lanes<kLanes>(xp, n, v + i, c + i);
    for (; i < m; ++i) count_le_lanes<1>(xp, n, v + i, c + i);
    s = GallopState{};
}
```

`GallopState`는 앞의 정렬된 블록이 끝난 점과 그 $c$예요. 다음 블록의 첫 점이 그 점보다 작지 않으면 거기서 이어서 질주하고, 아니면 0에서 다시 시작해요. 상태는 태스크마다 따로 있으니 태스크의 첫 블록은 언제나 0에서 시작해요.

두 탐색은 같은 수를 세요. $c$는 "$x_i \le v$인 노드의 수"라는 정의 하나로 정해져 있고, 어느 탐색도 그 정의에서 벗어난 값을 낼 수 없어요. 그래서 블록이 어느 길을 탔는지, 질주가 어디서 출발했는지는 걸리는 시간만 바꾸고 구간은 바꾸지 않아요. 평가점을 섞어도 점마다의 값이 그대로인 것으로 볼 수 있어요.

```python
>>> rng = sd.random.default_rng(3)
>>> q = rng.random(100000) * 12.0 - 1.0
>>> order = sd.argsort(q)
>>> sd.take(cs(q), order).tolist() == cs(sd.take(q, order)).tolist()
True
```

NaN인 점은 어떤 비교도 참이 아니라 $c = 0$으로 세어지고, 부르는 쪽이 구간을 쓰기 전에 NaN을 먼저 걸러 그 점의 결과를 NaN으로 채워요. 평가점의 NaN이 어느 보간에서든 NaN인 것이 이 때문이에요.

### 구간 규칙의 변형

같은 $c$를 쓰는 쪽마다 구간으로 바꾸는 법이 조금씩 달라요.

| 쓰는 곳 | $c$에서 구간으로 | 까닭 |
|---|---|---|
| 조각 다항식, 선형 길 | $c - 1$을 $[0, n - 2]$로 자르기 | 위의 규칙 그대로 |
| 감소하는 중단점(`PPoly`) | $-x$를 열쇠로 같은 탐색 | 열쇠에서의 오른쪽 열린 규칙이 $x$에서는 거울 규칙 $x_{i+1} \lt v \le x_i$ |
| B-스플라인 | 매듭 $t$에서 센 $c - 1$을 $[k, n - 1]$로 자르기 | 겹친 매듭 사이의 빈 구간을 건너뛰고 기본 구간 $[t_k, t_n]$의 구간만 고르기 |
| `sd.interp` | $c = 0$은 `left`, $c = n$은 마지막 노드의 값이나 `right`, 그 밖은 $[x_{c-1}, x_c]$ | 반복된 노드에서 폭이 0인 구간을 고르지 않기([선형 커널](/internals/interpolate/linear/)) |

감소하는 중단점은 객체를 만들 때가 아니라 평가할 때 부호를 뒤집은 사본을 만들어 찾아요. 값의 계산은 원래 구간의 다항식 그대로예요.

```python
>>> down = sd.interpolate.PPoly([[1.0, 2.0, 3.0]], [3.0, 2.0, 1.0, 0.0])
>>> down([3.0, 2.5, 2.0, 1.0, 0.0]).tolist()
[1.0, 1.0, 2.0, 3.0, 3.0]
```

중단점 2.0에서 값이 2예요. 거울 규칙 $x_{i+1} \lt v \le x_i$에서 $v = 2$는 구간 $[2, 3]$이 아니라 $[1, 2]$에 들기 때문이에요. 증가하는 중단점에서 중단점의 값이 오른쪽(큰 쪽) 조각의 값이었던 것처럼, 감소하는 중단점에서는 작은 쪽 조각의 값이에요.

선형 보간은 구간 규칙이 달라도 값이 같아요. 선형 커널이 구간의 양 끝에서 끝값을 정확히 내니, 노드에 놓인 점을 왼쪽 구간으로 치든 오른쪽 구간으로 치든 결과가 그 노드의 값이에요. `sd.interp`와 k = 1 B-스플라인과 격자의 선형 보간이 서로 다른 규칙을 쓰면서도 같은 비트인 까닭이에요.

## 바깥의 규칙

정의역이 있는 한 변수 보간은 바깥을 `extrapolate` 하나로 정하고, 커널에는 세 값 가운데 하나로 넘어가요.

```cpp
// csrc/interpolate/search.hpp
enum class Extrapolate : int { Nan = 0, Extend = 1, Periodic = 2 };

// v wrapped into [x0, x1] for the periodic rule: x0 + (v - x0) % (x1 - x0), with numpy's remainder (scipy's
// PPoly and BSpline compute the same expression on numpy arrays)
inline double wrap_periodic(double v, double x0, double x1) { return x0 + ops::Remainder::f(v - x0, x1 - x0); }
```

- <strong>`Extend`</strong>(`True`)는 따로 하는 일이 없어요. 구간 찾기가 바깥의 점을 끝 구간으로 보내니 끝 조각의 식이 그대로 늘어나요.
- <strong>`Nan`</strong>(`False`)은 구간을 쓰기 전에 $v \lt x_0$이거나 $v \gt x_{n-1}$인 점을 NaN으로 채워요. 끝점은 안이에요.
- <strong>`Periodic`</strong>은 구간을 찾기 전에 점을 정의역으로 감아요. 나머지 연산은 배열 영역의 `%`와 같은 것(나누는 수의 부호를 따르는 나머지)이라 음수 쪽의 점도 $[x_0, x_1)$로 들어와요.

```python
>>> step([-1.0, 3.5, math.nan], extrapolate=False).tolist()
[nan, nan, nan]
>>> step([-1.0, 3.5, 7.25], extrapolate="periodic").tolist()
[3.0, 1.0, 2.0]
```

주기 3으로 감으면 $-1$은 2, $3.5$는 0.5, $7.25$는 1.25라서 셋째, 첫째, 둘째 조각의 값이 나와요. `sd.interp`의 `left`·`right`·`period`와 격자의 `bounds_error`·`fill_value`는 이 규칙이 아니라 각각 따르는 뜻이 따로 있어요.

## 병렬화와 결정성

**같은 입력이면 스레드 수와 상관없이 같은 결과예요.** 지키는 방법은 둘이에요. 일은 크기로만 나누고, 점 하나(열 하나, 조각 하나)는 한 태스크가 처음부터 끝까지 같은 연산으로 계산해요. 합이 있는 곳은 더하는 순서를 길이로만 정해요.

| 병렬 경로 | 나누는 방법 | 결과가 같은 까닭 |
|---|---|---|
| 평가(`__call__`, `sd.interp`, 격자, RBF) | 평가점 조각 | 점 하나는 한 커널이고, 구간 찾기의 길은 구간을 바꾸지 않아요 |
| `CubicSpline`의 기울기, B-스플라인의 계수 | 배치의 열 묶음(8열) | 분해는 한 번이고 열마다 같은 대입이에요 |
| PCHIP·Akima의 기울기, Hermite 계수 | 노드 조각, 구간 조각 | 이웃 몇 개만 읽는 국소 계산이에요 |
| 역미분의 상수 | 4096조각 블록의 부분합을 차례로 | 블록의 경계가 길이로 정해져요 |
| `integrate` | pairwise 트리의 잎 | 배열의 pairwise 합과 같은 트리예요 |
| `roots` | 조각 묶음 | 조각마다 독립이고 조각 순서로 모아요 |
| B-스플라인 배치 행렬의 채우기, `from_spline` | 행 조각, 조각 묶음 | 행과 조각마다 독립이에요 |
| 다항식·유리식의 평가와 무게 | 평가점 조각, 노드 조각 | 점과 노드 하나는 한 커널이에요 |
| 삼각분할 위의 평가(선형, Clough–Tocher) | 평가점 256개 | 단체는 `find_simplex`의 정의로 정해지고, 점의 값은 그 단체와 점만의 계산이에요 |
| Clough–Tocher의 기울기 | 값의 열 | 열 안의 Gauss–Seidel 훑기는 한 스레드이고 차례가 색인 순서 하나예요 |
| RBF의 전역 풀이, AAA의 SVD, AAA와 Floater–Hormann의 극점·영점·유수 | Accelerate | Accelerate의 스레드 모드가 같으면 같아요 |

마지막 줄만 조건이 붙어요. LAPACK을 부르는 곳은 Accelerate 안에서 일이 나뉘니 이 영역이 순서를 정할 수 없어요. 스플라인과 다항식 쪽에는 그런 곳이 없어요.

나누기 시작하는 크기는 배열 영역의 규칙이에요. 작업량이 float64 연산 $2^{15}$개 분량 이상이면 태스크로 나누고, 그 크기부터는 스레드 수와 상관없이 GIL을 놓아요. 작업량은 함수마다 어림해요.

| 함수 | 작업량의 어림 | 태스크의 크기 |
|---|---|---|
| `sd.interp` | 점마다 $2\lfloor\log_2(n+1)\rfloor + 8$ | 1024점 |
| 선형 길 | 점마다 $2\lfloor\log_2(n+1)\rfloor + 8K$ | $1024 / K$점 |
| `PPoly`의 평가 | 점마다 $2\lfloor\log_2(n+1)\rfloor + 2(k+1)K$ | $4096 / ((k+1)K)$과 256 가운데 큰 쪽 |
| `BSpline`의 평가 | 점마다 $\lfloor\log_2(N+1)\rfloor + 3(k+1)^2 + 2(k+1)K$ | 256점 이상 |
| `LinearNDInterpolator`의 평가 | 점마다 $128 + 16(d + 2) + 2K$ | 256점 |
| `CloughTocher2DInterpolator`의 평가 | 점마다 $128 + 160 + 40K$ | 256점 |
| Clough–Tocher의 기울기 | $64n\max(1, K)$ | 열 하나 |

태스크의 경계는 점의 수와 작업량으로만 정해지고, 태스크 안의 256점 블록도 태스크의 첫 점부터 끊으니 블록의 경계도 스레드 수와 무관해요. 블록이 어느 탐색을 타든 구간은 같다는 것까지 더하면, 스레드 수를 바꿔 가며 같은 호출을 해도 바이트까지 같아요.

```python
>>> n0 = sd.get_num_threads()
>>> outs = []
>>> for t in (1, 2, 3, 7, 10):
...     sd.set_num_threads(t)
...     outs.append(cs(q).tolist())
>>> sd.set_num_threads(n0)
>>> [o == outs[0] for o in outs]
[True, True, True, True, True]
```

하나의 긴 열을 푸는 삼중대각·띠 풀이는 나누지 않아요. 분해와 대입이 앞 행의 결과를 받아 다음 행을 계산하는 사슬이라, 점 $10^6$개의 열 하나는 한 스레드가 처음부터 끝까지 풀어요. 배치의 열이 여럿이면 열 묶음으로 나눠요. 사슬을 끊어 나란히 푸는 방법(순환 소거)은 연산의 순서가 달라져 반올림이 바뀌고, 이 영역이 증명해 둔 오차 한계([띠 풀이](/internals/interpolate/banded/))가 그 순서에 서 있어서 쓰지 않아요.

## 메모리

- **객체**는 계수 배열 하나와 중단점(또는 매듭)을 쥐어요. `CubicSpline`은 $(4, n - 1, K)$의 계수와 $n$개의 중단점, `BSpline`은 매듭과 계수예요. 생성자는 받은 배열을 복사해서 쥐니 원래 배열을 고쳐도 객체는 그대로예요.
- **만들기의 작업 메모리**는 자료의 크기에 비례해요. `CubicSpline`은 열이 8개 이하면 삼중대각 행렬을 저장하지 않고 피벗의 역수 $n$개만 둬요. 띠 행렬은 (행 수) × (띠의 너비)예요.
- **평가의 작업 메모리**는 태스크마다 블록 하나(256점의 값과 노드 수)라 평가점의 수와 무관해요. 감소하는 중단점만 부호를 뒤집은 사본 $n$개를 더 써요.
- **흩어진 점.** `LinearNDInterpolator`는 `Delaunay`와 값만 쥐어요. `CloughTocher2DInterpolator`는 기울기 $(n, K, 2)$를 더 쥐고, 만드는 동안 방향 있는 변마다 32바이트와 꼭짓점마다 24바이트를 써요([삼각분할 위의 보간](/internals/interpolate/scattered/#메모리)).
- **결과**는 평가점의 모양 × 배치 모양이에요. 사용자가 모양으로 요청한 출력은 할당 전에 물리 메모리와 견주고, 넘으면 `MemoryError`예요.

## 다른 영역과 만나는 자리

- **배열.** `sd.interp`와 이 영역의 선형 길이 `base/lerp.hpp`의 커널과 `base/interval.hpp`의 탐색을 함께 써요. 구간 찾기의 순서 규칙은 `searchsorted`와 같고, `integrate`의 합은 배열의 pairwise 합과 같은 트리(`base/pairwise.hpp`)예요.
- **linalg.** 스플라인의 띠 연립방정식은 이 영역의 풀이라서 `sd.linalg.solve_banded`와 끝자리가 다를 수 있어요. 둘 다 틀린 것이 아니고 소거의 순서가 달라요. RBF, AAA, Floater–Hormann의 극점·영점·유수만 `linalg/lapack.hpp`의 래퍼로 LAPACK을 불러요.
- **spatial.** `RBFInterpolator(neighbors=k)`와 `NearestNDInterpolator`가 `KDTree`의 이웃 찾기를 써요. 이웃의 동점이 (거리, 색인) 순서로 정해져 있어서 이웃 집합이 실행과 스레드 수와 무관해요. `LinearNDInterpolator`와 `CloughTocher2DInterpolator`는 `sd.spatial.Delaunay`의 네이티브 객체를 C++에서 직접 읽어, 그 위치 찾기(`locate_each`)와 행렬식의 값 커널로 값을 내요. 삼각분할이 정확하고 동점 규칙이 정해져 있어서, 평가점이 든 단체와 무게가 실행과 스레드 수와 무관해요([삼각분할 위의 보간](/internals/interpolate/scattered/)).
- **sparse.** `BSpline.design_matrix`가 `sd.sparse.csr_array`를 돌려줘요. 이 의존은 Python 층에만 있어요. C++는 CSR의 세 배열을 채우고 Python이 그것을 희소 배열로 감싸요.
- **integrate.** `PPoly.integrate`는 조각 다항식의 정확한 역미분으로 계산하고 `sd.integrate.quad`를 부르지 않아요.
