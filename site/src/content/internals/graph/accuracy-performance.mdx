## 한눈에 보기

그래프 영역의 결과는 세 가지로 확인해요.

1. **정수와 집합의 답은 정의와 똑같이.** 연결 요소, 순회, 위상 정렬, 최소 신장 트리(고른 변의 집합과 자리), 역 Cuthill–McKee, 구조적 랭크, 매칭의 크기, 흐름 값(과 흐름의 보존·용량 조건), 단절점, 다리, 이중 연결 요소, 코어 수는 반올림이 없거나 답이 하나라서 참값과 바이트까지 같아야 해요.
2. **실수의 답은 계약 안.** 최단 거리, `yen`, 실수 비용의 배정, `laplacian`, `pagerank`, `betweenness_centrality`는 반올림을 세어 만든 한계가 있고, 정확한 유리수나 Arb(구간 산술)로 만든 참값과의 차이를 그 한계로 나눈 값(계약 대비)이 1 이하여야 해요.
3. **반올림이 아닌 동작은 scipy·networkx와 견줘서.** 결과의 모양과 형, 기본값, 에러, 동점이 없을 때의 선행 노드·순서·레이블을 scipy 1.18.1과 networkx 3.7의 기록, 그리고 그 자리에서 부른 결과와 견줘요. 다르게 정한 곳은 함수 페이지의 끝 절에 모여 있어요.

그리고 모든 결과가 스레드 수와 무관한지를 테스트와 골든 출력이 봐요.

## 시험 그래프

테스트, 참값 도구, scipy·networkx의 기록, 측정이 모두 같은 그래프 목록(`tests/graph/graphs.py`)에서 아이디로 그래프를 가져와요. 61개 모두 식과 고정 시드로 만들고 내려받는 것이 없어요. 그래프마다 입력의 해시(`digest`)를 가져서, 만드는 식이 바뀌면 참값 파일과 기록이 맞지 않는 것을 테스트가 바로 알아요.

| 묶음 | 그래프 | 무엇을 보려고 |
|---|---|---|
| 모양 | 빈 그래프($n = 0, 1$), 고립 노드, 경로, 순환, 별, 완전 그래프, 2·3차원 격자, 사다리, 이분 그래프(직사각), DAG, 무작위 유향·무향(Erdős–Rényi, 차수가 긴 꼬리), 여러 요소, 자기 고리, 한 방향만의 변, 두 방향 무게가 다른 변 | 격자는 같은 거리의 경로가 아주 많고, 사다리는 경로 수가 $2^{n/2}$예요 |
| 무게 | 작은 정수(동점이 많아요), $2^{53}$ 둘레의 큰 정수, 2진 유리수, $10^{-8}$–$10^{8}$의 넓은 범위, 흡수가 생기는 무게, 저장된 0(무게 0의 변과 0 무게 순환), 음수(순환 없음, 닿는 음수 순환, 닿지 않는 음수 순환, 정확한 합 0의 순환), bool | 정수·2진 유리수·bool은 합이 double에서 정확해 결과가 정확해야 해요 |
| 경계 | 밀집의 0·NaN·$\pm\infty$, 희소의 저장된 NaN·$\pm\infty$, 범위 밖 노드, `limit`의 경계와 그 앞뒤 double | 입력 규칙과 에러 |
| 흐름과 매칭 | int64 경계 근처의 정수 용량, 완전 매칭이 없는 경우, 동점이 많은 비용, 직사각 | 넘침 검사, 실패의 모양, 고정된 동점 순서 |

입력 꼴(`tests/graph/forms.py`)은 희소 넷(`csr_array`, `csc_array`, `coo_array`, `dok_array`)과 밀집이에요. 같은 그래프를 모든 꼴로 넣어 같은 결과인지도 봐요.

## 정의 구현과 참값

### 정의를 그대로 옮긴 구현

정확해야 하는 결과는 참값 파일 대신 테스트 안의 파이썬 구현(`tests/graph/definitions.py`)과 견줘요. 빠른 알고리즘이 아니라 정의를 그대로 옮긴 것이고, 무게는 `Fraction`으로 정확히 다뤄요.

| 함수 | 정의 구현 |
|---|---|
| `minimum_spanning_tree` | 키 $(w, \min(i, j), \max(i, j))$를 `Fraction`으로 견주는 Kruskal, 고른 변의 저장 자리까지 |
| `maximum_flow` | 파이썬 정수의 증가 경로(넘침이 없어요) |
| `maximum_bipartite_matching`, `structural_rank` | 증가 경로로 구한 매칭의 크기 |
| 배정 둘 | 작은 문제는 모든 배정의 나열, 큰 문제는 정확한 유리수 풀이 `assignment_exact` |
| `reverse_cuthill_mckee` | 시작 노드와 이웃을 (차수, 번호)로 줄 세우는 정의 그대로 |
| 단절점, 다리 | 노드나 변을 하나씩 지우고 연결 요소를 다시 세기 |
| `biconnected_components` | 어느 노드 $x$를 지워도 두 변이 같은 요소에 남으면 한 요소로 묶기 |
| `core_number` | 차수가 $k$보다 작은 노드를 더는 없을 때까지 지우기 |
| `betweenness_centrality` | 계산한 DAG 위의 정확한 유리수 Brandes(경로 수는 파이썬 정수) |

흐름은 값만이 아니라 돌려준 흐름이 용량과 보존 조건을 지키는지도 정수로 확인해요. 정수 비용의 배정은 돌려준 배정과 함께 쌍대 변수가 최적의 증명서(모든 짝에서 $u_i + v_j \le c_{ij}$, 고른 짝에서 등호)를 이루는지 정수로 확인해요([매칭과 배정](/internals/graph/matching/)).

### 참값 파일

실수의 계약을 판정하는 참값은 도구 하나(`tools/graph_ref.py`)가 만든 여섯 묶음, 536점이에요(`tests/graph/ref/`).

| 묶음 | 점 | 내용 |
|---|---:|---|
| `paths` | 315 | 정확한 유리수 큐 Bellman–Ford의 참 거리와 선행 노드 규칙을 정확히 계산한 선행 노드, 그 경로의 변 수와 $\sum\lvert w\rvert$, 닿는 음수 순환의 표시. 그래프 39개, $n \le 120$, 읽기 넷(유향, 무게 없음, 무향, 무향 무게 없음) |
| `yen` | 55 | 고리 없는 경로 전부를 (정확한 길이, 변 수, 노드 열)로 정렬한 앞 20개와 경로 수 |
| `assignment` | 14 | $8 \times 8$까지의 모든 배정을 나열한 정확한 최적 비용(최소·최대), 최적 배정의 수, 사전 순서로 가장 작은 최적 배정 |
| `pagerank` | 25 | $(I - \alpha M^{\mathsf T})x = (1 - \alpha)v$를 Arb의 행렬 풀이로 푼 참값(원소마다 정해질 때까지 정밀도를 올려요) |
| `betweenness` | 76 | 정확한 거리 위의 정확한 유리수 Brandes, networkx의 비율과 끝점 |
| `laplacian` | 51 | Arb로 구한 차수와 정규화 원소($\sqrt{\cdot}$도 Arb) |

## 계약

판정은 테스트와 정확도 스윕이 함께 쓰는 한 곳(`tests/graph/refdata.py`)에 있어요. $\gamma_k = ku/(1 - ku)$, $u = 2^{-53}$이에요.

| 계산 | 계약 | 증명이 있는 곳 |
|---|---|---|
| 최단 거리(FW를 뺀 방법) | 방법끼리 비트까지 같음. 정수 무게(모든 부분합 $\le 2^{53}$)와 `unweighted`는 정확. 일반 무게는 $\lvert \hat d - d^* \rvert \le \gamma_{H-1}\max(\sum_{\hat p}\lvert w\rvert, \sum_{p^*}\lvert w\rvert)$ | [최단 경로](/internals/graph/shortest-paths/) |
| `floyd_warshall` | 같은 한계($\hat p$는 FW의 선행 노드가 그리는 경로) | [블록 Floyd–Warshall](/internals/graph/floyd-warshall/) |
| `yen` | 정수 무게에서 정확한 정렬의 앞 $K$개, 일반 무게에서 경로마다 거리의 계약 | [Yen](/internals/graph/yen/) |
| 배정 둘 | 정수 비용에서 정확한 최적. 실수 비용에서 돌려준 배정의 정확한 비용이 $C^* + \gamma_{2r}\sum_i(\lvert c_{i\hat\sigma(i)}\rvert + \lvert c_{i\sigma^*(i)}\rvert)$ 이하($r$은 작은 쪽) | [매칭과 배정](/internals/graph/matching/) |
| `laplacian` | 차수 $\gamma_k s$, 대칭화의 대각 밖 $\gamma_1(\lvert A_{ij}\rvert + \lvert A_{ji}\rvert)$, 정규화의 대각 밖은 상대 $(1 + \gamma_c)/\sqrt{(1 - \rho_i)(1 - \rho_j)} - 1$, 나머지는 정확 | [순서와 라플라시안](/internals/graph/ordering/) |
| `pagerank` | $\lVert \hat x - x^* \rVert_1 \le \mathtt{tol} + \gamma_K(1 + 10^{-9})/(1 - \alpha)$ | [PageRank와 매개 중심성](/internals/graph/centrality/) |
| `betweenness_centrality` | 노드마다 상대 $\gamma_K$, 참값 0은 정확히 0 | 같은 글 |

최단 거리의 한계는 경로 하나의 차례 합에 대한 표준 한계에서 나와요. 돌려준 경로 $\hat p$의 계산한 길이는 그 정확한 합보다 $\gamma\sum\lvert w\rvert$ 이상 작을 수 없고 정확한 합은 $d^*$ 이상이니 아래쪽이, 참 최단 경로 $p^*$의 계산한 길이가 $\hat d$ 이상이고 $d^* + \gamma\sum\lvert w\rvert$ 이하이니 위쪽이 서요. 음수 순환은 정확한 합이 음수인 순환이 요청한 원점에서 닿으면 언제나 `NegativeCycleError`예요.

배정의 실수 한계는 판정 기준이에요. 정확한 유리수 풀이로 구한 참 최적과 견주어, 돌려준 배정의 비용을 정확히 계산한 값이 이 한계 안인지 봐요.

PageRank의 최대 ULP가 큰 것은 계약이 `tol`만큼의 오차를 허락하기 때문이에요. `tol` $= 10^{-12}$에서 결과는 해와 $10^{-13}$쯤 달라서 원소마다 수천 ULP이고, 바닥 아래(`tol` $= 10^{-15}$)에서는 사전 횟수까지 돌아 몇 ULP예요.

### 비교 패키지 열

라이브러리의 정확도 표(`bench/graph/accuracy.md`)에는 같은 점에서 그 자리에서 잰 비교 패키지의 열이 더 있어요. 같은 참값, 같은 척도이고, 같은 양을 계산하는 공개 함수가 없으면 줄표예요.

- <strong>networkx 3.7의 `pagerank`</strong>는 연속한 두 반복의 $\ell_1$ 차로 멈춰요. 측정에서는 그 차가 $10^{-12}$ 아래가 되면 멈추도록 맞춰 불렀고, components/40에서 4.43배, selfloop/10에서 1.5배, path/10에서 1.2배 계약을 넘었어요. 연속한 차가 작아도 해까지의 거리는 그 차의 $\alpha/(1 - \alpha)$배까지일 수 있어서예요. 바닥 아래에서는 모든 영역이 계약 안이에요.
- <strong>networkx의 `betweenness_centrality`</strong>는 모든 영역에서 계약 안이에요.
- <strong>scipy의 `laplacian`</strong>도 모든 영역에서 같은 한계 안이에요.
- 최단 경로와 배정의 기준선은 비교 패키지 없이 기록한 실행이라 그 열이 비어 있어요.

비교 패키지와 끝자리가 다른 곳(동점의 선행 노드, FW의 끝자리, 덧셈 순서)은 계약이 아니라 이 열로 드러나요. 다른 덧셈 순서일 뿐 어느 쪽이 틀린 것이 아니에요.

## 결정성

라이브러리의 약속은 같은 기계, 같은 스레드 수, 같은 입력이면 실행마다 같은 비트라는 것이에요. 그래프 영역은 그보다 세게, 같은 입력이면 **스레드 수와 상관없이** 같은 결과(값, 선행 노드, 순서, 레이블, 흐름, 매칭)예요. 최단 경로는 FW를 뺀 `method`와도 무관해요. 근거는 결과를 알고리즘이 아니라 정의로 정한 것(연결 요소의 번호는 가장 작은 노드 순서, 순회의 이웃은 번호 오름차순, 최소 신장 트리는 전순서로 하나, 흐름·매칭·배정은 고정된 훑기 순서)과, 병렬 길의 분할을 모두 크기로만 정한 것이에요.

| 병렬 길 | 나누는 방법 | 결과가 같은 까닭 |
|---|---|---|
| 입력 변환(밀집 → CSR), 전치 | 원소 $2^{15}$개씩의 행 구간 | 행 하나가 한 태스크이고 조각 순서가 정해져 있어요 |
| 여러 원점의 최단 경로 | 크기로만 정한 수의 원점이 태스크 하나 | 원점 하나의 결과가 정의로 정해져요 |
| 블록 Floyd–Warshall | 단계마다 $64 \times 64$ 블록이 태스크 하나 | 블록 하나의 연산 순서가 블록 크기로만 정해져요 |
| 큰 그래프의 약한 연결 요소 | 행 구간 | 분할이 하나이고 번호는 가장 작은 노드 순서예요 |
| `laplacian` | 행 구간과 열 묶음 | 행 하나, 열 하나의 합이 한 태스크예요 |
| `pagerank` | 패턴으로 정한 행 구간, $2^{16}$항의 잎 | 행 하나의 나무가 정해져 있고, 잎을 같은 나무로 합쳐요 |
| `betweenness_centrality` | 원점 $\lceil n/256 \rceil$개의 태스크 | 부분합을 태스크 번호 순서로 더해요 |

나머지(단일 원점 최단 경로, `yen`, 순회, 강한 연결 요소, 위상 정렬, 최소 신장 트리, 흐름, 매칭, 배정, 역 Cuthill–McKee, 구조 넷)는 직렬이고 훑는 순서가 고정되어 있어요. 작업량이 $2^{15}$ 이상이면 직렬 알고리즘도 계산하는 동안 GIL을 놓아요.

테스트(`tests/graph/test_threads.py`)는 병렬 길과 GIL을 놓는 크기의 입력을 1, 3, 10스레드에서 돌려 결과의 바이트를 견줘요. 골든 출력(`tests/golden/cases_graph.py`)은 모든 공개 함수와 대표 시험 그래프, 최단 경로의 방법 다섯, 틀린 호출, 병렬 길을 탈 큰 케이스를 담고, 1·3·10스레드에서 같은 바이트여야 해요.

## 성능

속도는 통합 측정 체계의 사례(`bench/speed/cases/graph.py`)로 재요. scipy 1.18.1의 `csgraph`와 `linear_sum_assignment`, scipy에 없는 일곱은 networkx 3.7과 같은 크기에서 견주고, 1스레드와 10스레드를 둘 다 재요. 사례는 결과(거리, 레이블, 흐름 값, 희소 결과의 세 배열)도 견줘요.

질적으로 보면 이래요.

- **변환이 없어요.** 희소 입력은 표준 꼴 CSR이 보장되어 복사 없이 그대로 읽고, 색인은 int64 그대로예요. 밀집 입력은 가지 없는 두 번의 훑기로 CSR을 만들어요. 직렬 알고리즘의 빠르기는 주로 여기서 나와요.
- **Accelerate를 쓰지 않아요.** 그래프 알고리즘은 정수 색인을 따라가는 흩어진 읽기와 큐·힙·스택이 대부분이라 밀집 선형대수 루틴이 할 일이 없어요. 행 합과 벡터 합은 결정성을 위해 공용 pairwise 나무로 직접 더해요.
- **여러 원점은 원점마다 독립이라** 원점 태스크로 나눠 스레드 수에 가깝게 빨라져요. 모든 쌍의 최단 경로, `johnson`, `auto`의 밀집 Dijkstra, 매개 중심성이 여기에 들어요.
- **블록 Floyd–Warshall**은 블록마다 연속한 작업 사본을 두어 캐시에서 돌고, 블록 단위로 병렬이에요.
- **PageRank**의 걸음 하나는 희소 행렬과 벡터의 곱 하나와 비슷한 일이에요. 준비(나가는 무게, 전치, 전이 확률)도 풀이 있으면 병렬이에요.
- **직렬인 것.** 순회, 강한 연결 요소, 단일 원점 최단 경로, 최소 신장 트리, 흐름, 매칭, 배정, 역 Cuthill–McKee, 구조 넷은 앞선 걸음의 결과가 다음 걸음을 정하는 알고리즘이라 나누지 않아요. 모두 $O(n + E)$나 그 알고리즘의 표준 복잡도의 한 번 훑기예요.
- **메모리.** 사용자가 모양으로 요청한 큰 출력(모든 쌍의 $n^2$ 거리와 선행 노드, `yen`의 $K \times n$, `csgraph_to_dense`의 $n^2$)은 할당 전에 물리 메모리와 견주어 넘으면 `MemoryError`예요. 내부의 CSR 사본(무향의 합친 CSR, 전치, 잔여 그래프)은 입력의 1–2배이고, 원점마다의 작업은 길이 $n$의 배열 몇 줄이에요.
