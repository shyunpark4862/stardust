## 대입

아래 삼각 행렬 $L$의 $Lx = b$는 위에서부터 한 행씩 풀려요. 행 $i$에서 $x_1, \ldots, x_{i-1}$은 이미 알므로

$$
x_i = \frac{b_i - s_i}{l_{ii}}, \qquad s_i = \sum_{j < i} l_{ij}\,x_j
$$

이에요(앞 대입). 위 삼각은 아래 행부터 같은 식을 $j > i$에 대해 풀어요(뒤 대입). 희소 행렬이면 $s_i$의 합이 행에 저장된 원소만 돌므로, 일은 저장 수 + n이에요.

CSR로 바꾸는 이유가 여기 있어요. 행의 원소가 연속이라 $s_i$가 한 줄의 합이 되고, 다른 희소 곱(SpMV)과 같은 규칙으로 더할 수 있어요. CSC·COO·DOK 입력도 CSR로 바꾸므로 결과의 비트가 형식과 무관해요.

## 고른 삼각만 읽기

`upper`는 꼭 주는 키워드이고, 고른 삼각 밖의 원소는 읽지 않아요. 행 $i$의 원소는 열 번호 오름차순으로 저장돼 있으므로, 열 번호가 $i$ 이상인 첫 원소의 자리를 이분 탐색으로 찾으면 행이 "대각 왼쪽 / 대각 / 대각 오른쪽"으로 나뉘어요. 우변이 여럿이면 모든 행의 그 자리 `split[i]`를 먼저 찾아 두고 판정한 뒤 풀어요.

```cpp
    // csrc/sparse/triangular.cpp, sptrsv_typed
    // split[i]: the first entry of row i with column >= i; diag[i]: whether that entry is (i, i).
    std::vector<int64_t> split(static_cast<std::size_t>(n));
    std::vector<char> diag(static_cast<std::size_t>(n));
    bool singular = false;
    for_tasks(1, nnz + n, [&](int64_t) {
        for (int64_t i = 0; i < n; ++i) {
            const int64_t p = std::lower_bound(ix + ip[i], ix + ip[i + 1], i) - ix;
            split[static_cast<std::size_t>(i)] = p;
            const bool has = p < ip[i + 1] && ix[p] == i;
            diag[static_cast<std::size_t>(i)] = has;
            if (!unit && (!has || is_zero(v[p]))) singular = true;
        }
    });
    if (singular) throw linalg::LinAlgError(func + "(): singular matrix");
```

이 훑기는 태스크 하나예요. `for_tasks`로 감싼 것은 일이 2¹⁵ 단위 이상이면 GIL을 놓기 위해서예요. 대각이 없거나 정확히 0이면(`unit_diagonal=False`일 때) `LinAlgError("spsolve_triangular(): singular matrix")`예요. 우변이 여럿이면 풀기 전에, 하나면 대입을 한 번 훑은 뒤에 내고 그때까지의 결과는 버려요. 밀집의 `sd.linalg.solve_triangular`가 대각의 0을 보는 것과 같은 판정이에요. `unit_diagonal=True`면 대각을 읽지 않고 1로 봐요.

유한성도 읽는 원소만 봐요. 다른 직접 풀이는 저장된 NaN·inf가 하나라도 있으면 `ValueError`이지만, 여기서는 고른 삼각과(`unit_diagonal=False`면) 대각에 있는 것만 `ValueError`예요. 읽지 않는 원소는 결과에 영향이 없으니 밀집 `sd.linalg.solve_triangular`의 규칙과 같게 둬요. 저장된 값이 모두 유한하면(흔한 경우) 검사가 값 배열을 한 번 보는 것으로 끝나고, 아닐 때만 원소마다 행과 열을 견줘요.

```python
    # src/stardust/sparse/_direct.py, spsolve_triangular
    if data.size and not bool(_sd.all(_sd.isfinite(data))):
        # only the values read must be finite: the chosen triangle, and the diagonal unless
        # unit_diagonal (sd.linalg.solve_triangular's rule; the others may be NaN)
        rows = _core._expand(A.indptr, n, data.shape[0])
        cols = A.indices
        read = (cols != rows) if unit_diagonal else (cols == cols)
        read = read & ((cols >= rows) if upper else (cols <= rows))
        if bool(_sd.any(read & ~_sd.isfinite(data))):
            raise ValueError(f"{func}(): 'A' contains NaN or infinity")
```

## 대입 커널

```cpp
    // csrc/sparse/triangular.cpp, sptrsv_typed
    NDArray out = new_array(dtype_of<T>, b.shape_span());
    T* x = typed<T>(out);
    const int64_t blocks = (k + kColumnBlock - 1) / kColumnBlock;
    for_tasks(blocks, (nnz + n) * std::max<int64_t>(k, 1), [&](int64_t t) {
        const int64_t c0 = t * kColumnBlock, c1 = std::min(k, c0 + kColumnBlock);
        std::vector<T> parts;
        auto row = [&](int64_t i) {
            const int64_t s = split[static_cast<std::size_t>(i)];
            const bool has = diag[static_cast<std::size_t>(i)];
            const int64_t lo = lower ? ip[i] : s + (has ? 1 : 0);
            const int64_t hi = lower ? s : ip[i + 1];
            for (int64_t c = c0; c < c1; ++c) {
                auto step = [&](int64_t p, T acc) { return madd(v[p], x[ix[p] * k + c], acc); };
                const T r = minus(bp[i * k + c], ordered_sum<T>(lo, hi, step, parts));
                x[i * k + c] = unit ? r : divide(r, v[s]);
            }
        };
        if (lower)
            for (int64_t i = 0; i < n; ++i) row(i);
        else
            for (int64_t i = n - 1; i >= 0; --i) row(i);
    });
```

- **줄 합의 순서.** $s_i$는 `ordered_sum`이에요. 0에서 시작해 열 번호 오름차순으로 항마다 `fma(a, x, acc)`를 하고(복소는 numpy의 복소 곱 뒤 덧셈), 항이 4096개를 넘는 줄은 4096개씩의 고정 조각을 각각 차례로 더한 뒤 조각 합을 쌍 트리로 더해요. SpMV·SpGEMM·리덕션과 같은 규칙이라([곱](/internals/sparse/products/)), 결과가 값과 모양만으로 정해져요. 그 다음 $b_i - s_i$를 한 번 빼고 대각으로 한 번 나눠요. 복소 나눗셈은 배열의 `divide`와 같은 꼴(`ops::cdiv`)이에요.
- **우변 여럿.** 열끼리는 서로 기대지 않아요. 열 16개(`kColumnBlock`)를 한 태스크로 묶고, 묶음들이 스레드풀에서 돌아요. 묶음 안에서는 행을 차례로 지나며 그 행의 16열을 풀어요. 행의 원소를 한 번 읽어 여러 열에 쓰는 셈이에요. 열 하나의 계산은 같은 행 순서, 같은 줄 합이므로 **열의 비트가 k나 다른 열, 스레드 수와 무관해요**.
- **우변 하나**는 한 스레드예요. 대입은 행이 앞 행의 결과를 기다리므로 그대로는 나눌 수 없어요. 서로 기대지 않는 행들을 단계로 묶어 단계 안에서 나누는 방법(level scheduling)이 있지만 쓰지 않아요. 그 대신 대각 찾기, 특이 판정, 대입을 행마다 한 번에 해서 행렬을 한 번만 훑어요.

```cpp
            // csrc/sparse/triangular.cpp, sptrsv_typed
            auto row = [&](int64_t i) {
                const int64_t s = ip[i], e = ip[i + 1];
                const int64_t p = std::lower_bound(ix + s, ix + e, i) - ix;
                const bool has = p < e && ix[p] == i;
                if (!unit && (!has || is_zero(v[p]))) singular = true;
                const int64_t lo = lower ? s : p + (has ? 1 : 0);
                const int64_t hi = lower ? p : e;
                auto step = [&](int64_t q, T acc) { return madd(v[q], x[ix[q]], acc); };
                const T r = minus(bp[i], ordered_sum<T>(lo, hi, step, parts));
                x[i] = unit ? r : divide(r, has ? v[p] : T(1));
            };
```

줄 합과 나눗셈은 우변 여럿의 커널과 같아서, 같은 열이면 두 길의 비트가 같아요. 대각이 없는 행은 1로 나눠 계속 가고, 다 훑은 뒤 `singular`가 참이면 에러를 내요.

## 정확도

대입의 표준 역오차 한계(Higham 2002, 8장)를 원소마다 확인해요.

$$
|b - T\hat x| \ \le\ \gamma_n\,|T|\,|\hat x|, \qquad \gamma_n = \frac{n u}{1 - n u}, \quad u = 2^{-53}
$$

잔차는 정확한 유리수로 계산하고, 실수·복소와 긴 행(4096 넘는 줄)에서 봐요. 계산 순서가 정해져 있으므로 Python의 `math.fma`로 같은 순서를 짠 것과 비트까지 같은지도 봐요.

## scipy와 다른 점

- scipy는 `lower=True`가 기본이에요. 여기서는 `upper`를 꼭 줘야 해요(`sd.linalg.solve_triangular`와 같아요).
- scipy 1.18.1은 고른 삼각 밖의 원소가 있으면 그것을 SuperLU의 `gstrs`에 그대로 넘겨 경고 없이 틀린 답을 내요. 여기서는 읽지 않아요.
- scipy는 $A\,\mathrm{diag}(1/d)$로 단위 삼각을 푼 뒤 $1/d$를 곱하는 순서라 반올림이 달라요. `overwrite_A`, `overwrite_b`는 없어요.
