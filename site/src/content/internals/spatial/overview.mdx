## 한눈에 보기

`sd.spatial`은 네 가지 일을 해요. 점 사이의 거리를 재고(`pdist`, `cdist`, 거리 함수 열네 개, `squareform`), 전체 거리 행렬을 만들지 않고 가까운 이웃을 찾고(`kneighbors`, `radius_neighbors`), 한 번 만든 KD 트리로 같은 데이터에 여러 번 묻게 해 주고(`KDTree`와 그 메서드 여섯), 2차원과 3차원 점 집합의 모양을 구해요(`Delaunay`, `ConvexHull`, `Voronoi`).

이 영역의 설계는 한 문장으로 모여요. **짝 하나의 거리는 한 커널이 정하고, 이웃의 순서는 (거리, 색인)의 전순서가 정해요.** 그래서 같은 짝 $(x, y)$는 `pdist`, `cdist`, 거리 함수, `kneighbors`, 트리의 잎 어디서 계산하든 같은 비트이고, 이웃 찾기의 답은 "모든 짝을 그 커널로 계산해 (거리, 색인)으로 정렬한 것"이라는 정의 하나로 정해져요. 빠른 길(GEMM 고르기, KD 트리, 단위 구 위의 트리)은 이 정의를 바꾸지 않고, 답이 될 수 없다고 증명된 짝을 건너뛸 뿐이에요.

계산 기하도 같은 꼴의 문장으로 모여요. **판정은 정확한 술어가 하고, 동점은 정해진 섭동이 가르고, 배열은 표준 꼴 하나로 적어요.** 어느 점이 껍질의 꼭짓점인지, 어느 단체가 있는지는 입력 float64를 유리수로 읽은 정확한 답이고([정확한 기하 술어](/internals/spatial/predicates/)), 한 원 위의 점처럼 답이 여럿인 경우는 좌표의 사전 순서로 정한 기호 섭동이 하나를 골라요. 그래서 2차원의 나눠서 합치기와 3차원의 하나씩 넣기, 넣는 순서, 스레드 수가 결과의 바이트를 바꾸지 못해요([삼각분할 만들기](/internals/spatial/delaunay/)).

층은 아래로만 기대요. `csrc/spatial/`은 배열, 스레드풀, Accelerate의 BLAS 래퍼, `base/`의 사인·코사인 위에 서요. 다른 영역 가운데 C++에서 `spatial/`을 include하는 것은 `interpolate/`뿐이에요(RBF의 거리 커널, 삼각분할 위의 보간). 거리는 linalg의 합과 노름에 기대지 않아요. 거리의 합은 이 영역이 정한 타일 순서라서([한 짝 커널](/internals/spatial/pair-kernel/)) 남의 합을 빌려 쓰면 그 순서가 깨지기 때문이에요. 계산 기하는 BLAS와 LAPACK을 부르지 않고, Qhull 같은 밖의 기하 라이브러리도 쓰지 않아요. 술어부터 삼각분할, 껍질, 보로노이까지 모두 이 디렉터리의 코드예요.

C++ 하위 모듈 `stardust._core.spatial`은 소스 파일마다 하나씩 있는 `bind_*`(`bind_distance`, `bind_kdtree`, `bind_neighbors`, `bind_query`, `bind_dual`, `bind_sphere`, `bind_predicates`, `bind_hull`, `bind_delaunay`, `bind_voronoi`)를 차례로 불러 만들어요. 그래서 네이티브 이름은 모두 밑줄로 시작하는 내부 이름이고, 사용자는 Python 함수와 클래스(`KDTree`, `Delaunay`, `ConvexHull`, `Voronoi`)만 봐요. 아래는 거리와 전수 이웃 찾기(`distance.cpp`, `neighbors.cpp`)의 이름, KD 트리와 구면 트리(`kdtree.cpp`, `query.cpp`, `dual.cpp`, `sphere.cpp`)의 이름, 그리고 계산 기하(`delaunay2.cpp`, `hull.cpp`, `voronoi.cpp`)와 술어의 테스트용 바인딩(`predicates.cpp`)의 이름이에요.

술어의 바인딩은 공개 API가 아니에요. 테스트와 측정이 단계(거르기, 전개식, 넓은 정수)를 강제로 골라 부르는 문이에요. `_circumcenter`도 보로노이 꼭짓점의 커널을 테스트가 따로 부르는 문이에요.

Python 층은 인자를 모두 검사하고 C++ 층은 넘겨받은 배치(dtype, 차원, 연속성)만 확인해요. 검사가 한곳(`_common.py`)에 모여 있어서 `kneighbors`와 `KDTree.query`가 `k`와 `distance_upper_bound`를 같은 함수, 같은 메시지로 검사해요. 공개 함수의 에러는 부른 함수의 이름으로 시작하고, C++ 쪽의 에러는 Python이 이미 막은 배치가 어긋났을 때만 나요.

## 길 고르기

같은 질문을 푸는 길이 넷이에요. 고르는 기준은 거리 이름과 입력의 모양뿐이고 값은 보지 않아요.

| 길 | 쓰는 곳 | 조건 | 자세히 |
|---|---|---|---|
| 직접 전수 | 모든 거리 | 다른 길이 맞지 않을 때 | [한 짝 커널](/internals/spatial/pair-kernel/), [병렬화와 결정성](/internals/spatial/parallel/) |
| GEMM 고르기 | 가중치 없는 `euclidean`·`sqeuclidean`(`minkowski` $p = 2$ 포함) | $1 \le n \le 2^{16}$, $m_A \ge 64$, $m_B \ge 2048$($n \ge 8$이면 1024) | [유클리드 혼합 계산](/internals/spatial/euclid-gemm/) |
| XB로 만든 KD 트리 | 가중치 없는 `euclidean`·`cityblock`·`chebyshev`·`minkowski`($p \ge 1$) | $n \le 4$, $k \le 32$, $m_B \ge 2048$이고 $m_A \ge 2048$이거나 ($m_A \ge 512$, $m_B \ge 32768$). 다른 $p$의 `minkowski`는 $n \le 8$, $m_B \ge 1024$, $m_A m_B \ge 2^{17}$ | [KD 트리](/internals/spatial/kdtree/), [질의](/internals/spatial/queries/) |
| 단위 구 KD 트리 | `haversine` | $m_B \ge 128$, $m_A \ge 16$, $8k \le m_B$, 그리고 모든 점이 $\lvert\text{위도}\rvert \le \mathrm{fl}(\pi/2)$, $\lvert\text{경도}\rvert \le 8$ | [단위 구 위의 KD 트리](/internals/spatial/haversine-tree/) |

`KDTree.query`도 반대 방향으로 고르기를 해요. $p = 2$이고 점의 차원 $m$이 점 수 $n$에 비해 높으면 트리 대신 입력 순서의 `data`에 `kneighbors`의 전수(모양이 맞으면 GEMM 고르기)를 써요. 트리의 질의당 일은 대략 $2^{5m/6}$로, 전수는 $n$으로 자라니 그 둘을 견주는 식이에요. `_kdtree.py`의 `_brute_pays(n, m, k)`가 $5m/6 + \tfrac14\log_2 k + 7 - \log_2 n \ge 0.5$이면 전수를 골라요($k$가 크면 트리가 조금 더 불리해지는 몫이 $\tfrac14\log_2 k$예요).

```python
>>> from stardust.spatial._kdtree import _brute_pays
>>> _brute_pays(10**5, 3, 1), _brute_pays(10**5, 16, 10)
(False, True)
```

`sqeuclidean`은 KD 트리 길에 들지 않아요. 트리는 $\sqrt{\ }$를 씌운 거리 $\hat d$로 순서를 정하는데, 서로 다른 두 제곱합이 $\sqrt{\ }$의 반올림 뒤 같은 $\hat d$가 될 수 있어요. 그러면 제곱합 $(\hat s, j)$의 순서와 $(\hat d, j)$의 순서가 동점에서 갈려 결과가 정의와 달라질 수 있어요.

### 길이 결과를 바꾸지 않는 까닭

답이 길과 무관하려면 세 가지가 서야 해요.

1. **거리가 같은 비트.** 어느 길이든 짝의 거리는 `cdist`의 커널이 구해요. 전수 길은 `cdist`의 구동기를 블록마다 그대로 부르고(`CdistBlocks`), GEMM 길은 남은 짝을 같은 한 짝 커널(`pair_scalar`)과 같은 마무리 함수로 다시 계산하고, 트리의 잎도 같은 커널이에요. 타일 커널의 레인과 한 짝 커널이 같은 비트라는 것은 [한 짝 커널](/internals/spatial/pair-kernel/)에서 보여요.
2. **순서가 전순서.** 힙과 정렬과 합치기가 모두 `before(a, b) = a.d < b.d || (a.d == b.d && a.j < b.j)` 하나로 견줘요. 전순서라 어떤 순서로 넣고 어떻게 나눠 합쳐도 가장 작은 k개는 하나로 정해져요. NaN인 거리는 `d < upper`도 `d <= r`도 거짓이라 힙에 들어오지 않아요.
3. **건너뛰기가 보수적.** 빠른 길이 짝을 건너뛰는 것은 그 짝의 거리 $\hat d$가 지금의 문턱 $T$보다 **엄격히** 크다고 증명될 때뿐이에요. 엄격하니 같은 거리에 색인이 작은 점(동점)도 빠지지 않아요. GEMM 고르기는 [정리 3](/internals/spatial/euclid-gemm/), KD 트리는 상자까지의 거리 하한, 단위 구 트리는 현 거리의 여유가 그 증명이에요.

테스트용 숨은 인자 `path`(1 전수, 2 GEMM, 3 트리)로 세 길을 강제로 타 보면 거리와 색인이 바이트까지 같아요.

```python
>>> from stardust.spatial import _neighbors as N
>>> rng = sd.random.default_rng(7)
>>> XA, XB = rng.random((300, 3)), rng.random((5000, 3))
>>> outs = [N._knn("kneighbors", XA, XB, 4, "euclidean", None, None, None, None, math.inf, path=p) for p in (1, 2, 3)]
>>> [o.distances.tolist() == outs[0].distances.tolist() and o.indices.tolist() == outs[0].indices.tolist() for o in outs]
[True, True, True]
```

스레드 수도 같은 이유로 답을 바꾸지 않아요. 일은 크기로만 나누고, 질의 하나나 짝 하나는 한 태스크가 처음부터 끝까지 계산해요. GEMM은 고르기에만 쓰이니 Accelerate의 스레드 모드(`VECLIB_MAXIMUM_THREADS`)가 GEMM의 끝자리를 바꿔도 답은 그대로예요. 나누는 방식은 [병렬화와 결정성](/internals/spatial/parallel/)에 모았어요.

## 결과 객체

`query`와 `kneighbors`는 `QueryResult(distances, indices)`를 돌려줘요. 다른 영역의 결과 튜플과 함께 `stardust/_results.py`에 있는 namedtuple이고, 두 배열은 돌려주기 전에 쓰기 금지가 돼요.

```python
>>> r = sd.spatial.kneighbors(XA[:2], XB, k=3)
>>> type(r).__name__, type(r).__module__
('QueryResult', 'stardust._results')
>>> r.indices.tolist()
[[827, 2296, 3973], [451, 966, 3202]]
>>> r.indices._flags()["writeable"]
False
```

반경 질의 셋(`radius_neighbors`, `query_ball_point`, `query_ball_tree`)은 `_radius.py`의 `RadiusResult`를 써요. 생성자는 CSR 꼴의 세 배열과 모양을 받아 검사도 복사도 하지 않고 쓰기 금지로만 만들어요. 꼴(행마다 색인 오름차순, `indptr`의 누적 개수)은 그것을 만든 네이티브 찾기가 보장하니까요. `tocsr()`는 부를 때마다 희소 배열 `sd.sparse.csr_array((distances.copy(), indices, indptr), shape=shape)`를 만들어요. 거리는 복사하므로 그 `data`는 쓸 수 있는 새 배열이라, 희소 배열의 제자리 연산(`A.data *= 2`)이 결과 객체의 거리를 건드리지 않아요. 색인 둘은 결과와 함께 써요.

```python
>>> rr = sd.spatial.radius_neighbors(XA[:4], XB, 0.05)
>>> rr
RadiusResult(shape=(4, 5000), nnz=10)
>>> rr.tocsr()
<csr_array of shape (4, 5000), float64, 10 stored elements>
```

거리가 0인 짝(자기 자신, 중복된 점)은 CSR에 **저장된 0**으로 남아요. 희소 행렬의 저장 자리가 곧 이웃 그래프의 변이라서, 0을 지우면 중복된 점이 이웃에서 사라지기 때문이에요. 필드와 쓰임은 [결과 객체](/api/spatial/results/) 페이지에 있어요.

계산 기하의 세 클래스는 결과를 두 가지 꼴로 쥐어요. `Delaunay`는 네이티브 삼각분할 객체(`_core.spatial._Delaunay`)를 쥐어요. `find_simplex`가 그 안의 위치 격자와 술어를 다시 쓰고, 흩어진 점 보간도 그 객체를 C++에서 직접 읽기 때문이에요. `simplices`, `neighbors`, `vertex_to_simplex`는 만들 때, `convex_hull`, `vertex_neighbor_vertices`, `coplanar`, `transform`, `min_bound`, `max_bound`는 처음 읽을 때 만들어 쥐어요. `ConvexHull`과 `Voronoi`는 질의가 없어서 네이티브 함수 하나가 모든 배열을 한 번에 돌려주고, 클래스는 그 배열만 쥐어요. 어느 쪽이든 배열은 쓰기 금지예요.

```python
>>> tri = sd.spatial.Delaunay(XB[:1000, :2])
>>> tri, type(tri._tri).__name__
(Delaunay(n=1000, d=2, nsimplex=1983), '_Delaunay')
>>> tri.simplices.dtype, tri.simplices._flags()["writeable"]
(int64, False)
>>> sd.spatial.ConvexHull(XB[:1000]), sd.spatial.Voronoi(XB[:1000, :2])
(ConvexHull(n=1000, d=3, nvertices=69), Voronoi(n=1000, d=2, nvertices=1983))
```

피클과 복사는 점의 바이트만 담고 되살릴 때 다시 만들어요. 결과가 점 집합의 정의로 정해지니 다시 만든 객체는 바이트까지 같아요.

## 계산 기하의 메모리

삼각분할의 크기는 2차원에서 점 수로 정해지지만(서로 다른 점 $m$개, 경계의 점 $b$개면 삼각형 $2m - 2 - b$개), 3차원에서는 입력에 따라 점마다 몇 개에서 점 수에 비례하는 수까지 달라져요. 그래서 메모리를 두 겹으로 지켜요.

- **만들기 전.** Python이 점 수로 어림한 작업 메모리를 이 기계의 물리 메모리와 견줘요(`check_alloc`). 점 하나에 `Delaunay`는 2차원 360바이트, 3차원 328바이트, `Voronoi`는 640바이트, 552바이트예요. 사본과 정렬 키, 만드는 동안의 구조, 표준 꼴의 행·차례·자리, 결과가 함께 있을 때의 정점을 어림한 값이에요.
- **만드는 동안(3차원).** 사면체를 세다가 (물리 메모리 − $200n$)/128개를 넘으면 모두 놓고 `MemoryError`예요. `Voronoi`는 만든 뒤 사면체마다 352바이트로 한 번 더 견줘요.

쥐는 배열은 2차원 `Delaunay`가 점마다 약 122바이트, 고른 점의 3차원이 약 464바이트예요. `Voronoi`는 삼각분할을 놓고 결과만 쥐어요. 자세한 셈은 [삼각분할 만들기](/internals/spatial/delaunay/#메모리)와 [볼록 껍질과 보로노이](/internals/spatial/hull-voronoi/#병렬과-메모리)에 있어요. `ConvexHull`은 점의 사본과 극점·면의 배열만 쥐고, 크기가 점 수와 껍질의 크기로 정해져서 만들기 전의 어림을 따로 두지 않아요.

## 다른 영역과 만나는 자리

- **sparse.** `RadiusResult.tocsr()`와 `KDTree.sparse_distance_matrix`가 `sd.sparse.csr_array`를 만들어요. 이 의존은 Python 층에만 있어요. C++의 `spatial/`은 `sparse/`를 모르고, CSR의 세 배열을 직접 채운 뒤 Python이 그것을 희소 배열로 감싸요. 정수 인자 판별 하나(`is_int`)도 sparse의 Python 도우미를 빌려 써요. `Delaunay.vertex_neighbor_vertices`의 `(indptr, indices)`도 CSR의 두 배열이라, 따로 바꾸지 않고 희소 배열의 생성자에 넣으면 삼각분할의 변 그래프가 돼요.

```python
>>> indptr, indices = tri.vertex_neighbor_vertices
>>> sd.sparse.csr_array((sd.ones(indices.shape[0]), indices, indptr), shape=(1000, 1000)).nnz
5964
```

- **linalg와 배열.** `mahalanobis`의 기본 `VI`는 `sd.cov(X, rowvar=False, correction=1)`의 역행렬을 `sd.linalg.inv`로 구하고, `seuclidean`의 기본 `V`는 `sd.var(..., correction=1)`이에요. 공분산이 특이하면 `inv`의 `LinAlgError`를 받아 이 영역의 메시지로 바꿔 다시 던져요. 기본 `V`는 값이 모두 같은 열이 있으면 `ValueError`예요. 그런 열의 `sd.var`는 평균의 반올림 때문에 0이 아닌 찌꺼기(0.1 세 개에서 $2.9 \times 10^{-34}$)일 수 있어서, 분산이 0인지만 보지 않고 `rows == rows[:1]`의 열마다 `all`로 열 자체를 한 번 봐요. NaN은 자기와 같지 않으니 상수 열로 보지 않고, 그 열의 분산이 NaN이라 거리로 퍼져요.
- **linalg의 노름과는 비트가 다를 수 있어요.** 거리의 합은 linalg의 합을 쓰지 않으니 `euclidean(x, y)`와 `sd.linalg.vector_norm(x - y)`는 $n \ge 16$에서 끝자리가 갈릴 수 있어요. $n \lt 16$이면 두 순서가 같은 차례 합이라 언제나 같아요.

```python
>>> a = sd.asarray([0.1 * i for i in range(40)])
>>> b = sd.asarray([0.07 * i * i % 1.0 for i in range(40)])
>>> sd.spatial.euclidean(a[:15], b[:15]) == sd.linalg.vector_norm(a[:15] - b[:15])
True
>>> d1, d2 = sd.spatial.euclidean(a, b), sd.linalg.vector_norm(a - b)
>>> d1 == d2, abs(d1 - d2) <= 2 * math.ulp(d1)
(False, True)
```

어느 쪽도 틀린 것이 아니에요. 둘 다 정확도 계약 안이고, 합의 순서만 달라요. 이 영역이 linalg의 16레인 순서 대신 타일 순서를 고른 까닭은 [한 짝 커널](/internals/spatial/pair-kernel/)에서 다뤄요.

- **Accelerate.** BLAS는 GEMM 고르기의 `cblas_dgemm` 하나만 불러요. 돌려주는 거리는 BLAS를 거치지 않으니 Accelerate의 스레드 모드와 무관해요. 이 점이 결과를 Accelerate에 맡기는 linalg와 다른 곳이에요.
- **interpolate.** 보간 영역이 이 영역의 C++를 두 곳에서 써요. `RBFInterpolator`는 거리를 유클리드 짝 커널(`metric.hpp`)로 구해 `cdist`와 같은 비트를 쓰고, 흩어진 점 보간(`LinearNDInterpolator`, `CloughTocher2DInterpolator`)은 `Delaunay`의 네이티브 객체를 직접 읽어 위치 찾기(`locate_each`)와 값 커널(`det2`, `det3`)로 값을 내요([삼각분할 위의 보간](/internals/interpolate/scattered/)). Python 층의 `NearestNDInterpolator`와 `RBFInterpolator(neighbors=k)`는 `KDTree`를 써요.
